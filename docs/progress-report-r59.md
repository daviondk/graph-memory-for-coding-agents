# Отчёт об экспериментах с графовой памятью кодового агента

Проверили, как сократить стоимость чтения истории совместных изменений файлов. Реализовали в SQLite два варианта памяти. Первый кеширует полный список событий файла. Второй может хранить только число событий и XOR их идентификаторов. Если в кеше не хватает ровно одного события, его ID восстанавливается без запроса полного списка.

На шести новых репозиториях и 721 запросе при дополнительном кеше 1 КиБ объём чтения из SQLite снизился на 8,7%. При обращении к той же базе по TCP двусторонний трафик сократился с 36 582 до 33 180 байт (−9,3%), число обменов — с 688 до 670. Все ответы совпали с эталоном. При 4 КиБ полные списки оказались экономнее. Устойчивого ускорения на локальной машине не получили.

Проверили также восстановление после перезапуска. На 189 редких запросах к 12 проектам сохранение адресов событий с загрузкой по требованию потребовало 18 005 байт против 37 876 у сжатой копии. Обычный LRU-кеш на 4 КиБ без снимка потребовал ещё меньше — 11 600 байт. В 108 реальных траекториях SWE-agent перенос сведений о совпадающих строках сэкономил 239 чтений, но увеличил общий трафик на 7 919 байт.

На SWE-ContextBench Lite проверили, помогают ли связи «чтение → правка» локальной Qwen3-4B выбрать релевантную прошлую сессию. На 57 задачах получено 44/57 верных выборов как со связями, так и с одними вершинами. На других 33 задачах замена пятого кандидата графовым снизила Hit@5 с 28/33 до 26/33. Подтверждённый результат для ICDE — снижение стоимости точного доступа при малом кеше. Выигрыш по качеству решения задач относительно SOTA пока не установлен.

# Отчёт о графовой памяти с учётом вытеснений

В прошлой серии краткая сводка позволяла восстановить один пропущенный идентификатор события Git. В этой серии реализован метод для нескольких пропусков. Когда из кеша исчезает последняя копия события, память сохраняет его адрес для участвовавших в нём файлов. Следующий запрос может прочитать только недостающие события и вернуть те же восемь файлов и баллы.

На шести новых репозиториях и 485 запросах при дополнительном кеше 1 КиБ метод сократил чтение из SQLite с 11 531 до 9 213 байт. После усиления контрольного метода выбором из четырёх семейств кодеков выигрыш сохранился — 9 201 против 11 372 байт (−19,1%). При доступе по TCP трафик снизился с 20 115 до 16 533 байт (−17,8%), число обменов — с 412 до 374. При 4 КиБ полный список и новый метод сравнялись. В 108 реальных сессиях SWE-agent на основной конфигурации все методы также прочитали одинаковые 1 668 байт.

Отдельно проверено, когда агенту стоит перечитывать прошлую сессию. На всех 99 задачах SWE-ContextBench Lite вызов Qwen 27B только при расхождении трёх поисковых выдач дал 73 корректных выбора при 31 обращении к модели. При постоянном чтении — 75 из 99 при 99 обращениях. Оценка выполнена на архивных ответах, учитывает выбор подходящей сессии. Доля исправленных задач в этом опыте не измерялась.

Для ICDE подготовлены четырёхстраничная рукопись, интерактивная демонстрация с реальным запросом SQLite и видео. Наиболее подтверждённый вклад — снижение стоимости точного доступа к длинной истории при малом кеше.

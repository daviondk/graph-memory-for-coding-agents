# Отчёт о графовой памяти агента

Добрый день! После прошлого отчёта проверил, можно ли повторно использовать историю совместных правок. Если одна правка затронула два файла и уже вышла из восьми последних изменений первого, её всё ещё можно прочитать через запись второго.

- **Поиск связанных файлов.** На 196 правках в NetworkX, Matplotlib и Sphinx измерил, какую долю остальных изменённых файлов удаётся найти в восьми рекомендациях. Собственная история файла дала 41,97% Recall@8, использование событий, сохранённых другими участниками, — 43,53%. При выборе восьми наименьших правок получилось 45,88%, при чтении всей истории — 46,33%. Результат зависел от проекта. [Эксперимент](../experiments/graph_memory_round56/shared_evidence/REPORT_RU.md)
- **Реализация в SQLite.** На 880 запросах новая схема вернула те же восемь файлов с теми же баллами и сократила чтение составов событий из архива с 74 840 до 8 076 байт. На длинных историях суммарный размер баз уменьшился с 664 до 500 КиБ, на коротких вырос с 196 до 200 КиБ. [Измерения хранения и чтения](../experiments/graph_memory_round56/durable/REPORT_RU.md)
- **Внешний бенчмарк и генерация кода.** На 105 задачах поиска тестов из Agent Retrieval Bench основной вариант дал 69,62% Recall@5 против 68,98% без графа. В дополнительном эксперименте граф улучшил ансамбль поисковиков с 75,05% до 78,03%, но с ещё одним поисковиком прирост сократился до 0,48 п.п. На 36 функциях Qwen3-4B с компактной памятью и BM25 по полной истории прошла все авторские тестовые примеры в 15 случаях, без памяти — в 13. После исключения пяти функций с совпадающими примерами все три варианта дали 11/31. [Поиск тестов](../experiments/graph_memory_round56/code2test/REPORT_RU.md) · [Исполняемые проверки](../experiments/graph_memory_round56/solver/REPORT_RU.md)

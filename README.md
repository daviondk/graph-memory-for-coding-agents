# Графовая память кодового агента

Исследование того, какие наблюдения из работы с кодом стоит сохранять, как обновлять их после правок и когда показывать агенту.

**Отчёт** · [PDF, 4 страницы](docs/report.pdf) · [редактируемый Word](docs/report.docx) · [читать на GitHub](docs/report.md).

[Пятнадцатая серия](experiments/graph_memory_round15/REPORT_RU.md) — запись путей из вывода инструментов, решения Qwen о следующем чтении, свидетельства pytest, сохранение рабочего дерева и оценка на SWE-Explore и IssueLoc.

[Четырнадцатая серия](experiments/graph_memory_round14/REPORT_RU.md) — сравнение с предобученным SweRank, 120 чтений Qwen, проверка актуальности на трёх файловых системах и официальная оценка всех наблюдавшихся промежуточных патчей.

[Тринадцатая серия](experiments/graph_memory_round13/REPORT_RU.md) — локализация по ранее увиденным фрагментам, 54 инструментальных чтения Qwen, проверка происхождения наблюдений и правильный патч, найденный в рабочем состоянии перед завершением.

[Двенадцатая серия](experiments/graph_memory_round12/REPORT_RU.md) — проверка актуальности и повторного использования наблюдений, цена обновления тестового графа, два новых задания VibeMemBench с Qwen и официальным оценщиком.

[Одиннадцатая серия](experiments/graph_memory_round11/REPORT_RU.md) — естественные пустые поиски, побайтно проверенные ссылки на прошлые чтения, сравнение с sqz и интервенции на памяти Qwen.

[Десятая серия](experiments/graph_memory_round10/REPORT_RU.md) — отрицательные зависимости, компактные словари, нативные свидетельства MemTrace и выбор одного теста с Qwen.

[Девятая серия](experiments/graph_memory_round9/REPORT_RU.md) — внешние Java-панели, Loc-Bench, память о тестовых исходах и абляции с реальным решателем.

[Восьмая серия](experiments/graph_memory_round8/REPORT_RU.md) — восстановление ссылок после рефакторинга, типы связей, сравнение с SweRank и три парных опыта с исполняемыми ссылками.

[Седьмая серия](experiments/graph_memory_round7/REPORT_RU.md) — прогноз следующего чтения, проверка сохранённых связей между версиями кода, локализация строк и парный прогон Qwen с pytest.

## Основные результаты

| Что проверяли | Что получилось | Как читать результат |
| --- | --- | --- |
| Восстановление кода после изменений | По 186 запросам из 48 задач архив с актуальными координатами восстановил 129 блоков целиком против 121 в исходном архиве. Ошибочных строк в выдаче стало 2 вместо 113. | Путь и диапазон заранее известны. Сравниваются варианты записи на компонентах MemTrace. |
| Задержка чтения | Добавление 4 КиБ локальной памяти уменьшило число открытий страниц со 141 до 11. На прогретой Linux-системе средняя задержка составила 0,47 мс против 3,97 мс при той же конечной выдаче. | Простой LRU дал 0,47 мс. В этот замер входит чтение готовой памяти. |
| Предсказание других файлов в Git | На 10 отложенных проектах средняя полнота первых пяти предложений выросла с 39,27% до 53,50% при использовании истории совместных правок. | Известен один изменённый файл. |
| Исправления SymPy | На первых 16 задачах с текстовой памятью целевые тесты прошли 4 решения, с графом вызовов — 3. При предъявлении правильного участка исходного кода и тех же разрешённых путях — 10. | Привилегированные координаты служат диагностикой. На 12 новых задачах оба автоматических метода дали 0/12. |

Устойчивого превосходства по числу автономно решённых задач в опубликованном полном бенчмарке пока не установлено. Сравнения, ограничения по бюджету, независимые репликации и отрицательные результаты включены в отчёты.

## Как проверить

В корне репозитория запустите:

```sh
python tools/check_results.py
```

Для этой проверки достаточно Python 3.8+ со стандартной библиотекой. Скрипт пересчитывает по сохранённым наблюдениям полные ответы и ошибочные строки, число обращений, равенство контрольных сумм выдачи, средние задержки и успешные исправления. Для возобновления полных опытов используйте протокол выбранной серии и соответствующий архив релиза. Запросы и ответы модели уже сохранены. Для повторной генерации потребуются указанные в протоколе зависимости и веса.

Данные по 186 чтениям экспортированы из нативных ответов архива и журнала времени. Результаты SymPy взяты из прогонов исходной, эталонной и сгенерированных версий на тестах. Экспорт при наличии исходного дерева шестой серии выполняется командой `python tools/export_key_results.py ПУТЬ_К_СЕРИИ_6 results`. Для экспорта требуются зависимости исходного оценщика; для проверки готовых таблиц они не нужны.

## Первоисточники

Архитектуры памяти и хранение происхождения описаны в [MemOS](https://arxiv.org/abs/2507.03724), [MIRIX‑2.0](https://arxiv.org/abs/2611.12068), [WikiTrace](https://arxiv.org/abs/2611.14320) и [MemTrace](https://arxiv.org/abs/2610.04838). Протокол поиска внешнего фрагмента приведён в [RepoBench](https://github.com/Leolty/repobench), а условия стандартной проверки патчей — в [SWE-bench](https://www.swebench.com/SWE-bench/guides/evaluation/). Версии исходных проектов, дополнительные публикации и сведения об адаптированных условиях собраны в материалах отдельных серий.

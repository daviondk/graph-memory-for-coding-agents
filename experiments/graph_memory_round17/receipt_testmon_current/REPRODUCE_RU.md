# Воспроизведение нативного CLI

Запуск использует два окружения на D и официальный [pytest-testmon](https://pypi.org/project/pytest-testmon/). Точные версии и порядок условий зафиксированы в [назначении](assignment.json). Рабочие копии восстанавливаются из Git-блобов. Нужны соседние папки receipt_invalidation и receipt_holdout с зафиксированными реестрами, а также официальный клон more-itertools в расположении, заданном первым экспериментом.

```text
python -B benchmark.py
python -B verify.py
```

Для каждой из 26 комбинаций коммита и версии создаются новая копия файлов и пустая база testmon. Предыдущий этап написания отчёта был прерван после 23 завершённых условий, до агрегирования XML. Короткий журнал и исходное назначение сохранены в interrupted.log и original-assignment.json. До повторного измерения изменили сохранение завершённых блоков. Теперь каждый блок атомарно записывается в отдельный сжатый JSON на диске D. При повторном исполнении разрешены только файлы для той же контрольной суммы кода и назначения. Изолированные блоки допускают параллельность до трёх заданий. Законченный набор в official-runs.gz полностью включает XML и stdout всех 104 процессов финального прогона. Первые 23 блока в опубликованные суммы не включены. Время отражает конкуренцию параллельных процессов.

Верификатор сверяет SHA скрипта и протокола и пересчитывает каждое имя и итог теста из XML. Все метки полного повторного запуска, а также все результаты до редактирования сравниваются между версиями. Выбор запомненных результатов вычисляется только на методах, для которых при прогреве был положительный исход. Сохранены также сырые результаты для единственного исходно пропущенного теста. Полные оценки на разных версиях дают дополнительную проверку воспроизводимости меток. [Первоначальный протокол](PROTOCOL_RU.md)

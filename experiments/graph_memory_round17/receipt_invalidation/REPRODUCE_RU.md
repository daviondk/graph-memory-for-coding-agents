# Воспроизведение

Три панели решают разные измерительные задачи. Скриптам требуется Python. Первые два блока исходно выполнены на CPython 3.14, дополнительное сравнение с pytest-testmon использует отдельное готовое окружение.

1. Для архивной панели разместить `graph_memory_round15/test_receipts` рядом с другими сериями и предоставить публичный HF snapshot под `D:/CodexResearch/x20-official-vibe/VibeMemBench`. `python -B observe.py` сначала сверяет SHA-256 панели, каждой использованной траектории и замораживает решения. `python -B score.py` присоединяет итоговые строки последующих тестов. Прогноз каждой пары содержит ID обеих квитанций, номера шагов, хеш команды, адреса возможных изменений, хеш и класс каждого промежуточного действия. Содержимое всех 35 пар доступно в [архиве свидетельств](paired-evidence.gz). Исходные команды не исполняются.
2. Клонировать [официальный more-itertools](https://github.com/more-itertools/more-itertools) в `D:/CodexResearch/x20-round17-test-history` с тегами от v10.6.0 до v10.8.0. `python -B rollback.py prepare` формирует фиксированный состав когорт по коммитам и синтаксическим различиям, `python -B rollback.py` запускает изолированные процессы unittest. Проверяем Git-хеши содержимого, исходный AST и все 47 исходов после отката. Нативные stdout, причины падения и карта вызванных функций находятся в [базовых запусках](rollback-child.gz) и [запусках с изменённым модулем](rollback-runs.gz). Коммиты, SHA-256 файлов и точные тестовые идентификаторы перечислены в [реестре](rollback-roster.json). Для Windows при архивировании явно задать core.autocrlf=false. Первый остановленный запуск обнаружил преобразование LF в CRLF сверкой до исполнения тестов. [Журнал исправления окружения](checkout-recovery.json)
3. Для дополнительной панели `python -B testmon_comparison.py` обращается к `D:/CodexResearch/x20-validity-releases/testmon-env/Scripts/python.exe`. Установлены Python 3.12.13, pytest 8.4.2, pytest-testmon 2.3.0 и coverage 7.10.7. Корень экспериментального checkout создаётся заново, авторские плагины pytest подгружаются явно. В [прогреве](testmon-warm.gz) и [повторных запусках](testmon-runs.gz) сохранены журнал процесса, машинная запись фаз для каждого реально исполненного nodeid и XML JUnit. В пустом контроле исходный статус хука pytest_sessionfinish и окончательный статус процесса могут равняться 5 и 0 соответственно. Программа принимает такую комбинацию только при пустом списке исполненных тестов и записывает оба значения. [Журнал калибровки](testmon-calibration-recovery.json)

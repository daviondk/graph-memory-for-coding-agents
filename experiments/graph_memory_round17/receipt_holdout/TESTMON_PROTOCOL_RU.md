# Дополнительный контроль оригинальным pytest-testmon

Основная серия 47 методов на пяти заранее выбранных коммитах уже оценена. До запуска дополнительного контроля фиксируем те же 47 nodeid и те же пары версий, оригинальную реализацию pytest-testmon 2.3.0 в имеющейся среде Python 3.12.13, pytest 8.4.2, coverage 7.10.7. Под pytest той же версии и на том же исходном запуске дополнительно регистрируем динамический граф использованных верхнеуровневых функций или классов. Прогрев выполняется в новом каталоге каждого коммита со всеми избранными nodeid и пустой базой .testmondata. Явные nodeid требуют --testmon-forceselect. Контроль без изменений ожидаемо выбирает пустое множество. После замены байтов того же производственного модуля выполняем нативный выбор. Отдельный процесс pytest без testmon запускает все зафиксированные тесты на этой же изменённой рабочей копии. Полный повтор выполняем дважды, исходный pytest и одно полное повторение также подтверждают стартовые исходы. Сохраняем фактически исполненные nodeid, причины ошибок, вывод процесса, размер базы, стеновое время каждой фазы и дополнительно машинные метки исходов. Дубли инструментированы для наблюдения, очередность методов задаётся прежней когортой. Любое расхождение среды с первым запуском на Python 3.14 раскрываем. Выбор методов не зависит от результата testmon. [Документация pytest-testmon](https://www.testmon.org/) · [Первичная серия](ROLLBACK_PROTOCOL_RU.md)

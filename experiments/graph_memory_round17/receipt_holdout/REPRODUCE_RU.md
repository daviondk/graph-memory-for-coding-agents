# Воспроизведение

Скрипт run_holdout.py вызывает исходные функции соседней [серии](../receipt_invalidation/REPRODUCE_RU.md). В папке сохранены точные копии порождающих скриптов и исходных протоколов. Границы коммитов и расположение временного хранилища задаёт [новый протокол](PROTOCOL_RU.md). Запуск для Windows из копии папки в той же структуре work:

```text
python -B run_holdout.py prepare
python -B prune_uncollected.py
python -B run_holdout.py reference
python -B run_holdout.py native
python -B action_adapter.py
python -B verify_holdout.py
```

Реестр до проверки доступности методов сохранён отдельно. Один из 82 первоначально выбранных методов относится к примеси класса без собственного nodeid, что выяснилось при загрузке unittest в первом прогоне. Поштучное сопоставление всех адресов с исходным pytest --collect-only во всех восьми коммитах выполнено до оценки изменённой версии. Исключение без замены зафиксировано в [аудите коллектора](collection-audit.json). Один собранный тест был помечен авторским скипом. Граф функции выдаёт пригодную к повтору квитанцию только после действительно прошедшего теста. Адаптер регистрации сохраняет все реальные статусы и отправляет случай без положительной квитанции на повторную проверку отдельно от основного знаменателя. Никакая метка после отката в данное правило не входит. Для интервала по восьми коммитам используются эквивалентные точные мультиномиальные веса вместо хранения всех 8⁸ перестановок.

# Как граф ранее исполненных функций влияет на реальный выбор одного теста

Проверяем перенос с решения о пригодности старого pass на следующее действие работающего агента. Используем все заранее определённые пять и восемь коммитов more-itertools из двух экспериментов, без отбора по исходам тестов. Результаты предыдущей оценки известны исследователю. До нового запуска Qwen фиксируются условия и выборка, индивидуальный исход в запрос модели не попадает. В пределах коммита модель получает имена изменённых верхнеуровневых функций, один общий модуль и точные nodeid ранее прошедших тестов. Требуется выбрать и реально запустить ровно один тест на изменённом коде. Исход «обнаружен провал» означает воспроизводимый провал в JUnit, ограничение одного теста одинаково для всех политик.

Три способа выдачи памяти. Контроль показывает только идентификаторы. Основной вариант добавляет наблюдавшийся ранее набор вызывавшихся функций для каждого теста. Пространственный отрицательный контроль циклически переносит эти же наборы между тестами при неизменном порядке тестов, сохраняя набор показанных функций и записей. Наборы сдвигаются на один элемент после сортировки по фиксированному хешу. Идентичные модельные запросы можно разделить между условиями. Отдельные детерминированные политики выбирают по совпадению имён теста с именами изменившихся функций или сначала по фактическому пересечению изменённых и наблюдавшихся функций, затем по тому же текстовому правилу. При равенстве выбирается первая запись в зафиксированном порядке. Всем политикам исполняется выбранный pytest. Один и тот же участок можно исполнить многократно для оценки стабильности. После записи решений отдельно сверяем с ранее сохранёнными полными прогонами.

Решатель — локальный Qwen3.8-27B UD-Q4_K_M на RTX 3090, greedy, фиксированный seed, нативный вызов одного инструмента, максимум 96 выходных токенов. При отсутствии корректного вызова результат нулевой. Основной парный исход — обнаружение провала, граф против одних имён. Перестановка — контроль информативности правильных связей. Дополнительно показываем сравнение с программным выбором, расхождения решений, потолок при одном тесте на коммит и токены. Доля падений в этом опыте получена на целевых контролируемых откатах. Это повторное использование панели, ограниченная модель и один проект. Сквозное исправление задач не измеряется.

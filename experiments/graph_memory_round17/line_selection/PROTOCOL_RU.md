# Какие строки просмотренного файла стоит вернуть в контекст

Гипотеза. При одинаковых источниках и лимите в 60 строк явная связь между именем функции из описания задачи и строками её тела позволит вернуть больше размеченного кода, чем поиск совпадающих слов по видимому фрагменту. Рассматриваем только сведения, которые к моменту выбора действительно показал редактор. Индекс всего проекта отсутствует.

Предварительно фиксируем два набора. Исследовательский набор состоит из 199 задач и их первых трёх чтений R11, с заранее известным результатом про приоритет первого файла из R15. Проверочный набор — все задачи независимой когорты R16/anchor_transfer, до трёх прочитанных фрагментов на каждую из двух версий агента. Его индивидуальные исходы при построении политик не используются. Пустые наблюдения остаются в знаменателе. Разметку и статусы завершения задачи считывает отдельная программа после фиксации прогнозов. Текстом запроса служит только исходный problem_statement из SWE-bench Verified. Для каждого наблюдения отмечаем архивное происхождение. Допускаются только совпадающие с исходной ревизией наблюдения, если таковые отдельно проверялись при подготовке панели.

Контроли. Первый или последний прочитанный файл получает приоритет, строки выдаются в порядке их номеров. Ещё один контроль резервирует половину бюджета за первым файлом и половину за последним. Разницу между политикой на графе и текстовым поиском измеряем при одинаковом наборе кандидатов и одинаковом правиле расходования бюджета. Оба сохраняют до 24 первых видимых строк первого файла. Оставшиеся строки разбиваются по файлу и непрерывному диапазону на непересекающиеся блоки длиной до 12. Текстовый вариант ранжирует блоки по сумме локальных IDF слов запроса, встретившихся в блоке. Графовый вариант добавляет те же веса совпавших с запросом имён лексически охватывающих функций и классов. Связь строим исключительно по видимому заголовку и отступу, пропуск в нумерации закрывает текущую область. При одинаковой оценке ранее открытый файл и меньший номер строки имеют приоритет. Вспомогательная абляция снимает резерв первых 24 строк у обоих ранжировщиков. Все варианты возвращают одинаковое число доступных строк до лимита 60. Запрещены обращения к новым файлам или восстановление невидимых строк. Это ограниченная аппроксимация структуры Python.

Первичный исход — макроусреднённая доля полезных строк (нативная precision SWE-Explore). Главный парный контраст на независимых задачах — графовый вариант минус текстовый при резерве 24. Два исполнителя на одной задаче сначала усредняются, для 95% интервала ресемплируем задачи 5 000 раз с seed 1731. Отдельно приводим исходы по моделям, число изменившихся выдач, эффективное покрытие, recall и F1, диагностику относительно первого файла. Проверка изолирует выбор памяти после чтения, без причинного вывода о качестве исправления. Условная метрика на непустых префиксах диагностическая. Положительный основной контраст, который проигрывает простому контролю, не свидетельствует об общем выигрыше.

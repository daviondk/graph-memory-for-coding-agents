# Какой фрагмент реально откроет агент, получив 60 строк памяти

Исследуем действие кодового агента в пределах ранее показанных 60 строк по условию реального issue. Используем закреплённую независимую панель R16 из 54 задач без пересечения с исторической панелью, два источника, три прежних просмотра. Сравниваем уже вычисленные варианты R17 lexical24, scope24 и recent. Политики определяют только содержание памяти. Подавать историю решения или метки в запрос запрещено. Полученный вывод модели измеряет выбор места чтения внутри уже составленного меню.

Отбор до новых ответов модели. Все три меню должны содержать по 60 найденных ранее строк. Включаем только задачи, где хотя бы одно меню отличается после канонической сортировки путей/строк. Основной контраст — scope24 против lexical24. Для задач с доступным префиксом, где эти два меню расходятся, приоритет отдаём такому префиксу, затем сортируем источники по SHA от идентификаторов. Из числа этих задач по постоянному хешу берём до 12, пополняем до 24 задачами, на которых различается хотя бы одно меню. Если во втором слое не хватает задач, заполняем остаток из первого. Для каждой задачи фиксируем только один источник. Отдельно выводим охват по всем 54 задачам, число возможных и фактических различий по политикам. Вывод относится к выбранной условной панели.

По каждому меню разбиваем каждый непрерывный диапазон видимых строк в порядке номеров на непересекающиеся отрезки до 12 строк, без внешнего дополнения. В общей для всех условий инструкции предлагаем Qwen3.8-27B UD-Q4_K_M выбрать одно действие read_span — открыть уже показанный участок, где полезнее всего исследовать причину запроса и возможное изменение. Содержимое каждого блока показано полностью, включая имя файла и номера строк. Порядок файлов и блоков задаётся координатами, имена вариантов и ранги исключены. Проверяем, что payload побайтно идентичен при одинаковых меню, переиспользуем единственный нативный ответ для дубликатов. Декодирование greedy, один seed. Одно фактическое чтение строк из исходного blob на каждый заявленный выбор. Для сравнения применяем статический локальный выбор блока по сумме IDF токенов, встречающихся и в issue, и в тексте или имени файла, рассчитанной на блоках данного меню. При равенстве выбираем первый блок в том же порядке. Эта политика имеет доступ к точно тем же номерам и текстам, требует ноль токенов генерации и даёт отдельно исполняемое действие.

Основной исход — пересечение фактически открытого фрагмента с удалёнными или заменёнными строками на старой стороне авторского gold patch. Долю считаем условно на задачах с хотя бы одной такой Python-строкой и отдельно на всей выбранной панели. Чистые вставки отмечаем отдельно, не задавая им вымышленной старой строки. Публикуем число задач, где исходная память вообще позволяла найти эти строки, потери при выдаче 60 строк и при выборе одной команды. Абсолютный охват среди всех 54 даём как долю подтверждённых действий нашего протокола на его полном исходном потоке, с отдельной пометкой для невыбранных. Эти задачи не были прогнаны через модель. Дополнительные результаты — нативные SWE-Explore precision, recall и F1 по реально открытым строкам, размеры меню, токены и длительность. При парном сравнении долей выводим число выигрышей и потерь и двусторонний точный тест знаков. Обобщение на выполнение задачи требует отдельного полноценного запуска.

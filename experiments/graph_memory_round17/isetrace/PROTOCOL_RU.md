# Упаковка доказательств исполнения в память агента под лимитом токенов

Цель — проверить, улучшает ли заполнение остатка контекста качество извлечения полного комплекта опорных фрагментов. Исходные материалы — закреплённый v7 корпус с 6 597 запросами, его таблица происхождения и первый полный JSONL-шард ISETrace. Из файла запросов берём первый последовательный префикс до появления 1 201-й уникальной траектории по авторской metadata. Официальный алгоритм выделяет первые 1 207 уникальных корректно сопоставленных траекторий в тест. Уменьшение этого множества после удаления некорректных соответствий не исключает корректный ранний запрос при подтверждённом исходном ID. Глобальная проверка уникальности технических соответствий через все восемь шардов в этом ограниченном анализе отсутствует. 

Берём до 64 траекторий из пересечения ранних ID с trajectories-00000 по порядку SHA-256 строки `r17-fit/{trajectory_id}`, все их допустимые запросы в данном префиксе. Разрешаем общие вычислительные, документные и деловые задачи. Фильтр безопасности по тексту исходных намерений и запросу исключает военные, опасные, биологические и наступательные киберсценарии, исходные команды остаются данными. Сообщаем число исключённых и ошибки источника. Оценки не участвуют в выборе. Проверяем точные аргументы, ответы инструментов, исходный ID и уникальность каждого поддерживающего источника по авторскому адаптеру. Невозможность спроецировать конкретный запрос регистрируем как техническое исключение и не подбираем замену после просмотра исходов.

Для каждой траектории строим авторские плоские фрагменты и provenance units из всей реально сохранённой истории, закреплённый E5 tokenizer, 512/8/64 для max/reserved/overlap. Одинаковый авторский BM25 ранжирует обе коллекции. Варианты для каждого представления (1) исходный авторский непрерывный префикс до первого переполнения, (2) пройти тот же список до конца, пропуская каждую не помещающуюся целую запись, (3) заполнить остаток после первого переполнения по убыванию BM25-score / sqrt(числа токенов). Для provenance дополнительно (4) после того же префикса сначала рассмотреть в исходном порядке фрагменты противоположной роли аргумент/ответ, принадлежащие к одному инструментальному вызову с любым уже включённым фрагментом, затем прочие в исходном порядке. При отсутствии подтверждённого общего вызова связь не предполагается. Сопоставление (4) и (2) изолирует добавку структуры при том же способе упаковки и наборе кандидатов. Топология определяется до просмотра эталона. Файлы запросов используются для точной связи целевой разметки с сырыми событиями при оценивании.

Первичный исход — **Full Support при 2 048** по неизменённому авторскому scorer на выбранных узлах. Предварительно заданные парные контрасты — provenance (2) против (1) и (4) против (2). Дополнительно сообщаем Full Support при 512 и 1 024, coverage, density, f1, число реально выбранных узлов, расход официального бюджета и размер вытесненного/использованного остатка. Покрытие является монотонным по добавлению узлов при сохранении префикса; независимая ценность правила измеряется числом переведённых в full support запросов, ценой токенов и падением либо ростом density. Кластерный bootstrap по траектории (10 000 повторов, seed 13, макросреднее по запросам), описательное представление вторичных метрик. Результаты на выбранном шарде касаются извлечения памяти отдельных действий. Полноценное сравнение с обученными системами, пятью seeds или итоговой успешностью решателя требует другого дизайна.

# Контроль частичного чтения на известной панели

После получения результатов BM25 проверяем дополнительное объяснение. Простой пропуск первого не помещающегося узла может выигрывать потому, что получает ещё до нескольких сотен токенов по сравнению со штатным префиксом. Контроль сохраняет тот же штатный префикс и выдаёт ровно первые r WordPiece-токенов первого не помещающегося узла, где r — свободный объём. Полную границу символов проецируем по исходному полю целого вызова/ответа, используя тот же закреплённый токенизатор и исходное окно, включая перекрытие. Пустой остаток ничего не добавляет. Выборку, ранжировки и исходные бюджеты обеих панелей сохраняем. Правило реализуется без знания целевых меток. Прогнозы этого контроля фиксируем до расчёта его исходов. Поскольку прежние исходы тех же задач уже известны, результат носит дополнительный характер.

Главный контраст — полная поддержка при 2 048 токенах для целочисленного пропуска против частичной выдачи узла. Для каждой панели сохраняем выигрыши, потери, расходы и траекторные интервалы. Повторяем сравнение с нормировкой по √стоимости и с приоритетом другого источника того же вызова. Анализ проводится на целиком определённом provenance-представлении, у которого отрезок кандидата относится к одному исходному полю. На дополнительной CPU-E5 панели в точности то же правило применяется, как только будут готовы ранжировки.

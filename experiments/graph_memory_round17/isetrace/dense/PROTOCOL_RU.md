# Контроль с предобученным intfloat/e5-base-v2

До получения dense-ранжирований фиксируем по восемь успешно сопоставленных траекторий каждого из двух шардов. Сортировка по SHA-256 строки `r17-e5/{trajectory_id}`, все запросы из исходной панели для выбранной траектории. Одинаковая память состоит из аргументов и результатов вызовов, полученных исходным авторским графом. Проверяем точное совпадение множеств candidate IDs с сохранённой BM25 панелью. Берём закреплённую весовую ревизию E5 авторов, Sentence Transformers 2.7.0, нормированные векторы, авторские префиксы query/passsage, batch_size 64 и авторский DenseTaskRetriever. Выполнение на CPU в float32. Кэшируются только тождественные строки одного и того же энкодера. Повторный запуск на случайной подвыборке или изменения параметров по итоговым меткам не предусмотрены.

Для каждого ранжирования четыре неизменённых правила проходят сравнение при 512, 1 024 и 2 048 токенах. Главная метрика — авторский Full Support@2048. Показываем те же показатели BM25 на точно тех же ID, расходы фактических токенов согласно авторской функции учёта, противоречащие случаи и ограничения малой панели. Для вероятного переноса эффекта, полученного на BM25, нужны подтверждённые улучшения по сравнению со штатным префиксом dense; преимущество топологии проверяется дополнительно относительно нормировки BM25 или dense по sqrt стоимости.

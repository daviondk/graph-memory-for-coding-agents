# Перенос на три ранее не размеченные для этого опыта пары Loguru

Список пар и содержание изменений просмотрены до отбора, опубликованные ground truth и предсказания для Loguru не открывались. Заранее выбираем три разных базовых дерева, меняющие только один Python-файл библиотеки: 76355dd9 (parse), 80f05fd2 и 3ace6db5 (формат даты). Это целевой выбор известных постановок трёх задач. Выборка отличается по проекту и по коммитам от изученной группы matplotlib. Исходная единица NameRTS — целый файл тестов. Сравниваем множества файлов на одинаковой панели стандартных тестов форматирования, представления объектов, настройки и разбора, заданной в коде до проведения нового эксперимента. Среди файлов целенаправленно есть test_parse и test_datetime. Публикуем полный знаменатель родного набора по данным авторов, ограничение нашего исполняемого поднабора и отдельно консервативную подстановку «выполнить любой непроверенный файл».

Для каждой пары запускаем каждый файл в отдельном процессе pytest на **true_parent**, сохраняем наблюдение имени функции и номера реально исполнявшихся строк в изменённом Python-файле. Процесс начинает наблюдать до импорта pytest. Трасса содержит только координаты в исходном коде общих программных функций библиотеки, включая контекст загрузки. Ошибки подготовки окружения и пустая коллекция исключают положительное утверждение о пройденных тестах. Для таких файлов консервативно назначается повторный запуск, они учитываются отдельно. Сопоставляем методы: повторять все тесты с историческим наблюдением модуля; выбирать по исполнению изменённой функции; выбирать по исполнению старой удалённой/заменённой строки с консервативным переходом на окружающую функцию, когда hunk содержит только вставки. Если изменён код вне функции или возникает новое имя без подходящего старого владельца, консервативно выбираем затронутый модуль. Все прогнозы замораживаются до открытия индивидуальных авторских меток Loguru. Считаем количество выбрано/пропущено, false negatives, файлы с официальной меткой и исход каждого тёплого запуска. Единица официальной истины — исполненная зависимость, с ручным учётом использования инициализированного состояния. Падение теста на новой версии этим источником не устанавливается. Дополнительный механизм файлового контроля — официальный NameRTS, EkstaP и BabelRTS из авторских предсказаний. Отдельно оговариваем, что наши исходные наблюдения собираются на настоящих запусках, а чужие результаты читаются из первичного исходного пакета.

Эта проверка диагностирует пользу сохранения уже наблюдавшегося исполнения при следующем изменении. Она использует стандартные зависимости «тест–функция/строка» и не воспроизводит весь алгоритм NameRTS или граф связей имён R17/Colorama.

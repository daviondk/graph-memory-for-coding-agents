# Опровержение универсальной применимости памяти о вызовах функций

Сигнатуру Python-функции можно прочитать без исполнения её тела. Проверили это на реальном коммите more-itertools, изменившем сигнатуру и поведение distinct_derangements. На шести специально заданных тестах граф обычных вызовов нашёл **1 из 4** фактических падений после отката. При добавлении наблюдавшейся во время исходного теста связи между вызовом inspect.signature и переданным в него объектом найдены **3 из 4**. Оригинальный pytest-testmon 2.3.1 нашёл **1 из 4** на этой специально сконструированной панели. [Результаты по каждому nodeid](results.json) · [Предварительный протокол](PROTOCOL_RU.md)

| Что проверяет тест | Полный повтор после отката | Граф вызовов выбрал | Граф с inspect.signature выбрал | Testmon выбрал |
|---|---|---:|---:|---:|
| Вызов функции с новым ключевым аргументом | fail | да | да | да |
| Прямой вызов inspect.signature | fail | нет | да | нет |
| Вызов inspect.signature через вспомогательную функцию | fail | нет | да | нет |
| Чтение __defaults__ без вызова функции | fail | нет | нет | нет |
| Другой алгоритм из того же модуля | pass | нет | нет | да |
| Другой модуль | pass | нет | нет | нет |

Сначала все шесть методов действительно прошли на исходном коде с новой сигнатурой. Контроль testmon без обновления не выбрал ни одного теста. При том же списке тестов откатили только производственный модуль к родительской версии и физически исполнили полный набор, оба графовых отбора и штатный CLI. Выбор графа зафиксирован до получения меток изменённой версии. Новое ребро было получено в момент работы Python по объекту callable, переданному в inspect.signature. Такое ребро сохранило идентичность целевой функции при косвенном вызове. Прямое чтение __defaults__ не породило события входа в inspect.signature, поэтому узкое правило также потеряло этот сигнал. [Наблюдавшиеся связи](sealed-edges.json) · [Код тестов](contracts.py) · [Журналы, XML JUnit и действия](runs.gz)

Это диагностический эксперимент с намеренно выбранными различимыми случаями. Он даёт исполняемый контрпример к универсальной безопасности графа вызовов и очерчивает ожидаемый механизм расширения. Частота инспекции сигнатуры в практических задачах, затраты наблюдателя и перенос на естественные тесты остаются неизвестными. Для повторения запустить python -B control.py при наличии основной папки receipt_invalidation, указанной локальной среды pytest-testmon 2.3.1 и закреплённого репозитория.

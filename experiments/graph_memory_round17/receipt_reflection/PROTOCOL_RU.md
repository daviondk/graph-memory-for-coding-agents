# Граница графа вызовов при изменении сигнатуры

Выборочно исследуем механизм, найденный в основном сравнении. Авторский коммит more-itertools 0d745055 добавляет аргумент by_index существующей функции distinct_derangements и меняет её тело. Зафиксируем новый набор из шести специально сконструированных программных тестов поверх этих реальных двух версий. Тесты проверяют вызов с keyword, прямой и косвенный inspect.signature, чтение __defaults__ и два посторонних рабочих вызова. Предполагаем, что тест может перестать проходить даже при отсутствии исполнения тела целевой функции. Граф из call events сравним с тем же графом, дополненным парой (цель, операция) для вызова inspect.signature. Наблюдатель берёт уже переданный inspect.signature объект из Python-frame и идентифицирует его модуль и qualname в наблюдаемом checkout. Чтение __defaults__ без вызова signature оставляем явным контрпримером к узкому расширению. Все тесты сначала действительно исполняются после коммита. При неизменных тестах откатываем только производственный модуль, запускаем весь набор и отдельно реальные политики выбора. Сравниваем официальный CLI pytest-testmon 2.3.1. Это контролируемые примеры семантики, не выборка популяционной частоты. [Авторский diff](https://github.com/more-itertools/more-itertools/commit/0d74505531b3b10279f8e18572ba6857b2748936)

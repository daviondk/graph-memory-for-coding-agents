# Зависимости, которые возникают до первого теста

Контролируемый механизм. После положительного теста агент хранит только связи с вызванными в этом тесте функциями. При новом запуске Python импорт модуля выполняется заново. Изменение тела функции, которая вычисляла значение во время импорта, может изменить результат теста, хотя сам тест её больше не вызывает. Эксперимент использует маленький специально написанный модуль, чтобы механизм был проверяемым и не зависел от чужой разметки.

Девять независимых запусков сравнивают исходную версию с одной заменой возвращаемого числа в одной функции. Паттерны включают прямой вызов во время теста, глобальное значение, последовательное присваивание, вложенный словарь, аргумент по умолчанию, атрибут класса, регистрацию побочного эффекта, динамический доступ к globals и неиспользуемое вычисление. Десятый тест постоянно возвращает прежнее значение без зависимостей. Гипотеза — учёт зависимостей, наблюдавшихся во время загрузки модуля, снизит число ложных переносов прошлых pass при сопоставимом с полным сбросом обнаружении реальных провалов. Обобщение проверяется отдельно на настоящей истории библиотек.

Политики заранее фиксированы. Полный повтор запускает все тесты. Наивный граф повторяет тест при изменении функции, вызванной во время теста. Дополнительный контроль привязывает все вызовы при импорте ко всем тестам этого модуля, а при прямом изменении сохраняет обычный граф. Наш метод связывает наблюдавшиеся вызываемые при импорте функции с именем, которому присвоен результат, или с объявленной функцией/классом. Транзитивные присваивания добавляют связи имён. Тест получает исходные имена из исполнявшихся им функций. При наблюдавшихся во время импорта вызовах внутри отдельного выражения с потенциальным побочным эффектом консервативно сбрасываем весь модуль, а при непрозрачном чтении globals или locals повторяем использовавший его тест. Это специализированная политика для однопоточного Python с фиксированным окружением. Все её предсказания сохраняются до выполнения изменённых тестов.

Будем сравнивать долю устаревших положительных результатов среди пропущенных, число повторов и пропущенных фактических провалов. Истина — полный pytest по точным nodeid. Сильный контроль — прогрев и реальное исполнение штатного pytest-testmon 2.3.0 в той же версии Python/pytest, на той же копии и изменении. Убедимся, что при неизменённом исходнике контроль действительно использует кеш. Покажем отдельно нулевую цену ошибки на заранее построенном микронаборе и цену консервативного сброса. Метрики микронабора не являются оценкой частоты в реальных репозиториях.

# Воспроизведение наблюдения при импорте

Запуски выполнялись локально, в независимых дочерних процессах pytest 8.4.2 и Python 3.12.13. Для микронабора используйте experiment.py; он сохранит исходный граф, зафиксирует предсказания и затем исполнит изменения. Реальная проверка требует клона tartley/colorama на коммите 3de9f013df4b470069d03d250224062e8cf15c49 в D:/CodexResearch/x20-r17-real-bindings. Для неё выполните Python-скрипт colorama.py.experiment. Его расположение и расширение исключают конфликт имени со сторонней библиотекой. Scratch-путь нужен отдельный для каждого повторного запуска.

Исполнители cli_check.py и other_controls.py запускают штатные pytest-плагины в отдельных виртуальных окружениях. Их пути явно указаны в скриптах. costs.py выполняет пять пар чистого прогрева на неизменённом проекте. Чтобы независимо проверить сохранённую запись без новых запусков pytest, выполните verify.py. Эта программа сверяет зафиксированные прогнозы, имена фактически исполненных тестов, исходы трёх фаз pytest и JUnit XML от четырёх независимых установок. [Аудит первичных данных](verification.json) · [Оригинальный пакет testmon](https://pypi.org/project/pytest-testmon/) · [Mortadelo](https://pypi.org/project/pytest-mortadelo/)


Для дополнительного контроля без ручных экспортов запустить python -B auto_control.py. Скрипт создаёт новые временные рабочие копии, фиксирует исходный сбор, анонимные SHA и предсказания, затем запускает все три полных набора pytest и все непустые выбранные наборы. Потребуются тот же Git-клон Colorama и прежняя среда pytest. Для проверки сохранённых XML и контрольных сумм без повторных вызовов pytest выполнить python -B auto_verify.py.

# Что именно воспроизведено из постановки MIRIX

Мы запустили оригинальные текстовые игры ALFWorld; состав шести семейств unseen (24 / 18 / 31 / 23 / 21 / 17), размер test и максимум 50 ходов совпадают с приложением MIRIX‑2.0. Сохранены полные переходы среды и индикатор won. Наши 39 обучающих задач выбирались самостоятельно из train без просмотра теста. Исследуемые способы памяти видят одинаковые сборочные траектории. В нашей постановке открыто меню допустимых команд и заранее запрограммирована предметная манипуляция. Qwen планирует поиск, затем команды выполняет общий контроллер. Статья использует LLM-актора на каждом ходе. Равенство среды, размера обучения и горизонта сохраняет смысл величин, но не устраняет разницу возможностей акторов.

Проверен официальный GitHub-репозиторий Mirix-AI/MIRIX, main на ревизии 9077e4b229dd8f61c5703b431a97788c6b61acfb. В нём есть реализация процедурного агента, distillation и evolution, а также тесты. Поиск alfworld, webshop и reasoningbank по тексту этого checkout находит README и unit-тесты. Поиск в деревьях семи опубликованных веток, включая evals (19ca5e95d26ac4be304b82e578f43c1246d99a65), не нашёл одноимённых программ прогона. В просмотренных материалах не установлен комплект точных 39 тренировочных episode ID, неизменённого actor prompt и исходных procedural rollouts для таблицы 10. Это ограничение проведённой проверки. Публичный код самого метода доступен. [Исходники](https://github.com/Mirix-AI/MIRIX/tree/9077e4b229dd8f61c5703b431a97788c6b61acfb) · [Статья, §3.3 и таблица 10](https://arxiv.org/html/2611.12068v1).

Для строгого следующего сравнения собрать общий контейнер LLM-актора, вывести трассы обучения только на train, передать один и тот же набор MIRIX, AWM и новому методу, зафиксировать версии, все затраты на извлечение навыков, общий шаблон запроса и меню действий. Во время blind test заморозить межзадачную память, разрешить одинаковые внутрисессионные обновления, случайно чередовать методы, повторить с независимыми seed. Отдельно показать переходы успешно→неуспешно на тех же задачах, журналы случаев, ошибочные чтения и цену на решённую задачу. Выполненный исходный контроль Compact-Bench и pytest-testmon уже дают прямые сопоставления на соответствующих узких метриках.

# Selective validity of executable observations when a coding agent changes its checkout

Frozen before running or inspecting any probe outcome. This is a paired non-LLM benchmark of the exact observable return value/exception of small Python API commands. Checkpoint is a published package release. Previous observed commands may be reused if their old dependencies still hold. There is no claim of executing historical LLM agents or of measuring downstream task resolution. Python and dependencies stay fixed. Use standard pure-Python release wheels from PyPI, downloading by pinned SHA. Four libraries chosen by ease of deterministic observation rather than measured performance.

* packaging 22.0, 23.0, 23.1, 23.2, 24.0, 24.1, 24.2, 25.0. Observe version parsing/normalization, requirements, specifiers including invalid inputs and boundary fields.
* idna 2.10, 3.2, 3.4, 3.6, 3.7, 3.8, 3.9, 3.10. Observe Unicode host encoding/decoding and UTS46 variants for ASCII, IDNs, punctuation, emoji and codepoints from fixed ranges.
* wcwidth 0.1.9, 0.2.5, 0.2.6, 0.2.8, 0.2.10, 0.2.12, 0.2.13, 0.2.14. Observe codepoint and string widths on fixed sets of Unicode chars and combinations, including variation selectors and ZWJ. Environment UNICODE_VERSION=auto.
* more-itertools 7.2.0, 8.0.2, 8.12.0, 9.0.0, 9.1.0, 10.0.0, 10.3.0, 10.5.0. Observe finite outputs of common iterable utility calls over fixed integer/empty/duplicate/corner inputs. Treat API absence as an actual observed exception, with direct named attribute binding checked on reuse. Pin program and generated command roster before any execution. A release may be skipped only if wheel unavailable, no import or protocol invalidity, reporting the failure and adjacent actual transitions. Cover all 28 adjacent transitions, no selection by outcomes.

The candidate associates a cached answer with (1) whether its public binding resolves to the same target module+qualname, (2) fingerprints of functions/dependencies reached, (3) the execution footprint of its observed branches. Ignore locations when canonicalizing AST. For unexecuted branches under a previously reached function, mask the contents of that branch on both versions. Preserve all surrounding control conditions, insertions outside excluded branch interiors and old branch identity. Conservative fallback if the function layout cannot be interpreted. Include earlier observed module-level bindings relevant to old function code, including local data module accesses by name. This is not guaranteed safe under dynamic imports, external state, implicit C dependencies, or newly introduced code. Publish observed stale uses. Source-scoped variants should require only touched source modules to validate a memory; our offline implementation may preparse them for all methods, with cost disclosed.

Compare always replay / always reuse; direct API implementation file hash; all dynamically executed Python files; AST including full body of all reached scopes; AST of reached scopes plus their referenced top-level assignments; and the candidate with branch masking, bindings and referenced assignment guards. Attempt comparison with real pytest-testmon (not a reimplementation) on identical command IDs and release pairs. Commands assert determinism/serializability and do not compare output with gold on the callback path; the gold standard remains physical execution of each release. Record outcomes, exact version and selection, including plugin misses or technical failures. If plugin cannot discriminate changed versions, diagnose and display, not claim an equivalently configured state of the art. Use the unconstrained official package in a separate local CPU environment. All packages live on disk D.

Timing: compare instrumented and plain real observations on the same fixtures. Per-project and aggregate report total 1) avoided reruns, 2) stale reuses, 3) redundant reruns when unchanged, 4) missed-change fraction and precision of reuse, 5) cost of writing/checking provenance including cost versus cheap direct observations. Old and new command outputs never enter policy computation, except an observation's old dynamic dependency metadata. For each release transition freeze the policies/decisions before joining with the exact label. File/AST/branch results deterministic; log hash of roster, data inventory, versions and outputs. Pair all methods by the same inputs. The unit of external generalization is a repository, with many nested adjacent versions/commands; report raw project-level counts. No claim of 4 independent families of Unicode evolution or a p-value for thousands of dependent probes. Online reruns may coalesce duplicate actions; we count one verification per probe. This is an exploratory scientific record. No tuning after observing outcomes unless clearly separated as post hoc.

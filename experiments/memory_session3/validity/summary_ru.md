# Когда кодовый агент может доверять старому результату команды

**17 ноября 2026.** Проверили один тип памяти агента — сохранённый результат диагностической команды. На 28 переходах между настоящими версиями четырёх Python-библиотек проверка ранее выполненных ветвей и используемых привязок позволила взять из памяти 1 380 из 4 249 ответов (32,5%). При сравнении с реальным выполнением все 1 380 совпали. На трёх других проектах тот же код сохранил 378 из 1 428 ответов (26,5%). Там все 378 сохранила и более простая проверка функций. На исходных коротких вызовах накладные расходы превысили сэкономленное время. Серия выделяет перспективный объект для агентной памяти и показывает границы эффекта.

## Что именно измеряли

В памяти лежит предыдущий вход инструмента, наблюдаемый ответ и свидетельства о его происхождении. Следующая сессия открывает новую версию кода. Ей доступно имя и текущее разрешение публичной функции, а также затронутый в прошлый раз исходный код. Контрольная метка — совпали ли фактические ответы команды на двух версиях. Для исключения учитывались тип и сообщение, для итераторов — материализованный по фиксированным правилам вывод. Составные результаты канонизированы. Стоимость сравнения текущего публичного имени существенна для коротких функций.

В основной серии 607 входов × 8 выпущенных версий в пределах четырёх проектов дали 4 856 наблюдений. Во внешней серии 357 входов × 5 версий дали ещё 1 785. Каждое из 6 641 наблюдений физически получено дважды — с трассировкой и без неё, с одинаковым результатом. Всего 47 снимков кода, 7 проектов и 40 переходов между соседями в зафиксированных списках. В списках есть пропущенные промежуточные релизы. Зависимости, интерпретатор и параметры основной серии фиксированы. Исходники извлечены из опубликованных wheel, адреса, версии, даты загрузки и SHA-256 лежат в двух файлах sources.json. Сравнения выполнялись локально на Windows 10, AMD Ryzen 7 8700F, CPython 3.12.13. LLM и GPU в этой серии не участвовали.

Для прогноза каждой паре передавались старые линии/функции и текущая привязка публичного входа. Маска решений записывалась до объединения с реальными исходами. Модули программы трассировались после разрешения публичного имени, внутри выполнения команды. Аргументы пробы были одни и те же. Подмена глобальных данных, импорты, сохранённые отрицательные наблюдения, альтернативные реализации, внешняя среда и зависимые модули ограничивают область применимости. Конечное качество патча агента не измерялось.

## Соседние версии и реальные конкуренты

«Устарели» показывает, сколько повторно использованных ответов уже изменилось. «Лишние запуски» показывает число заново исполненных команд, чей результат сохранился. Единство измерения — команда с фиксированным входом на одной паре релизов. В основной серии 261 изменившийся и 3 988 стабильных результатов.

| Политика | Взято из памяти | Верно | Устарели | Лишние запуски |
|---|---:|---:|---:|---:|
| Всегда запускать | 0 | 0 | 0 | 3 988 |
| Всегда брать старый ответ | 4 249 | 3 988 | 261 | 0 |
| Хеш файла публичной реализации | 382 | 382 | 0 | 3 606 |
| Хеши выполненных файлов | 298 | 298 | 0 | 3 690 |
| Полные выполненные функции, AST | 1 876 | 1 875 | 1 | 2 113 |
| Те же функции с проверкой использованных глобальных привязок | 1 214 | 1 214 | 0 | 2 774 |
| Плюс исключение тел ранее непосещённых ветвей | **1 380** | **1 380** | **0** | **2 608** |
| pytest-testmon 2.3.0 с переимпортом пакета для каждой пробы | 0 | 0 | 0 | 3 988 |
| pytest-testmon 2.3.0, обычные общие импорты pytest | 563 | 497 | 66 | 3 491 |
| Предыдущий вариант с такой же проверкой публичного имени, добавлен после анализа | 502 | 497 | 5 | 3 491 |

Сигнатура каждой выполненной функции включает AST вместе с условиями ветвления. В последнем варианте тела прежде непосещённых ветвей скрываются при сравнении. Для прежних обращений к локальным глобальным именам код сравнивает определения и часть связанных импортов на обеих версиях. Подробные правила, включая глубину разрешения и fallback, в scope.py. Исходит из старого пути выполнения, поэтому возможны ошибки при появлении новых зависимостей. Например, каскады декораторов, динамическая диспетчеризация, внешние процессы, вызовы на C, чтение конфигурации и побочные эффекты импорта требуют отдельного покрытия.

Для каждого из 28 переходов создавалась независимая свежая база pytest-testmon. Версии pytest 8.4.2, coverage 7.10.7 и testmon 2.3.0. Каждый тест сохранял хеш вызова. Все фактически выполненные результаты плагина совпали с внешним эталоном. Положительный контроль на каждой из четырёх неизменённых версий пропустил весь набор. При искусственном полном переимпорте инструмента для каждого теста плагин повторно выбрал все команды. Поэтому для сравнения по существу использовали обычные общие импорты. Блоки и динамические зависимости уже применяются в самом testmon. [Описание алгоритма](https://www.testmon.org/blog/determining-affected-tests/) · [Проверенная версия плагина](https://pypi.org/project/pytest-testmon/2.3.0/)

Из 66 устаревших пропусков testmon 61 относится к появлению ранее отсутствовавших функций more-itertools. Наша постановка считает наблюдаемый раньше AttributeError полноценной записью памяти. Тест обрабатывает ожидаемые исключения и технически проходит в обоих случаях. Такой пропуск нельзя интерпретировать как 61 пропущенный регрессионный тест проекта. Дополнительная проверка доступности имени устраняет все 61 случая. Оставшиеся пять относятся к изменившимся ширинам символов wcwidth. Если ограничиться 3 173 парами, где обе версии вызова вернули значение, ветви и привязки сохранили 1 016 ответов без устаревших, а усиленный плагин — 324, из них 5 устарели.

Функции без проверок глобальных данных ошиблись на U+1160. В wcwidth 0.2.12 функция возвращала 1, в 0.2.13 вернула 0. История проекта фиксирует исправление ширины Hangul Jamo в этом релизе. Пример удачной экономии при маскировании — idna.encode("example.com") при смене 3.7 на 3.8 вернул те же байты. [Журнал wcwidth](https://pypi.org/project/wcwidth/0.2.13/)

## Где воспроизвёлся эффект

В таблице числа повторных использований, включая устаревшие у плагина. Число ошибок указано в скобках у плагина. У остальных трёх колонок на этих переходах ошибок не наблюдали.

| Проект | Все пары | Ответ изменился | Хеш файла | Функции + привязки | Ветви + привязки | pytest-testmon, общие импорты |
|---|---:|---:|---:|---:|---:|---:|
| packaging | 553 | 7 | 239 | 208 | 208 | 169 (0) |
| idna | 1 260 | 134 | 0 | 20 | 184 | 20 (0) |
| wcwidth | 378 | 19 | 54 | 56 | 57 | 189 (5) |
| more-itertools | 2 058 | 101 | 89 | 930 | 931 | 185 (61) |
| humanize, внешняя проверка | 972 | 6 | 162 | 378 | 378 | — |
| pathspec, внешняя проверка | 304 | 44 | 0 | 0 | 0 | — |
| tomli, внешняя проверка | 152 | 20 | 0 | 0 | 0 | — |

Внешние проекты выбраны после анализа первой серии. Политика, код прогноза и основной показатель были зафиксированы до сбора новых ответов. Из 166 дополнительных попаданий от маскирования ветвей в первой серии **164 приходятся на idna**. Во внешней серии ветви добавили ноль попаданий, в том числе в парсере TOML и gitignore. Выигрыш защитных проверок функций против хеширования файлов во внешней серии (+216) полностью приходится на humanize. Отдельно wcwidth показывает, что обычный testmon может пропускать больше правильных проверок, одновременно допуская больше устаревших наблюдений. Тысячи пар вложены в несколько проектов, поэтому биномиальный интервал или p-value с каждой строкой как независимой был бы необоснован. Категории публичных API и их количество подобраны вручную, внешняя валидность ограничена.

### Проверка более старой памяти

Для всех семи проектов рассмотрены также все прямые переходы через хотя бы один промежуточный снимок без обновления записи. Те же 6 641 фактических наблюдений дали 14 889 дополнительных сравнений. На них изменились 2 088 ответов. Хеш файла разрешил 74 использования, функции с проверкой привязок 743, маскирование ветвей 747. У последних двух политик ноль обнаруженных устаревших ответов. На трёх внешних проектах в этом режиме обе политики запустили повторно каждую команду. Умеренная экономия для короткой истории быстро исчезает при более старой памяти. Для пропуска на 2 позиции кандидат сохранил 439 из 4 713 ответов, на 7 позиций — 5 из 607. Число позиций в выбранном списке не задаёт календарную длительность. Эти контрасты переиспользуют те же версии и команды.

### Контрпример при изменении среды

При неизменном исходном коде поменяли документированную переменную UNICODE_VERSION и добавили независимую переменную-маркер. Четыре состояния среды, четыре библиотеки, 798 команд. Каждый результат реально получен с наблюдением чтений среды и без него. На 4 788 парах сравнений изменились 612 ответов. Все изменения произошли в специально выбранном положительном контроле wcwidth. Условия среды и выбор новых символов были записаны до прогона. [Режим выбора версии Unicode](https://pypi.org/project/wcwidth/0.2.13/)

| Правило | Взято из памяти | Устарели | Лишние запуски |
|---|---:|---:|---:|
| Код совпал | 4 788 | 612 | 0 |
| Проверить совпадение всех варьируемых переменных | 0 | 0 | 4 176 |
| Перечень известных переменных по пакету, добавлен после анализа | 3 604 | 0 | 572 |
| Проверять только имена переменных, прочитанные прежней командой | 3 640 | 0 | 536 |

Эффект тонкого отслеживания против простой справочной таблицы равен **36 дополнительным правильным использованиям**. Включение этого контроля резко меняет оценку добавленной ценности. В серии один вид реально меняющей выход настройки и одна нерелевантная переменная. Перехват использует Python os.environ и не охватывает потребителей в C или дочерних процессах. Сумма времени выполнения и разрешения вызовов была 15,35 с с перехватом и 15,47 с без него. Это единичные парные измерения на одном компьютере, численно меньшая стоимость совместима с шумом. Метрики смены среды считаются отдельно от смены выпуска программы.

## Сколько стоит память

По микросекундным и миллисекундным API-вызовам основной серии старая работа с трассировкой заняла 4,422 с против 2,784 с без неё (дополнительно 1,638 с). Формирование масок всех политик, общее для данного прототипа, заняло 4,367 с. Пропущенные повторные вызовы без разрешения имени экономили 0,378 с. Под этим способом учёта прототип потратил дополнительно **5,626 с**, на внешней серии **0,684 с**. В идеализированном расчёте на том же наборе затрат точка окупаемости — 4,35 мс на фактически пропущенный вызов в основной и 1,82 мс во внешней серии. Фактические затраты на трассировку дорогой команды могут расти с её сложностью. В расчёт не вошли все стадии полного агентного конвейера, в частности импорт для новой привязки, запись и передача памяти. Затраты всех политик считаются вместе и включают служебные операции. Результат не устанавливает порог окупаемости для будущей системы.

Для контекста, в работе Ekstazi авторы измеряли end-to-end время настоящих Java-тестов на 615 версиях 32 проектов и отдельно проверяли длительные тесты. Доли выбранных команд и числа в их таблицах имеют разные единицы. Ближайший артефакт для этой серии — открытая реализация pytest-testmon на тех же наших данных. Для сравнения агентных систем на их собственных бенчмарках нужны другие эксперименты. [Gligoric, Eloussi, Marinov, ISSTA 2015](https://users.ece.utexas.edu/~gligoric/papers/GligoricETAL15Ekstazi.pdf)

## Исследовательское решение

В качестве кандидата для полноценной агентной работы стоит проверить повторное использование **дорогих** фактов о выполнении с явным сроком действия. Для будущего сравнения разумно брать настоящие траектории кодовых агентов, фиксировать версию рабочей копии и фактическую смену зависимостей/настроек, одинаковую модель и один набор задач. Контроли — история действий агента с обычной повторной проверкой, дешёвый файловый/окруженческий ключ и готовый механизм выбора зависимых проверок. Главные выходы — доля решённых задач по скрытым тестам, полный wall time, расход токенов и доля действий, основанных на устаревшем факте. Уже полученные данные позволяют отодвинуть дорогое маскирование ветвей как самостоятельную тему до воспроизведения на других проектах. При планировании стоит отдельно выделить наблюдения об отсутствии функции и свидетельства, зависящие от изменяемой среды.

## Артефакты и воспроизводимость

- **PROTOCOL.md**, **PLUGIN_ADDENDUM.md**, **external_validation/PROTOCOL.md**, **age/PROTOCOL.md**, **environment/PROTOCOL.md** — постановка и время принятия решений. Постановки локально датированы и хешированы, публичной предварительной регистрации не было.
- **results.json**, **external_validation/results.json**, **age/results.json**, **environment/results.json** — итоговые счётчики. **economics.json** в двух каталогах — накладные расходы; **posthoc_baseline.json**, **environment/static_key_baseline.json** — сравнения, добавленные по итогам диагностики.
- **runs/**, **external_validation/runs/**, **environment/runs/** — действительные выводы и метаданные каждого вызова. **testmon/** и **testmon_normal/** — команды, вывод pytest, выбранные ID и хеши ответов для каждого перехода. **plugin-initialization-failure.log** фиксирует первоначальную ошибку загрузки плагина, запускались заново все пары.
- **decisions.csv**, **per_check.csv** и аналоги в подкаталогах — прогноз и проверяемые построчные метки. Файлы **observation_lock.json** и **prediction_lock.json** связывают наборы и скрипты с SHA-256. Для внешней серии и основной серии код принятия решений побайтно одинаков.
- **REPRODUCE.md** содержит команды повторения. **verify.py --with-wheels** проверяет локальные wheel, 6 641 пару plain/traced, все метки и числа в основных таблицах, включая 56 журналов переходов плагина и четыре случая без изменений. **environment/check.py** независимо пересчитывает проверку изменения среды.

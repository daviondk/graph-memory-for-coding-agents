# Reusing observed file reads within a coding-agent session
Frozen before evaluating any cache hits. The schema of the first astropy/12907 Claude trajectory was inspected to identify tool call IDs, native output and visible output; no benchmark results or candidate hit rates inspected. This exploratory offline replay compares policies on the same trajectories.

Universe: complete public SWE-bench Verified baselines submitted by the mini-SWE-agent authors for Claude Opus 4.6 and GPT-5.2-Codex (both mini v2.0.0) and the later public Gemini 3.5 Flash v2.4.2 submission. All available task IDs. Primary units are PR/issue IDs and model runs. Same issue appearing in multiple model runs is a shared unit and must be grouped. Include unsuccessful original sessions. No cross-task writes. Do not use patches, grader results, issue labels, model thought text, or future actions as input. Download using pinned Git and official S3 object keys/ETags, record SHA per source. The outcome is exact byte equality of reconstructed pre-execution response with later observed native output plus return code; it measures a proxy for tool execution avoided, not accuracy of model decisions or solved patches.

Memory object: previously observed plaintext file output, indexed only when agent queried it in this episode. Recognize simple cat file, head -n N file and sed -n 'A,Bp' file, with optional cd into a known directory. No shell execution by the benchmark replayer. Exclude expansion, redirects, mutations, query formats that cannot be statically resolved. Invalidate after opaque shell actions. Whitelisted simple non-mutating searches and file reads retain entries. Trusted explicit-path edits may invalidate those paths only; ambiguous edits flush whole cache. Treat parallel batch containing any possible write as ambiguous; never use examples within the same assistant batch, even when all reads. Missing/unpaired tool results must be logged and invalidate state. For writing bytes, require that complete native output was actually visible in the historical response. Successful durable observations only. Mark known EOF on complete cat or a successful read shorter than the requested finite range. File path canonicalized relative to /testbed unless working-directory evidence conflicts.

Primary contrast: range reconstruction with strict dependency invalidation versus canonical exact request (path+line interval) with the same invalidation and caps. Also compare literal-command exact, naive always-valid range, transcript-global coarse invalidation, no cache. Range can join adjacent previously seen rows. At equal payload budgets, a bounded LRU of the last 16 successful read records capped at 64 KiB serialized output per episode; keep each policy's identical record pool for fair comparisons. Extra sensitivity: caps 4/16 KiB and 64/256 KiB. Cache requests are predicted before opening current tool response; hash audit each prediction. Use all permitted requests denominator and all terminal calls, report correct/stale hits; unique tasks benefited/harmed, bytes of correct outputs, additional hits and PR-clustered bootstrap differences under the fixed highest-priority contrast. Separate cohorts by model. Distinguish simulation of saved external calls from time and tokens saved by a deployed agent. No assumptions that individual calls are independent. No unreported oracle future edits or source checkout index.

Prior art: TVCACHE already models environment state, using matching rollout histories for reuse across agent rollouts. sqz reports range containment in private Claude Code sessions and describes range-overlap measurement, so caching file ranges is not claimed novel. Our test compares causal-prefix reconstruction and invalidation policies on public, independent agent trajectories scored by later true byte outputs.

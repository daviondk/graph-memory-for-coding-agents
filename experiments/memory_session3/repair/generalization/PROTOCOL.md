# Replication with new property-based QuixBugs tests

This protocol was written before opening stored candidates, comparisons or grades for this extension. Use all 29 JSON programs previously marked eligible by the reference calibration. Target 16 unique deterministic generated inputs per program (less only if not attainable). Fixed seed from SHA-256 of "quix-property-v1" + program, reject duplicates of every public JSON argument tuple and parseable named doctest example in the public source, including keyword spelling when bindable. Compile inputs and independent oracles before inspecting corrected control, candidate code or aggregate model scores. Do not modify prior frozen fixtures or modules. Candidate arms and code reused byte-for-byte, no additional LLM calls.

One predeclared primary endpoint: all new valid cases for the program pass. Micro case accuracy and paired wins/losses by program are secondary. Report original buggy, published corrected and each frozen memory arm on the same inputs. Include end-to-end public-heldout and new contrast once new metrics are fixed. A failed reference marks an oracle/contract mismatch: retain logs, exclude entire affected program in primary, report sensitivity with exclusions, no generator edits after outcomes unless explicitly separate. Correct reference is only calibration and is not the expectation generator. When original satisfies every generated case flag test insensitivity; report sensitivity among programs actually detecting a known bug. Small n and same programs/models constrain claims.

Use public mathematical contracts and independent stdlib specifications. Known ambiguous outputs accept any optimal subsequence, any matching index, any legal minimal Hanoi solution, equivalent enumeration of subsets and combinations; verify exact multiplicities; for wrap construct words smaller than the width and accept any legal whole-word split preserving whitespace. Use exact independent stdlib sort/index/combinations/next-permutation enumeration, arithmetic/trial division/string search, brute force for small inputs. Restrict inputs to published preconditions. Generate several structured regimes incl duplicates, negatives, no-hit/early-hit, prefixes, combinatorial ties, carry, nested empty arrays, valid/invalid balanced parens. Use nonnegative GCD including one zero but never both; relative and absolute float tolerance only where specified. Freeze generator, oracle and complete argument roster by SHA-256 before grading.

Run corrected, original and candidate modules only in separate nonroot read-only network-disabled Docker processes with no host mounts. Within each job each case gets a new isolated Python child, cap memory and wall-time; execution child sees code and argument only. Preserve full observed values, timings, verdicts and content IDs, deduplicate identical programs per task. Confirm earlier output lock and image, wait for plans locked gate before WSL or any Docker command. Method comparison is on novel inputs from the same task contracts, not evaluation on new tasks, with possible QuixBugs training contamination and post-selection of experiment after previous round. No use of hidden expected responses from the LLM.

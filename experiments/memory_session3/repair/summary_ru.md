# Возобновление ремонта по сохранённым наблюдениям

Во время предыдущей части эпизода сценарий действительно выполнил тесты на ошибочном коде QuixBugs. После разрыва контекста локальный Qwen3.8-27B (GGUF UD-Q4_K_M, RTX 3090, llama.cpp b12441) видел тот же исходник и получал один из четырёх вариантов памяти. Проверялась способность исправить программу за один ответ при наличии сведений о прошлой работе. Это изолированный этап принятия решения. Полноценный многошаговый coding agent мог бы самостоятельно перезапускать тесты.

## Контроль и разделение данных

В официальном срезе было 31 задание на Python с JSON-парами вход/ожидаемый выход. Для каждого одинаковые входы объединены. Сортировка по SHA-256 канонического входа и чередование индексов разделили ранее выполненные примеры и будущую оценку. Две эталонные программы не уложились в заданный режим исполнения одного входа. У knapsack была ошибка MemoryError, у levenshtein — превышение времени 1,8 с. Обе исключены до запуска решателя. Осталось 29 программ и 105 отложенных тестовых входов. В 27 задачах предшественник видел хотя бы один сбой. В 28 задачах хотя бы один будущий тест обнаруживал исходный дефект. В 22 исходных модулях есть примеры doctest: некоторые закономерности модели уже знакомы. Публичный тестовый корпус даёт лишь ограниченную гарантию корректности.

Для пары «сбой и контроль» против двух последних наблюдений получились одна победа, два поражения и 26 совпадений. Разность −3,45 п.п., парный описательный 95% bootstrap по программам от −17,24 до +6,90 п.п. Против пустого журнала получились ноль побед и два поражения. Расходятся четыре задачи. Например, у wrap только пустая память прошла все отложенные входы, а у longest_common_subsequence прошли два последних наблюдения и полный журнал. Можно открыть каждое решение и точное отличие в grades и per_program.csv. Сложные и неоднозначные алгоритмы чувствительны к составу тестов; дополнительные, отдельно замороженные проверки записываются в generalization.

## Расходы и происхождение

116 назначений (29 × 4); 110 полных уникальных запросов к модели после устранения байтовых дубликатов, 44 485 входных и 14 043 выходных токена суммарно. По хешу результата получилось 50 разных исходников внутри задач. Ни одна из 110 генераций не закончилась по длине. Модель работала локально, temperature 0, seed 17112026, max_tokens 1536, одна независимая генерация за решение, внутренний режим размышлений отключён. Повторы одного и того же запроса не являются независимыми повторностями. Новые исходники исполнялись во временном Linux-контейнере, без сети, без прав root, в read-only окружении; эталоны недоступны исполняемому модулю.

Хеши до генерации — input_lock.json, solver_lock.json. Серверные ответы — calls. Привязка назначения к конкретному ответу — decisions.json. Отдельный оценщик стартовал после output_lock.json. Код, каждый исходник, конкретный вывод, ожидаемый ответ, исключение, таймаут и метрика по каждому случаю доступны в коллекции. Пересчёт исходных 29 задач и всех таблиц: python score.py из этой папки.

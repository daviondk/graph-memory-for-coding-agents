# Exact stored observations for interrupted repair — locally registered pilot

Frozen before cloning or inspecting the target programs/individual cases or generating model outputs. Use QuixBugs pinned 4257f44b0ff1181dedaedee6a447e133219fcebf, Python programs with released JSON input/output cases. Use all available such tasks, subject only to >=3 runnable distinct cases, verified reference-output controls and specified loader compatibility. Always enumerate exclusions. The other graph tasks have a different data interface. This is a small familiar algorithm-repair corpus, not SWE-bench. No number here is a SOTA claim.

One interrupted session has the buggy checkout and results of running about half of its public cases, as a fixed deterministic scripted predecessor (not a paid teacher). Split unique cases per task by SHA256 of canonical input, alternating in sorted hash order into prefix and later tests; do not select tasks by failure in the prefix. The future roll-out model receives the buggy function/module and a common repair instruction. It never sees an expected function implementation, future examples, their outcome or the program name as task metadata beyond its source. No target-specific actions after observing comparisons.

Four matched assignment arms, every solver/configuration sees a fresh context. Empty receives no executed observation. Recent gets up to two most recent prefix records. Witness keeps the shortest observed failure plus earliest passing control (if no failure keep shortest observations, if no pass fill with another failure). Full gets all initial records, within a shared upper bound of 6,000 characters. Recent and witness share a per-record cap, 450 characters, max 2 observations each, so one cannot simply add context. The record contains earlier call arguments, observed result/error/timeout, expected result and test verdict. Expected values are the assertions that the original agent actually ran. Deduplicate executable inputs BEFORE the split. Original source docstrings common to arms. Report any public example embedded in source. Exact duplicate prompts across arms may be cached by content+native settings and counted separately in isolated method costs.

Return a complete corrected module in a single bounded Qwen3.8-27B generation (temperature 0, same seed, max 1536 output tokens, native thinking off). Extract fenced Python deterministically or parse raw Python. Syntax error, timeout, malformed response = failure. Evaluate in separate read-only, offline child processes in a resource-bounded Linux container. Use the benchmark's conversion/comparator and a wall-clock deadline per case. Main endpoint is every held-out unique case passing, including abstentions/no-op; report the full public suite and proportion of held-out cases passed as sensitivities. Baselines: original buggy program, known corrected code calibration, Full, Recent, Empty. Pair by program, include W/L, descriptive exact sign and program cluster CI. Positive ground-truth runs may expose loader bugs; log any correction before model generation. Secondary: the subset with an observed failure in history and the subset with a held-out bug-triggering case measured from original code. No metric based only on text similarity. Store prompt and output, input/output tokens, all per-case statuses and rank/control manifest; report limited generalization, model contamination risk and lack of live iterative shell for this isolated handoff.

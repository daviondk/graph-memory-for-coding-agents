# Prospective ALFWorld feedback-only control

After a previous admissible-menu study, before evaluating this actor on test games, rerun all 134 frozen official valid_unseen text games with a limit of exactly 50 environment commands. The policy receives only initial user-visible text, then self-issued action and its visible textual feedback. Disable collection of admissible commands in the environment itself. Engine win and termination used externally only for scoring and stopping. No episode identity, predicate graph, expert hints, internal metadata, admissible list or previous study's priors enter policy. Use a common, explicitly task-specific deterministic grammar and goal controller; grammar debugging is permitted only on the frozen 39 training cases. This checks a stripped-down interface for the same memory intervention, not a model leaderboard submission. Previous benchmark observations available to study designers remain a limitation.

Reset text announces numbered potential locations; extract names from literal text. A successful move/open reports visible objects; record current inventory from explicit successful take/put feedback. A changed search phase releases exploration history. Shared operational state covers current location, previous feedback, held/delivered items, process stage. Compare no search memory, cursor (most recently searched location), full visited list, and full visited + training-derived raw location/target sighting frequencies. Use identical grammar and tie order across arms. Predeclare one scout policy exploring at most 50 steps in each of the same 39 train games via feedback-only actions. Use its observed rooms to count one sighting per object type per visited receptacle per game. No reused admissible-menu trajectories, training priors, object IDs from game filenames, or held-out feedback tuning. Cursor is a location string per search phase; none can still avoid issuing a go-to for its *current* location, as can all arms. Invalid actions/grammar violations/repeats consume the same budget. Use a stable deterministic tie order; no backoff experiments using unseen games.

Report successful tasks, family breakdown, attempted actions, budget-capped completion steps (failures charged 50), operationally rejected parser/physics actions, paired wins/losses and episode bootstrap intervals, level of per-episode search memory. Group non-independent room layouts for sensitivity if identifiers allow, using metadata only for post-hoc stratification. All actions and feedback logged, input and output hashes; an independent offline check replays policy from text incl inventory and recomputes results. Positive/negative results retained with 2 CPU worker maximum. No LLM generations. A menu-free policy can still exploit simulator language/room listing and task-type templates. Compare across interfaces descriptively since controller details differ.

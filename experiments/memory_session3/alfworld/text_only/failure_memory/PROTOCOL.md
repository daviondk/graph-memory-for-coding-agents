# Feedback-based memory for rejected transitions

The previous feedback-only valid_unseen test discovered repeated "Nothing happens." responses following travel between visible receptacles. This follow-up was designed after observing all valid_unseen scores and these failures. The 134-game valid_unseen arm is retrospective development evidence. Before consulting any feedback-only outcome on valid_seen, freeze this policy and exact roster for the separate 140-game prospectively held-out transfer. valid_seen is ALFWorld's held-out games in familiar layouts; here the split serves as a new evaluation set, does not imply unseen floor plans. Previous studies on other interfaces in this workspace may include these layouts. No tuning, retuning, prompt generation, use of admissible commands or learning from either split.

Freeze the parent text-only trained actor and its train-only raw sighting table. Keep ordinary search history, grammar, inventory, goal stages and ordering unchanged. Three arms: frozen trained actor; immediate fallback, which suppresses the last rejected travel destination on just the next decision from the same known pose; and storage of all rejected travel destinations since arriving at this pose. Only clean simulator feedback exactly "Nothing happens." following a self-issued "go to <destination>" can create a negative record. Both variants filter candidate destination strings already present in the visible initial room list. On a successful change of pose clear the set. Do not write model guesses, state predicates or game metadata. If all options are filtered, ordinary fallback is "look", charged as a step. Entry set capacity is bounded by the announced room inventory. The single-step arm includes ongoing operational memory of the unchanged actor; compare additional negative history only.

Primary completion endpoint per split at 50 paid environment actions, paired by episode. Secondary 10,20,30,40,50 completion, capped steps (failures charged 50), number of rejections/redraws, max stored negative transitions, per-family counts and action-level identity. Compute wins/losses/ties and paired bootstrap intervals for both rejection variants vs baseline and each other; resample games and, separately, layouts, report few clusters. Retain all episodes. Final state, terminal bit and budget available to external scorer only. The closed unseen baseline is reused from its raw physical receipts; run the other two arms independently in the native simulator. On valid_seen run all three arms, no simulating counterfactual actions from a recorded prefix. Up to four processes, no GPU/LLM. Keep code and data in this subdirectory and provide independent, self-contained replay verifier and SHA-256 seals. No further tuning on either split.

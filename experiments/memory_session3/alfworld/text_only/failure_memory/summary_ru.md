# Память об отвергнутых командах в текстовом ALFWorld

В предыдущем опыте агент освоил приоритеты поиска предметов по 39 тренировочным играм. При проверке только по тексту он десять раз не завершил задачу после повторов перехода с ответом «Nothing happens.». Мы проверили, достаточно ли один раз пропустить отвергнутую команду или полезно помнить все такие направления до смены позиции. Во всех условиях доступны те же обученные приоритеты, общий список осмотренных мест, грамматика команд, наблюдаемая позиция и инвентарь. Работа выполнялась локально в симуляторе на CPU. LLM не вызывалась.

Правило записи срабатывало только на точный ответ «Nothing happens.» вслед за собственной командой go to. Одношаговый вариант исключал это направление на следующем выборе. Вариант с набором исключал все отвергнутые назначения из этой позиции, а успешный переход очищал набор. С ценой в один шаг учитывались каждая отклонённая попытка и команда look при отсутствии доступного по правилу направления. Меню допустимых действий в TextWorld отключено. Системная отметка победы использована для внешней оценки и остановки, а действия восстанавливаются только по видимому тексту.

В 134 играх valid_unseen прежние результаты послужили основанием для гипотезы. Здесь её проверка ретроспективна. Вторая выборка valid_seen содержит 140 новых эпизодов из знакомых планировок. До просмотра результатов этого текстового теста заранее зафиксированы алгоритмы, частоты и идентификаторы обеих выборок. Предыдущие исследования этой рабочей группы на иных интерфейсах могли использовать те же миры. Все три условия физически запущены на valid_seen. Для valid_unseen повторно взяты 134 хешированных исходных траектории, остальные 268 разыграны заново. Всего получено 688 дополнительных физических разыгрываний, в трёхстороннем сравнении участвуют 822. [ALFWorld](https://arxiv.org/abs/2010.03768)

## Как интерпретировать

На заранее отложенных задачах одношаговая реакция на отказ увеличила число побед с 127 до 137 из 140. Набор отказов дал те же исходы и число действий в каждой игре. На выборке обнаружения все 134 цепочки команд двух способов обработки отказов полностью совпали. На внешней выборке в единственной расходящейся игре набор после двух отвергнутых переходов исследовал полку и действительно поднял CD, тогда как одношаговый вариант чередовал два недоступных направления. Оба варианта исчерпали бюджет. На внешней выборке суммарное число отвергнутых переходов снизилось с 64 до 25, при том же числе побед и средних затратах. Добавленная сложность полезна для устранения повторных неудачных действий, но её самостоятельное преимущество по решению задач в данной проверке отсутствует.

Различия между исходной политикой и одношаговым пропуском измеряют пользу реакции на отказ. Дополнительная ценность сохранения нескольких отрицательных фактов измеряется только сравнением с одношаговым правилом. Совпадение цепочек действий при различных внутренних правилах означает, что данное окружение не проявило соответствующее различие на этих эпизодах. Нулевая разность успехов при 50 шагах может сочетаться с разной стоимостью и успехом при меньшем бюджете.

Чтобы переносить вывод на память кодового агента, требуется проверка на его реальных повторных действиях (например, повторный запуск уже отклонённой команды с неизменившимися предпосылками), на конечном успехе и затратах при одинаковом бюджете. Здесь исходный механизм навигации и грамматика известны разработчику. Набор интерактивных ALFWorld-игр позволяет измерить поведение политики с объективным сигналом, но остаётся доменно-специфической моделью агентной работы.

## Проверка журнала

Команда `python verify.py --check` работает автономно в этом каталоге, без Docker или моделей. Она проверяет входные хеши, заново выбирает каждую команду каждой политики из текстов, сверяет флаги и пересчитывает метрики. Файлы results.json, per_episode.csv, divergences.json содержат показатели, построчные результаты и первые различия между двумя вариантами памяти при их наличии. Подробности физического повтора — в REPRODUCE.md.

# Frozen extension before inspecting any held-out trajectory or outcome
Research question: given a capable model's prior about where objects are stored, can selected positive and negative search experiences improve a real new episode? Same official 134 evaluation games, fixed actor for all low-level manipulation and within-episode full search coverage, identical goal parser, 50 commands. Only the candidate ordering changes. Use native local Qwen3.8-27B Q4_K_M, deterministic seed 17112026, temperature zero, 256 output tokens max, reasoning off, at most one planning call per unique public (target class, available location classes, memory text). Some tasks require both pickup and lamp search; command budget unchanged, record number and cost of calls separately. Anonymous facts: for each available location class give training 'trials' and 'present', from the 39 fixed training exploration logs. Do not reselect data or thresholds by unseen rewards.
Four paired arms: q_prior uses model's ordered list and empty evidence. q_shown lets same model see all target-specific exposures and sightings. q_placebo presents a same-format set of counts from a predetermined different training object type (hash selects donor before answering); zero-denominator entries retained. q_fused reuses the identical q_prior output and adjusts class ordering with a fixed beta-style estimate (hits + 8/(rank+1))/(examined+8), zero-based rank, with inter-instance exploration penalty (rank only between location classes with same instance index for the common round-robin Q arms). Confirmatory contrast q_shown vs q_prior on capped 50-step burden and success, q_shown vs placebo and q_fused vs prior exploratory. Four floorplans: report explicit floorplan gains as well as paired raw outcomes. Optimistic uncertainty from treating 134 tasks as independent must be labeled. Report differences in actor, public command set, experience source, command budget, replanning and environment versus MIRIX. No change to earlier frozen policies. Use fresh environment, retain all native prompts/outputs and every state/action. Goal templates/train episodes can be used for infrastructure QA; no more policy tuning once this file is written.

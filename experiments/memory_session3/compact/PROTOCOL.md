# Local prospective protocol · Compact-Bench E2 · 2026-11-17

Question: can a deterministic writer choose technical references from a long coding session more efficiently than Compact-Bench's mechanical anchor_index, using only pre-compaction observations? Primary outcome: the authors' literal recurring-detail recall averaged equally over all eligible released E2 records. Source: Sun et al., arXiv 2610.31710v2, GitHub cai-jianfeng/compact-bench 9dd9a3f5a91b2de5acdf56cee2fc0a4d16dcefc5, HF caijanfeng/compact-bench ff20521e6a2293ba74317efb076f0c338ca5fb6b. The article's 79.1% anchor_index aggregate and 16% model aggregate were known. No gold atoms, model outputs or per-case outcomes were viewed while writing this protocol.

* Population: all 146 public retention records, no task picking. Segregate histories and labels, implement and SHA-lock all predictions before joining labels. Code reads only ordinal and H to build memory; labels, future request IDs, client and sample ID cannot determine allocation. Read original JSON serialized with ensure_ascii=False, first 400,000 characters as in anchor_index. Use authors' original atom extractor and case-sensitive substring scorer. No learning, LLM or embeddings. Reproduce the unmodified baseline on all records using pinned author code and true natural output lengths; report any mismatch vs paper.
* The primary intervention keeps paths, commit abbreviations, PR IDs, errors, URLs, variable assignments and IP addresses. Prefer items that appear across distinct messages, throughout separate phases (8 equal bins of visible messages), and in more than one message role. Score fixed before labels: 2·ln(1 + occupied time bins) + ln(1 + distinct roles) + ln(1 + distinct messages) + 0.5·last normalized message position. Break ties stably by type then Unicode value. Serialize the retained facts under per-type headings to avoid repeating a type label. No inclusion of multiple atoms inside one output token is required by the algorithm; add a secondary exact typed-item scorer that gives no incidental substring credit.
* Primary comparator: unmodified author anchor_index (each type alphabetically, at most 40). For each source, the candidate may use at most min(400000, len(author output)) characters; character budget is the authors' reporting unit and we separately measure bytes. Author and candidate have the same input. Additional budgets, specified now, are at most 1,024 and 4,096 chars, additionally capped by that session's natural author length. At reduced budgets truncate at a whole item/line; avoid breaking a saved fact. Include raw serialized history tail at the same exact length as a basic comparator and a type-balanced round-robin alphabetic control. Two ablations: author per-line syntax + new rank, same grouped encoding + authors' order. Baselines using same grouped syntax but last occurrence, frequency of distinct messages alone, SHA-fixed shuffle. Count independent explicit typed membership as supplemental score. Size policy pays for headings and line breaks. Record real total input/output chars, bytes, wall/CPU, and macro and micro performance.
* Primary paired difference: combined writer minus released anchor_index at natural budget. Report cluster-bootstrap interval by source session (10,000 replicates, independent session equally sampled, metric recomputed across records). Also summarize gains/losses/ties, per-client and atom-type breakdowns. If source sessions repeat report clustering and potential duplicates. Official scoring is descriptive for this fixed public suite. Paired bootstrap represents uncertainty under resampling these session groups. Coverage is not program repair, answer quality or verified usefulness. Secondary methods/budgets exploratory, avoid champion claims across many cells. A negative result must be retained. Every decision and output as content-addressed artifacts, per-session outcomes, offline verification, and separate source manifest.

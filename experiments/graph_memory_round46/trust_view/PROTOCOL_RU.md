# Как обслуживать повторные изменения веса одного источника

На 40 неизменных проекциях и всех 2 528 источниках преобразуем функцию, возвращающую оптимальный пакет при общем сдвиге полезности, в индекс отрезков SQLite. Парная целевая область — все целые Q32 в [−1/4; +1/4] в исходных единицах. Рассматривается независимый пересмотр одного источника относительно того же исходного состояния, в пределах заявленной области и сохранённых ранга, цен, ограничений и полного порядка. Из предыдущего диагностического опыта известна частота сохранения исходного пакета на шести уровнях. Новые критерии — стоимость построения и обслуживания *всех* пакетов, включая случаи изменения результата. Задаём нагрузку и алгоритмы до прогонов этой процедуры.

Если один полный пакет выбран на обоих концах отрезка, он выигрывает на всём отрезке. Каждая разность полезностей двух допустимых пакетов аффинна по параметру. При нулевой разности используется один и тот же порядок полных пакетов. Если концевые пакеты различны, ищем отрезки с помощью пересечения их прямых, отдельно проверяя соседние целые точки (включая допустимый победитель, существующий в единственной точке). Сохраняем только идентификатор лучшего пакета и начало каждого максимального последовательного интервала. Общая таблица dedup хранит полные идентификаторы пакета один раз на запрос.

При случайном порядке обработаем по 32 целочисленных сдвига для каждой пары запрос–источник, seed 46209, независимо от исходов, плюс граничные точки. Проверим одновременно прямой нативный решатель и правило первой серии (сертификат только исходного пакета). Если выходы совпадают, измерим четыре перемешанных парных прохода после одного прогрева по 8 из этих фиксированных сдвигов на источник. Варианты: прямой оптимизатор с разогретыми входными массивами; SQLite-интервал для исходного пакета с пересчётом при выходе; полный SQLite-индекс смен пакета. В каждой ветви материализуем и проверяем одинаковые упорядоченные идентификаторы. Единица bootstrap — все вызовы на одной траектории с общими 4 повторениями (10 000 выборок, seed 46210). Отдельно публикуем время построения, затраты хранения и порог окупаемости в запросах, если теплое ускорение положительно. Фиксируем различие между синтетическим потоком изменений и применением к реальным коррекциям доверия пользователей. Текстовая модель и исходное построение графа вне этих замеров.

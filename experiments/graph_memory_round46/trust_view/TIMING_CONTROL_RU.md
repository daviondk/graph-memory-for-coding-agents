# Контроль сильного прямого оператора и повторов одного параметра

Основной прогон использует одни и те же восемь весов по четыре раза и упаковывает ответ прямого C++-решателя в Python. После получения этих замеров выполним второй, раздельно обозначенный опыт. Вводим прямой C++-оператор с повторно используемыми рабочими буферами, возвратом упорядоченных uint16 ID непосредственно из нативного кода и выделением неизменного окружения вне таймера. Два режима на всех 40 траекториях: новые 8 весов на каждую пару и проход, а также постоянные 8 весов. До четырёх замеряемых проходов идёт прогрев. Сопоставляем прямой оператор, SQL-индекс всех интервалов, поиск по тем же интервалам в памяти и полный кэш точных параметров с нативным вычислением при промахе. При повторениях прогрев заполняет кэш, при новых весах запускаем полный кэш с таким же правилом, без верхнего ограничения числа записей; считаем попадания и число ключей. Общая единица результата — байтовый список ID всего пакета. Состояние пересмотра одно-параметрическое, распределение равномерно на том же дискретном домене. Порядок проходов методов и вопросов перемешивается по фиксированному seed 46461; 10 000 парных перевыборок траекторий. Публикуем в том числе режимы, где SQLite уступает более простому обслуживанию. Все условия второго опыта фиксируются до его измерения.

# Проверка плотности кодирования после основного опыта

Основная реализация хранит семь возможных логических состояний направления, однако дублирует в младших разрядах два уже вычисленных флага для ускорения выдачи. Проверим более компактный физический конкурент для K=3. Уберём копии битов: код пары равен 7a+b и принимает только значения 0..48. Сравним извлечение двух флагов в SQL и по одной общей Python-таблице на 49 целых чисел. В остальном остаются тот же авторитетный граф, обновления одной транзакцией, ровно те же сигналы восстановления и общая цена индексов. Заранее задаём три повтора, одну выдачу на каждую из 31 279 границ, парный bootstrap по 1 207 трассам, физические байты по dbstat, точный, односкановый и основной отложенный контроль. Это вторичная чувствительность к кодированию после обнаруженного нулевого выигрыша K=3 по общей вместимости страниц.

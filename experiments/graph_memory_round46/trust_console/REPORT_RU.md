# Source weight для консоли ISETrace

Страница открывается на интервале, где штатный исходный пакет действительно меняется. Для проекции q01 и источника 0083fc400… точка **6 307 132** сохраняет 9 исходных единиц за 2 030 токенов. В следующей целой точке **6 307 133** пакет содержит 13 единиц за 2 048 токенов. Исчезает #0, добавляются #27, #52, #35, #159, #152. Кнопка полного пересчёта независимо воспроизводит оба результата из исходной таблицы узлов и адресов их источников. [Проверенные исходы](./checks.json)

### Подключение

Скопируйте `weights.py` и `weights.html` рядом с `apps/trace/launcher.py`, а подготовленную базу `trust_view/view.sqlite` положите в `apps/trace/runtime/view.sqlite` рядом с существующей `reader.sqlite`. В начало `Handler.do_GET` добавьте следующий вызов; импорт можно расположить в начале файла. Оба файла баз открываются read-only. Код сервера использует стандартную библиотеку Python, страница обслуживается локально без внешних ресурсов.

```python
from weights import handle_weights

if handle_weights(self):
    return
```

Клиент запрашивает `GET /weights`. Запрос `/api/weights/catalog` перечисляет проекции, `/api/weights/sources?q=q01` — источники, `/api/weights/packet?q=…&s=…&delta=…` возвращает исходный и текущий упорядоченные пакеты, число токенов, точные границы включительно и ближайшие точки соседних интервалов. Текущий пакет выбирает SQL с условием start≤delta и ORDER BY start DESC LIMIT 1. Также возвращаются интервалы выбранного источника, добавленные и удалённые ID. Запрос `/api/weights/verify` с теми же параметрами дополнительно вычисляет оптимум по исходным ценам и полезностям. Для этого сначала строится обязательный префикс до 1 024 токенов, каждая полезность округляется до Q32, к каждому узлу данного источника один раз прибавляется delta, а хвост обрабатывает целая динамическая программа с бюджетом 2 048 и строгим сравнением >. При ничьей сохраняется старое решение. Обработчик возвращает False для чужих маршрутов. Через именованные аргументы `index_path` и `reader_path` можно использовать базы без копирования. ### Проверка

Ниже команды запуска из каталога исследования. Для независимого запуска приложения передайте пути к подготовленной и исходной базе. Зафиксированные бинарные данные в данный каталог не копировались.

```powershell
python -B test_weights.py
python -B test_weights.py --browser
python -B weights.py --index ../trust_view/view.sqlite --reader ../../graph_memory_round45/paper_revision/apps/trace/runtime/reader.sqlite --port 8784
```

На каждой из 40 реальных проекций выбран источник с максимальным числом интервалов. Для него проверены оба конца каждого интервала и ноль. Независимая динамическая программа совпала во всех 320 точках. В каталоге всех проекций проверены 2 528 источников. Браузерная проверка откроет различимый случай, запустит полный пересчёт, пройдёт соседние значения по обе стороны границы, сброс к нулю, край диапазона и смену проекции. На окнах 1180×820 и 390×844 ошибок JavaScript и горизонтального переполнения не обнаружено. Проверка неправильного источника, запросов вне диапазона и неполного запроса дала HTTP 400.

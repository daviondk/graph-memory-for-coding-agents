# Дополнительная малая проверка с реальным Qwen3-Reranker

Даже если удалось получить улучшение детерминантной выдачи, оно потребует сравнения с реальным нейронным переупорядочиванием. До оценки выбираем двенадцать состояний двенадцати разных репозиториев из фиксированных 204 по возрастанию SHA-256 строки "r46-cross-check/"+state_id, первое состояние в каждом репозитории. Из полного немаскированного ранга R45 Qwen3-Embedding-8B используем первые 16. Новая Qwen3-Reranker-0.6B в формате GGUF Q4_K_M на CPU упорядочивает те же 16 кандидатов по результату оригинальной yes/no-головы, при равенстве по прежнему порядку. Остальной хвост унаследован от Qwen. Старые и новые ранги, как и DPP, сначала замораживаем, затем считаем официальные метрики на той же подпанели; дополнительно приводим DPP, ограниченную теми же 16 кандидатами. Первичный интерес в этой подсерии — проверка реального изменения качества при переходе от dense к cross-encoder. На 12 состояниях интервалы будут широкими.

Подаём те же три исходных поля запроса и тот же источник текста (путь плюс выдержка) с предварительным ограничением в 511 Qwen BPE-токенов по тому же checkpoint embedding; сервис получает декодированное содержимое этих токенов. Документ может занимать ещё не более 511. Модель переупорядочивания добавляет собственный служебный шаблон, измеряем её фактический расход отдельно. Исключаем любые внешние обработчики, используем localhost на CPU. Критерий результата — при успешном запуске полные 12 состояний и все 192 пары; инфраструктурный сбой отражается отдельно. Опубликованная авторами конфигурация использовала другую по размеру Qwen3-Reranker-8B, проходила до первых 100 единиц и использовала иную сериализацию. Результат этой подпанели нельзя подписывать числом авторской строки.

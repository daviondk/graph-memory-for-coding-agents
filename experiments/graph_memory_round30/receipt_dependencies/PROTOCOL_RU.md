# Запись памяти по идентификаторам отзываемых наблюдений

Эксперимент мотивирован потерей преимущества геометрического Pareto перед NMS-0,3 по эмпирическому присутствию победителя в сгенерированных запросах R29. На этапе записи заранее известен полный список физических записей (источниковых интервалов), уже присутствовавших при инференсе. Использование меток будущих ответов или будущих выбранных отзывов для формирования памяти исключено. Для каждого кандидатного span i определим Dᵢ как множество всех идентификаторов записей, физически пересекающих его цитату. При отзыве набора полных записей R допустимость эквивалентна Dᵢ ∩ R = ∅. Первая по рангу запись для каждой идентичной сигнатуры даёт точное сжатие; более строгая политика удаляет также все более слабые надмножества Dⱼ. Сигнатура учитывает перекрывающиеся источниковые записи.

При K=8 и 64 сравниваем одинаковый потолок числа строк. Условия — обычный top-K, лучший на каждую исходную запись-производитель span, лучший на каждую точную маску зависимостей, лучшие недоминируемые маски, геометрический Pareto и hard NMS с заранее ранее заданным IoU=0,3. Размер реально занятых строк и размер реестра исходных записей оплачиваем, показываем общую память с теми же сжатыми логитами и границами окон. Если число возможных победителей меньше K, храним полный точный набор и умеем удостоверить пустой ответ. Сравнения источников и небезопасного NMS получают тот же благоприятный скалярный сертификат первой пропущенной потенциальной победы среди всех масок. В случае недостаточности доказательства резерв использует те же логиты и локальные верхние границы. Первичные показатели на 576 сохранённых событий R29 — число запросов, целиком обслуженных без резерва с доказанной точностью при K=64, и число сохранённых кандидатов/байтов. Случаи NULL считаются явным доказанным ответом и показываются отдельно. Отдельно сравним строгую необходимость skyline с простой дедупликацией по идентичной маске.

Для проверки переносимости политики событий генерируем дополнительно 64 ранее не использованных запроса на вопрос с вероятностями удаления каждой полной исходной записи 0,1; 0,3; 0,5; 0,8, по 16 фиксированных независимых хеш-наборов на уровень, включая перекрывающиеся записи. Основа сравнения — полный перебор исходных координат на объединении отозванных интервалов. Чтобы измерить границу применения, на вопрос генерируем 8 запросов о частичных интервалах и 4 смешанных запроса с частичным и полным отзывом. Отсутствующий в реестре интервал принудительно переводит специализацию по ID в точную проверку, используя допустимый кэш-кандидат как нижнюю границу; дополнительно показываем результат при ошибочном допущении, будто неизвестный интервал можно игнорировать. Побайтно сравниваем весь результат с координатным эталоном. Дополнительный запечатанный набор фиксирует конкретные запросы до построения этой памяти.

Время обслуживания на первичной панели 16 статей, двух вопросов и шести событий измеряем для raw, producer, mask dedup, mask Pareto, геометрического Pareto и NMS при K=64 в одном открытом read transaction, 12 повторов со случайным порядком. Отдельно логируем расходы построения, обычный вывод результата и реально загруженные числовые BLOB. Эта постановка допускает одновременный отзыв нескольких записей и трактует каждую как отзыв физических координат из всех их вхождений. Операция удаления только одной ссылки при сохранении альтернативного источника является другим языком обновлений.

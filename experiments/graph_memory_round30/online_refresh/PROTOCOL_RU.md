# Работает ли правило обновления при последовательном поступлении запросов

Оценка R29 давала методу право ранжировать весь пакет и выбрать лучшие 171 из 514. Посетитель системы памяти может поставить один вопрос, когда следующих запросов ещё нет. Проверяем онлайн-планирование, фиксируем общий размер очереди и предельное число обновлений. На шаге разрешены только данные текущего запроса, оставшийся бюджет и число вопросов до конца. Все признаки и веса уже обучены на прежних 460 вопросах ROPES. Сохраняем зафиксированные веса для обоих читателей. Для оценки квантиля используем распределение оценок на обучающих примерах RoBERTa даже при переносе на DistilBERT.

Сравниваем простой и расширенный регрессоры, случайную выборку из потока с вероятностью остаток/длина остатка, фиксированный порог по обучению с вынужденной тратой в конце, а также адаптивный порог по квантилю, соответствующему доле оставшегося бюджета. Первичный контраст — расширенное и базовое правило с адаптивным порогом. Остаток квоты и длина потока должны быть идентичны у всех методов. Проверяем 32 фиксированных перестановки вопросов и отдельно серии, в которых все вопросы одного семейства приходят подряд. Контрольный набор уже известен по результатам R29, это дополнительная проверка эксплуатационного ограничения. Оцениваем среднюю разницу F1, кластерный интервал по семействам на усреднённых по порядкам парных исходах и диапазон по порядкам. Перестановки не являются новыми независимыми примерами. Обучающие оценки при наличии ничьих разрешаем постоянным хешом. Гарантированно расходуем не больше 171 обновления. Метод с офлайн-ранжированием остаётся ориентиром по данным предыдущей серии.

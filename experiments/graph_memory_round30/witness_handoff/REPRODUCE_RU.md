# Воспроизведение

Применить подготовку данных R27/code_boundary для исходных SWE-Explore Verified и pyarrow, а также R18/isetrace_official для оригинальных восьми trajectories-*.jsonl. Тут из SWE-Explore используются только исходные id, dataset и read_step_info, из SWE-bench Verified — repo, instance_id, base_commit, problem_statement. Контрольные суммы восьми физических ISETrace-шардов с размерами записаны в ise4-inventory.json. Публичные адреса SWE-Explore и SWE-bench, ревизии и SHA указаны в R27. Список файлов на base_commit и их SHA создаётся в D:/CodexResearch/x20-r30-witness/base-source-map.json. Текст источников и файлы по ссылкам инструмента не исполняются.

Запускать run.ps1 из этой папки. Чтение истории требует нескольких проходов по исходным данным. Выделенные CPU времена и контрольные суммы файлов, содержащих времена, естественно изменяются на повторной машине. Чтобы воспроизвести только счёт, при наличии записанных проекций можно вызвать score.py swe, score.py ise4 и audit.py, затем отдельную проверку audit('ise4') и physical.main('ise4'). Все исходы и физические расходы записываются в отдельные JSON.

Приватный каталог D:/CodexResearch/x20-r30-witness хранит полный исходный срез, последующие обращения для независимого evaluator, source-map и прогнозы до результатов. Для каждой панели байтовые файлы именуются <panel>-one.bin, <panel>-first_two.bin, <panel>-latest.bin, <panel>-distinct_worker.bin, <panel>-full.bin и <panel>-keys.bin. Каждая пара little-endian uint32 хранит индекс в массиве событий. Sentinel 0xffffffff обозначает пустой резерв. Ключ содержит 32 байта хеша пути, uint32 номера строки и 32 байта SHA256 её UTF-8 байтов без EOL. Хеши указаны в *-forecast-seal.json. Список полных свидетельств, вспомогательные 32-bit смещения и битовые карты вычисляются по тому же узлу/префиксу. Источники SHA-256 не удостоверяют подлинность или смысл утверждения.

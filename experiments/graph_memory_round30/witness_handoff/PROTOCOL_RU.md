# Сколько независимых ссылок хранить на уже прочитанную цитату

В первичном аудите SWE-Explore (161 научная benign-задача) обнаружено 106 задач с пересечением адресов между запусками. В 23 132 траекториях ISETrace среди 11 519 отобранных по benign-интенту были 2 144 с допустимым текстовым read, 104 с подтверждённым повтором тех же байтов в той же строке того же пути. Девять вызовов sessions_send в семи разрешённых траекториях не содержали полного буквального совпадения с допустимой строкой более раннего read. Флаг успеха инструментальной оболочки не гарантирует реальную доставку. Следующий тест — доступность первичных адресов при моделируемом отзыве доставки. Он не подменяет исследование конфликтов в реальных делегирующих командах Zhang.

## Фиксация прогноза до наблюдения цели

SWE-Explore. Объединяем префиксы независимых успешных запусков одного issue в модель нескольких исполнителей. У каждого в префиксе до трёх первых разных step_idx с ограниченным production Python read. Все наблюдения одного шага принадлежат одному сообщению. Оцениваем по **первому следующему** ограниченному шагу каждого запуска, по всем его различным диапазонам. Новые обращения к другим файлам и недоступные в префиксе цели сохраняются с нулём. Политики не видят будущие адреса. Координаты проверяются по инеpтному файлу на base_commit. Срез строк внутри диапазона обрезается по EOF. Для каждого будущего чтения пара целей — первая и последняя две разные информативные физические строки (32–320 байт, четыре разных словоподобных последовательности) данного обращения, точнее его первая и последняя подходящие строки. Ветки с менее чем двумя подходящими строками не оцениваются, отдельно считаются. Байт-совпадение здесь реконструировано на закреплённом коммите, реальный stdout и рабочая ревизия конкретного раннего шага в релизе не записаны.

ISETrace. Строгая панель реального текста. В каждой сессии вход — первые **два** подходящих положительных read сообщения, цель — первое следующее подходящее read сообщение, те же правила первой/последней строк. При наличии минимум трёх таких событий возможна прогностическая проверка. Альтернативный независимый адрес принимается только при совпадении номера строки, пути внутри сессии и SHA-256 всех байтов содержимого. Кроме главной будущей выборки считаем доступность всех пар «первая и последняя строки» уже наблюдавшихся сообщений того же префикса по каждой сессии с двумя чтениями. Невозможность проверить хеш/SHA исторической версии исходного файла объясняется отдельно.

## Правила передачи при одинаковом бюджете

При передаче хранится фиксированная карта видимых цитат. На каждую исходно видимую строку имеется две 32-битные ячейки для ID первого и резервного сообщения, 8 байт. Ключи адресов, таблица сообщений и исходный журнал общие, их цена учитывается отдельно. Первый свидетель — самый ранний наблюдавшийся по локальному номеру события с детерминированным чередованием исполнителей по рангу и непрозрачному идентификатору. Сравним один адрес, первые два **разных сообщения**, последний дополнительный, первый из другого исполнителя (иначе самый ранний оставшийся), все свидетели из полного журнала. Для контроля интерпретации считаем непосредственно сканирование полных уже доступных записей и прямой доступ к исправному закреплённому источнику для SWE. Предсказания резервов для всех доступных строк хешируются до доступа к будущим целям. Источники цитирования ошибочных версий в прикладном сценарии можно проверять только после явной модели версий.

Основная величина — вероятность адресовать обе строки будущего чтения после отказа одного равновероятного исполняющего процесса на SWE. Перебираем все активные исполнители, отозвав все их сообщения, вес каждого будущего обращения одинаков внутри issue, исходный issue имеет один вес при агрегации. Главный контраст — резерв у другого исполнителя минус первые два разных сообщения. Вторичные сценарии — равномерный единичный отказ сообщения, отзыв именно первого сообщения первой цитаты (где оно есть), исходное состояние, исключение общего исходного файла (обе строки принадлежат одному файлу). На ISETrace по исходной сессии известен один владелец журналируемых read, там основное сравнение — любые два против одного после единичного отзыва сообщения. История не содержит факта этих отказов. Считаем знаменатели без условия на достижимость и отдельно для изначально доступных пар. Парный bootstrap 10 000 целых issue/сессий с фиксированным seed 30031. Между цитатами пользуемся точным совместным перебором отказов, не перемножаем их маржинальные вероятности. Метрики описывают восстанавливаемость ссылок. Семантика «двух противоречивых утверждений» и качество финального ответа не измеряются.

Публикуются размеры бинарных предсказаний и трассировок, фактические расходы построения и декодирования в CPU-времени. Дополнительно будут проверены неизменность исходной истории для всех вариантов, полный повтор случаев напрямую из фактических адресов, включая разницу между исчезновением одного сообщения и всего источника. Правило безлимитного чтения старого журнала реализует верхнюю границу. Прямой адрес на живую авторитетную неизменённую копию разрешает восстановление без хранения повторных свидетельств. Практическое преимущество возникает в более узкой модели, где по правилам передачи опора должна быть связана с доступным наблюдением/исторической версией.

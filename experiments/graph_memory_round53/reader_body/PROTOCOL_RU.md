# Зарегистрированный контроль тела второго документа

Панель и исходная разность F1 уже известны. Контроль включает все 512 исторически новых вопросов R52, по которым сравнивались learned_href и learned_literal в опыте global_answers/confirm/supplement. Проверяем абсолютные ответы для обеих политик. Основная величина — парная разность Answer F1 «ссылка минус буквальный адрес» после замены содержания второго источника. Второй запланированный контраст — разность двух таких эффектов, исходный минус эффект с заменённым текстом, на тех же вопросах. EM вторичен. Для эффекта и взаимодействия — 10 000 совместных парных bootstrap по идентификатору первого документа, seed 532572. Для неопределённости приводим также двусторонний тест смены знаков кластерных сумм. Декодер, веса, шаблон, инструкцию, границы и исходную длину запроса берём из R52. Эпизоды с совпавшими адресами остаются в знаменателе.

Для каждого вопроса полностью сохраняем токенизированные вопрос, инструкцию, первый документ, окончание и количество разрешённых токенов второй статьи. Сохраняем точное видимое начало второй статьи по конец заголовка вместе с границей строки. Если изначально видна только часть названия, сохраняем ровно исходный префикс и указываем число таких случаев. Используем нативные токены Qwen из архива и проверяем совпадение префикса с токенизацией заголовка, разделителя и настоящего текста. При BPE-токене, объединяющем разделитель и первые знаки тела, сохраняется токенизированная заново точная строка названия с переводом строки при том же общем бюджете; если этого потребует хотя бы одна граница, число случаев укажем отдельно. Остаток заполняется префиксом тела одной реальной статьи-донора, общей для двух методов в вопросе. Различие длин названий оставляет разное число доступных токенов одного и того же донора.

Донор выбирается детерминированно среди вторых статей других 511 вопросов по SHA256("r53-donor-v1|" + ID вопроса + "|" + row ID донора), без использования оценок. Исключаем собственные ранее прочитанные/выбранные статьи всех четырёх первоначальных политик и все источники, фигурирующие в качестве опорных в текущем вопросе, через техническое исключение по заранее замороженным метаданным автора; ни один вопрос не исключается. Чтобы избежать доступа к меткам вообще, можно вместо последней проверки исключить весь набор названий из исходного контекста этого вопроса, содержащий все опоры: применяется именно это более строгое правило. Фильтр не смотрит верный ответ или результаты политик. Донор должен иметь не меньше нативных токенов для максимальной требуемой длины; если общая популяция не предоставила такого кандидата, это ошибка протокола. Случайный текст может случайно подсказать ответ; семантическая нерелевантность каждого донора не предполагается. Не обучаем новую модель, не настраиваем правило на эффекты. Регистрируем результаты независимо от направления. При одном доноре на вопрос вывод условен на этот воспроизводимый выбор.

Все источники, входы, доноры, токены, ответы и поэпизодные метрики сохраняются с контрольными суммами. Используем официальный 2Wiki v1.1 scorer, включая aliases и demonyms, как в R52. Время новых прогонов и версия GPU учитываются отдельно.

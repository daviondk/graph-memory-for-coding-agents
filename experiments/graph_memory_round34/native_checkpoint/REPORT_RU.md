# ISETrace. Зафиксированный парный результат для первых двух инициализаций

Политика R33 выбирает фрагменты памяти инструментальных агентов при ограниченном контексте. Для одних и тех же 2 000 вопросов из 1 207 траекторий она ранжирует те же provenance units, что полный residual R-GCN и отдельно переобученная модель без связей между соседними фрагментами. На каждом seed все три используют один Dense-FT checkpoint. Одинаковые происхождение и длины фрагментов, правила упаковки, тестовые метки и все шесть метрик проверены при повторном вычислении из полных порядков. Для каждого seed это 6 000 оценок ранжирования (3 × 2 000), в таблицах сохранены 4 000 связанных наблюдений seed × вопрос.

| Seed | R33 FS@2048 | Полный R-GCN | Δ в п.п. и 95% ДИ | Без chunk adjacency | Δ в п.п. и 95% ДИ |
|---|---:|---:|---:|---:|---:|
| 13 | 80,60% | 78,85% | +1,75 [0,15; 3,36] | 80,05% | +0,55 [−0,99; 2,12] |
| 17 | 80,35% | 78,00% | +2,35 [0,74; 4,03] | 78,10% | +2,25 [0,46; 4,06] |
| Среднее двух seed | 80,475% | 78,425% | +2,05 [0,67; 3,47] | 79,075% | +1,40 [−0,02; 2,86] |

Парный bootstrap из 10 000 выборок переносит целую траекторию со всеми вопросами, при исходном равном весе каждого вопроса и каждого seed. Дополнительная перевыборка обоих измерений даёт интервалы [0,46; 3,64] и [−0,52; 3,48] п.п. соответственно. Пять seed были определены заранее, а при фиксации самого протокола уже был известен результат первого. На втором seed обе разницы положительны. Совместная оценка двух seed пока совместима с нулевым изменением против более сильной абляции.

При сравнении с абляцией среднее покрытие C@1024 выросло на 2,22 п.п. [0,67; 3,78], C@2048 — на 1,44 [0,19; 2,70]. Одновременно span Recall@5 уменьшился на 1,48 [−3,00; −0,03], MRR — на 1,37 [−2,81; 0,03]. Это описательные вторичные интервалы без поправки на множественные сравнения. Положительные значения относятся к качеству под бюджетом токенов. [Все значения](interim-2.json)

## Отбор и граница вывода

R33 выбирался по FS@2048, затем C@2048 на 580 dev-вопросах. Штатный R-GCN выбирает epoch из 0–15 по node Recall@5 на тех же 580. Для seed 13 выбраны эпохи 14 / 12, для seed 17 — 9 / 13 (полный граф / абляция). Дополнительная CPU-проверка на seed 13 показала FS 438/580 для нулевого residual, 450/580 для полного и 470/580 для абляции. Сама политика R33 получила 462/580, проиграв абляции на восьми dev-вопросах в чистом итоге. Для замены критерия отбора по всем 16 состояниям требуется повторить обучение — в исходном запуске остался checkpoint только штатного победителя. План отдельного повтора фиксирует все 10 dev-выборов до тестовых расчётов. [Проверка двух состояний](dev-two-epochs.json) · [Зафиксированный план выбора эпохи](epoch-plan.json) · [Полный протокол выбора](../dev_metric/PROTOCOL_RU.md)

Эта папка — неизменяемый срез двух законченных блоков эксперимента. Очередь продолжает три оставшиеся инициализации 29, 37, 41. Они записываются в соседнюю рабочую папку. Для финального положительного результата требуются обе положительные нижние границы парного 95% интервала FS@2048 после всех пяти инициализаций. Для сопоставления с обучением по той же бюджетной метрике дополнительно используется заранее определённая чувствительность выбора эпохи. ## Воспроизведение

Выполнить `python -B check.py` требуется Python и NumPy. Отдельный проверочный скрипт заново вычисляет шесть показателей и оба типа доверительных интервалов из двух сжатых файлов исходов и проверяет хеши manifest. Каждый файл содержит словарь по ID вопроса. Значение состоит из ID траектории, затем из трёх векторов в порядке R33, полный R-GCN, без chunk adjacency. Каждый вектор содержит FS@2048, C@512, C@1024, C@2048, span Recall@5 и MRR. Для пересчёта самих показателей из исходных ранжирований сохранён использованный код и индивидуальные хеши исходных прогнозов, весов и меток.

# Парное сравнение бюджетного ранжирования со штатными графовыми моделями ISETrace

Кандидат заранее фиксирован по выбору R33/budget_loss: cost_worst_0.03. Сравниваем с двумя официальными конфигурациями обучаемого графа ISETrace — полным residual R-GCN и заново обученной абляцией без chunk adjacency. Выбор этих соперников фиксирован до появления любого результата на втором–пятом официальном seed. В момент фиксации известны исходы R33 и обеих баз на первом seed, а также результаты R33 на тех же задачах с другими Dense-компонентами. Описываем эту серию как парную проверку сильных баз на знакомом публичном test. Новая независимая выборка задач дала бы отдельное свидетельство переноса.

Первичный критерий — разница Full Support при строгом лимите 2 048 токенов выше нуля для каждой из двух баз по нижней границе двустороннего 95% парного интервала на всех пяти заранее заданных seed 13, 17, 29, 37 и 41 и на всех 2 000 test-вопросах. Для совместного заявления нужны обе положительные нижние границы. Автономные утверждения по вторичным показателям требуют поправки на множественность. Среднее берём по seed внутри вопроса, затем по вопросам. Bootstrap 10 000 раз выбирает с возвращением 1 207 целых траекторий с переменным числом вопросов. Дополнительно выводим все пять парных эффектов, группы 17–41 и интервал с перевыборкой обеих осей (модельных seed всего пять). Верхний ориентир по более сильной из двух баз на каждом вопросе — только диагностическая задача при наличии явной заявки. Никакого отбора благоприятного seed, ранней остановки или перенастройки модели. Промежуточные срезы выпускаются при полном наличии обеих баз очередного seed. Для вторичных показателей задаём в явном виде Coverage при 512/1024/2048 токенах, Recall@5 и MRR, как в реализации benchmark.

Сверяем идентичность всех 2 000 ID и 1 207 траекторий, полные перестановки общего множества исходных единиц памяти, их токенизацию, соответствие отбора Dense-весов на dev580 и наследование этих весов обеими политиками, совпадение исходной span-разметки и функции наполнения строгого контекста. На каждой из трёх фактических ранжировок заново применяем нативные метрики, сверяем с опубликованными по каждой политике. Модели имеют собственные способы отбора: R33 выбирает политику по Full Support и Coverage на 580 dev один раз, а R-GCN выбирает графовую эпоху из 0..15 по штатному dev Recall@5 на каждом seed. Сравнение воспроизводит эти правила и не уравнивает объём обучающих вычислений. Основная научная единица — траектория, повторные инициализации обрабатываются как связанные измерения.

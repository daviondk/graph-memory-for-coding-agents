# Физическая стоимость чтения графовой памяти на CPU

На маршруте от сжатой истории и локальной SQLite с сохранёнными E5-эмбеддингами до готового контекста медиана задержки **35,62 мс** у cost_worst и **51,84 мс** у сильной нативной R-GCN без смежности. Пара «полная R-GCN / cost_worst» даёт отношение средних медиан **1,47× [1,36, 1,62]**, пара «без смежности / cost_worst» — **1,37× [1,31, 1,42]**. Замер включает построение структуры с нуля для каждого чтения. При уже резидентной структуре и векторах разрыв значительно больше. Измерено локальное извлечение контекста, с одинаковыми эмбеддингами и без последующей генерации ответа. [Сквозные времена](file-summary.json) · [Все повторы](file-times.json.gz)

## Системы и качество выдачи

Обе нейронные модели — действительные checkpoint R22 seed 13, отобранные по официальным 580 dev-вопросам. Загружали их реальные state_dict и вызывали штатный PyTorch forward с тремя слоями на нативных типизированных рёбрах. Каждый метод использовал ту же ревизию E5 Dense-FT 683f3314… и один пул кандидатов. Простой Dense возвращал порядок по косинусному сходству. У cost_worst 23 структурных признака, rank prior и четырёхкоэффициентная поправка сведены в один статический вклад узла и функцию его текущего семантического ранга. Эта компиляция учитывает типизированные степени и их относительный порядок внутри роли. В момент вызова нужно заново отсортировать семантические score и сумму факторов. Готовые ответы во время измерения не читались. [Исходная архитектура Wang et al.](https://arxiv.org/html/2609.25913v3#S4.SS3) · [Загруженные веса и окружение](runtime.json) · [Реализация компиляции и служебный код](reader.py)

Панель зафиксирована по хешу ID до измерений, 96 из 2 000 вопросов, 94 траектории. Сверены полный порядок, последовательность возвращённых фрагментов, множество ID и Full Support@2048 каждого вопроса относительно сохранённых прогнозов. В числителе FS число вопросов с полным покрытием.

| Метод | Идентичный полный порядок | Идентичная последовательность при B=2048 | Идентичное множество при B=2048 | FS панели |
|---|---:|---:|---:|---:|
| Dense-FT | 94/96 | 96/96 | 96/96 | 70/96 |
| cost_worst | 94/96 | 96/96 | 96/96 | 78/96 |
| Полная R-GCN | 88/96 | 95/96 | 96/96 | 76/96 |
| R-GCN без смежности | 89/96 | 95/96 | 96/96 | **81/96** |

FS совпал с исходным прогоном по всем 384 парам «вопрос, метод». У Dense все инверсии относились к строго равным значениям CPU-косинуса. У cost_worst присвоение разных базовых рангов этим равным значениям может усиливать различие в балле. Подстановка исходного порядка Dense восстанавливает исходный порядок cost_worst во всех затронутых случаях. У двух R-GCN максимальный разрыв CPU-баллов на инвертированных парах менее 0,000003. Репликация производилась на CPU с batch=1, исходное ранжирование R22 было пакетным. На этой панели сильнейший компаратор имеет на три полных ответа больше, чем cost_worst. Из небольшой панели для измерения времени нельзя выводить общее преимущество качества. [Поштучная проверка](replay.json.gz) · [Разбор перестановок](replay-differences.json)

## Время до готового контекста

Windows, Ryzen 7 8700F (8 ядер, 16 логических процессоров), один закреплённый логический процессор, по одному потоку PyTorch и BLAS, batch=1. В каждом блоке методы запускались в перемешанном порядке. В таблице p50 и p95 по медианам времени отдельных запросов, в миллисекундах. В JSON также доступны квантили всех вызовов. Интервалы разностей и отношений рассчитаны для средних медиан, совместной перевыборкой целых траекторий, 10 000 раз.

| Реальная точка входа | Вопросов × повторов на метод | Dense p50 / p95 | cost_worst p50 / p95 | Полная R-GCN p50 / p95 | Без смежности p50 / p95 |
|---|---:|---:|---:|---:|---:|
| Семантические баллы и готовый graph batch | 96 × 8 | 0,016 / 0,040 | 0,024 / 0,062 | 8,867 / 19,037 | 7,914 / 15,638 |
| Готовые векторы и статическая структура, формирование запроса включено | 96 × 2 | 0,169 / 0,581 | 0,174 / 0,531 | 17,223 / 62,717 | 16,840 / 67,772 |
| Файл графа, локальная SQLite и пустое представление текущей истории | 24 × 3 | 34,45 / 99,19 | 35,62 / 104,22 | 52,08 / 148,85 | 51,84 / 141,18 |

При подготовленных векторах разность средней задержки с полной R-GCN равна 24,03 мс [19,40, 30,09], с R-GCN без смежности 22,66 мс [18,32, 27,78]. Отношения средних равны 98,28× и 92,74×. Эта граница уже располагает нужными векторами и графом в памяти. Маршрут от файла для каждого из 288 вызовов действительно читал и десериализовал граф, запрашивал эмбеддинги в SQLite, заново строил представление и тот же полный порядок и префикс. Модели и соединение были прогреты, файловые кэши ОС сохранялись. Отношения задержек снизились до 1,47× и 1,37×. Абсолютная экономия относительно базы без смежности составила **15,84 мс [12,10, 20,13]**; относительно простой Dense-сортировки cost_worst добавил **1,72 мс [0,21, 3,09]**. Все методы в этом маршруте оплачивали чтение векторов всех узлов, хотя линейным читателям требуются только кандидатные. [Основные времена](summary.json) · [Полный маршрут и протокол](FILEPATH_RU.md)

На основной панели типичная история имела 109 кандидатных узлов и 144 типизированных связи после проекции. Первичная компиляция двух массивов cost_worst заняла медианно 1,66 мс. Медиана независимого замера подготовки официального batch — 9,42 мс для полной R-GCN и 9,08 мс для абляции. Отдельные диагностические стадии включали первое обращение к данным и имеют иную степень прогрева SQLite/файловой системы. Их медианы нельзя складывать и подставлять вместо физически измеренного маршрута. Запуск E5-инференса исключён во всех трёх режимах. Авторские миллисекунды на MetaX C500 получены другой машиной и протоколом. [Поисторические и позапросные затраты](setup.json.gz) · [Эксперимент авторов](https://arxiv.org/html/2609.25913v3#A6)

## Физический объём

| Компонент | Размер |
|---|---:|
| Общие веса E5 Dense-FT, используемые для создания кеша | 437 951 328 байт |
| Поставленные числовые параметры читателя cost_worst, JSON | **902 байта** |
| Файл каждого обученного graph checkpoint | 13 402 018 байт |
| Элементы state_dict каждой R-GCN | 13 383 684 байта |
| Резидентные статические числовые массивы cost_worst типичной истории | 1 744 байта |
| Общий вектор длин кандидатов типичной истории | 872 байта |
| Неповторяющиеся tensor storage готового batch, полная / без смежности, медиана | 579 920 / 577 344 байта |

902 байта описывают коэффициенты сверх E5. В это число не входят код, исходная история, общие векторы, таблицы адресов или интерпретатор. Размер batch учитывает тензорные буферы, включая эмбеддинги, некоторые из которых уже могут присутствовать в общих входах. Для измерения работающего процесса отдельно запустили восемь чистых процессов, два на политику, с одинаковыми первыми восемью запросами. Рабочий набор с общими входами составлял примерно 458 МиБ. Средний прирост Windows WorkingSetSize после загрузки метода, подготовки и трёх проходов — **0,24 МиБ Dense, 0,42 МиБ cost_worst, 44,93 МиБ полной R-GCN и 46,60 МиБ без смежности**. Прирост Windows PrivateUsage составил 0,00; 32,06; 69,69 и 70,01 МиБ соответственно. PrivateUsage отражает частную выделенную память процесса, часть которой может не находиться в физическом рабочем наборе. Эти величины зависят от библиотек и аллокатора. [Снимки каждого процесса](summary.json) · [Протокол измерения памяти](MEMORY_PROTOCOL_RU.md)

Для демонстрации системы релевантен выбор точки входа. Если одна история обслуживает много запросов, можно амортизировать чтение, индексацию структуры и получение представлений. Для первого обращения к истории главный воспроизводимый результат этого опыта — **1,37× по средней задержке против сильной R-GCN без смежности** при уже рассчитанных E5 и локальном хранилище. Такой вывод не переносится автоматически на генерацию E5, серверный GPU, весь агентный цикл или многопользовательскую нагрузку.

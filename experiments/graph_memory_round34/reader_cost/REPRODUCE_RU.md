# Воспроизведение

`python verify.py` из этой папки автономно проверяет контрольные суммы, результаты на всех 96 вопросах, исходные 4 128 измерений, медианы, парность блоков и идентичность выдачи из восьми отдельных процессов. Нужна стандартная библиотека Python. Фактические затраты зависят от оборудования и текущей нагрузки. Для повторения измерений используйте копию каталога, сохранив исходную раскладку D. Новые времена и рабочие наборы будут иметь другие хеши, даже при совпадении рангов.

Для расчёта нужны энкодерные SQLite-кэши и нативные best.pt R22 official580 для seed 13, архив графов и прогнозов R19, модельные параметры и прогнозы R33, официальные SourceSpan с бенчмарка. Основные варианты исполняются в существующем окружении ISETrace. Код закрепляет процесс за логическим ядром 8 из доступных 0…15 и использует один вычислительный поток, PyTorch eval() и inference_mode(). Не запускайте тяжёлые задачи одновременно с измерением, если нужна оценка задержки на свободном хосте. Исходную серию выполнили на общей рабочей станции; аппаратно эксклюзивная машина не требовалась и не проверялась.

```powershell
Set-Location 'D:/CodexResearch/x20-bench-workspace/work/graph_memory_round34/reader_cost'
$py = 'D:/CodexResearch/x20-isetrace-e5-gpu/venv/Scripts/python.exe'
& $py reader.py
& $py measure.py
foreach ($i in 1,2) {
    $order = if ($i -eq 1) { 'dense','full_rgcn','cost','wo_chunk_adjacency' } else { 'wo_chunk_adjacency','cost','full_rgcn','dense' }
    foreach ($method in $order) { & $py probe.py $method $i }
}
& $py from_file.py
& $py replay_differences.py
& $py summarize.py
& $py filesummary.py
```

В times.json.gz каждая строка — траектория, вопрос, точка входа, номер повтора, позиция метода внутри блока, метод, наносекунды. В file-times.json.gz точка входа одинакова и опущена. summary.json и file-summary.json содержат также объединённые распределения вызовов, средние медиан, парные разности, отношения и их доверительные интервалы. В replay-differences.json хранятся только вопросы с различием хотя бы одной перестановки. Материализация настоящих нативных задач использует upstream GraphMemory из существующей зафиксированной рабочей среды. [Первичный код](https://github.com/xiaoqi-7/GraphMemory)

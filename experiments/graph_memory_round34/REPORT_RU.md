# Отчёт. Чтение изменяющегося графа памяти при ограничении на контекст

На ISETrace мы проверили, помогает ли агенту знать, как связаны выполненные действия и возвращённые ими данные, когда часть истории ещё впереди. На SERBench проверили, переносится ли принцип отбора на поиск исходного кода в момент следующего решения. В отдельном сравнении воспроизвели опубликованный ранжировщик R-GCN. Все различия ниже выражены в процентных пунктах, интервалы соответствуют парным 95%-ным оценкам, если не указано иное.

## Три результата

| Проверка | Метод | Контроль | Разница |
|---|---:|---:|---:|
| ISETrace, середина выполнения, Full Support при 2 048 токенах, 901 допустимый вопрос | 752/901 | 732/901, предыдущая модель чтения | +2,22 [0,65; 3,93] |
| Та же выборка и те же веса, актуальный граф против накопления всех когда-либо наблюдавшихся рёбер | 752/901 | 725/901 | +3,00 [1,33; 4,70] |
| SERBench Cal500, все необходимые исходные фрагменты в первых восьми и 6 144 токенах | 101/214 | 96/214, BGE по текущему состоянию | +2,34 [0,48; 4,46] |

**Когда отзывать связь.** На ISETrace соответствие между вызовом инструмента и его результатом может уточниться позже. Если при таком уточнении убирать старые рёбра, меняются степени узлов и их приоритет при чтении. Для основного сравнения брались только вопросы, на которые к середине истории уже существовал полный набор свидетельств. Если включить все 1 845 непилотных вопросов, полное покрытие составило 40,76% у нового и 39,67% у предыдущего метода. Вопросы сформулированы ретроспективно. Повторный расчёт штатного плотного поиска на 8 000 парах «вопрос × состояние» воспроизвёл все бинарные исходы обеих моделей. [Проверка по ходу выполнения](live_reader/REPORT_RU.md)

**Что переносится на код.** Функция обучения штрафует расходы на нерелевантные фрагменты, расположенные в выдаче перед последним необходимым свидетельством. Для SERBench её адаптировали к нескольким допустимым наборам и переобучили на 179 состояниях. 101 состояние использовали для выбора параметров, 214 состояний из 69 отдельных репозиториев оставили для оценки. Заранее назначенный перенос весов ISETrace дал 44,39% при исходных 44,86%. Разность измерена на новом разбиении публичного Cal500. На нём уже проводились предыдущие исследования. При условном перемешивании путей часть преимущества сохранилась, поэтому вклад точного соответствия адресов пока неопределён. [Перенос](external_transfer/REPORT_RU.md) · [Контроль структуры](external_transfer/ALIGNMENT_RU.md)

**Сравнение с опубликованным графовым методом.** На одном пуле из 2 000 вопросов и двух обучениях общего Dense-FT наш метод дал 80,475% полного покрытия при 2 048 токенах. Полная R-GCN дала 78,425%, её наиболее сильная опубликованная абляция с исключённой смежностью фрагментов — 79,075%. Разности +2,05 [0,67; 3,47] и +1,40 [−0,02; 2,86]. С учётом вариации и траекторий, и инициализаций интервалы [0,46; 3,64] и [−0,52; 3,48]. По Recall@5 преимущество у сильной абляции, у нашего метода −1,48 п.п. Сам R-GCN выбирал эпоху по штатному Recall@5, наш метод выбирался по полному покрытию. Протокол полного сравнения включает пять инициализаций и дополнительный выбор эпохи по одинаковой dev-метрике. Первые две фиксируем отдельно. [2 × 2 000 поштучных сравнений](native_checkpoint/REPORT_RU.md) · [Опубликованные базы](strong_reader_controls/REPORT_RU.md)

## Какие объяснения выдержали проверки

- **Бюджет важнее формы сглаживания.** Жёсткий минимум и мягкий минимум в стоимости ранжирования дали одинаковый Full Support для каждого из 2 000 вопросов. При выбранной на dev квадратичной функции и одинаковом весе отвлекающих узлов качество составило 79,55%, основной метод дал 80,60%. Выведена верхняя граница для доли стоимости отвлекающих узлов до самого слабого необходимого свидетельства. Это связь с задачей ранжирования семейства TopPush. [Контроли](cost_push/REPORT_RU.md) · [Математика и предшествующие работы](cost_push/PRIOR_ART_RU.md)
- **Качество сохраняется при изменении бюджета.** По шести предопределённым бюджетам площадь под кривой Full Support в логарифмической шкале выросла с 67,172 до 67,803 (+0,631 [0,380; 0,886]) относительно уже откалиброванного по ролям графа. Аналогичное изменение площади покрытия +0,578 [0,337; 0,822]. При 2 048 токенах эффект самой бюджетной поправки +0,86 [0,33; 1,40] в анализе чувствительности к траекториям и пяти обучениям общего энкодера. [Площадь под кривыми](strong_reader_controls/auc.json) · [Чувствительность](uncertainty/REPORT_RU.md) · [График](uncertainty/budget-effects.pdf)
- **Точный критерий полного покрытия можно вычислить по исходным интервалам.** Для каждого атомарного участка эталона берём самый ранний ранг любого покрывающего его фрагмента. Максимум этих рангов даёт минимальный префикс, достаточный для полного покрытия. Это объяснило все 20 расхождений с правилом «вернуть все помеченные узлы». Добавление критерия в обучение не дало прироста на этом наборе. [Формула и верификация](interval_witness/REPORT_RU.md)
- **Усложнение графа само по себе не окупилось.** Согласие соседей по типам рёбер дало 80,05% против 80,60% у более простого метода. Дополнительный вес для пограничных примеров по бюджету снизил качество в соответствующей панели с 80,33% до 79,81% по пяти инициализациям. [Типы соседей](typed_neighbors/REPORT_RU.md) · [Взвешивание по остатку бюджета](budget_slack/REPORT_RU.md)

## Что можно показать на ICDE

[Интерактивное демо](reader_demo/index.html) открывается локально. На восьми реальных примерах можно сравнить порядок тех же результатов инструментов, изменить токенный бюджет, отключить рёбра и увидеть, какой исходный фрагмент потерялся или вернулся и какой член функции ранжирования изменил его позицию. В выборке есть улучшения, ухудшения и совпадения. 320 комбинаций интерфейса сверены с независимым расчётом. [Проверка интерфейса](reader_demo/REPORT_RU.md)

Для статьи защищаемая постановка сейчас — получение полного набора свидетельств при ограничении на чтение и обновление связей по мере изменения состояния. Чтобы судить о SOTA, нужны полный согласованный прогон по всем запланированным инициализациям и сопоставимый выбор контрольных точек. Рост качества итогового решения задачи агентом требует отдельного сквозного эксперимента. [Метод и пять обучений](../graph_memory_round33/REPORT_RU.md)

## Чего стоит одно чтение

На одном ядре CPU сравнили чтение графа из файла, разбор состояния, получение общих заранее вычисленных E5-векторов из SQLite и построение выдачи. На 24 вопросах из разных траекторий при трёх повторах медианная задержка составила 34,45 мс для Dense, 35,62 мс для нашего метода, 52,08 мс для полной R-GCN и 51,84 мс для сильной абляции. По парным замерам сильная абляция расходовала в 1,37 раза больше времени [1,31; 1,42]. Если исключить чтение и подготовку данных, разрыв существенно возрастает. Публикуем обе границы измерения. На хешированной панели из 96 вопросов все четыре метода воспроизвели свой состав выдачи при 2 048 токенах. Полное покрытие здесь 78/96 для нашей модели и 81/96 для сильной абляции.

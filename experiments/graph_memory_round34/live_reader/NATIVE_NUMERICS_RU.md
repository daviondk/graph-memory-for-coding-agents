# Проверка плотного ранжирования при физическом изменении пула

В основном опыте отбрасывались ещё не видимые кандидаты из прежней выдачи, затем полностью пересчитывался текущий граф. Во время проверки исходным DenseTaskRetriever на настоящих обрезанных графах обнаружена почти точная связка: косинус при изменении формы матрицы в FP64 на одной паре различался на 2,22×10⁻¹⁶, и два плотных ранга поменялись местами. Сохраняем исходную серию и дополнительно запускаем нативное вычисление Dense по всем видимым пулам. Эмбеддинги E5 фиксированы, сверены с checkpoint seed 13. В каждом срезе native получает только вопрос и видимых кандидатов. Пакуем по обновлённому порядку обе основные модели — cost_worst и прежний читатель R22. Ожидаем небольшую долю расхождений, но регистрируем и любой эффект на первичном парном сравнении 901 вопроса. Контроль сравнивает числовые эффекты, число изменений порядка, изменений выбранного префикса и исхода Full Support. Проверяется и отдельная фиксированная панель из 24 внепилотных траекторий с авторской сборкой графа непосредственно по усечённому списку событий.

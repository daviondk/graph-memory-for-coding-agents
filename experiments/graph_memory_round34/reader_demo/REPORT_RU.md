# Что агент прочитает из памяти

[Открыть автономную демонстрацию](index.html). Один HTML-файл содержит все числовые данные восьми реальных вопросов и четыре работающих ранжировщика. Страница открывается с диска без сервера, сети или модели. Полнота и покрытие пересчитываются при каждом изменении бюджета (128–4 096 токенов). Переход к связанным отчётам требует исходного дерева файлов проекта.

## Сценарий показа

Кнопка **«Начать разбор»** проводит по четырём шагам с бюджетом 2 048. В первом случае графовый reader R33 с поправкой за стоимость доставляет 234/234 символа эталона. Он прочёл 22 фрагмента и потратил 2 005 токенов. Убираем поправку — порядок меняется, чтение останавливается после 19 фрагментов и 1 710 токенов, покрытие 0/234. Важный узел находится на 20-м месте с поправкой и на 21-м без неё, но граница доступного префикса тоже сдвинулась. При изменении бюджета видны обе стороны этого механизма.

Во втором случае обе модели читают по четыре узла на 2 016 токенов. С поправкой модель теряет эталон, без неё читает 137/137 символов. Здесь причина — **состав четвёрки**, даже при одинаковых длине контекста и числе фрагментов. На любом шаге можно выбрать узел в очереди, сопоставить вклады модели и посмотреть адрес его источника, положение эталона и первый узел, не поместившийся в контекст. [Исходный эксперимент](../../graph_memory_round33/budget_loss/REPORT_RU.md)

## Откуда примеры и что означают числа

На всех 2 000 вопросах ISETrace с seed 13 бюджетный reader вернул полный источник в **1 612 случаях (80,60%)**, исходный графовый — в **1 594 (79,70%)**. В 33 случаях добавление поправки помогло, в 15 навредило. В 1 579 случаях обе модели нашли весь источник, в 373 обе пропустили его часть. Для демонстрации отобраны два минимальных SHA-256 от строки `R34-reader-demo-v1|` и ID вопроса в каждой из четырёх групп. Панель из восьми специально представляет редкие выигрыши и потери; оценка эффекта опирается на полный знаменатель. Примеры иллюстрируют retrieval при одном обучении Dense-FT. В исследовательском отчёте отдельно приведён перенос на пять обучений и сравнение с R-GCN. [Исходы всех вопросов](../../graph_memory_round33/budget_loss/test-outcomes.json.gz) · [Пять обучений](../../graph_memory_round33/budget_loss/TRANSFER_RU.md)

Выдача пересчитывается по полной совокупности нативных кандидатов каждого примера, включая все фрагменты после первого превышения бюджета. В файле 1 826 записей кандидатов. Строка «Dense, калибровка ранга» показывает логит позиции по прежней калибровке R20. Значение косинуса показывается отдельно. Локальная форма объединяет роль, положение и длину фрагмента вместе со свободным членом. Абсолютные и относительные степени используют четыре типа отношений в двух направлениях. Бюджетная поправка использует позицию Dense, длину, роль и произведение роли с длиной. Столбцы с отключёнными компонентами помечаются в интерфейсе. В режиме «Dense и форма узла» коэффициенты остаются исходными, рёбра, процентильные вклады и бюджетная поправка выключаются. Это интерактивная абляция без переобучения. В режиме «Только Dense-FT» воспроизводится исходная выдача семантического ранжировщика. [Структурная модель](../../graph_memory_round33/relative_structure/REPORT_RU.md) · [Веса бюджетной модели](../../graph_memory_round33/budget_loss/models.json)

Поле события и ID узла представлены стабильными псевдонимами, границы фрагмента — оригинальными смещениями в символах. Исходные тексты инструментов и формулировки вопросов в HTML не включены. Эталон показан в отдельном блоке для проверки уже сформированной выдачи. Пересечение и объединение интервалов считаются только внутри одного поля события. Нативная политика останавливается перед первым целым узлом, превышающим остаток бюджета. [ISETrace, определения метрик](https://arxiv.org/html/2609.25913v3#S5)

## Независимая проверка

Скрипт проверки не импортирует генератор HTML. Он восстановил 3 910 типизированных рёбер через вторую реализацию проекции R21/R22, вычислил степени, средние ранги при связках, вклады всех 23 структурных признаков и четыре бюджетных слагаемых. Для обеих моделей R33 ранги совпали со всеми сохранёнными нативными позициями восьми примеров. Четыре ранжировщика и десять бюджетов дали 320 проверенных состояний. В каждом пересечение интервалов совпало со штатной функцией ISETrace. [Квитанция пересчёта](verification.json) · [Проверочные значения](ui-oracle.json)

Headless Chrome открыл конечный HTML через file://, сверил все 32 полных порядка и 320 состояний с независимыми числами. Проверены переключение модели, кейса и бюджета, фильтры, переходы между страницами и выбор узла, все четыре шага сценария и сброс. Зарегистрировано 0 внешних запросов и 0 исключений JavaScript. Визуально проверены снимки при ширине 1 380 и 390 пикселей, включая карточку формулы на мобильном экране. ## Воспроизведение

В исследовательской среде D из текущего каталога выполняются следующие команды. Для показа достаточно открыть index.html.

```powershell
$researchPy = 'D:/CodexResearch/x20-isetrace-e5-gpu/venv/Scripts/python.exe'
& $researchPy -B build_demo.py
& $researchPy -B verify_demo.py
node browser_check.mjs
```

Верификация комплекта требует только стандартной библиотеки Python: `python verify_manifest.py`. Браузерный тест запускает установленный Chrome, получает снимки и сохраняет их в qa. Генерация и независимый пересчёт используют прежние файлы проекта на D, зафиксированные хеши которых перечислены в квитанции. [Происхождение данных](source.json)

# Проверка на сильном исходном читателе

После оценки основной серии обнаружилось, что BGE по текущему состоянию опережает использованный RRF на dev и test. До запуска второго прогона задаём механический выбор основного ранга по 101 dev-состоянию между четырьмя неизменяемыми источниками (BM25, BGE по состоянию, BGE с адресами, RRF). Заранее фиксируем одинаковые λ, признаки, бюджетные отсечения, оба варианта роли, логику soft min/max, train/dev/test и кластеры. Все функции обучения и оценки повторно используем без изменения. Обновляются только ordinal rank и его замороженное преобразование в логит. Ключ rrf в автоматически сформированных результатах подпапки strong обозначает новый выбранный исходный ранг. Поле anchor.json хранит его действительное имя. Проверяем отдельно основную метрику и чувствительность к 2 048 токенам. Это последующая проверка на тех же состояниях, важная для интерпретации результата первичной серии.

# Протокол сравнения интервальных свидетелей

Гипотеза состоит в том, что обучение порога полного покрытия происхождения по минимуму из максимумов внутри альтернативных групп улучшит Full Support при бюджете 2048. Проверяем на ISETrace, с ранжированием по fine-tuned E5 seed 13, замороженным структурным смещением и четырьмя признаками R33. Сначала восстанавливаем нативные интервалы для обучающей панели из 196 вопросов. Учитываем неидентифицируемость, если примеров со взаимозаменяемыми узлами мало. Фиксируем до оценки теста.

На train строим группы источников для каждого элементарного интервала. Вложенные надмножества групп можно отбросить для порога полного покрытия. Сравниваем четыре альтернативы: опубликованные в локальном журнале R33 cost_worst и R34 hard cost_log, среднюю логистическую потерю по всем positive–negative парам с весом стоимости distractor, а также жёсткий порог по одному фиксированному на основании замороженного ранжирования свидетелю на минимальную группу. Основной новый метод разрешает самому ранжировщику выбирать лучшего свидетеля при обучении. Отрицательные примеры для всех новых функций одинаковы и не имеют пересечения ни с одним эталонным символом. Величину стоимости реально считанного префикса рассчитываем отдельно со всеми узлами.

Регуляризация 0.03 или 0.3, выбор по 580 dev-вопросам по Full Support@2048, затем Coverage@2048, затем более сильная регуляризация. Основной контроль — лучший на dev среди указанных контролей. Тестовый контраст ровно один, seed 13, 2000 вопросов. Порядок при равных баллах стабилен по исходной позиции Dense. Регистрируем исходы по всем вопросам, изменения покрытия и бюджетов 512/1024/2048, парный интервал с кластеризацией по траектории и положительные/отрицательные переключения. Результаты вторичного анализа на ранее использованном тесте.

Для нелинейного min-max фиксируем координатный выбор свидетелей, оптимизируем выпуклую подзадачу и повторяем до стабильности с максимумом 12 итераций. Начальные условия — нулевое, R34 hard cost_log и среднее по положительным. Выбор решения по точной обучающей целевой функции, без доступа к dev или test. Если доминирование делает подзадачи одинаковыми, фиксируем эквивалентность вместе с частотой действительно неоднозначных примеров.

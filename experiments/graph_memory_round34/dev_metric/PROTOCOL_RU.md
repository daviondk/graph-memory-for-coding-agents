# Сопоставление критериев выбора графового checkpoint

В штатных результатах R22 по каждой из двух архитектур сохраняется состояние, выбранное по dev Recall@5, а также сводная таблица метрик с отсечениями top-5/top-10 по эпохам. Оценка всех допустимых эпох по строгому бюджету требует порядка всех исходных единиц dev и их размерностей. Одинаковое значение Recall@5 не определяет долю ответов с полной поддержкой при 2 048 токенах. У первого seed в обеих папках есть ровно один best.pt и журнал 15 обученных эпох с начальными метриками. Прежние сохранённые состояния на dev500 также представляют только отдельных победителей.

Основная новая sensitivity-проверка повторяет обучение R-GCN после полной канонической GPU-очереди, с теми же весами Dense, парами обучения, порядком 580 dev, оптимизатором, seed и 15 эпохами. Callback считывает полные упорядоченные оценки всех dev-узлов из вычислений исходного trainer и сохраняет CPU-слепок каждой эпохи, включая 0 (16 состояний). Выбор на dev лексикографический по среднему Full Support@2048, затем среднему Coverage@2048, оба округлены до 12 десятичных знаков как в R33. При полном равенстве выбирается более ранняя эпоха. Выбор checkpoint отдельно для каждой модели и seed фиксируется до открытия test в дополнительном опыте. Параллельно сверяем, что исходный выбор по Recall@5 при повторении воспроизводится; при расхождении помечаем эффект повторного обучения и не приписываем всю разницу одному критерию. Сохраняем per-epoch dev-порядки, исходные идентификаторы, выбранные эпохи и основание выбора.

Для проверки механизма чтения берём только 580 dev-запросов и сохранённое состояние полного R-GCN seed13, выполняем прямой forward на CPU и сравниваем полный порядок по бюджетной метрике и по исходной нативной node Recall@5. Этот один контрольный срез проверяет валидность подключения к данным. Для полного эксперимента требуются десять обучений по 15 эпох с сохранением 16 состояний. Между собой сравниваем ровно два заранее заданных критерия. Test, метод R33, правила упаковки, пять seed и конечный критерий совпадают с парным протоколом.

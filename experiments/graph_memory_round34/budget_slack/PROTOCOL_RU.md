# Стоимость отвлекающих фрагментов относительно свободного бюджета

На входе уже обученные Dense-FT E5-base-v2 и графовый prior global_role из R33. Испытываем калибровку четырёх признаков ранга/стоимости по разному вкладу обучающих вопросов. Во всех вариантах задаются одинаковые L2=0,03 или 0,3 и гладкий минимум R33 (температура 0,25). Изменяются лишь веса вопросов. Ранее в R34/cost_push заменяли гладкий минимум на жёсткий и вид индивидуального штрафа. Там графики весов по запасу бюджета не проверялись. [R33](../../graph_memory_round33/budget_loss/REPORT_RU.md) · [TopPush](https://arxiv.org/abs/1410.1462)

**Основание.** Для модельной цели «все положительные PU» пусть P — их суммарная целая стоимость, N — стоимость всех отрицательных PU, A — стоимость отрицательных строго раньше последнего положительного в окончательном порядке с фиксированным разрешением связок. При префиксном чтении положительные помещаются тогда и только тогда, когда P+A≤B. Если P≤B, то L=B−P+1≥1 и 1[провал]≤A/L=(N/L) Σⱼ(cⱼ/N) 1[отрицательный j раньше последнего положительного]. В частности, вероятность провала по рандомизации ранга условно на данный вопрос не превышает min(1,E[A]/L). Независимость фрагментов не требуется. Когда P>B, прокси-полнота недостижима. Когда P+N≤B, она гарантирована. При непустом полном покрытии эталона всеми положительными PU провал нативного покрытия влечёт провал данной прокси-цели; перекрывающиеся альтернативные PU могут обеспечить полное нативное покрытие при недостающем положительном PU. P, N и A используются в обучении и аудите, ранжировщик получает только прежние признаки.

**От строгой границы к обучению.** Пороговая потеря с точным минимумом мажорируется softplus(sⱼ−min sₚ)/ln 2, включая консервативный учёт связок. Нормированный softmin R33 находится не ниже точного минимума, поэтому его логистический штраф без добавки τ log m не обязан быть мажорантой. Сохраняем исходный штраф во всех сравнениях. Граница мотивирует форму веса вопроса, теоретического сертификата для обученного или усечённого риска не заявляем.

**Регистрация до рассмотрения dev/test результатов.** Только известные train-стоимости использованы при записи протокола: 196 вопросов, 13 тривиально помещаются, 0 случаев P>B. На нетривиальных вопросах используем r=N/(B−P+1), B=2048. Два варианта — sqrt(r) и r/(1+r). Контроль той же размерности и формы использует только N/2048; дополнительные контроли — равный вес по тем же нетривиальным вопросам и исходный R33 по всем вопросам. Для всех маскированных вариантов вклад тривиальных и недостижимых прокси примеров нулевой. Все веса нормируются на сумму, центр и масштаб четырёх признаков вычисляются по прежним R33 train-строкам одинаково во всех случаях. Публикуются необработанные P,N и эффективный размер выборки по весам.

Выбор внутри семейства запаса и семейства длины делается на всех 580 official dev по FS@2048, затем Coverage@2048, затем в порядке soft (r/(1+r)), sqrt, больший L2. Для равновесного контроля выбирается L2 по тому же правилу; для исходного R33 сохраняется прежний выбор cost_worst_0.03. Сильнейший контроль среди R33, равных, длины определяется тем же дев-критерием. Заранее записывается один первичный контраст выбранной адаптации к запасу против сильнейшего контроля при усреднении всех пяти training seed на одних и тех же 2 000 вопросах. Веса прогноза с seed13 замораживаются для seed 17/29/37/41. Отдельно публикуются seed13, четыре дополнительных seed и контроль только по N при тех же преобразовании и L2. Все тестовые порядки фиксируются до загрузки gold-координат. Парные bootstrap-интервалы по траекториям, 10 000 повторений, seed 13. Остальные метрики — Coverage@2048, Span Recall@5 и MRR. Любой исход сохраняется; прежние оценки исходного теста уже многократно использовались. [ISETrace](https://arxiv.org/abs/2609.25913v3)

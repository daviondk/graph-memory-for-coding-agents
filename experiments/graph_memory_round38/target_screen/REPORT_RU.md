# Отбор независимой задачи и проверка оценщика VibeMemBench

Для PyBaMM-4267 воспроизведён контрольный переход с 0/1 до 1/1 на FAIL_TO_PASS (F2P). Все 7/7 регрессионных PASS_TO_PASS (P2P) проходят в обоих состояниях. Официальная функция оценивания VibeMemBench вернула false на исходном коде и true на эталонном патче. Эксперимент устанавливает пригодность одной задачи для проверки патчей. Эффект памяти, качество конкретной модели и уровень SOTA по этим двум контрольным запускам оценить нельзя.

## Как отобраны цели

Из 111 целевых задач публичной ревизии VibeMemBench сформирован порядок по SHA-256 с фиксированным ключом. По предварительному протоколу просмотрена 21 задача до появления двух подходящих задач из разных репозиториев. В журнале screen.json перечислены причины пропуска всех предшествующих кандидатов. По каждой из двух целей проверены три отдельные архивные траектории. Их содержимое совпало с контрольной суммой объекта Hugging Face, коммит принятой правки предшествовал целевой базе по графу Git, точные идентификаторы целевой задачи в тексте не найдены. Эти проверки подтверждают происхождение и часть хронологии. Семантическое совпадение решений остаётся возможным. ## Измерения на PyBaMM

| Условия | Патч | F2P | P2P | Точное совпадение набора PASSED по исходному оценщику |
|---|---|---:|---:|---|
| Базовые пакеты, pytest без xdist-процесса | Пустой | 0/1 | 7/7 | Нет |
| Те же | Эталон | 1/1 | 7/7 | Нет |
| Добавлены JAX и библиографические зависимости, pytest без xdist-процесса | Пустой | 0/1 | 7/7 | Нет |
| Те же | Эталон | 1/1 | 7/7 | Нет |
| JAX и библиографические зависимости, штатный xdist с одним процессом | Пустой | 0/1 | 7/7 | Нет |
| Те же | Эталон | 1/1 | 7/7 | Да |

В полном тестовом файле девять тестов. С установленным JAX дополнительный тест вне восьми зарегистрированных ID штатно пропускается. В режиме без процесса xdist живая запись логгера делит строку pytest на две, а парсер авторов ошибочно извлекает из второй строки имя «[». Это объясняет расхождение метрики при корректных статусах восьми тестов. Первые четыре запуска сохранены как диагностика выбора окружения. Для сравнения методов фиксируется последняя пара с параметром --paper-extras. Количество xdist-процессов ограничено одним через штатную настройку, оба условия используют идентичную конфигурацию. Ни один строковый статус перед передачей оценщику не редактируется. [Исходный оценщик авторов](https://github.com/AlibabaResearch/DAMO-ConvAI/tree/7152cf96809b45343ccc1caf7115a7d3fa43f956/VibeMemBench/scripts/vendor)

Контрольные измерения выполнены на Windows CPU, Python 3.10.20. Для каждого прогона заново извлекается закреплённый архив PyBaMM, проверяется импорт из свежего дерева, применяется оригинальный тестовый патч и исполняется тестовый файл целиком. Модули исходного оценщика получают фактические код завершения и текст вывода этой команды. Повторное извлечение статусов из JUnit независимо подтвердило все восемь тестов. Совпадение двух контрольных вердиктов проверено в этом окружении. Официальный OCI-образ объёмом 1 715 939 708 байт в сжатом виде превышает предусмотренный для данных предел 700 MB, поэтому побитовое воспроизведение авторского Linux-окружения остаётся открытым.

Выходные JSON с префиксом native содержат результат оценщика, раздельные F2P и P2P, статусы по каждому ID и SHA-256 патча, оценщика, тестовой правки, вывода и JUnit. Файлы с префиксами stock и extra сохраняют диагностические запуски предыдущей ревизии оболочки. Каждый файл, вошедший в отчёт, перечислен в manifest.json.

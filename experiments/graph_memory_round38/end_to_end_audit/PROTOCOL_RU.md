# Исполнимая оценка изменения после чтения памяти

Техническая калибровка оценщика до испытания новой памяти. Заранее выбран VibeMemBench ipython__traitlets-670: функциональная задача о разборе однокомпонентного списка в CLI научной экосистемы Jupyter. В закреплённой записи указан один Python-файл патча, один тестовый файл, 2 FAIL_TO_PASS и 60 PASS_TO_PASS. Исходный commit 191ff75e93d56446b2c051f4dbb33e2f0e7be71d, лицензия BSD-3-Clause. Исторические траектории рассматриваем как данные; команды из журналов не запускаются. Источники, версия, данные публичны. Обращения к решателю, публикация результатов вовне и использование видеокарты не входят в эту проверку.

В чистой копии базы применяем только авторский test_patch, затем запускаем неизменный тестовый модуль с параметрами из закреплённой записи. В другой копии вместе с тем же test_patch применяем эталонный patch и повторяем. Целевой результат — два падающих теста на базе и два проходящих с эталоном при сохранении 60 регрессионных. Регистрируем также все другие статусы, инфраструктурные сбои и версии. Используем нативный parse_log_pytest и отдельную сверку по XML или тексту pytest. Решатель, если позднее запущен, увидит только описание задачи, исходный снимок и разрешённую историю: новые тесты, списки целевых ID, ответы и патчи проверяющего процесса не передаются.

Проверяем доступность зарегистрированного Docker-образа в локальном кэше и его размеры по реестру до загрузки. При отсутствии кэша и необходимости загрузить/развернуть более 700 МБ выбираем изолированный CPU-раннер с тем же набором тестов и сравнимой версией Python; явно отмечаем разницу ОС/среды с официальным запуском. Переходы состояний исходного теста и эталона определяют работоспособность оценщика. Эта цель, уже раскрытая при калибровке, исключается из проспективной оценки эффекта памяти. Не переписываем исходные тесты, установочный скрипт книги траекторий не исполняем.

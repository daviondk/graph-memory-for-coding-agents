# Как оценить память кодового агента по работающему исправлению

На публичной задаче VibeMemBench из репозитория Jupyter traitlets воспроизведены оба контроля исполнимого оценщика. Один и тот же тестовый модуль запускался в Windows и Linux. Для будущего сравнения решателей подготовлены независимые входы и 331-байтная память о местах предыдущих чтений. Здесь приведены результаты калибровки. Единица результата для оценки пользы памяти — новая задача разработки, целиком решённая агентом.

## Результат калибровки

| Код, поданный в оценщик | Новые целевые тесты пройдены | Регрессионные тесты пройдены | Вывод |
|---|---:|---:|---|
| Исходный публичный снимок до применения авторских тестов, Windows | оба отсутствуют | 60/60 | проверена исходная батарея |
| Исходный код с авторскими тестами, Windows и Linux | 0/2 | 60/60 | задача остаётся открытой |
| Эталонное изменение с теми же авторскими тестами, Windows и Linux | 2/2 | 60/60 | задача решена по критерию авторов |

Грейдер принимает произвольный зафиксированный дифф исходного кода в формате Git. При успешном запуске он возвращает SHA256 патча, статусы всех тестов и признак точного совпадения множества прошедших тестов с эталонным. В Windows результаты штатного текстового парсера совпали с JUnit XML из отдельного запуска для всех условий. В Linux прошли две отдельные проверки. Временный контейнер реально выполнил тесты под непривилегированным пользователем. Затем опубликованная функция evaluate_instance пересчитала результат по полному выводу обоих запусков. Ложное применение патча в первой проверке Windows выявилось по неизменному хешу исходника. После создания отдельных Git-корней успешность применения проверена по фактическим изменениям файлов.

**Сопоставимость окружения.** Задача, commit, авторские тесты, аргументы pytest, идентичности регрессионных тестов, эталон и функция разбора совпадают с релизом. Для опубликованного образа измерено 447,8 МБ сжатых слоёв, нижняя граница раскрытых tar-слоёв составляет 1180,2 МБ. Под установленный лимит развёрнут отдельный Linux amd64 образ Python 3.10.20 и pytest 7.4.4 (330 МБ по docker system df -v). Нативная доставка патчей через host bind mount на этой машине была отклонена Docker Desktop. Рабочий грейдер доставляет два артефакта через stdin в одноразовый контейнер без сети. Таблица устанавливает совпадение исходов на одном экземпляре. Время инференса, зависимости других проектов и оригинальный образ целиком здесь не измерялись. [Опубликованный оценщик](https://github.com/AlibabaResearch/DAMO-ConvAI/blob/7152cf96809b45343ccc1caf7115a7d3fa43f956/VibeMemBench/scripts/vendor/eval.py)

## Что именно может получить решатель

Оба участника получают одинаковые 63 файла базового коммита без базы Git и дословное поле problem_statement. Экспорт проверяет множество файлов и побайтовое содержимое каждого. Тестовая разметка, ID ожидаемых результатов и оценщик находятся отдельно. Лицензия базового кода BSD-3-Clause, лицензия релиза VibeMemBench Apache-2.0. [Исходный снимок](https://github.com/ipython/traitlets/tree/191ff75e93d56446b2c051f4dbb33e2f0e7be71d) · [Лицензия](https://github.com/ipython/traitlets/blob/191ff75e93d56446b2c051f4dbb33e2f0e7be71d/COPYING.md) · [Версия набора](https://huggingface.co/datasets/Tongyi-ConvAI/VibeMemBench/tree/11164976b4f920cdb0d0cd570ca572e49acea1e8)

В полном каталоге истории traitlets опубликованы 18 траекторий. Одна относится к самой цели и ещё пять идут позже. Для этой проверки использованы только PR 264, 274, 293, 306, 319, 332, 517, 613, 615, 619, 629 и 630. Все 12 базовых и все 12 merge-коммитов являются предками целевого снимка по Git. Файлы ранних траекторий, суммарно 5 579 842 байта, прошли проверку по идентификаторам blob закреплённой публичной версии. Тексты остальных шести траекторий не загружались для этой проверки. Стабильные Git patch-ID полных изменений Python-реализации в предшествующих PR отличались от целевого во всех 12 случаях. Близкие подзадачи при этом возможны. [Дерево публичного корпуса](https://huggingface.co/datasets/Tongyi-ConvAI/VibeMemBench/tree/11164976b4f920cdb0d0cd570ca572e49acea1e8/history/python/ipython__traitlets)

Поиск явных упоминаний идентификаторов целевых issue и PR дал 0 из 12 историй. Вход содержит сохранённые позднее реконструкции работы агента. Для компактной памяти из структурированного поля аргументов инструментов механически извлекаются только адреса Python-файлов в командах чтения, встречающиеся и в прежнем, и в текущем публичном дереве. Проверено 1286 сообщений в 12 историях. После отсева тестов и неоднозначных команд получилось 220 пар «простой запрос чтения — путь». Агенту с памятью можно передать шесть наиболее часто встречавшихся адресов и их частоту. Пакет исключает текст исходников, результаты инструментов, запросы поиска, рассуждения и исходы задач. Подсчёт частоты отражает действия записи, успешность вызова отдельно не проверена. Это бюджетный контроль межзадачной навигационной памяти. Сам по себе он не проверяет вклад рёбер графа, истории версий или преимуществ проактивной выдачи.

## Граница вывода и следующая проверка

Техническая калибровка здесь включает ноль эпизодов работы решателя. Регрессионные тесты одной задачи не являются независимыми повторностями сравнения памяти. Индивидуальные новые решатели со скрытыми тестами на этой же задаче позволят проверить работоспособность полного контура. Ранее разработчик оценщика уже видел эталон, поэтому выбор методики по этому примеру делает результат разведочным.

Для следующего подтверждающего испытания по идентификаторам и открытым формулировкам отобраны две доступные цели: pallets__click-1915 о регистрации названия команды и python-attrs__attrs-1372 о композиции преобразований значений. До настройки метода следует зафиксировать всю будущую панель, исполнителя, бюджеты чтения и генерации, допустимые предшествующие снимки и память. Нужны отдельные чистые копии, отсутствие обратной связи по скрытым тестам до фиксации обеих правок, качество в парах для каждого репозитория, число шагов/прочитанных токенов с учётом построения памяти и учёт срывов исполнения. Два предлагаемых экземпляра подходят для наладки, а оценка качества уровня всей публикации требует более широкой заранее определённой панели. Сводную таблицу лидеров можно сопоставлять только после воспроизведения того же набора, решателя, контролей и правил допуска задач.

# Вторая сквозная задача кодового агента

На официальной задаче PyBaMM-4267 из VibeMemBench три независимо запущенных исполнителя Codex получили разные патчи. При внешней проверке каждый прошёл 1 из 1 целевых и 7 из 7 регрессионных тестов. Авторский строгий критерий точного совпадения множества прошедших тестов дал успех всем трём патчам. На исходном коммите он дал отказ, на авторском патче — успех. Это второй репозиторий после traitlets, где дополнительная память сохранила качество, а исполнитель с пустым контекстом достиг того же результата. [Сырые итоги](results.json) · [Калибровка оценщика](../target_screen/REPORT_RU.md) · [Первая задача](../solver_pilot/REPORT_RU.md)

Общий разведочный агент сделал восемь обращений, увидел 19 292 байта и выбрал четыре диапазона исходного кода. Пустая выдача обходится без этого этапа при самостоятельном применении. Исполнители имели чистые рабочие каталоги, одну постановку, одинаковые лимиты и пустую историю диалога. Во всех случаях изменения затронули поиск параметров в двух модулях PyBaMM. Предварительный выбор задачи зависел от воспроизводимости базового результата и наличия истории. Точные веса и версия сервиса Codex в окружении исполнителей не зафиксированы. [Протокол](PROTOCOL_RU.md) · [Запечатанные пакеты](packets.json) · [Хеши патчей до оценки](solve-seal.json)

Каждый исполнитель дважды вызвал открытые тесты и оба раза получил ошибку конфигурации из-за недоступности pytest-mock и pytest-xdist. Все три внешние проверки впоследствии прошли до конца в отдельном окружении Windows CPU с зависимостями, согласованными с опубликованной конфигурацией, включая JAX и один рабочий процесс xdist. Совпадение исходов на двух объектах и один запуск на условие оставляют величину влияния памяти на вероятность решения неопределённой. Меньший вывод инструментов в отдельной попытке также зависит от выбранных запросов. [Проверка трёх журналов и JUnit](verify.py) · [Исходная лицензия](SOURCE_LICENSE.md)

Для проверки опубликованных данных запустите `python -B verify.py` из этой папки. Для повторного исполнения используйте `grade_patch.py --paper-extras --patch <абсолютный путь к diff> --out <новый JSON>` из соседнего каталога target_screen. Для сопоставления доступны точные правки и полные наблюдения каждого исполнителя. [Воспроизведение окружения](../target_screen/REPRODUCE_RU.md)

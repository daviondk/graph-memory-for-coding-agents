# Можно ли увидеть устаревшее содержимое в квитанции редактора

Известны исходные характеристики R37, включая пять неверно перенесённых строк в дополнительных строгих окнах и отсутствие ошибок в основной строгой части. Эта диагностика повторно использует те же открытые траектории. До открытия наблюдений следующего чтения фиксируем выборку всех 1 282 эпизодов, основную ошибкосодержащую подвыборку из дополнительных строгих окон и раздельные результаты для всех четырёх групп. Проверяется ограниченный доступный на записи сигнал; оценки не предназначены для подтверждения переноса на новые проекты.

У каждой старой видимой строки вне заменённого интервала есть предполагаемое новое положение: до интервала номер сохраняется, после интервала прибавляется разность числа строк δ. Если адрес находится также в видимой квитанции, сравниваем хеши. При совпадении есть подтверждающий свидетель, при несовпадении — конфликт. Начало правки, которое нельзя локализовать, оставляет только факты квитанции. Целые строки внутри заменённого диапазона исключаются. Сигнал вычисляется после локализованной правки по данным переданного в R37 ограниченного префикса, без следующего наблюдения и служебных полных снимков.

Контроль воспроизводит стандартный перенос T, приоритет квитанции и 128 слотов. **Side** снимает уцелевшие старые факты с каждой стороны, где найден конфликт. **Local** снимает старый факт, только если ближайшие сопоставимые свидетели с его стороны все конфликтуют и до них не более восьми строк включительно. При равном расстоянии и смешанных исходах факт сохраняется. Новые строки квитанции всегда сохраняются. Фильтрация применяется после выбора исходных 128 фактов и не заполняет освободившиеся слоты. Для обеих политик строится контроль равной ёмкости: удаляется ровно то же число старых уцелевших фактов по независимому от хешей содержимого фиксированному порядку SHA-256(идентификатор эпизода,номер строки). Добавочный случайный ориентир — ожидаемое число снятых правильных и неверных при равномерной выборке такого размера среди всех уцелевших старых фактов. Политики рассчитаны на одной и той же выдаче.

Первичный диагностический потолок — доля проверенных неверных фактов T, для которых на момент записи был виден конфликт хоть где-нибудь и факт пришёл из старого чтения. Дополнительно показываем потолок по своей стороне, ошибки самой квитанции, сколько правильных наблюдений теряется, и сколько ошибочных фактически сняли политики. Знаменатель — ошибки T на адресах, действительно доступных следующему просмотру. Нулевой знаменатель помечаем отдельно. По задачам вычисляем число правильных и неверных строк относительно всех видимых строк, агрегируем вначале внутри задачи, затем поровну по задачам. Для разностей — 10 000 парных перевыборок задач с фиксированным seed 38199. Числа эпизодов, свидетелей и адресов отражают разный масштаб. Непроверенные будущим чтением адреса не считаются ни верными, ни ошибочными. Промежуточное непрозрачное действие после правки может изменить текущее состояние и испортить даже свежий ответ редактора. В этой серии такие будущие действия используются только для интерпретации.

Сначала запишем и захешируем сигналы и конкретные прогнозы всех политик, затем отдельно загрузим размеченное следующее чтение и воспроизведём старую политику T побайтовым сравнением списка адресов и хешей. Проверим синтетические случаи со сдвигом обоих знаков, свежей квитанцией, совпадающими и конфликтными свидетелями и разрывом между свидетельствами.

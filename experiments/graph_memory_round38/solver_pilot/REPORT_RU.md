# Изменяет ли передача наблюдений исход реальной задачи кодового агента

На задаче VibeMemBench `ipython/traitlets` три независимых агента Codex создали три различных патча. **Каждый прошёл 2 из 2 целевых тестов и сохранил 60 из 60 регрессионных.** Без изменений исходник проходил 0 из 2 целевых и 60 из 60 регрессионных. Это первый сквозной пилот данной серии с результатом, проверяемым исполнением кода. Улучшение от памяти в этом испытании не наблюдалось. |---|---:|---:|---:|---:|---:|---:|

Вопрос касался значения командной строки для списка с одним элементом. Каждому исполнителю передали официальный текст, одинаковое чистое дерево закреплённого коммита и максимум 18 обращений к одному интерфейсу. Каждый менял только `traitlets/config/loader.py`. Первое изменение во всех трёх случаях стало итоговым патчем. Оставшиеся действия ушли на проверку. Колонка «байт» учитывает реально показанный текст инструмента в UTF-8. Токены внутреннего рассуждения, вся стоимость сервиса и CPU-время среды в неё не входят. [Три замороженных патча и суммы](solve-seal.json)

## Как передавали память

Отдельный исследователь Codex с пустой историей получил лишь исходную задачу и доступ к поиску и чтению. Он выполнил восемь действий и увидел 18 278 байт вывода. До запуска любого решателя зафиксированы четыре наблюдения о разных ветвях разбора параметров с точными интервалами строк. Автоматическая проверка допустила только существующие строки из фактического вывода общего исследователя. Сначала в пакет вошли адреса и проверяемые замечания, затем — целые выдержки кода в пределах 1 600 байт. Из конца того же журнала сформировали второй пакет равного размера. В пустом условии предыдущий контекст полностью потерян, общая предварительная работа исследователя одинакова для всех трёх вариантов. [Оба фактических пакета](packets.json) · [Правило отбора и хеши до запусков](pack-seal.json)

Исполнители стартовали с пустой историей чата на отдельных копиях исходника, с одним шаблоном задания и унаследованными моделью и настройками Codex. Идентификатор внутреннего снимка сервиса и воспроизводимый seed сэмплирования не предоставлялись. Общий файловый хост означает процедурное разграничение. Доступ через журналируемые инструменты ограничивался собственной копией, скрытые проверки хранились отдельно. Патчи всех исполнителей зафиксированы до первого обращения к скрытому оценщику. В журналах нет изменений других файлов. Два вида памяти имеют одинаковую длину и различное содержание; сравнение также включает работу исследователя по выбору наблюдений и формулированию замечаний. [Исходный протокол](PROTOCOL_RU.md) · [Шаблон задания](SOLVER_PROMPT.md)

Оценщик запускал кандидаты в изолированных Linux-контейнерах без сети, применяя штатный тестовый патч к чистой базе и штатный парсер pytest. Контейнер использовал компактное окружение CPython вместо исходного образа бенчмарка. Полный список 62 проверенных идентификаторов и исход каждого теста сохранены для каждой версии. В исследованиях использованы обычные кодовые субагенты Codex; GPU-модель Qwen в этих трёх решениях не участвовала. ## Что ограничивает вывод

Одна задача, один исполнитель на условие, открытый старый проект. Нельзя отделить вариативность генерации и потенциальную знакомость модели с кодом от влияния памяти. Пилот показывает возможность честно проверить использование памяти в составе полного решения, а также случай, где исполнитель самостоятельно находит нужные места и дополнительный контекст не сокращает число обращений. Это испытание передачи контекста между агентами. В нём нет независимой оценки эффекта конкретного оператора переноса после правки или подтверждения преимущества на всём VibeMemBench.

Параллельные чтения в шлюзе иногда получали одинаковый порядковый номер, поскольку счётчик снимался до исполнения действия. Число действий перепроверено по всем исходным завершённым записям. Ни один исполнитель не вышел за предел 18. Порядок строк журнала определяется завершением записи, в том числе для хронологического контроля. У каждого исполнителя один запрос завершился диагностикой шлюза. В одном широком локальном запуске открытых тестов встречалась ошибка проверки строкового представления перечисления. Измеряемые 62 скрытых теста у всех трёх патчей полностью совпали с эталонным исходом. [Автономный аудит](verify.py) · [Лицензия исходного кода traitlets](SOURCE_LICENSE.md)

Для независимой сверки сохранённых исходов выполните `python verify.py` из этой папки. Для повторного применения патча используйте `grade_patch.py --patch <файл.diff> --out <отдельный-результат.json>` из дочернего проекта воспроизведения тестового окружения.

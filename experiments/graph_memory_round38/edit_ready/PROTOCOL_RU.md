# Удержание текста для следующей замены

Регистрация до извлечения новых целевых строк или вычисления метрик. Корпус — закреплённая в R31 и R37 выборка Handoff Debt, без смены политик допуска. Основная популяция — первая в каждом основном прогоне (predecessors/main_takeovers) подтверждённая уникальная непустая str_replace рабочего Python-файла после явно показанных пронумерованных строк того же пути в текущем непрерывном интервале. Другие попытки записи этого пути очищают прежние строки. Непрозрачный инструмент, повреждение события или известный разрыв индексов очищают весь кэш. Между началом целевой операции и подтверждением не допускаем непрозрачность или пересекающуюся запись того же пути. Связь устанавливаем по индексу действия, ID инструментов и пути. По закрытым old_content/new_content подтверждаем ровно одно вхождение old_str и точное единственное изменение. Не считаем пробельные замены. Отдельно опишем повторные подходящие операции в этих же запусках и первые в дополнительных запусках тех же issue. Учитываются только явно наблюдавшиеся инструментальные view, успешные действия редактора инвалидируют путь. Квитанции, terminal, гипотезы агента и закрытые поля не пополняют текст.

Момент предсказания — перед каждой попыткой записи, без её аргументов: в онлайн-кэше уже выбраны адреса среди ВСЕХ виденных путей. Правила не получают тип предстоящей записи, путь, номер строки, old_str, размеры правки, before/after или будущий успех. В момент текущего view им доступны только путь, границы показанных строк, их текст и прошлая память. Для масштаба хранения используем модель ключа (идентификатор пути 8 байт, координата 4, признак наблюдаемого окончания 1) плюс UTF-8 данного текста. Это логический объём полезной нагрузки; журналы доказательств с хешами и внутренние накладные расходы машины не входят. Честные общие бюджеты — 16/64/128 сохранённых строк и отдельно 2048 байт с указанной моделью адресов и текста. Для каждого ограниченного варианта допускается только его собственный кэш плюс последний просмотренный путь и диапазон (постоянный объём метаданных). Очевидный полный контроль хранит все ранее виденные строки той же чистой версии.

Все политики предпочитают последний по времени view, вытесняют старые записи и сохраняют их при наличии свободного места. Внутри view порядок tail (чистая давность относительно порядка показываемых строк), head (начало непрерывного блока), center (центр, затем ближайшие), grid (равномерное распределение по видимому диапазону через рекурсивное деление), focus (если предыдущий view был по тому же пути, сначала окрестность центра пересечения; иначе центр нового). Исключить из использованного кэша старую версию адреса, когда новая строка больше бюджета. Вторичный анализ стоимости — число удержанных строк и среднее число модельных байтов. Правила фиксированы, обучение или выбор после оценки не предусмотрены.

Первичный исход — достаточный сертификат для воспроизведения буквального old_str в реальном месте замены: каждый затронутый номер содержит точный текст исходной строки перед этой операцией и для каждого потреблённого перевода строки ранее показана непосредственно следующая строка в одном ответе. Неполные первая/последняя строки в old_str входят через полную исходную строку; это достаточное, консервативное условие для генерации фрагмента при известных границах. Разметка и адрес для проверки доступны исключительно оценщику. Вторичные исходы — доля затронутых строк с сертификатом, стоимость и потолок полного кэша, причины неполноты. Сравнение подтверждает только поддержку фактического адреса и фрагмента, не выбор агентом требуемого файла и не исправление задачи. В данных доступно лишь подмножество действий редактора с подтверждённой уникальностью.

Первичный контраст — focus против tail при 64 строках, разность полных сертификатов в п.п., парное макро по issue. Привести абсолютные результаты всех политик при всех бюджетах, вторичные срезы и 95% процентильный интервал 10000 парных bootstrap по целым issue, seed 380671. При одинаковых результатах регистрируем нулевой эффект. Заранее разрешаем обработку исходных строк только в памяти; сохраняем хеши, номера, длины, списки/сводки без прикладного текста. Отдельно сверить последовательность наблюдаемых адресов с подписанным R37. Меняющиеся технические детали разборки записываем явно.

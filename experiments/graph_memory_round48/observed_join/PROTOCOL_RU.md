# Связь наблюдаемых FEEDS с доступными источниками пакета ISETrace

До совмещения с исходами фиксируем все 40 запросов из подписанной панели R39/provenance_packet_demo, по одной траектории на запрос. Исходная нагрузка — все закрытые группы соответствующих траекторий из ранее опубликованного R44/sql_flow/normalized.json.gz. Главный знаменатель — все их границы, включая пустые, отдельно — границы с ненулевым чистым изменением числа исходящих свидетельств у двух или более различных производителей. Учитываем положительные и отрицательные поправки, агрегируя всю транзакцию. Частота относится к отобранным траекториям.

Связываем две независимо именованные проекции только по исходному ID траектории. Проверяем исходные сохранённые SHA256, SHA256 исходной строки архива по R39, номер строки fixture в порядке SHA256('sql-flow-v1/'+id), байтовый диапазон и хеш массива этой траектории внутри распакованного R44. Повторно разбираем записи штатным адаптером исключительно как данные. Проверяем направленную пару, знак и кратность каждой дельты по каждой группе, полный флаг и число групп. Отдельно проверяем точную последовательность операций внутри каждой группы, так как исходный сериализатор обходил Python set. Порядок внутри одной транзакции не влияет на численность после неё. Ошибка мультимножества, флага, идентификатора, источника или байт не допускается.

Производитель — локальный порядковый номер tool_call R44, сопоставленный с тем же call_id у события tool_output. Строгий источник — SHA256 компактного JSON-массива [event_id результата, "/content"], с той же кодировкой, что в R39. Аргументы вызова имеют собственный event_id и "/raw_arguments"; даже совпадающий call_id не делает их источником результата. Для каждого origin R39 устанавливаем роль, поле, позицию сообщения, символьную длину и хеш полного текста; сверяем границы всех spans. Сырые тексты, исходные идентификаторы, значения свидетельств, команды и оценочные метки в результаты не попадают.

До границы видим события по конец предыдущей закрытой группы включительно; после — по конец текущей. Нулевая граница пуста. Источник доступен по времени после наблюдения события, кандидат — после наблюдения всех его непустых исходных полей. Кандидаты без устанавливаемых по spans источников считаем отдельно и исключаем из временного пула. Для каждого производителя различаем наблюдаемость до/после, наличие кандидатной строки точного поля результата, наличие только поля аргументов того же вызова и отсутствие обоих. Для группы измеряем, представлены ли не менее двух изменившихся производителей точными результатами до/после; дополнительный строгий показатель — результаты как минимум двух уже присутствуют в выбранном пакете до/после. Для состава пакета выполняем оптимизацию по доступным к этому моменту кандидатам R39 при замороженных терминальных рангах и Q32-полезностях, с бюджетом 2048, префиксом до 1024 и правилом strict >. При полном снимке сверяем весь список с опубликованным нулевым пакетом. Отдельно отмечаем, что этот ретроспективный селектор не восстанавливает реальный исторический запрос памяти или причинный онлайн-ранг.

Основной результат — числитель и знаменатель для двух различных производителей, строго сопоставленных с кандидатами результата уже до границы. Показываем также доли среди всех границ, среди совместных изменений, по траекториям и после границы. Двусторонние 95%-интервалы считаем по 10 000 выборкам с возвращением целых траекторий, seed 48017, отношение заново суммированных числителей и знаменателей. Пары считаем исчерпывающе, не считаем независимыми репликациями. Если пересечение или число подходящих наблюдений мало, сохраняем результат.

Отдельный проверяющий алгоритм проверяет проекцию без исходных текстов, повторяет агрегирование пар и принадлежность источников кандидатам и выбранным пакетам. Выход для следующего анализа содержит q, шаг, локальный ID производителя, до/после чистого числа исходящих свидетельств, SHA точного поля результата, технические ID доступных источников и выбранные ID. Это изменения наблюдаемой поддержки в архиве. Изменения пользовательского доверия, поведение агента при чтении и качество ответа данным дизайном не измеряются.

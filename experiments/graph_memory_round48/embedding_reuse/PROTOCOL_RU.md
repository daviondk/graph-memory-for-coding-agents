# Кеш эмбеддингов между состояниями кодового агента

Включаем те же 101 + 204 состояния Cal500. Основная величина — какой процент всех входных токенов Qwen (документы плюс всегда заново кодируемый запрос) можно сэкономить только за счёт прежде закодированных документов из более ранних состояний той же траектории. Вторично считаем экономию от устранения повторов внутри запроса, суммарную экономию, количество обращений, объём векторов и показатели отдельно на двух репозиторных панелях. Выбор документов ограничен предоставленным SERBench пулом. Это последовательное обслуживание фиксированного набора запросов к памяти. В самих сохранённых исследованиях агенты не запускали этот кодировщик.

**Строгая причинная история.** Перед выдачей доступны только более ранние состояния той же панели, repo, issue, base_commit и run_id. Вся история событий предшественника должна быть точным строгим префиксом истории текущего запроса. Сверяем SHA-256 канонической записи каждого события. У предшественников с одинаковой историей сохраняем один детерминированный представитель (минимальный SHA-256 идентификатора с солью r48-representative). Состояния с одинаковым префиксом не согревают кеш друг друга. Инвентаризуем step_id и наличие реальных временных меток. Отдельно рассматриваем порядки по номеру шага, по хешу и обратный, включая равные шаги, внутри той же траектории. Порядок по хешу иллюстрирует поведение кеша, хронологией он не является. Кеш по умолчанию не пересекает issue и коммиты.

**Ключ и контроли.** SHA-256 от отпечатка модели/токенизатора, схемы входа, ограничения 511 + EOS, pooling, backend и канонических целочисленных token IDs фрагмента. Строка включает путь и содержание. Совпадение токенов проверяем в дополнение к совпадению дайджеста. Повтор с изменённым параметром модели проходит через отдельное пространство ключей. Строим те же журналы для полного текста входа, evidence_id, пути и пути с координатами. Для каждого слабого ключа явно считаем случаи, где он предложил повторное использование при разных входных token IDs, без влияния округления эмбеддингов. Результаты для ограниченной ёмкости 32 и 128 векторов LRU и максимальной ёмкости дополняют оценку доступного выигрыша. Парные 95%-е процентильные интервалы по 20 000 перевыборкам целых репозиториев (seed 48052) для доли сэкономленных токенов, без превращения числа кандидатов в число независимых наблюдений.

**Аппаратная проверка.** Из всех траекторий с парой строго последовательных доступных префиксов берём до восьми пар разных репозиториев, определяем порядок по хешу с солью r48-gpu-pair, без сведений о кеш-попаданиях и качестве. Если таких пар менее восьми, проверяем все доступные разные репозитории. Дважды обслуживаем каждый двухшаговый запрос на той же GPU и версии Qwen3-Embedding-8B Q4_K_M, один раз с новой обработкой каждого вектора, другой с реальным переиспользованием точных векторов. Порядок двух режимов чередуется по номеру пары, модель заранее прогревается. Сравниваем фактические обработанные токены и время вызовов кодировщика, отклонения векторов и косинусных оценок, состав и порядок top‑5/8, исходные опубликованные ранги из R45/R47. Одинаковые токены задают один математический вход; CUDA-квантизация, пакетирование и порядок вычислений могут дать численные различия. Выводы о сохранении качества ограничены измеренным поднабором.

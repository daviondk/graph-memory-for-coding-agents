# Проверка результатов

Числовая проверка: с NumPy запустите `python -B verify.py`. Сторонние тексты для неё не требуются. Ординалы сохраняют равенства элементов, предыдущие события, границы задач и стоимость. Проверка отдельно воспроизводит совпадения и ложные попадания каждого ключа, 2 LRU, принадлежность SQLite, первичный интервал, затраченные токены и порядок каждой аппаратной выдачи.

В рабочей копии нужны исходные данные SERBench, токены и веса из [R45](../../graph_memory_round45/qwen_panel214/REPRODUCE_RU.md), а также обе подписанные части [R47](../../graph_memory_round47/facet_confirmation/REPRODUCE_RU.md). Для полной аппаратной проверки рабочий путь `work/graph_memory_round39/author_baseline` заполняется из [опубликованного Qwen-комплекта](../../graph_memory_round39/qwen_reference/QWEN_REPRODUCE_RU.md). Расчёт проводился из отдельного рабочего каталога на диске D. В автономном пакете отсутствуют тексты исходных проектов, веса и эмбеддинги.

```powershell
$env:OPENBLAS_NUM_THREADS='1'
python -B inventory.py
python -B measure.py
python -B sqlite_replay.py
./gpu.ps1
python -B verify.py
```

GPU-режим захватывает общий Windows mutex. Сначала выбираются пары по структуре траекторий и хешу; качество и число кеш-попаданий в выборе не участвуют. Повторно проведённый замер времени и аппаратный журнал изменят хеши файлов прогона. Исходный манифест сохраните отдельно. [Протокол](PROTOCOL_RU.md) · [Параметры модели и кеша](input-seal.json)

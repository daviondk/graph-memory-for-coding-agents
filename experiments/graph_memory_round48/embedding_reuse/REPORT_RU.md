# Сколько эмбеддингов можно переиспользовать из предыдущих шагов агента

**36,65% входных токенов кодировщика** на 305 состояниях SERBench уже приходились на документы, которые агентный поиск полностью кодировал в более раннем допустимом состоянии. Это 3 862 038 из 10 537 511 токенов, 95%-й интервал по 103 репозиториям [33,50%; 39,44%]. Запрос на каждом шаге кодировали заново. При равном весе каждому репозиторию доля составила 30,57%. Все кандидаты принадлежат текущему заданному пулу, кеш инициализируется пустым в пределах каждой отдельной траектории. [Протокол](PROTOCOL_RU.md) · [Подробные числа](reuse.json)

| Проверка | Результат |
|---|---:|
| Основная панель 204, доля межсостояниевой экономии | 37,51% [33,85%; 40,68%] |
| Отдельная панель 101 | 34,87% [28,58%; 40,16%] |
| Число повторов документа из более раннего состояния | 9 649 из 26 446 |
| Экономия за счёт повторов только внутри текущего пакета | 7 865 токенов |
| Приращение от хранения между запросами поверх внутрипакетной дедупликации | 3 859 778 токенов, 36,63% |
| Совместная экономия двух режимов | 3 867 643 токена, 36,70% |

**Хронология.** В наборе 147 изолированных траекторий. Для 143 запросов доступны более ранние состояния с полностью совпадающим строгим префиксом истории. Все эти 143 запроса содержат хотя бы один повтор. Остальные 162 начинают с пустого кеша. У всех 1 288 событий отсутствует временная метка, у всех 305 состояний шаги упорядочены. Сопоставлялись репозиторий, задача, базовый коммит и запуск. Искусственное упорядочение запросов по номеру шага или стабильному хешу даёт 39,87% совокупной экономии. Оно допускает использование несовместимых префиксов; это оценка чувствительности, для основной цифры её не применяли. [Ординальные данные и полные истории](inventory.json.gz) · [Допустимые предшественники](predecessors.json)

**Что даёт сам ключ.** Хеш включает модель, конфигурацию, путь с текстом в точной последовательности видимых токенов и EOS. Изменение конфигурации приводит к отдельному пространству и нулю ложных попаданий. Полная строка «путь + содержание» дала ровно столько же правильных попаданий, сколько токены. Простой evidence_id либо путь с координатами дали 9 648 правильных и ноль ложных попаданий, то есть почти всю экономию. Один лишь путь дал 3 586 правильных и 16 690 ложных повторов. На этой панели специфического преимущества перед ключом полного текста не выявлено. На версиях, где текст меняется за границей усечения, свойства этих ключей могут различаться. Измерение касается сессий внутри одного коммита. [Контроли идентичности](reuse.json)

**Аппаратная проверка.** Для восьми заранее выбранных пар состояний из разных репозиториев выполнили оба режима на RTX 3090, Qwen3-Embedding-8B Q4_K_M, одинаковые лимиты. В режиме без кеша потребовались 469 509 токенов и 108,56 с вызовов кодировщика. С реальным хранением векторов получили 268 899 токенов и 62,37 с. Сокращение времени — **42,55%**, от 35,39% до 48,86% по парам. Полезные результаты сравнили отдельно: совпали побитово все 1 278 векторов запросов и документов в этих двух режимах. На 16 из 16 состояний совпали все косинусные оценки и полный порядок кандидатов; прежние Qwen-результаты также точно воспроизвелись. Совпадение наблюдали на одном backend и выбранном поднаборе. При изменении пакетирования на другом backend округление следует проверять заново. Панель GPU покрывает пары с возможной причинной связью, поэтому её процент ускорения нельзя переносить на все 305 состояний. [Измерения для каждой пары](gpu-results.json.gz)

**Хранилище и ёмкость.** Независимая реализация в SQLite сохранила 26 392 связи ключа с состоянием и при каждой из 305 выдач получила ту же каузальную доступность. Основной индекс хранит 32-байтные ключи и пространство модели. Локальная БД этих связей занимает 2 211 840 байт, значения самих векторов в это число не входят. Для строгой истории максимум составлял 205 различных векторов (3,20 МиБ при 4 096 float32 на вектор). Потоковый LRU на 128 значений сохранил 3 861 167 токенов, а на 32 — только 6 321. Это сравнение поочерёдного чтения/вытеснения. Когда идентификаторы всего пакета известны заранее, можно читать всех резидентов до первой записи — этот более сильный режим исследуется отдельно. [Физический индекс SQLite](sql-audit.json) · [Воспроизведение](REPRODUCE_RU.md)

Это измерение стоимости чтения заданного пула свидетельств. Оно устанавливает достижимую экономию при данном распределении запросов и сохранение рангов на проверенной GPU-панели. Обычное мемоизирование по полному входу остаётся сильным объяснением результата. Ускорение решения issue, перенос через независимые ветви Git и превосходство над авторским поиском на Test500 здесь не измерялись.

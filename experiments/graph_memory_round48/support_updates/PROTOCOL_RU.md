# Меняется ли содержимое памяти при изменении фактически наблюдавшихся подтверждений

Предыдущие точные результаты для двух источников предполагали искусственные значения двух весов. Здесь проверяем более конкретный вопрос на тех же 40 проекциях ISETrace. Может ли обновление подтверждений происхождения, которое действительно произошло, поменять оптимальный пакет при фиксированной политике, и заметен ли случай совместного изменения, незаметного при рассмотрении каждого источника по отдельности?

Единица наблюдения — конец группы инструментальных вызовов. Берём все пары источников с изменившимися числами исходящих подтверждений, с непустыми ссылками на фрагменты результата и видимые к концу группы. Для каждой пары держим неизменными доступность фрагментов, их цены и принадлежность источникам на одном срезе. Перебор пар одной группы — статическое контрфактическое разложение; группе с четырьмя изменениями соответствуют шесть проверок пар. Для исходного состояния используем балансы всех производителей до текущей группы. Состояние до и после получает одинаковые кандидаты, уже доступные после группы. Такая постановка измеряет только эффект билатеральной поправки и исключает смешение с появлением новых кандидатов. Если нет достаточной информации для установления момента целостной доступности кандидата или явной принадлежности полю результата, исключаем его и публикуем количество. Если не получим достоверный межтабличный ключ, эксперимент фиксирует предел данных.

Предварительно фиксируем две политики. Основная использует общий прирост Q32 на каждый фрагмент источника с хотя бы одним исходящим подтверждением — 1/16 (0 при нуле). Вторая — min(счётчик,4)/16, с насыщением до 1/4. Первая уравнивает несколько свидетельств от одного производителя, вторая допускает изменение при появлении второго, третьего или четвёртого свидетельства. В каждой сравниваются исходный пакет, изменения каждого источника в отдельности и их совместное применение. Основная метрика — доля проверяемых пар с другим полным упорядоченным ответом при совместном изменении относительно исходного. Вторичная — доля пар, где каждое одиночное изменение сохраняет пакет, а два совместных меняют. Отдельно публикуем нулевые эффективные поправки после насыщения, число траекторий, групп и пар, раскладку относительно бюджета. Для редких событий интервал рассчитываем по траекториям и показываем исходные числители и знаменатели, в т.ч. число ненулевых траекторий; при нуле событий не выдаём вырожденный bootstrap за оценку верхней границы.

Чтобы избежать утечки из конечных рангов ISETrace, задаём воспроизводимый читатель без обученного ранжирования. Сортируем видимые единицы по убыванию позиции самого позднего источника, затем самого раннего, затем по стабильному анонимному ID узла. Исходная полезность на ранге r с нуля — округление Q32/(1+r) по правилу целочисленного ближайшего. Плюс доплата от каждого доступного источника результата по оговорённой функции. Все фрагменты маркируются по полям результатов. Бюджет 2 048, обязательный ранговый префикс до 1 024. Ранговый порядок один для всех четырёх состояний и меняется только между срезами. Все ответы проверяются полной нативной оптимизацией. Время не первичный исход; параметры функции доплаты исследовательские и не оценены по предпочтениям пользователя. Проекция кандидатов построена из конечной трассы, поэтому отдельно проверяем её происхождение и явно оговариваем остаточное ограничение даже при маскировании доступности.

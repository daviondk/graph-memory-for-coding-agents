# Независимая перепроверка совместной транзакции

Из предыдущего анализа известно, что в группе 9 проекции q25 при определённом насыщении счётчика достаточно важен совместный эффект. Это выбранная после просмотра иллюстрация. Пересчитываем все 64 подмножества шести происходивших в группе обновлений для обоих заранее описанных уровней насыщения, 1 и 4. Для каждого сохраняем весь упорядоченный пакет, токены и значение полезности. Вычисляем все минимальные по включению подмножества, которые меняют исходную выдачу; отдельно считаем подмножества, которые восстанавливают полный результат транзакции. Для контроля реализации используем исходные цены и порядок, общий бюджет 2 048, обязательный последовательный префикс до 1 024 и предпочтение отсутствия наибольшего различающегося ранга при равенстве. Определяем лучшее состояние для каждой точной суммарной цены и затем берём оптимум среди всех цен.

Дополнительно берём одну группу для каждой из всех 40 заранее закреплённых траекторий. Выбираем минимальный SHA-256 строки `r48.independent.v1|q|step` среди существующих шагов; выбор не зависит от числа изменений, эталонного пакета или ответа модели. В каждой группе проверим все одиночные поправки, совместный эффект и исходный состав; пустая группа учитывается один раз. Число групп для перепроверки выбирает проект, статистических оценок корпуса по этому малому набору не делаем.

На этапе пересчёта открываются только три колонки узла (локальный ID, хеш-идентификатор, токены), принадлежность конкретным полям источников, их роли и позиции из R39/reader.sqlite и чистая событийная проекция из observed_join. В последней читаем источники, их доступность, их владельцев и только тройки (производитель, баланс до, баланс после). Сохранённый выбор пакета, текст и эталонные ответы не используются. Выход перепроверки замораживается до механического сравнения с основным вычислением. Источники сразу после группы определяют общий пул для всех вмешательств. Ранги упорядочены по убыванию наиболее поздней и затем наиболее ранней позиции источника и по возрастающему хешу кандидата. Баланс поддержки для старого пакета восстанавливаем только по ранее закрытым группам. Стабильное правило при равенстве действует на все сравнения.

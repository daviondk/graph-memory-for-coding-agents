# Дополнительный контроль с учётом стоимости и старения

После наблюдения первичного выигрыша над пакетным LRU, до вычисления исходов этого дополнительного опыта фиксируем сравнение с опубликованной GreedyDual-Size-Frequency, HPL‑98‑69(R.1), разделы 5 и 7. При равном размере вектора можно измерять приоритет в единицах стоимости H = Clock + Fr·tokens. У нового элемента Fr=1; при новом обращении к резиденту увеличиваем Fr. Вставка лишнего элемента сравнивает всех, включая претендента. Если удаляется сам претендент, часы сохраняют прежнее значение. При реальном вытеснении прежнего резидента Clock принимает приоритет жертвы. Равенства разрешаем оставлением меньшего стабильного хеша, как у основного алгоритма. Вектор и метаданные занимают тот же слот.

Все варианты читают из начального снимка до записи. Первая версия воспроизводит последовательные операции GDSF при обновлении в заданном порядке пакета. Вторая обновляет сначала фактически затребованные резиденты, затем пропуски. Обе версии реализуют правило приоритета оригинала при своей явной сериализации. Третья версия — отдельная **пакетная адаптация**: назначаем приоритеты всем текущим запросам относительно Clock на начало пакета, сохраняем C высших из объединения с прежними резидентами, обновляем Clock максимумом приоритетов реально вытесненных прежних резидентов. Это иной способ встраивания идеи GDSF в пакетный интерфейс. Основное дополнительное сравнение — прежняя политика против первой версии в 512 КиБ, остальные показываем наравне. Не объявляем формулу cost×frequency новым изобретением. [Определение авторского алгоритма, с. 8–9](https://eclass.uoa.gr/modules/document/file.php/D245/2015/HPL-98-69R1_GDS.pdf)

Для всех трёх версий публикуем дополнительно 128 КиБ и 2 МиБ, интервалы на двух прежних панелях. На заранее отобранных в исходном аппаратном опыте восьми парах независимо воспроизводим токенные расходы этих политик при 512 КиБ, начиная каждый раз с пустого кеша. Новый замер GPU для ограниченных политик не выполняется: вывод касается воспроизведённых счётчиков токенов. Различия во времени и численной стабильности для отдельных политик остаются неизмеренными. Уже измеренные GPU-результаты относятся только к фактически исполненному полному и неограниченному кешированному режиму. [Предыдущий протокол](../embedding_reuse/PROTOCOL_RU.md)

# Адресная передача исходных наблюдений

Используем фиксированную задачу преемника из R31/natural_handoff и всю доступную популяцию из 37 issue. Предшественник передаёт до 512 WordPiece адресов наблюдений. Преемник получает только путь своего фактического следующего запроса. Он может открыть одну указанную ранее историческую выдачу, заплатив ещё до 512 WordPiece за доставку исходных строк. Номер нужной строки, содержимое будущего чтения и эталон при чтении недоступны. Бинарный первичный исход — обе граничные строки будущего чтения получены с совпадением пути, номера и SHA исходных байтов. Таким образом фиксируется точное историческое состояние. Номер события задаёт неизменяемый объект в пределах данного checkpoint. Резерв с историческим телом — явный дополнительный ресурс. Считаем его строки и размер сериализации отдельно.

Сравниваем очереди отправителя в одинаковом синтаксисе «путь@номер_события[начало-конец]». Базы — последние события, самые широкие наблюдения, по одному последнему наблюдению каждого пути перед дубликатами, максимальное число ранее ещё не представленных (путь, строка, SHA) на адресный токен. Более простой табличный контроль отправляет один адрес самого широкого прошлого чтения на каждый путь. Полноразмерный справочник адресов с таким же получателем даёт ориентир цены ограничения на адреса. На приёме по заданному пути открываем самое широкое отправленное наблюдение, при равенстве — наиболее позднее. Ширину считаем по числу информативных строк в его историческом теле. Сильный контроль читает строки по порядку, наш кандидат чередует начало и конец реального наблюдения. Такое чередование обусловлено заданной метрикой R31, его обобщаемость на другие строки проверяем дополнительно на 25-м и 75-м процентилях исходно доступных строк будущего чтения, где источником служит полный вывод до выбора двух границ. Если доступен только исходный таргет с двумя границами, ограничение будет явно документировано.

Первичный контраст — прирост от чередования на контроле с одним крупнейшим чтением на путь. Вторичный — вклад сложности отправителя при фиксированном получателе. Лимит включает серийный путь и номер для каждой доставленной строки. Дополнительно сравниваем с хронологической стратегией при одинаковом токен-бюджете. Нулевая стоимость отсутствия совпадений по пути наблюдаема отдельно. Разведочная часть — первые 12 issue по SHA256 от «r32-split/» и ID, остальные 25 составляют тест. Во всех методах и вычислительных бюджетах один и тот же тестовый набор. Анализ по моментам передачи и равному весу issue, 10 000 парных bootstrap по целым issue, seed 32031. Гипотеза возникла после просмотра агрегатов всего корпуса R31, это перенос на новую операцию в том же корпусе. Для проверки независимости нужны новые issue из другого источника.

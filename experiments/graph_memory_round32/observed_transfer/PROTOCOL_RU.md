# Проверка переноса на 2WikiMultihopQA

До загрузки оценок фиксируем новый набор по ревизии автора 612bc5039a457880d9e7d84c3b0a4cf154b70e4f. Во всех задачах dev первое чтение выбирает BM25 только по заголовкам. Доступны вопрос, справочник названий и первые 192 WordPiece одного документа. После этого метод выбирает второй документ. Для задач с ровно двумя различными размеченными названиями считаем точное совпадение множества, для остальных — число и долю найденных документов. Все документы сохраняют позиционный ID даже при совпадении названий. При оценке попадания считаются различные названия. В основной метрике включаем все двухопорные задачи, включая несовпадение названия в каталоге, если оно встречается. Обычная проверка предполагает, что последовательность операций доступна без эталонных данных.

В HotpotQA расширение лексического запроса оказалось слабее исходного вопроса как запасного порядка. Из этого вытекает новый фиксированный вариант. Сначала отдаём приоритет буквальному упоминанию каталожного заголовка, затем покрытию слов вопроса в его контексте из 12 слов по обе стороны после исключения первого заголовка, при равенстве возвращаемся к исходному BM25 вопроса. Первичный контроль — тот же приоритет наличия упоминания, затем исходный BM25. Все веса R31 сохраняются. Другие контроли — исходный поиск и расширение, правильные и переставленные ссылки. После просмотра исхода 2Wiki метод не изменяем. Разрезы по размеченному типу и числу опор являются диагностическими. Считаем число выигрышей и потерь по вопросам, парный percentile bootstrap из 10 000 перевыборок. Дополнительно группируем вопросы по общему размеченному набору названий и оцениваем перенос неопределенности по этим кластерам. Основная задача проверяет перенос алгоритма следующего чтения.

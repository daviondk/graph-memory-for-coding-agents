# От чего зависит перенос правила чтения

Фиксируем проверку на всех примерах MuSiQue-Ans dev. Каждая вершина соответствует абзацу с оригинальным ID. Повторение заголовка у двух абзацев сохраняет оба ID. На входе модели есть вопрос и каталог заголовков, затем одно чтение до 192 WordPiece. Выбор первого абзаца, разбор упоминаний, веса и окно ±12 переносятся из 2Wiki без подгонки. Перемешиваем ID при равенстве по хешу вопроса и исходной позиции. Предсказываем два ID у всех вопросов. Первичный контраст — локальный контекст упоминания с исходным BM25 против наличия упоминания с исходным BM25 на вопросах с двумя размеченными абзацами, метрика — точная пара. Заранее добавляем сильные контроли при нескольких упоминаниях — первая позиция упоминания, его частота, а также последовательное применение частоты и первой позиции. Равенство разрешает тот же BM25. По всем случаям вычисляем macro Support F1 как 2·число правильных ID / (2 + число размеченных ID), включая задачи с тремя и четырьмя опорами. Лимит двух адресов ограничивает достижимый F1 в этих двух группах. Сравниваем достоверность локального эффекта парным bootstrap по вопросам. Дополнительно считаем точность первого шага и случаи, где методы реально разошлись.
 
Официальный формат оценивания поддерживает раздельные answer F1 и support F1. Мы предсказываем только абзацы. Сравнение с авторской full-context системой иллюстрирует разрыв при разных входах. Вводный файл взят из версионированной публичной копии, исходную выборку сверяем по ID и контрольным суммам доступных независимых копий.

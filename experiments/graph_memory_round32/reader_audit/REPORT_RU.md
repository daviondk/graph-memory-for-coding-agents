# Независимая проверка выбора следующего документа

Из исходных двух корпусов и зафиксированных ID прогнозов заново восстановлены первое чтение, граница в 192 WordPiece, буквальные лексические упоминания заголовков, BM25 каталога и оба спорных выбора следующего адреса. По каждому сериализованному варианту заново посчитаны метрики относительно авторских меток. Реализации исходного ретривера, его оценщика и их пообъектные оценки при проверке не загружались. У MuSiQue совпадают Support F1 всех десяти политик и точная идентичность адресов при одноимённых абзацах. У 2Wiki совпадают точные пары всех семи политик и полнота по всему dev.

| Событие | 2WikiMultihopQA | MuSiQue-Ans |
|---|---:|---:|
| Проверены вопросы | 12 576 | 2 417 |
| Из них с двумя опорами | 9 825 | 1 252 |
| В двухопорных найдено несколько упоминаний | 577 | 119 |
| В двухопорных изменился выбранный адрес | 104 | 10 |
| Выигрыши / потери / оба исхода равны при смене адреса | 65 / 28 / 11 | 2 / 1 / 7 |
| Проверочные вопросы с любым числом опор, где изменён выбранный адрес | 176 | 17 |

Во всех 193 случаях изменения адреса на двух корпусах оба конкурирующих заголовка буквально присутствовали в лексически нормализованном тексте единственного прочитанного документа. Локальное взвешенное покрытие слов вопроса у вновь выбранного кандидата было строго выше. Ни одно переключение не объясняется совпадающими названиями. Для двухопорного 2Wiki эффект в точном парном тесте Мак-Немара p=0,000158, для MuSiQue p=1,00. Тест считает разные вопросы независимыми. В исходном отчёте 2Wiki также доступны интервалы с группировкой по общим эталонным парам.

В 2Wiki при выборе между *Bonne of Berry* и *Bernard VII, Count of Armagnac* локальный контекст обнаружил требуемый второй адрес. На другой задаче выбор *Jack Shaheen* вместо *Sut Jhally* потерял опору. В MuSiQue выигрыш при выборе *Merseburg* вместо *Joachim* соседствует с потерей при выборе *Justice League* вместо *Smallville*. Локальная текстовая близость поддерживает разные типы связи. Семантическая полезность выбранной связи для ответа требует отдельной оценки. Точные ID, позиции и оценки обоих кандидатов для каждого расхождения находятся в disagreements.json.gz.

Для повторения установите Python с pyarrow и tokenizers, восстановите файлы по инструкциям соседних observed_transfer и musique_links и выполните `python -B audit_reads.py`. Скрипт проверит SHA корпусов, токенизатора и прогнозов, напечатает знаменатели, числа расхождений и двусторонние p-значения. Исходные агрегаты служат только для завершающей проверки равенства.

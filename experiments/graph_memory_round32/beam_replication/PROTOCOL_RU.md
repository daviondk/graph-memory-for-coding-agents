# Стоимость материализации динамических ответов в Beam Retrieval

Новый фиксированный тест переносит алгоритм R31 на 64 других вопроса HotpotQA distractor dev с десятью документами. Выбор — первые 64 по SHA256 строки «r32-native-replication/» и id после исключения всех восьми вопросов R31, до доступа к индивидуальным оценкам и меткам этого опыта. Корпус dev уже использован для иных опытов, в том числе для сводной оценки опубликованных пар. Статистическая единица — вопрос. Основной контраст при ровно двух отзывах — согласие с полным повторным beam=2 для дерева по победителю и глобального префикса такого же размера среди пар первых четырёх корней. Оба метода дополнительно хранят четыре упорядоченных адреса. Критерий успеха — прирост по парному 95% интервалу перевыборки вопросов. Стоимость сравниваем также с сохранением всех 30 доступных пар первых четырёх корней, с фильтрацией первоначальных 17, с полным ранжированием 45 пар. Даем число уникальных и повторных лишних обращений и реально переданные токены. Заданы ровно все 0/1/2 отзывов, с равными весами внутри уровня.

Для построения дерева только по текущему победителю впервые материализуем оценки пар по требованию. При посещении узла сканируем допустимые пары с двумя первыми живыми документами, запрашивая только ещё не оценённые пары. Балл пары зависит от запроса и текстов двух адресов. Первым в модели идёт тот документ, чей неизменный балл первого шага больше. Граница обрезки длинного первого документа и маска конечного SEP воспроизводят авторский forward. После посещения дочерних узлов память для дальнейшего обслуживания состоит из отсортированных достижимых пар и первых четырёх одиночных адресов. Удаление двух адресов может открыть максимум четвёртый документ в первом порядке, поэтому физическая стоимость ленивого способа ограничена 30 разными парами. Конкретное число вычислений измеряем.

Для оценки физически вычисляем на CPU обе головы исходного DeBERTa-v3-large FP32, сначала весь первый шаг и только оценки, впервые запрошенные деревом. Затем в отдельную фазу дособираются оценки до пула четырёх корней и до всех 45 для вычисления независимых референсных исходов и полного ранжирования. Каждая фаза реально вызывается, повторное использование разделяемых баллов измеряется числом и временем calls. Эти последовательные времена не являются head-to-head изолированным бенчмарком. Вначале на прежних восьми вопросах сравним прямую реализацию с сохранённым авторским полным графом, все 448 состояний и ранги. При расхождении честно фиксируем численную и ранговую ошибку и исследуем её причину до анализа 64. Метод и панель после фиксации сохраняются. На новой панели качественные итоги и разметка присоединяются только после финальной подписи всех 64. Сохраняются промежуточные закрытые checkpoints, чтобы отключение системы не требовало повторного инференса. Ограничения включают N=64 и предварительно фиксированные синтетические отзывы.

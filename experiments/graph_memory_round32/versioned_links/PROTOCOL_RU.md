# Повторное чтение по версии и изменяющемуся каталогу

До оценки фиксируем весь dev-файл авторской версии 2WikiMultihopQA в его физическом порядке и контрольный порядок по SHA256 ID. Это два сценария потока запросов. Файл составлен для статической QA, поэтому календарную последовательность событий он не восстанавливает. Первый документ и эталон следующего выбора определяются замороженной политикой local_static из observed_transfer. Реальный первый фрагмент ограничен 192 WordPiece. Запись памяти имеет доступ лишь к запросам и фактическим наблюдениям префикса. На границе хранилища предполагается доступный независимо от чтения идентификатор версии, который при подготовке имитируется SHA256 полного текста. При отсутствии такой метадаты выгода от проверки версии требует отдельной оценки.

Контроли сохраняют сжатый UTF-8 текст фрагмента либо сжатую последовательность нормализованных лексических токенов. Ещё один контроль хранит только ответы по заголовкам каталога, которые уже проверялись в этой версии, включая отрицательные. В тестируемом варианте сохраняем позиции через множества слов ±12 для каждого найденного упоминания и фильтр Блума по всем униграммам и соседним биграммам фактического фрагмента, 512 бит и две хеш-функции. На следующем запросе неизменной версии фильтр исключает новые заголовки с точно отсутствующей лексемой или биграммой. Если остаётся хотя бы один непроверенный кандидат, открываем оригинальный фрагмент раз за запрос и дополняем кэш. После отрицательной проверки сохраняем явно только результаты, для которых фильтр даёт «возможно». Веса IDF и позиция заголовка пересчитываются из текущего каталога. Оценка проверяет выбор того же второго документа, что при полном чтении.

Первичная точка сравнения — LRU с бюджетом 256 КиБ в порядке исходного файла. Дополнительно фиксируем 64 КиБ, 1 МиБ, 4 МиБ и свободное хранение. Для каждого метода бюджет учитывает байты ключа, идентификатор версии и длину фактически сериализованной полезной нагрузки. Указываем число чтений и WordPiece, байты памяти в конце и расход на обновления. Это логический бюджет полезных данных. Сжатие zlib=6 используется у всех методов. Если запись не помещается, она не сохраняется. Внешний фрагмент, каталог и доступный идентификатор версии общие. Отдельно измеряем повторы заголовка с изменившейся версией и эффект кэша текста только по заголовку. Если таких случаев мало, допускается отдельная контролируемая проверка с заведомо изменённым текстом. Публикуем все исходы, включая преимущество сохранения полного фрагмента.

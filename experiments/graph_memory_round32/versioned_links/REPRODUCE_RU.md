# Повторение эксперимента

В каталоге `../observed_transfer` нужны зафиксированные `predictions.json.gz`, `plan.json`, `seal.json` и тот же локальный dev-файл по ревизии `612bc5039a457880d9e7d84c3b0a4cf154b70e4f`. Используется одно исследовательское окружение с pyarrow, NumPy, tokenizers и зависимостями модуля `predict.py` из R31. Прогон вызывает лексическую политику на CPU. Веса LLM и удалённая генерация для оценки не нужны. Ссылка на данные и SHA256 записаны в [описании исходной выборки](../observed_transfer/plan.json).

```powershell
python -B replay.py
python -B audit.py
python -B revision.py
```

`replay.py` заново извлекает фактически наблюдаемые WordPiece-фрагменты, проверяет исходный индекс, расход токенов и каждый из 503 040 версионных выборов против зафиксированных решений полного читателя. Пять методов, пять уровней бюджета и два порядка дают 628 800 записей. В файле `events.json.gz` лежат упорядоченные идентификаторы вопросов, хеши заголовков и редакций, токены чтения и эталон адреса. Каждый файл `{порядок}-{метод}-{бюджет}.json.gz` содержит в порядке выбранного потока пары [индикатор чтения, выбранный адрес]. Нулевой бюджет в имени означает неограниченное хранение. Размеры сериализации измеряются в байтах. При сжатии zlib уровень равен 6. Для воспроизведения контрольных сумм используйте то же окружение Python и версию zlib. Результаты относятся к двум заданным последовательностям.

`audit.py` проверяет размеры траекторий и заново агрегирует число чтений, WordPiece и ошибок из индивидуальных исходов. `revision.py` сопоставляет последовательные редакции одного заголовка и отдельно прогоняет контролируемую замену текста. Хеши корпусов, протокола, кода основного опыта и зафиксированного полного читателя находятся в [plan.json](plan.json). Тексты и эталонные ответы корпуса в этом каталоге не распространяются.

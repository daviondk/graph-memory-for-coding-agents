# Прямое сравнение с деревом представительного семейства

В первичной работе Monien вершина дерева содержит множество, а исходящие ветви помечены его элементами. На фиксированном строгом порядке пар достаточно в каждой вершине выбрать самую раннюю допустимую пару. Это близкий прямой предшественник статического варианта R31. Новизну самой схемы ветвления по двум концам заявлять нельзя. [Monien, How to Find Long Paths Efficiently](https://digital.ub.uni-paderborn.de/hsx/download/pdf/42079)

Сравниваем три физические структуры при f=2. В неявном полном двоичном дереве нужны семь однобайтовых позиций. Список различных достижимых ID по рангу использует в среднем менее шести позиций. Сильный контроль — весь плотный список из не более 45 ID. Все получают одинаковые лексические ранги, одинаковые маски и одну таблицу из 256 декодированных масок рёбер. В дереве при отзыве обеих вершин следуем по меньшему концу. Проверяем все сочетания размера ≤2 на всех вопросах. Основные системные метрики — среднее и максимум просмотренных меток, байты BLOB, размер отдельной SQLite после VACUUM и медиана/p95 реальных запросов на 256 вопросах, выбранных хешем, по 4 сценария и 5 повторов в перемешанном порядке. Добавляем ранний выход по числу живых документов всем вариантам. Неявная адресация сильнее хранения отдельных указателей. Эта проверка заранее фиксирует реализацию читателя и пересматривает границу возможной новизны статического метода.

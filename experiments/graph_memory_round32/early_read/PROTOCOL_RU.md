# Когда можно закончить чтение до конца фрагмента

Проверяем точную остановку для политики «сначала любой явно упомянутый заголовок, затем BM25 по исходному вопросу». Первый документ выбирается как раньше. Если уже встретился наивысший по исходному рангу допустимый второй заголовок, никакое продолжение текста не сможет поднять другой выше. Поэтому оставшиеся блоки можно пропустить. При чтении непоследнего блока его последнее незавершённое слово исключается. Эталон — точный ID второго адреса у уже зафиксированного 192-WordPiece варианта R31/R32. Для двух корпусов используем все задачи 2Wiki и MuSiQue, не изменяя назначения позиционных ID. Предыдущие результаты известны при формулировании, метрики стоимости нового метода ещё не измерены.

Основная политика — блоки по 16 WordPiece с остановкой по сертификату. Также проверяем блоки по 32 и 64 и фиксированные длины 32, 64, 96. Метрики — среднее число доступных прочитанных токенов, сэкономленные токены, число блоков, совпадение выбранных адресов с полным префиксом и точность двух опор. Параметры до расчёта фиксированы. Измеряем видимые позиции в последовательности токенов, стоимость запуска модели, число физически переданных байтов и число операций диска этим опытом не определяются. Для блоков моделируем последовательную выдачу префиксов; расчёт границ токенизатором относится к источнику данных и в стоимость фаз чтения агента не включён.

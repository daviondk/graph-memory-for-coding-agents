# Что известно о памяти для ранжированного запроса с отзывом источников

**Статический результат имеет прямого предшественника.** В q-дереве Monien в каждом узле записывается допустимое множество U, каждая ветвь запрещает один элемент U, а путь определяет уже запрещённые элементы. Это совпадает со структурой нашего статического дерева. Выбор лучшей оставшейся метки по строгому рангу превращает поиск любого допустимого множества в поиск первого по рангу. Если в ответе обязателен конкретный ID и читатель выбирает среди сохранённых ID, каждый достижимый победитель обязан присутствовать в памяти. Это минимальность явного множества кандидатов для заданного читателя. Размер сжатой программы, число байтов и затраты на первоначальный расчёт относятся к другим задачам оптимизации. [Monien, с. 245–247, определение q-tree и лемма 1](https://digital.ub.uni-paderborn.de/hsx/download/pdf/42079)

## Два воспроизводимых теста

1. **Статический q-tree против плоского списка.** На 7 405 вопросах HotpotQA независимо построены q-деревья с наилучшей допустимой меткой и перечислены все отказы размера до двух. Множества не пустых меток совпали с полным перебором победителей. Максимум шесть различных пар и граница C(4,2)=6 достигается. Для ровно двух удалений в 331 063 состояниях переход по ветви посетил в среднем 1,449 узла, просмотр компактного упорядоченного списка — 1,814 записей. Всего 46 668 различных узлов-состояний против 42 993 различных записей списков по всем вопросам. Один узел дерева может потребовать ссылки на детей и дополнительный ключ. Подсчёт посещений не определяет объём SQLite или время. Число узлов до устранения повторов не превосходит 1+2+4=7. В общем случае граница достижимости C(p+f,p) следует из существования представительного семейства, а в худшем случае достигается на всех p-подмножествах p+f элементов при отзыве дополнения.

2. **Динамический первый этап и случаи пустого результата.** Для фиксированного порядка первого шага, ширины B и статических строгих баллов простых неориентированных пар вычислили отдельный базовый индекс. Храним первые B+f документов, для каждого — первые f+1 инцидентных пар, с объединением повторов. Если документ жив, каждый из f отказов уничтожает не более одного его соседа из списка. Если список короче f+1, учтены все его соседи. Каждый реально попавший в beam документ содержится в первых B+f. Значит, лучший допустимый сосед каждой активной вершины и вся лучшая пара восстанавливаются точно даже при пустом результате. На восьми зафиксированных вопросах Beam Retrieval этот контроль правилен во всех 448 состояниях, хранит в среднем 10,375 пар против 4,125 у множества достижимых победителей. Оба требуют доступ к порядку первого этапа и к предварительным оценкам. Это контроль по существующим баллам. Широкий глобальный индекс присутствует при инициализации, и число сохранённых пар не даёт само по себе ускорения модели.

Для разреженных пар у динамического дерева есть существенный крайний случай. Возьмём документы 0, 1, 2 по порядку, beam=1 и единственную пару {1,2}. Пока разрешён документ 0, у запроса отсутствует ответ. Удаление 0 открывает {1,2}. В пустом узле ветвление только по победителю остановится слишком рано. Ветвление в таком узле по активным документам beam корректно: пока выживает весь текущий beam, новых допущенных рёбер появиться не может. В непустом узле требуется отдельно доказанная обменная лемма. После исправления общая верхняя оценка числа посещений для зависимостей размера p использует ветвление до max(p,B). На полном графе пар пустой узел при достаточном числе живых документов невозможен.

Проверены все 1 957 упорядоченных подсемейств шести пар четырёх документов для двух ширин beam, одного фиксированного порядка документов и всех 11 множеств удаления размера ≤2. Фиксация порядка без потери общности следует из переименования вершин. У 50 из 3 914 комбинаций семейства и ширины исходное правило пропустило достижимый результат. После обработки пустого узла все множества сохранённых результатов совпали с перебором. Независимый индекс по соседям дал правильный ответ во всех 43 054 состояниях. Для списка направленных переходов, где балл пары зависит от выбранной первой вершины, нужно хранить и сравнивать именно направленные переходы по правилам модели.

## Позиционирование для демонстрации

Обоснованная системная заявка — посетитель отзывает источник, видит доказательство сохранения или смены пары, запрос к архиву при нехватке свидетельств и фактическую стоимость разных представлений. Для неизменного ранга математическая основа давно опубликована. Узкая исследовательская возможность — показать, как двухступенчатый допуск ограничивает достижимые пары, сколько стоит обслуживание такого представления по сравнению с индексом по соседям, когда дешевле перечитать историю и что действительно получает следующий агент. Сопоставление с восемью первоисточниками целевое. Приоритет обменной леммы в полном корпусе теоретической и поисковой литературы остаётся открытым.

Для проверки выполните `python -B check.py` из этой папки. Нужны соседние зафиксированные файлы R31/support_pairs/rankings.json.gz и R31/hotpot_native/ranking-seal.json с восемью прогнозами. Программа работает на стандартной библиотеке, записывает checks.json с отдельными размерами по вопросам и первым контрпримером.

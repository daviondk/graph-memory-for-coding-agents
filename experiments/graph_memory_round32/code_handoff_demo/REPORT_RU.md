# Проверка памяти при передаче задачи между кодовыми агентами

В [интерактивной демонстрации](handoff.html) можно открыть архив фактических наблюдений кода в момент передачи задачи, выбрать версию фрагмента и проверить, какие строки из первого последующего чтения преемника удалось восстановить. Набор включает все 171 подходящее событие на 25 отложенных задачах Handoff Debt. Реальными являются чтения файлов предшественником и преемником. Содержание списка адресов и выбор строк моделируются для этих событий. Сценарий не требует обучения или вызова языковой модели. [Статья Handoff Debt](https://aclanthology.org/2026.emnlp-main.738/) · [Версия данных](https://huggingface.co/datasets/kc-academy/handoff-debt/tree/79244eedc9d58349da0fcf1a2e05916e0ac5af00) · [Эксперимент и условия отбора](../handoff_ranges/REPORT_RU.md)

### Что видно в одном примере

В задаче `astropy__astropy-14369` преемник запросил `astropy/io/ascii/cds.py`. В построенном каталоге сохранён адрес наблюдения №12. Каталог занимает 38 WordPiece. При чтении поочерёдно с начала и конца система выдаёт 18 адресованных строк за 511 WordPiece. Этим покрыты крайние целевые строки 2 и 357, а внутренние 127 и 288 остались за пределами выборки. Можно переключиться на последовательное чтение, уменьшить бюджет, задать диапазон строк или раскрыть отпечатки. Кнопка «Recover interior lines» выбирает другой реальный случай, в котором последовательное чтение покрывает обе внутренние цели. Подбор иллюстраций по исходу не меняет состав проверочной выборки. ### Что хранится и измеряется

В SQLite представлены 58 снимков, 346 исторических наблюдений, 17 583 записи о строках и 133 адреса в моделируемых каталогах. Хранилище занимает 2 826 240 байт. Запись хранит путь, идентификатор события, номер строки, SHA-256 её точного текста и стоимость выдачи в WordPiece при исходном форматировании с адресом. Версия наблюдения вычисляется по упорядоченному списку номеров и отпечатков наблюдавшихся строк. Область охвата версии ограничена этим фрагментом. В дистрибутиве отсутствуют тексты исходного кода, запросы и команды. Самостоятельная HTML-копия содержит только проекцию тех же таблиц. [Состав](build.json)

Полный бюджет по умолчанию составляет 512 токенов на список адресов и отдельно до 512 токенов на открытие. По каждому пути в списке находится одно наиболее широкое прошлое наблюдение. Живой сервис делает параметризованный запрос к локальной SQLite, используя выбранное событие, путь и числовые границы. Последовательная стратегия перебирает доступные строки по порядку, двусторонняя — поочерёдно с двух концов. Строка выдаётся целиком, если помещается в остаток бюджета. При ручном выборе иного архивного события интерфейс явно указывает, входил ли адрес в каталог. Бюджет ручного поиска и знание будущих целей в основной эксперимент не входят.

### Проверка

Для обеих политик во всех 171 передачах сверены полный упорядоченный список номеров и SHA-256, токены, попадания и оба исхода относительно замороженного эксперимента. Двустороннее чтение извлекло обе крайние строки в 48/171 передачах и обе внутренние в 0/171. Последовательное чтение дало соответственно 0/171 и 4/171. Это микроагрегаты событий, основной эксперимент также публикует оценки с одинаковым весом задач. Для каждого доступного архивного адреса выполнены дополнительные проверки числового диапазона, бюджета в 96 токенов и нулевого бюджета, всего 4 080 запросов. В браузере проверены примеры с версиями и отсутствующим путём, ручной выбор, обработка некорректных границ и мобильная ширина 390 px. Автономный браузер повторил четыре сводных счётчика в 342 запросах, без обращения к серверу. [SQL-проверка](verified.json) · [Браузерная проверка](browser-receipt.json)

Совпадение требует правильных пути, номера и отпечатка. Такой исход измеряет точную доступность цитаты в переданном материале. Изменение вероятности решения задачи агентом потребует отдельного запуска решателя.

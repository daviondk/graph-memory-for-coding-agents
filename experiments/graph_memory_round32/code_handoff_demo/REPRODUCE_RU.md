# Запуск

Откройте `handoff.html` в современном браузере. Автономной версии достаточно этого файла. Для просмотра того же эксперимента через реальную локальную SQLite выполните в каталоге демонстрации следующую команду. Затем откройте напечатанный адрес. Сервер использует предоставленную БД в режиме чтения и привязывается к 127.0.0.1.

```powershell
python -B serve.py --port 0
```

### Проверка и повторная сборка

Для серверного режима достаточно стандартного Python. Сборка новой проекции использует `tokenizers`, исходный `prefix.json.gz` R31/natural_handoff и запечатанные результаты R32/handoff_ranges. Пути и ожидаемые хеши находятся в `build.py` и исходном протоколе. Из текста извлекаются только номера, SHA-256 и WordPiece-стоимости строк с адресами. Скрипты обращаются к полям траекторий как к данным. В отдельной копии рабочего дерева запустите последовательно следующие команды.

```powershell
python -B build.py
python -B verify.py
python -B export.py
node browser_check.mjs
```

`verify.py` сверяет ответы SQLite с каждосрочными результатами исходного эксперимента. Для запуска только живой демонстрации достаточно файлов `serve.py`, `index.html`, `verified.json` и `handoff.sqlite`. Чтобы заново получить автономный HTML, достаточно готовой SQLite, серверного модуля, результата проверки, шаблона и `export.py`. Браузерный тест запускает локальные процессы Chrome и Python, проверяет два режима и создаёт `demo.png`. Пути к Chrome, Python и временному каталогу можно задать через `CHROME_PATH`, `PYTHON` и `INSPECT_BROWSER_TMP`. Проверено в Node.js 24.14.1. При повторной сборке двоичный размер SQLite зависит в том числе от версии библиотеки. Семантическое совпадение проверяется в `verify.py`.

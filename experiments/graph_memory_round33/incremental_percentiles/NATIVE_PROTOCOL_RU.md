# Контроль влияния реализации

После первичного замера NumPy проверяем ту же гипотезу в общем модуле C++17. Обе реализации поддерживают одинаковые типизированные степени, вычисляют перцентили из плотных целочисленных бинов и кэшируют прочитанный структурный логит узла в пределах одного состояния. Первая двигает счётчики при сообщении о новом узле и изменении степени на каждом конце ребра. Вторая строит бины только на первом чтении состояния одним проходом по доступным узлам. Обе вычисляют накопленные суммы один раз при первом чтении. Калибровка Dense, веса, разбиение, частота групповых изменений, состав запросов и полный/восьмиэлементный режим общие. Валидация во всех состояниях сверяет логиты с независимой SciPy-реализацией при абсолютном допуске 1e−11 и полный порядок, включая обнаруженный Python-ранжировщик. Тайминги исключают разбор числовых файлов, восстановление событий, эмбеддинги и сериализацию. Выполняем пять чередующихся измерительных блоков на траекторию, десять воспроизведений внутри блока. Вклад естественной частоты срезов приводится отдельно как разведочный анализ по заранее фиксированным 8/40 историям.

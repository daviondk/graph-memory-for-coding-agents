# Точное обслуживание относительной степени в растущей памяти агента

На 48 историях ISETrace и 364 реально построенных состояниях графа проверена поддержка структурного ранжировщика R33 при поступлении наблюдений. **514 выдач совпали полностью**, в том числе после 126 отзывов типизированных рёбер. В нативной реализации C++ при чтении после каждого изменения состояния время полного оператора обновления и ранжирования сократилось в среднем геометрически на **8,1%** относительно пересчёта гистограмм при первом чтении (отношение 0,919, 95%-й парный ДИ [0,871; 0,959]). При единственном чтении в конце инкрементальное обслуживание потребовало на 6,2% больше времени.

## Что именно обновляется

У каждого фрагмента есть роль (аргумент или результат инструмента) и восемь целых степеней по четырём типам направленной связи. Хранятся целые степени узлов и числа узлов каждого значения степени для каждой пары «роль, направление связи». Добавление ребра перемещает по одному узлу между соседними значениями в двух гистограммах, отзыв выполняет обратное перемещение. Новый узел включается в гистограммы своей роли. При первом чтении изменённого состояния вычисляются накопленные суммы. Для узла степени d относительное значение равно

```text
(число степеней меньше d + 0,5 × число степеней, равных d) / размер группы − 0,5.
```

Равенство с ранжированием всего массива следует из среднего ранга при связках. После корректного поступления дельты каждый узел учтён один раз в каждом из восьми каналов своей роли. Логарифм абсолютной степени строго возрастает и сохраняет разбиение по порядку и связкам. Поэтому метод воспроизводит восьмёрку относительных признаков R33, включая единственный элемент и константные группы. К ним добавляются семь признаков формы и восемь абсолютных логарифмированных степеней, затем применяются фиксированные веса global_role. [Модель и исходный reader](../relative_structure/study.py) · [Реализация](index.py) · [C++17](native.cpp)

Для целочисленных степеней с максимальным наблюдавшимся значением D и числом каналов K=8 стоимость обработки изменений амортизированно порядка O(K × число вставленных/удалённых узлов + число изменений рёбер). Первое чтение после изменений требует O(2K(D+1)) для накопленных сумм и O(Km) для m запрошенных узлов. Следующее чтение до записи переиспользует суммы, а C++ также переиспользует структурные логиты. Дополнительно сортировка m кандидатов стоит O(m log m). Сильный контроль поддерживает те же степени, при первом чтении один раз обходит все V узлов — O(KV) плюс построение накопленных сумм. Обе структуры занимают O(KV + 2K(D+1)) при плотных постоянных идентификаторах без накопления пустых слотов. В текущем массиве после удаления большого числа узлов объём может следовать максимальному числу выданных ID, освобождение и переиспользование ID не включены. Классические решения для динамических кумулятивных частот и материализованных представлений известны. Здесь проверен конкретный оператор графовой памяти и режим, в котором он окупается. [Fenwick](https://doi.org/10.1002/SPE.4380240306) · [Ahmad et al., DBToaster](https://www.vldb.org/pvldb/vol5/p968_yanifahmad_vldb2012.pdf)

## Состояния и проверка эквивалентности

Выбраны первые 48 траекторий из заранее определённого хеш-порядка R21. У 40 историй использованы четыре квартильные точки R22 (159 различных состояний), у первых восьми — конец каждой завершённой группы вызовов (205 состояний). Нативный построитель ISETrace каждый раз получал физически обрезанную последовательность событий, пустой финальный ответ и пустые метаданные полного источника. Из этих снимков экспортированы только числовые приращения, метаданные узлов и Dense-порядки. Исходный семантический порядок имеющихся кандидатов получен ограничением сохранённых покандидатных оценок Dense-FT, с учётом только уже доступных узлов. Для проверки справедливости времени все реализации получают один и тот же поток числовых изменений. Его выделение из необработанных событий измеряется отдельно в других экспериментах серии. Почти все старые процентильные векторы изменились, хотя собственные степени изменились лишь в 2,89% сопоставимых случаев. Сохранённая гистограмма позволяет узнать новый процентиль при чтении, без перезаписи всех этих векторов. Цифра 5 834 считает различные узлы внутри каждого перехода с итоговым изменением и новые узлы. Фактических записей счётчиков в C++ может быть больше, когда несколько рёбер касаются одного узла за переход.

Во всех состояниях Python-индексы воспроизвели все 23 входа и структурные логиты независимого вычисления через SciPy с максимальной абсолютной ошибкой 0. Нативная реализация C++ дала 2,89×10⁻¹⁵ из-за порядка сложения. Во всех 514 парах «вопрос, состояние» полный порядок сохранился. На концах траекторий все 73 порядка совпали с зафиксированным R33 global_role. Исторических удалений самих узлов в этом наборе не было. Отдельный тест применил 364 обратных числовых приращения к Python-индексу, получив те же признаки на каждом предыдущем состоянии и пустую гистограмму в конце. ## Когда окупается обслуживание гистограмм

Ниже отношение времени «инкрементально / гистограмма только при чтении». За единицу статистической репликации взята траектория, интервал рассчитан 10 000 парными выборками. Чтение «восемь» оценивает восемь первых кандидатов внешнего Dense-порядка. Такое измерение относится к стоимости точечного чтения и не гарантирует глобальный top-8 после структурного ранжирования.

| Каждый срез, 364 чтения состояний | **0,919 [0,871; 0,959]** | **0,877 [0,833; 0,918]** | 1,055 [1,034; 1,074] | 1,066 [1,041; 1,092] |
| Каждый четвёртый и финальный, 94 | 1,055 [1,020; 1,096] | 1,049 [1,007; 1,089] | 1,332 [1,301; 1,365] | 1,360 [1,339; 1,381] |
| Только последний, 48 | 1,062 [1,042; 1,081] | 1,104 [1,072; 1,132] | 1,426 [1,381; 1,476] | 1,440 [1,381; 1,506] |

Сумма медианных длительностей C++ для полного ранжирования при каждом срезе составила 1,81 и 2,09 мс за все 48 историй. Время оператора мало в абсолютных единицах. В независимом повторном запуске на той же машине отношение составило 0,930 [0,896; 0,959] и 0,850 [0,804; 0,895] при проверке восьми узлов. При единственном полном чтении повтор дал 1,074 [1,053; 1,100]. В разведочном срезе по восьми историям с измерением после каждой завершённой группы вызовов первый запуск дал 0,733 [0,603; 0,860] для полного и 0,654 [0,573; 0,741] для восьми узлов. Количество историй в этой подгруппе мало. Технические повторы одного воспроизведения не увеличивают число независимых историй. [Нативные тайминги](native-results.json) · [Независимый повтор](native-repeat.json)

В NumPy инкрементальная обработка проиграла сильному контролю во всех шести режимах. Применение количественно небольших дельт требует нескольких вызовов NumPy и обновлений индексированных ячеек. Даже относительно полного отложенного восстановления из активных рёбер на каждом срезе отношение для всех узлов составило 0,979 [0,944; 1,015]. При полном чтении только в конце оно составило 1,587 [1,500; 1,684]. Медианный пик учитываемых tracemalloc выделений NumPy/Python на историю в режиме полного частого чтения — 61 454 байта у инкрементального варианта, 60 138 у отложенной гистограммы и 73 851 у восстановления из рёбер. Исходные фикстуры и заранее подготовленные индексы запросов загружены до начала измерения. Это память оператора в процессе Python.

# Диагностика механизма при 256 токенах

После просмотра двух предыдущих серий и разложения пустых контекстов на seed 13 фиксируем еще один тест единого порядка для всех бюджетов. При обратной передаче применяем прежний префикс из двух узлов лишь там, где он сохраняет число узлов, доступных при ограничении 256 токенов. Если в префикс с первыми двумя помещается меньше узлов, чем у cost_worst, целиком используем cost_worst. Это вычисление требует только порядка кандидатов и их длины. Простой контроль переключает порядок только тогда, когда после закрепления префикс пуст, хотя исходный cost_worst помещает не менее одного узла. Нового параметра для подбора нет. Порог выбран по наблюдению на seed 13. Оба метода возвращают единственный вложенный порядок для любого последующего бюджета. Преимущество по числу узлов само по себе не гарантирует релевантности.

Заранее фиксируем сравнения с исходным cost_worst и с закреплением двух узлов без ограничения. Основной показатель MeanCoverage, диагностические C256, C512, FS2048 и MRR. Сообщаем отдельно ранее увиденный seed 13 и четыре остальных. Источники вопросов у пяти запусков общие, этап имеет исследовательский статус. Сохраняем решения о переключении до присоединения существующих нативных оценок двух исходных порядков. Операционную цену выражаем долей переключений от простого префикса; реализация служит воспроизведению, время работы по ней не сравниваем.

# Стоимость единого порядка при меняющемся бюджете

Сравниваем два уже обученных ранжирования ISETrace, global_role и поправку cost_worst из R33/budget_loss. Выбор cost_worst и её λ использовал dev580 в прежней серии. Сохраняем обе модели без переобучения и фиксируем бюджеты 256, 512, 1 024, 2 048 и 4 096 токенов. Первичная метрика MeanCoverage — арифметическое среднее нативной Coverage по этим пяти бюджетам для каждого вопроса, затем по вопросам. Это показатель данного протокола с равным весом пяти бюджетов. Основные контрасты — выбираемая на dev плавная бюджетная интерполяция против (а) лучшего единого коэффициента и (б) свободного выбора между двумя готовыми порядками отдельно для каждого бюджета. Сопутствующие показатели — Coverage по каждому бюджету, FullSupport@2048 и MRR при бюджете, который задаёт конкретный порядок. Интервалы считаем парно по траекториям.

Делим 352 различные dev-траектории пополам по SHA256('frontier-v1/'+ID), без пересечения источников между половинами. Параметры и индексы выбираются только на первой половине. Вторая оценивает эту процедуру, без последующего переобучения и смены правил. Все заранее названные варианты публикуются на test с замороженными настройками. Поскольку исходная надстройка уже выбиралась на полном dev, это независимость выбора маршрутизатора, условная на родительские модели. Тест ранее использован для других вопросов по этим моделям. Определяем α как коэффициент добавления к замороженному баллу уже обученной линейной поправки. Возможные α — 0, 0,25, 0,5, 0,75, 1. Веса выбираются по средней Coverage, при равенстве предпочтителен меньший α. Для свободного двухпозиционного маршрутизатора разрешены 0 и 1 отдельно на каждый бюджет. Дополнительно даём свободную настройку всех пяти α по бюджету. Для плавного правила выбираем начальный и конечный бюджет из заданной сетки, α=0 перед началом, α=1 после конца, между ними линейно по log2(B), с округлением к ближайшему разрешённому α. При равенстве метрик выбираем лексикографически меньшую пару порогов.

Проверяем и метод с единственным постоянным порядком на запрос. Закрепляем начало global_role до первого фрагмента, при котором суммарные затраты превысили порог, включая этот фрагмент, затем дописываем остальные узлы в порядке cost_worst без дубликатов. Получатель при любом меньшем бюджете увидит ровно исходный префикс, а освободившийся хвост допускает иную расстановку. Порог 256 либо 512 выбираем той же калибровочной половиной dev. Ранний неизменный фрагмент префикса в сравнении может привести к потерям полного покрытия при 2048. Этот вариант позволяет сохранить один порядок для кеша независимо от бюджета. Также показываем оба готовых ранга, простой фиксированный переход при B≥1024, число требуемых различных порядков и число нарушений вложенности наборов полученных доказательств с ростом бюджета. Данные, исходный смысл метрик и условия стокового сборщика контекста наследуются от R33/budget_loss. При равенстве порядка или качества новизна бюджетной маршрутизации требует отдельного обоснования.

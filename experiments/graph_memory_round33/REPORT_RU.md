# Как графовая память агента выбирает свидетельства при ограниченном контексте

При бюджете 2 048 токенов полное покрытие размеченных свидетельств выросло с **72,97% у Dense-FT до 80,46%** после добавления структуры графа и калибровки стоимости чтения. Метрика Full Support требует покрытия каждого эталонного интервала. Для каждого из пяти обученных Dense-FT ранжировали один и тот же набор фрагментов инструментальных вызовов на 2 000 тестовых вопросах ISETrace из 1 207 траекторий. Все расчёты в этой серии использовали реальные Dense-FT ранги и изначальное правило упаковки. [ISETrace](https://arxiv.org/abs/2609.25913) · [Метод и исходы](budget_loss/REPORT_RU.md)

| Читатель на одном и том же пуле фрагментов | Полное покрытие при 2 048 токенах, пять seed |
|---|---:|
| Только Dense-FT | 72,97% |
| Dense-FT и абсолютные структурные признаки R20 | 78,44% |
| Дополнительно процентили степеней среди узлов той же роли | 79,60% |
| Ролевые процентили и точечная калибровка | 79,65% |
| Ролевые процентили и калибровка по стоимости чтения | **80,46%** |

Первое изменение даёт +1,16 п.п. [0,54; 1,79] к абсолютным признакам. Второе даёт +0,86 п.п. [0,39; 1,32] к ролевым процентилям и +0,81 [0,40; 1,23] к точечной калибровке. Интервалы рассчитаны парным bootstrap по целым траекториям после усреднения их вопросов по инициализациям. Одни и те же тестовые вопросы использовались в прежних сериях. Вывод относится к извлечению свидетельств из траекторий, а проверка исполнения последующих кодовых задач требует отдельного опыта. [Графовые признаки](relative_structure/REPORT_RU.md) · [Функция потерь](budget_loss/REPORT_RU.md)

## Из чего складывается результат

1. **Относительная роль узла.** У двух фрагментов с одинаковой степенью может быть разное положение среди аргументов или результатов инструментов в конкретной истории. Сохраняем обе характеристики. Старый вариант выиграл выбор на малой панели dev80; прирост относится к фиксированной гипотезе и опубликован с этим ограничением. [Эксперимент](relative_structure/REPORT_RU.md)
2. **Стоимость до последнего свидетельства.** Если длинный отвлекающий фрагмент опередил последнее нужное свидетельство, весь набор может выйти за бюджет. Новый штраф учитывает длину таких фрагментов. При одинаковых кандидатах и калибровке по стоимости удаление признаков рёбер снизило FS@2048 с 80,60 до 74,75% на seed 13, парная разница 5,85 п.п. [4,39; 7,33]. [Независимая абляция графа](graph_ablation/REPORT_RU.md)
3. **Разные бюджеты вознаграждают разный порядок.** Оптимизация полного покрытия снижает MRR на 0,95 п.п. [−1,36; −0,53]. Сохранение первых двух узлов прежнего ранжирования восстанавливает 1,00 п.п. MRR и 0,75 п.п. Coverage@512 при FS@2048 80,45%. Для 256 токенов покрытие снижается. В исходной статье ISETrace уже есть метод с фиксацией первых двух плотных кандидатов; отличия здесь в источнике обоих рангов и проверенном компромиссе. [Пять бюджетов и абляции](budget_frontier/REPORT_RU.md) · [Исходная постановка](https://arxiv.org/html/2609.25913v3)
4. **Сила графового сигнала в зависимости от уверенности Dense-FT.** По пяти инициализациям условный приоритет дал +0,09 п.п. FS@2048 относительно прежнего структурного приоритета, 95% ДИ [−0,30; 0,50]. Его преимущества по полной выдаче не подтвердились. [Результаты](conditional_prior/REPORT_RU.md)

## Что получает база данных

При обновлении графа изменились 20 785 процентилей прежних узлов, чья собственная степень сохранилась. Поэтому вместо массовой перезаписи признака поддерживаем число узлов каждой степени внутри роли и вычисляем процентиль при чтении. На 364 состояниях, восстановленных из доступной на тот момент истории 48 траекторий, все 514 порядков совпали с полным пересчётом. При полном чтении после каждого изменения C++-оператор дал ускорение по времени на 8,1% против сильного отложенного контроля, повтор — 7,0%. При единственном чтении в конце быстрее оказался отложенный пересчёт; в NumPy выигрыш при частом чтении также не повторился. [Формула обновления и измерения](incremental_percentiles/REPORT_RU.md)

Для более раннего фиксированного структурного ранжировщика отдельно разделили FP64 на старшие разряды и точное уточнение. SQLite возвращал на 68,83% меньше полезных байтов, порядок совпал для всех 10 000 выдач. Плата на тёплом локальном SQLite — медиана 32,25 вместо 11,70 мкс. Эти измерения описывают отдельный оператор. [Хранение, трафик и задержка](precision/REPORT_RU.md)

## Доходит ли свидетельство до конечного ответа

Независимый опыт на 2 417 вопросах MuSiQue-Ans использовал настоящий замороженный экстрактивный DistilBERT на CPU. При точно выровненном по каждому вопросу размере контекста переход по упоминанию дал 12,50 Answer F1 против 10,51 при поиске второго документа по заголовку, +1,99 п.п. [1,19; 2,79]. Простого упоминания оказалось достаточно для того же F1, что и более сложная локальная формула. Это проверка использования переданного текста в отдельной задаче. [Оценка ответов](musique_answers/REPORT_RU.md)

## Сопоставимость с опубликованными методами

Для seed 13 наш выбор по dev580 даёт 80,60%. Полная локально воспроизведённая R-GCN — 78,85%, Δ +1,75 п.п. [0,15; 3,37]. Сильная абляция без рёбер соседства фрагментов — 80,05%, Δ +0,55 [−1,05; 2,11]. Интервалы в этой серии привязаны к фиксированным инициализациям. Общие вопросы, узлы, упаковка и бюджет проверены поштучно. Каноническая R-GCN выбирает эпоху по Recall@5, наша калибровка — по полному покрытию. Лидерство относительно сильной абляции пока не установлено. [Детали сравнения](budget_loss/REPORT_RU.md) · [Поштучные контрольные суммы](release.json)

Для демонстрации ICDE эти результаты дают интерактивный сценарий: добавить событие, увидеть изменения степеней, настроить бюджет и проверить, какие адреса свидетельств фактически вошли в контекст. В исследованиях по коду уже доступен [инспектор передачи между исполнителями](../graph_memory_round32/code_handoff_demo/handoff.html).

# Ранжирование свидетельств с учётом цены ошибочного чтения

Если перед последним нужным фрагментом в очереди чтения оказывается длинный отвлекающий фрагмент, он может исчерпать контекстный бюджет. Мы проверили, помогает ли при обучении сильнее штрафовать именно такие ошибки. На 2 000 тестовых вопросах ISETrace, при среднем по пяти Dense-FT, **FullSupport@2048 вырос с 79,60% до 80,46%**. Парная разница +0,86 п.п., 95%-й интервал [0,39 … 1,32]. Точечная калибровка с теми же признаками дала 79,65%, разница +0,81 п.п. [0,40 … 1,23]. Сравнение относится к возврату свидетельств при заданном бюджете. [Результаты по seed](transfer-results.json) · [Исходный ISETrace](https://arxiv.org/abs/2609.25913)

## Что изменилось

Мы заморозили предыдущую модель с абсолютными и относительными степенями узлов по роли. Её прежнюю оценку дополняют четыре числовых признака кандидата — исходная плотная позиция, длина в токенах, роль (результат либо аргумент инструмента) и взаимодействие роли с длиной. Позиция и длина логарифмируются. Сравниваемые функции потерь обучают эти же коэффициенты на 196 вопросах и 123 траекториях из исходного train, отложенных при обучении структурных признаков. Ни один коэффициент после dev580 не менялся. Политика выбора на dev предпочла взвешенный по токенам штраф при L2=0,03. На dev полное покрытие составило 462/580 против 458/580 у замороженной модели и 459/580 у точечной калибровки. [Протокол](PROTOCOL_RU.md) · [Веса](models.json) · [Выбор модели](selection.json)

Для одного вопроса пусть P — множество положительных единиц, N — отрицательных, s — баллы, c — стоимость в токенах. Для строго префиксного чтения стоимость до последней положительной единицы складывается из суммы затрат на все P и затрат на узлы N, которые оказались перед ней с учётом разрешения связок. Наша гладкая функция заменяет наименьший положительный балл величиной L = −τ log(mean exp(−sₚ / τ)), τ = 0,25. Для каждого отрицательного j вносим в потерю log(1 + exp(sⱼ − L)) с весом cⱼ / Σ cₙ. Деление на сумму стоимостей и усреднение по вопросам сохраняет равный вклад каждого примера. Сам бюджет 2 048 не входит в формулу обучения. Привязка к этому бюджету происходит при выборе модели по нативному FullSupport@2048. Это суррогат порядка и цены ошибок. На dev для замороженной модели встретились 6/580 вопросов, где официальный оценщик подтвердил полное покрытие интервалов при отсутствии части положительных единиц. Для выбранной модели таких вопросов 5/580. [Поштучная диагностика](dev-results.json)

## Сравнение с R-GCN

На тех же 2 000 вопросах и seed 13, с выбором checkpoint R-GCN по официальным dev580, полная модель R-GCN получила 78,85% против наших 80,60%, +1,75 п.п. [0,15 … 3,37]. Сильная абляция R-GCN без рёбер соседства `content.next` получила 80,05%, разница +0,55 п.п. [−1,05 … 2,11]. С выбором checkpoint по прежним dev500 те же различия составили +2,50 [0,78 … 4,25] и +0,30 [−1,26 … 1,89]. Локальное сравнение графовых моделей относится к одному seed. Оно даёт более высокую точечную оценку бюджетного метода по этой метрике, однако интервал сильнейшей абляции допускает как выигрыш, так и проигрыш. Разница по полному графу относится к дополнительному сравнению, без коррекции за множественные метрики. Доказательства общего лидерства на бенчмарке пока недостаточно.

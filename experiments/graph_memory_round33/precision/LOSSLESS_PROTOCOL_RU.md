# Физическое представление без дублирования исходной оценки

В первичном тесте иерархия 4+4 снижала объём уточнений относительно немедленного запроса FP64, но требовала отдельной таблицы точных чисел. После получения этих результатов фиксируем второй опыт. Точное значение IEEE float64 разбивается на старшие 24 бита и младшие 40 бит. Старшая часть определяет закрытый интервал как два значения с суффиксами из нулей и единиц, с учётом знака. Младшие пять байтов запрашиваются только при пересечении интервалов. Для каждой траектории дополнительно попробуем представить 12 бит знака и экспоненты словарём из ≤16 значений и записать номер класса в тетраде. Вместе с 12 старшими битами мантиссы на быстрый слой тогда приходится два байта на узел и таблица классов, а пять байтов суффикса остаются без изменений. Для траекторий с большим числом классов используем плоское 24-битное представление. Точная исходная таблица в обоих вариантах восстанавливается из двух слоёв.

Проверяем сохранение всех 64 бит на каждом узле 1 207 траекторий и точный порядок контекста на пяти инициализациях. Сильные контроли — полная последовательность FP64, сжатая zlib последовательность с полной распаковкой, исходный FP64 при полном неявном разделении, компактный FP32 с выдачей приближённого контекста и варианты без чтения суффикса. Для практического чтения есть две точные стратегии. Последовательная выбирает лидера среди верхних границ и по одному читает спорный суффикс. Пакетная сначала проверяет весь приближённый префикс вместе с первым не умещающимся узлом. Если сертификата мало, в одном обращении SQLite получает суффиксы потенциальных участников результата. Нижняя граница кандидата, на котором суммарная стоимость кандидатов в порядке нижней оценки впервые превысила бюджет, даёт порог. Выше порога гарантированно достаточно токенов для остановки. Сохраняем конкурентов с верхней оценкой не ниже порога, в том числе равенства. Внутри этого множества нужны точные значения только для пересекающихся интервалов. Все варианты получают те же семантические ранги и стоимости.

Первичные системные показатели — полный размер отдельных БД после VACUUM, байты в быстром и холодном слое, доля запросов без уточнений, задержки p50/p95 реальных чтений и фактическое количество дополнительных SQL-вызовов. Холодный слой означает логический раздел данных. В эксперименте SQLite и кэш ОС прогреты. Оценку реального дискового или сетевого чтения по числу возвращённых полезных байтов не выводим. Берём 256 вопросов по хешу и seed 13, семь повторений в перемешанном порядке после прогрева. В этом опыте используются анонимные числовые проекции наблюдений. Возможное отсутствие выигрыша в задержке считаем содержательным результатом.

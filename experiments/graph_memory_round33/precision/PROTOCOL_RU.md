# Сколько точности хранить для графового приоритета

В ISETrace структурный приоритет каждой записи одинаков для всех запросов к данной траектории. При сложении с семантическим сигналом нужны только адреса верхнего префикса, пока следующий документ превышает остаток в 2 048 токенов. Проверяем, можно ли хранить для каждого узла четыре старших бита в быстром слое, уточнять вторую тетраду только для конкурирующих узлов, а точное число читать из исходной таблицы лишь в последнюю очередь. Фильтрация по верхней и нижней границам известна в top-k и многоступенчатом поиске. Новая измеряемая величина здесь — стоимость точного чтения конечного контекста агента из многоуровневой памяти. [Theobald et al.](https://www.vldb.org/conf/2004/RS17P3.PDF)

До получения результатов фиксируем все 2 000 исходных вопросов ISETrace, все пять ранее обученных E5 и один и тот же структурный prior. Модель кандидатов и окончательная проверка — по неизменённым прогнозам R21. Ранги повторяются на одних вопросах. Первичный контраст на уровне вопроса — число логических байтов уточнения при четырёх горячих битах с получением восьми дополнительных байтов сразу либо с промежуточным чтением одного байта (по две тетрады в байте). В пределах одного вопроса обращение за обеими тетрадами одного байта учитываем один раз. Более сильные контроли — восемь бит в горячем слое с точным резервом, FP16 с сертификатом, полностью точная таблица FP64 и локальный точный словарь уникальных чисел. Отдельно сравниваем приближённый вывод середины интервала с точным упорядоченным префиксом. Оплачиваем границы шкалы, группировку по траектории, горячий и полный размер. Позднее измерение времени и страниц SQLite описываем своим протоколом.

Пары сравниваются в порядке убывания балла, равные баллы разрешаются семантическим рангом. Если нижняя граница текущего лидера не уступает верхним границам всех остальных с учётом порядка при равенстве, лидер уже определён. Иначе уточняем кандидата с максимальной верхней границей. Если он точен, уточняем лучшего пересекающегося конкурента при необходимости. Извлечение заканчивается при первом точно установленном превышении бюджета или исчерпании списка. Префикс должен точно совпасть со всем списком выбранных ID у каждого seed каждого вопроса. Первичное сравнение не использует разметку, а знание ранее опубликованных рангов не позволяет считать опыт независимой проверкой качества модели. Счётчики видимых байтов не измеряют физический ввод-вывод. Проверим также количество холодных ключей и стоимость группового доступа. Контекст конечного ответа LLM не генерируется.

# Влияет ли сохранённый адрес поиска на реальное чтение и исправление

Единица — одна публичная математическая задача SymPy. Выбираются все последние десять позиций [20:30] в фиксированном SHA-порядке R6 transfer. Первые 12 ранее использовались в генерации R6, следующие восемь в R7. Для последних десяти проводили CPU-локализацию, эти задачи новые для нашей GPU-генерации. Смотрели только публичные заголовки для проверки тематики. Проект один, это конечный парный пилот. Оба варианта запускаются на каждом issue; порядок вариантов для каждой задачи фиксируется хешем. Любой базовый/эталонный сбой отмечается, замены задач нет.

В обеих руках одинаковые issue, публично выбранный в R6 пул не более восьми исходных файлов, модель Qwen3.8-27B (UD-Q4_K_M) на локальной RTX 3090, детерминированное greedy-декодирование и один случай попытки исправления. Источник считывается из зафиксированных версий; тесты, патч и эталонные координаты недоступны до запечатывания ответов. Начальный короткий буквальный поисковый запрос генерирует модель, общий для пары. Реальный rg -n -i -F с этим литералом вызывается по доступным файлам; первый типичный результат не фильтруется по эталону. До восьми совпадений из разных файлов выдаются round-robin, начальный порядок файлов — R6. Каждое доступно как путь, строка и обрезанный текст. Ноль совпадений и невалидная команда отражаются в наблюдении. Список совпадений остаётся в журнале у обоих вариантов и снабжён одинаковыми номерами, которыми может воспользоваться агент.

После общей выдачи два адаптивных инструментальных шага. Агент выбирает чтение по номеру совпадения, по явному пути и строке, новый поиск или завершение. Окно содержит до 28 строк (9 перед адресом), не более 470 токенов, максимальная выдача на каждый поисковый вызов 8 совпадений. Показ строк идёт из текущей базовой версии. Невалидная команда расходует один шаг; автоматически предоставляемой замены нет. На последнем шаге новый поиск разрешён и может дать контекст финальной генерации. Состояние указателя обновляется первым показанным совпадением последнего непустого поиска, сбрасывается чтением (включая невалидный номер) и пустым поиском. После успешного поиска в treatment дополнительно показываем явную запись «адрес последнего поиска, номер совпадения, файл, строка». В сильном контроле сохраняется полная пронумерованная выдача и все те же операции, но нет отдельного поля с дублированной ссылкой. При отсутствии указателя ветки получают одинаковые промпты. Запись основана только на состоявшемся вызове. Читатель сам выбирает адрес, конфигурация не расширяет допустимые файлы. Это тест явного выделения указателя при наличии полной истории, коротком горизонте и стабильном checkout; долговременная передача адреса после сжатия отдельно не проверяется.

На генерацию патча одинаковые предельные 850 токенов. Окончательная подсказка передаёт общий issue, допустимые файлы и реально полученные поиски/чтения; техническое поле выделения указателя здесь удаляется. Для эквивалентных запросов используется точный SHA-кеш. Все сообщения, ответы, траектории, выходы инструментов и стоимость записываются. Считаем полные логические токены/время по каждой руке (включая общий начальный запрос), реальные уникальные вызовы и расходы с кешированием отдельно. Инструменты локальные, время rg/чтения измеряется; предварительный выбор файлов и тестовый контур не входят в латентность решателя. Если операция вызвана только один раз и ответ переиспользован, логическое время берётся по исходному измерению.

Первичный исход — все целевые FAIL_TO_PASS и сохранение ранее проходивших PASS_TO_PASS из проверяемой подвыборки до 12 на задачу. Проверяются базовый и эталонный варианты, применимость патча, работоспособность тестового контура и восстановление изменённых файлов после оценки. Парный точный двусторонний McNemar и число приобретений/потерь; при 10 задачах результат разведочный. Вторичные — реальные изменения выбора инструментов, доля подходящих задач с попаданием выбранного чтения в эталонную старую строку, число употреблений указателя (точное соответствие последнему сохранённому адресу, фоновая частота в контроле), успешные применения, объём контекста и цена. Не отбираем только случаи, в которых указатель был полезен; условные показатели вычисляем отдельно. Если не все исходы полны, приводим число доступных. Результат не заменяет стандартную проверку SWE-bench Verified на полном наборе и не даёт оценки SOTA.

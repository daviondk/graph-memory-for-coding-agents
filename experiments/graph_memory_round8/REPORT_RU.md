# Графовая память кодового агента между действиями и версиями репозитория

Восьмая серия отвечает на три практических вопроса. Как снова найти функцию, которую агент уже видел? Когда записанная связь становится неверной? Увеличивает ли доступность записи число решённых задач? Для первого вопроса есть измеримый выигрыш на размеченных изменениях кода. Эксперименты с работающим агентом пока показывают изменение поведения без прибавки к числу прошедших тесты исправлений.

В основном заранее фиксированном эксперименте по восстановлению функции структурные и лексические отпечатки вместе дали 146/157 против 147/157 у лексических. Выигрыш 151/157 обнаружен позже при добавлении информации о положении в Git. Специализированные трекеры рефакторингов и полные агентные системы решают более широкие задачи. Превосходство над SOTA по качеству решений в этой серии не установлено. [Сопоставление с MemTrace, MemDev-Bench, VibeMemBench, SweRank и CodeTracker](LITERATURE_RU.md)

Для дальнейшего изучения приоритет имеет **семантика ребра после изменения кода**. Адрес получателя может быть точным и одновременно выдавать неверный ответ на вопрос об идентичности функции. На следующей панели особенно информативны естественные встраивания, переносы в уже существующие методы и дублированные функции в других проектах. При испытании с агентом нужны отдельные условия с памятью собственного метода, доступом к корректному эталонному свидетельству и обычным поиском. Верхняя граница показывает, способен ли выбранный решатель воспользоваться даже правильным свидетельством.

Поштучные прогнозы, контрольные суммы, протоколы до оценки, запросы моделей, детали исходов и процедуры воспроизведения сохранены вместе с экспериментами. Числа задач между разными постановками и повторными прогонами одного и того же решателя не складываются. [Как воспроизвести](REPRODUCE_RU.md)

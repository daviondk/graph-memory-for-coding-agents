# Проверка на других типах изменений

На момент фиксации известны результаты основной панели Rename/Move, результаты identity.py и описания категорий в эталоне. В новой панели используем все TP Inline Method, Pull Up Method и Push Down Method из того же набора после прежнего тематического фильтра. Порядок, веса, пороги и разбор AST зафиксированы. Это другие записи тех же репозиториев. Показываем пересечение коммитов. Для Pull Up/Push Down сравниваем точный новый адрес у Git, редких отпечатков и комбинации, а также количество верных и неверных уверенных ответов с проверкой предшественника и без неё. Inline — естественные отрицательные примеры для запроса на *самостоятельное определение исходной функции*. Новый владелец встроенного кода был бы другой целью при запросе на происхождение строк; эти постановки различаются. Если после встраивания старый адрес всё же существует в изменённых файлах, такой случай помечаем неоднозначным и исключаем из отрицательных с явным учётом. Прежний метод должен однозначно разрешаться в изменённых Python-файлах. Сначала сохраняются прогнозы без новой разметки и их хеш, затем отдельный вызов оценивает их. Малое число случаев, проценты на такой панели не обобщаем.

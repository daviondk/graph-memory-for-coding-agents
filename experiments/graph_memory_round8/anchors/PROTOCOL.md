# Проверка устойчивых ссылок на ранее прочитанную функцию

Задача памяти — восстановить адрес метода после того, как агент уже видел его в старой версии, а репозиторий обновился. В отличие от предыдущей проверки точности статического ответа в известном файле, здесь неизвестны и текущий путь, и имя. Цель — выбрать конкретное новое определение после реального переименования или перемещения.

Внешняя разметка — Python-oracle проекта RefactoringMiner, ревизия 136ee7da5a3a13e10bea2ca8f4f8342f3fd40c98, раздел src/test/resources/oracle/python-dataset. Просмотр схемы, доступных репозиториев и типов до фиксации допустим. Включаются все подтверждённые записи TP типов Rename Method, Move Method, Move And Rename Method. Три проекта — dit, texar и ffmpeg-python. Исключаем пути/описания специальных security-задач, merge-коммиты и случаи, когда исходное определение не удалось однозначно идентифицировать в Python AST по прежнему имени и суффиксу модуля/класса. Дубликаты одной и той же записи в коммите учитываются один раз. Фильтр по доступности новой цели до выдачи не применяется. Новая разметка не участвует в выделении признаков. Неоднозначные либо отсутствующие новые сущности засчитываются как промах в основном знаменателе. Отдельно показываем метрику на однозначно сопоставимой разметке.

Доступ на записи ограничен старым прочитанным модулем и известным прежним адресом (путь, классы, имя, диапазон). На чтении все методы видят один список функций в изменённых Python-файлах Git против родителя (плюс прежний путь, если он существует). Вложенные функции также извлекаются. Для оценки кандидатам присваиваем идентификатор path, qualname, строка начала. Объективно это поиск внутри известной дельты; размер фронтира и число кандидатов сохраняются. Стоимость чтения новых файлов и разбора не равна нулю и не заменяет интерактивный поиск.

Независимая переменная — какие данные об уже виденном теле функции записать. Структурная политика сохраняет четыре 64-битных отпечатка лексических 5-грамм и четыре отпечатка 5-грамм с нормализованными именами и литералами. В каждом канале берутся наиболее редкие в старом модуле, при равенстве — меньшие хеши. Исключаются шапка функции, её собственная строка документации и комментарии. Все варианты используют один старый адрес и один порядок разрешения ничьей: равенство старого имени, равенство файла и владельца, близость старого номера строки внутри этого файла, затем стабильный лексикографический порядок. Основной бюджет дополнения к адресу — 64 байта. Контроли: прежний адрес без содержимого, восемь наименьших лексических хешей (без учёта редкости), восемь редких лексических, восемь редких нормализованных, полнотекстовое множество всех лексических 5-грамм с Jaccard. Для короткого тела с менее чем пятью токенами используется один отпечаток последовательности. Память каждого компактного варианта оцениваем также по фактическому числу сохранённых отпечатков. Компактные варианты ранжируют по доле сохранённых совпавших отпечатков по всем занятым слотам. Контроль полного текста использует больше памяти.

Первичен парный контраст смешанной политики и восьми редких лексических отпечатков по Hit@1 среди всех запросов с опознанным исходным методом. Ключевые вторичные метрики Hit@3, MRR, доля имеющих хотя бы одно подтверждающее совпадение, сравнение с полным текстом, разделение на переименования и межфайловые переносы. Для основной разности — 95% bootstrap по коммитам, 10000 выборок, seed 81173, при малом числе проектов интервал описывает только эту панель. Сохраняются результаты по отдельным проектам и поражения относительно простого контроля. Для диагностики ложного доверия — доля ошибочных рекомендаций с уникальным лидером при не менее двух совпадениях и при отрыве хотя бы в два отпечатка. В стресс-варианте из пула удаляется настоящий преемник; частоту ложных уверенных ответов считаем отдельно, это искусственная проверка исчезнувшей цели. Не считаем процедуру детектором рефакторингов и не сравниваем свою долю угадывания с опубликованными precision/recall RefactoringMiner. Протокол зафиксирован до оценки сравнительных результатов.

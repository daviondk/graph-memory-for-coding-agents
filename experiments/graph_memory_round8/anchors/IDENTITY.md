# Диагностика сохранения идентичности

После получения агрегатов основной панели фиксируем дополнительную гипотезу для тех же коммитов. Сходство тела даёт ложную уверенность, когда в новой версии присутствует похожая функция, которая сама пережила изменение. Можно проверить происхождение лидера в Git. Для кандидата с другим (путь, квалифицированное имя), чем исходная ссылка, самым дешёвым доступным свидетельством чужой идентичности считаем существование в родительской версии единственного определения по его собственному адресу, с таким же непустым множеством лексических 5-грамм тела. Проверяем это только для лидера. Такой запрос переводится в воздержание. Остальной классификатор доверия остаётся прежним (минимум 2 совпадения и отрыв минимум 2). Ошибочные и верные воздержания, покрытие, условная точность и ложное принятие при удалении эталона считаются попарно. Повторно ранжировать после отклонения лидера не будем. Учитываем стоимость чтения прежнего файла кандидата; наличие предыдущего Git-снимка и дополнительные чтения — требования метода. Выборку уже использовали, пороги по ней не подбираем. Ключевой следующий шаг — проверка на независимых историях с настоящими отрицательными примерами.

К сравнению с Git добавляем более прямой контроль. В первую очередь проверяем сопоставленный по Git путь, затем расстояние от спроецированной Git строки до строки определения, затем прежнее имя. Контроль из route.py ставит равенство прежнего имени на первое место. Обе версии используют одну и ту же карту hunks. В диагностике также показываем их объединение с компактной лексической памятью: восемь редких лексических отпечатков, а при одинаковом числе совпадений — порядок позиционного контроля. Дополнительное оборудование и подбор параметров не требуются.

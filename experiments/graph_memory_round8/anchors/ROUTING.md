# Последовательное чтение файлов

До просмотра результатов ранжирования фиксируем вторичную политику. Если прежний путь присутствует в текущей Git-дельте, агент может сначала прочитать только этот файл. При двух и более совпавших хешах и отрыве хотя бы в два хеша среди кандидатов файла принимается локальный ответ. Иначе читаются все изменённые Python-файлы. Считаем число открытых файлов и исходные байты распакованных Git-блобов на один запрос без кеша между запросами. Индекс путей дельты доступен всем политикам. Сравниваем с постоянным чтением всей дельты и только старого файла. Основные исходы — Hit@1 и средний объём прочитанных байтов. Это дополнительное измерение стоимости восстановления адреса. Отдельно проверяем слепое доверие локальной подсказке при удалении истинной цели из списка кандидатов. Для основного парного контраста отпечатков используем ранее зафиксированный протокол.

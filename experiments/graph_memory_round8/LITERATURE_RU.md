# Где проходит граница научного вклада

Целевой поиск по исследованиям памяти кодовых агентов, отслеживанию функций в Git и локализации по описанию задачи дал три разных уровня оценки. Для них нужны разные контрольные методы и знаменатели. Ниже первичные работы, влияющие на интерпретацию этой серии.

| Работа | Что реализовано или измерено | Как это влияет на наш эксперимент |
|---|---|---|
| Xu и соавт., *MemTrace* | Историю действий связывают с файлами, символами и тестами. При восстановлении контекста система проверяет прежние свидетельства на текущем состоянии репозитория. Оценка включает DeepSWE, SWE-EVO и SWE-Milestone с агентом. | Граф истории, проверка актуальности и компактная ссылка уже описаны. Предмет нашей гипотезы уже: по каким дешёвым наблюдениям можно восстановить или отклонить конкретное ребро после изменения кода. [Препринт](https://arxiv.org/abs/2610.04838) |
| Chen и соавт., *MemDev-Bench* | К 555 базовым задачам привязаны релевантные и нерелевантные истории из того же репозитория. Авторы сравнивают функциональную корректность, шаги агента и ошибки повторного использования истории. | Если после встраивания функции память предлагает другого владельца кода, это можно проверять по цене ложной подсказки и исходу целевого теста. [Препринт](https://arxiv.org/abs/2610.27524) |
| Fan и соавт., *VibeMemBench* | 111 задач из 90 репозиториев, для которых найден полезный в референсной конфигурации опыт. При переносе на других решателей непосредственно переданная история и память, которую система должна извлечь самостоятельно, дают разные результаты. | Для интеграции нужны три условия: без памяти, с корректным адресом, с адресом, найденным исследуемой политикой. Разница между двумя последними показывает цену ошибки извлечения. Отбор задач должен быть виден при интерпретации. [Препринт](https://arxiv.org/abs/2609.23570) |
| Reddy и соавт., *SweRank*, ICLR 2026 | Обучаемый поиск и вторичное ранжирование по описанию issue на уровне программных сущностей. Публичны модель, код и наборы. | На общей панели можно изолировать добавочный вклад наблюдённого символа и ребра вызова, используя оригинальные веса. Сопоставление с итогами статьи требует полного корпуса, той же версии и размера модели, правил агрегации функций и метрик. [Статья](https://proceedings.iclr.cc/paper_files/paper/2026/hash/7f6901ebab786e43b21530328fc989ca-Abstract-Conference.html) · [Код и команды авторов](https://github.com/SalesforceAIResearch/SweRank) |
| Jodavi и Tsantalis, *Accurate Method and Variable Tracking in Commit History*, FSE | CodeTracker восстанавливает историю изменений методов и переменных. Авторы используют размеченные истории Java и оценивают precision и recall событий. | Номер строки, Git-проекция, сохранившиеся строки тела и специализированный трекер — естественные конкуренты для версионного ребра памяти. Здесь мы выбираем адрес в одном переходе Python, поэтому цифры CodeTracker из статьи нельзя переносить в нашу таблицу Hit@1. [Статья](https://users.encs.concordia.ca/~nikolaos/publications/FSE_2022.pdf) |
| PyRef и уточнённый Python oracle RefactoringMiner | Публичные описания реальных преобразований кода с версиями, валидаторами и названиями инструментов. Статус повторной проверки различается между записями. | Для нашей задачи взяты подтверждённые пары старой и новой сущностей. Они позволяют тестировать точность адреса и не задают распределение всех изменений Python или полноту детектора. [Описание](https://github.com/tsantalis/RefactoringMiner/blob/136ee7da5a3a13e10bea2ca8f4f8342f3fd40c98/documentation/accuracy.md#python-benchmark) · [Зафиксированная разметка](https://github.com/tsantalis/RefactoringMiner/blob/136ee7da5a3a13e10bea2ca8f4f8342f3fd40c98/src/test/resources/oracle/python-dataset/data.json) |

Для статьи интересен вопрос о жизненном цикле одного ребра памяти. Агент записывает связь наблюдения с определением. Изменение репозитория порождает три решения — оставить прежнюю связь, привязать к другому адресу либо воздержаться. Сохранившиеся строки Git учитывают происхождение текста, отпечатки учитывают перекрытие содержимого. Эти сигналы могут расходиться при перемещениях, переименованиях и дублированном коде. Практическая гипотеза состоит в том, что проверка ошибки привязки перед выдачей контекста сокращает повторное чтение или увеличивает долю исправлений, проходящих тесты. Измерения этой серии позволяют оценить предпосылки такой гипотезы; проверяемое улучшение всего агента требует отдельных задач.

Для будущего прямого сравнения с MemTrace разумно зафиксировать конкретный снимок задачи, версию агента, модель, лимит контекста, политику сжатия, список исторических наблюдений и тестовый образ. Варианты должны видеть один поток событий до точки чтения. Сравниваем MemTrace с заменённым только модулем привязки, исходный MemTrace, вариант без памяти и верхнюю границу с корректным адресом. Полный проход включает сравнение по парным исходам задач и затратам на запись, проверку и чтение. Это проект следующего сравнения, воспроизведение MemTrace в этой серии не проводилось.

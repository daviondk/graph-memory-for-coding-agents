# Дополнительная проверка после основного анализа

В первичном прогоне пять селекторов делили одну и ту же 4-адресную таблицу. Переносим сравнение на реально различающиеся реализации хранения. До расчёта этой абляции фиксируем два новых режима: один или четыре первых адреса по файлу при самостоятельном LRU и точном лимите 128 или 512 байтов. Одинаковые fallback, сроки жизни, выдача одной строки и сериализация. Проверяем first@1 vs first@4, занимаемые байты, размер снимков и добавочный выигрыш кодирования: сравниваем на собственных состояниях лучший обратимый код для каждого режима (включая произвольный сохранившийся в памяти файла адрес). При смене инвентаря цена полного явного снимка считается для каждого режима отдельно. Это сравнение способов хранения при фиксированном лимите.

Чтобы исключить особенность одного детерминированного псевдослучайного индекса, для 4-адресного режима аналитически вычисляем ожидаемую долю попаданий равномерного выбора среди доступных адресов. Удаление привязки этих строк к предыдущему месту чтения — контроль структуры на одинаковых кандидатах. Новых траекторий и независимой проверки выбранных после первичной оценки идей здесь нет.

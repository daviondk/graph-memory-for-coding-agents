# R8. Выбор одного адреса по известному пути и стоимость передачи диапазона

Протокол до извлечения входов и подсчёта новых метрик. Повторный анализ существующих открытых траекторий. Результаты прежнего безусловного предсказания R7 уже известны. Гипотезы и условия этого раунда на этих панелях ранее здесь не измерялись. Закрытой тестовой выборки здесь нет.

## Ряд экспериментов

1. Когда агент уже передал путь к Python-файлу, но будущие строки ещё неизвестны, выбирать ближайший к последнему обычному просмотру адрес из первых четырёх найденных grep строк. Ожидаем больше попаданий в последующее наблюдаемое множество строк, чем при выборе первой строки grep для этого же файла. Один указатель на запрос в обоих вариантах. Ожидание фиксируется для основной панели Kimi, те же параметры переносятся на Claude и непересекающуюся репликацию Kimi. Заведомо полная доступность будущего диапазона нигде не предполагается. Размер строки и число других строк в ответе агента не используются для выбора.
2. Для успешных чтений с явно заданным конечным диапазоном проверить, насколько компактнее передавать точный адрес запроса через сохранённое ребро «предыдущее наблюдение → адрес». Декодер имеет только префикс траектории и кодовое слово. Первичная метрика — число байтов сверх сильного режима с таблицей путей, последней позицией в файле и одним активным первым адресом последнего поиска, выигранных при добавлении нескольких ранее виденных поисковых адресов по файлу. Учитывать полное число случаев, объём таблицы, стоимость её явного сообщения и проверку точного декодирования. Минимум по валидным кодовым словам представляет достижимую для программы длину при заранее известном запросе. Для модели без интерфейса чтения таблицы это идеальная оценка.

## Данные и реализация

Используются все заранее отобранные безопасные эпизоды R7 search и followup. Ветви Kimi и Claude по разным задачам. Принимаем только обычные обращения к коду, где путь определяется из исходных аргументов. Для редактора используем поле path. Для shell — команды чтения с ровно одним явным путём к .py, без подстановки переменных и перехода в другой каталог, с проверкой совпадения наблюдаемого результата. Работаем с проекцией R7 и потому сохраняем адреса первой распознанной группы одного файла в результате поиска. Деноминатор включает эпизоды и обращения без предшествующего поиска. Явные конечные границы для эксперимента 2 — view_range и простой sed -n с положительными числами. Названия задач, тексты и решение модели в политике не используются.

На каждый эпизод сбрасывается словарь с LRU-вытеснением путей и состоянием до 512 байтов канонического компактного JSON (дополнительно 128). Для файла сохраняем последние до четырёх различных строк одного поиска и последнюю медианную строку обычного просмотра. Обычное чтение обновляет медиану. Результат поиска сохраняется до нового поиска в том же файле, вытеснения или распознанной правки. После правки удаляем файл. Контроль глобального первого grep использует прежнее время жизни до следующего распознанного обычного обращения/правки и последнюю наблюдавшуюся позицию как резервный вариант. Учёт состояния у этого контроля отдельный. Контроли для той же таблицы — только последняя позиция по пути, первая найденная grep-строка по пути и выбор одного адреса тем же набором, но с произвольным воспроизводимым индексом. Если позиции нет, стартуем со строки 1. Между равноудалёнными адресами выбираем более ранний в выводе поиска. Потолок по всем четырём адресам выводится отдельно. Дополнительные метрики — попадание в первую 16-строчную страницу, диагностика коротких ответов и количества активных прогнозов.

Формат передачи диапазона — однозначный бинарный префикс типа варианта, далее ULEB128 индексы, позиции и длины, ZigZag для смещений, UTF-8 для буквального пути. Сравниваются вложенные режимы literal, path, cursor, latest-search, multi-search. Последний вариант адресуется индексом в плоском списке поисковых строк LRU-таблицы. Кодировщик выбирает самый короткий доступный вариант, декодер восстанавливает тройку (путь, начало, длина). Отдельно считаем стоимость публикации снимков поисковых адресов, если эти адреса необходимо дополнительно показывать агенту.

Первичный анализ выбора строки — парная разность hit rate, 95% процентильный bootstrap по задачам, внутри панелей. Несколько обращений одной задачи пересэмплируются блоком. Абсолютные числители, знаменатели и расхождения обязательны. Ограничение — число токенов LM, pass rate изменений, польза для живого агента и сравнение с SOTA этими исходами не измеряются. Протокол и хеши входов, прогнозы, поэлементные результаты и агрегаты сохраняются локально.

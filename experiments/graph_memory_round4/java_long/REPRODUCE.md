# Репликация диагностики с 30 последними строками

Использованные входы и хеши исходных файлов перечислены в `long_data_lock.json`. Скрипт подготовки рассчитан на каталоги round4/java_reader и round4/repo с исходными панелями B и RepoBench-R Java test v0, на токенизатор из `java_reader/prepare.py` и установленные PyArrow и tokenizers. Версия сравнительного генератора фиксируется контрольными суммами `infer.py` и артефактами сервера в `../repair/model_receipt.json` и `../repair/runtime_receipt.json`. Запросы адресованы только локальному серверу. Перед повторной генерацией используйте отдельную копию каталога, поскольку исходные журналы сохраняют все ответы первого прогона. Для полной повторной оценки с исходными ответами доступ к GPU не требуется.

1. Сверьте исходные наборы с `../java_reader/B_data_lock.json`. Выполните `python prepare_long.py`. Проверьте 96 записей, четыре группы по 24 и 56 проектов. Журнал `source_selection.json` фиксирует порядок кандидатов, `long_data_lock.json` — окончательный набор.
2. Запустите такую же локальную сборку, как в `../repair/start_server.ps1`. Для новой генерации выполните `python -u run_long.py` в отдельной копии. Для воспроизведения оценки с сохранёнными ответами пропустите обращения к серверу. В `long_calls/` каждому уникальному запросу соответствует отдельный файл с полным входом, ответом, счётчиком токенов и измеренным временем запроса. `long_decisions.json` служит описью их SHA256. Один и тот же фрагмент у двух способов чтения одного задания потребляет один измеренный вызов.
3. В Python c NumPy и PyArrow выполните `python score.py long`, затем `python extended.py --short --include-empty`. Последняя команда требует запечатанных ответов и оценок B, а также запечатанной серии Z (короткий префикс без внешнего фрагмента) из соседнего java_reader. Поле `physical_requests` в исходном сравнительном scorer означает число уникальных входов. Отдельные сравнительные подсчёты содержит `long_extended.json`.
4. `long_items.json.gz` содержит эталонную и сгенерированные строки, исходные значения метрик, идентификаторы проектов и соответствие ранга эталону. `short_long_compare.json` содержит парные разности, интервалы, победы и поражения на тех же заданиях. Новые примеры, проекты и модели для этого сравнения не добавляли.

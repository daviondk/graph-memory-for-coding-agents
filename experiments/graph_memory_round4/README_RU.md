# Рабочая графовая память. Серия 4
Полный текст исследования хранится в report/artifact.md и в оформленных версиях graph-memory-research-round4.pdf и .docx каталога outputs. Сводный документ объясняет происхождение задач, условия сравнения и ограничения выводов каждой серии. Исходные значения отдельных панелей связаны по ID, сложение пересекающихся панелей недопустимо.

| Вопрос | Что было запущено | Где лежат данные и воспроизведение |
|---|---|---|
| Какие внешние объявления вспоминать | Замороженный ранжировщик графа и контроли, опубликованный scorecard, настоящий Semlith, полные Java-архивы, контроль переноса и перестановок | repo/RESULTS_RU.md, repo/REPRODUCE.md, результаты по примерам в repo/*.scores.jsonl.gz, исходные ranks в repo/*.pred.jsonl.gz |
| Как построить граф по мере открытия фрагментов | Точный пересчёт, дозапись с обратным словарём, облегчённая дозапись с обновлением веса при появлении одноимённого объявления, контроль с холодным разбором и полноценным ранжированием | repo/INCREMENTAL_RU.md, repo/LEAN_RU.md, repo/LEAN_COLD_RU.md, repo/*cycle*, repo/*lean*, repo/archive_streaming* |
| Как граф соотносится с опубликованным энкодером | Локальный UniXcoder на исходных open weights, два окна запроса и две схемы обрезки, объединение рангов | encoder/RESULTS_RU.md, encoder/REPRODUCE.md |
| Влияет ли прочитанный фрагмент на генерацию | Настоящие вызовы Qwen, одна модель, варианты памяти, экономия токенов, короткий и длинный префиксы, правильный фрагмент как диагностический оракул | java_reader/RESULTS_RU.md, java_long/RESULTS_RU.md, java_reader/*calls и java_long/long_calls |
| Какие строки хранить и когда обновить адрес | Пошаговое наблюдение реальных траекторий Claude и CodeSweep/Kimi K2, размер состояния 4 КиБ, перенос между агентами | writer/RESULTS_RU.md, writer/anchor/RESULTS_RU.md, writer/REPRODUCE.md |
| Какой объём требуется для чтения | Реальное кодирование и декодирование каждого сообщения, повторная загрузка при несовпадении | action/RESULTS_RU.md, action/REPRODUCE.md |
| Какие наблюдения тестов сохранить для исправления | Локальный Qwen, запуск реальных Python-программ, численный анализ каждого теста и прогон полных исходных проверок | repair/RESULTS_RU.md, repair/audit.json, repair/per_task.json.gz, repair/full_suite_items.json.gz |
| Как сверить выпуск | Архивные манифесты, SHA-256, CRC, выборочный повтор на распакованной копии, проверка основных результатов из сырых данных, проверка документа | package_round4.py, report/cross_audit.py, report/final/cross_audit.json, report/final/qa.json |

Python и Java использовали один и тот же собственный локальный inference-сервер и один GGUF, точные сведения в repair/launch.json, hardware.json, model_receipt.json, runtime_receipt.json и stop.json. Универсальный внешний сервис для выставления оценок не использовался. Источники данных и закрываемые до оценки файлы имеют хеши в каждой ветке. Для полного пересчёта из исходников нужны большие скачиваемые датасеты и открытые модельные веса на D. В архиве сохранены компактные решения по примерам, программные зависимости собственной разработки и инструкции их повторной проверки.

Общая сверка run_totals.json обнаружила 1 688 различных идентификаторов фактических ответов GPU-сервера, 438 796 входных и 36 588 выходных токенов. Три ответа упёрлись в лимит длины; их оценили по общему правилу. Сервер штатно остановлен после последней серии генераций.

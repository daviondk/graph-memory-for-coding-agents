# Может ли агент по старым наблюдениям выбрать уже предложенное исправление

Дополнительный эксперимент зафиксирован после подготовки истории, до вскрытия качества любых предложений. Те же 64 задачи. Формируем по три независимых от содержимого памяти предложения: жадная генерация с пустой памятью из базового опыта и две новые генерации с точно такими же сообщениями, температурой 0,7, top-p 0,95 и разными заранее зафиксированными seed. Три кандидата неизменны для сравнения всех выборщиков. Реальные коды выполняются на доступных им исторических проверках. По числу совпавших проверок выбираем лучшую программу, при равенстве берём более раннюю из тройки (жадная, сэмпл 1, сэмпл 2). При пустой памяти это в точности жадная программа. Основной контраст — ограниченная память объединения против контроля с приоритетом последних упавших. Внешний исход — все новые входы прошли; также сообщаем число смен выбранного кандидата, потолок лучшего из трёх по скрытым тестам только для диагностики и вычислительную стоимость трёх генераций.

Второй сценарий — отдельное условие с доступом к архиву старых тестов. Тройка та же, после начального выбора можно сделать один запрос к архиву. Чтобы честно учесть допуск к архиву и дополнительную обработку, сравниваем недавний невыбранный тест, невыбранный тест, на котором исходная программа упала (ближайший к концу, если такого нет — последний), и адресный запрос. Для адресного запроса сервер выполняет все три кандидатные программы на архивных входах, не открывая ожидаемые значения выборщику. Выбираем вход, разбивающий пока лидирующие программы на максимальное число пар с различающимися выводами. При равенстве предпочитаем разбивающий всю тройку, затем недавний. Ответ сервера — одна старая проверка с ожидаемым результатом. Выборщик повторяет голосование, используя эту проверку вместе с изначальной памятью; все три политики могут обратиться в архив один раз. Теоретический смысл — если оставшиеся кандидаты дают одинаковое наблюдаемое поведение, его проверка не может помочь различить их. Такое использование контрпримеров известно в активном обучении и test-based patch selection. Издержки поиска входа, вычислительные ограничения, число реальных различий и случаи ложного соответствия отражаем в журнале. Этот сценарий подразумевает внешнее хранилище прежних тестов и процедурный поиск по нему. Отдельно от постоянной памяти учитываем временную третью запись и стоимость сервера. Не предсказываем и не читаем новые входы до фиксации решений. Основное сравнение для условия одного чтения — адресная политика против чтения последней упавшей проверки при одной и той же начальной памяти union. Остальные результаты рассматриваем как разведочные. При нескольких первичных endpoint (нейроредактор, селекция без чтения, селекция с чтением) даём также поправку Holm.

# Какой опыт тестирования стоит запомнить до следующего исправления

18 ноября 2026 года. План до оценки политик и вызовов модели. Историей служит последовательность опубликованных регрессионных проверок алгоритмических Python-функций HumanEvalFix. Агент знает исходную ошибочную функцию, сохранившиеся старые утверждения с ожидаемым результатом и отметку об их прохождении на старой версии. Полный контракт и авторское решение в запрос не включаются. Нам важно, какие прежние наблюдения реально помогут следующему ремонту. Сценарий условный: существовали старые тесты с верными ожидаемыми результатами, но их журнал больше не вмещается в рабочую память. До четырёх вариантов параметров здесь не подбираются.

Предлагаем связывать каждое наблюдение с правдоподобными альтернативами реализации, которым оно противоречит. Альтернативы получаем из самой ошибочной функции фиксированными одношаговыми AST-изменениями обычных операторов, границ, min/max и условий. Максимум 24 альтернативы плюс исходник на задачу, отбор по хешу. Доступно максимум два примера, до 384 байтов сериализованного переменного состояния (исходник и фиксированный алгоритм доступны всем, расход генерации масок измеряется отдельно). При поступлении нового наблюдения разрешено рассмотреть только его и текущую память. Лучший допустимый набор выбирается по суммарному весу объединения исключённых альтернатив. Вес исходной ошибочной функции равен числу альтернатив, каждая другая альтернатива весит единицу. Если две проверки исключают один и тот же вариант, совместная полезность начисляется однажды. Это вариант задачи максимального покрытия, а тестирование мутантов и сокращение набора тестов — известные методы. Новизна здесь исследовательская: ограниченная рабочая память при передаче реальному исправляющему агенту с проверкой на новых входах.

Сравниваем пустую память, две последние помещающиеся проверки, приоритет последних упавших, сумму индивидуальных весов без скидки за повтор и объединение. Одинаковая вместимость и общий формат свидетельства у четырёх ограниченных политик. Проверим также весь журнал как дорогую границу у детерминированного решателя. Внутренние маски нужны политикам для выбора и в промпт не попадают. Проверяем программу ремонта из того же дискретного множества с фиксированным приоритетом и независимый локальный Qwen3.8-27B UD-Q4_K_M на RTX 3090, температура 0, без thinking, одна попытка, до 640 выходных токенов. Основной запрос Qwen получают память исключённых альтернатив и контроль по последним упавшим, также пустой контроль. При совпадении стимулов ответ используется повторно. Детерминированный и нейросетевой решатели оцениваются отдельно. Порядок физических запросов по хешу.

Корпуса — Python HumanEvalPack 164 примера, ревизия 9a41762f73a8cb23bb5811b73d5aab164efcf378, и опубликованный HumanEval+ OriginFmt v0.1.10. Разделяем доступные прошлые тесты и новые входы для оценки. Берём однозначные прямые вызовы с литеральными аргументами из исходного HumanEval; видимы только такие утверждения, прошедшие проверку ограниченного синтаксиса, помещающиеся в самостоятельную запись, без дублей аргументов. Для независимого оценивания берём авторские заранее вычисленные входы, эталоны и допуски стандартного компаратора OriginFmt, исключаем ВСЕ аргументы из доступной истории, включая невместившиеся и невыбранные. Остальные формы задания учитываем в журнале отбора. Дубли новых входов по аргументам убираются. Для одинаковой исполнимости ограничиваем размер и стоимость отдельного входа заранее, выбираем по хешу до 64 новых входов на задачу. Требуем минимум 3 прошлых примера и 4 новых. Примеры Python/0,1,2 были просмотрены для понимания формата и исключены. Условия отбора применяем до инференса; для отобранных задач источник поддерживает изолированную чистую вычислительную среду, опубликованный эталон проходит выбранные проверки, старая функция ошибается на новых. Данные ранее использовались в иных экспериментах; отдельно сообщим пересечение идентификаторов. План — до 64 задач по хешу, все получают все политики. Для нейросетевого сравнения используем ту же панель. Рабочие тесты библиотеки не считаются новыми входами.

Главный исход — полностью исправленная функция на всех выбранных новых проверках; главный контраст Qwen с объединением против приоритета упавших. Сообщаем поштучные результаты, парный разрыв, 95% парный bootstrap задач, точный тест Мак-Немара, долю отдельных новых тестов и число различающихся подсказок. Отдельно полный публичный suite в прочитанном поднаборе доступных регрессионных проверок, стоимость промпта, изменяемые байты, ошибки формата, ограничения среды и вычисления. Для гипотезы о переносе важна генерация нового кода, а улучшение на самом наборе мутантов является внутренней проверкой. Совпадение названия бенчмарка не разрешает сравнивать цифры с официальным рейтингом HumanEvalFix или EvalPlus. Постановки доступа к тестам различаются.

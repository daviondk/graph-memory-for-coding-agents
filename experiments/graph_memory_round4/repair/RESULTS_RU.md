# Какие два теста стоит запомнить перед исправлением
> На 64 функциях из HumanEvalFix два прошлых теста подняли результат локального Qwen3.8-27B с 43 до 53 исправлений. Простой приоритет упавших тестов дал все те же 53 успеха, что и запись по графу.
Из HumanEvalPack взяли ошибочную Python-функцию и историю доступных проверок. Из расширенного HumanEval+ выделили другие входы. Число наблюдений составило 418 до исправления и 3 869 для последующей оценки. Из 164 исходных задач 115 прошли калибровку, 64 выбраны по хешу. Пятьдесят идентификаторов встречались в предыдущей серии. Публичные задачи могли быть знакомы и самой модели.
Опыт проверяет двудольный граф. Слева в нём тесты, справа — исходная программа и её локальные изменения, например замена «меньше» на «меньше или равно». Ребро означает, что программа провалила тест. При записи нового события оставляем до двух тестов в пределах 384 байт. Из старых и нового выбираем набор, который совместно отсеивает наибольший вес ошибочных вариантов. Повторное отсеивание того же варианта ничего не добавляет.
| Что видит Qwen | Все новые тесты, из 64 | Пройдено входов, из 3 869 | Вся исходная проверка, из 64 |
| Ошибочный код без сохранённых тестов | 43 | 3 086 | 43 |
| Две записи с приоритетом ошибок | 53 | 3 578 | 53 |
| Два теста с общим покрытием графа | 53 | 3 592 | 52 |
Граф изменил подсказку в 30 задачах. На новых входах выигрыш против пустой памяти составил 10 побед при нуле потерь, парная разница +15,63 п.п., 95% интервал [7,81; 25,00]. Выигрыш против приоритета упавших равен нулю задач. Полный неизменённый набор HumanEval+ дал по всем 64 функциям 39, 49 и 48 успехов соответственно. На нём эталон HumanEvalPack прошёл 57 задач, поэтому в журнале отдельно приведена откалиброванная группа.

# Почему граф помог выбрать патч только в узком случае
> Если решатель выбирает исправление из тех же типов изменений, по которым построена память, граф полезен. Замена этого решателя настоящими программами Qwen позволила проверить перенос механизма.
Внутренний решатель перебирал ограниченный список программ. На 64 функциях правило с приоритетом упавших восстановило 14, индивидуальная полезность двух тестов — 16, покрытие их объединения — 18. При полном доступе ко всем прошлым тестам решено 19. Выигрыш графа над приоритетом ошибок составил четыре победы без потерь. Двусторонний точный парный тест даёт p = 0,125. Расчёт покрытий потребовал 803 запусков исходных и изменённых программ на предыдущих проверках.
| Как выбран один из трёх ответов Qwen | Все новые проверки, из 64 | Пройдено входов, из 3 869 |
| Первый ответ, без чтения памяти | 43 | 3 086 |
| Два упавших теста | 45 | 3 224 |
| Два теста из графа | 45 | 3 228 |
| Граф и дополнительное чтение по расхождению | 45 | 3 186 |
Для внешнего решателя создали три ответа на каждую задачу без подсказок, затем выбирали один из них по тем же старым тестам. Отдельно разрешили прочесть ещё один архивный ответ о тесте, в котором программы расходились. Гипотеза предсказывала, что такое чтение устранит ничью. Лучший доступный кандидат проходил новые тесты в 45 задачах. Уже два простых примера достигли этого потолка. Два правила дополнительного чтения выбрали разные программы всего один раз.
Здесь три заранее заданных основных сравнения получили p = 1 после поправки Холма. Важнее отсутствие практического запаса у процедуры выбора. Сохранённый контрпример до генерации изменил множество предлагаемых решений и дал больший наблюдаемый выигрыш. Полезность памяти для генерации и для выбора уже написанного патча следует измерять отдельно.

## Поштучное воспроизведение
Протоколы PROTOCOL_RU.md, RERANK_PROTOCOL_RU.md и FULL_PROTOCOL_RU.md описывают разные виды доступа к памяти. Последовательность программ: prepare.py, write.py, solve.py, sample.py, decide.py, grade.py, full_grade.py, audit.py. Сервер запускается отдельным start_server.ps1. Для повторного анализа без инференса достаточно audit.py, который сверяет исходные ответы и поштучные квитанции, а grade.py и full_grade.py переисполняют программы. В results.json присутствуют отдельные результаты по каждому методу, поштучные проверки в per_task.json.gz, ошибки полного набора в full_suite_items.json.gz. Всего использовано 46 784 токена входа и 21 510 выхода у 286 запросов. Квоты включали 640 токенов для исправления. Основной исход — доля функций, прошедших все выбранные будущие входы; доли отдельных входов чувствительны к числу тестов каждой задачи. Среднее полное число байт у двух сохранённых записей было 113,44 для графа и 116,97 для приоритета упавших. Внутри ограниченного опыта время выполнения политики включает порождение локальных изменений и их проверку, чего простой приоритет не требует. Полная оценка EvalPlus использует дополнительные случаи и иной режим процесса; на группе с рабочим эталоном 57 задач, у трёх прямых вариантов результаты 39/57, 48/57, 47/57.

Дополнительный поштучный срез sensitivity.json и sensitivity.py учитывает регрессии на старых входах. Одновременно прошли прошлые и новые проверки 43, 53 и 52 прямых исправления; на 14 ранее не использованных в наших экспериментах задачах — 6, 11 и 11 соответственно.

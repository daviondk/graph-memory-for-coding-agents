# Перенос выигрыша Java retrieval в следующую строку

18 ноября 2026 года, после открытых агрегатов выбора объявления и до генерации Java-строк. Исходные данные RepoBench-R v0 содержат настоящую следующую строку и список возможных внешних фрагментов. Мы проверяем сквозную задачу на исходных строках R. В официальном RepoBench-P другие правила доступа к контексту и другие совокупности, поэтому прямое сравнение наших процентов с leaderboard P невозможно.

Один неизменный локальный Qwen3.8-27B UD-Q4_K_M на RTX 3090 получает последние 3 строки исходного файла (если они очень длинные, последние 512 токенов), одну и ту же инструкцию дописать следующую непустую Java-строку и один фрагмент. Фрагмент выбирает (1) зафиксированный граф контекстов обращений, обученный на 5000 Java-примерах из других проектов, либо (2) реально запущенный Semlith 0.36.0 на том же списке, готовый универсальный инструмент. В обеих ветвях берём top-1 и передаём начало фрагмента до 256 токенов одним и тем же токенизатором; бюджеты и фактическое потребление логируем. На начальных 96 случаях включён дополнительный контроль без памяти. На второй панели измеряем основной контраст граф–Semlith во всех до 320 заранее отобранных парных примерах. Обе внешние выборки зафиксированы исследованием поиска независимо от качества генераций, у второй панели проекты отделены от исходной подвыборки и обучения. В извлечении видим только code и context, для оценки в отдельном процессе читаются next_line и индекс эталонного объявления. Состав и тесты хешируются. Для инертных текстовых контекстов, явно связанных с разработкой эксплойтов или оружия, предусматривается симметричный фильтр по имени проекта/пути, трём строкам и обоим передаваемым фрагментам, причина фиксируется без выдачи кода. Данные не выполняются.

Температура 0, thinking выключен, один ответ длиной до 80 токенов, первый содержательный ряд после удаления необязательной разметки тройных кавычек. Пустой или лишний текст учитывается обычным образом, исправлений по ответу нет. В обеих ветвях совпадающие промпты с одинаковым seed физически вычисляем один раз. Основной исход — точное совпадение с next_line после удаления краевых пробелов (EM). Вторичные — сходство символов (округлённая нормализованная Indel similarity, вариант fuzz.ratio), использование токенов, данные при разных выбранных объявлениях, попадание в первое место, текстовые идентификаторы. Независимой единицей неопределённости при повторных задачах служит проект: 10 000 парных групповых bootstrap-повторов. На каждой панели публикуем все случаи и эффекты, даже если улучшение ранга ничего не изменяет в выводе Qwen. Наша постановка измеряет воспроизведение авторской строки; другие правильные реализации возможны. Исходная статья RepoBench использует EM и edit similarity и различает поиск, генерацию и их комбинацию.

# Помог ли лучший поиск написать следующую строку
> На тех же 320 задачах граф чаще отдавал правильное объявление первым. Но Qwen точно воспроизвёл строку автора в 16 случаях с графом и в 18 с Semlith. Преимущество по рангу не перенеслось в основной исход генерации.
Локальный Qwen3.8-27B получал последние три строки видимого Java-кода, один выбранный фрагмент до 256 токенов и одинаковую инструкцию. Температура 0, одинаковые входы вычислены один раз. Метка правильного объявления и следующая строка использовались при оценивании. Проект служил единицей повторной выборки для 95% интервалов. Число точных строк оказалось малым при столь коротком локальном контексте.
![Парный результат](../report/paired-outcomes.png)
У графа три выигрыша и пять потерь относительно Semlith по точным строкам. Парный разрыв −0,63 п.п., интервал [−2,19; 0,92]. Среднее сходство с авторской строкой по шкале 0–100 составило 43,61 и 45,44, разница −1,83 [−3,99; 0,34]. Средняя F1 по множествам идентификаторов — 0,255 и 0,277. Взвешивание по проектам учитывает повторные примеры. Предсказание другой работающей строки может считаться ошибкой.
На первой панели из 96 задач оба поиска дали по четыре точных строки, пустой контекст — одну. График показывает разницу долей на основной панели. Верхние четыре строки обозначают качество поиска, нижняя — результат модели. У официального RepoBench-P другой состав примеров и другое формирование контекста.
~ [RepoBench, исходная постановка поиска и генерации](https://arxiv.org/abs/2306.03091)

# Когда стоит передавать найденный фрагмент модели
> На 320 задачах простое правило чтения уменьшило среднюю длину запроса с 304 до 178 токенов. Модель воспроизвела 13 строк вместо 16 при постоянном чтении графа. Условия для отказа от памяти заслуживают отдельной проверки.
После выбора графом внешнего объявления проверяли, встречается ли имя типа или метода из предлагаемого фрагмента в последних трёх строках. Совпадение открывает фрагмент, иначе модель получает пустой контекст. Правило применили к 121 из 320 запросов. Для контроля в каждой страте выдали граф ровно столько же раз на псевдослучайных позициях. Контроль получил почти такой же средний расход токенов. Для оценки каждого варианта есть ответ модели на тот же пример с памятью и без неё.
| Условие чтения, 320 задач | Точных строк | Сходство, 0–100 | Входных токенов на задачу |
|---|---:|---:|---:|
| Без внешнего фрагмента | 6 | 42,61 | 99,4 |
| Всегда граф | 16 | 43,61 | 303,9 |
| Всегда Semlith | 18 | 45,44 | 310,6 |
| 121 случайная выдача графа | 10 | 43,95 | 178,6 |
| 121 выдача при совпадении имён | 13 | 42,36 | 177,9 |
Относительно случайного контроля правило прибавило 0,94 п.п. точных строк, интервал по проектам [−0,33; 2,37]. Различия в точном совпадении и среднем сходстве направлены по-разному. Дополнительно вычислили распределение результата по всем наборам случайных выдач при тех же квотах. Математическое ожидание — 9,9 строк, вероятность получить 13 или больше — 6,05%. У производственного правила пока нет подтверждённого преимущества при фиксированном расходе.
Относительно постоянного графа средняя экономия составила 126 входных токенов на запрос при потере трёх точных ответов. Индекс и короткие признаки объявления доступны к моменту решения. Расходы на их получение в эту экономию не входят. Для генерации в двух коротких панелях выполнено 1 085 реальных локальных запросов.
~ [Repoformer, выбор момента поиска](https://proceedings.mlr.press/v235/wu24a.html)

## Пересчёт

Использованы процедуры prepare.py A/B, infer.py A/B, score.py A/B (после инференса), selective.py plan/infer/grade, random_control.py, audit.py. Отдельный запуск с тридцатью строками хранится в ../java_long. Верифицированы назначение, хеш и фактическое число использованных токенов 1 085 уникальных запросов. Разбиения A/B не складываются с диагностическими срезами их собственных строк.



## Связь между рангом и исходом

Разрез по 53 задачам, где верное объявление первым нашёл только граф, поясняет расхождение. Qwen воспроизвёл точную строку лишь 5 раз с этим фрагментом и 3 раза с выдачей Semlith. В 35 случаях, где верное объявление нашли оба, модель дала 7 точных строк с каждым. Это описательный срез уже раскрытых результатов. Поштучные группы и примеры внутри каждой пары исходов выбраны по хешу в rank_outcome.json. Если верный фрагмент выбрал только Semlith, точных строк было 0 против 2, если оба промахнулись — 4 против 6. Категории определены по эталону только для последующего анализа.

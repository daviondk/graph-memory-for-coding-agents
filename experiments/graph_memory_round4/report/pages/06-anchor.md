# Как сохранить адреса после правки
> Редактор возвращает агенту пронумерованный фрагмент уже изменённого файла. По нему можно сохранить часть истории даже тогда, когда в памяти отсутствовал полный старый текст.
Алгоритм ищет единственное вхождение нового текста в подтверждении редактора. Он оставляет ранее виденные строки перед заменой и сдвигает адреса строк после неё на известную разницу длин. При расхождении с показанным текстом перенос отменяется. Для оценки обращаем будущую замену по её подтверждению и проверяем побайтовое совпадение полных исходных строк в ранее запечатанной памяти. Поэтому у Claude из 833 замен в этой таблице есть независимый эталон для 831.
@ 7.0 4.0 4.0
| Вытеснение и обновление | Claude, из 831 | Kimi, из 218 |
| Давность, прежнее обновление | 406 | 92 |
| Давность, привязка по новому тексту | 412 | 96 |
| Калиброванное вытеснение, прежнее обновление | 423 | 93 |
| Калиброванное вытеснение и привязка | 431 | 96 |
При неизменном вытеснении по давности привязка добавила 16 и 13 полных совпадений на двух открытых панелях Claude. На третьей панели осталось шесть дополнительных совпадений, +0,72 п.п. [−0,13; 1,70]. На Kimi выигрыш составил четыре попадания без потерь. Из дополнительных строк, которые Claude затем повторно увидел в независимых просмотрах, подтвердились все 320. Для Kimi таких просмотров в выборке не было.
Совместный запуск обоих изменений имел разведочный характер. На Claude он дал 25 дополнительных полных совпадений против обычной давности, +3,01 п.п. [1,29; 4,89] при повторной выборке задач внутри Django и SymPy. На действиях Kimi обе политики с привязкой дали одинаковое число попаданий. Такой контроль показывает, сколько добавляет работа с координатами независимо от сложности вытеснения.

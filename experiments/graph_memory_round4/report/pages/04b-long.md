# Когда внешняя память помогает написать код
> На одних и тех же 96 заданиях более длинный контекст текущего файла увеличил число точных ответов при всех трёх доступных способах чтения. Когда правильное внешнее объявление выбиралось по эталонной разметке, модель воспроизвела 27 строк против 14 без внешнего фрагмента.
До генерации из панели B выбрали по 24 примера из четырёх страт по воспроизводимому хешу идентификатора. В выборку попали 56 проектов. Для Qwen3.8-27B увеличили число последних строк текущего файла с 3 до 30. В среднем это 29 и 257 токенов соответственно. Оба поисковых метода по-прежнему получали запрос из трёх строк. Так можно отделить эффект локального контекста модели от повторного поиска.
@ 5.3 3.3 3.4 4.4
| Внешний фрагмент | Точно при 3 строках | Точно при 30 строках | Сходство при 30, из 100 |
| Отсутствует | 0 / 96 | 14 / 96 | 56,15 |
| Граф | 2 / 96 | 13 / 96 | 55,52 |
| Semlith | 3 / 96 | 15 / 96 | 56,15 |
| Эталонное объявление | — | 27 / 96 | 67,03 |
С графом прибавка при расширении контекста равна 11,46 процентного пункта, 95% интервал по проектам [4,17; 20,00]. При длинном контексте оба реальных метода выбрали эталон по 19 раз. В 12 заданиях его нашёл только граф, ещё в 12 — только Semlith. Это объясняет, почему одного сравнения средней точности поиска недостаточно для выбора способа чтения.
Эталонный выбор доступен только исследователю. Относительно пустой памяти он прибавил 13,54 процентного пункта точных ответов [6,73; 20,83]. Ни один переданный эталонный фрагмент не содержал готовой следующей строки целиком. Такой контроль показывает, что модель способна использовать внешнее объявление в этих условиях. Получить ту же пользу без доступа к разметке предстоит проверить отдельно.

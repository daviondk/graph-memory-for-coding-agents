# Академический контроль UniXcoder на строгой Java-панели

Оцениваем ранжирование кандидатов RepoBench-R. Во всех режимах одни и те же 320 ранее выбранных для Semlith-независимого теста строк в paired_roster.json, по 80 в каждой из CFF easy/hard, CFR easy/hard. Эту панель уже использовали для оценки ранее замороженных методов. Для нового нейросетевого контроля переносим обученную модель без настройки. Основной срез — контекст в последние 3 строки по splitlines, как в strict_binary.py, дополнительный — 10; верхний результат по числу попаданий, MRR, Hit@3 и для hard Hit@5. Отдельно измеряем эквивалентность авторской обрезки split('\n') и вычисляем её результат при расхождениях.

Модель microsoft/unixcoder-base, редакция 5604afdc964f6c53782a6813140ade5216b99006. Авторская обёртка RepoBench редакции ccacd12a68783ca27e9997c3b754d3e9e0d958da. Входы запроса и кандидата — код с исходным форматированием. Авторская обрезка первых 508 BPE-токенов, четыре служебных токена, полная двусторонняя маска, среднее по незаполненным позициям, cosine; пустая строка получает нулевой вектор, ничьи решает исходный порядок. CPU FP32 на всех примерах. При ускорении батчированием сравниваем первые по хешу 12 уникальных входов с последовательным вызовом обёртки. Заранее заданный критерий: max abs разница координат < 1e-4. Проверяем порядок кандидатов при малых зазорах пересчётом небезразличных к рангу результатов.

Программа инференса получает только код, контексты и идентификаторы. До открытия эталона записывается SHA-256 всех решений. Время моделирования включает токенизацию и расчёт на CPU, расходы подготовки разделены. Сравниваем парные решения на одинаковых примерах с официальным бинарником Semlith, существующим графом и BM25, при наличии — с ассоциативным графом. Для разности Top-1 и MRR приводим 95% процентильный интервал 5000 повторных выборок целых репозиториев (seed 20261118), число выигрышей/проигрышей; отдельно публикуем страты. Ни один результат не служит критерием отбора строк. Доля исправленных задач здесь не измеряется.

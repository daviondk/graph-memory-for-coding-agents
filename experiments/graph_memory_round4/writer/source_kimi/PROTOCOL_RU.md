# Перенос с Claude на Kimi K2 Instruct без подбора

Пока результаты памяти на этом источнике не открыты. Используем публичные траектории официальной отправки SWE-bench experiments 20250804_codesweep_sweagent_kimi_k2_instruct. Берём до десяти задач по SHA256("r4-kimi|"+id) на каждый проект из объединения стратифицированных отборов A и B. В этих случаях прежний агент решал те же issues. Этим проверяем перенос на другие реально совершённые действия и другую модель в известных задачах. Включаем все подходящие выбранные попытки при том же лимите 48 МиБ. Долю resolved не используем.

У Kimi ID функции повторяются между ответами. Для открытого ранее исключённого примера sympy__sympy-11618 подтверждено, что обычный числовой ID может повториться девять раз. Разрешаем совпадение строго между одной assistant-репликой и следующим набором ответов инструментов до новой assistant-реплики. После канонизации пары внутри хода используем тот же консервативный фильтр двух полей траектории как в R3. Каждый номер и текст строки обязан совпасть в истории tool и в observation. Несогласованные или непригодные источники логируем. Никаких команд из траекторий не выполняем.

С теми же 4096 байтами отдельно оцениваем (1) замороженное вытеснение cal_neighbor против минимального LRU, прежнего mixed и сильного dict_mixed, с cal_pages как абляцией, по исходному прямому эталону и (2) перенос неповреждённых фактов по подтверждению редактора по его отдельному обращённому эталону с LRU/без лимита. Гипотеза подтверждается на этом источнике, если paired преимущество нового способа над сильным контролем имеет положительную нижнюю границу 95% ДИ по репозиториям при доступной точности. Описательные показатели и контрасты публикуем во всех случаях. Источники, код и выбор методов фиксируются до открытия результатов. Не получаем свежих ответов модели, исследуем запись опубликованного взаимодействия.

# Дозапись графа при последовательном открытии фрагментов
Системный опыт на всех тех же 320 заранее выбранных Java-задачах без меток ответа. Порядок предоставленных кандидатов имитирует поступление объявлений. Отдельно фиксированная хеш-перестановка показывает чувствительность к порядку. Это симуляция событий, реальные времена открытия файлов в наборе отсутствуют. Эталон после каждой вставки заново строит граф из всего уже известного списка. В качестве сильного простого сравнения для одного последнего чтения эталон строит граф однократно в конце.
Новый прототип хранит обратный словарь «терм → уже виденные фрагменты», пополняет степени и статистики слов. При появлении нового корневого имени нужно посетить только источники из его обратного списка и найти в них места употребления. Новые ссылки вперёд добавляются при первом появлении назначения. Для нового источника однократно разбираются ссылки на существующие корни. Веса неоднозначных имён нормируются по текущему числу объявлений при запросе. Ожидаем сокращения CPU при многократном чтении и рост вспомогательного индекса. Проверяем точное равенство всех объектов и первых/последних кандидатов на каждом шаге. Контроль и прототип работают на общей уже токенизированной памяти в одном процессе на CPU. Измеряем process_time_ns без I/O и без проверки правильности, два повтора со сбалансированным порядком. Для неопределённости ресемплируем проекты. Описаны отдельно одно чтение в конце и чтение после каждой вставки. Измерение не включает поиск файлов и работу модели.

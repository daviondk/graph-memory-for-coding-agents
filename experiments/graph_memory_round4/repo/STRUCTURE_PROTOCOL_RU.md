# За счёт чего работает связь между кандидатами

Дополнение сформулировано после открытия основных 2000 результатов, до оценки 1000 дополнительных Java-запросов. Главная альтернативная причина выигрыша — априорная популярность кандидата. Даже без просмотра вопроса более часто упоминаемый тип может чаще быть истинным ответом. Сравним на тех же обучающих проектах следующие модели с одинаковым GBDT. Контроль видит предыдущие обращения и совпадения текущего текста. Следующая модель получает ещё три величины — число упоминаний кандидата, число разных входящих и исходящих ссылок. Следующая модель также видит, насколько по именам, сигнатурам и локальным строкам заинтересовал запрос какой-либо её сосед. Полная модель получает ещё совпадения записанного текста непосредственно перед упоминанием цели. Опишем различия контролей по всем основным 2000 и по дополнительным 1000 задачам. Главный для этой диагностики новый результат — разность степени вершин и исходного контроля при трёх строках на 1000 дополнительных задачах. При недостатке преимущества предыдущего контекста не будем приписывать ему действие степени вершины. Это сравнительный механизм проверки модели, которая выбирает одно из уже предоставленных объявлений.

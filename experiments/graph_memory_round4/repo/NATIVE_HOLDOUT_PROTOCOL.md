# Независимая проверка Semlith на репозиториях вне основной серии

Фиксировано после основной публичной таблицы Java (но до получения каких-либо оценок дополнительных примеров). Из всех официальных Java test-шардов исключить каждый репозиторий, представленный в первом наборе 2000 Java-запросов. Старые train-проекты не пересекают даже полное множество test-проектов. Сначала использовать уже зафиксированные дополнительные примеры, принадлежащие новым репозиториям. Их 850 из 1000. Дополнить до 1000, поочерёдно беря по одному оставшемуся по SHA-256 внутри каждой непустой страты. Окончательные количества по стратам публикуются до генерации. Для фактического парного сопоставления с Semlith 0.36.0 отобрать 80 из этой тысячи в каждой страте по отдельному детерминированному хешу = 320 задач. Примеров из одного и того же проекта в пределах панели может быть несколько.

Без изменения алгоритмов и весов из основного опыта (5000 размеченных публичных Java train-эпизодов; Semlith — без настройки на train) ранжировать одни и те же кандидаты при 3 и 10 строках. Новый бинарный прогон использует первичную CPU архитектуру поставщика, его официальный MCP и тот же способ ограничения поискового запроса файлами кандидатов. Для каждого first/random строится отдельный индекс, содержащий по 160 задач обеих сложностей. Размер индекса отлично от исходного публичного расчёта по 1000 на config. Метрики — прежние Acc@1,3,5, MRR, входной пакет @512/3, стоимость. Заранее указанное основное сравнение — полная модель межкандидатных связей против реально исполненного Semlith на 320 задачах при 3 строках, кластерная парная оценка по репозиториям; @5 и 10 строк вторичны. Дополнительное исследование изменения с 3 до 10 строк использует поштучный сдвиг ранга истинного текста и число возвращённых до стабильного дополнения кандидатов. Объяснение механизма падения внешнего метода требует отдельного вмешательства и здесь не обещается. Результаты и пороги не используются для корректировки метода.

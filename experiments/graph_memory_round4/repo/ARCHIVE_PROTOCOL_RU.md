# Проверка первоначального опубликованного Java test
После оценок Hugging Face без изменения весов и гиперпараметров открываем первоначальный test.zip по ссылке в README авторов, commit ccacd12a68783ca27e9997c3b754d3e9e0d958da. Контроль — функции crop_code_lines и Jaccard по коду авторов, официальный CodeGen multi tokenizer, стабильный порядок кандидатов при равном результате. До оценки собственных предсказаний фиксируем на диске каждый список. Основная проверка сопоставимости — размеры и распределение задач из Table 1 и совпадение всех пяти метрик Jaccard Table 2 с округлением, независимая проверка известного набора случайным математическим ожиданием. Проверяем пересечение полной предобработанной задачи, репозитория и идентификаторов с отобранными примерами обучения и прежде оценёнными панелями. Идентичность результатов семантических методов проверяется лишь по таблице при подтверждённом положительном контроле. Если совпадение лексического контроля не подтверждается, внешние значения остаются исключительно ориентиром. Никогда не смешиваем два датасета. Даты и имена репозиториев не входят в модель. Gold-индексы хранятся исключительно для scoring.
Группировки и парный статистический анализ совпадают с FULL_PROTOCOL_RU. Первична разность с равно обученным owner-control по доле попаданий на первое место. Абсолютные Acc@1/3/5 на easy/hard сравниваем с Таблицей 2 по её исходным долям задач. Отдельно при непустом пересечении тестовых репозиториев с обучением публикуем результат после их исключения. Не выдаём дополнительные агрегаты за зарегистрированный holdout ранней серии.

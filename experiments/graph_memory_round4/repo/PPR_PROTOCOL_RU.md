# Контроль без обучения на Java: персонализированный PageRank
Дополнительный опыт зарегистрирован после основного сравнения на 24 000, до вскрытия результатов и меток для ранжирования 36 000 в первоначальном архиве. Этот контроль отвечает на вопрос, насколько далеко можно продвинуться обычным безучительным распространением активации по направленным рёбрам упоминаний. Запрос — те же три строки. Исходный вектор — пропорционален Jaccard авторского CodeGen-токенизатора. Рёбра соответствуют упоминаниям имени другого кандидата. Веса пропорциональны числу упоминаний, с делением на неоднозначные объявления. Используем обычное затухание PageRank 0,85, висячие вершины передают массу обратно в исходное распределение. Ранжируем по стационарной вероятности, при равенстве — как в оригинале. Никакой настройки параметра по тесту. Сравнение с исходной лексикой оценивает добавочный эффект структуры, с нейтрально переназначенными владельцами рёбер — специфичность структуры. Метрики Acc@1, Acc@3, Acc@5 и MRR, paired 95%-interval по репозиториям, первичная Acc@1. Сохранить знаки и размеры отличий на всех трёх панелях. Первоначальные 2 000 Java и новые 1 000 задач имеют общие только с предшествующей оценкой данного исследования, а архивная подвыборка использует по 300/страта, фиксированных через SHA-256 от строки 'r4-ppr-archive|{panel}|{id}'. В ней официальный crop на split('\n'), в двух остальных — splitlines как в scorecard. На архиве нет совпадений репозиториев или стимулов с обоими предыдущими наборами. Даты и имена репозитория не входят в метод. Допускается отрицательный результат, он сохраняется целиком.

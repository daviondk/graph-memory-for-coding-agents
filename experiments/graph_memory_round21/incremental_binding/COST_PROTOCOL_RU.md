# Стоимость повторных запросов к меняющемуся графу

После измерения семантики и чтения проверяем время обслуживания только отношения data.feeds. Берём первые 48 из заранее зафиксированных 96 траекторий по тому же рангу SHA-256. Рабочие нагрузки: один запрос на последней замкнутой границе, четыре ранее проверенных контрольных точки и запрос после каждого завершения всей группы ожидавшихся вызовов. Результат запроса — полностью материализованное множество текущих пар. Исходные тексты уже находятся в памяти.

Обе реализации используют одни и те же выделители типизированных значений и подстрок аргументов, один проход событий в исходном порядке и одинаковый вывод. Контроль один раз выделяет токены каждого вывода и хранит аргументы вызовов. При чтении он строит точное отношение из однозначных производителей и доступных более поздних вызовов. Альтернатива поддерживает значения, текущие обоснования и пары в момент добавления событий. Холодный разбор JSON и разметка не входят в измерение, выделение значений из текстов входит. Порядок двух вариантов чередуется по траектории, режиму и повтору, три технических повтора. Медиана CPU process time на траекторию основной показатель; стеновое время вторично. Для отношения затрат строим парный cluster bootstrap по 48 траекториям. Обе реализации работают в памяти одного процесса Python. Стоимость SQLite/диска и отдельных инструментов агента этим опытом не оценивается. При редких чтениях оптимизация может себя не окупить.

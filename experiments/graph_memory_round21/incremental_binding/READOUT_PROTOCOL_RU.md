# Меняют ли недействующие связи чтение графовой памяти?

Потоковый индекс ISETrace и необратимое добавление рёбер дали разные состояния на 96 пилотных траекториях. До расчёта качества определяем основное сравнение на всех прочих 1 111 траекториях официального test. Число вопросов получается соединением с замороженной таблицей R19. Отдельно отчитаемся по пилотным и полным данным. Тест использовался ранее для других гипотез.

В каждой истории берём неизменённые Dense-FT ранги, исходные направленные связи остальных трёх типов, один и тот же R20 typed reader с замороженными 27 весами и свободным членом, авторское prefix до 2 048 токенов. Изменяется только множество связей «вывод → вывод» по значениям между вызовами. Сравниваем точное финальное состояние с политикой удержания всех когда-либо однозначно наблюдённых пар. Частный интерес представляет Full Support точной политики минус append-only. Даже если теория предсказывает несовпадение графа, знак изменения качества заранее неизвестен.

Два дополнительных варианта используют (а) вес 1/2 для вклада различия между полными векторами признаков обеих политик, (б) перестановку ложных связей с сохранением входных/выходных степеней на уровне событий, вне истинных рёбер и без петель, с сохранением допустимого порядка событий. Доля действительно переставленных связей указывается отдельно. Для всех вариантов измеряем Coverage, долю вопросов с другим контекстом, парные исходы и 95% кластерные ДИ по траекториям. Сохраняем решения до чтения эталонов. На этапе подготовки трассы держим в памяти только прошлые события для автообновляемой части. Кэш базового графа используется для проверки семантики в финале и трёх неизменных типов рёбер. Списки индексов кандидатов и идентификаторы истории являются достаточным публичным следом для пересчёта.

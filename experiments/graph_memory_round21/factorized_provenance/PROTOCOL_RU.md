# Можно ли обслуживать граф чтения без хранения всех пар фрагментов?

ISETrace связывает все фрагменты двух связанных событий полным двудольным графом. Предсказываем, что представление связи на уровне событий позволяет точно воспроизвести сумму, максимум и количество соседей каждого типа у каждого фрагмента. Группа — непересекающееся множество фрагментов одного события. При связи A → B каждый член A получает |B|, сумму и максимум значений из B. Отдельные прямые рёбра между соседними фрагментами сохраняются явно. В исследовании используются четыре авторские категории направленных связей. Веса читателя и порядок одинаковых баллов заморожены из R20; новые параметры не обучаются.

**Проверка эквивалентности.** Все 2 000 вопросов и 1 207 траекторий test ISETrace. Требуем совпадения множеств направленных типизированных пар с прямой проекцией R20 и поэлементного совпадения признаков в double с допуском 1e−10. Независимая проверка по ранее сохранённым решениям R20 включает упорядоченные списки выбранных позиций при prefix и skip с лимитом 2 048. Расхождения выводятся поштучно. Успешная эквивалентность позволяет унаследовать качество замороженной модели. Сам метод вычисления не должен повышать Full Support.

**Стоимость БД.** Две SQLite-базы на том же диске со всеми траекториями. Обе хранят те же локальные номера фрагментов. В первой — плоские пары, во второй — членство в группе, прямое соседство и связи групп. Сравнить размер после VACUUM, число физических строк, абсолютные байты. Текст, отдельный каталог идентификаторов и веса общие вне обеих БД. На первых 128 траекториях по SHA-256 от фиксированного префикса factor-store-v1 и идентификатора измерить, сколько времени занимает прочитать представление одной истории из БД в Python и вычислить все статистики соседей (один заранее выбранный вопрос на историю, чередование порядка, семь раз на прогретых БД). Сравнивать по медианам на уровне траектории и дать 95% парный бутстрэп. В обеих реализациях допускаются векторизованные численные операции. Таймер исключает построение исходного физического графа, кодирование текста и обучение. Качество проверяется отдельно на всей выборке.

Вторая операция для будущего демо — добавление заранее известной группы фрагментов и видимых к этому моменту связей. Нужно различать хронологический повтор готовых рёбер и онлайн-извлечение отношений из реальных действий. Данный опыт проверяет физическое представление и вычисление признаков уже известной проекции. Сопоставление с плоской SQLite локальное. Конструкции факторизованных представлений ранее опубликованы.

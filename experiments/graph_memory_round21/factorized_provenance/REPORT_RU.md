# Одинаковое чтение памяти при меньшем объёме графа

На официальном тесте ISETrace две базы SQLite дали одинаковые упорядоченные списки источников во всех **2 000 вопросах из 1 207 траекторий**, при выборе по префиксу и при доборе с пропусками. Размер графовой части после VACUUM снизился с **5 025 792 до 3 190 784 байт (−36,51%)**. Обе базы содержат идентификаторы фрагментов. В упакованном варианте хранение принадлежности к группе включено в эту стоимость. Исходные тексты, ранги Dense-FT и веса модели общие для обеих реализаций и находятся вне этих файлов.

У исходного читателя (R20, обучение на 500 dev-вопросах) результат зависит от числа, суммы и максимума рангов соседей каждого из четырёх типов в обоих направлениях. Если A и B связаны целиком, каждый фрагмент A получает одну и ту же тройку величин, вычисленную по B. Для непересекающихся групп сумма и количество складываются по группам, максимум берётся по их максимумам. Прямое соседство внутри события остаётся явным. Отсюда следует равенство вещественных признаков при точной арифметике. Максимальная фактически наблюдавшаяся абсолютная погрешность до логарифмирования составила 1,07×10⁻¹⁴. У каждого из 1 207 графов множество развёрнутых направленных типизированных рёбер совпало с независимой проекцией из R20.

**Задержка.** По 128 заранее выбранным траекториям выполнено семь чередующихся повторов на прогретой SQLite. Медианы полного чтения геометрии из БД и вычисления статистик составили 0,222 мс и 0,215 мс. Геометрическое среднее отношений времени «группы / пары» составило 0,968 (95% парный ДИ 0,916–1,018). Загрузка из БД стала быстрее, дополнительная агрегация в NumPy — медленнее. Уверенного выигрыша по общей задержке здесь нет. Параллельно выполнялись другие исследовательские процессы. Измерение не включает извлечение физических отношений, Dense-энкодер или генерацию ответа.

**Граница вывода.** Сокращение измерено у двух указанных физических схем SQLite для конкретного графа. Процент экономии для всего приложения с текстовыми наблюдениями будет другим. Факторизация отношений известна в базах данных. Исследовательский результат — возможность точно применить её к типам связей памяти ISETrace, сохранить решения обученного читателя и измерить экономию на полном тесте. Это преимущество по объёму реализации, без изменения качества относительно её исходного читателя.

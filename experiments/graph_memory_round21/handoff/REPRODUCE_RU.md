# Воспроизведение

Открытый каталог содержит протоколы, код, поэлементные прогнозы в виде адресов и хешей, решения модели и таблицы результатов. Все исходные документы восстанавливаются из обозначенных ревизий. Каталог D:/CodexResearch/x20-wikicontradict используется только для реконструируемых векторов, закрытых от предсказателя эталонов, текстов, БД, серверных логов и кеша вызовов модели. Повторяющиеся строки upstream-корпуса учитываются как зависимые наблюдения.

1. Использовать Python из окружения D:/CodexResearch/x20-isetrace-e5-gpu/venv, либо версии пакетов из input-lock.json. В D:/CodexResearch/x20-isetrace-runtime/e5-base-v2 разместить файлы E5 из ревизии f52bf8ec8c7124536f0efb74aca902b2995e5bcd. Если путь другой, задать его в prepare.py и pointer_prepare.py. Автозагрузка выполняется только для небольших CSV/TSV по зафиксированным URL. При авторском сравнении используется один из двух одноимённых CSV WikiContradict, путь внутри каталога WikiContradict указан в protocol.json. [E5](https://huggingface.co/intfloat/e5-base-v2/tree/f52bf8ec8c7124536f0efb74aca902b2995e5bcd)
2. Из данного каталога последовательно запустить `python -B paper_table.py`, `python -B prepare.py`, `python -B predict.py`, `python -B score.py`. Первый расчёт использует опубликованные округлённые данные и число случаев из §4.3. Остальные восстанавливают данные, фиксируют 7590 поэлементных прогнозов и открывают эталоны. Исходные последовательности UTF-8 и проверенные прогнозы снабжены SHA-256.
3. Затем выполнить `python -B pointer_prepare.py`, `python -B pointer_predict.py`, `python -B pointer_score.py` и `python -B audit.py`. База строится по двум закреплённым источникам. Скрипт создаёт 7768 прогнозов с реальными подсчётами переданных байт. Результаты включая промежуточные дополнительные бюджеты и абляции лежат в results.json и pointer-results.json. В каждой строке указаны числители, знаменатели и количество кластеров в данном поданализе. Версии BLAS и архитектура CPU могут влиять на совпадение низших знаков E5 и хеша вычисленных векторов. На машине опыта OPENBLAS_NUM_THREADS=1, OMP_NUM_THREADS=2, CPU float32.
4. Для чтения моделью установить бинарный файл llama-server.exe выпуска llama.cpp b12441 и Qwen3-4B-Instruct-2507-Q4_K_M.gguf по адресам в reader.py. Проверяются SHA модели и бинарника. Из тех же исходных пакетов последовательно выполнить `python -B reader.py predict`, `python -B reader.py score`, `python -B schema_control.py`. Каждый запуск сам создаёт и завершает свой локальный CPU-сервер на свободном порту. [Веса](https://huggingface.co/unsloth/Qwen3-4B-Instruct-2507-GGUF/tree/a06e946bb6b655725eafa393f4a9745d460374c9) · [llama.cpp](https://github.com/ggml-org/llama.cpp/releases/tag/b12441)
5. Для независимой проверки опубликованных файлов достаточно `python -B verify.py`. JSON манифеста содержит SHA-256 всех файлов исследования кроме себя. Проверка сравнивает все первичные прогнозы и сводку решений с запечатанными хешами.

Публичные логи не включают тексты источников, свободное модельное рассуждение или произвольные команды исторических трасс. Результаты приводятся на уровне приложения. Для фонда общей памяти модель затрат на загрузку отдельно отмечена как гипотетическая. Опыт повторно использует размеченные темы Ragability и WikiContradict и не представляет проверку на независимом внешнем источнике.

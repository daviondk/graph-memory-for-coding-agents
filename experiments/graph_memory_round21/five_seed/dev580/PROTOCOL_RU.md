# Выбор контрольной точки Dense-FT на 580 вопросах

В выпущенной конфигурации ISETrace полный dev содержит 580 вопросов из 352 траекторий. Изначальный R21 зафиксировал 500 вопросов из 331 траектории. Этот дополнительный контроль зарегистрирован после получения исторических результатов seed 13 и до обучения seed 17, 29, 37 и 41. Используем неизменные 3 894 train и 2 000 test. Порядок вопросов берём из независимо восстановленного полного split. В этот контроль входят только вопросы dev.

Для каждой из двух эпох (исходный E5 и E5 после одной эпохи) запускаем авторскую процедуру task-local выбора по среднему Recall@5 для идентификаторов PU, пересекающихся с размеченными интервалами. Фиксируем также Recall@2, Recall@10 и MRR по идентификаторам, число вопросов, SHA256 весов, порядок вопросов и значения для каждого вопроса. При равенстве выбираем более раннюю эпоху, как в исходном коде. Это критерий выбора контрольной точки. Таблица 2 использует нативные метрики по символьным интервалам.

Модель внутри первоначального цикла обучается и оценивается на 500 по неизменному нативному коду. Наблюдатель считывает уже рассчитанные значения и сохраняет необратимо теряемую эпоху 1 отдельно, если победила эпоха 0. Для полных 580 запускается тот же авторский evaluator и тот же model checkpoint, с исходной последовательностью запросов и batch size. У исходного E5 одна контрольная точка для всех пяти запусков. При повторном использовании исходных прогнозов сверяются значения на 500 с нативным журналом каждого запуска. У seed 13 обе стадии уже доступны. Нативный evaluator на исходном и обученном checkpoint отдельно восстанавливает его 500 и 580. Эталонные ответы test для выбора весов не открываются.

Если выбор совпадёт, существующие тестовые перестановки и калибровка hash64 переносим по SHA выбранных весов. Если разойдётся, сохраняем обе серии и передаём альтернативные веса в отдельную очередь для калибровки и предсказания Dense и factor, после чего требуется сравнение с графовым методом на тех же весах. Совпадение dev-метрики само по себе не доказывает равенства прогнозов разных весов.

Для замороженных прогнозов на общем подмножестве достаточная проверка выбора имеет вид 500·(R1−R0)>80. Вклад каждого дополнительного запроса в разность ограничен интервалом от −1 до 1. Для исторического seed известно превышение этой границы. Прямой полный расчёт дополнительно проверит численные различия при изменении состава минибатчей.

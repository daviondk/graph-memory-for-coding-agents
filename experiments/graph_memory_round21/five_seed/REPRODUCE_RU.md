# Повторное выполнение и проверка

Из каталога five_seed запускается один процесс PowerShell. Требуется окружение с upstream GraphMemory и Torch/CUDA, предыдущие проекты R18, R19 и R20, а также приватные проекции на D. Все новые файлы располагаются на D. Одновременно работающие копии скрипта исключает именованный mutex.

```powershell
pwsh -NoProfile -File .\run.ps1
```

**Порядок.** Сначала создаются хеши источников, единый корпус уникальных текстов, полный контрольный пересчёт seed 13 и оригинальные отрицательные обучающие пары для четырёх новых seed. Исторические веса сохраняются в R19. Программа сравнивает все новые порядки и восемь метрик каждого из 2 000 вопросов с контрольными значениями из R19/R20.

В очереди GPU обучению предшествует завершение полного нативного R-GCN в R20 и его переобученной сильной абляции без chunk adjacency. После публикации обоих forecast-seal run.ps1 ждёт выхода соответствующих процессов исполнения. Дальше идут последовательно fit, encode, calibrate, predict, score и aggregate для каждого seed. Процесс и код выхода видны в D:/CodexResearch/x20-isetrace-multiseed/queue.log. Этот журнал, PID и текущие счётчики SQLite позволяют подтвердить реальный статус независимым запросом операционной системы. Свободное место проверяется по остаточным потребностям записи, исходный и ранее созданные кеши сохраняются.

Каждая завершённая стадия публикует квитанцию в seed-N. Четыре строки обучения используют одинаковую неизменную разметку, собственные конфигурации выбора отрицательных примеров и собственную директорию модели. Вектора имеют ключ SHA-256 точного текста с официальным префиксом и хранятся в отдельной базе конкретного набора весов. При повторном запуске уже завершённые стадии пропускаются. Незаконченный проход кодирования догружает отсутствующие строки. Если обучение было прервано внутри исходной эпохи, следующая попытка начинает эпоху в отдельной директории и сохраняет предшествующую. По первой исторической модели зарегистрировано полное совпадение прогнозов и метрик.

**Портативные результаты.** picks-*.json.gz хранят порядки индексов, адресующих исходные R19/forecasts-main-I.json.gz в соответствующем шарде, без текстов корпуса. Каждая строка содержит q, t и обе полные перестановки. forecast-seal связывает эти массивы с хешами канонических кандидатов, исходными весами, ранг-калибровкой и кодом. В metrics.json.gz хранятся реальные метрики для каждого вопроса обеих политик. Обновить агрегированные таблицы по уже готовым seed возможно без GPU командой:

```powershell
python -B score.py aggregate
```

Отчёт помечает фактическое число доступных seed и сохраняет промежуточные числовые снимки. Публикуемый основной парный интервал по всем пяти seed вычисляется после появления всех пяти полных результатов.

# Полный пятиseed-протокол для оперативной графовой памяти

**Гипотеза.** При неизменном множестве PU и бюджете 2 048 добавление типизированной априорной оценки узла к калиброванному рангу Dense-FT увеличивает вероятность извлечь все размеченные источники вопроса ISETrace. Единственный основной кандидат — полная факторизованная модель R20 (роль, геометрия и восемь направленных степеней). Первичная метрика — нативный Full Support на строгом префиксе целых узлов. Используем исходные 2 000 вопросов test в 1 207 траекториях. Более ранние результаты для seed 13 и других моделей этих вопросов известны. Эта серия проверяет устойчивость уже выбранного правила к обучающему seed. Дополнительные 80 вопросов R20 составляют отдельную панель.

**Обучение и контроль.** Фиксируем исходное разбиение split_seed=13, все 3 894 train-вопроса на 2 410 траекториях и 500 dev-вопросов авторского full profile. Для каждого из model seeds 13, 17, 29, 37, 41 применяется исходное provenance-unit Dense-FT с intfloat/e5-base-v2, эпохой 1, batch 16, FP32, LR 2×10⁻⁵, выбором checkpoint по task-local dev Recall@5. В официальный configs/stage/dense_ft.yaml подставляется seed в генератор случайных отрицательных пар и в тренер. Каждый новый seed использует собственные отрицательные пары из нативного build_train_pairs (2 easy, 2 BM25, пул 30). На один положительный пример выбирается один hard negative исходной функцией. Корпус, положительные PU, графы и параметры модели зафиксированы. Контрольный плотный ранжировщик и фактор для каждого seed используют один обученный checkpoint.

Априорный компонент неизменён по отношению к R20. Из его обучения исключены обе ранее зафиксированные калибровочные группы. Логит семантического ранга переоцениваем для каждого seed на тех же 101 вопросе тех же 64 hash64-траекторий train с тем же классовым взвешиванием и реализацией R20. Нормализацию, C=1 и формулу суммы логитов сохраняем. Ни промежуточные тестовые результаты, ни порядок поступления seed не меняют правил.

**Вывод по пяти seed.** Для каждого seed сохраняем метрики по каждому вопросу, абсолютные средние, отдельно FS и Coverage, а также все шесть столбцов таблицы 2 (Coverage@512, @1024, @2048, FS@2048, Recall@5 и MRR). При наличии пяти завершённых seed публикуем среднее и выборочное SD по seed для каждого метода. Для сравнения берём разность factor−Dense внутри одних и тех же вопроса и seed, затем сначала усредняем разности по пяти seed каждого вопроса. Ресэмплируем целые исходные траектории 10 000 раз с seed 13, знаменатель в каждой выборке — число включённых вопросов. Промежуточные числа снабжаем фактическим числом готовых seed. С опубликованными абсолютными оценками возможны описательные сравнения. Парный вывод о превосходстве над R-GCN требует его поштучных выходов со всеми пятью соответствующими checkpoint; сильная опубликованная абляция без chunk adjacency рассматривается отдельно.

**Восстановление исполнения.** Seed 13 загружается из неизменяемых замороженных материалов R19/R20 и сохраняется ссылкой, хешами и переносимой таблицей метрик. Для новых seed на D создаются отдельные директории модели, попыток обучения и SQLite с проверкой идентичности checkpoint. Кодирование дописывает только отсутствующие строки и коммитит блоками. Прерванная эпоха начинается с новой рабочей директории попытки. Проверяем свободное место перед новым этапом, не удаляя предыдущие результаты. Загрузка обучающих и точных источников остаётся внутри локального хранилища. В репозиторий предназначены протокол, версии, сжатые списки предсказаний, метрики и отчёт. Никакие данные из траекторий не исполняются.

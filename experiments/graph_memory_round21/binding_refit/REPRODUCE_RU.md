# Воспроизведение

Выполнять из каталога binding_refit с тем же Python-окружением, что и R20 typed_reader. Использованы D:/CodexResearch/x20-isetrace-e5-gpu/venv/Scripts/python.exe, один поток BLAS и сохранённые ранги DenseFT. Настройки encoder и разбиения находятся в R19/trained_rank и R20/residual_graph. Видеокарта этому расчёту не требуется. Упаковка выбирает непрерывный префикс ранга до 2048 токенов. Стенд читает только сохранённые публичные траектории как данные.

1. Получить исходные ISETrace-данные и графы согласно R18/isetrace_official и R20/residual_graph. Проверить пути к данным, зафиксированные в setup_graph.py и study.py, и архитектуру каталогов. Путь к кешу геометрий в refit.py можно заменить для другого компьютера. Этап воспроизведения требует исходные файлы с совпадающими SHA-256.
2. Выполнить `python -B refit.py geo 0 1 2 3 4 5 6 7`. В отдельном кеше появятся канонические группы, группы с отозванными связями и их размеры. Для каждой траектории канонический набор data.feeds сравнивается с активными связями инкрементального счётчика. Все рёбра, добавленные для append, принадлежат типу data.feeds. Пустые дополнительные рёбра сохраняются явно.
3. Выполнить `python -B refit.py fit`. Для проверки исходным контролем служат ранее замороженные R20-коэффициенты. Новые коэффициенты получаются отдельным вызовом LogisticRegression в каждом режиме. Веса берутся только из тех 500 вопросов dev, на которых обучали сопоставимый линейный R20 читатель. Для всех 27 базовых признаков совпадают политика построения, веса классов и масштабирование.
4. Выполнить `python -B refit.py predict 0 1 2 3 4 5 6 7`, затем `python -B refit.py seal`, затем `python -B score_refit.py test`. Проверяется точное совпадение выбираемых позиций старого R20 при обеих топологиях с ранее опубликованным контролем. Вычислитель метрик читает эталоны после проверки итогового хеша прогнозов. Независимая реализация пересечения интервалов сверяет каждый уникальный набор выбранных записей с опубликованным span_metrics_under_token_budget.
5. Когда отдельный ранжировщик R20/untuned_holdout закончил все 80 дополнительных запросов и создал forecast-seal.json, выполнить `python -B refit.py predict extra`, затем `python -B score_refit.py extra`. Изолированная панель включает только 27 запросов на 21 траектории вне обучающих архивов. В ней высокая неопределённость. Наборам из проверявшихся ранее вопросов, перекрывающихся траекторий и пилота присвоены отдельные статусы.
6. Для сверки файлов и расчётных ограничений выполнить `python -B verify.py`. Для читаемой сводки использовать REPORT_RU.md. Маркеры exact, append, dual в JSON обозначают тип тренировочной матрицы. После косой черты указан режим чтения. Дополнительно приводятся значения при обращении к самой оценке DenseFT и при применении R20-коэффициентов.

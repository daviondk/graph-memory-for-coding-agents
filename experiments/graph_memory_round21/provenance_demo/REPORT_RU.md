# Интерактивная история связей памяти

[Открыть автономное демо](explorer.html) · [Предпросмотр](explorer.png) · [Проверка содержимого БД](verification.json) · [Проверка браузера](offline-receipt.json)

Выберите историю, перейдите к любому событию и сравните три реконструкции связей. Для выбранной пары «исходный вывод → следующий вызов» правая панель показывает интервалы действия и число уникальных значений, обосновывавших связь. Стрелки позволяют увидеть смену состояния по одному событию. Фильтр выделяет устаревшие связи, которые сохранила бы запись только с добавлением, либо исторически оправданные связи, исчезнувшие из финального графа.

**Пример демонстрации.** Нажмите **Inspect a revoked link**. Кнопка откроет контрольную точку 60 первой по идентификатору истории и выберет нужную связь. В этот момент существуют 5 обоснованных связей. Хранилище, в которое только добавляют рёбра, показывает 9. При фильтрации остаются четыре отозванные связи. Для пары «вывод 14 → вызов 19» видно, что в событии 53 вызов 19 использовал значение V6 из вывода 14. В событии 55 сам вывод 19 также содержал V6. С этого момента формальное правило единственного производителя отзывает связь. Нумерация событий в интерфейсе начинается с единицы. Затем посетитель может выбрать другой момент и проверить, какие наблюдения были доступны агенту тогда.

**Архитектура.** При чтении события потоковый индекс обновляет число обоснований для затронутых пар. Для каждой смены количества SQLite закрывает предыдущий полуоткрытый интервал действия и при положительном количестве открывает новый. Запрос на момент t выбирает строки со start ≤ t < end, текущие интервалы имеют открытый конец. Авторская повторная сборка отдельных префиксов — внешний эталон. Транзакции загрузчика прототипа сгруппированы по траекториям. Сохранены 96 траекторий, 8 342 события, 2 339 вызовов и 1 095 интервалов. Дополнительная таблица содержит 1 777 изменений обоснований с локальными псевдонимами значений и номерами производителей. Файл базы занимает 565 248 байт. Имена вызовов заменены локальными номерами. Исходные тексты и значения инструментов отсутствуют в поставляемой БД.

**Проверка.** На 383 срезах проверены точные множества пар для трёх запросов к SQLite (1 149 сравнений). При проверке браузера автономная HTML-версия дала те же связи, состояния и числа обоснований, что и локальный SQLite-сервер на всех 383 срезах. Проверены перемещение по времени, смена истории, фильтр, детализация пары и мобильная ширина. Исследовательские показатели качества извлечения рассчитаны на отдельном этапе. [Проверка влияния на чтение](../incremental_binding/REPORT_RU.md)

**Запуск.** Файл explorer.html открывается прямо в браузере. В автономной версии браузер читает проверенную копию интервалов. Чтобы выполнять запросы непосредственно в SQLite, из этой папки запустите `python serve.py` и откройте адрес, показанный в терминале. Сервер использует стандартную библиотеку Python и принимает соединения только на локальном компьютере. Исходная БД уже входит в эту папку. Для повторной сборки при наличии корпуса и исследовательских зависимостей используйте build.py и export_offline.py. Для повторной проверки интерфейса доступны `node browser_check.mjs` и `node browser_check.mjs --offline`.

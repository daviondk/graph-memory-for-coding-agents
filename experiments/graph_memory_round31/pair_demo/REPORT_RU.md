# Демонстрация отзыва источников в графовой памяти

Посетитель выбирает вопрос HotpotQA и снимает доступность отдельных документов. Система возвращает лучшую допустимую пару согласно зафиксированному до отзыва ранжированию. На экране можно сравнить два списка сохранённых пар, увидеть, какой метод обращается к полной таблице, и раскрыть разметку HotpotQA. В интерактивную панель вошли 24 вопроса, выбранные по хешу идентификатора. Каждый содержит десять документов и 45 различных пар. [Автономная демонстрация](evidence.html) · [Снимок](demo.png) · [Полный эксперимент на 7 405 вопросах](../support_pairs/REPORT_RU.md)

Обычный кэш хранит шесть первых пар. Второй сохраняет пары, которые могут стать первыми после отзыва до двух источников включительно. При более крупных изменениях система проверяет подмножества отозванных источников мощности до двух. Если победитель для одного из таких подмножеств остаётся доступным при полном наборе отзывов, он сохраняет первенство. При отсутствии подтверждения сервис извлекает полный порядок. На живом маршруте решение приходит из SQLite. Клиент получает идентификаторы сохранённых пар только при раскрытии списка. Автономная версия проигрывает те же решения по адресам в HTML.

| Проверка на 24 вопросах | Результат |
|---|---:|
| Все конфигурации отзыва, включая пустой ответ | 24 576 |
| Совпадение с полным перебором после учёта резервного чтения | 24 576 / 24 576 |
| Конфигурации с 0–2 отзывами | 1 344 |
| Обращения к полной таблице при 0–2 отзывах, обычный кэш / достижимые победители | 127 / 0 |
| Непустые конфигурации с более чем двумя отзывами | 22 968 |
| Для них ответ подтверждён по меньшему множеству отзывов | 15 360 |
| Для них понадобилась полная таблица у метода достижимых победителей | 7 608 |
| Конфигурации, в которых осталось меньше двух документов | 264 |

Каждая конфигурация прошла через рабочую функцию запроса к SQLite и независимый перебор опубликованного порядка. Для каждого вопроса множество сохранённых победителей совпало с множеством всех достижимых победителей при 0–2 отзывах. В Chromium автономный алгоритм воспроизвёл все 24 576 состояний с той же контрольной суммой, включая сертификат, пустой ответ и оба решения об обращении к резерву. Дополнительно проверены 44 интерактивных состояния в каждом из двух режимов, ширина 390 px, раскрытие списков, реакция на четыре ошибочных запроса и отсутствие внешних HTTP-запросов при работе с локальным HTML. [Результаты перебора](verification.json) · [Протокол браузера](browser-receipt.json)

На снимке отозваны German Spitz и English Springer Spaniel. Для выбранного вопроса пять достижимых победителей позволяют вернуть наиболее высоко расположенную доступную пару. Обычный список из шести пар требует просмотра полной таблицы. Одно из размеченных названий было отозвано. Поэтому восстановленная пара отличается от эталонной. Снимок выбран для иллюстрации этого различия. Частоту резервного чтения в рабочих нагрузках следует измерять по эмпирическому распределению изменений. Таблица выше даёт полный перебор демонстрационной панели при одинаковом весе всех конфигураций. Числа описывают поведение поиска и сервиса. Качество сгенерированного ответа в демонстрации не измерялось.

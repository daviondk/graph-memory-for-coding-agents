# Компрессия исходного двухступенчатого поиска

Дополнение зафиксировано до получения первого результата нейросети. Для каждого допустимого множества удалений сравним исходное полное расширение beam=2 с четырьмя способами отвечать по сохранённой памяти. Ранжирование документов первой головы и ранжирование ориентированных пар второй головы фиксированы. Модель на входе получает только текст запроса и соответствующую пару. Удаление несвязанных документов сохраняет её индивидуальные баллы.

* Исходные 17 открытых пар фильтруются по удалению. Отдельно фильтруем их с пересчётом первых двух живых документов.
* Все пары, инцидентные как минимум одному из первых четырёх документов, покрывают пул повторного beam=2 при ≤2 удалениях (из 10 это 30 пар). Храним первые четыре одиночных id для восстановления двух первых допустимых.
* Для каждого уже посещённого множества R вычисляем два первых живых документа H(R) и побеждающую пару P(R). Дочерние состояния запрета строим только по элементам H(R) ∪ P(R). Пока не задето ни одного из этих документов, пул допустимых расширений может только терять пары и сохраняет текущего победителя. Для любой надстройки запрета, меняющей решение, существует первый удаляемый элемент сертификата. Индукция по числу удалений доказывает, что при глубине 2 перебор охватит всех возможных победителей. Нормальный beam=2 всегда возвращает пару, инцидентную одному из двух первых документов, поэтому размер сертификата ≤3. До удаления повторных состояний при двух отказах достаточно 1+3+9=13 посещений. Это верхняя граница на число посещений, а не обязательное число хранимых пар. При запросе восстанавливаем два первых живых из первых четырёх, оставляем доступные сохранённые пары, инцидентные хотя бы одному из них, выбираем лучший балл. Сравниваем с исчерпывающим перечислением всех 56 состояний, проверяем тождественность множества победителей.
* Отрицательные контроли — дерево, ветвящееся только по двум документам текущей выигравшей пары, и усечение полного двухступенчатого пула по совместному баллу до стольких же пар, сколько сохранило дерево сертификатов. Те же первые четыре документа и тот же алгоритм извлечения для всех адаптивных контролей.

По состояниям отдельно покажем долю смены лучшей пары между фиксированным пулом, полной совместной выдачей и адаптивным исходным поиском. По вопросам — число пар/одиночных id, число просмотренных состояний, число потенциальных пропусков (с пустым и ошибочным ответом), случаи смены при сохранении исходной выигравшей пары. Проверяем корректность на всех состояниях, не оцениваем ускорение полной нейросети по времени малых операций кэша.

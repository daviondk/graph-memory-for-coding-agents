# Нейронный поиск пары документов после отзыва источников

Исполнены обученные классификационные головы и DeBERTa-v3-large метода Beam Retrieval. Вопросы предварительно выбраны по хешу из HotpotQA distractor dev. Для каждого из восьми вопросов получили индивидуальные баллы 10 документов и 45 пар. Модель независимо вычисляет балл текста документа и вопроса, а затем условную оценку пары. При отзыве кандидатов меняется список двух первых живых документов. Пара участвует в повторном поиске, если содержит хотя бы один из них. [Beam Retrieval, NAACL](https://aclanthology.org/2024.naacl-long.96/) · [Авторские веса](https://github.com/canghongjian/beam_retriever/issues/1)

## До двух отзывов

| Метод | Фиксированные 45 пар, ровно два отзыва | Адаптивный beam=2, ровно два отзыва |
|---|---:|---:|
| Полный пересчёт допустимых пар | 360/360 | 360/360 |
| Обычный префикс при бюджете метода | 357/360 | 342/360 |
| Известное взвешенное представительное семейство | 360/360 | — |
| Префикс пар, инцидентных четырём первым адресам, при равном числе строк | — | 354/360 |
| Все 30 пар, инцидентных этим четырём адресам | — | 360/360 |
| Фильтрация первоначально раскрытых 17 пар | — | 237/360 |
| Статическое дерево плюс проверка двух живых корней | 360/360 | 333/360 |
| Дерево адаптивного поиска по документам победившей пары | — | 360/360 |

При адаптивном поиске хранили 4–5 пар, в среднем 4.12, плюс исходные четыре адреса первого шага. Ближайший контроль с тем же числом строк среди пар четырёх возможных корней дал 180/180 в первых четырёх вопросах и 174/180 в следующих четырёх. Дерево дало по 180/180. Шесть отличий сосредоточены в трёх вопросах. Поскольку все 45 пар уже были рассчитаны, далее указана только логическая стоимость построения. Построение посетило 6–7 состояний из 56. При двух отзывах фиксированный полный порядок и адаптивный поиск разошлись в 55/360 случаях. Удаление не задело начальную пару, но динамический ответ сменился в 0/360 случаях. Упорядоченный состав всех достижимых ответов проверен полным перебором. Для статического порядка известна конструкция представительных семейств. [Fomin et al.](https://arxiv.org/abs/1304.4626)

Изначально ветвление только по победителю было контрольной абляцией. После синтетических наблюдений получена лемма обмена. Она требует фиксированных порядков первой и второй ступеней и наличия победителя в промежуточных состояниях. При размере пары p и глубине f достаточно посетить не более суммы p^j для j от 0 до f. Каждая сохранённая пара достигается при некотором допустимом отзыве, что даёт нижнюю границу в модели явных строк. Проверка охватила 34 560 состояний всех порядков шести рёбер на четырёх вершинах для указанных B и f и 748 700 состояний на случайных порядках с 5–12 вершинами. [Доказательство и предпосылки](EXCHANGE_RU.md)

## За пределом гарантии

Сертификаты используют первые четыре адреса и сохранённые пары. Для раздельной проверки по корням каждое из двух направлений расширения получает верхнюю границу от одного из более ранних подмножеств. Для префикса оставляем столько же пар. У объединённого варианта дополнительный список явно увеличивает память.

| Отзывов | Состояний | Один общий сертификат | Раздельные пределы | Равный глобальный префикс | Объединение | Ошибок без проверки среди возвращённых |
|---|---:|---:|---:|---:|---:|---:|
| 3 | 960 | 891 | 891 | 822 | 897 | 1/898 |
| 4 | 1680 | 1295 | 1295 | 1181 | 1321 | 5/1328 |

Все сертифицированные ответы совпали с полным динамическим поиском. Раздельная проверка границ и один общий сертификат покрыли одинаковые запросы на этой панели. При неизвестном либо неподтверждённом результате нужен полный резерв. Внешняя задержка и частота подобных событий в работающем агенте не измерялись. [Протокол](OVERFLOW_RU.md)

## Минимальное изменение и вероятность результата

Перечисление обязательных удалений и обязательных живых документов для каждой пары и возможного первого эшелона дало 1030 достижимых областей на восьми вопросах. Представление верно во всех 8 192 масках, включая случаи с единственным оставшимся документом или пустой базой. Проверены минимальные бюджеты для всех 360 пар. При независимом отзыве каждого документа с вероятностью 0,2 модельная вероятность сохранить начальную пару на этих примерах лежит между 0.6400 и 0.6400. Для трёх однородных и одного неоднородного набора вероятностей максимальное расхождение формулы с суммированием по маскам составило 5.7e-15. Эти вероятности заданы исследователем. Записи включают минимальную маску для каждой пары и области с вынужденными живыми и отозванными адресами. [Вывод и условия](COUNTERFACTUAL_RU.md)

Вероятностное ранжирование и объяснение результатов запросов через изменения исходных данных имеют длительную историю в исследованиях БД. Проверяемая здесь специализация использует совместные зависимости двухступенчатого читателя и факторизацию по множеству его первых живых документов. Универсальный приоритет этой конструкции над существующей литературой не установлен. [Soliman, Ilyas, Chang, ICDE](https://cs.uwaterloo.ca/~ilyas/papers/SolimanICDE2007.pdf) · [Meliou et al., PVLDB](https://www.vldb.org/pvldb/vol4/p34-meliou.pdf)

## Нейросеть, внешний ориентир и расходы

На всех 7405 вопросах исходные опубликованные пары авторов содержат оба размеченных документа в 7204 случаях (97.29%). На нашей панели локальный исходный beam=2 совпал с эталоном в 8/8, полный поиск по 45 парам в 8/8. Совпадение локального beam=2 с опубликованными парами 8/8. Индивидуальная разметка для сопоставления с нейронной панелью присоединялась после фиксации прогнозов. Во время фонового расчёта отдельно проверялось агрегированное качество публичных пар на полном dev. Изменения выдачи при отзыве в полном официальном dev эти восемь вопросов не оценивают. [Опубликованные прогнозы](https://github.com/canghongjian/beam_retriever/blob/902980bfb5bd47a963569ab9c3621fd5ae81204a/results/retrieval/hotpot_pred_best_retr.json)

CPU FP32, 434,016,260 параметров, два потока. Семь стандартных полных прогонов по 55 encoder-вызовов занимали 58.8–85.8 с (медиана 77.5 с). Первый дополнительно включал 24 encoder-вызова для прямой проверки после одного отзыва. Максимальный рабочий набор основного процесса 1.98 GiB. Один повтор запуска с локально доступными файлами потребовал 6.69 с до получения инициализированной модели. Страничный кэш ОС неконтролируем. В отдельной проверке исходная батчевая реализация на двух вопросах и двух сценариях сохранила составы пулов и все четыре результата. Максимальное расхождение отдельных logits 4.8e-06. Расходы на исходное получение рангов входят в полную стоимость построения. Локальный кэш моделирует дальнейшие обращения после первичного чтения.

Оценки последствий отзыва парные внутри вопроса. Восемь вопросов (4+4) ограничивают вывод о частоте расхождений на всей коллекции. Метрика восстановления измеряет совпадение ранжирования, документный exact match измеряет выбор размеченной пары. Для утверждения о качестве ответа LLM нужны отдельный читатель и его оценка.

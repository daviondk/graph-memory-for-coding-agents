# Выбор записей памяти по графу зависимостей на ISETrace

В журнале инструментальных действий ISETrace одна и та же физическая строка файла иногда появляется в ответах нескольких реальных read-вызовов. Мы проверили, помогает ли учитывать эти пересечения при записи небольшого кэша. Изучаем отзыв **канонического содержания** наблюдения: если версия строки устарела, все её повторные появления исключаются. При потере отдельного сообщения прочие копии остаются пригодными, и для такой задачи нужен другой оператор. [ISETrace, описание корпуса авторами](https://huggingface.co/datasets/valiere/ISETrace/blob/main/README.md)

Кандидат первичного эксперимента — подлинное вхождение строки в выводе инструмента. Её ключ включает путь, исходный номер строки и хеш всех байтов без разделителя строк. Для каждой сессии BM25 ранжирует строки по запросу из natural_language_intent. Для составного узла проверяется актуальность всех наблюдавшихся в этом read строк. Ранги фиксировали до оценки событий отзыва. Данные и связь чтений подлинные, сами отзывы смоделированы. Практическая метрика — возможность получить тот же ответ, что и при полном просмотре ранга, из заранее ограниченной памяти. Исследование оценивает стоимость обслуживания такого запроса. Опубликованный benchmark Full Support@2048 для R-GCN на ISETrace измеряет качество восстановления размеченных доказательств и задаёт другую задачу. [Wang et al., When Does Execution Provenance Help Agent Memory Retrieval?](https://arxiv.org/abs/2609.25913)

## Какая память нужна

Для каждого кандидата вычисляется множество ID наблюдений, затрагивающих его обязательные атомы. Кандидат, чьё множество содержит множество более высокорангового кандидата, никогда не становится лучшим допустимым ответом. Одинаковые множества уже можно объединить, оставив лучшего. Основное сравнение показывает, что добавляет проверка **строгого включения** сверх такой дедупликации. Гарантия работает для неизменного ранга и явно заданной семантики отзыва. Для каждой из двух шкал ранга и обоих типов кандидатов мы дополнительно перечислили все возможные подмножества событий всех 280 сессий и подтвердили точное множество достижимых победителей. Получено 29 776 конфигураций «ранг, уровень и маска отзыва» и 744 400 проверок точного результата с непосредственным исключением атомов.

## Основной результат

Заранее выделили 67 сессий с минимум тремя чтениями и подлинным пересечением координат и байтов. Здесь 11 260 строк-кандидатов, 8 224 различных канонических строк, у 5 149 вхождений две или более зависимости. Для BM25 получилось 257 отдельных сигнатур, после проверки строгого включения — 218 потенциально выигрывающих. В 23 из 67 сессий существовало хотя бы одно строгое доминирование. Кэш может хранить до четырёх строк на сессию. Каждая сессия имеет одинаковый вес и 64 запроса отзыва с четырьмя уровнями вероятности.

| Правило записи, K≤4 | Строк на 67 сессий | Доказанных ответов из 4 288 | Доказанных NULL | Физический SQL p50 / p95, мкс |
|---|---:|---:|---:|---:|
| Обычный top-K | 268 | 3 050 | 386 | 3,5 / 18,8 |
| Лучший на каждое исходное сообщение | 237 | 3 688 | 713 | 3,3 / 12,2 |
| Дедупликация равных канонических строк | 268 | 3 281 | 498 | 3,4 / 17,7 |
| Лучший на каждую одинаковую маску зависимостей | 212 | 4 112 | 922 | 3,2 / 6,7 |
| Лучшие недоминируемые маски | 197 | **4 176** | 952 | **3,2 / 5,4** |

Строгое включение относительно равных масок даёт **+1,49 п.п. [0,40; 2,85]** по доказанному обслуживанию из кэша. Всего 64 дополнительных ответа в 7 сессиях и 0 потерянных. Из прироста 34 случая — правильные непустые ответы и 30 — доказанное отсутствие решения. Относительно одного лучшего на исходное сообщение прирост **+11,38 п.п. [7,30; 15,95]**. Полный резерв получил 112 вызовов вместо 176 при дедупликации масок; логически просмотрено 13 116 вместо 20 509 ранговых позиций. На всех 292 одиночных отзывах строгая политика обошлась кэшем, простая — в 291. Число случаев отсутствия ответа в основной смеси четырёх частот составляло 1 020; поведение смеси зависит от распределения обновлений.

**Границы эффекта.** На тех же строках при ранге по давности дополнительный выигрыш сверх равных масок +0,21 п.п. [0,00; 0,61]. При BM25 для целых read-блоков обе политики решили 4 190/4 288. В 37 сессиях с пересечениями и всего двумя сообщениями равные и недоминируемые маски при K≤4 дали 2 368/2 368. В 176 сессиях минимум с тремя чтениями и без пересечений одна запись на producer, равные и недоминируемые маски дали одинаковые 11 129/11 264 при BM25 строк. Следовательно, выигрыш зависит и от реального пересечения наблюдений, и от того, как упорядочены конкурирующие кандидаты.

## Цена и расширенная проверка источника

Для 280 сессий исходно сверено 973 чтения, 31 175 различных координат с хешем и длиной байтов. После загрузки исходных JSON сопоставление и проверка доступных байтов заняли 0,057 с, расчёт BM25 для строк и целых блоков — 1,210 с. В основной группе формирование масок строк заняло 0,0023 с, вычисление всех пяти политик отбора — 0,0038 с. Эти одноразовые измерения исключают чтение и разбор 4,92 ГБ исходных шардов. Время разбора входа зависит от ввода-вывода и конкурирующих задач.

Общая SQLite БД координат и связей занимает 3 231 744 байта, физический полный резерв для обеих гранулярностей и обоих рангов — 1 175 552 байта. Дополнительный файл K≤4 для всех 280 сессий и четырёх представлений занимает 77 824 байта у **обеих** политик по маскам, 81 920 у producer и 90 112 у raw. Разница строк основной когорты не перешла в уменьшение числа страниц файла для всего смешанного набора. Задержки в таблице сняты на одном локальном SQLite с общим открытым снимком, 85 760 фактических измерений. Для всех 4 288 исходных запросов ответы SQLite контролировались независимо.

Независимый повтор по двум дополнительным допустимым именам параметра пути обнаружил 11 ранее отсутствовавших сессий с минимум тремя чтениями и повторным каноническим атомом. При тех же BM25 и K≤4 по 704 запросам получили 690 доказанных ответов у недоминируемых масок, 677 у равных масок и 598 у producer. Разница над равными масками +1,85 п.п. [0; 5,54], все 13 добавочных случаев в **одной** новой сессии. Разница над producer +13,07 п.п. [3,13; 24,43]. Это малая независимая проверка с неопределённостью, включающей ноль для эффекта строгого включения. Изменённые ранее наблюдавшиеся истории приведены отдельно в alias4/extension-results.json. Перенос на иные корпуса и естественные обновления остаётся открытым вопросом.

## Воспроизведение

В этом каталоге выполнить `python prepare.py`, `python study.py`, `python summarize.py`. Расширение воспроизводится запуском `python alias4/repeat.py`. Только чтение исходных сообщений и вычисление по сохранённым данным, без выполнения команд из траекторий. Все бюджеты, когорты и исходные hashes зафиксированы в планах. Физические файлы на D указаны в скриптах, переносимые результаты защищены контрольными суммами.

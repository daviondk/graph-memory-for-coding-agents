# Какую память хранить для совместного чтения двух источников

Для демонстрации ICDE реализован граф, у которого вершины — наблюдавшиеся источники, а ребро означает пару, оценённую читателем. Пользователь выбирает вопрос, отзывает источники и видит новую лучшую пару, причину её выбора и необходимость обращения к полному списку. В режиме сервера решения принимает SQLite. Автономную копию можно открыть непосредственно в браузере. [Демонстрация](pair_demo/evidence.html) · [Запуск SQLite](pair_demo/REPRODUCE_RU.md) · [Требования к демонстрациям ICDE](https://icde2027.github.io/cf-demonstrations.html)

В присланной работе Zhang и соавторов работники передали обе конфликтующие посылки только для 35,2% пар, которые уже нашли. Наши опыты проверяют другие, операционально измеримые этапы — сохранение строки, передачу её адреса и восстановление доступных опор после отзыва. Объединять эти проценты в одну метрику некорректно. [Zhang и соавторы](https://arxiv.org/abs/2611.22245)

Для статьи сильнее всего подтверждён системный результат о размере и точности памяти при ограниченном числе отзывов. Качество конечного ответа агента и выигрыш у лучшей опубликованной системы остаются открытыми. Для адаптивного нейронного поиска остаётся проверить перенос результата на большее число независимых вопросов и фактическую стоимость построения компактной памяти.

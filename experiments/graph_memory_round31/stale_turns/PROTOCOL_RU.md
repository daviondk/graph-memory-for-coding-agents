# Точная доставка реплики об изменении состояния в STALE

Эксперимент включает 400 опубликованных сценариев, три исходных вопроса на сценарий. Три вопроса одной истории целиком входят в один split. В разведочную часть D80 включаем восемь сценариев раннего пилота R29, затем добираем 72 сценария по SHA-256 от константы r31-stale-split и opaque case. Оставшиеся 320 составляют основную панель T320. Выборка зависит только от ID, ранее просмотренных сценариев и размера split. Фиксируем все методы до оценки. На D80 настройки не подбираем. Публикуем отдельно N и результаты по D80, T320, всем 400, трём исходным измерениям и двум типам обновления.

Обычный доступ видит только датированные реплики пользователя в 50 сессиях и ровно один вопрос. Две сессии обычного поиска задаём лучшими разными адресами из глобального RRF(60) BM25 и вектора E5 для пользовательских реплик, лучший ранг реплики задаёт ранг соответствующей сессии. Тонкая локализация затем получает конкретные два адреса, хронологический порядок и исходный вопрос. Для отдельной проверки с привилегированными адресами составитель даёт два размеченных ID; их текстовые факты, код типа, рубрики и отмеченные номера реплик всех методов локализации не касаются. Привилегированная выдача — условный тест локализации, обычная — измерение всего поиска. Ранжировщик видит одинаковый интерфейс для обоих типов пары и не получает ключ типа. Результаты публикуем только после фиксации адресов и всех текстовых передач. Одно семейство алгоритмов видит один и тот же документ целиком. Индексирование всех сессий здесь служит контролем внешней коллекции.

Обычные единицы поиска — пользовательские реплики и сдвигаемые окна. Окна по 96 нативных токенов Qwen, шаг 48, последнее дозаполняется влево. Если исходная реплика длиннее окна, её центр остаётся в центре возвращаемой выдержки; для короткой реплики добавляется реальный соседний текст той же сессии. Длина фактического датированного источника одинакова внутри каждой пары и каждой позиции между методами. Для каждой сессии используем постоянный заголовок с датой и адресом, обе позиции хронологически отсортированы. Обозначаем точные символьные смещения и отдельно число нативных токенов заголовка, выдержки и их совместного представления. Никаких вспомогательных текстов с эталонной формулировкой.

Контроли: BM25 внутри сессии по репликам, пуловый E5-small-v2 по репликам, их RRF(60), гибридное RRF-ранжирование сдвигаемых окон, а также позднее взаимодействие токенов MaxSim. Контроль MaxSim ранжирует реплики по среднему наилучшему совпадению каждого несервисного токена вопроса с токеном реплики. Альтернатива Pair — RRF(10) для трёх свидетельств релевантности отдельной реплики (BM25, E5, MaxSim), затем совместный выбор пары: сумма двух внутрисессионных reciprocal rank (1/(5+r)) плюс 0,25 от суммы взаимных reciprocal rank по косинусной близости реплик разных сессий. Вводим независимый контроль без связи с тем же RRF(10). Сравниваем Pair с Window hybrid и независимо с тем же представлением без связи. Главный исход — доля вопросов, для которых фактически переданы оба полных эталонных утверждения в своих источниках на T320 при привилегированной паре. Дополнительные — тот же исход при обычных адресах, раздельные old/new, точная доля покрытых слов в эталонных спанах и попадание их исходных реплик. Условия выбора и набор компараторов зафиксированы до scoring. При выходе за предел документа окно выравниваем в обратную сторону до доступной длины.

Ошибки буквального совпадения отличаем от смысловой эквивалентности. Для буквальной метрики связываем последовательность нормализованных слов с символьными координатами в пользовательском источнике. Если одна и та же строка упоминается дважды в правильном источнике, учитываем лучше всего покрытое наблюдение. Фразы без надёжного точного спана учитываем в общем знаменателе и сообщаем отдельно. Ограниченную проверку смыслового покрытия делаем вслепую на не более 24 выдержках, сбалансировав полное, частичное и нулевое буквальное покрытие по известному после теста исходу; это калибровка метрики, не оценка частоты парафразов в популяции. До начала оценивания фиксируем воспроизводимый выбор по хешу, без подбора тем и без названий методов в пакете. Второй независимый оценщик проверяет, можно ли обосновать тот же факт по предъявленной выдержке и конкретной цитате. Каждая проверка имеет локальные ссылку на исходную реплику и позицию.

Случайная единица при оценке неопределённости — сценарий. Для двух основных контрастов по привилегированным адресам строим парные процентильные интервалы 97,5% по сценариям, 10 000 повторов фиксированного генератора; для остальных контрастов — описательные 95%. Отдельно отчитаемся о совпадающих предсказаниях, абсолютных ошибках и токенах. Полный реальный ответ LLM относится к другому исходу. На этом этапе дорогой отдельный QA-прогон заслуживает выделения ресурсов только при надёжном положительном приросте по обоим заранее заданным контролям на T320 и подтверждении качества локализованных фактов. Этот фильтр не меняет результатов на 1200 вопросах. Полученный процент не сопоставим с официальной метрикой ответов STALE.

# Выбор следующего документа по одному наблюдению

В HotpotQA разрешили одно чтение до 192 WordPiece и предложили вернуть два адреса. Стоимость первого чтения, каталог и число выдаваемых адресов совпадают между методами внутри панели. Лексический поиск на всех 7 405 вопросах верно открыл первый документ в 5 613 случаях. Средний фактический объём — 94,58 токена.

| Как выбран второй адрес | Обе опоры, все 7 405, BM25 | Обе опоры, 512, E5-small-v2 INT8 CPU |
|---|---:|---:|
| Исходный вопрос | 28,62% | 37,70% |
| Расширение запроса после чтения | 21,86% | 44,53% |
| Буквальное упоминание, затем исходный порядок | **53,32%** | 58,20% |
| Упоминание, затем расширенный порядок | 43,59% | 59,57% |
| То же с учётом слов вокруг упоминания | 44,52% | **60,55%** |
| Случайная перестановка концов обнаруженных связей | 15,21% | 31,64% |

Первичное сравнение локального контекста с упоминанием при одинаковом расширении дало 93 улучшения и 24 ухудшения на полной панели, +0,93 п.п., 95% интервал [0,65; 1,22]. Среди 577 вопросов с несколькими упомянутыми адресами эффект составил +11,96 п.п. На плотной панели 310/512 против 305/512, пять улучшений при нуле потерь. На тех же 512 вопросах лексический вариант с упоминанием и исходным порядком дал 286/512. Плотная панель включена в полную. Различия между колонками сочетают смену размера панели и первого документа. Парные сравнения на общих 512 вопросах приведены в results.json.

Источник крупной прибавки — содержание уже прочитанного фрагмента указывает на следующий адрес. Словарное расширение запроса у лексического метода заметно понизило качество запасного порядка. Следующая проверка на другом корпусе сохраняет исходный BM25 в качестве запасного порядка. Эти результаты описывают выбор двух документов, генерация ответа здесь не запускалась.

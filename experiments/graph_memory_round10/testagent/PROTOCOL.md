# Решение агента о повторной проверке под жёстким ограничением

18 исторических математических изменений SymPy, 10 из R8 и 8 других из R7. Берём состав, старые исходы тестов и эталоны из совместимых фактических запусков R9. Модель впервые используется для решения этой задачи выбора теста. Для каждого снимка имеется несколько ранее выполненных тестов; после правки агент получает имя каждого теста, прежний pass/fail и сокращённый diff производственного кода. Бюджет — ровно один вызов pytest на задачу и направление. У всех рук одинаковые тесты и лимиты. Цель — выбрать тест, старый исход которого изменился. Когда выбор сделан, меняем в памяти только исход выбранного теста по исполнению. Считаем, сколько устаревших исходов осталось, сколько изменившихся предыдущих «зелёных» тестов реально нашли. По каждой задаче также сравниваем с достижимым максимумом при одном запуске. На двух направлениях одновременно не утверждаем удвоение размера выборки.

Сравниваем четыре варианта подачи Qwen3.8-27B UD-Q4_K_M, локально на RTX 3090, greedy: (1) у старых записей тег отсутствует, (2) реальная связь с изменившимся определением по точному графу старого теста R9, (3) та же численность связей с циклической перестановкой между тестами одного снимка, (4) привилегированная битовая маска, указывающая тесты с изменившимся исходом (контроль потолка; значения никогда не передаются остальным рукам). В инструкции нейтрально описываем бит как отметку для приоритетной перепроверки; одинаковый текст и место бита во всех вариантах. Тестовый diff, имена issue и статусы текущей версии скрыты. Очерёдность и порядок ID закреплены хешем до генерации, одинаковы внутри пары. Код использует только старые графы и разрешённый текущий diff. Ветка с привилегированным сигналом строится отдельно как отдельный процесс после закрытия остальных входов и ответов. Дополнительный дешёвый контроль — приоритет прежних падений, затем токены имени теста из изменения, затем заданный порядок; версия с тестовой зависимостью использует дополнительный приоритет перед лексическим. Порогов и подгонки нет. Новые занятия по исправлению кода и pass@1 в этом протоколе не измеряются.

Основное сравнение — сколько из 18 новых падений-переходов или задач с новым падением обнаружено при откате (одна смена на команду максимум) у настоящего сигнала против переставленного, с парными выигрышами и потерями по issue и точным McNemar. Число действительных падений определяется полным тестовым прогоном, не предполагается ровно один тест на каждую задачу. Отдельно forward и агрегат точных обновлений. Каждое реально выбранное уникальное сочетание версия–тест проверяется отдельным pytest после фиксации предсказаний. Статусы с расхождением маркируем. Сохраняем предложения, токены, время, отсутствие результата из-за ошибки формата и записи каждого выполнения. Результат описывает маленький бюджет на действие агента на известной панели, а не общую вероятность исправления репозитория.

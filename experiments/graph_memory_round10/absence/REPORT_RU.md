# Когда память о неуспешном поиске помогает агенту повторно использовать результат

Если инструмент раньше сообщил, что модуль или ресурс отсутствует, его появление способно изменить результат операции, хотя содержимое ни одного ранее прочитанного файла не изменилось. В этой серии мы проверили политику, которая сохраняет точное имя такого объекта и пересчитывает результат, когда объект появляется. На трёх исторических обновлениях базы часовых поясов и в четырёх библиотеках политика обнаружила все 14 изменений прикладного результата в обоих направлениях. Из них семь при появлении ресурса или модуля пропустила политика, учитывающая только успешные чтения. Обратные переходы повторно проверяют те же механизмы. Выборка целевая.

## Какие операции выполнены

| Источник | Сценарий | Измеряемый результат |
|---|---|---|
| IANA tzdb через колёса tzdata | Соседние версии 2022.1→2022.2, 2022.6→2022.7 и 2025.1→2025.2, а также откаты | Настоящий вызов Python zoneinfo для Europe/Kyiv, America/Ciudad_Juarez, America/Coyhaique, UTC, Europe/London и America/New_York. Получаем числовые смещения UTC за январь и июль либо результат об отсутствии зоны |
| tabulate 0.10.0 | Установка и удаление wcwidth 0.9.4 | Таблица с заголовком CJK и правильной шириной ячейки |
| markdown-it-py 4.3.0 | Установка и удаление linkify-it-py 2.2.0 | HTML-ссылка из URL при обработке Markdown |
| NetworkX 3.6.1 | Установка и удаление pydot 4.0.1 | Список рёбер после преобразования графа в DOT |
| fsspec 2026.9.0 | Установка и удаление lz4 4.4.5 | Побайтовое восстановление строки после сжатия LZ4 |

Пары tzdata взяты из опубликованных выпусков данных. Четыре установки опциональных модулей воспроизводят контролируемое изменение среды официальных библиотек. В каждом из этих четырёх проектов заранее выбраны основная операция, обычная операция библиотеки и независимый вызов стандартной библиотеки. Плацебо устанавливает и удаляет постороннее колесо six 1.17.0 в тот же каталог. Во всех состояниях сохраняются реальные метаданные колёс. Для tzdata целиком заменяется дерево TZif в отдельном TZPATH, набор установленных Python-дистрибутивов постоянен. Протокол, версии и контрольные суммы доступны в [протоколе](PROTOCOL_RU.md) и [реестре источников](sources.lock.json). [Архив выпусков IANA](https://data.iana.org/time-zones/releases/) · [Документация zoneinfo](https://docs.python.org/3/library/zoneinfo.html).

Граф двудольный. Узел операции связан с успешно прочитанными файлами и с именами, поиск которых завершился без результата. Поток событий импортов и обращений к файлам получен при реальном выполнении. Для старого положительного множества P и старого отрицательного множества N решение о повторе принимается, если P пересекается с изменёнными или удалёнными файлами либо N пересекается с именами, добавленными обновлением. Сравнение с каталогом активирует операцию при появлении любого файла в каталоге ранее безуспешного поиска. Список изменённых путей известен всем политикам. Решения зафиксированы до сбора новых результатов. Весь эксперимент выполнен на CPU с Python 3.11.15, pytest 7.4.4, pytest-testmon 2.3.1 и coverage 7.13.5. [Зафиксированный дизайн](design.lock.json) · [Зафиксированные предсказания](forecast.lock.json).

## Результаты

В ячейке указаны **число повторно выполненных операций / число пропущенных изменений результата**. Устаревший результат — изменившееся каноническое значение, которое политика решила переиспользовать. Для всех 14 наблюдавшихся изменений поменялся и исход нашего функционального pytest-контракта. Полный повтор требует выполнить все операции в столбце N и ловит все изменения. Безусловное переиспользование пропускает все изменения в столбце Δ. [Сводная таблица](results.json) · [Все 84 решения с совпавшими ключами](rows.json).

| Переход | N | Δ | Успешные чтения | Каталог | Точные ключи | pytest-testmon |
|---|---:|---:|---:|---:|---:|---:|
| tzdata, новый выпуск | 18 | 3 | 0 / 3 | 4 / 0 | **3 / 0** | 6 / 0 |
| tzdata, откат | 18 | 3 | 3 / 0 | 3 / 0 | **3 / 0** | 3 / 3 |
| Добавлен опциональный модуль | 12 | 4 | 0 / 4 | 8 / 0 | **7 / 0** | 12 / 0 |
| Удалён опциональный модуль | 12 | 4 | 7 / 0 | 7 / 0 | **7 / 0** | 12 / 0 |

Шесть лишних повторов у точной политики пришлись на обычные операции tabulate, markdown-it-py и fsspec в обоих направлениях. Инициализация библиотеки обращалась к опциональному модулю даже при вычислении результата, независимого от него. Например, таблица из ASCII остаётся прежней при появлении поддержки широких символов. У NetworkX проверка pydot привязана к экспорту графа, поэтому вычисление длины кратчайшего пути не вызвало лишнего повтора. Разница точного ключа и каталога особенно заметна при установке six — восемь лишних запусков у проверки каталога. На функциональных установках и откатах разница между ними составляет всего один запуск из 24.

У pytest-testmon выполнялись оригинальный сбор и выбор тестов с ключами `--testmon --testmon-forceselect`, одинаковыми nodeid и штатной проверкой окружения. В контролируемых установках и плацебо менялся набор метаданных пакетов и плагин повторял все тесты. На трёх откатах tzdata удалялись файлы данных при стабильном Python-окружении. Плагин не запустил три ранее проходивших теста, результат которых поменялся, и повторил три ранее падавших теста с неизменившимся значением. Это свойство конкретной конфигурации с внешними TZif. [Пооперационные протоколы оригинального плагина](plugin) · [Пример отката](plugin/tzdata_2022.2_2022.1/receipt.json).

## Независимая проверка и цена хранения

Повторное выполнение 72 уникальных комбинаций «проект, версия/состояние, операция» в новых интерпретаторах без перехватов полностью воспроизвело канонические значения и функциональные исходы. Проверены хеши 22 исходных архивов и содержимого 18 развёрнутых состояний. Из неизменённых релизных тестов авторов с провайдером прошли 37 из 37 выбранных случаев — один tabulate, 31 markdown-it-py, четыре NetworkX и один fsspec. Без провайдера и при установке six исходные тесты штатно пропускались. NetworkX пропустил модуль целиком ещё до сбора четырёх отдельных случаев. Число 37 относится к выбранным функциям и параметризациям, а единица основного сравнения — вызов прикладной операции. ## Что следует из результата для памяти агента

Точный адрес прежнего промаха стоит сохранять, когда ранее полученное значение использует fallback и у инструмента есть определённый контекст разрешения имени. На этих наблюдениях связка положительных и отрицательных рёбер покрывает появление и исчезновение объекта. Отдельное отрицательное ребро здесь добавляет ценность именно при появлении. Если поиск зависел от порядка путей импорта, сетевого источника, namespace-пакета или переменной среды, имя само по себе не задаёт все условия воспроизводимости. Сигналы в выборке специально отобраны по известному механизму. Три исторических изменения принадлежат одной базе данных, четыре библиотечных установки проверяют разные исходные проекты. 84 решения связаны внутри переходов и не дают 84 независимых репликаций. Генеративный агент, задачи исправления кода и сравнение с лидербордом SOTA в дизайн этой серии не входят.

Приоритет самого принципа уже установлен в инкрементальных сборках. redo-ifcreate объявляет ранее отсутствующий путь входом для последующего запуска. Tup отслеживает несуществующие файлы в виде ghost nodes. Для статьи сильнее вопрос о том, как отделить обращение во время общего импорта от отрицательного наблюдения, действительно влияющего на ответ инструмента, и сохранить это объяснение в памяти агента. Этот следующий шаг можно фальсифицировать на новых репозиториях по снижению шести ложных срабатываний при сохранении чувствительности и с учётом стоимости инструментирования. [redo-ifcreate](https://redo.readthedocs.io/en/latest/redo-ifcreate/) · [Руководство Tup](https://gittup.org/tup/manual.html).

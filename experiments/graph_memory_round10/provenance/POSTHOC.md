# Дополнительные контроли после основной оценки

После записи результатов R10 добавляем более сильный контроль adaptive_flat. Этот вариант независимо оптимизирует число хешей каждого обычного фильтра при 256 байтах на тест и не выделяет общую часть. Сохраняем и считываем новые буферы через тот же нативный интерфейс CODE_OBSERVATION, в отдельных базах. Все исторические и текущие квитанции тестов, наборы изменений, старый порядок, budget и seed остаются прежними. Выбор параметров работает только с исходными множествами. Оценщик читает будущие статусы после записи расписания. Эти данные оценщика уже известны из основной серии. Сравнение selected−adaptive_flat является вторичным. Заранее заданные для этой проверки расчеты совпадают с основной серией. Также сообщаем значение штрафа за ошибку, при котором безусловный перенос уступает политике с воздержанием при равных ценах подтверждения.

# Воспроизведение сравнения R10

Использован Python 3.12.13 и NumPy 2.5.5. GPU, модель и учётная запись не требуются. Сохранённые байты считываются стандартной библиотекой Python. NumPy нужен для построения и статистики. Корневой каталог — текущая папка. Функции разрешают все локальные пути относительно файлов скриптов.

В двух соседних сериях должны быть доступны каталоги graph_memory_round9/budget, graph_memory_round9/testmemory_compat и graph_memory_round9/testmemory_holdout. Для исторического R9 нужны budget/sketch.py, budget/{testmemory_compat,testmemory_holdout}/rows.json.gz. Для исходных графов и исходов нужны graphs.json.gz, outcomes.json и runs/<issue>/nodes.json каждой панели. Их SHA-256 сохранены в input_receipt.json и results.json. Перенос на другой диск поддержан проверкой суффикса пути к graph_memory_round9 в verify_integrity.py.

Проверка готового пакета:

    python verify_integrity.py

Перед повторным экспериментом скопируйте код, протоколы и структуру соседних путей R9 в свежую рабочую папку. Предохранитель построителя ожидает отсутствие state_seal.json и ef_seal.json на новом запуске. Исходные квитанции удалять не требуется. Порядок воспроизведения:

    python prepare.py
    python build.py
    python query.py
    python grade.py
    python timing.py
    python ef_build.py
    python ef_evaluate.py
    python ef_direct_verify.py
    python challenge.py
    python verify_integrity.py

Файлы old/ и future/ содержат раздельные проекции прежних рёбер и будущих запросов. Каталоги states/ и ef_states/ содержат все 16 128 состояний проверки в виде base64-строк в детерминированно упакованных gzip JSON. Это исследовательская упаковка массива состояний. В бюджет теста входит сохранённое внутри строки байтовое представление. Декодеры reader.py, ef_reader.py и ef_direct.py не читают old/ или списки тестов. Файлы reads.json.gz и ef_graded.json.gz содержат фактические маски, graded.json.gz — счётчики каждой записи. Полная раскладка по задаче, варианту, бюджету и соли сохранена в results.json, ef_results.json и challenge_rows.json.gz. Случайные ключи определяются кодом challenge.py.

Первый локальный запуск build.py завершил запись 36 наборов состояний, затем преждевременно дошёл до получения SHA скриптов чтения, которые ещё записывались на диск. После появления этих файлов повторный запуск взял уже подготовленные наборы и зафиксировал контрольные суммы до первого чтения запросов и подсчёта исходов; состояние R9 не менялось. Подробности в build.log. Для полностью нового запуска предварительно скопируйте весь комплект скриптов. Численные времена записи в архивах могут отличаться между машинами и меняют SHA самих архивов. Объект сравнения состояний — декодированная base64 последовательность байтов. Времена следует оценивать через timing.py, результаты в основном отчёте.

MANIFEST_SHA256.json описывает файлы исследования, включая отдельное подтверждение verification.json. Проверка квитанций сверяет входные снимки, сохранявшиеся состояния и новые агрегации по исходным тестовым событиям. В R10 не запрашивались внешние API и не выполнялась синхронизация Git.

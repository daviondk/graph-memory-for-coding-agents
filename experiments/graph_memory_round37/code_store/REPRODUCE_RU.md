# Воспроизведение

Для независимого пересчёта выдачи, минимального числа SQL-мутаций, итоговых показателей журнала и средних времени достаточно стандартного Python.

~~~powershell
python verify.py
~~~

Для физического прогона создать копию этого каталога рядом с code_visibility на том же диске D и запустить из неё:

~~~powershell
$pythonResearch='D:/CodexResearch/x20-isetrace-e5-gpu/venv/Scripts/python.exe'
& $pythonResearch inputs.py
& $pythonResearch benchmark.py
& $pythonResearch analyze.py
& $pythonResearch verify.py
~~~

Скрипт inputs.py открывает только подписанную проекцию событий и эталон уже выданных политикой T адресов. Для наполнения рабочей базы он выбирает исключительно предыдущий просмотр и подтверждённую операцию правки. Эталон хранится в отдельном файле и используется только для проверки ответа. Скрипт benchmark.py создаёт изолированные временные файлы SQLite и WAL внутри каталога запуска, проверяет выдачу, записывает счётчики и тайминги, затем закрывает соединения и очищает свои временные файлы. Windows-функция QueryThreadCycleTime используется только для дополнительного показателя числа циклов.

В plan.json зафиксированы ID панели, отпечатки входов, протокола и программ до замеров. Полные числовые исходы — full_counts.json.gz и timings.json.gz. Физические размеры таблиц и WAL расположены в run-seal.json. Повторный тайминг даст новые числа; идентичность прогнозов и число логических изменений воспроизводимы.

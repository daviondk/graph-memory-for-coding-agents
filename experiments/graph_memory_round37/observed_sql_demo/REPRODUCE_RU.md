# Запуск работающей демонстрации

В PowerShell откройте папку комплекта и запустите стандартный Python 3.10+:

~~~powershell
Set-Location 'D:/CodexResearch/x20-bench-workspace/work/graph_memory_round37/observed_sql_demo'
python -B serve.py
~~~

Откройте в браузере [локальный интерфейс](http://127.0.0.1:8781/). Если этот порт занят, задайте другой через `python -B serve.py --port 8782`; выбранный адрес появится в консоли. Для остановки нажмите Ctrl+C. Сервер слушает только IPv4 loopback и открывает обе базы в режиме SQLite `mode=ro&immutable=1` с `PRAGMA query_only=ON`. Сеть, GPU, учётная запись и исходный исследовательский workspace для показа не нужны. Для переносимого комплекта скопируйте эту папку с вложенными каталогами. Открытие index.html напрямую с диска не запускает SQLite.

1. Выберите **File expansion**. Обратите внимание на перенесённый адрес 3647 → 3655 и три адреса из ответа редактора.
2. На **File contraction** нажмите **Edited region**. Измените границы вручную и нажмите **Run range query**. Раскройте **Answer SHA-256**, чтобы сравнить полные ответы двух читателей.
3. На **Capacity overflow** выберите **Evicted line**. Для строки 271 оба читателя вернут пустой ответ при разном числе переданных записей.

Проверка целостности всех файлов комплекта:

~~~powershell
python -B verify.py
~~~

Для независимой повторной проверки SQL и HTTP используйте `python -B -X utf8 selftest.py` в рабочей копии. Процесс поднимет локальный сервер на случайном порту, сделает проверки и закроет его. Для повторной браузерной проверки подойдут системный Chrome или Edge и Python-пакет Playwright; запускается `python -B -X utf8 browser_check.py`. Переменная CHROME_PATH может указывать на другой исполняемый файл браузера. У браузерного теста собственный временный сервер. Он обновляет снимки и протокол браузера в рабочей копии, поэтому их контрольные суммы могут отличаться на другой машине. Повторная сборка из исходных экспериментов возможна через `python -B build.py` при наличии соседних исходных папок code_visibility, code_store и range_read. Версия SQLite может менять физические байты собранной БД; эталонные упорядоченные пары и тесты содержимого проверяются отдельно.

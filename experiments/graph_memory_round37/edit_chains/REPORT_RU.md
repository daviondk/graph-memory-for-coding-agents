# Адреса строк после нескольких правок одного файла

В траекториях Handoff Debt нашли 14 строгих интервалов между чтениями одного файла, в которых редактор подтвердил несколько последовательных замен. На следующем чтении проверились 111 информативных строк. **Перенос адреса через каждую правку сохранил 22 правильные строки; хранение по старым номерам дало 13 правильных и 4 ошибочные.** Преимущество переноса над старыми номерами происходит из двух задач. Этого недостаточно для надёжной оценки размера эффекта на новых проектах. [Протокол](PROTOCOL_RU.md) · [Все исходы](outcomes.json.gz)

## Что доступно при обновлении памяти

На старте агент уже видел часть файла. После каждого успешного str_replace ему доступна пронумерованная квитанция редактора. В прежней проекции положение правки определяется единственным видимым вхождением нового текста, длины старого и нового фрагментов известны из аргументов операции. Только эти наблюдения входят в память. Изменение переносит надёжные адреса ниже заменённого участка на разность числа строк. Старые наблюдения внутри участка удаляются, свежая квитанция перезаписывает совпавшие адреса. Если не удаётся определить место замены, остаётся только квитанция. Каждая из политик хранит до 128 пар «номер, SHA-256 текста» после каждой операции. Оценка читает следующее фактическое наблюдение отдельно от прогноза. Остальные адреса в памяти остаются непроверенными. [Оригинальная проекция](../code_visibility/REPORT_RU.md) · [Алгоритм](forecast.py)

## Строгие основные окна

Покрытие — доля правильно предсказанных пар «номер, хеш» среди информативных строк следующего просмотра. Сначала объединяли все просмотры внутри задачи, затем усредняли шесть задач с одинаковым весом. Сырые счётчики в таблице дают также возможность восстановить долю с весом строк.

| Политика накопления | Правильно / ошибочно | Покрытие с равным весом задач | Фактов в среднем |
|---|---:|---:|---:|
| F, только последняя квитанция | 11 / 0 | 10,54% | 7,50 |
| K, все обновления на старых номерах | 13 / 4 | 12,75% | 16,43 |
| T, последовательный перенос и квитанции | 22 / 0 | 32,19% | 15,29 |
| H, старые номера при равном числе фактов | 12 / 3 | 11,82% | 15,14 |
| T*, перенос при равном числе фактов | 20 / 0 | 30,34% | 15,14 |
| C, перенос только фактов из квитанций | 12 / 0 | 11,47% | 10,14 |

Парная разность T−K составила **+19,44 п.п.**, 95% кластерный bootstrap по задачам **[0,00; 52,78]**. T−F дал +21,65 [1,28; 53,70], T*−H при точном равенстве числа фактов после каждого шага +18,52 [0,00; 51,85], T−C +20,73 [1,28; 52,78]. По 111 строкам прирост T−K равен 9/111, или +8,11 п.п. В scikit-learn при следующем просмотре отличились шесть из шести строк (6 против 0), в matplotlib — три из восемнадцати (14 против 11). На остальных четырёх задачах покрытие T и K совпало. При исключении задачи scikit-learn разность T−K с равным весом оставшихся задач снижается до +3,33 п.п. В восьми эпизодах одной задачи SymPy ни одна из 66 наблюдавшихся строк не была правильно предсказана T, K или F. [Исходы по задачам и интервалы](results.json)

**Откуда берутся правильные строки.** У T 11 фактов подтверждены последней квитанцией, один пришёл из промежуточной квитанции и десять — из исходного просмотра до всех правок. Поэтому накопление промежуточных квитанций само по себе мало объясняет прирост на этом наборе. В 151 основном непрозрачном окне распределение другое: 695 из последней квитанции, 374 из промежуточных и 385 из исходного просмотра. Последующая видимая квитанция получает авторство строки даже при совпадении с её старым значением.

В трёх задачах строгие основные и строгие дополнительные окна относятся к одним и тем же issue. Все дополнительные запуски происходят из ранее выбранного исходного набора задач. Непрозрачное событие могло изменить файл, а служебный признак «строгое окно» свидетельствует лишь об отсутствии зарегистрированного барьера. Корпус наблюдений ретроспективен. Проекция охватывает пронумерованные информативные строки из ранее отфильтрованных научных Python-репозиториев. В таком окне можно измерить корректность оставшихся адресов при повторном чтении; доля решённых задач, фактически предотвращённые чтения и сравнение с внешней SOTA требуют другого эксперимента.

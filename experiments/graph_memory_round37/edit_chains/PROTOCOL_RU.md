# Адресная память после последовательности замен

До вычисления исходов фиксируем единственный источник фактов: статическая версия code_visibility/events.json.gz, проверенная по source-seal.json. Прикладные строки представлены только адресами и SHA-256. Алгоритм получает из прошлой операции адрес видимого якоря, число старых переводов строк, смещение и выданные инструментом информативные строки. Поля нативного аудита и следующий просмотр отделены от входов алгоритма. Обучение, подбор параметров и исполнение кода из корпуса отсутствуют.

Берём два последовательных успешных явных просмотра того же нормализованного пути в одном запуске. Требуются информативные строки в обоих. Между ними не менее двух успешных замен str_replace на этом пути, все связаны со своими действиями, дополнительных попыток записи и иных успешных записей на этом пути нет. Действие и ответ каждой операции должны строго следовать за ответом предыдущей. Основная группа — predecessors и main_takeovers без непрозрачного события в интервале. Окна с потенциально изменяющим среду непрозрачным действием/ответом рассматриваем отдельно. Дополнительные прогоны тех же задач анализируются с той же стратификацией. Регистрируем все знаменатели потока отбора до проверки результатов.

На каждом шаге вместимость равна 128 фактам (номер, SHA-256 содержимого) на текущий файл. Предыдущий просмотр и каждый видимый фрагмент квитанции при переполнении урезаются в порядке SHA-256 от строки «R37-128|путь|номер», затем номера. Сначала новые факты, остальные свободные места заполняют старые в том же порядке. Три основных политики:

- F оставляет только последнюю квитанцию.
- K со старыми номерами накладывает ту же квитанцию на прежнюю память без переноса.
- T при видимом якоре k удаляет старые строки в [k,k+old_breaks], сохраняет адреса выше, двигает адреса ниже на delta; при отсутствии якоря хранит только новую квитанцию. Композиция применяется после каждой операции онлайн, с ограничением вместимости на каждом шаге.

H и T* — отдельные, последовательно поддерживаемые K и T. На каждом шаге их расширения сверх квитанции усекаются до меньшей доступной длины, без использования будущего; для обоих выбираем старые факты детерминированным порядком. C проверяет, сколько покрытия T можно получить только из совокупности прошлых квитанций: тот же алгоритм T со стартовой пустой памятью. Сообщим также происхождение верных строк T: начальный просмотр, промежуточная квитанция, последняя квитанция; новая квитанция меняет происхождение даже при совпадении факта. Метки происхождения диагностические, в ранжировании не участвуют.

На следующем фактическом просмотре считаем правильные и ошибочные пары «наблюдаемый адрес, хеш», остальные адреса памяти непроверены. Основной показатель — внутри issue доля правильно предсказанных информативных строк всех подходящих просмотров, затем арифметическое среднее по issue. Основные описательные парные контрасты T−F и T−K. Тот же знаменатель для доли ошибок. Покажем T*−H и T−C, сырые счётчики, охват, размеры памяти, распределение длины цепочки и число разнородных задач с выигрышем/проигрышем. 95%-интервал — процентильный парный bootstrap 10 000 целых задач, seed 370541. При числе задач меньше пяти интервалы не интерпретируем, при одной задаче не вычисляем. При полном совпадении всех задач эмпирический вырожденный интервал не оценивает риск в новой популяции. Дополнительные траектории тех же задач не являются независимой репликацией. Проверяем условное сохранение наблюдаемых фактов; экономия обращений, решаемость задач и SOTA не оцениваются.

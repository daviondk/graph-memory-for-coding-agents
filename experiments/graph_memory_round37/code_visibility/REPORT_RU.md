# Какие строки кодовый агент может сохранить после правки файла

На 102 эпизодах из реальных траекторий Handoff Debt перенос номеров строк по подтверждённой правке увеличил покрытие следующего просмотра файла с **30,70% до 39,25%**. Парная разность по 22 задачам составляет **+8,55 п.п.**, 95% ДИ **[+1,14; +18,35]**. Выигрыш сохранился, когда обеим политикам разрешили удержать одинаковое число фактов. Проверялись наблюдаемые строки Python-файлов и их содержимое. Выполнение задач агентом в этом опыте не измерялось. [Протокол](PROTOCOL_RU.md) · [Метрики](results.json)

## Как возникала проверяемая задача

В Handoff Debt зарегистрированы вызовы инструментов кодовых агентов, явные просмотры, результаты изменений и следующие действия. Мы взяли тот же ранее зафиксированный набор задач из научных Python-репозиториев, что в исследованиях R31/R32. Там определяли, какие строки передаются новому агенту. Здесь проверяем, можно ли внутри одного рабочего запуска сохранить адрес старого наблюдения после настоящего изменения файла. Код, команды и патчи корпуса обрабатывались статически. [Первоисточник, EMNLP](https://aclanthology.org/2026.emnlp-main.738/) · [Закреплённая ревизия данных](https://huggingface.co/datasets/kc-academy/handoff-debt/tree/79244eedc9d58349da0fcf1a2e05916e0ac5af00) · [Предыдущая задача переноса R32](../../graph_memory_round32/handoff_ranges/REPORT_RU.md)

Единица наблюдения — два последовательных успешных явных просмотра одного рабочего файла в одном запуске. Между ними должна быть одна успешная операция редактора str_replace; идентификаторы действия, вызова инструмента, ответа и путь сверяются. Первый просмотр даёт память агента, квитанция правки — доступную информацию о новом состоянии. Следующий просмотр только оценивает прогноз. В обоих просмотрах должны быть пронумерованные информативные строки согласно ранее установленному фильтру. Код оценивает SHA-256 текста на конкретном номере строки и не получает ни целевой патч, ни разметку правильного решения.

В основной части 111 запусков исходных агентов и 1032 основных запуска преемников на 37 задачах. Из 5934 просмотров получилось 4148 последовательных пар одного пути; 579 содержали успешную запись; 372 — ровно одну успешную замену; 368 сохранили информативные строки и связанную пару действие/ответ. После исключения дополнительных попыток записи остались 102 эпизода без промежуточного терминального или иного непрозрачного события и 241 с таким событием. Строгие 102 эпизода происходят из 37 запусков, 22 задач и пяти репозиториев. Прочие просмотры остаются вне этого условного знаменателя.

## Что можно предсказать до следующего чтения

Прошлое наблюдение хранит до 128 троек «путь, номер строки, хеш текста». При успешной замене известны старый и новый фрагменты из действия. Возвращённая редактором видимая пронумерованная квитанция показывает кусок обновлённого файла. Ищем единственное буквальное вхождение нового фрагмента в этом непрерывном участке. Если оно начинается на строке k, старый затронутый диапазон — от k до k плюс число переводов строк в старом фрагменте, включительно. Прежние строки выше диапазона сохраняют свои номера; нижние сдвигаются на разность числа переводов строк в новом и старом фрагментах. Строки внутри диапазона забываются, даже если изменился только один символ. При отсутствии однозначного якоря сохраняется одна квитанция.

Это правило следует из разбиения текста файла на неизменные префикс и суффикс вокруг единственного интервала замены. Его предпосылки — верная исходная строка, правильная локализация правки и отсутствие иной мутации между состояниями. Служебные полные снимки до и после правки обрабатывались отдельной диагностической ветвью. Её результаты сопоставлены с прогнозами при подсчёте метрик. В основной строгой части все 102 видимых якоря совпали с позицией уникальной подтверждённой замены. Во всех четырёх группах 1274 из 1282 эпизодов имели видимый якорь; в каждом из 1274 служебные данные подтвердили позицию. Полные снимки не нужны алгоритму. [Код прогноза](predict.py) · [Код проекции и проверки источника](project.py)

Все политики сначала сохраняют подтверждённые строки квитанции. Суммарная ёмкость каждой памяти ограничена 128 фактами. **Сброс** удаляет предыдущее чтение этого файла. **Старые номера** сохраняют оставшиеся факты по их прежним адресам. **Перенос** использует описанное смещение. Для сравнения строго одинаковых размеров **H** сохраняет старые номера в порядке фиксированного хеша; **T\*** удерживает ровно столько же адресов с учётом смещения. Дополнительный контроль U знает затронутый диапазон и отбрасывает соответствующие строки, оставляя остальные на старых номерах.

## Основная проверка

В следующих просмотрах фактически наблюдались **922 информативные строки**. Покрытие равно доле строк с подтверждённой парой «номер, хеш». Для основного показателя сначала объединяем строки внутри задачи и затем усредняем 22 задачи с одинаковым весом. Адреса памяти за пределами следующего просмотренного диапазона остаются непроверенными. Поштучные числители ниже имеют другой вес задач, поэтому простое деление числа подтверждённых строк на 922 даёт другую оценку.

|---|---:|---:|---:|---:|---:|
| Сброс + квитанция | 115 | 0 | 19,77% | 0% | 8,05 |
| Старые номера + квитанция | 187 | 7 | 30,70% | 2,95% | 13,25 |

Интервалы рассчитаны по 10 000 парным перевыборкам задач. Против сброса прибавка составила **+19,48 п.п. [8,21; 31,81]**, против сохранения старых номеров **+8,55 [1,14; 18,35]**, при строго равном числе фактов **+7,97 [1,10; 17,19]**. Для доли ошибочных прогнозов относительно старых номеров изменение −2,95 п.п. [−7,10; 0,00]. На 31 эпизоде с изменением числа строк перенос дал 147 верных фактов против 118 у старых номеров. В эпизодах с неизменным числом строк общий прирост числа верных фактов равен нулю. [Поштучные исходы](outcomes.json.gz)

Рост покрытия относительно старых адресов возник у **5 из 22 задач**, у остальных 17 исход тот же. На SymPy приходится 75 из 102 эпизодов и 5 из 22 задач. При поочерёдном исключении одного из пяти репозиториев средняя по задачам разность остаётся от +5,42 до +10,53 п.п. Небольшое число задач с ненулевой разностью существенно ограничивает обобщение.

В полном снимке непосредственно **до** подтверждённой правки исходный хеш уже отличался от последнего прочитанного агентом, а фактическое следующее чтение совпало с полным снимком после правки. Ошибки находятся на строках выше этой замены, так что смещение у них нулевое. Причину расхождения между предыдущим чтением и снимком из наблюдаемых действий установить нельзя. В основной группе с непрозрачными действиями три ошибочных адреса одного эпизода показывают ту же картину. Дополнительные группы повторно используют исходные задачи. **Граница вывода.** Видимой квитанции реального редактора часто хватает, чтобы сохранить адреса старых наблюдений после локальной замены и увеличить количество проверяемых фактов при той же ёмкости. Уже устаревшая исходная строка может пережить эту процедуру. Следующее открытие файла даёт частичную проверку актуальности; результат относится к покрытию полезных строк при наблюдаемом повторном чтении и не устанавливает выигрыш в решаемости задач, экономии времени или сравнении с внешним SOTA.

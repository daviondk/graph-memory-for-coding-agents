# Проверка адресной памяти после реальной правки файла

Первичная задача — предсказать строки следующего фактического пронумерованного просмотра того же рабочего Python-файла в научных задачах Handoff Debt. R31 и R32 предсказывали перенос крайних строк через смену агента, R32 versioned_links изучала версии документов в QA. Здесь наблюдаем единственный успешный str_replace между двумя последовательными успешными явными просмотрами этого пути в том же реальном запуске. Применяем прежний allowlist научных Python-репозиториев и фильтр безопасных issue. Исследуем 111 исходных и 1032 основных запусков с преемником; вторично — отдельно дополнительные прогоны тех же задач. При любом числе случаев публикуем полный поток отбора.

Сначала из предыдущего просмотра запоминаем максимум 128 информативных строк (путь, номер, SHA-256 текста, по правилу отбора R31); при переполнении применяем порядок SHA-256 от пути и номера. Из аргументов подтверждённой операции берём только old_str и new_str. Место операции определяем по единственному буквальному вхождению new_str в непрерывный пронумерованный фрагмент непосредственно видимой квитанции редактора. Пустые и неоднозначные совпадения не задают адреса. Для якоря на строке k старый диапазон, который мог измениться, включительно k … k+число переводов строк в old_str. Выше него прежние строки остаются на старом адресе, ниже смещаются на разность числа переводов строк. Пересекающиеся строки требуют нового наблюдения. Все методы сначала запоминают информативные строки из одной и той же квитанции (они имеют приоритет перед прежними фактами), общий максимум памяти после операции одинаков, 128 строк. Сведения о полном файле при правке (old_content/new_content), закрытый патч задачи, успешность решения и следующий просмотр не используются в прогнозе.

Сравниваем четыре зафиксированных метода. F забывает все старые строки файла и сохраняет строки из квитанции. K сохраняет прежние номера плюс квитанцию независимо от правки. T при доступном якоре отбрасывает старые строки изменяемого диапазона и переносит последующие строки на новые номера; при отсутствии якоря действует как F. H — контроль с точным числом фактов T, выбирающий такой же объём старых строк на старых номерах, по заранее определённому SHA без чтения будущего. Дополнительно U использует ту же область и отбрасывает те же старые строки, что T, но сохраняет старые номера у оставшихся. Время чтения и сетевой бюджет не различаются, внешний диск повторно не запрашиваем.

Подвыборка для основной оценки — основные и исходные прогоны, ровно одна успешная типизированная замена между двумя просмотрами, без промежуточных терминальных вызовов или неизвестных файловых правок того же пути. Последовательность событий и идентичность вызова/квитанции проверяем. Путь будущего чтения известен после обращения. В прогнозе неизвестны его адреса и содержимое. Если нет чистых эпизодов, сохраняем этот результат. Вторично публикуем эпизоды с промежуточным запуском терминала (неизвестное изменение среды), данные по дополнительным прогонам и случаи ненулевого числа добавленных/удалённых строк. Используются только ранее наблюдавшиеся строки. Фактически известной считается только строка, заново увиденная на соответствующем номере следующего просмотра; оценка не объявляет ненаблюдавшиеся адреса ошибочными. Совпадение нескольких одинаковых текстов само по себе не тождественно сохранению источника.

Первичные показатели — доля строк следующего просмотра с правильным номером и SHA-256 и доля неверных прогнозов среди адресов следующего просмотра, обе с равным весом issue. Основные контрасты T−F и T−K; также сообщаем число ошибок, точность среди реально проверяемых прогнозов, размер памяти, охват явными якорями, T−H и T−U. Регистрируем 10 000 парных bootstrap-перевыборок issue с seed 370153. Отдельно публикуем разбивку по репозиториям и чувствительность при исключении по одному репозиторию. Оценка относится к хранению адресных фактов в наблюдённых реальных историях, причинный эффект на решение issue потребовал бы новых прогонов агента. Все файлы исходника и команды остаются данными для статического парсера.

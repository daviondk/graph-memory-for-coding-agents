# Диагностика конкурентов SERBench до подсчёта

Исходные условия и результаты R34/R37 для 214 отложенных состояний Cal500 уже известны. Настоящая вторичная проверка использует те же 214 состояний, 69 репозиториев, те же ID и исходные пулы, без подбора по исходам этой панели. Нативные Complete-MSS@5 и @8 первичные. Отдельно ранжированный префикс из первых восьми целых фрагментов при 2 048 и 6 144 Qwen-токенах, дополнительно при 2 048 E5 WordPiece. Сериализация путь + LF + фрагмент + LF LF и округление как в R34. При переполнении остановка, пропуск неподходящего фрагмента запрещён. Нативный scorer на готовых ID. Состояния и содержимое в сервисы не отправляются.

При проверке доступности просмотрены первичная статья v3, полный публичный GitHub-снимок 8c27a88e48dcbcd4a5745573c95937a4740f4406, каталог reference_results, инструкции воспроизведения, список релизов/веток и арXiv-source. Публичный OpenReview API указывает приложение к 07qozKbnPm, но загрузчик требует интерактивную проверку (HTTP 403 ChallengeRequiredError). Его содержимое не установлено. В GitHub 12 опубликованных основных результатов содержат агрегаты Test500. Прямых поштучных предсказаний MSS-Complement/Qwen3-Reranker на Cal500 в этом снимке не найдено. Starter BM25 уже исполнен в R34. Пример custom_method сортирует по пути и строке и не является сильным читателем. Зафиксируем машинную проверку форматов.

Новые локальные контроли:

1. MMR реализует описанный авторами принцип компромисса релевантности/разнообразия на замороженных BGE-векторах. Полный пул, косинус запроса по состоянию как релевантность, максимальный косинус к уже выбранным фрагментам как штраф за избыточность; первый выбор = BGE top-1. Обе величины в нативной шкале косинуса. Сетка λ ∈ {0,25; 0,50; 0,75; 1,0}. Максимизация Complete-MSS@5 на имеющемся dev из 101 состояния, при равенстве выбираем большее λ. Официальная комбинация статьи использует исходный Qwen3 и опубликованный λ=1,0. Наш контроль вводит тот же тип агрегирования с доступным читателем и собственной калибровкой.
2. Публичный cross-encoder/ms-marco-MiniLM-L6-v2, ревизия 233902d25c440f23af6f7d6e94d2946bac0bee0a, экспорт ONNX quint8 AVX2 на CPU. Замороженные первые 32 кандидата BGE переупорядочиваются по скалярному выходу модели с разрешением равенства в исходном порядке BGE. Запрос — information_need, current_subgoal, issue в этой последовательности через LF. Документ — путь и исходный текст через LF. Парный BERT-токенизатор, max_length=256, longest_first, стандартные специальные токены. Никаких меток, дообучения, калибровки или подбора веса. Меняются также вычислительный бюджет и тип модели относительно Qwen-8B из статьи; это публичный встречный контроль с иной моделью, а не реплика авторского результата.

Публикуем сравнения каждого контроля с dense_state и union_cost по обоим первичным показателям и указанным бюджетам. Парный репозиторный bootstrap, 20 000 выборок, seed 370624; выигрыши и потери по состояниям. Перепроверяем зарегистрированные исходы R34, полноту выдач, хеши данных и принадлежность контрольных кандидатов. Числа на разных разбиениях не используем как оценку превосходства над авторами. Если матрица зависимости не установится, сохраняем реально полученный контроль и регистрируем точный технический блокер.

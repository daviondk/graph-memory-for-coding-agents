# Диапазонное чтение после подтверждённой правки

Фиксируем 1 282 уже опубликованных перехода Handoff Debt, базу SQLite и ёмкость 128 записей из R37/code_store. Когда клиент просит диапазон текущих номеров [l,r], полный ленивый читатель переносит всю старую память и отбрасывает строки вне диапазона. Гипотеза: проекция диапазона назад на неизменившиеся участки уменьшит объём извлечённых строк при точном совпадении ответа. Сильный контроль — поиск диапазона по готовому составному первичному ключу (эпизод, актуальный номер строки) после материализации. Ещё один контроль — прочесть всю готовую таблицу и отфильтровать в клиенте.

Первичная метрика — число фактически возвращённых SQLite строк при чтении, включая метаданные. Дополнительные — размер результата и время на тёплом локальном SQLite-соединении для одного запроса. Отдельно покажем сравнение со строго индексированным контролем и расходы на метаданные. Окно клиента — от первой до последней пронумерованной строки следующего видимого просмотра. Это ретроспективная нагрузка по фактически прочитанному диапазону, который известен только при обращении. Ни одна граница и ни один ответ из следующего просмотра не доступны при построении хранилища. Интересуют все сохранённые строки внутри окна, включая внутренние пропуски видимого вывода. Содержимое будущих строк при проверке эквивалентности не используется.

На записи учитываем консервативную верхнюю границу числа возможных фактов — число прошлых сохранённых строк плюс число строк в ответе редактора. Если она выше ёмкости и старые адреса могут быть перенесены, необходим глобальный выбор по приоритету. Тогда оператор возвращается к полному просмотру с теми же правилами выбора. Иначе допускается проекция. Дефолтные параметры фиксированы. Перед проверкой эталонных ответов записываем физические результаты по всем трём схемам и всех запросов. Время оцениваем на 128 переходах, заранее выбранных фиксированным хешем в code_store. Проведём все 24 перестановки порядка четырёх способов чтения, одинаковые запросы, повторимые блоки. Контрасты времени агрегируем по переходам с парной перевыборкой задач (10 000); доверительные интервалы условны относительно одной машины. Сборка индексов и время записи вне измерения чтения. Заявление о выигрыше времени возможно только по измеренному контрасту и указанному базовому методу.

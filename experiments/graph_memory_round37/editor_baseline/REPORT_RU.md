# Сравнение переноса адресов с CodeMirror

На всех **1 282 из 1 282** переходов в историях работы с кодом опубликованный оператор CodeMirror вернул точно те же пары «номер строки, хеш содержимого», что и наш перенос по подтверждённой правке. Сравнение включает **28 391** сохранённую пару по эпизодам, в том числе строки, которые следующий видимый запрос не читал. Значит, выигрыш **+8,55 п.п.** относительно сохранения прежних номеров воспроизводится стандартной библиотекой при той же политике памяти. Разность качества по отношению к CodeMirror в данной постановке **0,00 п.п.** [Прогнозы](predictions.json.gz) · [Проверка по эпизодам](results.json)

Использовали `ChangeSet.of` и `mapPos` из фактического пакета `@codemirror/state` 6.7.6. Одна позиция виртуального документа обозначает одну строку. Частично перезаписанная строка целиком теряет статус прежнего свидетельства. Адреса внутри заменённого интервала отбрасывает режим `TrackAfter`. Остальные адреса проходят через библиотечное отображение. В обоих подходах одинаковы границы правки, выбор наблюдаемых строк и приоритет строк из ответа инструмента. Для установления размера виртуального пространства достаточно наибольшей наблюдавшейся строки и конца замены. Полный файл читать не требуется. [Интерфейс редактора](https://codemirror.net/docs/ref/#state.ChangeDesc.mapPos) · [Исполняемый код](baseline.mjs)

Знаменатель покрытия — число строк следующего видимого чтения. Сначала суммируем числитель и знаменатель внутри задачи, затем усредняем получившиеся доли с одинаковым весом для каждой задачи. В основной строгой группе альтернативный контроль удаляет затронутый интервал и оставляет старые номера остальных строк. Он даёт те же **30,70%** и те же **7 ошибок**, что и более простой контроль сохранения номеров. При таком наборе правок разницу объясняет перемещение уцелевших адресов. Неизмеренной остаётся полезность этих строк для решения исходной задачи агентом. [Политики хранения и исходные измерения](../code_visibility/REPORT_RU.md)

С математической стороны движутся только адреса суффикса: после замены ширины o на n его смещение равно n−o. CodeMirror применяет эту геометрию в координатах документа. В литературе по сопровождению кода решается и более трудная задача восстановления соответствия строк между двумя известными версиями при произвольных перемещениях и переписывании. Наш сценарий предполагает один локализованный интервал и частично наблюдаемый файл. Обоснованный предмет заявки — какие свидетельства может удержать память по ответам инструментов, как передать или перепроверить их после правок и сколько стоит обслуживание. Библиотечный результат снимает претензию на новизну самой формулы смещения. [LHDiff, первичная публикация](https://www.cs.usask.ca/~croy/papers/2013/LHDiffFullPaper-preprint.pdf) · [Протокол эксперимента](PROTOCOL_RU.md)

Для воспроизведения достаточно Node, Python и соседней подписанной папки `code_visibility`. Установите зависимости из приложенного lock-файла командой `npm ci --ignore-scripts` в каталоге эксперимента. Затем выполните `node baseline.mjs` и `python check.py`. В исследовательской среде зависимости хранятся отдельно на D. Скрипт фиксирует версию, хеш выполняемого файла библиотеки, исходную проекцию и хеш всех прогнозов.

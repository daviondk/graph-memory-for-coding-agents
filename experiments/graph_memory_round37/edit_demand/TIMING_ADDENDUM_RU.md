До любого нового измерения времени фиксируем дополнительный контроль выбора нагрузки: на тех же 128 полностью прослеженных окнах сравним фактическую кратность R со сценарием «один полный запрос памяти на каждую правку». Для каждого сценария — отдельные заранее подготовленные файлы SQLite, та же замороженная схема и та же панель, порядок сценариев чередуется между блоками. Это вторичное сравнение изолирует изменение числа запросов внутри одной панели и не делает её несмещённым представителем цензурированных правок. Для окон с R=0 в основном тайминге оператор не открывает память после записи. Состояния нулевых окон независимо сверяются после завершения разогрева, вне замеров.

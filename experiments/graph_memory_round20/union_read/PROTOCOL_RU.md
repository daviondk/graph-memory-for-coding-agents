# Однократное чтение совпадающих исходных диапазонов

Закрепляем до вычисления новых тестовых прогнозов. Две панели на общем официальном test ISETrace из 2 000 запросов и 1 207 траекторий. Первая использует замороженные ранги R19 PU Dense-FT, один seed. Вторая применяет те же правила к R20 residual R-GCN, как только будет запечатан его полный тестовый порядок. Новый упаковщик не получает эталон, train и dev для подбора правил не используются. Исходные результаты для Dense-FT на test уже доступны.

Бюджет 2 048 WordPiece E5. Сначала воспроизводим выбранные целые PU обычного skip, включая все их символы. Контроль raw skip использует нативную цену исходной единицы. В новом варианте все пересекающиеся и соприкасающиеся интервалы этих PU объединяются только внутри одинаковой пары (event_id, json_pointer). Цитируем исходные строковые срезы буквально, без пропусков внутри диапазонов, сохраняем их координаты в отдельном канале. Порядок вывода — первое появление источника среди отобранных элементов, затем исходные позиции в поле. Между отдельными срезами в тексте один перевод строки. Проверяем действительную токенизацию всей выданной строки без спецтокенов и без усечения. Индексы к исходникам, системный промпт и разметка упаковки не входят в этот экспериментальный бюджет. При переполнении объединённого представления возвращаем исходные раздельные PU; измеряем такую тарификацию отдельно. Если буквальный текст раздельных PU также не помещается, помечаем случай как неосуществимый для строго текстового режима, сохраняем нативный skip и сообщаем об этом явно.

Три последовательных варианта сохраняют все исходные координаты: только объединение (U), объединение с добором целых PU (W), затем фиксированный дробный добор (F). Для W просматриваем все PU в том же порядке ранжировщика. Если кандидат добавляет символы и новая суммарная цена распакованного текста не превышает 2 048, добавляем его целиком, в том числе только недостающую часть пересекающегося источника. Для F последовательно рассматриваем ранги ещё раз. В каждом первом пригодном родителе рассматриваем только ранее не прочитанные непрерывные диапазоны. Строим окна из максимум min(64, остаток бюджета) нативных WordPiece, шаг в половину ширины и последнее окно с привязкой к концу. Выбираем одно окно на родителя по числу различных содержательных терминов запроса, присутствующих в окне. Ничья разрешается по более раннему началу среза. Повторно проверяем фактическую цену объединения и принимаем первое подходящее в таком порядке. При отсутствии лексических совпадений тот же порядок даёт наиболее раннее окно. Остановка при полном бюджете. Никаких запросов к LLM.

Первичный контраст F − обычный skip по Full Support@2048. Вторичные — W−skip, F−W, Coverage, Density, токены, новые символы и частота изменения набора источников. Поштучно проверяем включение исходных символов skip ⊆ U ⊆ W ⊆ F на обеих панелях. Раздельно указываем число вопросов с исходным перекрытием и с новым свидетельством, статистику размера освобождённого бюджета, случаи переполнения после повторной токенизации и реальные расходы CPU. Нативную оценку сверяем с независимой арифметикой объединений и пересечений. Парные процентильные ДИ 95%, 10 000 выборок целых траекторий, seed 20. Все прогнозы каждой модели фиксируются до открытия соответствующей оценки. В отчёте по R-GCN обозначим, что оцениваем новую упаковку опубликованного представления, и приведём калибровку исходного skip отдельно от табличного prefix.

# Как воспроизвести сравнение условного вызова графа

Для проверки готовой панели требуется стандартная библиотека Python и файлы данного каталога. Запустите `python -B verify.py`. Проверяются все 2 000 решений по признакам и весам, точное срабатывание порогов, независимый SHA-контроль с тем же числом обращений, состав разделов и подсчёт результатов.

Для полного прогона нужна среда ISETrace в структуре R18/R19/R20 (NumPy, tokenizers, локальный пакет GraphMemory), test и dev проекции со строками и исходными пунктами, сохранённые ранги обеих моделей. Выполните `python -B -X utf8 gate.py prepare`; признаки требуют лишь Dense-FT и строк вопросов. Этот этап читает gold только из полного dev-файла для оценки плотной модели среди 500 запланированных dev-запросов. Оставшиеся 80 не используются. Идентификаторы траекторий 500 dev и 2 000 test не пересекаются.

После запечатывания исходных рангов каждого графа запустите `run_cpu.ps1 -Panel availability` и `run_cpu.ps1 -Panel hash64`. Скрипт сверяет SHA dev-рангов, запускает fit, сохраняет пороги и коэффициенты, запечатывает все независимые test решения и только затем разрешает чтение test разметки. Ранги residual для вычисления test-признаков или срабатывания gate не требуются. Политика margin использует отрицательную разность score первых двух плотных кандидатов. Среди равных значений применяются заранее зафиксированные SHA-256 по идентификатору вопроса. При доле ровно 50% на dev выбирается ровно 250 вопросов.

Для иной отдельно запечатанной графовой панели доступны CLI `gate.py fit <dev_пути> <sha256> <тег>`, `gate.py predict <тег>`, `evaluate.py <тег> <каталог_рангов> <шаблон_файлов> <манифест_рангов>`. Эталонные символы первых 500 dev и полного test оцениваются нативным span_metrics_under_token_budget. Проверяется тождество всех candidate ID, координат и цен пула между Dense-FT и графом, все политики используют один и тот же skip и 2 048 токенов. Процедура обучения предиктора совпадает для каждого графового чекпойнта.

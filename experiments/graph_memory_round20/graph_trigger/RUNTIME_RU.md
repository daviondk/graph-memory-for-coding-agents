# Время графовой стадии на сохранённых признаках

Дополнительная проверка зарегистрирована после метрик availability и до прогнозов hash64. Из 2 000 test выбираются 96 первых ID по SHA-256 от строки «R20 gate runtime v1|» и ID запроса. Входы для всех 96 восстанавливаются по нативным тензорам и сохранённым векторам. CPU, FP32, один поток PyTorch, batch=1, без градиентов. Одинаковый порядок запросов. Сначала один непротоколируемый прогрев для всех 96 графов. После прогрева четыре парных повторения в порядке AB/BA/BA/AB. A включает упаковку тензоров запроса и реальный forward для каждого графа. B на каждом запросе заново вычисляет скалярный Ridge score по 13 уже рассчитанным признакам, сверяет индивидуальное решение с запечатанным и запускает ту же графовую операцию для выбранных. При сравнении общий код не подсчитывает метрики и не открывает test gold. Контрольная сумма выходов и число вызовов сравниваются с прогревом. Полные ранги сравниваются со штатным пакетным FP32 расчётом, максимум абсолютного расхождения сообщается отдельно.

Показываем времена четырёх повторений и их парные отношения. Выбор 96 вопросов фиксирован до первого измерения. Офлайн-прогрев и восстановление тензоров имеют отдельную цену. Время первой плотной модели, вычисления 13 признаков из сырых рангов, сортировки результатов и генерации ответа в измеряемый интервал не входят. Проверка характеризует только остаточную графовую стадию конкретной конфигурации.

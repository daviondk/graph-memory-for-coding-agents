# Дословное пересечение источников калибровки и теста

Дополнительная проверка была спроектирована после первоначального графового обучения availability и до получения любого прогноза hash64. Выполнение начинается после запечатывания решений обеих политик. Используем прежнюю процедуру R19 сопоставления полных исходных полей по SHA-256 в данных генерации вопросов. Для каждого test-запроса определяем, совпадает ли хотя бы одно его поле с эталонным свидетельством с любым полем хотя бы одного из 500 dev-запросов, на которых подбирался маршрутизатор. Отдельно исключаем такие совпадения с 3 894 train плотной модели по готовым флагам R19. Обучение сокращённых графовых сетей использует подмножества того же train; для выбора их чекпойнта использовалась dev-выборка.

Показываем Ridge50 против постоянного графа на двух подвыборках, отдельно очищенных по dev и по объединению train с dev, при тех же решениях и неизменных критериях. Различные перефразировки и частичные текстовые пересечения этот фильтр не выявляет. Все основные оценки на полных 2 000 вопросах сохраняются. Индекс по источникам dev строится только для аудита. Он не используется при вычислении признаков, обучении или предсказании.

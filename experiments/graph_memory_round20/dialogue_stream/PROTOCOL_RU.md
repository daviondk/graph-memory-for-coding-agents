# Каузальная запись реплик с фиксированным бюджетом

Проверяем перенос наблюдения о роли и длине в потоковый режим на пяти заранее фиксированных folds панели из 62 историй LongMemEval-S, 59 с метками. Ранее на этой панели изучен другой режим, где были известны полная длина истории, все длины реплик и число сохраняемых записей. Здесь при записи не передаём длину будущей истории, будущий вопрос или будущие реплики. Для каждого нового завершённого сообщения вычисляем I(user), процентиль числа слов по только предшествующим сообщениям той же роли (32 фиксированные корзины floor(4·log2(1+n)), мягкое начальное значение по 0,5 на ячейку) и их произведение. После обработки обновляем счётчик. Бюджет на всём протяжении истории абсолютный: 4096 WordPiece на тексты целых реплик, с абляцией 2048/8192. Единица длиннее всего бюджета пропускается. При переполнении вытесняем худшую живую реплику, отвергнутые записи недоступны для восстановления. В метрику не входят модель и метаданные; учёт гистограммы и числа ссылок приводим отдельно. Размеченная реплика, попавшая в архив полностью, считается найденной.

Первичный контраст при 4096: каузальная версия TF–IDF-классификатора LRE с ролью и потоковым процентилем минус та же модель без трёх признаков. Одинаковые TF–IDF и четыре исходных структурных признака, вместо двух функций от будущей длины берём log1p(число предыдущих реплик) и 1/(1+это число). Дополнительно: простая модель на трёх признаках, её либо полная модель с делением скора на цену, FIFO, короткие сначала, короткие пользовательские сначала. Одинаковые source-disjoint folds, одинаковое удаление нормализованных дублей с тестом, balanced logistic C=1. Одно первичное сравнение macro Recall точных has_answer реплик. Отмечаем также полное сохранение всех нужных реплик, цену и парные 95% percentile bootstrap по размеченным историям. Мы знаем предыдущие агрегаты этой панели, вывод разведочный. Цель — реализуемая запись с фиксированной ёмкостью.

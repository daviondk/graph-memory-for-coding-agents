# Протокол переноса оценки реплик на LongMemEval-S

Первичная гипотеза — добавление семи признаков предыдущей реплики из R19 к LRE, обученной на LoCoMo, увеличивает macro Recall@20% на другом корпусе, без разметки целевого корпуса при обучении. Единица отбора — реплика в полной доступной истории вопроса. Это оценка после получения истории и до раскрытия вопроса. Положение и относительная давность используют длину доступного окна. Отдельная проверяемая альтернатива — признаки дают пользу только после обучения в домене.

## Замороженные данные и процедуры

* Исходное обучение — все десять диалогов LoCoMo, родные объединённые метки LRE, полный оригинальный LongMemEval-S из 500 историй как внешний тест. Канонизация текста использует Unicode NFKC, casefold и схлопывание пробелов. Реплики LoCoMo с текстом, совпадающим с любым текстом внешнего корпуса после нормализации, удаляем перед обучением. Считаем общеупотребительные совпадающие реплики и совпадающие полные сессии. Путь или ID вопроса и тема не входят в признаки.
* Три ветви с одинаковыми текстами и гиперпараметрами. Исходная LRE (10 000 TF–IDF, 6 авторских числовых признаков, StandardScaler, сбалансированная логистическая регрессия, seed 0), LRE с 7 настоящими признаками R19, и такой же классификатор со сдвигом предыдущей реплики на полдлины внутри сессии по формуле R19. Последний контроль может видеть более позднюю реплику. Рёбра не пересекают границы сессий. Обучение и тест используют соответствующее представление. Приоритет порядка реплик — порядок опубликованных массивов. Отбор не использует текст будущего вопроса или ответа.
* Масштаб — все поставленные истории, отдельно жадная панель с непересекающимися исходными сессиями. Для неё идём по SHA256 исходного идентификатора вопроса по возрастанию и принимаем историю, только если ни один ID сессии и ни один хеш нормализованного полного диалога не пересекается с предыдущими принятыми. Отбор вслепую к меткам и результатам. Роли сохраняем в хеше сессии. Группируем полную панель в компоненты по повтору сессии, чтобы увидеть реальную зависимость. Для ноль-положительных историй публикуем количество, а Recall вычисляем там, где определён, AUC — при наличии обоих классов.
* Дополнительное внутридоменное сравнение — берём каждую уникальную сессию с положительными и отрицательными репликами, объединяя бинарные turn-метки по одинаковому нормализованному диалогу. Это условная задача выбора реплики внутри уже известной доказательной сессии. Сессии, совместно помеченные в исходном задании, и алиасы исходного ID объединяем в компоненту. Используем авторскую GroupKFold с пятью блоками по компонентам (если меньше пяти, используем число доступных; при единственной компоненте публикуем причину невозможности). Совпадающие тексты обучающих реплик удаляются штатным dedup по test fold. Все три ветви получают одни и те же folds. Оценка и макроусреднение по сессиям. Это отдельно обученные модели.
* Основная метрика — macro Recall при сохранении ceil(0.20·N) реплик; вторичные — macro ROC AUC и Recall при 10%, 40%. Сравнения real−original и real−shifted, W/L/T по единицам. Внешние 500 описательно с учётом компонентов; на источнико-раздельной панели бутстреп историй, во внутридоменном опыте бутстреп целых компонент, фиксированный seed 13 и 10 000 выборок, 95% процентильный интервал. При одной единице независимости интервал не оцениваем. Основной вывод о переносе требует положительного эффекта на полной панели и положительной нижней границы на раздельной панели. Малый объём независимой панели ограничивает силу вывода. Исходные тексты остаются вне пакета. Экспортируем хеши, координаты, метки, оценки и проверяемые групповые метрики.

Официальная работа LRE определяет отдельную задачу LongMemEval по сессиям. Числа этой серии характеризуют реплики; прямое сопоставление с опубликованной таблицей по сессиям некорректно. Если вход или схема расходится с описанием, останавливаемся для фиксации отклонения.

# Какие связи считает читатель

**Локальная структура.** Native next_chunk соединяет соседние чанки внутри поля. Вторая группа проецирует принадлежность к вызову. Каждый чанк аргумента связан с чанками соответствующего результата. Эти два признака частично кодируют размер полей и роль узла.

**Связи между действиями.** Для data.feeds в исходном построителе типизированное значение должно встретиться в выводе ровно одного производителя и затем присутствовать в аргументе более позднего вызова. Направленный выход–вызов объединяется с возвратом второго вызова и проецируется на чанки выходов обеих сторон. Resource flow соединяет результаты, когда более ранний вызов последним записал артефакт, который затем прочитал другой вызов. Это операционные определения, восстановленные из наблюдаемой трассы. Одной переиспользованной строке может соответствовать много рёбер между чанками. Поэтому степень содержит информацию о размере соседнего поля. Семантическая причинность и необходимость каждого ребра для ответа отдельно не размечены. [Построитель data.feeds](https://github.com/xiaoqi-7/GraphMemory/blob/df29287116fa1565b3fd6b485022cd6090dc0b27/graph_memory/graphs/provenance/builder.py) · [Проекция зависимостей](https://github.com/xiaoqi-7/GraphMemory/blob/df29287116fa1565b3fd6b485022cd6090dc0b27/graph_memory/graphs/provenance/dependencies.py)

**Связь с авторской абляцией.** Авторы ISETrace сравнивают пять seed GNN с удалением семейств рёбер и случайной перестановкой концов при сохранённых степенях. После удаления feeds или структуры владения best-dev отбирал начальную плотную модель. В их постановке нейросетевая передача сообщений требовала конкретных связей. Мы проверяем другой механизм. Линейное статистическое правило получает только восемь счётчиков и исходный ранг. Полезность feeds для GNN уже известна. Новое проверяемое утверждение касается того, какую часть сигнала дают одни счётчики и сохраняется ли прибавка на дополнительных вопросах. Для сравнения с авторскими пятью seed необходимы соответствующие плотные базовые модели для каждого seed и сопоставимый разброс. [ISETrace, §7 и таблица 3](https://arxiv.org/html/2609.25913v3#S7)

## Воспроизведение

Из корня round20 в окружении ISETrace запускаются команды:

```powershell
python -B factor_reader/channel_controls/channels.py fit
python -B factor_reader/channel_controls/channels.py predict test
python -B factor_reader/channel_controls/channels.py predict extra80
python -B factor_reader/channel_controls/channels.py score test
python -B factor_reader/channel_controls/channels.py score extra80
python -B factor_reader/channel_controls/channels.py report
```

Для первичной проверки нужны замороженные hash64-веса калибровки ранга. Обучающие чанки и тексты остаются в исходном локальном кеше. Для воспроизведения выдачи и нативных метрик нужны родительские плотные ранги, графы и входная разметка замороженной версии ISETrace. В этой папке сохранены решения по каждому вопросу, их исходы и хеши входов. [Первичная пара и дизайн](PROTOCOL_RU.md) · [Результаты](REPORT_RU.md)

# Повторные команды pytest в опубликованных траекториях кодового агента

Вторичная внешняя проверка после контролируемой панели QuixBugs. Результаты этой новой выборки неизвестны. Используем VibeMemBench, репозитории mpmath, PyBaMM, harmonica, arch, pyqtgraph, xgcm, pydatastructs и brutils-python. Берём полные публичные журналы mini-SWE-agent; содержание остаётся в исходном наборе. Созданные агентом команды не выполняются. Включаем безопасные задачи научного и прикладного Python, после фильтра по тематике. Исключаем issue, уже попавшие в 35 пар R17/receipt_invalidation. Отбираем пары последовательных идентичных канонических команд одного и того же файла тестов (ночные перезапуски и изменения рабочего дерева возможны). Нужны одна команда pytest и ровно один файловый селектор, без фильтра -k, нескольких целей и pipe. Сохраняем идентичность полного командного текста внутри пары, бюджет чтения и записи не участвует в отборе. У каждого issue выбираем одну пару по SHA-256, затем не более 12 от каждого репозитория и 64 всего по SHA-256 без результатов запусков. При отсутствии пар публикуем нулевую выборку.

Непосредственно перед повтором из истории разрешены ответы прошлых типичных команд чтения и тестов. Остальные шаги остаются пропусками. Вопрос называет тестовый файл и просит выбрать один точный ранее падавший тест, который снова упадёт, или воздержаться. Будущие исправления, коды возврата второго процесса, выход второго процесса и следующий ход ему недоступны. Универсальная память использует исходные функции R19, инструмент exec, бюджеты 8 192/2 048, фиксированный BM25 и одинаковый парсер строк FAILED. Контроли — output_head, FIFO, позиционная модель, полный BM25, а также один nodeid из последнего доступного вывода pytest для целевого файла. Данные для отложенной классификации отделяем во время подготовки, публикуются их хеши. Отдельно указываем повторные действия при неизвестной идентичности исходного состояния репозитория.

Опорный результат взят только из реально выполнившейся архивной команды: подтверждённая финальная строка об успехе и нулевой exit code либо подтверждённые терминальные FAILED nodeid в нужном файле и ненулевой код. Неполные terminal summaries, ERROR при сборке, отсечение вывода и отсутствие rc дают неизвестный исход. Успех — верное воздержание при подтверждённом успешном повторе или совпадение выбранного теста с одним из реально зарегистрированных падений. Считаем каждый эпизод, отдельно — число определённых исходов, положительных и отрицательных, число с превышением бюджета, число разных репозиториев, размер фактического индекса. Для малого числа репозиториев показываем описательные счётчики и парные разногласия. Архив подтверждает вывод инструмента, но не предоставляет полноценный независимый локальный повтор в точном рабочем состоянии.

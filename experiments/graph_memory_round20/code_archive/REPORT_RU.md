# Одинаковые повторы pytest в реальных журналах VibeMemBench

В восьми заранее указанных Python-проектах найдено **4 пригодных независимых issue из 144 журналов**. Все четыре последующих запуска файла тестов завершились успешно. У всех шести способов памяти получены одинаковые 3/4 верных решений. Выборка позволяет выявить один случай устаревания записи и оценить доступность этого типа проверяемых переходов в архиве. Чувствительность к повторному падению здесь оценить нельзя. [Критерии до чтения исходов](PROTOCOL_RU.md) · [Публичный VibeMemBench](https://huggingface.co/datasets/Tongyi-ConvAI/VibeMemBench)

Пять журналов исключены из-за пересечения с прежней R17, один — по тематике задания. В оставшихся 138 журналах встречались 38 подходящих команд, пять переходов между идентичными командами и четыре различных issue. По SHA-256 для каждого issue выбрана одна пара. Ни отбор, ни число повторов не зависят от выводов второй команды. Контекст формировался только из предыдущих наблюдений, а во время записи конкретный вопрос оставался недоступен. Зарегистрированы хеши источников и принятых решений. [Скрининг и состав](design-lock.json) · [Ответы до проверки](forecast.json)

Лимит записи 8 192 был активен в двух случаях, лимит чтения составлял 2 048. Сравнивались неизменная логистическая модель ISETrace, output_head, FIFO, позиционная абляция, полный BM25 и точный идентификатор последнего упавшего теста. Отдельная диагностическая проверка не запускает команды из архива. Она сопоставляет предложенный ID с фактически зафиксированным более поздним результатом pytest. У трёх пар доступна предшествующая квитанция нужного файла в поддерживаемом формате. Между двумя командами каждой пары обнаружены признаки изменения кода и шаги, содержание которых не подавалось в память. В PyBaMM прошлое падение действительно было в доступном выводе; его сохранение само по себе не предсказывает исход после последующей работы. Четыре случая в четырёх проектах не дают основания оценивать превосходство моделей или выделять причинный эффект правки. [Поштучная разметка](outcomes.json) · [Агрегаты](results.json)

# Чтение блоков внутри графовых узлов

Как расходовать 2 048 токенов, когда ранжировщик нашёл правильную область, но один узел содержит до 504 токенов? Весь опыт остаётся доступным. Завершённые события разбиваются на неперекрывающиеся блоки примерно по 64 WordPiece. Обучаем на 500 dev-вопросах скор пересечения мелкого блока с эталоном. В запросе доступны текущий текст, ранги родителя и BM25, геометрия и противоположная сторона вызова. Для p/c два самых высокоранговых узла защищены, далее используются новые координаты без перекрытия с ними. Публичный test уже применялся в предшествующих сериях. Обучение читателя использует разметку dev дополнительно к обучению самого Dense-FT. Ниже приведены восемь правил, первичная пара фиксирована заранее.

## Стоимость чтения

На фиксированной по хешу выборке из 128 траекторий при уже вычисленных рангах Dense-FT медиана выбора целых узлов — 0,0043 мс на вопрос, мелких блоков — 1,314 мс. Однократная подготовка геометрии фрагментов и BM25 заняла 5,32 мс на траекторию. Это CPU-измерение после получения рангов с пятью повторениями. Загрузка диска и нейросетевое кодирование предшествуют таймеру. [Квантили и условия](runtime-summary.json)

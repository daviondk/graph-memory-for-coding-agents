# Восстановление после отключения видеокарты

При исходном полном расчёте Windows потеряла RTX 3090. В системном журнале Display event 4101, новый процесс PyTorch видел ноль устройств, Windows PnP показал CM_PROB_PHANTOM. Попытка обнаружить устройство через pnputil /scan-devices вернула отказ в доступе. Резервных вычислений с пониженной точностью в научном сравнении нет. Проверка SQLite после сбоя вернула «ok». Сохранены 372 088 точных FP32-строк для Dense-FT и 1 914 для исходного E5. Они включают все графовые признаки на 2 000 test и 500 dev, на исходном train на момент сбоя не хватало 93 986 FT-строк. Старый GPU-лог содержит последнее подтверждённое сообщение 196 608 / 43 641 325 непаддированных токенов этой стадии за 890,3 с. [Снимок](gpu-outage.json) · [Доступность целых графов](outage-coverage.json)

Пока устройство отсутствует, cpu_full.py дозаполняет оставшиеся исходные векторы при FP32, проверяя ключ и фиксируя транзакцию каждые 32 строки. Файл RUN/logs/full-cpu.progress.jsonl учитывает фактические входные токены и время каждого блока. Отдельно программа малых панелей выполняет обычное графовое обучение, нативный выбор типов отрицательных и полную проверку на 2 000 test. Две первоначальные группы CPU-панелей закреплены до тестовых результатов [в их протоколе](cpu_fallback/PROTOCOL_RU.md). Полный CPU-encoder резервирует ключи незавершённых малых панелей для их ускорения. После завершения панелей он использует больше CPU-потоков. continue_full_cpu.ps1 запускает дальнейшие стадии полного расчёта на CPU при подтверждённом покрытии всех исходных embeddings.

Если Windows снова обнаружит GPU, из корня серии можно вызвать resume_after_device.ps1. Этот сценарий сначала проверяет умножение матриц на CUDA. Вычислительные ресурсы CPU передаются обратно после успешной проверки. Уже сохранённые W=768 FP32-строки остаются в базе. GPU использует для дополнительных строк batch32 и повторно проверяет SHA точных весов; прежний GPU использовал batch64 и оба режима отключают TF32. Остаточные различия округления по геометрии батчей контролируются отдельно. Скрипт проходит полный авторский miner, fit, запечатывает все ранги, считает метрики и контроль изменённой топологии. При перезагрузке компьютера оперативные процессы прекращаются, SQLite и артефакты на D остаются. Подготовленные отчёты и маленькие checkpoint имеют индивидуальные манифесты.

При повторном запуске CPU сначала проверить отсутствие активного cuda-worker и full-cpu worker. Маркер RUN/yield-cpu-full означает, что полный CPU расчёт уступил место GPU. Для восстановления CPU при этом маркер переносится в отдельный архивный файл перед запуском cpu_full.py и continue_full_cpu.ps1. Не очищать vectors.sqlite3: ключи и точные веса проверяются отдельно. Результаты незавершённого full-train эксперимента и метрики двух малых панелей сохраняют раздельные статусы.


После повторного обнаружения устройства прошла проверка умножения матриц CUDA. В режиме FP32 batch32 RTX 3090 дозаписала 89 646 векторов E5-FT на 45 020 173 токенах за 907,17 с. Независимый SQL-поиск отсутствующих ключей подтвердил все 466 074 исходные строки. Базовый E5 для майнинга обучающих пар ведёт отдельный транзакционный журнал блоков. Измеренные затраты хранятся как нижняя граница, так как у части сохранённых CPU-векторов от исходного запуска отсутствует финальный счётчик токенов. Отдельный наблюдатель контролирует ресурс диска, время и температуру GPU; операционная система и конфигурация видеокарты остаются в ведении пользователя.

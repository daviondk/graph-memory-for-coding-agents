# Совместное извлечение нескольких событий на одном запросе

В работе Zhang и соавторов обнаружена потеря одного из двух уже найденных фактов при передаче результатов специалистами ведущему агенту. На ISETrace доступен другой этап обработки — чтение исходных свидетельств из локальной памяти. Для проверки накопительного эффекта от графового ранжирования измеряем полноту каждого события отдельно и доступность пары событий в одном физически ограниченном контексте. ISETrace не содержит в этой постановке разметки конфликта или передачи между специалистами. [Zhang et al.](https://arxiv.org/abs/2611.22245)

Регистрируем план дополнительного анализа после публикации исходов primary availability и до вычисления новых метрик обеих уменьшенных моделей. Первичный набор определяется разметкой исходного официального теста и включает запросы, для которых эталонные символьные координаты принадлежат как минимум двум различным event_id. Все поля JSON одного события составляют одну группу. Группа считается полностью извлечённой, если после объединения пересекающихся диапазонов покрыт каждый эталонный символ во всех её полях. Знаменатель всегда определяется полным исходным эталоном. Анализ чувствительности отдельно использует ровно два события.

Для запроса с m событиями, из которых k целиком видны в пределах одного контекста, p_i=k/m есть вероятность полного покрытия одного случайного события, j_i=k(k−1)/(m(m−1)) — вероятность покрытия двух различных событий. Средние p и j берутся по запросам с одинаковыми весами, поэтому длинные эталоны не получают квадратичного преимущества. Для ровно двух событий j равен обычному Full Support. Для произвольных m отдельно публикуется вероятность полного восстановления всех m событий. Уровень одного полностью найденного события при наличии второго выражается как j/p с учётом симметричного выбора порядка пары. Условная доля зависит от состава отобранных событий.

Для двух политик A и B тождественно выполняется Δj = Δ(p²) + Δ(j−p²). Вторая часть — изменение ковариации индикаторов для двух случайно выбранных событий одного запроса. Ковариация отражает также неоднородность сложности запросов. Разложение является описательным и не идентифицирует причинную связь между событиями.

Первичный контраст — обученный нативный R-GCN против его точного cosine seed при одинаковом prefix до 2 048 токенов. Вторичный — принудительное предпочтение связанной стороны вызова против обычного skip после R-GCN. До расчёта ни один тестовый ранг не меняется. Отдельно анализируем две уже определённые train-панели и, после полной калибровки, полный seed 13. Интервалы 95% — парные процентильные кластерные bootstrap по траекториям, 10 000 повторов с возвращением и повторным вычислением нелинейного разложения внутри повтора. Дополнительные метрики описательные, поправки на множественность не вводятся.

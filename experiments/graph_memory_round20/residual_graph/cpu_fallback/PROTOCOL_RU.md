# Резервные CPU-прогоны нативной R-GCN после отключения GPU

Всё тестовое и dev-покрытие уже закодировано в FP32, тестовые графовые прогнозы ещё не построены и не оценивались. При прерывании на train сохранились все FT-строки для 12 из 2410 траекторий; полный базовый mining был доступен для нуля целых траекторий. У 62 траекторий всего до двух недостающих FT-строк в каждой.

Предварительно фиксируем две разные обучающие панели. Практическая панель «availability» включает ровно эти 62 полностью наблюдаемые исходные train-траектории (100 вопросов), условные на времени прерывания и количестве оставшихся к кодированию строк. Независимая от свойств кэша «hash64» включает первые 64 из всех 2410 train-траекторий, упорядоченных по SHA-256 от utf8 строки «r20-native-cpu-hash64|» + ID. Обе используют все входящие вопросы в исходном порядке нативной train-выборки. Между панелями возможны совпадения, это не две независимые репликации.

Для каждой панели вычисляем недостающие точные базовые E5-векторы для hard-negative mining и FT-векторы признаков. Штатная модель, 3 слоя, 14 типов сообщений, 256 скрытых, native отрицательные 2 easy/2 BM25/1 base Dense/1 graph neighbour на положительный, бинарная классификация с положительными весами, seed13, AdamW, 15 эпох, batch graph count 128. Получающийся малый размер train меняет число шагов. Выбор нулевой или обученной эпохи — штатный dev_recall_at_5 на всех 500 официальных dev. Все 2000 test ранжируются только после выбора checkpoint. Истинный seed-passthrough проверяется на тех же features. Основные исходы этой резервной проверки — разница R-GCN и matched seed-порядка для нативного prefix и related против skip при том же R-GCN, Full Support@2048, доверительный интервал парным кластерным бутстрепом 10000 раз. Пределы обобщения — малая train-выборка, один seed, гибридное FP32-кодирование на GPU/CPU. Сравнение с полноценным опубликованным R-GCN по пяти семенам только ориентировочное. Все test и dev скоры выгружаются поштучно. Первоначальный эксперимент на полном train сохраняет свой отдельный протокол.

# Проверка и воспроизведение

## Быстрая проверка архива

Из каталога residual_graph запустите:

    python -B verify.py

Достаточно Python 3.11 или новее. Архив включает разметку в координатах, список кандидатов и идентификаторы вызовов, все упорядоченные кандидатные узлы с длинами и координатами, 18 000 индивидуальных исходов, модель R-GCN и SHA-256. Стандартная библиотека заново применяет prefix, skip и related ко всем рангам; затем объединяет символьные интервалы одного события и поля, воспроизводит все четыре метрики отобранных свидетельств и шесть колонок исходной статьи для обеих систем. Для проверки финальных метрических результатов распаковка полного корпуса и загрузка моделей не нужны. Контрольные суммы фиксируют конкретный произведённый запуск.

## Полный исходный расчёт

Входные зависимости:

- публичный GraphMemory, revision df29287116fa1565b3fd6b485022cd6090dc0b27;
- исходный ISETrace и точный tokenizer из R18/isetrace_official и R18/isetrace_e5;
- R19/trained_rank, исходный и дообученный checkpoint E5, R19 train/dev проекция;
- R19/bounded_dense, только как кэш идентичных строк под тем же самым checkpoint. Наличие этих уже вычисленных векторов экономит время; при восстановлении из нуля их можно вычислить в том же режиме;
- Python-среды R19/trained_rank. В GPU-среде PyTorch 2.6.0+cu124, transformers 4.52.4, sentence-transformers 2.7.0. Кодирование и fitting выполнены на одном RTX 3090 в FP32 при выключенном TF32. Используется отдельный D:/CodexResearch/x20-isetrace-residual. Все скрипты с координатами входа рассчитывают пути относительно исходной структуры x20-bench-workspace/work.

См. также [учитываемые признаки и loss](METHOD_RU.md), [исходный протокол](PROTOCOL_RU.md), [обучение первого ранжировщика](../../graph_memory_round19/trained_rank/REPRODUCE_RU.md) и [исходный код GraphMemory](https://github.com/xiaoqi-7/GraphMemory/tree/df29287116fa1565b3fd6b485022cd6090dc0b27).

В отдельной рабочей копии и пустом пространстве для результатов создайте каталог RUN/graphs и RUN/logs. Для первой стадии:

    python -B setup_graph.py lock
    python -B setup_graph.py 0 1 2 3 4 5 6 7
    python -B vectors.py prepare
    python -B fit_graph.py lock
    python -B vectors.py dev
    python -B data.py
    python -B dev_calibration.py
    python -B vectors.py ft
    python -B vectors.py base
    python -B cache_audit.py sources
    python -B cache_audit.py direct

Подготовитель проверяет SHA исходников, материализует нативный граф каждой траектории и собирает только точные уникальные строки с соответствующим префиксом. В таблице ключом служит пара SHA строки и вида encoder. Базовый кодируется исключительно для train-кандидатов и вопросов, необходимых выборщику hard negatives. Отдельное кодирование ft для dev раньше остального не меняет имеющиеся кандидаты. Значения FP32 при изменении порядка динамического паддинга и размера аппаратных ядер могут различаться в младших разрядах; диагностика показывает измеренное расхождение.

Для обучения и инференса:

    python -B fit_graph.py pairs
    python -B fit_graph.py fit
    python -B infer_graph.py lock
    python -B infer_graph.py infer
    python -B evaluate_graph.py
    python -B candidate_map.py

Модель и признаки в нативных тензорах остаются неизменны относительно выбранного авторского профиля. Векторизатор отрицательных извлекает заранее рассчитанные точные векторы и отдаёт их штатному DenseTaskRetriever. build_train_pairs формирует положительные и все четыре разновидности отрицательных. Для ограничения RAM нативные запросы тензоризуются по одной траектории; 768-мерные FP32 признаки размещаются в memmap на диске. train_materialized_graph_retriever выполняет тот же нативный optimizer, семена, shuffle, веса примеров, начальную валидацию и выбор лучшей эпохи, как его вызывает provenance_training.py. Native dev scorer и сбор метрик вызываются в исходной последовательности. Единственный нулевой графовый comparator — та же архитектура с исходной нулевой выходной головой; проверка torch.equal на test гарантирует, что каждый возвращаемый logit равен входному cosine seed.

Для вмешательства в топологию:

    python -B topology/edges.py lock
    python -B topology/strata.py lock
    python -B topology/edges.py build
    python -B topology/intervene.py rank
    python -B topology/intervene.py score
    python -B topology/strata.py run

В рабочем прогоне порядок фиксации protоcol и запечатанных прогнозов отражают SHA и последовательность журналов. Почти все вычислительные выходы хранятся локально. Связанные исходные checkpoint Dense-FT, сырые траектории и матрицы E5 занимают существенно больше архива, поэтому их SHA/источники указаны отдельно. Нативный небольшой обученный residual доступен непосредственно в best.pt. Обучение с GPU на другой версии ПО может слегка отличаться из-за dtype и параллельного агрегирования рёбер.

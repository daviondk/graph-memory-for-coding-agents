# Search scope after a handoff

Protocol fixed on 16 November 2026 UTC, before any experimental model response. The write time, content hashes and fixture manifest are recorded in freeze.json. Seed 460731. The four candidate commands were checked for a unique correct definition before running any agent. Fixture validation did not involve the model.

Does preserving the scope of a prior negative repository search change the next useful action a coding model takes? Can explicit fields outperform a full terminal transcript with the same information? The unit is one distinct CPython symbol in a separately constructed repository. Each repository contains an unchanged, complete CPython 3.14.4 module and generated registry entries. The rest of the original projects are absent. These are constructed one-step code-navigation tasks. Neither model nor previous searches change the repository.

## Fixed sample and exclusions

Use all 12 symbols specified in build_study.py. Each gets all three arms in distinct fresh calls, 36 calls in a seeded shuffled submission order. Match arms on repository, candidate letters, prompt body, question, and candidate order. Balance real target directories and correct command letters at exactly three cases per category. The model sees ordinary shard and option names, an opaque episode identifier is used by the runner, and neither treatment labels, phase labels, source placement, gold path, scoring rules nor study hypotheses enter the prompt. Four candidate shard names and one-read budget bound the action. The agent cannot broaden the query across all shards. A single randomized draw of repository layouts and one model sample per cell are used.

All experiments use the same model and low reasoning effort selected by the parent runner. Do not adapt prompts, stop early, or rerun a valid response. Infrastructure failures get the shared runner's capped retry, all attempts are retained. A final infrastructure failure is missing, invalid JSON or any detected tool violation is a failed task. Score exact object with one uppercase choice letter only, then execute that option with the actual repository and ripgrep binary. Invalid actions return zero. Report denominator and missing outcomes. Before scoring, verify each frozen input hash.

## Fixtures and interventions

Four actual old ripgrep scans, one per shard, search for the symbol as a literal. Record exact command, cwd, exit code, stdout records presented, total matched rows, displayed rows and display limit. Only the first four rows are visible. A scan can miss a definition because its working directory excludes a subtree, an explicit glob excludes generated code, a default search skips hidden folders, or the output display clips later matches. Each mechanism occurs on three symbols. Exactly one previously searched shard remains compatible with the unseen definition on eight tasks. Two remain compatible on the other four, one per mechanism. The placement of source in the second set is a hidden fact, so even an evidence-sensitive decision can return an empty result. The repository manifests contain only non-defining references. In the clipping case with two plausible shards, the actual and empty shards have identical row-limit, produced-row and displayed-row counts.

The summary arm gets the symbol plus the observation that references were found but the definition was absent from visible excerpts. The raw arm gets all four command transcripts and wrapper counters. The structured arm gets the identical observations in JSON with named fields and arrays. The generator parses the complete raw representation back to canonical dictionaries and asserts equality with the JSON. The enhanced arms add no diagnosis or next action. They both carry more facts than the short summary. The raw-vs-structured contrast isolates reformatting, including the unavoidable token-length difference. The summary contrast combines added content and increased context length. The roll of the correct command letter and shard is fixed across arms. The model deciding the next step never receives access to cases.json or fixture files. The evaluator's oracle is the original AST top-level function line and module path; no model produces labels.

## Outcomes and analysis

Primary outcome per case is whether the stdout of the selected command contains the exact case's target path and original definition line. Secondary outcome is selecting a shard left unresolved by the previous scans. The latter stays positive if either compatible shard is selected in an ambiguous case. Record applied command, exit code, stdout count, wall time, input/output/cached-input token counts and actual retries. Report pass counts overall and split by one versus two plausible shards, plus memory size. Uniform random selection would hit 3 of 12 definitions in expectation. With perfect use of scope evidence and fair guessing between two equally plausible shards, the reference expectation is 10 of 12; neither is an observed model.

Pair by case; first contrast is structured minus raw. Raw minus summary and structured minus summary quantify the combined effect of the extra evidence and its presentation. Report discordant wins/losses and mean paired difference for all contrasts. Exact two-sided conditional sign/McNemar p-values are descriptive under exchangeability, without a population sampling claim or a multiple-testing correction. With 12 constructed cases and four mechanism groups, small format effects and differences between mechanisms cannot be resolved. The trial measures one bounded selection and its executable result. Multi-turn issue resolution, search over a full project, retrieval, long-term memory durability, and population performance of coding agents require separate evidence.

## Reproduction

The bundled snapshots, request order, allocation, trace logs, original source attribution, and scorer suffice to replay the existing outcomes with Python 3.14 and ripgrep 15.2. The Windows-host transcript preserves native path separators. From the study parent directory, run `python shared/run_model.py search/requests.jsonl search/runs --workers 2`, then `python search/score.py`. In a fresh tree, `python search/build_study.py` can regenerate the fixtures from a CPython 3.14.4 installation or re-use bundled source copies. The frozen hashes apply to the shipped files; regenerated OS-specific traces and line endings may differ. Installed source provenance: [CPython v3.14.4 standard library](https://github.com/python/cpython/tree/v3.14.4/Lib); license text is bundled.

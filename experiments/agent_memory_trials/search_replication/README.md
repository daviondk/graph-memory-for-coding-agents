# Репликация на gpt-6-luna

Все 81 зафиксированный файл первичного опыта скопирован байт-в-байт. Протокол первичной постановки находится в protocol.md, дополнительный план для второй модели — в REPLICATION_PROTOCOL.md. Второй план, общая реализация запуска и первая фиксация проверяются по replication_freeze.json.

Совместно с каталогами ../search и ../shared эта папка образует полный набор для сопоставления. Сохранённые ответы и фактически выполненные команды находятся в runs и executed_actions.json. Таблицы observations.csv и results.json используют без изменений оценщик первого опыта. replication_audit.json сопоставляет промпты двух моделей и собирает расходы с учётом всех попыток. Файл transport_probe.json хранит отдельную проверку транспорта.

Для верификации существующих ответов из этого каталога нужны Python 3.14 и ripgrep. Выполнить последовательно:

```sh
python -B replicate.py score
python -B audit_replication.py
```

Оценка повторяет команды ripgrep на включённых фикстурах. Текст ответов модели сохраняется. Измеренное время выполнения локальных команд в observations.csv при повторной оценке меняется.

Для независимого сбора новых модельных ответов используют копию каталога с зафиксированными входами, пустым каталогом runs и без прежнего transport_probe.json. Общий ../shared/run_model.py должен быть доступен по исходному относительному пути, а CLI должен поддерживать выбранную модель. В новой копии последовательность такова:

```sh
python -B replicate.py probe
python -B replicate.py run
python -B replicate.py score
```

Шаг run разрешается только после успешного probe. Каждый завершившийся запрос сохраняется, поэтому повтор прерванной команды run продолжает незавершённые ячейки. Новые стохастические ответы модели могут отличаться при идентичных промптах.

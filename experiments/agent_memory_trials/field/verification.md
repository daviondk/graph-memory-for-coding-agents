# Независимая проверка команд поиска

Проверка проведена 16 ноября 2026 года после получения основной таблицы. С помощью стандартной библиотеки Python повторно загружены 48 исходных историй по неизменяемой ревизии. SHA-256 каждого файла совпал с сохранённым в traces.jsonl. Проверочный скрипт не импортирует основной анализатор. Он заново связывает команду с ответом по идентификатору вызова, сверяет текст команды, порядковый номер сообщения и код возврата. Синтаксис завершающего head проверяется отдельным выражением. Команды из историй не исполнялись. [Снимок VibeMemBench](https://huggingface.co/datasets/Tongyi-ConvAI/VibeMemBench/tree/11164976b4f920cdb0d0cd570ca572e49acea1e8)

## Что означают три разных счётчика

Из 3 078 вызовов bash с парным ответом основной парсер распознал 444 простые команды текстового поиска. В 137 из этих 444 команд была явная граница числа строк. Во всех 137 случаях её задал завершающий head. Опция максимального числа совпадений на файл не встретилась среди распознанных ограничений. 33/48 историй содержали хотя бы один такой вызов. Одна история могла дать много команд.

Из поля extra.raw_output каждого из 137 ответов получено фактическое число строк сохранённого вывода. В 97 случаях оно было меньше предела, в 40 совпало с пределом. Ровно предела достиг хотя бы один ответ в 20/48 историях. При равенстве могли существовать как ровно N, так и более N строк до head. Код возврата оболочки равен нулю во всех 137 случаях. В конвейере этот код может отражать успешное окончание head даже при отсутствии совпадений в grep.

Величина N у head относится к строкам потока. Строки могут представлять совпавшие строки исходника, имена файлов при grep -l, либо контекст при grep -A/-B. Несколько вхождений подстроки в одной строке grep обычно выводит одной строкой. Ответ инструмента иногда может включать диагностику. Поэтому счётчик строк имеет более узкую интерпретацию, чем «число найденных фрагментов программы».

## В одном случае отсечение подтверждается исходным текстом

В истории eodag-616 сообщение 14 содержит cat eodag/plugins/search/qssearch.py. В ответе сохранились 1 222 строки. Следующим сообщением агента под индексом 16 идёт поиск по этому же файлу с grep -n и head -80. Между ними только результат cat. В независимой проверке пять альтернатив из исходного шаблона сопоставлены со строками ответа cat. Получены 110 совпавших строк. Первые 80 вместе с номерами посимвольно воспроизводят весь сохранённый ответ поиска. Последней видимой стала строка исходника 943, первой пропущенной — 954. Таким способом подтверждено отсечение 30 строк по меньшей мере в одном вызове. Для остальных 39 ответов, достигших лимита, такой вывод здесь не проверялся. [Оригинал истории eodag-616](https://huggingface.co/datasets/Tongyi-ConvAI/VibeMemBench/blob/11164976b4f920cdb0d0cd570ca572e49acea1e8/history/python/CS-SI__eodag/cs-si__eodag-616/cs-si__eodag-616.traj.json)

## Разбор восьми событий

Индексы сообщений начинаются с нуля. Примеры отобраны после основного анализа для проверки конкретных ветвей классификации. Точные команды, идентификаторы, пути и хеши сохранены в verification_examples.json. Здесь приведены только признаки вызовов.

| Проект и сообщение | Формат команды | Учёт основным парсером | Наблюдение |
|---|---|---|---|
| eodag-616, 16 | grep по одному файлу, head -80 | С лимитом | 80 строк из проверенных 110 |
| woodwork-1315, 35 | рекурсивный grep, head -30 | С лимитом | 27 строк |
| umongo-245, 27 | grep по одному файлу, head -30 | С лимитом | 0 строк, код оболочки 0 |
| attrs-704, 14 | cd и grep -n по одному файлу | Без лимита | 3 строки |
| hypothesis-3924, 10 | find, xargs grep -l, перенаправление, head -30 | Пропущена | 11 строк с именами файлов |
| pyqtgraph-1653, 2 | find, xargs grep -l, head -20 | Пропущена | 0 строк |
| pandas-60230, 16 | grep и два последовательных grep -v | Пропущена | 10 строк |
| click-1609, 90 | cd, grep с 2>/dev/null | Пропущена | 2 строки |

Парсер исключает ряд конвейеров, перенаправления, многострочные команды и другие инструменты. Поэтому встречаемость среди распознанных команд зависит от выбранной грамматики. Среди пропущенных примеров есть и вывод с head, и поиск без явного лимита. Корректировать долю всех вызовов по этим целевым восьми примерам нельзя. Четыре истории на проект задают равный вес проектам и иной вес активно представленным в корпусе репозиториям. Повтором основной анализ называет точное текстовое совпадение среди распознанных команд одной истории. Изменение кавычек или опций может скрыть повтор действия, а дословный повтор после правки может быть оправдан. Влияние ограничения или повтора на качество решения по этим счётчикам не установлено.

Для воспроизведения достаточно Python 3 и доступа к неизменяемым URL в traces.jsonl. Запуск python check_field.py из этого каталога формирует verification_examples.json и проверяет все утверждения, для которых приводятся численные результаты повторного чтения.

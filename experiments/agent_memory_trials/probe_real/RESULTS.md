# Различающая проба на опубликованных библиотеках Python

16 ноября 2026 года. Взяты три документированных изменения API. Для каждого пакета два исторических wheel-файла использованы для получения карточки и два других — для целевых заданий. В журнале wheels.lock.json указаны исходные URL и SHA-256 всех 12 файлов. Вызовы исполнялись в изолированных процессах из временно распакованного дистрибутива, без установки пакетов в систему.

| Пакет и операция | Исторические версии | Целевые версии | Что различает рабочая проба |
|---|---|---|---|
| packaging.version.parse | 20.9 / 22.0 | 21.3 / 23.0 | Нестандартная строка версии даёт объект LegacyVersion либо исключение InvalidVersion. |
| PyJWT jwt.decode | 1.7.0 / 2.0.0 | 1.7.1 / 2.0.1 | Корректная подпись HS256 при вызове без аргумента algorithms даёт словарь либо исключение DecodeError. |
| more_itertools.chunked | 8.4.0 / 8.6.0 | 8.5.0 / 8.7.0 | Строгая разбивка с неполным последним блоком вызывает TypeError при неизвестном параметре либо ValueError при проверке размера. |

Обе группы полностью решили **6 из 6 заданий** и верно предсказали **24 из 24 результатов** своих отложенных вызовов. В обеих группах все шесть выбранных проб дали разные результаты на двух целевых версиях соответствующего пакета. Дословно исторический ввод использовался в 5 из 6 случаев с карточкой и в 0 из 6 без неё. Ни одна текущая проба не совпала с отложенным входом целиком. Внутри каждого пакета обе группы решили два задания из двух.

Например, для старой целевой версии packaging агент без карточки выбрал строку «1.0-final» и получил LegacyVersion. Для новой версии он выбрал «1.0_1» и получил InvalidVersion. Агент с карточкой в обоих случаях использовал «vendor-nightly». Таким образом удалось проследить различие в поведении агентов, хотя конечная оценка в обоих условиях достигла предела.

Все 24 запроса к GPT-6.1-sol, по одному модельному ответу на задачу и этап, завершились с первой попытки. Расход модели по группам с карточкой и без неё составил 874 и 1090 выходных токенов, сумма длительностей запросов — 105,7 и 111,3 секунды. Цифры описывают этот запуск при параллельной обработке и работе серверного кэша.

Условия сильного контроля существенно упрощают диагностику. Модель знала имя публичного API, допустимые параметры и имена возможных исходов. Три изменения были выбраны по документации. Дата выпуска старой целевой версии предшествует более новой исторической версии. Пилот проверяет распознавание неизвестной установленной версии на других файлах дистрибутива. Из шести совпавших пар нельзя оценить эквивалентность стратегий на новых пакетах, стоимость поиска подходящей карточки или эффект при исправлении репозитория.

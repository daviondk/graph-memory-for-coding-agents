# Real-package replication of saved diagnostic probes

Dated 2026-11-16. This independent prospective pilot uses three published Python packages. Its freeze follows the synthetic study and precedes the first model response in this replication. The local freeze.json records the actual UTC time, SHA-256 values, interpreter and assignment seed. No external timestamping service or registration was used. No model has run on these cases before the freeze. The separate source executions confirm the historical contracts by running the real wheels.

## Scope and choice of packages

The packages are a purposive convenience sample of documented changes. Each provides a public operation and a finite, meaningful success or error result detectable with a single call. The source and target wheels differ within every family. The chronological release of the held-out older target predates the latest source snapshot. The scenario is identifying an unknown deployed version from an old/new release line. It does not simulate a strictly time-forward rollout. Package and callable names are public to the executor, installed versions and labels are concealed. The model may already know their published contracts.

| Package | Historical pair | Withheld deployment snapshots | Reason for selection |
|---|---|---|---|
| packaging | 20.9, 22.0 | 21.3, 23.0 | Non-PEP 440 inputs formerly produced LegacyVersion; 22.0 removed that class. [22.0 release notes](https://github.com/pypa/packaging/blob/22.0/CHANGELOG.rst) |
| PyJWT | 1.7.0, 2.0.0 | 1.7.1, 2.0.1 | 2.0 requires an explicit algorithms argument when verifying a JWT. [2.0.0 release notes](https://pyjwt.readthedocs.io/en/2.0.1/changelog.html#require-explicit-algorithms-in-jwt-decode-by-default) |
| more-itertools | 8.4.0, 8.6.0 | 8.5.0, 8.7.0 | 8.6.0 introduced the strict keyword for chunked; consuming a partial final chunk can now raise ValueError. [8.6.0 release notes](https://more-itertools.readthedocs.io/en/v8.14.0/versions.html) |

All twelve unmodified pure-Python wheel files are distributed here with their original contents and licenses. wheels.lock.json records the individual PyPI metadata URL, canonical download URL, publisher-provided SHA-256, byte count and release/upload date. At every use the harness hashes the wheel, unpacks it into a fresh private temporary directory and starts a Python child with -I -S -B, no site-packages, and that unpacked distribution on its search path. The child verifies that the imported module lives under the temporary wheel root. No package is installed on the workstation. The three tested code paths run with only the standard library. PyJWT receives valid HS256 tokens generated by the same deterministic stdlib HMAC factory. The experiment does not exercise other package features or security primitives.

## Cases, recurrence and controls

The two historical builds for each package execute the same three inputs (18 archived API executions total). The archive constructor saves the first input on which the observed classes differ, plus the class on the newer source wheel. It sees no hidden values or labels. Selecting the historical input cassette and release lines used the public changes; there is no claim of automatic discovery. A historical example and no-memory fresh probing are compared on each of six target snapshots, one retaining and one differing from the historical post-change contract per package. Each target has a fixed application workload of four further inputs. A seeded shuffle allocates one workload to each snapshot independently within each package and randomizes the order of the 12 arm-case requests. Release identities and workloads never appear in probe-design prompts. Every arm may invent a useful probe. The two arms see identical instructions, public wrapper schema, common output class names and permitted input domain. The only added material is the one archived I/O pair. Showing the schema and class names makes fresh probing a deliberately capable comparison. A routine-card arm is absent in this smaller replication.

The LLM decides a single current probe, separately for each arm and target (one case per request). The harness executes it and returns its observed class. The second LLM call in a fresh conversation sees the same manual and archive, the exact chosen input and its actual result, plus the four pending parameters. No version ids or hidden correct results are provided. It predicts four return or exception class strings. Both arms receive precisely one target call opportunity. An invalid probe consumes it with a schema error. The immutable adapter is shared by observation and arm-blind scoring. The harness re-executes each of the four application calls against the target wheel after the decision. Counterfactual executions of the proposed probe against the other target wheel are performed only for offline diagnosticity scoring after decisions. Exact JSON strings determine correctness. An invalid final array yields zero points for the case. Other than technical retries in the frozen runner each decision is one draw. All 12 scheduled trajectories are scored, with failures retained.

## Outcomes and uncertainty

Primary endpoint is all four application return/exception classes exactly correct per target. Compare six paired outcomes by absolute rate difference and wins/ties/losses. Secondary measures are scalar accuracy, informative-probe rate, exact archive replays, older/newer outcomes, resource usage and exact overlap of a chosen input with a held-out query. Each package contributes two dependent release cases; expose all three paired package totals and leave-one-package-out differences. There are three purposively selected clusters, no population-level significance test, effect interval or pooled estimate with the synthetic pilot. Generalization to autonomous package selection, repository repair, unknown drift axes, economic benefit or models other than the recorded executor is untested. This illustrates contract diagnosis under a one-call budget.

## Reproduction

From this directory with the sibling shared/run_model.py and bundled wheels:

```text
python -X utf8 -B study_real.py verify
python -X utf8 ../shared/run_model.py stage1.jsonl runs1 --workers 2
python -X utf8 -B study_real.py observe
python -X utf8 ../shared/run_model.py stage2.jsonl runs2 --workers 2
python -X utf8 -B study_real.py score
python -X utf8 -B study_real.py audit
```

For fresh stochastic draws copy the frozen inputs and scripts into another sibling study folder without runs1 and runs2. Existing runner files are reused. For offline verification of already collected runs, use verify and audit; scoring and audit require no model service. To reproduce preparation in a new directory, copy releases.py, adapter.py, fixtures.py, study_real.py, PROTOCOL.md and run releases.py, followed by study_real.py prepare and study_real.py freeze. Download timestamps, source execution timestamps and freeze timestamp will be newly created. Wheels and their digests are fixed. The consulted experimental-design and statistical-analysis workflows are described by [Kassis et al., v2 (2026)](https://doi.org/10.48550/arXiv.2609.00065).

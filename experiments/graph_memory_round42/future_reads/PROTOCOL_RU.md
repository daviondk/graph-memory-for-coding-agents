# Были ли сохранённые строки затем востребованы

До присоединения будущих чтений фиксируем сравнение на существующих выдачах R40–R42. Ранее наблюдали частоты сохранения целого первоначального пакета и частоту возврата к файлу вообще. Новая цель — проверить конкретные пары (новая координата, точное содержимое), которые отобранная память фактически могла бы дать на последующие запросы того же рабочего файла. Для первичного анализа берём 1 071 событие из прежних 13 отложенных задач. Отдельно все 2 696 событий, 676 основных, полностью наблюдаемые окна, окна с положительным зарегистрированным спросом. Читатель будущего не может влиять на выбор пакета, координат, источника или параметров. Публичная панель и расписание будущих просмотров уже существовали; эта работа связывает их с новыми зафиксированными методами.

До чтения исходов собираем адресуемое содержимое реально выбранного **нового** пакета каждой политики на изменённом пути под общим бюджетом прежних экспериментов. Методы — файловый, символьный, точный поиск по содержимому в полном файле, интервал, края замены, локальное сопоставление, а также подписанная политика объединения интервала и поиска по целому файлу из R42/lazy_validation при совпадении исходных пулов и карт адресов. Для каждого адреса храним хеш текста и размер. Оставляем только строки, уже распознанные как информативные в предыдущем видимом чтении. Из каждого пакета вычитаем совпадающие строки уже показанной агенту квитанции той же правки из исходной проекции R37. У такого baseline нулевые дополнительные расходы памяти. Параллельно сообщаем результаты вместе с квитанцией. Пустой и файловый пакеты могут по-прежнему воспользоваться самой квитанцией.

В строгом окне сначала наступает успешная квитанция str_replace. Состояние цензурируется на первой непрозрачной операции, разрыве или неподтверждённой записи, прекращается на следующей достоверной мутации или завершении. Берём все подтверждённые последующие наблюдения view **именно изменённого пути** в доступном префиксе строго после квитанции и до границы, включая только фактически возвращённые пронумерованные информативные строки исходного набора R37 (изначально определённые фильтры длины, токенов и повторяемых служебных строк). Дубликаты адрес+текст внутри одного запроса не учитываем повторно. Одно и то же обращение в разных запросах считаем отдельно. Сверяем число/первый индекс запросов с подписанными строгими окнами R37. Правоцензурированная трасса может содержать известные попадания до момента цензуры.

Первичная метрика — индикатор хотя бы одной строки, фактически запрошенной в наблюдаемом строгом префиксе и полученной из выбранной памяти сверх самой квитанции; парный контраст локальный метод минус интервал, макро по issue с 10 000 парными перевыборками целых issue. Дополнительные контрасты — локальный минус поиск по содержимому, символьный, края; объединение источников минус локальный и минус интервал. Сохраняем число совпавших строк-событий и их байтов, число запросов, для которых покрыта вся наблюдаемая информативная часть, суммарный спрос, полные/цензурированные окна, долю совпадений у самих квитанций. Для условных результатов на просмотренных или полных окнах всегда указываем знаменатель. Для двоичного исхода сообщаем границы полной потенциальной частоты и разности с учётом общего ненаблюдаемого будущего: при цензуре новое попадание возможно только для непустой памяти; при двух нулевых результатах отдельная победа возможна только при наличии уникальных для метода строк. Числа ответов на задания, экономия вызова инструмента и причинное изменение поведения LLM по журналам не идентифицируются.

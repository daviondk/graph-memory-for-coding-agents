# Как повторно использовать контекст внутри наблюдённой замены

При отзыве всего указанного диапазона сохранилось **302** пакета. Получили **21 парное улучшение и 0 ухудшений**, разность при равном весе 13 задач **+1,97 п.п. [1,02; 3,03]**. **Какой компонент дал выигрыш.** В 888 из 1 071 операций нашёлся хотя бы один общий край. Проверки краёв достаточно для 20 из 21 дополнительного сохранения целого пакета. Внутреннее сопоставление добавило ещё 60 доступных блоков, но ровно один полный пакет; парная разность +0,15 п.п. с интервалом от 0 до 0,45 при усреднении по задачам. В сравнении с уникальным поиском по полному новому файлу получены 52 выигрыша и 16 проигрышей, разность по задачам **+3,53 п.п. [−0,35; 7,71]**. Превосходство над этим сильным контролем по частоте целых пакетов остаётся неопределённым. На пяти репозиториях чистые приросты числа пакетов относительно прежнего интервала составили 0, 1, 5, 7 и 8. **Как работает перенос.** Если агент попросил заменить несколько строк, то вводная и заключительная строки шаблона нередко остаются буквально теми же. Зная путь, подтверждённую позицию и обе строки замены, хранитель памяти может перенумеровать такие наблюдения, сохранив связь с исходным чтением. Неизвестный префикс первой физической строки и суффикс последней обозначаются отличимыми граничными метками; их учитывают даже при замене внутри строки. Весь блок сохраняется только при последовательном отображении всех его старых строк в непрерывные позиции новой версии. У расширенного варианта внутри замены используется SequenceMatcher с фиксированным верхним пределом произведения длин центральных частей. На основной панели порог не сработал. Исчерпывающая синтетическая проверка сконструировала 14 040 различных записей и 70 560 запросов к блокам; все 15 744 сочетания, принятые расширенным правилом, совпали побайтно. Проверена и ветвь превышения предела. При повторяющихся одинаковых фрагментах правило гарантирует совпадение байтов; оно не устанавливает намерение редактора переместить семантический объект. **Стоимость доступа.** Для 1 071 операции старые и новые литералы в агентских действиях заняли суммарно 1,224 МБ, медиана 838 байт на действие. Пара полных служебных версий для сравнения по содержимому заняла 141,18 МБ с учётом повторов, медиана 142 722 байта. Это размеры фактических полей корпуса, которые разные алгоритмы используют для того же сравнения. Данные действия уже были видны агенту; хранитель также должен получить правильный адрес успешной операции. На повторном локальном замере подготовка хешированных строк из пары литералов заняла в сумме 0,0329 с, сопоставление краёв — 0,0020 с, расширенное сопоставление — 0,0140 с на этой панели. Для каждого события бралась медиана трёх запусков. Затраты вытягивания Parquet и доступа к рабочему дереву в это время не входят.

# Независимая проверка шестой серии

Пересчёт по журналам подтверждает точное восстановление множества файлов в разыгранных запросах и заметно разную реакцию двух читателей на даты. Основное испытание кодового агента дало равный результат против одной слепой политики. Обобщать цену, частоту пользы и преимущество системы можно только при совпадающих постановках.

## Стоимость поддержки поиска

Из событий, эталонных снимков и журнала сообщений восстановлены 9 репозиториев × 42 перехода, 195 наблюдаемых имён и 90, 378, 3 024 запроса при трёх частотах. Три частоты переигрывают одни и те же изменения. Сумма физических полезных нагрузок для точных дельт — 1 937 байт плюс 2 648 байт расчётной регистрации, всего **4 585 байт**. Для уведомлений о смене принадлежности — 908 плюс 6 510, всего **7 418 байт**. При редких запросах pull потребовал 6 880 байт, включая ту же регистрацию. Меньшая полезная нагрузка обновлений сама по себе не определяет более дешёвый протокол. [Журнал сообщений](validity/stream/log.json.gz) · [Симулятор](validity/stream/sim.py)

В этих числах бесплатно доступны первоначальная полная поисковая заметка и общий поток изменённых путей. Если словарь прежних путей надо передавать, для него оценено ещё 18 662 байта. Тексты Git diff в этом наборе занимали 5 873 312 байт. Сканирование писателем, поддержка состояния клиента у сервера, сетевой транспорт и процессорное время не входят в 4 585 байт. В плотном режиме клиент с локальной инвалидацией обратился к 29 752 901 байту исходников, с подписанным 512-байтным фильтром — к 9 522 812 при дополнительных 107 741 байте управляющего трафика. Стоимость подписанного фильтра рассчитана по размеру массива и заголовку. Он используется внутри симулятора, а обратное декодирование пакета проверяется у точных методов и протокола Bloom-регистрации. Кеш объектов внутри истории не ограничен, первоначально он пуст. Независимая сверка OID с начальным деревом нашла только 4 повторных исходных объекта суммарно на 3 185 байт — верхнюю границу эффекта предварительного заполнения этого кеша на данных переходах. Точность прямого обновления проверяется по новым снимкам, а фактическое чтение содержимого клиентом имитируется получением истинной принадлежности каждого выбранного файла. Это поддержка регистрозависимого поиска ASCII-идентификаторов в обычных файлах Python. [Проекция источников](validity/stream/project.py) · [Протокол](validity/stream/PROTOCOL.md)

Частота нужных повторных запросов в эксплуатации остаётся открытой. В 4 310 изученных трассах в 126 задачах повторился идентификатор после зарегистрированного редактирования, в 28 повторился и полный текст команды. Это 31 повторное событие второго типа. Имена для потокового теста происходят из реальных трасс, моменты их запроса сымитированы. [Подсчёт исходных обращений](validity/exposure_results.json)

## Кодовый агент и зависимость наблюдений

Независимое соединение строк item_results.csv по ID даёт на авторских тестах **44/64 против 44/64** для SHA и слепого выбора, одно улучшение, одна потеря; на второй когорте **26/32 против 21/32**, пять улучшений, ноль потерь. Точный парный двусторонний p для второго сравнения равен 0,0625. При равномерном выборе половины чтений математические ожидания из двух физических исходов каждой задачи равны 42,5/64 и 23/32. Следовательно, выигрыш во второй когорте — пять задач над одной слепой реализацией и три задачи над её ожиданием. На MBPP+ пересчёт дал 39:39 из 57 и 20:16 из 26, соответственно. В этих двух срезах обе сравниваемые политики читают 28 и 14 условий, квота 50% задавалась на первоначальных 64 и 32 задачах. [Пообъектный журнал](repair/item_results.csv) · [Опыт программирования](repair/summary_ru.md)

Доля изменений условия ровно 50% сконструирована отдельно в каждой когорте. В доступной после фильтров части было 101 изменённое описание из 221. Свежесть полной байтовой строки — прокси к полезности. На основном срезе дословная память без повторного чтения решила 45/64. Поставщик версии изучил все текущие описания или мог воспользоваться существующим индексом версий. Стоимость индекса следует считать отдельно. Одна программа на уникальный промпт используется в нескольких политиках, а MBPP+ повторно оценивает ту же программу. Единица сравнения — задача. Две раздельные когорты принадлежат одному корпусу и одному актору. Пул из политик, метрик и повторных тестов не увеличивает число независимых задач.

## Результаты для читателя

Для бинарного признака «разошлись первые места» независимо посчитана диагностическая площадь под ROC-кривой. Положительный исход — печать годов исправила неверный ответ, остальные исходы объединены. При большем балле для расхождения у Qwen TPR = 50/192, FPR = 190/276, AUC = **0,286**. У GLM TPR = 105/163, FPR = 135/305, AUC = **0,601**. У Qwen обратный знак даёт AUC 0,714. Площадь учитывает связи как половину выигрыша и характеризует распознавание исправления; полезность при квоте дополнительно учитывает испорченные ответы. Одни и те же 468 фактов оценены обоими читателями, 32 варианта калибровки переиспользуют эти факты. Прежний сильный знак выбран с учётом этих данных. Вывод о двух опубликованных логах оправдан, универсальный выбор знака для неизвестной модели не установлен. [Оценки обеих ветвей](literature/paired_scores.jsonl.gz) · [Проверка калибровки](reader/calibration/summary_ru.md)

На отдельном CAsT 2021 замороженное правило Cal500 показало 0,39879 nDCG@3 при 135 вызовах, простое правило пропуска первой реплики — 0,40215 при 139. Сравниваются выходы одного настроенного BM25+monoT5, опубликованные авторами воспроизведения. У двух первых вопросов совпадали исходная и переписанная строки, но различались оценки. Вмешательство относится к выбору полных выдач. Наблюдения группируются по теме. [Внешняя проверка](reader/transfer/summary_ru.md)

## ConcordBench и предел сравнения с лучшими системами

Проверен протокол для 40 случаев ConcordBench-Pioneer HotpotQA с программно заданным восстановлением источника. Сравнение локальной Qwen ведётся с исходным block_context и raw того же SDK. При включённом дополнении подсказка передаёт до 600 байт, но при промахе кеша реализация физически читает весь соответствующий файл. Для интерпретации нужны все 40 случаев в знаменателе, число реальных восстановлений источников, число случаев с разошедшимися входами, полученный ответ, EM/F1 и стоимость чтений. Идентичные запросы могут обслуживаться общим кешем. Транспортная ошибка может сохранить пропуск счётчика действий после промежуточных обращений. Такой пропуск следует сохранять как неизвестный, даже когда оценка ответа равна нулю. Этот раздел проверяет критерии эксперимента, количественные выводы делаются по его окончательному комплекту результатов.

В статье Concord исходный результат восстановления определён для трёх иных моделей и схемы оценивания авторов. Балл локальной Qwen по EM/F1 не образует единой шкалы с оценкой восстановления, вынесенной авторским LLM-судьёй. Сравнение запущенных на одной выборке реализаций допустимо с явным указанием модели, квантования, лимитов, контрольной ветви и метрики. Совокупность тестов шестой серии не устанавливает мировой рекорд по агентной памяти или преимущество на закрытом SERBench Test500.

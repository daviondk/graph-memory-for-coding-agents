# Воспроизведение эксперимента

Откройте PowerShell в каталоге с этим файлом. Проверка архивных результатов без GPU и сети использует стандартную библиотеку Python.

```powershell
python -B verify.py
```

Для повторной проверки программ на авторских тестах нужны Python, NumPy и Windows Job Objects для исходного лимита памяти. На другой ОС действует только таймаут. Команды ниже создают выходные таблицы и программы эталонов в текущей папке. Для побайтового сравнения запускайте их на отдельной копии. Между запусками вблизи порога 5 секунд возможен иной статус таймаута.

```powershell
python -B grade.py
python -B plus_grade.py
python -B analyze.py
python -B verify.py
```

Для независимой генерации создайте пустой каталог. Скопируйте в него все корневые файлы .py, start_server.ps1, оба файла *protocol.md, tokenizer.json, mbppplus.jsonl.gz, upstream-mbpp.jsonl, upstream-sanitized-mbpp.json, upstream-README.md, plus_lock.json и sources.json. Воспроизводимость подразумевает те же опубликованные входные данные, Python, requests, tokenizers, NumPy, GGUF и сборку llama.cpp/CUDA; сведения о версиях находятся в runtime. Собственные двоичные файлы можно передать параметрами -LlamaServer и -ModelPath. Этот сервер слушает только loopback. После запуска дождитесь ответа status=ok от http://127.0.0.1:18961/health .

```powershell
./start_server.ps1
python -B prepare.py
python -B infer.py
python -B token_check.py
python -B grade.py
python -B plus_grade.py
python -B analyze.py
python -B verify.py
```

Сервер можно остановить через Stop-Process по его собственному ProcessId из runtime/launch.json. Не включайте прежние calls, tasks, allocations или scores при независимой генерации. Детерминированный кэш внутри одного исследования связывает равные запросы с одним фактическим ответом. Реализация и точный порядок запросов, ограничения генерации и маршрутизации находятся в prepare.py, infer.py и policies.py. Для повторной генерации не требуется создавать Docker-контейнер или изменять предыдущие серии.

Первичные данные разнесены по каталогу tasks/ID. В нём хранятся оба издания условия, заголовок вызываемой функции, записка модели, исходный и текущий SHA в общем roster.json, а также три материала программы. У каждого ответа есть исходная строка и ID архивного запроса; в calls лежат полные request/response llama.cpp, нативные токены и время. «Слепой» контроль использует фиксированный хеш для выбора половины задач каждой выборки. Политики с неопределённостью используют детерминированный порядок разрешения одинаковых оценок. Расчёт затрат не суммирует разные политики между собой. Ресурсы, которые уже были общими в эксперименте, начисляются каждой политике отдельно в зависимости от её потребностей.

Фиксация методики локальная. design_lock.json содержит UTC и SHA-256 протокола, программ первичного опыта и всех входов; prediction_lock.json фиксирует запросы и исходы генерации до присоединения результатов тестов. plus_lock.json фиксирует вторичные тесты и код их запуска. Внешняя служба отметок времени не применялась. Файлы scores.json и plus_scores.json содержат детальные статусы каждого задания и программных ветвей. В item_results.csv приведены результаты каждого способа на каждом доступном задании.

MBPP распространяется по CC BY 4.0, оригинальная работа Jacob Austin и соавторов. Исходные редакции, статьи и хеши перечислены в sources.json. Дополнительные тесты EvalPlus подготовили авторы проекта EvalPlus, релиз v0.2.0. [Архив Google Research](https://github.com/google-research/google-research/tree/f82046ba5aabbbb427dbfd38a254d26bff08b533/mbpp), [карточка данных и лицензия](https://huggingface.co/datasets/google-research-datasets/mbpp), [статья MBPP](https://arxiv.org/abs/2108.07732), [релиз MBPP+](https://github.com/evalplus/mbppplus_release/releases/tag/v0.2.0).

## Проверка лимита после открытия первичных результатов

Для проверки сохранённой чувствительности без GPU достаточно `python -B cap_report.py`. Для повторной CPU-оценки запустите `python -B cap_grade.py` перед этой командой. Дополнительные файлы и таблицы хранятся в cap1024. Полное независимое повторение запускается в отдельной копии после завершения и оценки первоначальной генерации, без переноса cap1024 из архива. Скопируйте sensitivity_protocol.md и все cap_*.py. При работающем исходном сервере выполните `python -B cap_generate.py`, затем `python -B cap_grade.py` и `python -B cap_report.py`. Корневой итоговый текст пересоздаёт `python -B report.py` после `python -B verify.py --record`. Для повторного физического исполнения двух первичных тестовых наборов и отдельной сверки каждого статуса доступна `python -B replay.py`. При генерации собственных регистров временные метки и полный SHA файлов закономерно отличаются.

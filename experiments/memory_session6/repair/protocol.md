# Locked before inference and functional evaluation, 18 November 2026

Study whether a code agent should use a content-version signal to spend a limited reread budget after its conversation is reset. Use the Google Research MBPP original and author-verified editions, pinned commit f82046ba5aabbbb427dbfd38a254d26bff08b533, official evaluation IDs 11–510. The source files contain solutions and tests for grading. The actor receives only the public function interface and the ticket prose. The old ticket is the original MBPP text and the current ticket the sanitized prompt for the same id, including truly identical pairs. These are genuine publisher editions; the simulated handoff, fingerprint service, fixed budget and relative timing are experimental. Read the two local files physically; do not generate fake revisions.

Select tasks before scoring. Require exactly one top-level function in each edition, identical function name and AST arguments in both, plain positional parameters, no defaults or annotations. Exclude inspected IDs 237,280,257,223,255,277,140,94,118,272,273,172,265,77,232,251 and security, networking, clinical or weapon content. Exclude only by public description/interface, never on reference performance. Hash order with seed mbpp-version6-20261118. Allocate 32 byte-identical and 32 changed original/current pairs to main, then 16+16 to disjoint replication from the same corpus. The balanced mixture deliberately enriches edited tickets. One deterministic trajectory per task/branch, no training.

Stage 1. Editor reads the old ticket from disk and writes a free-form memory note in JSON and an ambiguity rating (0–100). Keep up to 40 native Qwen tokens of the recovered text. Malformed JSON: use clipped old prose and assign ambiguity 50. The verbatim alternative is the first 40 tokens of old prose. The interface is supplied intact at both stages and is excluded from the note budget. No access to the current prose, tests, example I/O, solution, or later scores in this stage. URLs in publisher prose are inert strings. Stage 2. Reset conversation. Reader sees the interface and exactly one text, either the carried old note, the carried old verbatim prefix, or the current ticket physically reread from disk. Common prompt, grammar, seed and maximum 416 generated tokens; output a Python implementation. No test feedback/resampling. Use deterministic cache for byte-identical requests. All three branches are run for every item; fixed policies replay real branches. No second chat turn is required because choosing which file to read is a host policy decision.

The source-version signal compares SHA256 of UTF-8 bytes. Only the digest is available to routing, not the replacement source. The physical source provider's digest computation is accounted separately. Fixed-budget policies each reread exactly half the tasks in each cohort. Primary: changed-only reread with the model note versus a blind, reproducible allocation of the same number of rereads with the same model notes. Both keep the model note when skipping. Secondary: reread highest writer-reported ambiguity; hybrid reserve 3/4 of allowed reads for changed and 1/4 for unchanged (in each stratum prioritize high ambiguity); changed-only with raw prefix; blind with raw prefix. References outside this 50% constraint: never reread model note; never reread raw prefix; always reread full current ticket. Per-policy candidate code and costs are actual branch replays. Also report expected solve for uniformly random allocations analytically; the realized blind schedule is seeded before outcomes and comparisons will not choose a favorable seed.

Primary endpoint: all the publisher's sanitized assertions pass on the generated program, with its test_imports and a 5s/192MiB bounded process. Secondary: valid reference and failing stub subset, solves by changed/identical and direct paired read value; attempted source reads, delivered bytes and native prompt/output token counts (shared writer charged to model-note and uncertainty policies; raw prefix skips model writer), wall time, token caps, exact discordances. Reference body used only after prediction seal; tests evaluated in separate harness, not shown to actor. Count policy restriction, absent entry point, exception, timeout and truncation as failures, show separate statuses. Cold model/runtime startup excluded and reported separately. Main paired percentage-points with exact two-sided discordance sign test and 95% paired task bootstrap stratified by version (10,000 draws, seed 18062026); replication reported separately, no pooling required. No superiority assertion from a non-significant or imprecise result. Descriptive secondary contrasts, no multiplicity-adjusted inferential claim. This evaluates an adapted memory handoff on short public tickets, not the published few-shot MBPP protocol and not a comparison against an external end-to-end agent. Keep all requests, response bodies, generated programs, raw statuses, source hashes and ordering.

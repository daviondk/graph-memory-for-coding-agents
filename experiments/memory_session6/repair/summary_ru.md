# Когда кодовому агенту стоит перечитывать условие

**На основной выборке** маршрутизация по хешу решила 44 из 64 задач, слепой контроль — 44 из 64. Число повторных чтений в каждом условии равнялось 32. Парная разница 0,00 п.п., 95% стратифицированный бутстреп-интервал [-4,69, +4,69], выигрыши/потери 1/1, точный двусторонний p = 1,0000.

**На отложенной выборке** маршрутизация по хешу решила 26 из 32 задач, слепой контроль — 21 из 32. Число повторных чтений в каждом условии равнялось 16. Парная разница +15,62 п.п., 95% стратифицированный бутстреп-интервал [+3,12, +28,12], выигрыши/потери 5/0, точный двусторонний p = 0,0625.

Google Research опубликовала исходную и вручную проверенную редакции одних и тех же задач MBPP. Исходное описание физически читалось до сброса контекста. Новое условие поступало в запрос Qwen только при перечитывании. В текстах изданий встречаются изменения требований, уточнения и редакторская правка. На каждом этапе модель видела неизменный публичный интерфейс. Референсные тела, списки тестов, ожидаемые ответы и обратная связь от оценщика в её промпты не входили. Примеры внутри авторской прозы сохранялись. [Корпус и авторский протокол](https://github.com/google-research/google-research/tree/f82046ba5aabbbb427dbfd38a254d26bff08b533/mbpp), [статья MBPP](https://arxiv.org/abs/2108.07732).

Из 257 проверенных задач тестовой части условия отбора прошла 221, включая 101 изменённое описание и 120 неизменённых. После заранее указанного хеширования выделено 64 задачи в основную и 32 в отдельную проверочную выборку. Оба среза содержат поровну изменений и совпадений. Из состава исключены 16 задач, описания которых просматривались при проверке структуры данных. Для каждой задачи была одна детерминированная генерация каждого отличающегося запроса. Репликация разделена по заданиям и использует тот же корпус, модель и процедуру.

Перед сбросом Qwen формировала заметку и оценивала неоднозначность исходной заявки по шкале 0–100. Максимум памяти составлял 40 токенов текста плюс сигнатура. Сравнение байтовых SHA-256 использует отдельный индекс текущих ревизий. В память метода входит и прежний 32-байтный SHA. Для слепого расписания SHA истории не нужен. Роутер распределяет перечитывания, после чего декодер получает либо актуальное полное описание, либо один из двух вариантов памяти. Выбор по неоднозначности использует упорядоченный пакет заданий, гибрид выдаёт три четверти своих чтений изменённым описаниям, остальные неизменённым. Внутри каждой группы он берёт наивысшую оценку неоднозначности.

На проверочной выборке положительный контроль Google прошёл 32 из 32, отрицательный — 0. Повреждённых JSON-заметок с подстановкой исходного текста — 0. Медиана размера заметки Qwen 30,0 токенов, дословной записи — 15,0. Суммарное время запросов при раздельном исполнении политик по сохранённым временам отклика составляет 180,4 с для SHA с заметкой, 142,3 с для SHA с дословной записью и 142,3 с для полного текущего текста.

За две когорты выполнено 336 различных нативных вызовов Qwen3.8-27B UD-Q4_K_M на NVIDIA RTX 3090 из 384 запросов фаз записи и чтения с учётом повторов. Фактически обработано 34 740 входных и 36 957 выходных токенов за 1014,5 с суммарного времени HTTP-запросов. Параллелизм сервера 1, температура 0, seed 18112026, для каждого варианта программы максимум 416 выходных токенов. Решающие политики воспроизводятся офлайн из действительно сгенерированных ветвей. Девять политик не означают девять независимых серий генерации.

У двух политик первичного сравнения одинаковы модель, число записей и решений, верхние пределы токенов и число чтений. Переданная длина условий и фактически израсходованные токены различаются. Время включает вызов писателя для политик с заметкой; копирование дословного текста не требует LLM. Отдельные байты и токены посчитаны в results.json и item_results.csv. Для выбора по SHA нужен доступ к версии каждого источника. При вынужденном хешировании всех документов экономия касается текста, отправляемого модели; при наличии индекса объекта в VCS его формирование может быть общей инфраструктурной операцией.

Размер эффекта относится к коротким англоязычным заявкам из одного публичного корпуса, где модель могла ранее видеть задачу. В опыте не измерялись долговременные изменения репозитория, самостоятельное обнаружение изменённых файлов, сохранение плана многошагового исправления, другие модели или вариация по seed. На дополнительные проверки действовал предел 5 с и 192 МиБ на процесс; все диагностические коды, ограничения синтаксиса и таймауты доступны в файлах оценок. Перепроверка хешей, исходных промптов, декодированных программ и присоединения результатов выполняется командой из REPRODUCE.md.

## Что влияет на численную разницу

У всех 96 заданий исходный текст занимал от 8 до 39 токенов и целиком помещался в предел 40. На 94 заданиях модель записала заметку длиннее оригинала. Копирование исходного текста вместе с SHA воспроизвело все запросы полного чтения и сэкономило ровно половину повторных загрузок. Число входных и выходных токенов решателя в этих двух условиях совпадает до единицы. На 63 из 96 исходных заявок Qwen присвоила неоднозначности одну и ту же оценку 15 из 100; порядок разрешения совпадений влиял на распределение чтений.

В основной выборке преимущество маршрутизации по SHA над заранее выбранным слепым расписанием равно нулю. На отложенных заданиях есть пять парных выигрышей, три на действительно изменённых описаниях и два на неизменённых. В четырёх из пяти случаев проигравшая ветвь достигла лимита 416 выходных токенов и дала синтаксически незавершённый файл. Такие исходы объясняются в том числе взаимодействием формулировки и бюджета генерации. При пяти дискордантных парах точный двусторонний тест даёт 0,0625; положительная нижняя граница обычного бутстрепа по задачам чувствительна к отсутствию наблюдавшихся проигрышей.

Ограниченный исполнитель заблокировал два исходных эталона в основной когорте. В задаче 264 встречался вызов exit, в задаче 307 — импорт deepcopy. На срезе остальных 62 задач разница SHA+заметка и слепого расписания составила 0 п.п. Все 83 усиленных эталона EvalPlus прошли. На MBPP+ исключение задач с таймаутом любой ветви или контроля оставило 54 основных задания и все 26 проверочных; выводы главного сравнения при этом сохранились.

При полном повторном исполнении совпали все 480 строк статусов MBPP и все 498 строк MBPP+, включая положительные и отрицательные контроли. В пределах одного задания байтово одинаковые программы тестировались один раз.

По собственному журналу сервер был готов принимать запросы через 17,33 с после запуска. Это время вынесено из длительности генераций. В 58 аппаратных замерах на основной генерации максимальное наблюдавшееся использование видеопамяти всей видеокарты достигло 16 966 МиБ. Программные и модельные SHA-256 находятся в runtime/confirmed_binaries.json.

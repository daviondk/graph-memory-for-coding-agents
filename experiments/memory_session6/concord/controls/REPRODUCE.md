# Воспроизведение пяти локальных политик ConcordBench

Закреплённый upstream — FFFFFFFANG1/Concord, git 4116936349995f0f30597931c0dbbebcbf7e58ac. Сопоставление режимов опубликовано в README.md на строках 168–174. Для Oracle авторский eval_pioneer.py оставляет race_controller=None, когда файл патчей не задан. Внутреннее имя reread реализовано как немедленный NotImplementedError. Отличие проверяется отдельным прямым вызовом на чистом материале без обращения к LLM.

Полностью автономная сверка чисел, ответов и парных сравнений для компактной поставки использует только Python и файлы util.py, verify.py, cases.json.gz, native_index.json.gz и results.json. Файлы с _with_highlight проверяются при наличии.

```powershell
python -B verify.py
```

В полной рабочей папке для повторения хода каждого агента по сохранённым нативным ответам используйте закреплённую зависимость concord/venv и локальные исходники upstream. Кэш родительского опыта и все кэши controls только читаются. Программа заново материализует чистый корпус в системном временном каталоге, проверяет все 120 последовательностей побайтовых хешей запросов, переданные инструменты, возвращённые тексты, решения и число актуализаций. Для дополнительной сверки исходных файлов сравнивает начальные SHA корпуса, которые видят все три способа.

```powershell
$env:PYTHONUTF8='1'
../venv/Scripts/python.exe -B offline_actor.py
../venv/Scripts/python.exe -B judge.py --verify
../venv/Scripts/python.exe -B analysis.py
../venv/Scripts/python.exe -B analysis.py --highlight
../venv/Scripts/python.exe -B report.py
python -B verify.py
```

Ветка --highlight требует завершённых 80 траекторий и слепого судьи соответствующих соседних экспериментов. Режим --verify судьи гарантирует отсутствие сетевых вызовов. Первичный и дополнительный способы оценивания разделены. Идентичные запросы к инструментальному актору проверяются по SHA полного тела с сообщениями, системным промптом и схемами инструментов. Ключ слепого судьи — SHA видимых ему сообщений; полные параметры модели отдельно проверяются при чтении нативного ответа.

Независимую генерацию проводите на копии исходной структуры папок с установленными upstream-зависимостями. Скопируйте исходные родительские таблицы, trials, calls, исходники и общий benchmark. В пустой controls-папке скопируйте PROTOCOL.md, util.py, run.py, judge.py и программы анализа. Задайте PYTHONUTF8=1, дождитесь локального Llama.cpp на 127.0.0.1:18961 с исходным Qwen3.8-27B (настройки включают --jinja, 8192 контекста и один слот). Запустите run.py, затем judge.py, analysis.py, offline_actor.py, verify.py, report.py. Производительность железа, время очереди, плавающий предел контекста и реализация нативного сервера влияют на стоимость. Журнал ENCODING_RESTART.md описывает перезапуск после ошибки Windows в первом процессе.

Сырые трейсы трёх новых режимов находятся в trials, собственные ответы сервера — в calls, а начальные повторно использованные ответы — в ../calls. По каждой исходной реплике сохранены tool-call ID, аргументы, получили ли инструменты ответ и фактический текст наблюдения. В таблице case-level представлены пропущенные метрики и неполные журналы. judge_assignments.json.gz и judge_receipts.json.gz позволяют восстановить оценку, не вводя метки политики в независимый вызов судьи. Полные файлы первоначального source, dependency lock, GPU хеши и учет ядра модели лежат в соседних материалах серии.

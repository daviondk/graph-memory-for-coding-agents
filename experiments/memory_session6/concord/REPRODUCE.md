# ConcordBench score replay

From this directory run `python verify.py` to independently check raw answers, judge counts, token receipts, all pairings and costs using the Python standard library. Run `python grade.py --offline` (Python + NumPy) to reproduce all 10,000 case-bootstrap intervals, exact paired sign tests and published/local summaries. These offline commands require grade.py, verify.py, published_projection.json.gz, published_results.json, local_projection.json.gz, call_projection.json.gz and local_results.json. The compact projections carry raw final answers, task IDs, gold answers and reported judge decisions or native costs. Full raw prompts and conversations stay in the source/trial receipts. The verifier makes no requests to a model or the internet.

For author-side extraction, check out https://github.com/FFFFFFFANG1/Concord at 4116936349995f0f30597931c0dbbebcbf7e58ac into upstream/ and run `python grade.py --public-only`. It reads the original and judged archive for all 15 combinations, verifies the final answer and gold in both files against the roster, checks every original EM and F1 against fresh scoring, and stores the archive SHA256 values. The LLM judge verdict is read from the archived judge output, not reevaluated by a new LLM. Text normalization matches qa_agent.eval_pioneer (case, US ASCII punctuation, English articles, whitespace), F1 uses token multiplicity. All 40 cases contribute to each arm. There is no new local external judge.

To reread the original local logs, run `python grade.py` once experiment.py has written decision_lock.json for all 120 trials. Every gzipped trial receipt is checked against that lock; every request message is hashed against the native response filename. Logical token counts count each call reference as though each policy ran separately. The unique physical request inventory covers deduplicated final-run keys; prior failures and unreferenced receipts are counted separately. Prefix-cached tokens reported by the model server are also separate. Missing response/transport receipts and incomplete event counts remain observable. In cost contrasts missing data are excluded pairwise; the number of eligible cases is given for every contrast. Timing measures server-reported prompt plus generation time, excluding transport and disk overhead. Exact/verbose answer metrics and official judge recoveries are distinct.

All three local pairings are ordered window minus baseline, window minus raw, and baseline minus raw. The primary contrast is the first. Bootstrap uses 10,000 common whole-case resamples and seed 20261118, retaining all zeros and repeated cases. Sign tests are exact two-sided binomial tests on discordant cases. Reported auxiliary comparisons and confidence intervals are descriptive, without multiple-comparison correction. For exact request-sequence identity, order and multiplicity count; a shared prefix alone does not make the whole trial identical. Reused responses arise only from an exact request-content hash. The cases assigned to different-input subsets are selected by the intervention and are descriptive.
With the upstream benchmark dependencies installed, run python official_crosscheck.py to invoke the pinned official exact_match and token_f1 functions directly on all 720 final answers after both projections exist. python report_results.py recreates the Russian summary from the checked local and published results.

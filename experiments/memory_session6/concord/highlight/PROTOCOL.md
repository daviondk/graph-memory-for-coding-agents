# Mark a correction in an observed source return

Exploratory follow-up registered after the first extension had zero opportunities and after primary Qwen quality was known. This is not an independent test on new questions. The Hotpot tool registry exports no span in the mutable verbatim records, but it does preserve original tool text and current rematerialized model-visible evidence. No gold, answer, case ID, mutation schedule or private race annotations may drive a cue.

Before starting any new inference, check a deterministic fallback order on CPU using original Concord message inputs and original tool returns. A. Prefer detecting that a tool return actually appeared in a *previous model prompt* and was then replaced by different nonempty text at the same tool-call ID. B. If A occurs on fewer than 10 of the 40 baseline trajectories, use the first prompt where a nonempty, already executed tool return has changed from its originally returned text in the trusted runtime to the current rematerialized version. In B explicitly distinguish the observed tool output from proof that the model previously saw its old form. Ignore punctuation/whitespace-only rearrangement, source removals without replacement, and formatting of multi-hit grep. If neither qualifies, freeze a further revision before inference; never run different fallback rules on different tasks.

Source unit is an individual previously emitted tool return. Compare its original and newly rendered token sequences; retain a nonempty inserted/replaced alphanumeric phrase, prioritizing the last genuinely affected tool return in message order. Cap at the first 16 new whitespace tokens and 120 UTF-8 bytes. Locate a stable document path from public tool arguments/content (when several, use the matching path aligned with the changed passage where available, otherwise use tool name; no future state). Re-emit only new content. One short suffix appended to the same latest provider-facing message (after upstream refresh notice when present, otherwise a separate user status message); normal evidence and notices stay as in official Concord. The same fixed prefix/suffix shape and same triggering algorithm apply to both arms. Mark the event as served once across later requests in that trajectory. Multiple simultaneous revisions get at most one update per model request; record all candidate events and consumed ones. The equal-budget control uses the same locator and an unaffected token span in the current message, matched to number of words and as closely as possible UTF-8 bytes (no target words where possible). A generic acknowledgement is fallback if no unchanged tokens exist. Both arms receive current true text, no deliberately stale alternatives. Audit actual Qwen prompt token costs rather than asserting exact token-matching of textual spans.

Primary comparison = correction cue vs unaffected cue, secondary vs the 40 stored stock Concord traces. All 40 questions, both new arms. Exactly same model, roles, decoding, server and 30-event limit; deterministic randomized arm order by case. Reuse exact original request payload receipts from the previous run read-only, store all other receipts in this extension. Measure exact match, F1, whole-case paired intervals/sign test, submitted answers, tokens, actions, number and length of cue emissions. Showing an already materialized buffer adds zero source-file rereads; include source-file reads the acting model requested and observed source restoration events. Track actual opportunities reached in each arm because policies may diverge. Lock all answers before reading new grades, and deliver paired answers for an independent blind judge. No sending to an external evaluator. Record the CPU eligibility test, chosen mode, implementation hashes, numerator for rendered prompt differences and any implementation corrections.

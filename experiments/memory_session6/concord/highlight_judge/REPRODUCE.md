# Дополнительные 80 семантических оценок

Собраны ответы всех 40 пар correction/control из ../highlight/answers_for_judge.json после фиксации траекторий. Запросы того же формата, что в ../judge. decision_lock.json для каждого действительно использованного файла включает каталог-источник и SHA-256. Часть одинаковых запросов могла выполняться в двух локальных очередях до появления первой квитанции. Расход учитывается по физическим файлам. Офлайн-проверка назначения вердиктов из реально выбранных квитанций выполняется `python -B ../judge/audit.py`. Сводные парные разности — `python -B verify.py` (NumPy).

Одинаковые неразобранные ответы обеих ветвей учитываются совместно при построении границ эффекта; вердикт при максимальных 384 токенах остаётся неопределённым. Локальная модель совпадает с решателем. Объективные EM/F1, действие подсказок и стоимость исходных траекторий оцениваются независимо в ../highlight. При новом запуске порядок появления файлов кэша может отличаться; lock фиксирует фактически использованные первичные квитанции данной серии.

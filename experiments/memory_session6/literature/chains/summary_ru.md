# Как отделить обучение от проверки на цепочках настоящих задач

Для проверки эффекта памяти на исполняемых тестах проверена разметка ChainSWE. В EMNLP 2026 описаны 304 issues и 54 Python-проекта. Закреплённый публичный выпуск имеет собственный состав. В конфигурации unique пересчитаны 213 уникальных идентификаторов цепочек, 956 позиций, 661 уникальная пара «репозиторий и issue» и 80 строковых имён репозиториев. В объединении трёх длин 376 цепочек и 1 504 позиции. В обеих совокупностях одинаковое число различных issue и упорядоченных соседних пар (534). Сравниваясь с авторами, надо установить конкретный список примеров из их прогона. [Статья ChainSWE](https://aclanthology.org/2026.emnlp-main.371/) · [Зафиксированные данные](https://huggingface.co/datasets/C-lister/ChainSWE/tree/dcaa484eca5b38caca71420712b1b194c1235d6e)

Одинаковые задачи встречаются в различных цепочках раздела unique. При нашем детерминированном разбиении по цепочкам на пять частей 118 из 213 проверочных цепочек содержали issue, доступный в обучающих частях той же итерации, 109 имели по меньшей мере одну общую соседнюю пару. Всего совпали 439 из 956 позиций. При разделении по репозиториям совпали 0 позиций. Это измерение риска для будущего обучения маршрутизатора. Опубликованным результатам ChainSWE здесь не приписывается утечка. Проверка читает только пять полей метаданных и ничего не выполняет из набора. Команда для офлайн-пересчёта — `python -B check.py`. Для повторного извлечения с проверкой четырёх SHA-256 — `python -B check.py --fetch`, зависимости requests и pyarrow.

**Предпочтительный тест для результата на коде.** Зафиксировать тестовые репозитории до подбора момента перечитывания. Создать пару продолжений из *одинакового* состояния файлов и журнала до вмешательства. Проверить последний запрос и накопленные регрессионные тесты раздельно; посчитать физические и логические чтения, токены, обращения к уже исправленным местам и количество изменённых входов. Несовпадение состояния репозитория способно дать эффект масштаба всей исследуемой прибавки. В SWE-Maintain на 100 трёхэтапных эпизодах средняя разность между наследованием собственных предыдущих патчей и патчей разработчика составила −5,6 п.п. по следующему заданию и −14,0 п.п. при требовании пройти ранние тесты. После ограничения рабочим исходным кодом и ещё нерешёнными задачами разница составляла +2,7 п.п. с интервалом [−0,5; +6,1]. [SWE-Maintain](https://arxiv.org/abs/2610.14768)

**Ещё две постановки для выбора.** VibeMemBench проверяет перенос опыта на 111 задачах из 90 репозиториев, с 3 634 завершёнными историческими траекториями. Опорная когорта специально отобрана по положительному эффекту опыта у одного решателя; оценить на ней распространённость полезных записей среди всех обращений нельзя. CompactionBench проверяет момент сжатия внутри продолжительной сессии на последовательностях с исполняемыми тестами. Полезный контроль из APEC — асинхронное резюмирование завершённых шагов с сохранением неизменяемого префикса и последних действий. Его учёт времени и кеширования требует отдельно закрепить порог сжатия и режим конкуренции за вычисления. [VibeMemBench](https://arxiv.org/abs/2609.23570) · [CompactionBench / APEC](https://www.microsoft.com/en-us/research/wp-content/uploads/2026/10/CompactionBench_preprint.pdf)

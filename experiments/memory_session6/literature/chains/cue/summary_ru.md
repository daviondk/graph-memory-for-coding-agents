# Один указатель файла по текущей задаче

Названия ранее изменённых файлов оказались более полезной подсказкой, чем добавление слов из прежних задач. На 374 следующих задачах из 77 репозиториев совпадение слов текущей задачи с компонентами пути правильно выбрало один изменённый файл 175 раз. Выбор по давности дал 154 попадания. Разность составила +5,61 процентного пункта с 95%-м интервалом по репозиториям [+2,58; +8,55]. Обогащение пути полной лексикой последней задачи дало 147 попаданий.

Основной новый метод сначала переносил до четырёх совпавших слов из предыдущей восьмёрки для того же пути. Затем заполнял свободные места частыми словами нового описания. Он получил на пять попаданий больше, чем правило восьми частых слов. Разность +1,34 п.п. [0,00; +2,98], шесть побед, одно поражение, 367 ничьих. Оба варианта выбрали разные пути на 20 задачах. На этих 20 попаданий было 9 против 4. Наборы сохранённых слов разошлись для 234 из 1 619 записей кэша и хотя бы для одной записи в 171 задаче.

Для основной разности шесть репозиториев дали положительный итог, один отрицательный и 70 нулевой.

## Что и сколько читали

Для каждого из тех же 374 префиксов воспроизвели кэш прежнего исследования записи с пределом восемь production-файлов Python. Состав кэша для каждой задачи сверили по всем ID с прежним замком. После двух, трёх или четырёх завершённых задач кэш содержал от одного до восьми файлов. В 55 задачах оставался единственный кандидат. Всего на 374 момента выбора пришлось 1 619 резидентных записей. Восемь кандидатов имелись в 64 задачах. Хотя бы один действительно изменённый файл был доступен в 233/374 случаях. По этому условному знаменателю попадания правила по пути составили 175/233. Каждый метод выдал ровно один указатель на задачу, включая недостижимые случаи.

При обработке прошлых завершённых задач из patch извлекались только заголовки путей. Из текущей задачи читался текст предъявленного пользователем описания. Англоязычные слова и идентификаторы, их компоненты camelCase и snake_case хешировались в 96 бит. Лексика пути включала компоненты директорий и основу имени файла. Оценка пути и оценка прошлой заметки по отдельности суммировали IDF совпадающих слов внутри текущего кэша. Для сложного правила две оценки складывались с единичными весами. Ничьи разрешались по давности, затем по ID файла. Исходные слова, пути, содержимое файлов и патчи в артефакты не записывались. Входные данные не исполнялись.

У трёх компактных правил количество сохранённых слов совпало на каждом префиксе. Таблица учитывает 12 байт на ID и отдельную запись для каждого пути. Учитывать объекты Python, адреса, выравнивание, сжатие либо устранение дубликатов необходимо отдельно для физической реализации. У path-only также есть стоимость хранения или вычисления собственных компонентов пути — 6 200 ID суммарно на 374 снимках, в среднем 16,58 ID или около 199 байт. Это общая база правил с лексическим поиском. Новому методу нужны до восьми слов предыдущей резидентной записи, при её вытеснении они пропадают. За все проигранные префиксы он просмотрел 4 583 предыдущих ID и внёс 17 146 новых ID слов. Простое обновление по частоте внесло 17 616. Получение уже видимого описания не требует дополнительного чтения исходного файла. На этом испытании учитывался один логический выбранный указатель; фактического чтения среды разработки или запуска исправления не было.

## Источник и воспроизведение

Использован открытый файл unique.parquet ревизии dcaa484eca5b38caca71420712b1b194c1235d6e. Общий префикс, прежнее исключение чувствительных эпизодов и выбор одной истории на следующий issue сохранены. Подходящие префиксы заранее отобраны по протоколу исследования записи. Проекция читает историю каждого случая только до его цели. Решения по всем шести правилам заморожены до открытия файла будущих путей новым оценщиком. Длинные цепочки могут повторно использовать одну прошлую задачу. Ресемплирование выполнялось парно по 77 целым репозиториям, 10 000 повторов, seed 18112026. Интервалы описательные, без поправки на множественные сравнения. Это второй разведочный этап на уже исследованной выборке, с фиксированными до расчёта лексическими правилами. Одна и та же реплика задачи могла содержать пример кода, который обрабатывался исключительно как текст. Предсказание membership следующей разработческой правки отличается от официального результата выполнения ChainSWE. Подсчёты относятся к публичному файлу unique, тогда как аннотация статьи описывает 304 задачи и 54 проекта. [Статья ChainSWE](https://aclanthology.org/2026.emnlp-main.371/) · [Данные на фиксированной ревизии](https://huggingface.co/datasets/C-lister/ChainSWE/tree/dcaa484eca5b38caca71420712b1b194c1235d6e/data).

Команда `python -B verify.py` повторяет прогнозы на обезличенных признаках, проверяет блокировки, прошлый состав кэша, размеры памяти и все парные итоги на стандартной библиотеке Python. Команда `python -B grade_cues.py` повторяет оценки и все интервалы с NumPy. Для повторной выгрузки требуются requests и PyArrow. Порядок полного запуска — project_cues.py, predict.py, grade_cues.py, verify.py. Используются родительские файлы write/retain.py, write/project.py, write/decisions.json.gz, write/decision_lock.json и write/gold.json.gz. Полный текст результата, его исходная идентичность и SHA-256 сохранены в отдельных артефактах.

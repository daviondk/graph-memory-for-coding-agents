# Стоит ли читать заметку только при ничьей по именам файлов?

На внешних задачах SWE Context Bench правило с чтением коротких заметок при ничьей не улучшило выбор одного файла. В зарегистрированном сравнении по датам открытия PR простой поиск по пути дал **38/219** попаданий, правило с заметками — **37/219**. Дополнительная проверка ограничила историю патчами, уже слитыми при открытии целевого PR. На таком материале обе политики дали **35/218**, разность 0,00 п.п. с 95%-м интервалом [−3,51; +2,70]. При этом правило с заметками выбрало другой файл в 60 задачах. В пяти помогло, в пяти навредило.

## Условия и результаты

Для каждого текущего запроса кэш хранил не более восьми путей из завершённых задач. Каждое правило выбирало один файл. Базовый метод сопоставлял слова текущего описания со словами имён и директорий и разрешал ничью по давности и хешу. Новое правило читало до восьми слов из записи каждого пути, разделившего первое место; при единственном лидере дополнительные чтения отсутствовали. Среди кандидатов с равным баллом слова ранжировались по IDF. Слепой контроль на тех же событиях читал те же записи, но переставлял между кандидатами их привязки. Ранее изученное «общее сложение» складывало оценки пути и заметки для всех резидентных файлов.

Внешний материал использовал только официальный выпуск, одну запись на цель и одинаковые кэши для всех методов. В основной истории выбирались до восьми последних по времени создания задач Experience того же репозитория, без запроса к таблице релевантности. Напротив, прямые связи авторов задают благоприятный контекст. Все 76 таких целей входят также в основную внешнюю выборку и оцениваются отдельно. Более высокая достижимость 56/76 в режиме прямых связей отражает выбор источников. У всех 76 был ровно один пригодный эпизод опыта. Слова его описания одинаковы у всех одновременно изменённых файлов. Они дают нулевой IDF внутри ничьей — изменить выбор в этом случае невозможно. То же верно для всех 125 вторых задач ChainSWE. Из них у 123 текст либо идентификатор раньше уже встречался *в истории* исходных примеров, но ни одна не являлась их оцениваемой целью.

Ничья с положительным баллом имени файла и отсутствие различающего лексического совпадения дали разные результаты. На первых 219 целях было 107 единственных лидеров, 52 положительные ничьи и 60 ничьих при нулевом балле. Среди 52 правило помогло один раз, навредило четыре раза. Среди 60 — четыре и два раза. В 18 из 60 вообще отсутствовало совпадение слов пути с запросом, на остальных 42 совпавшие слова были общими для всех записей. В 18 случаях без буквального совпадения восемь выборов изменились, число попаданий осталось тем же. На строгих 218 были 107 единственных лидеров, 45 положительных и 66 нулевых ничьих, соответственно 0/0, 1/3 и 4/2 побед/поражений. Эти разбиения описательны и имеют мало расходящихся результатов.

## Проверка доступности патчей по времени

У файлов Related/Experience есть created_at и base_commit, но нет merged_at. В исходном сборщике SWE-bench created_at берётся из даты открытия PR. Для четырёх детерминированно выбранных целевых примеров мы дополнительно сверили собственные журналы GitHub: во всех четырёх дата выпуска совпала до секунды с открытием указанного авторами PR. При наличии ссылки на issue его дата открытия могла быть другой. На 362 строках связей у 361 experience с разбираемым PR URL суффикс ID совпал с номером PR; у Related совпало лишь 31/362. Для цели использовалась явная ссылка авторов. [Исходный сборщик SWE-bench](https://github.com/SWE-bench/SWE-bench/blob/main/swebench/collect/build_dataset.py) · [Описание полей Pull Request в GitHub](https://docs.github.com/en/rest/pulls/pulls#get-a-pull-request).

Для 592 уникальных исторических PR в объединении анализируемых полок получены точные timestamps слияния. Для 551 время дал публичный архив событий GitHub, для 41 недостающего — первичный REST API GitHub. Шесть дополнительно проверенных архивных дат совпали с первичными ответами, конфликтов не обнаружено. На 219 основных целях встретилось 559 уникальных исторических PR и 1591 связь «прошлый PR — цель». Из них 1436 уже были слиты к открытию целевого PR, 155 ещё не были слиты. У 108/219 целей отсеялась какая-либо ссылка, у одной после этого не осталось ни одного пригодного файла. Во всех 219 знаменатель доли остаётся известным: по 35 попаданий и одному общему воздержанию в строгом варианте. При ограничении на непустой подтверждённый кэш результат 35/218.

Строгая чувствительность использовала исходные выбранные полки без дозаполнения более ранними PR. После удаления поздних связей оставшиеся задачи упорядочивались по времени слияния. У 112 доступных полок порядок изменился. В 111 целиком подтверждённых историях выбор только по пути и правило при ничьей дали по 22 попадания, в 107 частично сохранённых — по 13. С сохранением прежнего взаимного порядка тех же подтверждённых задач результаты составили 34/218 по пути и 35/218 с заметками. В режиме прямых связей 11 из 76 прежних PR ещё не были слиты; остаётся 65 с доступной историей. Это проверка существования публично слитого патча на момент открытия целевого PR. Наследование патча конкретным base_commit и его наличие на момент первоначального открытия пользовательского issue требуют дополнительных условий.

В Related есть пять повторяющихся целевых ID. У двух групп различается текст, у одной — патч и время открытия. Исходный протокол заранее выбирал первую строку. Сверка всех 228 замороженных дат с независимым инвентарём выявила единственную расхожую дату из-за выбора последней строки в первой версии инвентаря. Пересчёт в этой записке и strict_results.json использует первую строку каждой группы и подтверждён по обеим выгрузкам дат. Устаревшая дополнительная версия сохранена в strict_revisions. Первичное сравнение на 219 задачах не менялось. ## Вычислительная цена и обобщение

Поиск по пути делает ноль чтений сохранённых лексических заметок. В зарегистрированной внешней группе новое правило открывало заметки на 112 из 219 задач, всего 538 записей и 4304 хеша слов. Глобальное сложение просматривало 1537 записей и 12 296 хешей. В строгой группе правило обращалось к заметкам в 111/218 случаях, 523 записи и 4184 хеша; глобальный метод — 1416 записей и 11 328 хешей. Стоимость слепого контроля совпала с правилом при ничьей по каждой задаче. Хеш имеет номинальную длину 12 байт. Размещение объектов, общие префиксы, кэш оборудования и извлечение компонентов пути не переводились в физическое время. Потребность в дополнительных чтениях исходного файла для оценки заметки равна нулю. Один выданный путь — логическое действие, его содержимое моделям не отправлялось.

В полном авторском выпуске 1007 Experience, 362 строки Related с 357 уникальными ID и 362 явные связи. После фильтра чувствительных описаний исключены шесть целей, после проверки идентичности с исходными 374 — ещё две. У 42 отсутствовала подходящая более ранняя задача, у 79 не было файлов в кэше и у 9 из 228 замороженных целей отсутствовал целевой production-файл Python. Для прямых связей 79 решений прошли замок, 76 получили оценку. Из 10 внешних репозиториев 6 также представлены в исходных 374 ChainSWE. Из 219 внешних целей 33 относятся к четырём новым репозиториям; только одна цель раньше встречалась в истории исходных примеров. Проверялись точный ID, пара репозиторий/PR и хеш нормализованного текста. Исходные 374 уже были изучены при формулировке правила.

Интервалы получены 10 000 парных выборок целых репозиториев при seed 18112026. При 10 внешних репозиториях и небольшом числе несогласных попаданий интервалы следует читать вместе с абсолютными числителями. При структурном совпадении всех решений парная разность в измеренных задачах точно равна нулю. Предсказание одного файла следующей правки по прошлым разработческим правкам не оценивает выполнение тестов, устранение дефекта или соревнование с опубликованными агентами.

Источники и протоколы доступны в этой папке: PROTOCOL.md для исходного gate, STRICT_PROTOCOL.md для временной чувствительности, decisions.json.gz и strict_decisions.json.gz для замороженных выборов, scores.json.gz и strict_scores.json.gz для пообъектных итогов. Стандартная библиотека Python выполняет `python -B verify_gate.py` без сети. NumPy нужен для `python -B grade_gate.py --offline` и полной проверки строгих интервалов командой `python -B strict.py`. Для повторной первичной проекции на сеть и PyArrow опираются sources.py, grade_gate.py, date_semantics.py и strict_cutoffs.py. Входные данные парсились как текст и заголовки путей, код проектов не выполнялся.

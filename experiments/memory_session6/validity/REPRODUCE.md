# Воспроизведение

В папке validity выполните `python -B verify.py` (Python 3.11+ и NumPy). Программа сверяет закреплённые хеши входов и решений, заново создаёт каждое решение писателя в отдельном временном каталоге и сравнивает распакованные потоки целиком. Затем проверяет точный результат поиска по истинным снимкам, стоимость и интервалы по репозиториям, частоту фактических повторов и декодирование каждого пакета для 378 более ранних переходов.

Для восстановления из публичной истории выполните fetch.py, prepare.py, natural_project.py, run.py и score.py в отдельной копии, сохранив source_lock.json, real_intents.json и обе фиксации протокола. Для более ранней последовательности запустите stream/fetch.py, stream/project.py, stream/sim.py. Даты коммитов, ветви и заголовки сайта могут меняться, ориентиром служат зафиксированные Git SHA. Код проектов при извлечении не исполняется.

Парсер действительных обращений приведён в intents.py и exposure.py. Извлечение из исходного Parquet требует PyArrow, архивов ранее отобранных записей memory_session5/packets и публичных шардов в memory_session4/compact/.scratch. Адрес набора, LFS-хеши и привязки к строкам находятся в real_intents.json, хеши проекций предыдущего этапа в intent_receipt.json. Всё нужное для основной офлайн-проверки уже включено. Поля затрат являются байтами кода или протокола и логическими/физическими чтениями в указанных таблицах. Частоты реального повторения проверяются отдельно от условных симуляций.

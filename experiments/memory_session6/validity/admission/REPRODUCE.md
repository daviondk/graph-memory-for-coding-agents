# Воспроизведение и аудит

Опыт использует только стандартную библиотеку Python. Полные shell-команды не извлекались из архива и не исполнялись. Обязательный вход — соседний ../exposure.jsonl.gz с SHA-256 0dfd59bceac0c6a5bac7ccdf082d358fe911b647c3e963b620c2cb6ec0772605. Родительский exposure.py описывает точное извлечение этих хешей из опубликованных SWE-smith траекторий. Для нового каталога сохраняйте взаимное расположение файла и этой папки.

```powershell
python -B verify.py
python -B report.py
```

verify.py создаёт чистую временную копию реализации и входа, пересчитывает журналы решений/результатов, проектные таблицы и контроль сопоставимой стоимости и сверяет их побайтно. Дополнительно отдельная реализация LRU проверяет все три размера кэша на полном тексте команд. Формулы проверяются полным перебором возможных рангов bottom-k и выборов ключей Bernoulli на малых примерах.

Первый дизайн и SHA входа зарегистрированы в design_lock.json до симуляции. В decisions.jsonl.gz по каждой траектории хранится координата исходника и последовательность решений. Порядок внутренних массивов определяется run.py, ключевая идентичность cmd затем id, размер 1, 2, 4, далее never, lru, lfu, twohit, edit_twohit, bottomk. Семь полей каждого решения — найденные ключи до обновления, новые полноценные регистрации, записанные ключи, предварительные записи, вытесненные ключи, повышения предварительной записи и итоговые зарегистрированные ключи. После записи SHA в decision_lock.json отдельный grade.py соединял журнал с повторами и выяснял, какая регистрация получила следующие посещения.

Таблица trajectory.jsonl.gz содержит исходные координаты, проект, знаменатели и метрики каждой политики для каждой траектории, включая строки с нулевой экспозицией. Таблица projects.json содержит те же показатели по всем проектам. Таблица policy_table.csv даёт готовые значения для публикации и помечает фронт Парето; отдельно в pareto.json перечислены недоминируемые правила. Равномерный аналитический контроль даёт ожидаемые числа событий и регистраций. Внутреннее значение 0 у полей trajectories_with_hit и trajectories_with_after_edit_hit для uniform_exact является техническим заполнителем: вероятности «хотя бы один hit за траекторию» не вычислялись. Для этого контроля следует использовать только явные ожидаемые поля в policy_table.csv. Реальные прогоны конкретных политик такого ограничения не имеют.

После просмотра первичных результатов отдельный протокол MATCHED_PRELOCK.md зафиксировал более строгий контроль совпадающей стоимости. matched_design.json и calibration_lock.json фиксируют метод и конкретные вероятности допуска на отложенных половинах. Алгоритм получает только ключ в текущий момент; вычисление точного математического ожидания использует размер префикса и историю различных промежуточных ключей. matched_results.json содержит полные условные ожидания по основным срезам и проектам. Наблюдаемые числа и математические ожидания хранятся раздельно.

Один слот в эксперименте — один удерживаемый ключ с небольшими атрибутами политики. Абсолютное число хранимых байтов, цена регистрации, верификации, время реальной команды и пригодность возвращаемого содержимого не определены. Порог в summary_ru.md относится к дополнительно измеренным расходам, с отдельной предельной ценой регистрации поверх цены простой записи состояния.

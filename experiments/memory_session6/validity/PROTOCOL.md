# Reusing an agent's earlier identifier search across real changes
Fixed 18 November 2026 before downloading the selected repository histories or examining the resulting queries/outcomes. Unit: an old complete set of .py paths containing a case-sensitive ASCII identifier [A-Za-z_][A-Za-z_0-9]*, followed by a real change and a request for the same set. Immutable shared file paths, symlinks and submodules excluded; a rename counts as removal+addition. No execution of repository code. Interested in when a source note can be trusted. Baseline scans all changed paths; retained answers and mutations are ordinary runtime state. Model-free systems experiment, separate from live agent benchmark. No claim to invent incremental view maintenance.
Frozen roster of 12 upstream projects: pallets/click, pydantic/pydantic, marshmallow-code/marshmallow, agronholm/typeguard, python-jsonschema/jsonschema, python-attrs/attrs, pallets/jinja, tkrajina/gpxpy, arrow-py/arrow, mahmoud/boltons, pyparsing/pyparsing, mido/mido. Resolve current default branch once and pin HEAD, inspect up to 42 first-parent transitions as chronological pairs, including unchanged episodes. First transition is history warm-up. Query distribution independent of the current change: up to 12 identifiers from the prior transition's affected vocabulary (observed previous activity, regardless of whether still in corpus), up to 12 sampled from outside that set in pre-change files, avoiding Python keywords, length<3 and placeholder dunders. Deterministic SHA sampling. Separate natural workload: up to 24 literal identifiers parsed from real historical search command arguments from earlier SWE-smith traces, same repository only, with no knowledge of this change. Report real-query coverage and denominators separately. No invented missing names in primary sample. Multiple revisions share a repo, bootstrap 12 entire repos paired, report micro rates plus project-level difference and cost.
A run-time fact holds the matching files; richer variant holds occurrence counts when known. Writer can consume per-file inserted/deleted text after the observed mutation and changed-path roster. Encode one per-change shared 512-byte fixed-size summary, independent of requested keys. Primary compare two signed counts (hashed positive/negative counts by path+word; upper bound even on collisions; saturating last bucket means unbounded) with a strong scoped Bloom recording per-file net changes, on number of file reads per query needed to return the exact current result. Check 128, 2,048 bytes. Cheap controls: invalidate changed files, ignore mutations and count wrong answers, literal token touched per file Bloom without net cancellation, direction-sensitive binary Bloom, unbounded per-file exact net delta, and strongest exact comparison of just the new/old changed file content. If whole reads at write time are used for presence-flip Bloom count that effort; do not assume free. All shared metadata incl file path roster common and costed separately; compare marginal message bytes and additional costs to retain counts in the old note. Additional practical competitor: subscriptions — if writer is told names of previously registered notes, compute exact deltas for them and send an invalidation bitmap for the changed answers. Account for registering key bytes and maintaining old multiplicities separately. No gold required at inference; hidden new result checked by exact source snapshot for every decision. Gates that yield a stale answer disqualify. Cost is estimated # files reread plus source bytes; not LLM tokens/dollars or end-to-end solved tasks. Document weak or negative evidence and exact eligibility.

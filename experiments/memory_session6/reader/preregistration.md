# Locked selective memory protocol

Frozen on 2026-11-18 before deriving new per-turn grades, inspecting their distributions or fitting any switch. The earlier SERBench Cal500 aggregate results and design were known. CAsT 2020 is new to this study. No manual rewrites, raw corpus execution, online requests to evaluate answers, or GPU required.

## Estimands

A policy decides whether to request the history-conditioned reader (ON) or use the current-query reader (OFF). Both potential outcomes are observed by deterministic paired replay. The policy sees only the current request and cheap prefix metadata before the request. Conditional-on-replay intervention effects are interpretable; improvement in downstream agents, actual production latency or human outcomes are outside this estimand.

For SERBench use frozen BGE-large, fixed identical visible current-query prefix, ON = the previous study's strongest fixed @5 writer (arguments), OFF = empty. Score official Complete-MSS@5, secondary @8. For TREC CAsT 2020 use organizers' raw vs automatic (never manual) BM25+BERT runs, public NIST qrels, nDCG@3 with trec_eval linear relevance gain, secondary nDCG@5. Score all judged query IDs with the evaluation convention, missing returned docs get zero. Correctness primary = mean gain over the larger of the two constant policy means on the same evaluation roster. This is a paired baseline whose identity is reselected in each bootstrap. Savings = fraction *not* requesting the history-conditioned read, not actual compute. A win requires strictly positive lower two-sided 95% interval on the primary gain; also report wins, harms, ties and opportunity (per-state oracle). Deliberately include first turns in the official roster.

## Locked switch and transfer

Five outer groups by repo (the existing SERBench folds) / topic (CAsT). Inner folds assign intact groups greedily by descending size, seeded SHA-256 tie-break, to the smallest of four bins. For CAsT the five outer folds use the same balancing. Fit a ridge on paired ON minus OFF outcomes with standardized training-only features, unpenalized intercept, mean loss + lambda times squared slopes. Features are shared exactly across domains: log1p(number of ASCII word tokens in current need), log1p(previous event count), zero previous events, fraction of unique word tokens, any anaphor from the fixed list [it, its, they, them, their, theirs, this, that, these, those, he, she, his, her, former, latter, same, such], leading continuation [and, but, what about, how about, also, then], any digit, fraction of uppercase-initial tokens. In SERBench use information_need alone as the gate's current request and number of trajectory_prefix events. CAsT uses raw_utterance and number of preceding turns in the topic. Never read history values for the gate. At inference choose ON if predicted gain exceeds the threshold. Inner CV maximizes pooled quality, breaks ties in favor of lower number of ON requests, then higher regularization and higher threshold. Candidates lambda [0.01,0.1,1,10], thresholds [-0.10,-0.03,0,0.03,0.10] plus both constant controls. Thresholds operate on 0–1 quality scales. The gate must earn both quality and read savings.

Primary new benchmark is nested grouped CAsT, then separate zero-shot transfer CAsT -> Cal500 trained only on CAsT; report reverse transfer and within-Cal500 nested evaluation as diagnostics. Cross-domain refits choose hyperparameters with grouped inner splits on the full source only, and transform target using source statistics. Do not change the validated switch after seeing target grades. Bootstrap 10,000 paired group-resamples per benchmark, with fixed OOF decisions (conditional on fitted rules, no retraining), seed 20261118. Report secondary endpoints descriptively. No pooling across benchmarks. CAsT's ON is an automated rewriting subsystem plus the same retrieval/rerank pipeline. Cal500's ON is a query augmentation, so domain and architecture both shift. Latency savings are unknown. If a constant wins selection report the degeneracy. Per-state grades, both actions and fold identifiers will be saved. Record hashes and versions. Only parse data as inert text.

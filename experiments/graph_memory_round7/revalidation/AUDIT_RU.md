# Независимая сверка повторного использования AST-ответов

Проверены три каталога `revalidation`, `binding` и `rare`. Для 265 уникальных архивов wheel сверены SHA-256 их байтов. В трёх файлах фиксации сверены соответственно 6, 9 и 10 записей. По исходникам обоих релизов независимая реализация построила множество прямых именованных вызовов локальных функций и хеши их объявленных сигнатур, затем проверила `old_answer`, истинность `same`, все идентификаторы и агрегаты для каждой зафиксированной строки. Внутри панели идентификаторы уникальны. Расхождений не найдено.

Адресный сброс учитывает имена из прежнего тела вызывающей функции, включая кандидатов, которые ранее не соответствовали уникальной функции модуля. Глобальное правило отклоняет запись, если среди изменённых строк обнаружено имя любой подходящей декларации данного модуля. Строгий контроль следит за полными определениями ранее известных зависимостей. В независимой панели перенос экономит 77 повторных вычислений относительно глобального правила и четыре открытия при группировке по файлу и релизу. Более простые правила по заголовкам и положительным зависимостям дают там те же 717 решений. На более ранних версиях одно дополнительное срабатывание адресного правила было ложным. Устаревшие ответы, предотвращённые благодаря учёту ранее неразрешённых имён, найдены только на панели разработки. Среднее по восьми новым проектам преимущество в корректном повторном использовании над глобальным правилом составляет 11,60 п.п., bootstrap-интервал [3,99; 19,99]. В этой оценке проекты имеют равный вес.

## Ограничения

- В режиме решения новые исходники участвуют в построении диффа. В первом прогоне политике передаются координаты. В `binding` и `rare` передаются ещё распознанные по изменённым строкам имена в строках `def`/`async def`. Предиктор через импорт видит объект функции `score.oracle`, но его пути `predict`, `observations` и `rows_for` не вызывают её и не читают результаты. Сравнение с AST нового исходного текста выполняется при оценке. Фиксация SHA подтверждает согласованность текущих байтов. Внешняя проверка времени или процессная изоляция в этой схеме не применялись.
- Запрос задан синтаксически. Оцениваются имена вызовов, совпадающие с уникальными функциями верхнего уровня внутри одного модуля. Связывание имён в Python, переопределение переменных, вызовы методов, импорты, декораторы, результаты выполнения и изменение поведения тела требуют других эталонов. Ограниченный объект оценки объясняет пользу проверки только заголовков.
- Счётчик повторных вычислений относится к холодным запросам при уже доступном диффе. Для вывода об ускорении нужно включить получение обеих версий, построение диффа, извлечение имён, хранение и реальное чтение/доступ к кешу. Функции одного исходного файла разделяют стоимость физического чтения.
- Запросы включены только в изменённых или удалённых модулях и только при наличии ранее известного ребра. Смежные версии одного проекта зависимы. Ранние версии дают 2404 запроса от 13 проектов при 132 реально представленных переходах. Проверка `transfer_strong_control` повторяет те же 717 событий. Их повторный учёт искусственно увеличил бы выборку.

# Дополнительный замер стоимости после основного эксперимента

Проверяем важное для интерпретации условие: окупаются ли сэкономленные перечитывания, если дельту координат должен строить сам потребитель. На неизменной панели переноса (717 запросов, восемь проектов) сравниваем три режима одного процесса Python. (1) Рассчитать текущий синтаксический ответ напрямую, полный разбор каждого востребованного файла один раз на переход. (2) При заранее доступных дельтах обрабатывать графовые зависимости выборочно и пересчитывать весь файл только при первом промахе. (3) Получить тот же ответ, но включить в таймер построение сопоставления SequenceMatcher из исходных байтов предыдущей и текущей версий каждого востребованного файла. Получение архивов, чтение с диска, первичное построение ранее наблюдавшейся памяти, инференс и инструменты агента вне таймера; затраты относятся только к CPU-пути ответа на пакет. Базовому варианту также предоставляются текущие байты без I/O. Измеряются wall/process time для всей панели.

Заранее фиксируем прогрев каждого режима, семь последующих повторов, псевдослучайную перестановку по режимам внутри каждого повтора (seed 70811), медиану и диапазон. Полное содержимое ответа по всем 717 запросам проверяем по независимой оценке; при расхождении время соответствующей политики нельзя интерпретировать как ускорение эквивалентного запроса. Порядок запросов одинаков; на одном файле один дорогой разбор даже при многих запросах. Это постфактум проверка стоимости уже выбранного метода, измеренная на одной машине. Для замера независимый новый holdout не заявляется.

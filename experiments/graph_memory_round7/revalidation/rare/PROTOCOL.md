# Проверка редких изменений на более ранних версиях

На восьми новых проектах базовый вариант по диапазонам и вариант с отрицательными зависимостями дали одинаковые решения. Для проверки редкого механизма до просмотра новых выпусков фиксируем отдельное расширение. Используем те же 16 проектов, у каждого максимум 16 непосредственно предшествующих стабильных pure-wheel версий, строго ниже самой ранней уже проверенной версии этого проекта. Смежные переходы рассматриваются только внутри этого нового периода. Список проектов не независим от разработки; переходы не пересекаются ни с первой, ни со второй панелью. Для пакетов без двух подходящих релизов учитываем отсутствие переходов. Выбор периода без фильтрации по ответам. Корпус чужого кода используется только статически.

До оценки применяем те же пять политик из двух протоколов. Включаем строгий контроль по полным определениям callees, а также тот же контроль на прежней первой панели переноса для сравнения при одинаковом доступе к данным. Новый основной контраст — S против B на всех подходящих переходах, отдельно условно на случаях, когда S требует чтения, а B доверяет записи. В таких случаях считаем сохранённые ошибочные ответы, ненужные сбросы, цену (дополнительные чтения на одну предотвращённую ошибку), число проектов с эффектом. Это не оценка частоты при произвольном обновлении пакета. Условный срез определяется только исходными признаками и решением двух зафиксированных политик. Для строгого контроля измеряем риски и перечитывания при холодном запросе и пакетной обработке. Показатели сохраняются даже при нулевых расхождениях. Дополнительные направления и пороги после фиксации не подбираются.

# Поиск фрагмента кода по контракту объявления

Сравнили обычный BM25 по фрагментам и графовую политику, повышающую ранг исполняемых окон функции, если запрос совпадает с её docstring и примером использования. Граф учитывает только объявления в исторически выбранных восьми файлах базовой ревизии. Схема выбора файлов, набор окон по 14 строк, входные 850 токенов и потолок 1800 токенов памяти общие. Протокол и публичные прогнозы запечатаны до оценки. Лимит файлов — до восьми: в одной из 30 задач SymPy исходный поиск вернул только три файла и все политики получили эти же три. В остальных 53 случаях было по восемь. Новые прогнозы построены детерминированно на CPU без вызовов модели.

| Панель | В восьми файлах есть целевая старая строка | Она представима в окне функции | BM25 | Граф контрактов | Перемешанные связи | Исходный flat R6 |
|---|---:|---:|---:|---:|---:|---:|
| SymPy, 30 ранее исследованных задач | 17 | 15 | 12 | 6 | 6 | 12 |
| Sphinx, 24 задачи другого проекта | 9 | 9 | 8 | 5 | 3 | 8 |

Ячейки методов — число issues с хотя бы одной целевой старой строкой в переданном пакете. Для SymPy 0 выигрышей против BM25 и 6 потерь, −20,0 п.п., 95% парный bootstrap [−36,67; −6,67], точный двусторонний McNemar p=0,03125. Для Sphinx 1 выигрыш и 4 потери, −12,5 п.п. [−29,17; +4,17], p=0,375. Среди достижимых задач BM25 получил 12/15 и 8/9, граф — 6/15 и 5/9. На Sphinx граф охватил 25 из 129 целевых строк против 20 у BM25, поэтому сумма строк и доля задач дают разные выводы. На SymPy соответствующие числа 12/179 и 59/179. Расход контекста сходен, среднее по каждой группе и политике 1768–1776 токенов.

По основной метрике гипотеза проиграла плоскому контролю. Значимый отрицательный результат относится к повторно использованной группе SymPy. 24 задачи Sphinx выбраны хеш-порядком из 44 задач SWE-bench Verified до расчёта результатов. Обе группы представляют по одному проекту. Измерение локализации само по себе не оценивает итоговые исправления. Файловый поиск сканирует только имена объявлений и пути во всём проекте, вне рассматриваемого бюджета памяти. Заметный резерв связан с выбором файлов. Фазу нового сравнения восьмифайловой политики см. в frontier.

## Воспроизведение

Выполнять из этой директории. Нужны Python и tokenizers для predict.py, а для collect_external.py и evaluate.py локальное окружение repair/env с duckdb. Исходный токенизатор и 30 локальных снимков SymPy расположены в предшествующих каталогах. Протокол — PROTOCOL_RU.md, публичные источники и SHA — inputs/<id>/source.json и source_integrity.json. Чтобы повторить, выполнить collect_external.py, predict.py, evaluate.py, verify.py. Для действующего оценщика обязательна локальная изоляция временной git-директории перед применением эталонного патча. Проверено содержимое всех 427 выбранных файлов относительно архивов базовых коммитов.

В первом техническом запуске внешнего оценщика Git нашёл существующий корень на диске D и пропустил применение патчей в рабочей подпапке. Аномалия была обнаружена по нулевому числу целевых строк во всех внешних задачах. Этот недействительный запуск сохранён в invalid_external_grade. После изоляции Git и дополнительной проверки непустого изменения оценка повторена на тех же prediction SHA. Основные данные — predictions.lock.json, scores_per_issue.json, results.json и evaluation.lock.json. Порядок выборок и все версии политики зафиксированы.

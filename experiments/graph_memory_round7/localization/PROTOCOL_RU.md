# Локализация по свидетельствам из документации уже виденных объявлений

Задача — выбрать фрагменты уже прочитанного исходного кода для памяти агента в пределах 1800 токенов. Проверяем, помогает ли явная связь «пример использования/контракт в docstring → реализация функции» переместить внимание с самой документации на исполняемую часть нужной функции. Реализация детерминированная, без обучения. Работа на уровне retrieval, без генерации patch или запуска кода из задач.

**Панели.** Основная — все 30 давно оценённых в шестой серии задач SymPy transfer. Эта репликация повторно использует случаи с опубликованным прежним результатом. Внешняя заранее заданная — до 24 задач другого проекта sphinx-doc/sphinx из SWE-bench Verified, выбранных первыми по SHA256('r7-local-doc-transfer-v1|'+instance_id) после фильтрации явных security/CVE запросов по публичному описанию. Фиксируем все выбранные задачи и исключения. Никакого отбора по содержимому патча, успешности поиска или запуска. Для новой выборки берём официальные снимки базовых коммитов с codeload.github.com. Первая выборка локальная, вторая впервые оценивается в данной постановке; могли фигурировать в иных предшествующих исследованиях.

**Информация и бюджеты.** Используем публичный текст issue, обрезанный до первых 850 токенов исходным Qwen-токенизатором, и исходники базового коммита. 8 кандидатов по алгоритму шестой серии: совпадения имен объявлений с запросом, именами вызовов и путями, затем лексическая сортировка. Для SymPy берём ранее зафиксированную восьмёрку, поскольку порядок задан до чтения эталона. Для Sphinx переносим процедуру с символьной подстановкой имени пакета. Начальный поиск сканирует объявления в дереве и не входит в цену чтения памяти. Внутри восьми файлов блоки по 14 строк в функциях и методах; одни и те же блоки для каждого условия. Итоговый сериализованный контекст включает пути, номера строк и исходный код; не более 1800 Qwen-токенов. При полном равенстве ранга используем имя файла и строку. Золотые участки кода, тесты, диффы и диагноз прошлой работы строго отделены от прогнозирования. Две фазы запечатаны отдельными SHA-256 до оценки.

**Условия.** BM25 k1=1.2, b=0.75 по телу блока и метаданным (путь, класс, функция). Отдельно исходный flat шестой серии (зафиксированные пакеты SymPy и буквальный перенос формулы на Sphinx). Метод контрактов: BM25 по виртуальному документу из квалифицированного имени и docstring объявления (контракт, примеры) привязывается к окнам исполняемой части той же функции. Fusion текстового ранга окна и ранга владельца по reciprocal rank с константой 30 и одинаковыми весами; ранг владельца задаём по максимальному выделенному месту среди владельцев, связям с нулевым score бонус нулевой. Окна, целиком принадлежащие docstring, не получают бонус. Контроль связей — детерминированная перестановка меток владельцев на базе instance_id внутри каждого файла; штрафов или доступа к дополнительному тексту нет. Сохраняем все результаты. Настройку весов по партитуре не выполняем.

**Основной контраст** — разность долей задач с ≥1 покрытой эталонной старой строкой между связанным контрактом и плоским BM25 на панели SymPy. Повторить без изменений на Sphinx. На каждую задачу сохраняем число целевых строк, число в 8 файлах, число, достижимое в блоках функций, число полученных, токены. Диагностика — покрытие всех целевых строк, условная доля попаданий среди задач с доступным блоком, прежний flat и контроль с перестановкой. Единица анализа — issue. Для разности долей двусторонний точный McNemar по дискордантным парам и 95%-й парный percentile bootstrap с 10 000 повторов, seed 71027. Интервалы внутри проекта, без выводов о генеральной совокупности репозиториев. Результат не интерпретируем как end-to-end SWE-bench; родительская оценка сопоставляет локальные метрики и стандартизованные условия. Для SymPy используем сохранённый список старых строк старого оценщика, для Sphinx получаем его из эталонного патча после фиксации прогнозов. Для чистых вставок якорь — следующая строка старой версии. Нет строки у вновь добавленного файла, файлов вне продукционного пакета и не-Python: для прозрачности сохраняем число исключённых файлов. Для SymPy эталон оставляем в прежней политике для точного парного сравнения.

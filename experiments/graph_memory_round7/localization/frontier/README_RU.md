# Проверка выбора файлов на непересекающейся выборке Sphinx

Получены оставшиеся 20 из 44 задач SWE-bench Verified проекта Sphinx, прошедшие тот же публичный фильтр. Ни один идентификатор не присутствует в первых 24. При выборе индексы и тексты эталонных патчей закрыты. Ранжирование не запускает код проекта и не обращается к Git-истории после базового коммита. После хеширования прогнозов исходные строки размечены тем же изолированным оценщиком. На одной задаче для всех политик раскрывали ровно восемь файлов, передавали не более 1800 токенов.

| Вариант файлового фронтира | Задач с целевой строкой среди 8 файлов | Задач с целевой строкой в конечном пакете | Целевых строк в файлах / в конечном пакете из 96 |
|---|---:|---:|---:|
| Исходный R6 | 10/20 | 9/20 | 50 / 17 |
| + Пакетные __init__.py с объявлениями | 12/20 | 10/20 | 68 / 18 |
| + Редкость совпавших имён по файлам | 13/20 | 10/20 | 71 / 18 |
| + Раскрытие импортов из первых 6 файлов | 12/20 | 10/20 | 70 / 18 |

Первичное сравнение — граф импортов против той же модели редкости без рёбер. Изменился состав восьми файлов у всех 20 задач. Получено 0 парных выигрышей и 1 потеря, −5 п.п., процентильный 95% bootstrap [−15; 0], двусторонний точный McNemar p=1. Отсутствие парных различий в конечных попаданиях относится только к этим 20 задачам. Обычная реабилитация файлов инициализации добавила 2 пригодных случая без потерь (p=0,5), взвешивание редких имён — 1 без потерь (p=1). Комбинация этих двух простых правок относительно первоначального ранжирования даёт 13/20 вместо 10/20 (3 приобретения без потерь, p=0,25, вторичный описательный контраст). Вычислительные расходы инвентаризации исходников не измерялись.

Результат оправдывает учёт фактических объявлений в пакетных инициализаторах при выборе допустимого пространства адресов. Он не доказывает преимущества графового раскрытия по правилу импорта, роста точности генерации патчей или превосходства над SOTA. Время работы, бюджет модели и baseline для автономного исправления следует проверять отдельно.

## Воспроизведение

Запустить collect_external.py (окружение с duckdb и truststore), select_frontier.py (Python с tokenizers), затем grade_frontier.py (окружение duckdb). Все исходные исходники доступны по публичным ссылкам на базовые коммиты; снимки и SHA-256 сохранены в inputs. Прогнозы, их хеши и первичные метрики находятся в predictions, predictions.lock.json, scores_per_issue.json, results.json, evaluation.lock.json. Парные интервалы и размеры выборок следует читать по каждому контрасту отдельно.

# Независимая проверка восьмифайлового фронтира

Предшествующий тест на первых 24 из 44 Sphinx issues показал, что простой текстовый читатель уже находит 8 из 9 доступных в восьми файлах задач. Поэтому переносим вмешательство на выбор самих файлов. Метод и веса фиксируются до получения разметки оставшихся 20 задач. Используем все оставшиеся после SHA-упорядочивания и прежнего фильтра публичных описаний задачи, без доселекции. Общий репозиторий и публичный benchmark известны, однако эта группа не использовалась для разработки метода в данной серии. Выборка уточняет механизм, а не даёт оснований для утверждения SOTA. Критерий для продолжения — фиксируем и отрицательный результат.

Четыре политики при одинаковом бюджете восьми файлов, первых 850 токенов запроса и памяти 1800 токенов. (1) old — прежний поиск R6: лексические совпадения пути, объявлений и вызовов, исключаются __init__.py. (2) init — тот же поиск, разрешаем пакетные __init__.py, если они содержат хотя бы одно настоящее объявление. (3) rare — тот же пул, явный путь имеет вес 10, прочие совпадения по исходным четырём полям получают тот же коэффициент, умноженный на IDF термина по файлам, log(1 + (N+.5)/(df+.5)), с одним голосом на термин на файл. (4) import — сначала первые шесть по rare, затем выбор двух файлов среди оставшихся по сумме обратного ранга rare (1/(10+rank)) и бонуса импортной связи. Выдвижение соседей разрешено только из уже раскрытых шести. Голосуют from/import из уровней модуля и условных блоков, если импортируемый идентификатор или конечное имя модуля упомянуты в запросе; разрешение точное проектное (sphinx.* или относительное). Для одного файла учитываем максимальный 1/(10+rank_seed), естественное избыточное дублирование голосов исключено. У каждого условия одинаковый читатель: BM25 по метаданным + исходному блоку, без docstring-рёбер. Ранжирование кандидатов использует проектную опись названий объявлений и путей как R6. Данный опыт не включает стоимость построения описи; это не безындексный метод.

Первичная метрика — доля задач хотя бы с одной эталонной старой строкой в восьми выбранных файлах, первичный контраст import минус rare (абляция связи). Пакетное попадание строки при равных токенах, число доступных строк и контрасты init-old, rare-init, import-old — вторичные диагностические. Уровень ресемплирования issue, 10 000 парных bootstrap с seed 71027, двусторонний точный McNemar. Единственный запуск, без поиска параметров. Ранжировки и пакеты запечатать перед чтением патчей, тот же исправленный оценщик локальных исходных координат в изолированной git-директории. Первичные результаты этого follow-up интерпретируются отдельно от прежней панели.

# Адрес следующего чтения и цена предвыборки

Исследовали, какую подсказку агент может сформировать до следующего обращения к исходному коду. Все политики получают один адрес либо пустой ответ на холодном старте. Данные — ранее опубликованные траектории SWE-agent с Claude 4 Sonnet и CodeSweep/SWE-agent с Kimi K2 на SWE-bench Verified. Наблюдения взяты из сохранённых проекций прошлых серий. Эпизоды не перезапускались, модель не вызывается. Политика не получает будущие аргументы команды, патчи, целевые тесты или результаты решения задачи. У Kimi большая часть обращений происходит через shell, поэтому оценка только на editor-view плохо отражает его поведение.

## От графа последовательностей к явному адресу

Модель переходов использует последнее прочитанное место, продолжение диапазона, ранее посещённое место в том же либо другом файле и эмпирический граф переходов. Адаптивный выбор, отдельно обучающийся на просмотрах и правках, сравнивался с тем же набором правил с общими счётчиками. Всего 11 143 прогноза до очередного действия. На 947 явных editor-view в 97 задачах Claude типизированный маршрут дал 26 точных path+page против 29 общего и 28 политики давности. Разность −0,32 п.п., 0 улучшений и 3 потери, 95% ДИ кластерного бутстрепа по задачам [−0,71; 0,00]. На Kimi 4/79 у обеих политик, только 55 из 162 эпизодов с подходящим чтением. У Claude простой выбор последнего файла верен 477/947 раз, но даже идеальный выбор среди пяти кандидатов угадывает первую 16-строчную страницу лишь 76/947 раз. Политики делают прогнозы перед каждым действием, результаты учитывают только действительно состоявшиеся просмотры. [Протокол](PROTOCOL.md) · [Поштучные прогнозы](predictions.jsonl.gz) · [Результаты](results.json)

Во втором опыте добавлена связь из фактически показанного результата grep/rg с ключом -n к пути и номеру строки. Основная политика сохраняет первую выведенную координату до следующего чтения/правки, с исходным ограничением в два шага. Цель — вхождение одной предсказанной строки в фактически показанные строки последующего чтения файла редактором или простым shell-инструментом. Метрика второй таблицы отличается от path+page первого опыта.

| Панель | Чтения / задачи / проекты | Давность последней обычной строки | Поиск, точный адрес | Тот же путь, старый номер | Прирост против давности, п.п., 95% ДИ по задачам | Поиск без истечения по шагам |
|---|---|---:|---:|---:|---|---:|
| Kimi, основная | 210 / 59 / 4 | 10 | 33 | 12 | +10,95 [2,99; 17,86] | 43 |
| Claude, перенос | 348 / 37 / 9 | 18 | 32 | 18 | +4,02 [1,80; 6,67] | 32 |
| Kimi, отдельная репликация | 225 / 88 / 7 | 21 | 34 | 21 | +5,78 [2,39; 9,52] | 51 |

В трёх строках таблицы issue ID различны. Первая пара панелей определена до проверки новой гипотезы; дополнительная Kimi-репликация выбрана до оценки её адресов, уже после первого сравнения. Все три источника ранее использовались в проекте для других исследований. На основной панели 13 из 23 новых попаданий приходятся на одну задачу. При удалении любой одной задачи разница остаётся от +6,21 до +11,92 п.п. Среди случаев, когда оба метода действительно выдали адрес, отношения выигрыш/потеря составили 22/0, 14/0, 11/1. Безусловное удержание первой координаты до следующего обычного чтения/правки оказалось сильнее двухшагового срока на обеих панелях Kimi. Результат поддерживает использование явного адреса и задаёт сильный простой контроль. Система сравнивается с локальными правилами. ## Когда выгодно читать целую страницу

Симулятор выделяет одну выровненную страницу на 16 строк после каждой адресной команды поиска, включая все промахи, вытеснения и конец задачи. Строки из этого же вывода grep вычитаются при подсчёте добавочного покрытия. Оракул предполагает, что предполагаемая страница реально существует и доступна в нужной версии. Латентность и байты файлов не измерялись. Ресурсный лимит задан числом строк.

| Панель | Загрузки | Хотя бы одна полезная строка, срок 2 / без срока | Дополнительные востребованные строки, срок 2 / без срока | Полные чтения, срок 2 / без срока |
|---|---:|---:|---:|---:|
| Kimi | 57 | 23 / 33 | 225 / 312 | 5 / 7 |
| Claude | 42 | 14 / 14 | 131 / 131 | 0 / 0 |
| Kimi, репликация | 63 | 14 / 31 | 87 / 207 | 0 / 0 |

Среди ближайших чтений длиной ≤16 строк фиксированный срок полностью покрыл 5 из 8, 0 из 5 и 0 из 5. Если одна востребованная строка сверх текущего поискового вывода приносит b, а предвыборка стоит c, порог c/b для исходного срока равен 3,95, 3,12 и 1,38 строки по панелям. Без срока значения составляют 5,47, 3,12 и 3,29. Более строгая метрика новизны по всем ранее встречавшимся адресам дала 147, 104 и 207 дополнительных востребованных строк суммарно по соответствующим панелям без срока. Если польза возникает лишь при полной замене инструментального вызова, на обеих панелях переноса частота такой замены равна нулю. На последней панели ни одно из 51 последующих чтений при бессрочном удержании физически не умещалось в одну выровненную 16-строчную страницу. Это уточняет выбор следующего опыта: передавать агенту дешёвый указатель и читать при необходимости. ## Воспроизведение

Из этой папки выполнить последовательно:

```text
python -B predict.py
python -B score.py
python -B search/run.py predict
python -B search/run.py score
python -B search/followup/evaluate.py predict
python -B search/followup/evaluate.py score
python -B search/followup/diagnostic.py
python -B search/followup/cost_sensitivity.py
```

Сохранённые минимальные журналы содержат только типы действий, относительные пути и числа строк. Этим командам достаточно Python 3.10+ и стандартной библиотеки. Для повторной сборки проекций запустить перед соответствующей фазой `python prepare.py`, `python search/run.py prepare`, `python search/followup/evaluate.py prepare` в полном дереве прошлых серий с зависимостями исходного парсера. Порядок стадий разделён файлами контрольных сумм: freeze.json для входов и алгоритма, predictions_lock.json для уже выданных прогнозов. В основном roster.json у Kimi поле source_sha256 не заполнилось из-за другого имени в исходной схеме; отдельные точные upstream SHA-256 для всех 162 задач восстановлены из прежних квитанций в [дополнении](kimi-upstream-receipts.json). Хеши самих входных шардов зафиксированы до прогонов.

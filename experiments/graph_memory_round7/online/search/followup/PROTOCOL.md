# Проверка переноса и бюджета предвыборки

Дополнение к основному тесту после просмотра его результатов. До подсчёта этих дополнительных метрик фиксируются два анализа.

1. Перенос на оставшиеся ранее записанные Kimi R5 writer с терминальным raw_pairs (R5 action_probe), без повторения issue из обеих панелей исходного теста search. Тот же фильтр задач и восстановление строк. Политики из search не меняем. Два сильных контроля из тех же сырых наблюдений берут первую или медианную строку первого файла в последнем выводе grep и используют её до следующего чтения/правки без ограничения в два шага. На этой панели сравнение Search и базовой давности — репликация новой метрики на ранее не оценённых для данной гипотезы ID. Контроли показывают отдельно эффект чтения явного адреса и эффект срока его действия.
2. Ретроспективный анализ бюджета на всех трёх панелях. После **каждого** распознанного grep/rg с Python-адресами выдаём один указатель на 16-строчную страницу, выровненную по 1,17,33… и содержащую первую строку первого показанного файла. Сравним с тем же путём, но страницей последнего замеченного обычного чтения файла (его медиана), по умолчанию первая страница. Одинаковое число спекулятивных запросов, один активный слот; считаем обращения, даже если за ними не было чтения. Новый сигнал замещает старый, правка его снимает, через 2 шага он истекает, на первом обычном чтении или в конце эпизода закрывается. Не начисляем экономию от кеширования повторных предвыборок. Запускаем симуляцию реальных адресов, без измерений реальной latency или исполнения команды. Вместимость выражена в строках, не байтах. Для каждой спекуляции записываем причину завершения, попадание/промах, число пересекающихся строк ближайшего чтения, полного покрытия, полезных строк за вычетом уже показанных в этой же команде grep. Приводим результаты для коротких чтений ≤16 строк и ≤64 строк, по всем целевым обращениям и отдельно по триггерам, когда следующий просмотр наступил. Дополнительно консервативный показатель для широкого вывода grep: вычитаем строки, уже видимые у выбранного файла. В метаданных старого парсера может отсутствовать подтверждённая позиция отдельных строк — результат условен на извлечённом потоке.
3. Цена. Пусть одна фактически использованная новая строка приносит b, каждая начатая предвыборка стоит c: предвыборка окупается лишь при c/b < сумма новых использованных строк / число попыток. Для случая, когда экономится только весь инструментальный вызов, верхняя граница c/C — полностью покрытые чтения / число попыток при одинаковой цене такого чтения. Это граница для данной фиксированной политики, при идеальной доступности и актуальности запрошенных строк, а не наблюдаемая экономия в миллисекундах. Стохастический интерфейс реального агента может менять его следующие действия.

# Предсказание адреса следующего явного чтения

## Постановка

После каждого шага агент может назвать один адрес следующей операции `view`, не получая её аргументы или вывод. Адрес — нормализованный путь Python-файла и номер 16-строчной страницы (нулевая база). Цель — страница первой действительно показанной нумерованной строки. Эксперимент проверяет механизм выбора адреса и потенциальной предварительной загрузки. Запрос к репозиторию не выполняется. Качество программных исправлений и задержку инструмента этот опыт не измеряет.

R3–R6 использовали те же публичные траектории для восстановления содержимого, прогноза будущей правки либо чтения по известному адресу. Здесь новая целевая операция: следующее явное редакторское чтение, включая первое и новые файлы. Используем готовые проекции с совпадением фактически показанных строк в trajectory и history. Из пяти старых каталогов берем непересекающиеся внутри агента когорты Claude 4 Sonnet (R3 real_swe, followup, R4 writer) и Kimi (R5 writer, action_transfer). Включаем astropy, matplotlib, seaborn, scikit-learn, sympy, xarray, pytest, pylint, sphinx. Исключаем задачи с признаками безопасности по исходным фильтрам и дополнительному фильтру по описанию. Для независимости между панелями все issue ID панели Kimi исключаем из Claude (до просмотра исходов). Это переоценка ранее использовавшихся источников на новом определении цели, а не независимый международный тест. Положения вне репозитория и другие расширения не являются наблюдениями. Сначала фиксируем список файлов и SHA, протокол и код, прогнозируем, запечатываем прогнозы SHA и затем считаем итоги.

## Политики и контроль

Разрешены только сведения уже завершённых действий, включая документированные содержательные просмотры и подтверждённые редактирования с видимыми нумерованными строками. Никаких текстов задач, патчей, тестов, будущих действий и индекса всего проекта у политик нет. В каждом эпизоде состояние обнуляется. После запроса сохраняется его факт только для последующих запросов. В качестве основного контекста используется последнее такое наблюдение. В каждом условии один прогноз (или пустой при холодном старте).

Пять фиксированных правил кандидатов: страница начала последнего наблюдения (recency); следующая страница после первого непрерывного видимого диапазона (forward); начало последнего диапазона на другом файле (return); страница предыдущего наблюдения на том же файле (previous); самый частый наблюдавшийся переход от текущего адреса к следующему просмотру, ничьи по последнему наблюдавшемуся переходу (graph). Кандидат из отсутствующего контекста заменяется recency. Простой граф переходов строится по всей истории текущей задачи. В каждую историю включаем просмотры даже когда последняя страница — новая.

Роутер выбирает правило с максимальным числом прошлых точных предсказаний. Все пять прогнозов можно оценить после каждого реально сделанного просмотра. Ничьи в указанном порядке (recency, forward, return, previous, graph). **Typed** ведёт отдельные счётчики для последнего наблюдаемого просмотра и редактирования; **pooled** объединяет их. Это абляция ролей при едином наборе правил и бюджете. Если ни один кандидат не угадал, все счётчики неизменны. Частота файла и разделение по ближайшей странице диагностические.

## Анализ

Основной контраст — точное попадание path+page Typed минус Pooled, все явные просмотры панели Claude, взвешенные поровну. Вторичный базовый контроль — сравнение с recency и graph. Kimi — независимая по issue панель переноса, без настройки и обучения на Claude. Привести n задач и запросов, попарные выигрыши и потери, разность в процентных пунктах, 95%-й процентильный кластерный бутстреп по целым задачам (10000, seed 71321). Показать по проектам, попадание в файл, страницу с погрешностью ±1 и эпизоды после предыдущего редактирования как описательные показатели. Описательный оракул — любое точное попадание среди пяти заранее определённых кандидатов. Провести проверку инвариантности прогнозов к замене суффикса и чистого состояния на старте. Любая положительная гипотеза о сквозном эффекте требует отдельного интерактивного теста. Нет подбора по результатам, отсутствие эффекта записывается.

Из работ по предвыборке сопоставим принцип графа предшественников и последователей файлов у [Griffioen и Appleton](https://www.usenix.org/legacy/publications/library/proceedings/bos94/griffioen.html) и контекстное моделирование у [Kroeger и Long](https://www.usenix.org/legacy/event/usenix01/kroeger.html). Политики являются локальными простыми реализациями, метрики не сравниваются с измерениями системных статей.

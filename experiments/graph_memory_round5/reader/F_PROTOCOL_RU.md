# Помогает ли распределение числа фрагментов написать код
Дополнение после разведочного результата 36 000 поисковых задач, до открытия ответов A и собственных генераций F. Наследуем 128 выбранных без генераций примеров A, по одному на репозиторий. Используем те же графовые ранги и тот же генератор. Сортируем по SHA256 с префиксом budget5 и разбиваем на четыре очереди по 32. В первой политике каждый запрос получает первые три объявления графа. Во второй неизменённая модель из retrieval/budget_model.json (только число кандидатов и их позиции) оценивает предельный прирост покрытия; первые места выделяются всем, остальные последовательно по максимальному предельному приросту до восьми. Обе получают одинаковое суммарное число фрагментов в каждом блоке. Передаём не более 64 токенов от начала каждого фрагмента и разделители, без дополнительной обрезки, сверху 512 токенов фрагментов плюс разделители. Фиксируем число слотов и реальные prompt-токены. Не используем результаты генерации для выбора глубины. Основной исход — парная разность EM, вторичные — ES, F1 имён и наличие эталонного объявления. Тест Мак-Немара и парный 95% bootstrap по 128 проектам условны на зафиксированные блоки и глубины. Чувствительность — по стратам и по четырём блокам (отдельно их разности); возможности переноса зависят от состава очереди. Это проверка переноса выигрыша поисковой метрики в качество строки, без публичного абсолютного сравнения.

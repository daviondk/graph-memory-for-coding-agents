# Где агент уже видел текст следующей правки
18.11.2026. Разведочная проверка после известного результата редакторской проекции R5 (115/253 без вытеснения в момент среза, 135 случаев без полного блока по правильному адресу непосредственно перед правкой). Предварительно индивидуальные исходы этой панели не открывались для выбора правил. Один и тот же корпус из 112 Kimi K2 Instruct траекторий и одна временная сетка, подготовленная до этой проверки. Статический разбор публичных данных, код и команды из записей не исполняются.

Основная гипотеза: некоторые фрагменты уже были показаны агенту в инструментальном наблюдении до среза, однако при записи потеряна связь фрагмента с его адресом. Считаем отдельно (a) текущий блок в модели rebase R4 без вытеснения, (b) точные строки прежде встречались по тем же номерам в том же файле, (c) целый непрерывный блок был напечатан за одно обращение редактора в этом же файле, но, возможно, под другим номером, (d) в другом файле редактора, (e) в непрерывном тексте ранее показанного результата другого инструмента, (f) все отдельные строки когда-либо наблюдались, хотя бы в разных местах, и (g) хотя бы одна отсутствует. Прямое сопоставление с будущим эталоном — диагностический потолок. Не приравниваем отсутствие в публичном логе к отсутствию у реального агента: есть ограничение длины, текст интерфейса и возможно несопоставленные tool-вызовы. До среза используются только результаты уже завершённых событий, отдельно прямо перед соответствующей правкой. В параметры matching не включаем саму текущую правку, её аргументы, tool output или последующие шаги. Фиксируем точный уровень равенства целых строк, включая пробелы. Пустые или типовые строки дают тривиальные совпадения. Храним пособытийно флаги, без вывода исходных программ и текста задач. Дополнительно считаем только нетривиальные блоки (≥1 строка с ≥8 буквенно-цифровыми символами).

Причинная политика: для каждого уже полученного результата инструмента, который R5 делал непрозрачным, разбираем только прямые обычные чтения sed -n с простым числовым диапазоном, cat/head по одному файлу без конвейера или перенаправления, nl -ba / cat -n, и номерные строки поиска rg/grep с указанным путём. Учитываем строки, подтверждённые одновременно в observation и непосредственно связанном tool-сообщении assistant history. Отвергаем строки оболочки, многооператорные команды и неоднозначные пути. Разбор не вызывает shell, не читает соответствующий исходный репозиторий. Присваиваем сведения по адресу и номеру с временем чтения; перенумерацию/сброс при наблюдаемых изменениях выполняет тот же anchored_advance. Дополнительный контроль: последнее историческое значение по каждому адресу + нынешнее состояние с приоритетом нынешнего (возможно устаревшее); ещё контроль — сдвиг добавленных адресов на одну строку. Без вытеснения у всех методов, чтобы выделить проекцию наблюдений. Номер отсечки для основного исхода прежний, цель одна для всех: точное наличие всех строк по истинному адресу в момент среза. Адрес следующего изменения нужен только при оценке запечатанных карт памяти, не строит их. Вторичный исход — совпадение со следующими реально показанными строками редактора, с отдельной отметкой числа проверенных дополнительных адресов и их точности. Основной знаменатель 253, пары выигрышей и потерь, парный интервал по задачам 10 000 раз. Проверяем те же сравнения отдельно непосредственно перед правкой, где раньше выявлено 135 отсутствий.

Дополнительные raw инструментальные ответы загружаются из публичного архива строго для тех же валидных задач, со сверкой SHA-256. Несопоставимые результаты и сбои отражаем в журнале. Отдельно указываем неполноту источника при отсутствии части raw-файлов. Политику и предсказания запечатываем до сравнения с индивидуальными метками. Ранее использованные агрегаты делают выводы по новой гипотезе разведочными.

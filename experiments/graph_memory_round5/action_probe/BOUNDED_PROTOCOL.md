После получения исходов без вытеснения переносим ровно тот же распознаватель в общий лимит состояния 4096 байт. Три варианта используют одни коэффициенты, cal_neighbor, одинаковый JSON/Zstandard-15 и общий фиксированный словарь. Первый байт каждого состояния хранит флаг известности рабочего каталога; на сжатое содержимое остаётся 4095. Ошибочный адрес +1 имеет тот же формат и исходные строки. Дополнительная проверка сопоставляет контроль с прежними 4096 байтами без этого флага. Закрываем состояния после каждого четвёртого шага перед оценкой по тому же старому коду. Измеряем @full, долю точных строк, выигрыши/потери, ДИ по задачам. Цель — проверить экономию при равном расходе и сколько реконструированных свидетельств переживает вытеснение. Критерии и параметры политики после раскрытия необрезанного результата сохраняются.

# Серия 5. Исследования чтения и записи графовой памяти

Рабочий каталог на D сохраняет исходные протоколы, задания и генерации, включая нулевые результаты. Итоговое изложение находится в report/pages и в опубликованных Word и PDF. Данные и программы разложены по операции памяти.

* retrieval — комбинации ранжировщиков, реальный запуск microsoft/unixcoder-base на CPU, политика изменения глубины поиска, внешняя проверка на Python, бюджет очереди и последовательный банк. В протоколах указаны обучающие и оценочные выборки. Структура графа унаследована из серии 4.
* reader — A: шесть представлений объявлений на 128 отдельных проектах. B: три на 64 других проектах с доступной связью. C0/C: настоящий черновик и четыре способа повторного чтения на 90 других проектах. F использует те же 128 проектов A для проверки переноса эффекта глубины в ответы Qwen. Каждая политика получает обычный запрос к локально запущенной модели. Генерируется только код следующей строки. Java-программы из наборов не выполнялись.
* crosscode — D: независимый от A/B/C выбор 96 отдельных проектов CrossCodeEval по нормализованному имени. E: полная оценочная популяция Java, 2139 строк. Для 92 изменившихся входов обеих политик получены реальные ответы. На 2047 одинаковых входах по определению общего декодирования парная разность ноль. Протоколы E и D частично используют те же задачи.
* writer — контроль записи видимых наблюдений на 112 новых для данного анализа траекториях Kimi. Состояния снимались после каждого четвёртого шага, затем сравнивались с последующей фактической заменой строк. Это воспроизведение журнала наблюдений решателя в хронологическом порядке.
* review, crossaudit — независимые проверки, первичные публикации и синтаксическая диагностика. report — источники отчёта и результаты визуальной проверки.

## Повторение оценки

Восстановите дерево work с теми же именами каталогов предыдущих серий. Публичный архив серии 4 содержит исходные программы и ранги; исходные Java-архивы автора RepoBench доступны через work/graph_memory_round4/repo/archive_probe.py, конвертация через archive_convert.py cff и cfr. Контрольные SHA-256 входов перечислены в записях данных и оценщиках. Для точного воспроизведения внешних источников нужна соответствующая версия pyarrow и исходные порядки строк. В zip серии 5 включены сами целевые строки выбранной панели, исходные пакеты для запросов, предсказания, метрики и оригинальный архив CrossCodeEval. Архив не дублирует большие веса моделей и исходники полного корпуса RepoBench. На рабочем диске эти зависимости сохранены. Для свежей загрузки модели используйте зафиксированный источник из reader/model_receipt.json; llama.cpp и параметры перечислены в runtime_receipt.json и launch.json.

Из каталога reader запуск score5.py A, B и C, затем score5.py holm и allocation_score.py строит метрики из сохранённых ответов. Нужен Python с numpy и pyarrow. Исходная проекция RepoBench-R в parquet хранила только метку поиска. Поэтому original_targets.py извлекает эталонную строку из соответствующего оригинального файла авторов по тому же номеру только после фиксации ответов A/B/C/F и проверяет весь код, банк кандидатов, путь, индекс и проект. Для CrossCodeEval выполните score.py D и score.py E. Нужны NumPy, nltk 3.9.2 и fuzzywuzzy 0.18.0 без optional Levenshtein. Официальные метрики Java извлекаются из неизменённых исходных файлов авторов и используют список ключевых слов. Архив содержит контрольные суммы, сырые ответы и результаты отдельной проверки.

Внутри одного прогона повторяющийся запрос имеет один физический вызов. Одинаковые входы в разных экспериментах запускались независимо. Затраты времени из параллельных ветвей зависят от очереди и оборудования. Оценка научной новизны ориентируется на результаты на фиксированных задачах, информационный доступ и литературу из review. Публикации и первая карта направления также находятся в предыдущих отчётах проекта.

## Адресная запись и выбор следующего места правки

action_probe содержит сравнение адресной записи простых терминальных чтений и контроля на 112 исходных трассах, сдвиг адреса, LRU при том же входе, поэлементные исходы и разбор устаревшей версии. action_transfer содержит 98 других идентификаторов задач, список до запуска и контрольные суммы исходных публичных .traj, фиксированный код обработки, состояния и оценку. Исходные репозитории не индексировались. Полный необработанный публичный журнал можно заново получить по сохранённым ссылкам. Обе ветви доступны для автономного исследования на CPU.
next_action содержит дополнительную проверку на GPU. Здесь в отдельном запросе Qwen получает только описание задачи и наблюдения до среза. Основная метрика требует от модели указать путь и позицию следующего редактирования с точностью до пяти строк, без подстановки будущего адреса. Файл score_action.py восстанавливает итоговые метрики по сохранённым полным ответам, H_decisions.json и оценочному файлу writer/headroom.jsonl.gz. Дополнительная проверка G в reader и review использует 21 отличающийся вызов GPU и 171 прежний ответ, совпадение по полному телу запроса обязательно. Результаты G и F повторно используют проекты A/B. Все экспериментальные даты в контрольных суммах и журналах приводятся в UTC.

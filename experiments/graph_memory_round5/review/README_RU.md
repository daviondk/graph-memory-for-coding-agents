# Независимая проверка серии 5

В этом каталоге сохранены обзор ближайших работ, проверка реальной семантики найденных ссылок, независимый пересчёт парных сравнений и воспроизводимое правило выбора представления. Первичные входы и оригинальные ответы модели лежат в соседнем каталоге reader. Сохранённые Parquet в graph_memory_round4/repo/archive_inputs являются проекцией архивного набора и не содержат next_line. Оригинальные эталонные строки извлекаются один раз в reader/original_targets.json.gz после завершения первичных прогонов. Независимый пересчёт получает эти общие метки и проверяет их привязку по репозиторию, пути, SHA-256 локального префикса и индексу эталонного объявления.

- LITERATURE_RU.md — различия с LC², HCP, ACAR, RepoCoder, Repoformer, AlignCoder, InlineCoder и Rivet.
- AST_PROTOCOL_RU.md, AST_RESULTS_RU.md, ast_roles.json — проверка роли каждого упоминания Java на CPU.
- AST_GATE_PROTOCOL_RU.md и ast_gate_lock.json — правило чтения по AST и доказательство фиксации раньше завершения GPU-прогонов A/B/C. Доступен размер всех подгрупп. Данные о работоспособности генератора при выборе правила не использовались.
- A_audit.json, B_audit.json, C_audit.json и сжатые таблицы по задачам — результаты независимого считывания реальных запросов и исходного эталона, строго после фиксации ответов. SHA проверяются до подсчёта результата.
- ast_cost.json описывает CPU-микротест. Отдельно измерено только подтверждение одного уже известного текстового ребра по двум находящимся в памяти фрагментам. Записаны затраты в миллисекундах с одним разогревом и пятью повторами. Время поиска кандидатов, чтения репозитория с диска и декодирования модели в этот показатель не входит.

Из каталога review команды выполняются интерпретатором из графовой серии 2. Пакеты Tree-sitter 0.25.2 и Java grammar 0.23.5 доступны в parser_lib. При переносе на другую платформу установить соответствующие бинарные пакеты той же версии в parser_lib. Для повторной оценки нужны pyarrow и numpy.

```powershell
$py = 'D:/CodexResearch/x20-bench-workspace/work/graph_memory_round2/multihop/dev_env/Scripts/python.exe'
& $py audit_reader.py inputs
& $py audit_reader.py both
& $py audit_adaptive.py
& $py score_ast_gate.py
& $py reconcile.py
```

audit_ast.py повторяет разметку видимого кода без золотых меток. Для репликации в новой копии при пересчёте временная метка в ast_roles.json меняется. Хеши оригинальных файлов в ast_gate_lock.json относятся именно к сохранённой версии ast_roles.json. Домашняя проверка score_ast_gate.py использует этот оригинал. Модели вызовы повторно не отправляются.


## Реальные альтернативные строки G и проверка очереди F

По результатам анализа доступности сильных мест использования до просмотра ответов A/B зафиксировали reader/G_PROTOCOL_RU.md и подготовили по одной альтернативной подсказке на все 192 задачи. В G_fresh сохранены реальные дополнительные ответы на 21 новое предъявление. Для остальных 171 используется идентичный запрос и фактический ранее полученный ответ. Полная сверка хешей и переносов проводится reader/run_g.py. Локальное ограничение совпадает с edge: не более 145 токенов от объявления и 100 от места использования, общий потолок 256. Реальное среднее число токенов отражено отдельно. prepare_g.py использует только входные объявления и ранги. Для G исходные файлы, циклы извлечения и отправки, номера новых строк и причины выбора сохранены под reader.

Варианты F используют общие блоки по 32 проекта. Оба условия имеют ровно по 96 слотов на блок. Аудит проверяет состав A/F и для каждого F — фактический запрос, ответ, адреса, среднюю длину и сопоставление со строкой из оригинального архива. Кроме парных результатов по задачам приводится чувствительность к группировке по четырём блокам. Осторожность требуется для переноса на новую очередь запросов другого состава.

Полный запуск после появления всех замков и receipt меток:

```powershell
& $py run_audit_round.py
```

Сводка по G хранится в reader/G_results.json, данные по каждому условию и каждой задаче — в review/G_audit_items.json.gz. Проверка F сохраняется в F_audit.json и F_audit_items.json.gz.
Отдельная проверка H вызывается как audit_next_action.py и сверяет будущие адреса действий исходного агента, сырые ответы генератора и оценки. Итоговые адреса и метки собраны в H_audit_items.json.gz, суммарные результаты и количество проверенных полей — в H_audit.json.

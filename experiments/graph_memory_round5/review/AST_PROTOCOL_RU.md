# Проверка семантики наблюдаемых рёбер

Зафиксировано после подготовки входов A и B, до чтения результатов генератора. Диагностический вопрос — когда текстовый поиск нашёл имя выбранного типа, что на самом деле находится в этой строке? Это отдельное CPU-измерение качества представления связи, использующее только видимые входные фрагменты.

1. Единица наблюдения — задача, где edge_event задан. A и B показываем отдельно. Для всех совпадений корня на выбранной строке запускаем Tree-sitter Java 0.23.5 по целому доступному фрагменту. Координаты определяем по UTF-8 байтам. Учитываем регистр Java.
2. Отмечаем роли **без разрешения символов и типов**: объект или класс в вызове метода, тип создаваемого объекта, тип/наследование/объявление, доступ к полю, другое употребление идентификатора, строковый литерал или комментарий, совпадение только без учёта регистра, ошибка или неоднозначность разбора. Вызов с новым объектом и прямой получатель метода — сильное синтаксическое свидетельство использования. Текст упоминания в аргументе или объявлении типа может помогать модели другим способом.
3. При нескольких совпадениях в строке сохраняем набор ролей и даём приоритет сильному свидетельству. Вложенный тип внутри параметров метода / конструктора не считается его непосредственным получателем; для Foo.Bar() проверяем имя объекта, для new Foo() имя типа. Глобальные ошибки парсинга учитываем отдельно. Доля strong = число строк с хотя бы одним таким свидетельством / все строки с ребром. Идентичный анализ по панели B относится к специально отобранным задачам.
4. После запечатывания GPU-ответов описательно посчитать выигрыши/проигрыши edge против local при сильном свидетельстве и в остальных случаях. Это диагностика механизма на подгруппах. Знаменатели привести рядом с результатами. Если появится правило чтения по данным подгрупп, проверять его на новых репозиториях.
Техническое уточнение при первой проверке реализации до сопоставления с ответами. Ключ record.root в коде графа приведён к нижнему регистру. Исходное написание восстанавливается из типового объявления в целевом фрагменте через AST. Если найден только метод или цель не разрешилась, сильное типовое свидетельство не засчитывается. Первая техническая версия сравнивала имя с нормализованным ключом, её числа отброшены.

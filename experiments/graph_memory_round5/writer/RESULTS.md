# Хранение графа наблюдений кодового агента при жёстком общем лимите

На 112 новых для этого исследования траекториях Kimi K2 Instruct три способа хранения дали одинаковый основной результат. При 4096 байтах каждое состояние позволило точно восстановить старый код 112 из 253 ближайших подтверждённых правок (44,27%). Методы совпали на каждом из 253 примеров. Обратимая запись исходного текста отдельно от адресов и времени сохранила 1,88% объёма на одинаковых состояниях относительно Zstandard с прежним форматом.

## Вопрос и устройство памяти

Агент наблюдает строки файлов и подтверждения изменений в ходе работы. Граф содержит узлы путей и наблюдений с координатами и шагами, рёбра принадлежности и соседства, историю изменений. Правило R4 переносит сохранившиеся наблюдения при изменении номеров строк, проверяет их по ответу редактора, при переполнении удаляет группы с низкой оценкой полезности для будущей правки. Оно одинаково во всех ветвях. В обычной схеме адреса, время и строки лежат во вложенном JSON. В новой схеме адреса кодируются относительно конца предыдущей серии, время относительно текущего шага, а исходный текст последовательно записывается отдельным потоком. Схема обратима, проверен цикл декодирования и повторного кодирования. Весь изменяемый контекст задачи укладывается в бюджет после каждого из 3386 действий, включая служебные байты. Кодек, общий словарь 32 КиБ и прежние обученные коэффициенты разделяются всеми задачами.

На 169 непустых прежних состояниях Claude C по сумме байтов JSON заранее выбрали Zstandard-15. Суммы байтов для deflate-3, deflate-9, Brotli-4, Brotli-6, Zstandard-8 и Zstandard-15 равны 640594, 600624, 671496, 624588, 608929 и 587272. Deflate и Zstandard используют один старый фиксированный словарь. Кодирование общего графа в JSON + Zstandard-15 служит основным контролем. Дополнительная ветвь legacy воспроизводит JSON с deflate-3 из R4. Для всех 3386 последовательных состояний независимо проверено полное совпадение legacy с неизменённым R4 после замены трёх байтов служебной сигнатуры.

## Данные и порядок проверки

Официальная подача CodeSweep SWE-agent с Kimi K2 Instruct на SWE-bench Verified от 4 августа 2025 года содержит реальные инструментальные траектории. Мы отобрали задачи до загрузки истории, исключив все 101 задачи прежней панели Kimi, и ограничили вклад каждого репозитория 16 задачами. Получили 113 исходных файлов (всего 346714943 байта). 112 прошли фиксированную проекцию R3; одна задача исключена на этапе проверки допустимости наблюдений. Всего восемь репозиториев. На панели Kimi задачи и история не встречались ранее в сравнении R4 Kimi. Среди 113 исходных идентификаторов 60, 33 и 20 встречались в списках Claude A, B и C соответственно. Старый подбор правила вытеснения использовал данные Claude A. Поэтому перенос относится к новым трассам другого агента на знакомых проектах и задачах. Обучения и запуска LLM в этом эксперименте не было. Измерения выполнялись локально на CPU. [Официальный репозиторий результатов SWE-bench](https://github.com/SWE-bench/experiments) · [Статья SWE-agent](https://arxiv.org/abs/2405.15793) · [Описание Zstandard](https://www.rfc-editor.org/rfc/rfc8878.html)

778 непересекающихся срезов после каждого четвёртого действия дали 314 ближайших попыток замены в окне следующих четырёх действий. Для 253 успешных попыток удалось восстановить координаты и полный старый код из аргументов вызова и последующего подтверждения редактора. Эти эпизоды относятся к 104 задачам. Предсказания записывались и хешировались до извлечения целей. Каждая строка хранения оценена по точному совпадению пути, координаты и содержимого. Основной критерий требует совпадения каждой строки блока. На 4096 байтах средняя доля совпавших строк в блоке у всех ветвей 45,52%, доля точных первых строк 47,04%. Набор отражает видимые и обратимые правки. Даже при одинаковом пространстве в байтах цена записи зависит от компрессора.

## Эффект при изменении ёмкости

Значения в тройках означают число полностью восстановленных блоков из 253 в порядке legacy, JSON + Zstandard, предложенная схема + тот же Zstandard. Основной контраст — новая схема минус JSON + Zstandard. Остальные бюджеты относятся к исследовательскому профилю на повторно использованной панели. 95%-е интервалы получены 10000 парных бутстрэп-выборок по задачам, p — двусторонняя точная перестановка знаков разностей по задачам. ## Размер, стоимость и механизм

Это изолирует эффект представления от разницы в уже вытесненных строках. Задержка — полное настенное время одного обновления, включая отбор материала и возможные повторные сжатия. При 4096 байтах повторное кодирование одинаковых 778 состояний сократило сумму с 882276 до 865651 байтов. В исходном потоке на контрольной ветви до вытеснения переполнялись лишь 50 из 3386 состояний. Обратимый кодер может увеличить эффективную ёмкость только если меняется решение о вытеснении и затронутый материал впоследствии понадобится агенту. Потенциальная вместимость отдельного состояния и точность последовательной политики различаются: каждое выселение меняет доступный набор на следующих шагах.

Дополнительный разбор 253 целей с тем же правилом обновления и неограниченным хранилищем дал 115 полностью доступных блоков в момент среза. Из 141 промаха при 4 КиБ только 3 восстановлены одним снятием лимита. Ещё 3 появились между срезом и следующим редактированием. Остальные 135 блоков правила не смогли восстановить даже к моменту замены. Часть инструментальных действий проецируется как непрозрачная. Эти 135 случаев указывают, где стоит изучать сбор наблюдений и восстановление адреса, но не доказывают, что таких строк никогда не видел исходный агент. Основная метрика проверяет сохранённый контекст. Для выводов о количестве решённых SWE-bench задач нужен отдельный запуск агента с тестами.

## Воспроизведение и проверка

В этой папке находятся исходные идентификаторы, URL и SHA-256 всех скачанных файлов, поток событий, каждое состояние в точках измерения и результаты для каждого эпизода. Не требуются GPU, API-ключ или исходный репозиторий оцениваемой задачи. Требуются Python 3.14 с модулем compression.zstd, NumPy, Brotli и указанные в method_lock.json артефакты R2–R4. Команды для чистой копии каталога приведены ниже. Команды score и audit можно повторять на уже запечатанном наборе. Не запускать sample.py повторно поверх проверенных исходников, поскольку gzip добавляет время создания.

```powershell
python sample.py
python schema_codec.py
python run.py predict
python run.py score
python audit.py
python sensitivity.py predict
python sensitivity.py score
python sweep.py predict
python sweep.py score
python make_report.py
```

Материалы первичной проверки — PROTOCOL.md, roster_lock.json, receipts.json, dev.json, method_lock.json, checkpoint_lock.json, events_*.gz, cuts_*.gz, scored.jsonl.gz, results.json. Дополнительные исследования — SENSITIVITY.md, SWEEP.md, profile_results.json и папки profile_*. В headroom.jsonl.gz сохранено разложение каждого случая, в audit.json итоговые счётчики. Сетка профиля зафиксирована после основной оценки 4096 и до получения отдельных баллов 1024, 512, 2048 и 8192. Ветки 1024 и 4096 повторены с проверкой хеша каждого состояния.

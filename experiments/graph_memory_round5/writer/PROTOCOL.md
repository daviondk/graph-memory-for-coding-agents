До просмотра оценок новой панели. Гипотеза: запись исходных строк общим потоком отдельно от рёбер «путь — позиция — шаг» повышает долю будущих подтверждённых замен, целиком доступных в памяти при 4096 байт. На сравниваемых ветвях одинаковы online anchored rebase и cal_neighbor, входной поток, бюджет и оценщик R4. Сравниваем (1) JSON исходной R4 + штатный словарный deflate и (2) JSON + выбранный универсальный компрессор и (3) дискретная схема + тот же компрессор. Для (2)/(3) на старых Claude C состояниях до разметки новой панели выбирается один компрессор по минимуму совокупных байтов JSON из zlib с общим словарём уровней 3 и 9, Brotli 4 и 6, zstd 8/15 со словарём. Для (3) допускается только обратимое преобразование, контроль roundtrip. Основной контраст (3)–(2), полная точность блока; дополнительные метрики покрытие строк, число сохранённых строк, CPU, объём на фиксированных состояниях. Анализ всех пригодных срезов через каждые 4 действия с горизонтом ровно 4 действия. Одни и те же оцениваемые эпизоды во всех ветвях. 10 000 парных бутстрэп-выборок по задачам, микроразность точности и двусторонний тест смены знака кластеров. Перенос по репозиториям описательный.

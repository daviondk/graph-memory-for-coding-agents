# Следующее место правки без подсказки о файле или номере строки
Исследовательский опыт после результата восстановления старого блока. Проверяем новый исход на тех же трассах Kimi. Прежняя метрика обращалась по правильному адресу при оценке. Здесь Qwen сама называет путь и стартовую строку следующей подтверждённой правки. На каждом четвёртом шаге фактическая правка должна попасть в горизонт следующих четырёх действий (определение уже построенного набора из 253 эпизодов). Из пригодных срезов берём не более одного на задачу, по заранее заданному хешу, максимум 96 задач. Фильтр по видимому содержимому и критерию наблюдения применяется до запроса к GPU. Условие существования правки известно при построении набора. Будущие путь, строка, текст правки, ответы и скрытые тесты в промпте отсутствуют. Источники данных, отбор по идентификатору и точке времени запечатываем до вычисления нового исхода.
Показываем исходное описание проблемы, краткую хронологию до среза и выдержки из предшествующих успешных наблюдений. Три варианта: (1) вывод редактора; (2) вывод редактора плюс уже виденные фрагменты успешных терминальных чтений, заголовок содержит исходную команду, исходную нумерацию сохраняем; (3) те же команды, ровно те же строки и порядок, дополнительно указываем вычисленный точный адрес начала каждого фрагмента. Для (2) и (3) границу выбираем совместно, не более 900 токенов внешнего текста; длину логируем. Сходство с вопросом и давность задают одинаковый отбор в обеих ветвях. При отсутствии отличий результат обеих политик берём из одного и того же вызова. Сравниваем с простым правилом последней увиденной позиции. Формат ответа — один JSON с путём и числовой строкой, один обычный вызов Qwen3.8-27B Q4_K_M, greedy, не более 90 токенов. Ни одна программа из журналов не исполняется.
Основной исход — назван правильный файл, номер отличается от начала будущей замены максимум на 5 строк. Основной контраст — (3) против (2). Дополнительно учитываем точный файл, точный старт, разбор ответа, изменившиеся входы, токены, поиск рядом с местом правки, адрес которой ещё не был известен. Адрес из сохранённой истории применяется как отдельный простой ориентир. Парные двусторонние точные тесты и bootstrap по независимой повторной выборке задач, также чувствительность по немногочисленным репозиториям. Маленькая панель измеряет способность локализовать следующее действие записанного агента. Возможны другие правильные действия по исходной задаче. Возможность снизить число инструментальных обращений или исправить больше задач потребует отдельного интерактивного теста.

# Причинная политика для последовательного читателя
После просмотра результатов пакетного планировщика изменяем предмет проверки. Внешние панели и их результаты для других методов уже раскрывались; анализ разведочный. Заранее фиксируем режим без знания будущих запросов. Для каждого репозитория ведётся собственный баланс b с нулём в начале. При приходе запроса прибавляем три места и видим только его список объявлений. Первое объявление читаем всегда. Для позиций 2–8 предварительно оцениваем вероятность полезности по уже замороженной Java-модели размера списка и ранга. Желаемая глубина — число полезных позиций выше единого порога, плюс первое место. Порог определяется только на 24k выделенных Java HF запросах так, чтобы средняя желаемая глубина была три. Вероятности не возрастают по позиции; ничьи разрешает заранее фиксированный хеш. Минимум чтения — одно место, максимум — доступный баланс и длина списка, остаток текущего баланса обязан лежать между нулём и 12. Среднее чтение на любом префиксе истории репозитория не превосходит трёх. Прогрева или обратного просмотра нет. Для сравнения применяем фиксированный top-3, аналогичную политику с гармоническими 1/[r H(n)] и равномерными приоритетами 1/n. Они калибруют порог без меток на размерах списков обучающего набора. Ограничение баланса одинаково. Средняя квота после последнего запроса может быть использована не полностью.

Единицы — 36 000 Java-запросов и 1 997 ранее выбранных Python-запросов. Реальной временной последовательности нет. Сохраняем десять публичных перестановок SHA, seed=0…9, одну и ту же для всех способов. Основной результат — покрытие учтённых запросов относительно фиксированных трёх мест при модели по размеру, усреднённое по порядкам. Кластерный парный bootstrap проектов по усреднённому для запроса эффекту; размах по порядкам показываем отдельно. Объём чтения — количество объявлений и, для Python, полные токены CodeGen. По завершении периода не тратим баланс задним числом. В дополнение к основному контролю строим условный контроль того же фактического расхода, который идёт по неизменному графовому списку, выбирая фиксированную глубину 2 или 3 без доступа к данным и меткам. При среднем ниже 2 используется смесь соседних глубин. Точный ожидаемый уровень покрытия при таком независимом распределении мест на случаи вычисляется аналитически; это расходно-сопоставимая оценка, а не второй online-запуск.

# Короткие истории и обязательное использование бюджета

После анализа отрицательного эффекта первой последовательной политики на Python ставим отдельный разведочный опыт. Положительный исход требует повторения на ещё одном наборе. Меняем ровно верхнюю границу накопленного кредита. Вместо постоянных 12 разрешаем хранить min(12, floor(3t/50)) мест после t-го запроса конкретного репозитория; порог, распределения вероятности на позициях, начальный баланс, порядок чтения, десять исходных перестановок, обучающая выборка и панели идентичны. Таким образом при любом t незатраченные места составляют не больше 2% выданной квоты. Если история оборвётся сейчас, уже прочитано от 98% до 100% доступного. Граница выбрана как операционное требование гарантированного использования бюджета, тестовые метки настраивать её не будут. Фиксируем только эту границу, сетку параметров не испытываем. Первые 16 запросов каждого репозитория всегда получают три места. Основное измерение — покрытие по отношению к постоянному top-3 на двух языках, цена в реально выданных местах и токенах, парные интервалы по проектам. Сравниваем также неизменённую исходную политику. Анализ уровня Easy/Hard обязателен.

# Точная разность на расширенной популяции CrossCodeEval
Дополнение после наблюдения применимости bridge у 5 из 96 D, до окончания D и доступа к его целевым результатам. Замораживаем ту же функцию ранжирования и ровно те же модели, форматирование, параметры и SHA для входа. Применяем обе политики order/bridge ко всему обычному открытому тесту Java из 2139 примеров. Две популяции: основная — все видимые задачи с непустым списком и прошедшие входной фильтр, включая проекты, ранее встречавшиеся в других наборах; вторичная — после удаления совпадений с репозиториями RepoBench по тому же правилу. Политика CrossCodeEval полностью детерминирована без обучения на этом наборе. Сохраняем по каждой записи идентификатор проекта, пригодность, пересечение, SHA контекста, активацию, реальные отличия в переданных токенах или тексте. Если два JSON-запроса совпадают, их выход по протоколу общего декодирования один и разность любой метрики равна нулю. Все различающиеся пары рассчитываем на GPU, сохраняя обе генерации для каждой. Совпадающие запросы D разрешено переиспользовать с проверкой полного тела и SHA. Для доказательства разности не требуются абсолютные значения каждой политики на неразличающихся входах.
Первичный результат — точная разность числа верных операторов на всех пригодных задачах, делённая на их полное число. Дополнительно разности ES, ID EM и ID F1, разрез иных проектов, число активных пар, стоимость подсчёта. Для неопределённости переноса — 95% парный кластерный bootstrap с пересэмплированием проектов (10 000 повторов) и двусторонняя кластерная знакоперемена сумм разностей EM; точная при числе ненулевых кластеров до 18, иначе 100 000 перестановок с фиксированным seed. Отдельно показываем результаты включённых запросов, для которых реально изменилась подсказка. Это исследовательское расширение D и включает некоторые его задания, результаты D и E не считаем независимой репликацией. До открытия целей фиксируем полный ростер и предсказания.

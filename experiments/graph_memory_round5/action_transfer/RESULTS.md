# Адресная запись терминальных наблюдений на новых траекториях кодового агента

При одинаковом лимите 4096 байт агентская память, записывающая показанную терминалом строку вместе с путём и её номером, сохранила полный исходный блок для 121 из 206 ближайших правок. Обычная память редактора сохранила 73. Разность **+23,30 п. п.**, 48 выигрышей, 0 потерь. Парный 95%-й интервал по задачам от +17,45 до +29,70 п. п. Перестановка знаков по задачам даёт p = 2,27 × 10⁻¹³. Здесь измерялось наличие исходного кода для последующего действия по записи. Качество выбора самого действия и доля исправлений, прошедших официальные тесты, требуют отдельного запуска решателя.

## Что переносилось

В первоначальном эксперименте R5 синхронизировались два поля публичного журнала SWE-agent — результат конкретного tool-вызова и соответствующий текст observation. Прямые чтения и поиск с указанием файла и строк позволяют восстановить точный адрес показанного агенту содержимого. Правило допуска проверяет известность текущего рабочего каталога, синтаксис команды и полноту отображения. Оно обрабатывает данные как текст. Методы сравнения получают строго те же исторические шаги, команды из историй не запускаются. Учтены только данные, поступившие к данному срезу. Оператор видит путь будущей правки лишь при проверке состояния. Код исходного bounded.run импортирован без изменений из зафиксированной версии 7a90019e325e2b7364a1aacb6627c21296de7809a7f39e6fa87a51e29fbbd9bc. Терминальные наблюдения получают возраст и координаты в том же графе, что и обычные чтения редактора. Утверждённые правки обновляют координаты сохранившихся наблюдений.

Выбор модели сжатия был уточнён до оценки по исходному коду проверяемого исследования. В каждой ограниченной ветви один байт хранит состояние текущего каталога, а остальные 4095 кодируют все изменяемые данные через один JSON/Zstandard-15 с общим словарём R4. Главным сравнением было добавление наблюдений в память с прежней политикой вытеснения cal_neighbor. Для простой стратегии LRU устранены различия в доступе к терминалу между сравниваемыми вариантами. Отдельно оценены политики с неограниченной ёмкостью, преднамеренный сдвиг всех новых адресов на одну строку и независимое подтверждение этих адресов будущими показами редактора.

## Независимость выборки и поток наблюдений

В списках R3/R4 было 499 официальных идентификаторов задач SWE-bench Verified. Исключили 101 идентификатор старой панели Kimi R4 и все 113 первоначально отобранных для R5. Из оставшихся 285 выбрали до 33 задач на каждый из пяти допустимых репозиториев по фиксированному хешу ID. Все 98 выбранных задач удалось скачать и обработать (452 812 724 байта исходных файлов). Пересечение идентификаторов с двумя предыдущими панелями Kimi равно нулю. Генератор историй тот же, Kimi K2 Instruct в публичной подаче CodeSweep SWE-agent от 4 августа 2025 года. Сами проекты и часть задач по историям других моделей были знакомы программе исследования. Перенос относится к новым задачам и последовательностям действий этого агента. [Репозиторий открытых запусков SWE-bench](https://github.com/SWE-bench/experiments) · [SWE-agent](https://arxiv.org/abs/2405.15793)

3428 обработанных событий дали 801 срез после каждого четвёртого события. В последующих четырёх событиях нашлись 329 первых попыток замены. 207 были подтверждены редактором. Для 206 можно независимо восстановить старый блок и его адрес по замене и подтверждению. Эти цели относятся к 87 из 98 задач. Входные файлы и список задач хешированы до расчёта исходов, 32 файла предсказаний и журналов запечатаны до декодирования целей. Терминальный распознаватель извлёк 10 330 строк за 321 шаг, включая 10 013 из чтений непрерывных диапазонов и 317 из поиска в указанном файле.

## Воспроизведение

В новой копии с установленными Python 3.14, numpy, Brotli и сохранёнными R2–R5 запустите по порядку collect.py, replicate.py, evaluate.py, sensitivity.py. Из существующей записи достаточно повторить evaluate.py. Сырьевые URL и SHA-256 всех 98 оригинальных файлов, подтверждения загрузки и сведения о проекции находятся в receipts.json. Порог, список и привязка к исходному коду зафиксированы в PROTOCOL.md, BOUNDED_MATCH.md, roster_lock.json, sources_lock.json и method_lock.json. Предсказания до оценки, размеры и хеши состояния на каждом шаге находятся в bounded_cuts_*.gz, bounded_steps_*.gz и unbounded_*.gz. Идентичность защищает decisions_lock.json. В scores.jsonl.gz есть состав и метрики каждого из 206 эпизодов, в results.json и sensitivity.json — агрегаты, все контрольные группы и статистические проверки.

# Сколько графовой памяти нужно для следующей правки

> При 4 КиБ три способа записи сохранили весь код будущей правки в одних и тех же 112 случаях из 253. Компактная схема уменьшила объём одинаковых состояний на 1,88%.

Мы воспроизвели 3386 действий Kimi K2 Instruct на 112 новых для этой панели траекториях SWE-bench Verified. Все методы видели одинаковые ответы редактора. Новый способ записывает наблюдаемые строки подряд, а путь, позицию и время хранит отдельно. Контроль использует тот же алгоритм Zstandard-15, выбранный по шести вариантам на старых состояниях.

@ 4 3 3
| Бюджет памяти | Обычный JSON | Новая схема |
| 512 Б | 35 / 253 | 37 / 253 |
| 1024 Б | 86 / 253 | 88 / 253 |
| 2048 Б | 103 / 253 | 103 / 253 |
| 4096 Б | 112 / 253 | 112 / 253 |
| 8192 Б | 115 / 253 | 115 / 253 |

Основную ёмкость 4096 байт выбрали заранее. Остальные строки показывают чувствительность на тех же задачах. Два дополнительных совпадения при каждом из малых бюджетов дали p = 0,50. Средняя задержка при 4 КиБ составила 3,65 мс против 3,60 мс. Без вытеснения прежнее правило считывания и обновления восстанавливает 115 блоков в момент среза. Из 141 промаха только три объяснимы одним снятием лимита. Для 135 блоков текста по нужным адресам недоставало даже непосредственно перед правкой. Перспективнее проверить, какие результаты инструментов агент теряет при записи. Эксперимент измеряет доступность кода. Для оценки исправленных задач нужен запуск решателя и тестов.

# Что даёт повторное чтение после черновика
> На 90 дополнительных проектах Qwen сначала написала черновую строку без внешнего кода. Использование вызовов из черновика помогло немного чаще выбрать эталонное объявление. Больше точных строк получить не удалось.
После черновика одна политика искала фрагмент по BM25. Вторая проверяла, совпадают ли тип получателя и имя вызванного метода с наблюдавшимся объявлением. При отсутствии подходящей связи оставляла исходный адрес графа. В финальный промпт попадали локальный код и до 256 токенов одного фрагмента. Сам черновик влиял только на поиск и выбор окна. У 74 из 90 черновиков явной связи для переключения не обнаружилось.

| Политика | Верное объявление | Точная строка | Сходство, 0–100 |
| Без внешнего кода | — | 13 | 52,6 |
| Начало первого фрагмента | 25 | 13 | 55,9 |
| Выбор окна в нём по черновику | 25 | 11 | 54,2 |
| Поиск BM25 по черновику | 24 | 12 | 56,0 |
| Выбор по связи с черновиком | 27 | 11 | 53,9 |
Из двух повторных поисков проверка связи дала на один точный ответ меньше, парная разность −1,11 п.п., 95% интервал от −5,56 до +2,22. Улучшился один ответ, ухудшились два. Вторая попытка добавляет стоимость генерации черновика, отдельный журнал содержит полный вход и выход обоих этапов.

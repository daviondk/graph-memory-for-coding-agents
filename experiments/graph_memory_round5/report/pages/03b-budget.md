# Сколько объявлений выдавать при чтении памяти

> При одинаковом общем числе прочитанных фрагментов простой планировщик покрыл ещё 1 541 запрос в Java и ещё 66 при переносе на Python.

Граф задаёт порядок объявлений. Планировщик оценивает на обучающих Java-примерах вероятность, что очередная позиция содержит эталон, зная только размер списка и ранг. В каждой группе до 32 одновременно доступных запросов он гарантирует всем одно объявление, затем раздаёт оставшиеся места по ожидаемой отдаче. Бюджет равен трём объявлениям на запрос в среднем. Таблица показывает долю запросов, получивших эталон.

@ 6 3.3 3.3
| Распределение мест | Java, 36 000 | Python, 1 997 |
| Фиксированный top-3 | 44,34% | 52,28% |
| Без обучения, равновероятные кандидаты | 48,03% | 53,28% |
| Изученные вероятности, общая очередь | 48,62% | 55,58% |
| Те же веса, очередь внутри каждого уровня | 45,61% | 52,88% |

В общей очереди на Java метод отдавал лёгким вопросам 4,45 места, трудным — 1,55. У трудных покрытие упало с 32,97% до 20,99%. При отдельной квоте каждого уровня выигрыш над top-3 составил +1,27 п.п. на Java (95% ДИ по проектам +0,53…+2,17) и +0,60 п.п. на Python (−0,87…+2,17). Общий выигрыш на Python составил +3,30 п.п. (+0,87…+5,83). Проверка разведочная. Внешние Python-проекты исключали по совпадению полного имени с Java-выборками. При обслуживании одиночного запроса общий бюджет очереди недоступен.

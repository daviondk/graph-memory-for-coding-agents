# Какие методы уже близки к нашему

> В литературе уже проверяли отбор строк, переход по использованию и поиск по черновику. Мы проверяем, какой тип свидетельства помогает одному и тому же генератору при одинаковом доступе к коду.

Oh и Lee выбирают фрагмент для поиска, затем расширяют его предшествующим кодом и сигнатурами вызываемых функций. В HCP измерен эффект удаления тел функций. У двух моделей DeepSeekCoder изменение точности имеет противоположные знаки. ACAR объединяет лексический и синтаксический поиск по строкам и использует код после курсора. [Late Code Chunking](https://aclanthology.org/2026.acl-short.64/) · [HCP](https://arxiv.org/abs/2406.18294) · [ACAR](https://aclanthology.org/2026.emnlp-main.81/)

RepoCoder использует промежуточную генерацию для повторного поиска. Repoformer обучает модель решать, когда вообще запрашивать контекст. Rivet переходит по зависимостям и местам использования и измеряет выполнение программ на DevEval и RepoExec. InlineCoder уже связывает черновик функции с местами вызова и вызываемыми процедурами. [RepoCoder](https://aclanthology.org/2023.emnlp-main.151/) · [Repoformer](https://proceedings.mlr.press/v235/wu24a.html) · [Rivet, препринт](https://arxiv.org/abs/2610.34967) · [InlineCoder](https://arxiv.org/abs/2601.00376)

Наши расчёты генерации используют строки архивной выборки RepoBench-R. В исходной работе это задание на поиск. Для заявления о лучшем опубликованном результате нужно воспроизвести официальный сценарий дополнения или всей системы, одинаковые префикс и суффикс, читателя, бюджет и метрики. [RepoBench](https://proceedings.iclr.cc/paper_files/paper/2024/hash/d191ba4c8923ed8fd8935b7c98658b5f-Abstract-Conference.html)

# Переносится ли выигрыш поиска в качество кода
> На тех же 128 проектах, что и в панели A, двумя способами распределили ровно 384 фрагмента. Управление глубиной дало три дополнительных попадания по объявлению и две потерянные точные строки у Qwen.
Для прямой проверки каждую очередь из 32 проектов обработали дважды. Постоянная глубина давала каждому запросу три фрагмента. В переменном режиме число фрагментов выбиралось по ранее зафиксированным весам, обученным на Java, и видимому размеру списка. Порядок объявлений графа был одинаков. Каждое выбранное объявление давало первые 64 токена. 111 из 128 запросов получили разную глубину.

| Исход на всей панели | Три фрагмента на запрос | Меняющаяся глубина |
| Число выданных фрагментов | 384 | 384 |
| Токены внешних фрагментов | 23 125 | 23 183 |
| Эталон оказался среди фрагментов | 61 | 64 |
| Правильная следующая строка | 16 | 14 |
По точной строке один результат улучшился, три ухудшились. Парная разность −1,56 п.п., интервал от −4,69 до +1,56 п.п., p = 0,625. Изменение среднего сходства текста составило −0,45 по шкале 0–100. Эта проверка учитывает почти одинаковую фактическую длину контекста. Её точности достаточно, чтобы увидеть расхождение между двумя метриками, но она оставляет неопределённость в величине эффекта на других проектах.

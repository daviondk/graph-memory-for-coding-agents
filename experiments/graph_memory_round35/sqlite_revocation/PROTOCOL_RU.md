# Измерение отложенного отзыва рёбер в физической SQLite

Используем записанный поток фактических изменений отношения «источник результата → потребитель» на ISETrace. Берём 64 истории с наименьшим SHA-256 строки «sqlite-revocation-v1/» с ID истории из всех 1 207 до открытия времени выполнения. Сохраняем пустые и короткие истории. Сравниваем две политики на одной схеме SQLite и одном D-диске. Обе немедленно записывают все новые пары. Первая немедленно удаляет отозванные пары. Вторая при отзыве помечает пару в памяти, отменяет пометку при её восстановлении и применяет все действующие удаления перед следующим реальным чтением. Непустые insert/delete на одном событии объединяются в одну транзакцию, четыре чтения следуют по исходной разметке. На конце выполняется полная согласующая очистка и принудительная контрольная точка WAL. Остальные индексы, исходные тексты, вектора и обучение вынесены за границу измерения.

Главный исход качества — абсолютное совпадение состава таблицы на каждом фактическом чтении и по окончании истории с независимым потоковым эталоном. Главный исход стоимости — парная разность времени SQLite на историю с финальной контрольной точкой в миллисекундах. Также фиксируем относительное отношение средних, время без контрольной точки, число непустых транзакций, число изменений строк, пиковый размер файла WAL перед контрольной точкой и долю историй с отложенным удалением. База отдельная для каждой пары «история × политика × повтор», схема и первоначальная контрольная точка создаются до замера. SQLite WAL, synchronous=FULL, одинаковый размер страницы, автоматическая контрольная точка выключена. Заранее готовим обе последовательности SQL-операций, тем самым измеряем границу SQLite и файловой системы. Очередь пометок живёт в памяти процесса. Восстановление очереди после аварийного завершения за рамками измерения.

Четыре повтора. Для каждой истории порядок двух политик чередуется со случайным началом из независимого хеша, очередность историй детерминированно меняется между повторами. Для каждого метода и истории используем медиану четырёх замеров, затем среднее по 64 историям. Интервал из 10 000 совместных перевыборок историй. Запись и чтение выполняются на физическом локальном файле SQLite. Параллельная нагрузка от исследований на машине возможна. Этот тест не измеряет задержку всего агента.

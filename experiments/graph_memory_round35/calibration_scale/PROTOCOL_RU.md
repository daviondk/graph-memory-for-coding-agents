# Протокол. Объём данных для обучения бюджетной коррекции

Исходная коррекция R33 обучена на 196 вопросах, отдельный структурный приоритет — на 3698 вопросах. Проверяем три вложенные панели из официального train: исходные 196, затем 1024, затем все 3894 вопроса. Добавляем вопросы по хешированному порядку траекторий и идентификаторов; выбор независим от разметки. Пять складок заданы первыми 64 битами SHA256 от строки scale-v1|trajectory, по модулю 5. Все вопросы траектории остаются в одной складке. Для структурного приоритета в обучающих смещениях рассматриваем три режима.

* OOF. Структурный приоритет обучен на прежних 3698 вопросах за вычетом траекторий текущей складки.
* Полная подгонка. Общий замороженный структурный приоритет R33 использует все 3698 вопросов; с увеличением выборки возникает пересечение обучения стадий.
* Ротация. Используем модель без следующей по циклу складки; размер обучающего корпуса базовой модели сопоставим с OOF, траектории текущей складки доступны ей, если они входили в исходные 3698.

Для семантической калибровки ранга сохраняем исходную обучающую панель hash64 и при вычислении обучающих смещений исключаем текущую складку во всех трёх режимах. На dev и test во всех условиях используем один и тот же исходный структурный приоритет и один и тот же исходный калибратор семантического ранга. Отдельно воспроизводим исторический R33 с полным базовым приоритетом и исходным калибратором. Предобученный Dense-FT seed 13 уже обучался на официальном train и остаётся общим. OOF здесь относится к линейным приоритетам после энкодера.

Коррекция использует прежние четыре признака, cost-weighted worst-positive loss, температуру 0,25 и **фиксированную λ=0,03** исходного R33. Гиперпараметров по тесту или dev не выбираем. Основной контраст — все 3894 OOF минус исторические 196 R33 на Full Support@2048. Вторичные — увеличение размера внутри OOF, OOF против той же выборки при полной подгонке и ротации, обе нормированные Budget-AUC, MRR, Coverage при 2048. Для 2000 тестовых вопросов строим парные 95% интервалы с 10000 перевыборками 1207 траекторий. Исходы dev и test ранее использовались программой в других сериях. Этот анализ остаётся разведочным. При недостатке плотных векторов регистрируем фактический воспроизводимый охват и причину. Сравнение исключительно на CPU.

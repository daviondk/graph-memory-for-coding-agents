# Протокол отложенного удаления связей графовой памяти

На тех же 1207 полных естественных траекториях ISETrace воспроизводим поступление событий по порядку. Отслеживаем логические направленные пары (вызов-источник, вызов-потребитель) отношения data.feeds. Количество свидетельств внутри пары ведётся прежним точным индексом. Операция пакетного удаления измеряется в таблице производных логических пар. Если у утраченной пары появилось новое действующее свидетельство до удаления, снимаем её из очереди без переписывания пары. Событие обрабатывается атомарно: наблюдаем состояние отношения по завершении события. Наблюдаемое новое ребро вставляется немедленно. Постоянные типы связей и видимость кандидатов поддерживаются как в R34. Тексты траекторий служат только входными данными.

Пять политик. Exact сразу удаляет все отозванные пары отдельным непустым пакетом на событие. Append сохраняет пары навсегда. Periodic4 выполняет накопленные отзывы после каждой четвёртой завершённой группы вызовов; группа завершается при закрытии всех параллельно открытых вызовов. LazyRead выполняет все накопленные отзывы непосредственно перед чтением состояния на 25/50/75/100% завершённых групп. При совпадающих срезах выполняется одно чтение и одна транзакция. Pending4 сбрасывает очередь после события, когда в ней минимум четыре различные логические пары. На четвертных срезах periodic/threshold не делают дополнительного сброса. Корректный сравнительный операционный баланс указываем как перед терминальным принудительным сбросом, так и при равной точности конечного состояния после такого сброса; постоянный append принудительно не очищается, его теоретический долг показывается отдельно.

Основные показатели фиксированы до расчёта: число непустых пакетов удаления по полной истории, фактические удалённые пары, число постановок ожидающих удаления, повторные активации и максимальный размер очереди; Full Support@2048 в середине среди 901 доступного вопроса после прежнего исключения пилотных траекторий. Вторая основная популяция для интерпретации состава графа — 1845 непилотных вопросов без условия доступности. Также фиксируем все 2000 вопросов и четыре среза. Трактуем все вопросы заданного состояния как одно чтение памяти, не реплицируем число транзакций по числу benchmark-вопросов. По исходам — парный bootstrap на траекториях, 10000 повторов. Для стоимости — парный траекторный bootstrap средних чисел действий и отношения сумм между политиками. Регистрируем и изменившийся состав/порядок префикса, и изменившийся бинарный FS. Формальная экономия транзакций не измеряет задержку сервера. Тест использовался ранее, исследование разведочное.

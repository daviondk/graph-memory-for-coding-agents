# Протокол чувствительности к расписанию чтения

До вычисления результатов фиксируем восемь расписаний для всех 1207 подписанных историй R35/deferred_revocation. (1) Чтение после каждого атомарного события, изменившего множество data.feeds, плюс на последней группе. (2–6) Чтение по завершении каждой 1-й, 2-й, 4-й, 8-й или 16-й группы инструментов плюс после последней группы, даже если она вне сетки. (7) Только после последней группы. (8) Четыре исходных чтения benchmark на 25/50/75/100%, с объединением совпавших срезов. Одинаковые сигналы одного события учитываем как один барьер. «После каждого изменения» трактуется в наблюдаемой атомарности входного события, не внутри его обработки. Альтернативные программы доступа синтетические, траектории и полная последовательность добавлений/отзывов настоящие.

Сравниваем материализацию с немедленными вставками и немедленными отзывами с материализацией, которая накапливает потери поддержки пар и сбрасывает перед чтением. На каждом барьере физическое множество должно совпадать с эталоном. Основные величины — непустые пачки удалений, отношение сумм к eager, число завершённых чтений, сколько из них нуждались в пачке и максимум буфера. Вторичные — строки, удалённые фактически, вставленные строки, отменённые отзывы, терминальный долг; при равной корректности также укажем число требуемых непустых интервалов между чтениями. Для каждого режима сохраняем траекторные медианы, min/max, квартильные оценки и число траекторий с ненулевыми изменениями. Для политики фиксируем парный 95% интервал по отношению сумм на 10000 перевыборках траекторий. Приводим условное доказательство нижней грани для непустых транзакций удаления. Указываем бюджет буфера и правила атомарности, при которых она достижима. Время и число физических SQL-транзакций этим опытом не измеряются.

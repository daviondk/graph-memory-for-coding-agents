# R2-E. Граф наблюдаемых мест правки в памяти кодового агента

Фиксация до обучения и чтения исходов новых политик. Источник — сохранённые реальные траектории SWE-smith с tool-use. Используем панели source/{train,test} и transfer/source из предыдущей серии, до первой траектории на instance включительно в фиксированном порядке. Более ранние опыты на этих данных оценивали, помещается ли следующая замена в окно токенов. Текущее измерение новое, но данные ранее изучены. Обучение и тесты разделены целыми репозиториями. Детерминированно сортируем проекты по SHA256('round2edit|'+repo), каждый третий (позиции 0,3,...) полностью оставляем на тест. Программа выбирает страницу каждые четыре действия, независимо от следующего шага. Наблюдает только выполненные операции. Единица оценки — первый запрошенный str_replace следующих четырёх действий при подтверждении редактором, включая случаи, когда текста в прочитанной памяти вообще не было. Один cut соответствует не более чем одному намерению. Цель — начало непрерывного однозначно найденного фрагмента среди ранее виденных, согласованных с версией страниц по 12 строк (максимум 48 кандидатов на cut). Качество ранжирования будущей точки правки, без вывода о корректности патча.

Предложение — маленький ориентированный граф «принятая замена → файл и место → страницы», с дополнением «замена → введённые/убранные идентификаторы → ранее виденные страницы». Конкретный след определяется поиском первой изменившейся строки старого текста в текущих сохранённых страницах, до применения события. Сохраняются последние две принятые замены с исходным файлом, координатой, изменением числа строк и введёнными/удалёнными идентификаторами. Известное последующее изменение того же файла сдвигает или сбрасывает прошлую координату. При операции с неизвестным местом правки координаты этого файла сбрасываются. При чтении культурно важна привязка координат к тому же файлу: близость страницы к числу без владельца может запутать. Проверяем более простую гипотезу, что результат дают сами числа, давность, термы и файл.

Все обучаемые сравнения — одинаковая логистическая модель с дискретными группами признаков, одинаковый отбор негативов, оптимизатор и кандидаты. Контроли: прежние признаки issue/давность/центр/тип текста и частота открытий; плоский — к ним добавлены давность последних замен, совпадение файла, дистанция до номера строки без проверки файла и общий набор термов; адресный — дополнительно дистанция только в правильном файле; полный — то же плюс отдельно введённые и удалённые идентификаторы; плацебо — вместо истинного владельца координаты детерминированно выбирается другой из виденных файлов при наличии альтернативы, иначе реальное ребро, с теми же плоскими признаками. Отдельно простой контроль недавности. Новое утверждение проверяется прежде всего разностью полного и плоского методов по Hit@1. Вторичные — Hit@3, полное покрытие верхними тремя страницами, абляции по частям. Все методы могут выбирать страницы даже при отсутствии предыдущей правки. При ничьей используется порядок прежнего контроля. Парные выигрыши, проигрыши, 95% bootstrap с ресемплированием целых репозиториев 10 000 раз, макроэффекты и знак по каждому проекту. Сохраняем прогнозы по всем cut до отдельной оценки. Репозитории с общим происхождением могут снижать независимость. Этот offline replay не устанавливает, что новые действия агента были бы успешны.

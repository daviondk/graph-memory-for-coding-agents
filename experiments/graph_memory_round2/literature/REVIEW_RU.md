# Где граф может повысить качество выбора контекста и исправлений

Срез на 18 ноября 2026 года, дополнение к [обзору первого раунда](../../graph_memory_round1/graph_literature_ru.md). Нужная для проекта операция — по накопленному опыту решить, какое свидетельство передать кодовому агенту сейчас. Три соседних исследовательских сообщества уже проверяют разные части этой идеи. В многошаговом поиске можно измерить полноту набора свидетельств. В локализации кода можно проверить, найден ли полный набор изменяемых файлов. В памяти о неудачной попытке можно, наконец, измерить долю исправлений, которые прошли тесты. Разница этих конечных точек существенна для выбора заявления в статье.

## Поиск полного набора свидетельств

**Последовательное расширение выдачи уже имеет прямой эмпирический прецедент.** В работе CIKM 2026 *Beyond One-Shot Expansion* используют e5-large-v2, Qwen2.5-7B, четыре шага поиска и переоценку покрытия свидетельств. В корпусной постановке MuSiQue 57,0% запросов получили все опорные пассажи в первых десяти против 39,2% лучшего из включённых базовых методов (LameR). Замена последовательного расширения одним раундом дала 36,5%, удаление завершающего покрытия — 54,6%, удаление контрастной переоценки — 55,6%. Это числа для полного комплекта, а не доли отдельных найденных пассажей. Самый большой разрыв соответствует дополнительным раундам поиска, и он одновременно меняет вычислительный бюджет. Объявлять контрастное расширение, уточнение остатка запроса или разнообразие финального набора новым алгоритмом по отдельности нельзя. [Статья и абляции, таблицы 1–2](https://arxiv.org/html/2609.07050v1)

**Нехватку партнёра в цепочке можно проверить без сборки дорогого графа.** В SAG2 авторский лексический индекс SQLite задаёт неявный гиперграф «пассаж–терм». Модель оценивает, добавляет ли кандидат нужный факт в контекст уже выбранных пассажей, затем текст выбранных пассажей даёт термы для нового поиска. Авторы сообщают 86,62% Recall@10 на подмножестве из 1 000 вопросов MuSiQue с каталогом 11 656 пассажей. У них есть контроль широкого одношагового поиска с сопоставимым числом вызовов оценщика. Исходная модель семантических решений — JEV. Результат описывает полный ансамбль и другую единицу успеха, чем 57,0% полного покрытия выше. GRiever (EMNLP Industry 2025) также исходил из гибридного первого поиска и недорогого отбора расширений триплетов. [SAG2, §§4–5](https://arxiv.org/html/2610.22588v1) · [GRiever](https://aclanthology.org/2025.emnlp-industry.174/)

Для режима с готовыми пассажами-дистракторами наиболее полезен непосредственно проверяемый соперник — **Beam Retrieval**. Авторы обучили последовательный выбор цепочки и сохраняют несколько частичных продолжений. Для MuSiQue-Ans у beam=1 и beam=2 опубликованы 77,37 и 79,31% точного совпадения опорных пассажей; соответствующие F1 — 89,77 и 90,51%. Авторский JSON содержит 2 417 уникальных ID и для каждого — список выбранных индексов параграфов. Например, для одного двухшагового запроса выданы два индекса. Перед сравнением нужно установить пересечение ID, порядок исходных параграфов, число шагов, конкретную версию/разбиение и по возможности воспроизвести опубликованное число. Из файла нельзя восстановить ранги остальных кандидатов. Передача истинной длины цепочки — преимущество, которое обе стороны должны получить на равных или оценить отдельно. [Статья, табл. 3](https://aclanthology.org/2024.naacl-long.96.pdf) · [Поштучные предсказания, закреплённый Git](https://github.com/canghongjian/beam_retriever/blob/902980bfb5bd47a963569ab9c3621fd5ae81204a/results/retrieval/musique_pred_best.json) · [Авторский оценщик MuSiQue](https://github.com/StonyBrookNLP/musique/blob/922ac98f19a201998dbdae6d7f2887a5258dbdeb/evaluate_v1.0.py)

Для отдельной постановки поиска по корпусу проверен публичный архив сравнения NeuroGraphDB. В выгрузке запуска HippoRAG на 500 вопросах MuSiQue есть поля ranked_titles, gold, questions и answers. В файле QA на 1 000 запросов хранятся исходы graph и dense. Это результаты сообщества по его собственному корпусу/запросам. При сопоставлении названий документов требуется проверить неоднозначность и соответствие полным пассажам. Результаты по всему корпусу и по подсказанному короткому списку ответов нельзя объединять в один рейтинг. [Архив 500 выдач](https://huggingface.co/datasets/goethe0101/neurographdb-results/blob/12ae99c3a0a2f0653d3edd9d9158b664fab041e8/runs/hipporag_musique_n500.json) · [Архив QA](https://huggingface.co/datasets/goethe0101/neurographdb-results/blob/12ae99c3a0a2f0653d3edd9d9158b664fab041e8/runs/qa_musique_n1000.json)

## Локализация нескольких файлов

LocAgent (ACL 2025) использует неоднородный граф элементов кода и инструментальный поиск. На проверенной ревизии репозитория сохранился файл Claude 3.5 с 300 уникальными instance_id и полями found_files, found_modules, found_entities. Выпускаемый пример по умолчанию оценивает czlll/SWE-bench_Lite. Этот файл может служить прямым контролем по совпадающим задачам. Для результата RepoMem на 500 SWE-bench Verified с GPT-4o требуется другой запуск. [LocAgent](https://aclanthology.org/2025.acl-long.426/) · [Прогнозы](https://github.com/gersteinlab/LocAgent/blob/4935b557326c154bad8e8dcf3747cc8d32d1f387/evaluation/loc_output/locagent/claude_3-5/loc_outputs.jsonl) · [RepoMem](https://arxiv.org/html/2510.01003v2)

В reference-функции acc_at_k и предсказанный, и идеальный список меток обрезают до k. При обычной идеальной сортировке и g релевантных файлах успех означает min(k,g) найденных. Если g>k, результат может быть единицей при том, что часть файлов физически не помещается. В тексте RepoMem §4.1 Acc@k описана как полное покрытие всех исправляемых файлов. Дословное определение и реализация могут дать разные числа. Полезно публиковать сверху вниз исходную метрику автора, настоящий FullCoverage@k, любой Hit@k и размер доступного множества. Также следует учитывать фильтр отсутствующих эталонов в исходном коде. [LocAgent, реализация метрик](https://github.com/gersteinlab/LocAgent/blob/4935b557326c154bad8e8dcf3747cc8d32d1f387/evaluation/eval_metric.py#L58-L76) · [Описание RepoMem](https://arxiv.org/html/2510.01003v2)

Новизна «сначала предсказать один файл, затем расширить по графу» ограничена. В **HitMore** (Information and Software Technology, 2025) модель на первой стадии отбирает правдоподобные дефектные файлы, от которых по трём типам отношений восстанавливает остальную группу. Хороший различающий контроль для новой схемы — оставить ту же первую выдачу, тот же доступ к кандидатам и то же число мест, изменяя способ распространения свидетельств. Проверять отдельно задачи с одной и несколькими реальными правками. [HitMore](https://doi.org/10.1016/j.infsof.2025.107675) · [Авторская версия](https://weiqin-zou.github.io/papers/IST2025.pdf)

## Память о прошлом действии и ошибке

У **Experience Memory Graph** граф играет процедурную роль. Авторы сопоставляют направленные графы неудачных попыток и эталонных успешных траекторий на обучающих задачах. Из сопоставления получают исправления для узлов и связи между задачами. В ALFWorld unseen при Qwen3-4B один тестовый проход дал 21,64% успешного завершения у ReAct, 52,99% при сохранении узлов и 60,45% в полном EMG. Таким образом, большая часть разности с ReAct возникает уже в режиме узлов; добавка всей системы к узлам — 7,46 п.п. Обучающая часть использовала более сильные модели для следов/построения памяти. Доступ к успешным демонстрациям, токены и извлечённый текст должны быть уравнены в собственном тесте, чтобы приписать эффект именно связям. Эти числа относятся к игре, а не к ремонту репозитория. [Препринт EMG, табл. 2–3](https://arxiv.org/html/2607.13884v1)

Прямой прецедент, в котором **добавление типа ребра не опередило простой динамический поиск**, — MERIT. По памяти предыдущих завершённых SQL-эпизодов политика выбирает примеры исправлений на основании грубого класса ошибки и гибридного поиска. При одинаковом Qwen2.5-7B и бюджете исправления точность исполнения Spider составила 66,34% у stateless iterative и 69,79% как у MERIT, так и у нетипизированного динамического поиска в среднем по трём порядкам. На BIRD — 47,35% у iterative и 48,44% у MERIT; Reflexion-style за бо́льшую стоимость достиг 51,24%. У авторов oracle-assisted feedback. Результат показывает пользу исторических примеров в конкретном режиме и необходимость контроля на ту же информацию с обычным поиском. [MERIT, табл. 1 и абляции](https://arxiv.org/html/2608.05906v1)

**Ближайший исполнимый контроль для кодовой памяти об ошибке** — препринт *What Does a Repair Agent Gain from Remembering Its Failure?* На 75 BugsInPy-задачах из 12 проектов авторы запустили шесть исходных попыток, получили 181 неудачу в 52 задачах из 11 проектов и сохранили исход повторного запуска в пяти условиях. Актор gpt-5.4-mini, не более восьми ответов на попытку. Доля исправленных по bug-revealing tests составила 29,8% у чистого повтора, 39,2% у сырой истории, 37,2% у рефлексии, 35,4% у тестового сигнала, 39,8% у формата BOTH. Для четырёх основных сравнений с пустым условием скорректированные p составили 0,17–0,33. Более дорогая рефлексия проиграла сырой истории по оценке на 1,7 п.п., 95% ДИ [−8,7; +4,9]. Post hoc расширение до полной тестовой батареи сократило часть преимуществ. Это подходящая основа для оценки политики, которая перед повтором выбирает один из реально исполненных форматов на основании *первой* неудачи. У каждого контрфактического формата имеется отдельный стохастический запуск, а итог решения задачи следует оценивать также устойчивостью к регрессиям. [Статья, таблица II](https://arxiv.org/html/2610.41433v1) · [Поштучная таблица авторов](https://github.com/Weypher/agent-failure-memory/blob/1827cdb9f8a939d653baf6be3d94f1e00589fe93/data/results/full/C.json) · [Определения исходов](https://github.com/Weypher/agent-failure-memory/tree/1827cdb9f8a939d653baf6be3d94f1e00589fe93/m1)

## Что останется от гипотезы про различающие испытания после проверки предшественников

**Уже сделано.** CodeT генерирует тесты и программы, исполняет пары и ищет группы согласованных кандидатов и тестов. На HumanEval у code-davinci-002 авторы сообщали 65,8% pass@1, разность 18,8 п.п. с прямым исходным вариантом. Это старый актор и внутри-задачная селекция. Исполнительная матрица, поведенческое разнообразие и выбор по согласованности уже опубликованы. xTestCluster строит кластеры патчей по динамическому поведению после перекрёстного запуска сгенерированных тестов (902 патча, 21 инструмент APR, Defects4J). S* генерирует различающий вход для пары кандидатов и использует результаты исполнения для выбора программы. [CodeT](https://arxiv.org/abs/2207.10397) · [Исходные кандидаты и тесты CodeT](https://github.com/microsoft/CodeT/tree/35f54d60b152cc31d134b788e702878ad613d9f7/CodeT/data/generated_data) · [xTestCluster](https://doi.org/10.1007/s10664-024-10503-2) · [S*, Findings EMNLP 2025](https://aclanthology.org/2025.findings-emnlp.865/)

**Проверяемое отличие.** Как меняется качество повторного решения, если через границу сессии перенести короткий наблюдаемый контраст: какие две гипотезы различал тест, что он фактически наблюдал и при какой версии это было истинно? Для другой задачи передавать можно аналогичный способ различения и его предпосылки. Фактический вывод теста по чужой программе нельзя автоматически подставлять как наблюдение о текущей. Дешёвые контроли — исходный транскрипт с таким же ограничением по токенам, выбор последних тестов, отбор по разнообразию без результата, перемешивание связей с сохранением исходов и бюджетов, ближайшие соседи по тем же входным признакам. Пример на старой задаче должен иметь реально наблюдавшийся результат; использовать золотой патч или результаты скрытых тестов для отбора до решения нельзя.

**Математическая граница.** При фиксированном наборе возможных объяснений и неизменных результатах теста каждая проверка покрывает пары объяснений, которые отвечают на неё по-разному. Прирост взвешенного покрытия от очередного теста — масса ранее неразличимых пар, которые он впервые разделяет. Это классическая задача покрытия. С вероятностным состоянием и наблюдением каждого исхода родственны методы EC² и активный выбор тестов по областям решения. Отбор по количеству разных ответов не равнозначен выбору правильного исправления; если два правдоподобных патча расходятся на несущественном вводе, разбиение добавляет информации о программе, но может дать нулевую полезность для решения задачи. Для нового вклада нужно оценить **предсказание ценности сохранённого контраста до раскрытия результатов новой задачи**. Одна только субмодулярность покрытия и хранение тестовых результатов в графе такую новизну не устанавливают. [EC²](https://proceedings.neurips.cc/paper_files/paper/2010/file/1e6e0a04d20f50967c64dac2d639a577-Paper.pdf) · [Активное принятие решения, AISTATS](https://proceedings.mlr.press/v33/javdani14.html)

Если состояние S содержит наблюдения, а a — формат передаваемой памяти, целевая полезность имеет вид E[Y(a)|S]−λE[c(a)|S]. Y — тестируемый результат, c — затраты. Новое правило оправдано, только когда выбор меняет ожидаемую полезность сверх лучшего постоянного формата, выбранного на прошлых проектах. Сильная проверка — фиксированное разбиение по проекту, закрытый оценщик с исходами всех ветвей и отчёт о каждом проигрыше. Для полного цикла со свободной генерацией потребуются свежие парные прогоны под одинаковым решателем и официальным раннером.

Это целевой обзор близких методов, а не перепись всех публикаций. Запросы, граница проверки и закреплённые артефакты перечислены в [журнале поиска](SEARCH.md). Свои новые эмпирические результаты R2 следует читать отдельно от приведённых результатов авторов. Для определения границ поиска использован Literature Review из Scientific Agent Skills. [Kassis и др.](https://arxiv.org/abs/2609.00065)

## Как сравнивать выбор цельного фрагмента кода

Новый результат серии относится к накопленной рабочей памяти уже виденных участков. Для него есть более близкие соперники, чем общие GraphRAG. **SWE-Pruner** v4 предлагает актору сформулировать цель текущего чтения, а обученному модулю на 0,6B параметров — выбрать подходящие строки. Авторы проверяли как сжатие, так и решения задач программирования, включая SWE-bench Verified, и сообщают снижение расхода токенов на агентных задачах на 23–54%. **LongCodeZip** сначала ранжирует функции, затем выбирает блоки с адаптивным распределением токенного бюджета. В **Late Code Chunking**, ACL 2026, найденный поиском фрагмент расширяется дополнительным контекстом для интерпретации кода. Приоритет идеи адаптивного выбора соседних блоков и экономии контекста уже принадлежит этим и другим работам. [SWE-Pruner](https://arxiv.org/abs/2601.16746v4) · [LongCodeZip](https://arxiv.org/abs/2510.00446) · [Late Code Chunking](https://aclanthology.org/2026.acl-short.64/)

**Rivet** объединяет лексические, семантические и структурные сигналы, расширяет якоря по связям и укладывает кодовые свидетельства в заданное окно. На DevEval и RepoExec авторы сообщают положительную разность Pass@1 к лучшему из выбранных контролей при разных моделях и бюджетах 4K/8K. По их сводке это 3,73–5,15 п.п. в среднем. Наш результат по полному попаданию в будущую правку в траекториях SWE-smith измеряет другую величину. Перед заявлением о преимуществе для программирования нужен общий исполнительный тест или онлайн-эксперимент с одним и тем же актором, лимитом и доступными наблюдениями. [Rivet, препринт v1](https://arxiv.org/abs/2610.34967v1)

Возможная специфика R2-F — прогноз распределения не только начала, но и длины конкретной следующей правки условно на локальное соседство доступных страниц с последующей максимизацией вероятности *полного* покрытия. Оптимальность перебора относится к заданному распределению, а качество самого распределения доказывается только экспериментом. Независимый агентский запуск и сравнение с существующим адаптивным подрезанием пока открыты.

# Память о поведении программ до проверки скрытыми тестами

18 ноября 2026, локальная фиксация до оценки новых правил и генерации новых программ. Основная цель — повысить вероятность выбрать одну работающую реализацию. В рабочей памяти хранятся идентификаторы попыток и исполненные пары «вход → выход или ошибка». Граф строится для данной задачи по мере проверок и используется для выбора одного дополнительного вопроса модели. Дополнительный вопрос не предоставляет ни референсную программу, ни эталонный ответ. Настоящий результат определяет ранее не показанное кандидату выполнение усиленных авторских тестов. Это адаптированный протокол выбора из попыток, не официальный одиночный pass@1 акторской модели. Предшественники — CodeT/MBR-Exec, PATSSEL, методы ценности информации. Вклад конкретной комбинации подлежит проверке.

**Популяции.** Предыдущие 96 допустимых задач из локального протокола memory_session6/repair служат ретроспективной диагностикой, результаты исходных старых решений исследователям ранее были доступны. Использовать все задачи, для которых в закреплённом MBPP+ v0.2.0 имеется совпадающий программный интерфейс. До трёх ранее полученных реальных вариантов (current/raw/note с капом 1024 и fallback к исходной записи при неизменной генерации). Повтор программы по хешу сохраняет отдельный слот происхождения. Основная свежая панель — первые 48 по SHA256('r2new|id') среди остальных допустимых задач того же издателя, по прежним общим критериям и совместимому имени, без изучения меток. При нехватке — все пригодные. Старые и новые ID не пересекаются. Это новая генерация и новые для данной серии задачи, публичные датасеты могли входить в предобучение. Параметры зафиксированы заранее, решение о публикации не зависит от знака результата.

**Писатель.** Для свежих задач один и тот же локальный Qwen3.8-27B UD-Q4_K_M строит три реализации по современному описанию и интерфейсу. Разные фиксированные семена и нейтральные указания о способе решения; роли (обычное, с проверкой граничных случаев, альтернативное решение) общие для всех методов. До 384 новых токенов, температура 0.45, без thinking. Первая попытка — одиночная baseline. Синтаксически некорректные ответы и неподдерживаемое исполнение считаются наблюдаемой ошибкой, не заменяются успешной попыткой. Дубликаты хешируются и переиспользуются. Инструкции и текст из задач не выполняются как команды. Выполняются только разрешённые чистые вычисления в ограниченном subprocess. В семени проб разрешены аргументы из публичных примеров задачи Google MBPP (до трёх); ожидаемые значения этих примеров не используются как метки синтетических проб. Исполняемый первый публичный assert является исходным наблюдением у всех сравниваемых систем. Истинные результаты остальных авторских тестов доступны только финальному оценщику; все три исходные реализации оцениваются независимо от результата первого assert.

**Наблюдения и чтение.** Семена и их детерминированные малые изменения (число ±1 или 0/1, усечение, разворот, повтор элемента строки/последовательности, простая перестановка совместимых аргументов) дают до 16 неповторяющихся проб. Видимые оригинальные примеры исключены из запрашиваемых судье проб. Не запрашивать искусственные варианты, на которых одна из выживших попыток выбрасывает исключение или результат нельзя кратко показать. Типы tuple/list и порядок элементов кодировать, ограничивать размер представления. Это эвристика допустимости; человек или модель могут счесть вход вне спецификации. Разрешить ответ UNKNOWN. Двухдольный граф программ/проб с подписанными рёбрами можно также представить матрицей; отдельная СУБД не требуется.

Все способы оставляют попытки с максимальным доступным успехом на первом публичном assert. Из трёх слотов кластеры одинаковых векторов поведения делят повторённый голос: для класса с m происхождениями априорная масса пропорциональна sqrt(m). Внутри класса одинаковым правилом выбирается более ранний слот. Класс сравнивают только по доступным наблюдениям. Тест-опрос для неоднозначного входа показывает модели полную формулировку, сигнатуру, вход и нейтральный список реальных вариантов результата в хеш-порядке. Модель возвращает букву или UNKNOWN. Одинаковые запросы не оплачиваются повторно физически, логическая стоимость при раздельном запуске сообщается. Модель спрашивают максимум один раз на задачу для каждого способа. Контроли: первая попытка; первый прошедший публичный тест; статический выбор самого тяжёлого класса; один равномерно выбранный по хешу различающий вход; самая короткая различающая проба; проба максимальной weighted Gini (ничьи по фиксированному хешу); плацебо с циклически переставленным соответствием выходов классам для выбранной пробы. Если различающей пробы нет, все способы с вопросом возвращают статический результат. Стоимость исполнения одинакового набора проб учитывается у всех графовых способов, плоский контроль требует только первого теста.

Предлагаемое правило максимизирует ожидаемую вероятность выбрать правильный класс с одного шумного наблюдения. Для пробы x и правдоподобных классов i с массами p_i, результаты классов o_i известны. Пусть r(x)=0.56+0.39/(1+L/80), где L — число символов представления входа и всех различных выходов. При k>=2 вариантах P(y|i,x)=r, если y=o_i, иначе (1-r)/(k-1). Вычитать вероятность исходного решения необязательно, она одинакова для всех проб. Выбираем argmax_x Σ_y max_i[p_i P(y|i,x)]. Это точная формула для заданной модели шума и 0–1 потерь, не доказательство калибровки Qwen. После ответа выбираем максимум апостериорной массы; UNKNOWN/невалидный ответ оставляет исходное решение. Все активные контроли используют тот же prior, тот же способ интерпретации, то же ограничение вызовов. Эта оценка выигрыша математически близка стандартному value of information; не заявляем нового математического принципа. Проверить, различаются ли реально действия от простого выбора кратчайшего входа. Технические детали канонизации и точные hash-ties фиксируются в скрипте до получения результатов.

**Оценка.** Cross-task парные подсчёты по всем назначенным задачам, отсутствие кандидата или timeout — провал. Первичная метрика — доля выбранных программ, прошедших полный опубликованный усиленный тест данной задачи (MBPP+ OriginFmt); сравнить на свежих задачах предлагаемую стратегию с сильным контролем кратчайшей различающей пробы, показать всё семейство методов, парные выигрыши/потери, exact McNemar и 95% парный bootstrap по задачам (10 000, seed 182611). Вторичные: против плоского контроля и правильность решений на новых пилотных пробах, ширина потолка при выборе из трёх. Не смешивать первичный критерий с долей выживших, попаданием в тест либо выигрышем на диагностической старой панели. При наличии реального улучшения на публичных примерах перепроверить на усиленных скрытых тестах. Разрешено отдельно провести поисковый анализ признаков ошибок после запечатывания предсказаний. Не делать вывод о SOTA с другим решателем или иным количеством попыток.

# Как выбрать реализацию программы по пробам
> На 48 свежих задачах новая политика и простые способы выбора решили по 40 задач. Даже выбор задним числом из всех сгенерированных вариантов не мог дать 41-ю.
Для каждой задачи MBPP+ локальная Qwen3.8-27B в квантовании UD-Q4_K_M на RTX 3090 написала три варианта кода, всего 144 генерации. Один и тот же решатель получил три нейтральные постановки и заранее выбранные семена. Для каждого варианта отдельно выполнили первый публичный тест. Затем выполнили до 16 дополнительных малых проб и построили граф программ и наблюдённых ответов. Методы использовали один пул программ и одинаковые наблюдения.
**Решение.** Если несколько допустимых вариантов расходятся в ответе, агент может спросить модель об одном входе. Новая политика оценивает, насколько ожидаемый ответ изменит выбор кандидата. Базовые способы берут короткую различающую пробу, частое поведение программы или спрашивают модель напрямую про код. Окончательный успех определяется прохождением усиленных скрытых от селектора тестов EvalPlus. Это выбор одной программы из трёх при общем бюджете генерации.

**Почему важен потолок пула.** На свежей панели лишь в одной задаче одновременно оставались допустимые варианты, для которых политика выбирала различающий вопрос к модели. В ней ни один вариант не проходил все тесты. Таким образом, замена механизма чтения этой памяти не может улучшить свежий показатель. Для эксперимента с более чувствительным измерением нужны кандидаты, которые выживают после публичной проверки, расходятся на дополнительных пробах и хотя бы иногда проходят скрытую проверку. Отбор по скрытой проверке допустим только для анализа уже завершённого эксперимента.

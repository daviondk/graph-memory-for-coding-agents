# Как отделить эффект памяти от эффекта модели
> Для статьи интересен механизм, который улучшает заранее выбранный результат при одинаковых доступных данных. Графу предстоит превзойти лучшего содержательного соперника, а улучшение поиска предстоит связать с действиями агента.
**Чтение полного фрагмента.** Главный кандидат для следующей проверки — условная длина правки при ограниченном бюджете. SWE-Pruner уже выбирает строки по цели шага, LongCodeZip распределяет бюджет по блокам, Rivet отбирает свидетельства и проверяет Pass@1 в DevEval и RepoExec. У нас прогноз относится к будущей правке по наблюдениям конкретной траектории. Нужна прямая проверка против подходящего опубликованного алгоритма на одинаковых задачах и при том же решателе. [SWE-Pruner](https://arxiv.org/abs/2601.16746v4) · [LongCodeZip](https://arxiv.org/abs/2510.00446) · [Rivet](https://arxiv.org/abs/2610.34967v1)
**Локализация кода.** Кандидат на повторную проверку — хранить объявление и употребления только для файлов, уже найденных агентом. В качестве альтернативы использовать локальные объявления без межфайловых связей, полный текст с теми же идентификаторами и перестановку ролей. Причинный прогноз ограничен задачами, где имя встречается в нескольких кандидатах, а правильный файл уже присутствует. Этот подтип нужно задавать по входу, до обращения к ответу. Строгий тест — новые выпуски репозиториев или независимый набор задач, зафиксированный пул и веса до проверки.
**Многошаговое чтение.** Сохранять направление связи полезно, если вопрос даёт разные свидетельства о начальном и конечном узлах. На 2Wiki этот сигнал наблюдается, на MuSiQue преимущества в той же форме не обнаружено. Следующий дизайн должен различать тип вопроса, неоднозначность имени и простой эффект шаблонов. На одном и том же наборе пар нужен сильный обученный baseline и независимый корпус. Семантическая правдоподобность маршрута сама по себе ничего не говорит об улучшении ответа.
**Память в работе решателя.** Нужен эксперимент, в котором одинаковый базовый агент может запросить записи из разных политик. Общими должны быть исходный коммит, пользовательская задача, модель, инструменты, лимиты вызовов и доступный объём контекста. Финальную метку дают тесты исправленной программы, включая регрессии. Дополнительные измерения — число открытий до первого нужного файла и затраты на заполнение и чтение памяти. Подбор гипотезы по текущим результатам требует новых данных для подтверждения.
**Как читать архив.** В каждой серии сохранены исходный план и машинные таблицы. В локализации, многошаговом поиске и выборе памяти результаты привязаны к ID запроса. В экспериментах с кодом хранятся версии модели, ответы и хеши программ; для реальных повторов сохранены авторские исходы. Это позволяет менять метрику и проверять устойчивость, одновременно сохраняя результат исходного сравнения.

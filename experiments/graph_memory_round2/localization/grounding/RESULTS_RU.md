# Когда граф прочитанных файлов меняет первый выбор агента

**Эксперимент R2-A2, 18 ноября 2026.** На 407 задачах SWE-bench Verified повторное ранжирование выданных поисковиком файлов увеличило число правильных первых ответов с 193 до 250. Из этих 57 дополнительных попаданий 42 даёт ранжирование по позиции и словам, ещё 9 дают локальные роли идентификаторов и 6 — связи между файлами. Доверительный интервал для последних шести допускает ухудшение. На 274 задачах, где файлы уже отобрал и упорядочил LocAgent с Claude 3.5, граф не изменил ни одного первого ответа. Вызовы нейросети, генерация патчей и запуск тестов в этот эксперимент не входили.

## Почему проверяли первый файл

[R2-A](../RESULTS_RU.md) показал, что добавлением файлов к LocAgent при запрете вытеснения можно исправить максимум три пропуска в 274 задачах. Следующую гипотезу сформулировали после этого результата. Первую позицию можно изменить, проверяя, какой из прочитанных файлов определяет упомянутый в задаче символ, а какой только использует его. Единица проверки — задача из реального проекта, мера успеха — первый возвращённый файл входит в список файлов эталонного изменения. Шесть нижеприведённых попаданий измеряют вклад межфайловых признаков после учёта локальных. [Протокол](PROTOCOL.md)

## Какие данные видела память

Берём первые пять различных путей по порядку из опубликованного ответа. Читаем только эти Python-файлы из коммита, предшествующего эталонному изменению. Память записывает связи между файлом и объявлением, использованием или явным импортом идентификатора. При чтении учитываются имена, встречающиеся в описании задачи. Для файла, где объявлено имя t, вклад одной связи пропорционален весу слова в запросе, делённому на число кандидатов, объявляющих t, и умноженному на log₂(1 + число других кандидатов, использующих t). Отдельные признаки отражают явный импорт и единственного владельца имени. Совпадение имён в Python допускает ложные связи. Этим методом можно объяснить, откуда взялась подсказка. [Вычисление признаков](features.py)

Все обучаемые варианты получают те же пути, тексты и позиции. Базовый вариант flat учитывает ранг, путь, BM25 слов и точных идентификаторов. Вариант decl также учитывает объявления и употребления внутри каждого файла. Graph добавляет шесть признаков связи между файлами. Placebo переставляет соответствия имён и ролей внутри файла с фиксированным хешем, сохраняя наборы имён, размер ролей и размер их пересечений. Этот контроль разрушает как локальную, так и межфайловую информацию. Изоляцию собственно рёбер обеспечивает сравнение с decl.

Веса линейного скорера выбираются на парах «правильный файл и посторонний файл» других репозиториев с той же системой первоначального поиска. Общий вес каждой обучающей задачи равен единице. Минимизируется среднеквадратичное отклонение разности оценок от единичного зазора с фиксированной L2-регуляризацией 0,02. Шкалы вычисляются внутри каждого списка без меток. Если доступно менее 15 пригодных обучающих задач, возвращается исходный ранг. Проверены также обучение только на более ранних датах задач других репозиториев и перенос между системами выдачи. Дата задачи из SWE-bench служит приближением, реальный момент доступности исправления в этом тесте не установлен. [Обучение и оценка](model.py)

**Входные выборки.** На первом наборе официальные 274 задачи LocAgent, по одному целевому файлу согласно разметке авторов. Второй набор опубликован RiverRider на 500 задачах SWE-bench Verified. Это открытый технический релиз локализатора на bge-small-en-v1.5. Из 500 исключены все 93 идентификатора, встречающиеся среди первоначальных 300 ответов LocAgent. Оставшиеся 407 задач требуют работать с новыми вопросами, но охватывают те же 12 проектов. В RiverRider авторы исключали каталоги тестов и документации при формировании выдачи. Здесь выпуски разных локализаторов сравниваются только с абляциями на их собственной выдаче. Перенос без переобучения выделен отдельной строкой. [LocAgent, ACL 2025](https://arxiv.org/abs/2503.09089) · [Предсказания LocAgent](https://github.com/gersteinlab/LocAgent/tree/4935b557326c154bad8e8dcf3747cc8d32d1f387) · [Релиз RiverRider](https://huggingface.co/datasets/RiverRider/swebench-localisation/tree/c3035bcfa1fd2429884a9a73eb77b5c46ef198e5)

## Как возникает выигрыш или ошибка

Примеры выбраны после завершения оценки по заранее описываемому здесь воспроизводимому правилу. Для выигрыша и проигрыша относительно decl взяли первый SHA-256 идентификатора задачи среди случаев, где первый файл графа объявляет кодовое имя из запроса, а другой кандидат его использует. Это иллюстрации вычисляемых свидетельств. Каждый итоговый ранг учитывает одновременно все признаки.

- В Astropy #13579 локальные признаки подняли `wcs.py`. Граф вернул на первое место исходный `sliced_wcs.py`, где объявлен `SlicedLowLevelWCS`. Другой кандидат, `visualization/wcsaxes/wcsapi.py`, использует это имя. Эталон изменяет именно `sliced_wcs.py`.
- В Matplotlib #25775 граф поднял `patches.py`, где объявлен `set_antialiased`, используемый в `collections.py`. Среди правильных файлов были `text.py` и два бэкенда. Локальный ранкер выбрал `text.py`. Имя связывает части библиотеки, но связь ведёт к иному месту, чем требуемое исправление. [Проверяемые пути и идентификаторы](audit.json)

## Проверки и границы вывода

- Авторский скрипт RiverRider принимает любой путь из `gold_files`. Это уточнили до присоединения меток, сохранив первоначально указанную метрику по одному номинированному файлу. На полном релизе получены те же 229/500, что у автора. У нормализованного равенства путей и авторской проверки суффикса — 0 расхождений по первому результату. Для 71 из 500 число допустимых путей зависит от выбранного определения. На отложенных 407 при обучении на всех целевых файлах и оценке по единственному файлу получено 174/214/224/231/214 (исходный/flat/decl/graph/placebo). При обучении и тесте по единственному файлу получено 174/216/222/224/213, а при тесте по любому — 193/237/242/244/234. При оценке по путям фактического патча результат 193/235/244/250/235. [Решение о метрике](METRIC_NOTE.md) · [Аудит авторской метрики](metric_audit.json)
- Из 3 068 позиций прочитаны и успешно разобраны 3 024 Python-файла в состоянии соответствующего базового коммита, среди них 2 628 уникальных Git-объектов. У остальных 44 позиций отсутствовали исходные признаки. 34 пути относились к другим типам файлов, 10 путей Python не разрешились в базовом дереве. Пути сохранили во всех вариантах. Обход всего дерева для построения графа не требуется. Считали число прочитанных файлов. Экономия времени и токенов работающего агента не измерялась. [Квитанция данных](source_receipt.json)
- Файлы с признаками и текстом модели зафиксированы хешами до присоединения эталонов. Отдельная программа заново сравнила ранги с эталонными путями для всех 2 583 строк «задача × режим», проверила Hit@1, обратный ранг, отсутствие пересечения идентификаторов входных выборок, хеши и одинаковый состав списков у пяти способов. [Фиксация дизайна](design_lock.json) · [Проверка](audit.py) · [Аудит](audit.json) · [Ранги по задачам](score_rows.jsonl.gz) · [Веса всех моделей](coefficients.json.gz)
- Поисковая система RiverRider воспроизведена по сохранённой выдаче. Модель локального повторного ранжирования обучалась заново на других репозиториях той же выдачи. При смене типа исходной выдачи перенос весов LocAgent → RiverRider обнуляет преимущество по Hit@1. Это ограничивает предлагаемый метод случаями, где доступны решённые примеры для данного исходного поисковика. Для заявления о новом SOTA требуются независимый выпуск локализатора, оценка относительно современных систем на том же наборе и результаты настоящего агента на исправлениях.

# R2-A2. Grounding a file recommendation in the observed code

Exploratory follow-up defined 18 November 2026 *after* inspecting aggregate R2-A Acc@5, including the very low 3/168 headroom. Newly targeted outcome Hit@1. The native LocAgent aggregate 213/274 was seen, no per-issue correctness reviews, no outcomes from proposed new features, no transfer outcome data were read beyond the independent benchmark's advertised global native score. Keep all earlier outcomes. Systemic novelty relative to LocAgent, RepoMem and lexical ranking is unresolved; proposed operation is a short-lived memory that stores typed evidence only in files from the initial shortlist, then predicts the file to inspect first.

**Populations.** Internal LocAgent author test (274, canonical author labels) and a separate independent published localisation run (RiverRider on SWE-bench Verified, 500 issues before exclusions). Remove ALL issue IDs appearing in LocAgent's original 300 before transfer. Independent single nominated file via RiverRider published gold; also report sensitivity to any actual gold_files and multiple files from pinned Verified diff separately if practical. Deduplicate predictions by path, preserve first order; maximum five distinct initial files for all arms, no gold or hinted repair patch used for scoring candidates. Norm source paths by verifying exact file existence at benchmark base_commit (RiverRider prepends one path component; prefer stripping its project prefix). Preserve native first and any unavailable source. Source access to prechange Git blobs only, no execution or future revisions. Retain no raw code other than official data already available read-only. Security-related issue descriptions screened like R2-A, freeze a fallback original ranking for those if present. Absolute original publisher baseline on all 500 reported separately from matched transfer.

**Claims.** Primary, the domain with agent-generated initial ranks is the LocAgent official 274 (exploratory and reused for A1). External validation operates on unique non-Lite Verified issues with a different upstream retriever. Within each test corpus, estimate fixed weights by leave-one-repository-out with the target repo excluded. In the transfer corpus *strict* zero-shot additionally applies coefficients trained exclusively on LocAgent cases from other projects, no external training. For chronological sensitivity fit on only historically EARLIER released task dates of other repos, with no target labels exposed. Fixed-fold offline training is a diagnostic of transfer across projects, it does not assume a label was available historically unless explicitly masked by time. If training has fewer than 15 eligible comparisons, fall back to native order. Inspect primary and transfer mixed outcomes, never select comparator using the observed scores.

**Methods.** Store, for the at most five files observed during a request, file-to-identifier incidence, definition and use roles from Python AST, including attributes and imports. Python features and parsed source are read from the exact old blob. From the user message extract query identifiers, weighting code-shaped names. Test the candidate that a query term observed in several snippets is more useful when its owner is identifiable; require actual declaration, and track support from distinct other observed candidates where the identity has a use. The graph compares a literal name, a local declaration and cross-file use, with IDF within the observed candidate set. A same-name reference is evidence of a lexical connection and does not prove a runtime binding. Source reads are bounded by the baseline slate, so this evaluates a working-memory reader after the preexisting localizer. Primary comparison is typed graph vs a learned matched flat model using native rank, path features and bag-of-words/identifier overlap from exactly the same source content. Strong ablation also admits declaration-local features but removes cross-file use links; placebo permutes roles at fixed file contents and per-file count of unique declared names. Evaluate native, flat, declaration alone (local source), full graph, shuffled graph. Optional source-omission fallback flag. No neural calls; relate model only to frozen earlier LocAgent Claude output. Measuring top-one correctness and any gold in the slate, not executable fixes.

**Model.** Pairwise ridge on ground-truth vs non-gold file within each training query, each query total weight one, constant penalty 0.02 for empirical mean, target margin 1, no intercept. Keep raw features bounded or normalized within query; lowest initial rank breaks ties. Frozen scorer source and feature hashes recorded before joining labels. For source correction when no new positive information in any competition, native rank prior is available to all learners. Report comparisons with native, flat, declaration-only, shuffle; paired bootstrap resampling whole repositories holding question weights, win/loss counts, unadjusted exact sign test descriptive. Sensitivities: cross-domain held-out application to RiverRider, leave-one-project-out on external sources, chronological prior-only labels, combined performance vs all native files. No guarantee that candidate recall or token budgets match cross-dataset pilots. Output per-item and data hashes, excluded counts, source fetch failures. Include R2-A native all-300 sensitivity scored using changed *patch files* under an explicit different endpoint.

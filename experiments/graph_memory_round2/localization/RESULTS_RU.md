# Можно ли дополнить список файлов агента памятью о прошлых изменениях

**Результат фиксированного сравнения.** На всех 274 размеченных задачах авторского test из SWE-bench Lite новая политика получила 258 правильных результатов на первых пяти местах; тот же итог у исходного LocAgent с Claude 3.5 и классического графа совместных изменений. Равный по бюджету текстовый контроль нашёл ещё один правильный файл и дал 259/274. Результат объясняется ограниченным числом возможных исправлений именно в проверяемой операции. После его просмотра запущен отдельный, явно адаптивный опыт о выборе *первого* файла в [grounding/RESULTS_RU.md](grounding/RESULTS_RU.md).

В публичном ноутбуке авторов указаны 0,7774 / 0,9197 / 0,9416. Все три исходных значения воспроизведены. В оценщике LocAgent Acc@k проверяет равенство числа найденных целей и min(k, число эталонных файлов). В этом релизе все 274 задачи теста имеют один эталонный файл, поэтому определение совпало с Hit@k и полным покрытием. [Оценщик](https://github.com/gersteinlab/LocAgent/blob/4935b557326c154bad8e8dcf3747cc8d32d1f387/evaluation/eval_metric.py#L66-L75) · [Ноутбук с числами](https://github.com/gersteinlab/LocAgent/blob/4935b557326c154bad8e8dcf3747cc8d32d1f387/evaluation/run_evaluation.ipynb) · [Разметка](https://huggingface.co/datasets/czlll/SWE-bench_Lite/tree/97f9af8814fe7eb15dcd9b2abaa9010e1eadda63).

У 106 задач уже было не менее пяти предложений, и мы сохраняли исходную пятёрку. Ещё у 168 имелись свободные места. Среди них 165 задач уже содержали правильный ответ. Даже идеальный метод с правом заполнять только пустые позиции не может добавить более трёх попаданий, или 1,09 п.п. по всей выборке. Граф и сильный текстовый контроль дали разные списки в 139 случаях, истинные и переставленные связи — в 155. Нулевая прибавка наблюдалась при реальных изменениях выдачи. По основной паре с классическим графом — ноль парных побед и поражений. Для поздней половины по каждому репозиторию у графа 128/138, у текстовой политики 129/138. Описание времени — диагностическое, ранги заморожены без обучения.

## Что записывали и что читали

Агент уже составил список файлов по пользовательской задаче. Его ранговые подозрения играют роль неопределённых якорей, правильный файл нам неизвестен. Память содержит до 384 событий Git строго по первой родительской цепочке от фактического base_commit конкретной задачи. Прошлое событие хранит SHA, тему и множество изменённых Python-файлов. При чтении события, объясняющие несколько подозрений агента, получают дополнительный вес; поддержка делится между неизвестными участниками правки и снижается для очень активных файлов. Итог смешивается с независимым ранжированием по путям, эпизодам и частоте. Обычный контроль учитывает прямую частоту совместных правок, текстовый — термы запроса, BM25 по темам предыдущих изменений и частоту файлов. Все варианты видят одни и те же исходные подозрения и могут дополнять список до одного и того же предела. Классическое родство совместных правок описано задолго до LLM. Новизна применения конкретного бонуса должна оцениваться отдельно. [Zimmermann и др.](https://doi.org/10.1109/ICSE.2004.1317478) · [LocAgent](https://arxiv.org/abs/2503.09089) · [RepoMem](https://arxiv.org/abs/2510.01003).

## Проверка состава выборки и воспроизведение

Архив Claude содержит 300 уникальных выдач. В авторском тестовом файле 274 строки, входные предсказания присутствуют во всех. В качестве чувствительности отдельно разметили все 300 по именам файлов из заголовков diff исправления. Исходный LocAgent и новый граф на этой другой разметке дают по 281/300, текстовый контроль — 282/300. Дополнительные 26 задач дали всем трём 23/26. В этой серии не запускались исходники программ и не генерировались исправления. Локальный индекс путей и чтение истории дают дополнительные вычислительные расходы. [Сопоставление 300 задач](sensitivity300/summary.json).

Порядок запуска из этого каталога — fetch.py, prepare.py (требуется PyArrow), rank.py, score.py (PyArrow); для альтернативной разметки all300.py. Общие версии данных и SHA в sources.json. Исходный протокол сохранили перед расчётом рангов, прогнозы и хеш исходных правил — перед соединением с эталоном. В predictions.jsonl для предложенного дополнения сохранены исторические коммиты-свидетельства. Архив исходного агента содержит patch в поле метаданных, поэтому этап prepare.py переносит только идентификатор, момент задачи, пользовательский вопрос и ранее спрогнозированные имена; rank.py не импортирует исходный датасет. При расчёте метрик использованы только конечные ответы и официальные edit_functions. Наборы старых Git-объектов загружены анонимно, не проверялись пользовательские аккаунты. Двенадцать групп и явное ограничение на дополнение пустых позиций ограничивают обобщение.

# R2-D. Формат памяти после неудачного исправления

Зафиксировано до вычисления собственных результатов. При выборе постановки были известны опубликованные средние, схема JSON и определения авторского оценщика. Публичный источник закреплён на ревизии 1827cdb9f8a939d653baf6be3d94f1e00589fe93. Снимок из data/results/full/C.json. Подтверждающей независимой выборки пока нет.

**Единица.** Одна неудачная первичная попытка из BugsInPy, для которой авторы реально запустили все пять повторов с разным представлением памяти. Основной исход воспроизводит авторский ITT: resolved = 1, agent-caused failure и excluded_integrity = 0, ошибка harness = отсутствующий результат. Основной расчёт — пересечение пяти наблюдаемых исходов; отдельно сохранить причину потерь, сопоставимость с исходной популяцией и расхождения в знаменателях. Таймаут агента c действительным зарегистрированным outcome сохраняется. Псевдоним проекта и уникальный идентификатор события используются только для разбиения и аудита. Исходы, gold-файлы и любые свойства будущих повторов запрещены на стороне выбора формата. Берём агрегаты авторов, не исполняем задачи, команды или код из траекторий.

**Признаки.** status, subtype первой попытки; responses сгруппирован в ≤3, 4–6, ≥7; количество затронутых файлов и имён функций и отдельно файлов и имён функций из traceback, каждое в группах 0, 1, ≥2; явная категория пропуска. Дополнительный общий для обеих моделей признак — пара групп числа затронутых файлов и файлов в traceback. Только идентификаторы категорий; число ответов и списки подозреваемых получены на первой попытке. Признаки автора с именами reference, hit и precision запрещены. Не читать текст задачи, патчи или команды. Исходы пяти ветвей доступны отдельным процессом только для обучения и подсчёта метрик.

**Правило выбора.** Исключить целый проект в каждом фолде, выбирать один формат для каждого его события. Пять исходов каждой обучающей строки центрируются по её среднему. Вес обучающей строки обратно пропорционален числу строк задачи, суммарный вес одной задачи равен 1. Во всех ничьих порядок HISTORY, NONE, SIGNAL, REFLECT, BOTH. Постоянный формат выбирается по среднему на обучающих проектах. Граф типизированных связей событие → значение признака → прошлое событие → формат; IDF значения = 1 + ln((1 + число обучающих строк)/(1 + частота по обучающим строкам)); взвешенный Jaccard восьми типизированных значений в кубе. Для выбора формата агрегировать центрированный исход предыдущих событий с весом задачи, умноженным на ядро, добавить четыре единицы веса априорному среднему обучающей выборки и выбрать максимум. Это граф по агрегатам первой попытки; идентичность исходных функций и тестов из признаков недоступна. Эквивалентный алгоритм с инвертированным индексом возможен.

**Контроли.** Все пять постоянных форматов, обучающийся постоянный формат, неграфовая линейная ridge-регрессия по тем же восьми one-hot полям с взвешенным центрированием, штрафом 4 и свободным intercept. Для контроля связей графа детерминированно переместить целые векторы пяти исходов на один шаг в цикле внутри каждого обучающего проекта; порядок по SHA256 от строки «r2d-placebo|<fold>|<id>». Пусть одноэлементные блоки сохраняются. Для placebo пересчитать такую же политику. Эти настройки и tie-break зафиксированы до результатов. Условия остаются независимыми от ответов отложенного проекта. Поскольку фолды совместно используют обучающие задачи, один прогон оценивает перенос между проектами в составе этого корпуса.

**Метрики.** Основная — разность доли успешных повторов графовой политики и лучшего постоянного формата, выбранного без отложенного проекта. Проектный bootstrap 10 000, seed 41433, по имеющимся out-of-project прогнозам с пересчётом отношения сумм; интервал описательный условно на обученные правила. Дополнительно показать самостоятельный успех, полный парный расклад, подстановку каждой ветви, macro по проектам и разбивку по проектам. Показать максимум задним числом сугубо как предел данного массива измеренных попыток. Единичные стохастические повторы на ветвь ограничивают интерпретацию. Отдельный золотой набор для полного тестового прогона не используется в основном исходе. Порог рекомендации к онлайн-репликации — положительная первичная разность и выигрыш к HISTORY с поддержкой по нескольким проектам; для вывода о превосходстве нужны свежие независимые живые попытки и полный набор тестов.

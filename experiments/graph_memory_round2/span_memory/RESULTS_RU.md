# Какие фрагменты кода стоит возвращать агенту из рабочей памяти

Для выбора контекста оказалось существенно, должна ли следующая правка поместиться целиком. Если оценивать каждую страницу отдельно, в выдачу часто попадают три правдоподобных начала, а продолжение нужного фрагмента теряется. Проверили совместный выбор до трёх ранее прочитанных страниц, которые агент мог бы получить перед очередным действием редактора. По состоянию кода и наблюдаемой истории оценивается, сколько страниц займёт следующая правка. Предварительное индексирование репозитория не требуется.

На 1 907 принятых заменах модель условной ширины вернула полный фрагмент 356 раз; тот же граф и алгоритм с общей частотой длин — 315 раз. Приращение 2,15 процентного пункта, 95% ДИ [0,88; 3,11] при парном bootstrap 17 репозиториев; 91 выигрыш и 50 проигрышей. Девять проектов дали увеличение, четыре — снижение и четыре — равенство. В среднем с одинаковым весом каждому проекту разность +0,73 п.п., 95% [−1,82; 2,69]. При исключении по одному проекту основной взвешенный эффект остаётся в пределах +1,88…+2,38 п.п. Результат относится к распределению наблюдаемых действий в этой выборке.

| Правило чтения | Полный фрагмент / 1907 | Среднее число символов кода |
|---|---:|---:|
| Три наиболее недавние страницы, при равной давности — ближе к центру просмотра | 325 | 1198 |

Реальные действия предоставили авторы [SWE-smith](https://swesmith.com/). В первичный набор вошли все 567 доступных новых экземпляров по зафиксированным ограничениям и отбору (максимум 700). С более ранними наборами экземпляры не пересекаются. Для обучения взяты другие 44 проекта. Предсказания записаны на 4 091 границе. В 558 траекториях для оценки найдено 1 907 окон, где первая непустая попытка замены в ближайшие четыре действия была принята редактором. Ещё 41 окно содержало принятую замену после неудачной первой попытки и не входило в этот заранее определённый знаменатель. Эталон будущего получен в отдельной фазе. Списки read-only источников и хеши сохранены. Независимый оценщик сверил 4 091 состояние, 72 построенных примера и 8 реальных состояний с полным перебором; он подтвердил оптимальность алгоритма для заданного критерия. Средние объёмы указаны в символах. Дополнительное сравнение при фиксированных токенах приведено отдельно в BUDGET_RU.md.

**Почему можно сравнить механизм.** Пусть I — единственный интервал следующей правки, а A — множество возвращённых страниц. При награде 1 за полное покрытие условное математическое ожидание награды равно сумме P(I | история) по интервалам I, полностью входящим в A. Для ранжирования оцениваются вес начала и условное распределение ширины от одной до трёх страниц и отдельный класс более длинных интервалов. Модели видят одни и те же наблюдения; у условной ширины добавлены признаки общей давности, заполнения страниц, отступов и начала определений у соседей. Из максимум 48 кандидатов можно точно перебрать 17 296 троек. Максимизация точная для заданных весов. Сами веса оцениваются моделью, а разности результатов показывают их практическую полезность для выбора набора. Для переносимости вероятностей требуется отдельное исследование калибровки.

**Из каких правок складывается разность.** Для одностраничных целей результат нового и постоянного правила 139 против 112 (+27), для двухстраничных 141 против 119 (+22), для трёхстраничных 76 против 84 (−8). Это дополнительный разбор после оценки. В 538 случаях текст нельзя было однозначно восстановить в доступной памяти; ещё 397 целей занимали минимум четыре страницы. В одном шаге pydantic (cut 36, issue instance pr_10210) постоянная модель включила страницы 373–408, условная освободила третье место под строки 301–312, именно там была следующая замена. На шаге jsonschema (cut 44) условная модель пропустила строки 229–240, выбрав более позднюю страницу; постоянная покрыла все три. В mechanism_descriptive.json приведены неизменённые ID и критерий выбора иллюстраций по хешу.

**Место среди существующих работ.** Выбор соседних блоков кода и упаковка контекста уже имеют предшественников. [Rivet](https://arxiv.org/abs/2610.34967) оценивает генерацию в репозитории при бюджетах 4K/8K, [LongCodeZip](https://arxiv.org/abs/2510.00446) адаптирует сжатие, [Late Code Chunking](https://aclanthology.org/2026.acl-short.64/) расширяет найденный фрагмент. Здесь проверена комбинация памяти только по уже прочитанным страницам, восстановленных координат после правок, предсказания ширины следующей принятой замены и полезности полного покрытия. В этой проверке агент и его следующий патч зафиксированы исторически. Чтобы установить влияние на исправление исходной задачи, требуется сравнить точность исполняемого кода у одного и того же решателя при равном бюджете и одинаковом протоколе проверки.

В исходном рабочем каталоге зависимости для повторной оценки — NumPy, код R2-E и исходные модули packets. Команда python score.py сверяет хеши, оценивает зафиксированные прогнозы и создаёт results.json. Скрипт audit_independent.py независимо проверяет полный перебор и итоги. Для воспроизведения обучения и прогнозов используется run.py с исходными данными из work/memory_session5/packets и R2-E. Получение новой выборки производится acquire.py в Python 3.12 с PyArrow; записанные проекции уже приложены. Разбор по проектам и по ширине — project_sensitivity.py и diagnose.py.

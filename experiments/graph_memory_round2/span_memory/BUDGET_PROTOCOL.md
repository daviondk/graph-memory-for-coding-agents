# R2-F. Чувствительность к стоимости чтения

Эксплораторная проверка от 18 ноября 2026, зафиксирована до расчёта новых вариантов и их оценок. Исходный эксперимент R2-F с ограничением в три страницы уже оценён; используем те же экземпляры, данные и веса; это проверка устойчивости на прежней выборке. На каждом исходном решении все варианты получают одинаковые ≤48 кандидатных страниц из префикса и могут выбирать **0–3 страницы по 12 строк** при B=256 или B=512. Оба бюджета публикуются. Записываем выборы для всех префиксов ещё до присоединения оценочных меток. Код и команды из траекторий используются только как текст.

Рендер берётся из предшествующего пакета policy.render: строка с путём и строковыми координатами, затем тело. Стоимость набора S — сумма длин независимых Qwen-токенизаций каждой отрендеренной страницы без специальных токенов плюс (|S|−1) независимых токенизаций разделителя newline (0 для пустого). Дополнительно проверяем фактическую длину всего текста, склеенного newline. Если склеенный текст превышает предел, выбираем следующий допустимый набор. Ничьи разрешаем порядком кандидатов, среди равных оценок предпочитаем меньшее количество страниц. Лимит применяется к блоку памяти, системный запрос и окружение не входят.

Recent и pointwise жадно пропускают страницы, которые уже не помещаются; порядок исходного метода. Для global, history, typed, placebo та же условная частота ширины и тот же балл начала, что в F. Выбираем точный максимум суммы масс полностью покрытых интервалов длины 1–3. В каждом состоянии перечисляются все наборы размера 1, 2, 3 и пустой набор. Вероятность ширины 4+ даёт ноль при ограничении тремя страницами. Параметры, явные признаки и корпус обучения R2-F неизменны. Для проверок корректности используем весовой ручной перебор на небольших синтетических примерах; проверяем токены всех выбранных наборов и ограничения для каждого вопроса.

Итог — полное покрытие уникального аргумента следующей принятой замены для всех 1 907 решений тех же 567 траекторий (сообщаем отдельно скольким задачам принадлежало такое решение). Метрика включает промахи при отсутствии текста в памяти. Для каждого бюджета публикуем абсолютные n/N, wins/losses typed vs все контроли, парные двусторонние 95% bootstrap-интервалы по репозиториям (10 000, seed=261118), число и долю покрываемых решений при бюджете, среднюю стоимость и изменение точности при переходе с исходного page-only режима. Оба бюджета, все контрасты описательные. Потенциальные объяснения потери преимущества — дорогие длинные связные фрагменты или общее снижение достижимого потолка.

# Предварительный план проверки качества ответов в полном каталоге 2Wiki

Адреса, оценки поддержки всех 12 576 вопросов dev и порядок политик уже известны до этого исследования. Ответы выбранного читателя на новые контексты закрыты до фиксации плана и входов. Выбрать 384 первых ID по SHA256("r52-global-reader-v1|" + question_id) по всему dev. Без отбора по правильности, поддержке, пересечению политик или маршруту. Две политики используют одно правило прямого адреса, различаются резервной связью (primary_href против primary_text); третья всегда выбирает по href-first. Два документа, идентичный первый у всех вариантов. Первичный результат — парная разница официального Answer F1, primary_href минус primary_text. Дополнительно EM, полнота покрытия всех эталонных заголовков в двух выбранных адресах и сравнение с безусловным href_first. Для 95% интервала 10 000 парных bootstrap с кластером по первому документу, seed 523841. Указываем число отличающихся адресов и число уникальных входов. Данные по answer aliases официальных авторов используются при наличии.

Модель Qwen3-4B-Instruct-2507 Q4_K_M, greedy, RTX 3090, одно место llama.cpp, 96 выходных токенов, остановка по первому переводу строки, одинаковый шаблон запроса. Первый документ берём из уже реально открытого префикса родительской политики. Заголовок с текстом — до 192 нативных токенов модели. Вторые документы — тексты выбранных адресов из полного авторского ZIP. Для каждого вопроса ширина второго документа — минимум из трёх вариантов и 192. Совпадающие последовательности токенов порождают один детерминированный ответ. Фиксируем хеши входов до генерации, хеши ответов до доступа к эталонам. Различающиеся предсказания сохраняются независимо от результата. Полный dev служил базой отбора, заключения относятся к этой панели. Это сравнение фиксированного двухдокументного поиска, а не официальный joint score всего пайплайна.

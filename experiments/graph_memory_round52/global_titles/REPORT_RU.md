# Поиск второго источника в полном каталоге 2Wiki

В эксперименте один и тот же первый абзац читают несколько алгоритмов. Второй источник они выбирают среди 5 989 847 записей авторского снимка. Репозиторий хранит предсказания и эталонные заголовки для всех 12 576 вопросов dev. Копии всей Википедии в репозитории нет. Исходная постановка и открытая версия данных опубликованы авторами 2WikiMultiHopQA. [Ho et al.](https://aclanthology.org/2020.coling-main.580/) · [Авторский снимок и код](https://github.com/Alab-NII/2wikimultihop/tree/13800e5be57df1b4040b9b1588c6c811779e69e9)

## При каком условии помогает гиперссылка

Полное покрытие — доля вопросов, для которых два выбранных заголовка охватывают все эталонные документы. Алгоритм с приоритетом оставшегося явно написанного в вопросе названия и гиперссылкой из первого абзаца получил 2 063 полных набора, с буквальным совпадением вместо ссылки — 252. Парная разность +14,40 п.п., 95% ДИ [13,73; 15,08], 1 811 выигрышей, 0 потерь. Такой результат сам по себе переоценивает пользу навигации. В 1 785 выигранных случаях оператор выбрал резервный адрес без подтверждающей ссылки, ещё в 26 выбранное название встречалось буквально. Буквальная политика легко принимает название-подстроку или обычное слово за независимую цель.

| Политика второго чтения (первый источник общий) | Полных наборов из 12 576 | Средняя полнота по эталонным заголовкам |
|---|---:|---:|
| BM25 только по вопросу | 2 475 | 57,37% |
| Вопрос и видимый префикс, приоритет буквального названия в вопросе | 2 151 | 56,22% |
| При таком приоритете ограничить поиск буквальным совпадением в префиксе | 252 | 44,79% |
| При таком приоритете ограничить поиск реальной ссылкой | 2 063 | 55,67% |
| Сначала буквальное совпадение в префиксе | 803 | 46,89% |
| Сначала реальная исходящая ссылка | 2 479 | 54,97% |

При пустом ограниченном списке применяется общий лексический выбор. При наличии группы явно названных заголовков первичное правило ищет пересечение с ребром внутри группы. Правила «сначала» снимают это условие. В среднем один открытый префикс давал 43,08 буквальных совпадения и 5,48 проверенных исходящих адреса. Различие размеров входит в функциональное сравнение. Переключение по независимому от первого заголовка участку вопроса исследуется в [следующем эксперименте](../global_policy/PROTOCOL_RU.md).

## Что доступно при решении

Индекс содержит названия, числовые идентификаторы и статистику слов в названиях. Из корпуса читается текст только назначенных источников; физический последовательный проход по архиву служит для доступа к этим строкам. Первое решение основано только на вопросе. Для всех 23 561 различных эталонных названий в каталоге нашлась запись. В 12 325 вопросах выбранный первый заголовок оказался эталонным. После первого чтения в 9 608 случаях оставалась ровно одна нужная статья. У 2 751 вопроса четыре опоры, поэтому два чтения принципиально не дают полное покрытие. Все эти вопросы включены в знаменатель.

Открыто 11 433 различных первых абзаца. Проверялся полный интервал анкера внутри первых 192 токенов E5, затем сопоставление канонического адреса и ID. Обработано 64 062 разрешённых вхождения анкеров и 12 108 неразрешённых; ещё 152 записи имели некорректные индексы или границы при проверке. Статистика относится к использованной процедуре разрешения. Сохранялись только однозначные адреса. Приведение эталонных названий — NFC, замена подчёркивания пробелом и свёртка пробельных символов с сохранением регистра.

## Воспроизведение

Готовая проверка по сохранённым прогнозам требует Python 3.11+ и NumPy. Команда `python -B grade.py` проверяет хеши прогноза, пересчитывает все метрики и интервалы. В [результатах](results.json) лежат доли по каждому типу и размеру эталонного набора. Для восьми вопросов, выбранных по SHA от ID, независимый двухпроходный перебор полного каталога сверил 72 решения вместе с размерами четырёх множеств, включая одинаковые оценки и исключение первого документа. [Квитанция прогноза](prediction-seal.json) · [Проверка полным перебором](brute-force.json)

Для построения с нуля нужны Python 3.12, pyarrow, tokenizers, NumPy и компилятор C++17. Каталог исходных данных задаётся через R52_WIKI_WORK. Пути к parquet и tokenizer.json указаны в corpus.py и open_first.py; контрольные суммы — в source.json и opening.json. Под Windows использовался g++ с отключённым слиянием операций с плавающей запятой. Из каталога исходников:

1. Загрузить закреплённый dev.parquet в D:/CodexResearch/x20-r32-2wiki и токенизатор в D:/CodexResearch/x20-r23-multidoc2dial/model. Архив Википедии скачивает и проверяет `python -B corpus.py all`. [Авторский parquet](https://huggingface.co/datasets/xanhho/2WikiMultihopQA/blob/612bc5039a457880d9e7d84c3b0a4cf154b70e4f/dev.parquet)
2. Выполнить `python -B lexicon.py`; собрать `g++ -O3 -std=c++17 -ffp-contract=off retrieval.cpp -o <WORK>/retrieval.exe`. Из WORK вызвать `./retrieval.exe seed`.
3. Из каталога исходников вызвать `python -B open_first.py`; из WORK — `./retrieval.exe second`. Затем из исходников `python -B seal.py`. Только после этого запускать `python -B grade.py --extract`. Полный независимый перебор по выборке запускается командой `python -B verify_scan.py`.

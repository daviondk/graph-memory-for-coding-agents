# Повторный выбор пути после правки

## Наблюдаемый исход

В момент подтверждённого str_replace агент может подготовить адреса двух файлов. Первый слот всегда содержит только что изменённый путь. Для второго слота доступны ранее просмотренные или успешно изменённые Python-файлы проекта из того же запуска. Предсказывается путь первого последующего непустого view производственного Python-файла до следующей успешной правки или конца записи. Возвращение к изменённому файлу засчитывается всем вариантам, впервые увиденный другой путь — промах всем. Эпизоды без подходящего просмотра регистрируются отдельно и не имеют метки выбора пути. Это наблюдаемый спрос на адрес; содержимое не кешируется и успешность решения задачи не оценивается. Прочие действия по умолчанию пропускаются. Отдельно считаем исходы до первого непрозрачного инструмента, без использования сведений о невидимом доступе.

## Прогноз до разметки теста

Источник разработки — архив последовательностей Handoff Debt R37. Для успешной записи требуется согласованный вызов с полем matched. В просмотре требуется видимый номер строки. Совпадающие префиксы и исходы нескольких продолжений одной задачи не получают дополнительного веса при обучении. Внешний тест — оба существующих зафиксированных архива SWE-agent Claude 4 Sonnet, без всех идентификаторов issue из Handoff Debt. Используем свойство публичных траекторий и числовые события. Содержимое кода, инструкции и результаты тестов в предиктор не поступают. Фильтр производственных Python-файлов идентичен R27. Условие приземления события для SWE — порядковый номер видимой строки у view или подтверждение успешной команды str_replace у edit. Выбор тестовых вопросов и гиперпараметров по качеству на SWE запрещён. После записи весов и прогнозов измеряем результаты. Две исторические панели SWE ранее использовались для иных методов, поэтому это внешний корпус для нового оператора, а не впервые открытый набор вообще.

**Контроли.** MRU (последний посещённый другой путь), LFU (число ранее видимых обращений, ничьи по MRU), последняя входящая связь (откуда агент последний раз переключился на текущий путь), последний фактически наблюдавшийся переход из текущего файла (откат к MRU), обученный контроль. У последнего наблюдаемы возраст в числе успешных обращений, обратный ранг по давности, частоты просмотров и правок, тип последнего обращения и общая директория. Обученный контроль минимизирует условную отрицательную логарифмическую правдоподобность на доступных кандидатах. В фиксированном контроле добавляем три признака: частоту переключений текущий→кандидат, кандидат→текущий, а также сколько раз после прошлых правок текущего пути первый просмотр до следующей правки пришёлся на кандидата. Все три значения насыщаются по правилу n/(1+n). На первом появлении новой пары значения равны нулю. Оба этапа используют штраф L2 0,01 на квадрат нормы пополам и равный суммарный вес каждого обучающего issue. Ничьи по давности, затем по имени. Отдельный контроль подменяет имя текущего пути в прежней истории исходящих рёбер, сохраняя пул и исходные оценки (если есть другой узел). Расход памяти на исходящие и наблюдавшиеся после правки рёбра учитываем отдельно.

## Оценка

Первичный контраст — доля попаданий двух адресов при равном весе задач, графовый вариант минус обученный контроль на всех внешних эпизодах с наблюдаемым исходом. Интервал — парный процентильный bootstrap по задачам, 10 тыс. перевыборок, seed 520812. Двусторонняя смена знака парных эффектов на уровне задачи, точный перебор до 20 ненулевых разностей, иначе 100 тыс. случайных векторов с поправкой плюс один. Дополнительно показываем micro-hit, покрытие достижимого спроса другими путями, изменённые выборы и интервал при перевыборке репозиториев с равным весом репозитория. Отдельно считаем результаты на ранее не виденных репозиториях, на двух панелях и в подгруппе, где целевой путь отличается от изменённого. Эти разрезы описательные. Знак эффекта заранее не задан. Регистрацию сохраняем до первого расчёта показателей и отдельно фиксируем поколения весов и прогнозов.

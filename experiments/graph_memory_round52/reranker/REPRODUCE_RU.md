# Воспроизведение

Все пути заданы в `common.py`. Эта подпапка опирается на сохранённые артефакты раундов 46, 50 и 51 в том же репозитории. Два исходных корпуса — 2WikiMultiHopQA и HotpotQA в режиме distractor. Панели построены из официальных train-разделов и зафиксированы в старых раундах. Файлы `catalog-input.json.gz` предоставляют ровно вопрос, ранее открытый фрагмент и каталог заголовков. Первые документы уникальны внутри панели. Часть прочих документов используется повторно. Историю отбора и пересечения можно проверить в [2Wiki](../../graph_memory_round50/gate_confirmation/PROTOCOL_RU.md) и [Hotpot](../../graph_memory_round51/routing/PROTOCOL_RU.md).

На машине эксперимента Python и зависимости доступны в `D:/CodexResearch/x20-isetrace-e5-gpu/venv`. Для CPU используются NumPy, SciPy и requests. Для повторного GPU-прогона нужны исходные видимые панели (`PANELS`), две модели GGUF, бинарник llama-server с CUDA, официальные скрипты оценок с контрольными суммами из `grade.py`. Кэш полных весов и исходные корпуса хранятся вне репозитория. Спецификация и контрольная сумма конверсии ранжировщика даны в [протоколе](PROTOCOL_RU.md). Для читателя сверяются бинарник, веса, шаблон и результат на 24 архивных промптах. Сервер работает через loopback и завершается после своего этапа.

```powershell
$py='D:/CodexResearch/x20-isetrace-e5-gpu/venv/Scripts/python.exe'
$env:OPENBLAS_NUM_THREADS='1'
& $py -B score_ce.py
& $py -B rank.py
& $py -B reader.py
& $py -B grade.py
& $py -B audit.py
```

В чистом checkout запускайте `python -B audit.py --portable` из этой папки. Эта команда пересчитывает решения и исходы по сохранённым в репозитории рангам, квитанциям каталога и токенам, сверяет полный результат с архивом. Нужны NumPy, SciPy и requests. Веса, сырые корпуса, официальные скрипты, сеть и GPU для неё не требуются.

На машине эксперимента сохранённые решения и оценки также можно проверить командами `grade.py` и `audit.py` без GPU. Первый скрипт требует исходные официальные оценщики, второй перепроверяет метрики, адреса и токены независимым кодом по архиву проекта и видимым каталогам. При повторе полного вывода запускайте в рабочей копии. Скрипты сохраняют пересчитанные файлы и аппаратные тайминги. Для чистого GPU-повтора используйте другую пустую директорию `RUN`. Существующие журналы возобновляют обработку по хешу протокола или входов. Условия планирования параллельного GPU могут влиять на округление оценок.

Артефакты этапов: `registration.json` → `ce-seal.json` → `decision-seal.json` → `input-seal.json` → `answer-seal.json` → `grade-seal.json`. Рабочие таблицы сохраняют баллы каждого кандидата, выбор каждого правила, ID подсказок, ответы, исходы по каждому вопросу и дельты с интервалами. SHA256 связывает последовательные этапы. Официальные метрики ответов проверяются по всем назначениям. Для доли полных пар и recall используется множество эталонных **заголовков**. Эти метрики уровня документа отличаются от официальных supporting-fact метрик уровня предложений.

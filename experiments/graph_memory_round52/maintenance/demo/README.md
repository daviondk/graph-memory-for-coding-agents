# Versioned retrieval in SQLite

From this directory run `python serve.py` (or `python3 serve.py`), then open **http://127.0.0.1:8052**. An alternative port can be chosen with `--port 9000`. Requires Python 3.9+ with SQLite 3.33+, standard library only. All data are bundled, and the server binds to loopback. `python test_console.py` starts its own temporary local HTTP server and checks all 88 historical/mention setting combinations against direct recomputation.

Start with **In the Name of the Kaisers**. Receive version 2 and query version 1: the result is **Dance Girl Dance**. Change the query to version 2: words 20–21 have verified the mention **Robert Dinesen**, now the selected second document. Omit the mention: the counterfactual winner is **Dance Girl Dance**. The same controls on the second trace verify **Edward Sedgwick** but leave the leader unchanged. In the third trace **Jay Craven** keeps the same address while his winning score increases, which still requires a new journal entry.

The journal and eligible partial index are separately created and queried with live SQLite in memory on every HTTP request. The signed maintenance benchmark measures performance using the corresponding file-backed plans, WAL, durable commits under the documented synchronous policy and multiple repetitions. This console shows matching choices, exact index query plans and the bound on journal versions. Screenshots and interactive response time are not performance evidence.

The three deliberately selected examples come from the archived R51 adaptive-address panel. Bundled data include the episode hashes, public article titles, token offsets, dense ranks and precomputed scores. No retrieved passage text or model responses are distributed. A version discloses 16 more normalized words. Full-passage base scores stay fixed as the edge is revealed. The switch suppresses one genuine match as a hypothetical intervention. A lookup may select a version up to the most recently received version.

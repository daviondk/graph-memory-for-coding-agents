# Перенос выбора второго источника на вопросы с ранее не встречавшимся первым адресом

Новый тест (официальное разбиение train 2WikiMultiHopQA, R50 зафиксировал контрольную сумму локального parquet) предназначен для проверки переноса правила из global_policy. Все 12 576 dev теперь считаются разработкой. Полученные там исходы используются только для обучения явно обозначенного дополнительного контроля. В train до фиксации прогнозов доступны только поля ID и текст вопроса. Исключаем все ID и вопросы из dev и ранее использованной панели 640 train R50. Для проверки текстовых совпадений берём NFKC, lower/casefold, последовательность буквенно-цифровых слов без пунктуации. Дедупликация идёт также внутри новой выборки.

Кандидатов упорядочиваем по SHA256("r52-disjoint-confirm-v1|"+ID). Для первых 4500 запускаем неизменённое первое чтение из global_titles, затем в том же хеш-порядке оставляем первые 2400 с первым адресом вне всех 12 576 dev. Исключаем также первые адреса исторической панели R50 train по полному заголовку. Первый адрес может повторяться внутри новой панели, его повторы учитывает кластерный анализ. Если первый блок не даст 2400, последовательно продлеваем список такими же блоками. Отбор использует только вопрос, метаданные каталога и выбранный первый адрес. В итоговых данных регистрируем счётчики исключений и список ID. Семантическое родство сущностей и жанров вопросов между разбиениями возможно.

Проверяем прежний фиксированный метод: независимый полный заголовок вне всех фрагментов первого заголовка, с новым содержательным словом и двумя различными содержательными словами либо единственным с df ≤59. Если такого нет, переходим по видимому href (иначе общий fallback). Сопоставленный контроль применяет то же условие и заменяет href буквальным заголовком первого префикса. Та же первая страница, 192 токена, полная база адресов, любое правило выбирает только один второй адрес.

**Сильные контроли координации.** Ищем английский токен and/or вне всех полных вхождений первого заголовка. Такой маркер допускает независимый второй поиск. Первый вариант при наличии маркера берёт второй документ из глобального BM25 только по вопросу с исключением первого, иначе выбирает безусловный href_first. Второй вариант при маркере берёт независимый явно названный источник по прежнему правилу, если есть, иначе второй по глобальному question-only BM25, без маркера берёт href_first. Третий, более осторожный, использует независимый источник, только если присутствуют и маркер, и такой источник, в остальных случаях href_first. Способ предсказания зафиксирован независимо от типа вопроса.

**Дополнительный обучаемый вариант.** Разрешено обучить бинарное логистическое правило только на уже оценённых dev, где независимый источник доступен и результаты независимого чтения и href_first различаются по полному покрытию. Единица — вопрос. Цель равна единице, если выиграл независимый источник. Признаки заранее фиксированы: маркер and/or вне первого названия, число таких маркеров с насыщением, наличие токенов both, same, which, who, where, when, whose, earlier, first, later, more, older, younger, число токенов вопроса с насыщением n/(n+20), длина независимого заголовка, количество его содержательных слов, число подходящих кандидатов (все три n/(1+n)), уникальность и доля каталога для редкого одиночного слова в виде df/(df+59). L2, C=1, обычный порог вероятности 0,5, без настройки. Иначе выбираем href_first. Все преобразования, признаки и веса фиксируются до открытия train-эталонов.

**Измерение.** Полное покрытие всех различных эталонных заголовков двумя чтениями. Основные два сравнения — фиксированное правило относительно осторожного координационного контроля и относительно того же правила с текстовым переходом. Показываем также оставшиеся контроли и обучаемую модель, разность в процентных пунктах, кластерный percentile bootstrap по первому адресу (10 тыс., фиксированный seed 520117), выигрыши/потери, долю найденных опор и описательные результаты по типу вопроса. Дополнительно pooled для прежнего dev и новой выборки при явно различной роли этих наборов; для настраиваемого контроля train отдельно имеет интерпретацию внешней проверки. Стандартные метрики answer EM/F1 и supporting sentence F1 из этого протокола не следуют.

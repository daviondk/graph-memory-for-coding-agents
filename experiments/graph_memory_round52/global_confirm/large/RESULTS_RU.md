# Что воспроизвелось на 12 000 новых вопросов

Простое правило **«and/or или same … as»**, логистический переключатель на 21 признаке и независимо обученное дерево **выбрали одинаковые вторые адреса во всех 12 000 случаях**. Все три метода нашли полный набор опорных заголовков в 5 419 вопросах. Повторился другой результат — в ветви, где агент ищет продолжение в уже прочитанном источнике, подлинные гиперссылки существенно полезнее буквального поиска названий.

**Задача и разделение.** Из официального train 2WikiMultiHopQA взят новый хеш-порядок. Исключены известные ID и нормализованные вопросы, все первые адреса и их нормализованные названия из 12 576 dev и предыдущих 2 400, а также доступные исторические первые названия. При построении запрещённого множества использованы 17 510 исторических ID и 16 471 нормализованное название первого источника. Для получения 12 000 рассмотрено 13 679 заранее упорядоченных кандидатов с вычисленным первым адресом. В выборке 11 504 различных первых адреса. Это новая выборка тех же авторов, того же корпуса и того же семейства вопросов. Авторский ZIP и parquet совпали по всем выбранным ID, текстам вопросов, типам и уникальным эталонным заголовкам.

**Как выбирается второй адрес.** Один из вариантов — независимое полное название из отдельного участка вопроса. Оно должно содержать новое содержательное слово и либо два различных содержательных слова, либо одно редкое с df ≤59 в каталоге. Альтернатива — реальная исходящая ссылка, видимая в первых 192 токенах первого источника. При пустом списке ссылок применяется прежнее общее лексическое ранжирование. В варианте с правилом поверхности прямое название используется, когда оно доступно и в вопросе вне первого названия есть and/or либо same, а позже as. Это уточнение записано после анализа прежних 2 400 и **до формирования прогнозов для 12 000**. Логистическая регрессия и дерево обучались только на прежнем dev. Дерево CART с максимальной глубиной 3 и минимальным листом 20 фактически оставило два вопроса: имеется ли and/or вне названия и имеется ли токен same. Коэффициенты и разбиения были зафиксированы до открытия новых эталонов.

| Политика | Полное покрытие из 12 000 | Доля | Средняя доля найденных опор |
|---|---:|---:|---:|
| Безусловный приоритет видимого href | 1 514 | 12,62% | 52,13% |
| Отдельное название, иначе буквальный переход | 4 251 | 35,43% | 67,05% |
| Отдельное название, иначе href | 5 285 | 44,04% | 71,47% |
| And/or и отдельное название, иначе href | 5 334 | 44,45% | 71,68% |
| And/or либо same … as и отдельное название, иначе href | 5 419 | 45,16% | 72,03% |
| Логистический выбор, обученный на dev | 5 419 | 45,16% | 72,03% |
| Дерево решений, обученное на том же dev | 5 419 | 45,16% | 72,03% |

**Первичный результат.** Обученная логистическая модель относительно исключительно and/or дала **+0,71 п. п.**, 95% парный кластерный интервал [0,56; 0,87], изменено 85 адресов, все 85 дали дополнительное попадание. Во всех этих вопросах встречается буквальный оборот «same nationality as». Как только механический контроль учитывает same … as, исчезают все 85 различий. Тот же результат получен с обученным деревом. Относительно каждого из них у логистической модели 0 выигрышей и 0 потерь; вырожденный эмпирический bootstrap [0; 0] следует непосредственно из совпадения адресов данной выборки. Из него нельзя установить будущую эквивалентность на произвольных вопросах. Пересчёт на предыдущих 2 400 дал 1 091 у расширенного правила, дерева и логистической модели, 1 080 у простого and/or. Расширенное правило было выведено из ошибок этих 2 400; его самостоятельная проверка — только новые 12 000.

**Отдельный результат по графу.** При одинаковом фиксированном распознавании независимого заголовка href вместо буквального следующего заголовка дал **5 285 против 4 251**, то есть **+8,62 п. п.** [8,10; 9,16], 1 060 выигрышей, 26 потерь и 4 294 изменения адреса. В 6 897 случаях с самостоятельным названием оба дали 4 007 полных попаданий. На 5 103 оставшихся, где методы действительно могли различиться, получены 1 278 и 244. Все 2 327 вопросов последнего типа имеют четыре опорных заголовка, прочитать четыре источника при бюджете двух нельзя. Протокол измеряет адреса и доступ к документам. Официальные answer F1, supporting facts на уровне предложений и качество кодового агента требуют других тестов. Интервалы основаны на 10 000 парных перевыборок по первому адресу с сохранением вопросных весов; они не учитывают неопределённость переноса на новые шаблоны. Авторы 2Wiki явно описывают построение вопросов по шаблонам и структурированным данным. ## Воспроизведение

Используются те же исходные данные на диске D, что и в двух предыдущих сериях. Общий каталог и лексический индекс доступны через hardlink без второй копии. Чтобы заново посчитать баллы уже сохранённых адресов, запустите python grade_large.py, затем python verify_large.py. Пересчёт сверяет оба исходных источника и 84 000 результатов. Для пересборки адресов порядок следующий:

~~~text
python large_panel.py candidate
confirm-seeds.exe
python large_panel.py accept
python run_pipeline.py build
python large_model.py
python run_pipeline.py open
large-retrieval.exe second
large-policy.exe
python large_predictions.py
python grade_large.py
python verify_large.py
~~~

Команды .exe выполняются в D:/CodexResearch/x20-r52-directory-confirm-large, скрипты Python — из каталога данного исследования. Нужны C++17, NumPy, sklearn, pyarrow и tokenizer предыдущего протокола. До чтения эталонов SHA-256 прогнозов и входов зафиксирован в prediction-seal.json. Независимая проверка восстановила попадания и долю доступных опор из исходных выбранных адресов и ещё раз проверила непересечение с предыдущими панелями.

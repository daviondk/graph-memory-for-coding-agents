# Воспроизведение экспериментов по онлайн-записи

Независимый пересчёт из сохранённых координат занимает несколько секунд. Сохраните внутри общего каталога экспериментов соседнюю серию 18 с официальным файлом разметки. Внутри online_write выполните `python verify.py`. Проверяются прогнозы, адреса, размер сериализованного состояния и все 2 000 ID. Для этого достаточно Python 3.10+ со стандартной библиотекой. [Авторский источник эталона и способ его получения](../../graph_memory_round18/isetrace_official/REPRODUCE_RU.md)

Для полного повторения на Windows использовались CPU, Python 3.14.4, numpy 2.5.5, rank-bm25 0.2.2, tokenizers 0.23.3 и pydantic 2.14.4. Закреплённый код graph_memory берётся из репозитория авторов. Путь до него по умолчанию D:/CodexResearch/x20-isetrace-runtime/upstream, до исходного WordPiece-токенизатора — x20-isetrace-runtime/inputs/tokenizer.json, до входных 1 207 файлов — x20-isetrace-e5-gpu/cache/projection внутри того же каталога. Эти проекции восстанавливаются функцией project.py серии 18 из восьми публичных шардов; для этой серии эмбеддинги E5 получать не требуется. Переменная X20_DATA меняет корень кеша на иной диск. [Проекция](../../graph_memory_round18/isetrace_e5/project.py) · [Ревизия кода](https://github.com/xiaoqi-7/GraphMemory/tree/df29287116fa1565b3fd6b485022cd6090dc0b27)

В отдельной рабочей копии этого каталога последовательно выполните:

```powershell
python predict.py --workers 4
python score.py
python graph_write.py
python graph_score.py
python byte_memory.py predict
python byte_memory.py score
python read_diagnostic.py predict
python read_diagnostic.py score
python verify.py
```

Пакет содержит неизменяемый манифест исходного запуска. При пересборке на копии перенесите исходный MANIFEST_SHA256.json за пределы каталога пересчёта: временные заголовки gzip меняются при новом запуске. Сравнивайте на повторе распакованные координаты, прогнозы и числовые таблицы; оригинальный архив отдельно проверяется по его манифесту. Идентификаторы исходного входа, текста протокола, модели токенизации и кода содержатся в input-lock.json, четыре семейства прогнозов по шардированным файлам связаны с соответствующими lock-файлами. Команды оболочки и инструменты из исследуемых данных в конвейере не исполняются. Библиотека с зависимостями для модели-решателя в эту проверку не входит.

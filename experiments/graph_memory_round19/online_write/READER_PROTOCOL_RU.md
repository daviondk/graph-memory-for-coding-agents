# Почему сокращение памяти может улучшить выдачу BM25

Разбор механизма предложен после просмотра первичных метрик. На прежнем тесте сравним три состояния без подбора параметров. A — BM25 на всех блоках и все кандидаты; B — тот же ранговый порядок на всех блоках, затем жёсткая маска допустимых кандидатов, полученная от онлайн-правила; C — BM25 заново индексирует только допущенные блоки. В каждом случае добор целых блоков до 2048 пропускает неподходящие по размеру. Пары B−A и C−B дают точное арифметическое разложение C−A для Full Support и Coverage: эффект ограничения списка при неизменных оценках и эффект переоценки обратных документных частот и средней длины оставшихся документов. Единственное различие A и B — маска кандидатов; B и C — ранги внутри этой маски. B — диагностический офлайн-контрфактуал со статистиками всех текстов, непригодный для развёртывания с необратимым удалением. Фиксируем маски FIFO и Output-head, запись 8192, единый tie-break и поправку на зависимые запросы кластерным bootstrap. Проверяем совпадение собственного A и архивного C с уже зафиксированными рядами; никаких новых параметров.

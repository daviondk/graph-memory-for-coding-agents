# Проверка чувствительности к цене адреса

Основное сравнение уже оценено на одинаковом бюджете WordPiece. Head удерживает больше отдельных событий, поэтому адреса у него дороже. До оценки этой проверки фиксируем 32768 байт на траекторию для каждого из трёх вариантов FIFO, Head и Output-head. Формат хранения состоит из UTF-8 наблюдений, заголовка блока в 20 байт (ordinal события uint32, смещение начала uint64, длина в байтах и число WordPiece uint32) и одной словарной записи на активное событие (ordinal и размеры id/pointer по uint32 плюс UTF-8 двух строк). Добавляем второй uint64 в заголовок, чтобы восстановить длину исходного диапазона в символах без повторного декодирования; итог 28 байт. Разрешён пустой словарь без заголовка, размеры отдельных записей фиксированы, framing всего файла и постоянные рабочие расходы не включаем. В заголовке блока пишем начало и длину в символах, по длине байтов можно прочитать payload, поэтому исходный файл для использования данных не нужен.

При превышении лимита удаляем худший фрагмент и освобождаем словарную запись сразу после удаления последней ссылки. Время оценки — конец траектории. Для выдачи тот же BM25 и 2048 WordPiece, те же вопросы и эталоны. Журнал симулятора отделён от рабочего хранилища. Первичное сравнение этой дополнительной проверки — Head против FIFO по полному сохранению; вторичная метрика — Full Support после чтения. Проверяем воспроизводимость веса побайтовой сериализацией удержанных записей. Предел относится к сериализованной полезной нагрузке и адресам, метаданные индекса BM25 и heap, Python-объекты и RAM процесса в него не входят. Эта проверка предложена после просмотра основного сравнения и использует тот же тестовый набор.

# Воспроизведение и вычислительная стоимость

Первичная партия использует официальное разделение trained_rank/split.json.gz, подтверждённые train-проекции, фиксированные query-authoring и восемь шардов ISETrace. Для 256 выбранных train-ревизий программа дополнительно сопоставляет исходный raw-record SHA, определяет точные координаты размеченных символов официальным адаптером и формирует признаки 64-токенных блоков. Вычисление train-меток отделено от scoring test. Подготовка обучающих данных и подгонка обеих моделей заняли 34,2 секунды на CPU; эта величина включает чтение шардов из имеющегося локального кеша, исключая первоначальное получение корпуса и подготовку чужих проекций. Веса E5, GPU inference или API модели не используются. scikit-learn 1.8.0, NumPy 2.5.5 для обучения; небольшое окружение исходного ISETrace используется для независимой оценки. Нужные native версии и SHA перечислены в родительских источниках. [Запечатанный план](plan.json) · [Инструкции online_write](../online_write/PROTOCOL_RU.md) · [Исходные SHA ISETrace](../../graph_memory_round18/isetrace_official/source-lock.json)

Без модельных зависимостей, при сохранённых соседних каталогах со шардированными координатами и официальным gold, работает `python -B verify_learned.py`. Дополнительное `--api-check` использует локальные проекции, numpy и исходную среду. Оно физически удаляет будущие события в выбранных по хешу примерах при повторном вычислении признаков. Контролируется воспроизводимость списков записей, а BM25 повторяется с объектом, где отсутствующие в памяти фрагменты вовсе не представлены. [Проверка](verify_learned.py)

Для повторных запусков используйте копию результатов. Окружение Windows, все проектные данные на диске D:. Пакет trained_rank/prepare.py ожидает приватные сырые проекции train из D:/CodexResearch/x20-isetrace-trained; online_write использует проверенные проекции test из D:/CodexResearch/x20-isetrace-e5-gpu/cache/projection. Для полного dev используются D:/CodexResearch/x20-isetrace-runtime/write-dev-private/projection. При другом расположении исправьте пути в рабочей копии. Информация об интерпретаторах — ниже. Переизмерение времени и новые gzip-заголовки могут изменить SHA архивов при сохранении тех же результатов; первоначальные печати и модель не меняйте для самостоятельной проверки первоначального опыта.

```powershell
$env:CUDA_VISIBLE_DEVICES = '-1'
$env:PYTHONDONTWRITEBYTECODE = '1'
$trainPy = 'D:/CodexResearch/x20-isetrace-e5-gpu/venv/Scripts/python.exe'
$scorePy = 'D:/CodexResearch/x20-isetrace-runtime/venv/Scripts/python.exe'
& $trainPy -B train_write.py lock
& $trainPy -B train_write.py train
& $trainPy -B forecast_write.py
& $scorePy -B evaluate_write.py
& $scorePy -B transfer_write.py lock
& $scorePy -B transfer_write.py run
& $scorePy -B transfer_evaluate.py
& $scorePy -B reference_all.py
```

Контракт write — четыре аргумента: адреса, блоки, исходные поля и публичные метаданные пула (плюс фиксированные веса). Перечень блоков ограничен вызовами инструментов и их результатами; stream может содержать исходную историю как вход симулятора, но признаки группируются по event_id и не выходят за границы завершённого поля. Шкалы средних и отклонений, intercept и коэффициенты сериализованы в model.json. Внепредельного теневого корпуса у BM25 нет, его статистика переобучается на сохранённых блоках отдельно на каждой трассе. Код тестовой записи не импортирует загрузчик gold. В процессе проверки dev/test используются одинаковые координаты адресов и бюджета. Полные списки сохранённых и прочитанных блоков находятся в forecast-*.jsonl.gz и transfer-{dev,test}-*.jsonl.gz, поштучные исходы в outcomes.json.gz и transfer-outcomes.json.gz. Test-партия с префиксом transfer-test содержит дополнительный режим списания размера модели; прочие test прогнозы повторно берутся из первой замороженной серии. Операции `--write-manifest` предназначены для новой упакованной копии после воспроизведения.

# Перенос закреплённого скорера и стоимость модели

После исходов 2 000 тестовых вопросов замораживаем перенос без переобучения или изменения параметров на полные 580 вопросов авторского dev / 352 траектории, предоставленные write_transfer. Модель зафиксирована, SHA контролируется и до, и после анализа. Целевая проверка — парные Full–output_head и Full–Positional для read FS, дополнительно write FS и FIFO. Результаты предшествующей серии простых правил на dev существовали до регистрации; новые прогнозы обученного скорера на dev ранее не вычислялись. Dev — другое траекторно-непересекающееся разбиение того же корпуса. Обучение использовало только 256 целей из train, настройка на dev отсутствовала. Перед запуском сверяем собственные query_id и trajectory_id train/test с полным dev, а также SHA сохранённых raw projections и исходных тестовых блоков.

Отдельная чувствительность на **обеих** выборках — режим единственного пользователя с общим бюджетом 32 768 байт, в который включаем полный фактический размер сериализованного model.json (3 911 байт, в том числе коэффициенты обеих абляций). Скореру остаётся 28 857 байт для записей. FIFO и output_head по-прежнему получают 32 768; все сравниваемые варианты используют тот же исходный сериализатор данных и индекс событий. Общий Python-интерпретатор и код эвристик никому не тарифицируются. Это чувствительность к явно объявленному учёту веса модели, а не измерение RAM процесса; при общем для нескольких траекторий скорере исходные значения остаются релевантными. Для новых условий сохраняем выборы каждой политики и фиксируем до оценивания. Пишущий API получает исходные поля и метаданные завершившихся событий, без вопросов и разметки. Читающий API получает только сохранённые блоки и тексты вопросов. Сквозное действие агента в этом сравнении не оцениваем. [Разделение write_transfer](../write_transfer/split-audit.json)

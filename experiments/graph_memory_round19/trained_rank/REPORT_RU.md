# Упаковка доказательств после дообучения E5 на ISETrace

Проверяем, сохраняется ли преимущество дополнения пары «аргумент — результат» после обучения модели ранжировать источники для этой задачи. Использована нативная реализация provenance-unit Dense-FT проекта GraphMemory. Полные веса E5 дообучены на всех 3 894 train-запросах. Из 580 доступных dev-запросов публичный профиль использует 500. Фиксированная тестовая выборка включает 2 000 запросов из 1 207 отдельных траекторий. Seed обучения 13. Пользовательские задачи и команды из траекторий служат текстом для извлечения.

**Основной результат.** При 2 048 токенах парное дополнение получает 1494/2 000 случаев полного покрытия (74,70%), обычный добор skip — 1503/2 000 (75,15%). Разница -0,45 п.п., 95% кластерный ДИ [-1,01; 0,10]. Против skip поштучно 11 выигрышей, 20 проигрышей и 1969 совпадений, средняя разница фактически прочитанного 0,03 токена.

## Сравнение способов чтения

|---|---:|---:|---:|---:|---:|---:|---:|
| prefix | 1458/2000 | 72,90 | 78,94 | 2,90 | 5,47 | 1846,0 | 8,2 |
| clip | 1488/2000 | 74,40 | 80,19 | 2,64 | 5,02 | 2046,4 | 9,2 |
| skip | 1503/2000 | 75,15 | 80,83 | 2,64 | 5,02 | 2039,2 | 12,2 |
| value | 1499/2000 | 74,95 | 80,56 | 2,63 | 5,00 | 2036,4 | 15,2 |
| related | 1494/2000 | 74,70 | 80,14 | 2,64 | 5,01 | 2039,3 | 12,4 |

FS измеряет наличие всех размеченных символов, Coverage — долю покрытых символов, Density — долю эталонных символов среди прочитанного. Все политики получают один и тот же обученный порядок узлов. Prefix останавливается перед первым переполнением, clip добавляет допустимую часть следующего узла, skip добирает последующие помещающиеся узлы. Value переупорядочивает остаток по score/√tokens. Related первым рассматривает блок противоположной стороны уже выбранного вызова, затем сохраняет исходный порядок.

Все интервалы — парный бутстреп с 10 000 выборками целых траекторий. Различия ранжировщиков с меткой frozen получены на тех же ID из R18. Выборка общая для предыдущих исследований, этот повтор проверяет перенос политики на новые оценки узлов.

Опубликованный residual R-GCN c нативным prefix имеет 77,33 ± 0,53% Full Support. Наша строка related численно отличается от этого среднего на -2,63 п.п. Для честного сравнения добавочного вклада порядка чтения на разных архитектурах требуется применение той же упаковки к индивидуальным рангам R-GCN и несколько одинаковых seeds. В статье разность ранжировщиков парно оценивается после усреднения соответствующих 5 seeds. [Таблица 1 авторов](https://arxiv.org/html/2609.25913v3#S6.T1)

## Контроль обучения и вычислительные расходы

Все 26 650 авторских обучающих пар дали 5 330 троек и 337 шагов. При выборе лучшей из epoch 0 и 1 по метрике dev_recall_at_5 получено 0,72700. Сверка исходного и выбранного encoder обнаружила изменения в 197 из 199 тензоров, относительная L2-разность весов 0,00556. Закреплены SHA каждой части чекпойнта; сами веса хранятся на D. Исходный run со всеми проверками dev занял 11,3 мин. Отдельно переиндексация всех 138671 уникальных тестовых строк — 13,2 мин, FP32, TF32 выключен, RTX 3090. Хеш планов и чекпойнта зафиксирован раньше тестовых прогнозов, поштучные прогнозы — раньше тестовой оценки.

Оригинальный архив TeX v3 содержит девять файлов — текст, библиографию, служебные файлы и четыре PDF-фигуры. В проверенном дереве GitHub (329 записей), официальных releases/tags и обнаруженных HF-репозиториях не обнаружены отдельные ранги или чекпойнты residual R-GCN. В public-artifact-audit.json перечислены проверенные URLs, содержимое и SHA. Для следующего прямого сравнения R-GCN нужны его индивидуальные прогнозы либо воспроизведение графового обучения. В train/dev-проекции 300 931 дополнительная уникальная PU/query строка относительно test. При наблюдаемом ранее темпе E5 FP32 только эта часть соответствует примерно 27 минутам; цена непроекционных узлов и 15 эпох графа требует отдельного замера. [Код и конфигурации](https://github.com/xiaoqi-7/GraphMemory/tree/df29287116fa1565b3fd6b485022cd6090dc0b27)

## Дополнительная верификация

Независимый прямой CPU-вызов авторского DenseTaskRetriever на восьми заранее хеш-отобранных запросах использовал сохранённый обученный checkpoint. Совпало top-1 на 8/8, top-5 в точном порядке на 8/8 и полная перестановка на 7/8. Максимальная абсолютная разность оценок 7.7e-07.

Одна тестовая задача изменяет FS отдельного seed на 0,05 п.п. При среднем по пяти seed и округлённом выборочном SD можно ограничить отдельные значения. Для R-GCN таблица допускает 371 неупорядоченных пятёрок целых чисел попаданий и значения отдельного seed от 76,40 до 78,25%. Для PU Dense-FT диапазон 71,65–73,90%. Эти интервалы — арифметически возможные значения отчётных результатов, не доверительные интервалы и не восстановленные результаты конкретного seed.

При наличии исходных рангов R-GCN сам постпроцессинг недорог. Для 249089 элементов уже имеющихся рангов R18 E5 при той же форме входа декодирование и подготовка метаданных всех 2 000 задач заняли 0,92 с CPU, применение paired имело медиану 0,089 с за пять повторов. Для R-GCN это ориентир по данным той же размерности.

Во время запуска первая попытка read-only подключения к SQLite остановилась до первого test-вектора. Исправлен параметр URI для Windows, зафиксировано нулевое число строк, сохранены исходный SHA, код и stderr. Повтор использовал те же данные, обученные веса и параметры.

**Доступ к разметке.** Preprocessor prepare.py вызывает авторский _read_queries для всего смешанного raw JSONL. Он десериализует и записи test, включая вложенные поля gold, прежде чем отфильтровать 3 894 train и 500 dev ID. Эти test-метки не использовались при создании положительных/отрицательных примеров, вычислении loss или выборе checkpoint. Это программная изоляция по разделам внутри процесса с физическим доступом к общей разметке. Поисковые ранги были запечатаны до оценивания. Класс исследователя также имел доступ к прежним агрегатам R18 на том же test. Подтверждающие проверки собраны в leakage-audit.json.

**Осуществимость нативного R-GCN.** Повторное построение графов для всех 3 948 используемых траекторий дало 466074 уникальных текстов узлов и запросов. Требуется 327403 новых строк относительно текущего кэша. Развёрнутый авторский train/dev mmap имеет объём 2,31 GiB. Пакет из 128 реальных train-запросов дал 21172 узлов и 51738 двунаправленных рёбер после нативной фильтрации. На RTX 3090 три нативных слоя 256/14 на этой топологии прошли forward/backward AdamW с пиком 0,68 GiB. Тест использует синтетические замороженные признаки и скалярную диагностическую loss. Он проверяет вместимость рабочего графового ядра, но не качество R-GCN, пиковую RAM полного процесса или все batch. Отдельные метки рёбер не требуются: связи строит исходный код, supervision берётся из выпущенных символьных spans.

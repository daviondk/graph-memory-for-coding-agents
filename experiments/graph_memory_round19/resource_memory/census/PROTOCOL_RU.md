# Проверка пропуска обращения stat и полный перебор type stub

После основной панели и направленного контрпримера зафиксировано единственное расширение правила. Для модифицированного type stub или Python-помощника следим также за вызовами os.stat и os.lstat из Python, включая обращения pathlib, на приёме точного изменённого пути. Регистрируем совпадение пути до выполнения реальной функции, включая несостоявшиеся запросы. При относительном пути и неизвестном dir_fd получаем неопределённость и назначаем повтор. Если имелся такой запрос метаданных, выбираем файл даже при отсутствии обычного открытия. Для pyproject это расширение отключено: штатный discovery pytest постоянно проверяет наличие файла и нуждается в отдельной систематической проверке уровней метаданных. Тем самым новая граница заранее обозначена. Механизм не перехватывает нативные системные вызовы и дескрипторы без известного пути.

На том же синтетическом наборе из 35 случаев проверяем, устранился ли наблюдавшийся пропуск, и изменился ли расход. Это починка на известном контрпримере, не независимое подтверждение. Отдельно на единственной из четырёх первичных ревизий, затронувшей только .pyi среди интересующих ресурсов (296af975), запускаем полный набор из 48 общих test-файлов на исходном и новом SHA с новой диагностикой и предиктором до открытия дополнительных поштучных меток. Файлы уже известны из родительского plan.json; на первых 14 результаты уже известны. Полная серия post hoc и не меняет чисел первичной панели. Предсказываем сначала, сверяем авторский список с прогнозами после их фиксации, повторно исполняем все файлы для сравнения фактических исходов. При нулевом количестве авторских affected или чистых pass→fail явно указываем неопределяемость полноты. Оцениваем число повторов, исходы всех файлов и чтения type stub, в том числе неожиданные.

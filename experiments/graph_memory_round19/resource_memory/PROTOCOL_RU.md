# Память наблюдавшихся ресурсов в дополнение к графу ранее пройденных тестов

Для каждой программы известен реальный истинный родитель и новый SHA. Основной baseline R18 сбрасывает все результаты при любой правке pyproject.toml, файла .pyi пакета или тестового помощника. Первичная политика заменяет такие общие сбросы на рёбра «тестовый файл → наблюдавшийся ресурс», сохраняя прежнее правило для всех остальных правок. Для файла проекта добавляется отдельное типизированное ребро «файл тестов → чтение секции tool.pytest.ini_options закреплённой функцией pytest». Запускается точный исходный pytest с регистрацией событий audit и динамических входов в изменяемые модули. Относительные и абсолютные пути нормализуются. Признак чтения conftest/скрипта и загрузки .py фиксируется через open или реально исполненный frame тестового помощника. У модифицированного .pyi повтор нужен, если в данном запуске исполняемый код действительно обращался к этому пути. В контексте конкретного инструмента важен путь, тип читателя и та часть состояния, которую он мог использовать.

При изменении файла, необъяснённого чтения или динамического вызова дочернего процесса сохраняется осторожное решение. Уточнение: модификация ресурса с зарегистрированным чтением требует повтора, кроме чтения pyproject исключительно закреплённой load_config_dict_from_file, когда обе версии успешно разбираются и значение tool.pytest.ini_options неизменно. Добавление/удаление любого ресурса, непрозрачное имя пути, ошибка парсинга TOML, неизвестный исполняемый модуль, общий conftest или грязный исходный test run требуют повтора. Если изменённая секция вообще не открывалась в реализации наблюдавшейся команды, сохранённое свидетельство допускается при сохранении других условий. Нативный код, проверка метаданных файла без его открытия и непротрассированные обращения ОС могут сделать это допущение неверным. Модель не гарантирует отсутствия пропущенных регрессий.

Замораживаем до оценивания условий последующих проверок (1) исходный граф R18 + прежние массовые сбросы, (2) только файлы, которые открывались (pyproject считается обычным файлом), (3) типизированный читатель конфигурации и наблюдаемые ресурсы — основной вариант, (4) отдельная абляция, где к варианту 3 добавляется пропуск правок Python при полном равенстве ast.dump(include_attributes=False), включая значения строк документации. Вариант 4 позволяет изучить независимый эффект форматирования, он не является основанием приписывать основной политике дополнительные выигрыши. Остальные причины перепроверки наследуются. Контроль сверху — все файлы. Опубликованные NameRTS, BabelRTS и EkstaP сравниваются по исходным файлам RQ1 на тех же авторских парах и пересечении тех же тестовых файлов. Предиктор не читает авторскую разметку. До ранжирования выдачи состав панели описан в SCREEN_RU.md.

Основное измерение — количество повторов и TP/FP/FN по авторским affected; дополнительные показатели — доля чистых базовых запусков и число обязательных повторов из-за неопределённости. Приводим также знак изменения числа проверок по ревизиям и пару рисков: риск пропустить affected и риск пропустить реальный исход pass→fail. Для последнего повторно выполняем на новом SHA все 14 выбранных файлов каждой новой пары, сопоставляем фактические результаты для строго одинаковых nodeid на обеих сторонах; коллекционные ошибки, пропуски, добавленные и исчезнувшие тесты считаем отдельно. Инструментирование применяется одинаково. Для известной калибровки 280e584e публикуются 14 независимых файлов, их показатели не объединяются с новой когортой. Дополнительно декомпозируем причины решений. Первая стоимость сбора и стадия тестирования новых версий учитываются раздельно. CPU, максимум 5 независимых процессов, 150 секунд на один test-файл. Выбор политик и данных подтверждается SHA-256. Один и тот же механизм также контролируется синтетическими изменениями в отдельном локальном диагностическом стенде при наличии времени.

# Исполнимые положительные и отрицательные контроли

После фиксации основной панели и её прогнозов создаём отдельный тестовый пакет на Python для фальсификации критерия. Пять отдельно применённых мутаций ресурсов: (i) изменён параметр Ruff, (ii) изменено имя проекта в TOML, (iii) фильтр предупреждений pytest переводится из default в error, (iv) в type stub изменено значение и длина файла, (v) в существующем тестовом Python-помощнике изменена возвращаемая строка. В каждой фиксированы семь тест-файлов: обычное вычисление, проверка имени из прямого чтения конфигурации, генерация предупреждения, прямое чтение type stub, проверка размера type stub через stat, запуск дочернего Python с чтением type stub и импорт тестового помощника. Каждая мутация проверяется на всех семи файлах. Сравниваем неизменённый предиктор основной серии с полным повтором, отдельно устанавливаем настоящие переходы pass→fail при одинаковом nodeid. Предсказание провала модели наблюдения — stat может вернуть изменённое значение без Python open и вызвать пропуск падения. Число специально сконструированных отказов не используется для оценки их частоты в репозиториях. Для каждого случая включена проверка реально изменившегося SHA данных, источники и все журналы сохраняются. Момент регистрации после формирования основной панели и до обращения этой программы к её данным явно отмечен.

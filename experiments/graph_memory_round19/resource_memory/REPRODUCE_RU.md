# Воспроизведение

Все данные эксперимента находятся в этой папке. Сохранены исходные пары SHA, протоколы, решения по каждому файлу до открытия меток, исходы pytest на каждой фазе, имена изменённых ресурсов, классификация их читателей, причины повторного запуска, полные текстовые журналы и отдельные результаты отбора Sphinx. Временные рабочие деревья извлекаются из git archive в этой же папке отдельно для каждого процесса и автоматически удаляются после завершения. Тексты программ Loguru не копируются в итоговый архив. [План и SHA](plan.json) · [Исходники Loguru](https://github.com/Delgan/loguru) · [Артефакт NameRTS](https://github.com/ZJU-CTAG/NameRTS/tree/f1acdae0f2b2d1ed6e3e2956d510db49bb7c276f)

Автономная проверка из каталога опыта: `python -B verify19.py`. Для повторных исполнений нужен Python 3.13.5 на Windows с версией pytest 8.3.5 и зависимостями в поле environment плана, локальный Git-клон Loguru, закреплённый пакет авторов NameRTS и каталог R18/namerts_transfer. В исходной раскладке интерпретатор и оба клона находятся под D:/CodexResearch/x20-r17-namerts. Программа plan19 использует ранее зафиксированный R18 plan.py и его Git-конфигурацию; experiment.py дополнительно использует отбор по прежнему владельцу AST из R18. На другой машине пути можно адаптировать в независимой рабочей копии. Для повторного эксперимента используйте чистую копию каталогов скриптов и Markdown без прежних результатов и манифестов. Наблюдаемое CPU/стенное время и пути временных файлов будут отличаться. [Предыдущая серия и прикреплённый интерпретатор](../../graph_memory_round18/namerts_transfer/REPRODUCE_RU.md)

Первичные источники авторского сравнения фиксируются по четырём Git blobs на одной ревизии. Аргументы ранжирования не включают gold. 70 базовых испытаний и 56 испытаний на текущем SHA сохраняются в двух отдельных архивах. При оценке эффективности единица наблюдения — файл тестов на определённой паре SHA. Одинаковые nodeid в разных ревизиях повторно учитываются; их число содержит информацию о размере исполнения, независимыми статистическими повторностями они не являются. В коде проверки результатов используется `runtime.pytest_rc` и фазовые данные; нулевой exit code оболочки сам по себе не означает успех pytest.

Нативное исполнение начинается вызовом отдельного дочернего интерпретатора с `-B`, отключённой автозагрузкой pytest-плагинов и фиксированным PYTHONHASHSEED. Внутри вызывается `pytest.main(["-q","-o","addopts=","-p","no:cacheprovider",file], plugins=[Capture()])`. Явно импортированные в conftest плагины работают штатно. Таймаут 150 с, синтетический стенд — 30 с. Ограничен запуск максимум пяти файлов одновременно. Локальная абляция AST игнорирует лишь координаты и сохраняет литералы и docstrings. Перечень сохранённых модулей зависит от фактического диффа в Git. Для проверки целостности и согласования таблиц в скачанном пакете достаточно стандартной библиотеки. ## Байтовая проверка переноса

Команда `python -B export_redaction.py` проверяет хеши пакета, число замен и согласованность с контрольной суммой распакованных нормализованных байтов. При наличии защищённых исследовательских оригиналов `python -B export_redaction.py --private-originals <каталог>` проверяет также исходный манифест, исходную фиксацию до оценки и восстанавливает оба переносимых журнала. В каждом из 70 базовых и 56 проверочных наблюдений сравниваются все поля. Изменились два пути в одном базовом и одном проверочном поле `log`.

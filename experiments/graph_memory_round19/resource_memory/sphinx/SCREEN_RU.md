# Внешняя переносимость на Sphinx

Отдельная проверка переноса до открытия любых меток Sphinx. Источник кандидатов — 50 официальных NameRTS target-пар из commit_pairs_sphinx.json. Просматриваем первые 12 в порядке SHA-256("r19-sphinx|"+current). В способах отбора нас интересует достаточно чистое испытание изолированного ресурса; допускаются модификации pyproject.toml, существующего .pyi под sphinx/, существующего тестового ресурса под tests/roots/ или tests/fixtures/. При скрининге допускаем документы и тесты одновременно, допускаем только пары без иных изменений производственного Python-кода sphinx/**/*.py, новых произвольных исполняемых файлов или общего conftest. Cохраняем причины пропусков всех 12 пар независимо от доступности подходящего примера. Запускать максимум одну первую подходящую пару, до 12 файлов на обоих SHA, одним отдельным новым окружением с исходной пакетной структурой. При отсутствии подходящих случаев публикуем нулевую доступность без подбора нового commit range по исходам. Ни метки, ни прогнозы авторов при скрининге не используются. Для публичного GitHub API используются только имена изменённых файлов, статусы, заголовки, признаки обрезанной выдачи; содержимое патчей не передаётся тестам или решателю. Проблемы безопасности исключаются по заголовку. Внешний скрининг даёт вторичную проверку применимости с заранее ограниченным вычислительным бюджетом.

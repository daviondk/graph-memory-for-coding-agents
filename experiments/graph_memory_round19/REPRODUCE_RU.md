# Проверка серии 19

Архив включает двенадцать разделов исследований и аудита. В каждом каталоге есть зафиксированный протокол, код и сводный отчёт. Входы фиксируются версиями и хешами. Крупные исходные корпусы, веса модели, полный текст терминальных сообщений и временные рабочие копии находятся отдельно. Воспроизводимость числового результата и совпадение байтов упаковки проверяются раздельно.

Для проверки ZIP выполните в его распакованном каталоге `python package_local.py путь_к_архиву.zip --verify`. Для части числовых проверок нужны соседние каталоги серий 17–18 с официальной разметкой и контрольными прогнозами. Так организовано и дерево репозитория. Стандартная библиотека достаточна для проверки целостности ZIP; зависимости полного обучения и воспроизведения перечислены в отдельных инструкциях. Для регенерации рисунка в рабочей копии нужен matplotlib 3.10.8 и команда `python figure.py`.

Один GPU использовался для обучения E5, получения эмбеддингов и отдельной проверки Qwen. Правила записи, BM25, логистические модели, LoCoMo и проверка координат выполнялись на CPU. У исполнимых тестов записаны версии библиотек, контрольные SHA версий кода и случаи прекращения до выбора теста. Корпус инструментальных траекторий в retrieval-экспериментах читается как данные.

Скрипт stage_effects.py с NumPy пересчитывает разложение парной разницы на случаи, где полный набор при записи удержали обе политики или только одна из них. Результаты находятся в stage-effects.json.

В двух диагностических сообщениях pytest из исследования Loguru локальные пути временных файлов заменены переносимой меткой. Исходные и экспортные хеши сопоставлены в [квитанции экспорта](resource_memory/export-receipt.json); наблюдения и числовые исходы повторно проверены.

# Даёт ли политика записи преимущество при выборе свидетельства моделью

До формирования новых входов и оценивания подписываем все 36 ранее назначенных разных траекторий и прямых вопросов R18/isetrace_reader (27 основной и 9 контрольной страты того другого эксперимента). Отбор R18 зависел от тематики и доступных при двух прежних способах упаковки фрагментов; вывод относится к этой условной панели. Подвыборок по текущим исходам не формируем. Веса обученного правила записи заморожены, методы сравнения — Full и output_head при 8 192 E5-токенах хранения и том же BM25 при 2 048 E5-токенах выдачи. Первичная гипотеза — рост Full Support после единственного реального действия open_evidence при Full относительно output_head. Качество обоих методов извлечения на полном test ранее изучено, ранее измерялись также иные действия на этой панели. Новые входы и новые решения фиксируются до разрешения текущих исходов.

В пределах каждого вопроса группируем только реально сохранённые и отобранные BM25 блоки по исходному событию. ID — хронологический индекс события внутри полной траектории, постоянный для обеих политик. Общие блоки отображаются в исходном порядке, непрочитанные промежутки маркируются константой. Никаких заголовков, сгенерированных с использованием скрытого текста, времени запуска, названия политики, ранга, эталона и ожидаемого действия. Ранее закреплённый фильтр чувствительных полей применяется по полному полю источника одинаково в обеих политиках, независимо от выбранных для чтения блоков. Такое событие не показывается и не засчитывается как доступное; выдачу сверх полученной от BM25 не пополняем, ни один вопрос не исключается. Приведём число затронутых блоков и доступность до/после фильтра. При пустом меню действие невозможно, исход равен нулю и модель не вызывается.

Нативная Qwen3.8-27B-UD-Q4_K_M, llama.cpp b12441, RTX 3090, temperature 0, top_k 1, seed 18431, thinking выключен, единственная доступная typed функция open_evidence принимает ровно один целочисленный ID. Вызов читает только показанные куски выбранного события, даже если другие куски того же события присутствовали в исходной траектории или были удалены из памяти. Одинаковые побайтно входы кэшируются; максимум 72 ответа. Невалидный выбор даёт ноль. Инфраструктурный сбой можно возобновлять по хешам уже записанных ответов. Сырые вопросы/тексты/ответы не попадают в публичные артефакты. Содержимое событий не исполняется.

Оцениваем нативные Full Support и Coverage открытых координат, число валидных действий, число вопросов, где любой один допустимый event способен полностью покрыть gold, и число при чтении всех показанных частей. Дополнительный детерминированный ориентир — открыть событие самого высокорангового показанного блока BM25. Для paired Full−output_head считаем выигрыши/потери и описательный 95% кластерный bootstrap по траекториям, 10 000 повторов, seed 13. Страты отличающихся и одинаковых новых входов — описательный анализ. Чтение источника не измеряет точность свободного ответа или успешность изменения кода.

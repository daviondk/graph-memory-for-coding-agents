# Исполняемое воспроизведение числовой границы по истории тестов

Исходный проект boltons. В старой версии 23.1.1 (9005642440e1479dd26c2c5d64c27f596445aaac) сохраняем для каждого реально выполненного upstream pytest node ID наблюдения о достигнутых строках, выполненных сравнениях и о том, сравнивались ли в них равные встроенные конечные числа int/float. Булевы и пользовательские типы не включаются в числовое свидетельство. При воспроизведении на следующем релизе 24.0.0 (992a58c1036fcf4d52cbf3313b6217b7c07b11d9) агенту даётся изменённый регион кода, он выбирает ровно один исторический тест. Задача — обнаружить внесённую граничную регрессию. Эти модификации синтетические. Реальны исходники, оба релиза и неизменные авторские тесты старого релиза.

Первичный исход — доля заранее назначенных изменений, где выбранный реально исполненный тест проходит на чистом новом релизе и завершается ошибкой проверки/исключением на мутанте. Отдельно выделяем timeout и ошибки инфраструктуры. Выбор детерминирован, без LLM. Исходы на мутанте и новом релизе открываются после регистрации прогнозов. Библиотеки — dictutils, formatutils, iterutils, listutils, mathutils, namedutils, queueutils, setutils, statsutils, strutils, tableutils, timeutils, typeutils. Никаких сетевых и привилегированных действий в тестах задачи.

Все однооператорные <, <=, >, >= в функциях/методах, с точным соответствием выражения AST, квалифицированного имени и номера вхождения между релизами; поддеревья while пропускаются. Перестановка границы: <↔<= или >↔>=. При нескольких выражениях в одной функции выбираем не более двух по SHA256("r19-boundary|"+идентификатор). Полная панель — максимум 48 равновероятных по тому же хешу мест, без учёта трасс и реакции тестов. Включаем места даже без предыдущего наблюдения. Неизвестная граница до изменения не требуется — политика получает показанный diff, но не выбирает изменение и не видит текущие исполнения. Тесты-кандидаты из авторского одноимённого тестового модуля, для statsutils также histogram. Кандидат должен пройти на старом релизе в чистом и инструментированном режиме. Ключ результата — точная команда pytest nodeid.

Политика pairs отдаёт приоритет связанному с командой свидетельству равенства, затем достижению предиката, затем ранжированию по лексическому пересечению и давности. Роли и наблюдения сохраняются в placebo: флаги равенства переставляются циклически по отсортированному SHA256(site, seed, nodeid) среди тестов, которые действительно дошли до сравнения. Неизменяемые по этому правилу случаи остаются в знаменателе. Seed 0–15 без отбора. Сильные контроли: известное выполнение предиката/строки без равенства, известное достижение строки, лексический Jaccard названия теста и места изменения, последний прошедший тест. Внутри равного приоритета используется один и тот же порядок. Суммарная первичная разность pairs против средней placebo. Отдельно сравнения pairs против predicate reach, line, lexical, last; выигрыш/проигрыш, точность и интервал bootstrap 10000 по функциям (seed 19). Исходы прогнозов оцениваются после фиксации SHA. Ошибка/таймаут не приравнивается к обнаружению. Если тест не проходит на чистой новой версии, выбор промах для первичного показателя, число таких случаев отдельно. Тесты, дата и метод внедрения мутации — условие обобщения. [Boltons](https://github.com/mahmoud/boltons) · [Mutation testing](https://cosmic-ray.readthedocs.io/en/latest/index.html).

# Проверка и повторение

Для офлайн-аудита достаточно Python 3.11+ и `python -B verify.py`. Скрипт контролирует SHA-256 архива, заново вычисляет привязку каждого исторического признака, восстанавливает все 16 перестановок и выбранные тесты, затем сверяет предъявленные количества с фактически записанными исходами pytest.

Полный повтор на чистой копии запускается командой `python -u -B run.py all`. Аналитический Python требует NumPy и pytest. Для исполнения авторских тестов в отдельном окружении используйте Python 3.11.15 и pytest 7.4.4; укажите путь к этому интерпретатору в переменной `R19_TEST_PYTHON`. Версии приведены в environment.json. Внешние плагины pytest при испытаниях отключены. При первом прогоне загружаются два зафиксированных публичных архива, проверяются полные SHA-256 исходников и составляется список неизменных по выражению участков. Исходные программы и тесты разворачиваются во временном каталоге текущего опыта, который удаляется после завершения. Дальнейшие сравнительные запуски работают локально. Чтобы повторить только исполнения по уже сохранённым прогнозам и истории, используйте `python -u -B run.py resume`.

Лимит времени — 12 секунд на один изолированный тест, 24 секунды на все доступные тесты изменения, 100 секунд на обработку модуля авторских тестов в чистой/исторической версии. Начальные остановки при проверке пути и несовместимой версии pytest, а также обработка импорта тестового файла описаны отдельно. Числовое поле full_suite_timeout в summary.json является числом изменений с недоступной оценкой потолка по любой причине; две ошибки текущего опыта относятся к collection_error. Типы причин есть в exhaustive-matrix.json.gz. Нативные файлы предыдущих исследований не изменяются. [Протокол](PROTOCOL_RU.md) · [Обработка неполной матрицы](EXECUTION_NOTE_RU.md)

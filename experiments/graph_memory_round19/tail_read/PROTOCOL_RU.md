# Чтение остатка бюджета мелкими блоками

Проверяем полный официальный test ISETrace (2 000 вопросов) на рангах двух заранее названных моделей. Замороженная E5-base-v2 FP32 из R18 доступна сразу; вторым идёт Dense-FT, один заранее обучаемый seed из R19, строго после его forecast-seal. Ранги моделей и исходные PU остаются неизменными. Результаты исходных контролей ранее анализировались; эта проверка на том же test исследовательская. План фиксируется до нового выбора узлов и подсчёта.

При бюджете 2 048 E5-токенов сперва берём штатный префикс целых узлов до первого переполнения. Потом в исходном порядке ранга добавляем целые узлы противоположной роли, относящиеся к вызовам из исходного префикса, если узел помещается в оставшийся бюджет. Это первая приоритетная группа related, вычисленная ровно по логике R17/pilot.py. Все узлы префикса и этой группы тарифицируются целиком, включая возможное повторное чтение символов в соседних PU.

В основном контроле related оставшийся бюджет заполняется остальными целыми PU в исходном порядке, с пропуском не помещающихся. Переиспользуем подпись этого контроля. В эксперименте после того же префикса и тех же целых противоположных узлов разрешены только неперекрывающиеся исходные блоки ~64 WordPiece-токена по разбиению уже подписанного online_write. Блок должен быть полностью внутри хотя бы одного PU и иметь пустое пересечение (в полуоткрытых координатах одного event_id и json_pointer) со всеми уже прочитанными целыми узлами. При перекрытии между PU родитель — лучший ранг среди всех содержащих узлов. Мелкие блоки официальной разбивки попарно непересекаются, оплачивается их точная ранее рассчитанная WordPiece-стоимость. Алгоритм проходит сортировку один раз и пропускает неподходящие по стоимости блоки.

Три заранее заданные сортировки. A — по рангу родителя, затем по хронологии события и символьному началу блока. B (основной) — по рангу родителя, затем по убыванию глобального BM25 fine-score внутри родителя; остаточные равенства по хронологии. C — по убыванию 1/(60 + ранг родителя) + 1/(60 + глобальный лексический ранг мелкого блока), ранги с единицы, равенства по хронологии. BM25Okapi и content_tokens взяты из подписанного online_write, глобальная статистика считается на всех непустых мелких блоках траектории, равные BM25 scores разбиваются хронологическим индексом блока, независимо от доступа к эталону. Физический лимит одной политики и одного вопроса стабилен. Фоновое сканирование/лексический индекс мелких частей не входит в стоимость выдачи; укажем объём корпуса и ограничения.

Первичный контраст B−related по Full Support@2048. Дополнительно — Coverage, Density, расход, парные выигрыши/потери, B−A, C−B и B−штатный префикс. Проверяем обе модели отдельно. Считаем описательные кластерные интервалы по траекториям (10 000, seed 13), без подбора политик по результату; вероятность потери из-за отказа от крупных остаточных блоков остаётся. Метрика относится к исходным интервалам опоры, а не к свободному ответу. Хешируем выбор каждого метода до подсчёта метрик. Все чтения статические.

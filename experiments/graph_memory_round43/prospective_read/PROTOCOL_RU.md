# Прогноз нужных чтений на другом репозитории

После результатов R42/future_reads фиксируем новый исход исследования. Удостоверенная сохранность старых блоков повышалась, но зарегистрированный будущий спрос был редким. Проверяем, повышает ли изменение **выбора** удостоверенных блоков пользу в следующих наблюдаемых запросах. В локальной памяти доступны адреса и байты, которые разрешил R42/context_edits, с теми же граничными метками. Метрика касается информативных строк именно отредактированного файла. Такой спрос не оценивает потребность в сведениях о других файлах; для каждого метода будем показывать, сколько байтов других путей он вытесняет.

Основная панель — все 2 696 подтверждённых действий в пяти исходных репозиториях. Каждому из пяти репозиториев назначаем отдельный внешний fold. Для его прогноза все обучаемые способы видят только обращения четырёх остальных репозиториев. Сохраняем обучающие и проверочные ID, конфигурации и прогнозы каждой модели. Алгоритмы и параметры фиксируем сейчас, без подбора по будущей метрике. Ранее известны результаты старых политик и расписания из R42, поэтому это перекрёстная проверка на публичных повторно исследуемых историях, а не новая независимая коллекция. Дополнительно покажем прежний срез 1 071. Никакие значения будущего события, завершения, цензуры, эталонной правки, имена репозитория или задачи не входят в признаки решателя.

Во всех сравниваемых режимах один и тот же допустимый пул после R42/context_edits. Общий префикс до 1 024 байт исходного поштучного порядка фиксируется заранее, оставшийся лимит до суммарных 2 048 байт перераспределяется. Адрес и содержимое берём из прежнего видимого чтения с сертификатом и из уже показанной квитанции. Для каждого кандидата известны исходный порядок, стоимость, старая полезность, число информативных строк в новом адресе, число строк, отсутствовавших в квитанции, расстояние в строках до новой области замены, направление от области правки. Для остальных путей вклад в метрику этого файла равен нулю; при равных целевых значениях используем прежнюю полезность. Контролируем вместимость, неизменность общего префикса и воспроизведение точного базового пакета.

Способы выбора суффикса, в порядке регистрации. Старые полезности из R42. Контроль приоритета редактируемого файла вместо других путей по числу доступных его информативных строк без вычитания квитанции. Удаление повторов квитанции — максимизируем число его различных новых для агента информативных строк. Геометрический контроль — для каждой такой строки полезность убывает с расстоянием d до ближайшей границы нового изменённого диапазона как 1/(1+d/32), ценность блока есть сумма ценностей строк. Последний объявлен сильным простым контролем для оценки обученного ранжирования. Для всех контролей остаточные равенства разрешаются прежней полезностью и исходным детерминированным порядком.

Предлагаемый фиксированный обучаемый способ — небольшая регуляризованная L2 логистическая регрессия о вероятности, что **блок** даст хотя бы одну действительно запрошенную информативную строку сверх квитанции. Стандартизация только по внешней обучающей части, 1/C с C=0,5, баланс классов, нормирование веса строки по числу допустимых блоков в её эпизоде, один заранее установленный набор признаков. Признаки без дат/ID включают логарифмы размеров, стоимости, расстояния, позиции и прежней полезности, количества доступных и новых строк, долю повтора квитанции и знак расположения. Ценность блока для суффикса равна предсказанной вероятности, среди точных равенств исходная полезность. Оценивается потребность в реально наблюдаемом префиксе окна, включая цензурированные окна; нули означают отсутствие зарегистрированного совпадения до границы. Требуем не меньше двадцати положительно размеченных блоков и пяти задач с положительным блоком в четырёх обучающих репозиториях. Иначе именно для этого внешнего fold используем геометрический контроль.

До оценивания формируем и запечатываем отдельные метки обучения и прогнозы для каждого внешнего репозитория. Модуль выдачи данного fold не загружает его метки. Диагностический верхний предел отдельно получает **будущие** запросы всех эпизодов и оптимизирует точное число покрытых строк-событий под тем же префиксом и бюджетом. Удостоверенные локальные координаты монотонны; проверяем отсутствие двойного кредита между кандидатами. Верхний предел проверяем также по двоичному вопросу «существует ли хотя бы один подходящий блок, который может поместиться вместе с префиксом». Дополнительно измеряем ограничения самого пула вне обязательного префикса. Верхний предел не является применимой политикой.

Первичный контраст — обученное ранжирование минус геометрическое контрольное правило по индикатору наблюдаемой пользы сверх квитанции, равный вес каждого из пяти удержанных репозиториев. Также сравниваем заранее заданное геометрическое правило со старым выбором. При общей будущей разметке считаем парные выигрыши/проигрыши и интервалы по пяти целым репозиториям (все 5⁵ упорядоченных перевыборок), дополнительно усреднение по задачам и событиям, число байтов, строк и запросов с полным покрытием информативной части, реально востребованную долю верхнего предела и объём нецелевых данных. Пять кластеров и редкие наблюдаемые обращения ограничивают оценку неопределённости. Публикуем полные и цензурированные окна и логически возможные границы конечного двоичного эффекта, без допущения о случайной цензуре.

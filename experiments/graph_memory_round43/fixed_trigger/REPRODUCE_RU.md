# Исполнение и независимая проверка

Рабочий каталог — `D:/CodexResearch/x20-bench-workspace/work/graph_memory_round43/fixed_trigger`. Короткая реплика готового результата работает на стандартном Python. Для каждого предложенного пакета она независимо пересчитывает покрытые интервалы и число токенов, а также сверяет все шесть знаменателей.

```powershell
python -B verify43.py
Get-FileHash -Algorithm SHA256 -LiteralPath manifest.json
```

Для исполнения всех этапов необходимы исходные траектории ISETrace, SDK и локальные CPU-доступные FP32-кеши, использованные в R41 и R42. Точечные источники SDK, их хеши и версии перечислены в `graph_memory_round41/prefix_native/runtime.json`. Имена модулей, объявляющих модели и структуру признаков, закреплены подписанными каталогами R41 и R42.

```powershell
$runner='D:/CodexResearch/x20-isetrace-e5-gpu/venv/Scripts/python.exe'
python -B register43.py
python -B schedule43.py
& $runner -B forecast43.py
python -B seal43.py
python -B timing43.py
& $runner -B same_time43.py
& $runner -B grade43.py
& $runner -B analyze43.py
```

* `trigger43.py` содержит чистую функцию над итератором сырых сообщений. Ей неизвестны длина, конечный ответ и итоговое число вызовов.
* `schedule43.py` независимо выводит положение срабатывания по балансу начатых вызовов и пришедших ответов. Для каждой траектории, достигшей триггера, тот же реальный префикс выдаётся итератором, вызывающим исключение при попытке прочитать ещё одно сообщение. Контрольные записи содержат только позицию, число закрытий и число фактических вызовов.
* `forecast43.py` создаёт новый объект записи с фактически наблюдавшимися сообщениями, очищенной служебной оболочкой и локальным счётчиком вызовов. Лишь после этого вызываются авторские адаптер и построитель графа. Оцениваются все текущие строки семантического кодировщика, строятся признаки R42 и тензоры нативной модели, затем выполняется настоящий CPU-forward. Из конечной таблицы для оценщика используются лишь внешние индексы уже выбранных ID. Каждое срабатывание сопровождает хеш графа в `traces-i.json.gz`. Пакеты и видимый пул хранятся в `packets-i.json.gz`. Несработавшие вопросы имеют отдельную запись с пустым словарём выданных результатов.
* `seal43.py` требует наличия всех восьми фрагментов, подтверждает границы по независимой реплике и проверяет совпадения с другим расписанием при фактическом совпадении времени. Только после фиксации `forecast-seal.json` открывается независимый оценщик.
* `grade43.py` проверяет полноту всех возможных видимых источников и каждого реального пакета по авторской метрике и по независимым атомарным интервалам. `outcomes.json.gz` содержит результаты для каждого вопроса. На знаменателе назначений несработавшие запросы учитывает `analyze43.py` с нулевой доставкой. Условные таблицы включают только соответствующие срабатывания.
* Для полного повторного нативного прохода используйте чистую копию каталога с исходными `.py`, протоколом и регистрацией в аналогичном дереве `work`. `forecast43.py` проверяет уже зафиксированные фрагменты и умеет продолжать после остановки. Пересчитать перечисленные фрагменты можно командой `forecast43.py 0 1`. Временные поля фиксаций зависят от машины. Упорядоченные пакеты, хеши графов и индивидуальные исходы можно проверять отдельно от этого времени.

Исходное разбиение хранится в `graph_memory_round22/native_multiseed/official580/split.json.gz`, исходные фрагменты — в `D:/CodexResearch/x20-isetrace-runtime/inputs/trajectories`. Фиксация `registration.json` включает хеши неизменённых весов R42, манифестов R41 и R42, протокола и исполняемого триггера. Входы и артефакты соседних исследований открываются только для чтения.

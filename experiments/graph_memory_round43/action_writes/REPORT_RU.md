# Что добавляет запись содержимого действия str_replace

Подтверждённые аргументы замены позволили восстановить **33 816** полных строк новой версии без ошибок при независимой сверке источника. Исходная функция update_literal, которой нужен целиком видимый старый шаблон, вернула **13 826** новых строк, также без ошибок. Однако **все 19 028 информативных строк**, восстановленных предлагаемым способом, агент уже получил в квитанции редактора. На 2 696 правках дополнительный пакет после вычитания квитанции **побайтно совпал у всех пяти политик для каждого события и каждого из трёх бюджетов**. В этой среде расширение механизма записи улучшило реконструкцию содержимого без выигрыша для последующего чтения. [Протокол](PROTOCOL_RU.md) · [Численные результаты](results.json)

**Сильный исходный контроль.** Запущена прежняя функция update_literal без модификации. Все способы получили одно и то же недавнее чтение, те же аргументы действия, путь, положение и ответ редактора. Полный literal rebase нашёл старый шаблон и принял результат в 1 013 из 2 696 случаев, в том числе 438 из 1 071 случаев основной панели. Локальная реконструкция новых границ требует только видимого префикса или суффикса соседней прежней строки. Для однострочной замены старая подстрока должна находиться в первой строке ровно один раз. Для внутренних строк достаточно расположения подтверждённого действия. Дословное использование всех элементов new_str допустило 1 598 неверных информативных строк; они все расходились с уже показанным текстом квитанции и были исключены до формирования пакета. **Польза в наблюдаемых последующих чтениях.** На панели 1 071 события при бюджете 2 048 байт каждый способ дал дополнительное покрытие в одних и тех же 11 эпизодах и для 77 строк. Это означает 0 парных побед и 0 поражений между новой и исходной реализациями. При бюджетах 512 и 8 192 байта получено соответственно 10 эпизодов / 62 строки и 11 / 91. На всех 2 696 событиях значения составили 34 / 180, 36 / 234 и 38 / 285. Все методы выделяли одинаковое место информативным строкам изменённого пути. Каждый переданный байт проверили по полной служебной версии после запечатывания прогнозов. Данные из этих версий не передавались производителю записей. Полученная доля корректной реконструкции относится к подтверждённым однократным заменам при известном пути и положении; распространение на другие инструменты и неполные квитанции требует отдельной проверки.

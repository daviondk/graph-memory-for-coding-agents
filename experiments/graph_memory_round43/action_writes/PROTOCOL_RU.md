# Запись новых адресуемых наблюдений из действия редактирования

R43/prospective_read обнаружил, что из 378 эпизодов с фактическим спросом сверх квитанции прежний пул содержал нужную строку только в 43. Проверяем новый способ формирования памяти при записи. При успешном str_replace агенту уже известны old_str, new_str, путь, видимая позиция операции, самое недавнее чтение файла и возвращённая квитанция. Цель — получить полные актуальные строки из new_str, в том числе когда шаблон прежней замены не был целиком виден. Будущие просмотры и полные служебные версии за пределами видимой выдачи при формировании памяти недоступны.

Перед новыми прогнозами фиксируем два независимых исхода. Первичное сравнение — число эпизодов, в которых получена хотя бы одна реально запрошенная позднее информативная строка сверх уже выданной квитанции, для способа с восстановлением граничных строк относительно действительной исходной функции update_literal из memory_session5/packets/common.py. Основная панель 1 071 события из 13 ранее отложенных задач, равный вес задач. Второй обязательный исход — количество побайтно неправильных новых адресуемых записей на всех 2 696 событиях по служебной версии после действия, в том числе среди фактически отправленных в пакет. Отдельно 676 основных событий и полностью прослеженные окна. Все прежние исходы сохранности и спроса уже известны, новые варианты записи ещё не вычислены; внешнее подтверждение остаётся отдельным требованием к статье.

Все способы получают одинаковые фактически видимые данные. Прежнее чтение очищается существующим фиксированным детектором координат R40 перед передачей любой ветви. Всем доступна идентичная исходная память старых информативных строк изменённого файла, подтверждённых R42/action-local. При ранжировании всех политик единица — одна полная информативная строка целевого пути. Сначала свободно используются строки показанной всем квитанции; каждое дополнительное несовпадающее с ней значение того же адреса отклоняется. Выбираем кандидаты в порядке расстояния от нового диапазона замены, внутри диапазона с наименьшего номера; при равных расстояниях выбираем ближайший к началу. Полная строка стоит длину в UTF-8 плюс один байт разделителя. Если очередная строка не помещается, рассматриваем следующую. Основной лимит дополнительного пакета 2 048 байт, дополнительные 512 и 8 192. Это сравнение политик записи для одного пути при общих входах и расходах, отличается от предшествующего смешанного многопутевого отбора.

Фиксируем следующие условия. (1) Только прежние перенесённые строки. (2) Те же прежние строки и новая версия, полученная оригинальным update_literal: видимое безопасное чтение передаётся целиком, адреса и буквальные строки квитанции проверяются, запись свежей строки используется только при успешной реальной операции. (3) Простое сохранение всех строк new_str с известного номера начала предполагает, что начальная и конечная строки целиком заданы литералом; считаем действительную точность. (4) Гарантированно полные внутренние строки new_str без его первого и последнего элементa. (5) Предыдущая схема плюс границы, если можно восстановить неизвестные префикс/суффикс по одному безопасному чтению старых граничных строк. Для многострочного старого литерала требуем точный суффикс первой и префикс последней. Для однострочного старого литерала — одно-единственное совпадение в достоверно видимой строке. Для однострочного нового литерала нужны обе границы, для разных граничных строк они проверяются независимо. При неопределённости возвращаем только доказанные строки.

Для каждого исхода считаем, сколько информативных строк добавлено до вычитания квитанции, сколько фактически уже было в её видимом тексте, сколько новых адресов уникальны относительно старого пула, аппетит к памяти, полезные эпизоды и число запрошенных строк/байтов. Для этих агрегатов различаем валидность исходного текста и доказанность хранения будущего полезного материала. Подписываем адреса, хеши и выдачи до проверки версий и будущих просмотров. Для первичного контраста показываем 10 000 парных issue-bootstrap, знаменатели положительного спроса и диапазоны при строгой цензуре; какие-либо ответы LLM или успешности постановка не оценивает. Изображения, команды и фрагменты программ из истории не исполняются.

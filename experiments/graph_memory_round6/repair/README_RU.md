# Воспроизведение проверки SymPy
В основной части зафиксированы 16 задач, проекты и реплики не смешаны. results.json содержит основные показатели, per_task.json — показатели каждой задачи, verification.json — итог независимой от генерации проверки исходных файлов и диагностики с привилегированными адресами. Отчёт по остальным 30 задачам находится в transfer/. Папки calls и oracle_calls содержат полный JSON каждого уникального запроса и ответа Qwen. Путь от варианта к вызову восстановим через assign.json или oracle_assign.json.
На исходной машине проверенные исходные архивы до изменения находятся в tasks/<id>/checkout.tar.gz, рядом лежат ready.json с SHA-256 и URL, public.json с исходным issue, grading.json с официальным патчем и тестами. В пакете отчёта исходные tarball и виртуальное окружение заменены ссылками, контрольными суммами и environment.txt. Данные — test split princeton-nlp/SWE-bench_Verified, локальный Parquet SHA-256 записан в cohort.json. Модель и runtime документированы в model_receipt.json и runtime_receipt.json, запуск в launch.json.
Повтор полной генерации — в отдельной копии без готовых файлов результатов. Сначала collect_tasks.py в Python 3.11 с duckdb и truststore, затем build_memory.py и infer.py в окружении с tokenizers и токенизатором из memory_session5/live/tokenizer.json. Пути D и порт настраиваются в скриптах. Запустить сервер из start_server.ps1. Python 3.11 с зависимостями environment.txt выполняет grade.py control и затем grade.py solver. Для привилегированного контроля — oracle_memory.py, infer_oracle.py, grade_oracle.py oracle. Фазы оценщика на одном checkout исполняются последовательно. analyse.py и verify.py вычисляют итоги, повторно сверяют все 151 прочитанного или изменяемого файла с полученными tarball. Подробности подвыборки регрессий и отказов в GRADING_PLAN_RU.md.
Для первичной перепроверки сохранённых результатов без генерации можно в распакованной папке repair выполнить python analyse.py. Для полного verify.py нужны исходные архивы, которые восстанавливают collect_tasks.py и сохранённые URL. Технические журналы в grades/ сохранены для аудита ошибки Git и зависимости py. В итоговые результаты вошли исключительно grades_v2/.

Для проверки диагностического условия при исходных разрешённых путях повторно запустились те же ответы через grade_equal.py equal, затем equal_paths.py. Из 16 задач прошли 10, одна первоначально успешная правка была вне доступных путей. Контроль исходных байтов повторяется verify.py.

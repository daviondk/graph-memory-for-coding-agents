# Независимая проверка поиска места исправления на 30 задачах SymPy

На оставшихся 30 задачах исходного списка SWE-bench Verified все четыре правила показали хотя бы одну строку авторского исправления в **12/30 задачах**. Исходное текстовое правило и новый вариант с адресами трассировок и связями класса с методом показали ровно те же **61 из 179 эталонных координат**. Результат каждого отдельного задания совпал. Парный бутстреп по 30 задачам даёт эмпирический интервал [0, 0] для разности, точный тест знаков даёт p = 1. Выборка не содержит расхождений для оценки их частоты на других проектах.

|---|---:|---:|---:|---:|

Прежнее правило подбирает восемь модулей по словам и именам определений из первых 850 токенов issue. Оно ранжирует отрывки функций и методов по 14 строк. Новый вариант получает точно те же кандидаты и максимум 1800 токенов. К исходной оценке добавляется до 32 баллов за близость к строке явно указанного файла, 22 за связанную пару класс–метод и 7 за одновременное упоминание обоих имён. Для пар учитываются вызовы конструктора, обращение к методу через класс и простое предварительное присваивание переменной. Патчи и тесты недоступны ранжировщику. В исходном коде нет исполнения текста из issue. На трёх заранее выбранных позициях списка отдельный вызов неизменённого родительского ранжировщика воспроизвёл тот же список файлов и пакет flat побайтово.

В шести задачах с распознанным путём и номером строки текстовое правило уже показывало хотя бы одну нужную строку во всех шести. Пары класс–метод найдены в 12 задачах с пятью попаданиями в обеих ветвях. В остальных случаях видимость часто терялась раньше ранжирования. Для 13 задач среди восьми выбранных файлов не было ни одной нужной координаты. В двух нужный файл был прочитан, но все нужные строки находились вне возвращаемых блоков функций. В трёх хотя бы одна подходящая строка присутствовала среди кандидатов, но не поместилась в отобранный пакет. В восьми файлах были 88/179 эталонных строк, в допустимых фрагментах — 76/179, в предъявленных пакетах — 61/179. Все значения рассчитаны по исходным коммитам с исходным определением координаты чистой вставки.

Новый список получен тем же хеш-порядком из 46 подходящих задач, из него исключены первые 16. Все 30 архивов скачаны по точным коммитам, суммарно 213 547 077 байт. SHA-256 фиксации протокола с методом — 7f1f12eb74df26d70dca9ee0aebbcc4063bd325129c9435c680caea793b27401. Каждому архиву соответствует tasks/<ID>/ready.json с URL и SHA-256. В policy_lock.json зафиксированы метод, оценки, исходные сведения и порядок задач. packet_lock.json закрывает все 30 пакетов до оценки, cpu_rows.json содержит целевые координаты и исходы, diagnosis.json отслеживает потерю видимости на каждом этапе.

## Фактические исправления Qwen на первых 12 задачах

Обе политики дали **0 из 12 исправлений**, прошедших все FAIL_TO_PASS, при 11 применимых предложениях у каждой. В исходном состоянии во всех 12 задачах возникли реальные отказы, после авторских исправлений прошли все 22 целевые проверки. Ни одно предложение модели не провело ни одного из этих 22 тестов. Для обеих политик один ранее проходивший тест из 126 проверенных PASS_TO_PASS стал падать на задаче sympy-24562. В задаче sympy-19495 модель предъявила неподходящую для однозначной замены старую строку в обеих ветвях. По всем задачам этого поднабора исходные пакеты каждой политики покрывали в сумме 16 из 85 эталонных координат, хотя бы одну координату в 5 из 12 задач. Пять пар различались по предъявленному контексту. Нулевая разность числа прошедших исправлений не устанавливает равенство методов в более широкой популяции.

Выполнено 17 реальных вызовов локального Qwen3.8-27B UD-Q4_K_M, остальные семь пар имели побайтово одинаковые полные запросы. Израсходовано 37 591 входных и 2834 выходных токена, сумма длительностей вызовов 105,61 с. Назначения записаны до запросов, все ответы запечатаны до тестов предложений. В gpu_answer_lock.json SHA-256 9224b3be89e35ba1016393272753420da19fa89c42b5ba4cad6eea7d87a84403 указаны отдельные файлы ответов. Локальные проверки использовали исходную среду Python 3.11.15 с pytest 7.4.4 и mpmath 1.2.1. Среда Windows отличается от официального контейнера, регрессионную панель ограничивали двенадцатью адресами на задачу, итог относится к этой адаптации.

Для проверки сохранённых результатов запустите из этой папки `python -B score_cpu.py`, `python -B score_gpu.py` и `python -B verify_transfer.py`. Для воспроизведения вызовов нужны исходные веса и llama.cpp из родительских model_receipt.json и runtime_receipt.json. Последовательность в чистой отдельной копии — collect_tasks.py, driver.py freeze, driver.py build, driver.py verify-flat, start_server.ps1, infer.py, seal_answers.py, контрольные и модельные прогоны grade.py control и grade.py solver с интерпретатором родительской env. Затем пересчитываются score_cpu.py, diagnose.py и score_gpu.py. Для оценки CPU во время повторных тестов исходные файлы должны быть уже восстановлены. В сохранённом запуске проверены все 30 контрольных сумм архивов, а после тестов — оригинальное состояние 122 затронутых путей. Независимый расчёт по 85 эталонным координатам всех 12 задач дал те же адреса, что и исходный контрольный оценщик. В evaluation_lock.json перечислены сырые результаты, журналы тестов и JUnit XML, SHA-256 055f63d1e2a752f4e9a6a5f0bde546b19752698293daadfb4b70e81f886ea5cd.

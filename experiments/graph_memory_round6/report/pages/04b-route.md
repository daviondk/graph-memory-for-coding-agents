# Когда следующий адрес неизвестен
Предыдущему опыту оценщик сообщал координаты. Здесь политика получает только описание issue и состояние памяти на момент выбора. Она может передать одно или три непересекающихся окна до десяти строк каждое. Оценивается попадание начала реальной будущей правки в окно. На тех же контрольных точках проверяется и более строгий исход — сохранился ли весь правильный текст.
@ 5.1 3.3 3.7 4.2
| Следующее окно | Свежесть | Последний правленый путь | Текст issue + история |
| Старт в 1 окне, все 645 | 89 | 81 | 101 |
| Старт в 3 окнах, все 645 | 195 | 192 | 197 |
| Полный текст в 3 окнах, все 645 | 150 | 147 | 126 |
На переносе между двумя группами Kimi правило, использующее более одного сигнала, достигло 70/206 по старту в трёх окнах против 57/206 у свежести. На внешних историях Claude оно уступило 43/186 против 47/186. В первоначальной панели Kimi результат тоже снизился: 84/253 против 91/253. Улучшение выбора файла может ухудшить выбор конкретного места внутри него. По сумме панелей правильный файл попал в три окна в 450 случаях против 404, а полный текст в тех же окнах — в 126 против 150.
Дополнительно сопоставили одинаковые 96 задач с сохранёнными прогнозами локального Qwen из прошлой серии. С допуском ±5 строк Qwen с адресным контекстом попал 31 раз, Qwen с сырым терминальным наблюдением — 28, новое CPU-правило — 19, свежесть — 15. Модель этого сравнения не переобучалась и повторно здесь не запускалась. Это проверка выбора места действия. Качество исправлений с новой генерацией проверено отдельно на SymPy.
Эти результаты задают два независимых вопроса к будущей системе. Как часто память выбирает правильный адрес без помощи эталона? Если адрес найден, достаточно ли хранится достоверного текста для следующей операции? Условный результат 129/186 отвечает только на второй.

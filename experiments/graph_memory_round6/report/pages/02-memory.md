# Что именно улучшило чтение памяти
На вход операции подаётся запрос «путь, первая строка, число строк». Правильные символы до ответа знает только оценщик. Успех засчитывается, если возвращён весь текст диапазона на нужных координатах. Оценщик брал координаты из будущей успешной замены, однозначно обратимой по подтверждению редактора, максимум через четыре шага. В основной панели 206 таких запросов из историй Kimi, во внешней — 186 по 48 задачам Claude Sonnet 4 из 12 репозиториев. Число запросов отличается от числа независимых задач.

На внешней панели первоначальный гибрид выигрывал у первого архивного адаптера в восьми запросах и не проигрывал ни в одном. Разность +4,30 п.п., интервал по задачам [+1,60; +7,53]. В строгой проверке архив получил тот же код до и после подтверждённых изменений. Общая промежуточная карта без лимита пересчитала актуальные координаты и повторно опубликовала их как страницы. Устаревшие адреса убирались из текущего каталога. Весь прежний прирост воспроизвёл обновлённый архив сам. Формирование более полной записи выбрано после просмотра первых результатов.
Усиление архива повысило стоимость записи. Число сохранённых страниц выросло с 690 до 884, объём хранилища — с 65,85 до 76,41 МБ по сумме 48 баз. Зато для уже согласованного архива кеш снизил число запросов к архивным страницам на 92,2%, объём промежуточной выдачи — с 2 315 441 до 403 150 байт. В итоговом JSON ответы совпали полностью во всех 186 случаях и во всех 46 контрольных чтениях. Подсчёт страниц отражает работу приложения. ОС может обслуживать эти обращения из собственного кеша.
Применялись авторские SQLite, PageStore, SemanticStore и RecallService. Под адаптацию попали запись наблюдений и выбор архивных страниц. 33 авторских теста Recall прошли в Linux. Показатели полного агента из статьи получены в другой постановке. [Код авторов](https://github.com/Homy-Xu/MemTrace/tree/5508f8be81025d8aa90726b1e06aef4ea484e577).

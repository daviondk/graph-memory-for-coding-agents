# Сколько времени занимает одно чтение
На 186 внешних запросах измерили получение конечного JSON. Оба маршрута используют один архив с одинаковой записью изменений. Горячая ветвь распаковывает реальные 4096 байт или меньше, ищет строки и при неполном диапазоне обращается в тот же архив. На каждом запросе — прогрев и три парных повтора. В таблице приведено среднее по запросам после взятия медианы трёх повторов каждого запроса.

Для Linux интервал снижения по 48 задачам составил [81,3%; 93,7%], по 12 репозиториям [80,2%; 94,0%]. На той же Linux-системе вариант с обычным LRU занял 0,469 мс. 95-й процентиль у архива — 7,57 мс, у гибрида — 4,69 мс. Суммарная задержка на 63 промахах кеша выросла на 7,8%. Из них лишь 11 потребовали открыть страницу, при остальных архивный каталог сам обнаружил отсутствие данных.

~ Каждая точка — один запрос на Linux. Ниже диагонали гибрид отдал тот же JSON быстрее. Для длинной группы попаданий в кеш основная стоимость — распаковка фрагмента в памяти.
Это задержка готового оператора чтения на одной машине. Кеш ОС прогрет, снимок уже доступен в RAM. Построение и обновление графа, запись страниц, холодный старт, генерация модели и запуск тестов в эти времена не входят. Эти расходы нужно измерять отдельно при сравнении полных агентов.

# Когда память устаревает после правки
Обычная запись «файл, номер строки, текст» может стать ложной сразу после команды, переписавшей файл. Мы сравнили прежний граф, LRU с теми же наблюдениями, отключение подозрительных адресов и перенос тех адресов, чьё изменение выводится из наблюдаемой команды. Исторические команды обрабатывались как данные. Тексты и события после контрольной точки оставались у оценщика.
@ 5 3.6 3.6 3.6
| Политика, 4 КиБ | Kimi, 112 задач | Kimi, 98 задач | Claude, 48 задач |
| LRU по адресам | 172 / 253 | 119 / 206 | 122 / 186 |
| Прежняя графовая память | 173 / 253 | 121 / 206 | 122 / 186 |
| Инвалидация или перенос | 173 / 253 | 121 / 206 | 122 / 186 |
Во всех 645 проверках обе версии политики совпали по основному исходу с прежней графовой памятью. При независимом повторном чтении строк на второй панели Kimi было 72 неправильных адресных ответа среди 20 865 проверок. Новая политика убрала все 72, но также потеряла 127 правильных ответов. Эти ошибки сосредоточены в двух задачах. На внешней панели 13 ошибок сохранились. При оценке согласованности важно считать и ошибку, и цену отказа отвечать.
**Почему лучшее сжатие почти ничего не меняет.** Из 229 пропущенных блоков только 13 восстановились при снятии лимита старой памяти. Для 212 хотя бы одна строка отсутствовала даже во всей прежней адресованной истории и текстах аргументов по этому пути. Ещё у четырёх были отдельные строки. История может содержать нужный текст без распознанного адреса. Эти числа относятся к конкретному формату наблюдений.
На 9646 событиях три варианта LRU при строгих 4096 байтах восстановили одни и те же 413 блоков. Двоичная запись относительных адресов и отступов с выбором кодека хранила в среднем 216,84 строки против 212,83. Время перехода выросло с 3,46 до 9,01 мс на CPU. Распаковка всех 28 938 пакетов проверена. Малый прирост ёмкости имеет измеримую цену и не устраняет отсутствие исходных наблюдений.

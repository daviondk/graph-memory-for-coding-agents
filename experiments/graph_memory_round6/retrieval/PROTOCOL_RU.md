# Предварительный протокол R6 · 19 ноября 2026
Ранжируем внешние фрагменты для продолжения кода по последним трём строкам. Гипотеза: переменные getUserName, user_name и User могут содержать сведения о будущем объявлении даже при отсутствии точного совпадения. Сигнал зависит от роли совпавшего слова и от числа альтернатив, которые его покрывают.

Одну и ту же базовую модель из 43 признаков R4 дополняем признаками раздельного покрытия частей имени корневого объявления, методов и тела, локальной обратной частоты по списку кандидатов, последнего упоминания и морфологии имени. Контроль direct использует эти признаки без нового обмена по рёбрам, хотя включает исходные признаки графа R4. Полная модель full дополнительно агрегирует сходство полей у соседей со ссылкой на тип. Placebo переставляет новые сообщения по кандидатам фиксированным циклическим сдвигом, сохраняя прямые новые признаки. Используем исходный Java train R4, идентичные гиперпараметры бустинга и веса. Отдельная ablation only_fields учит только новые прямые признаки. Никакой настройки по тесту. Порядок решения ничьих исходный. Исключены имя репозитория и путь, исходный порядок как признак, полные импорты, следующая строка и индексы ответов на тесте. Новые признаки читают только те же три строки и те же кандидаты.

Первичные исходы — paired Accuracy@1 модели full против замороженного R4 на Java HF, 2000 исходных строк публичной панели Semlith, и против действительно исполненного официального UniXcoder на строгой панели Java HF 320 (отдельные проекты по отношению к 2000). Две двусторонние проверки со знаковой перестановкой кластерных сумм, поправка Holm. Сравнение с фактическим Semlith 0.36.0, Java BM25 издателя, MRR и @3/5, перенос на исходные 2000 Python-задач HF, абляции и отдельные страты вторичны. Не делать вывод о SOTA по одному сопоставлению. На исходном Java архиве дополнительная панель 224 R5 позволяет сравнить с независимым фактическим UniXcoder, его прямой смесью и авторским Jaccard в том же пуле. Для проверки сохранения бюджета использовать последнюю тройку .splitlines() для HF и ту же тройку, что R5, на архивной панели.

Для независимости проверки переносимости дополнительно сформировать новую панель Python из HF, устранив проекты при любом пересечении с Java train, Python первичной панелью R4 и Java-панелями эксперимента. На каждую из четырёх страт брать по SHA-256 не больше 4 запросов одного проекта и максимум 150 на страту; обработать также неполную страту. Сравнить с авторским Jaccard (CodeGen BPE), R4 и BM25 издателя. Это подвыборка из малых и ранее не выбранных проектов, поэтому приводить фактические числа и отдельно оценивать уже использованную панель. Остальные панели старых серий публичные и были оценены прежними моделями. Объединять их в единый независимый тест нельзя.

Хешировать используемые входы и сверять зафиксированные результаты исходных методов. У всех методов одинаковый набор кандидатов в каждом парном сравнении. Невалидный эталон — промах всем. Парный 95% процентильный интервал микросредней разности — 10000 повторных выборок целых проектов, seed 260619; отдельно равный вес проекта и wins/losses.

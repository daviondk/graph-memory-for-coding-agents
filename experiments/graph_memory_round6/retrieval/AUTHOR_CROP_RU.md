# Проверка выявленного расхождения в обработке конца строки
Аудит входов до подсчёта исходов выявил, что splitlines() режима поставщика и архивная авторская функция RepoBench crop_code_lines (split по символу LF) выдают разные строки для 52 из 224 архивных Java-задач и 352 из 353 свежих Python-задач. Для точного академического сравнения на всех 224 архивных Java и 106 сбалансированных Python запустить исходную функцию авторов для каждого запроса и применить один и тот же полученный текст к R6 full, R4, BM25, Jaccard и реальному UniXcoder. Для идентичного текста допустимо переиспользовать строго совпавшую ранее запечатанную выдачу энкодера, для остальных запустить тот же CPU FP32 энкодер 512 BPE. До открытия любых исходов фиксировать обе выдачи. Строгий контроль по всем 224 Java-спискам Jaccard сверить с R4-оценкой исходного архива. Это дополнение к первичной семье, вызванное проверяемой реализационной разницей. Результаты отдельных языков не объединять.

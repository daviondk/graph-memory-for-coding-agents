# Выбор места следующей правки без подсказки будущего адреса

На всех контрольных точках (каждое четвёртое завершённое действие) три правила получают только неизменное описание задачи и декодированное состояние адресной R5 размером до 4096 байт. Правила заполняют прогноз и тогда, когда позднее правки не окажется. Каждый непрерывный фрагмент одного пути по возрастанию координат разбивается на последовательные непересекающиеся окна по десять резидентных строк. Последнее окно может быть короче. Заранее выдаются первые три окна, первое также образует бюджет одного окна. Бюджет не превышает 10 или 30 строк и одинаков для всех методов. Базовое правило предпочитает самый свежий текст и недавний путь, затем близость к центру последнего наблюдения. Второе отдаёт приоритет пути последней подтверждённой правки; внутри пути работает базовое правило. Третье совмещает ранги по давности и совпадениям с описанием задачи (редкие по текущим окнам слова кода и пути), добавляет ограниченные вклады повторных посещений и подтверждённой правки. Все коэффициенты фиксированы в find_route.py до оценки. Обучение на целевых задачах отсутствует.

Основной контраст заранее задан на панели переноса Kimi: комбинированное правило против давности по попаданию начала будущей правки в одно выбранное окно с правильным путём. Также оцениваются три окна, правильный файл, восстановление полного старого текста по объединению выбранных координат и доля достижимых стартов во всей 4-КиБ памяти. Прежние 645 срезов раскрывает только оценщик после SHA всех прогнозов. На 96 общих срезах из R5/H сравниваются единые метрики правильного пути и расстояния не далее пяти строк от единственного предсказания (середина первого окна, округление вниз; для старых моделей сохранённый вывод). У моделей отличаются вход и вычислительный бюджет. Кластерный бутстреп по задачам, 10000 повторов, seed 67231; вторичные сравнения описательные. Проверяются наблюдаемые действия записанного агента; успешность исполнения правки не является исходом.

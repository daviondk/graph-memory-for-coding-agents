# Версии строк после изменения файла через shell

Новая политика восстановила те же 416 из 645 будущих блоков, что и адресная память R5. На основной панели переноса это 121/206 у обеих политик, с одинаковым исходом для каждой правки. Повторный показ кода на этой панели выявил 72 ошибки R5, которые новая политика устранила ценой отказа отвечать и на часть правильных адресов. Ошибки сосредоточены в двух задачах.

## Выполненная проверка

CPU-проигрывание 9646 событий на 258 непересекающихся задачах SWE-bench Verified. Панель проектирования содержит 112 историй Kimi, основная проверка переноса — 98 других историй Kimi. Дополнительно получены 48 публичных историй Claude Sonnet 4 из 12 проектов. Контрольные суммы всех 460 936 480 загруженных байт совпали с ранее зафиксированными SHA оригиналов. Все изменяемые данные каждого метода, включая флаг каталога и скрытые старые строки, на каждом шаге закодированы в пакет размером не более 4096 байт. Следующий шаг получает только этот пакет, общие веса, исходную задачу и очередное наблюдение. Обе ветви R5 точно воспроизвели прежние контрольные суммы на каждом из 6814 шагов Kimi. Команды из историй обрабатывались как данные.

| Панель | Задач с целью | Блоков | R5 | LRU с тем же входом | Инвалидация файла | Перенос и якоря | Когда-либо была распознана shell-запись в целевой файл к срезу |
|---|---:|---:|---:|---:|---:|---:|---:|
| Kimi, исходная | 104 | 253 | 173 | 172 | 173 | 173 | 7 |
| Kimi, перенос | 87 | 206 | 121 | 119 | 121 | 121 | 4 |
| Claude, внешняя | 48 | 186 | 122 | 122 | 122 | 122 | 0 |

Цель — точный полный текст старых строк на своих координатах в ближайшей попытке правки в пределах четырёх следующих шагов. Состояния фиксировались каждый четвёртый шаг. Оценщику для проверки даётся будущий путь. Парный бутстреп 10 000 раз выбирал задачи целиком. Для переноса против R5 во всех трёх панелях эмпирическая разность и обе границы интервала равны нулю, поскольку ни одного расхождения по основному критерию не было. Это не оценивает величину эффекта на новых задачах с частыми shell-изменениями. Относительно LRU разность на основной панели +0,97 п. п., ДИ от 0 до +2,51, на внешней 0,00 п. п., ДИ от −1,56 до +1,55.

## Точность сохранённых адресов

Вспомогательный аудит сверяет память непосредственно перед независимым будущим чтением терминала, просмотром редактора или показом неизменившегося соседа подтверждённой правки. Внутри версии файла используется первая проверка каждого номера. Для всех доступных проверок приведены числа верных и ошибочных ответов. Остальное — отсутствие ответа.

| Панель | Проверок | R5 верно / ошибка | LRU верно / ошибка | Инвалидация верно / ошибка | Перенос верно / ошибка |
|---|---:|---:|---:|---:|---:|
| Kimi, исходная | 26 267 | 1865 / 78 | 1852 / 78 | 1856 / 0 | 1866 / 0 |
| Kimi, перенос | 20 865 | 1390 / 72 | 1378 / 72 | 1253 / 0 | 1263 / 0 |
| Claude | 33 681 | 1436 / 13 | 1499 / 13 | 1436 / 13 | 1436 / 13 |

На переносе R5 ответил неверно в 72/1462 предъявленных ответов (4,92%), новая политика — в 0/1263. Выигрыш по ошибкам сопровождается потерей 127 правильных адресов и ростом числа пропусков с 19 403 до 19 602. Разность ошибок относительно всех 20 865 сверок −0,35 п. п., парный ДИ по 97 задачам от −1,14 до 0,00. Из 250 проверенных адресов после последней распознанной shell-записи R5 дал 112 верных, 72 ошибочных и 66 пустых ответов, перенос — 10 верных и 240 пустых. Эта подгруппа состоит всего из двух задач. На строках самих целевых правок две ошибки стали пропусками, 1784 верные строки сохранились. На внешней панели видимый повторный показ затронутого файла после shell-записи отсутствовал, а 13 других ошибок сохранились. Устранение ошибок на двух панелях Kimi не даёт основания присвоить памяти общую гарантию согласованности версий.

## Откуда берётся ограничение по полному блоку

На 80, 85 и 64 промахах R5 соответственно хотя бы одна нужная строка отсутствовала в ограниченном состоянии для целевого пути даже при произвольной перестановке и учёте кратности. Простое перемещение сохранённого текста не могло восстановить ни один из 229 блоков. В отдельной описательной проверке после основной оценки неограниченная адресная память с прежним источником наблюдений восстановила ещё 5, 1 и 7 блоков. Для ещё 1, 2 и 1 блока все строки по отдельности нашлись в изменявшейся истории того же пути либо в аргументах инструментов. Для остальных 74, 82 и 56 хотя бы одной строки не нашлось даже в этом расширенном множестве. Проекция охватывает распознанные наблюдения с адресом. Вывод нераспознанных команд, иные пути и полный репозиторий выходят за пределы этой проверки.

Распознаватель помечал явную попытку изменения именованного файла по ограниченной грамматике shell и статического Python. Код выхода в проекции доступен не всегда. Простые численные команды sed позволяют предсказать сдвиг при условии успеха, часть строк при подстановках сохраняет адрес. Неопределённые строки переносились под внутренний адрес и могли быть восстановлены по двум различительным совпадениям с новым показом в ограниченной окрестности. В трёх панелях обнаружено 201, 172 и 227 попыток изменения; в ветви переноса лишь 40, 44 и 29 из них встретили резидентные строки. Перенос вернул по якорям одну строку на исходной панели и ни одной на двух других. На внешней панели все 227 распознанных попыток попали в общий класс записи, для которого явного сдвига не было.

| Панель | Средние байты R5 / LRU / инвалидация / перенос | Средние CPU-мс на событие в том же порядке |
|---|---|---|
| Kimi, исходная | 1559 / 1524 / 1546 / 1557 | 4,71 / 3,58 / 4,25 / 4,55 |
| Kimi, перенос | 1619 / 1587 / 1589 / 1600 | 4,00 / 3,34 / 3,98 / 3,92 |
| Claude | 3505 / 3455 / 3489 / 3505 | 14,06 / 7,14 / 14,16 / 14,23 |

Все четыре метода достигали максимума 4096 байт в каждой панели. Время относится к локальной Windows-машине и хронологическому проходу с тремя рабочими процессами. Общий неизменный словарь, веса и описание текущей задачи исключены из байтов изменяемого состояния. Качество решений SWE-bench в этой проверке не измерялось.

## Материалы и воспроизведение

`PROTOCOL_RU.md`, `version_policy.py`, `replay.py` и `score.py` задают первичный эксперимент. SHA-256 файла фиксации метода — `430a093e1497ea59bdb30d4c1aaa1b7f8350389ee6679a420062c462049e7e66`. Семнадцать файлов состояний запечатаны перед оценкой в `state_lock.json`, SHA-256 `79e9847de831e39f8fe9c33e909228be4c531669143f17a67e8dc8ceba4d569e`. Два динамических импорта старого неизменённого кода дополнительно зафиксированы перед оценкой в `dependency_lock.json`. Каждая строка `states_*.gz` содержит ID задачи, шаг, четыре обратимых пакета в base64, замеры CPU и размера, счётчики изменений. Сопоставления по целям, адресам и распознанным операциям сохранены в `block_outcomes.jsonl.gz`, `address_audit.jsonl.gz`, `operations.jsonl.gz`. В `results.json` есть полные знаменатели и интервалы. `headroom_records.jsonl.gz` и `history_records.jsonl.gz` дают обе диагностики по каждому срезу.

Для автономного повтора поместите эту папку в `work/graph_memory_round6/version`, распакуйте `upstream_inputs.zip` в `work`. Из `version` запустите `python -B score.py`, затем `python -B headroom.py` и `python -B history_diagnostic.py`. Результат `results.json` побайтово совпал при повторе в изолированном дереве с 65 упакованными исходными зависимостями. Полный повтор генерации выполняется в отдельной копии без `state_lock.json` командой `python -B replay.py predict`. Требуются Python 3.14, NumPy и Brotli. План парной проверки и анализа кластеров оформлен с использованием experimental-design и statistical-analysis. [Kassis и соавт., 2026](https://arxiv.org/abs/2609.00065)

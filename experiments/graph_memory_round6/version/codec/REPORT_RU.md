# Более плотная запись строк при лимите 4096 байт

На одних и тех же логических состояниях новое адаптивное кодирование сэкономило **3,66% байтов** относительно JSON с Zstandard-15 и общим словарём. В последовательном запуске LRU это увеличило среднее число сохранённых строк с 212,83 до 216,84. Полностью восстановлены те же **413 из 645 блоков**. Ни в одной задаче или панели полнота отдельного блока не изменилась.

| Политика LRU | Полные блоки Kimi, исходная / перенос / Claude | Верные строки из 8515 | Средние байты | Среднее число строк | CPU-мс на переход |
|---|---|---:|---:|---:|---:|
| JSON + Zstandard-15 | 172/253 · 119/206 · 122/186 | 6159 | 2113,44 | 212,83 | 3,46 |
| Раздельные адреса и текст R5 + Zstandard-15 | 172/253 · 119/206 · 122/186 | 6161 | 2087,28 | 215,52 | 3,30 |
| Кратчайший из трёх форматов + Zstandard-15 | 172/253 · 119/206 · 122/186 | 6161 | 2071,38 | 216,84 | 9,01 |

Новый двоичный формат хранит переменными целыми числами координаты, возраст блока и количество ведущих пробелов у каждой строки. Отступы отделяются от исходного текста при упаковке и в точности восстанавливаются декодером. Для каждого предлагаемого состояния адаптивный кодер выбирает кратчайшее из JSON, прежнего раздельного формата и нового двоичного представления. Бинарное представление выбрано в 8893 из 9646 конечных состояний, прежний раздельный поток — в 753. На одинаковых логических состояниях стандартной ветви сумма длин составила 20 386 211 байт для JSON, 19 898 981 для прежнего раздельного формата, 19 649 785 для двоичного и 19 639 427 для выбора минимума. Сюда включены байты заголовков и флаг рабочего каталога. Неизменный 32-КиБ словарь компрессора общий для всех задач.

На панели Claude, где памяти требовалось больше, среднее число сохранённых строк выросло с 354,99 до 365,93. Точные целевые строки по-прежнему совпали в 1706 позициях. На исходной панели Kimi обе альтернативы дали две дополнительные верные целевые строки, на двух других панелях — ноль. Все кодеры дали пять ошибочных строк в сумме. Набор из 645 срезов включает 239 задач. Парный бутстреп 10 000 раз выбирал задачи целиком; при одинаковых 645 исходах его эмпирический интервал для разности по полным блокам вырожден в ноль. Сопоставление с прежней графовой политикой вытеснения даёт 413 против 416, −0,47 п. п., 95% ДИ от −1,29 до +0,31. Общие результаты этой выборки были известны до выбора формата.

Затраты на адаптивный перебор оказались в 2,61 раза выше стандартного контроля. Замеры локального CPU охватывают чтение наблюдения, предложение состояния и все попытки упаковки при вытеснении. Повторное кодирование одинаковых состояний и проверка обратимости вынесены за границы таймера. По всем панелям только 411 из 9646 стандартных обновлений первоначально превысили бюджет и потребовали вытеснения. В независимом диагностическом проходе основной работы неограниченная адресная память восстановила ещё 13 блоков относительно ограниченной графовой ветви. Эти числа характеризуют доступную возможность для улучшения на этой выборке.

Генератор подтвердил идентичность стандартного LRU прежним пакетам на всех 9646 шагах. Для каждого из 28 938 записанных пакетов независимо проверено полное совпадение декодированного графа с логическим состоянием перед упаковкой. Все конечные состояния уложились в 4096 байт. В полном прогнозе используются наблюдения только до текущего шага. Файлы `codec_*.gz` содержат проверяемые состояния после каждого шага и сырые замеры размера, времени, числа строк и вытесненных страниц. `scored.jsonl.gz` хранит исход по каждому целевому блоку. `results.json` содержит разрезы и интервалы.

Протокол и код запечатаны в `method_lock.json`, SHA-256 `9334b0858ef3d770bc381b46af2db1874c7d7d7c05ae0ee690a4e211e6f6c4cc`. До оценки добавлен явный выбор оценщика по пути, поскольку в старых каталогах несколько модулей называются score.py. Его хеш есть в `evaluator_lock.json`, алгоритм оценки взят из замороженного родительского опыта. SHA-256 `state_lock.json` перед декодированием целей — `f7cace63ec93b80cc86d582329c5770521800b5c40a629f7754618f864648a99`. Из этой папки `python -B evaluate.py` повторяет оценку. Для нового полного прохода используйте отдельную копию без `state_lock.json`, выполните `python -B run_codec.py` и затем `python -B evaluate.py`. Зависимости находятся в родительском `upstream_inputs.zip`; порядок распаковки указан в основном отчёте.

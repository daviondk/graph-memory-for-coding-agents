# Дополнительная проверка кодирования

Априорный вопрос для новой политики кодирования на уже изученных панелях: увеличит ли обратимое кодирование адресов, возраста наблюдений и отступов число полностью восстановленных блоков при обычном вытеснении LRU, если выбирать минимальное представление каждого состояния по его фактическому числу байт? Три варианта имеют один и тот же наблюдаемый вход, точный R5-обработчик событий и один и тот же порядок удаления страниц LRU. Стандартный контроль — Zstandard-15 с общим словарём R4 и JSON. Второй контроль — опубликованный R5 поток адресов/текста с Zstandard-15, ранее проверенный на проекции редактора. Новый кодер сравнивает длины этих двух и нового бинарного варианта. Последний хранит относительные координаты и возраст беззнаковыми переменными целыми, отступы переносит в отдельную последовательность длин, а код без ведущих пробелов соединяет в один поток. Компрессор и общий словарь остаются теми же. Байты идентификатора варианта и состояния каталога оплачиваются. Декодирование каждого записанного состояния сверяется с полным графом до упаковки при генерации, а у стандартной ветви байты на каждом шаге обязаны совпасть с ранее запечатанными.

Первичный контраст — адаптивный кодер против JSON для LRU по доле восстановленных целиком блоков на всех 645 ранее оценённых срезах. Парный бутстреп 10 000 раз выбирает целые задачи (seed 67231). Три агенто-панели показываются отдельно, а вытеснение cal_neighbor из первого эксперимента даёт внешний ориентир. Срезы и ответы серии уже известны. Параметры кодера определены до его запуска и до открытия различий с контролем. Никакой калибровки на ошибках или выбора выгодной панели. Ещё измеряем число точных строк, средние и максимальные байты, количество резидентных строк, долю выбора кодеков, число новых/потерянных блоков и затраты CPU. Сэкономленные байты оцениваем также при одинаковом логическом состоянии стандартной ветви. По каждому шагу сохраняем три фактически сериализованных состояния; SHA-256 закрывает результаты до оценки целей. Стандартные библиотеки Python и CPU, исходные команды не запускаются.

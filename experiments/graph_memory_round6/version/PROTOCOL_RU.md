# R6. Версии адресованных строк

Проверяем, повышает ли обработка наблюдаемой shell-записи полноту реконструкции старого блока будущей правки при лимите 4096 байт. Зафиксированный адресный метод R5 и его LRU получают те же редакторские наблюдения и тот же парный терминальный журнал. Две новые политики используют тот же cal_neighbor и тот же кодек. При распознанной попытке изменения файла первая удаляет всю его текущую карту. Вторая переносит адреса для простой численной команды sed, сохраняет заведомо непричастные строки простых подстановок, а строки с неизвестной судьбой прячет под внутренним именем пути. Последующие независимые буквальные наблюдения могут вернуть локальный фрагмент по двум различительным якорям с одинаковым смещением. Порядок, все пороги и ограниченная грамматика описаны исполняемым методом. Ввод включает только наблюдения на текущем шаге и неизменное описание задания. Каждый следующий вызов декодирует исключительно предыдущий пакет. Теневые строки и флаг текущего каталога входят в бюджет. Команды журнала не исполняются. Статический синтаксический разбор Python разрешён.

Исходная панель состоит из 112 траекторий R5. Описанный ранее случай смещения в django-16560 относится к проектированию. Первичная проверка на 98 непересекающихся задачах Kimi R5 использует ранее опубликованный протокол каждой четвёртой точки и ближайшей попытки str_replace в пределах четырёх шагов. Проверяющая сторона восстанавливает старый текст и координаты по успешной операции. Первичный контраст — версия с переносом минус R5 по доле целиком восстановленных блоков. Дополнительный контроль — уничтожение всего файла, LRU, доля точных строк, частота уверенно выставленных ошибочных строк и затраты. Новая независимая панель состоит из 48 других ID Claude Sonnet 4 из ранее полученных проекций редактора. Файлы исходных публичных историй повторно загружаются только для восстановления их видимого терминала. Репозитории чередуются по алфавиту, строки внутри репозиториев сортируются по заранее заданному SHA-256, два списка ID R5 исключены. Список новых ID фиксируется до загрузки, ошибки загрузки видны в receipts. Результаты всех панелей сообщаем отдельно. Предыдущие агрегаты R5 известны.

Независимый аудит перед каждым новым наблюдением проверяет, какой текст память уже выставляла по координатам последующего буквального чтения терминала, view редактора и неизменённых соседей успешной редакторской правки (в старых координатах). При совпадающих источниках терминал ниже редактора по приоритету. Одна первая проверка на адрес и эпоху файла (с известной shell-попытки изменения или изменения редактора). Храним пропуски как отдельный исход, отдельно показываем проверки в эпохах shell-записи и риск на целевых строках правок. Это проверка потенциального устаревания условно на последующий показ. Скорость учитывает CPU процесса при реальном обновлении, отдельно приводим средние байты, максимум и шаги; замеры CPU зависят от порядка и кэшей. Бутстреп повторно выбирает целые задачи, 10000 повторов, seed 67231, 95% процентильный интервал парной разности. При вырожденном бутстрепе явно указываем отсутствие наблюдаемых разногласий. Подгруппы и остальные контрасты описательные. Не выводим вывод о решении SWE-bench и не меняем политики по результатам.

Метод, вычисление метрик и источники фиксируются SHA-256 перед прогнозом. По завершении журнал всех состояний и метрик затрат запечатывается отдельно перед открытием целей. Существующие шаговые SHA обоих старых методов должны совпасть для обеих панелей Kimi.

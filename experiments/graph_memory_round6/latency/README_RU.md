# Парный замер цены чтения
Результаты Linux в native_results.json и сырые времена трёх повторов каждого метода в times_native.jsonl (микросекунды). Для Windows-каталога под WSL см. results.json и times.jsonl. Оба хранилища физически на диске D. В отличие от первоначального учёта открытий, таймер здесь охватывает поиск по фактически распакованному состоянию и преобразование доставленного текста в единый ответ. Полезное действие проверяется одинаково во всех ветвях — 186/186 на том же адресе отдают байтово идентичный JSON с учётом пропусков.
- Файл bench.py хеширует исходные материалы и запускает последовательный хронологический replay авторского PageStore и RecallService. На каждом запросе timed заново читает из настоящего архива или из 4-КиБ буфера Zstandard. Общая форма данных для ответа — JSON с file, first, lines. Сгенерированные архивные идентификаторы и каталог версий общие для сравниваемых маршрутов. Порядок измерений меняется. Состояние кеша заранее находится в ОЗУ, декодирование полностью оплачено в каждом измерении. Сами файлы эталонных ответов используются только в assert после остановки таймера.
- Файл bench_native.py повторяет работу с каталогом страниц в локальной Linux-файловой системе и третьей ветвью LRU. Это повтор на ином размещении с иной стоимостью ввода-вывода, аналитическая единица та же. Ускорение на горячем запросе и дополнительное время при промахе обобщаются отдельно. На Linux при промахе суммарная задержка выросла с 65,83 до 70,99 мс по 63 запросам.
- Для перепроверки чисел без пересоздания архива выполнить python analyse.py и python analyse_native.py с NumPy. Для нового измерения восстановить структуру work/graph_memory_round6, распаковать материалы published/published_replay.zip в соответствии с его внутренним деревом, поместить официальный src в published/MemTrace/src. Согласованные архивы и каталоги создаются заново. Использовать свежий каталог БД и имена файлов сырых измерений, чтобы сохранить исходный прогон. Версия Linux/Python и SHA зависимостей находятся в method_lock.json и native_lock.json.
Результат относится к предложенному чтению по заранее заданному адресу на прогретой машине, к одному вызову после построения памяти. Стоимость облачного API, время решения задачи моделью и чтение физических секторов диска требуют отдельных измерений.

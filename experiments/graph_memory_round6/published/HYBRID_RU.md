# Дополнительная проверка кэша перед MemoryRef

До вычисления результатов многократного чтения и гибрида фиксируем правило. Внешний клиент передаёт путь к файлу, номер первой строки и число последовательных строк. На тесте ближайшей правки этот адрес выдаёт оценочный сценарий из будущего действия. Решатель, который должен сам выбрать файл и место правки, такой информации не имеет. Текст цели не передаётся. У горячего R5 лимит состояния 4096 байт. Если локально сохранена каждая запрошенная координата, отдаём весь найденный текст. Судить о том, верен ли он на самом деле, маршрутизатор не умеет. На любом пропуске передаём весь адрес в неизменённую процедуру многократного чтения MemTrace. Кэширование не меняет холодное хранилище и его непрерывную запись. В холодной ветви те же пределы 8 открытий и 32768 условных токенов автора (≤98 304 байта отданных нативных кадров). Горячая выдача обязана укладываться в 98 304 байта. Измеряем полное точное совпадение строк, число физических вызовов RecallService, прочитанные страницы и байты его фактически возвращённых кадров (на горячем маршруте — байты короткого адресного JSON). Дополнительно показываем единый JSON с извлечённым текстом для сравнения полезной выдачи. Чтения холодной ветви повторяем реальным авторским движком. Сравнение условно на прежнем отборе задач и адресов. Слепое исследование на новых задачах по ходу этого опыта не проводится.

# R6. Парное чтение источника в MemTrace и адресной памяти R5

Фиксируем до сравнительной оценки официальный исходный код Homy-Xu/MemTrace, коммит 5508f8be81025d8aa90726b1e06aef4ea484e577. Используем честный CPU-режим чтения памяти внутри одного решаемого задания. Для воспроизведения pass@1 DeepSWE авторы указывают доступ к DeepSeek V4 Flash 0731, 200 000 токенов и свежий контейнер на каждый экземпляр. У текущего окружения отсутствует переменная авторского поставщика. Публичная реализация позволяет вызвать настоящий PageStore со сбросом на диск, SemanticStore с SQLite и RecallService, включая проверку содержимого и возвращаемый решателю контекст. Авторские внутренние подмены для тестирования отдельных ветвей не участвуют в сравнении.

Панель фиксирована серией 5. Берём все 98 задач action_transfer и все подходящие каждые четвёртые срезы, до ближайшей успешной замены по её исходному алгоритму. Сравнение повторно использует эту публичную панель, известен прежний результат R5. Запрос на чтение содержит путь и [первую, последнюю] строки цели. Он не содержит эталонного текста. Этот режим измеряет доступность текста для уже известного адреса. Для положительного контроля берём до одного ранее показанного трёхстрочного блока на задачу, в одной наблюдаемой редакции, по детерминированному хешу (prepare.py). Заранее разрешаем цитировать любой исход. Основная метрика — доля запросов, в которых все строки ответа на своих позициях посимвольно совпали. Указываем исходы каждой задачи и кластерный парный 95%-й bootstrap-интервал.

Для обеих систем доступен один и тот же хронологический журнал. Берём наблюдаемые пронумерованные строки редактора и исходный распознаватель терминального чтения R5. Репозитории не подгружаются, строки команд являются инертными данными. Снимки R5 были запечатаны до раскрытия исходов в предыдущей серии. Новый адаптер MemTrace публикует в PageStore один EventGroup на путь и шаг наблюдения с типом CODE_OBSERVATION, ключом file и ролью provider_observed_read, строковыми координатами и оригинальным текстом в code_excerpt или code_sections. Смена номера видимой редакции происходит после подтверждённого str_replace либо консервативного события insert/create/undo_edit в соответствии с R5. Иной терминальной информации для установления точного ref репозитория в траектории нет. Проверяемое хранилище не имеет доступа к файлам ответов или полным исходным файлам.

Проверяются два интерфейса MemTrace. Первый выполняет штатный одноразовый запрос по точному file EvidenceKey текущей видимой редакции с обычным лимитом 8192 условных токена. Во втором рабочий адаптер выбирает ранее полученный адрес страницы из видимых диапазонов (наибольшее пересечение с интервалом запроса, далее более свежий шаг). Он передаёт прямой MemoryRef, путь и запрошенные строки в авторский RecallService с лимитом выдачи 32 768 условных токенов. Разрешён доступ к исторической странице по исходной редакции. Так даже после записи сравниваются как возвращённые строки, так и возможные устаревшие значения. Для положительного контроля передаём ссылку на сам показанный источник. Это намеренно благоприятный диагностический режим для MemTrace, у адаптера есть незаряженный внешний указатель на источник. Пустой каталог возвращает пустые координаты. Проверяем только реально отданный публичный rendered_content. Сохраняем его, число переданных байтов, количество открытых страниц и статус. Набор не является оценкой навигации планировщика MemTrace, его Repository State Graph, онлайн-выбора правки или прохождения тестов.

Адресный R5, исходный R5 без терминальных адресов и простой LRU R5 декодируются из запечатанных 4096-байтных снимков. Их read получает тот же диапазон. Расходы на память и размер возврата описываются отдельно. MemTrace имеет постоянное неограниченное хранилище и дополнительный индекс диапазонов в режиме прямого чтения. Размер ответа MemTrace включает собственные открытые поля происхождения. Уравнивание размеров хранилища разрушило бы авторскую модель долговременных страниц. Не складываем эти величины в единый коэффициент эффективности.

Отдельно выполняются тесты ядра Recall из авторского репозитория в Linux. Табличные результаты статей и локальный эксперимент приводятся с указанием соответствующих единиц.

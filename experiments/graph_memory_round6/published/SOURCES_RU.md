# Кодовая память и близкие опубликованные сравнения

Таблицы статей приводят результаты своих полных решателей. Наша локальная операция чтения имеет другую единицу наблюдения.

| Метод или набор | Режим, объём, результат по данным авторов | Связь с проверкой |
|---|---|---|
| MemTrace, граф следов MTG, граф репозитория RSG | На DeepSWE, DeepSeek V4 Flash 0731 high, Codex CLI 35,4% pass@1 с обычным контекстом и 56,6% с MemTrace. Под mini-swe-agent — 48,7% и 66,4%. На SWE-EVO под Codex MemTrace даёт 69,6% полного решения против 65,2% с Observation Masking. Для частичного Fix Rate порядок обратный, 70,6% и 72,1%. | Текущая редакция и происхождение факта. Проверены исходная публикация, авторская таблица 2, таблица абляций 3 и публичный код. Указанный в разделе экспериментальных условий статьи открытый предел по шагам расходится с 200 ходами в публичном профиле. [Статья и таблицы](https://arxiv.org/html/2610.04838v1) · [Зафиксированный исходный код](https://github.com/Homy-Xu/MemTrace/tree/5508f8be81025d8aa90726b1e06aef4ea484e577) · [Профиль воспроизведения](https://github.com/Homy-Xu/MemTrace/blob/5508f8be81025d8aa90726b1e06aef4ea484e577/docs/deepswe-reproduction.md) |
| Observation Masking и RepoGraph | В сравнении MemTrace на Python-подмножестве DeepSWE под Codex CLI pass@1 составляет 38,2% для маскирования, 41,2% для RepoGraph и 67,6% для MemTrace. Отдельный проект JetBrains исследовал 500 задач SWE-bench Verified и сообщил снижение средней стоимости на 52% для Qwen3-Coder 480B при маскировании старых наблюдений. | Маскирование контролирует удержание истории, RepoGraph предоставляет структурную карту кода. Для сравнения RepoGraph выборку DeepSWE ограничивали Python. [MemTrace, таблица 2](https://arxiv.org/html/2610.04838v1) · [Авторы исследования маскирования](https://blog.jetbrains.com/research/2025/12/efficient-context-management/) · [Код RepoGraph](https://github.com/ozyyshr/RepoGraph) |
| VibeMemBench, долговременная память между задачами | 111 целевых задач, 90 репозиториев, 3634 исторические траектории. Прямая передача заранее подобранного опыта повысила наблюдаемую долю решений у четырёх из пяти независимых решателей на 1,1–4,5 п.п., все пять 95%-х интервалов включают ноль. В режиме поиска SimpleMem на DeepSeek V4 Pro даёт 66,9% (−0,2 п.п. к отключённой памяти), Mem0 — 62,8% (−4,3 п.п.). | У одной и той же найденной истории различная ценность в зависимости от решателя. Набор отбирался по полезности истории на опорном решателе. [Публикация и таблицы 1–2](https://arxiv.org/abs/2609.23570) |
| Compact-Bench, реальные продолжения сжатой истории | 35 ремонтов SWE-bench, 146 агентских сессий и 106 производственных цепочек. Среди 22 ремонтов, которые проходили с полной историей, доля потерянного устойчивого успеха варьировалась от 5% до 64% у 14 суммаризаторов. Лучшее сохранение успешных ремонтов в этом сравнении показал Claude Opus 4.8. | Измеряет, может ли агент продолжить работу после сжатия. [Первичная публикация](https://arxiv.org/abs/2610.31710) · [Код оценщика](https://github.com/cai-jianfeng/compact-bench) |
| Microsoft CompactionBench и APEC | Авторы проанализировали 13,5 млн реальных сессий GitHub Copilot. 7,8% сессий со сжатием потребили 44,2% токенов. На отдельном исполняемом многошаговом тесте асинхронная подготовка контекста сократила расходы до 25,4% и время работы агента на 9,6%. | Проверяет качество при повторных сжатиях, задержку и работу кеша.

# Дополнительная проверка нескольких исторических источников

В основном анализе точное чтение одной ранее показанной страницы уступило запечатанному графу на 8 полных блоков. До расчёта следующего результата фиксируем усиленный режим. На каждом из тех же срезов адаптер ведёт указатели на все видимые ранее наблюдения. Для каждой строки известного диапазона выбирает самое свежее указание того же файла и номера строки. Затем ранжирует различные страницы по числу обслуживаемых координат, далее по свежести. Запрашивает нативным RecallService до 8 страниц при суммарном бюджете 32 768 условных токенов на запрос. Объединяются только реально возвращённые строки и только из заранее выбранных для них наблюдений. Выбор не зависит от ответа. Обращение к исторической версии сохраняет риск устаревшего содержания и смещения координат. Контрольные запросы используют то же правило без специального указания на исходную страницу. Модель и файлы репозитория не нужны. Источник прошлых состояний переигрывается хронологически в новых базах. Это разведочная проверка после просмотра результата основной схемы.

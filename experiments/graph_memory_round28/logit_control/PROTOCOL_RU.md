# Сильный контроль памяти из факторизованных оценок

Дополнение составлено после первичного результата R28/retraction_db. У полного SQLite-индекса сохранён каждый span, хотя нейросеть выдаёт только две оценки на токен. Новая проверка оценивает физическую БД с исходными logit-векторами, адресами и принадлежностью сегментам. Это самостоятельный точный резерв для top-K. Две реализации резерва — отдельный BLOB на каждое модельное окно без сжатия и тот же BLOB в zlib level 6. Декодируем little-endian массивы и вычисляем лучшую допустимую сумму в независимых окнах. Совпадение относится к битам float32, идентификатору и обеим координатам. Нейросеть повторно не вызывается.

Фиксируем прежние 96 вопросов, все 2 202 интервальные проверки и ту же панель 16 × 2 статьи/вопроса для 3 основных запретов. Контроли — повтор прежнего точного skyline, прямой on-demand scan двух видов и исходный top-8/top-64 с новым резервом каждого вида. При попадании кэш отвечает одним SQL-запросом; при промахе загружаются BLOB нужных окон. Для основной пары skyline / top-64 + сжатый резерв даём разницу медиан и 95% кластерный интервал по статье, p95, физический размер обоих файлов и истинно переданные из SQLite в Python BLOB-байты. Случай с несжатым резервом количественно отделяет стоимость декомпрессии. Одинаковая панель, порядок случайно чередуется, 15 повторов после прогрева. Проверим одноразовое создание баз. Эталонные ответы доступны и эксперимент служит описательной проверкой. Все старые артефакты остаются отдельно.

До запуска добавлены два режима для top-K. Режим local возвращает собственных победителей окон без пересечения и пересчитывает только остальные окна. Режим bound сначала сортирует окна по паре (−score, ord) исходного победителя и прекращает обход, когда следующая верхняя граница уже уступает лучшему допустимому варианту. Для произвольной ничьей сравнивается полная пара. Таблица локальных победителей оплачивается как отдельный физический файл. Первичный сильный контраст — skyline / top-64 + сжатые исходные оценки + bound. Для ясности кладём сведения об интервалах и логиты каждого окна отдельными BLOB, выводим объём переноса для реально прочитанных BLOB отдельно от прикладного ответа.

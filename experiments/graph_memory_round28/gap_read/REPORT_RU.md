# Чтение ближайших невидимых интервалов из адресуемой памяти

Адрес уже выбран прежним ранжировщиком R25. Вычитание видимых диапазонов выполняется в SQLite при подготовке интервального представления. Два индексных запроса выбирают по три ближайших пробела вокруг той же компоненты. У каждого возвращённого отрезка собственный адрес. Проверка заново читает из SQLite байты каждого выданного диапазона. [Протокол](PROTOCOL_RU.md) · [SQL и планы запросов](db-receipt.json) · [оператор](reader.py)

Подготовленная SQLite-база занимает 21,024,768 байт и хранит 2410 пар «контекст, поле», 6892 уже известных интервалов и 6291 пробелов. Данные этой реализации материализуют пробелы для каждого запроса. Компактность в системе с большой совместной памятью и стоимость инкрементальных обновлений здесь не измерены. Единица обращений в таблице — непустой возвращаемый диапазон или оплаченный адрес обычного контроля, не число физических чтений страниц. [SQL-план и объём](db-receipt.json) · [независимое воспроизведение](verified.json)

Попарная равная цена рассчитывается после получения двух длин. Онлайн-режим ограничивает оба решения одним потолком. Результаты характеризуют наличие координат исходного доказательства при неизменном выборе наблюдения. Это вторичное исследование ранее использованных тестов, и вывод о новом лучшем методе потребует независимого подтверждения и оценки использования памяти решателем.

На ISETrace переход от обычного чтения к SQL устраняет повторные символы и сокращает расход, хотя среднее число адресных диапазонов возрастает. При одинаковом лимите SQL покрывает больше ответов, чем окно строк, и тратит больше токенов. При равном фактическом расходе преимущество над ним исчезает. В переносе на MultiDoc2Dial предложение как структурная единица даёт четыре дополнительных полных ответа при сопоставимой длине, а обычное двустороннее чтение совпадает с SQL по полному покрытию во всех парах. Эти результаты указывают на эффективность устранения повторов как операции хранения и чтения, а улучшение качества зависит от контроля и режима учёта расходов.

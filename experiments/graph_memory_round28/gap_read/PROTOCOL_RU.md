# Оператор чтения пробелов в интервальной памяти

Проверяем одну операцию после принятого решения о чтении. Выбор вопроса, источника и связной компоненты видимой памяти полностью заимствуем у R25. На основной выборке 2000 запросов ISETrace из 1207 траекторий. Перенос — 661 вопрос MultiDoc2Dial. По одному и тому же адресу сравниваются три оператора без дообучения. Обе выборки уже использовались ранее, поэтому новые контрасты характеризуют эти данные. Они могут служить основанием для отдельного подтверждения на независимых данных.

1. Обычное двустороннее чтение — исходный оператор R25. При двух доступных направлениях квота 128+128, иначе 256 вправо. Для каждого запроса проверяются исходные диапазоны и их буквальная цена.
2. Окно соседних структурных единиц — по три ближайшие строки с новыми символами у каждой границы для истории инструментов ISETrace. Строки определяет splitlines(keepends=True) без разворачивания литеральных escape-последовательностей. Для естественного текста MultiDoc2Dial используются три предложения по тому же правилу Punkt, что в R27. Если граничная строка или предложение содержит неизвестное продолжение, оно считается. Из выбранных единиц вычитается полное множество видимых интервалов. Пересекающиеся остатки объединяются. От каждой границы возвращается максимум три ближайших непрерывных остатка.
3. SQL gap-read — выбранное поле представлено источником с координатами и таблицей уже видимых непересекающихся интервалов. Оконный SQL-запрос строит их точное дополнение. Индексные запросы возвращают не более трёх ближайших пробелов слева и трёх справа в том же поле, без ограничения длиной строки или предложения. Их координаты сверяются с независимым вычитанием множеств. Содержание каждого реально выданного отрезка дополнительно восстанавливается через SQLite substr и сравнивается с оригиналом. R23 marginal_open использовал оценку будущего повтора при выборе адреса. Здесь адрес и исходная компонента неизменны, оператор изменяет способ выполнения уже выбранного чтения. [Предыдущая модель выбора](../../graph_memory_round23/marginal_open/novelty.py) · [выбор компоненты и контроль](../../graph_memory_round25/directional_open/direction.py)

Оба новых оператора получают до трёх адресных отрезков на направление. Начальное распределение 128+128, неизрасходованная квота доступна другой стороне. Порядок выдачи левый, затем правый, внутри каждой стороны — по близости к границе. Один непустой отрезок оплачивает один заголовок. Пересчёт в WordPiece учитывает буквальные заголовки и разделяющие переводы строк, максимальная онлайн-цена 256. После двух онлайн-решений отдельно измеряется эффективность при строго равной физической цене. В каждой паре берётся меньшая из двух исходных длин, оба правила повторяются с этим лимитом до равенства фактических токенов, включая возможный взаимный отказ. Перенос не меняет параметры квоты, числа операций или выбора адреса.

**Первичная проверка** — на ISETrace доля вопросов с полным покрытием эталонного набора после gap-read минус та же доля после структурного окна при равной цене. Дополнительно фиксируем равную по цене пару с R25, онлайн-предел, частичное покрытие, долю повторно переданных символов, число дополнительных диапазонов, пустые ответы и реальные токены. Повторно считаем полное покрытие после добавления к первоначальной памяти. Интервалы bootstrap группируют вопросы по траектории ISETrace и диалогу MultiDoc2Dial. Число повторов 20 000. Проверка смены знака работает на уровне той же группы, до 100 000 случайных знаковых перестановок. Для процентов на двух корпусах используются разные знаменатели. Услуга SQLite оценивается отдельно от последующих действий решателя; токены выдачи не равны внутреннему дисковому вводу-выводу.

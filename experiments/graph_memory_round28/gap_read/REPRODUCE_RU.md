# Воспроизведение проверки

Ранжирование и первоначальные диапазоны берутся из подписанных файлов R25/directional_open. Для контрольного чтения требуются проекции ISETrace на D и MultiDoc2Dial из каталога R23/transfer. Программы используют тот же токенизатор, что и исходное исследование каждого корпуса. Для воспроизведения используются Python, NumPy, NLTK, tokenizers и встроенная SQLite. Видеоадаптер не участвует.

```powershell
$py='D:/CodexResearch/x20-isetrace-e5-gpu/venv/Scripts/python.exe'
& $py -B store.py
& $py -B freeze.py
& $py -B reader.py ise
& $py -B reader.py mdd
& $py -B score.py ise
& $py -B score.py mdd
& $py -B verify.py
& $py -B report.py
```

Рабочая база D:/CodexResearch/x20-r28-gap/intervals.sqlite атомарно публикуется после проверки integrity_check. План, версия SQLite и два плана индексного доступа сохранены в db-receipt.json. При повторном запуске существующая база проверяется по SHA-256. Для нового окружения сначала восстановите зависимости предыдущих раундов и запустите в отдельной копии каталога результатов. Время построения относится к конкретному устройству.

Оба процесса прогнозирования были запущены на CPU. Контроли и SQL-оператор фиксируют все самостоятельные решения и обе попарно равнозатратные выдачи до обращения к эталону. Для каждого действительно выданного интервала выполнен SQL-запрос substr по UTF-8 BLOB, затем данные сверены с подстрокой исходного Unicode-поля. Координаты задаются в Unicode-символах, стоимость чтения измеряется в токенах WordPiece. Верификатор восстанавливает буквальные заголовки, физически токенизирует выдачу, заново считает геометрические исходы, отсутствие повторов в новых операторах, равные платежи и основной интервал.

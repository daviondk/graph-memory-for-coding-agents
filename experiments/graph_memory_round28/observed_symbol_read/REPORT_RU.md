# Переход из наблюдаемого вызова к определению

Проверили, помогает ли один переход по имени вызванной функции внутри уже открытого файла получить больше исходных строк последующего изменения. При равной цене **14,60% против 14,17%** в основной панели и **20,75% против 20,75%** в переносе. Первичная разница в первом случае возникла на одной из 84 задач; во втором на всех 40 задачах значения совпали. Во всех 124 оцениваемых задачах простой переход к ближайшему вхождению того же слова дал ровно ту же полноту, что и переход к определению. Данные не устанавливают выигрыш от синтаксической связи.

## Как получены входы

В основной панели первый производственный .py задаётся фактической траекторией SWE-Explore, выбранной хешированием независимо от будущего изменения. Данные SWE-bench Verified сообщают исходную ревизию и описание. Из 500 задач 306 относятся к пяти допущенным репозиториям. После ограничений предметной области исключены 192 задачи, ещё для 11 не было записи SWE-Explore. Для остальных 103 сделаны прогнозы. В отдельной панели Loc-Bench из 560 задач 147 входят в новые для этой серии библиотеки. 20 исключены по теме, в 71 отсутствовал распознаваемый путь к производственному файлу, в восьми не подтвердился адрес на base_commit. Сохранены прогнозы 48 задач из 19 репозиториев. По сравнению с R27 и между панелями наборы репозиториев полностью различаются. До получения прогнозов из parquet физически запрашивались четыре колонки: repo, instance_id, base_commit и problem_statement. Патч стал доступен оценщику только после фиксации обеих выдач. [SWE-Explore](https://arxiv.org/abs/2606.07297), [SWE-bench Verified](https://huggingface.co/datasets/princeton-nlp/SWE-bench_Verified/tree/c104f840cc67f8b6eec6f759ebc8b2693d585d4a), [Loc-Bench](https://huggingface.co/datasets/czlll/Loc-Bench_V1/tree/c44cf3b74e07ca642cec841b471a9939907c12a7).

У всех методов первый видимый блок один: 16 последовательных строк с максимальным BM25 по issue, внутри уже выбранного файла. Дополнительное чтение открывает один адрес в том же исходнике и платит за заголовок и действительные токены, максимум 256 WordPiece. Код решения и поздняя версия файла не передаются. Графовая политика извлекает из наблюдаемого текста имена, за которыми следует скобка вызова, пересекает части имени с словами из issue и при наличии одноимённого определения прыгает на его начало. При неоднозначности берётся ближайшее невидимое определение, при отсутствии опоры повторяется BM25. Динамическое разрешение Python во время исполнения не имитируется. Обычные переходы по коду рассматривались, в частности, авторами LocAgent, где индексируются зависимости иерархического графа репозитория, а задачей служит ранжирование файлов и функций. Здесь испытание ограничено дополнительным чтением из одного файла. [LocAgent, ACL](https://aclanthology.org/2025.acl-long.426/).

В оценку вошли 84 задачи из пяти проектов. В выбранном файле оказались исходные измененные строки 60 задач. ## Цена и проверка реализации

Холодное создание полноценного указателя имён в уже прочитанном исходнике и поиск только требуемого поднабора измерены на CPU отдельно. Порядок четырёх реализаций сбалансирован, по четыре повтора на файл; это тёплые страницы в памяти, без сетевой или дисковой задержки. Измерения относятся к разрешению имени после готовых общих BM25 и первого блока.

| Запрос к резидентному тексту | Среднее время на задачу SWE, мс | Среднее время на задачу Loc, мс |
|---|---:|---:|
| Полностью построить указатель def/class | 3,419 | 3,692 |
| Точный лексер, прочитать исходник лишь по положительному запросу на имя | 0,864 | 1,237 |
| Обратиться к уже готовому отображению | 0,0014 | 0,0017 |
| Начало строк def/class по регулярному выражению, поиск только по спросу | 0,073 | 0,136 |

До фильтра существования определения запрос на разрешение адреса возникает лишь в 30/103 и 22/48 случаях. Точным ленивым поиском достаточно обработать логически 949 511 из 3 629 138 байт и 786 294 из 2 300 686 байт соответственно (нормализованный UTF-8; общая первоначальная BM25-индексация всего отобранного файла оплачивается отдельно). У всех 151 выходов варианты с точным лексером и готовым указателем совпали. Регулярное выражение также выбрало те же адреса на этом наборе. Вообще оно способно принять текст примера внутри многострочной строки за настоящее объявление. Для одного резидентного файла при положительном спросе медиана точного ленивого поиска была 1,73/2,09 мс против 1,76/2,01 мс на полноценную сборку. Основная экономия получается при полном пропуске чтения файла.

В реальном фрагменте не всегда видны открывающие скобки или начальные кавычки. Привилегированная офлайн-проверка с целым файлом обнаружила разницу в наборе видимых имён вызовов на 13/103 и 8/48 блоках. Основная политика использует только доступный фрагмент. Независимый аудит повторно разобрал первоначальный патч, восстановил каждую строку из символьных смещений полной токенизации файла, перепроверил 1364 адресованных выдачи и оба первичных парных интервала. Наборы, репозитории, предсказания, случаи совпадения с дешёвыми контролями и затраты сохранены в этом каталоге. Критерии и два первичных сравнения фиксировались до результатов, прочие интервалы описательны и не скорректированы на множественность.

Эти панели выделяют проблему оценки нового механизма. Доходящий до поиска определения триггер редок, а попадание в строки последующего изменения ещё реже различает переход по объявлению и по обычному слову. Покрытие принятого авторского изменения служит наблюдаемым прокси; для заявления об улучшении работы агента потребуется новая независимая выборка с большим числом различающихся исходов и конечной задачей.

# Воспроизведение

Исходные данные, проверенные SHA и токенизатор совпадают с R27/code_boundary. На Windows можно поместить этот каталог рядом с R27 и вызвать run.ps1. Входы скачиваются через существующий R27/fetch.ps1. Пути для диска D, зависимости numpy/pyarrow/tokenizers и точные ревизии приведены в common28.py и отчёте R27. Промежуточные базовые версии исходников и тексты issue живут в D:/CodexResearch/x20-r28-symbols. У каждой выбранной строки есть исходный URL, восстанавливаемый из repo, commit и path. SHA и размер файла сохранены в inputs.json.gz обеих панелей.

Очередность — подготовка обоих наборов, сохранение обоих прогнозов, вскрытие двух наборов отчётных исходов, физический опыт, аудит токенизации и независимая оценка. В predict28.py для общего BМ25 переиспользуется R27/predict.py; зафиксированные одинаковые версии зависимостей можно проверить по R27/environment.json. Результаты качества детерминированы. Метки времени отдельных вычислений внутри forecasts и физические микрозамеры меняют хеши при воспроизведении. Проверяйте официальный артефакт командой verify.py. Для повторного исполнения используйте рабочую копию исходников.

Дополнительное поле времени в каждом прогнозе отражает полный лексер, запущенный для всех контрольных методов. Для цены только query_call используйте четыре сбалансированные реализации в physical.py и physical-runs.json.gz. Главная метрика и генерация адресов не используют данные этого дополнительного измерения.

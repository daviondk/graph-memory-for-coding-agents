# Что сохранять, чтобы точно отозвать цитату

У читателя фиксированы вопрос, версия модели и уже прочитанная память. БД получает интервал источника, который больше нельзя использовать как цитату. Проверяем две самостоятельные операции. (1) У модели остаётся тот же исторический вход, но цитировать можно только за пределами интервала. (2) Удаляем все вхождения отозванного диапазона из входа, заново сериализуем оставшиеся записи и оцениваем ответ читателя. Реальные изменения версий файлов сюда не входят, отзыв вводится экспериментатором. Чтобы проверить добавление, отдельно воспроизводим реально переданные обе стороны из серии 26.

Выборка — два вопроса по фиксированному хешу из каждой из 48 статей SQuAD dev, 96 всего. Выбор сделан до анализа таких обновлений. Публикуем порядок и хеш исходного ридера. Локальный INT8 DistilBERT, те же ONNX CPU-параметры, окно 384 с перекрытием 128, ответ содержит максимум 30 токенов внутри одной непрерывной записи. Стартовые адреса и адреса при добавлении сверяем с предыдущим полным прогоном. Обновлённую память действительно пересчитываем моделью. Описываем технологии ограниченного экстрактивного читателя, перенос на свободную генерацию требует отдельной проверки.

**Гипотеза для зафиксированного входа.** Достаточно сохранить две короткие последовательности рекордов лучшего кандидата: при движении по правым концам цитат слева направо и по левым концам справа налево. После отзыва одного непрерывного диапазона остаются только кандидаты слева или справа от него. Проверяем точный выбор текста, адреса, балла и приоритета при равенствах относительно полного перебора. Конкурирующие варианты — один победитель, восемь и 64 лучших до отзыва, полные логиты ридера и полный список допустимых цитат. Учитываем размер компактных фиксированных записей в байтах до и после сжатия, реальное число резервных кандидатов. Дополнительно проверяем случайный отрезок на видимом участке, отрезок самого лучшего ответа и диапазон всей записи, содержащей ответ. Все три сценария фиксированы без эталонной разметки.

**Гипотеза для изменённого входа.** Если в действительности отозвать всю запись, прогноз по историческим оценкам иногда разойдётся с новым ответом модели. Для сохранения точности можно хранить максимум по каждому окну, использовать его только при совпадении входа, границ допустимых цитат и версии ридера, а для изменившихся окон действительно выполнить ONNX. Сравним с пересчётом каждого окна, с кэшем всех логитов и с переиспользованием только непрерывного префикса окон. Переназначение координат всегда выполняется по текущему источнику. При неизменном тензоре и новой карте недопустимых границ старый максимум может стать неверным. Отдельно фиксируем число физических инференсов, логически избегаемых вычислений, расхождения со старым фиксированным входом и долю доступного золота после отзыва. Измеряем размер производных представлений без общего исходного журнала. Выводы по знакомой выборке исследовательские.

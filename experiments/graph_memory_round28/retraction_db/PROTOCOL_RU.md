# Индекс допустимого ответа при отзыве интервала

## Постановка и дизайн до построения БД

На неизменном входе DistilBERT каждый ранее рассчитанный допустимый span имеет исходные полуоткрытые координаты [l,h), оценку float32 и порядковый номер. После запрета одного непустого интервала [a,b) допускаются h ≤ a или l ≥ b. Минимизируем пару (−score, ordinal). Сравниваем реализации одного запроса к сохранённым данным. Изменение входа нейросети относится к отдельному эксперименту R28/revoked_evidence.

Все 96 вопросов фиксирует capture-plan соседней работы. Точное равенство проверяем на каждом вопросе для трёх запретов из её evaluate_views.py (исходный победитель, целая запись, случайный отрезок с шириной победителя в другой доступной записи), для каждого показанного источникового интервала и для двух крайних границ (запрет всего и вне доступных координат). Эталон — независимое исчерпывающее перечисление допустимых пар длины 1–30 в одном сегменте каждого перекрывающегося окна, сортировка по float32 сумме и ord = (window × 384 + start) × 30 + end − start. Сравниваем сериализованные score, ord, l, h либо NULL. Первичный критерий корректности — 0 ошибок на полном наборе запросов. Совпадение с независимо запечатанными ответами соседнего исследования проверяем дополнительно.

Основной контроль — SQLite WITHOUT ROWID, физический порядок по (q, score DESC, ord), отбор первого допустимого SQL LIMIT 1 без внешней сортировки. Альтернативы — два компактных упорядоченных набора смен победителя, по концу слева и началу справа, и материализованный top-8/top-64 с переходом на полный индекс при промахе. Для prefix/suffix один SQL-запрос получает два возможных победителя и выбирает лучшего. Каждый индекс хранит полную полезную нагрузку и может вернуть ответ без обращения к отдельной таблице текстов. Для кэша фиксируем долю попаданий, размер одного кэша и суммарный с резервным индексом.

Для задержки выбираем первые 16 из 48 статей по SHA256('r28-db-timing-v1|' + title), оба вопроса каждой статьи, по три запрета. Минимум 15 прогретых повторов в чередующемся порядке, одинаковый SQL connection, один CPU worker, данные на D, конкурирующая нагрузка возможна. Первичный системный показатель — медианная задержка запроса для пары skyline / полный порядок. Дадим также p95, интервалы парной разницы медиан по запросу через кластерный бутстрэп по статьям и разбивку по сценариям. Повторения внутри запроса служат измерению времени. Оценим число проверенных кандидатов полного порядка, число вызовов SQLite и фактические сериализованные байты результата через определённый двоичный интерфейс с маркером NULL; сетевой передачи внутри процесса нет. Через dbstat или отдельные файлы SQLite измеряем число реально занятых страниц. Раздельно логируем перечисление и сортировку кандидатов, запись полного индекса, вычисление и запись frontiers и top-K. Ассоциация медиан с нагрузкой конкретной машины требует внешней проверки. Отсутствие выигрыша или ухудшение сохраняем. Источники — зафиксированный capture-plan, R26 directional_answers и исходный код R28/revoked_evidence. Код строит БД из числовых массивов без запуска команд из наблюдений.

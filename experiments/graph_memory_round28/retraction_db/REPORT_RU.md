# Хранение точного ответа после исключения одной цитаты

При фиксированных логитах читателя для каждого вопроса можно сохранить два списка смен лучшего ответа. Один описывает лучший span с концом левее заданной границы, второй — с началом правее другой границы. Два поиска по первичному ключу SQLite восстанавливают лучший допустимый ответ после запрета любого одного непустого интервала исходного текста. Поскольку допустимость эквивалентна дизъюнкции этих двух условий, максимум из двух частных максимумов точен при едином правиле разрешения ничьих. Разные вхождения одного источника в пересекающихся модельных окнах сохраняют собственные оценку и порядковый номер.

## Измерение

В 96 вопросах из 48 статей SQuAD v1.1 модель DistilBERT дала 6 677 914 допустимых вариантов. Перечисление независимо от разработки родительского оператора проходит по длинам span и векторизует позиции начала. Для каждого сравнения проверены битовое представление float32, идентификатор вхождения и две координаты либо NULL. Четыре SQL-схемы правильно решили 2 202 запроса каждая (8 808 сравнений). Сюда входят запреты победителя, всей содержащей его записи, случайного интервала, всех исходных видимых записей по очереди, полного диапазона и внешнего интервала. Для всех 288 основных запросов также совпали номер в отсортированном порядке и ответ независимой реализации соседнего исследования.

| Реализация | Строк SQLite | Размер отдельного файла, байт | Общий размер точного решения, байт | Переход к резервному индексу из 288 |
|---|---:|---:|---:|---:|
| Полный физический порядок по score и ord | 6 677 914 | 189 145 088 | 189 145 088 | 0 |
| Два списка смен лучшего ответа | 3 059 | 110 592 | 110 592 | 0 |
| Top-8 с полным резервным индексом | 768 | 28 672 | 189 173 760 | 112 |
| Top-64 с полным резервным индексом | 6 144 | 176 128 | 189 321 216 | 37 |

Сжатый точный индекс занимает в 1 710 раз меньше места относительно полной материализации всех span. Из 3 059 строк 1 402 относятся к левой границе и 1 657 к правой. Размеры включают все занятые страницы SQLite и схему. Отдельный top-8 без резерва дешевле, но в 38,9% основных запросов для него требовался резерв. Для top-64 доля составляет 12,8%. Метрика размера относится именно к индексу для этого семейства запросов. Частные массивы модели, исходные тексты и сама модель остаются отдельными статьями затрат. Возможное хранение логитов с повторным перечислением и повторный forward имеют другие издержки. При буквальном удалении текста из входа значения логитов могут меняться. Строгое равенство выше относится к исключению допустимых координат на исходных логитах.

## Задержка и построение

Прогретый тест включал 32 заранее выбранных вопроса из 16 статей, 3 запрета, 24 чередующихся повторения каждой из 4 схем и всего 9 216 вызовов. Каждая таблица доступна через один локальный SQLite connection (Python 3.14, SQLite 3.50.4). Время охватывает запрос и сериализацию результата. В таблице приведены квантили по 96 индивидуальным медианам. Доверительные интервалы построены 10 000 кластерными выборками статей.

| Реализация | p50, мкс | p95, мкс |
|---|---:|---:|
| Полный физический порядок | 19,40 | 23,31 |
| Два списка смен победителя | 22,05 | 22,48 |
| Top-8 с полным резервом | 18,35 | 41,91 |
| Top-64 с полным резервом | 18,90 | 44,78 |

Сжатый индекс повышает медианную задержку в 1,137 раза, 95% интервал [1,127; 1,145]. Медиана парной разницы составляет +2,625 мкс [2,50; 2,70]. Обычный полный индекс проверяет в среднем 47,8 кандидата, медиана 3, максимум 1 266. При случайном запрете исходный победитель оказывался допустимым во всех 96 вопросах. При исключении всей записи обычный индекс проверял медианно 23 кандидата против одного при случайном запрете. По плану SQLite для сжатого индекса доступ к двум таблицам по ключам дополнительно сопровождается сортировкой двух частичных ответов. Вероятные вклады этих факторов не разложены отдельным экспериментом. Внешнюю воспроизводимость латентности ограничивают один диск, прогретое состояние и фоновая нагрузка. Измерений холодного дискового I/O или сетевых байтов здесь нет.

Один непустой результат занимает 17 реально сериализованных байт (маркер, float32 и три целых), пустой — 1 байт. Для 288 основных запросов все реализации вернули непустые ответы на 4 896 байт прикладного результата. Обращений к SQLite соответственно 288, 288, 400 и 325. При кодировании каждого промежуточного ответа NULL однобайтовым маркером получились бы ещё 112 и 37 байт у top-K. Глубина прохода полного индекса отражает логическое число рассмотренных кандидатов, а не переданные байты или дисковые страницы.

Общее один раз измеренное перечисление и сортировка заняли 14,44 с. Последующая запись полного индекса заняла 8,93 с. Для двух списков подготовка заняла 3,52 с, запись 0,45 с. Для top-8/top-64 дополнительная запись заняла по 0,19/0,20 с. Каждая реализация получала одни и те же отсортированные данные, коммиты выполнялись для каждого вопроса. Стоимость вывода нейросети вынесена в исходный эксперимент. Здесь показан обмен памяти на задержку для одного строго определённого оператора. Изменение качества ответов живого агента этой реализацией отдельно не проверялось.

Четыре проверенные через SQLite integrity_check физические БД сохраняются в `D:/CodexResearch/x20-r28-retraction-db/<sha256 plan.json>/`.

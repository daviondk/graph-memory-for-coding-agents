# Память для следующей исполняемой правки

**Окончательные результаты авторских тестов получены с исправленной областью видимости тестового окружения.** Первоначальная оболочка скрывала вспомогательные функции encode_shift и encode_cyclic в двух задачах. Для всех 777 исходов повторно оценены уже зафиксированные ответы. Все 111 эталонов проходят авторские тесты, все 111 неисправных исходников их проваливают. Первоначальные оценки сохранены для аудита. Подробности исправления и проверки неизменности вспомогательных функций находятся в NAMESPACE_CORRECTION.md и helper_integrity.json.

Подлинные исправления генерировала локальная Qwen3.8-27B, файл GGUF UD-Q4_K_M, RTX 3090. После одного физического чтения исходного файла модель указывала подозрительную строку. Инструмент действительно читал соседние пять строк и запускал опубликованные примеры. Введённая исследователем граница обнуляла историю разговора. Каждый новый reader получал описание задачи и запись одного из пяти форматов. Можно было один раз запросить целиком текущий файл и затем вернуть одну замену диапазона строк. Применённые исправления оценены полными авторскими тестами HumanEvalPack Python.

Выборка зафиксирована до генерации. Из 164 задач 111 удовлетворили условиям по размеру, области и разрешённому синтаксису. Первые 48 по фиксированному хешу образовали основную выборку. Проверка на всех оставшихся 63 зарегистрирована до открытия результатов первых 48. Обе части происходят из одного публичного набора. Декодирование детерминированное, одна траектория каждого условия.

Новый способ начинал с полной наблюдавшейся инструкции Python, содержащей указанную моделью строку. Затем добавлялись управляющие заголовки и ближайшие строки, пока представление помещалось в 80 токенов. Главный контроль компактно восстанавливал один непрерывный участок вокруг той же строки. У всех ограниченных способов верхняя граница идентична, фактическое заполнение различается. Контроль последних наблюдений включал текст последнего чтения и результат примеров. При пустой записи можно было вновь прочитать файл. Полный исходник задавал ориентир при снятом ограничении объёма памяти.

## Вычисления и границы сравнения

С учётом общего вызова для выбора места чтения выполнено 828 различных нативных запросов. Учтено 326 180 входных и 29 644 выходных токенов. Табличные оценки по политикам считают логическую цену каждой независимо развёрнутой ветви. Идентичные запросы в эксперименте получали один завершённый ответ.

Пары сравнивались по полным авторским тестам. Функции исполнялись в отдельных процессах с ограничением времени и памяти. Использован ограниченный Python AST. Список разрешённых операций зафиксирован до просмотра ответов. Отклонение синтаксиса среды, неправильный JSON, пустая замена и неверные тестовые исходы разнесены в данных. Ограничение на одну замену и искусственная пауза отличаются от исходного протокола свободной генерации HumanEvalFix. Потенциальное знакомство модели с публичными задачами неизвестно. Проекты SWE и более длинные сессии требуют отдельного исполнимого сравнения.

## Проверка

verify.py проверяет манифесты, точное соответствие запросов и ответов, цену повторных чтений, SHA физически отредактированных файлов и парные статистики. Опции --execute --tokens повторно исполняют тесты и пересчитывают токенный бюджет. Доступ к сети и новая генерация не требуются. Native server logs, аппаратные сведения, модель и хеши бинарных файлов лежат в runtime. Сверка с оригинальной постановкой и ссылки находятся в HARNESS.md.

## Чувствительность HumanEval+ к лимиту исполнения

При независимом повторении физического теста prime_fib одна и та же программа получила pass после прежнего timeout. Оценка с пятисекундным лимитом зависит от нагрузки машины. Все опубликованные выше первичные знаменатели и метки сохранены. Дополнительно исключены задачи, на которых хотя бы один метод или контроль получил timeout в первоначальном расширенном тесте. На первой выборке это даёт 40 против 40 из 45. На переносе получено 45 против 43 из 56, 5 выигрышей и 3 потери, разность +3,57 п.п., интервал [−7,14, +14,29], p=0,727. Критерий выбирает задачи по наблюдавшемуся исходу и служит описательной проверкой. Все пообъектные повторы хранятся в evalplus_replay.json.gz и transfer/evalplus_replay.json.gz, итоги — в evalplus_timing_audit.json.

В полном повторном исполнении источники и статусы совпали для 406 из 407 уникальных программ. Для prime_fib в переносе изменился исход только у пустой памяти: 50 из 63 в первой серии и 51 из 63 при повторе. У инструкции с заголовками и непрерывного участка осталось по 47 из 63.

Команда python -B verify_final.py проверяет окончательные метки и статистики по двум наборам тестов. Флаг --execute повторяет обе серии физических тестов и сообщает каждое расхождение из-за таймаута, а --tokens пересчитывает бюджеты. Описание зависимостей находится в REPRODUCE.md.

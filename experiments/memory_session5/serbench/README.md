# SERBench • источники и воспроизведение
Данные и официальный scorer выпустили Zhexi Feng, Ruiyi Zhang, Yongbo Yang и Pengtao Xie. Проект: https://github.com/LordTARN1SHED/SERBench/tree/8c27a88e48dcbcd4a5745573c95937a4740f4406/ . Статья: https://arxiv.org/abs/2609.20050 . Числа здесь получены нашими методами на Cal500, публичной машинной разметке. Часть Test500 доступна для вывода предсказаний, метки закрыты. Наши 500 результатов Test500 прошли проверку структуры. Официальное оценивание требует публичного репозитория и согласия на публикацию.
В архиве оригинальный SDK и лицензии upstream, оригинальные публичные метки Cal500, наши числовые результаты и проекции идентификаторов. Входные файлы с текстами задач, кусков кода и бинарные веса остаются на D в рабочей папке. fetch.py получает точно те же версии обоих inference splits и сверяет Git blob hashes. Свойства необходимой среды — Python 3.14 с numpy, requests, tokenizers; dense_encode.py использовал вторую установленную среду CUDA из dense_runtime.json. Для воспроизведения применения моделей к исходным текстам запустить подкаталог как набор скриптов в порядке fetch.py, train.py, grade.py, trace.py, trace_grade.py, source_cost.py и cap.py. Для BGE — fetch_dense.py, dense_prepare.py, dense_encode.py (вариант CUDA), dense_grade.py. Порядок исходных экспериментов и момент доступа к разметке зафиксированы в отдельных PROTOCOL. Официальный SDK отвечает за оценку полных упорядоченных выдач. Скрипты обучения используют сертификаты только для репозиториев обучающей части и не подбирают порог по отложенным репозиториям.
Для независимой проверки результатов из архива (без GPU и сети) выполнить:
```powershell
python -B grade.py --verify
python -B trace_grade.py --verify
python -B dense_grade.py --verify
```
Последняя команда восстанавливает выдачу из сохранённых реальных эмбеддингов. Стоимость входной памяти и длина возвращённого исходного кода являются разными метриками. Исходный файл test500_predictions.jsonl следует лимиту 8 элементов. Для 9 состояний его восемь элементов превышают 6144 токена при счёте нативным токенизатором Qwen с текстом пути; cap.py независимо сохраняет суффикс-усечённый файл test500_cap6144.jsonl. Порядок до границы остаётся прежним. Включение или исключение этих состояний при локальной оценке Cal500 не применялось. Сравнивать число Cal500 с процентом закрытого Test500 из статьи напрямую нельзя.

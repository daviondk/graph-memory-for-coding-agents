# Живая правка Qwen после сжатия памяти

В 32 задачах из 12 репозиториев Qwen3.8-27B получила описание проблемы, путь к ранее увиденному Python-файлу и один из двух пакетов памяти с лимитом 512 токенов. Простое правило показывало конец последних актуальных наблюдений. Второе правило подбирало соседние страницы по вероятности целиком поместить в память диапазон будущей замены. Пары содержали одну и ту же публичную задачу и тот же путь. Менялся только текст выдачи памяти. Все 64 запроса различались. Модель сама прописывала обе строки замены, могла вернуть пустой объект при нехватке сведений. До конца генерации ей были недоступны последующие действия и эталонный исходник.

Для 160 отобранных по хешу задач нашлось 150 подходящих границ с видимым производственным файлом. В 136 случаях файл удалось получить по конкретному коммиту ветки задачи и подтвердить его наблюдавшиеся строки. Остальные 14 исключены по заранее заданному правилу доступности. Для первых 32 доступных случаев запечатан текст заданий. Могли остаться побочные эффекты ранее выполненных неучтённых shell-команд вне просмотренных строк. Исторические тесты не запускались. Физическая проверка применяет новый ответ модели к подтверждённому локальному снимку.

| Конечная точка | Совместные страницы | Последние строки | Парные выигрыши / проигрыши |
|---|---:|---:|---:|
| Уникальная применимая замена, меняющая AST с сохранением синтаксиса | 20/32 | 17/32 | 5 / 2 |
| Старая подстрока встречается в файле один раз | 23/32 | 22/32 | 3 / 2 |
| Указаны обе строки и допустимый путь | 26/32 | 24/32 | 2 / 0 |
| После замены полностью восстановлено исходное дерево изменённого файла | 0/25 | 0/25 | 0 / 0 |
| Обе строки полностью совпали со следующей принятой исторической заменой в том же файле | 0/9 | 0/9 | 0 / 0 |

Парная разность основной конечной точки равна +9,38 п.п., 95% интервал при bootstrap по 12 репозиториям [0,00; +21,43]. В дополнительной проверке точный двусторонний тест McNemar для 5 и 2 несовпадающих направлений даёт p=0,453. Контекст позволяет сгенерировать применимую замену, однако это слабый критерий качества. Из семи файлов, уже совпадавших с базовым деревом, два получили изменение в первом варианте и три во втором. Дословное совпадение со следующим историческим действием слишком строго для оценки альтернативных корректных решений.

Когда стало известно, что точных восстановлений исходного AST нет, мы дополнительно оценили расстояние редактирования между сериализованными деревьями. Учитывается порядок узлов, полей, списков и скалярных значений, опускаются координаты строк. Для 25 изначально различающихся файлов после применения совместной памяти дерево приблизилось к базовому в 3 случаях, удалилось в 12, в 10 расстояние сохранилось. Для последних строк соответствующие числа 2, 10, 13. Неприменимые правки оставляют расстояние до эталона прежним. Метрика измеряет сходство структуры и не определяет семантическую правильность. В этом пилоте прикладного преимущества в исправлении задач не установлено. [Полная таблица этого дополнительного анализа](distance.json)

Запуск на NVIDIA RTX 3090, локальный сервер llama.cpp, квантование UD-Q4_K_M, контекст 8 192, температура 0, seed 17112026, режим без thinking, максимум 320 выходных токенов. Число входных токенов за 32 вызова составило 29 899 против 29 981, выходных 4 551 против 4 462, сумма 34 450 против 34 443. Длительность запросов 147,4 и 145,3 с. По ограничению длины завершились 4 и 1 ответы соответственно. В памяти в среднем передано 479,09 против 481,66 токена. Все 64 нативных ответа, их счетчики и связывающие SHA сверены с независимо восстановленной выдачей из исторических префиксов.

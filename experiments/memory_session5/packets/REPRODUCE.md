# Проверка пакета

В папке packets находятся входные траектории в виде безопасной текстовой проекции, замороженные параметры, решения на каждой границе, отделённые от них оценки, входы и подлинные ответы модели в живой проверке. Каждая строка журнала содержит id задачи, причём расположение исходного сообщения можно проверить по полям shard, row, traj и messages_sha. Работайте из этой папки. Следующие команды читают сохранённые данные без обращения к сети, исходному диску или локальной модели.

```powershell
python -B verify.py
python -B all_costs.py
python -B live_score.py --verify
python -B live_audit.py
python -B live_distance.py
```

Первая проверка использует стандартную библиотеку Python 3.10+ и воспроизводит покрытие для всех вариантов, согласованность сохранённых решений с оценками, разбиение, допустимость координат и бюджетов. Проверка живых ответов воспроизводит физическую замену текста в локальном временном файле и его Python AST. Версия Python для сверки сериализованного AST исходной оценки — 3.14.4. Не выполняются инструкции сгенерированного или исходного кода. Порядок методов и числа побед подсчитываются заново. Диагностика стоимости на CPU приведена в cpu_cost.json. Данные всех вызовов модели и действительные входные и выходные токены лежат в live/capsule_calls/calls.

Для полной проверки стоимости и эксперимента C нужен пакет `tokenizers==0.22.2`. Токенизатор Qwen входит в архив. Проверяется получившаяся сериализованная выдача вплоть до текстовых заголовков. Контроль C воспроизводит на каждом шаге и запрошенные лимиты, и остатки, и запечатанные решения, перепроверяет метрики и доверительные интервалы.

```powershell
python -B verify.py --tokens
python -B allocation_audit.py --tokens
```

Для необязательной сверки с оригиналом скачайте **восемь** файлов tool-*-of-00008.parquet из указанной редакции Hugging Face. Пути, размеры и контрольные суммы перечислены в shards.json. Потребуются Python ≥3.11, `requests` и `pyarrow`. Затем передайте программе каталог с этими восемью файлами. Перед чтением сверяется SHA-256 всего файла, затем сравниваются все объекты публичной проекции для отобранных координат, включая четыре исключённых предметным фильтром. Процедура не исполняет наблюдения и инструменты исторического агента. [Исходные данные на фиксированной ревизии](https://huggingface.co/datasets/SWE-bench/SWE-smith-trajectories/tree/08e109b4a59eaeebf80e4675cd125d42e7ac99a4/data)

```powershell
python -B verify_public_sources.py D:/path/to/parquet
```

Чтобы независимо учить модели и пересчитывать решения, создайте отдельную рабочую копию packets. Команды ниже перезаписывают производные результаты **в рабочей копии**. Для обучения A/B также нужен NumPy. Идентичность точных байтов gzip после повторной записи может зависеть от времени и версии zlib. Для проверки запечатанной опубликованной серии используйте первые команды над исходным архивом. Повторное обучение проверяется по содержанию, выбору фрагментов и итоговым метрикам.

```powershell
python -B pipeline.py fit
python -B pipeline.py predict
python -B pipeline.py score
python -B analyze.py
python -B transfer_run.py
python -B transfer_analyze.py
python -B allocation_run.py
```

Для новой живой генерации используются reader_inputs.json и сервер из соседнего эксперимента live в полном комплекте исследования. Точный JSON нативного запроса и ответа и настройки модели доступны в каждом calls/*.json.gz. Повторный локальный запуск полезен для нового seed или решателя. Оценка первичного опыта использует ранее замороженный набор из 64 нативных ответов. Имена программ и контрольных точек сохранены в live/live_input_lock.json, live/grader_lock.json и live/capsule_calls/prediction_lock.json.

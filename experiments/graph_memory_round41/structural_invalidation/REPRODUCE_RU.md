# Воспроизведение

Автономная проверка агрегатов, сохранённых ранжирований, исходов и действительных нативных SQL-результатов выполняется стандартной библиотекой Python.

```powershell
python -B verify.py
```

Полный пересчёт использует 319 подписанных локальных файлов Parquet Handoff Debt и отфильтрованные кандидаты с защищённым префиксом из R40/guarded_updates. Для AST используется только стандартная библиотека. Исходный файл и две версии загружаются во время повторного чтения данных, в записываемых результатах нет реализаций функций или их имён. Валидатор SQL запускается в WSL на диске D и импортирует проверенный исходный MemTrace через предыдущую репликацию с [инструкцией проверки SHA](../../graph_memory_round40/memtrace_reference/REPRODUCE_RU.md). Для нового расчёта использовать отдельную рабочую копию: результаты измерений времени меняются между запусками.

```powershell
$runner = 'D:/CodexResearch/x20-isetrace-e5-gpu/venv/Scripts/python.exe'
& $runner -B predict.py
& $runner -B audit.py
& $runner -B analyze.py
& $runner -B prepare_sql.py
wsl -d CodexX20MSR --cd /mnt/d/CodexResearch/x20-bench-workspace/work/graph_memory_round41/structural_invalidation -- /usr/bin/python3 -B -u sql.py
& $runner -B verify.py
```

`predictions.json.gz` фиксирует исходные и обновлённые идентификаторы четырёх пакетов, новые координаты каждого оставшегося блока изменённого файла и причины отказов. `audit.json.gz` содержит пересчитанные из источника поблочные счётчики. `results.json` содержит все страты, интервалы, байты, времена и распределение причин. Видимый файл при обычном запросе является лишь срезом, полные служебные версии используются в этом конкретном сценарии с равными доступными источниками для политик. Дополнительный эксперимент с 64 SQLite выполняется отдельным процессом и сохраняет фактические закрытые идентификаторы и количество рёбер.

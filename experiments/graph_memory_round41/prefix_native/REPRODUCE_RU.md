## Инференс и оценка по источникам

```powershell
$runner = 'D:/CodexResearch/x20-isetrace-e5-gpu/venv/Scripts/python.exe'
& $runner -B native.py --quick
python -B packets.py --quick
& $runner -B native.py

& $runner -B terminal_numeric.py
& $runner -B grade.py
& $runner -B analyze.py
python -B control_report.py

```

При повторном запуске `native.py` сверяет уже зафиксированные фрагменты. Для полной реплики в отдельной копии каталога сохраните исходные скрипты, `registration.json` и протокол, не переносите выходные `forecast-*` и `quick-*`. Отдельные фрагменты можно пересчитать с `--shards 0 1`. Временные поля в файлах фиксации новой реплики зависят от машины. Для сверки по содержимому сравните SHA сжатых перестановок и SHA `*-packets.json.gz`, а также первичные исходы по каждому вопросу. При другой версии CPU-библиотек возможны расхождения в близких оценках. Последующий контроль показывает их позиции и влияние на пакет. В прочитанных архивах хранятся данные; исполняются только исследовательские скрипты.

* `register.py` один раз создал `registration.json` перед нативным прогоном. В нём хеши десяти моделей и десяти конечных подписанных перестановок, проверенных по R22, исходного разбиения, расписания срезов и причинных прогнозов R39. Технические 48 траекторий определены по SHA идентификаторов. Первые три образуют короткий Smoke-тест. Состав 901 отложенного вопроса новый читатель получает только при оценке.
* `native.py` разбирает исходные траектории, останавливается на наблюдаемой границе, создаёт отдельно валидированный объект `CanonicalTrajectory` с нейтральной служебной оболочкой и передаёт его `build_provenance_graph`. Авторская нарезка источников — 504 токена с перекрытием 64. Все узлы и рёбра проверяются по идентификаторам исходных событий. Для актуальных текстов и запроса используется `fit.features` и тот же FP32-кеш выбранного seed. Каждый запрос и каждая модель проходят `tensorize_provenance_ranking_task`, авторскую пакетизацию и настоящий CPU forward. После сортировки по оценке и идентификатору его результат переводится в общие индексы для оценщика.
* `packets.py` читает сохранённые перестановки, собирает строгий пакет и first-fit, повторяет упаковку после ограничения опубликованного конечного ранга и проверяет конечную техническую панель. Итоговый `forecast-seal.json` предшествует чтению эталонных интервалов новым оценщиком.
* `hybrids.py` восстанавливает причинные полезности R39 и собирает два способа упаковки нативного wo-порядка. Отдельная предварительная регистрация `hybrid-registration.json` записана командой `hybrids.py --register` до получения новых исходов. Каждый seed фиксируется отдельно; оценщик требует все пять фиксаций. Для каждой строки сверяется результат R39 DP на порядке R35. Конечная техническая панель дополнительно проверяется по R39/hybrid_controls.
* `prefix_audit.py` независимо вырезает ещё не предъявленные сообщения на уровне исходной записи, до подачи в SDK, и сравнивает хеши построенных графов. Для 48 конечных состояний также сверяются все узлы и рёбра с опубликованными физическими графами. `verify.py` сопоставляет эту реплику со входами каждого исполненного forward.
* `terminal_numeric.py` разбирает конечные случаи, где отличается первая пятёрка или пакет. Для каждой инверсии из повторного нативного CPU forward сохраняется численная разность оценок. Публичные конечные GPU-артефакты хранят перестановку, поэтому эта величина выражает разрыв между **двумя CPU-оценками**.
* `grade.py` сверяет авторскую span-метрику по отдельным спискам с независимой суммой неперекрывающихся атомарных интервалов R34. `analyze.py` сохраняет FS, долю покрытых символов, число переданных токенов, разности и парные интервалы по 10 000 перевыборок траекторий и пяти общих seed. `outcomes.json.gz` содержит отдельное наблюдение на каждый вопрос, модель и способ упаковки.

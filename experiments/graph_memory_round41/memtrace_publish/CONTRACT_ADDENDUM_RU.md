# Проверка контракта записи перед полной панелью

При техническом smoke на первом предопределённом примере с фрагментом 48 байтов исходный файл был закрыт. Контроль без новой записи выдал EMPTY. При записи EvidenceDraft с Authority.DERIVED фактический PageStore отклонил закрытие страницы на ребре SUPPORTS. Вызов native.py до исправления подготовки адаптера возвращал ValueError с текстом «DERIVED is not allowed for SUPPORTS». Код передавал действительный milestone_id внутрь события. В исходном проекторе оно порождает связь с текущей вехой плана. Начальная постановка о выдаче DERIVED при такой привязке требует явной проверки совместимости.

До полной панели фиксируем следующие ветви. В исходной ветви DERIVED с привязанным событием документируем фактическое отклонение операции на всех положительных случаях и отсутствие попыток при отказе адаптера. Для независимой проверки развязываем два поля. Первая допускаемая альтернативная операция — EvidenceDraft с Authority.DERIVED в событии без milestone_id; группа, задача и текущая веха запроса сохраняются. Контроль безусловного копирования использует тот же режим. Вторая операция — исходная привязка к вехе и Authority.ASSERTED для факта о том, что внешний проверяющий удостоверил перенос. Происхождение заключения записывается в содержании. Отдельно сообщаем возможность восстановления в каждом режиме и все иные сбои. Факт, что исходная программа MemTrace разрешает материализацию подходящего целого EvidenceDraft, сам по себе не удостоверяет истинность копии.

Все границы интервалов, варианты подмены данных, число состояний и критерий проверки блоков из первого протокола сохраняются. Этой поправкой не оцениваем производительность или поведение решения задач.

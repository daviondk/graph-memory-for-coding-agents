# Независимая репликация фиксированного двустороннего чтения

Основной показатель фиксируем до загрузки и оценивания нового массива. Сравниваем оба края 128+128 с заранее выбранным сильным чтением только вправо 256, при СТРОГО одинаковой суммарной фактической оплате каждого запроса. Те же токенизатор, правый BM25-компонент, упорядочение блоков и обращение R25. Применяем симметричную процедуру равной цены R25: начинаем с меньшего из двух реальных расходов неизменных решений, если нужна обрезка — сохраняем заранее заданное распределение квоты, ретокенизируем, уменьшаем лимит до точного совпадения либо отказа. Обе стороны сохраняют первоначальный текст. Вариант 128+128 оплачивает два заголовка и обращается к двум диапазонам одного поля. Выравнивание использует длины обоих ответов после принятия исходных решений и служит симметричной оценкой эффективности, отдельно сообщаем достижимый онлайн исход при одном лимите 256. Сохраняем обычный правый контроль, строгий левый, доступный левый с переходом вправо при l=0, адаптивный лексический R25 и двусторонний; других настроек не добавляем.

**Независимость статей и вопросов.** Новый материал — официальный train SQuAD v1.1. На этой части не обучали и не выбирали параметры алгоритма. Базовый retriever — фиксированный BM25, статистики вычисляются в текущей известной статье. Текстовые ответы из будущего запроса в память не записываются. Прежняя dev-часть используется только для исключения совпадений до выбора. Нормализация строки: NFKC, casefold, последовательности whitespace → один пробел и strip; для заголовка символ подчёркивания считаем пробелом. Исключаем статью при совпадении нормализованного заголовка, хеша полного нормализованного текста или любого нормализованного абзаца из ≥128 символов с dev либо с уже принятой train-статьёй. Обходим train по нормализованному заголовку, затем по SHA нормализованного текста. Во всех оставшихся статьях отбрасываем ID и нормализованные формулировки, встречающиеся где-либо в dev, устраняем дубли ID/формулировок между оставшимися train-вопросами. При дубле оставляем первый по SHA-256 от `replication-v1/` + ID, затем по заголовку. В каждой статье выбираем до 12 первых вопросов в том же хеш-порядке. Публикуем точные счётчики и контрольные суммы, фиксируем статьи, вопросы и начальные проекции до соединения с золотыми координатами. При отсутствии допустимого gold вопрос отражается как проблема разметки, не заменяем его. Для альтернативных аннотаций успех означает видимость хотя бы одного целого официального диапазона. Метрики по реально существующим точным диапазонам; отдельно показываем число несовпадающих с источником аннотаций.

**Анализ.** На новом массиве ровно один первичный контраст both минус right при совпадающем расходе. Единица ресэмплинга — статья целиком, статистика — разность долей у всех вопросов; 20 000 парных percentile bootstrap, двусторонний кластерный sign-flip точный при ≤20 ненулевых группах, иначе 100 000 рандомизаций с +1. Публикуем числа приобретённых и потерянных случаев, информативных статей, 95% ДИ, частоту наличия обеих сторон и результаты на всём наборе и условном подмножестве l>0. Вторичные — накопленная доля самого полного допустимого диапазона, расположение затрат, дополнительные результаты при общем потолке, лучший контроль без обучения. Здесь ни графовый энкодер, ни LLM не участвуют. Сведения об исходных текстах в предобучении возможного будущего LLM на retrieval-опыт не влияют.

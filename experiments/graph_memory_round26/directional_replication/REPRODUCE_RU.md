# Воспроизведение на CPU

Официальные неизменённые train-v1.1.json и dev-v1.1.json должны находиться в D:/CodexResearch/x20-r25-squad/. Скрипт сверяет их контрольные суммы. Используются исходные модули R25/directional_open и тот же локальный WordPiece-токенизатор ISETrace. Требуются Python с NumPy и tokenizers; локальная GPU и платный API не используются. [Официальный train](https://rajpurkar.github.io/SQuAD-explorer/dataset/train-v1.1.json) · [Официальный dev](https://rajpurkar.github.io/SQuAD-explorer/dataset/dev-v1.1.json)

Запустить `./run.ps1`. `rep_io.py` фиксирует протокол, `cohort.py` исключает пересечения до выбора вопросов. `collect.py choices` сохраняет видимые исходные диапазоны и выбранные компоненты; `collect.py read` возвращает настоящие интервалы всех политик от зафиксированных границ. Обе стадии используют по два CPU-процесса и публикуют хеши восьми шардов. Строгую первичную статистику пересчитывает `evaluate.py`. `strong.py` выполняет отдельно зарегистрированный последующий контроль с учётом исходов основного этапа. Входной JSON изначально содержит аннотации. Код проекции в стадиях cohort/choices читает из структур вопроса только его ID и текст; эталонные диапазоны используются в evaluate/verify после фиксации действий.

`verify_replication.py` повторно проверяет отбор, исходные данные, реальные строки и расходы и использует независимый алгоритм покрытия. Сведения для аудита и все контрольные суммы находятся в `verified.json` и `manifest.json`. Крупные исходные файлы датасета в архив не включены. Строгий фактический бюджет сравнивает пару после выдачи, один общий верхний лимит 256 доступен без информации о второй политике.

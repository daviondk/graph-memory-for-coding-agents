# Как воспроизвести сравнение

1. Подготовить официальный dev-v1.1.json, модели из R3, основной WordPiece из R25 и запечатанные squad-choices / squad-opened из R25/directional_open. Скрипт prepare.py проверяет SHA256, извлекает вопросы и объединённый текст статей и создаёт локальную копию без аннотаций. Модель находится в graph_memory_round3/qa/models/reader, перечень весов и публичных ссылок — в graph_memory_round3/qa/models.json. Кэши и буквальные статьи хранятся в D:/CodexResearch/x20-r26-squad-qa. [Данные Stanford](https://rajpurkar.github.io/SQuAD-explorer/dataset/dev-v1.1.json) · [дистиллированные веса](https://huggingface.co/Xenova/distilbert-base-cased-distilled-squad/tree/bdbb0a5e9c617c3c7ea9f3cbaf2be3ad871bcd7d)
2. Из этой папки исполнить prepare.py и audit_inputs.py. Независимая функция проверки восстанавливает все 2 304 сериализованные строки из очищенной копии, сверяет принадлежность фрагмента изначально выбранной стороне, оба токенизатора и фактические координаты. Пересчёт выборки вопросов возможен через dataset.py в серии R25.
3. Запустить launch.py. Эта оболочка запускает infer.py и повторяет атомарную запись, если Windows временно удерживает файл статуса. Использованы Python 3.12.13, tokenizers 0.21.4, ONNX Runtime 1.23.2 c CPUExecutionProvider, два intra-op потока и один inter-op. Прогресс после каждого вопроса сохраняется в progress.json. Приватный кэш разделён по хешу входов, кода и конфигурации. Все запечатанные ответы представлены началом и концом в исходной статье и SHA256 строки ответа в predictions.json.gz. Буквальный текст можно восстановить из публичного dev. Внутри запроса одинаковые последовательности входных ID модели рассчитываются один раз. Для всех условий используется один детерминированный декодер с общим ограничением в 30 токенов и проверкой допустимой непрерывности.
4. Сохранить исходный официальный скрипт AI2 как D:/CodexResearch/x20-r26-squad-qa/official.py, сверить SHA256 f5a673dbbd173e29e9ea38f1b2091d883583b77b3a4c17144b223fb0f2f9bd09 и после появления forecast-seal.json запустить score.py. Его функции также перепроверяют значение EM и F1 на всех вопросах одним стандартным вызовом официального оценщика. [Зафиксированная версия официального оценщика](https://github.com/allenai/bi-att-flow/blob/498c8026d92a8bcf0286e2d216d092d444d02d76/squad/evaluate-v1.1.py)

В каждом сравнении цена строчки с координатой входит в нативный токен-бюджет ридера. Учитываются также повторы в перекрывающихся окнах, специальная разметка и токены повторяемого вопроса. Цена у систем хранения и число отдельных диапазонов — самостоятельные характеристики. Фактических запросов в сетевую СУБД в этом опыте нет: проверяются реальные чтения публичного документа по сохранённым смещениям, обработка текста локальной моделью и качество ответа.

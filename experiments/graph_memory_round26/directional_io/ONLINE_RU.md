# Стоимость полного чтения, когда известны только границы видимой памяти

Основной микротест получил уже разрешённые конечные координаты. Фиксируем дополнительный опыт с теми же 288 строками. Сервису доступны только идентификатор поля, левая и правая границы показанной компоненты, длина поля и лимиты 128+128 либо 256. Токенизатор тот же, адреса сформированы до открытия. Измеряем единый SELECT с двумя локальными substr и два отдельных SELECT, наряду с получением всего TEXT одним индексированным SELECT и одинарным правым расширением. Начальное окно для локального SQL — до 2 048 символов с каждой запрошенной стороны, при недостатке данных удваиваем и снова читаем требуемое окно. На границе доступной выборки неполное слово исключаем, если за ним может быть продолжение вне загруженного куска. Полученный текст с заголовками полностью ретокенизируем, ожидаемые координаты и байты сравниваем за пределами timed-кода. Никаких меток и известных конечных координат внутри метода. Обозначим количество SQL-команд, байты от SQLite, токены результата и полное wall time. 5 рандомизированных тёплых повторов, один с новой connection, интервал warm-отношения с группировкой по полю. Малое число холодных connection означает описательную оценку, ОС продолжает кэшировать файл. Порядок оценки фиксируем после первого теста, до измерения этих операторов.

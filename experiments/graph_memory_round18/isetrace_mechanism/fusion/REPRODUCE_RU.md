# Воспроизведение гибридного ранжирования

Расчёт не запускает encoder. Нужны восемь завершённых файлов BM25 и E5 основного условия, обе печати прогнозов, исходные метаданные событий, cohort, данные скорера и окружение серии R18. Поиск исходного файла устроен относительно пути скриптов. Для исходного опыта упаковщик зафиксирован командой `predict.py lock` в момент, когда итоговой печати и результатов E5 ещё не было. Опубликованную печать используйте для ретроспективного воспроизведения. [Пререгистрация](PROTOCOL_RU.md) · [Ревизии и проверка источников E5](../../isetrace_e5/REPRODUCE_RU.md)

```powershell
$pyRrf = 'D:/CodexResearch/x20-isetrace-runtime/venv/Scripts/python.exe'
& $pyRrf -B predict.py predict
& $pyRrf -B evaluate_fusion.py
& $pyRrf -B verify_fusion.py
```

Исходные полные списки используются в порядке авторских ранжировщиков, с привязкой номера 1 к первому кандидату. Для точных ничьих при перестановке обоих рангов применяется рациональная арифметика Python. Для RRF value каждый узел имеет положительный балл; деление квадрата балла на длину эквивалентно сравнению исходного балла, поделённого на квадратный корень длины. В архиве прогнозов номера узлов — индексы с нуля в списке node_id для текущего запроса в лексикографическом порядке. Нулевая индексация этого компактного представления не меняет позиции в формуле RRF. Сохранён отдельный SHA-256 полного итогового порядка каждого запроса, пригодный для сравнения при воспроизведении. Код проверяет равенство идентификаторов, стоимости и всех координат между источниками; открытие меток вынесено в отдельный исполняемый модуль.

Filesystem к исходному корпусу не нужен для повторного формирования ранга из сохранённых прогнозов. Для градации используются первоначальный Python-модуль метрики из закреплённого авторского Git checkout и второе вычисление по объединению интервалов символов. Unit исходного анализа — запрос, единица ресемплирования — траектория. Поштучные результаты содержат 24 000 записей (2 000 запросов × 4 политики × 3 ранжирования). При равном бюджете число токенов реально заполненного контекста может различаться. Во время повторного `predict.py predict` и `evaluate_fusion.py` уже существующие результаты обязаны совпасть с прежними байтами.

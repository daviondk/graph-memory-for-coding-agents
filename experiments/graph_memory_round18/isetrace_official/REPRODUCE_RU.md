# Воспроизведение полного теста ISETrace

Нужны публичные данные v7, закреплённая версия GraphMemory, Python с pydantic, rank-bm25, numpy, tokenizers и requests, а также расположенная рядом серия graph_memory_round17/isetrace. В ней размещены уже проверенные общие функции и ссылки на исходные версии. Исполнитель использует CPU. Запуск архивных инструментальных команд не входит в процедуру.

```powershell
$env:PYTHONUTF8='1'
$env:OPENBLAS_NUM_THREADS='1'
$env:OMP_NUM_THREADS='1'
$env:TOKENIZERS_PARALLELISM='false'
python -B fetch_all.py
python -B discover.py
python -B rank.py lock
0..7 | ForEach-Object { python -B rank.py $_ }
python -B score.py
python -B placebo.py freeze
python -B placebo.py metadata
python -B placebo.py forecasts
python -B placebo.py summary
python -B report.py
python -B verify_package.py
python -B verify_placebo.py
```

Исходные файлы проверяются по ревизии, размеру и хешу LFS либо Git blob. Каталог среды D:/CodexResearch/x20-isetrace-runtime содержит скачанные шард-файлы и checkout GraphMemory. В src-коде предполагается та же структура каталогов, что и в предшествующем исследовании. При первоначальном запуске каждая группа из четырёх шардов обрабатывалась параллельно. Порядок не влияет на итоговые прогнозы. Перед перезаписью исходных материалов или при смене версии следует задать отдельный каталог. Проверенные по хешу промежуточные файлы в full-checkpoints позволяют возобновлять исходное ранжирование по траекториям. Итоговый комплект включает восемь gzip-файлов, содержащих ранги, размеры узлов и координаты источников в исходных событиях; полные тексты источников берутся только из публичного релиза данных.

Сопоставление запросов и исходных траекторий, разрешение эталонных цитат, распределение train/dev/test, ранжирование BM25 и основная функция подсчёта взяты из исходного GraphMemory. Нативная плоская функция ранжирует окна всей отформатированной траектории. Функция provenance ранжирует аргументы и вывод инструментов. У усечённой записи остаются только те интервалы источника, которые действительно входят в первые токены следующего узла; служебные префиксы плоского окна занимают бюджет и не добавляют эталонных символов. Результаты рассчитаны после фиксации прогнозов. Финальный verify_package.py независимо проверяет ранги исходного префикса, учтённые токены, полноту и долю опорных символов, используя стандартную библиотеку. Онлайн-доступ нужен при первом развёртывании внешних источников. [Протокол](PROTOCOL_RU.md) · [Официальная таблица](https://arxiv.org/html/2609.25913v3)

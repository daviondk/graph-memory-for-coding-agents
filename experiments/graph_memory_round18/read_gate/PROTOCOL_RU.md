# Когда передавать выбор фрагмента кода языковой модели

Проверяем, помогает ли разрыв между двумя лучшими лексическими оценками направить ограниченное число обращений к модели на задачи с наибольшей пользой. Первичный исход — реальное открытие блока, который включает хотя бы одну удалённую или заменённую Python-строку на исходной стороне эталонной правки. Рассматриваем все 30 задач из независимой панели 54, на которых ранее опыт R17/line_action не предъявлял модели ни один запрос. Качество статической памяти для части широкого набора уже изучалось. Новыми здесь являются ответы инструмента на эти задачи и выбор политики обращения.

Перед чтением истины и запросами закрепляем один архивный префикс для каждой задачи. В приоритете меню из 60 подтверждённых ранее просмотренных строк, далее непустые неполные меню, затем пустые. Внутри подходящей группы источник выбираем SHA256 от фиксированного пространства r18/gate/source, ID задачи и ID старого способа решения. Граф и параметры памяти из прежних серий фиксированы. Используем lexical24 и тот же статический выбор, идентичную сериализацию issue, списков адресов, системной подсказки, параметров и инструментов Qwen3.8-27B. Для меню короче 60 идентично разбиваем присутствующие диапазоны в блоки длиной до 12 строк. Доля доступных меню считается отдельно; пустое меню исключает вызов, даёт нулевую полезность и сохраняет задачу в полном знаменателе.

Каждому блоку присваивается прежняя лексическая оценка R17 по пересечению токенов описания задачи с текстом и путём блока и сумме весов IDF внутри меню. При равенстве самый ранний в координатном порядке блок выигрывает. Разница между самой высокой оценкой и второй задаёт неопределённость. При одном блоке разрыв считается бесконечным, при одинаковых оценках — нулевым. Пускаем модель на ровно floor(N/2) задач с наименьшим разрывом, где N — число непустых меню. При совпадении разрыва порядок задаёт SHA от r18/gate/tiebreak и ID. На остальных выполняем статическое чтение. Контроли — 0, N и floor(N/2) вызовов по независимой хеш-сортировке r18/gate/control. Никакой настройки порогов, гиперпараметров, источника или квоты по результату.

Для измерения контрфактических действий действительно вызываем локальный Qwen один раз на каждом доступном меню, а затем физически читаем выбранный фрагмент из базового Git-файла. Статическое действие также выполняется. Ценность политик под общей квотой определяется по этим же точным действиям, без повторной генерации. Ошибочные адреса считаем отсутствием чтения. Считаем номера верных файлов/строк, стоимость по точному usage соответствующих ответов, число входных и выходных токенов. По каждому допустимому случайному подмножеству фиксированного размера веса равны. Публикуем точное математическое ожидание и центральный 95% интервал случайных попаданий без возвращения, вероятность результата не хуже наблюдаемого и достижимый при знании ответов максимум под той же квотой. Это распределение рандомизации внутри данной проверки, не доверительный интервал для генеральной совокупности. Исходы всего агента после этого шага не измеряются.

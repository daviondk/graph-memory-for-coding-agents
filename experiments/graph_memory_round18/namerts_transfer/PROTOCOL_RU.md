# Перенос определения владельца правки на официальных изменениях Loguru

Исходная серия R17 показала 15/15 повторов для двух известных правок. Это выборка для разработки. Читаем только их диффы, прежние решения и наблюдения. Гипотеза: добавленная вложенная функция в уже существующем теле доступна только через этот прежний лексический контекст при обычном исполнении. Старый алгоритм при неизвестном имени приказывал заново проверить все тесты, загрузившие модуль. Новое правило пытается поднять новую вложенную область к ближайшей охватывающей функции, существовавшей в старой версии. При отсутствии такого сопоставления повторно проверяются все тестовые файлы, загрузившие модуль. Изменение на уровне модуля, декоратор/смещение определения вне известного тела, вставка новой верхнеуровневой функции и отсутствующее прежнее наблюдение должны остаться консервативными. Правило не обеспечивает полной безопасности рефлексии и внешних побочных эффектов. Используются те же динамические строки и функции на исходном SHA, без входов из нового исполнения.

Независимая когорта — первые шесть пар с флагом target=1 в сортировке SHA-256 от строки «owner-r18|current_sha» из закреплённого официального commit_pairs_loguru.json. Всего 50 целевых пар. Исключаем три ранее изученных current SHA, а затем любую пару с пересечением хотя бы по одному из трёх SHA (истинный родитель, непосредственный родитель, текущая ревизия) с предыдущей серией. Фильтруем темы безопасности и коды, название которых явно на них указывает; не воспроизводим такие дефекты. Репозиторию достаточно одного или нескольких изменённых Python-модулей, неподдерживаемые изменения кода и фикстур вызывают полный сброс. Для каждой пары берём до 20 существующих на обеих сторонах файлов тестов tests/test_*.py верхнего уровня по фиксированному SHA-256 от «file-r18|current_sha|path». На Linux/Windows и в разных версиях фактический состав файлов может отличаться, поэтому считаем знаменатели по соответствующему SHA и сверяем авторский total_tests отдельно. Сначала фиксируем список всех 50 ссылок, исходные SHA, причины исключений и полный пул тестовых путей. До прогнозов доступ к официальным меткам и спискам предсказаний для новых пар не нужен.

Одна единица наблюдения — отдельный файл тестов и фиксированная пара версий. На истинном родителе запускаем этот файл нативным pytest в новом процессе без сети из кода эксперимента; команды из истории агента отсутствуют. Сохраняем полные итоги pytest, трассу входов и строк для затронутых модулей, правильность импорта и ошибки среды. Максимум 150 с на один файл. Если базовый запуск не подтвердил pass или не смог завершиться, все наши политики назначают повтор; отдельно публикуем покрытие, включая условное по чистым запускам. При изменении самого тестового файла назначаем его повтор, при изменениях общих тестовых фикстур — всей панели. Сохраняем для прежнего графа и нового варианта как политику входов в функцию, так и правило прежней строки плюс вход в функцию для добавления строк. Кандидат первичного сравнения — новая политика на уровне функций, контроли — прежняя политика, все файлы импортированного модуля, ранее исполнявшиеся строки, полный повтор и опубликованный NameRTS на точно тех же файлах. Эффективность — число предписанных повторов; качество — сколько авторских затронутых файлов найдено/пропущено и в скольких парах не потерян ни один размеченный файл. Неизученные файлы не считаем сэкономленными. Дополнительно приводим EkstaP/BabelRTS, покрытие, время базовых запусков и интерпретацию каждого случая расширения. Готовые прогнозы авторов не измеряют время выполнения их инструментов на этой машине.

Все правила, выборка и входы фиксируются до обращения к индивидуальным меткам новых pair/file. Коммиты с отрицательными или равными результатами остаются в выборке. Стоимость повторов означает предписанную из сохранённой памяти работу на новой версии. Фактические новые падения и разметка affected — разные исходы.

# Воспроизведение

Для автономной проверки архива достаточно Python 3 стандартной библиотеки. Команда `python -B verify.py` сверяет весь плоский манифест, шесть контрольных наборов SHA-256, поштучные прогнозы, опубликованные числа и соответствие выбранных файлов сохранённым наблюдениям. Авторские оригиналы были прочитаны через `git show <revision>:<path>` и дополнительно сопоставлены с рабочей копией после декодирования JSON. Git blob ID, SHA-256 и путь для каждой метрики приведены отдельно. [Идентификация первичных источников](author-sources.json) · [Справочник первичных файлов авторов](https://github.com/ZJU-CTAG/NameRTS/tree/f1acdae0f2b2d1ed6e3e2956d510db49bb7c276f)

## Повтор эксперимента

Рабочая система Windows / PowerShell. Исходные репозитории и среда расположены на D:. Переменные в `plan.py` указывают на NameRTS и полную/частичную Git-копию Loguru в `D:/CodexResearch/x20-r17-namerts/{NameRTS,loguru}`, на интерпретатор `D:/CodexResearch/x20-r17-namerts/runtime/Scripts/python.exe` и восстановимый кэш `D:/CodexResearch/x20-r18-owner-transfer`. Исторические входы R17 в соседнем каталоге `graph_memory_round17/namer_ts` нужны для непересекающегося отбора SHA и для калибровки. Внешние репозитории доступны без токена GitHub. Версии Python и всех runtime-пакетов записаны в полях python и environment файла plan.json. Для независимого воспроизведения используйте отдельную копию выходного каталога и пустой каталог кэша. Закрытые артефакты и манифест первого прогона остаются эталоном. Время, журналы pytest с путями временных файлов и новые SHA заморозок вследствие этого могут отличаться. [План и среда](plan.json) · [Исходники Loguru](https://github.com/Delgan/loguru) · [Ранее закреплённая выборка и среда](../../graph_memory_round17/namer_ts/REPRODUCE_RU.md)

```powershell
$env:PYTHONDONTWRITEBYTECODE = '1'
$pythonExe = 'D:/CodexResearch/x20-r17-namerts/runtime/Scripts/python.exe'
& $pythonExe -B plan.py
& $pythonExe -B forecast.py
& $pythonExe -B frequency.py
& $pythonExe -B score.py
& $pythonExe -B audit.py
& $pythonExe -B census.py
```

Первая команда выбирает пару и файлы только из метаданных кандидатов и Git-деревьев. Вторая исполняет 120 нативных файлов в изолированных временных деревьях, получает доказательства исходного pass и замораживает прогнозы. Третья до чтения авторской разметки проводит диагностику 41 пары, запускает дополнительные базовые файлы и 18 раз проверяет текущую версию. Четвёртая связывает запечатанные решения с авторскими результатами, пятая сверяет идентичности узлов и оценивает механистическую подвыборку. Шестая расширяет её до полного множества 48 файлов, сохраняя прежние 20 наблюдений. Для новой копии после воспроизведения можно провести `python -B verify.py --write-manifest`. Эта опция пересчитывает хеши в новой копии. [Протокол](PROTOCOL_RU.md) · [Дополнительный отбор](FREQUENCY_PROTOCOL_RU.md) · [Полный перебор](FULL_CENSUS_RU.md)

Внутри дочернего процесса перед импортом pytest включается профилирование событий вызова и строки. Фактический вызов `pytest.main(["-q", "-o", "addopts=", "-p", "no:cacheprovider", file], plugins=[Capture()])`; аргумент `-B`, фиксированный PYTHONHASHSEED и отключённая автозагрузка плагинов применяются ко всем нашим измерениям. Импорт loguru обязан указывать внутрь выбранной временной копии. Чистый результат требует одновременно успешного процесса, pytest_rc=0, хотя бы одного pass и отсутствия failed на всех фазах. Время ограничено 150 с на файл. Результат конкретного теста следует читать из runtime.pytest_rc и runtime.outcomes, так как обёртка может завершиться штатно и при сообщённых pytest падениях. [Реализация](worker.py) · [Валидация](forecast.py)

Архивы *.gz — UTF-8 JSON в gzip. Первичные прогнозы включают current, true_parent, file, clean, stderr/stdout, время, тройки pytest nodeid / phase / outcome, наблюдавшиеся строки/функции и флаги политик. Дополнительная таблица current-diagnostic сопоставляет реальные исходы файла до/после, а author-sources задаёт происхождение каждой метки. Общая стадия git-обслуживания частичной копии выводила предупреждения Windows об удалении заблокированных файлов индекса pack. Все операции чтения и архивирования выбранных SHA завершились, контрольные проверки модулей и файлов пройдены. Для самостоятельного воспроизведения рекомендуется полноценный клон проекта.

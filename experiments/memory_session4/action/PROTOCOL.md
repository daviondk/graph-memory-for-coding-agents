# Evidence about a retry as a piece of experience memory
Registered on 2026-11-17 before examining individual rerun outcomes or associations. A prior startup on ALFWorld benefited from remembering one rejected transition; an earlier SWE replay had only 14 guarded warnings, mostly timeouts. Transfer target here is a code agent deciding whether to spend its scarce CI rerun budget on an initially failed job/build. Primary dataset: exhaustive matched actual pre/post rerun observations of Travis CI in the MSR 2020 official artifact (10.5281/zenodo.3601137); use all binary restarts meeting temporal and exact run identity checks from the dump. Primary intervention is offline policy replay conditional on a developer actually requesting the retry, not a prospective randomized job-level intervention. Arrange attempts in temporal order; a completed retry's label is readable for another decision only after its actual completion. Replay on same SHA/immutable build ID, exclude ambiguous duplicate pairings/statuses, record all exclusions. No simulated failures/costs passed off as observed. If no exact match on metadata alone use the authors' original after-attempt records. Intended age shift: separately evaluate an independently collected modern public Github Actions subset if feasible. GHA manuscript's three anonymous repository APIs return 410 during corpus screening; avoid treating their selected examples of flakes as representative negatives.
Primary unit: observed failed or errored build subsequently passing/failing/erroring. Forecast recovery, not exact error identity. Last observed failed state => always expect failure; stronger controls are global running recovery rate, most recent comparable project retry's outcome, same initial outcome pooled globally, all prior comparable events in a project. Candidate: empirically calibrated rerun history keyed by repository and observed failure context (state/event/settings when available), shrink short history to global context. Initially fix pseudocount 8, not tuned. Costed reading: 1/8/32 recent completed matches as a sensitivity, observed provenance, compare to richer/global priors and shuffled or stale reference. Only features of the original failed attempt. Use a temporally blocked held-out tail (last 50% by original finish time, retaining complete earlier cases to populate memory); compute primary Brier loss and fraction of actual recoveries captured at 20% rerun budget within predeclared fixed-size blocks in temporal order. Within each block the fixed-quota score is an offline prioritisation illustration (candidate pool is known), not an online threshold. Also compute exact minutes actually spent and successful retries, if second-attempt timing available, partial coverage and subgroup support, failure-to-failure counts. Secondary live decision: fixed threshold p>=0.5 or lower thresholds in sensitivity, no downstream feedback leakage on this retrospective data. Primary contrast candidate vs global-context estimate; compare strong project-only and recency baselines with paired confidence intervals resampling entire projects. Report chronological, project-level and first-seen limits. Unobservable counterfactual unretried builds, CI vs agent choice, skipped failures and retries selected by people limit interpretation. Protocol corrections due solely to schema/software limitations must precede outcome inspection and be logged. No claiming numerical superiority to a published model without matched sample, splits, inputs and label definitions.

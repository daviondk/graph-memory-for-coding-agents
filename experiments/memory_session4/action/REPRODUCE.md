# Воспроизведение CPU-эксперимента

## Быстрая автономная проверка

Используйте Python 3.10 или новее. Прогон выполнен в Python 3.14. Все зависимости входят в стандартную библиотеку. GPU, WSL, платный API и сетевой доступ для проверки готовых результатов не нужны.

Из каталога `action` выполните

```powershell
python -B verify.py
python -B evaluate.py --check
python -B score_tail.py --check
```

Первый вызов проверяет контрольные суммы, заново строит хронологическую историю памяти и проверяет предсказания основных вариантов по данным, доступным до момента решения. Также заново считает квадратичную ошибку, число выбранных повторов и число реально успешных повторов. Последние две команды пересчитывают основные таблицы и bootstrap по проектам. Фиксированные seed сохранены в коде. Полный пересчёт занимает порядка минуты на CPU.

Проверка GLM-receipts в первом вызове ограничена контрольными суммами. Для независимого полного повторного обучения FTRL выполните `python -B glm.py` в рабочей копии. Обучение использует сохранённые входы и наблюдаемые исходы, производит `glm_results.json` и файлы `*_glm_receipts.jsonl.gz`. Проверьте контрольные суммы повторным запуском `verify.py`. Основные стратегии воспроизводятся командой `python -B run.py`.

## Переносимая копия

Сохраните все небольшие файлы, каталог `github`, код, протоколы, производные JSON/JSONL, контрольные суммы и этот документ. Для автономной проверки не нужны четыре исходных архива

- `restarted_builds.bson.gz`
- `restarted_jobs.bson.gz`
- `restarted_logs.prefix.gz.part`
- `restarted_logs.tail128.gz.part`

Каталоги `__pycache__`, временные файлы и консольные `*.log` можно исключить. Исходные публичные идентификаторы сохранены для сверки с источником. Их обезличивание изменит hash-based ordering и контрольные суммы.

`checksums.json` запечатывает переносимые файлы. `input_lock.json` и `tail_input_lock.json` фиксируют протокол и код до соответствующего результата. Это локальные файлы, внешняя регистрация протокола не проводилась.

## Исходные данные и полный пересчёт

Ссылки и SHA256 исходных архивов находятся в `source.json`, `job_sources.json` и `tail_source.json`. Получение

```powershell
python -B fetch.py
python -B fetch_jobs.py
python -B fetch_tail.py
```

Первый архив build, второй job, затем фиксированные первые 64 MiB и следующие 128 MiB сжатого потока логов. Полное скачивание 2,16 GB логов не требуется. Данные находятся в официальном архиве авторов на Zenodo.

Для перестроения первичных проекций используйте `python -B project.py`, затем `python -B run.py`, `python -B evaluate.py`, `python -B glm.py`, `python -B tail_run.py`, `python -B score_tail.py`. Выполняйте это в отдельной копии, поскольку команды перезаписывают производные файлы. Исходный lock ожидает те же данные и код.

GitHub Actions census хранится отдельно в `github`. `python -B external_score.py` пересчитывает описательную проверку из сохранённых минимизированных API-проекций. Новое `external_collect.py` обращается к изменяемому API и может дать другое содержимое. Оно не требуется для проверки сохранённого census.

## Интерпретация

Все исходы CI уже были фактически исполнены авторами или пользователями публичных репозиториев. Здесь выполнен вычислительный replay политик памяти на CPU. Нового запуска исторического CI, локального решателя LLM или живого интервенционного эксперимента на агентах в этой части работы не было.

Основной архив относится к 2019 году. Он содержит повторы, выбранные разработчиками. Бюджетная симуляция предполагает сохранение наблюдаемого второго исхода при выборе пары политикой. Такое предположение требует живой проверки. Квадратичная ошибка вероятности, полезность выбора и историческое время CI отчётливо различены в `summary_ru.md`.

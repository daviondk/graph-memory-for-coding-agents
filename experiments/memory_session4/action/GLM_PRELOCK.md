# Strong adaptive benchmark before inspecting any aggregate scores
In addition to the count-based controls, compare an online logistic model using standard FTRL-Proximal updates (McMahan et al., KDD 2013): alpha 0.25, beta 1, zero L1 and unit L2, initial weights zero, one update per actually revealed historical outcome after it completes; no hyperparameter search. Features are a constant, project ID, original state, event, language, matrix bucket, project+state, state+event+language+matrix and project+full signature. For typed jobs add global state+original reason tuple and project+state+original reason tuple. Evaluate metadata-only and typed GLM with the same forward-only Brier and rank them in the same restricted-feedback block/20% allocation. Direct comparisons to count-based recent8 on builds and typed/rate baselines on jobs; same 2000 paired project bootstrap. No model pretrained on proprietary outcomes. Distinct from 2026 FlakeDetector, whose label allows success within up to ten additional experimental reruns, beyond this corpus's first actual retry.

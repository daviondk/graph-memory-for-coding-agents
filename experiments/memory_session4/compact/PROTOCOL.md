# Exact edit preconditions after a bounded handoff
Local prospective registration, 17 November 2026. Dataset SWE-bench/SWE-smith-trajectories, HF 08e109b4a59eaeebf80e4675cd125d42e7ac99a4, all eight tool parquet shards. Only row zero was used for schema/prompt development; exclude that instance_id from analysis. Freeze these rules before examining other trajectories, their successes, future edits or scores. Original tokens and tool calls were produced by the released agents; no model, GPU, or feedback to the actor used here.
Sample an issue, not an outcome: SHA256("compact-s4|"+instance_id) modulo 10 == 0, all trajectories of selected issues, all eight shards. First four shards = primary cohort, last four independent block sensitivity; explicitly audit cross-block duplicate issues and additionally reserve issues by hash for replication. No threshold/model tuning. Exclude no task on resolved/patch labels; neither enters any input. Original SWE-smith instances are generated bugs, and this dataset is drawn from long training/inference conversations. This is not the 500-issue SWE-bench Verified or Compact-Bench.
At each fixed synthetic handoff after 4, 8, 12, ... completed action/observation interactions, predict without access to any subsequent action or outcome. Within the next at most four interactions, score the first structurally valid old-string/new-string editor replacement, regardless of historical outcome; non-replacement blocks are a separate coverage denominator. No overlap in the future windows. A primary micro endpoint is exact recovery of file and matching preimage of a historically accepted replacement, sufficient to run the same replacement uniquely on a produced historical excerpt. Count failures of historical replacements separately as unavailable; conditional denominator and all-intent denominator reported. Module/path and preimage may be known from the issue but are not fed into retrieval. An oracle future old_string is used only for *grading* predictions, never their generation/ranking.
The writer can use the public user request, tool calls and their text observations up to the boundary. Extract read evidence from actual numbered str_replace_editor view outputs and from successful editor snippets with known paths. Do not infer arbitrary bash outputs as line-addressed evidence. Main memory hypotheses: (1) prioritize exact observed text near recent repeated identifiers vs retaining full raw recent excerpts alone; (2) choosing a compact pointer to already observed source + a single deterministic selective reopen can supply more actionable code per hot-context budget than keeping the transcript, after accounting for the reopened bytes. Compare same output token limit on ALL decoded texts, including reopened information. Budgets 512 primary, 256 and 1024 sensitivities using the same archived Qwen tokenizer, fully local. Exclude any over-budget output as an implementation failure, no gold-dependent trimming. Strong controls: paths only (navigation only), recent-tool tail, most recent complete lines from the last viewed paths, an overlap of issue identifiers with lines (query lexical), rank-identical no-special-coverage selection, within-path/full-history evidence ceiling. Distinguish hot-state bytes, externally stored bytes, reopen operations and returned tokens; cannot claim total storage or wall-time saving from an index. Plan may use globally fixed 12- or 16-line provenance blocks plus direct recent contiguous windows and line-per-file diversity. More states must not add to the common output budget. Report the primary proposed arm even when it loses.
Physical check on recovery: write selected past numbered contiguous code portions as scratch files of the correct relative origin; reconstruct original whitespace; require a unique literal old string within one contiguous portion and replace with historical new_string exactly (no future aiding context). Re-read expected replacement bytes and validate; this proves the local edit precondition, not unique matching in the full file, later repair, or test success. Upstream accepted vs rejected comes from actual subsequent tool return and is not exposed to the writer. If runnable, add a stricter independent check using a complete prior observed file / verification against public backing source; report ambiguity and coverage. Support multi-line matches without concatenating nonadjacent chunks. Log unknown/unstable path states; no claim of a live agent continuation.
Statistical unit: per-issue cluster with nested session and boundary; pair outcomes within identical boundaries, 5000 fixed-seed issue resamples, cohorts by shard and disjoint issue hash strata, repo heterogeneity, preimage bytes, new file vs stale/no longer observed, and source storage counts. Other ablations are exploratory. Save raw projected actions, frozen predictions and hashes before inspecting outcome totals, per-boundary scores, raw scores from every arm, executable audit and limitations. Avoid claiming improvement over end-to-end SOTA from retrieval replay.

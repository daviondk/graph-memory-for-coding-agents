# Compatibility with published evaluator record layouts
All four reader output sets were already complete and sealed. The collector then stopped at a published Claude report whose fields (patch_is_None, patch_exists, patch_successfully_applied, resolved, tests_status) were at the document root, while the initial parser expected the same fields nested under instance_id. No scoring or selection was performed from this partial fetch. The compatible collector accepts exactly these two layouts and requires resolved to be a boolean. The item identity is pinned by the source URL and verified artifact digest. Preserve original raw bytes alongside the parsed report, outcome, URL and original SHA. No outcomes are inferred for missing files. Original collector and grade lock remain intact. The compatibility wrapper and this amendment have an additional code lock. Full verification must support both documented schemas and check byte-level sources offline.

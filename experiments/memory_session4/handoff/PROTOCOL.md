# Executable outcomes behind a coding-agent handoff
17 November 2026. Design entered before fetching submission patches, per-instance resolved labels, per-candidate ranks, or Qwen outputs for this study. The previous project already used these public traces to evaluate file caching, test-command reuse, and stale-error warnings. The present question and official final-patch endpoint differ. Observational action traces cannot tell us whether prompting the original agent would change its work.

A new agent chooses one of two existing implementations of the same SWE-bench Verified issue after context interruption. Each implementation is a final actually submitted mini-SWE-agent patch. All work before the handoff is common to arms. The earlier actor may have verified a different revision; a late exit code or a claim that testing succeeded is insufficient evidence for the submitted diff. Hypothesis: retain small executable verification records with a pre/post edit witness and freshness/visibility so that the reader can choose better, or read them only when two patch-only decisions disagree. Tests invoked by the candidate, no hidden tests or grading outputs allowed in memory. Trace evidence is a proxy for revision; a shell transcript is not a source-tree hash. A prospective deployment would use actual workspace snapshots.

Main cohort: all 500 paired submissions Claude Opus 4.6 and GPT-5.2-Codex from the pinned mini-SWE-agent leaderboard entries used by the previous round. Include empty patches, identical patches and ties in totals, report separately. Secondary transport use all available paired Gemini 3.5 Flash submissions against each main model, listing coverage, overlap, and missingness. Unavailable artifacts: enumerate exclusions rather than imputing success. Rule development only on documentation or <=3 issues as a parsing control, excluded from the primary Qwen roster if reviewed. No reading a gold patch or resolved labels to form either packet or roster. Source text comes from published predictions and task statement. Award selected-patch success only from the separate official evaluator record for precisely that submission. Report baseline for both source models, stronger leave-one-repository-out estimated-source prior, shorter diff, equal random expectation and best-of-pair oracle. No model names visible to Qwen.

Causal prefix: retain tool command and visible return code only up to submission; do not feed reasoning, grader messages, run exit reason, elapsed task time, identity or hidden test/patch names into reader. Candidate's own observed tools may contain test paths. Latest memory stores up to two last verifications. New writer favors repeated tests exhibiting changed outcomes across observed edits, then verification after most recent plausible source mutation. Explicitly tag ambiguous shell status, edits since and missing evidence. Include a standalone freshness-only control and compare latest/fresh/witness deterministic rules for all issues. Score scripts and ranks sealed before opening outcome labels. Test names are not guaranteed to test the requested behavior. Descriptive eligibility counts for witnesses, number of abstentions, failed tests, price, and error examples. Report simple last-exit control and static source skill. Fix only infrastructure/parser errors with a dated addendum before grading.

Fixed real-reader cohort: first 96 paired issues by salted SHA256 issue ID ('s4-judge-20261117' prefix, no outcome labels). Ground truth held separate until outputs sealed. Same local Qwen3.8-27B Q4_K_M, temperature 0, seed 17112026, native thinking off, one slot and a small bounded output. For each issue, compare identical patch+issue text with no session memory, last two verification notes, and contrast/freshness notes. Two orders per arm. Within each instance keep issue and candidate-diff excerpt caps fixed; the two note arms use the same char cap per patch. Dedupe only byte-identical native requests. Count nominal and actual costs. Main end point is mean success of the selected final patch under the two presentation orders, paired by issue. Invalid model response uses the deterministic issue+order-independent hash tie-breaker, record malformed answers. Immediate success, fixed source, shorter patch and attainable success reported. When order votes disagree, use same blind tie-break for a single final action, separately. Secondary gating condition requests memory only when the two no-memory orders disagree. Compare with always/never reading, equal-count hash-selected gate, actual marginal reader tokens. All multiple contrasts exploratory; report paired W/L, both-resolved/neither-resolved, repository-cluster intervals and dispersion, plus absolute solved numerator. No winner claim with weak support. This measures selection from existing patches, not SWE-bench standalone agent pass@1 or a new leaderboard score.

Aim for independent review of the raw official label source and exact prediction hash. Archive emitted packets, inputs, decisions, native calls, score vectors, environment and a portable offline verifier. The mechanism is a hypothesis about what to write and when to read it; the trained verifier, tests/hidden labels and benchmark may be known to the underlying model.

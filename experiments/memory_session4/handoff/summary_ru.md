# Проверяемые записи тестирования при передаче coding задачи

17 ноября 2026 года. После фиксации всех ответов новые прогоны локальной Qwen3.8-27B сопоставлены с 1 441 отдельным официальным отчётом SWE-bench. Первичный опыт использует 96 задач из 433 пар, для которых и Claude, и Gemini опубликовали совпадающие по байтам итоговый patch и submission в траектории.

## Главный результат

Каждый метод предъявлен в двух порядках кандидатов. Без памяти выбраны прошедшие официальную проверку патчи в 152 из 192 предъявлений. Последние проверки дали 150, записи с признаками свежести и наблюдённой смены результата — 152, перемешанные между задачами записи — 150. Строгий отбор shell-свидетельств дал 152. Первичная разность witness − no memory равна нулю, 95% bootstrap по десяти репозиториям [−5,00, +1,76] п.п. Перемешивание сохраняет весь набор записок каждого источника и их общий объём. Правильная привязка witness к задаче добавила два успешных выбора относительно перемешивания, но интервал разности [−2,86, +2,34] п.п. совместим с нулём.

У 70 задач оба кандидата прошли проверку, у 14 оба провалились. Только 12 пар различаются по исходу. На этих 12 средняя доля правильного выбора равна 50% без памяти, 41,67% с последними тестами и 50% с witness. Такая выборка даёт слабую мощность для небольшого эффекта. Общий высокий процент успехов в значительной мере обусловлен качеством уже готовых кандидатов.

Межрепозиторный prior, обучаемый на исходах остальных репозиториев, дал эквивалент 154/192. Простое правило последнего статуса дало 160/192 на этих 96 задачах. На полном корпусе 433 пар приоритет источника выбрал 353 успешных patch, последний статус — 351, freshness и witness — по 344. Потенциальная верхняя граница выбора из двух равна 376/433. Witness не изменил ни одного результата относительно простого freshness rule на полном корпусе.

## Что видит решатель

Промпт одинаков для всех вариантов. Он содержит ограниченные выдержки issue и двух patch, затем необязательные записи наблюдаемых проверок. Размер issue ограничен 2 850 символами, каждого patch — 3 450, записки каждого кандидата — 450. Идентичные выдержки сохраняются между условиями. Полные raw prompts и ответы доступны в calls. В промпт не передаются официальный resolved, hidden test output, итоговая оценка исходного агента или его рассуждения.

Writer извлекает только явно наблюдавшиеся команды, return code и краткие диагностические строки. Сигнал свежести означает отсутствие обнаруженной последующей записи, а не доказанный hash состояния репозитория. Контраст fail→edit→pass требует той же текстовой команды и обнаруженной записи по пути патча. Достоверность такого признака ограничена разбором shell.

Зафиксированы temperature 0, seed 17112026, thinking off и предел 12 выходных токенов. Выбор является реальным новым ответом Qwen, создание нового исправления в данном опыте не оценивается. Полный протокол находится в PROTOCOL.md, уточнение пары источников в PROVENANCE_AMENDMENT.md.

## Позиция и стоимость чтения

Без памяти решатель выбирает позицию B в 173 из 192 предъявлений. С witness — в 151 из 192. При обратном порядке источник выбранного patch меняется у 77 задач без памяти и у 55 с witness. Десять пар содержат идентичные полные и видимые patch. Среди оставшихся 86 source flip без памяти встречается 67 раз. Усреднение двух порядков сохраняет этот эффект в результатах и предотвращает выбор удобной позиции для сравнения.

Зарегистрированный gate обращается к witness при расхождении двух no-memory выборов. Он читает память для 77 задач и сохраняет результат 152/192. Номинальная стоимость составила 426 138 токенов с учётом обеих стадий. Всегда читать witness стоит 252 150 токенов, не читать — 224 446. Число дополнительных вызовов нельзя трактовать как общую экономию.

После результатов отдельно проверен gate по идентичности самого patch. Он исключает десять бессмысленных смен источника одинакового артефакта, читает 67 задач, расходует 402 580 токенов и сохраняет результат 152/192. Это post-result диагностика. Она демонстрирует важность совпадения действия при построении trigger, но преимущества по стоимости перед always-read всё равно нет.

## Аудит источника и parser

В 459 из 500 первоначально собранных GPT-5.2-Codex пар байты траектории и evaluator patch расходятся. В самих 500 траекториях указана GPT-5.2, а ETag совпадают с соседней заявкой GPT-5.2-high. Исходная пара и её 576 назначений сохранены как sensitivity к ошибке связывания. Основная clean пара выбрана до чтения официальных исходов. Подписи модели в прежней серии memory_session3 требуют поправки из HANDOFF_CORRECTION.md.

Внешний census охватил 52 дополнительных mini-каталога. У 41 есть совместимые пары, всего заранее отобрано 984. В 948 обе стороны непустые, из них 945 совпадают побайтно. Три расхождения сосредоточены в GPT-OSS-120B, два имеют разные полноценные patch signatures, одно содержит RetryError. Это описательный аудит данных, а не независимые репликации или доказательство ошибки официального score.

Независимый аудит writer показал возможность приписать общий вывод последнему тесту составной команды. Шесть реальных событий имеют несколько тестов и общую сводку, одно встречается в основной выборке. Фактические неверные verdict этих случаев отдельно не установлены. Strict arm до открытия исходов исключил compound shell вместе с pipeline и redirect. У Claude осталось 39 из 325 наблюдений, у Gemini 469 из 483. Строгий отбор одновременно меняет точность привязки и покрытие.

## Backend и восстановление

Выполнено 1 536 назначений условий, после точного кэширования одинаковых запросов — 1 464 новых вызова. Фактическое потребление составляет 1 866 025 входных и 2 928 выходных токенов. На RTX 3090 выполнено 1 455 запросов. После CUDA illegal memory access и перезапуска устройство перестало определяться, и оставшиеся девять strict запросов та же модель исполнила на CPU. Полные no-memory/latest/witness/shuffle сравнения основной пары завершились до сбоя на GPU.

Строгий полный результат 152/192 объединяет backend. Дополнительно оценены 87 задач, для которых оба strict ответа получены на GPU. На них strict даёт 136/174, no-memory и witness — по 135/174. Интервалы различий включают ноль. Все ответы до сбоя сохранены, отсутствующий запрос повторён с прежними параметрами. Журналы CUDA, запуска, ресурсов и backend attribution входят в архив. Системное восстановление GPU в эту серию не выполнялось.

## Что можно переносить в дальнейшее исследование

Эта форма коротких тестовых записок не дала выигрыша над сильными контролями. Есть измеренные диагностические причины — малая доля различимых кандидатов, позиционное предпочтение решателя, неполная привязка shell-наблюдения к версии кода и дорогая двухстадийная проверка неопределённости. Следующая гипотеза должна выбирать минимальное свидетельство, различающее реально конкурирующие действия, и оценивать его на новом продолжении агента.

Все официальные исходы относятся к историческим публикациям разных исполнителей. Они не пересчитаны в общей текущей версии evaluator и окружения. Возможное присутствие публичных SWE-bench задач в обучении Qwen неизвестно. Для статьи необходимы один закреплённый harness, новый решатель после одинакового состояния, полный учёт token/tool/time costs и больше независимых информативных случаев.

## Проверяемость

verify.py --require-report-bytes независимо проверяет sealed inputs и predictions, 1 441 projection, 1 441 original HTTP report body, соответствие ответов native request receipts, все итоговые score vectors и bootstrap. Дополнительные diagnostics.py, patch_identity.py и backend_sensitivity.py сохраняют анализ позиций, равных patch и смены backend. Две поддерживаемые схемы official report, вложенная и плоская, описаны в LABEL_SCHEMA_AMENDMENT.md.

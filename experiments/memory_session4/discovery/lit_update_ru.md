# Обновление prior art для наблюдаемой замены результатов

Дата проверки 17 ноября 2026 года.

## Invalidation Contracts

Wu и Canedo предлагают версионированные recovery suggestions, cacheability hint, изменения строк при reload и проверки зависимостей. Работа разделяет детерминированную валидность записи и фактическое применение подсказки планировщиком. Эксперименты используют синтетические API и семь моделей. Точность row-level eviction оценена относительно объявленного row-level oracle. Поэтому версии, receipt-подобное свидетельство происхождения и зависимостная инвалидация уже имеют прямой agent-memory prior art. [Оригинальная работа](https://arxiv.org/html/2609.00243v1)

Для нашего observed replacement причинное свидетельство возникает, когда идентичный доступный запрос уже вернул новый наблюдаемый результат. Оно покрывает конкретный ключ и путь наблюдения. Контракт сервера дополнительно сообщает о ненаблюдавшихся изменениях через версии и diff. Узкий возможный вклад требуется искать в частичной наблюдаемости без такого контракта и измерять ошибки сохранения/удаления на дальнейшем исполнении. Простая замена старого значения после чтения нового остаётся инженерной базой. Общее наличие metadata и hash не подтверждает исследовательскую новизну.

## Hierarchical Caching for Agentic Workflows

Begum и соавторы публикуют двухуровневый workflow/tool cache, статический граф reads_from/writes_to, TTL и session scope. Алгоритм инвалидирует записи затронутых инструментов и содержащие их workflow. Эксперименты контролируемые синтетические, включая повторяемость и writes. Проверен публичный код с результатами и тестами, commit 5480632bae9725b427f55333ef44f7777a9d97a1. Dependency metadata здесь задаётся при описании инструментов. [Статья](https://www.mdpi.com/2504-4990/8/2/30), [авторский код](https://github.com/Farhana211/Hierarchical-Caching-for-Agentic-Workflows/tree/5480632bae9725b427f55333ef44f7777a9d97a1)

Этот baseline обязателен для идеи safe compact tool memory. Наша точная наблюдаемая замена использует более узкое основание и может сохранять записи соседних ключей. Нужно сопоставить стоимость чтения метаданных, несовпадение ключей, удаление ещё нужных записей и downstream correctness. Новая гипотеза может касаться переноса зависимости по наблюдаемому результату с проверяемой неопределённостью, если она выдержит сравнение с точными ключами и объявленным dependency graph.

## Дополнительная свежая работа

AdMem от 16 ноября 2026 года записывает ожидаемый исход перед действием, сравнивает его с наблюдаемым исходом критиком и обновляет utility процедурных записей. Ожидание, локальное подтверждение и lifecycle уже составляют опубликованную комбинацию. Для предложений о contradiction-triggered recall требуется абляция против такого expectation-grounded critic с одинаковой стоимостью его вызовов. [AdMem](https://arxiv.org/html/2611.20605v1)

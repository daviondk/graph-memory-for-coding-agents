# Целевой обзор рабочей памяти агента и три гипотезы

Проверка выполнена 17 ноября 2026 года. Это целевой обзор подходов к записи, чтению и удалению сведений во время исполнения. Поиск включал точные названия CompactionBench, APEC, CoReMem, Continual-SWE, REM, SWE-ContextBench и запросы об action-conditioned memory, workflow memory, invalidation и expectation-grounded agent memory. Использованы исходные статьи, авторские страницы, GitHub API и Hugging Face API. Полная систематическая полнота по области этим поиском не установлена.

## Ближайшие оригинальные работы

- REM, октябрь 2026. Короткий документ вводится в начале задачи, подробный опыт появляется после признака затруднения и удаляется после одного предъявления. Нужна отдельная абляция полезности формата документа и recall gate. На 297 paired task-runs авторы приводят 20 побед и 12 потерь, exact McNemar p=0,22. Обобщение, что gate сам надёжно повышает task resolution, превышало бы этот результат. [REM](https://arxiv.org/html/2610.27377v1)

- CoReMem, ноябрь 2026. Ценность фрагментов проверяется на следующей задаче из одинакового inherited repository state. Компактная память содержит места кода и исполняемые проверки. Адаптация актёра и memory writing оцениваются отдельными частями и вместе. Протокол использует repository-disjoint chain split, контроль без памяти, full history, другие memory layers и стоимость writer calls. Это ближайший baseline для переноса проверяемых действий между задачами. [CoReMem](https://arxiv.org/html/2611.17316v1)

- AdMem, 16 ноября 2026. Ожидание перед действием и наблюдение после него обеспечивают локальную оценку процедурной записи. Utility влияет на чтение, объединение и удаление. Поэтому простая идея хранить outcome и forgetting по полезности требует сравнения с этим методом. [AdMem](https://arxiv.org/html/2611.20605v1)

- SCLATE, сентябрь 2026. Общая временная модель и открытый event scheduler позволяют учитывать остановку сессии, consolidation и фоновые события. Авторы сравнивают неизменённые harness и memory configurations. Важное требование к нашей будущей работе — общий реально исполняемый жизненный цикл и воспроизводимый учёт вызовов. [SCLATE](https://arxiv.org/html/2609.32391v1)

- What Is This Memory Useful For, ноябрь 2026. Writer не знает будущего вопроса, reader сравнивается на matched input с памятью и без неё. Есть отдельный cost ledger и анализ task-conditioned utility. Это сильный дизайн для контрфактической проверки конкретной записи. [Task-conditioned utility](https://arxiv.org/html/2611.03930v1)

- Agent Workflow Memory, 2024. Индуцирует повторно используемые процедуры и проверяет их на Mind2Web и WebArena в offline и online постановках. Для нашей маленькой памяти незавершённого действия это более ранний prior art переносимых процедур. Его полная политика решателя существенно шире UID-reranking. [AWM](https://arxiv.org/abs/2409.07429)

- Invalidation Contracts и Hierarchical Caching подробно рассмотрены в lit_update_ru.md. Они задают ближайшие версионные, зависимостные и tool-cache baselines. [Контракты](https://arxiv.org/html/2609.00243v1), [иерархический cache](https://www.mdpi.com/2504-4990/8/2/30)

## H1 Незавершённое действие как временное обязательство

Механизм состоит в хранении ожидаемого следующего взаимодействия и его объекта до наблюдаемого завершения или смены намерения. Возраст сам по себе не определяет срок действия. Сильнейшие соперники — последняя адресация с type tag, извлечение из recent-history и procedural expectation memory.

Предсказание — выигрыш при разрыве между открытием обязательства и его завершением, особенно когда обычная история уже вытеснена. Опровержение — эффект сохраняется только для соседнего click→text_input и полностью восстанавливается из входной истории. E1/E3 уже реализовали такое опровержение для одноэлементного WebLINX-варианта. Возвращаться к нему имеет смысл при другом реально наблюдаемом механизме утраты истории.

## H2 Чтение памяти как выбор проверяемого свидетельства

Агент сначала формирует две конкурирующие гипотезы о причине ошибки и один тест, результаты которого различаются между ними. В памяти сохраняется связь между гипотезой, исходной версией наблюдения и этим тестом. Триггер извлечения возникает при конкретном противоречии между текущим исходом и ожидаемым. Извлекается минимальный прошлый факт, меняющий выбор проверки.

REM уже исследует struggle-gated detail, CoReMem сохраняет executable anchors, AdMem использует expected outcome. Потенциальный вклад ограничен выбором контрфактически различающего свидетельства при одинаковом бюджете. Предсказание — меньше повторов неинформативных проверок и выше resolved per total token, при равном resolve rate или его росте. Опровержение — effect исчезает при сравнении с короткой summary плюс один тест, либо critic cost превышает сэкономленные вызовы.

Эксперимент — официальные related issues SWE-ContextBench Lite, writer-only trajectories до текущей задачи, frozen reader. Сравнить phase document, REM detail, anchor-only, предложенный conditional evidence. Hidden tests оценивают итоговый patch. Pre-register число цепочек, одинаковые repeated seeds и clustered interval по experience group. Сохранять исход ошибки до выбора памяти, включая безуспешные попытки.

## H3 Забывание после отмены причинной предпосылки

Запись содержит условие применимости и наблюдение, на котором основано действие. После конкретного нового наблюдения возможны три решения — сохранение, временный запрет использования, запрос проверки. Запрет обратим, что позволяет позднее восстановить опыт после возврата условия. Работающая гипотеза — selective suspension снижает цену агрессивной инвалидизации для обратимых смен состояния.

Invalidation Contracts уже предоставляют точные версии и row diff. Hierarchical Caching уже инвалидирует зависимости. Проверять нужно именно частичную наблюдаемость, когда инструмент не выдаёт полный контракт. Сильный baseline хранит последние точные значения по ключу и детерминированно заменяет их. Дополнительный baseline имеет oracle dependency metadata и задаёт верхнюю границу.

Предсказание — suspension помогает на возврате ранее валидного состояния, одновременно не увеличивая долю stale-action execution. Опровержение — нет выигрыша при равных mutable-state наблюдениях и числе проверок, либо выигрыши появляются лишь за счёт доступа к будущему diff. Дизайн должен иметь независимые task trajectories, фиксацию drift до метода, пару сред с одинаковым исходным snapshot и полноценную оценку всех реально выполненных действий.

## Граница текущих результатов

E2 реализовал только узкий probe прошлого DOM UID. Он не дал подтверждения H2 или H3. Следующий выбор лучше делать после сопоставления сильного actor и полноценного environment, сохранив три уровня сравнения — текущая история, стандартная память, исследуемый механизм. Решение о новизне требует просмотра исходников найденных методов и отдельного теста на тех же задачах и бюджете.

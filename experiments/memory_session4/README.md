# Исследования рабочей памяти агентов
## Четвёртая серия от 17 ноября 2026

Эта папка содержит новые эксперименты и целевой обзор публикаций. Полный читаемый отчёт находится в архивной папке delivered в форматах DOCX и PDF. В рабочем каталоге опубликованные документы находятся в соседнем outputs.

Основные результаты и ограничения изложены в action/summary_ru.md, compact/summary_ru.md, discovery/summary_ru.md и handoff/summary_ru.md. Дополнительный критический выбор следующих гипотез находится в next_hypotheses_review_ru.md. Исходы всех вариантов, включая проигрыши, сохранены.

## Содержание

- action содержит временной replay настоящих повторов CI, online feedback, сравнение с FTRL и два временных job-level теста.
- compact содержит обновление наблюдавшихся строк кода, 256/512/1024-токенные условия, строгие сильные контроли, физическое подтверждение правок и полный token audit.
- discovery содержит WebLINX E1, post-result current-history контроль E3, DOM-grounding E2, источники и аудит доступности свежих benchmark artifacts.
- handoff содержит новые native Qwen-reader вызовы, точные входы и ответы, sealed решения, исходные байты 1 441 официального отчёта, bootstrap vectors и аудит связи tool trajectory с итоговым patch.
- handoff/attestation/external содержит дополнительный census 52 каталогов и 984 заранее выбранные пары из 41 совместимого каталога.
- runtime содержит model/binary receipts, настройки сервера, все успешные запросы и resource logs. Смена backend описана в handoff/BACKEND_AMENDMENT.md.
- report содержит сборку и проверку оформления документа. Его bundled DOCX runtime и LibreOffice нужны только для повторной генерации документа.

## Локальная проверка без сети и новой генерации

Запустить из распакованного корня с Python 3.12 или более новой версией. Проверенный основной интерпретатор этой серии — CPython 3.14. Для четырёх основных verifier достаточно стандартной библиотеки.

```powershell
python -B action/verify.py
python -B compact/verify.py
python -B discovery/verify.py
python -B handoff/verify.py --require-report-bytes
python -B handoff/verify_patch_identity.py
python -B handoff/attestation/external/verify.py
```

Последний verifier при доступном Git дополнительно пересчитывает stable patch-id. При недоступном Git сравнения сохранённых байтов и SHA остаются доступны. Полный пересчёт токенов compact запускается с tokenizers и сохранённым qwen_tokenizer.json.

```powershell
python -B compact/verify.py --tokens
```

Файл MANIFEST.sha256.json в корне ZIP позволяет проверить каждый включённый файл. distribution_verified.json фиксирует запуск из отдельной распакованной копии. test_distribution.py создаёт новый выделенный каталог на D и намеренно требует, чтобы его ещё не существовало.

## Получение и повторная оценка

Скрипты fetch/collect/project/read описаны в локальных REPRODUCE и протоколах серий. Внешние источники закреплены ревизиями, URL, ETag и SHA. Полное восстановление исходных авторских архивов требует интернета и дополнительных requests/pyarrow/tokenizers. Raw WebLINX страницы в пакет не входят, для офлайн-проверки сохранены проекции идентификаторов, действий и геометрии. Большие исходные BSON/parquet загрузки и временные офисные профили находятся вне распространяемого пакета. Публичные исходные trajectories можно повторно получить по записанным URL и сверить их первоначальные digest.

Повторный запуск grader использует уже сохранённые решения и официальные исходы, GPU не требуется. Изменение writer/reader или числа условий создаёт новый эксперимент и требует новой фиксации входов и бюджетов. Старые sealed результаты не перезаписываются.

## Важные уточнения

Названия моделей у части публичных траекторий прежней серии требуют исправления, подробности в handoff/HANDOFF_CORRECTION.md. Основной handoff использует подтверждённую пару Claude/Gemini. Официальные исходы относятся к историческим runs разных исполнителей. Репозиторные тесты всех patch заново в едином harness в этой серии не запускались.

Из 1 464 реальных новых вызовов Qwen3.8-27B 1 455 выполнены на RTX 3090. После CUDA failure девять последних запросов дополнительного strict arm завершены на CPU с тем же GGUF. Основные сравнения памяти полностью выполнены до сбоя на GPU. Для strict сохранена отдельная проверка 87 полных GPU-пар. Native сервер после завершения остановлен.

Установлены ограниченные положительные эффекты относительно некоторых контролей, несколько сильных контролей объяснили исходные выигрыши. Подтверждение превосходства нового метода над SOTA остаётся целью следующих сопоставимых live-экспериментов. Литература и критерии выбора следующих направлений включены в отчёт.

# Предобученная модель поиска кода как контроль графовой памяти

Замораживаем план до построения новых прогнозов и до чтения индивидуальных меток. Итоги сравнения прежних ненейронных методов по панелям уже известны. Отдельный контроль SweRank на Loc-Bench в прежних сериях относится к другому пулу и другой единице релевантности. Обе оценочные панели здесь повторно используются.

**Вход.** Все 267 и 73 ранее запечатанных события VibeMemBench после пустого поиска из R13/reformulation и replication. Доступны ровно пути и фрагменты ранее наблюдавшихся Python-файлов, текущие область, литерал и условие задачи. Пустое меню возвращает пустой список. Файлы целиком, последующие наблюдения, PR и Git-дерево недоступны методу. Проверяем контрольные суммы старой фиксации и множеств кандидатов. Объединять панели для основного вывода не будем.

**Гипотеза.** Добавление структуры к замороженному dense retrieval улучшает выбор будущего изменённого файла относительно равноправного объединения того же dense retrieval с исходным лексико-временным контролем. Основная оценка — парная разность Hit@1 для производственных Python-файлов прямого PR в повторной панели. Поведенческая вторичная оценка — попадание в первое распознанное успешное чтение; отдельно прямые чтения и все Python-файлы патча. Для каждой показываем H@1, H@3, MRR, число событий, задач и достижимость. Для парных разностей — кластерный bootstrap задач отдельно по панелям (5000 выборок, seed 301754, percentile, повторные события задачи остаются вместе). Интервалы описательные, множественные вторичные сравнения без поправки.

**Модель.** Salesforce/SweRankEmbed-Small 137M, фиксированная ревизия 745d2a06103a66d3cfa600aa52fc0d3523010daa, выпуск под CC BY-NC 4.0. Берём уже сохранённые веса. Query = официальный префикс + литерал и область пустого поиска + исходное условие задачи, в таком порядке, candidate = путь + перевод строки + запечатанный фрагмент. Fp32 CPU, CLS + L2 + cosine, максимум 512 токенов на текст (пример авторов), batch 8. При равной оценке используем последнюю позицию в префиксе и лексикографический путь. Вторичные абляции — кандидат только по пути при том же запросе, а также чистый текст задачи по тому же полному кандидату. По итогам параметры не выбираются.

**Ранжирования.** Базовые виды R13 — strong, graph, shuffled, last_scope, bm25 и граф с равными массами начальных узлов (uniform). Для каждого из strong, graph, shuffled и uniform объединяем его замороженные ранги с dense одним и тем же Reciprocal Rank Fusion, k=60, равный вес: sum 1/(60+r) по двум спискам, позиции с единицы. Для равной суммы общий tie-break по давности и пути. Это контролирует вес добавочной модальности. Сравнения только рангов без настройки смеси. Отдельно raw dense и dense+graph против graph. Выборка со всеми подтверждёнными исходами, включая недостижимые и пустые меню (результат 0); цензурированные исходы исключаем из соответствующего знаменателя. Проверяем воспроизведение агрегатов R13. Инференс работает в отдельном процессе, который не открывает файлы меток; полные прогнозы и исходные скаляры фиксируются хешами перед вызовом оценщика.

**Цена.** Размер весов, версия backend, CPU-потоки, время на кодирование и сравнение, число текстов, пар и пустых меню. Межпрефиксная дедупликация одинаковых байтов — ускорение офлайн-оценки; для нового префикса дополнительно указываем число новых документов и верхнюю границу числа вызовов. Стенд оценивает чтение уже доступной долговременной памяти. Официальные Func@k в других задачах с полным корпусом функций не являются численным эталоном данной постановки.

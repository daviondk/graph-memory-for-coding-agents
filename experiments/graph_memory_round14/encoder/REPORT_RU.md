# Даёт ли граф агентной памяти прибавку поверх предобученного поиска кода?

Сравнили граф R13 с опубликованным биэнкодером SweRankEmbed-Small на 340 событиях после безрезультатного поиска в реальных историях кодовых агентов. На основной панели граф, объединяющий текст, давность и связи по общим идентификаторам, чаще ставил первым будущий изменённый файл, чем чистый SweRank. На повторной панели оценки сблизились. Основная гипотеза о добавочной ценности структуры при объединении с нейронным поиском подтверждения не получила. На повторной панели обе системы выдали одинаковый результат Hit@1 во всех 45 размеченных событиях.

## Что сравнили

Использовали тот же вход, меню и разметку, что в R13. После пустого поиска агент может заново прочитать один из уже известных Python-файлов. Запрос нейросети содержит литерал, область и исходное условие задачи. Каждый документ состоит из ранее наблюдавшегося пути и фрагмента текста. Файл патча размечен только при строгом совпадении исходной версии с базой PR. Фактическое следующее чтение ищется среди следующих пяти вызовов. Каждая метрика начисляет ноль, если ни один подходящий файл недоступен. Состав выборки зафиксирован до новых прогнозов. Предыдущие контрольные показатели панелей уже были публичны в этом исследовании.

В основной панели 267 меню, в повторной 73. Из 2025 пар запроса с кандидатом 1795 и 230 приходятся на соответствующие панели. В 46 и 8 меню не было ни одного файла. Цель патча присутствовала в 137 из 191 и 35 из 45 размеченных меню. Ближайшее успешное чтение — в 114 из 176 и 32 из 58. Следовательно, пополнение меню и ранжирование доступных файлов остаются отдельными задачами. Показатель ближайшего чтения отражает наблюдаемое поведение агента и может расходиться с полезностью чтения для решения issue. [VibeMemBench](https://arxiv.org/abs/2609.23570)

Контроль strong из R13 объединяет BM25, давность просмотра и близость пути к области поиска. Граф добавляет распространение балла по общим редким идентификаторам от трёх сильнейших исходных файлов. Контроль uniform задаёт равную массу всем начальным узлам, shuffled переставляет наборы идентификаторов. Нейронные веса не дообучались. Официальное преобразование строки включает поисковый префикс, CLS-представление и косинус после L2-нормировки. Для каждого варианта RRF использовано одно правило с равным весом модальностей и k=60. Полные списки и три нейронные оценки каждой пары зафиксированы до чтения индивидуальных исходов. [SweRank](https://arxiv.org/abs/2505.07849) · [Веса и лицензия](https://huggingface.co/Salesforce/SweRankEmbed-Small/tree/745d2a06103a66d3cfa600aa52fc0d3523010daa) · [RRF](https://cormack.uwaterloo.ca/cormack/cormacksigir09-rrf.pdf)

## Результаты

В каждой ячейке указаны число попаданий на первом месте, число попаданий в тройку и MRR. Знаменатель общий для всех методов внутри столбца. Пустые меню с известной целью включены.

| Метод | Файл патча, основная, 191 | Файл патча, повторная, 45 | Следующее чтение, основная, 176 | Следующее чтение, повторная, 58 |
|---|---:|---:|---:|---:|
| BM25, давность и путь (strong) | 86 / 123 / 0,553 | 26 / 33 / 0,653 | 59 / 95 / 0,450 | 21 / 28 / 0,438 |
| Граф с тремя начальными узлами | 91 / 126 / 0,565 | 28 / 32 / 0,674 | 60 / 92 / 0,450 | 22 / 29 / 0,450 |
| Граф с равной начальной массой | 90 / 127 / 0,568 | 29 / 33 / 0,694 | 59 / 94 / 0,447 | 20 / 29 / 0,430 |
| SweRank по запросу и фрагменту | 76 / 118 / 0,517 | 27 / 33 / 0,670 | 55 / 94 / 0,426 | 22 / 28 / 0,439 |
| SweRank + strong | 87 / 122 / 0,555 | 29 / 33 / 0,695 | 57 / 93 / 0,443 | 20 / 27 / 0,423 |
| SweRank + граф | 86 / 123 / 0,557 | 29 / 33 / 0,699 | 57 / 95 / 0,441 | 21 / 27 / 0,432 |
| SweRank + граф с перемешанными связями | 80 / 121 / 0,534 | 29 / 33 / 0,691 | 55 / 94 / 0,433 | 21 / 27 / 0,432 |

**Основное парное сравнение.** Разница Hit@1 между SweRank + граф и SweRank + strong на будущих файлах патча составила −0,52 п.п. в основной панели (3 выигрыша, 4 проигрыша, 184 совпадения, 95% кластерный интервал от −3,39 до +2,14 п.п.). В повторной панели разница нулевая при 45 попарных совпадениях исхода. Любой bootstrap этой конкретной выборки также даёт ноль. Это ограничивает информацию о вероятности расхождения в других задачах. Для MRR разницы составили +0,0020 [−0,0149 … +0,0178] и +0,0037 [0,0000 … +0,0119]. При равном весе задач разницы Hit@1 составили −1,46 и 0 п.п. Основная и повторная панели содержали 120 и 31 задачу с проверенной целью патча.

**Граф как отдельный метод.** Разница Hit@1 графа и чистого SweRank на файлах патча составила +7,85 п.п. в основной панели [+0,49 … +15,43] и +2,22 п.п. в повторной [−7,69 … +11,63]. Этот контраст сравнивает системы целиком. У графа есть информация о давности и положении пути. Контроль strong без распространения по рёбрам также набрал 86 против 76 попаданий чистого SweRank в основной панели. Граф и SweRank дали 60 и 55 попаданий из 176 в основной панели, 22 и 22 из 58 в повторной.

**Влияние формулировки запроса.** На основной панели чистое условие issue дало SweRank 83/191 в поиске файла патча и 39/176 в прогнозе следующего чтения. После включения области и литерала получены 76/191 и 55/176. На повторной панели соответственно 26/45 и 21/58 для одного условия, 27/45 и 22/58 для полного запроса. Это наблюдение помогает различать цель «найти файл, который изменили» и цель «предсказать ближайший шаг». Порог переключения между ними на этих данных не подбирали.

Во всём независящем от исходов меню объединение с графом изменило файл на первом месте против объединения с strong в 16 из 267 и 1 из 73 событий. У SweRank + граф равенство балла RRF за первое место потребовало разрешения по прежней давности в 32 и 13 непустых меню. Таким образом, небольшой сдвиг MRR при одинаковом Hit@1 может отражать изменения глубже в списке. Остальные исходы, интервалы, равномерный граф, чистый BM25 и абляция текста документа приведены в [полных таблицах](TABLES_RU.md).

## Стоимость

Использованы AMD Ryzen 7 8700F, четыре потока PyTorch, float32, без GPU. Размер опубликованных весов на диске 273 474 944 байта, проверенного скачанного комплекта модели 274 474 917 байт. В работе использовались 137 млн параметров. Максимум входа — 512 токенов, до усечения дошли 198 из 1512 уникальных документов и 2 из 280 уникальных основных запросов. При дедупликации идентичных строк их кодирование заняло 312,2 и 83,1 с. Две абляции потребовали ещё 18,6 с для путей и 56,7 с для текста issue. Четыре объединения рангов и расчёт скалярных оценок при готовых векторах заняли 0,018 с на обе панели.

На заранее выбранных 12 непустых меню размером 1–14 файлов измерили одно обращение при загруженных весах. Медиана составила 285 мс для кодирования запроса и ранжирования при готовых векторах документов и 1556 мс с кодированием всех документов (диапазоны 96–356 и 152–5391 мс). Все 12 первых мест совпали с пакетными прогнозами. Это целевая выборка по размерам меню, она не оценивает распределение времени в продукционной системе. Полностью пересчитанный strong в исходном Python-коде занимал в среднем 1,19 и 1,06 мс на событие, графовый шаг добавлял 0,139 и 0,105 мс в соответствующих панелях. При таком размере известной памяти простой граф остаётся дешёвым самостоятельным вариантом.

## Граница вывода

В результате получена прямая проверка одного опубликованного предобученного биэнкодера и его предопределённых комбинаций на запечатанных префиксах. Использовано ограниченное историей меню, полные файлы модели недоступны. Обучающие данные SweRank собирались из публичных репозиториев, независимость предобучения от каждого issue здесь не проверялась. Числа официальных таблиц SweRank для полного корпуса функций и официальный downstream-балл VibeMemBench отвечают другим вопросам. Для утверждения о выигрыше графовой структуры требуется раздельная проверка источника прибавки и переноса на самостоятельные исправления. В текущем опыте наиболее заметен выигрыш дешёвого полного графового ранжировщика над чистым биэнкодером на одной панели.

# Воспроизводимость нейронного контроля

В папке находятся неизменяемые прогнозы, исходные скалярные оценки для каждой пары «запрос — файл», полные списки каждого метода, позиции первого релевантного файла и целевые пути для всех оцениваемых исходов. Внешним входом служит ранее опубликованная проекция префиксов. Необязательные межпрефиксные сокращения вычислений ограничиваются повторным использованием вектора идентичной строки.

## Проверить готовые результаты

Из этой папки выполнить команду `python -B verify.py` на стандартной библиотеке Python 3. Она перепроверяет SHA256, все порядки по нейронным оценкам, четыре варианта RRF с общим разрешением равенств, пересечение меню с целью и агрегаты каждого прогноза. При изменении или исчезновении члена манифеста проверка завершится с ошибкой. Файл `evaluation_rows.json.gz` содержит только уже раскрытые целевые пути и позиции; `predictions.json.gz` содержит исключительно прогнозы.

## Повторить инференс

В опубликованной структуре соседних серий нужны каталоги `graph_memory_round13/reformulation` с подпапкой `replication` и `graph_memory_round8/retrieval` с контрольными суммами модели и backend. Путь к R13 можно переопределить переменной `PREFIX_REFORMULATION`. В качестве готового runtime на этом компьютере использован `D:/CodexResearch/x20-r8-swerank-runtime`. Путь к нему меняется переменной `SWERANK_TEMP`. Требуются его `model` и `snowflake_cpu`. Файлы весов, конфигурации и токенизатора сверяются с `input.lock.json`. В отдельном каталоге окружения доступны зависимости экспериментов R8; полное имя Python здесь — `D:/CodexResearch/x20-r8-swerank-runtime/venv/Scripts/python.exe`. Версии библиотек указаны в `inference.json`. На другом компьютере можно скачать файлы `model_files` с опубликованной ревизии и два Python-файла backend с опубликованной ревизии Snowflake, поместить их в каталоги с теми же именами и создать пустой `snowflake_cpu/__init__.py`. [Оригинальные веса](https://huggingface.co/Salesforce/SweRankEmbed-Small/tree/745d2a06103a66d3cfa600aa52fc0d3523010daa) · [CPU-совместимый backend](https://huggingface.co/Snowflake/snowflake-arctic-embed-m-long/tree/92d97331f1f4b6a366c1f161354b9f3390cc219f)

Инференс заново проводить в рабочей копии архива. По порядку выполнить `python -B capture_ties.py`, `python -B forecast.py`, `python -B grade.py`, `python -B diagnostics.py`. Первые два процесса имеют доступ только к входам и ранее зафиксированным порядкам. Оценщик сначала проверяет фиксацию новых прогнозов, затем открывает файлы исходов. `grade.py` независимо пересчитывает метрики всех шести контрольных методов R13 и сверяет их с обеими оригинальными таблицами. Время в новом запуске изменится, поэтому новый файл `inference.json` и его контрольная сумма могут отличаться; скалярные оценки зависят от реализации CPU линейной алгебры. Для контроля рангов следует сравнить `predictions.json.gz` с эталонным.

Для повторения вторичных измерений выполнить `python -B latency.py` при свободном CPU и `python -B tables.py`. План выбора 12 меню находится в [LATENCY_PLAN.md](LATENCY_PLAN.md), разбиение по числу кандидатов — в [DIAGNOSTICS_PLAN.md](DIAGNOSTICS_PLAN.md). Для выпуска нового комплекта после проверки файлов служит `python -B package.py`. Команда перезаписывает манифест лишь в текущей рабочей копии.

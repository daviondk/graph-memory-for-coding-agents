# Четырнадцатая серия. Сильные контроли для графовой памяти

**Ограничением при выборе следующего файла оказался состав доступных кандидатов.** На новом наборе 30 задач Qwen самостоятельно исчерпал все достижимые попадания в будущий патч на строгой панели. Отдельно воспроизведено снижение объёма чтения пользовательских данных в подлинном инструменте OctoFS на трёх файловых системах. Это выигрыш по вводу-выводу. Устойчивого превосходства графа по доле решённых задач на полном опубликованном бенчмарке пока нет.

## Приоритет для статьи

В локализации перспективнее исследовать, может ли агент с начала работы дёшево сохранять адреса **ещё не открытых** файлов, уже появившиеся в tool output, и вернуть их ровно тогда, когда фактически прочитанные кандидаты исчерпаны. Контроли должны иметь тот же бюджет видимых файлов. При записи успешных проверок отдельного изучения заслуживает достоверность ребра «версия → прошедший тест», в частности несоответствие между кодом последнего звена pipeline и исходом проверяемой программы. Формально дешевизна проверки актуальности имеет смысл только при достаточной доле повторов, при которых она заменяет более дорогое полное чтение. Платформенная репликация показала, что специальные метаданные могут повысить устойчивость к определённому классу обновлений и при этом почти не добавлять пользы на обычном выпуске.

Сопоставление с результатами статей ограничено одинаковым протоколом. В нашем опыте SweRank ранжировал уже виденные артефакты; числа из полного бенчмарка авторов к этой панели неприменимы. Работу Ledger учитывали при выборе вопроса. В доступных источниках авторскую реализацию inform/govern идентифицировать не удалось, поэтому для проверки чтения использован OctoFS. Все нулевые, положительные и отрицательные исходы сохранены. [Независимое воспроизведение](REPRODUCE_RU.md)

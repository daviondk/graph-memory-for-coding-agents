# Запуск и аудит

Нужен неизменённый соседний каталог ../ledger с манифестом 0c411ba80b4157db16fadbd705c08dd9807013cc683bac982140437ed7ba4722. Для пересчёта метрик, проверки фактических syscall и содержания без Linux-сервера или доступа к сети выполните:

```powershell
python -B audit_linux.py
python -B verify_payloads.py
python -B field_ablation.py
```

Первый скрипт сравнивает каждый нативный read с измеренным целевым файлом и временным интервалом настоящего MCP-обращения, включая нулевые обращения при совпадении метаданных. Проверка полезной работы сравнивает восстановленное из ответов состояние с ранее замороженным SHA источника истины. Хеши входных файлов и их лицензии хранятся в ../ledger.

Для нового полного запуска на том же хосте команды следующие:

```powershell
python -B get_linux.py
python -B trace_deps.py
wsl.exe -d CodexX20MSR -- python3 -B run.py
wsl.exe -d CodexX20MSR -- python3 -B run.py --trace
wsl.exe -d CodexX20MSR -- python3 -B stat_probe.py
python -B audit_linux.py
python -B verify_payloads.py
python -B field_ablation.py
```

Linux-процессы используют /tmp на ext4 и /dev/shm на tmpfs. Для каждой части создаётся отдельный временный каталог с проверенным исполняемым файлом. Образ WSL, системные пакеты и сервисы не меняются. strace 6.13 и нужные библиотеки скачиваются из официального репозитория Alpine 3.22 в локальный vendor. Сырые файлы трассировки на временном томе после извлечения наблюдений удаляются. В каталог исследования записываются полные строки strace, относящиеся к выбранным путям, и все MCP-запросы и ответы. MCP-время, pid, gid, inode и абсолютный путь временного каталога при новом запуске могут отличаться.

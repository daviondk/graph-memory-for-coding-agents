# Ретроспективная оценка промежуточных состояний

Вслед за Yang и соавторами оцениваем промежуточные наблюдавшиеся версии реальным скрытым тестом и сравниваем правила выбора, которым этот тест недоступен. Публикация — Done, But Still Working: Anytime Evaluation of When Coding Agents Should Stop, arXiv:2611.22901. В исходной работе использовались другие проекты, модели и объём данных. Настоящий анализ фиксируется после завершения R13 и до получения новых промежуточных меток. Итоги выбранных ранее последних снимков R13 уже известны: flake8/raw решён, остальные три — нет.

**Когорта.** Все 4 эпизода в запечатанном R13/selection.json из 2 отдельных задач и 236 событий наблюдения. Два ранее завершённых эпизода исходной R12 ранее исключены. У flake8/base наблюдение началось с задержкой. Ни один эпизод не подменяем после оценки. SHA256 и байты каждого снимка сверяем с неизменяемыми журналом и архивом. Каждой паре (задача, байты diff) ставим один официальный результат, повторно используемый только внутри той же задачи, с проверкой полного байтового равенства. Новые прогоны выполняются через оригинальный run_eval.evaluate_seed и vendor в локальном Docker R12 без сети и с 0,5 CPU. Для переиспользованных исходов даём исходный SHA отчёта. Пустой diff остаётся исходом «не решено, unit-тесты не начались».

**Стратегии до новых меток.** (1) Последний зафиксированный diff в наблюдаемом потоке. (2) Первый непустой diff; при его отсутствии стратегия воздерживается. (3) Последняя наблюдавшаяся версия с видимым успешным тестом с достоверной привязкой. Принимаем одиночную команду pytest либо python -m pytest с необязательным cd /testbed &&; исключаем конвейеры, сложные команды, фоновое исполнение и маскирование кода возврата. Требуем код 0 и явный успешный итог pytest с положительным числом пройденных тестов. Для привязки используем предыдущий опрос diff и следующий по окончании теста с одинаковыми байтами, из того же эпизода, не более 15 секунд до начала и после конца вызова; между этими снимками не должно быть другого инструментарного действия. Объединённые многоинструментные сообщения и случаи неоднозначного времени приводят к воздержанию. Такой двусторонний прикладной контроль не эквивалентен инструментированию самого pytest; доступность в потоке указываем по факту. (4) Один git diff в самом конце — сильный простой контроль: наблюдатель записал только результаты периодических опросов и затем контейнер был удалён. Отдельной точки съёма после последнего действия/перед удалением нет. Исполняемый суррогат — передать только последний доступный снимок, удалив из памяти все прежние. Побитовое равенство его входа со стратегией (1) проверяем. Официальная фактическая submission из R12 — дополнительная точка сравнения. Никогда не используем официальный скрытый успех как сигнал выбора; oracle «хоть один когда-либо прошёл» только диагностический верхний предел.

Сначала фиксируем индекс состояний и решения стратегий без доступа к промежуточным меткам; после их SHA запускаем grader. На эпизод показываем порядок версий, число независимых SHA и переходов, когда впервые увидена проходящая версия, исчезла ли она потом, время относительно первой и последней точки наблюдения и накопленный номер модельного запроса. Оценим также uncompressed/gzip полезной нагрузки полных снимков без дедупликации, с дедупликацией и только для последнего, реальные байты журнала отдельно. Разделяем наблюдаемое время от возможного сокращения времени и не интерпретируем записи одного эпизода как независимые прогоны. Малый объём не позволяет выводить эффект ранней остановки на популяции.

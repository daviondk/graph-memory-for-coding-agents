# Актуальность сохранённого наблюдения кода

Основной вопрос — может ли кодовый агент безопасно повторно использовать адрес и текст уже выполненного чтения после обычной внешней правки. Первой проверяется идентифицируемость полноценного авторского Ledger по ссылкам публикации, персональной странице, GitHub автора и предыдущим локальным запускам. Для недоступного артефакта отдельно описываются опубликованное описание и доступная ближайшая реализация настоящего MCP-инструмента просмотра. В качестве ближайшего публичного инструмента выбран Muvon/octofs 0.25.2 с целым повторным view в одной сессии. В проекте R11 ранее проверялся другой инструмент sqz на задаче сжатия результатов. Локализация, решатель и Pass@1 не входят в эту постановку.

До измерений фиксируем четыре обычных репозитория из открытого корпуса кода — Click, attrs, Hypothesis и PyYAML. В каждом берём первые до трёх доступных производственных .py-файлов по хеш-порядку с 30–180 строками без CRLF, UTF-8 и табуляции. Воспроизводим фиксированный cut выбранного официального выпуска или коммита. Лицензии и источник содержимого сохраняем. Если отбор в лимитах пуст, фиксируем нулевое покрытие репозитория. Контролируемые изменения поверх реального кода создаёт отдельный процесс, исходные checkout не изменяем.

Для каждого файла независимо показываем одинаковую изначальную копию, затем 7 событий: повтор без изменения, касание даты файла, изменение соседнего файла, замена одной строки комментарием той же длины при обычном времени, такая же редакторская замена с сохранённым исходным mtime, замена файла через атомарную запись с сохранением исходного mtime и размера, добавление смыслового комментария в конец файла. Инструмент получает один сеанс для пары чтений с новым путём для следующей пары. Измеряем правильность подавления неизменившегося ответа, восстановимость ожидаемых изменённых строк/полного представления, ошибочные сообщения об отсутствии изменений, размер сообщения на проводе, возможный размер дисковых чтений отдельно от размера ответа. Если исходник адаптера читает полное содержимое каждый раз, учитываем это как источник обоснованной логической оценки байтов наряду с наблюдаемыми размерами. Сравниваем фактический MCP view, всегда повторное чтение, байтовое сравнение за один проход, простой mtime+size, тот же валидатор с file identity и проверку выбранной области прямым чтением. Для ограниченного чтения задано окно 8 строк, включающее изменяемую строку. Для него используются отдельный источник истины и отдельный знаменатель, если поддерживается штатная семантика. Контролируемое сохранение mtime — намеренный стресс-тест, его частота в эксплуатации неизвестна. Условие сценария не доступно проверяющей политике.

Для дешёвого контрольного отпечатка whole-file сравнение проводится с тем же бюджетом видимости, чтение источника и ответ пользователю учитываем раздельно. В конце проверяем восстановление состояния и перенос после изменения представления. Воспроизводимость — пин официальной версии, подлинность исполняемого файла, полные запросы/ответы MCP построчно, сценарии с хешами до/после, дополнительное аудируемое извлечение агрегатов. Код оригинального инструмента не меняем.

# Помогает ли имя, связывающее два просмотренных файла, выбрать следующий файл

**На этой панели явное предъявление общего идентификатора не улучшило выбор следующего файла.** На 19 задачах со строгой Git-разметкой Qwen3.8-27B открыл изменённый в PR файл в 12 случаях при предъявлении двух путей и общего имени и в 13 случаях при предъявлении тех же путей без имени. Вариант без подсказки тоже дал 13/19. Это был потолок доступного меню: в остальных шести задачах ни один предложенный файл не принадлежал подходящим изменениям PR. ## Отбор и проверка действия

Из 376 исходных историй из пяти заранее зафиксированных репозиториев 22 исключили по тексту задачи. Среди остальных обнаружили 111 численно подтверждённых пустых поисков. В 66 префиксах нашлась подходящая связь между файлами, это 47 различных задач. Для каждой задачи использовали первый подходящий префикс. Взяли 30 задач по фиксированному хеш-порядку. В итоге 19 задач поступили из Moto, 10 из cfn-lint и одна из pandas-ai. Каждому из четырёх вариантов модели показали одинаковый текст задачи, пустой поиск и меню до шести уже адресованных файлов в одинаковом порядке. Модель возвращала ровно один вызов read_file. Условия сравнивались попарно внутри задачи. [Протокол](PROTOCOL_RU.md) · [Отбор](flow.json) · [Снимки до действия](cases.gz)

Перед вскрытием меток зафиксированы SHA всех решений и фактов открытия файлов. Во всех **120/120** обращениях модель выбрала допустимый путь и файл реально открылся по точному SHA исходной версии. По отдельному Git-зеркалу оценщик прочитал 40 разных троек «репозиторий, ревизия, путь». SHA-256 и объём совпали с приёмкой каждого открытия во всех 120 случаях. Основной исход — открытый .py-файл, существовавший до PR и вошедший в производственную часть патча. Первый родитель merge-коммита должен в точности совпасть с base из бенчмарка. В 9 задачах исходные SHA различались, в 2 при совпавшей версии в патче не было подходящего изменения. Остались 12 задач Moto и 7 cfn-lint. Второй исход — первый реально успешный просмотр одного Python-файла в той же рабочей папке за следующие пять вызовов bash прежнего агента. Он наблюдался в 25 задачах, в 16 из них адрес содержался в меню. ## Что позволяет утверждать сравнение

Добавление имени изменило адрес **1 раз из 30**. По попаданию в PR в этой паре 0 выигрышей, 1 проигрыш и 18 совпадений. Разница −5,3 п.п., точный двусторонний парный тест p=1,0. Процентильный bootstrap по 19 задачам дал интервал [−15,8; 0,0] п.п. Он отражает повторную выборку единственного наблюдаемого расхождения, поэтому доказательств общего вреда также недостаточно. Сравнение имени с отсутствием подсказки дало 5 смен адреса на 30 задачах, по строгому патчу — 0 выигрышей и 1 проигрыш. Сравнение имени с одним рекомендованным путём дало 8 смен, по патчу — 1 выигрыш и 1 проигрыш. Простая рекомендация увеличила выбор своего адреса с 19 до 26, но количество попаданий в патч уменьшилось с 13 до 12. [Все парные контрасты](results.json)

Единственное расхождение между условиями с двумя путями произошло в cfn-lint. При добавлении идентификатора collections модель сменила изменённый в PR файл _resolvers_cfn.py на _filter.py. Пример показывает, почему «редкое среди малочисленных фрагментов» не гарантирует, что имя различает подходящую реализацию и соседний модуль. [PR cfn-lint №3439](https://github.com/aws-cloudformation/cfn-lint/pull/3439)

Лексика условий частично совпадала. В 24/30 задачах имя уже встречалось в общем описании, литерале или фрагментах кода. При учёте путей и других полей общего меню таких задач **26/30**. В обоих видимых отрывках связанной пары имя одновременно встречалось в 5 задачах, в одном — в 15 и ни в одном — в 10. Из четырёх задач, где общее меню вообще не содержало имени, только две получили строгую PR-метку. Это ограничивает вывод о добавлении действительно новой информации. Результат обосновывает более узкую гипотезу для дальнейшего исследования: принесёт ли выгоду дополнительная проверяемая запись в ситуациях, где пользователь меню ещё не видит её содержания и где сохраняется пространство для улучшения самостоятельного выбора. Гарантировать рост качества исправлений по этому опыту нельзя.

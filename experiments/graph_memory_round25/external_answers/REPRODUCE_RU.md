# Воспроизведение проверки на QASPER v0.3

1. Из этой папки запустить fetch.py для скачивания официального тестового архива AI2 и нативного токенизатора Qwen. Файлы и приватный кэш располагаются в D:/CodexResearch/x20-r25-qasper. Хеш архива сверяется с контрольной суммой AI2; распаковка по явному списку создаёт три файла. Вопросы и адреса разрешается восстанавливать по публичным ID из selection.json. [Ревизия загрузчика](https://huggingface.co/datasets/allenai/qasper/blob/7bde7e4a9f805bed6c6e79e664c37057263dbc1d/qasper.py)
2. Запустить prepare.py, затем blind_audit.py. Подготовка выносит документ и вопрос в отдельное представление без разметки. Код основной политики напрямую импортируется из соседних серий R23 и R24. Зафиксированные хеши реализаций и обоих токенизаторов находятся в input-lock.json. BM25 ранжирует блоки внутри конкретной статьи. Абстракт и заголовок входят в первоначально доступный корпус, фиксированный заголовок добавляется всем четырём reader-входам.
3. Запустить infer.py с локальным llama-server и с проверяемым файлом весов Qwen, SHA256 3605803b982cb64aead44f6c1b2ae36e3acdb41d8e46c8a94c6533bc4c67e597. На машине для исследования использованы Ryzen 7 8700F, два потока CPU, Python 3.12.13, tokenizers 0.21.4, NumPy 2.5.5 и SciPy 1.18.1. По умолчанию входы независимы, запросы проходят в детерминированном хешированном порядке, очередной вход содержит только вопрос, заголовок и выделенный ему контекст. Совпавшие полностью входы используют один и тот же ответ. progress.json показывает завершённые уникальные входы. Повторный запуск использует кэш, только если совпадают программа, система, настройки, веса и манифест входов. Полные промпты и исходные ответы хранятся только локально. [Модель Qwen](https://huggingface.co/Qwen/Qwen3-4B-Instruct-2507/tree/cdbee75f17c01a7cc42f958dc650907174af0554)
4. После появления forecast-seal.json запустить score.py. Он сверяет приватные ответы с публичными хешами, использует исходные функции AI2 и записывает результаты по каждому вопросу и методу. Эти промежуточные данные позволяют пересчитывать парные контрасты без публикации статей и буквальных ответов. Для повторной полной оценки официальный архив содержит разметку. [Официальный архив с оценщиком](https://qasper-dataset.s3.us-west-2.amazonaws.com/qasper-test-and-evaluator-v0.3.tgz)

Технический журнал содержит фактические токены входа/выхода и число обращений. Колонка wp_source_read учитывает извлечённое по одному адресу до усечения, wp_delivered — реально пересланную после усечения дополнительную часть. В replay дополнительный фрагмент повторяет кэш и не обращается в источник. Бюджет генерации составляет 64 токена, реальная длина зависит от ответа. Политика чтения видит только уже переданный текст и длину поля, начальный BM25 использует весь текст статьи. Одно случайное по хешу наблюдение на статью даёт одинаковый вес статьям, в официальном среднем одинаковый вес получает каждый вопрос.

Политика выбора evidence в этом опыте сообщает ID всех исходных абзацев, пересечённых фактически переданным текстом. Официальный Evidence F1 применяется к этим ID по строкам. Это метрика локализации источника. Для совершенно невидимой части абзаца сигнал может быть положительным, поэтому отдельно приводится покрытие его символов. В оценке используется text_evidence_only, как допускает официальный скрипт, изображения таблиц не читаются. Вопросы с отсутствием текстового свидетельства остаются в общем Answer F1.

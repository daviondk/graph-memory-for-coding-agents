# Последовательные обращения к памяти

Одно нужное чтение не определяет оптимальную политику на нескольких шагах. Проверили пять способов выбрать источник до четырёх раз подряд. Каждое действие может открыть до 256 WordPiece с адресом. Реально полученные символы дописываются в память и доступны при следующем решении. Основной срез — до 768 дополнительных токенов в сумме. Смежные отрывки одного поля объединяются. На первом шаге воспроизведены прежние адреса двух контрольных правил для всех 2 661 вопросов.

| Политика выбора поля | Все доказательства ISETrace, из 2 000 | Средние токены | Все доказательства MultiDoc2Dial, из 661 | Средние токены |
|---|---:|---:|---:|---:|
| До первого обращения | 1 671 | 0 | 444 | 0 |
| Расширять первое доступное поле | 1 754 | 708,6 | **484** | 721,0 |
| Сохранить первоначальный порядок BM25 | 1 741 | 708,6 | 479 | 729,9 |
| Обновлять BM25 по всем видимым окнам | 1 749 | 708,9 | 479 | 730,6 |
| Сначала наименее читанные поля, затем BM25 | **1 767** | 704,8 | 471 | 734,2 |
| Считать BM25 только на краю каждой компоненты | 1 765 | 710,0 | 472 | 737,1 |

Для заранее выбранной гипотезы о релевантности последних 128 токенов ISETrace дал +16 полных наборов относительно всех видимых окон (+0,80 п.п., одновременный ДИ [−0,15; 1,74], Holm p = 0,1905). На диалогах разность составила −7 вопросов, −1,06 п.п., ДИ [−2,78; 0,48], Holm p = 0,5054. Относительно распределения обращений между полями у ISETrace разность −2 и у MultiDoc2Dial +1. Четыре заранее заданных сравнения не установили общего преимущества краевого BM25.

Зато можно отделить **ценность обновления памяти** при одинаковом способе лексического ранжирования: на ISETrace пересчёт по новым текстам дал 1 749 против 1 741 при замороженном приоритете, 8 выигрышей, 0 потерь (вторичное сравнение). В диалогах по 479, один выигрыш и одна потеря. Отдельно по числу полных вызовов распределение между полями дало на ISETrace 1 710 → 1 736 → 1 761 → 1 780; на MultiDoc2Dial — 456 → 467 → 469 → 475. Это более свободный горизонт вплоть до 1 024 токенов после четвёртого вызова. [Исходы и парные расходы](results.json)

**Разбор причин.** Даже если недостающие доказательства лежат в одном *уже видимом* поле, алгоритм не знает в каком. Среди 236 таких вопросов ISETrace первое поле помогло полностью покрыть ещё 82 вопроса, полный BM25 — 77, распределение по полям — 94. В 118 таких диалогах те же правила добавили 40, 35 и 27. Значит, различие корпусов не объясняется одним лишь числом эталонных полей. Когда всё недостающее было в одном отсутствующем поле, ни одна стратегия локального продолжения не могла добавить полный набор (67 вопросов ISETrace, 99 диалогов). Этот разбор использует эталон после эксперимента. [Стратификация](strata.json)

Это воспроизведение истории наблюдаемых диапазонов. Оно проверяет работу планировщика при заданном вопросе и не оценивает генерацию ответа. Токены обращений добавляются к начальной памяти, повторная оплата старого контекста моделью в этом опыте не моделировалась. Независимый повтор выявил особенность расхода на последнем шаге. После обрезки к 768 токенам некоторые последовательности оканчивались частью адресного заголовка. У Any это произошло в 10/2 000 и 7/661 случаях. Такой вызов оплачен и не добавляет текста. При требовании передавать целый заголовок и при повторном строгом выравнивании фактического расхода Full Support сохранился у обеих сторон во всех восьми парных сопоставлениях.

# Как обновлять приоритет источников после каждого чтения

Один шаг расширения памяти от конца известного интервала уже проверен в R24. На полном ISETrace (2 000 вопросов, 1 207 историй) и MultiDoc2Dial (661 диалог) сравниваем политики, которые могут открыть до четырёх последовательных продолжений. Входом остаётся одна и та же адресованная память до 2 048 WordPiece. Соседние и пересекающиеся интервалы одного поля образуют компоненту. Каждый вызов возвращает до 256 WordPiece с заголовком. В индекс добавляются только реально полученные символы. На следующем шаге кандидат — правый конец каждой видимой компоненты, у которой есть продолжение. Знание длины поля — метаданные, невидимый текст не участвует в выборе. Возвращённая запись иногда соединяет две уже известные компоненты. Порядок компоненты тогда наследуется от наиболее раннего из её кусков. Если расширение невозможно, разрешён отказ.

Сравниваем пять правил до получения новых исходов. **First** выбирает первую расширяемую компоненту в порядке выдачи. **Frozen** сортирует исходные 128-токенные окна один раз по BM25 и сохраняет это предпочтение источников после каждого обновления геометрии. **Any** заново вычисляет BM25 по всем видимым 128-токенным окнам и продолжает компоненту лучшего окна. **Balanced** сначала выбирает поля, к которым политика обращалась минимальное число раз, затем применяет тот же Any. **Tail** оценивает последние до 128 видимых WordPiece каждой компоненты. Для них берутся те же IDF, средняя длина и параметры BM25, что для Any из всех текущих неперекрывающихся окон. При равенстве баллов используется прежний порядок компонент. Гипотеза Tail — лексика на границе лучше предсказывает полезность следующей записи, чем давнее совпадение глубоко в уже прочитанном тексте. Альтернатива — полезнее продолжать первое релевантное поле или распределять чтения между источниками. Учитываем результаты всех условий независимо от направления эффекта.

Основной предел — до четырёх действий с суммарной оплатой до 768 дополнительных токенов (заголовки включены, исходные 2 048 остаются видимы). Срез есть префикс реально принятой последовательности, последняя выдача сокращается с ретокенизацией. При исчерпании квоты действий может быть меньше четырёх. Ни одно дальнейшее действие, основанное на отброшенной части, не включается. Сохраняем также результаты после 1, 2, 3 и 4 полных обращений с максимумом 1 024 токена, число успешных дополнений на каждом шаге, расходы и количество разных полей. Отдельно сверяем равную фактическую кумулятивную квоту внутри каждой пары, включая случаи отказа.

Первичный исход — полный набор доказательств в объединении накопленного контекста. Для каждого корпуса планируем Tail против Any и Tail против Balanced — четыре сравнения. Двусторонние кластерные перестановки и поправка Holm по всем четырём. Интервалы для каждого контраста 98,75% из парного бутстрэпа по траектории или исходному документу; семейное покрытие приблизительно 95%. Дополнительно смотрим среднюю долю покрытых эталонных символов, кривую прироста и различие Frozen/Any. Для первого действия Any и First проверяются по запечатанным адресам R24 во всех 2 661 случаях. Измерение касается накопленной памяти и последующего выбора источника, а не качества конечного ответа языковой модели. Эти два корпуса уже знакомы по одношаговой работе; новые последовательности пока не измерялись.

Многошаговое извлечение по мере выполнения задачи исследовали IRCoT и FLARE. В нашем протоколе вопрос постоянен, что позволяет отделить обновление видимой памяти от изменения запроса генеративной моделью.

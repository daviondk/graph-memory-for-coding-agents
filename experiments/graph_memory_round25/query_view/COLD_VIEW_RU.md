# Считывание и раскрытие самой структуры памяти

В первой проверке все метаданные уже находились в объектах Python. Для дополнительной проверки фиксируем каждый вариант в виде настоящего отдельного сжатого BLOB в SQLite. Перед каждым будущим вопросом одним SELECT извлекаем его целиком, затем распаковываем и декодируем, вычисляем точный или приближённый лучший адрес тем же правилом. Индекс обратных списков использует только списки для слов вопроса при подсчёте баллов, но физическое декодирование единого BLOB оплачено целиком. Запись сканирующего контроля содержит только координаты. Размер каждого BLOB должен совпасть побайтно по длине с ранее учтённым форматом. Оригинальные текстовые строки читаются из общей таблицы payload. Порядок вариантов перемешивается с фиксированным seed, первичный замер на всех вопросах, три дополнительных повтора на хеш-определённом подмножестве. Измеряется суммарное время от запроса BLOB до решения, число и суммарные байты возвращённых SQL-строк, включая метаданные. Кеш страниц ОС и соединение SQLite прогреты; «раскрытие» означает повторное создание объекта представления. Эту проверку планируем после первоначального профиля. Альтернативы per-term SQL и FTS требуют отдельного физического дизайна.

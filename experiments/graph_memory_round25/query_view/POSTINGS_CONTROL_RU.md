# Сильный контроль — прочитать только списки для слов нового вопроса

Опыт раскрытия сжатого BLOB показал, что инвертированный индекс быстр в памяти, но его полная декомпрессия тратит время. Фиксируем два адресных контроля. (1) Декодируем тот же исходный BLOB, преобразуя списки в счётчики Python только для фактических слов запроса. (2) Физическая таблица SQLite с первичным ключом (номер наблюдавшегося состояния, слово), в каждой строке коды приращений номеров окон и частот; выборка только нужных списков одним параметризованным SELECT. Координаты и длины окон хранятся отдельным сжатым BLOB на состояние. Сортировка и счёт BM25 остаются прежними. Сопоставляем точные адреса на всех 1 321 запросах, размер файла с индексом, выборочные байты SQL и медианную задержку, включая создание нужных объектов из ответа. Сравнения локальные на том же соединении и с прогретым кешем ОС.

Кроме обычного инвертированного индекса включаем гибрид из предыдущего опыта с оценками и Bloom в ту же перемешанную серию замеров. Для каждого режима раскрытия исходные таблицы, текст запроса и семантика адреса проверяются независимо. Это контроль реализации после первых замеров, а не новое независимое подтверждение.

# Как повторить сравнение эпох в одной траектории обучения

**Переносимая проверка.** Python и NumPy достаточны для команды `python -B verify.py`. Она проверяет все контрольные суммы, перестановки кандидатов для 30 000 пар «вопрос × уникальная сеть», тождественность выходов для совпадающих эпох и парные интервалы из численных результатов. Главные файлы — [протокол](PROTOCOL_RU.md), [исходные эпохи и хеши состояний](registration.json), [результаты по каждому вопросу](scores.json.gz) и [статистика](results.json).

**Полный повтор.** На исходном диске доступны замороженные эмбеддинги Dense-FT, сырые тензорные состояния, графы и авторский evaluator. Используется Python исследовательского окружения ISETrace и зависимости подписанных R22/R34/R41/R43. Запуск на CPU проверяет маскирование CUDA. По порядку выполнить `forecast.py`, `grade.py`, `analyze.py --write`, `verify.py` с одинаковым Python и ключом `-B`. Для повторной записи технических таймеров прогноза и новых контрольных сумм нужен отдельный рабочий каталог с тем же расположением исходных раундов. Уже архивированная версия остаётся доступной для сравнения хешей. Длительность операции зависит от файлового кеша. Версии библиотек и исходные процедуры GPU-обучения приведены в [импорте весов](../../graph_memory_round43/checkpoint_selection/REPORT_RU.md).

**Схема выходов.** В каждой из 13 частей `ranks-*.json.gz` сохранены ID запроса, ID траектории и полное упорядочение локальных индексов исходных единиц. Ключ сети объединяет seed, архитектуру и эпоху. Для двух совпавших критериев выбора сохраняется одна перестановка. `grade.py` применяет строгую отсечку при 512/1 024/2 048 токенах и проверяет полный вектор по библиотеке ISETrace. В `scores.json.gz` у каждого seed и архитектуры поля `recall` и `matched` описывают один CPU backend, а `gpu_matched` и `gpu_canonical` хранят ранее опубликованные показатели для проверки численной переносимости. `analyze.py` заново строит доверительные интервалы, в которых все методы попарно получают одинаковые траектории и seed.

В первом техническом пилоте выявили ошибку индекса служебного контейнера записи результата. Ни один прогноз из этого запуска не сохранился, разметка не присоединялась. Уточнение реализации сохранило исходный протокол и все пары эпох.

# Сохранение подтверждённой истории через последовательные правки

Исходная задача — удержать строки из любого наблюдённого ранее обращения к коду и корректно адресовать их в будущей версии, хотя путь и момент следующего вопроса неизвестны. При записи старых явных просмотров и ответов редактора потолок на 2 696 правках достиг 465 из 5 685 последующих информативных запросов строк. Возможное ограничение заключается в том, что первая же попытка изменения уничтожает всю историю данного пути. Проверяем, добавляет ли пользу перенос состояния через прежние подтверждённые модификации. Разметку новых вариантов до регистрации не открываем. [Режим с обычным сбросом](../../graph_memory_round44/receipt_history/REPORT_RU.md)

**Писатель.** Восстанавливается ровно тот же причинный поток на 1 313 запусках Handoff Debt. Заданы глобальные лимиты 2, 8, 32 КиБ и без лимита. Все стратегии хранят только доступные информативные строки и их версии согласно реализации R44. На любом непрозрачном действии/разрыве всё состояние обнуляется. Неизвестная мутация либо неидентифицируемая выдача отзывают целевой путь. Успешная квитанция отдельно пополняет память показанными строками по строгим правилам R44. Настройка по будущим обращениям, достаточности набора или координатам следующей правки отсутствует.

**Протокол отложенного изменения.** При видимой попытке str_replace записываем в память состояние незавершённой транзакции. Прежние строки этого пути остаются только внутри той же единственной структуры текущего бюджета с отметкой недоступности до подтверждения. Тела и индексы записей не дублируются. Для компактного консервативного варианта сохраняем оба исходных UTF-8 литерала целиком, хеш пути, индекс действия, идентификаторы привязки и двоичные границы длины. Размер исчисляется фактической сериализацией для каждого состояния, включая временно недоступные строки. В этот период обе версии недоступны для чтения данного пути. Если служебное состояние не помещается в глобальный бюджет, продолжаем с полным сбросом пути и без незавершённой транзакции. При необходимости удаляем глобально старейшие строки до восстановления ёмкости. Подтверждение принимается только при совпадении пути, идентификаторов действия и вызова и непосредственно следующем исходном индексе события. Любое иное промежуточное событие аннулирует ожидание и старые строки пути. Непосредственная смежность проверяется сырыми порядковыми номерами до обращения к эталонному исходнику.

**Обработка подтверждения.** В точном тексте успешной квитанции находим единственный видимый якорь нового литерала по заранее зафиксированной функции locate. Из старого и нового литералов определяем удалённые/добавленные переводы строк и карту равных строк с метками границ R42/local. Адреса прежней версии, для которых отображение не определено, отзываем. Остальные переводим в новую версию с прежней частотой и отметками времени. Механизм переносит записи через сколько угодно последовательных подтверждений при сохранении бюджета и непрерывной истории. После этого принимаем новые строки квитанции, включая замену фактически отличающихся значений. Контроль A — подписанный LRU из views и прошлых receipts со сбросом пути. Контроль B — та же отложенная транзакция с тем же учётом ёмкости, после подтверждения всё старое содержимое пути удаляется. Контроль C — перевод только текстов вне старого интервала через то же подтверждение. Кандидат D — полный перевод, включая наблюдённые равные строки старого и нового литералов. Базовые четырёхсторонние сравнения используют один числовой порядок событий и одинаковый ранжировщик. Никакой исходник или команда трассы не исполняются.

**Высота эффекта.** Каждый новый целевой пакет замораживается при наступлении следующего действия. Настоящие литералы, положение текущей правки и её квитанция используются только на стадии readback для равного вычитания того, что уже увидит получатель. Основная оценка — парная разница D минус A в вероятности хотя бы одного совпавшего со следующим запросом нового информативного адреса. Писатель и читатель соответственно 8 и 2 КиБ, равный вес каждой из 37 задач, 10 000 общих перевыборок задач. Результаты A должны точно совпасть по каждой координате и целевому бюджету с прежней фиксацией. Дополнительные контрасты D–B и D–C отделяют эффект переноса от временного переполнения состояния и от частного случая равного содержимого внутри старого интервала. Сохраняем все срезы R44 и число востребованных вхождений и байтов. Общая отложенная группа содержит 1 071 эпизод, скрытое новое тестовое множество отсутствует. Ранее известны данные исходной политики, но не исходы транзакционного писателя.

**Проверки границ.** Отдельный оценщик после заморозки сверяет адрес/хеш каждого достижимого кандидата с исходными версиями до и после целевой операции. Считаем число старых операций, причины отказа по несмежности/якорю/объёму, действительную занимаемую память с незавершёнными операциями, разрушенные ёмкостью строки, долю по глубине цепочки (0, 1, ≥2 подтверждений). Дополнительная метка глубины существует только для аудита и не используется для ранжирования/решения о записи. Её стоимость отдельно указывается, если хранится в состоянии работающего писателя. Отчитываем также покрытие спроса при неограниченных писателе и читателе, ошибочные координаты и число полностью покрытых новых просмотров. Поскольку результат может держаться на единичной задаче, приводим число задач и репозиториев с любым выигрышем.

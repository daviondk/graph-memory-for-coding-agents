# Контроль равенства видимого текста на SERBench

Qwen3-Embedding-8B и два лексических ранжировщика получили одну последовательность входа. Она составлена из инструкции, информационной потребности агента, текущей цели и описания issue. Текст каждого кандидата содержит путь и выдержку. На стороне лексических моделей все признаки вычислены после той же токенизации GGUF, по первым 511 токенам плюс EOS. Словарь и входные представления остаются равными. Логистическая модель видела train-разметку SERBench, Qwen использовалась zero-shot. [Заранее заданный протокол](MATCHED_INPUT_RU.md)

На 204 состояниях вне пилота в режиме общей отсрочки просмотренных единиц логистическая модель закрыла MSS@5 в 17 случаях, BM25 — в 15, Qwen — в 95. При одинаковом потолке в 2 048 токенов эти числа равны соответственно 19, 9 и 78.

Дополнительные поля изменили фактические токены запроса в 204/204 случаях. Позиция поля issue перемещается относительно точки усечения, поэтому это совокупный эффект доступной истории и распределения ограниченных входных токенов. Выбор C на 101 dev: 0.1 для трёх полей и 0.1 для расширенного запроса. Обучение включало 179 состояний, из них 0 с единственным классом кандидатов. Лексические методы используют точные BPE-единицы, без стемминга и дополнительной токенизации исходных символов.

По всем 214 состояниям независимо подтверждены длины 18812 строк перед усечением, включая весь набор кандидатов Qwen. Несовпадений 0. В данном запуске получены 25901 уникальных текстов для всех 494 состояний train/dev/test, все 25901 строки по отдельности обработаны исходной HTTP-функцией /tokenize. Сравнение с первоначальной пакетной токенизацией выявило 2 несовпадающих входов, их исправили до оценки качества текстовых контролей. Программа токенизации работала на CPU, эмбеддинги Qwen — на RTX 3090. В архиве сохранены ранги и числовые признаки проверки; токенизированный исходный текст находится только в локальном кэше.

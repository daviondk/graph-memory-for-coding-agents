# Воспроизведение и проверка

Сохранённый числовой результат проверяется в этом каталоге без сети, GPU или весов модели. Нужен Python 3.11 или новее. Официальные группы Cal500 и альтернативные множества представлены порядковыми номерами, с сохранением минимальных количеств и исходной стоимости каждой единицы. В архиве нет исходного текста фрагментов.

```powershell
python -B verify.py --final
python -B verify_fusion.py
python -B verify_matched.py
python -B verify_metrics.py
python -B verify_budget.py
```

Первая команда сверяет контрольные суммы, состав непересекающихся панелей, основной порядок и итоги. Вторая пересчитывает все слияния RRF с рациональной арифметикой. Третья восстанавливает логистические предсказания из числовых признаков, коэффициентов и полных рангов. Четвёртая независимо пересчитывает семь показателей и четыре измерения расхода для каждой системы и каждого состояния. Пятая интегрирует ступенчатую кривую стоимости и заново проверяет девять бюджетных точек каждой системы.

Для полного воспроизведения нужны исходные скрипты и локальные данные [пилота](../../graph_memory_round39/qwen_reference/QWEN_REPRODUCE_RU.md), [контрольных систем](../../graph_memory_round39/repo_crossfit/) и [SERBench R34](../../graph_memory_round34/external_transfer/). Файлы из каталога пилота размещаются в `work/graph_memory_round39/author_baseline`. Координаты весов, токенизации, llama.cpp и SDK зафиксированы в пилоте. Веса хранятся на D в единственном экземпляре. Публичные данные и разметка SERBench Cal500 должны быть распакованы по структуре `panel.py` из пилота. По относительным ссылкам сохраняются версии функций, использованных для контроля публичной видимости. Основному ранжировщику требуются NumPy, requests и sklearn. Лексический повтор также требует scipy, tokenizers и токенизатора llama.cpp из того же дистрибутива.

Полный пересчёт проводится в отдельной копии `work/graph_memory_roundNN/qwen_panel214` той же глубины, при отложенном исходном манифесте. Замеры времени и адрес порта меняются. Независимый GPU-повтор использует отдельный небольшой каталог квитанций для `embed_gpu.py`, с сохранением тех же весов, бинарника и алгоритмических параметров. Если расчёт прерван, программа продолжает по фиксированному порядку и сверяет контрольные суммы при каждом восстановлении. Перед чистым повтором низкозатратной токенизации нужен отдельный локальный каталог `PRIVATE` в `matched_fit.py`. Он содержит потенциально обратимые токены исходного текста и исключён из публикуемых артефактов. Более ранняя диагностика Windows CRLF описана [отдельно](TOKENIZER_NOTE_RU.md).

```powershell
$runner = 'D:/CodexResearch/x20-isetrace-e5-gpu/venv/Scripts/python.exe'
$env:OPENBLAS_NUM_THREADS = '1'
$env:OMP_NUM_THREADS = '1'
& $runner -B common.py
& $runner -B controls.py
& $runner -B fusion.py prepare
& $runner -B info_contract.py
& $runner -B matched_tokens.py
& $runner -B preserve_token_comparison.py
& $runner -B matched_native.py
& $runner -B matched_fit.py
& $runner -B matched_numeric.py
& $runner -B verify.py
& .\run.ps1
& $runner -B project_checks.py
& $runner -B matched_grade.py
& $runner -B budget_curve.py
& $runner -B report.py
& $runner -B matched_report.py
& $runner -B budget_report.py
& $runner -B context_report.py
```

Завершив пересчёт, выполните пять проверок из начала документа. Скрипт `run.ps1` ждёт общего Windows-мьютекса GPU, рассчитывает Qwen для всех 214 состояний, фиксирует основной и дополнительный ранги RRF, после этого объединяет их с публичной разметкой. В данном исследовании дешёвые лексические контроли и протоколы были зафиксированы до оценивания новых исходов Qwen, могут выполняться параллельно с инференсом без доступа к GPU. `panel.json` содержит точный порядок 10 пилотных и 204 остальных состояний. Ни одна из команд не передаёт прогнозы в закрытый трек Test500.

Для повторного опыта при одновременном старом расчёте можно установить `$env:R40_WAIT_FOR_CANONICAL = "1"`, чтобы дождаться его результата. Исторический запуск дождался именно этого условия. В переносимой версии ожидание архивного R22 опционально, а взаимная блокировка GPU сохраняется всегда. Инференс, его отпечатки и параметры идентичны.

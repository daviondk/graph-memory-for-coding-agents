# Как хранить флаг связи, если точное число подтверждений редко нужно читать

На 31 279 последовательных обновлениях из 1 207 реальных трасс проверили маленький кэш для двух ответов «есть входящая связь» и «есть исходящая связь». После удаления подтверждения простой оператор сразу узнаёт точную сумму в SQLite, если его локальный счётчик ранее переполнился. Второй оператор ждёт момента, когда известная нижняя граница уже допускает ноль. При одинаковых **7 состояниях на направление** (K=3) отложенная проверка сделала **343** индексных запроса против **490**, на **30,0%** меньше. В пересчёте на 100 транзакций разность **0,470 [0,363; 0,585]**. Бутстреп парный, по целым траекториям. Выдачи обеих ветвей совпали с независимо сохранёнными флагами на каждой границе. **Почему выдача точна.** Пусть истинное число подтверждений равно s. Храним либо точное s до K, либо нижнюю границу 1 ≤ L ≤ min(s,K). При изменении на d верно s+d ≥ L+d. Если правая часть положительна, связь сохранена. Обновлённая граница min(K,L+d) снова удовлетворяет инварианту. В остальных случаях SQL возвращает точную неотрицательную сумму в том же зафиксированном состоянии графа. Далее та же процедура кодирует результат. Индукция от пустой памяти устанавливает правильность для всей истории. В области 0…12 отдельно проверены все достижимые состояния и допустимые изменения от −4 до 4. Реальные трассы содержали счётчик величиной до 64. [Код оператора и проверка переходов](experiment.py) · [Контрольные суммы и размеры конечных моделей](checks.json)

Для понимания цены справочного доступа рассмотрим одно направление, допустимые единичные вычитания и точную выдачу после каждого шага. Если обращения к другим данным запрещены, любые два разных числа a<b из 0…D должны иметь различимые внутренние состояния. Одна и та же последовательность из a вычитаний оставит первое число нулевым, а второе положительным. Поэтому нужно не менее D+1 состояний для точной поддержки всех таких потоков. Наше малое представление обменивает локальные состояния на редкие обращения к уже имеющемуся графу. Это элементарное обоснование условий алгоритма.

Здесь измерено число обращений. Чтобы сравнить задержку, объём страниц и общую стоимость, нужно выбрать физическую упаковку, учитывать ключи вершин и индекс, обеспечивающий обращения. Полноразмерный локальный счётчик использует ноль запросов к парам и остаётся подходящим для сценария без такой таблицы. Результат дополняет измерения двух физических SQLite-схем и сам по себе не означает ускорения агента.

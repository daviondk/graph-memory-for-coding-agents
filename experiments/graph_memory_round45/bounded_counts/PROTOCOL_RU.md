# Отложенная проверка ограниченного счётчика связи

Проверяем, можно ли отдавать в точности те же два флага FEEDS при ограниченном локальном состоянии на направление, если в постоянном хранилище уже есть взвешенные пары. Сжатие счётчика имеет смысл для горячего представления флагов, когда граф нужен и для других запросов. Изменения входят транзакциями. У каждого направления и вершины суммируем подписанные вклады транзакции. Беззнаковое значение вершины после всего коммита неотрицательно.

Состояние хранит точное число до K или нижнюю границу от 1 до K включительно. При переполнении записываем нижнюю границу K. Для ограниченной записи сначала прибавляем изменение к нижней границе, ограничивая результат сверху K. Если оставшаяся граница положительна, флаг по-прежнему истинен. Если граница может пересечь ноль, узнаём точную сумму из таблицы свидетельств после коммита. Парный контроль с тем же пространством состояний запрашивает сумму при каждом чистом уменьшении неточной записи. У полного целого счётчика справочных чтений нет. Удаляем точные нули из обеих таблиц.

Основное сравнение при K=3, зафиксировано до вычисления показателей этого запроса. Метрика — число отдельных запросов точной суммы по вершине и направлению за весь проход. Условие допустимости — ноль неверных выдач на всех 31 279 опубликованных границах. Вторичные K=1 и K=7, доля транзакций с обращением, число затронутых направлений, максимум фактической суммы, попарные различия и кластерный 95% интервал разности на 100 транзакций (10 000 bootstrap по 1 207 траекториям, seed 45901). Единица справочного чтения — одна индексная SQLite-агрегация. Одинаковые обращения разных алгоритмов в измерениях не объединяем. Это число запросов, не длительность. Записи и индекс, нужные для получения точного значения, существуют в обеих ветвях и учитываются как предпосылка.
   
Дополнительно исчерпывающе проверяем ограниченный автомат на одноключевых допустимых переходах для чисел 0…12 и изменений −4…4 при K=1,3,7. Число состояний 2K+1 характеризует теоретическую стоимость кодирования значения. Отдельно отмечаем необходимость хранить ключ вершины и upstream-индекс; физический размер системы не выводится из этой формулы.

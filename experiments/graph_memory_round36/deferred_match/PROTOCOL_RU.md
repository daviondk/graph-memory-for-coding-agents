# Протокол отложенного сопоставления аргументов

Отложить сопоставление можно при неизменных исходных аргументах, монотонной видимости результатов и поглощающей неоднозначности. Если значение стало неоднозначным, оно не может снова стать уникальным. Если аргументы меняются между вызовом и результатом или уникальность восстанавливается, равенство раннего и отложенного сопоставления в общем случае не гарантируется. Перечисленные предпосылки и сравнение исходных позиций тестируем отдельными граничными случаями.

Сравниваем с подписанным однопроходным HistoricalFeeds из R36/streaming_witnesses. Он при вызове сопоставляет аргументы со всеми более ранними уникальными производителями и сохраняет ссылки на совпавшие значения до выхода, затем обработав коллизии публикует оставшиеся пары. Новый оператор при вызове сохраняет лишь ссылку на неизменное событие и исходную позицию; после получения результата сначала применяет все его значения/коллизии. Если выход имеет PU, перебирает сохранившиеся уникальные видимые источники с позицией строго меньше позиции вызова, при необходимости один раз получает аргументы из уже существующего лога и проверяет текущие значения штатным _argument_contains. Ни будущие значения, ни свидетели, потерявшие уникальность, не должны приводить к связи. Исторический выход — логические пары между видимыми output, а PU-проекция должна совпадать с R36.

Сравниваем идентичности всех пар после каждого из 72 186 релевантных событий, по 1207 естественным траекториям. Первичные системные показатели: количество фактических вызовов _argument_contains, обращений к архиву, максимум и интеграл числа открытых ссылок на аргументы. Считаем длину UTF-8 raw_arguments и отдельно UTF-8 JSON структурированных arguments, потому что штатный предикат использует обе формы. Байтам логического чтения из архива не приписываем обязательную передачу всего объёма на машине с уже доступными Python-объектами. Регистрируем также число перебираемых записей словаря и разлагаем экономию проверок на недоступный выход, невидимый источник и устранённые до появления результата коллизии.

Для парного времени CPU определяем выборку 96 минимальных SHA-256 от R36-deferred-match-cpu|trajectory_id до измерений. Засекаем один поток, новый чистый оператор на каждый повтор, один разогрев и четыре чередующихся повторения на каждой траектории. Попарный порядок чередуется детерминированно. Чтение готовых событий, построение графа видимости, инструментирование, сериализация эксперимента и вычисление метрик вне таймера. Основное время — process_time_ns, дополнительное — perf_counter_ns. До оценки зафиксированы два транспорта аргументов: ссылка в имеющемся списке событий (основное сравнение) и дополнительное обращение к заранее заполненной SQLite :memory: с восстановлением обеих форм. Для SQLite явно выделяем построение/наличие внешнего хранилища как допущение, сырые аргументы на диске не сохраняются. Для разностей объёма и отношения сумм времени по траекториям — 10000 парных bootstrap-перевыборок. Число повторов времени не увеличивает число независимых траекторий. Нулевые и отрицательные исходы сохраняем.

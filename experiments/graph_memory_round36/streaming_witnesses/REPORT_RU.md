# Однопроходная запись исторически обоснованных связей

При проверке результата инструмента достаточно временно удерживать свидетелей незавершённых вызовов. Средний по 1 207 историям максимум таких служебных ссылок снизился с **9,59 до 3,22**, на 66,47% [64,82%; 68,01%]. Медиана снизилась с 6 до 3. В 1 085 историях пик уменьшился, в 122 совпал, увеличений не было. Если суммировать число удерживаемых ссылок по всем 72 186 релевантным событиям, получаем 354 058 против 25 178. По окончании историй в новом операторе временных кандидатов не осталось. Это отдельный класс вспомогательных ссылок, а не размер всей памяти в байтах. [Поштучные агрегаты и интервалы](results.json)

На **каждом из 72 186** событий множества возвращаемых исторических логических пар совпали по идентификаторам с независимой реализацией, которая ведёт штатные обратные ссылки и собирает объединение всех действительно наблюдавшихся состояний. В 795 историях одновременно были открыты несколько вызовов. Развёрнутые количества пар фрагментов дополнительно совпали на 4 828 срезах. Обе модели имеют общий по смыслу словарь значений, их производителей и признаков неоднозначности. Выходные исторические пары всё равно необходимо хранить.

**Почему можно забыть свидетелей закрытого вызова.** Для данного потребителя кандидаты возникают только в момент его вызова. До первой публикации выхода они могут потерять единственного производителя. Уникальность в данном правиле после потери не возвращается. Обрабатываем все значения публикуемого результата, затем записываем связь с каждым производителем, для которого остался хотя бы один свидетель, и освобождаем очередь этого потребителя. Позднейший отзыв меняет текущий граф, но уже записанная связь остаётся обоснованной как исторический факт. Это алгоритм оператора «когда-либо существовала связь между двумя доступными фрагментами». Для запроса о текущих действующих связях нужно отдельно вести поддержку отзывов.

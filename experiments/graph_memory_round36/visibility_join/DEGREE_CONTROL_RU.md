# Дополнительный контроль предварительного вычисления степеней

После результата для двух сохранённых размеров групп проверяем сильный конкурент, который тоже ускоряет запрос за счёт хранения производных данных. Для каждой истории, узла и момента впервые видимой PU-связи сохраняем суммарное приращение его исходящей и входящей степени. Сумма до среза даёт точный ответ по степеням. Сравниваем две физические схемы — только эти приращения (поддерживает один интерфейс) и таблица явных PU-пар вместе с приращениями (поддерживает оба). Отдельная SQL-альтернатива без новых данных сводит все конечные узлы PU-пар в единственную агрегацию GROUP BY вместо предварительных группировок по двум направлениям. На той же исходной панели фиксируем 5 построений двух новых схем, размеры файлов, точность на 512 срезах и 9 попарно перемешанных замеров чтения степеней с исходным flat и grouped_arity. Объём этих БД включает высчитанные при построении приращения. Публикуем все варианты вне зависимости от результата.

# Воспроизведение

Проверка поставленного результата занимает несколько секунд. Запустите из каталога опыта

```powershell
$joinPython = 'D:/CodexResearch/x20-isetrace-e5-gpu/venv/Scripts/python.exe'
& $joinPython -B -X utf8 verify.py
```

На CPU использованы Python 3.12.13, SQLite 3.50.4, NumPy, SciPy и ранее установленные модули ISETrace. Исходные сравнения находятся в соседних каталогах materialized_append и visibility_oracle. Параметры энкодера и чтение исходных данных при повторении эксперимента обрабатываются существующими инструментами локального проекта на D. Графы и содержимое журналов обрабатываются как данные.

Для нового прогона удобно взять рабочую копию папки рядом с подписанным результатом, чтобы сохранить исходные измерения. Команды выполняются последовательно. Время SQLite зависит от компьютера и состояния ОС.

```powershell
& $joinPython -B -X utf8 extract.py
& $joinPython -B -X utf8 sqlbench.py
& $joinPython -B -X utf8 native_ranking.py
& $joinPython -B -X utf8 operators.py
& $joinPython -B -X utf8 slices.py
& $joinPython -B -X utf8 degree_controls.py
& $joinPython -B -X utf8 verify.py --seal
```

extract.py пересобирает вход из исходных восьми файлов сессий и кэшей порядка Dense; на каждой выбранной истории проверяет родительские контрольные суммы. Только нормализованные числовые адреса, времена, признаки и хеши выдач входят в поставленные производные данные. Собственный SQLite-прогон можно повторить с этапа sqlbench.py, используя уже готовые input.json.gz и reader-checks.json.gz. native_ranking.py заново получает степени из физической базы и пересчитывает сравнение с порядками R36. Дополнения operators.py и degree_controls.py кодируют отдельно объявленные физические контроли; для них сохраняются самостоятельные протоколы и первичные тайминги.

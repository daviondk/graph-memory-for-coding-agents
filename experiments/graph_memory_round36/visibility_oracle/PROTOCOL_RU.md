# Проверка границы видимости результата

Для всех 1 207 тестовых траекторий R34 вычисляем логические пары вызовов и количества соответствующих типизированных направленных пар фрагментов на четырёх закрытых срезах. Входы — прежний публичный поток ISETrace и размеры пулов из R19, только первый seed. Размеченные ответы и качество политик в вычислении не используются. Альтернативная офлайн-процедура сначала определяет момент первого появления каждого значения у одного производителя и момент утраты его уникальности, затем сопоставляет эти интервалы с моментами вызова и появления результата читателя. Она независима по реализации от потокового кода FeedIndex; правила выделения типизированных значений и их поиска в аргументах взяты из нативного benchmark.

Каждое атомарное событие сначала обрабатывается полностью. Связь между фрагментами результатов считается наблюдаемой, только если после обработки присутствуют оба конца и сохраняется хотя бы одно валидное соответствие. После каждого вызова читателя множество изначально поддерживавших пару значений способно только сокращаться. Проверяем аналитический критерий отдельно на четырёх заранее заданных классах: исчезновение последнего соответствия на самом результате читателя, исчезновение раньше результата во время параллельного вызова, исчезновение позже результата и два соответствия, из которых одно исчезает на границе, а второе продолжает поддерживать пару.

Состояния E (текущие), M (хотя бы раз материализованные) и L (когда-либо замеченные связи вызовов при видимых сейчас концах) считаем по всем траекториям и отдельно сообщаем, сколько пар L∖M потеряли последнее соответствие на том же событии, которое открыло конец связи, либо раньше этого события. Не смешиваем число пар вызовов с числом пар PU или улучшением качества. Для валидации дополнительно выбираем 16 траекторий с минимальным SHA-256 от «R36-visibility-oracle/» + идентификатор, без обращения к исходам. На каждом их событии output нативный построитель графа обрабатывает предшествующие события завершённых вызовов с исходными позициями; множество актуальных логических пар и его историческое объединение сверяются с интервальным алгоритмом по идентичности. Суммы четырёх срезов сверяем с независимым R36/materialized_append при появлении его результатов.

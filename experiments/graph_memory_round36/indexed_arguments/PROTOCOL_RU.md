# Сопоставление значений в аргументах одного вызова

Гипотеза первичного сравнения C/A. Однократная подготовка только тех декодированных строковых значений аргументов, которые не покрыты сырым текстом, сократит число циклов потока на построение точного исторического FEEDS при равенстве выходов. Положительное направление — отношение сумм циклов меньше единицы. Сильный контроль B отделяет эффект однократного обхода от эффекта исключения избыточных строк; фиксируем B/A и C/B как вторичные. A — опубликованный в R36/streaming_witnesses лёгкий потоковый оператор со штатным предикатом, включая поиск по raw и при промахе перечисление листовых строк рекурсивным генератором. B получает на каждом вызове полный упорядоченный кортеж листьев, C получает при подготовке уникальные сохранённые листья, ещё не содержащиеся целиком в raw. Оба сначала ищут в raw, затем по отдельным оставшимся строкам, без изменений регистра, нормализации Unicode и объединения строк. Перечень существует только на время обработки аргументов текущего вызова.

Время включает создание перечней и функции сопоставления для этого вызова. Формат входа, создание графов, порядок событий, позиции, ревизия и реальные объекты аргументов общие. Никакой дополнительной сериализации и индекса между вызовами. Качество определяется точным равенством открытых свидетелей и исторических пар после каждого вызова/результата во всех 1207 исходных траекториях. Помимо 72 186 событий проверим 4828 ранее подписанных состояний. Посчитаем фактические кандидаты, совпадения в сырой и декодированной формах, число обходов и выдач рекурсивного генератора, строковых проверок с учётом досрочного выхода и число сохранённых листьев. Проверки на разработанных контрпримерах включают Unicode-экранирование, кавычки и обратную косую черту, повторяющиеся leaf, пустые строки, JSON-ключи и запрет соединять разные строки.

Тайминг — ранее фиксированные 96 траекторий с наименьшим SHA-256 от R36-deferred-match-cpu|ID, одна разминка и шесть повторов всех трёх реализаций, внутри каждой траектории используем все шесть перестановок в детерминированно сдвинутом порядке. Первично число циклов текущего потока (Windows QueryThreadCycleTime), дополнительно process_time_ns и perf_counter_ns. Результат — отношение суммы усреднённых по повторам времён каждой траектории, парный перцентильный bootstrap 10 000 выборок траекторий, seed=360614. Без удаления наблюдений. Синтетические входы и разметка retrieval не используются при замерах. Изменения проходят как отдельный локальный технический опыт, состояние прошлых исследований сохраняется.

# Точное ускорение сопоставления аргументов при построении графа памяти

На 96 заранее отобранных траекториях ISETrace однократная подготовка строк аргументов и исключение избыточных строк сократили число циклов потока на **14,58%** (парный 95% ДИ **10,02–18,80%**) относительно прежнего потокового оператора. При полном повторе 1207 траекторий открытые свидетели и опубликованные исторические связи совпали после **72 186 из 72 186 событий**. Это результат для построения одного типа связей FEEDS, описывающего происхождение аргументов вызова. [Протокол](PROTOCOL_RU.md) · [Сводные метрики](results.json)

## Почему сокращение сохраняет граф

Прежняя реализация **A** сопоставляет каждое значение v предыдущего уникального производителя с исходным текстом аргументов R. При промахе рекурсивно обходит значения вложенных словарей и последовательностей, проверяя все встреченные строки L. Запись признаётся совпавшей, когда v входит в R или хотя бы в одну строку из L. Все операции выполняются на тех же строках Python, с чувствительностью к регистру и без нормализации.

**B** один раз на вызов перечисляет все декодированные строковые значения в исходном порядке. **C** дополнительно удаляет дубликаты и значения, которые целиком входят в сырой текст R. Если строка s входит в R, любая её подстрока v уже входит в R по транзитивности. Следовательно, удаление s не влияет на результат. Наружные кавычки, пробелы и ключи по-прежнему доступны для точной штатной проверки в R. Экранированные символы могут встречаться только в декодированной строке, поэтому C сохраняет такие строки. Совпадение предиката для каждого v даёт те же свидетели при вызове. Обработчик результата инструмента у всех реализаций один и тот же, поэтому индукцией по событиям сохраняется всё множество FEEDS. Временный кортеж строк освобождается после обработки каждого вызова. [Реализация](indexed.py)

## Объём повторной работы

Поток содержал 36 093 вызова инструментов и столько же результатов. По каждому из 72 186 событий проверялись идентичности открытых свидетелей, производителей и уже опубликованных пар. На четырёх срезах каждой траектории сверены также числа пар и фрагментных рёбер, всего 4828 состояний. Во всех реализациях совпал список кандидатов, всего 2 801 155 проверок.

| Операция по 1207 траекториям | A — повторный обход | B — все строки | C — непокрытые строки |
|---|---:|---:|---:|
| Начатые рекурсивные обходы аргументов | 2 783 314 | 36 093 | 36 093 |
| Строки, выданные рекурсивным обходом | 3 695 275 | 48 899 | 48 899 |
| Поиски значения в декодированной строке | 3 695 275 | 3 695 275 | 1 570 401 |
| Добавочные проверки «вся строка входит в R» | 0 | 0 | 48 853 |
| Суммарная длина подготовленных кортежей в ссылках | — | 48 899 | 19 787 |

Число обходов снизилось в 77,1 раза. Сокращённое представление уменьшило число поэлементных поисков на 57,50% относительно B. На тестовом потоке все 17 841 совпадение нашлись уже в сыром тексте. При этом на 18 082 вызовах оставались целые строки вне сырого текста. Возможность совпадения только после декодирования проверена независимо, в том числе для кавычек, Unicode, обратной косой черты и перевода строки. Прошли 13 явных случаев и 2302 запроса, перечисленных для двух способов сериализации девяти искусственных объектов. [Граничные проверки](fixture-results.json)

## Время построения

На панели из 96 траекторий единицей статистического анализа служит траектория. В каждом блоке — один разогрев и все шесть перестановок A/B/C, с заранее заданным порядком. Исходные события и их сериализация одинаковы. Замер включает подготовку кортежей, обход словаря производителей, поиск совпадений, обработку результатов и создание пар. Загрузка корпуса, распаковка, материализация фрагментов и оценка ответов находятся вне замера. Один поток Python 3.12.13 на Windows. В таблице — отношения сумм средних времён по траекториям и интервалы по 10 000 парных перевыборок. [Поштучные измерения](clock_samples.json.gz)

| Сравнение | Циклы потока | Время по монотонным часам | CPU-время процесса |
|---|---:|---:|---:|
| C / A, первичное | **0,854 [0,812; 0,900]** | 0,854 [0,812; 0,900] | 0,898 [0,804; 1,016] |
| B / A | 0,879 [0,844; 0,916] | 0,879 [0,844; 0,916] | 0,911 [0,826; 1,024] |
| C / B | 0,972 [0,961; 0,983] | 0,972 [0,961; 0,983] | 0,986 [0,886; 1,099] |

Среднее по повторам суммарное время панели составило 0,812 с для A, 0,714 с для B и 0,694 с для C. С понижением числа циклов завершились 77 из 96 траекторий C против A, 89 из 96 B против A и 62 из 96 C против B. Для типичной траектории выигрыш меньше агрегированного. Медианное попарное C/A равно 0,942, а при поочерёдном исключении каждой траектории агрегированное C/A лежит в пределах 0,851–0,874. Дополнительный Windows-таймер времени процесса дал нули в 373, 375 и 374 из 576 коротких повторов для A, B и C соответственно, поэтому интервалы по нему шире. [Независимый пересчёт](independent.json)

**Интерпретация.** Основной выигрыш даёт перенос рекурсивного обхода из цикла по значениям в подготовку одного вызова. Последующее исключение покрытых строк даёт ещё 2,80% снижения совокупных циклов относительно B [1,66%; 3,89%]. Суммарное время на другом корпусе будет зависеть прежде всего от числа проверяемых производителей, глубины аргументов и длины строк. Измерения относятся к одному локальному CPU и реализации на Python. Эксперимент демонстрирует инженерный выигрыш при точном сохранении графа. Сравнение с внешними системами, ускорение полного агента и качество его ответов требуют иных измерений.

План парных повторных измерений и анализ на уровне траектории оформлены с использованием процедур experimental-design и statistical-analysis из библиотеки Scientific Agent Skills. [Kassis и соавт., 2026](https://arxiv.org/abs/2609.00065)

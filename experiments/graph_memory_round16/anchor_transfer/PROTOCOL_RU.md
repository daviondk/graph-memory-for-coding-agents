# Репликация приоритета первых чтений на независимых задачах SWE-Explore

Исследуем, какие ранее показанные строки кода следует сохранять при фиксированном объёме памяти. Главная проверка воспроизводит направление результата R15 — первая открытая цель выше последнего файла по макроусреднённой нативной line precision. Дополнительно проверяем перенос между исполнителями и достаточно ли сохранить по половине места для первого и последнего файла. Сравниваем с числом повторных чтений и графом пересечений идентификаторов R15. Гипотезы об улучшении итогового исправления этим опытом не проверяются.

Используем 60 новых идентификаторов SWE-bench Verified из пересечения авторских каталогов двух запусков SWE-agent и публичного SWE-Explore. Исключаем все 199 ID R11 и единственный просмотренный для проверки формата файл astropy__astropy-12907. До обращения к индивидуальным меткам допускаем только явно указанные в коде научные проекты и инструменты Python и отсеиваем явно связанные с безопасностью условия. Сортировка кандидатов по SHA256 от постоянной строки r16-anchor и ID, первые 60. Одна и та же задача для обоих архивных исполнителей. В основной выборке 60 единиц, 120 траекторий; агрегируем исполнителей внутри задачи. Сохраняем также результаты отдельно по источнику. Отложенные случаи включают новые задачи, но могут относиться к проектам и семействам моделей предыдущей работы.

В основной политике берём первые три, в дополнительной первые шесть успешных ранее показанных native open / goto / scroll_up / scroll_down Python-файла с заголовком редактора и пронумерованными строками из корня репозитория. Событие с устаревшим или созданным агентом содержимым входит в лимит просмотров, но право передать его строки получает только полное побайтовое по содержимому строк совпадение с данным файлом на исходном commit Verified, кроме разделителей строк. Кандидаты не дополняются из будущих просмотров. Обрабатываем только исторические наблюдения до соответствующего префикса. Файлы Github используются для проверки ранее показанного текста. Скрытые строки из Git не выдаются. Отсутствие view или отсутствие совпадений даёт пустое предсказание. Отсутствующий удалённый артефакт по сетевой ошибке должен получить явный статус незавершённого наблюдения. 404 по проверенному Git SHA и корректному пути считается отсутствием файла в предписанной базе.

В строковом бюджете 60 и лимите 3 файлов первая, последняя, частотная и графовая политики воспроизводят функции R15, включая стабильный порядок по имени и возрастание номера строки. Пятая выдаёт максимум 30 строк первого файла и 30 последнего отличного файла в хронологическом порядке встречаемости (при единственном файле отдаёт ему весь бюджет). Остаток перераспределяет в первый, затем последний, затем другие файлы в порядке первой встречаемости. Предел в три файла и 60 уникальных строк общий. Скрипт и прогнозы по каждой паре контроль/репликация фиксируются по SHA до открытия публичной разметки.

Первичный результат — line precision по исходному ExploreEvaluator (core). Вторично считаем recall, F1, nDCG@100, долю непустой памяти, цену построения и число согласованных направлений среди испытуемых. Для разницы first минус recent и split минус first приводим парный разностный кластерный bootstrap по репозиториям (5000 повторов, seed 1630), а для обоих архивных исполнителей на одном ID сначала усредняем результаты. Малая численность кластеров ограничивает интерпретацию интервалов. Не используем прогноз успешности патча для выборки или наблюдений. Более высокие метрики отдельной политики сравнимы при одном бюджете, с опубликованным полным исследующим агентом потребуется отдельный запуск.

# Вторичная чувствительность к формату передачи

После получения результатов по основному формату проверяем влияние размера счётчиков. У обеих сторон члены множеств отсортированы по ID и передаются дельтами в ULEB128; первым ID можно быть нулю. Для сырого ответа передаём число событий, затем размер и дельты участников каждого события, в общем известном порядке запросов. У сводки число страт и размеры, A₀,B₀,J и число клеток передаём ULEB128; далее дельта ID кандидата и пара u/v в одном байте, если оба ≤14. В остальных случаях байт 255 и два ULEB128. Поскольку каждый запрос имеет известный селектор из не более чем 16 событий, для навигации кодируем совместные события по их индексу внутри такого селектора. В исходном основном формате остаются полные uint32 адреса. Уточняемые эпизоды кодируются так же, как обычные. Публикуем дополнительно zlib уровня 6 для независимого пакета каждого источника в каждом запросе (уточнения отдельным ответом, платим заголовок только при ненулевой передаче). Это чувствительность конкретного протокола; сырые счётчики и первичный формат зафиксированы отдельно. Проверяем декодированием полный payload каждого сравниваемого представления.

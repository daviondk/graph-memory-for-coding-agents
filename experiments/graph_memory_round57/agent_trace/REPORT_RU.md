# Повторные чтения в настоящих траекториях SWE-agent

**Межфайловые связи не повысили точность предсказания следующего возвращения к файлу.** На 134 таких переходах локальная история, совместно удержанные события и обычный выбор последнего просмотренного альтернативного файла дали 109 попаданий Top-1 (81,34%). Зато при оценке кэша обнаружился конкретный эффект организации записей. На 822 показах редактора группировка строк по файлам позволила повторно использовать 327 334 байта при ёмкости 16 КиБ. Построчный LRU вернул 268 905 байт. Простой двухуровневый LRU полностью воспроизвёл результат графового кэша на каждом показе. [Основные результаты](results.json) · [Проверка двухуровневого контроля](verify.py)

## Условия

Воспроизведены 3 284 действия из 108 опубликованных траекторий SWE-agent на 54 задачах SWE-bench Verified из восьми репозиториев. Для каждой задачи доступны траектории GPT-4 и Claude 3.5 Sonnet. Это полностью те же задачи, на которых в R16 изучались первые несколько окон редактора; здесь прочитаны полные журналы. Зафиксированы 822 успешных наблюдения с нумерованными строками, из них 394 явных открытия файла командой open. Для 292 открытий имеется предыдущий показ редактора, по которому можно делать прогноз. Путь команды и ответ инструмента скрыты до выдачи рейтинга. Представление наблюдения хранит путь, номер, непрозрачный идентификатор точного содержания строки и размер. Метки исходной задачи, состояние закрытых файлов и будущие действия недоступны. ## Что предсказывает возвращение к файлу

Смена показанного файла создаёт двустороннее событие для предыдущего и текущего файлов. Каждый файл хранит адреса двух последних своих переходов. Если у одного из участников ссылка сохранилась, это событие остаётся читаемым для обоих. Перед очередным открытием сравниваются собственные события текущего файла, все ещё доступные совместные события и полная хронология. Учитываем также частоту и давность просмотров и сходство путей. На первичной условной панели из кандидатов заранее исключается текущий файл. Из 134 возвратов только 83 имеют хотя бы два равноправных по доступности кандидата. В остальных 51 задаётся единственный ранее просмотренный иной путь. Возвраты пришлись на 36 траекторий, 29 задач и восемь репозиториев. [Зафиксированные прогнозы](forecasts.json.gz)

| Источник | Top-1 | Hit@3 | MRR |
|---|---:|---:|---:|
| Сходство имён и каталогов | 61,19% | 93,28% | 0,775 |
| Частота всех прошлых просмотров | 76,87% | 97,01% | 0,867 |

Расширение добавило сведения в 31 из 134 случаев и повысило стоимость чтения с 219 до 271 событий. Изменение Top-1 составило 0 п.п. при нуле наблюдавшихся выигрышей и потерь. Нулевой парный бутстрэп-интервал отражает тождественность наблюдаемых исходов на этом наборе. Совместное чтение добавило одно попадание Hit@3. Полная история потребовала 482 события. Среди 86 возвратов с хотя бы одним промежуточным действием совместная память и LRU дали одинаковые 87,21% Top-1. На GPT-4 было 15 возвратов, на Claude 3.5 Sonnet 119, что ограничивает сравнение исполнителей. На всех 292 открытиях, включая новые пути, дополнительный контроль, предпочитающий последний альтернативный путь и текущий файл при отсутствии альтернатив, дал 121 попадание, столько же, сколько обе ограниченные графовые политики. ## Какие наблюдения действительно можно повторно выдать

Кэш на 16 КиБ учитывает полезные байты строки с завершающим переносом, без служебного заголовка и метаданных индекса. Каждая выдача проверяется по фактическому последующему содержимому того же адреса. При неизвестной команде, способной менять рабочее дерево, применяется консервативный сброс. Лимит относится к резидентным байтам между действиями, обработка входного ответа требует отдельного временного буфера. Результаты описывают симуляцию кэша при неизменной реальной последовательности действий. Достигнутая экономия входных токенов модели, задержки и влияние на исправление кода не измерялись.

- На 394 явных открытиях обе базовые политики вернули 37 024 из 1 034 072 байт (3,58%), полностью покрыв 12 открытий. На всех 822 окнах, включая переходы и прокрутку внутри файла, группировка строк по файлам подняла покрытие с 10,73% до 13,06% (+2,33 п.п., парный 95% интервал по задачам [0,00; +6,37]). Полностью покрыты 57 окон против 46. Различия сосредоточены в 28 показах трёх задач. Для всех 822 окон двухуровневый LRU и графовая группировка выдали одинаковое число байтов, одинаковое полное покрытие и одинаковый счётчик устаревших строк. [Сравнение кэшей](results.json) · [Абляция группировки](writeback-results.json)
- После 838 штатных правок локальная инвалидация очищала только известный путь. В 75 случаях при этом сохранились строки другого файла. Дополнительных попаданий за счёт сохранения этих строк не возникло при 4, 16 и 64 КиБ. Диагностический режим без сбросов при 16 КиБ вернул 26,73% совпадающих байтов на открытиях, но встретил ещё 945 несовпавших строк по тем же адресам. Для такой политики нужна проверка версии источника. [Проверка инвалидации](invalidation-results.json)
- Успешные правки редактора сами показывали актуальный текст. Запись всех 529 таких окон обрабатывает дополнительно 1 170 168 входных байтов. На 394 явных открытиях улучшений не появилось. На всех показах повторно пригодились 1 750 дополнительных байтов в одном случае. Тот же результат дал отбор только ранее виденных адресов внутри вывода правки при 856 636 входных байтах. Это стоимость полезного содержимого, предлагаемого к записи, без учёта накладных расходов. [Проверка результатов правок](writeback-results.json) · [Индивидуальные наблюдения](writeback-events.json.gz)

**Вывод для статьи.** Положительный результат графа на совместных изменениях Git требует отдельной проверки на последовательности реальных инструментальных действий. В этой панели недавний файл хорошо предсказывает возвраты, в первую очередь при малом числе ранее посещённых путей. При ограниченной ёмкости эффект на возвращаемые байты объясняется группировкой строк одного файла. Для дальнейшей проверки разумны более длинные сессии с несколькими активными файлами и дешёвая проверка актуальности наблюдения после запуска стороннего инструмента.

## Воспроизведение

Из этой директории достаточно запустить `python -B verify.py` для быстрой независимой проверки 292 прогнозов и 822 сравнений кэша. Полный офлайн-пересчёт по сохранённым проекциям использует Python и NumPy.

```sh
python -B replay.py
python -B score.py
python -B invalidate.py
python -B writeback.py
python -B verify.py
```

Для независимого извлечения из оригиналов у скриптов `extract.py`, `invalidate.py --project` и `writeback.py --project` есть параметр `--archive-dir`. Подкаталоги соответствуют двум идентификаторам исполнителей из реестра, JSON каждого прогона называется по идентификатору issue. Сжатые проекции содержат все данные для оценки офлайн.

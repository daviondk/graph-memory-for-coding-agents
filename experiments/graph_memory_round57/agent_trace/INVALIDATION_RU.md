# Вторая гипотеза о сохранении строк при правке известного файла

После получения первичных результатов фиксируем отдельный разведочный контраст на тех же 108 траекториях. Гипотеза — после штатной однофайловой команды редактора память может сохранить наблюдения по другим путям. Ожидается больше проверенных повторно прочитанных байтов. Основной контроль очищает всё содержимое после каждого барьера. Экспериментальное правило меняет только обработку законченной команды SWE-agent вида edit диапазон … end_of_edit. Команда должна состоять ровно из одного такого действия. В уже полученном выводе требуется единственный однозначный заголовок файла под корнем репозитория. До последующего действия сбрасываем все сохранённые строки этого пути и сохраняем остальные. Любое другое действие с возможной записью вызывает общий сброс. Эталонные патчи и имена будущих путей в решениях недоступны. Команды не исполняются.

Сравниваем LRU при 16 КиБ с чувствительностью 4 и 64 КиБ. Отдельно строим диагностический потолок без сбросов, проверяя совпадение строк с реальным последующим выводом. Засчитываем только равные байты. Несовпадающие сохранённые строки показываются как потенциально устаревшие. На практике это требует учёта алиасов путей и внешних изменений. Основная метрика — разность доли обслуженных байтов среди всех явно открытых редактором строк с бутстрэпом по issue. Также указываем число полных открытий, случаи сработавшей выборочной инвалидации и число наблюдавшихся несовпадений. Используем тот же зафиксированный набор запросов и те же наблюдения, механического преимущества над действующей промышленной системой этот тест не устанавливает.

# Какие результаты инструментов сохранять

Фиксируем вторичный опыт до извлечения содержимого ответов на команду edit. При успешной правке штатный редактор уже выводит содержимое файла около изменённых строк. Проверяем, сколько будущих явно запрошенных байтов выдаёт кэш, если сохранить это наблюдение как новый источник, включая строки, прежде не прочитанные агентом. Доказательством успеха считаем стандартное сообщение «File updated» вместе с единственным заголовком и непрерывной нумерацией строк. При неполном доказательстве действуют прежние сбросы. Контроль с теми же инвалидациями и LRU заполняется только обычными командами чтения. Бюджет полезного содержимого 16 КиБ у обеих сторон, дополнительно 4 и 64 КиБ. На чтении измеряем совпадение пути, номера и точного содержания строки, число полностью доступных открытий и несовпадающих сохранённых строк. Любые обращения нужно оценивать до приёма очередного ответа в память.

Дополнительные контроли — сохранять из ответа edit только строки с адресами, уже наблюдавшимися до записи, и сохранять всё подтверждённое окно с отдельным учётом суммарных записанных байтов. Это позволяет отделить обновление старых наблюдений от добавления новых адресов. Для сравнения с группировкой по графу на исходных данных строим обычную иерархическую LRU по файлам и строкам с теми же глобальными барьерами. Такие абляции на уже использованной выборке носят разведочный характер. Учитываем стоимость записи проекции окна при той же ёмкости памяти. Этот опыт меняет правила кэширования в replay и сохраняет дальнейшие реальные действия неизменными.

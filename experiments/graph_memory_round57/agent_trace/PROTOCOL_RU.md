# Следующее чтение и точное повторное использование наблюдений SWE-agent

Используем все 108 архивных траекторий из заранее зафиксированного невредоносного корпуса R16, два исполнителя на одних 54 задачах SWE-bench Verified. Прогнозы фиксируются до оценки. Каждый журнал обрабатываем от начала до конца. Вводом служат только уже завершённые действия этой траектории. Никаких сведений из другой траектории, эталонного патча, финального ответа или будущей команды. Цель основного испытания — угадать, какой ранее встречавшийся файл агент снова откроет после просмотра другого файла. Разбиение ведём по событиям редактора, включая команды поиска и оболочки между ними. Путь будущего открытия из текста команды скрыт. Отдельно считаем также все открытия, включая новые пути. Итог относится к воспроизведению записанной политики агента.

**Испытание адресов.** Каждый переход между двумя различными файлами, показанными редактором, порождает одно событие со ссылками на обоих участников. В памяти остаются два последних разных по времени события каждого файла. Событие хранится один раз до освобождения последней ссылки. Из состояния перед следующим чтением ранжируем ранее наблюдавшиеся файлы. Основной контроль — последние два собственных события текущего файла. Политика совместного чтения дополнительно учитывает оставшиеся события этого файла, теперь удерживаемые другим участником. Ранг кандидата задают число соответствующих переходов, затем давность последнего просмотра и путь. Отдельно сравниваем LRU, частоту просмотров, статическое совпадение токенов имён и каталогов, все прошлые переходы, равный бюджет двух декодирований по давности и направленную статистику переходов. Для старта нужен хотя бы один предыдущий показанный редактором файл. Для главной метрики требуется явная команда open, смена файла и хотя бы одно предшествующее наблюдение целевого файла. Условие повторного посещения определяет панель после прогноза и считается отдельно от результата на всех открытиях.

**Цена и ценность повторного чтения.** В дополнительной симуляции кэша принимается максимум 16 КиБ фактически напечатанных строк. Сравниваются LRU и замена с приоритетом ранга файлов из общего графа. На момент решения известны только адреса и содержимое ранее наблюдавшихся строк. Запрос обслуживается перед добавлением нового наблюдения. Засчитываются только ранее сохранённые строки по тому же пути и номеру с точным совпадением байтов. После любого действия с возможностью записи кэш целиком инвалидируется. Разрешён узкий список команд редактора, навигации и поиска с безопасными аргументами, остальные действия консервативно считаются барьером. Отчёт отражает проверенные повторно использованные байты и полностью покрытые открытия, пиковый сохранённый объём и число просмотренных событий. Считаем UTF-8 байты полезного содержимого с переносом строки. Данных о токенизаторе инструментального протокола для обоих агентов нет.

**Оценивание.** Первичная метрика — Top-1 на явных возвратах к другому файлу; сравнение совместной и локальной истории. Вторичные — Hit@3, MRR, охват по задачам, работа чтения, повторно использованные байты на всех открытиях. Отдельно по исполнителям, задачам и событиям с промежуточным действием. Пары агентов одного issue остаются одним кластером при бутстрэпе 20 000 раз, seed 57083. При малом числе выживших для совместного чтения событий укажем ограничение мощности. Повторное использование данных R16 раскрываем. Историческую стоимость решения, эффект на исправления и фактическое поведение агента при изменённой памяти этот replay не идентифицирует.

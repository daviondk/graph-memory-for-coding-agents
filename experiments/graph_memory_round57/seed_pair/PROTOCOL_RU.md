# Сохранять ли отдельную правку, если уже есть граф весов пар

Исследуем запрос агента с **двумя известными путями**. Для каждого будущего коммита с 3–64 путями Python равновероятно раскрываем одну неупорядоченную пару по SHA, ранжируем 8 остальных исторически известных путей. Невидимые ранее цели входят в знаменатель m−2. Весь прогноз делается по префиксу до проверяемой правки; выбор двух правильных путей моделирует условную задачу, масштаб эффекта у реального агента проверяется отдельно.

**Новая выборка до анализа.** Проекты pygments/pygments, python-pillow/Pillow, pydata/xarray, dask/dask, pypa/hatch, astropy/astropy. По 1 024 последовательных перехода first-parent либо сколько доступно. Допускается отсутствие подходящих запросов и явно отмеченный сбой источника без замены. Изучаем вторую половину всех потоков. Эти репозитории выбраны до расчёта по ним двухъякорного результата и отличаются от обеих панелей текущей серии. В качестве вторичных панелей используем 6 репозиториев R57/replication и 3 длинных истории R56; эффект одноякорных методов там уже известен. Для длинной вторичной панели — те же SHA modulo 11. Для двух новых панелей — все подходящие коммиты. SHA modulo C(m,2) определяет индекс пары в лексикографическом порядке сочетаний путей.

**Память и общий вход.** Для каждого якоря берём восемь самых недавних удержанных событий, предпочитая правки до 6 файлов с заполнением свободных слотов. Все сравниваемые варианты получают равное объединение этих наборов, каждое исходное событие декодируется один раз. Две проекции содержат по одному весу для каждого кандидата x относительно якорей a и b. За эпизод с якорем и x добавляется 1/(m−1). Нормировка вторичных ключей совпадает с R56. Сумма двух оценок даёт основной попарный контроль. Обозначим через p(x) положительные суммы, нормированные на единицу по всем кандидатам вне обоих якорей. Число совместных прошлых событий обоих якорей с третьим участником — c. Во всех них q(x) получает по 1/(m−2) за совместное присутствие, поэтому сумма q равна c. Выдача предложенного метода ранжируется по p(x)+q(x); при c=0 точно совпадает с попарной суммой.

**Сильные контроли.** По двум проекциям дополнительно считаем геометрическое и гармоническое средние; равенства разрешает попарная сумма, затем частота в прошлых 32 коммитах и ID. Плацебо использует то же число совместных событий c и тот же суммарный вес бонуса, но направляет его кандидатам пропорционально гармоническому среднему проекций. При отсутствии общего кандидата возвращается исходная сумма. Вторичная политика сначала сортирует по свидетельствам тройки, затем по p. Для каждого запроса замеряем число повторно используемых эпизодов, их байты и SHA. Существенны сравнения и при полном отсутствии ранее наблюдавшихся троек. Первичная пара — p+q против p на новой панели, средний по проектам Recall@8 и 95% описательный парный кластерный bootstrap (20 000, seed 57201). Публикуем также среднее по запросам, Hit@8, изменения по проектам, покрытие c>0, полные ничьи и сильные контроли. Обобщение требует независимого подтверждения при альтернативных сценариях поступления якорей.

**Математический контроль представления.** В разных историях тройки равны (Aᵢ,Bⱼ,Cᵢ₊ⱼ₊ₛ) по модулю n. При изменении s полные попарные веса и степени одинаковы, а третий файл для пары Aᵢ,Bⱼ меняется. Для равновероятных s любой метод, которому доступны только эти агрегаты, при k≤n имеет ожидаемый Hit@k не выше k/n; память с полными событиями идентифицирует нужный файл. Не включаем временные метки отдельных рёбер в этот аргумент: они могут идентифицировать исходную правку. На реальных данных проверяем, насколько часто такая неоднозначность существенна после учёта исходного качества попарного поиска. Существуют работы по прогнозу симплициального замыкания на гиперграфах и по объединению ассоциативных правил при рекомендации программных изменений.

# Репликация выбора эпизодов на новых историях

До расчёта результатов фиксируем шесть публичных библиотек: pypa/trove-classifiers, pallets-eco/blinker, lepture/mistune, python-babel/babel, pyparsing/pyparsing, Python-Markdown/markdown. Критерий выбора — публичная библиотека Python с историей Git и отсутствие проекта в панелях cochange и partner_clock R55, а также в retrieval-панелях R56. Размер и качество предсказания в новой панели заранее не использовались. Для каждого проекта фиксируем текущий HEAD основной ветки, последние 1 024 перехода по первому родителю или все имеющиеся, если история короче. Пропавший, недоступный или не образующий запросов проект показываем явно, другие проекты не подставляем. В Git берём только коммиты и деревья. Историю отложенной половины не смотрим для выбора метода.

После прогрева на первых floor(N/2) переходах оцениваем все коммиты с 2–64 изменёнными .py-путями. Список упорядочен лексикографически. Якорь — один из этих файлов по int(SHA,16) mod m; прогноз формируется до добавления коммита в память. Цели — остальные m−1 путей, в том числе ранее невидимые. Кандидаты — все ранее виденные пути кроме якоря. Однофайловые коммиты обновляют недавние частоты; сверхкрупные исключены и из частот. Требуется угадать до восьми файлов. При равенстве балла выше файл, чаще встречавшийся в последних 32 прошедших коммитах, затем меньший ID первого появления. Файлы с нулевым баллом участвуют в заполнении списка.

Каждый путь владеет последними восемью многофайловыми событиями, в которых участвовал. Доступны все события якоря, остающиеся у любого их владельца. Состав одного события декодируется не более одного раза. Общий потолок — 8 событий на запрос. Размеры и порядок известны до декодирования. Сравниваем заранее определённые шесть вариантов выбора из [R56](../../graph_memory_round56/size_control/PROTOCOL_RU.md): последние восемь (тождественны своим последним), восемь наименьших с приоритетом недавности, жёсткий порог m≤6 и m≤8 с выбором самых недавних, те же два порога с заполнением свободных мест недавними превышающими порог событиями. У каждого выбора два правила голосования — единица или 1/(m−1) за каждого партнёра. Нормировку вычисляем точно. Выбор для нового теста зафиксирован после ретроспективной разработки на прежних проектах.

**Основной контраст** — порог 6 с заполнением и весом 1/(m−1) против последних восьми с тем же весом. Основная метрика — разность Recall@8, усредняем по запросам внутри каждого проекта, затем поровну по проектам с запросами. Двусторонний процентильный 95% интервал строим по 20 000 парным выборкам проектов с возвращением, seed 57061. Дополнительно сообщаем pooled Recall@8, Hit@8, индивидуальные разности, попарные выигрыши/равенства/проигрыши и точный двусторонний sign-flip по проектным разностям с оговоркой об обменности. Эти статистики описывают шесть целенаправленно выбранных проектов. Число запросов не заменяет число независимых проектов.

**Контроль стоимости.** Запишем число раскодированных событий, число входящих в них путей и размер прочитанного состава (четыре байта на ID пути) без учёта метаданных. В дополнительном парном сравнении дадим обоим основным вариантам один и тот же персональный для запроса потолок байт — минимум их номинальных объёмов при восьми событиях, известный по метаданным. Пройдём первоначально выбранный список в порядке приоритета, пропуская эпизод, если он уже не помещается в остаток. Оба ограничены теми же 8 событиями и тем же потолком байт. Из-за неделимости событий фактически потраченные байты могут различаться. Полный SQL/LLM запуск сюда не входит. Публикуем все исходы, включая малые проекты и альтернативы, и сохраняем сырые ранги и список прочитанных событий.

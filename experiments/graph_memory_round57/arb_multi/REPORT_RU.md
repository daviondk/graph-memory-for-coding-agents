# Достаточно ли в истории эпизодов с несколькими известными путями

На **105 задачах поиска тестовых файлов** Agent Retrieval Bench кодовый агент получает известные пути реализации и выбирает пять адресов тестов. Мы проверили, полезно ли выше ранжировать тест, если в одном прошлом коммите вместе с ним изменились сразу несколько известных файлов задачи. Среди 33 задач с несколькими исходными путями такой коммит с доступным тестом нашёлся лишь **в семи**. Правило изменило состав итоговой пятёрки в одном случае и потеряло один из двух эталонных тестов. На всей панели Recall@5 снизился с **78,03% до 77,56%** (−0,48 п.п., парный 95% интервал по репозиториям [−1,44; 0,00]). Ни одного дополнительного эталонного адреса не найдено. [Протокол, зафиксированный до расчёта коммитом f714f10a](PROTOCOL_RU.md) · [Исходы](results.json).

**Сравнение.** В прежнем фиксированном ансамбле R56 пять источников — Qwen3-Embedding-4B/8B, опубликованные Lexical и RepoMap с ограничением на тесты и сходство имён. Шестой источник — ранги тестов из истории Git. Исходный граф даёт голос 1/(m−1) за каждый эпизод из m файлов, в котором одновременно встречались seed и тест. Новый метод сначала сортирует по сумме C(k,2)/(m−1), где k обозначает число различных исходных файлов задачи в данном эпизоде с тестом, затем по старому линейному баллу и прежним правилам ничьих. Коммит учитывается один раз. До оценки исходные top‑5 статического и линейного вариантов воспроизвелись во всех 105 задачах. Обе графовые схемы получили ровно те же 179 событий, уникальных внутри каждого запроса, и те же 921 перечисленных адресов в них. Внешние системы представлены опубликованными списками. Исполнялись только алгоритмы ранжирования путей. На семи задачах с групповыми свидетельствами обнаружено 12 таких событий, содержащих тест. Графовый список изменил порядок в двух задачах, в обоих случаях изменение дошло до ансамбля. В задаче **huggingface/transformers** (базовый коммит 23d3e8c251df, ID d33132ce299c01e986c74210) более общий tests/test_modeling_common.py вытеснил целевой tests/utils/test_core_model_loading.py. Recall@5 уменьшился с 1 до 0,5; первый верный адрес сохранил вторую позицию. В задаче **tokio-rs/tokio** (f24b9824e67f, ID c5186727aa0268eb514ee57c) переставились адреса внутри той же пятёрки, оба метода получили нулевой Recall@5. На уровне всех запросов — 0 выигрышей, 1 проигрыш, 104 равенства. Эффект новой схемы плохо идентифицируется на этой панели из-за редкости случаев, где она способна изменить выдачу. При воспроизведении обнаружили особенность исходного фиксированного ансамбля: на двух запросах один известный seed сам имел тестовую роль и занял позицию в первом top‑5. Дополнительно исключили все известные адреса перед отсечением, заполнив обе позиции следующими файлами. Все схемы выдали ровно пять новых путей; значения всех трёх метрик в таблице при этом совпали с исходными. Ансамбль использует дополнительные источники и Git-историю. Одиночным системам доступен другой вычислительный бюджет.

# Стоимость первого обращения к двум источникам

В основной оценке SQLite из R47 пары материализованы заранее. Здесь впервые измеряем задержку, если при запуске есть только неизменяемая проекция кандидатов и списки источников. Тест использует ровно 1 280 равномерно выбранных пар из того же опубликованного протокола (32 на каждую из 40 траекторий). Оба плана получают одинаковый ранжированный массив и двоичный признак принадлежности каждой из двух вершин. Компиляция библиотеки и подготовка общих данных не входят во время ни одного плана.

Для каждой пары проверяем 1, 2, 4, 8 и 16 разных запросов к весам внутри одного запроса к памяти. У прямого плана каждый раз вызывается нативный C++ с повторным использованием буферов. У материализующего плана в измерение входят вычисление всех аффинных кандидатов, хранение полных последовательностей в оперативной памяти и каждый последующий выбор. Первичная проверка — время до выдачи **восьми** полных пакетов с учётом построения. Остальные горизонты показывают границу окупаемости. Порядок исполнения двух планов и временных блоков перемешан, seed 47071, четыре записываемых повтора после одного прогрева. Для каждого префикса измеряется сумма времени независимых последовательных выборок; один замер построения на пару и повтор. Вся последовательность пакетов сравнивается побайтно. Замеры по паре зависят друг от друга, единица bootstrap — одна из 40 траекторий, 10 000 парных выборок, 95% перцентильный интервал для отношения сумм и для разности средних. Публикуем также случаи замедления и долю пар, окупающихся к каждому горизонту. Это локальная граница выгодности при заданных повторных чтениях одного снимка. Количество обращений в реальном интерактивном продукте не наблюдалось. Байты базы на диске в этой проверке не создаются.

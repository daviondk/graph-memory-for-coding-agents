# Когда окупается создание индекса по запросу

Для восьми разных изменений весов одной пары источников создание таблицы возможных пакетов в RAM вместе со всеми восемью выдачами заняло **133,39 мкс**, восемь прямых переоптимизаций на C++ — **439,38 мкс**. Отношение средних **3,29× [3,15; 3,43]**. Первое чтение само по себе стоило дороже в 2,21 раза (95% ДИ 2,13–2,31). На первой и второй точках по совокупности дешевле прямой план, на четвёртой выиграл подготовленный. Среднее по четырём блокам дало преимущество материализации на 1 238 из 1 280 пар к четвёртому чтению (ещё одна пара дала точное равенство суммы наносекунд) и на всех 1 280 к восьмому. Панель из 40 независимых проекций дала 102 400 поэлементных сравнений двух полных упорядоченных ответов с учётом прогрева; все совпали. Обоим планам заранее доступны подготовленные исходные массивы и отметки источников. «Первое обращение» означает отсутствие двухмерного индекса для этой пары. База и ОС прогреты. На отдельной наблюдаемой нагрузке повторно встречались только 29,09% упоминаний пар производителей значений. Две панели имеют разные ключи и семантику. Из этих результатов нельзя вывести долю пользовательских запросов, которые доходят до четвёртого чтения. [Сопоставление с наблюдениями](../observed_updates/REPORT_RU.md) · [Измерение готового SQL-представления](../joint_packets/REPORT_RU.md)

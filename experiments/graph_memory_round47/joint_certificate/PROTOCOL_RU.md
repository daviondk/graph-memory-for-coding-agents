# Сохранение исходного пакета при двух одновременных изменениях веса

До извлечения исходов фиксируем повторное исследование 40 проекций ISETrace из R46, в которых там меняли только один вес. Как часто одномерная информация может гарантировать сохранение контекста при одновременной аддитивной поправке двух источников? Новое событие — две разные пары запрос–источник, принадлежащие одному запросу, со знаковыми целочисленными поправками. Один кандидат может ссылаться на оба источника, тогда получает обе поправки, первичные цены, префикс, полезности и порядок фиксированы. Измеряется точное равенство всего упорядоченного пакета, бюджет 2 048, порог префикса 1 024. P — исходный оптимум. Все эксперименты выполняются на CPU. Настоящие метаданные относятся к синтетическим траекториям OS-агента, в которых инструментальные вызовы исполнялись.

**Выбор до результатов.** Для каждого из 40 запросов среди всех неупорядоченных пар источников берём первые 32 по SHA-256 от строки «470531|q|sourceA|sourceB», где идентификаторы упорядочены лексикографически. Если пар меньше, берём все. Это основная панель. Дополнительно отдельно берём до 8 пар с пересечением множеств допустимых необязательных кандидатов и до 8 с непересекающимися непустыми множествами по тому же правилу, исключая основную панель. В дополнительной панели определяющий признак виден при выборе. Если в проекции нет пар данной категории, сохраняем нулевое число. Различаем метки в общих допускаемых узлах и среди фиксированного префикса. Обязательно публикуем долю случаев, когда хотя бы один источник не поддерживает ни одного кандидата, способного поместиться в хвост.

**Нагрузка.** Для каждой пары декартово произведение шести ненулевых поправок — обеих знаковых величин Q32/64, Q32/16, Q32/4, итого 36 комбинированных событий. Полное динамическое программирование строит исходный и каждый новый пакет при едином полном порядке отсутствия последнего различающегося ранга при равенстве. Отдельный диагностический набор берёт определённые по осевым интервалам угловые точки текущей области [−Q32/4,+Q32/4]² и соседнюю к каждому углу внутреннюю точку, приблизительно посередине отрезка между соответствующими осевыми границами с округлением к нулю. В этой панели выбор точек зависит от осевого индекса и обсуждается отдельно от фиксированной шкалы. Углы, для которых хотя бы одна компонента нулевая, всё равно регистрируются.

**Основное сравнение.** (1) Полная оптимизация для каждого события. (2) Наивный прямоугольный допуск при принадлежности обеих компонент своим осевым интервалам. (3) Выпуклая оболочка четырёх сертифицированных осевых концов, ограниченных текущей областью. (4) Та же достаточная проверка с полными целочисленными пределами из исходного сертификата, используя истинные бесконечные направления как рецессионные лучи. (5) Консервативный контроль, который переиспользует результат только когда обе поправки лежат в благоприятных неограниченных направлениях или равны нулю. Для бесконечности используем символический случай; наблюдаемые значения всегда конечны. Эталон — побитовое совпадение полной оптимизации. Проверяем также на каждой проекции отсутствие переполнения int64 по сумме модулей. При сравнении с сертификатом проверяем все его принятые и отклонённые запросы. Любое ложное принятие достаточным правилом опровергает реализацию. У небезопасного прямоугольника сохраняем явный пример при наличии. Для каждого измеряем долю безопасно пропущенных вызовов полной оптимизации, precision, recall для неизменного пакета и случаи ошибок. Показатели новой основной панели агрегируем с равным весом каждой траектории. 95%-й процентильный интервал — 10 000 парных перевыборок целых траекторий, seed 470532; пары и 36 точек одного случая не считаются независимыми. Частота искусственных событий не оценивает распределение будущих пользовательских исправлений.

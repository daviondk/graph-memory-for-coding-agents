# Совместная коррекция двух источников и сохранение прежнего пакета памяти

**99,22% фактически неизменных пакетов распознаны без единой ошибочной выдачи** при заранее заданных одновременных поправках двух весов ISETrace. Это 17 014 из 17 147 сохранившихся результатов и 36,92% всех 46 080 запросов. При изменении результата метод передаёт управление полному оптимизатору. Основной вывод относится к возможности сохранить старый пакет на фиксированных числовых метаданных. [Протокол](PROTOCOL_RU.md) · [Все исходы](results.json)

## Что проверялось

Для каждой пары проверили все 36 сочетаний шести независимо заданных положительных и отрицательных поправок ±1/64, ±1/16, ±1/4. Исходный контекст имеет общий бюджет 2 048 токенов и фиксированный ранговый префикс до 1 024. Эталон — полный оптимальный упорядоченный пакет при каждой поправке. Данные ISETrace происходят из синтетических траекторий OS-агента с реально исполненными вызовами. Изменения доверия к источникам заданы экспериментом. ## Математическое основание

Пусть $P$ — старый победитель, $T$ — конкурент, $u$ — базовая полезность пакета. Числа кандидатов, на которые действуют поправки, обозначим $a(T)$ и $b(T)$. Чтобы $P$ сохранился, для каждого $T$ нужна неотрицательная разность

$$u(P)-u(T)+x\,[a(P)-a(T)]+y\,[b(P)-b(T)].$$

Разность должна быть строго положительной для конкурента, предпочитаемого при равенстве. Во всех точках, где выбран один и тот же полный пакет, выполняются эти линейные условия. Их выпуклая комбинация сохраняет как нестрогие, так и требуемые строгие неравенства. Поэтому обрезанный сертификат, выбирающий по знакам полуоси с допустимыми радиусами $r_x,r_y$, проверяет $|x|r_y+|y|r_x\leq r_xr_y$. На оси достаточно собственного интервала. Если радиус равен нулю, любое ненулевое смещение в этом направлении отвергается.

Неограниченный луч требует отдельного доказательства. Если при сколь угодно большой положительной осевой поправке пакет остаётся победителем, у него нет конкурента с большим наклоном по этой оси. Иначе такой конкурент рано или поздно вытеснил бы пакет. Следовательно, движение вдоль этого луча из любой уже допустимой точки может только увеличить преимущество над каждым конкурентом или сохранить его. Это справедливо и на самой второй, конечной границе при ничьей. При одном неограниченном благоприятном направлении достаточно проверить компоненту по второй оси. Две благоприятные бесконечности дают весь соответствующий квадрант. Для реализации использованы целые числа Q32, единый порядок ничьих для полных пакетов и проверенная верхняя граница истинных конечных порогов 5 042 468 045, далеко ниже маркера бесконечности. Числа осевых пределов взяты из базы исходной одномерной проверки. [Алгоритм](geometry.py) · [Осевые интервалы R46](../../graph_memory_round46/source_sensitivity/REPORT_RU.md)

## Почему независимый прямоугольник ошибается

В проекции q03 прибавка 268 435 456 Q32 к каждому из двух источников по отдельности сохраняет пакет. Верхние допустимые границы составляют 300 142 398 и 516 140 408. При одновременной прибавке старые идентификаторы [0, 1, 4, 3, 72] сменились последовательностью [0, 1, 4, 5, 72, 73, 78, 94, 114, 74, 110]. Поддерживаемые этими источниками кандидаты различны, конкуренцию создаёт общий бюджет. На всей основной панели 96 из 104 ошибочных принятий возникли при однонаправленных поправках, восемь — при разнонаправленных. Пограничная диагностика, намеренно выбирающая углы и внутренние полусуммы осевых пределов, нашла 540 ошибочных принятий из 10 240 событий; полный сертификат распознал 9 120 из 9 700 сохранившихся. Эту частоту нельзя переносить на основную шкалу запросов.

На выбранных 40 проекциях **ни у одной из 97 676 возможных пар** не нашлось общего подходящего кандидата хвоста. Все 5 009 узлов с зафиксированным происхождением ссылались ровно на один источник. Для 181 из 1 280 основных пар хотя бы один источник не затрагивал подходящего кандидата. Среди оставшихся 1 099 пар оба источника активны: полный сертификат нашёл 13 474 из 13 607 неизменных пакетов, прямоугольник дал все 104 ошибки. На отдельной дополнительной панели из 320 непересекающихся активных пар полная версия нашла 3 739 из 3 802 неизменных без ошибок; прямоугольник ошибся 14 раз. Это дополнительная выборка, обусловленная наблюдаемыми метаданными. В доказательстве разрешено перекрытие: кандидат, поддержанный обоими источниками, получает обе прибавки. На отдельном контроле из 160 синтетических пулов с принудительным пересечением и полным перебором 19 360 координат полный сертификат принял 4 155 из 6 729 неизменных, без ошибок. Прямоугольник ошибся 387 раз. [Независимый контроль](independent.json)

## Воспроизведение

`python -B replay.py` запускает C++17-оптимизатор на включённом числовом снимке и сверяет все полные маски. Требуется доступный для процесса g++ либо переменная CXX. `python -B independent.py` проверяет 320 реальных положений через отдельную реализацию Python с полными масками в динамической таблице и выполняет синтетический перебор перекрытий. `python -B analyze.py` пересчитывает все показатели и интервалы посредством NumPy. `python -B verify.py` проверяет состав по контрольным суммам, панель и расчёты. Сборку самого снимка можно повторить через `python -B build.py` в дереве серий R46–R47. Тела инструментальных вызовов в артефакте отсутствуют.

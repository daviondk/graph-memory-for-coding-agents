# Роли свидетельств при чтении памяти агента

Проверяем, помогает ли агенту выбирать фрагменты, дополняющие друг друга по функциональной роли. Первичная оценка — доля запросов, для которых первые пять фрагментов содержат достаточное множество (Complete-MSS@5). Основной контраст — условное ролевое покрытие минус статическое ранжирование с теми же обученными вероятностями и весом. Сравнение с одиночным Qwen3-Embedding-8B, с перестановкой ролей и с R46 DPP/MMR проверяет практическую значимость. Используем 204 состояния 69 репозиториев вне прежнего пилота. Также приводим все 214, отдельно 10 пилотных, результаты при восьми фрагментах, полноту групп и два общих бюджета. Эту часть публичного Cal500 исследовали в предыдущих циклах. Скрытый Test500 здесь недоступен для локального оценивания.

**Источники информации.** Репозитории распределены до начала серии по 179 train, 101 dev и 214 test состояниям. Для обучения роли разрешены публичные сертификаты только train. Изучена частотность ролей в train. Поведение (176 групп), локализация ошибки (125), ограничение API (31) и объединённый класс из verification/interaction/history (10+4+1) образуют четыре координаты. Несколько групп одного типа и альтернативные достаточные наборы создают неполное соответствие между четырьмя ролями и сертификатом, это проверяется диагностически. Для чтения доступны те же первые 511 токенов Qwen: в запросе information_need, current_subgoal, issue; у кандидата путь и фрагмент. Состояние просмотра используется только в одинаковом дополнительном режиме отсрочки. Дополнительные действия и история остаются скрыты.

**Модель.** Четыре L2-логистические регрессии предсказывают вхождение фрагмента в официальную группу данного типа. Отдельные четыре логистические регрессии по одним признакам запроса предсказывают востребованность ролей. Признаки строятся из совпадения символов/идентификаторов в объявлении, вызовах, тексте и пути, слов запроса, BM25 по видимым фрагментам, синтаксических и тестовых индикаторов. Обучение использует только числовые представления и train-разметку. Языковая модель и дополнительные эмбеддинги для этих признаков не нужны. Обучаем также одноместный контроль union на объединении ролевых попаданий. L2 C=0,15 для классов кандидатов и C=0,1 для классов запросов, стандартизация по train. В подборе коэффициентов dev не участвует. Доступный Qwen-ранг есть только для test. Для независимой диагностики тех же весов на 101 dev и 214 test повторяем ролевую и статическую политику от одинакового BM25. Веса заморожены для обеих исходных выдач.

**Выбор.** Внутри состояния делим вероятность каждого класса кандидатов на максимальную вероятность в его столбце и умножаем на предсказанную востребованность этой роли. Общий скаляр делит всю матрицу на максимальную по кандидатам сумму, получаем G с 0≤Gᵢᵣ≤1. Для выбранного множества S моделируем покрытие как F(S)=Σᵣ[1−∏ᵢ∈S(1−Gᵢᵣ)]. Прирост составляет Σᵣ Gⱼᵣ∏ᵢ∈S(1−Gᵢᵣ). При неотрицательных G это монотонная субмодулярная функция. Жадный читатель выбирает максимум суммы 1/√rank(j)+0,65·приращение, полный порядок сохраняется. Интерпретация вероятностей после нормировки эвристическая. Код разрешает равенства исходным порядком. Для статического контроля заменяем произведение остатка единицей. Для placebo независимо переставляем столбцы каждого кандидата с фиксированным hash-seed, сохраняя его сумму, начальную цену и все четыре значения; нарушается согласованность ролевых названий между документами. Для union используем одно нормированное предсказание при том же весе и без затухания. Отдельный простой контроль сочетает семантический и BM25-ранги, поправка 0,65/√lex_rank. Сравнения повторяются после сдвига просмотренных в хвост (хвост целиком по исходной выдаче для всех обученных политик). Без сдвига — основной режим. Маскирование отражает устройство набора.

**Анализ.** Фиксируем прогнозы всех новых политик до чтения test-исходов. Точечные оценки микро/макро, 95%-е номинальные интервалы по 20 000 парным перевыборкам целых репозиториев, seed 4721401. Учитываем совпадения/потери при одинаковых k и префиксе целых единиц при 2 048/6 144 токенах; при первом превышении лимита останавливаемся. Метрики ролевых вероятностей — average precision кандидатов, распространённость, качество прогноза типов и число состояний, где у запроса несколько типов. Это вторичные диагностики. Все оценочные ролевые классы проверяются после сохранения прогнозов; ни одной эталонной роли в процедуре чтения.

# Проверка и запуск

Для независимой проверки готовой выгрузки достаточно стандартного Python и подписанных `graph_memory_round46/reader_transfer` и `reader_length` в том же дереве. Команда проверяет токены полных запросов, сохранение рёбер и их позиций, цель в каждом лексическом порядке, исходные эталоны, сумму метрик и все основные парные разности.

```powershell
python -B verify47.py
```

Для пересчёта в копии исследования необходимы существующие R31/R32, корпусная проекция R46, фиксированный GGUF, локальный GPU-сервер и общий интерпретатор с NumPy. Модель и бинарник закреплены в R46 и перепроверяются по SHA256. Запускать llama-server с аргументами R46, заменив только порт на 18866: `--host 127.0.0.1 --port 18866 --parallel 1 --ctx-size 1024 --n-gpu-layers all --flash-attn on --threads 4 --no-warmup`. В новой копии приватный каталог `P47` в base47.py должен существовать. Туда сохраняются локальный журнал исполнения и полученные только из токенов выданные текстовые фрагменты.

```powershell
$runner='D:/CodexResearch/x20-isetrace-e5-gpu/venv/Scripts/python.exe'
& $runner -B rewire.py
python -B contexts47.py
python -B generate47.py
& $runner -B grade47.py
python -B verify47.py
```

`orders.json.gz` задаёт каталог по полному расширенному лексическому порядку, два ранга по исходным запросам, исходные позиции каждого упоминания, переназначения адресов и вторую цель при каждом семени. `contexts.json.gz` связывает режимы с хешами полных запросов и содержит обе фактические длины второго текста. Отдельно фиксируются исходные порядки, затем токены, затем все ответы. Этапы генерации и получения входов не читают эталоны. Происхождение корпуса и фиксированной модели описано в R46.

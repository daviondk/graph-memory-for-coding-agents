# Точный пакет памяти при изменении весов двух источников

На 40 проекциях ISETrace из R39 фиксируем исходные ранги, цены, допустимость, полезности Q32, бюджет в 2 048 токенов, обязательный префикс до 1 024 и один порядок полных пакетов при равенстве. В каждом запросе двум источникам присваиваются независимые поправки к полезности. Кандидат может принадлежать обоим и получает обе поправки. Цель — вернуть полный упорядоченный результат как при прямой переоптимизации, включая случаи, когда исходный пакет изменился.

Для каждого возможного числа (i,j) выбранных необязательных элементов двух источников вычисляем лучший исходный пакет среди пакетов с этим числом. Он даёт аффинную оценку V(i,j)+i·x+j·y; обязательная часть одинакова для всех допустимых решений. При равных значениях выбираем меньшую битовую маску по порядку ранга полного пакета. Мантисса Q32 и фиксированный домен x,y∈[−0,25,0,25] используют точные int64 при вычислении в SQLite. Обычный одномерный индекс для каждого источника отдельно уже показал ошибки в синтетических двухкоординатных примерах. Предмет нового опыта — доступное для чтения представление всех результирующих пакетов при совместном пересмотре источников, его стоимость и область полезности. Многопараметрическая целочисленная оптимизация и параметрический рюкзак имеют собственную литературу. [Классическая работа](https://doi.org/10.1145/321978.321982) · [Параметрический рюкзак](https://doi.org/10.1016/j.ipl.2016.12.003)

До просмотра новых исходов выбираем **32** неупорядоченные пары на запрос равномерно среди всех пар различных источников (или все, если их меньше). Дополнительная нагрузка — все пары между шестью источниками с наибольшим количеством разных допустимых необязательных кандидатов, при равенстве сортируем ID; пересечение двух панелей отмечается в поштучной таблице. В запросах селектор видит только доступную проекцию, без эталонных ответов. Для каждого сочетания источников сравниваем новый индекс с полным нативным C++-решателем на сетке 5×5 (−1/4,−1/16,0,1/16,1/4), плюс 32 равномерных пар целых поправок в пределах диапазона. Дополнительная проверка — независимый полный перебор малых пулов с двумя пересекающимися множествами, нулевыми ценами, отрицательной полезностью и ничьими; проверяем выигравшую последовательность ID. Фиксированный общий генератор seed 47029, отдельный bootstrap по траекториям.

Первичный критерий корректности — ноль несовпадений полного пакета. Считаем число пар, наборов (i,j), изменение состава по сравнению с нулём и фактический размер физической базы с учётом списка ID. Для времени тёплой выдачи на каждом из двух классов пар: четыре парных повтора после прогрева, по восемь новых пар весов на каждое сочетание источников в каждом повторе, один порядок параметров и верификация одинаковых ID у всех методов. Сравнение — нативный C++ с повторным использованием буферов и одинаковыми подготовленными кандидатами, SQLite-поиск по строкам (i,j), эквивалентные строки, загруженные в RAM. Для повторяющихся параметров отдельно оцениваем кэш точного ключа. Интервалы по траекториям (10 000 переподборов); время сборки и чтения показаны раздельно. Время, наблюдаемое при программном пересмотре весов, не является скоростью решения задачи агентом.

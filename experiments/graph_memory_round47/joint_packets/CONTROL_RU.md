# Дополнение к сравнению обслуживания
До запуска нашего парного опыта в параллельном исследовании joint_certificate получен результат, что осевая выпуклая оболочка часто распознаёт неизменность старого пакета. Поэтому добавляем сильный план: взять исходный пакет, проверить совместную поправку по двум полным осевым интервалам из R46 и вернуть исходный пакет, если сертификат достаточен. Иначе используется тот же полный нативный C++-решатель. Эта проверка использует предварительно известные индивидуальные пределы, включая неограниченные направления, и сохраняет корректность, когда оба источника присутствуют в одном узле. Вычисляем на своей исходной выборке, с тем же расписанием. Время первоначального построения осевых интервалов в цену каждого чтения не включается. Полнота сертификата для исходного пакета и точность возвращения *изменившегося* пакета — разные критерии.

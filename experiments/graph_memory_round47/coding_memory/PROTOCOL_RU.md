# R47. Изолированная парная проверка памяти при исправлении публичной задачи Click

До чтения исходного кода фиксируем задачу pallets__click-1915. Публичный снимок pallets/click соответствует 329b1001755452c96dcefcf4a3c799a2463710e0; постановка SHA256 f5b752ed841829362e93fad0ddabd2f4deea18f199d46d1a85128e56e173d107. Владелец независимой проверки отдельно хранит проверочные тесты и эталон. Общий разведчик, конструктор памяти и исполнители получают только публичную постановку и исходные рабочие файлы. Скрытая оценка открывается отдельному владельцу после фиксации всех трёх патчей. Одна историческая задача, по одному изолированному исполнению на условие, это проверка работоспособности и возможных механизмов. Статистическое обобщение на задачи или агентов не предусмотрено.

Общий детерминированный разведчик ограничен src/click/*.py. Запросы первого шага — только два буквальных идентификатора из постановки: add_command, default_map. Для каждого ищем определения и обычные употребления; не больше шести выданных попаданий на запрос, до трёх на файл. Цитируем по месту найденных строк. Из наблюдённых фрагментов выбираем до шести дополнительных имён вида obj.name( для точечного поиска определений. Сортировка по числу различных наблюдений, затем по имени. Пропускаем универсальные операции контейнеров и два стартовых термина. Для каждого такого поиска выдаём до трёх определений. Отдельные поиски используют rg, целый репозиторий не индексируется. Сохраняем запросы, выданные строки, все фрагменты с точными смещениями и хешами, породившие их обращения и связи.

Единица памяти содержит заголовок с путём и смещением, подлинную непрерывную цитату и перевод строки — ровно 464 байта UTF-8. При одинаковом начале повторная цитата учитывается один раз. Последняя строка может быть обрезана на границе UTF-8. Плоский контроль ранжирует тот же опыт по BM25 запроса к цитатам с добавкой недавности. Графовый метод использует те же начальные веса, добавляя персонализированный случайный обход по рёбрам (i) от наблюдаемого обращения к уникальному процитированному определению и (ii) от наблюдения к результату поиска определения обнаруженного в нём имени. Схожие по расположению блоки исключаются одним правилом. Оба пакета содержат одинаковое число блоков (до четырёх) и одинаковое число фактически выданных байтов; резервный проход заполняет доступные слоты. Порядок выдачи выбранных цитат хронологический для обеих политик. Третье условие получает постановку без унаследованных цитат. Метка условия не сообщается исполнителю; пустая память в третьем условии наблюдаема.

Назначение трёх условий анонимным endpoint определяется до действий исполнителей и фиксируется SHA256 приватного файла. Каждому исполнителю — независимая новая беседа с fork_turns=none, одна и та же модель/настройки, один и тот же шаблон и свой локальный HTTP-токен. Каждому доступна независимая копия публичных файлов. Функции шлюза: постановка и память, список файлов, буквальный поиск, чтение, точная замена и окончательная фиксация. Общие предельные бюджеты после выдачи памяти — 2 перечисления, 8 поисков, 12 чтений, 12 000 байт фактически выданного исходного текста (поисковые строки включены), 6 точечных изменений до трёх файлов. Изменение выполняется только при единственном точном совпадении; ошибочные запросы учитываются в пределах своего типа. Произвольные команды и исполнение изменённого кода выполняются только отдельным оценщиком после фиксации. Доступ из самой беседы к файловой системе и сети ограничивается организационно точным слепым промптом; шлюз изолирует свой API, он не является системной песочницей Codex. Метрики — результат независимого оценщика, число и байты наблюдений/редактирований, объём и хеш патча. Фиксируем и случаи без патча или без различия условий.

# Слепой независимый оценщик трёх исправлений Click

Проверена ранее выбранная публичная задача `pallets__click-1915` о регистрации имени CLI-команды из VibeMemBench. Во всех трёх условиях агент сохранил патч, который прошёл целевой и все 15 зарегистрированных регрессионных тестов. Авторский критерий — точное совпадение множества прошедших тестов. Пустой снимок этот критерий не прошёл, эталонное исправление прошло полностью. Два из трёх независимо переданных патчей побайтно совпали. Исполнители не видели тестовый патч и авторское решение. Соответствие анонимных идентификаторов условиям было скрыто от оценщика до фиксации оценок. Это одна задача с одним исполнителем на условие. **Расширенная проверка.** После фиксации официального результата каждый патч прошёл отдельный запуск всего каталога тестов. В каждой ветви собраны одни и те же 509 идентификаторов. Вне зарегистрированных тестов все 493 сохранили исходное состояние: 470 прошли, 22 получили JUnit-состояние skipped (в том числе ожидаемый сбой), один ранее имел как неудачу самого теста, так и ошибку завершения из-за атрибута `encoding`. Эти два события относятся к одному идентификатору. Целевые 16 состояний совпали с нативным парсером во всех пяти ветвях. Всего после исправления прошли 486 из 509, в исходной версии — 485. **Происхождение.** Слепые среды получили 136 файлов (893 079 байт) из GitHub-снимка `329b1001755452c96dcefcf4a3c799a2463710e0`. В закреплённом по digest официальном образе Docker сверены SHA всех этих файлов, Git HEAD, tree и чистое состояние. Использованы Linux amd64, Python 3.10.19 и pytest 9.0.2. Для первичного оценивания сначала сверены все три переданные SHA. Потом в пяти новых контейнерах исполнялись исходная команда из опубликованного задания и авторские правила применения патчей. Контейнеры получили патчи через стандартный ввод при отключённой сети. Голый исходник запускался без шага применения отсутствующего патча. Нативные `evaluate_instance` и `parse_log_pytest` определяли точное совпадение эталонных и фактически прошедших тестов. Отдельно исследованный набор тестов полным запуском имеет собственный JUnit-парсер. **Повтор.** Команда `python -B verify.py` в извлечённой папке исследования проверяет контрольные суммы, сырые логи, метки всех тестов и матрицы результатов на стандартной библиотеке. Для повторного исполнения нужен Docker в режиме Linux containers и образ, закреплённый в `image.json`. После получения образа команды `python -B grade_locked.py locked.json replay-official` и `python -B suite.py replay-suite` запускают все пять ветвей в новых контейнерах, с отключённой сетью. Папки результатов должны быть новыми. Включены минимальная строка оценщика и три обезличенных патча. Исходные файлы проекта уже входят в официальный образ.

# Какие данные дают отдельную проверку

В карточке SERBench указаны два официальных набора. Cal500 содержит 500 состояний из 241 issue и 174 репозиториев, Test500 — 500 состояний из 242 issue и 45 других репозиториев. Для Cal500 опубликованы сертификаты, построенные с машинной калибровкой и перекрёстными исправлениями. Test500 использует закрытые сертификаты. Авторы также публикуют пример формата, предназначенный для проверки программной интеграции. В перечне официальных наборов дополнительной полноценной размеченной тестовой группы нет. Полный срез репозитория авторов и контрольные суммы его результатов проверены в R46. [Карточка данных](https://github.com/LordTARN1SHED/SERBench/blob/8c27a88e48dcbcd4a5745573c95937a4740f4406/docs/DATASET.md) · [Архив официальных результатов](../../graph_memory_round46/set_reader/public-audit.json)

На 494 ранее отобранных состояниях локальное разбиение по проекту дало 179/101/214. Первичный опыт использовал 204 из последних 214. В подтверждающем опыте используются другие 34 репозитория — все 101 состояния бывшей dev-части. Для каждой из трёх частей сверены исходные идентификаторы репозитория, и каждая попарная проверка даёт пустое пересечение. Аналогичная независимость от выбора гипотезы отсутствует: ранее на этих 101 состояниях измеряли BM25, логистические методы и другие реализации, а в первичном ролевом опыте уже сообщили результат поправки с BM25. При этом вероятность каждого dev-кандидата зафиксирована до первого измерения его семантического ранга в новом опыте. Значение сравнения определяется именно новым составом выдач Qwen с заранее замороженной поправкой. [Предыдущий подписанный отчёт](../facet_reader/REPORT_RU.md) · [План проверки](PROTOCOL_RU.md)

Цель метрики — нужные агенту свидетельства внутри предложенного пула. Пул участвует в конструкции бенчмарка. Такое измерение не устанавливает качество поиска по целому репозиторию или эффективность накопления графовой памяти. Для сопоставления с лидером нужны та же Test500 и её официальный способ оценки.

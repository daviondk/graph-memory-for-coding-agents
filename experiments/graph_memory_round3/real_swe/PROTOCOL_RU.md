# Замороженный перенос на реальные задачи SWE-bench Verified

Протокол на 18.11.2026 записан до вычисления каких-либо результатов политик на публичном прогоне. Предыдущие эксперименты использовали синтетические или мутационные задачи SWE-smith. Здесь работаем с реальными пользовательскими issues из официальных 500 SWE-bench Verified и единственной авторской попыткой SWE-agent 1.0 с Claude Sonnet 4, опубликованной 22 мая 2025. Публикация прикрепляет открытый S3-каталог. Скрин формата проверен на sympy__sympy-11618, которую поэтому исключаем заранее. Из локальных 300 Claude Code .jsonl выборку дополнять не будем: другой редактор и другие правила. Золотые патчи, исходы официальных тестов и resolved не используются при отборе, обучении или измерении сохранности текста.

Отбор — до 18 human issue на каждый из официальных репозиториев по SHA256('r3realverified|'+instance_id), после предметного фильтра на задачи явной эксплуатации, безопасности, оружия/биологии по исходной формулировке. Это стратифицированная выборка, частоты репозиториев не равны исходным частотам Verified. Сохраняются идентификаторы, базовая ревизия, исходный текст запроса, публичный адрес и хеш тела. Верхняя граница размера одной скачанной JSON-траектории 48 MiB для ограничения разбора памяти; завершаемые/незавершаемые запросы учитываются отдельно. Ни история ранжирования результатов, ни успешный патч не выступают критерием включения. Архивные текстовые команды и код не выполняются. Асинхронное чтение производится публично без учётной записи. Оставляем только очищенную проекцию действий текстового редактора. Вся переписка/рассуждения и содержимое не относящихся команд отбрасываются.

Сверяем историю tool_calls ↔ tool_call_ids и результат оператора с независимой секцией trajectory. Для view и подтверждённого str_replace используем ровно опубликованные тесктовые адреса и номера строк. Разные формы обёртки ответа проверяем на совпадение положительных маркеров и показанных строк. Если необрабатываемый интерактивный формат материально меняет восстановление, сообщаем покрытие и причины. Первичная единица совпадает с прошлым опытом: каждые четыре фактических действия запечатывается память, ближайшая непустая попытка str_replace среди следующих четырёх входит в исходы, только если подтверждена редактором. Поэтому для однозначных эталонов составляется отдельная неограниченная память того же публичного набора наблюдений. Публикуем также число полученных/исключённых сессий, сырые операции, долю неизвестных эталонов и покрытие проектов.

Только три фиксированных политики strict writer из сериализованного раунда, 4096 байт на всё сохранённое состояние и никакого изменения кода метода или весов: минимальный LRU, point и typed. Предсказания на любом срезе рождаются до оценки этого корпуса. Метрики — целиком сохранившийся текст правильных строк будущей принятой команды, доля правильных строк и наличие первой, среднее/максимальное количество байтов, парные 95% bootstrap по проектам 10000 раз, число выигрышей/проигрышей и результаты каждого проекта. Это перенос на человеческие задачи при фиксированном ходе офлайн-агента; официальный показатель resolved для новых политик такой опыт не измеряет.

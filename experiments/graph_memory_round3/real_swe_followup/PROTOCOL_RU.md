# Перенос на вторую группу SWE-bench Verified, до отбора и оценивания

Панель первого реального переноса использована только как повод для новой гипотезы. Перед загрузкой траекторий берём первые до 32 по SHA256("r3real-followup|"+instance_id) в каждом официальном проекте из оставшихся задач, исключая все 165 прежних идентификаторов, демонстрационный sympy__sympy-11618 и тот же фильтр нежелательных задач. Ни результат решения, ни история не влияют на выбор. Возможны прежние репозитории, но идентификаторы задач между панелями полностью различаются. Та же авторская отправка SWE-agent Claude Sonnet 4, тот же максимум 48 МиБ на объект. Учитываем неизвлечённые объекты отдельно.

Один кандидат в 4096 байт. На переполнении рассмотрим все видимые блоки страниц, имеющие наиболее свежую дату наблюдения, и посчитаем байты их адресованного текста (UTF-8 заголовок, тело и перевод строки как в исходной модели). Если свежий пакет целиком поместился бы в 4096 байт без сжатия, предпочтём недавние доступы и удалим старые блоки в порядке LRU. Если одна свежая партия уже больше всего бюджета, давность перестаёт различать её страницы. Для вытеснения используем исходный граф вероятных соседних строк. Выбор определяется только содержимым единственного рабочего состояния и текущего публичного события. В обеих ветках сохраняется один и тот же полный формат и метаданные graph, ни одна пара альтернативных кешей не ведётся. Размер сравнивается с лимитом без подбора другого порога. Сжатый рабочий снимок, включая метаданные и графовую историю, реально ограничивается 4096 байт после каждого события. Формат метода с тем же пятибайтным идентификатором, что и typed. Разъяснение: свежесть страницы — максимальная дата строк в блоке 12, поэтому считаются также ранее посещавшиеся строки в той же странице. Для решения используется самый недавний возраст из имеющихся страниц.

Один первичный исход — сохранение всех точно совпадающих строк ожидаемой принятой замены на следующих четырёх фактических событиях. Точки каждые четыре события. Задачи с необозначимым адресом дают нули всем. Три фиксированных контроля — строго те же LRU, point, typed; та же оценка полной памяти. Никогда не наблюдавшийся текст не получает баллов. Вторичные — средняя доля верных строк, первая строка, байты, трудозатраты и ограничения; проверка по новому тексту из настоящего подтверждения. Репликация эффекта графа vs LRU и point без изменений. 10 000 парных bootstrap по репозиториям, выигрыши/потери. Главный критерий улучшения — положительная разность полного исхода с обоими LRU и typed, интервалы выше нуля. Никаких повторных вариантов на тесте. Остановимся при нехватке поддерживаемых записей, сообщим исключения и истинные знаменатели.

# Выбор между давностью доступа и графом по размеру свежего просмотра

## Вопрос и постановка

Проверено одно заранее зафиксированное изменение политики вытеснения на второй группе SWE-bench Verified. В исходном каталоге человеческих issues хеш-отбор дал 129 новых задач из 8 проектов. Отбор задач проведён до чтения их траекторий. С первой группой из 165 идентификаторов пересечений нет, проекты повторяются. Получено 129 проекций редактора. Отбор не учитывал успех агента. Из 1987 четырёхшаговых контрольных точек в 535 последовала подтверждённая правка, её адрес и точные строки однозначно известны для 318. Остальные 217 остались в знаменателе с нулевым баллом для всех. Отдельных задач с оцениваемым срезом 129.

У каждого варианта один восстанавливаемый бинарный снимок, максимум 4096 байт после каждого события. Новый вариант ведёт тот же объём метаданных, что граф. При переполнении он определяет размер всего пакета наиболее свежих страниц. Когда их несжатый текст с адресами помещается в 4096 байт, правило отдаёт приоритет страницам по давности доступа, применяя LRU. Иначе свежий доступ охватывает слишком большой объём, и граф ранжирует соседей при вытеснении. Последней датой просмотра страницы считается наиболее поздняя дата среди её строк в блоке из 12, полный размер — реально сериализованное состояние. Правило использовало фиксированный размер устройства, не подбирало веса или порог.

Предварительный критерий улучшения одновременно над LRU и исходным графом не достигнут. Интервалы рассчитаны 10 000 парными выборками с возвращением по проектам. На этой панели только восемь кластеров. В сравнении переключателя с LRU весь чистый выигрыш составили три дополнительные сохранённые правки. По одной пришлось на Astropy, Matplotlib и SymPy, пять репозиториев дали одинаковый результат. Дополнительная двусторонняя проверка знаков на трёх репозиториях с ненулевой разностью даёт p = 0,25. Это поясняет чувствительность интервала к выбору модели неопределённости. Число побед — срезы с полной правкой только у первой политики. Поскольку последовательность действий исходного агента всегда одна, улучшение здесь означало бы эффект на сохранность строк. Уровень решения задач и лидерборд SWE-bench данным запуском не измерялись.

## Аудит и воспроизведение

В проекции 8248 событий. Лимит проверен 32992 раз, восстановление исторических снимков — 7948 раз. Ветка LRU при переполнении одной общей памяти выбрана 887 раз, граф 143 раз. До оценки новой панели для неизменённых контролей побайтово воспроизведено 1929 прежних переходов на восьми других задачах, включая все диагностические значения. Сверено 110669 нумерованных строк в двух родных полях траекторий. По независимой проверке новым текстом правки {'agrees': 318, 'unlocated': 217}.
Статусы источников {'ok': 129}. 

На входе были публичные записи SWE-agent 1.0 с Claude Sonnet 4. Оценка фиксированных политик работала на CPU, без новых вызовов LLM или запуска команд из траекторий. Модель вероятностей блоков и веса ширины целиком перенесены из SWE-smith. Новый выбор ветки — детерминированный. Будущие события не участвуют в выборе ветки.

В этой папке PROTOCOL_RU.md, frozen_before_scoring.json и method_lock.json фиксируют дизайны и исходные реализации. selection_receipt.json, receipts.json и download_summary.json документируют отбор, URL и транспортные исключения. Предсказания и логи в cuts_*.jsonl.gz и events_*.jsonl.gz запечатаны до разметки. Построчные исходы в scored.jsonl.gz, доверительные интервалы и анализы чувствительности в results.json. Для повтора в исходной раскладке сначала select_followup.py (Python 3.12 и PyArrow), затем acquire_followup.py, generate.py, verify_controls.py, transfer_followup.py predict, transfer_followup.py grade, report.py. freeze.py предназначен для новой пустой рабочей папки до оценки.

# Ограничение полного размера рабочего состояния агента

Дополнительный инженерный стресс-тест. Правила зафиксированы до оценки этой реализации; результаты ранее выполненных политик на данной второй панели уже известны. Источник тот же, 336 траекторий, 12 проектов. В конце каждого события у кодового агента остаётся единственная последовательность байтов максимальной длины 4096 либо 12288. Внутри неё номер события, данные о файлах и строках с адресами и давностью, минимальная метаинформация ранжирования, а для обучаемых политик след последних двух правок и ограниченный словарь изменённых терминов. Следующее состояние вычисляется только транзакцией step(предыдущие байты, текущее событие, неизменный запрос, глобальные веса). Временные объекты и текстовые кэши очищаются между шагами. Текущий вход, неизменные глобальные веса/код и внешний журнал наблюдателя не учитываются в лимите; журнал самому алгоритму не передаётся. Задача фиксирует checkpoint между действиями. Пиковая оперативная память во время сжатия, текущего входа и ранжирования может превышать этот предел.

Сравнить LRU с минимальной служебной информацией, обучаемую вероятность стартовой страницы point и удаление связанных страниц по их маргинальной полезности typed. Для этих двух политик тот же предобученный предсказатель и вероятности длины из R2-F. Метаданные отложенных файлов вне резидентных данных удаляются. До 64 добавленных/удалённых идентификаторов на каждую из двух последних правок в детерминированном порядке для point и typed. Одни и те же группы версий строк сериализуются в канонически отсортированный компактный JSON и zlib level 3. Ценой является длина окончательного буфера с сигнатурой формата; проверяется после каждого события. Внутреннее ранжирование использует автономные размеры страниц как прокси, после каждого выбранного префикса удаления фактическая цена проверяется повторной сериализацией. Для ускорения дозволен поиск подходящего префикса с расширением и бинарным уточнением; глобальный оптимум по сжимаемости не предполагается. Если одно служебное состояние не помещается, сбрасываем словарь истории, затем давнюю историю и сохраняем только необходимый номер шага.

Первичный исход – полностью сохранены все правильные строки следующей принятой замены. Дополнительно средняя доля строк и попадание в начальную строку, фактически сохранённые байты, CPU/wall, число выталкиваний, временный размер перед выталкиванием. Оценщик использует независимо реконструированный эталон с неограниченной памятью; текст строки должен совпасть на том же пути и номере, при неоднозначности все три оценки равны нулю. Ресемплирование парных исходов целыми проектами 10000 раз. Сопоставляем методы внутри одной и той же сериализации и нагрузки. Предыдущий бюджет на один лишь текст страницы измерял другую величину.

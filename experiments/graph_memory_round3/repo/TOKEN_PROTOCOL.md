# Как меняется ценность порядка выдачи при фиксированной длине

Вторичная проверка после наблюдения основных результатов и длин в символах. Ранжирования v0 и v1.1 остаются запечатанными. Для бюджетов B=256,512,1024 токена из каждого фиксированного порядка выбрать до трёх целых доступных фрагментов. Пропускать кандидат, если его полная длина с одним токеном-разделителем уже не помещается. Единица расхода — число токенов Salesforce/codegen-350M-multi без спецсимволов в полном тексте фрагмента плюс один за отделение от уже упакованных. Посчитать полное попадание эталонного фрагмента, фактически занятые токены и свой потолок при известном правильном кандидате. Варианты используют один и тот же список, цену и ограничение. Долю по всем запросам и парную дельту graph vs owner представить по каждому бюджету. Это контроль ограничений на чтение, добавленный после первичной проверки.

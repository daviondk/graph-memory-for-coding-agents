# Временной перенос и распознавание первого использования

Зарегистрировано после наблюдения эффекта повторного использования на v0, до получения или оценки меток v1.1. В Python v1.1 авторы используют другой период и отдельно хранится список кандидатов. Здесь задача поиска — производная по авторскому индексу в наборе для completion. Вход строго состоит только из string snippet и последних строк all_code перед целевой строкой (сопоставление all_code и cropped_code проверяется вне оценщика; если all_code включает suffix или будущую строку, используем только публикационный cropped_code). Для полной изоляции сразу выбираем только cropped_code и до 120 последних строк; metadata identifier/path/import_statement не передаются ранжировщику. Требуем ≥5 кандидатов. Имена проектов сравниваем без регистра, удаляем все проекты из R3 v0 train и test, exact SHA префиксов из старого обучения и теста и дубликаты внутри одинаковой страты. По 1500 запросов с наименьшим SHA(seed, файл и номер строки) либо все доступные по страте. Показываем результаты по обеим стратам и общие с равным весом страт при расхождении числа запросов.

Гипотеза — правило возврата к знакомому использованию систематически помогает при повторном обращении, но может помешать впервые необходимому объявлению. На старых обучающих проектах учим два ранжировщика по одному на известный тип следующего обращения. На новой задаче тип обращения системе недоступен. Коэффициент смеси оценивает отдельная модель по статистике наблюдаемых предыдущих использований (доля объявлений с записями, концентрация и повторяемость переходов, число кандидатов). Выдаваемый вес кандидата есть сумма калибровочных приближений P(i | q,t)P(t | q) по двум типам. Сначала обучаем два отдельных HistGB с теми же гиперпараметрами как R3-R; вероятность кандидата нормируем внутри набора по отношению шансов p/(1-p). Классификатор типа имеет глубину в пределах max_leaf_nodes=7, 50 итераций, тот же seed. Базовые методы — предыдущие замороженные flat/owner/transition/placebo, равномерная смесь специалистов на тех же данных и обучаемая смесь. Отдельно диагностический недоступный агенту вариант знает тип следующего обращения. Первичное сравнение нового адаптивного чтения — с равномерной смесью тех же специалистов; второе — с замороженным transition. Отдельно прямой независимый перенос предзаданного transition vs owner. Проверим accuracy предсказания типа и Brier score સામે постоянной .5, так как общее улучшение ранга может не требовать качественного определения типа. Численные рецепты и прогнозы замораживаются до тестовых индексов. Для переноса разрешаем только старые тренировочные задачи с валидным индексом: в первичной серии три зарегистрированные обучающие задачи фактически не имели положительной строки. На исходном v0 отдельно пересчитаем результат с удалением этих трёх, сохранив ключевой исход R3-R как он был получен. Передаваемые служебные эталонные индексы не исправляем вручную.

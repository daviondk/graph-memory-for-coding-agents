# Лимит на всё состояние памяти
> Отдельный эксперимент ограничил полный сериализованный снимок кэша. После каждого действия исходные объекты уничтожались, дальнейшее решение начиналось из сохранённых байтов.
На второй панели из 12 проектов выполнено 10 584 обновления. В снимок попадают строки, адреса и служебные сведения, необходимые данному алгоритму для продолжения работы. Минимальный контроль по давности сохраняет только нужные ему метаданные; дополнительный контроль несёт столько же служебных сведений, сколько графовая политика. Совпадение результатов после восстановления проверялось отдельно.

При 4 КиБ минимальный LRU дал 686 покрытий, LRU с богатыми метаданными — 683. Разность графа и поштучной оценки +2,81 п.п. [1,37; 4,25], графа и минимального LRU +4,96 п.п. [1,52; 9,27]. Контроль всего состояния выполнен 84 672 раза, проверок round-trip — 19 392, побайтовых проверок холодного старта — 402. При 12 КиБ полный граф близок к доступному при неограниченной памяти потолку, 825 правок.

На графике показана доля правок, которые можно полностью предъявить из снимка. При 24 КиБ все правила достигают потолка, 825 из 1 210. Остальные цели не удалось однозначно сопоставить с полным текстом в предыдущей рабочей истории. При тесном бюджете поштучный выбор выигрывает по присутствию только первой строки будущей правки.

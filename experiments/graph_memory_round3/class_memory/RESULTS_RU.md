# Влияет ли граф памяти на работоспособность программы

Модель Qwen3.8-27B-UD-Q4_K_M на одной RTX 3090 писала настоящий Python-код, который проверялся авторскими unit-тестами ClassEval. При фиксированной прошлой истории сравниваем 108 методов в 50 классах. В отдельном последовательном режиме модель сама разрабатывает 14 классов из 54 методов. Это проверки функциональной корректности; список исходов отдельных задач приложен.

## Отдельный метод при известных предыдущих реализациях

Для каждого условия известны конструктор, сигнатуры и публичный авторский контракт целевого метода. При записи получены только уже законченные эталонные методы класса. По запросу из имени и публичного контракта выбираются их строки. Граф использует принадлежность к полю класса, зависимости от предыдущего присваивания и условия ветвления. Политика выводит выбранные строки в исходной очередности с именем метода, но без отступов. Тот же формат используется для остальных способов. После получения всех программ текущий метод подставляется в эталонный класс. Это изолирует качество одного шага и не моделирует накопление прежних ошибок.

| Память | Методы, все тесты / 108 | Пройденные тесты | Обработаны раннером / 108 | Средние токены памяти |
|---|---:|---:|---:|---:|
| Пустая | 67 | 418/551 | 97 | 0.0 |
| BM25 методов, заполнение строками | 77 | 446/551 | 99 | 102.6 |
| BM25 строк | 77 | 445/551 | 99 | 102.6 |
| Зависимости и состояние | 76 | 439/551 | 98 | 103.0 |
| Переставленный структурный вес | 75 | 439/551 | 98 | 102.6 |
| Вся предыдущая память до 800 токенов | 78 | 448/551 | 99 | 131.6 |

По всем 108 методам граф выиграл у BM25 в 0 случаях и уступил в 1. Разность -0,93 п.п., 95% bootstrap по классам [-2,86; 0,00]. Из-за коротких историй на 76 методах обе политики подготовили один и тот же запрос. На остальных 32 получилось 23 против 24. Полнота упоминания встречавшихся ранее эталонных self-атрибутов в памяти — 76/81 и 76/81 соответственно. Это диагностический показатель, эталон текущей реализации использовался только для его подсчёта после lock.

Во всех режимах основного опыта 338 различных запросов на 648 назначений. Для общих входов один и тот же ответ используется многократно. В реальных записях этой ветви 161232 входных и 66509 выходных токенов. Истинный полный контекст класса длиннее бюджетного варианта full, когда 800 токенов недостаточно.

## Целый класс при собственной предыдущей истории

Для каждого из 14 классов агент в каждом из трёх условий реализует все методы в авторском порядке. Каждой политике доступны только её собственные предыдущие ответы. После фиксации кода выполняются все профильные и интеграционные suites в публичном скелете класса. Общие веса модели, параметры, открытый конструктор и сигнатуры у всех одинаковы. Три случая сравниваются на одних и тех же 14 классах, панели частично пересекаются с первой проверкой. Официальные полные таблицы ClassEval не являются прямым сравнением с этим отбором и нашим промптом.

| Память | Целые классы / 14 | Профильные методы / 54 | Интеграционные suites / 14 | Тесты / 293 | Токены промптов |
|---|---:|---:|---:|---:|---:|
| BM25 строк | 7 | 40 | 7 | 224 | 23585 |
| Зависимости и состояние | 7 | 39 | 7 | 223 | 23580 |
| Вся предыдущая память до 800 токенов | 6 | 39 | 7 | 223 | 28428 |

При записи и чтении собственной истории граф и BM25 полностью решили одни и те же семь классов. Это измерение на 14 классах, статистическая мощность невысока. Итог по отдельным тестам отличается на один. Для различения двух техник здесь мало случаев, в которых выбор прошлых строк определяет работу всего класса.

## Валидация и воспроизведение

Эталон и падающая заглушка проверены при формировании панели методов. Публичные контракты содержат примеры использования: вход теста не обязан быть новым относительно примера. Сам тестовый код, прочие скрытые примеры и тело целевого метода не предъявляются модели. Раннер исполняет разрешённые чистые операции в изолированном дочернем процессе с ограничениями времени и памяти. Такая спецификация может отклонить корректную реализацию из-за неподдержанной функции. Дополнительная независимая проверка с расширенным перечнем чистых встроенных средств записана отдельно в материалах independent_*. Оба фактора ограничивают вывод о функциональном качестве на полном наборе ClassEval.

В этой серии не запускался внешний коммерческий решатель. Версии, GGUF, аргументы процесса и тексты запросов — launch.json, calls, online_calls. Предсказания и авторские совпадения хранятся в assignment.json, per_item.json и online_scored.json.gz. Для повторной оценки запечатанных программ в рабочем каталоге D выполните python grade.py и python -c "import online; online.evaluate()". Для повторной генерации нужны соответствующий GGUF/llama.cpp и новый запуск на свободном localhost порту 18891 в отдельной рабочей копии. В model_receipt.json и runtime_receipt.json указаны источник весов, SHA-256 и ревизия llama.cpp. В independent_compute.json проверены все физические вызовы по таймингам сервера. Получение публичной фиксированной версии данных описано в PROTOCOL.md. Ближайшие работы — [ClassEval](https://arxiv.org/abs/2308.01861), [авторские данные и стратегии](https://github.com/FudanSELab/ClassEval) и [GraphCoder](https://arxiv.org/abs/2406.07003).

## Независимый аудит модели и среды

439 различных запросов на 810 логических назначений сопоставлены с 439 физическими вызовами по журналу сервера. Совокупный расход — 214 004 входных и 85 663 выходных токена. Обработка входа заняла 265,2 с, декодирование 2 088,9 с. 39,2 минуты — суммарное серверное время этих операций, время ожидания в очереди учитывается отдельно. Модель работала на локальной RTX 3090.

Проверка с добавлением 17 чистых встроенных объектов Python сохранила число полностью прошедших методов и классов во всех режимах. При повторном исполнении ветви без памяти изменилось число пройденных элементарных проверок с 418 до 417 при тех же 67/108 методах. У метода get_all_major сгенерированный без памяти код превращает множество в список, а авторский тест ожидает определённый порядок. В 40 повторениях с новым процессом Python получили все три теста в 5 и 3 запусках исходной и расширенной среды соответственно. Ответ с памятью прошёл все три теста во всех 80 повторах. Полный журнал — independent_flakiness.json. Ветка с собственной историей дала те же результаты по каждому исходу. У всех восьми различных неразбираемых генераций этой ветки был достигнут лимит в 384 выходных токена.

# Чувствительность ClassEval к набору встроенных объектов Python

План на 18 ноября 2026 года, до фиксации обоих наборов ответов. Гипотеза возникла при проверке на собственном игрушечном классе — корректная программа с bytes прошла один из двух тестов из-за ограничения среды. Правила основного подсчёта сохраняются в исходном worker.py.

Выполняем повторно все зафиксированные программы и те же авторские тесты. Единственное изменение относительно исходной среды — добавление bytes, bytearray, memoryview, hash, NotImplemented, BufferError, LookupError, OverflowError, FloatingPointError, UnicodeError, UnicodeEncodeError, UnicodeDecodeError, UnicodeTranslateError, RecursionError, MemoryError, NameError и UnboundLocalError. Первые четыре выполняют вычисления в памяти, остальные представляют константу и типы исключений. Список выбран до открытия результатов. Модули, обработка AST, синтаксические ограничения, тесты, время, объём памяти и Windows Job идентичны. Среда ограничена и после расширения. Встроенный hash может зависеть от семени хеширования процессов Python.

У каждого решателя и на каждом режиме публикуем основной и вторичный pass_all, число пройденных тестов, поштучные переходы по методам или классам/тестовым группам. В основном режиме дополнительно считаем наблюдаемые индивидуальные ошибки NameError с именем и отмеченные статусы parser/harness. Такие ошибки могут иметь несколько причин; их наличие само по себе не даёт основания пересчитывать ответ как правильный. Если модель породила неверный код, берём первоначальный текст без ремонта. Запуск и изучение реальных ответов — только после наличия обоих decision locks. Скрипт сохраняет контрольные суммы исходных файлов и результатов. Независимый запуск python independent_sensitivity.py выводит результаты в independent_sensitivity.json и полный журнал несовпадений.

# ClassEval. Независимая проверка передачи памяти и оценки программ

**Что измеряется.** В первом режиме каждый метод генерируется отдельно. Предшествующие методы в памяти берутся из опубликованного эталона. Для оценки сгенерированный метод подставляется в полный эталонный класс, включая реализации более поздних методов. Во втором режиме модель последовательно реализует весь класс. У каждой политики собственная история. Метод считается верным при прохождении всех его профильных тестов. Для целого класса требуется также прохождение всех интеграционных тестов. Проверяется программирование с чтением памяти в одном проходе. Обратной связи тестера и исправления после неудачной попытки у генератора здесь нет.

## Сходство с авторской постановкой

У Du и соавторов ClassEval содержит 100 классов, 410 методов. Авторы сравнивали генерацию всего класса, инкрементальную генерацию с прежними ответами и генерацию с сигнатурами других методов. Они отдельно измеряли успешность при жадном декодировании и Pass@k при нескольких стохастических попытках. Определение успеха целого класса в нашем втором режиме совпадает с авторским. По сравнению со статьёй здесь иной состав классов, один ответ на метод, иной промпт и ограниченный набор операций Python. Даже дорогой контроль передаёт до 800 токенов строк кода в исходном порядке с удалёнными отступами. Разности между нашими политиками относятся к этой модели и выборке. [Статья, разделы 4.3–4.4](https://arxiv.org/html/2308.01861) · [Описание релиза и стратегий](https://github.com/FudanSELab/ClassEval/blob/eaeac44d0d5dcd8a95feec50726d66fedc73a98f/README.md)

## Что действительно видит модель

- Для 108 методов из 50 классов по исходному JSON заново собраны 648 логических запросов (338 различных). Воспроизведены 273 записи предшествующих методов, принадлежность выбранных строк их телам, исходный порядок, длина каждой выдачи и все хеши запросов. Полное тело текущего метода ни разу не совпало с телом более раннего метода. На шести значениях PYTHONHASHSEED повторены 3 888 проверок выходов политики без расхождений. Набор содержит 551 профильный unittest.
- Во входе доступны имя класса, публичное описание, импорты, заданный конструктор, сигнатуры всех методов, выбранные строки прошлых методов и контракт текущего метода. Ранжировщик получает имя и контракт текущего метода. Конструктор передаётся решателю. Файлы официальных тестов, скрытые тела будущих методов и метки зависимостей не сериализуются в запрос.
- 106 из 108 контрактов содержат публичные примеры. В 54 контрактах вызов с конкретными буквальными аргументами встречается и в тесте, для 30 контрактов удалось подтвердить также совпадение ожидаемого буквального результата в прямой проверке assertEqual/True/False. Для 54 методов второго режима соответствующие количества равны 49, 28 и 11. Алгоритм проверки пропускает косвенные сравнения, вызовы через локальные переменные и аргументы без литералов. Состояния объекта в примере и тесте могут различаться. По этим данным нельзя оценить знакомство модели с самим публичным бенчмарком до эксперимента.
- В онлайновом режиме отобрано 14 классов, 54 метода и 293 теста в 68 наборах. Все 14 классов и 28 методов встречаются также в первом режиме. В искусственном опыте каждая из трёх политик прошла пять шагов. Некорректный ответ в одной ветви стал заглушкой только в её последующей истории. В реальном опыте заново восстановлены все 162 входа по прошлым ответам соответствующей политики. Сделано 204 независимых повторных запуска наборов тестов. Ошибок в передаче истории и расхождений с первичным оценщиком не обнаружено.

## Проверка стенда и цена ограничений

Девять искусственных проверок различают рабочую реализацию, неверный код, частично правильный метод, ошибку формата и поломку в предшествующем методе. На одном из них корректный Python-код с bytes получил 1/2 из-за ограниченного списка встроенных функций. Чувствительность на реальных ответах проверяется заранее зафиксированным расширением этого списка на 17 объектов с сохранением исходных тестов, кода ответов и ресурсных ограничений.

## Независимая проверка всех ответов и чувствительности

| Первая серия | Методов / 108, исходная и расширенная среда | Тестов / 551, исходная | Тестов / 551, расширенная |
|---|---:|---:|---:|
| Пустая память | 67 | 418 | 417 |
| BM25 по методам | 77 | 446 | 446 |
| BM25 по строкам | 77 | 445 | 445 |
| Граф | 76 | 439 | 439 |
| Переставленные структурные веса | 75 | 439 | 439 |
| До 800 токенов | 78 | 448 | 448 |

Первичный оценщик проверен на всех 338 уникальных ответах первой серии, 235 из них прошли весь свой набор тестов, 74 дали отрицательный результат, 27 не разобрались как Python, два не завершились за шесть секунд. Для всех 27 синтаксических ошибок сервер указал исчерпание длины ответа. Из 108 сравнений графа с BM25 только 32 предъявляли решателю разные запросы. По прохождению методов наблюдались ноль выигрышей и один проигрыш. По сравнению с пустой памятью — 11 выигрышей и два проигрыша. Если интересует эффект конкретно графовой структуры, преимущество над пустой памятью включает полезность самого наличия кода в контексте.

После добавления 17 заранее указанных встроенных объектов Python все показатели прохождения целых методов и классов в обоих режимах совпали. Не найдено NameError в зарегистрированных исключениях тестов. В одном режиме с пустой памятью вместо двух из трёх тестов оказалась пройдена лишь одна проверка метода get_all_major. Решение возвращало список, построенный из множества строк, в то время как тест сравнивал список в заданном порядке. Для этого одного метода запустили поштучный дополнительный контроль, по 40 независимых процессов для каждой пары «программа × среда». В исходной среде код без памяти прошёл 1, 2, 3 проверки в 19, 16, 5 случаях, в расширенной — в 17, 20, 3. Один и тот же ответ всех непустых политик прошёл 3/3 в каждом из 80 запусков. Этот разброс наблюдается уже при повторении в одной среде. Первичная сводка и дополнительная проверка используют заранее фиксированные серии оценок, без выбора удачного перезапуска. ## Фактический объём вычислений

810 логических назначений дали 439 уникальных запросов и 439 уникальных ответов сервера (338 и 101 в двух режимах, пересечений между ними нет). Все квитанции сопоставились с разными записями нативного журнала по количествам токенов и парам времён чтения/генерации. Израсходовано 214 004 входных и 85 663 выходных токена, 299 667 суммарно. Сервер зарегистрировал 265,2 секунды обработки входов и 2 088,9 секунды декодирования, около 39,2 минуты чистого модельного вычисления. Сумма клиентских длительностей включает ожидание очереди. [Аудит запросов и вычислений](independent_compute.json)

Для воспроизведения можно запускать в этом каталоге python independent_audit.py, python independent_online_only.py, python independent_compute.py, python independent_sensitivity.py и python independent_flakiness.py. Для первой исходной серии сверка с сохранёнными оценками требует их совпадения при свежем запуске. Из-за выявленной нестабильности одного ответа такой запуск может обнаружить расхождение и остановиться на проверке. Архивные снимки результатов оставлены в каталоге.

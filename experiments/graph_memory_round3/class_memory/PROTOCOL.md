# R3-C. Передача состояния между правками класса

18 ноября 2026. План фиксируется до новых вызовов Qwen. На ClassEval завершаем один пропущенный метод, имея возможность читать память о предыдущих методах класса в опубликованном порядке. Список сигнатур, конструктор и авторский контракт целевого метода доступны всем, включая контроль без памяти. На стадии письма в память добавляется только очищенная от docstring реализация каждого ранее завершённого метода. Наблюдения учителя — ранее написанные эталонные методы. Тесты, тело, разметка зависимостей и будущие реализации целевого метода недоступны политике и решателю. После получения всех решений помещаем каждое в исходный класс и запускаем ровно авторский unittest-класс данного метода в изолированном процессе. Этим измеряется функциональная корректность отдельного действия агента при известном предыдущем состоянии. Официальное сквозное incremental generation генерирует также предшествующие методы; сравнение с его лидербордом требует иной постановки.

Гипотеза. При коротком бюджете важнее всего факты, которые объясняют состояние, созданное прежними методами: где значение было записано, какие переменные и предикаты определяют содержимое поля, какие ключи и типы понадобятся следующему читателю. Детерминированный граф связывает строки кода с полями, локальными определениями и управляющими условиями, наблюдавшимися ранее. Запрос строится из авторского описания текущего метода и конструктора. Граф расширяет лексический сигнал этих строк по зависимостям и по полям, отдавая приоритет неподдельному коду присваиваний и использований. Формат выдачи у всех равных по бюджету способов — идентификатор метода и выбранные строки в исходном порядке. Сохраняем реальный эффект чтения и абляции; идею программного среза не считаем новой.

По одному экземпляру на метод; не более 4 методов на класс, максимум 108, фиксированный порядок SHA256 и первичный ранг по числу ранее доступных методов внутри стратификации (см. prepare.py). Выбор из заранее указанных общих, чисто вычислительных задач: структура данных, административное состояние в памяти, текст, математика и простая логика. Требуются существующие предыдущие методы, корректный парсинг интерфейса, и возможность выполнить опубликованный класс с разрешёнными импортами в изолированном harness. Эталон и пустая заглушка валидируют каждое измерение до генерации. При неуспехе эталона или если заглушка проходит все тесты, случай до отбора записывается как исключённый. У генератора нет доступа к исходам эталона, названиям тестов и тестовым аргументам. Однословные @property и @staticmethod сохраняются. Вся семья задач и проверок логируется.

Основное сравнение по доле методов, прошедших все первичные unit-тесты: предлагаемый граф против ранжирования тех же строк BM25. Лимит 160 токенов на всю память по зафиксированному токенизатору, одинаковый жёсткий потолок; одинаковая модель с температурой 0, без thinking, максимум 384 новых токена. Контроли: пустая память; BM25 по целым методам с заполнением строками; BM25 по строкам; полная предшествующая память до 800 токенов как дорогой контроль. Плацебо переставляет структурные веса между строками внутри каждого метода (собственные лексические оценки сохраняются). Все включённые методы получают каждый вариант. Идентичные запросы по одному методу вычисляются физически один раз; сравниваем также логическую стоимость, частоту несовпадающих выдач, синтаксическую исполнимость, микродолю отдельных тестов и долю совпадающих ожидаемых свойств вида self.x (из скрытого тела берутся только после lock). При наличии механизма возможно увидеть пользу для классов с несколькими ожидаемыми полями, но это разведочный разрез. Для доли методов сообщаем парные выигрыши/проигрыши и 95% bootstrap по классам (10 тыс.). Пусть p — условная вероятность, что полезная строка будет доступна, а v — разность вероятности правильного ответа модели при наличии и отсутствии этой строки. Возможный эффект качества зависит одновременно от изменений p и v. Повышение полноты извлечения само по себе не даёт гарантии роста прохождения тестов. Параметры не подбираем по тестовой выборке, отчёт не зависит от знака эффекта.

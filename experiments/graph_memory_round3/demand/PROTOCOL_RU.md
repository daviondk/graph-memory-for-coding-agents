# Память для будущего чтения и будущей правки

Третья, заранее зафиксированная панель для исследования записи: другие репозитории и задачи SWE-smith. Предыдущие серии измеряли получение целого фрагмента при последующей правке. На практике агент также просит просмотреть файл повторно, причём полезно сохранить часть источника. Выдвигаем новую гипотезу — условную на тип следующего действия смесь двух функций полезности. Для будущей замены награда равна 1 при сохранении всех строк точной замены; для будущего просмотра — доля строк ответа инструмента, у которых совпадают путь, номер и фактический текст, поэтому эти строки уже определённо есть в памяти. Это потенциальная доступность при повторном чтении, не измеренное сокращение реальных сетевых запросов. Каждое измерение перед записью будущих меток. Для прогнозирования используем только предшествующий поток редактора.

На каждом четвёртом шаге берём первое в следующих четырёх событиях обращение к редактору. Если это успешная непустая замена или просмотр конкретного файла с пронумерованными строками, включаем наблюдение. Другой первый редакторский запрос не заменяем удобным более поздним запросом. Сохраняем все случаи, даже если ничего не было в памяти. Основное сравнение — средняя полезность по всему потоку между динамической и постоянной смесью на одинаковых 4096 байтах хранимой полезной нагрузки. Обе используют одни и те же модели и точный DP; динамическая зависит от типов предыдущих событий и истории правок, постоянная знает только среднюю частоту на обучении. Другие контроли — штатный LRU, только прогноз просмотра, только прогноз целой правки. Вторичные — процент целых правок, целых и частичных просмотров, макро двух видов действий, Brier прогноза типа. Парный bootstrap целых проектов (10 000). Раздельно показываем обе компоненты. Все исходы и пригодность метода для статьи записываются независимо от направления результата.

Учим модель просмотров и частотное правило для типов только на старых 44 обучающих проектах R2-E; текущие поля и структура тех же видимых страниц. Видимая доля следующего просмотра, приходящаяся на страницу, служит дробной обучающей меткой. Плотность вероятности начала замены и условная ширина заморожены из R2-F. Допустимые интервалы длины 1–3. При одиночном событии промаха вне памяти вероятность массы может быть ниже единицы; веса обоих прогнозов не перенормируются на известную память. Для полноты отдельно проверим калибровку типа запроса. Тест — до 24 пригодных экземпляров на каждый из заранее указанных общих проектов (список в acquire.py), SHA порядок до извлечения меток. Исключаем проекты из всех предыдущих панелей и обучающего множества, сохраняем безопасные текстовые проекции. Новый агентский код и исторические команды не исполняются. Динамическое программирование максимизирует принятую смесь прогнозных весов на момент вытеснения. Это не теорема о будущих истинных действиях или об оптимальном пожизненном поведении.

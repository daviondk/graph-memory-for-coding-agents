# Может ли память заранее выбрать между просмотром и редактированием

Проверили две разные причины, по которым агенту понадобится информация из кэша. Для правки нужна вся старая подстрока для замены. При повторном просмотре источника интересна доля уже имеющихся строк, совпадающих по номеру и тексту. На каждом четвёртом шаге политики сохраняли исключительно прочитанный код в пределах 4096 байтов полезного текста и адресов (см. одинаковую спецификацию writer). Затем оценщик определял первое действительное обращение к редактору в ближайшем четырёхсобытийном окне. На 282 новых экземплярах 13 проектов из 1795 исходных границ в знаменатель вошли 652 принятые правки и 432 просмотра файлов. Репозитории этой группы не входят в обучение и в обе предыдущие панели R3. Отбор шёл по ID, код из траекторий не исполнялся.

Для оценки будущих просмотров обучена модель ожидаемой доли выводимых строк для каждой страницы, а на 9893 тренировочных окнах фиксировано сглаженное правило вероятности типа запроса по истории последних четырёх действий. Сравниваем с известными из R2-F прогнозами интервалов редактирования. Во всех смешанных моделях один точный DP-решатель на байтовый бюджет. Если агенту понадобится править код, вознаграждение равно 1 при полном покрытии подстроки. Если потребуется посмотреть файл, начисляется доля совпавших строк из настоящего вывода редактора. Средняя полезность учитывает частоты двух целей в отложенном потоке. Просмотр с отсутствующим текстовым ответом или отклонённая первая попытка замены не входят в цель.

| Политика | Целые правки из 652 | Доля строк при 432 просмотрах | Общая полезность, % |
|---|---:|---:|---:|
| Давность | 265 | 8,4% | 27,8 |
| Только будущая правка | 303 | 10,0% | 32,0 |
| Только будущий просмотр | 229 | 13,2% | 26,4 |
| Постоянная смесь | 300 | 10,6% | 31,9 |
| Динамическая смесь | 287 | 12,2% | 31,3 |
| Вся доступная история | 472 | 27,0% | 54,3 |

При оценке типа следующего запроса динамическое правило снизило ошибку Brier с 0,249 до 0,157 (меньше — лучше). На настоящих просмотрах это улучшило долю доступных строк с 10,6% до 12,2%, 95% парный интервал разности по проектам [+0,90; +2,83] п.п. Однако 13 правок перестали помещаться в память целиком. В результате первичный показатель не вырос: изменение средней полезности относительно постоянной смеси имеет 95% ДИ [−1,68; +0,48] п.п. Из прогноза потребности ещё не следует, что найдено больше полезного контекста. Тесты программ в этой ветви не запускались. Вклад зависит от распределения задач, а многие будущие запросы вообще обращаются к строкам, ещё не показанным агенту.

Полный протокол и формула — PROTOCOL_RU.md, построение выборки — acquire.py, фиксация исходных шардов — acquisition.json. Код study.py и выделенные out-of-sample predictions находятся в sealed_*.jsonl.gz, поштучные результаты — в outcomes.jsonl.gz. Источник — [SWE-smith](https://swesmith.com/). Активное бюджетирование retrieval и оценку полезности под фиксированной ценой обсуждают [Dong et al.](https://arxiv.org/abs/2606.29959) и [When Should Active RAG Retrieve?](https://arxiv.org/abs/2607.24010). В этих работах другие задачи и цены действия.

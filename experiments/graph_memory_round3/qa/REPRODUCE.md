# Воспроизведение CPU-экспериментов

Данные LoCoMo выпущены Snap Research по CC BY-NC 4.0. Скрипты загрузки используют публичный HTTPS. Зафиксированные модели — ONNX INT8 MiniLM-L6-v2 (поиск) и DistilBERT distilled SQuAD (экстрактивный ответ); ревизии, SHA-256 и размер в models.json. Сходство, ранжирование и модель ответов запускаются только на CPU. Python 3.14, NumPy 2.4.4, onnxruntime 1.24.4, tokenizers 0.22.2, nltk 3.9.2. В этом эксперименте кеш MiniLM содержит 24 766 представлений; 1 259 785 токенов и 66,1 CPU-секунд стенового времени при 3 потоках. В это количество входят реплики, альтернативные варианты для экспериментов, окна и вопросы. Для одного выбранного способа все альтернативные поля физически хранить не требуется.

Из папки qa проверка сохранённых решений на Windows выполнена командами:

```powershell
python -m pip install --target deps nltk==3.9.2
python fetch_extra.py
python evaluate.py
python evaluate.py reader
python external.py
python score_transfer.py
python audit.py
```

Точечные результаты LoCoMo-Conv можно пересчитать из сохранённых прогнозов: python -c "from conversational import score; score()". Числовые исходы корпуса без доступа к моделям находятся в retrieval_results.json, external_results.json, reader_results.json, conversational_results.json и transfer_results.json. Выход индивидуальных вопросов в predictions.json.gz, reader_output.json, transfer_output.json и conversational_predictions.json.gz фиксирует не только успешные случаи. Перезапускайте обучение в отдельной копии.

Для получения всех исходных данных: python download.py и python fetch_extra.py. Для повторения инференса модели сначала получить их точные версии по адресам из models.json через get_models.py, после чего в порядке prepare.py, emb.py, rank.py, reader.py, conversational.py и transfer_reader.py. На всех десяти folds веса читателя и энкодера одинаковые. Формирование списка тестовых вопросов пользуется только наличием корректной разметки для заранее объявленной генеральной совокупности, веса не получают эталонных ответов. При независимой проверке прогнозов достаточно json и публикуемого исходного корпуса; hash запечатанного входа находится в prediction_lock.json.

Ни загруженный код чужих агентов, ни инструкции внутри корпуса не выполняются. Функции нормализации ответов воспроизведены из открытого scorer авторов. В нашем результате EM обозначает полное совпадение после нормализации пробелов, артиклей и пунктуации. Авторский F1 для составного ответа усредняется по элементам списка с разделителем-запятой, для категории 3 ограничивается первой частью до точки с запятой, для остальных используется F1 со стеммингом Porter. Правило оценивает совпадение слов, а экстрактивный читатель может вернуть только одну непрерывную последовательность.

Сопоставление с опубликованной таблицей 4 LoCoMo-Conv пересчитывается командой `python conv_official.py`. На Windows перед запуском установить `$env:PYTHONUTF8='1'` для чтения JSON исходными утилитами авторов. Точная ревизия, размер всех четырёх полных выборок, число совпавших ключей и путь авторского оценщика проверяются в official_conv_results.json. Файл авторского оценщика загружает fetch_extra.py. 

Дополнительный контроль с датами для плоского ранжирования воспроизводит `python matched_reader.py` после transfer_reader.py. Итоги — matched_reader_results.json и индивидуальные matched_reader_output.json. Зафиксированные обе разности (одинаковое оформление у двух поисковых политик и одинаковый поиск при смене оформления) нужны для вывода о роли графа. 

`python get_models.py` использует неизменяемые ревизии и SHA-256 каждого файла из включённого models.json. Даже при наличии файлов в локальном кеше размеры и контрольные суммы проверяются до инференса.

`python family_audit.py` проверяет пересчёт кластерных перестановочных p и поправку Холма по семействам из двух и четырёх исходов, сохраняя family_results.json.

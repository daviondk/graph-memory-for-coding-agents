# Кому принадлежит реплика в рабочей памяти диалогового агента

Локальный протокол до просмотра исходов новых политик, 18 ноября 2026. Десять диалогов LoCoMo, версия 3eb6f2c585f5e1699204e3c3bdf7adc5c28cb376. Надёжность оценки определяется десятью разговорами. Популяция — вопросы категорий 1–4 с размеченным свидетельством. Для метрик реплик проверяем, что все ID существуют (остальные отмечаем отдельно). Для сопоставления со сторонним авторским Memoria дополнительно оцениваем сессии, разбирая префикс D<номер> отдельно для каждого элемента evidence, ровно как в опубликованном scorer. Это диагностическая эвристика; исходная задача LoCoMo — QA. Все вопросы и все сохранённые реплики входят в прогнозы без меток. Категория, ответы, evidence, event_summary, observation, сгенерированные сводки и предыдущие QA не попадают в память. Данные рассматриваются только как текст.

**Механизм.** На записи сохраняем оригинальную реплику, дату, говорящего, ближайшие реплики того же разговора. В качестве компактного графа связываем местоимения первого лица с автором, второго — с собеседником. На чтении используем отдельно исходный текст и лексико-семантический поиск по представлению с явными участниками. Перенос релевантности на предыдущую/следующую реплику обусловлен сменой говорящего, вопросительным характером исходной реплики, первым/вторым лицом и тем, о ком спрашивает пользователь. Контроль без типов получает максимум по соседям и окно ближайших реплик, исходный текст и имена. Отдельно проверяем только привязку местоимений и плацебо с переставленным адресатом/направлением (та же стоимость). Полный метод не обучает нейронную сеть. Один раз пишутся эмбеддинги реплик и исходного окна. Запрос к внешнему сервису не нужен.

Контроли включают нормализованный BM25, плотный MiniLM, их нерегулируемое сочетание по рангам, и обучаемый ранжировщик тех же окон без типизации. Полный метод сравниваем прежде всего с обучаемым контролем. Предиктор и настройки общие. Для каждого тестового разговора девять остальных используются для подгонки линейной взвешенной логистической регрессии с фиксированным L2, усечённой детерминированной выборкой трудных и случайных отрицательных примеров. Никакой выбор конфигурации по результатам теста. Показываем все десять folds и все варианты независимо от знака. Позднейшие проверки явно маркируются.

**Задачи.** Первичные конечные точки — полное покрытие размеченных реплик в первых 5 и качество выдаваемого ответа. На всех десяти разговорах воспроизводимо выбираем до 35 вопросов на разговор по хешу идентификатора среди категорий 1–4 с допустимыми репликами для CPU-читателя, до раскрытия ответов. Читатель один и тот же для flat, attribution+graph и placebo (также lexical/fusion при наличии вычислительного бюджета). Получает исходные датированные реплики из top-5 и вопрос, не получает обучающих примеров ответов и эталона. Выбирает одну непрерывную последовательность слов общедоступной SQuAD-моделью с пределом длины 24 токена ответа и 384 токена входа, одинаково для каждого метода. Ответы и оценки фиксируются отдельно, измеряем авторский протокол token F1 там, где применим (иначе нормализованный F1 с явно описанными отличиями), точное совпадение, среднее число прочитанных токенов и случаев усечения. Разделяем вопросы с несколькими допустимыми ответами и сложные составные ответы, где экстрактивный читатель ограничен. Это реальный QA-читатель, а не пользовательский диалоговый агент в интерактивной среде.

Вторичные метрики: any/all, средняя доля найденных evidence, обычная MRR, nDCG; k=1,3,5,10 для реплик и сессий. Сессии ранжируются по лучшей реплике, одинаковая агрегация всех методов. Доля полного покрытия vs BM25 на другом уровне гранулярности не приписывается самому графу. На том же наборе сессий проверяем внешний опубликованный итог Memoria (уровень сессий, правила категорий совпадают), без парного интервала для непубличных поштучных ответов. Механистический разрез — собственник однозначно назван в вопросе, число свидетельств. 95% парный bootstrap на уровне разговоров с одинаковым ресемплированием для всех вопросов из разговора, знак/разность по каждому разговору, точный двусторонний sign-flip десяти разговоров с условиями симметрии. Две первичные конечные точки показываются обе; вторичные и анализ срезов — диагностические. Ни прореживание контекста читателя, ни QA категории не применяются как oracle вход ретривера. Ограничение однослойной регрессии и возможное попадание публичных данных в предобучение указываем в выводах.

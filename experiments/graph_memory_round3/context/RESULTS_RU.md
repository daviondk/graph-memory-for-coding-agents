# Что даёт точный выбор границ кода в рабочей памяти

Мы проверили два способа возвращать агенту уже виденный код. Первый прогнозирует, с какой строки начнётся будущая правка и сколько строк она займёт. Второй сохраняет прежнюю выдачу, объединяет соседние строки одного файла под общим адресом и тратит освободившиеся токены на ближайшие строки. Самый устойчивый выигрыш при **том же фактическом расходе каждого действия** дал второй, более простой способ.

## Числа для короткого доклада

На 2 135 принятых правках из 26 новых проектов прежний R2-F при лимите 512 вернул весь нужный фрагмент 428 раз. Алгоритм с обучаемыми границами — 588, симметричное расширение исходной выдачи — 611. Простое расширение добавило 183 полных попадания, +8,57 процентного пункта, 95% кластерный ДИ [7,21; 10,19]. Для этого оно использовало в среднем 452 токена вместо 328. На заранее отложенной **другой** группе из 12 проектов при том же потолке получили 317 против 221 из 1 210, +7,93 п.п., ДИ [5,57; 10,31]. Обе группы состояли из новых проектов для обучаемых политик.

Более строгая проверка запретила на каждом шаге превышать **реальную** стоимость исходного пакета, одновременно по сумме токенов отдельных блоков и числу токенов итоговой строки. Симметричное расширение дало **451 против 428** (+1,08 п.п., ДИ [0,66; 1,69]) и **229 против 221** (+0,66 п.п., ДИ [0,20; 1,15]). Средний расход улучшенного метода даже снизился до 320 вместо 328 и 318 вместо 326. По построению старые строки сохранены; величина дополнительного покрытия измерена по спрятанной до оценки следующей операции. Полученная гарантия применима к покрытию текста. Результат работы агента может меняться и от порядка предъявления, и от постороннего контекста.

## Какие свойства действительно изменились

1. **Длина правок.** В первой группе при 512 токенах 682 цели занимали не менее 25 строк. Из них структурная модель покрыла 137 целиком, прежняя 48, плоская модель с гибкими окнами 130. Для 894 целей на 1–12 строк показатели 270, 227, 264; для 559 целей на 13–24 строки — 181, 153, 183. Большая часть прибавки длинным правкам доступна уже за счёт предложений окон переменного размера.
2. **Выигрыш при одинаковом потолке отличается от выигрыша на фактически потраченный токен.** У структурной модели против R2-F по первой панели при 512 токенах +7,49 п.п. по полной правке, ДИ [5,77; 9,60], 248 выигрышей и 88 проигрышей. Полезное покрытие строк выросло с 26,87% до 34,24%, попадания по первой строке с 534 до 763. Но реальный расход вырос с 327,6 до 459,2 токена, а доля полезных строк в самой выдаче снизилась с 16,97% до 16,13%. На втором наборе наблюдаемый прирост полного покрытия +7,69 п.п., ДИ [4,45; 10,73], с ростом среднего расхода с 326,0 до 457,5.
3. **Тот же реальный расход.** Структурной модели разрешили заново выбрать пакет с индивидуальным потолком R2-F для каждого шага. Получили 413/2135 против 428, −0,70 п.п., ДИ [−1,97; +0,71], 90 улучшений/105 ухудшений. Доля покрытых строк 26,65% против 26,87%. Первую строку она продолжила предсказывать лучше — 628 против 534, +4,40 п.п., ДИ [2,77; 6,16], а точность возвращённых строк выросла на 0,79 п.п. Другой способ чтения может быть уместен для навигации и одновременно слабее для загрузки редактируемого фрагмента целиком.
4. **Модель против упаковки.** При номинальных 512 структурная модель выиграла у плоской модели при той же библиотеке 11 полных фрагментов в первой группе и 16 во второй. Оба кластерных интервала этой разности включают ноль. У простого расширения R2-F 611/317, у структурной модели 588/314. На первой выборке дополнительная структурная модель с собственным расширением дала 618, на второй 328; парные интервалы относительно расширенного R2-F также включают ноль. Эмпирические данные сильнее поддерживают правило упаковки.
5. **Что предсказывает эффект при равных расходах.** При обычных заголовках имя файла и оба номера строки повторяются для каждой страницы. Если путь включить только один раз на файл, сохранить короткие числовые границы и заново выровнять обе цены, симметричное расширение даёт 444 вместо 428 и 225 вместо 221. Если вообще убрать заголовки со всей разметкой, обе выдачи имеют одинаковое полное покрытие (428 = 428, 221 = 221). На этом материале эффект строгой экономии объясняется стоимостью адресов в протоколе. Общий лимит дополнительно позволяет потратить свободное место, особенно при 512 токенах.
6. **Что редактировал агент.** В исследовательском разрезе по имени файла в первой группе 444/2135 действий относились к явно названным сценариям воспроизведения или временным программам, ещё 160 — к тестам. У остальных 1531 путей структурный метод дал 516, расширенный исходный 521 и прежний 359; вариант равной цены 379. Во второй группе среди 793 остальных путей эти числа 252, 246, 167 и 175. Это эвристика имени файла. Воспроизведение исторического шага редактора остаётся промежуточной метрикой по отношению к качеству итогового патча.

## Механизм и математическая проверка

В структурном методе сохраняется граф реально прочитанных строк с текущим файлом, координатами и подтверждёнными изменениями. Старый ранжировщик оценивает массу каждой страницы. Условная softmax-модель распределяет её по строкам, используя отступ, вид оператора, лексическое совпадение задачи, положение внутри страницы и границы соседних строк. Длина будущей правки оценивается по старым действиям эмпирически с иерархическим сглаживанием. В совместное распределение входят полные наблюдаемые интервалы. Для любого выбранного объединения U и возможной правки I ожидаемая награда полного покрытия равна сумме P(I) по I, для которых I содержится в U. Численная модель может ошибаться в вероятностях. Перебирается только фиксированная библиотека связных окон до 72 строк и до двух оставшихся старых страниц. Прежний пакет — один из вариантов. Утверждение глобального оптимума по всем подмножествам строк здесь было бы неверным.

У монотонного расширения инвариант проще. Если S — строки базового пакета, выбираются только пакеты S′, где S ⊆ S′ и обе стоимости укладываются в заданные пределы. Тогда для каждого истинного интервала I выполнено 1[I ⊆ S′] ≥ 1[I ⊆ S]. Аналогично не убывает доля найденных строк I. Инвариант не гарантирует роста точности самих предсказаний модели. Проверены 77 700 включений множеств на всех 6 475 границах обеих панелей и 25 900 индивидуальных двойных ограничений цены. Ранее сохранённая выдача R2-F и цены воспроизведены в 88 проверках на архивных префиксах.

В одном из случаев (хеш-отбор примера, python-readability) следующая правка охватывала строки 10–38 небольшого сценария. Перекомпоновка поместила весь фрагмент в те же 406 токенов. Обратный пример для политики, заменяющей исходные строки: в grafanalib она не сохранила текст следующей замены, хотя потратила 486 токенов против прежних 215. Координаты и исходные/новые пакеты в illustrations.json.

## Область применимости и воспроизводимость

Источник — восемь шардов редактора SWE-smith. На первом этапе отобраны 628 задач, одна исключена фиксированным текстовым фильтром, 627 траекторий давали 4 051 границу; у 612 траекторий имелась подходящая принятая операция. На втором этапе 336 траекторий давали 2 424 границы, 329 — подходящий исход. Окно соответствует исходному R2-F: первая непустая попытка str_replace в ближайших четырёх действиях должна быть принята. По всем срокам принятия и каждому источнику политика видит только предшествующие действия. Неоднозначные цели оцениваются нулём, в первой группе таких 549. Для обучения использованы 5 631 однозначно локализованная правка из 44 других проектов. При 512 максимальная доля фрагментов первой группы, которые теоретически можно было вернуть одним точно угаданным адресуемым пакетом из доступных строк, — 1 338/2 135. Это показатель доступности и длины. Общедоступные траектории могли входить в предобучение исходных агентов. Прогонов нового агента на открытых репозиториях здесь нет. [Страница SWE-smith](https://swesmith.com/) · [Данные на фиксированной ревизии](https://huggingface.co/datasets/SWE-bench/SWE-smith-trajectories/tree/08e109b4a59eaeebf80e4675cd125d42e7ac99a4/data)

Интервалы — 10 000 ресемплирований проектов с возвращением, основная величина взвешена по наблюдаемым действиям. Все сравнения парные. В журнале содержатся также макро по проектам и результаты каждого проекта. Уровни 256/512 заданы заранее. Эксперимент расширения началcя после наблюдения первого результата гибких окон, его независимый перенос на другие 12 проектов и политика сохранения исходного контекста закреплены до новых исходов. Сравнение форматов wire – последующий механистический тест. На 197 префиксах маргинальный расход CPU на расширение уже выбранного пакета составил в среднем 14,0 мс при общем лимите и 1,5 мс при индивидуальном пределе; локальный счётчик Windows имеет грубое разрешение. Сюда не включены стоимость исходного поиска, модель и ввод-вывод.

Переменная гранулярность и компрессия кода уже изучаются в Late Code Chunking, LongCodeZip и Rivet. Отличие этой проверки – онлайн-память только на основании текущих наблюдений, цена на каждом отдельном решении и полное покрытие его будущей правки. Невозможно по данным этого replay объявить превосходство над опубликованным Pass@1 на DevEval, RepoExec или SWE-bench Verified. Для такого сравнения нужен общий решатель, одинаковые источники контекста и запуск официальных тестов. [Late Code Chunking](https://aclanthology.org/2026.acl-short.64/) · [LongCodeZip](https://arxiv.org/abs/2510.00446) · [Rivet](https://arxiv.org/abs/2610.34967)

Порядок запуска, файлы протоколов и правила повторной оценки приведены в REPRODUCE.md. В папке replication те же таблицы и предсказания для второй группы.

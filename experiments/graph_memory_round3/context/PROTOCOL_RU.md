# Память о границах прочитанного фрагмента

Зафиксировано 18.11.2026 до просмотра разметки новых репозиториев. Данные SWE-smith, хеши восьми исходных таблиц как в R2. Проверяем перенос на ранее не использованные проекты из той же коллекции. Из доступных в инвентаризации метаданных выбраны перечисленные в acquire.py библиотеки форматирования, построения документации, запросов и преобразования данных. Журналы прогоняются через тот же текстовый фильтр. Все прежние instance из E, F и S4 исключаются. Берём первый по хешу r3edge не более 48 задач на проект. Семя выбора траектории фиксированное. Обучающие данные – исключительно те же 44 проекта, что и у R2-F. Проект, задача и действие нового теста не используются для настройки. Сохраняем прогнозы на каждом четвёртом действии до отдельной оценки. Не запускаем старые действия агента и содержимое изучаемого кода.

Проверяем, стоит ли хранить переходы к началу предполагаемой правки по строкам внутри прочитанной страницы. R2-F возвращал до трёх целых страниц; ряд будущих правок пересекает границу страниц, и крайние страницы могут занимать много токенов ради нескольких полезных строк. Предлагаем сопоставлять будущую правку с парой граничных строк. Используем фиксированную старую модель вероятности начальной страницы. По старым обучающим правкам оцениваем распределение начала внутри страницы с учётом вида строки и соседей и распределение длины будущей замены. Вероятность покрытия интервала ожидаемым контекстом задаётся суммой вероятностей всех целиком покрытых гипотез; неполное покрытие измерим дополнительно. Чтобы сохранить возможность выигрышного старого решения, фиксированная библиотека альтернатив включает исходный пакет R2-F, пустой пакет и скользящие окна из настоящих, хронологически согласованных строк, прикреплённые к центрам и началам наиболее вероятных страниц. Окна могут переходить через границы страниц только у соседних фактически прочитанных строк того же файла. Доступ ограничен теми же 48 страницами. Один длинный блок читается за один запрос памяти; максимум три блока. Истинная и раздельно подсчитанная длина сериализации с адресом входит в бюджет. Это другой набор допустимых пакетов; чтобы различать эффект упаковки и модели, контроль с тем же набором выбирает пакет по равномерной позиции старта внутри страницы и общей эмпирической длине. Контроли: неизменённый R2-F, давность, короткий фиксированный пакет вокруг лучшей страницы; отдельно вклад структуры начала или длины. Новая политика не заглядывает в следующую команду. Архитектуру упрощаем по вычислительным соображениям до просмотра результатов любых новых методов.

Первичная метрика – доля будущих правок, точный непрерывный исходный текст которых целиком покрыт в лимите 512 токенов, сравнение со старым R2-F и с тем же набором альтернатив без структурных признаков. Вторичные: аналогично 256 токенов; средняя доля покрытых строк правки по каждой принятой операции; начальная строка; эффективность использования переданных токенов и число блоков; заранее указанные разрезы по длине (1–12, 13–24, 25+ строк; отдельно цели без однозначной локализации), по репозиториям и макро. При отсутствии однозначной позиции полные и дробные исходы равны нулю, что соответствует нижней оценке на данной памяти. Строго то же окно R2, первая непустая попытка замены следующих четырёх действий, принятая редактором. Ресемплирование целых репозиториев 10000 раз. Результаты включая потери сохраняются без отбора по знаку. Демонстрируется выбор рабочего контекста; качество решения issue измеряется в другой ветви.

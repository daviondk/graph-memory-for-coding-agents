# Почему целая правка меняет оптимальный выбор

Обозначим через S набор хранимых страниц, через I — страницы единственного будущего редактируемого фрагмента. Если для успешной передачи нужны все его страницы, ожидаемая полезность имеет вид

U(S) = Σᵢ wᵢ · 1[Iᵢ ⊆ S].

При истинном распределении w это вероятность покрытия. В экспериментах используются веса, оценённые по истории редактора. Масса ненаблюдаемого фрагмента может находиться вне кандидатов. При положительном масштабе нормировка всех w одним числом для данного состояния не изменит выбор S.

**Совместная полезность.** Для фиксированной страницы x приращение от её добавления — сумма весов тех интервалов, в которых x была последней недостающей страницей. Если A ⊆ B и x ∉ B, набор таких интервалов для A включён в соответствующий набор для B. При неотрицательных весах приращение U(A ∪ {x}) − U(A) не больше U(B ∪ {x}) − U(B). Это возрастающая супермодулярная функция. Вознаграждение за вернувшуюся долю отдельных страниц, напротив, складывается постранично. Оба критерия можно честно оптимизировать на одном и том же распределении запросов.

**Пример.** С вероятностью 0,60 потребуются две соседние страницы A и B, с вероятностью 0,40 — одиночная страница C. Вмещаются две страницы одинакового размера. Если за каждую вернуть пропорциональную часть веса, полезность C равна 0,40, A и B — по 0,30. По этому правилу выбираются C и любая из двух других. Полностью удовлетворён запрос только на C, то есть с вероятностью 0,40. Для целого применения нужно выбрать A и B, что даёт 0,60. Контрпример объясняет возможность разности. Её величину на реальных действиях определяет только эксперимент.

**Почему точный расчёт возможен в нашей постановке.** При последовательных интервалах длины до 3 достаточно помнить, сохранены ли одна или две предыдущие позиции. При включении текущей страницы j добавляются веса её одиночного интервала, пары с j−1 и тройки с j−2 и j−1, если соответствующие позиции оставлены. При разрыве по файлу или номеру строки вес несмежного интервала равен нулю. DP перебирает конечные состояния и возможный счётчик байтов; из каждого состояния индуктивно сохраняется лучший предшественник. Время O(nB) является псевдополиномиальным, поскольку B — целочисленный лимит в байтах, а ширина интервала ограничена константой. Жадное удаление дешевле. Результаты строгого DP при одинаковом прогнозе позволяют проверить эффект именно групповой функции полезности.

**Граница гарантии.** Если оценённое распределение будущих интервалов отличается от истинного на ε по полной вариации, то для любого S ошибка прогнозируемой вероятности покрытия не превосходит ε. Применение этого неравенства к истинному и выбранному оптимумам даёт верхнюю границу 2ε на потерю ожидаемой полезности в одном фиксированном состоянии. Для этой оценки нужны нормированные вероятности, включая категорию недоступных случаев. Наш обученный скорер служит для ранжирования; значение ε на реальных данных не известно. Более того, запись меняет будущий состав кэша, поэтому утверждение об одном решении не является глобальной гарантией online-алгоритма. В serialized_writer используется сжатое представление с взаимозависимыми байтовыми ценами; там ограничение проверяется фактической сериализацией, точное DP с аддитивными стоимостями к этому формату напрямую не применяется.

**Что подтверждено.** При одинаковом текущем наборе и весах точное решение часто повышает вычисленную полезность относительно жадного, но на второй полной траектории эмпирическое число полностью сохранённых фрагментов изменилось лишь с 494 до 496 (4 КиБ). Сильнее изменилось сравнение функций полезности: сохранение целых интервалов дало 496, деление их веса по страницам дало 464 при одинаковом точном решателе. В задачах с частичной ценностью знания, например при прогнозе отдельных строк просмотра, другой критерий может оказаться лучше. Исторически групповой критерий известен из [file-bundle caching](https://arxiv.org/abs/2011.03212) и [page-level hit ratio](https://www.microsoft.com/en-us/research/publication/maximizing-page-level-cache-hit-ratios-in-large-web-services/).

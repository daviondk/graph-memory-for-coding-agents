# Передача ограниченной памяти решателю

Дополнительный факторный эксперимент после отдельных результатов записи и чтения на одной и той же панели. При ограничении хранилища 4/12 KiB и выдачи 512 токенов комбинируем три уже замороженные политики записи (LRU по давности, точечная вероятность на байт, связные интервалы с условной шириной) и два замороженных читателя (R2-F с целыми страницами и R3 с гибкими границами строк). На каждом шаге читатель видит только фактически оставшиеся у данного писателя строки. Оценка достигаемого фрагмента идёт по unbounded эталону, включая сравнение текста каждой выбранной строки с текущей версией. Сохраняем также реально сериализованные токены. Сравнения по всей матрице, первичный вопрос — помогает ли новая запись при неизменном новом читателе (typed writer против point writer при 4096 и 512). Если преимущества установки памяти исчезнут после выдачи, сообщаем оба результата. Этот тест не использует новые экземпляры относительно отдельных ветвей; сравнение исследовательское. Новые запросы LLM не требуются.

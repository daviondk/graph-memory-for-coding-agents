# Воспроизведение одиннадцатой серии

Корневая команда `python package_local.py --verify ПУТЬ_ZIP` проверяет сохранённые записи побайтно по манифесту. Для просмотра либо пересчёта готовых агрегатов не требуется запускать большую модель. Скрипты подготовки, которые читают прежние данные, ожидают исходное дерево на D с каталогами всех серий.

- Пустые запросы. [Протокол](negative_actions/PROTOCOL_RU.md), [участники и ревизии](negative_actions/roster.json), [проверка](negative_actions/verification.json), [поштучная сводка и сценарии проверки](negative_actions/REPORT_RU.md). Зеркала Git восстанавливаются по сохранённым URL и ревизиям.
- Просмотры редактора. В readback запустить prepare.py и replay.py из исходного дерева. Первый создаёт набор views.gz на зафиксированной популяции R8. Второй считает токены и проверяет декодирование каждой выдачи. Перекрёстный подсчёт native_tokens.py использует служебный маршрут tokenize локального llama-server на 18950. [Поштучные размеры](readback/native-token-rows.gz) и [сводный аудит](readback/audit.json) уже включены.
- Генерации Qwen. Два отдельных каталога содержат по протоколу, входам, закрытому ключу, ответам и журналу запроса к серверу. В новой рабочей копии запустить probe.py prepare, run и score с отдельным запуском сервера на 18949. Для эксперимента замены строки аналогичная последовательность intervene.py prepare, run и grade с портом 18950. Ответы больше не нужно генерировать для аудита. [Основной тест](readback/probe/PROTOCOL_RU.md) · [Изменение основания](readback/probe/intervention/PROTOCOL_RU.md)
- sqz. В отчёте указаны commit, SHA бинарника, официальный CLI и проверка исходного MCP read_file. Включены фактические результаты store/expand и сопоставление каждого запроса с видимым источником. [Инструкции](native_dedup/README_RU.md)
- QuixBugs. Сбор, формирование состояний, чтение, оценивание, учёт времени CPU и независимая проверка отражены в [порядке воспроизведения](multiset_quix/REPRODUCE_RU.md). Сохранены архив исходных текстов, исходные тестовые наблюдения, сжатые состояния и результаты чтения.

Модели и двоичные дистрибутивы сторонних инструментов хранятся вне архива. Список распространяемых записей определяется упаковщиком. Программные файлы в логах служат данными исследования. Для повторного анализа извлекаются записанные поля, без выполнения команд из чужих траекторий.

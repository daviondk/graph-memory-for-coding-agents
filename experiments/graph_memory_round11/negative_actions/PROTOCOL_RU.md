# Устаревание отрицательных наблюдений в реальных действиях SWE-агентов

До просмотра результатов поиска и сверки с Git фиксируем три готовых публичных панели. Это все доступные траектории из запечатанных ранее Kimi action_transfer, Kimi writer/action_probe и Claude external. Включаем целиком доступные научные и документационные проекты SymPy, matplotlib, scikit-learn, astropy, sphinx. Ограничиваем предметную область обычными задачами о математике и API. Пропускаем по описанию задачи случаи, явно посвящённые уязвимостям. Эти архивы использовались раньше для другой цели (положительные чтения и поиск строк). Новая зависимая переменная и проверки Git раньше не использовались. Единица повтора — уникальный ключ на конкретной задаче и конкретном агенте, группируем также по задаче и репозиторию. Распределения действий и повторов ключей публикуем отдельно.

**Покрытие.** Подсчитать строго засвидетельствованные неуспешные действия поиска. Проверяем простые grep/rg по строке с неинтерпретируемым литералом, find по точному имени, проверяемый абсолютный/репозиторный путь с явной диагностикой отсутствия при чтении. Отдельно учитывать неразрешимые рабочие каталоги, длинные конвейеры, регулярные выражения и технические ошибки. Для grep чистый exit 1 означает отсутствие совпадения только у чистой команды, если целевой каталог существует и нет диагностики/незачтённого вывода. Exit 2, неизвестный exit при неоднозначной выдаче, ошибки регулярного выражения или запуска остаются вне строгого слоя. Для find нужен пустой stdout, подтверждённое завершение и точный шаблон. Явная диагностика об отсутствующем точном файле — результат о недоступности пути даже при другом коде выполнения. Команды из журналов не выполняются оболочкой. Используем подмножество явно разбираемых параметров, нормализацию путей при известном cwd, корпуса запросов и безопасные независимые операции с Git-объектами. Ключи, которые были найдены только по пустому stdout без подтверждения состояния, помечаются отдельно. Для файловых ключей отрицательный результат у редактора должен указывать тот же точный путь. Классификатор и все исключения будут приложены.

**Независимые исходы.** Сначала запечатываем записи и предсказанный отбор по хешу. Для каждой задачи со строгим пригодным наблюдением берём официальный base_commit SWE-bench и публичный merge_commit_sha исходного PR (GitHub, проверка идентификатора и факта слияния). При более чем 24 пригодных задачах берём первые 24 по SHA256 строки r11-natural-neg-v1|instance_id, без учёта наличия будущих изменений. В одном случае включаем все строгие уникальные наблюдения. Повторяем их на обоих деревьях отслеживаемых файлов исходного Git. Старое дерево должно подтвердить отсутствие. Отклонённые при сверке случаи оставляем в таблице с причиной. Новым исходом является присутствие буквального имени или совпадения на втором дереве, а для точного файла — наличие самого файла. Для простого grep воспроизводится именно наличие совпадения, а не формат строк. Ограничение исходов — поиск по отслеживаемому исходному коду. Пары записываются с SHA и источником. Оценка полезности при решении самой SWE-задачи этим критерием не задаётся.

**Политики записи и перечитывания.** (1) Переиспользовать каждый прежний отрицательный результат. (2) Хранить все строгие промахи и перечитывать при любом изменении дерева. (3) Хранить все ключи и перечитывать по пересечению области поиска с изменёнными путями. (4) Хранить все точные ключи, перечитывать при появлении совпадающего пути или при появлении литерала в добавленном/изменённом тексте в области запроса; считаем стоимость чтения диффа отдельно. (5) Сохранить ключ, если в ближайших трёх последующих наблюдаемых действиях агент использовал ту же строку в своих входных аргументах. Случайное сравнение при том же числе сохраняемых ключей — детерминированная перестановка по SHA256 внутри панелей. Не сохранённое наблюдение требует полного поиска при обращении и не получает бесплатного выигрыша. Ценность сигнала использования — ассоциация с последующим появлением ключа и экономия работы при корректном повторном запросе. Отдельно подсчитываем долю сохранённых наблюдений и компактные байты. Подсчитываем собственно изменения, stale, лишние перечитывания и длину патча или изменённых объектов. Различаем закрытую симуляцию повторного запроса от фактического повторного запроса в траектории.

Приводим нулевые частоты и объем фактического покрытия. Если строгих исходов мало, зафиксированный результат — внешняя оценка покрытия и причин исключений. Анализ дополнительно поддержанных грамматик или источников явно маркируется как разведочный. Никаких непроверенных утверждений об эффекте на LLM. Точные команды, состояния и метаданные доступны в локальной папке D. Публичная публикация артефактов в этой серии не выполняется.

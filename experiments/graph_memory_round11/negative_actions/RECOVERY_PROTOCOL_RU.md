# Дополнительная проверка наблюдаемой навигации после промаха

Зафиксирована после извлечения семи строгих путей и списка изменений, до просмотра текстов следующих чтений и до сверки их путей. Цель — понять, полезно ли записать переход «ошибочный путь → следующий успешно открытый файл». Для каждого первого строгого промаха целью служит первый явно успешный view обычного отслеживаемого файла в следующих шести вызовах. Подтверждаем вид показанного содержимого по успешному ответу инструмента и существование пути обычного файла в официальном старом SHA. Диагностики и просмотры каталогов пропускаем. Нет цели в пределах окна — цензурированный случай. Сравнения: исходный буквальный путь, две независимые от обучающих исходов операции с официальным старым деревом (эквивалент Python-модуля X.py→X/__init__.py и единственный полный путь с совпадающим суффиксом), а также сохранённый из другой задачи точный переход с тем же неправильным путём. Для памяти допустима только другая задача того же репозитория с меньшим номером GitHub PR, также ставим дополнительное требование реального порядка по временным меткам merged_at PR. Эти два порядка проверяются вместе. Последний подход публикуем только для случаев с разрешённой историей и в целом по всем семи. Если ранее наблюдалось несколько коррекций, используем последнюю по времени. При одинаковом времени решает номер. Это наблюдательная диагностика, само прочтение файла не устанавливает, что он нужен для решения issue. О числе независимых проектов сообщаем отдельно. Включает все семь случаев.

# Публичный sqz на фиксированных ответах редактора

Фиксируем сравнение до применения исполняемого файла к просмотрам. Берём полностью панель readback/views.gz с её каноническим нумерованным представлением; независимая единица — траектория, включая пустые. Официальный Windows release sqz 2.2.0 запускается локально по одному разу на сообщение в штатном stdin auto режиме с аргументами compress --cmd editor.view --lossless. Стандартный внешний вызов получает ровно содержимое строк, метка исходного события добавляется после компрессии одинаково обеим сторонам. Принудительно задаём отдельную пустую SQLite через SQZ_DB_PATH для каждой траектории и SQZ_QUIET=1, разрешая штатные ссылки. Никаких hook, личных сессий, shell-команд из данных или запросов к модели. Трасса содержит операции editor.view. Перехват произвольного просмотра редактора shell-хуком в реальном клиенте не предполагается. Прямое обращение к CLI на сохранённых результатах — адаптер этой работы.

Основной результат — токены принятого сообщения с верификацией в строгом режиме видимого контекста: если stdout возвращает полной копией строки, принимаем. Если в нём настоящая ссылка sqz, вызываем sqz expand и сохраняем исходные байты. Проверяем, что расширение в точности совпало с входом, и что основная страница обнаруживается по SHA256 в ранее предъявленном буквальном ответе того же файла не дальше 8 исходных событий. В остальных случаях отправляется целая исходная выдача и учитывается в стоимости. Время жизни в 8 событий задаёт адаптер. Отдельно измеряем родной неограниченный событиями кэш: физическая восстановимость через expand, числа точных ссылок и ссылок-диапазонов, токены stdout. Ошибку восстановимости регистрируем и предъявляем целый исходник. Нативный кэш по умолчанию имеет свою временную политику.

Сравниваем с уже замороженными raw, whole, single и union в readback на тех же просмотрах/окне/токенизаторе. Основной контраст strict sqz − union (сэкономленные токены как доля токенов raw); парный bootstrap 5 000 раз по траекториям, seed 11226, с разбивкой по панелям. Считаем также выигрыш/проигрыш по задачам. Байты входа/выхода, stdout/stderr, нативный expand и контрольные суммы доступны в журнале. Вызов expand — проверка экспериментатора, его ответ не прибавляется к контексту по умолчанию. Отдельно считаем цену, если все ссылки немедленно разворачивает клиент. Воспроизводимость проверяется автономным повторным подсчётом по сырым выдачам. Это тест передачи содержимого повторных просмотров; интерфейс редактора и решение исходной задачи не воспроизводятся.

Положительный контроль: на отдельной БД выдаём уже наблюдаемый полный номерной текст длиной не менее 24 строк, его точную копию и заведомый внутренний диапазон, каждый побайтово сравниваем с expand. Этот пример проверяет работоспособность прохода, он исключён из панельной статистики. [Официальный выпуск](https://github.com/ojuschugh1/sqz/releases/tag/v2.2.0)

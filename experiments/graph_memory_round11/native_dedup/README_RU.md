# Проверка реального sqz на повторных чтениях кода

Запустили официальный **sqz 2.2.0** на 426 сохранённых ответах редактора. Инструмент 86 раз вернул ссылку вместо кода. Все 86 удалось физически развернуть в исходный текст побайтно. При доступе обеих систем к восьми последним событиям наш кодировщик передал на **5 928 токенов меньше**, чем sqz с проверкой видимости (+1,16% от исходного текста, 95% интервал по траекториям [0,60%; 1,86%]). Из этой разницы всего **114 токенов** объясняется переходом от одной лучшей базы к нескольким в нашей реализации. [Основные результаты](results.json) · [Общий протокол](PROTOCOL_RU.md)

## Сравнение при двух правилах доступности истории

Состав панели — 199 зафиксированных траекторий, из них в 92 есть хотя бы один подходящий ответ; у остальных нулевой вклад. В 37 траекториях Claude найдено 347 просмотров, в 65 Kimi — 33, в 97 второй панели Kimi — 46. Учитывается канонический ответ по Python-файлу с пронумерованными строками и неизменяемой меткой события. Количество токенов измерено одним и тем же локальным токенизатором Qwen на фактически передаваемом тексте. Метод `whole` требует совпадения всего сообщения с одним предыдущим диапазоном. `single` может передавать частичные совпадения с одним старым просмотром. `union` допускает несколько таких источников. Все методы могут вернуть буквальный текст. [Формирование панели и исходные кодировщики](../readback/replay.py)

| Доступная история и условия | Сырые ответы | sqz | whole | single | union | Разница sqz − union |
|---|---:|---:|---:|---:|---:|---:|
| Последние 8 событий, обязательны прежние буквальные строки | 511 819 | 507 301 | 506 839 | 501 487 | **501 373** | 5 928 |
| Полная история траектории, обязательны прежние буквальные строки, вторичное сравнение | 511 819 | 485 375 | 484 074 | 478 821 | **478 490** | 6 885 |

В основной строке sqz отправил ссылку, которую можно было разрешить в буквальном контексте, 24 раза. Ещё 62 его ссылки указывали на прежнее наблюдение вне восьми событий или отсутствующее в таком окне как полное буквальное основание. Адаптер заменил их исходным текстом. Прибыль зафиксирована у 32 траекторий из 199, ни у одной нет увеличения стоимости `union` относительно sqz. Вся основная разница приходится на Claude (5 928 из 313 458, 1,89%, интервал [0,99%; 3,19%]). В обеих панелях Kimi при W=8 решения совпали по числу токенов. [Квитанции и основания решений по каждому просмотру](scored.gz) · [Результаты по траекториям](by-task.json)

Во второй строке sqz работает с нативным неограниченным числом событий кэша, каждая из 86 ссылок имеет ранее предъявленный буквальный источник того же файла. В обеих системах предшествующие просмотры только этой траектории сохраняются полностью. Выигрыш `union` равен 1,35% от raw, 95% интервал [0,76%; 2,07%]; добавка `union` к `single` составила 331 токен. Это отдельный вторичный анализ после первичного сравнения. Если же сопоставить нативный sqz с восьмисобытийным `union`, sqz передаёт на 15 998 токенов меньше. Это наблюдаемая цена разных предположений о доступности контекста. Если клиент действительно подставит тексты **всех** 86 расширений поверх ссылок, это добавит 28 572 токена самих исходных фрагментов к 485 375 токенам нативной выдачи. Такое число не включает обёртки дополнительных вызовов и служебный stderr. [Дополнительный протокол](LONG_SCOPE.md) · [Полная сессия](long-results.json) · [Скрипт расчёта](long_scope.py)

## Что именно исполнялось

Использовался официальный x86-64 Windows release-бинарник с проверкой SHA-256 архива через GitHub release metadata. Версия 2.2.0, SHA исходного коммита `68cccfba8d7728905e35476a5a6b6e2c75e01f5c`. Каждая траектория получила чистую отдельную SQLite (`SQZ_DB_PATH`). Каждый просмотр был передан штатному CLI через stdin командой `sqz compress --cmd editor.view --lossless`, с `SQZ_QUIET=1`. Опция `--lossless` сохраняет исходный текст при новом чтении и оставляет доступной нативную дедупликацию по полной строке или диапазону. Для каждой ссылки вызван настоящий `sqz expand`. Из 426 компрессий все завершились кодом 0, 340 вернули исходный текст, 6 вернули точную ссылку и 80 — ссылку на диапазон из ранее прочитанного текста. При чтении полного файла, его повторном чтении и последующем чтении внутренних строк положительный контроль восстановил оба варианта. [Официальный выпуск](https://github.com/ojuschugh1/sqz/releases/tag/v2.2.0) · [Привязка к хешам](upstream.json) · [Подлинная проверка диапазона в исходниках](https://github.com/ojuschugh1/sqz/blob/68cccfba8d7728905e35476a5a6b6e2c75e01f5c/sqz_engine/src/cache_manager.rs#L563) · [Сырые stdout, stderr и expand](native-receipts.gz)

В исходных траекториях агент получал результаты встроенных операций просмотра редактора. Работающий shell hook перехватывает подходящие терминальные команды; в данном опыте он не устанавливался. Подготовленный адаптер подаёт реальный текст прежней операции на стандартный вход sqz. Он добавляет к ответу общую для всех методов метку просмотра и проверяет видимость адресата при W=8. Это обеспечивает идентичность входов и делает возможным сопоставление семантики окна. Нативная политика sqz дополнительно использует собственное время жизни кэша, ограничения поиска диапазонов и порог для окупаемости ссылки. Стоимость каждой ссылки в наших метриках вычислена по её фактической строке. [Путь stdin](https://github.com/ojuschugh1/sqz/blob/68cccfba8d7728905e35476a5a6b6e2c75e01f5c/sqz/src/main.rs#L1250) · [Проверки кэша и режима](https://github.com/ojuschugh1/sqz/blob/68cccfba8d7728905e35476a5a6b6e2c75e01f5c/sqz/src/cli_proxy.rs#L279) · [Адаптер эксперимента](exercise.py)

Отдельно проверен реальный сервер **sqz-mcp** того же официального выпуска, локальный stdio JSON-RPC. В отдельном файле сохранили уже наблюдавшийся номерной текст одного просмотра. Через `sqz_read_file` запросили файл целиком, затем повторно и затем с `offset=11, limit=22`. При первом запросе пришёл исходный текст. Следующие вернули ссылки на полный текст и строки 11–32. Обе удалось побайтно прочитать встроенным `expand` после удаления явно отделённого служебного заголовка. При проверке интерфейса имя `sqz_expand`, относящееся к режиму MCP proxy, в standalone-сервере дало возврат аргумента. В основной положительной проверке использовано документированное для standalone имя `expand` с полем `prefix`. Это демонстрация API на одном файле, в 426 панельных наблюдениях использован CLI. [Оригинальный MCP-метод](https://github.com/ojuschugh1/sqz/blob/68cccfba8d7728905e35476a5a6b6e2c75e01f5c/sqz-mcp/src/lib.rs#L583) · [Реальный обмен MCP](mcp-control.json) · [Запись первоначального обращения по имени proxy](mcp-proxy-name-mismatch.json)

## Как интерпретировать результат

В обеих семантиках основную часть преимущества даёт даже вариант, умеющий сопоставить частичный ответ с одним прежним просмотром. Возможные объяснения оставшейся разницы — размер синтаксиса ссылки, минимальный размер диапазона, выбор отдавать частичное совпадение и способ выбора источника. Конкретный вклад каждого из этих механизмов эксперимент не разделяет. Выгода нескольких баз относительно одной мала, в исходном восьмисобытийном сравнении она сосредоточена в одной из трёх панелей. Перенос результата на решение задач, частоту обращений к инструментам и качество ответа LLM требует отдельного эксперимента. Нативный SQLite после завершения непустой задачи занимал медианно 157 696 байт, суммарно по всем задачам — 15 683 584 байта. Потребление памяти процессом и стоимость полного диалога не измерялись.

Для воспроизведения из этой папки выполните `python -B fetch.py`, `python -B exercise.py`, `python -B audit.py`, `python -B long_scope.py`. Для отдельной проверки MCP выполните `python -B mcp_probe.py`. Повторная оценка по сохранённым протоколам ввода-вывода выполняется локально командой `python -B audit.py`. Нужны прежние артефакты R11/readback и файл токенизатора, SHA проверяется при запуске. Доступ к сети нужен при загрузке публичных выпусков и исходников, все панельные обращения к sqz выполняются локально.

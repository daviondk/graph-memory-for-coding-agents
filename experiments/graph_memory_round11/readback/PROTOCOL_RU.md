# Доставка повторных чтений при ограниченном контексте

Проверяем, сколько токенов займут повторные чтения кода, если агент может сослаться на несколько ещё доступных фрагментов того же файла. Принимаем только буквальные совпадения строк. Нулевая гипотеза — лучший единичный ранее показанный фрагмент даёт всю достижимую экономию. Контрпримером служит область, уже показанная агенту в нескольких раздельных чтениях. Выгода может исчезнуть, если сами ссылки выталкивают прежний буквальный текст из окна.

Фиксируем три существующих непересекающихся списка R8, до извлечения полных текстов текущего теста. Берём все успешно пронумерованные ответы editor.view на Python-файлы из прежней разрешённой панели, в хронологии. Работаем с канонической выдачей пронумерованных строк реального ответа, отдельно считаем другие события. Не воссоздаём невидимую середину усечённой выдачи. Идентификаторы событий исходной траектории не переиспользуем внутри одной задачи.

Сравнения: весь текст, ссылка при полном совпадении диапазона, одна лучшая база на файл, объединение доказанных совпадений из нескольких чтений. Все политики используют одно и то же окно в исходных событиях. Основной размер 8, дополнительные 4 и 16. Адрес ссылки указывает событие и начальную позицию с числом строк. Цель — токены действительного сериализованного ответа по одному фиксированному токенизатору Qwen, которым пользовались в R8. Граница окупаемости проверяется после сериализации каждого варианта. Считаем две семантики: (1) рантайм может разыменовать ранее декодированные ответы; (2) агент может ссылаться только на строки, **буквально предъявленные** в ещё видимом более раннем ответе. Вторая — основная. Список окончательных строк проверяет отдельный декодер. Записываем построчные адреса в формате операций и контрольные суммы, за ошибку восстановления начисляем полный объём сообщения и регистрируем её. Никакие записи будущей версии или следующего запроса в кодер не передаются.

Первичный эффект — разница токенов на всей выдаче между объединением и лучшей одиночной базой при окне 8 в строгой семантике, с парным bootstrap по траекториям, отдельно для каждой панели. Считаем также число улучшенных и ухудшенных задач и долю затронутых ответов. Пустые траектории входят в состав. Это измерение повторной передачи вывода, а не стоимости полного сеанса или вероятности решить задачу. Принцип дедупликации имеет прямые реализации, общий принцип не заявляется как новый.

# External corpus replication: when exact line dependency memory fits

Use all nine benign Python graph algorithms with *both* existing base and gold test traces in the R9 agentvalue dataset. This is an external benchmark to the 18 SymPy issues used for R10, but these QuixBugs snapshots were previously used elsewhere in the research programme. No new model sessions or program repair. Inclusion is determined only by existing trace availability, never by relative method scores. Use the entire test roster present in the old snapshot and assert identical names across paired snapshots.

Each old test writes the integer lines executed inside this single target Python file, deduplicated. The scope of a memory is one known program file, shared by every arm. The query comprises old-source line numbers affected by the update: collect the full pre-image of every non-equal difflib.SequenceMatcher opcode on source lines after trimming trailing space (autojunk=False). For a pure insertion, include both available old neighbors flanking the insertion; report the rate of insertions and bounds. For the reverse transition swap sources and repeat. Numeric IDs as decimal strings are used by all approximate dictionaries. Changing actual outcome means status before differs from status after for the identical native test. Full exact coverage can miss outcome changes; measure selection both against reference intersection and real outcome changes. Do not use status fields during state fitting. Query uses only the diff that a real invalidation service would receive, independent of test outcomes. Measure 32 salts × both directions. Report counts averaged over salts at each capacity and paired issue effects with task bootstrap. An algorithm is the unit, not a test or salt. With nine algorithms and few distinct changes any advantage is exploratory.

Replicate R10 primary cap 256 and secondary cap 64 bytes/test, plus 16 as a scale control; all seven R10 methods are frozen before scores. Include always-rerun and a cheap, fully encoded **exact line-to-test matrix**. Two simple exact layouts: dense from line 1 to maximum seen, storing n test bits per line, or a sorted delta-varint list of seen lines and full n-test masks (literal bytes). Pick the shorter actual serialization fitted on the old data. The header includes representation, n, salt; line numbers and any dictionary are paid. If neither fits report this and use a conservative all-tests mask for the equal-price arm. Record the actual minimum cost before padding. Since the exact line universe is dense on small programs, break-even bytes/test and zero false positives for unseen coordinates are more informative than sampling variance alone. Also implement a no-dependency always-rerun control.

Seal old-only states before sending diff queries. Lock both input revisions and full test traces by SHA-256. Publish original payloads, decoded test masks, source hashes, per-unit values, sign test and paired bootstrap if variation permits, two-cohort scope and CPU timing on all nine algorithms. No change in R9 or R10. The R10 supplementary Elias–Fano technique is a pre-existing comparison here.

# Воспроизведение и обновление свидетельств в графовой памяти

В этой серии изучали два противоположных случая. Успешное чтение оставляет буквальный фрагмент, который можно повторно показать модели по ссылке. Пустой поиск оставляет утверждение об отсутствии совпадения, которое может устареть при добавлении одной строки. Для обоих случаев проверяли доступность основания и фактическую цену перепроверки. Дополнительно перенесли результат о сжатии графа тестов на другой корпус.

**Перспектива для статьи.** Наиболее проверяемый механизм — запись явного основания для результата инструмента. При чтении это ранее показанный фрагмент с конкретным адресом. При пустом поиске это пара «область, предикат», для которой входящее изменение может породить первое совпадение. Две записи требуют разного решения при выдаче. В первом случае важно, присутствует ли источник в доступном контексте. Во втором — могло ли изменение опровергнуть записанное отсутствие. На практике преимущество нужно оценивать относительно простого частичного дедупликатора и выборочной проверки diff, включив стоимость получения самого diff. Наблюдавшихся естественных изменений пока три. До вывода о качестве работающего агента нужны новые репозитории и исполняемые конечные задачи. [MemUse](https://arxiv.org/abs/2611.01718) · [DreamBench-SWE](https://arxiv.org/abs/2608.20664) · [VibeMemBench](https://arxiv.org/abs/2609.23570)

Общие предки данных у `readback` и `native_dedup` намеренны, они образуют сопоставление на тех же запросах. Задачи, тестовые исходы, токены и адреса имеют разные знаменатели. [Состав и порядок воспроизведения](REPRODUCE_RU.md)

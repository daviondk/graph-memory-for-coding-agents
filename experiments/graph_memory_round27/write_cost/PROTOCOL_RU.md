# Когда материализовать индекс по памяти эпизода

Эпизод получает устойчивые идентификаторы и сырые байты уже показанных окон. Гипотеза: немедленная полная индексация проиграет полному перебору при одном последующем чтении, но выиграет при одиннадцати. Если частичное сохранение списков для слов уже поступавших запросов может дать иной компромисс при той же точности, измерим это явно. Идея строить организацию данных по нагрузке давно обсуждается в СУБД. Здесь предмет измерения — конечный эпизод агентной памяти и полный цикл от первой записи до последнего чтения. [Database Cracking](https://stratos.seas.harvard.edu/publications/database-cracking)

Фиксируем 96 историй ISETrace по хешу из 793 и все 48 статей SQuAD dev прежней когорты. Исходный снимок текста вносится одной транзакцией с настоящим COMMIT. Шесть вариантов: минимальный сырой журнал с подсчётом длин только при сканировании, сканирование с сохранёнными длинами, полный индекс при записи, полный индекс на первом поиске, индекс на третьем поиске с двумя предварительными сканированиями, сохранение только списков слов текущего запроса при первом появлении. Последний кэш сохраняет и пустые списки и только при неизвестном слове читает тексты заново. Для всех режимов общий адрес, длина слова в BM25 считается по прежней токенизации, идентичная стоимость записи текста и координат включена в таймер каждого метода. Полный поиск по всем сырым окнам проверен ранее независимым аудитом. Каждое решение сравниваем с ранее записанным точным индексом окна.

Основная величина — накопленное время от записи до первого реального запроса для ISETrace и до одиннадцатого для SQuAD. Для SQuAD дополнительно показываем префиксы 0, 1, 3 и 6, задержку только запроса и количество логических байтов сырых окон. Каждый эпизод — блок. Три раздельных воспроизведения полной рабочей нагрузки, порядок вариантов перемешан внутри блока, шесть независимых файлов SQLite на повтор. Используем WAL, synchronous=FULL, одинаковые схемы и выключенную автоматическую контрольную точку в измеряемом цикле. Принудительный checkpoint и физический размер основной базы посчитаем отдельно. Для накопленного времени внутри эпизода берем медиану по трём повторам, затем приводим медиану по эпизодам и доверительный интервал парного среднего по эпизодам (ресемплирование блоков). Независимых повторов по железу и накопителям нет. Неизменность снимка — условие эксперимента. Исходный выбор статьями и трассами известен. Общая скорость приложения, удержание данных в распределённой системе и время модели требуют отдельных проверок.

# Продолжение чтения исходного кода после первого просмотра файла

## Гипотеза и популяция

В успешных траекториях SWE-Explore проверяем, повышает ли выдача обоих соседних диапазонов долю полностью видимых строк следующего обращения к тому же файлу при одинаковом реальном расходе WordPiece. Перенос с прозы на код может отсутствовать: агент способен последовательно листать файл либо перейти к удалённой функции. Конкурирующее объяснение — пользу обеспечивает ближайшая синтаксическая единица. Сравнение условно на первом уже открытом файле и единственном дополнительном чтении.

До подсчёта метрик фиксируем открытый SWE-Explore bdb0ae45d7c337d9e1dc3ebfe2a0af6bc7c1fbd9 и SWE-bench Verified c104f840cc67f8b6eec6f759ebc8b2693d585d4a. Из второй таблицы используем только id, repo, base_commit и problem_statement. Основная подвыборка — все совпавшие verified задачи astropy/astropy, matplotlib/matplotlib, pydata/xarray, scikit-learn/scikit-learn, scipy/scipy, numpy/numpy и sympy/sympy. Только производственные Python-файлы. Полные пути, названия пакетов и задачи безопасности исключаем до извлечения исходников. Публичные файлы читаются как текст на base_commit. Скрипты репозиториев не запускаются.

## Единица наблюдения

Для каждой пары «траектория × файл» берем ровно два **первых** зарегистрированных шага чтения этого файла. Шаги между ними могут обращаться к другим файлам. Оба должны иметь однозначные явно ограниченные положительные 1-based включительные координаты. Идентичные дубликаты в одном шаге схлопываем. При нескольких разных диапазонах на одном из первых двух шагов пару исключаем. Не пропускаем неудобные ранние обращения ради последующей подходящей пары. Метаданные задают запрошенный диапазон, доступные строки сверяем с базовым снимком. Концы за EOF ограничиваем длиной файла; старты за EOF, интервалы с обратным порядком, нулевая разметка непустых WordPiece-строк у цели исключаются с учётом причин и долей. Исходная видимость включает каждый токен первого диапазона; никаких иных доступных агенту сообщений в реконструированном чтении нет. Для каждой задачи усредняем результаты её пар, затем одинаково взвешиваем задачи. Задачи/файлы с целиком повторенным вторым чтением остаются.

## Политики, цена и исходы

У всех политик один и тот же первый диапазон и 256 дополнительных WordPiece максимальной длины. Повторяем словарь BERT-base-uncased из исследования R25. Перед каждым непустым отрезком идёт служебный заголовок [0:offset] из настоящих токенов, где offset — позиция границы в WordPiece. Направленное чтение влево платит заголовок у правой границы. Реальный wire содержит ids заголовка и соседних исходных токенов; для нескольких диапазонов их ids конкатенируются. При недостижимой границе байты на пустой ответ не взимаются. Метод обеих сторон поровну резервирует бюджет 128/128, у самой границы файла свободный полубюджет полностью отходит достижимой стороне.

* Right и left читают ближайшие доступные WordPiece по одну сторону.
* Both читает ближайшие WordPiece с обеих сторон.
* Line-neighbors чередует ближайшую полную строку слева и справа, начиная слева, с общим бюджетом для пары заголовков; когда целая строка более не помещается, сначала пробует другую сторону, затем останавливается. Токены одной физической стороны объединяет под одним заголовком. У границы весь бюджет доступен другой стороне.
* Scope-neighbors берет по AST самую малую доступную функцию или класс, перекрывающие соответствующую граничную строку с каждой стороны, и добирает непоказанные соседние строки, только пока они остаются внутри этих границ. Ближайший вложенный scope предпочтительнее родителя. Если scope нет или он уже закончился на границе, эта сторона использует обычную границу файла. Учитываем полную однократную статическую обработку файла. Метод допускает меньше выданных токенов.
* Lexical-direction выбирает сторону по количеству различных термов описания задачи в 32 видимых WordPiece у каждой границы; при равенстве выбирает право, при физическом отсутствии предпочитаемой стороны — достижимую. Виды доступа не знают будущую строку, позицию или файл решения.

Первичный исход — средняя по задачам доля строк следующего чтения, чьи **все WordPiece** доступны после объединения первого и дополнительного чтений. Единственный первичный контраст — both минус right, одинаковый расход индивидуально. Для точной цены уменьшаем общий cap до меньшей фактической цены сравниваемых политик и пересчитываем обе выдачи до совпадения. При целых строках возможна дискретность, поэтому вторичные line/scope сравнения прежде всего даем при общем потолке 256 и с реально оплаченными токенами. Другие исходы — any/all, recall среди только новых строк (при ненулевом знаменателе), стоимость, число видимых и невидимых целей, распределения по репозиторию, траектории и геометрии. 95% парный percentile bootstrap с 10 000 ресэмплов задач (seed 27027), чувствительность по каждому репозиторию. Декларируем зависимость разных задач одного репозитория и ограниченную переносимость. Отдельно считаем изначальную видимость.

Gold второго чтения открывается только на этапе оценки. Выбор записи по типу метаданных допускается; следующий диапазон не передается алгоритму. Шаг наблюдаемого успешного агента не эквивалентен фактической необходимости строки для решения. Единица отличается от официального SWE-Explore «issue → ranking» и leaderboard. Изменения рабочих файлов в самой траектории и насыщение чтений stdout нельзя восстановить только из опубликованных границ.

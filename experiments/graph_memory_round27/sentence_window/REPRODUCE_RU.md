# Воспроизведение

Основная среда — Python исследований на диске D с tokenizers, NumPy и исходными программами R25/R26. Для нативной обработки использована отдельная установка llama-index-core==0.14.26 и NLTK 3.10.4 в D:/CodexResearch/x20-r27-sentences/core-env. Исходный файл парсера из колеса побайтно совпал с файлом проекта. Его SHA фиксирует native-receipt.json. Библиотека распространяется под MIT. [Снимок кода](https://github.com/run-llama/llama_index/tree/0d4f96876cfe7e325f3c1b72ec5f5f580f173bb5) · [лицензия](https://github.com/run-llama/llama_index/blob/0d4f96876cfe7e325f3c1b72ec5f5f580f173bb5/LICENSE)

В первом запуске NLTK получил пустой каталог ресурсов, а штатный загрузчик не смог получить индекс через прокси. Во втором NLTK отклонил жёсткие ссылки кеша uv. Оригинальные данные stopwords и punkt_tab из установленного колеса скопированы обычными файлами на диск D с проверкой равенства SHA каждой копии. Далее сам LlamaIndex успешно построил весь индекс. В исходной версии помощник создаёт PunktSentenceTokenizer() с пустым набором предобученных сокращений. Число сокращений и все нативные окна проверены.

```powershell
& D:/CodexResearch/x20-isetrace-e5-gpu/venv/Scripts/python.exe -B prepare_library.py
& D:/CodexResearch/x20-r27-sentences/core-env/Scripts/python.exe -B native_index.py
pwsh -NoProfile -File ./run.ps1
```

Индекс содержит координаты, контрольные суммы и метаданные. Каждый вызов дополнительного чтения записан как рецепт из адресных заголовков, символов-разделителей и ссылок на точные подстроки оригинальной статьи. Проверка восстанавливает настоящую строку и токенизирует её заново. Команды прогнозирования и оценки можно повторить по отдельности. Очередь пишет локальный журнал в D:/CodexResearch/x20-r27-sentences/queue.log. Источники ISETrace и весов GPU для этого опыта не нужны. [Официальный SQuAD](https://rajpurkar.github.io/SQuAD-explorer/)

Расчёт прогнозов, оценивание и независимое воспроизведение завершились прежде, чем в очереди появился генератор отчёта. Этот последний служебный этап завершён отдельным повторным вызовом report.py. Результаты и подписанные прогнозы предшествуют созданию отчёта.

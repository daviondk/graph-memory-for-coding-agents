# Сравнение с окном предложений LlamaIndex

Используем те же вопросы, статьи, выбранные компоненты видимой памяти и токенизатор, что в R26. Единица меры интервала — символ оригинальной статьи. Исходная память, запрос и выбранные координаты известны до дополнительного обращения к источнику. Основной показатель — доля вопросов, у которых после чтения исходная память вместе с новыми координатами полностью покрывает один из размеченных ответов SQuAD. Для каждого запроса онлайн-потолок дополнительного чтения составляет 256 WordPiece, включая буквально переданные адреса. Отдельная основная оценка симметрично выравнивает фактически оплаченные длины двух политик для каждого запроса. Обучение и выбор гиперпараметров отсутствуют.

**Окно ±3.** Для каждого полного документа заранее строится настоящий SentenceWindowNodeParser из llama-index-core 0.14.26 с исходным window_size=3 и разбиением Punkt. Нативная запись содержит исходное предложение, по три соседа с каждой стороны и буквальные дополнительные пробелы между строками. Из предложений, пересекающих выбранную компоненту, центральное выбирает BM25 по видимой части предложения и вопросу. Статистика по терминам вычисляется только на этих видимых подстроках. Ничья разрешается в пользу более раннего предложения. Окно возвращается слева направо с одним платным адресом и обрезается по онлайн-лимиту. Если компонента отсутствует, все методы возвращают пустую строку. Это условная замена действия после одинакового ранжирования. Открытую библиотеку используем для построения индекса, подсистема поиска по всем предложениям и генератор LlamaIndex в этот эксперимент не входят.

**Усиленное окно по границам.** От левого края той же компоненты берутся три ближайших предложения с новыми символами слева, от правого — три с новыми символами справа. Незавершённое граничное предложение входит в счёт при наличии новой части. Из каждой стороны удаляются все ранее видимые интервалы, включая другие компоненты. Сохраняется исходный порядок внутри каждого нового отрезка. Левую сторону читаем от ближайшего края назад, правую — вперёд. Литеральный адрес оплачивается отдельно для каждого непрерывного отрезка. Начальная квота делится поровну. Если одна сторона исчерпана, оставшиеся токены доступны другой. Эта политика использует сведения о видимых координатах дополнительно к опубликованному правилу.

**Двустороннее чтение R26.** Тот же код делит лимит 128+128 между двумя границами и видит дословное продолжение. Прогноз при 256 должен совпасть с каждым исходным прогнозом R26, включая точные координаты и заголовки.

Первичный контраст — R26 минус усиленное окно при одинаковой фактической цене. Для каждой пары начинаем с меньшей из двух онлайн-цен, пересобираем оба варианта при общем лимите, при расхождении уменьшаем лимит до меньшего факта и повторяем до точного равенства. Это условное сравнение использует две наблюдаемые длины. Отдельно приводятся исходные онлайн-результаты и аналогичная пара с одиночным окном. Дополнительные показатели — частичное покрытие, средний фактический расход, выигранные и проигранные пары, число запросов с пустым действием, уже известной частью или доступом к обеим сторонам. Неопределённость рассчитываем парным bootstrap по статьям, 20 000 повторов. Двусторонний тест смены знака на уровне статьи использует 100 000 случайных перестановок или точный перебор при малом числе ненулевых кластеров. Набор ранее использован для сравнений R26.

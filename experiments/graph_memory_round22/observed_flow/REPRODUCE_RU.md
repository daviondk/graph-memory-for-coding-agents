# Воспроизведение

Прогон выполнен на CPU в Windows, Python 3.12.13, NumPy 2.5.5. Пакет использует стандартную библиотеку, NumPy для статистики и curl.exe для скачивания открытых ссылок. Исходные PROV-JSON лежат в отдельном каталоге. Отчёт, локальные псевдонимы событий, оценки и предсказания не включают текст исходных команд, значения переменных или снимки окружений.

## Порядок запуска

Открыть PowerShell в каталоге этого исследования. Ни одна команда, строка программы или инструкция из трасс не исполняется. Процесс читает статические JSON, выполняет нормализацию и сравнивает множества. Переменная OBSERVED_FLOW_CACHE переопределяет каталог оригиналов и внутренних пакетов. При переносе в новую среду с иным путём называть переменную сессионно в PowerShell, например `$env:OBSERVED_FLOW_CACHE = 'D:/CodexResearch/x20-observed-r-flow'`.

```powershell
python -B sources.py
python -B build_packets.py
python -B predict_flow.py
python -B score_flow.py
python -B paired_times.py predict
python -B paired_times.py score
python -B binding_sensitivity.py predict
python -B binding_sensitivity.py score
python -B verify.py
```

Скрипт `verify.py` перепроверяет по исходным сущностям каждую из 1 804 размеченных связей и принадлежность к множеству кандидатов, 155 отзывов, обе метки каждой из 1 348 пар и итоговые контрольные суммы. До скачивания доверенного манифеста SHA-256 можно пересчитать `Get-FileHash MANIFEST_SHA256.json`. Опция `--seal` используется при подготовке новой версии пакета. При проверке чужой копии опцию не задают. Для побитового сопоставления нужны идентичные версии Python, NumPy и переводов строк кода. Журналы прогнозов в gzip пишутся с нулевым временем. Кластерный bootstrap использует 5 000 перевыборок, seed 2209. Семейства объединяют тестовые программы в двух инструментаторах по имени. Доверительные интервалы описывают чувствительность к составу этих семейств.

## Файлы и поля

| Файл | Содержание |
|---|---|
| protocol.json, followup-protocol.json | Основной протокол и отдельно обозначенный последующий анализ после просмотра основных результатов. |
| sources.py, source-lock.json | Пять версий репозиториев, фильтры путей, commit и Git blob по каждому исходнику, SHA-256, размер. Источник для загрузки — raw.githubusercontent.com, целостность подтверждается хешом по Git-формату. |
| inspect_source.py, build_packets.py, corpus-audit.json, input-lock.json | Схема PROV, состав выборки, причины исключений, проверки исходных файлов, скрытых эталонов и допустимых прогнозисту полей. |
| predict_flow.py, predictions.json.gz, prediction-lock.json | Предсказания до доступа к эталону. Для режима по тексту функция получает только действие и предыдущие выходы, без входных карточек. У финального отзыва дополнительно учитывается общее число производителей к концу трассы. |
| score_flow.py, outcomes.json.gz, results.json, evaluation-lock.json | Одиночные поисковые запросы, TP/FP/FN по каждому правилу, групповые метрики, парные разности с кластерным ДИ. |
| paired_times.py, followup-forecasts.json.gz, followup-forecast-lock.json, time-query-outcomes.json.gz, followup-results.json | Два последовательных наблюдённых чтения, их истинные производители в псевдонимах, парные оценки и полный набор отрицательных исходов. А также слой по типу операции в исходном неусловном тесте. |
| binding_sensitivity.py, binding-forecasts.json.gz, binding-forecast-lock.json, binding-results.json | Дополнительные контрольные правила из ранее зафиксированных прогнозов, сравнение одного именного бита и обновления на каждом чтении, leave-one-family-out для pplant. |
| verify.py, audit.json, MANIFEST_SHA256.json | Независимая повторная стыковка исходных рёбер, проверка индивидуальных чтений и параллельных по смыслу вопросов, финальные SHA-256. |

В `predictions` ключ `trace` — локальное имя трассы. `cards` — условный режим, одна запись на версию, прочитанную действием. `text` — прогноз на каждое наблюдаемое действие, множество прошлых производителей с дедупликацией. В `outcomes` исходы каждого метода имеют порядок TP, FP, FN. В `time-query-outcomes` `truth` — две булевы метки для одного заранее выбранного кандидата. Сами исходные прикладные значения не нужны для просмотра результатов. Идентификаторы псевдонимизированы ради компактности и минимизации копирования исходных данных, они не обеспечивают криптографическую анонимность опубликованных трасс.

## Где граница эксперимента

- Неоднозначные, отсутствующие или последующие производители конкретной версии исключаются при построении эталона. Отдельны случаи, где одна версия известна инструментатору, но несколько действий выдали тот же скаляр. Именно они участвуют в оценке.
- Поиск по тексту — простой лексический анализ. Пропускаются комментарии и распознаваемые левые части присваиваний, есть поддержка элементарных обращений к полям. Интерпретация языка, алиасы динамических областей и сложные структуры не покрыты. Запрошенная точность разборщика R отдельно не измерялась.
- Действия с пустым набором подходящих скалярных зависимостей остаются в тесте для учёта ложных рёбер. Истинные связи через структуры, функции или файлы выходят за пределы скалярного эталона. Если они совпали с предсказанием, оценка всё равно считает его ложным относительно выбранной конечной точки.
- Первичный набор кандидатов по прочитанному значению условен по наблюдаемому чтению. Все первичные эвристики, кроме ретроспективного отзыва, видят предыдущих производителей. В парном анализе правила позднего бита считаются ретроспективными, когда ими отвечают на исторический вопрос.
- Чтобы выбрать следующее чтение, из нескольких карточек с одинаковыми значением и шагом брали одну по псевдониму карточки. Исключилось 146 повторов внутри шага, ещё 310 последних значений не имели следующего чтения. Возможен эффект исходного порядка при совпадающем времени.
- Модель байтов, аппаратный выигрыш или обучение LLM здесь не исследовались. Изначальные признаки доступны для пересчёта из журнала. Сохранение двух булевых полей — способ кодировать семантику запросов, физическая цена зависит от формата, индекса и удержания журнала.

# Один запрос агента к журналу производителей

Проверяем, сможет ли модель выбрать одно предыдущее событие для инспекции скалярного входа текущей операции. Источник — те же пассивные инструментированные трассы R/Python; фактически использованные версии открываются только при оценке. Это контролируемый тест выбора следующего чтения по наблюдаемому журналу. При подготовке входов используются только events из пакета observed_flow. Элементы cards и таблица used исключены из прогнозирующего кода.

До вскрытия эталона отбираем до четырёх операций по независимому хешу в каждой семье программ. Для допуска достаточно видеть хотя бы одно имя или литерал в тексте текущей операции, иметь не меньше четырёх предшествующих производителей скалярных выходов и хотя бы одно совпадение имён или значений с прошлым выходом. У операции могут оказаться другие фактические зависимости или ни одной размеченной скалярной зависимости. Честная основная популяция для точности — выбранные операции с зарегистрированным положительным исходом. Число остальных операций и покрытие эксперимента сообщаются отдельно.

При запросе выдаются четыре карточки, каждое поле фиксированной ширины: расстояние по номеру операции, число совпавших имён, число совпавших значений, признак последнего писателя для хотя бы одного совпавшего имени. Одна выдача — четыре последних производителя. Вторая отдаёт первые четыре по правилу «последняя запись совпавшего имени, число совпавших имён, число совпавших значений, близость по времени» в указанном порядке. Внутренний порядок обоих пакетов перемешан детерминированно, до показа решателю. Ограничение относится к чтению четырёх карточек. Обе политики имеют один и тот же архив всех предшествующих выходов.

Замороженный Qwen3-4B-Instruct-2507 Q4_K_M на CPU выбирает одну букву. Для обоих вариантов также оцениваем сильное детерминированное правило по тем же признакам, доступность правильного источника в пакете, случайную вероятность при равномерном выборе. Выбор засчитывается, если номер открытого события совпадает с хотя бы одной фактически использованной и зарегистрированной версией. Основной контраст — точность одного действия Qwen с индексом имён минус FIFO, двухсторонний 95% описательный парный bootstrap по семействам. При небольшом числе семейств обязательны также сырые wins/losses. Порядок карточек — помеха, его чувствительность проверяем повтором с обратным порядком. В основном исходе считаем одну исходную перестановку; повторы не увеличивают n. Все поданные сообщения и решения регистрируются под обезличенными идентификаторами. Сравнение применяется к нормализованному интерфейсу журнала, а не к успеху исправления кода.

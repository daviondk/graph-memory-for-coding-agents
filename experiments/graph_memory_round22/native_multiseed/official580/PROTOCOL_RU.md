# Проверка графовой памяти с официальной валидационной выборкой ISETrace

Проверка исполняемой конфигурации Hydra и [инструкции авторов](https://github.com/xiaoqi-7/GraphMemory/blob/df29287116fa1565b3fd6b485022cd6090dc0b27/docs/40-operations/paper-reproduction.md) выявила различие с локальной серией R19–R22. После разрешения параметров набор ISETrace использует все 580 dev-запросов на 352 траекториях. Локальное обучение графовых контролей выбирало эпоху на первых 500 запросах, охватывающих 331 траекторию. Все 3894 train и все 2000 test, включая порядок и идентичность траекторий, совпали. Пятьсот вопросов для ручного аудита в публикации принадлежат тестовой выборке. [Статья, раздел 3.4](https://arxiv.org/html/2609.25913v3#S3.SS4)

Первичный исход — полный охват эталонных диапазонов строгим префиксом при 2048 токенах. Два заранее зафиксированных сравнения — R21 factor с полной R-GCN и с отдельно переобученной сетью wo_chunk_adjacency, для одного и того же выбранного Dense-FT в пределах seed. Сохраняются восемь метрик и исходы по вопросам. По каждому seed даётся собственная разность, описательные значения усредняются по пяти seed, выборочная вариация показывается SD, условный 95% интервал разности считается бутстрепом по 1207 траекториям после внутривопросного усреднения seed. Для заявления о превосходстве над двумя сетями нужны положительные нижние границы обоих заранее указанных сравнений. Ранее наблюдавшиеся значения dev500 не участвуют в подборе вариантов.

Нативная выборка обучающих пар, разбиение, конфигурация оптимизатора, случайные инициализации и тестовый бюджет сохраняются. Для каждого конкретного seed используем checkpoint E5, выбранный на 580 запросах. R21 повторно сравнивает epoch 0 и 1. Порог выбора лучшей графовой эпохи воспроизводится штатным dev Recall@5, включая epoch 0 и все 15 обученных эпох. Старый dev500-победитель не может представлять остальные эпохи, поэтому точный контроль переобучает обе графовые модели. Изменение выбора Dense требует соответствующих новых FT-векторов и оценки обеих сравниваемых политик на выбранных весах. Каждая попытка получает отдельный каталог; тестовые ответы читаются только после записи полного порядка.

Составлена отдельная официальная очередь. Обновления в ней не изменяют результатов или процессов dev500. Общий GPU используется строго последовательно. Кеши корпусных векторов проверяются по SHA выбранных весов; два графовых варианта внутри seed пользуются одними парами. На новом полном dev наборе 43450 уникальных входных строк, из которых 3645 отсутствовали в корпусе 466074 строк прошлого эксперимента. Тензоры dev580 занимают 342998016 байт. Получены 352 независимых графа из исходных траекторий и точные положительные кандидаты по всем 580 вопросам.

# Замороженное мелкоблочное чтение после R-GCN без content.next

Гипотеза. Модель, обученная на исходных train-траекториях предсказывать пересечение короткого блока с эталонным интервалом, может сохранить больший объём источника после сильного ранжирования R-GCN без рёбер соседних PU. Опыт на обычном R-GCN и исходном Dense сформировал эту гипотезу. Test-набор тот же, поэтому опыт проверяет перенос между ранжировщиками, а не независимое обобщение на новые вопросы.

Общий массив составляет 2 000 вопросов и 1 207 траекторий тестового ISETrace. Оба правила получают одинаковые PU, ранжированные R-GCN без content.next после повторного обучения на всех 3 894 train с seed 13 и выбором модели на локальных 500 dev. Пара фиксируется до готовности восьми ранговых шардов этой модели. Зафиксированы SHA доступного алгоритма обучения, набора пар, полного split, исходной модели чтения и исходного механизма формирования коротких блоков.

Контроль `skip` последовательно перебирает целые PU в порядке ранга, добавляя каждую помещающуюся запись. Метод `ratio` сохраняет первые две PU, ранжирует собственные короткие интервалы по p/c (обученная вероятность пересечения с разметкой, делённая на длину в токенах), берёт только помещающиеся интервалы, не перекрывающиеся с уже выбранными. Используем окончательные веса R20 fine_train без переоценки. После объединения исходных цитат переводом строки повторно токенизируем итог и обрезаем по offsets авторского токенизатора до физического ограничения 2 048 токенов, затем оцениваем только действительно предъявленные символьные интервалы.

Первичный показатель — разность среднего Full Support@2048 по всем вопросам между ratio и skip. Вторичные — доля покрытых эталонных символов, плотность, F1, число переходов 0→1 и 1→0, фактическое число прочитанных токенов, число и последствия обрезаний. Используем тот же парный кластерный bootstrap (10 000 повторов, seed 13), кластер — исходная траектория. Для отчёта пригодны только полностью запечатанные 2 000 пар. Нативный скаляр до рендеринга сверяется с независимым интервальным расчётом. Код строит две политики и открывает эталон test для оценки после сохранения прогнозов. Данные и процедуры исходного R20 идентичны подписям в плане.

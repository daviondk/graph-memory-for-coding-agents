# Доставка плотного ранга из SQLite

После завершённого опыта с массивами известно, что однокурсорный порог вычисляет меньше баллов и медленнее NumPy в памяти. Для отдельного измерения фиксируем тот же корпус, набор весов, бюджеты и исходные порядки. Задача — измерить реальное изменение числа строк, переданных из SQLite приложению, и полное время локальной операции от SQL-запроса до готового списка ссылок.

**Четыре способа чтения.** Основной базовый вариант выгружает из таблицы Dense весь упорядоченный список integer ID и применяет полную стабильную сортировку NumPy с закешированными статическими priors. Основной альтернативный вариант начинает тот же SELECT и потребляет страницы по 16 строк, пока строгий префикс можно доказать по остаточной верхней границе. При доборе используется прежняя логика переменной стоимости. Третий контроль — полностью SQL JOIN метаданных, сортировка по сумме g+prior и по исходному рангу при равенстве. Четвёртый — заранее записанный полный итоговый ранг для каждого вопроса. Для него измеряем размер отдельной таблицы и время построения. Хранилище находится на диске D. Измерение использует один процесс, SQLite в режиме query_only и прогретые кэши. Стоимость формирования исходного Dense-ранга и графового prior общая. Для первых двух вариантов числовой prior доступен в памяти на всю историю. Затраты на его чтение всей историей измеряются отдельно.

**Оценка.** Каждый из четырёх способов должен вернуть исходный список PU в том же порядке на всех 2 000 вопросах по обеим политикам. Неудачи при сверке не исключаются. Основной контраст времени — постраничный вариант против полного чтения с NumPy для строгого префикса. Интервал отношения медиан по 256 тем же хеш-выбранным вопросам и 240 траекториям с семью парными перемешанными повторениями. При измерении считаем реально извлечённые fetchmany/fetchall строки. Внутренняя сортировка SQLite может просмотреть больше дисковых строк, чем вернула SQL-клиенту. Для всех четырёх SQL-запросов публикуем EXPLAIN QUERY PLAN, размер БД и отдельный размер материализации, версию sqlite и параметры страницы. Цель — измерить локальную границу «SQLite → приложение», без экстраполяции на сетевой сервер, холодный диск или ANN.

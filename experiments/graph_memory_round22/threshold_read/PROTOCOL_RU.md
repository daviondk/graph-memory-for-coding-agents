# Точное чтение из сортированных индексов при фиксированном бюджете

Есть один уже зафиксированный читатель factor_reader/hash64. Итоговый балл PU равен сумме g(r), зависящего только от исходного семантического ранга, и структурного prior p(u), общего для всех будущих вопросов к этой траектории. Полный базовый алгоритм собирает N сумм и стабильно сортирует все PU. Спрашиваем, сколько сумм можно не вычислять при гарантированно одинаковом упорядоченном результате. Предварительные результаты качества и размеры теста уже известны, измерения новых операторов до записи этого плана не выполнялись.

**Условия.** Весь официальный test ISETrace, 2 000 вопросов и 1 207 траекторий. Основная операция выдаёт строгий префикс при 2 048 токенах. Дополнительная операция пропускает непомещающийся PU и продолжает. Одни кандидаты, абсолютные баллы и веса. Любая несовпадающая позиция либо различие стоимости считаются ошибкой. Сверяем каждый порядок с заранее зафиксированными рангами R20, дополнительно проверяем пустой вывод, точное равенство баллов, равенство бюджету, немонотонный g, длинные узлы в начале и отсутствие помещающихся остатков.

**Реализации.** (1) Полная векторизованная стабильная сортировка NumPy. (2) Полное векторизованное вычисление баллов и heapify с извлечением победителей. (3) Один последовательный курсор Dense и статический индекс на убывание prior; указатель второго индекса отслеживает наибольший prior среди пока не оценённых узлов. (4) Два курсора, полный индекс обратного семантического ранга для случайного доступа и общий порог верхней границы; обратный индекс строится при каждом запросе и оплачивается в тайминге. При немонотонном g используем максимум по его оставшемуся суффиксу. Первичным считаем однокурсорный вариант против полной стабильной сортировки. Двухкурсорный вариант и heapify — вторичные контроли.

**Метрики.** Число вычисленных полных баллов, доля просмотренных строк Dense, отсортированных записей prior, индексных случайных обращений и принятых узлов. Дополнительно — число обращений по стоимости, оценки минимальной стоимости в skip, байты дополнительных индексов и время их подготовки. Эти величины включают логические чтения в колонковых массивах и не измеряют физические I/O. Dense-ранг предоставлен всем четырём вариантам. Однокурсорный вариант совместим с уже ранжированным потоковым итератором и заранее известным размером множества кандидатов; в этом исследовании источник Dense материализован заранее. Экономия построения ANN или нейросетевого ранжирования отдельно не предполагается.

Для времени выбираем заранее первые 256 вопросов по SHA-256('threshold-timing|'+q), без меток. Семь повторений, перемешанный порядок в блоке «вопрос × повторение», одна разминка каждого оператора. Сообщаем медиану времени на уже доступных рангах, p95, и отношение медиан с 95% парным кластерным bootstrap по траекториям. Счётчики событий учитываются во всех реализациях. Дополнительно нулевой таймер и стоимость обратного индекса. Проверка качества использует все вопросы; в таймингах отсутствует построение изначального графа и загрузка текстов. Отдельно измеряем построение статических таблиц приоритета и стоимости. Индекс приоритета обновляется при изменении структурных оценок, поэтому его нельзя считать бесплатным для интенсивно обновляемого хранилища.

Идея threshold access и различение sorted/random access восходят к Fagin, Lotem и Naor. Здесь исследуем адаптацию для составного префикса с переменной стоимостью, исторических графовых признаков и воспроизводимого списка ссылок на свидетельства.

# Проверка префиксов, выбора действия и содержимого демонстратора

Внутренний рабочий аудит после фиксации прогнозов. Для проверки использованы опубликованные определения, код исследования, журналы каждого вопроса и независимый вычислитель. Политики и ответы модели сохранены в исходном виде. Повторная генерация LLM не требовалась. [Код проверок](audit_readers.py) · [Машиночитаемые итоги](audit-readers.json)

## Момент запроса и доступность эталона в ISETrace

**Другие типы рёбер.** У видимых аргументов и результатов соседство фрагментов задаётся границами одного события. Ребро возврата зависит от конкретных вызова и результата. Для `resource.flow` официальный код выбирает последнюю запись данного артефакта среди вызовов строго раньше читателя. Достраивание будущего не может поменять этот максимум. На проверяемых срезах все начатые группы вызовов уже завершились, поэтому доступны и оба результата. Ребро `data.feeds` чувствительно к будущему совпадению значений. Именно его текущая политика перестраивает по уже просмотренным событиям. На 191 различных префиксах 48 заранее выбранных историй исходный контроль подтвердил ровно те же пары у всех четырёх типов. Это заключение ограничено срезами после замкнутых групп и конкретной версией построителя. [Официальный построитель](https://raw.githubusercontent.com/xiaoqi-7/GraphMemory/df29287116fa1565b3fd6b485022cd6090dc0b27/graph_memory/graphs/provenance/builder.py) · [Проекция зависимостей](https://raw.githubusercontent.com/xiaoqi-7/GraphMemory/df29287116fa1565b3fd6b485022cd6090dc0b27/graph_memory/graphs/provenance/dependencies.py) · [Код префиксов](prefix_read/forecast.py)

**Бюджет.** Первичная метка доступности проверяет объединение координат всех уже видимых кандидатов. Независимо нашли минимальную суммарную цену произвольного набора, который действительно покрывает все эталонные символы. Для каждой пары «событие, JSON Pointer» интервалы эталона объединяли, проектировали на них интервалы фрагментов и динамическим программированием находили минимальную стоимость непрерывного покрытия. У каждого кандидата в корпусе ровно одна пара координат, поэтому цены по источникам складываются. Алгоритм совпал с полным перебором на 189 малых конфигурациях. Во всех 8 000 строках теста индикаторы видимости и достижимости при бюджете 2 048 совпали. В середине истории все 901 доступный вопрос основной панели имеют допустимое решение. Его минимальная цена в медиане 493, максимум 1 545 токенов. Это проверка достижимости со знанием разметки, она не меняет выбора ранжировщиков. [Итоги по срезам](audit-readers.json) · [Основной отчёт](prefix_read/REPORT_RU.md)

**Что считается повторением.** Четыре среза каждого из 2 000 вопросов дают 8 000 измерений. В основной панели 901 вопрос и 657 траекторий. Bootstrap проводится по траекториям. Пересечение 2 000 тестовых вопросов с train/dev равно нулю по идентификаторам вопросов, траекторий, штатному `task_key` и тексту вопроса после приведения регистра и пробельных символов. Семантически близкие шаблоны могут встречаться в разных траекториях. Тестовые задачи уже встречались в предыдущих раундах проекта. Процент выполнения известен только по завершённой истории, и сами вопросы составлены ретроспективно. Поэтому результаты характеризуют чтение на заданном срезе. Эффективность выбора момента обращения к памяти во время работы здесь остаётся открытой. [Официальная постановка](https://arxiv.org/abs/2609.25913) · [Зафиксированная оценка](prefix_read/score.py)

## Одно действие в архиве программных операций

До получения ответов взяли максимум четыре примера из каждой из 21 семьи, всего 77 из 1 493 удовлетворяющих критериям операций. Для каждого решения все четыре предлагаемых производителя действительно предшествуют текущей операции. Повтор построения из одних `events`, ID трассы и семейства дал те же 77 случаев и 238 различных промптов. Возможный источник утечки в преобразователе — отбор скалярных сущностей с единственным зарегистрированным генератором по всей трассе. Проверка оригиналов нашла 871 сущность с одним генератором, четыре без генератора и ни одной с несколькими. Фильтр не скрыл ни одного текущего кандидата из-за будущей повторной записи в ту же сущность. У двух политик идентичны четыре кандидата в 34/77 случаях. Дублирование промптов между семействами отсутствует. [Отбор](action_reader/prepare.py) · [Повтор без полей входов и эталона](action_reader/blind-audit.json)

Сверены все 308 обращений к независимой копии SQLite. По выбранной букве восстановлены производитель, результат чтения, SHA-256 и совпадение с инструментированной версией. В обычном порядке каждый вызов модели расходовал 187 входных токенов. Среди 45 операций с размеченным скалярным источником Qwen выбрал подходящую запись в 41 случае с индексом по имени и в 36 с FIFO, при обратной перестановке — в 39 и 36. Индекс помещал подходящий источник в список 45 раз, FIFO — 37. Правило последней записи на том же индексном списке дало 40/45. Модель выбирает одну обезличенную карточку, исполнитель открывает одну строку архива. После возврата данных модель не принимает второго решения. Инструментатор при построении эталона также использует имена в выражении, что согласует задачу с именным индексом. [Журнал оценки](action_reader/results.json) · [Исполнение запроса](action_reader/score.py) · [Метод инструментирования](https://journal.r-project.org/articles/RJ-2023-003/)

**Статистическая чувствительность.** На 45 положительных случаях получены шесть выигрышей, один проигрыш и 38 ничьих. Среди 18 семейств только четыре имеют ненулевой суммарный перевес, равный +1, +1, +1 и +2. Для разности +11,11 п.п. процентильный bootstrap даёт [2,27; 21,57]. При дополнительной проверке перестановкой знака разности целиком по семейству двустороннее p = 0,125, при предположении симметрии знаков под нулевой гипотезой. Порядок интервенций в эксперименте детерминированный. Наблюдаемая разница по большей части объяснима лучшей доступностью кандидата. При 32 из 77 выбранных операций эталонного скалярного источника нет и правильный принудительный выбор невозможен. [Все группы и перестановки](action_reader/results.json) · [Независимая сверка](audit-readers.json)

## Данные в демонстраторе

В SQLite проверены уникальные значения каждой текстовой колонки, в автономном HTML — все элементы каждого из 96 встроенных журналов. Разрешённые строки представляют 96 непрозрачных идентификаторов историй, три вида событий и два кода `match` и `ambiguous`. Псевдонимы значений и производителей записаны числами. Сырые пути, команды, аргументы, ответы инструментов и имена переменных в проверенных записях отсутствуют. Связь с открытым корпусом всё ещё возможна по идентификатору истории. Интерактивная сцена показывает отзыв гипотезы при появлении второго производителя.

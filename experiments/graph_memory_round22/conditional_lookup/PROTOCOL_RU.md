# Можно ли по уже доставленному утверждению восстановить вторую сторону конфликта

Проверка переноса на отдельный корпус ContraDoc, который цитируют Zhang и соавторы. Берём все положительные документы из публичной версии d1c42d1e433595dd6e98fab7b669722cdc050b1d. У координатора заранее есть введённое противоречащее утверждение целиком. Он выбирает две полные записи из остальной части того же документа. Это условная задача второго чтения. Она допускает проверку только случаев, в которых исходная разметка называет вторую сторону. В официальной задаче модель самостоятельно обнаруживает и объясняет конфликт.

Один и тот же вход используется для всех методов. Нормализуем пробелы и Unicode, удаляем ровно переданную цитату, когда она встретилась в тексте ровно один раз. Делим оставшийся текст на предложения детерминированным правилом по конечной пунктуации. Сохраняем адрес каждой записи в документе. Алгоритму поиска доступны цитата, номер позиции и тексты других записей. Поля с указанием подтверждений, вида конфликта и области действия из поиска исключены. Контроль с известной позицией может искать соседей.

Основные методы — полнотекстовый BM25 по предложениям (k1=1,2, b=0,75), косинус E5-base-v2 и сумма обратных рангов BM25 и E5 с константой 60. Четвёртый контроль включает близость к позиции исходной цитаты как третий равноправный список. Первичная гипотеза — если сохранить первый выбор гибридного поиска и зарезервировать второй адрес под похожее утверждение с противоположным отрицанием или отличающимися числами, увеличится вероятность доставить размеченный источник. Рассматриваются только следующие четыре кандидата гибридного списка. При отсутствии такого кандидата возвращается обычный второй адрес. Один контроль резервирует тот же слот случайным детерминированным кандидатом из четырёх, другой всегда открывает ближайшего соседа в документе. Оба получают те же сведения о первом фрагменте. Дубликаты адресов исключены во всех выдачах.

Основной исход — наличие хотя бы одной целой референсной цитаты в одной из первых двух реально возвращённых записей. Адреса фиксируем до чтения референсных цитат. В основной знаменатель включаем каждую строку с однозначным первым утверждением и хотя бы одной референсной цитатой, которая умещается в одну запись отдельно от переданного текста. Также сообщаем количество строк до этого ограничения и долю по всем положительным документам с разметкой источника, считая непокрываемые случаи пропусками. Полноту фильтра и дубли аудитируем отдельно. Ценой запроса считаем количество записей и объём текста UTF-8. В основном опыте бюджет одинаков по числу чтений; равенство байтов не предполагается. Вторичные метрики — Hit@1, Hit@4 для исходных ранжировщиков и разбиение на локальные и глобальные случаи. Интервал парной разности — bootstrap по исходным семействам документов (общая часть ID до последнего суффикса), 10 000 повторов, seed 2219. Характеристика — перенос механизма, без подбора параметров по результатам, отдельный языковой решатель не используется.

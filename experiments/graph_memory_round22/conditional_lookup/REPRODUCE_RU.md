# Воспроизведение

Данные хранятся отдельно от кода и зафиксированных выдач. Понадобится [ContraDoc.json из указанной ревизии](https://github.com/ddhruvkr/CONTRADOC/blob/d1c42d1e433595dd6e98fab7b669722cdc050b1d/ContraDoc.json). SHA-256 файла проверяет prepare.py. Сохраните его в папку из переменной CONTRADOC_CACHE. Пакет E5-base-v2 указывается переменной CONTRADOC_E5, скрипт сверяет контрольную сумму весов.

```powershell
python -B prepare.py
python -B -u predict.py
python -B score.py
```

Для первого шага достаточно стандартной библиотеки Python. На втором шаге используются NumPy, PyTorch и Transformers с локальным E5 на CPU, усреднением по непустым токенам и L2-нормировкой. В рабочей директории данных сохраняется кэш по полному тексту входа, версии весов и способу нормировки. В прогнозирующем процессе открыт только файл подготовленных пакетов. Каждая сторона сравнения использует одни и те же рассчитанные векторы и границы записей.

Для переоценки готовых рангов достаточно шагов 1 и 3. Новые ответы моделей не требуются. score.py проверяет контрольную сумму рангов до доступа к референсным предложениям. SQLite возвращает текст по паре document/relative-address. В outcomes.json.gz хранятся номера записей, хеши возвращённых текстов и наблюдаемые исходы. Разбиение положительного документа на фрагменты и условие получения первого свидетельства описаны в [протоколе](PROTOCOL_RU.md).

Дополнительные измерения воспроизводятся командами `python -B audit.py`, `python -B family_sensitivity.py` и `python -B budget.py` из этой папки. runtime.json фиксирует версии библиотек и SHA-256 файлов токенизатора, конфигурации и весов E5. При первом подсчёте групп scope исходный JSON содержал строковые и списковые обозначения. Оценщик приводит список к строковому представлению, затем рассчитывает вторичные разрезы.

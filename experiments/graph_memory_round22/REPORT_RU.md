# Как различать фактический источник данных и текущую уверенность агента

Когда агент видит одинаковое значение в нескольких выводах, меняется сила текстового обоснования. У уже совершившегося чтения остаётся конкретный производитель данных. Эти два свойства можно проверить разными эталонами.

**На ISETrace** эталон реконструкции — официальный построитель графа на завершившихся к моменту запроса событиях. На середине истории для 901 вопроса уже были видимы все размеченные фрагменты. Читатель с точным текущим графом полностью восстановил свидетельства в **732/901** случаях, с добавлением связей без отзыва — в **719/901** (+1,44 п.п., 95% ДИ [0,22; 2,66]), с одним Dense — в 682/901. Фильтрация терминального графа дала **737/901**. Дополнительные пять успехов последнего варианта опираются на информацию о последующих событиях; на уровне отдельных вопросов было семь выигрышей и две потери. Этот контроль показывает размер смещения от доступа к будущему в экспериментальном replay. [Полный отчёт и четыре среза](prefix_read/REPORT_RU.md)

**В инструментированных запусках R/Python** эталон использует идентификатор версии объекта и операцию, которая его произвела. При доступном значении, которое реально читала операция, правило уникальности в момент чтения восстановило исторического производителя для **659/1 804** чтений скаляра. Если отзывать такие связи после поздней коллизии значений, остаётся **504/1 804**, разность −8,59 п.п. [−17,60; −4,78]. Передача уже прочитанного значения — сильное условие эксперимента. Отдельно проверяется случай, когда алгоритм видит только текст операции и раньше наблюдавшиеся выходы. В крупнейшем семействе pplant сосредоточено 834 чтения, включая 832 из одного исполнения. Регистратор части R-трасс определяет зависимости разбором выражений и сохраняет значения во время выполнения. Поэтому именной контроль частично согласован с процедурой разметки. Эти данные проверяют происхождение на уровне языка и конкретного регистратора. [Описание сбора данных, раздел 5](https://journal.r-project.org/articles/RJ-2023-003/) [Источники, постановка и сравнения](observed_flow/REPORT_RU.md) · [Инструментирование RDataTracker](https://github.com/End-to-end-provenance/RDataTracker)

**Следствие для проектирования.** Запись вида «в момент чтения A было единственным наблюдаемым источником» остаётся частью истории. Отдельное представление показывает, сохраняется ли уникальность после новых событий. Если среда предоставляет фактический идентификатор версии прочитанного объекта, его следует хранить вместе с отношением использования. Это даёт проверяемую архитектуру. Выигрыш по точности на любом приложении из неё автоматически не следует. [Предыдущая серия и интерактивный демонстратор](../graph_memory_round21/REPORT_RU.md)

## Сколько нужно физически прочитать из базы

Для уже обученного читателя сумма балла семантического ранга и постоянной графовой поправки допускает точную остановку до просмотра всех узлов. На 2 000 вопросах такой алгоритм по одному отсортированному списку вычислил 67 091 из 249 089 баллов при выборе префикса. При реальной постраничной выдаче SQLite приложению передано 81 505 строк вместо 249 089, сокращение на 67,3%. Медиана задержки для прогретой базы осталась около 55 мкс в обоих вариантах. Предварительно материализованный порядок дал 22,9 мкс ценой дополнительных 4 042 752 байт. Для чтения с пропусками потоковый вариант был медленнее полного. В этом опыте физическая экономия относится к числу строк между БД и приложением. [Точные операторы и контроли](threshold_read/REPORT_RU.md)

В отдельной проверке двух последовательных чтений одного значения раздельное хранение признака уникальности для двух моментов дало 909/1 348 полностью правильных пар ответов, копирование одного раннего или позднего признака — 832/1 348. Однако обычное сопоставление последнего писателя по имени из текста операции дало **1 013/1 348**. Именной контроль использует признаки, близкие к тому, как сам регистратор строит часть зависимостей. Вывод относится к доступному языковому интерфейсу и показывает, что одной работы с двумя моментами недостаточно для конкурентной точности. [Условные сравнения и анализ семейств](observed_flow/REPORT_RU.md)

## Какую версию источника откроет модель

При одном чтении SQLite и одинаковом числе показанных карточек локальный Qwen3-4B открыл правильного производителя для **41/45** операций при именном подборе и для **36/45** при выдаче последних по времени. Парная разность +11,11 п.п. [2,27; 21,57] по 18 семействам. На именной выдаче простое правило открыло верный источник в 40/45. При обратном порядке карточек модель получила 39 против 36, интервал разности включает ноль. Проверяется одно действие по отношению к размеченному источнику. [Методы, контроли и все прогоны](action_reader/REPORT_RU.md)

В дополнительном контроле на одном языке реализации C++17 и одном SQLite C API точное досрочное завершение запроса для префикса дало медиану 17,25 мкс, полный просмотр с сортировкой 20,80 мкс, отношение задержек 0,829 [0,80; 0,85]. Материализованная выдача оставалась быстрее, 15,8 мкс, с дополнительным построением и хранением. Это задержка оператора чтения с прогретой базой, после получения оценок от энкодера. [Измерения](threshold_read/native-results.json)

В дополнительном точном тесте смены знака только четыре семейства дали ненулевую суммарную разность между именной выдачей и FIFO. Двустороннее p = 0,125. Значимость эффекта выбора действия чувствительна к методу вывода на этой малой выборке. [Независимый аудит и проверка физического бюджета](AUDIT_RU.md)

Отзыв зарегистрированных утверждений и выдача альтернатив по одному известному конфликту уже реализованы в StateFuse. CodeNib проверяет обновлённые индексы репозитория независимой пересборкой. Эта работа сужает вопрос о новизне до учёта отдельных оснований связи и способности вернуть полные источники по измеримой цене. ## Восстановление пары после передачи первого утверждения

На отдельном корпусе ContraDoc проверили, что координатор может извлечь, уже получив одну сторону противоречия. Из 377 документов с референсным предложением в 271 оно целиком помещалось в одну отдельную запись. При двух чтениях BM25 + E5 вернул второе свидетельство в **180/271** случаях. Резервирование одного из двух адресов под запись с другим числом или отрицанием дало **178/271**, 0 выигрышей и 2 потери. Резервирование под ближайшую к известной цитате запись дало **185/271**, интервал разности с гибридом [−2,36; 6,37] п.п. При общем лимите передачи 256 байт гибрид дал 159 попаданий, сосед 158. Изменившийся поверхностный признак оказался слабым основанием для выдачи. [Сравнение с базовыми ранжировщиками, размеры записей и все исходы](conditional_lookup/REPORT_RU.md)

## Условие сравнения с опубликованным результатом ISETrace

В основной статье ISETrace заявлено 3 894 вопроса train, **580** dev, 2 000 test. Число 500 относится к ручному аудиту вопросов test. В локальном сравнении при подборе параметров использовались 500 dev-вопросов. Сравнения вариантов внутри такого опыта осмысленны, но выбранная эпоха или гиперпараметры могут измениться на 580 вопросах. Для утверждения о превосходстве над опубликованной моделью нужен выбор по полному dev и сопоставимый результат по пяти инициализациям. Отдельная панель из 27 дополнительных вопросов также принадлежит корпусу ISETrace. [Построение разбиений, §3.4](https://arxiv.org/html/2609.25913v3#S3.SS4) · [Локальный эксперимент с отзывом связей и результат на 27 вопросах](../graph_memory_round21/binding_refit/REPORT_RU.md)

# Как много может дать более точный выбор адреса

Перебрали все разрешённые начала окон, из которых читатель R23 может открыть до 256 токенов в дополнение к своей накопленной памяти. Эталон задействован только для оценки достижимости. Для вопроса с недостающими символами в нескольких разных полях ни одно одноисточниковое чтение не может дать полный набор. Если недостаёт символов только в одном поле, проверяем каждую разрешённую стартовую точку этого поля до первого недостающего символа. Любая более поздняя позиция не может восстановить этот символ при чтении вперёд. Метод даёт точный потолок для замороженного интерфейса.

| Дополнительные вопросы, которые допускают полное покрытие | ISETrace | MultiDoc2Dial |
|---|---:|---:|
| Изначально неполные | 329 | 217 |
| Все пробелы в одном поле, произвольный доступ без ограничения длины | 303 | 217 |
| Все пробелы в одном уже показанном поле, без ограничения длины | 236 | 118 |
| При открытии на точном первом пропуске в видимом поле, до 256 токенов | 232 | 118 |
| **Имеется успешное открытие из существующего меню окон** | **125** | **33** |
| Удалось обычному BM25 | 18 | 3 |
| Удалось первому окну BM25 с ожидаемой новизной | 26 | 6 |

У ISETrace на 26/329 вопросов остаток свидетельств лежит в нескольких полях, ещё у 67/329 — в единственном отсутствующем поле. В 111 случаях недостающее поле уже показывалось, но ни одно начало из меню не возвращало всё за одно чтение. На MultiDoc2Dial поле размечено одно во всех вопросах; для 99 из 217 оно полностью отсутствовало в начальной выдаче, а в 85 из оставшихся 118 имеющееся меню не позволяло получить нужное целиком. Указание точного первого пропуска — диагностическая позиция, которую обычный читатель не знает. При разрешении открыть также отсутствующее поле таким способом возможно получить 298 и 217 наборов соответственно.

**Вывод для выбора направления.** На ISETrace даже лучший возможный выбор среди имеющихся адресов исправил бы максимум 125/329 неполных вопросов; простое правило исправило 26 из этих 125. На диалогах — 33/217 и 6 из 33. Есть одновременно ограничение ранжирования и ограничение набора доступных действий. Проверяемое расширение интерфейса — предложить открыть продолжение от конца уже показанного непрерывного отрывка: эту координату агент знает без эталона. Смежные чанки уже изучаются в RAG; отдельной проверки требует способ выбора продолжения при накопленной памяти и одном обращении к БД.

# Перенос истории графа на поиск тестов

Переносим правило R55, разработанное на edit2ripple, на другой тип запросов Agent Retrieval Bench — code2test. Известны исходные файлы из поля changed_file или implementation_files. Нужны связанные тестовые файлы, существующие на base_commit. Подводим отдельные итоги для всех допустимых задач и для задач с указанными путями, существующими в корпусе. Одна ранее исключённая из R54 задача остаётся вне панели принятия решений. Другие типы запросов не используем. До прогноза используем только sample_id, repo, base_commit, указанные пользователем пути, каталог снимка и исходные авторские top-20. Заголовок, тело PR, будущая правка, gold, hard negatives и агенты-оценщики недоступны механизму памяти. Опубликованные поисковые системы уже обрабатывали свой исходный запрос. На всех 106 примерах отдельно проверим идентичность официального вычисления Recall@5.

**Первичная гипотеза.** Исторический граф помогает дополнить современный текстовый поиск при известной роли целевого файла. Сильный контроль сортирует тестовые пути из опубликованной Qwen3-Embedding-4B двадцатки по исходному рангу, дополняет короткий список тестов по сходству имён и каталогов с известными файлами. Отсутствующие тестовые пути ранжируются по точному совпадению нормализованного имени, Jaccard токенов имени, Jaccard остальных токенов, затем строке пути. Разметка роли определяется исключительно именем файла по опубликованному is_test_path. Если корпус содержит меньше пяти опознанных тестов, дополняем оставшиеся позиции исходной двадцаткой. Основной вариант сохраняет первые четыре результата контроля и пробует заменить пятый историческим тестом за пределами первых двадцати контроля. Одного исторического коммита с известным файлом и кандидатом достаточно, если также наблюдался другой из четырёх текущих кандидатов; в остальных случаях требуем два таких коммита. Ранжируем кандидатов по сумме 1/(m−1), затем по числу подтверждений, давности и адресу. При нескольких указанных файлах коммит учитывается один раз. Первичная память ограничена последними восемью пригодными эпизодами каждого указанного пути среди до 64 прошлых first-parent переходов, включая доступное на момент запроса изменение base. Последние восемь выбираются среди всех эпизодов с якорем и 2–20 неделетированными путями, даже если связи с тестами не было.

**Контроли.** Сравним ту же операцию при глобальном окне 32, полном префиксе 64, одном подтверждении и частотном подборе при совпадающем факте активации. Отдельно проверим исходное правило R55 без известной роли и без подбора по имени для Qwen, RepoMap, Lexical. Оцениваем авторские Qwen3-4B, Qwen3-8B, Lexical, RepoMap и остальные доступные сильные авторские ранги при одинаковом бюджете. Дополнительно проверим общественные CodeNib Dense/Hybrid и все три Oko 0.9.1, поскольку их поштучные ответы опубликованы.

**Бюджеты.** В основном контракте допускается пять новых адресов, известные пути удаляются у всех. При исходной цене позиций авторов не удаляем их из базовых списков; неизменное правило на неограниченном по роли списке никогда не использует якорь как самостоятельное подтверждение. В политике с ролью исходные файлы обычно исключаются самой фильтрацией по роли. Это дополнительная информация из постановки code2test. Различаем выигрыш от роли и выигрыш от истории.

**Оценка.** Средний по задачам Recall@5, дополнительные Hit@5 и MRR@5. Для первичной пары разность с парным percentile bootstrap по целым репозиториям (20 000 повторов, seed 56027), wins/ties/losses, число сработавших замен. 12 репозиториев ограничивают перенос; репозитории, базовые коммиты и ID пересекаем с R55 и R54 и раскрываем это. У CodeNib/Oko сверяем базовые адреса с тем же корпусом, три прогона Oko не утроят размер выборки. При недостаточной истории сохраняем задачи в знаменателе и отражаем глубину. Набор и параметры определены до открытия исходов этой политики.

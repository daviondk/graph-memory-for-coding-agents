# Достаточно ли истории сверх сильного статического поиска

Результат вторичной проверки с двумя полноценными tests_only поисковиками показал, что добавка Qwen3-8B конкурентоспособна. Поэтому фиксируем ещё одну проверку: к одному и тому же объединению голоса по имени, tests_only Lexical, tests_only RepoMap, 4B и 8B добавляем либо исторические связи, либо независимый статический pplx-embed-v1-4b, либо оба источника. Используем тот же RRF с 10 и первыми 20 кандидатами источника. Оригинальный бюджет, 5 адресов, корпус тестов, 105 задач. Основной контраст этой проверки — граф сверх всех статических источников, включая pplx. Это дополнительный анализ на тех же наблюдавшихся запросах.

Отдельная модель с фиксированными коэффициентами регуляризации проверит, может ли качество ранжирования тестов выиграть от обучения на других репозиториях. Каждому проекту назначается отдельная внешняя итерация. На остальных 11 оценивается линейная модель условного распределения файла по запросу: softmax(scores), кросс-энтропия к равномерному распределению по достижимым правильным файлам и L2 0,01. У каждой пригодной обучающей задачи одинаковый вес. Жёсткие гиперпараметры фиксированы для всех проектов; полный пул всех тестовых путей известен до разметки. Задачи без распознанных тестов среди меток пропускаем только при обучении, на тесте учитываем все. Контроль имеет признаки обратных рангов Qwen4/8, pplx, авторских Lexical/RepoMap tests_only, CodeNib Dense, порядка по имени и трёх характеристик сходства самого пути. Сравниваем с добавлением трёх исторических признаков: число эпизодов, суммарный вес, давность. Дополнительно перемешиваем те же три признака между кандидатами внутри запроса детерминированной хэш-перестановкой, оставляя остальные признаки неизменными. Сравниваем и с контролем общей частоты в тех же 64 коммитах. У всего корпуса в памяти храним только прошлые события, признаки не содержат будущих имён из PR.

При оценке даём Recall@5 и долю полного покрытия, парные интервалы по проектам, отдельный результат для проектов/коммитов вне edit2ripple. Фиксированный обзор нескольких вариантов на одном наборе имеет разведочный характер. Публикуем ошибки и индивидуальные решения.

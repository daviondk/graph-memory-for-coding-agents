# Как сохранившееся событие помогает найти связанный файл

[Открыть автономную демонстрацию](index.html) · [Полный предыдущий комплект R55 с видео, привязанный к коммиту](https://github.com/daviondk/graph-memory-for-coding-agents/blob/71b6349f0676b4aed0ca256d7fa78bb3c6ac3d44/experiments/graph_memory_round55/submission/candidate.zip) · [Протокол текущего исследования](../shared_evidence/PROTOCOL_RU.md)

Скачанный `index.html` открывается прямо в браузере. Раскройте один из двух реальных запросов NetworkX, сравните восемь кандидатов и посмотрите, какие файлы продолжали удерживать ранние события Git. В двух таблицах один и тот же архив. Слева учтены последние восемь собственных событий раскрытого файла, справа все его события, сохранившиеся хотя бы у одного участника. Балл равен числу совместных прошлых изменений. При равенстве баллов выше ставится файл, который чаще менялся за последние 32 коммита, затем файл с меньшим идентификатором первого появления.

В [примере с генераторами](https://github.com/networkx/networkx/commit/ce8c37876bfe5920d38223d9cbad652d85085006) тест занял пятое место после расширения чтения с 8 до 15 событий. Четыре дополнительных события явно связывали файлы реализации и теста. В [примере с HITS](https://github.com/networkx/networkx/commit/1e5933dfc65d48594d7e1f95b29bb19418b56f2e) тест выпал с четвёртого места за пределы восьмёрки, хотя два дополнительных события тоже содержали тест. Конкурирующие файлы получили ещё больше свидетельств. Эти случаи подобраны для показа обоих исходов. На всей длинной панели из 196 запросов Recall@8 вырос с 41,97% до 43,53% при росте числа декодированных событий с 1 258 до 4 988. [Полные результаты](../shared_evidence/results.json)

## Воспроизведение

Для CLI достаточно Python 3 со стандартной библиотекой и полного репозитория. Следующие команды выполняются из этой директории.

```sh
python -B show.py gain
python -B show.py loss --json
python -B show.py ce8c3787
python -B show.py --all
python -B page.py --verify
```

Префикс SHA выбирает любой из 196 запросов. Режим `--json` дополнительно показывает все события, их участников и владельцев. На вход ранжирования поступают раскрытый путь и состояние памяти перед контрольным коммитом. Эталонные пути используются при оценке и подсветке уже построенной выдачи. `--all` сверяет число попаданий и обе меры стоимости для всех 392 выдач с сохранённым журналом. `page.py --verify` проверяет побайтовое совпадение страницы с повторной сборкой. Доступ к сети нужен только для открытия ссылок на GitHub. При проверке в Chromium без сети работали обе таблицы, раскрытие событий и просмотр владельцев при ширине окна 390 и 1 365 пикселей.

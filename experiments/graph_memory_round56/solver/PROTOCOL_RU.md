# Восстановление функций с памятью прошлых проверок

Какое ранее наблюдавшееся использование API стоит прочитать, чтобы реализовать скрытую функцию? Из открытых библиотек последовательностей, коллекций и числовых утилит фиксируем boltons, more-itertools и toolz. Используем по одному финальному коммиту и до 192 переходов по первому родителю строго до него. Для каждого исторического изменения извлекаем добавленные или семантически изменённые функции тестов; к эпизоду привязываем пути производственных модулей, изменённых тем же коммитом. В памяти нет реализации целевой функции. Каждая запись содержит прежний тест, в котором наблюдалось использование API, и адрес его коммита. Тесты прошлых коммитов разрешены агенту как внешняя память.

В текущем снимке выбираем публичные функции верхнего уровня в заранее определённых модулях последовательностей, словарей, строк, множеств, времени, чисел и функциональных преобразований. Из видимого контракта исключаем всю документацию начиная с первого примера doctest. Оставляем сигнатуру и описание до примеров. Скрытый эталонный код не участвует в ранжировании. Эталонные исполняемые примеры — doctest из авторского контракта в текущем снимке, выполняемые в его модуле. Чтобы выделить содержательные проверки, требуем хотя бы два примера с проверяемым выводом и прямое обращение к имени функции. Отбираем только обычные операции в памяти. Исключаем доступ к сети и пользовательским данным, файловые операции, управление процессами, безопасность и метапрограммирование. Оригинальная функция должна пройти все тесты, заглушка должна провалить хотя бы один. Случаи, не прошедшие проверку окружения, публикуем до генерации. Из пригодных задач берём не более 12 на проект по детерминированной перестановке SHA-256. Для диагностики переносимости также фиксируем число задач, где вообще мог измениться контекст.

Один и тот же BM25 ранжирует прежние тесты по названию функции, сигнатуре и описанию. Четыре политики допускают (1) все предыдущие обновления тестов, (2) все эпизоды с совместным изменением текущего пути, (3) последние восемь таких коммитов, (4) записи из последних 32 общих коммитов. При отсутствии эпизодов в ограниченной области возвращаемся к полному BM25 и записываем возврат. Повторения идентичного текста в доступной истории сворачиваются, при равенстве score предпочтительнее более поздний тест. Для каждого вопроса каждый метод передаёт один исторический отрывок; сравниваются целочисленно одинаковые бюджеты реальных токенов (до 240). Дополнительный вариант видит только контракт и использует более короткий вход.

Решатель — Qwen3-4B-Instruct-2507 Q4_K_M, локальная RTX 3090, greedy, не более 640 выходных токенов. Повторяющиеся входные токены генерируются один раз. Независимая оценка — доля полностью пройденных функций, число пройденных примеров, попарные расхождения по функциям и отдельные результаты каждого проекта. Три проекта недостаточны для устойчивого межпроектного вывода; парная перестановка по проектам имеет низкое разрешение. Сохраняем все входные проекции, ранги, входные токены, ответы, результаты контрольных и модельных исполнений. Сходство исторического примера с нынешним тестом оцениваем отдельно после выбора. Опыт моделирует восстановление скрытой реализации по контракту. Прошлые тесты и память о реальном посещении могут различаться; обучение модели могло включать открытый код этих библиотек. [Документация doctest](https://docs.python.org/3/library/doctest.html) · [boltons](https://github.com/mahmoud/boltons) · [more-itertools](https://github.com/more-itertools/more-itertools) · [toolz](https://github.com/pytoolz/toolz).

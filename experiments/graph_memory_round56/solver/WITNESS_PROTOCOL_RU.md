# Можно ли исполнить историческое наблюдение при выборе реализации?

Дополнительная гипотеза сформулирована после основных результатов и до построения селектора. Один и тот же пул из пяти основных условий даёт реализации для каждой из тех же 36 функций. Повторяющийся сгенерированный исходный текст (после удаления оформления и нормализации AST) получает один голос. Отдельный селектор имеет доступ к контракту, старым наблюдениям тестов и этим реализациям. Закрытые doctest и правильную текущую реализацию при выборе использовать запрещено. Число GPU-прогонов одинаково для обоих проверяемых селекторов.

Выделяем исполнимые наблюдения из прежних тестов. Требуем прямое обращение к целевому имени, сравнение по равенству или проверку истинности; допускаем обёртки list, sorted, tuple, dict, set и другие безопасные встроенные операции. Все входные переменные и ожидания должны быть определены самим извлечённым выражением либо безопасными встроенными функциями. Локальные переменные и фикстуры за пределами выражения исключаем. Допускаем не более 12 уникальных проверок на задачу, сначала более поздние наблюдения со связью с текущим модулем, затем остальные в порядке давности. Повторы по одинаковому выражению и исходу сворачем. Никакой предварительной фильтрации по тому, какой кандидат выигрывает или проходит ли исходная новая реализация.

Селектор со свидетельствами выбирает реализацию, удовлетворяющую наибольшему числу старых проверок. Сильный контроль использует те же входные выражения, исполнения и расход ресурсов, но скрывает эталон старой проверки. Каждому результату начисляется доля остальных различных кандидатов, вернувших такой же наблюдаемый выход. Запрос с исключением не даёт положительного балла. При равенстве оба метода применяют одинаковый фиксированный порядок: полный BM25, последние восемь локальных, вся локальная история, последние 32 общих, контракт. При отсутствии применимых наблюдений сохраняем ответ полного BM25. Недопустимый формат ответа в отсутствие доказательств также остаётся исходным результатом базового метода.

Фиксируем выбранные идентификаторы и хеш входов до сопоставления селекторов с закрытым тестовым исходом. Для каждой задачи считаем результат на всех авторских doctest и отдельно число прошедших примеров. Показываем покрытие свидетельствами, случаи реального расхождения, общее число исполненных проверок, точную верхнюю границу любого выбора в данном пуле и чувствительность к совпадению конкретного входа прежнего теста с нынешним doctest. Опыт сравнивает способы выбора внутри общего пула, число генераций выше, чем в основном опыте с одним решением.

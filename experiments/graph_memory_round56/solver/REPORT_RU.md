# Помогает ли память о прежних тестах восстановить функцию

На 36 реальных функциях из трёх Python-библиотек модель Qwen3-4B-Instruct-2507 прошла все авторские примеры в **15/36** случаях с памятью последних восьми изменений, связанных с модулем. Полный BM25 по всем имевшимся историческим тестам также дал **15/36**. Методы изменили входные токены в 18 случаях. Произошло два расхождения по полному прохождению, по одному в каждую сторону. [Основная регистрация](PROTOCOL_RU.md) · [Полные результаты](results.json).

## Условия исполнения

Закреплены три открытых проекта — boltons, more-itertools и toolz. Для каждого взяли одну целевую ревизию и 192 строго предшествующих ей перехода по первому родителю Git. При изменении обычного тестового метода память сохраняет его код, SHA и пути производственных модулей, изменённых в том же коммите. Получили 264, 143 и 160 исторических наблюдений соответственно. Совместная правка даёт наблюдаемую связь, но в одном коммите могут оказаться разные изменения. Это модель журнала наблюдений по Git. Реальный агент в этой серии репозитории не редактировал. [Закреплённые ревизии](pins.json) · [567 эпизодов](history.json.gz).

На целевой ревизии скрыли одну публичную функцию. Модель увидела только её имя, сигнатуру, описание до первого doctest, путь и в соответствующих условиях один фрагмент старого теста. При отборе по предварительно установленным правилам подошли 146 функций по форме контракта. Для первых 18 в каждом проекте проверили эталонную функцию и заглушку. Все 54 дали полностью проходящую исходную реализацию и провал заглушки. В итоговую детерминированную выборку включили первые 12 каждого проекта. Эти функции необязательно менялись в последнем коммите. Оценщик запускал авторские doctest текущей функции в её исходном модуле после подстановки сгенерированного тела. Полные конфигурации проектов и отдельные issue в этом опыте не решались. [Калибровка](calibration.json.gz) · [Модуль изоляции](isolation.py).

Решатель работал локально на RTX 3090 с Q4_K_M, жадным декодированием и ограничением 640 выходных токенов. Каждый основной вариант со свидетельством получил целочисленно одинаковую длину входа для каждой задачи. Выделялось от 33 до 240 токенов на свидетельство, в среднем 118,56. Все четыре поиска используют одни и те же IDF по предшествующему корпусу и лексическую функцию BM25. Различается доступный набор прежних событий. Во всех 36 случаях ограниченные пулы были непустыми. Ограничение истории здесь характеризует доступ к записям; подсчёт IDF использовал полный прошлый корпус. Из 180 назначений получено 115 разных генераций и 20 560 выходных токенов. Ещё 30 уникальных генераций потребовалось для проверки дополнительных политик. Модель могла видеть публичные функции при обучении. Агрегирование по всем 178 примерам придаёт больший вес функциям с длинным набором проверок. Разность в два полностью пройденных задания относительно контракта соответствует трём выигрышам и одному проигрышу; точная двусторонняя перестановка знака по трём проектам даёт p=0,5. Для короткой локальной памяти против полного BM25 p=1. На boltons каждый подход решил 3/12, на more-itertools локальный метод и полный BM25 дали 5 и 4/12, на toolz — 7 и 8/12. Среди пяти функций с совпавшим полным текстом хотя бы одного вызова в старом фрагменте и нынешнем doctest могли работать близкие примеры. На оставшихся 31 вопросе локальная память, полный BM25 и условие только с контрактом дали одинаковые **11/31**. Данный способ обнаружения совпадений не исключает семантически сходных примеров с иными аргументами. [Поштучные исходы](records.json.gz) · [Проверка совпадений](overlap-by-task.json.gz).

**Два расхождения.** Для more-itertools.divide наблюдение из теста IchunkedTests.test_negative дало 7/7, а ValueChainTests.test_type_error_from_iter, выбранный по всей истории, — 0/7. Для toolz.interleave полный поиск выбрал тест скользящего окна и дал 2/2, локальная память выбрала test_compose_metadata и дала 0/2. Эти фрагменты не вызывают соответствующую целевую функцию напрямую. Из самих двух случаев нельзя установить причинный механизм конкретной строки программы. [Фрагменты, реально доступные решателю](visible.json.gz).

## Два контроля содержимого памяти

До раскрытия основных исполняемых результатов зафиксировали сравнение последних восьми эпизодов модуля c хеш-выборкой восьми, а также правило расширения области поиска до тех пор, пока в тесте не встретится прямой вызов функции. В четырёх задачах сократился общий токенный бюджет из-за нового более короткого кандидата, и соответствующие базовые реализации были заново сгенерированы. В этой постановке локальные восемь дали **15/36**, хеш-выборка — **14/36** и одна парная разница. Фильтр прямого вызова, такой же фильтр по всей истории и полный BM25 дали по 15/36 и одинаковый бинарный результат для каждого задания. При фильтрации нашлись прямые упоминания вызова только в 15 вопросах; в 21 вопросе был вынужденный возврат к полному поиску. В результате дополнительный фильтр изменил вход по сравнению с полным BM25 всего дважды. [План расширения](EXTENSION_RU.md) · [Сравнения](extra-results.json).

Отдельно проверили единственную усечённую основную генерацию для toolz.peekn. При увеличении до 1 024 токенов воспроизвёлся полный исходный байтовый префикс, но решатель вновь дошёл до ограничения с синтаксически незавершённым ответом. Два исходных EOS-ответа при таком лимите побайтово воспроизвелись. Единственный ответ с отклонённым импортом локального пакета отдельно исполнили в изоляции; он провалил 3/3 примера. Основные бинарные результаты от этих проверок не изменились. [Аудит ограничений исполнения](cap-and-import.json.gz).

## Что меняется при исполнении исторических свидетельств

После основного опыта задали другой вопрос: есть ли смысл хранить наблюдаемый исход старого теста и использовать его при выборе из уже сгенерированных кандидатов? Из доступных старых тестов извлекли 30 простых самостоятельно исполнимых проверок, применимых к восьми из 36 функций. Для каждой реализации подставляли её код в настоящую библиотеку. Выполнено 70 проверок на 19 кандидатах. Один селектор видит ожидавшееся историческое значение, другой наблюдает только согласие разных реализаций на тех же входах. Оба выбирают из одного пула, при равенстве сохраняют приоритет полного BM25. Выборы записаны до присоединения к независимым результатам doctest. [План](WITNESS_PROTOCOL_RU.md) · [Выборы](witness-decisions.json.gz).

Селектор по историческим исходам дал 15/36 функций и 115/178 примеров, по согласию — 15/36 и 114/178, фиксированный полный BM25 — 15/36 и 113/178. Максимум для **любого** селектора по всему набору имеющихся реализаций — 17/36. Для тех восьми функций, где вообще можно исполнить извлечённое свидетельство, этот потолок равен **3/8** и уже достигается исходным BM25. Значит, здесь даже совершенный выбор кандидата нового полностью решённого задания дать не мог. Три прежние проверки повторяли обнаруживаемое выражение из будущего doctest. После исключения затронутых трёх задач селекторы снова дали одинаковые бинарные результаты, 13/33. Ограниченность одновременно доступными кандидатами и диагностическими свидетельствами — измеримая причина нулевого эффекта на этой панели. [Проверка метрик](audit.json).

## Воспроизведение

Из этой папки `python -B verify.py` проверяет результаты на приложенных проекциях и поштучных исходах. Для независимого сопоставления со всеми 576 переходами Git используйте `python -B fetch_sources.py`, затем `python -B verify.py --git`. Для подготовки и повторного исполнения понадобятся Python 3.14 с requests, Docker с указанным в [study.py](study.py) образом Python 3.12, закреплённые GGUF и llama-server из [конфигурации R52](../../graph_memory_round52/reranker/common.py). Данные и графические веса хранятся на D. Порядок полного повтора: `prepare.py`, `select_tasks.py`, `generate.py`, `grade.py`, `extension.py select`, `extension.py generate`, `extra_grade.py`, `witness.py`, `audit.py`, `cap.py`, `verify.py --git`. Исходные модули берутся из закреплённых открытых коммитов. Для проверки пересечения авторских примеров файл входных выражений строится `prepare.py`. Настоящие реализации не передаются модели, grader использует их для штатной загрузки соседнего кода. Репозитории, изоляция и хеши зафиксированы; сборка оборудования и шаблон модели есть в квитанции генерации. [Лицензии на сохранённые выдержки и контракты](THIRD_PARTY_LICENSES.md).

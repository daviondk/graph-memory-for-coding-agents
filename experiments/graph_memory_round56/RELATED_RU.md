# Ближайшие предшественники графовой памяти R56

**Отбор небольших коммитов уже проверяли на задаче рекомендации файлов.** Moonen, Di Alesio, Binkley и Rolfsnes (ASE 2016) варьировали верхнюю границу размера исторической транзакции в двух промышленных и восьми открытых системах. Исследовали пороги 2, 4, 6, 8, 10, 20, 30 файлов и полную историю. Для группы лучших мер ассоциации пороги 6 и 8 вошли в одну верхнюю группу по MAP. В R56 выбираются до B наименьших из сохранившихся событий конкретного файла при ограничении B на число декодирований. Фиксированный порог в 6 или 8 относится к размеру отдельного события и может оставлять любое число событий. Это ближайшее опубликованное сравнение для проверки вклада адаптивного отбора. Сопоставление требует перенести оба порога на те же запросы, ту же доступную историю и согласовать бюджет чтения. [Practical Guidelines for Change Recommendation using Association Rule Mining, §5.3](https://web-backend.simula.no/sites/default/files/publications/files/practical_guidelines_for_change_recommendation_using_association_rule_mining_1.pdf)

**Почему состав события важен.** Herzig и Zeller (MSR 2013) вручную разбирали коммиты пяти Java-проектов. До 15% исправлений в исследованных проектах объединяли несколько задач. Такое смешение создаёт ложные связи при обучении по совместным изменениям. Размер события в R56 — дешёвый наблюдаемый признак. Для объяснения через тематическую однородность нужна отдельная разметка содержания. Newman (Physical Review E, 2001) ранее использовал вклад 1/(m−1) в вес каждой пары участников группового события для графа соавторства. Фиксированный участник имеет m−1 партнёров и распределяет единичный вес между ними. Та же нормировка применяется в ветке R56 по поиску тестов. В опыте с совместно удержанными событиями после отбора считаются обычные частоты. [The Impact of Tangled Code Changes](https://www.microsoft.com/en-us/research/wp-content/uploads/2013/01/msr2013-untangling.pdf) · [Scientific Collaboration Networks II, §III](https://public.websites.umich.edu/~mejn/papers/016132.pdf)

**Использование сведений из нескольких выборок тоже имеет прямой аналог.** Cohen и Kaplan (2009) использовали дополнительные ключи, попавшие в отдельные согласованные выборки множеств, для более точной оценки агрегатов. R56 хранит событие до отказа последнего файла-владельца. При запросе к другому участнику событие доступно через обратный индекс. Оценки Cohen и Kaplan относятся к случайным согласованным выборкам; для удержания последних событий качество top-k и объём чтения устанавливаются экспериментально. Ahmed, Duffield и Xia (IJCAI 2018) дали потоковую оценку матрицы общих соседей двудольного графа с двумя выборками фиксированного размера. Для графа «файл — коммит» число общих соседей равно числу совместных изменений. Такая аппроксимация подходит как контроль при сравнении стоимости и точности проекции. Прогноз следующего изменённого файла дополнительно требует хронологического теста. [Leveraging Discarded Samples for Tighter Estimation of Multiple-Set Aggregates](https://arxiv.org/abs/0903.0625) · [Sampling for Approximate Bipartite Network Projection](https://ijcai.org/proceedings/2018/456)

В этих пяти работах не найдено точного сочетания «несколько владельцев одного Git-события, ограничение памяти на файл, выбор B наименьших сохранившихся событий при чтении и проверка по следующей правке». Это результат ограниченного поиска. Обоснованный предмет статьи — вклад каждого из этих решений в Recall@k и в фактическую стоимость чтения при равных входах и бюджете.

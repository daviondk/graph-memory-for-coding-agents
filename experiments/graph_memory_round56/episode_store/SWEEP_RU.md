# Достаточная история без указателя на каждый источник

Подтверждение для файла a — последние B=8 эпизодов с a, с их исходными номерами коммитов и составом. Метрика качества зафиксирована предыдущим опытом. Проверяем, можно ли ещё уменьшить физический размер именно этого состояния, сохраняя результат на каждом запросе. Идею рассматриваем после первого измерения SQLite; ни одна оценка новых схем ещё не вычислялась.

Если событие e входит в последнюю восьмёрку хотя бы одного участника, его необходимо сохранять для предъявления этого свидетельства с идентификатором e. Если каждый его участник уже встретился в восьми более поздних событиях, e не входит ни в один текущий ответ и уже не сможет войти после новых добавлений. Поэтому можно хранить только объединение ещё востребованных эпизодов. Любое более позднее появление способно лишь вытолкнуть старое событие. В обратном хронологическом обходе счётчик предыдущих встреч каждого участника задаёт точное решение об удалении. Для выдачи конкретному якорю из оставшихся строк берём последние восемь **его собственных** эпизодов. Утверждение предполагает добавление коммитов в конец и отсутствие ручных отзывов прошлого.

Для проверки записываем четыре политики. Append-scan хранит полный журнал и читает назад до восьмого совпадения. Sweep-scan дополнительно освобождает потерявшие владельца события каждые 32 коммита. Block-scan объединяет события в блоки по 32 последовательным коммитам, хранит точный список участвующих файлов для каждого блока и пропускает payload блоков без якоря. Block-sweep выполняет тот же обход и удаление в блочном представлении. Индивидуальных ссылок в этих четырёх схемах нет. Отдельные контроли — упакованные ссылки из предыдущего дополнения и полные отдельные копии. Выбор 32 отвечает известному окну частотного признака; параметр не подбирается по результату. Все операции, включая сборку мусора, входят в измерение. Пять перемешанных блоков по 12 прежним репозиториям, тот же режим SQLite. Для компактной физической базы показываем размер целых SQLite-файлов после VACUUM (по проектам и суммарно); для работающей — перед VACUUM. Время выдачи включает общий вторичный порядок и сортировку. Во вторичном режиме измерим также одни чтения свидетельств после открытия базы. GС и восстановление происхождения будут проверены независимым сканированием сырых коммитов без использования логики хранения.

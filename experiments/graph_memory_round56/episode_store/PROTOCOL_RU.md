# Сколько стоит память прежних совместных правок

Используем оба набора R55 без отбора по качеству. Единица оценки — предсказание при одном заранее определённом якоре в многофайловой правке. SHA выбирает якорь, остальные пути скрыты, первые 64 коммита прогревают память. Кандидаты и вторичный порядок совпадают с R55: частота появления за 32 коммита, затем порядок первого появления. Все чтения предшествуют наблюдению правки. Учитываются Python-пути из R55, включая удалённые. Время и разметка будущих правок не участвуют в алгоритме.

**Физическое сравнение.** Запишем в файловую SQLite каталог путей и частотное состояние с журналом 32 коммитов во всех вариантах. Сравним накопительные двусторонние счётчики пар, полный журнал общих событий с обратным списком участия, последние восемь событий каждого файла в отдельных копиях, и последние восемь через общий неизменяемый состав события и ограниченные ссылки от якоря. При потере последней ссылки удаляем общую запись. Удельный контроль — объединение одинакового состава разных коммитов по точному ключу. При равных событиях эти реализации обязаны давать идентичные баллы. Ссылка ведёт к полному составу коммита, даже когда другой файл уже забыл этот эпизод. Будет измерен размер SQLite-файла до и после VACUUM, количество записей, вставок и изменённых строк, времена построения и переданных запросов. Порядок методов перемешивается в пяти блоках, seed 56071. Пишем одной SQLite-транзакцией на входной коммит, файловая база с journal_mode=MEMORY, synchronous=OFF. Это проверка структуры и исполнения, без гарантии долговечности. Холодный тест открывает новое соединение (кеш страниц ОС остаётся); тёплый использует то же соединение. Результаты каждой политики во всех состояниях будут сверены с полным пересчётом из префикса.

**Равное место в байтах.** Основной тест B=64, чувствительность 32 и 128. Для каждого когда-либо замеченного пути выделена строка с B байтами полезного состояния в одной таблице. Общий каталог путей, тай-брейки, частоты и журнал 32 коммитов идентичны; внешних словарей связей нет. Меняется только содержимое B байт. Наблюдение — набор остальных путей коммита. Три вложенных варианта: хранить последние наборы, включая пустые; опускать пустые; дополнительно объединять последовательные одинаковые непустые наборы, сохраняя число голосов. В порядке от новых к старым сохраняем целые записи, пока следующая не помещается. Новый непомещающийся набор пропускается. Контроль со счётчиками — Space-Saving с фиксированными четырьмя байтами на пару (uint16 ID, uint16 count), то есть B/4 кандидатов на якорь. Отдельный контроль — компактные переменной длины ID+count с вытеснением минимального счётчика при превышении B. Порядок обновления внутри одной правки — по ID. Выбор политик и бюджета зафиксирован до расчёта. Сравниваем качество при одинаковом числе и размере строк и измеряем фактический файл. Первичное качество — Recall@8 на замеченных в R55 880 многофайловых коммитах второй панели; первая панель показывает перенос в другую сторону. Рассчитываем Hit@8 и среднюю по проектам разность с парным 95% описательным bootstrap по 6 проектам. Главный контраст — сжатие одинаковых непустых наборов против хранения тех же наборов без их объединения. Обе политики используют одинаковые поля и параметры. Вторичный контроль — восстановить качество при отказе от пустых наблюдений. Положительный результат относительно одной политики не устанавливает оптимальность при данном бюджете.

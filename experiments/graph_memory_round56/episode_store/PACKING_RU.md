# Дополнительное сравнение физических схем

В первом прогоне общий журнал хранился компактнее двусторонней таблицы пар. В ограниченной истории строковая таблица ссылок с разделяемым составом событий показала меньший либо равный объём по сравнению с индивидуальными копиями. Многократное хранение одинакового состава и расходы реляционных записей могут влиять сильнее самого способа забывания.

До измерений дополнительных схем фиксируем четыре сильных контроля. Для накопительных счётчиков сохраняем (1) одну запись на неупорядоченную пару и дополнительный индекс для обратного поиска и (2) одну компактную строку с перекодированными по разностям ID и кратностями каждого соседа для каждого якоря. Оба обязаны восстановить все прежние оценки, но агрегированные счётчики теряют происхождение отдельного голоса. Для сохранения источника также проверяем (3) общий журнал с одной упакованной возрастающей последовательностью ID коммитов на якорь и (4) тот же журнал с последними восемью ссылками, с удалением состава события после утраты последней ссылки. Чтение составов использует SQL IN в пакетах до 400 ID. Смысл времени, бюджет кандидатов, панели и порядок разрешения равных оценок прежние. Проведём пять новых перемешанных блоков со всеми девятью физическими представлениями; суммы стоимостей без смешения серий. Первичный новый контраст — упакованные ссылки+GC против полных упакованных строк отдельных якорей при идентичном результате и доступности ID исторических событий.

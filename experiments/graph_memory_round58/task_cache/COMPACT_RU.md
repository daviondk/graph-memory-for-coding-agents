# После основной оценки: стоимость адреса и область повторения

Основная абляция показала эффект общего хранения при одинаковой фиксированной 12-байтовой записи адреса. Проверяем два возможных объяснения после просмотра этого результата. Первое — выигрыш вызван заведомо некомпактным форматом адресов. Второе — для экономии достаточно сжатия текста внутри одного файла, использование тела из другого файла не требуется.

1. Для основного 12-байтового формата и ёмкости 16 КиБ применим точные ссылки только внутри одного пути. Остальные правила основного сравнения сохраняются.
2. Для file-group LRU строим более компактный точный формат. Порядок файлов сам кодирует их давность, внутри каждого файла порядок строк кодирует их давность. Заголовок содержит число файлов uint16. Каждый файл записывается один раз как ULEB128 длина, UTF‑8 имя, uint16 число строк. Для строки — signed zigzag ULEB128 дельта номера от предыдущего сохранённого номера в этом файле, затем ULEB128 тег и тело для литерала. Чётный тег равен удвоенной длине, нечётный задаёт расстояние до ранее декодированной строки с тем же содержимым. Ссылку используем только когда короче литерала. Три варианта — только литералы, ссылки внутри одного файла, ссылки по всем активным файлам. Выбираем строки в том же порядке, что и при сериализации; кандидат принимается, если точное добавочное число байтов укладывается в лимит. Используем 4/16/64 КиБ, основной контроль 16 КиБ. Публикуем все варианты и IT-стоимость. Метрики те же, что для основного теста.
3. Воспроизводим длину и декодирование новых форматов на буквальных синтетических данных и отдельно проверяем соответствие размера оценщику. Настоящего текста в реальных проекциях нет, поэтому нельзя измерить экономию общецелевого текстового компрессора. Представление считается логически сериализованным; RSS и время запроса остаются отдельными показателями.

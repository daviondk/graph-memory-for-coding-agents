# Дополнительная проверка размера прочитанного текста

Основной опыт уже оценён. До извлечения длин фрагментов и оценки этого дополнения фиксируем сравнение. Для каждого из 25 репозиториев бюджет числа чтений равен числу эпизодов, а бюджет текста равен суммарному числу UTF-8 байтов первых фрагментов от равномерной политики Qwen3-Embedding-4B в данном репозитории. Считаем размер только содержимого поля text. Открытие одного адреса потребляет ровно один первый фрагмент, выбранный по тому же порядку, что в R54. Предварительные признаки и баллы всех методов заморожены.

В общий пул каждого эпизода включаем первые два кандидата static, snapshot, history и RRF и первый файл плотной модели. Для каждой политики выбираем бинарную переменную на пару «эпизод, путь», всего ровно N пар и максимум две на эпизод, с указанной верхней границей байтов. Максимизируем сумму округлённых до миллиардной доли предсказанных вероятностей или баллов RRF. При одинаковой сумме минимизируем суммарные байты. Фиксируем достигнутую границу оптимальности решателя и воспроизводимые решения. Контроль для новой задачи — та же оптимизация на том же пуле без верхней границы байтов и первоначальная плотная политика. Для сопоставления по байтам у агента должна быть заранее доступна длина каждого кандидата в каталоге фрагментов. Сбор каталога требует чтения исходного корпуса, что выносим из измерения объёма текста, переданного решателю.

Первичный описательный контраст — history минус snapshot под двумя ограничениями. Приводим все методы, достигнутую долю покрытия и объём прочитанного текста. Для условного сравнения файловых попаданий бутстрэпируем репозитории по основному протоколу. Качество не использовали для выбора тестируемых ограничений. Добавление опыта после знакомства с основными результатами сохраняет его исследовательский статус.

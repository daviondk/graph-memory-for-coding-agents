# Что дают предыдущие предложения агента при ограниченном бюджете чтения

## Дизайн до измерения

Используем те же 283 положительных эпизода GPT-5.4-mini из Agent Retrieval Bench и те же проверенные кандидаты, что в [предыдущем опыте](../../graph_memory_round54/learned_read/REPORT_RU.md). В том опыте все задачи получали одно чтение. Здесь у очереди из N задач одного репозитория есть ровно N дополнительных чтений и предел два чтения на задачу. Единица анализа — эпизод с исходной строгой выдачей. Первичная величина — число вновь найденных эталонных файлов на 100 чтений. Целевая функция аддитивна по парам «эпизод, файл». Показатели покрытия задачи, полноты и бюджета отдельно проверяют последствия концентрации чтений. Каждая политика возвращает разные адреса внутри одной задачи.

Не используем метки при извлечении признаков, выборе аналогов, ранжировании или распределении тестового бюджета. До составления протокола проверили схему архива и число промежуточных финальных предложений. Предыдущие результаты на этой панели известны. Каждый репозиторий целиком служит внешним фолдом. Никакой подбор гиперпараметров, порогов или вариантов по тестовой метрике не предусмотрен. В опубликованном каталоге закреплённой ревизии присутствует один отдельный архив строгих траекторий. [Первичная публикация](https://arxiv.org/abs/2607.24882) · [Архив](https://huggingface.co/datasets/eyuansu71/agent_retrieval_bench/tree/5901e1ee3aff048290db72edf9c63bc498b79ea3/releases/trajectories)

## Политики

* Статические ориентиры. По одному новому пути из авторской Qwen3-Embedding-4B и из RRF семи методов. RRF дополнительно распределяет чтения по максимальной сумме обратных рангов. Для отдельного плотного поиска при отсутствии допустимого результата в опубликованном top-20 заимствуем первое место RRF. Публикуем частоту такой подстановки.
* Три логистические модели с общей функцией потерь из R54. Каждому эпизоду даём вес один и делим его поровну между кандидатами. Штраф L2 с коэффициентом один на все коэффициенты, кроме константы. static использует семь дисконтированных рангов и три индикатора типа задачи. snapshot добавляет последний проверенный ранг предложения, числа уникальных открытых файлов и файлов строгой выдачи, предложений, финальных действий, действий поиска и чтения. Количества кодируем как x/(1+x). history дополнительно получает четыре признака *того же кандидата*: доля предыдущих финальных действий, в которых его предлагали, максимальный дисконтированный ранг в них, ранее предлагался и теперь отсутствует, согласие предыдущего и последнего предложения. Эти два последних признака различают отзы́в и повторное подтверждение. Никакие новые пути в исходный пул не добавляем. Дисконт ранга равен 1/log2(1+r), отсутствие даёт ноль.
* Первичный контраст — history против snapshot при пакетном распределении. Модели оценивают ожидаемую релевантность отдельных допустимых путей, выбирают два лучших разных адреса в каждой задаче, затем N самых высоких из этих пар в репозитории. Равенства разрешаем по идентификатору задачи и исходному лексикографическому номеру пути. Правило оптимизирует сумму предсказанных вероятностей при этих ограничениях. Чтение моделируется выбором доступного пути, единица бюджета не учитывает размер файла или стоимость предыдущего поиска.
* Абляции — по одному чтению для каждой модели, пакетный static, RRF, сравнение history при одинаковом способе ранжирования с одним чтением. Для последовательной работы определяем порог по распределению двух лучших прогнозов на обучающих задачах после подгонки к ним. В следующей задаче порог равен эмпирической квантили 1−B/(2n), где B и n — оставшиеся бюджет и размер очереди, до чтения. Границы числа чтений принудительно гарантируют, что оставшиеся задачи смогут выбрать остаток по ставке от нуля до двух. Порядок задач фиксирован SHA-256 идентификатора с солью 55001. В отличие от пакетной версии, этот вариант видит только признаки текущего эпизода и счётчик оставшихся. Публикуем разброс последовательной метрики по 32 хеш-порядкам как проверку чувствительности.

## Оценка

Для всех политик публикуем новые эталонные файлы, долю эпизодов хотя бы с одним новым попаданием, среднюю полноту строгой выдачи вместе с дополнением, полное покрытие, число эпизодов с 0/1/2 чтениями. Публикуем число уникальных текстов заданий, базовых коммитов и комбинаций (репозиторий, коммит, текст), число повторных предложений и отозванных кандидатов. Описательный oracle решает ту же задачу распределения с известными метками. Парный процентильный bootstrap 10 000 выборок по 25 репозиториям, seed 55001, с пересчётом общего знаменателя в каждой выборке и фиксированными out-of-fold прогнозами. Число репозиториев, в которых метод выиграл, проиграл или сыграл вничью, и среднее по репозиториям публикуем отдельно. Прогнозы и распределения фиксируем до итоговой оценки. Бенчмарк определяет файловую релевантность, правильность сгенерированного кода и успех задачи потребовали бы отдельных запусков.

Техническое уточнение до расчёта метрик. В пяти архивах последний список в журнале действий и сохранённый итоговый список различаются. Как в предыдущем раунде, для snapshot используем сохранённый итог. Для history предшествующими считаем только действия до последнего финального действия. Признак расхождения в модель не входит.

# Сколько дополнительных файлов читать и что даёт история предложений агента

На 283 архивных задачах программирования из 25 репозиториев сравнили два решения после завершения основного поиска — какой файл открыть следующим и стоит ли выделить данной задаче второе чтение. При одинаковых 283 чтениях модель, использующая последнюю запись агента, нашла 28 дополнительных эталонных файлов. Добавление истории повторённых и отозванных предложений дало 26. Разность составила −0,71 файла на 100 чтений, 95% ДИ [−3,94; +2,30]. Этого сравнения недостаточно для заявления о преимуществе истории или о новом SOTA. ## Один бюджет, разные решения

Воспроизвели конечное состояние строгих траекторий GPT-5.4-mini в Agent Retrieval Bench. Всего 283 уникальных запроса к 215 снимкам, из них 105 code2test, 100 trace2code и 78 comment2context. Уже открытые и выданные в условии пути исключили во всех вариантах. История поиска и пути проверены на том же коммите, к которому относится разметка. Один и тот же замороженный пул содержит 16 455 пар «задача — доступный файл». Исходная строгая выдача уже полностью покрывала 139 задач. Все эпизоды участвуют в сравнении. Каждый из 25 репозиториев целиком откладывали, веса подбирали на остальных 24. [Проверенные исходные кандидаты](../../graph_memory_round54/learned_read/REPORT_RU.md) · [Зафиксированные прогнозы](prediction-seal.json)

В очереди из N эпизодов одного репозитория все методы получают ровно N чтений. Равномерная политика выделяет по одному файлу каждой задаче. Пакетная политика сначала оценивает кандидатов во всей очереди. В каждой задаче оставляет два лучших разных файла, затем выбирает N наиболее перспективных пар «задача — файл». При аддитивном ожидаемом числе эталонных файлов это оптимум по предсказанным вероятностям при заданных ограничениях. Зависимость релевантности между файлами внутри задачи не меняет линейность ожидания. Для другой цели, например доли полностью покрытых задач, это обоснование неприменимо.

Статическая модель использует тип задания и семь авторских рангов. Пакетный вариант нашёл на семь файлов больше равномерного, +2,47 на 100 чтений [0,00; +5,08]. Весь выигрыш пришёлся на etcd, gin и tokio, в остальных 22 репозиториях суммарные попадания совпали. Для RRF такое же перераспределение привело к потере трёх файлов. Шкала RRF задаёт порядок внутри задачи, и её переносимость между задачами требует отдельной проверки. У гипотетического правила, которому доступны метки, потолок этого пула составляет 116 верных файлов при равномерном распределении и 142 при пакетном. Сильный отбор отдельных файлов и сравнимые оценки полезности разных задач остаются существенными ограничениями.

В прямом сравнении истории и последней записи по шести эпизодам стало больше попаданий, по девяти меньше. В 268 эпизодах число совпало. Разность при равном весе каждого репозитория составляет +1,82 на 100 чтений, при весе по числу запросов −0,71. Интервалы условны на зафиксированные out-of-fold прогнозы, кластером считался репозиторий. Эта панель уже использовалась в R54. Сравнение описывает дополнительное чтение после реальной траектории. Официальная таблица Agent Retrieval Bench оценивает самостоятельный поиск от начала задачи. [Парные исходы](episode-outcomes.json.gz)

## Как отличить повторное предложение от отзыва

У 140 задач агент сформировал хотя бы один промежуточный список предложений перед последним. Внутри этой подгруппы 19 из 220 кандидатов, фигурировавших и раньше, и в конце, оказались эталонными. Для впервые появившихся в конце — 6 из 134, для ранее предлагавшихся и впоследствии отозванных — 3 из 64, для остальных — 48 из 7 487. Это описательная стратификация: агент чаще повторяет пути, которые уже выглядят релевантными. Коэффициенты модели учили только на других репозиториях; добавление частоты, ранга, отзыва и повторного подтверждения не улучшило основной результат. В пяти траекториях сохранённый итоговый список дополнен относительно последнего действия; для последнего состояния использовали именно сохранённый список во всех сравнениях. [Разбор предложений](proposal-audit.json) · [Наблюдения без меток](observations.json.gz)

Последовательный вариант видит текущую задачу, остаток бюджета и число ещё ожидаемых задач. Порог берётся из распределения прогнозов на обучении. В основном порядке получили 25 файлов для статической модели, 27 для последней записи и 21 для истории. При 32 заранее заданных порядках диапазоны составили 21–28, 21–29 и 21–28 соответственно. Так можно оценить, сколько пакетный алгоритм выигрывает от доступа ко всем запросам очереди. В режиме интерактивной работы такой доступ может отсутствовать. ## Сопоставление объёма текста

В дополнительной проверке каждый репозиторий получил также лимит UTF-8 байтов, равный объёму  первых фрагментов при равномерном чтении Qwen3-Embedding-4B. Для 990 пар «задача — кандидат» извлекли из закреплённого корпуса размер и SHA-256 фактического первого фрагмента. У 855 пар контрольная сумма и границы независимо совпали с сохранёнными в R54. Все политики имеют одинаковый пул и точную квоту в 283 чтения. Оптимизатор максимизирует суммарную предсказанную полезность и при равенстве минимизирует байты. Проверили ограничения и совпадение с двойственной границей для каждого решения. После учёта объёма наблюдаемое преимущество статической модели по числу найденных файлов исчезло относительно последней записи. Последняя запись сохранила 28 попаданий при сокращении нагрузки на 131 163 байта (7,05%) относительно той же пакетной стратегии без лимита объёма. Относительно плотного поиска она дала +0,71 попадания на 100 чтений [−4,31; +4,49] и передала на 1,99% меньше текста. Байты взяты из поля text, стоимость поиска, метаданных, токенизации и инференса в них не входит. Каждая задача симулирует получение фрагмента по проверенному адресу; для вывода о решённых задачах нужны исполнения решателя и тестов. [Все сравнения](byte-results.json)

## Воспроизведение

Готовые проекции, баллы, решения и метки из R54 включены в репозиторий. Для повторения численного аудита нужны Python и NumPy. Для полного воспроизведения с исходных архивов использовали Python 3.14.4, NumPy 2.4.4 и отдельное окружение с SciPy 1.18.1 для целочисленной оптимизации. Подойдут закреплённые исходные архивы из каталога releases. [Исходные данные](https://huggingface.co/datasets/eyuansu71/agent_retrieval_bench/tree/5901e1ee3aff048290db72edf9c63bc498b79ea3/releases)

```text
python -B inputs.py --archive PATH_TO_STRICT_TRAJECTORIES
python -B predict.py
python -B grade.py
python -B chunks.py --corpus PATH_TO_MAIN_ARCHIVE
python -B byte_budget.py
python -B byte_grade.py
python -B proposal_audit.py
python -B audit.py
```

Аудит восстановил 49 365 вероятностей на отложенных репозиториях, 849 пакетных решений, градиенты на обучении всех 75 моделей и обе таблицы результатов. Наибольшая компонента градиента составила 6,82·10⁻¹³ или меньше. Все 566 равномерных одиночных решений плотной модели и RRF совпали с R54. [Численные проверки](audit.json)

# Где граф истории добавляет пропущенный лексическим поиском файл

На 54 задачах edit2ripple граф нашёл два полезных файла, которых не было в первой двадцатке Lexical, и повысил Recall@5 с **48,92% до 50,46%** при бюджете в пять **новых** файлов. При исходном учёте позиций в бенчмарке эффект изменил знак: **41,20%** против **43,36%**. Оба результата относятся к тем же задачам и базовым ревизиям. [Интерактивный разбор по каждому запросу](replay.html) · [Исходный бенчмарк Qin и Xie](https://arxiv.org/abs/2607.24882).

## Устройство и постановка

Агенту уже показана правка одного файла. Какие ещё файлы открыть? Для 42 базовых ревизий в 10 публичных репозиториях взяли по 64 перехода по первому родителю, заканчивая доступным в момент решения коммитом. Из каждого исторического изменения размером 2–20 путей сохраняем совместное участие файлов. Представление не требует эмбеддингов или содержимого файлов. В этом опыте исходный Lexical независимо использует корпус. Независимый аудит сверил все 2 688 переходов с Git, из них 1 556 различных, и проверил 63 982 адреса зафиксированных снимков. Кандидаты существуют в базовой ревизии. Выборка и исключения совпадают с R54. До этой серии уже были известны результаты базовых методов и состав 54 из 58 задач. [Протокол](PROTOCOL_RU.md) · [Аудит Git](independent-history-audit.json) · [Публикация R54](../../graph_memory_round54/code_links/REPORT_RU.md).

Первый опыт оставлял первые четыре файла неизменными и позволял повысить на пятую позицию исторического соседа из лексической двадцатки. Нужны два разных предшествующих коммита с этой парой файлов. Условие сработало на пяти задачах, изменило три пятёрки и не изменило ни одну оценку. Порог в один коммит изменил 14 пятёрок, также без выигрыша. Лексическая двадцатка покрывала в среднем 59,72% правильных файлов по задачам. [Зафиксированные прогнозы](selection.json) · [Оценки](results.json).

Во втором опыте кандидат должен находиться **за пределами** лексической двадцатки. Берём либо два независимых по SHA исторических эпизода совместного редактирования с якорем, либо один эпизод, где также присутствует другой файл из первых четырёх кандидатов поиска. Здесь разные SHA обозначают разные коммиты; статистической независимости коммитов мы не предполагаем. Из допущенных файлов выбираем наибольшую сумму 1/(m−1), где m — размер старого изменения. При отсутствии подтверждения сохраняем прежний ответ. Это исследовательское расширение было зафиксировано до оценки его прогнозов на той же панели. [Постановка расширения](EXPANSION_RU.md) · [Зафиксированные ответы](expanded-seal.json).

| Пять новых файлов, 54 задачи | Recall@5 | Hit@5 | MRR@5 | Изменившиеся пятёрки относительно Lexical |
|---|---:|---:|---:|---:|
| Опубликованный Lexical | 48,92% | 59,26% | 0,435 | 0 |
| Допустить любой внешний исторический эпизод | 47,69% | 59,26% | 0,435 | 20 |
| Требовать два эпизода | 49,54% | 61,11% | 0,439 | 5 |
| Два эпизода либо подтверждение другим файлом | **50,46%** | **61,11%** | **0,439** | 12 |
| Та же возможность замены, выбирать по популярности | 48,92% | 59,26% | 0,435 | 12 |

Полнота выросла в двух задачах и осталась прежней в 52. У Caddy удалось вернуть файл тестов конфигурации, у etcd — файл регистрации возможностей. В первом случае получено дополнительно ½, во втором ⅓ локального Recall@5. Сумма этих изменений, делённая на 54, даёт +1,54 п.п.; 95% парный интервал с перевыборкой репозиториев [0,00; +4,17]. Из 38 пар «задача — эталонный файл», недостающих в лексическом списке, какой-либо исторический сосед мог покрыть только три. На тех же 12 задачах равновероятный выбор одного из 74 допустимых по правилу кандидатов даёт в ожидании +0,69 п.п. против исходного Lexical; вероятность получить хотя бы наблюдаемый результат при этом условном случайном выборе 0,201. Это проверка выбора файла внутри уже отобранных групп. [Поштучные результаты](expanded-graded.json.gz) · [Точное условное распределение](conditional-control.json).

**Исходные позиции авторского поиска.** Если уже известный якорь занимает место в пятёрке, сохраняем фактические первые четыре позиции автора. Сам якорь никогда не выступает вторым подтверждением. Результат расширения — 41,20% против 43,36%, разность −2,16 п.п. [−6,55; +1,67], одна задача улучшилась, две ухудшились. Помещение якоря в список меняет сразу состав первых четырёх подтверждающих адресов, исключённых кандидатов и цену пятого места. Приписывать изменение знака одному из этих факторов в отдельности пока нельзя. Исходные оценки Lexical сверены с авторскими во всех 54 задачах. [План проверки](ORIGINAL_RU.md) · [Результаты](original-results.json).

## Что меняется при замене поисковой системы

Скачали опубликованные ранжирования Oko и CodeNib и воспроизвели их исходные средние Recall@5 на полном наборе из 58 задач с точностью округления авторских таблиц. Затем использовали одну и ту же подвыборку из 54 запросов, пять новых адресов и неизменное правило расширения. Для Oko три прогона сначала усреднены внутри одной задачи. Метрика ниже — средняя по задачам доля всех эталонных файлов в первых пяти позициях. [Авторская документация внешних сравнений](https://github.com/eyuansu62/agent-retrieval-bench/blob/9e4d68937f29d5967afd62f4f6a24c1478298133/docs/community_results.md) · [Квитанция источников](community-seal.json).

Изменение того же компонента у Oko составило −0,62, +1,23 и +1,23 п.п. в отдельных прогонах. CodeNib Graph Expansion индексирует полный исходный код. Остальным вариантам CodeNib достаточно выпущенного корпуса, в нашем дополнении дополнительно используется прошлое Git. Сам факт, что сочетание Lexical с историей превосходит CodeNib Dense на 7,41 п.п., складывается из исходной силы Lexical и добавки истории. Авторы бенчмарка также оценивали Qwen3-Embedding; выпущенный архив v2 edit2ripple содержит поштучные таблицы Lexical, RepoMap и BM25. Для опубликованных моделей Qwen исходные поштучные ранги этого трека в проверенных материалах отсутствовали. Заявление о новом SOTA не поддерживается. ## Воспроизведение

В этой папке `python grade.py`, `python expanded_grade.py`, `python original_budget.py grade`, `python community.py grade` и `python attribution.py` пересчитывают соответствующие таблицы. Первые две и условный контроль работают с включёнными проекциями. Для последней сверки авторских метрик два других оценщика используют исходный архив с SHA-256 из R54 по пути, указанному в [expand.py](expand.py). `python extract.py` заново получает публичную историю, `python verify_history.py` проверяет её через деревья Git и полные записи каталога. Для повторного извлечения внешних исходных рангов — `python community.py freeze`; адреса и контрольные суммы взяты из двух закреплённых выпусков. Файлы кода и тексты поручений в сохраняемую проекцию истории не входят.

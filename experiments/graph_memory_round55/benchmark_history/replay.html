    Retrospective reference

      Across 54 tasks, five additional reads give Recall@5 of 50.46% with Git evidence and 48.92% with lexical retrieval. The published five-slot budget counts a returned anchor. Under that budget the same rule scores 41.20% versus 43.36% for lexical retrieval (-2.16 percentage points).

      Method and limits

      Both policies preserve the first four lexical results. The history policy considers files outside the lexical top 20 that exist at the task’s base commit. A candidate qualifies after two shared commits or a shared commit with one of the first four results. Each witness contributes 1/(m−1), where m counts added or modified paths. Larger total weight wins, followed by more corroborated commits, recency and path order.

      Each case uses up to 64 pre-existing first-parent transitions including the base. Commits with 2–20 non-deleted paths provide evidence. The reference comes from the benchmark and is hidden until requested. This replay measures file retrieval on a previously studied panel. It does not execute a coding agent or measure completed fixes. All paths and evidence are embedded for offline use.

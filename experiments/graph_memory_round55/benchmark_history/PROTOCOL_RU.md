# Добавление истории Git к опубликованному поиску на edit2ripple

Используем все 54 ранее определённые задачи R54 с их замороженными базовыми коммитами и якорными файлами. Результат одного Lexical по этой панели известен. Новые списки будут зафиксированы до чтения меток экспериментальным оценщиком. Официальный архив v2 содержит индивидуальные top-20 для Lexical, RepoMap и BM25. Основной вопрос — улучшает ли граф истории лучший из этих трёх сравнимых методов на той же панели. Объём входных данных увеличивается за счёт истории Git, бюджет выдачи у всех равен пяти дополнительным адресам.

Для каждого base включаем изменения самого base и его первых родителей, всего до 64 переходов. Запрашиваем публичные объекты Git без содержимого файлов. Нет доступа к целевому PR, его будущим коммитам или списку правильных ответов в момент выбора. Изменения считаем относительно первого родителя, без распознавания переименования. Считаем эпизоды размером от 2 до 20 неделетированных путей всего репозитория. В каждом эпизоде с якорем кандидат получает один совместный голос и вес 1/(m−1). Для проверки хронологии сохраняем SHA, число путей и историю соучастников. При неполной истории явно отражаем глубину и оставляем все задачи в сравнении.

**Основной вариант.** Сохраняем первые четыре новых адреса Lexical. Среди оставшихся адресов его первой двадцатки ищем исторического соседа якоря с минимум двумя совместными коммитами. Выбираем наибольшую сумму весов, при равенстве сохраняем исходный лексический порядок. Переносим победителя на пятое место. Если кандидатов нет, оставляем исходную выдачу. Отдельно проверяем порог в один коммит и публикационные BM25 и RepoMap. Контроль популярности использует тот же метод, но считает посещения кандидата во всех допустимых коммитах, независимо от якоря. Дополнительный сопоставленный контроль применяет популярность только тогда, когда основной метод действительно нашёл кандидата. Заменяемая позиция и пространство кандидатов те же. Никакой донастройки по ответам.

**Исходы.** Средний по задачам Recall@5 с равным весом задачи, парная разность и 95% процентильный bootstrap по целым репозиториям (20 000, seed 55031). Дополнительно Hit@5, MRR@5, число меняющихся пятёрок, выигрыши/потери, случаи с 0/1/2+ свидетельствами и полнота кандидатов. Проверка касается переупорядочения существующих предложений после одной показанной правки. Результат не измеряет успешность исправления. При недоступном источнике воспроизводим исходную выдачу; указываем число таких задач.

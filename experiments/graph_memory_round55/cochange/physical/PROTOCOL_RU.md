# Физическая стоимость обслуживания рейтинга

До измерения времени и инструкций VM были известны логические числа запросов и строк. Проверяем все 3 023 последующих изменения шести репозиториев из основного протокола, окно 32, K=8. Основное физическое сравнение — partial8 против classic9 при равном объёме полезных данных. Испытываем также classic8, partial12 и classic13, без выбора проектов или событий по эффекту. Отдельная база и экземпляр контроллера на каждый запуск, те же алгоритмы, тот же индекс и входной поток. Прогрев графа по первым 64 изменениям выполняется одинаково, холодный запрос непрогретого контроллера регистрируется отдельно.

Основной таймер измеряет общее время после холодной инициализации: учёт рёбер и кандидатов в Python, запись новых баллов в SQLite, поддержание границы и любые упорядоченные чтения до заполнения выдачи, commit. Снимок результата каждого шага сохраняем для сверки с независимым полным расчётом после остановки таймера. Источник уже прочитан в память. Здесь нет модели, сетевых обращений, парсинга Git или скоринга эталона под таймером. Отдельный инструментированный повтор считает время только упорядоченных SQL SELECT от вызова execute до завершения fetchall. Контроль с нативной sqlite3_stmt_status считает реальные VM_STEP, FULLSCAN_STEP и SORT для этих же запросов и проверяет все результаты на отдельном читающем соединении после фиксации обновлений. Это логическая работа SQLite, не число дисковых чтений.

Режимы — SQLite in-memory и SQLite в локальном временном файле на D с WAL и synchronous=FULL. В последнем режиме результат фиксируется после каждого коммита; страницы ОС не сбрасываются. Одна техническая разминка каждого метода, затем 7 блоков, каждый содержит все шесть проектов и пять политик в фиксированно перемешанном порядке. Первичная величина — медиана сумм времён шести проектов каждого блока, дополнительно парные разности и число блоков по направлению выигрыша. Показываем раздельно индексную часть, исходный журнал предсказаний не входит в тест времени. Настройка, генерация эталона, верификация, завершающий checkpoint и удаление только созданных временных файлов исключены. Наращивать число запусков после просмотра результата не планируется.

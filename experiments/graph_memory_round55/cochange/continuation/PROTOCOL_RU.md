# Отложенная проверка локальной истории связей

Предыдущая выборка R55 выявила преимущество локального совместного изменения над глобальной частотой после получения одного известного пути. Проверяем переносимость на независимые от той выборки истории attrs/attrs, pytest-dev/pytest, pypa/pip, pallets/flask, encode/httpx и python-jsonschema/jsonschema. Выбор зафиксирован до получения SHA и изменений. Для каждого проекта фиксируем публичный HEAD, до 576 первых родительских переходов и используем входной формат, отсечение >64 Python-файлов, первые 64 коммита прогрева, хронологический порядок, ID по первому появлению и бюджет K=8 из основного эксперимента. Первичная единица агрегации — коммит, обязательно даём отдельные результаты и среднюю разность по проектам.

Для многофайловой правки одну подсказку выбирает индекс SHA modulo число путей, остальные должны быть предсказаны без доступа к их именам. Вторичная проверка усредняет по **всем** возможным подсказкам одного коммита с одинаковым весом каждой, а потом по коммитам. Файлы, которых в прошлом ещё не было, остаются в знаменателе. Основной накопительный контроль — число совместных изменений за все прошлые наблюдаемые коммиты, включая прогрев. Это история от начала сохранённого префикса, а не вся история проекта. Второй ключ для всех методов — частота целевого файла за последние 32 коммита, затем ID. Контроли — частота, глобальная степень W32, локальные рёбра W16 и W32, вся накопленная история связей. Нормализации за размер транзакции рассмотрены в [G1c](../../../graph_memory_round1/git_prediction/EXPOSURE_PROTOCOL.md), здесь сохраняется сырой вес совместного изменения.

Дополнительная гипотеза — старение связей определяется числом возможностей увидеть тот же путь. Если изменения несвязанных частей проекта многочисленны, W32 может быстро вытеснить редкие наблюдения. Если путь активно меняется, старые связи могут стать неактуальными. Проверяем последние 8 **коммитов с данным якорем**, включая однофайловые события как возможность изменения без повторения связи. При равном числе хранимых записей контроль выбирает до 8 исторических событий этого же якоря, равномерно по фиксированному хеш-приоритету SHA (bottom-k), даже если они относятся к далёкому прошлому. Основные направленные сравнения — локальные W32 против частоты, W32 против накопительной ассоциации, последние 8 возможностей против накопительной ассоциации. Остальные вторичны, все результаты публикуются. Первичная метрика macro Recall@8 по коммитам, дополнительно Hit@8, результат при полном переборе якорей и среднее число просмотренных записей для запроса. Удерживаем одинаковые кандидаты, tie-break и выдаваемый бюджет. Результаты относятся к предсказуемости путей при заданном якоре. Для новизны и успеха LLM нужны отдельные сравнения.

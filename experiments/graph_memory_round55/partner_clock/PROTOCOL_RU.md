# Когда устаревает связь между двумя файлами

Проверяем, можно ли улучшить поиск следующего файла для чтения по наблюдаемым опровержениям прежней связи. Известен один случайно раскрытый участник коммита. Остальные изменённые Python-файлы служат целями рекомендации. Эту постановку использовали в первой серии и в исследованиях evolutionary coupling. Внутри транзакции порядок работы разработчика неизвестен.

**Механизм.** Храним одно ребро для пары, которая менялась совместно. Удельный голос исторического коммита из m файлов равен 1/(m−1). Между голосами вес снижается вдвое через h наблюдений, когда менялся ровно один из двух файлов. Такие наблюдения предоставляют возможность перепроверить ребро. Новые голоса прибавляются после дисконтирования. Количество возможностей со времени свидетельства равно ΔN(a)+ΔN(b)−2ΔN(a,b). Это позволяет лениво обновлять ребро без обхода соседей. Счётчики используют только коммиты с 1–20 затронутыми Python-файлами, согласно заранее выбранной области применимости. Изменение обоих файлов поддерживает ребро даже при наличии других участников такого коммита.

**Контроли.** Одна и та же текущая совокупность доступных кандидатов, prior из путей и частот и масштаб исторической массы, как в G1. Включаем prior без графа, накопленный удельный голос, вес с поправкой на вероятность раскрытия якоря, Jaccard ассоциаций, нормировку Ochiai, дисконтирование по числу всех коммитов и только по изменениям якоря. Дополнительный контроль использует только изменения кандидата. Для текущих доступных кандидатов сумма весов любого графа приводится к сумме весов накопленного удельного голоса, после чего добавляется одинаковый prior с коэффициентом 4. Ранжирование по сумме, затем по частоте и пути. Все результаты ограничены известными в прошлом существующими путями. Цели, недостижимые в момент рекомендации, входят в знаменатель.

**Выбор параметров и проверка.** На двух старых панелях по 10 Git-проектов выбираем один h на метод по максимальному среднему по проектам Recall@5. Сетка h = 1, 2, 4, 8, 16, 32, 64, 128. При равенстве выбираем меньший h. Контролем для первичного сравнения станет лучший на этих панелях метод из всех перечисленных, кроме предлагаемого. Фиксируем параметры и контроль отдельной квитанцией до оценки следующей панели. Поиск новых панелей после получения оценок в основной тест не входит.

**Независимая панель.** Заранее фиксируем открытые проекты pallets/itsdangerous, python-hyper/h2, facelessuser/soupsieve, tqdm/tqdm, dateutil/dateutil, pytest-dev/iniconfig, python-semver/python-semver, pyca/bcrypt, marshmallow-code/apispec, agronholm/anyio. Некоторые организации участвовали в прежних опытах с другими проектами. Берём до 400 последовательных переходов по первому родителю с верхней ревизией публичной основной ветки. Первый коммит в извлечённом отрезке используется только как граница. Исходное состояние памяти пустое, как в G1. Первая половина переходов пополняет память, метрики рассчитываем во второй половине на коммитах с 2–20 затронутыми Python-файлами. Изменения определяются относительно первого родителя, переименование считается удалением и добавлением. Если проект недоступен или во второй половине нет пригодных коммитов, указываем это рядом с результатами. Новым проектом выбывший не заменяется.

**Проверка гипотезы.** Основной показатель — средний по репозиториям Recall@5 с равным весом каждого коммита внутри проекта. Парный контраст с выбранным контролем, двусторонний 95% процентильный bootstrap по целым репозиториям (20 000 повторов, seed 55013), знаки различий, точная двусторонняя знаковая проверка по ненулевым разностям. Вторичные — Hit@1 и MRR@5, результаты по каждому проекту, доля доступных целей. В обучении и тесте сначала выдаём рекомендации, затем принимаем текущие цели. Публикуем проекцию входных данных, ранги и метрики. Отдельная проверка на открытых объектах Git и прямая сумма по эпизодам проверят извлечение и ленивое вычисление. Эта проверка измеряет рекомендации по файлам. Исполняемое решение задачи агентом требует отдельного опыта.

Предшествующие работы изучают ассоциации файлов, фильтрацию больших транзакций и временное дисконтирование.

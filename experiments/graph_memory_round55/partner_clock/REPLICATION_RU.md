# Независимая проверка асимметричного старения связи

После получения результатов основной внешней панели фиксируем новую проверку. Основная гипотеза о штрафе за раздельные изменения обоих концов ребра не подтвердилась. Лучшим по Recall@5 на первой внешней панели стал ранее настроенный вариант, в котором ход времени зависит только от известного файла. Выбор этого варианта по уже просмотренной панели учитываем как поисковый. Ни один результат первой панели не входит в основную оценку репликации.

Гипотеза для следующей панели — anchor_8 имеет больший средний по проектам Recall@5, чем global_128. Прежние параметры, prior, набор кандидатов, обработка Git, иерархия усреднения и bootstrap остаются фиксированными. Дополнительно проверяем Hit@1, MRR@5, xor_16, unit и exposure. Мотив для асимметрии — агент уже знает якорный файл. Много самостоятельных правок возможного кандидата могут быть связаны с другими задачами и не опровергать зависимость, наблюдаемую при правке якоря.

Фиксированная внешняя выборка из десяти других репозиториев: python-attrs/cattrs, jaraco/path, tox-dev/filelock, pallets/werkzeug, aio-libs/yarl, python-rapidjson/python-rapidjson, beartype/beartype, pydantic/pydantic-settings, jcrist/msgspec, hukkin/tomli-w. Сохраняем до 400 переходов по первым родителям, половина служит прогревом памяти. Все проекты с наблюдаемой задачей имеют равный вес. Если транзакций нет или проект недоступен, сообщаем это и сохраняем исходный список. Инициирование второй проверки обусловлено вторичным результатом первой, поэтому не объединяем панели в одно заранее запланированное испытание.

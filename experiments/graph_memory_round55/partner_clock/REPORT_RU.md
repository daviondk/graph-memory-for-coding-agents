# По каким событиям должна стареть связь между двумя файлами

На 538 контрольных задачах новая мера старения по раздельным изменениям файлов дала 57,96% Recall@5 против 58,24% у обычного старения по коммитам. Разность −0,28 п.п., 95% ДИ [−1,61; +1,20]. Гипотеза состояла в том, что независимая правка каждого конца ребра служит поводом уменьшить доверие к прежней совместной правке. Доступные данные не подтверждают выигрыш от такого дисконтирования.

## Как устроена память

Задача моделирует решение агента после наблюдения одного файла изменения. Нужно предложить ещё пять путей. В момент прогноза доступны прошлые коммиты и один открытый путь. Каждый из остальных изменённых файлов текущего коммита входит в эталон, включая ранее неизвестные пути. Контролируем исходный лексический prior, пул кандидатов, суммарную массу графового сигнала и правило разрешения равенств. Окружение — CPU, Python, точное ранжирование по сохранённым счётчикам. [Зарегистрированная гипотеза](PROTOCOL_RU.md) · [Исходная задача и контроль первой серии](../../graph_memory_round1/git_prediction/TRANSFER_PROTOCOL.md).

Пусть оба файла участвовали в старом коммите из m файлов. Он добавляет вес 1/(m−1). После него число событий, в которых изменялся ровно один участник пары, равно ΔN(a)+ΔN(b)−2ΔN(a,b). За h таких событий вклад старого наблюдения уменьшается вдвое. Между двумя совместными коммитами всю сумму старых голосов можно умножать на один коэффициент, поскольку показатель складывается по последовательным интервалам. Поэтому ребро хранит предыдущую сумму и значения счётчиков. При обновлении учитываются только затронутые пары. При чтении можно восстановить вес по текущим счётчикам; просмотр всего репозитория или исходных эпизодов этому вычислению не требуется. Формула точна для выбранной меры, её предсказательная ценность проверяется отдельно. [Реализация](clock.py).

## Две проверки на новых проектах

На 19 прежних проектах и 887 запросах подобрали период полураспада каждой политики. Для одной из двадцати намеченных историй G1 отсутствовал успешный исходный снимок (pypa/cachecontrol), поэтому она не использовалась. Из зарегистрированных контролей сильнейшим оказался период в 128 коммитов. Вариант, учитывающий только изменения якоря, выбрал период в восемь таких изменений. Список проектов и контроль зафиксированы в Git до внешней оценки. На первой внешней панели получили 3 591 переход в десяти проектах; у pyca/bcrypt во второй половине не было подходящих многофайловых изменений Python. Оставшиеся девять проектов дали 538 задач. Средняя доля доступных целей составила 94,62%. [Параметры](selection.json) · [Первый внешний тест](external-results.json).

Каждый проект имеет одинаковый вес. Дополнительные Jaccard и Ochiai на первой панели дали 50,46% и 51,42% Recall@5. Основная разность XOR с контролем была положительной в трёх проектах, нулевой в одном и отрицательной в пяти. Точная двусторонняя проверка знаков p=0,727. Приблизительный знак эффекта зависит и от того, измеряем ли мы нахождение первого полезного файла или долю скрытых файлов в пятёрке.

Вторая панель была зарегистрирована **после** просмотра первой. Отдельно проверили вторичный результат — преимущество дисконтирования по одному якорю. Фиксированная модель прошла 721 задачу на десяти других проектах (3 682 перехода, средняя доступность целей 92,05%). Выигрыш относительно контроля составил +0,22 п.п., 95% ДИ [−0,18; +0,68], 3 выигрыша, 3 равенства и 4 потери по проектам. Для MRR@5 получено 53,52% против 53,06%. Обе панели поддерживают полезность истории по сравнению с приором. Данных для вывода об оптимальном счётчике старения пока мало. ## Что удалось проверить независимо

Вторая реализация восстановила списки изменений во всех 12 191 переходах 39 Git-проектов, сопоставила 293 231 оценку ребра с прямой суммой вкладов и пересчитала 17 151 ранжирование на 2 146 задачах. Все порядки с временным дисконтированием в этом аудите совпали. У накопительных контролей обнаружены три различия порядка на уровне машинного округления, одно из них меняет вторичный вектор метрик одного запроса. Сохранённые результаты отражают фактически выполненную реализацию. Ограничение идентичности пути — после удаления и появления того же пути старая связь может быть унаследована; первой внешней панели такие случаи не касались. 94 прежних показателя первой серии воспроизведены точно. [Независимый аудит](independent-audit.json) · [Код проверки](independent_audit.py).

# Исходный компонент MemTrace на зафиксированных парах правок

До запуска исходного SQL-компонента фиксируем Git SHA 5508f8be81025d8aa90726b1e06aef4ea484e577 из официального репозитория, указанного в статье MemTrace. Рабочая копия содержит только проверенные по Git blob файлы публичного исходного кода. Данные испытания — уже отобранные подтверждённые замены и прежние целые блоки в R40/span_updates. Из прошлой работы известны численные показатели файловой и интервальной инвалидации; данное исследование проверяет соответствие реальной опубликованной реализации. Немаскированные содержимое, команды и тексты трасс не нужны.

Контракт file-only обновления: каждую строковую единицу из прежнего выбранного пакета представляем как EvidenceDraft типа CODE_OBSERVATION, canonical_entity_id = file:<необратимый ID источника>, отдельная semantic_role для каждой единицы. Указывает предыдущую ревизию, ту же ветку, CURRENT и синтетическую полезную нагрузку из ID и координат. На подтверждённом изменении подаём только changed_entities=(file:<ID>,) и новый идентификатор ревизии. До и после проверяем устойчивость каждого материала через реальную SemanticStore.advance_workspace_revision и v2_semantic_evidence, а также наличие INVALIDATED_BY у закрытых единиц. Ни строковые границы, ни семантическая эквивалентность содержания не входят в changed_entities этой операции. Это прямое измерение при одинаковом файле-событии и одинаковых целых блоках. Если настоящая система располагает отдельными точными изменившимися символами, это другая информативность входа и отдельный режим.

Первыми вызываем две независимые функции из исходных unit tests авторов с локальной временной SQLite. Отдельный диагностический пример проверяет file-vs-symbol изменение и сохраняемость записей в БД. На всей панели real changes сравниваем предикат _entity_affected на всех прежних блоках с файловым контролем R40. Для реального SQL заранее берём первые 32 основных и 32 дополнительных события по SHA-256 rid+receipt, без подбора исходов. Если медианное время SQL на событие меньше 0,5 с, рабочий диск после этих 64 не ограничен и новые временные таблицы могут быть удалены безопасно, распространяем SQL на остальные 2632 в том же порядке. Наблюдения независимы, временная БД и страницы на D одноразовые.

Считаем число сохранённых неизменных целых пакетов, число закрытых блоков и байты как стоимость повторного доступа, отдельно в основной и дополнительной группе. Интервальный контроль признаётся проверяемым полным повторным использованием только при неизменном порядке и составе и нуле несовпадений исходного текста перенесённых выбранных строк изменённого пути из независимого аудита R40/span_updates. Для остальных путей полный снимок текста в событии отсутствует. Разности по пакетам сообщаем как доли событий и среднюю по задачам с парным bootstrap целых задач. Различаем частоту повторного использования, перепроверку записи и downstream качество исправления. Новый запуск агента или полный челночный запрос MemTrace сюда не входит.

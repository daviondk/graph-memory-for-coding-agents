# Материализованный вид наблюдений непосредственно перед действием редактора

Основная гипотеза состоит в том, что агент чаще выбирает для изменения путь, представленный в активном пакете памяти, чем при равномерном выборе пути из того же доступного пула. Поэтому реальный выбор пути чаще потребует изменения ответа. Эксперимент проверяет профиль отзывов источников при редактировании. Используем зарегистрированные расписания и видимые длины/адреса строк Handoff Debt из R38/edit_ready. Уже известны число расписаний и состав типов операций. Данные R38 отобраны вокруг подходящих подтверждённых замен после чтения того же файла. Сравнение относится только к этим окнам; это существенное ограничение при переносе на все обращения реальных агентов.

Состояние обновляется по порядку событий. reset уничтожает всё. view оставляет последний показ данного пути, увеличивает число его показов в текущем периоде доступности. Любой invalidate/snapshot+invalidate отзывает путь. Прогноз строится из состояния непосредственно перед событием и не получает имя предстоящего пути, тип будущего результата, целевые строки, успешность или содержимое текста. Отдельный оценщик получает фактический путь текущего действия и классификацию события из ранее подписанных записей R37 по (run,event). Основная единица — начало попытки записи (write_start), подтверждённые и остальные попытки также показаны отдельно. Другие типы инвалидации очищают состояние и не входят в знаменатель попыток. Абсолютные пути, команды, тела и эталонный текст не нужны.

Для активного пути используем только последнее видимое пронумерованное чтение. Делим его на непересекающиеся блоки не более восьми последовательных строк, разрываем на пропусках номеров. Цена блока — сумма исходных длин строк UTF-8 плюс 1 байт для каждого подтверждённого внутреннего разделителя LF. Границы номера/хеши в метаданных не тарифицируются. Это полезная нагрузка байтов, не стоимость хранения SQLite и не токены модели. Фиксированный порядок — последнее событие чтения в порядке убывания, затем хеш пути и начальная строка. При рангах r=0,1,… целая полезность равна 1 + 32 min(8,число чтений пути с момента появления) + floor(128/(r+1)). Запоминаем параметры состояния и никогда не пересчитываем порядок или полезности переживших узлов при сравнении двух отзывов. Бюджет 2 048 байт, порог защищённого префикса 1 024. При конце префикса используем стабильный точный целочисленный рюкзак. Для каждого возможного пути проверим реальную повторную оптимизацию, равенство результата, достаточный сертификат первого барьера и точное условие H'⊆P при сохранении всех выбранных.

Основной контраст заранее определён в main (предшественники и основной набор), на попытках с минимум двумя живыми путями и фактическим путём в пуле: доля изменившихся пакетов после настоящей записи минус математическое ожидание после равномерного выбора одного активного пути, включая сам фактический путь. Сравниваем в идентичном замороженном состоянии. Вторично фиксируем воспроизводимую одиночную жеребьёвку SHA-256 «r40-natural-path-v1|run|event» по упорядоченным хешам. Для пустого пула контрольная операция пуста. Публикуем все попытки, оба исходных набора отдельно, одиночные пути, отсутствующий фактический путь, пустые пулы, подтверждения записи, реальные и контрольные доли повторного использования, состав пула. Для основного контраста усредняем сначала операции внутри issue, затем равновзвешенные issue. Интервал 95% — 10 000 кластерных bootstrap-перевыборок issue с seed 403901 (если доступно не менее двух разных issue). Пять репозиториев не дают репрезентативной выборки всей разработки. Для подтверждения работы алгоритма будут сохранены число попыток и индивидуальные результаты; латентность из прежнего нативного эксперимента сюда не переносится. Итоги до фиксации этого протокола не вычислялись.

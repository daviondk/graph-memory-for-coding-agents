# Когда кодовому агенту действительно удаётся сохранить прежний пакет памяти

При отзыве файла, наблюдавшегося в текущем контексте, прежний пакет удалось безопасно использовать **6 раз из 2 820 (0,21%)**. Если включить записи в путь, которого уже нет в памяти, число вырастает до 711 из 3 525 (20,17%). Из этих 711 случаев 705 объясняются отсутствием пути, в том числе 638 пустыми состояниями. Эти числа измеряют возможность получить прежний ответ при изменении источника. Время работы и качество решения задачи в этом исследовании не измерялись.

## Материал и процедура

Проанализированы 1 324 доступных расписания взаимодействий кодовых агентов, 37 задач (issue), пять репозиториев. Материал происходит из Handoff Debt. Предыдущая обработка отбирала видимые окна вокруг подтверждённой замены после чтения того же файла. Отбор повышает вероятность присутствия редактируемого пути. Поэтому доли применимы к опубликованным исследованным окнам. В каждой записи планировщик видит только хеш пути, порядок чтений и интервалы с фактическими длинами строк. На пропуске или непрозрачном участке память очищается. На каждом отзыве пути планировщик замораживает ранги, цены и целочисленные полезности до получения пути и результата операции. [Handoff Debt, авторская публикация](https://aclanthology.org/2026.emnlp-main.738/)

На 4 413 событиях отзыва зафиксировано состояние. Оценщик выделил 3 525 начал попытки записи. Ещё 879 квитанций редактора и 9 прочих событий влияли на состояние, но исключались из числа попыток. Из фрагментов не более восьми последовательных строк подбирался пакет до 2 048 байт UTF-8. Префикс до 1 024 байт обязателен, хвост выбирается точной целочисленной оптимизацией. Повторные и недавние просмотры получают больший вес. Это фиксированная политика для проверки обслуживания памяти. Оценки обученного на ISETrace ранжировщика здесь не использовались.

Для каждого состояния сравнивали полный пересчёт после отзыва фактического пути и после отзыва каждого возможного активного пути. Среднее по второму набору даёт точное ожидание условного равномерного контроля. В пустом состоянии операция контроля ничего не меняет. Сохранена также воспроизводимая одиночная жеребьёвка. Первичный контраст зарегистрирован заранее на основной группе с несколькими активными путями и присутствующим фактическим путём. В интервале неопределённости единица повторной выборки — задача. Сначала усредняются расхождения внутри задачи.

При контрольном выборе по одному фиксированному жребию изменилось 2 879 пакетов. Основной набор содержит 864 попытки и 695 изменений, дополнительный — 2 661 и 2 119. Из 3 168 попыток с подтверждением замены в журнале изменилось 2 720 пакетов. Из девяти с подтверждением другого типа изменился один. Среди 348 попыток без связанной квитанции изменились 93. Отсутствие квитанции не устанавливает, завершилась ли запись ошибкой.

Точный сертификат сверен с полным расчётом для каждого из 3 101 возможных отзывов в соответствующих состояниях. Вместе с 3 525 исходными пакетами это 6 626 вызовов решателя. Независимый разреженный целочисленный алгоритм проверил тот же набор и парный результат. Простой достаточный сертификат разрешил безопасное использование пакета на всех шести фактических отзывах присутствующего пути с неизменным оптимумом.

## Интерпретация для статьи

В экспериментах на ISETrace источником служил один узел/фрагмент, здесь отзыв одного файла одновременно убирает все его видимые блоки. Дополнительно различаются распределение событий, веса и единицы бюджета. Нельзя приписать расхождение между корпусами одному из этих факторов. Проверка показывает, что доля повторного использования сильно зависит от состава живого пула и определения источника. Для режима «только что прочитан один изменяемый файл» подходящая контрольная операция почти всегда требует пересчёта. Следующая честная проверка — проспективный поток всех чтений и записей без отбора вокруг успешной замены, с отзывом только действительно изменённых диапазонов и заранее заданной единицей агрегации.

# Обновление материализованного набора после подтверждённой правки

Проверяем на тех же замороженных предшествующих пакетах Handoff Debt, что в natural_invalidations. Заранее известен низкий повторный доступ при отзыве всего присутствующего файла. Первичный исход — доля предшествующих пакетов, для которых после подтверждённой правки присутствующего файла можно вернуть в точности те же идентификаторы наблюдений в том же порядке, обновив координаты. Первичное сравнение — интервальная инвалидация против отзыва файла целиком на одной и той же подходящей правке. Единица — подтверждённое событие; основная группа predecessors/main_takeovers, с чистым наблюдаемым префиксом, присутствующим путём, установленной из видимой квитанции локализацией замены. Числитель, знаменатель и равновзвешенную по задаче парную разность с 95% issue bootstrap (10000, seed 401113) сообщим отдельно. Будущий просмотр, успех решения и закрытые версии файла в отбор выдачи не поступают.

Для каждого блока из ранее показанных строк сохраняем идентификатор наблюдения. Отзываем блоки с диапазоном, пересекающим включительно любой адрес между начальной и последней затронутыми строками. Строки ниже подтверждённой замены переводим на новое смещение по числу переводов строки. Стоимость текста и полезность уцелевшего блока прежние. Оставляем остальные пути. Полный расчёт использует тот же фиксированный порядок, целочисленную полезность, бюджет 2 048 **байт** и порог 1 024. Новые строки явно не добавляем, так как предмет измерения — обслуживание видов уже полученных наблюдений. Вторичные показатели — буквальное сохранение всех адресов, сохранение части ранее отобранных байтов, точность сертификата и доля обращений с достаточной видимой квитанцией среди всех попыток. Выделяем правки с изменением числа строк. База на всех попытках — прежний отзыв всего пути. При отсутствии чистого подходящего свидетельства оба режима применяют консервативный полный отзыв. Момент измерения — после успешной квитанции, до неё память изменяемого пути нельзя безопасно выдавать.

Для независимой проверки загружаем полные служебные версии файла только в оценщике и сравниваем хеш наблюдённой строки до и после переноса у каждого сохранившегося блока рассматриваемого пути. Публикуем все расхождения и отдельно учитываем заранее устаревшую строку. Даже единичное расхождение требует ограничить утверждение о корректности видимой квитанции либо отдельно проверить источник. Сохраняем только идентификаторы, диапазоны, счётчики и хеши. Выборка правок повторно использует корпус, по которому получены гипотезы, и не даёт независимой оценки выигрыша для всей разработки.

# Реплика и проверка

Рабочий каталог — `D:/CodexResearch/x20-bench-workspace/work/graph_memory_round40/guarded_updates`. Полный прогон использовал CPython 3.12.13, NumPy 2.5.5 и PyArrow 22.0.0. Короткая независимая проверка ниже работает и на CPython 3.14 со стандартной библиотекой. Все команды запускают только исследовательские скрипты из указанного каталога. Архивные действия парсятся как данные.

## Проверить готовые результаты

```powershell
python -B verify.py
Get-FileHash -Algorithm SHA256 -LiteralPath manifest.json
```

Проверка сравнивает файлы с SHA256 в manifest, прослеживает фиксацию прогнозов, заново строит по спискам допустимых блоков 8 088 оптимальных ответов, сверяет стоимость со свидетельствами по каждой квитанции, исходы отдельных issue и агрегированные эффекты. Этот решатель хранит лучшие пары «полезность, маска» отдельно для каждой точной суммы байтов. При равной полезности выбирается наименьшая битовая маска. Он не импортирует основной решатель и не зависит от NumPy. Другой независимый проход ищет ближайшие границы по каждому отозванному блоку другого пути в обе стороны от правки.

## Полный прогон из закреплённых источников

```powershell
$runner = 'D:/CodexResearch/x20-isetrace-e5-gpu/venv/Scripts/python.exe'
& $runner -B plan.py
& $runner -B select_updates.py
& $runner -B check_text.py
& $runner -B audit_geometry.py
& $runner -B analyze.py
python -B verify.py
```

1. `plan.py` восстанавливает просмотры и только допустимые кандидаты на всех 4 413 моментах. Получает лишь записи уже наблюдённых просмотров из сырых событий. `guarded-plans.json.gz` содержит для каждого разрешённого блока прежний идентификатор, хеш пути, начало, конец, размер, обновлённый вес и идентификатор последнего видимого просмотра. Отозванные блоки имеют прежний идентификатор, причину и идентификатор просмотра. `plan-seal.json` закрепляет SHA.
2. `select_updates.py` присоединяет уже опубликованные идентификаторы и геометрию подтверждённых замен, группу issue и исходные затраты. `selections.json.gz` содержит три новых списка на правку, координаты, контроль затрат и флаги совпадения. Новые списки запечатываются в `selection-seal.json` до открытия пар before/after этим оценщиком.
3. `check_text.py` открывает только необходимые исходные просмотры, запросы и квитанции. Сверяет полную операцию, затем сравнивает строки и разделители. `checked-text.json.gz` содержит количества по каждой правке, `text-check.json` — суммы и SHA. Полные тексты файлов и имена исходных путей не сохраняются.
4. `audit_geometry.py` отдельно сверяет начало, конец и дельту каждой правки с позицией уникальной замены в исходном полном файле. Затем `analyze.py` записывает `results.json`, включая 37 кластеров issue с основными счётчиками, заранее выбранные срезы, числители, знаменатели, цену фильтра и интервалы.
5. `verify.py` проверяет реплику. Первичное создание подписанного файла `replication.json` выполнялось командой `python -B verify.py --seal`. Финальная проверка использует эту запись и весь manifest.

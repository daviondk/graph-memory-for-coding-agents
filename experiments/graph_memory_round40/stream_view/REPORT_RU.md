# Потоковый запрос к памяти при поступлении сообщений

На 40 запросах ISETrace восстановили последовательность открытия свидетельств по исходным индексам сообщений. После каждого из **2 336 обновлений** инкрементальный оператор дал тот же упорядоченный пакет, что и независимый полный расчёт рюкзака. В 1 119 шагах пакет менялся. Полная перестройка расширенной таблицы потребовалась в 564 шагах, включая инициализацию. На остальных 1 772 шагах удалось обновить представление добавлением новых узлов. На одном CPU измеренная суммарная стоимость оператора уменьшилась **в 3,88 раза**, парный 95%-й интервал по 40 запросам **[3,16; 4,83]**. Все 40 конечных выдач по отдельности совпали с подписанными списками исходного читателя. [Протокол](PROTOCOL_RU.md) · [Результаты](results.json) · [Верификатор](verify.py)

**Как устроен оператор.** Для каждой возможной вместимости остаточного бюджета сохраняются два значения — максимальная целая полезность и битовая маска выбранных узлов. При поступлении узла i со стоимостью c и полезностью u обратный обход вместимостей сравнивает прежнее решение и решение для вместимости k−c вместе с i. При равенстве выигрывает меньшая целая маска в общем порядке кандидатов. Поэтому итог не зависит от того, в какой момент пришёл узел. Если изменяется обязательный префикс, хвост пересчитывается с новым бюджетом. Полное вычисление рассматривает узлы сразу в порядке ранга, выбирая ранее достигнутое решение при ничьей. Индукция по поступившим узлам даёт эквивалентность обоих решений на каждой вместимости. Одна добавленная единица при неизменном префиксе требует O(C·w) времени в худшем случае для C значений вместимости и w машинных слов битовой маски. У полной перестройки стоимость пропорциональна ещё и размеру активного пула. [Реализация C++](stream.cpp)

Измерены пять повторений каждой траектории с чередованием трёх вариантов. Время включает поиск префикса, обслуживание таблицы и извлечение ответа для всех сообщений в C++. Указанная память охватывает полезную нагрузку текущих двух массивов и исключает аллокатор, SQLite, входы и журнал. Исходные селекторные баллы, доступные на полном графе, зафиксированы. Оценка показывает цену поддержки материализованного результата при этом условии. Будущий эксперимент с меняющимися эмбеддингами, рангами и потоково вычисленными признаками требует отдельной проверки. Порядок поступления в первой строке взят из поля message_index реальных исполнений синтетических заданий ISETrace. Выбор сценариев и пределы интерпретации перечислены в протоколе. Независимый полный перебор подтвердил 6 201 результат на 650 малых примерах с нулевыми полезностями и ничьими. [Все пакеты](packets.json.gz) · [Поштучные замеры](outcomes.json.gz)

Для повтора использовать C++17 с O3, собрать stream.cpp в stream.dll либо stream.so и запустить `python -B run.py` с NumPy рядом с graph_memory_round39. Для сверки сохранённых результатов достаточно `python -B verify.py` со стандартной библиотекой Python.

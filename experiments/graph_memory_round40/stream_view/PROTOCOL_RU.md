# Потоковое обслуживание ограниченного представления

Одноразовая проверка source_arrival испытана при независимых открытиях источника на одном снимке. Здесь регистрируем отдельное испытание до вычисления исходов последовательной обработки. В каждом из всех 40 сохранённых запросов SQLite добавляем источники целыми сообщениями по исходному position = message_index. Все поля одного сообщения поступают атомарно. Воспроизводим тождество упорядоченного результата после каждого добавления с C++-расчётом с нуля. Стоимости, ранги и Q32-полезности фиксированы на снимке полной траектории. Хронология предложения источников наблюдалась в данных. Эта проверка оператора материализации не претендует на оценку онлайн-модели, которой доступны будущие признаки.

Предлагаемый оператор хранит для каждой вместимости остаточного бюджета оптимальное значение и компактное множество идентификаторов оптимального хвоста. При сохранении обязательного префикса обновляем все вместимости однократным обратным проходом на каждый новый узел. При ничьей выбираем лексикографически наименьшую маску, начиная с наименее приоритетного узла в общем стабильном порядке. Когда новый узел меняет обязательный префикс либо его вместимость, перестраиваем состояние. Проверяем также последовательность хешированного порядка тех же сообщений как анализ чувствительности. Измерения на каждой траектории проводятся в паре с чередованием порядка, 5 повторений после разогрева. Основной масштаб — суммарное время от уже готовых массивов новой партии до выдачи на едином CPU, парный bootstrap по целым запросам, 10 000 перевыборок, seed 405311. Загрузка SQLite, кодирование, построение графа и обучение за пределами этого интервала.

Основной контроль — исходный решатель рюкзака со строгим обновлением, хранящий историю выбора только для одного полного вычисления и выбрасывающий её. Вторичный контроль — предлагаемый оператор, который пересобирает свою расширенную таблицу после каждого сообщения. Стоимость инициализации структур памяти, перестроения и ответа учитываем для всех добавлений. Отдельно сообщаем число обновлений, обязательных перестроений, изменившихся выдач, максимум полезной нагрузки таблицы. На малых фиксированных примерах с нулями и ничьими сверяем выбор после каждого шага независимым полным перебором.

# Происхождение несовпадающих строк Handoff Debt

До нового разбора raw известны общие числа из R40/span_updates: 8 578 исходных расхождений на 74 241 строке и 428 на 22 466 строках полностью повторно использованных пакетов. Единица — конкретная пара просмотр–правка и перенесённый номер строки целевого файла. Повтор одного адреса в разных парах входит с исходным весом. На старте фиксируем входной SHA-256 журнала и split по полным issue: сортируем различные issue по SHA256 строки r40-view-fidelity|issue, каждый третий с позиции 0 отправляем в holdout. Остальные issue образуют диагностическую часть. Имена issue, пути, текст файлов и инструментальных команд в новых артефактах не сохраняем.

Гипотезы конкурируют и могут сосуществовать. Ошибка выделения строк предсказывает расхождение нового независимого разбора пронумерованного raw-view по заголовку пути с подписанным R38. Ошибка координат предсказывает точное совпадение содержимого на другом номере и общий ненулевой сдвиг нескольких соседних уникальных строк. Преобразование форматирования предсказывает совпадение после заранее определённых пробельных нормализаций/табуляции при том же номере. Ограничение длины, вырезка или очистка архивного поля предсказывает повторяющуюся границу длины у разных версий, явный синтаксический маркер, внезапное исчезновение хвоста или второй фрагмент, который выравнивается одним сдвигом. Расхождение последовательных версий предсказывает буквальное совпадение view с независимо доступной версией того же файла при отличии от before. Одна строка, которая встречается во многих местах, недостаточна для диагноза сдвига. Уберём из дифференциальных выводов совпадения пустых и повторяющихся строк без уникального соседнего контекста.

Отдельно проверяем сам источник адресов: актуальный последний view пути перед попыткой, идентификаторы действия и квитанции, имя редакторской операции, совпадение пути в заголовке и фактическое байтовое содержание visible с raw. Для before и after сравниваем длины и построчную разметку, проверяем изменение и перенос на уровне исходных байтов предоставленных полей. Если недоступно полное состояние, точный смысл редактирования и локализацию на диске не восстанавливаем. Проверяем только подписанные публичные архивные данные, архивные команды не выполняем.

До просмотра индивидуальных holdout-исходов фиксируем детектор на диагностических issue и сохраняем прогнозы. Допустимые признаки онлайн — индексы и диапазоны реально показанных строк, длины, признаки клиппинга/разрывов отображённого ответа и видимые числовые метаданные. Скрытые before/after, их длины и служебные маркеры вне display доступны только оценщику. Отдельно проверяем контроль «выдать только с проверенным авторитетным свидетельством строки» и указываем, требует ли он нового чтения либо специальных метаданных сервиса. Если после анализа диагностических issue понадобятся новые варианты, описываем их и фиксируем до градинга holdout. Учтём маски с пустой выдачей.

На всех строках и на выбранных строках полностью переиспользованных пакетов сообщим матрицы принятия/отзыва по точному совпадению с доступным before, число затронутых issue и ошибки на независимых issue. Нули на конечном holdout не дают универсальной гарантии. В отчёте явно разделим ошибки содержимого по предоставленным полям, неоднозначность адреса при обрезке и инструментально подтверждённую версионность.

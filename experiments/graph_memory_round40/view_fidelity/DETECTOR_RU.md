# Фиксация правила до открытия 13 отложенных issue

На 24 диагностических issue все 5 873 проблемные строки встретились дословно в том же before при ненулевом сдвиге, подтверждённом несколькими различными уникальными строками. Во всех 25 соответствующих просмотрах были маркер обрезки и разрыв номеров. Фиксируем правило на уровне одного отображённого ответа. Заголовок обязан относиться к запрошенному пути. Находим первую удалённую пронумерованную строку с маркером обрезки либо первый разрыв последовательности номеров. Все отображённые адреса после этого места требуют повторного адресного чтения. Предшествующий непрерывный фрагмент оставляем. Если отображение отмечено как обрезанное и начало сомнительной части нельзя локализовать, отзываем весь ответ. В штатных ответах с непрерывной нумерацией сохраняем все адреса. Отдельные фиксированные контроли — принимать весь ответ и отзывать весь ответ при признаке обрезки либо разрыве. Для всех методов одинаковый знаменатель выданных кандидатов.

Вычислитель получает только тело успешного view и его путь, без последующего редактирования и без закрытой длины файла. Проецируем флаги на ранее зарегистрированные строки решения R40. Для каждой строки сохраняем хеш и Boolean-флаги, затем подписываем все прогнозы до чтения проверочных before/after. Значение возможного смещения по закрытому снимку остаётся диагностикой. На основании внешне неизвестной длины алгоритм не восстанавливает произвольный отброшенный участок. Критерий пригодности для этой панели — нулевое число ошибочных принятых строк при ненулевом покрытии на holdout, отдельно охват и цена лишних отзывов. Прогнозы сравниваются с буквальным соответствием нарисованного адреса, поэтому случайно совпавшие пустые или дублирующиеся строки рассматриваются как совпадения по этому критерию.

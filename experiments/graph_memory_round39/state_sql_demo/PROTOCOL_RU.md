# Живой запрос SQL к состоянию читателя SERBench

До материализации новых состояний и измерения стоимости фиксируем реализацию. Берём все 214 test-состояний повторно использованной локальной части открытого Cal500. В R39/set_reader уже известны параметры и предсказания. Рабочий читатель — опубликованный matched_unary со всеми одноместными признаками, обученными деревьями и выбранным на dev весом 1. Жёсткий контроль — ранжирование BGE dense_state на той же панели. Восстановим baseline по признакам и узлам деревьев, включая исходный порядок разрешения равенств. Проверим восемь позиций у каждой политики по подписанным спискам R39. Ошибка в любой позиции означает, что реализация читателя не прошла проверку.

Для unit сохраняются исходная позиция в пуле, псевдонимы состояния и файла, диапазон строк, стоимость, исходный ранг BGE, все одноместные признаки, флаг observed_by_state и вычисленный score. Ребро кандидат–файл основано на опубликованном source_path. Ребро состояние–наблюдение соответствует только флагу SERBench. Разметка квот и альтернатив находится в отдельной базе оценщика и не подключается к запросу ранжирования. Интерактивные add/remove устанавливают или снимают один наблюдаемый кандидат. Остальные поля префикса, пути, исторические сигналы и эмбеддинги остаются зафиксированными в старом состоянии. Вмешательство проверяет прямую зависимость от видимости. История не проигрывается как команда.

При обновлении пересчитывается весь ансамбль из 65 деревьев для одного кандидата, затем извлекается top-k SQL-запросом по индексу. Сравним со свежим вычислением функции деревьев для всех кандидатов в том же состоянии и с контролем BGE. Для каждого исходного состояния поменяем флаг первой по исходному порядку единицы с каждой доступной исходной видимостью и вернём его обратно. Проверим точность восстановленных top-8, значений score, официального Complete-MSS@5 и @8 на исходной панели. Для изменённых состояний проверим собственный оценщик на официальном scorer SERBench с теми же замороженными метками. Метрика оценивает возвращённые идентификаторы, наблюдаемость сама по себе не присваивает попадания в MSS.

Засекаем тёплую SQLite в памяти. Сравниваем один транзакционный flip плюс получение top-8 инкрементальным путём и полным вычислением для того же вмешательства. Два независимых соединения, порядок ветвей чередуется. Пять измерений на вмешательство после одного прогрева. Регистрируем медиану и 95-й перцентиль времени, объём баз, количество вызовов ансамбля, число изменившихся top-5 и исходов MSS. Время построения признаков и загрузки базы указывается отдельно. Повторное использование известной панели ограничивает вывод проверкой исполнения и стоимости.

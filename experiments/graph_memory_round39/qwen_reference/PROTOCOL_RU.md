# Одноразовое сопоставление с Qwen3-Embedding на фиксированной панели

Авторская SERBench v3 сравнивает Qwen3-Embedding-8B на полном пуле и его top-100 с Qwen3-Reranker-8B. Здесь до новых прогнозов фиксируем десять состояний из 214 удержанных в R34, с уникальными репозиториями, в порядке SHA-256 строки «r39-qwen-panel-v1/» + state_id. По качеству, размеру пула и типу решения их не отбираем. Сравниваем полный пул каждого состояния, восемь идентификаторов, MSS@5/@8, до 2048/6144 токенов по тем же исходным единицам. Описательно сообщаем исходы на уровне состояния, парные выигрыши и потери, число кандидатов, расходы чтения и время. Панель служит проверкой реализуемости сравнения, выборка недостаточна для вывода об общем превосходстве.

Для основного Qwen-контроля используем официальный Qwen3-Embedding-8B-GGUF Q4_K_M, нормализованные 4096-мерные представления, косинус и полный пул. На случай замены по вместимости явно отмечается размер. Локальный llama.cpp на CPU, модель не обучается. В запросе — текст информационной потребности, подцель, описание задачи по порядку проекта R39 плюс инструкция retrieve missing source evidence; в документе — путь и фрагмент. Фиксируем ограничение 512 входных токенов и измеряем частоту усечения. Сравниваем версию без фильтра просмотренного (как в авторской таблице) и с отсрочкой просмотренного; дополнительный контроль отделяет свойства модели от известного устройства метрики. Все текстовые запросы направляются исключительно к локальному процессу. Оригинальные неквантованные веса, точная сериализация авторской 75-строчной настройки и исчезновение информации при усечении могут изменить результат. При недоступности exact checkpoint open-weight run остаётся приближением.

Версию нашего метода берём из вторичной абляции пустого префикса R39: параметры не меняются, запечатанные прогнозы one_distance на этих десяти состояниях уже существуют, устойчивость аналогов ранее изучалась на всей калибровочной панели. Для ориентиров используем те же BGE и union_cost с отсрочкой. Разметка не читается при отборе панели или формировании новых выдач. BGE-чтение и обученные модели на blind Test500 вследствие отдельного пула требуют дополнительной работы, а прежние локальные экспорты не оценивают новую модель. Ничего в публичный сервис не направляем.

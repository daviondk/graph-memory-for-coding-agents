# Что даёт точная оптимизация хвоста нативной выдачи

При одном защищённом префиксе R-GCN без смежности и одной графовой полезности кандидатов точный рюкзак поднял **Full Support AUC с 70,110% до 71,324%** относительно жадного отбора по полезности на токен. Разность составила **+1,214 п.п.**, парный 95%-й интервал по траекториям и инициализациям **[+0,909; +1,504] п.п.** При принудительном равенстве фактически доставленных токенов на каждом вопросе, бюджете и seed сохранилась разность **+0,422 [+0,263; +0,586] п.п.** Этот порядок выбран после просмотра результатов budget_curve. Диагностическое сравнение зарегистрировано перед вычислением его собственных исходов на той же панели. [Протокол](PROTOCOL_RU.md) · [Результаты](results.json)

**Простой отбор по абсолютной графовой полезности практически воспроизвёл качество рюкзака.** Он достиг 71,204% Full Support AUC. Преимущество точного решения составило +0,120 п.п., интервал [−0,053; +0,298] п.п. Переход от фиксированного полученного графового балла к баллу на токен существенно меняет результаты. Вывод о необходимости точного решателя для этой панели остаётся открытым.

## Что сравнивается

В каждом из 2 000 вопросов, 1 207 траекторий и пяти исходных инициализаций обе нативные модели задают свой порядок кандидатов. Верхние подряд идущие узлы стоимостью до половины бюджета остаются в пакете. Все новые правила обрабатывают тот же хвост в той же задаче. Графовые баллы — неизменная функция, обученная ранее в global_packet. Жадный алгоритм сортирует хвост либо по абсолютной полезности, либо по полезности на токен, пропускает слишком дорогие элементы и продолжает обход. Рюкзак максимизирует сумму тех же полезностей. Простой ранговый контроль использует log(1+1/r), где r — позиция в нативном хвосте. Замороженный dense-контроль использует плотный ранг, стоимость и размер пула. Во всех случаях действует один лимит для всего пакета.

Контроль равного расхода сначала получает жадный набор по полезности на токен и измеряет его стоимость. Второй решатель максимизирует исходную суммарную полезность среди наборов именно с этой стоимостью. Для обеих нативных моделей равенство проверено во всех **120 000** парах. Помимо этого отдельно измерено обычное решение с неравенством по стоимости. Контроль равного расхода меняет множество допустимых наборов и тем самым проверяет сравнение оптимизаторов при фиксированной доставке.

## Проверки

До обращения к размеченным диапазонам зафиксированы все пять прогнозов. Штатные функции ISETrace оценивают пересечение исходных диапазонов и нормированную AUC по log₂-бюджету. Обработано 960 000 пакетов, выполнено 516 903 различных вызова штатного span scorer внутри пар вопрос–инициализация, каждый проверен независимым объединением атомарных диапазонов. Все 360 000 пакетов и значений прежних strict, first-fit и graph-DP совпали с budget_curve на всех бюджетах, включая 60 000 сравнений при 2 048.

Отдельный числовой решатель на шести детерминированно выбранных вопросах каждого seed подтвердил 1 440 оптимальных значений четырёх вариантов рюкзака, включая обязательную стоимость. Максимальное измеренное отклонение — ноль. Независимый обход воспроизвёл 720 жадных списков, повторный подсчёт стоимости — все 120 000 пар с одинаковой фактической доставкой. Независимый bootstrap подтвердил 80 границ интервалов. Разметка относится к покрытию свидетельств. Успех агента при выполнении программной задачи и перенос на новый набор этими данными не установлены.

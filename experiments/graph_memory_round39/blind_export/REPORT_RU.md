**Граница интерпретации.** Авторский критерий награждает только ещё недостающие свидетельства, поэтому отправка уже просмотренных единиц в конец фиксированного порядка математически не ухудшает Complete-MSS. Перенос на настоящую память при изменении исходника или потере контекста требует другой постановки. На Cal500 флаг строки и агрегированный список просмотренных расходятся, тогда как на Test500 они согласованы. В частности, полный trajectory_prefix имеется у всех Cal, а на публичном Test он отсутствует. Лексическая модель скрытой выдачи использует общие поля. По открытому набору она уступила полноразмерному R39. Превосходство над опубликованным MSS-Complement по этим опытам установить нельзя. [Разбор методов и официальных условий](author_baseline/SOURCES_RU.md)

## Проверка и повторение

В корне снимка `python verify_snapshot.py` стандартной библиотекой проверяет SHA-256 всех артефактов, целостность отдельных запечатанных экспериментов, покрытие слепого файла и исходы Cal. Для независимого локального формального прогона официального валидатора достаточно публичного SERBench SDK и файла JSONL; из корня полного SDK используйте `python -m serbench validate --split test500 --predictions <путь-к-JSONL>`.

Для повторного обучения восстановите **копии** подкаталогов author_baseline и tie_audit в дерево `work/graph_memory_round39/`, рядом с исходными repo_crossfit и set_reader. Сохранённые скрипты обращаются к ним, к `work/graph_memory_round34/external_transfer/`, к `work/memory_session5/serbench/` и к токенизаторам D, перечисленным в исходном prepare.py R34. Каталог tie_audit при оценивании использует функцию bootstrap из соседнего author_baseline/grade.py. После восстановления запускайте команды из отдельных отчётов. Самодостаточный для проверки снимок содержит скрипты, обученные деревья, индивидуальные прогнозы, отдельные исходы, доверительные интервалы и зафиксированные протоколы.

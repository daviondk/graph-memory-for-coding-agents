# Что требуется для сравнения с авторами SERBench

В supplied-pool треке авторы ранжируют все фрагменты из состояния. Основной Qwen-контроль строит top-100 через Qwen3-Embedding-8B и применяет Qwen3-Reranker-8B. Вариант запроса они выбирают из issue-only и state-plus-need на фиксированных 75 калибровочных состояниях. В основной таблице они сохраняют в выдаче уже видимые кандидаты. В скрытом Test500 просмотренный ID не покрывает требуемую группу по правилам разметки. Поэтому его отложение интересно как контроль информации, которую получает алгоритм поиска, а само исключение — заведомая подсказка к этой конкретной метрике. В Section D.4 авторы дополнительно измеряют сравнение на состояниях с пересечением и без него. [SERBench, протокол D.1–D.4](https://arxiv.org/html/2609.20050v3#A4.SS2)

В работе приведены 52,60% и 64,20% Complete-MSS@5/@8 для Qwen3-Embedding-8B, 61,40% и 72,40% после дополнительного 8B-ранжирования, 73,00% и 80,60% у MSS-Complement. Все цифры относятся к отдельному авторскому Test500. MSS-Complement использует несколько поисковых представлений, предложение достаточного набора, поиск оставшегося условия и семантическую финализацию. Выполнение локального Qwen3-Embedding-8B воспроизводит общее семейство одного из сильных базовых методов. Квантование Q4_K_M, собственная сериализация и ограничение токенов делают наш прогон приближением. Нельзя обозначать его ни полным Qwen3 Embed + Reranker, ни новым запуском MSS-Complement. [Авторские метрики и абляции](https://arxiv.org/html/2609.20050v3#S6) · [Официальные GGUF Qwen](https://huggingface.co/Qwen/Qwen3-Embedding-8B-GGUF/tree/69d0e58a13e463cd99a9b83e3f5fee7c10265fab)

В авторской таблице источниковый бюджет 6 144 токена допускает более восьми фрагментов в длинной выдаче обычного Qwen и даёт 80,00% у Qwen с reranker. В наших R39 таблицах потолок равен восьми и дополнительное условие задаёт потолок по токенам. Поэтому опубликованную колонку бюджетов нельзя непосредственно сравнивать с ними. [SERBench, таблицы 11–12](https://arxiv.org/html/2609.20050v3#A4.SS3)

Публичный SDK содержит схемы, BM25-стартер, метрики, обе панели входов и калибровочную разметку. В аудите R37 зафиксированы публичное дерево по SHA, ветки, агрегаты и результат доступа к открытому приложению к препринту. Доступные агрегаты не содержат ранжированных ID для каждой строки теста или параллельных предсказаний на калибровочной панели. Официальные веса двух моделей Qwen опубликованы. Станция имеет одну копию официального 4,68-GB GGUF для embedding-контроля. Одновременная загрузка двух полноразмерных чекпойнтов при текущем доступном объёме D не помещается. [R37, аудит локальных материалов](../../../graph_memory_round37/serbench_reference/availability.json) · [Qwen3 Embedding](https://huggingface.co/Qwen/Qwen3-Embedding-8B) · [Qwen3 Reranker](https://huggingface.co/Qwen/Qwen3-Reranker-8B)

Скрытая проверка проходит в два разных этапа. В локальном SDK можно строго проверить полный файл из 500 строк, уникальность идентификаторов, принадлежность фрагментов своим пулам и длину списка. Для запуска закрытого оценщика авторы принимают открытый JSONL в собственном GitHub-репозитории подающего, неизменяемый raw-URL на полный commit SHA, SHA-256, идентификатор релиза, описание метода и согласие на публикацию. Оценщик возвращает пять первичных агрегатов, публикуя ответ в запросе GitHub; имена свидетельств и исходы отдельных состояний остаются закрытыми. Доступ к локальному gold для подготовки файла не нужен. Во время этого эксперимента файлы хранятся на D и не направляются вовне.

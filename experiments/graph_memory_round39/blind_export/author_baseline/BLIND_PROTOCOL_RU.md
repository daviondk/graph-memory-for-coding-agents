# Подготовка отдельного варианта R39 без плотных векторов к слепой проверке

До вычисления его качества выбираем тот же класс одноместных моделей и разметку на пустом префиксе через ближайшее достаточное множество, что в repo_crossfit. Для этого варианта удаляем все признаки, которым нужен BGE, балл union_cost и его ранг, а также смешивание. Остаются идентичные для калибровочной и слепой панелей BM25-ранг, наблюдаемость, сходство пути и слов с полями состояния, токенная стоимость, частота и давность открытий пути. Параметры фиксированы равными R39. Оцениваем полный и вариант без наблюдаемости, а также исходный BM25 и BM25 с отсрочкой прочитанного.

Для контролируемой оценки сохраняем разбиение repo_crossfit из пяти итераций и те же три обучающие группы для каждой внешней. Для итогового blind-экспорта переобучаем только заданный полный вариант на всех 494 доступных Cal500. Поскольку параметры фиксированы, внутренняя dev для этой модели не участвует в оптимизации. Неиспользованные dev-состояния в каждом внешнем обучении сохраняют сопоставимую обучающую выборку с полным R39. Используется официальный supplied candidate pool и ограничение top-8 без обязательного заполнения исключённых состояний. К задачам применяется тот же предварительный отбор по метаданным issue, information need и repo, что в R34, до чтения содержимого кандидатов для ранжирования. Для любого исключённого задания все строки его состояний получают пустой список; скрытый сервис считает это неуспехом. Все 500 строк обрабатываются официальным валидатором формата. Эталон Test500 локально недоступен. Внешней публикации, получения действительных скрытых метрик и сравнения с авторскими скрытыми значениями этот этап не включает.
Поправка до любой оценки нового метода. При первом построении blind-выдачи проверили общие поля двух схем. Полного trajectory_prefix нет ни в одной из 500 строк Test500, тогда как на Cal500 он имеется во всех. Поля latest_test_output и current_diff также отсутствуют в Test и пусты во всех Cal. Исключаем обе колонки частоты и давности событий пути и обе пустые группы из кода обеих панелей, переобучаем с нуля. Совпадения с opened_files остаются. Старый неоценённый прогноз Cal имел SHA-256 4b719b93d4e5ab45416d0708a43c5cd83edaddc80d1ae8b9184149c9bf103bc8. Эта поправка относится только к новому лексическому экспорту.

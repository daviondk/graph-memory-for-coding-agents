# Какие источники инвалидируют результат запроса памяти

На 40 траекториях ISETrace поочерёдно исключили каждый из 2 528 доступных источников. Запрос SQLite вернул в точности тот же порядок узлов, что полный новый расчёт, во всех 2 528 проверках. Для **2 041 исключения (80,74%)** он повторно использовал готовый пакет. Остальные 487 потребовали пересчёта, в 484 выдача действительно изменилась. При равном весе каждого вопроса доля повторного использования составила 77,80% (кластерный 95% ДИ 73,43–81,86%). [Протокол и доказательство](PROTOCOL_RU.md) · [Поштучный журнал](observations.json.gz) · [Итоги](results.json)

После первоначального чтения система записывает индекс источников для отобранных узлов и первого узла, на котором остановился обязательный префикс. Когда агент отзывает источник из текущего снимка, один запрос проверяет обе зависимости. При их отсутствии все ранее обязательные узлы сохраняются, ёмкость хвоста прежняя и прежний оптимальный пакет остаётся допустимым в меньшем множестве вариантов. Это позволяет точно вернуть старый пакет. Индекс построен из реальных узлов и ссылок на исходные диапазоны. В эксперименте использован C++-решатель для обоих сравниваемых методов, отдельная SQLite-таблица для самого пакета. При трёх чередующихся повторах сокращение суммарного времени составило **5,16 раза** (95% ДИ 4,36–6,17 по 40 траекториям). Дополнительная запись зависимостей занимала в среднем 116 мкс на первоначальный запрос. Средняя экономия на одиночном отзыве составила 246 мкс. Отсюда точка окупаемости при измеренной смеси — 0,47 отзыва на первоначальное построение. Параметры относятся к прогретой локальной SQLite и готовым рангам и полезностям. Большинство исключений затрагивает источник вне пакета, распределение реальных запросов приложения может отличаться. [Методика измерений](experiment.py)

В трёх случаях отзыв затронул только первый не прошедший узел, пакет после проверки остался прежним. Упрощённый контроль, отслеживающий лишь оставленные в выдаче источники, также совпал со всеми результатами на этой панели. В задаче из четырёх узлов он ошибается: бюджет 10, лимит префикса 5, цены 2, 9, 3, 8; полезности 1, 0,01, 0,01, 10. Исходный результат содержит первый и четвёртый узлы. Удаление невошедшего второго узла заставляет включить третий в префикс. Это объясняет, зачем корректной реализации нужна граница. Сохранение одного и того же пакета не измеряет качество ответа агента.

**Воспроизведение.** `python -B verify.py` проверяет сохранённые наблюдения стандартной библиотекой. Для новых таймингов используйте отдельную чистую копию каталога исходников с соседними исходными базами, соберите `choose.cpp` из remaining_budget и задайте `R39_KNAPSACK_DLL` абсолютным путём. Затем `python -B experiment.py`. Продолжительность запуска и точка окупаемости зависят от машины и нагрузки. [Проверка результатов](verify.py)

ISETrace содержит синтетические сценарии взаимодействия с агентом ОС. Вызовы инструментов выполнены в изолированном окружении, а вопросы к зафиксированной истории сгенерированы и привязаны к диапазонам исходного текста. Удаления в этом эксперименте — управляемые воздействия на сохранённые записи корпуса. [Описание авторами источника данных](https://arxiv.org/html/2609.25913v3#S3.SS4)

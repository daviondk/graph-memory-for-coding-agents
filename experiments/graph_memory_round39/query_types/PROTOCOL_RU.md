# В каких вопросах меняется состав достаточного пакета

Это диагностический разбор уже полученных общих исходов global_packet. До сопоставления разметки типа вопроса с исходами фиксируем три исходные категории авторов ISETrace (direct, linked, multi-fact) и два разбиения по геометрии свидетельства: 1 / 2 / 3+ различных эталонных события, 1 / 2+ исходных полей (event id и JSON pointer). Категории не видны читателю. Сохраняем все страты, даже если различия противоположны ожиданиям или количество задач мало. Предположение — замены в первой части пакета полезнее для распределённого свидетельства, чем для одиночного факта. Условные результаты описательные, разметка синтезирована авторами. Для проверки взаимодействия считаем прямую разницу эффектов между multi-fact и direct, а также >=2 событий и 1 событием. Используем общие bootstrap-перевыборки seed и полных траекторий, чтобы страты внутри одной траектории оставались связанными. Доверительные интервалы точечные без поправки за несколько диагностик.

Две пары: R39 graph-dp против R35 first-fit (узкий алгоритмический эффект) и нативного R-GCN без смежности с таким же first-fit (практический сильный контроль). При одинаковом B=2048 выводим Full Support, Coverage, занятые токены, число узлов, перешедшие полное/неполное ответы. Для объяснения механизма выводим число изменившихся пакетов и замен на каждом шаге — закрывается ли конкретное исходное поле, сколько узлов добавлено/удалено относительно замены и какова разница фактической стоимости. Для страты "несколько событий" используем только неизменные авторские gold, и лишь на этапе разбора готовых пакетов. Эта стратификация не доказывает причинную роль графа и не заменяет общий тест.

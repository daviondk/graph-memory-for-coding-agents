# Запуск и проверка автономной демонстрации

Распакуйте ZIP в одну папку, перейдите в неё и запустите команды. Для интерфейса, независимой проверки и повторного измерения достаточно Python 3.10 или новее со стандартным sqlite3. Готовые базы находятся рядом с кодом.

~~~console
python -B verify.py
python -B serve.py --port 8769
~~~

Откройте локальный адрес, выведенный сервером. Укажите q02, бюджет 2 048 и исключите верхний источник в раскрывающемся списке после варианта «Все источники доступны». Зафиксированы дельты узлов №19 и №11. Нажмите на узел, чтобы увидеть источник и соседние рёбра. Кнопка «Проверить покрытие» запускает отдельное обращение к оценщику. Кнопка восстановления сбрасывает источник и бюджет. Сервер слушает только 127.0.0.1. Копии баз открываются только для чтения.

~~~console
python -B smoke.py
python -B measure.py fresh-results
~~~

Новый каталог нужен для сохранения исходных журналов измерений. Время зависит от компьютера и нагрузки. Для браузерной проверки дополнительно используются установленный Chromium и Playwright. Переменная BROWSER_EXE задаёт путь к Chromium на вашей системе.

~~~console
python -B smoke.py --browser --screenshot preview.png --out browser-rerun.json
~~~

reader.sqlite обслуживает выбор пакета и объяснения. grader.sqlite содержит эталонные интервалы зарезервированного теста. reference.json содержит контрольные списки ID и опубликованные в нашей серии результаты исходного оценщика. В обычном запросе выбора читается только reader.sqlite. Полезности и порядок вычислены заранее, пересчёт после пользовательского вмешательства решает рюкзак по фактическим допустимым кандидатам.

Полное построение из исходных данных предусмотрено в исходной структуре исследовательского репозитория. Нужны соседние отмеченные в build.py R18–R39 исследования, локальный официальный Python-адаптер, закреплённые исходные графы, восемь публичных шардов ISETrace, ранги и обученная модель из global_packet. Команда `python -B build.py fresh-build` проверяет происхождение и записывает базы заново. Это отдельный тяжёлый этап. Для проверки готовой демонстрации исходные траектории не требуются.

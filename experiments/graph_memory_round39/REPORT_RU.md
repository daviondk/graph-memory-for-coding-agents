# Графовая память с ограничением по токенам и проверяемыми зависимостями

На 2 000 вопросах ISETrace лучший исследованный гибрид поместил все эталонные фрагменты в 2 048 токенов в среднем в **83,07%** случаев. Воспроизведённая R-GCN без рёбер смежности с тем же жадным заполнением бюджета, что и у нашего сильного контроля, достигла **81,19%**. Разность при пяти общих инициализациях составила **+1,88 п.п., 95% ДИ [0,76; 3,07]**. Рабочий прототип в SQLite позволяет увидеть, что именно прочитает агент и какие изменения источников требуют повторного расчёта. ## Как устроен запрос к памяти

У каждого поля аргумента или результата инструмента есть идентификатор исходного события, диапазон в источнике и стоимость в токенах. Агент обращается к уже накопленной истории. Исходный ранжировщик задаёт порядок чтения. Короткий обязательный префикс сохраняет верхние результаты, которые помещаются в половину бюджета. Для оставшихся кандидатов модель оценивает вероятность того, что узел содержит необходимое свидетельство. Она использует в том числе типы полей и признаки наблюдаемых связей в истории. Динамическая программа максимизирует сумму −log(1−p) при оставшемся бюджете. Это аддитивное приближение полезности. Полноту ответа оцениваем отдельно по исходным координатам. Ранее виденные репозитории целиком загружать в память этого прототипа не требуется. В оценке ISETrace пул составляли из уже доступной полной истории. ## Извлечение свидетельств на ISETrace

Единица сравнения — один вопрос при одном начальном состоянии ранжировщика. Использованы штатный тест из 1 207 отложенных траекторий и инициализации 13, 17, 29, 37, 41. Все методы получали одинаковые кандидаты и бюджет. Full Support означает полное покрытие всех эталонных диапазонов. AUC — нормированная площадь по шести значениям бюджета от 256 до 8 192 токенов на логарифмической шкале. Интервалы рассчитаны парным бутстрэпом по траекториям и инициализациям. Для каждого бюджета сформирована отдельная выдача. Собственный основной вариант с исходным порядком R35 поднял AUC относительно жадного заполнения на **0,427 п.п. [0,102; 0,758]**. При 2 048 токенах разность для этой пары составила +0,41 п.п. [−0,23; 1,08]. Средний расход был практически одинаковым, 2 039,1 и 2 039,3 токена. Вариант с нативным порядком без смежности выделен после сравнения исходных порядков на известном тесте. Для него разность AUC относительно исходного порядка с жадным заполнением составила **+1,786 п.п. [1,149; 2,460]**. Повторная проверка на независимых данных нужна для оценки переноса. Траектории ISETrace построены по синтетическим заданиям с реальным исполнением инструментов. **Что дало улучшение.** При одной и той же графовой оценке и обязательном префиксе рюкзак выиграл у сортировки по полезности на токен **1,214 п.п. AUC [0,909; 1,504]**. При уравнивании фактически занятого числа токенов в каждой паре преимущество составило **0,422 п.п. [0,263; 0,586]**. Сортировка по абсолютной полезности достигла **71,204% AUC**. Разность рюкзак минус этот простой контроль составила **+0,120 п.п. [−0,053; 0,298]**. Ранее проверенная стратегия, которая доучивает только заполнение остатка готовой выдачи, дала +0,04 п.п. при 2 048. Основания для статьи сильнее у модели полезности в сочетании с проверяемым обслуживанием запроса. ## Когда можно повторно использовать материализованную выдачу

При стабильных рангах, целочисленных полезностях, стоимостях и правиле разрешения ничьих после удаления источников старый оптимальный пакет сохраняется тогда и только тогда, когда все его узлы уцелели и новый обязательный префикс целиком содержится в старом пакете. Доказательство опирается на допустимость старого решения и вложенность допустимых множеств для изменившегося префикса при удалениях. Критерий можно проверять по зависимостям. Запись в источник с новым содержимым требует самостоятельного решения о валидности. [Формулировка, доказательство и контрпример](exact_certificate/REPORT_RU.md)

- Простой достаточный критерий позволил выдать сохранённый ответ в **2 041 из 2 528 (80,74%)** смоделированных одиночных исключений. Все упорядоченные выдачи совпали с полным пересчётом. На 40 траекториях ISETrace отношение суммарного времени при прогретой SQLite составило **5,16× [4,36; 6,17]**. Так измерена стоимость чтения после исключения источника при исследованном распределении запросов. [Профиль времени](packet_invalidation/REPORT_RU.md)
- Полный критерий верно распознал все **73 261** неизменившиеся выдачи при **108 204** одиночных и групповых исключениях. Отдельная реализация с Q32 воспроизвела все **10 000** исходных выдач на пяти инициализациях и все **108 204** запрошенных пересчёта на демонстрационной панели. [Проверка критерия](exact_certificate/REPORT_RU.md) · [Точная арифметика](fixed_point/REPORT_RU.md)

## Проверка применимости к кодовым агентам

На открытой панели SERBench из 494 состояний и 171 репозитория отложенные по репозиториям прогнозы дали **192/494** полных наборов при top-5 против **159/494** у полностью переобученного варианта без признака предыдущего просмотра. Простой контроль с маской дал **177/494**, разность с ним +3,04 п.п. [−0,20; 6,42]. Авторская метрика по построению поощряет дополнение к уже виденному. В отдельном пилоте сильный Qwen3-Embedding-8B и наш согласованный читатель набрали по **5/10** при top-5, **7/10** при top-8 и **4/10** при 2 048 токенах. Qwen запускался как модель эмбеддингов в Q4_K_M на RTX 3090. Это открытая калибровочная выборка. На закрытой Test500 подготовлены валидные прогнозы, официальной оценки нет. [Проверка по репозиториям](repo_crossfit/REPORT_RU.md) · [Пилот с Qwen](qwen_reference/REPORT_RU.md) · [Скрытая панель](blind_export/REPORT_RU.md)

Последовательный выбор очередного фрагмента дал 88/214 при top-5 против 90/214 у статического контроля с тем же обучением. Для динамического обновления статического порядка в SQLite проверены 428/428 запросов top-8, медиана запроса 35,9 мкс против 1 675,8 мкс при полном пересчёте. В двух прежних задачах на изменение кода все шесть независимых запусков решили свои задачи. Преимущество в доле успешных исправлений на них установить не удалось.

# Контроли дедупликации и разнообразия при фиксированном K

Дополнительное исследование после наблюдения R29/pareto_cache. Те же 96 вопросов, 576 основных событий, три граничных на вопрос. Все методы записывают ровно K=8 или 64 ответа. Контроли — исходный raw, дедупликация одинаковых координат, оставление одного лучшего исходного surface text (с сохранением регистра и объединением последовательного пробела по образцу n-best BERT), жёсткое одномерное non-maximum suppression (greedy score, интервал отвергается, если его IoU с уже выбранным строго выше порога), а также точный Pareto. Основной порог IoU=0,5. 0,3 и 0,8 задаём заранее как диагностические, без выбора по этим результатам. Совпадение строк текста в разных местах отдельно от правильного идентификатора вхождения. Это адаптация правил разнообразия к одному и тому же полному кандидатному пулу.

Высокая доля непустых попаданий разнообразного кеша может включать ошибку: отличный, но ранее подавленный ответ бывает допустим. Поэтому первичен **идеальный hit exact**: проверяем, содержит ли K-записный кэш истинного победителя источникового запрета. Это благоприятная верхняя граница для каждого контроля, независимо от того, способен ли алгоритм распознать такой случай. Вторично отдельно проверяем число ошибочных немедленных ответов, правильную поверхность текста и число гарантированных ответов с простой проверкой. Для последней сохраняем общий для всех схем один дополнительный скаляр — строгий ранг первого пропущенного кандидата, который по глобальному точному тесту мог бы стать победителем. При обнаруженном допустимом кэш-кандидате раньше этой границы ответ доказуем. Если гарантии нет, точный резерв проверяет окна из тех же BLOB и использует допустимый кэш-кандидат как текущее лучшее решение для отсечения. Альтернативные более информативные сертификаты требуют дополнительных сравнений размеров и остаются за пределами этой проверки. Резерв в каждой схеме сверяется с исчерпывающим ответом.

Метрически сравниваем Pareto с простым координатным контролем и каждым правилом NMS отдельно при одинаковом K. Интересуют oracle exact и строгое число резервных загрузок по главному K=64. Порог 0,5 первичен, все пороги опубликованы. 95% парный интервал строится по статьям. Протокол не настраивает эвристики; затраты на вычисление сертификата и его логический размер учитываем явно. Источники правил: исходный BERT run_squad.py (сопоставление строк n-best) и стандартный hard NMS для IoU. Эти методы первоначально решают другую задачу.

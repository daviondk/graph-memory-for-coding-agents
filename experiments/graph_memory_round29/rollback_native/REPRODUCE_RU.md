# Воспроизведение

Запустите run.ps1. Нужны uv, Python 3.12 и отдельный Python с NumPy для вычисления парных интервалов. Источники закреплены в fetch.py и проверяются по git blob ID. Установка зависимостей и загрузка upstream требуют интернета. Сам baseline запускается офлайн: offline_entry.py исполняет оригинальную точку входа, запрещает Python-события сетевого соединения и запуска дочерних команд, удаляет переменные ключей из окружения дочернего процесса. JSON и названия действий обрабатываются только как данные. Вся запись происходит на диске D.

Сначала запускаются отдельные официальные smoke на обоих реестрах, затем полные прогоны no_repair. Оригинальные артефакты и логи размещаются в D:/CodexResearch/x20-r29-rollback/native и /smoke. После исходного нативного прогноза используется именно eval/run_oracle.py и eval/metrics.py из авторского репозитория. Рекуррентные пробы вызвали бы отдельную модель и определялись бы только для успешно восстановленных кейсов, которых у no_repair нет. Для повторного воспроизведения с нуля используйте новый каталог D и обновите константу P в локальной копии fetch.py.

Вторая часть — controls.py на обоих реестрах. После двух seal — evaluate.py и applied_audit.py. Аудит подтверждает равенство original/returned структур во всех 200 no_repair результатах и применение всех пяти правил в отдельной queryable SQLite проекции. Единица нативного результата и дополнительных правил различается и указана в отчёте. Измеренное одиночное время разных алгоритмов в forecasts включает/исключает построение связей согласно имени поля; эти тайминги сохранены для диагностики и не используются для обещания ускорения работы агента. Проверка сохранённой поставки — verify.py.

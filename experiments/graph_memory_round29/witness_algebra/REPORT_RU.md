# Какие ответы вообще могут понадобиться после отзыва наблюдений

Рассмотрим память, в которой результат читателя уже зафиксирован. У запроса имеется конечный список кандидатов в детерминированном порядке от лучшего к худшему. Нужен идентификатор первого ответа с действующим свидетельством. Для одной цитаты таким свидетельством могут быть координаты текста, для решения кодового агента — результаты нескольких ранее сделанных чтений. Равные оценки упорядочиваются постоянным ключом.

### Когда для кандидата нужны все его источники

Пусть для ответа i требуется множество источников Dᵢ. Ответ допустим при сохранившемся наборе S, если Dᵢ ⊆ S. Если у более высокого кандидата j множество Dⱼ ⊆ Dᵢ, то в любом состоянии, допускающем i, допустим и j. Кандидат i можно исключить. Обратно, если такого j нет, при S = Dᵢ первым допустимым будет именно i. Поэтому процедура оставляет ровно множество **возможных идентификаторов победителей** при произвольном отзыве. Это точная характеристика сохраняемых результатов. Размер в байтах зависит от их кодирования.

Для одного текстового span источниками могут выступать его символы. Тогда включение источников эквивалентно вложению интервалов. Чтобы оставить ровно один интервал, достаточно отозвать два его внешних дополнения. Это объясняет, зачем для одного запрещённого интервала достаточно двух одномерных индексов, а для нескольких полезны недоминируемые вложенные span. Практический эксперимент содержит 6,68 млн кандидатов и реальные оценки DistilBERT. [Реализация и измерение](../multi_retraction/REPORT_RU.md)

### Если один факт подтверждают несколько наблюдений

Пусть Wᵢ — семейство альтернативных достаточных наборов. Ответ i допустим, если хотя бы одно w из Wᵢ целиком содержится в S. Ответ i может стать первым ровно тогда, когда у него есть набор w, для которого **ни у одного более высокого ответа нет достаточного набора, вложенного в w**. Доказательство сохраняется: если такой набор есть, берём S = w. Если его нет, какой бы свидетель ответ ни использовал, для него найдётся разрешённый ответ выше. В разных случаях его могут опережать разные кандидаты.

Например, у первого кандидата единственное свидетельство {A}, у второго {B}, у третьего два альтернативных свидетельства {A} и {B}. Третий никогда не победит, хотя ни один из первых двух по отдельности не доступен во всех тех состояниях, где доступен третий. Объединение двух путей в один набор {A,B} ошибочно требует наличия обоих сообщений. Этот случай непосредственно касается передачи одного и того же фрагмента через нескольких работников.

### Следствие для фиксированного числа строк в кэше

Берём первые K возможных победителей в исходном порядке. При любом отзыве итоговый победитель либо отсутствует, либо его позиция в отфильтрованном списке не позже позиции в полном. Когда обычный top-K содержал нужный ответ, отфильтрованный top-K тоже его содержит. Для конечного ответа при промахе обоим нужен одинаковый точный резервный поиск. Допускаются улучшения частоты попаданий и стоимости поиска. Качество самого точного ответа одинаково. Это гарантируется относительно обычного top-K. Политика, оптимизированная под конкретное распределение отзывов, способна выигрывать у обоих.

Утверждения требуют фиксированного порядка кандидатов, определённого контракта допустимости и известных достаточных свидетельств. Обновление весов, новое чтение или удаление контекста из модели может изменить ранги. Если разрешены лишь некоторые отзывы, описанное условие остаётся безопасным, но достижимость каждого оставленного кандидата уже не гарантирована. Когда приложению достаточно одинаковой строки ответа, различные адреса могут быть эквивалентны: тогда минимальность по идентификаторам не определяет минимальность по текстам.

Это применение идей provenance и skyline к выбору содержимого кэша читателя. Минимальные свидетели запроса и компоненты доминирования давно изучаются в БД. Область возможного вклада — точный контракт отзыва, выбор кандидатов при фиксированном K и измерение последствий в хранилище агентной памяти. [Buneman, Khanna и Tan, ICDT](https://www.research.ed.ac.uk/en/publications/why-and-where-a-characterization-of-data-provenance/) · [Green, Karvounarakis и Tannen, PODS](https://www.cs.ucdavis.edu/~green/papers/pods07.pdf) · [Börzsönyi, Kossmann и Stocker, ICDE](https://cse.hkust.edu.hk/~raywong/reading/paper/skyline.pdf) · [Zhang et al., передача свидетельств](https://arxiv.org/abs/2611.22245)

Скрипт check.py независимо перечисляет все монотонные условия допустимости по трём источникам для каждого из трёх ответов, все сохранившиеся состояния и три размера кэша. Это исчерпывающая проверка конечного пространства с известной семантикой. Эмпирическая полезность на агентных трассах исследуется отдельно.

# Построение памяти допустимых цитат непосредственно по логитам

Для 96 вопросов из 48 статей извлекающий читатель сформировал 793 окна, 283 239 позиций и 6 677 914 допустимых span длиной до 30 токенов. Для ответа после исключения одной цитаты достаточно 3 059 записей о смене победителя слева или справа от границы. Мы построили эти записи непосредственно по двум векторам логитов каждого окна и сравнили каждое поле записей с фактическим индексом R28 в SQLite. Все 1 152 полных сравнения NumPy и 864 сравнения компилируемого контроля совпали побайтно. Это повторы одних и тех же 96 вопросов.

## Почему можно пропустить пары

Пусть фиксирован конец j, а S — множество допустимых начал за последние K токенов в его сегменте. При конечных логитах операция сложения float32 монотонна. Поэтому максимальную оценку даёт fl(max{aᵢ, i ∈ S} + bⱼ). При ничьей нужен самый ранний i, который даёт именно эту округлённую сумму. В частности, различающиеся aᵢ могут после сложения иметь одну оценку. Случай проверен отдельно. Для фиксированного начала действует симметричное правило. После локального вычисления достаточно объединить не более двух победителей на позицию по её физическим координатам. Общий порядок по score и исходному номеру восстанавливает правильный выбор и для перекрывающихся окон. Две накопительные серии максимумов оставляют лишь моменты смены победителя.

Реализация хранит максимумы для блоков длины 1, 2, 4 и так далее. Запрос максимума диапазона использует два блока, затем метод пропускает целые блоки, максимальный элемент которых при сложении даёт строго меньшую округлённую оценку. Поиск останавливается на первом подходящем индексе. Локальная часть требует O(T log K) операций для T позиций непрерывных сегментов, потоковое перечисление — O(TK). Оба метода отдельно тратят время на упорядочивание уникальных исходных координат и объединение вхождений. Количество точных сохранённых смен определяется самими данными. Двоичные диапазонные максимумы и монотонная очередь имеют исследованную историю. Потенциальный вклад здесь — использование этой редукции для воспроизводимой, точной и физически компактной памяти цитат при запрете одного интервала. [Range Minimum Queries, Baumstark et al.](https://drops.dagstuhl.de/entities/document/10.4230/LIPIcs.SEA.2017.12) · [Streaming Maximum-Minimum Filter, Lemire](https://arxiv.org/abs/cs/0610046)

## Компилируемый контроль

Контроль использует три ядра C++ в одной библиотеке GCC 16.1.0 с одинаковыми настройками оптимизации и точности. Для каждой схемы одинаковы загрузка, объединение координат и сериализация. Время ядра включает переходы Python→C++ для окон одного вопроса. Скользящая монотонная очередь сохраняет точность при float32-ничьих. При возможном равенстве с непосредственным представимым предшественником исходного максимума она дополнительно проверяет ранние позиции. Интервалы по статьям описывают выборку вопросов при данном процессоре и реализации.

Оба прямых способа превосходят компилируемый перебор. Отношение медиан полного построения для таблицы 0,667 [0,636; 0,760], для очереди 0,678 [0,650; 0,755]. В прямом сравнении таблицы с очередью отношение **полного построения 0,984 [0,955; 1,047]**. Для одного вычислительного ядра отношение 0,705 [0,681; 0,747]. Результат указывает на выгоду перехода к двум победителям на позицию относительно полного перечисления. Выбор одной конкретной структуры диапазонного максимума пока не дал убедительного полного выигрыша над альтернативной реализацией того же принципа. Число точных проверок на специальных массивах, включая повторяющиеся сегменты, ничьи и предельные ширины, составило 280 в NumPy и 420 в C++.

# Компилируемый контроль устоявшихся алгоритмов

После первичного эксперимента NumPy проверяем альтернативное объяснение: преимущество сведéния к максимумам может зависеть от цены векторизации и временных массивов при K=30. Один оператор C++ проходит все допустимые пары в ограниченном вложенном цикле без создания или сортировки списка кандидатов, удерживая лучших для фиксированного начала и конца. Второй вычисляет диапазонные максимумы таблицей степеней двойки и находит самое раннее совпадение после сложения float32. Третий получает максимум стандартным скользящим deque и сохраняет лексикографическую точность дополнительной проверкой более ранних стартов/концов при возможном слиянии разных значений после округления. Граничные координаты у всех трёх сворачиваются общим кодом. Это отдельный контроль на C++, одна компиляция с GCC −O3 без fast-math, локальный DLL хранится на D. Проверяем те же 96 вопросов, 3×3 изолированных повтора, p50/p95 и совпадение полных записей с SQLite. Раздельно показываем стоимость полного построения и вызова вычислительного ядра. Преимущество NumPy не будет автоматически переноситься на C++.

# Воспроизведение пилота STALE

Использованы закрытые друг от друга этапы подготовки, поиска, генерации и оценки. Перед запуском следует создать локальный каталог D:/CodexResearch/x20-r29-stale-reader. Исходные сессии, авторские признаки, входы Qwen и полные ответы сохраняются там. Предметы архивирования в этой папке проекта — программы, контрольные суммы, обезличенные ID и статистика. Один и тот же Python из D:/CodexResearch/x20-isetrace-e5-gpu/venv/Scripts/python.exe запускает приведённые команды с диска D. Библиотеки ONNX лежат в каталоге R23, пути определены в retrieve29.py.

1. Восстановить закреплённую версию CC BY 4.0 STALE и проекцию R28 по соседнему руководству graph_memory_round28/retraction_sources/REPRODUCE_RU.md. Проверяется SHA-256 исходного файла 5f3ec375179e20e2e94469e018189188f34e2e7e5f21cbecbd99fcfa648c1876, исходных сессий и вопросов. Авторская инструкция судье сохранена R28 в D:/CodexResearch/x20-r28-retraction/judge_prompts.py.txt. [Данные, лицензия и атрибуция](https://huggingface.co/datasets/STALEproj/STALE/tree/617c51dc200b5ab09970834144c7e51c77959af0) · [Код STALE](https://github.com/icedreamc/STALE)
2. Поместить нативный Qwen-токенизатор по пути из retrieve29.py, а E5-small-v2 и int8 ONNX по пути E5. Хеши векторов-модели и токенизатора задаёт входной манифест R23. Указанный в программе llama-server и Qwen3-4B-Instruct-2507 Q4_K_M загружаются исключительно локально. Хеши весов, исполняемого файла, настройки вычисления и генератора зафиксированы в forecast-seal для каждого этапа. [E5](https://huggingface.co/intfloat/e5-small-v2/tree/ffb93f3bd4047442299a41ebb6fa998a38507c52) · [Qwen](https://huggingface.co/Qwen/Qwen3-4B-Instruct-2507)
3. Запустить последовательно setup29.py, retrieve29.py, actor_inputs.py, blind_audit29.py, prefix_correction.py и candidate_audit29.py без аргументов. Запускать их до материального открытия оценок. Публичные фиксаторы отделяют список кандидатов, выбор фрагментов и 160 назначений от эталонов. Для определения даты в сконструированном историческом вопросе только составитель теста видит индексы старого и нового сообщения. Дата даётся ридеру и ранжировщикам как часть постановки задачи. Предикторы видят запрос и обычные обращения пользователя со временем.
4. Для точного повторения последовательности выполнить qwen29.py actor, qwen29.py prefix, prefix_correction.py finish, judge_inputs.py и qwen29.py judge. Для уже запущенного actor те же оставшиеся этапы исполняет continue29.py. Запросы к локальному llama.cpp передают только два независимых сообщения через loopback. Температура 0, seed 13, лексическая грамматика у судьи, 2 CPU-потока на выполнение Qwen, GPU-слои 0. При совпадении хешей конфигурации и входов повторный запуск использует вычисленный закрытый кэш. Публичные журналы фиксируют каждый запрос, попытку, фактические длины и причину окончания.
5. Два ранних вопроса изменились при физическом исключении будущих сессий до int8-кодирования. Первоначальные и физически изолированные прогоны сохранены. Основным прогнозам соответствуют только **effective**-хеши. Для позднего чтения архива источники T/G восстанавливаются из физического префикса, затем три метода выравниваются по длине. Слепому H в позднем архиве разрешено читать более новые записи. Этот общий бюджет может зависеть от размеров H-выдержек. Читатель видит реальные даты и сохранённый текст.
6. После effective-actor-forecast-seal.json случайные по заранее фиксированному хешу 20 примеров направляются независимому оценщику без имён методов, весов и локальных оценок. Оценки по анонимным ID сохраняются в peer-ratings.json в закрытом каталоге. Выполнить score29.py, candidate_audit29.py score, audit_judge29.py. score-rows.json.gz позволяет пересчитать все объективные и локальные метрики, judge-audit.json — проверить расхождения с независимой оценкой. Публичный candidate-score.json хранит потолок по ID, обусловленный восьмёркой кандидатов, сохранением первой сессии и ограничением направления. Это диагностический оракул доступности, его результаты не являются прогнозами ридера.

Воспроизводятся состав стенда, подборки, запросы, бюджеты и оценивание замороженных прогнозов. Приведённые задержки относятся к конкретной машине с параллельными работами. Независимый рецензент работает со стратифицированным срезом. Результат его повторного субъективного оценивания может отличаться.

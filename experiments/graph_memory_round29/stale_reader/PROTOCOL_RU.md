# Проверка актуальности памяти на STALE и исторического чтения

Используем публичную синтетическую тестовую коллекцию STALE, прошедшую валидацию авторами. Все 50 сессий каждого сценария доступны обычным методам. Выбираем 4 из 200 T1 и 4 из 200 T2 минимальным SHA256("r29-stale-reader-v1/"+opaque_case). Отбор учитывает только тип и идентификатор. Сохраняем все 3 авторских вопроса каждого сценария (24 всего), каждый в отдельном запросе без ответов на соседние вопросы. Ни содержание, ни успех поиска, ни наличие удобной формулировки не являются критерием выбора.

Авторы задают три измерения текущего состояния (разрешение состояния SR, сопротивление ложной предпосылке PR, применение обновления в действии IPA). Для отдельной проверки времени добавляем к каждому SR два диагностических запроса, 16 всего: (1) состояние на момент между old и new при физически обрезанном префиксе истории, (2) то же состояние на тот же момент при доступе ко всей последующей истории. В сочетании с исходным текущим SR это три режима времени по одной теме. Дата запроса определяется по средней позиции между сессиями экспертов, округлением вниз. Это сконструированный тест исторического применения, отдельно от авторского балла. В обычный запрос попадает только дата среза, исходный вопрос и разрешённые сессии. Поля old/new/тип/объяснение/маркированные ID недоступны предиктору. Для исторического вопроса спрашиваем, что пользователь последний раз сообщил по теме до среза. Такая формулировка устраняет допущение, будто поездка, погода или иное временное состояние обязательно продолжалось до даты среза. Время прошлого запроса выбрано с помощью разметки при конструировании теста; будущие сессии не могут попасть в ранний физический префикс.

Во всех слепых вариантах индексируем только слово пользователя. Внутри каждой сессии сцепляем реплики в исходном порядке, сохраняем смещения по репликам и разбиваем на 144 нативных токена Qwen, шаг 96, с заполнением короткого последнего окна влево. Словарь BM25 всего доступного префикса и векторы E5-small-v2 (intfloat, ревизия ffb93f3bd4047442299a41ebb6fa998a38507c52), CPU, используются совместно. Сильный обычный контроль H выбирает два лучших разных источника по reciprocal rank fusion (k=60) BM25 и плотного поиска. Контроль T применяет такой же поиск с ограничением по специальной дате для исторического вопроса. Сохраняет первую сессию и из семи лучших оставшихся предпочитает сочетание релевантности и более свежей применимой сессии, score = 2/(5+rank_q)+1/(5+rank_time). Кандидат G сохраняет тот же первый источник, предпочитает вторую, более позднюю применимую сессию из тех же семи, если такая есть, и добавляет 1/(5+rank_link) по косинусной близости найденного отрывка к первому. Сходство двух источников проверяет гипотезу, что доказательство пересмотра состояния связано с темой первого свидетельства. В H историческая дата входит только в запрос к читателю, в T/G она ограничивает выбор сессий. Все методы видят один и тот же предметный текст запроса для ранжирования. Чистый BM25 дополнительно оценивается по адресам без отдельного генеративного прогона.

Каждое слепое условие доставляет до двух датированных фрагментов из разных сессий. Фрагменты внутри вызова предъявляются хронологически. При сравнении слепых методов для каждой позиции выбираем общую достижимую нативную длину полного слота, фиксируем длину всего chat prompt из llama.cpp. В диагностическом O явно доставляются авторские старое и новое утверждение с их датами, в раннем префиксе только старое. Извлекатель и образцовое состояние не смешиваются; O имеет привилегию и иную длину входа, это калибровка качества ридера при доставке нужного материала.

Ридер Qwen3-4B-Instruct-2507 Q4_K_M, CPU 2 потока, llama.cpp, без инструментов, temperature 0, seed 13, до 80 выходных токенов. Порядок запросов определяется хешем, один и тот же вход допускает один физический вызов. Перед извлечением оценок запечатываем 160 назначений (8×5 вопросов×4 условия) и все реальные прогнозы. Публичные квитанции содержат хеши и размеры; тексты авторских диалогов, ответы и потенциально чувствительные фрагменты остаются локально в D.

Авторы используют Gemini-3.1-flash-lite и общий для трёх измерений рубрикатор. Локальный Qwen в отдельном вызове без названия режима применяет тот же рубрикатор к тройке исходных прогнозов и получает old/new/объяснение только после запечатывания. Для исторического теста отдельный закрытый рубрикатор различает правильное применение старого факта, явное ошибочное отрицание ранее верного факта, неопределённость и прочую ошибку. Независимому рецензенту вслепую передаём детерминированный хеш-срез отдельных ответов с эталоном, без метода, результатов судьи или имени модели. Основной proxy — локальная доля принятых исходных ответов, сравнение G–T, отдельные SR/PR/IPA, T1/T2. Дополнительные — сохранение historical SR, ложное отрицание old в прошлом, попадание точного ID old/new и нормализованной строки высказывания. Парные интервалы по восьми сценариям; при 4 на тип выводы о подгруппах описательные. Не сравниваем локальный процент с официальным лидербордом. Предыдущая серия R11 затрагивала устаревание результатов действий в коде; в этом опыте речь идёт о применении персонального состояния в ответе. Сравниваются связь исторических свидетельств и маркированное время запроса, а не один жёсткий cutoff.

# Смена правила наполнения кэша при том же резерве

Проверяем вывод следующего эксперимента после наблюдения полного Pareto-индекса R29/multi_retraction. Если отфильтрованный кандидат T полностью содержит лучшего кандидата S, любой запрет, допускающий T, допускает и S. Значит, первый допустимый по score/tie кандидат полного списка всегда недоминируем. При сокращении списка его ранг только улучшается. По каждому вопросу и каждому K правило записи в память «записать K лучших недоминируемых» гарантированно находит ответ без резерва всякий раз, когда это удалось обычному top-K. Строгое улучшение ожидается при многочисленных высокоранговых вариациях одного отзываемого span.

Строим четыре отдельные SQLite-таблицы одинакового формата (raw top-8/64 и Pareto top-8/64). При промахе абсолютно одинаковый резерв из физических logit BLOB, локальных победителей и верхней границы. Полный Pareto-индекс после наполнения кэша не нужен онлайн. Основной контраст raw-64 / Pareto-64 на 576 уже замороженных запросах, отдельно 8 и разные виды отзыва. Каждую конечную полезную нагрузку сверяем с записью независимого исходного векторизованного перебора. Первичная метрика — число переходов к резерву в 576 случаях, дополнительная — BLOB SQLite→Python и число пересчитанных окон. Сравнение попадания парное, 95% интервал по исходным статьям, оценка также раздельно по двум режимам генерации. Задержки измеряем снова в общей read transaction, 16 статей × 2 вопроса × 6 событий, 18 чередующихся прогретых повторов, p50/p95 по медианам. Фиксируем физические байты вместе с общим резервом и число строк, время создания поверх ранее построенного множества и отдельно его уже измеренную цену. Этот тест использует известные данные и служит механистической проверкой.

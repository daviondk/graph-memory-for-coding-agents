# Какие ответы записывать в ограниченную память

Вместо обычных K лучших ответов по оценке модели записали K лучших **недоминируемых**. Из кандидатов убирается T, если раньше по стабильному рангу есть S с меньшим или равным множеством требуемых символов, S ⊆ T. Основная разница между методами — решение о записи. Размер кэша в строках, исходные оценки, механизм проверки интервалов, резервный читатель и шесть запросов к каждому из 96 вопросов одинаковы.

**Гарантия.** Пусть множество отозванных позиций R, а кандидат i допустим при Dᵢ ∩ R = ∅. Тогда из допустимости T следует допустимость каждого вложенного S. Более высокоранговый S исключает возможность победы T на этом запросе. Поэтому истинный первый допустимый кандидат всего порядка всегда недоминируем. Его позиция в сокращённом списке не больше исходной. Для каждого K и каждого R успешное точное чтение из обычного top-K обязательно успешно и в новом. Гарантия относится к фиксированному рангу и обязательной зависимости от всех позиций Dᵢ. Альтернативные источники («достаточна любая из двух цитат»), изменение ранга после повторного вывода и буквальное редактирование входа требуют другой модели допустимости.

При K=64 доля запросов, полностью обслуженных из кэша, выросла с **51,39% до 79,34%**, +27,95 п.п., 95% кластерный интервал по 48 статьям [23,96; 32,12]. Возвращено 161 дополнительное попадание, потеряно 0. Число дорогих переходов к резерву снизилось на 57,5%, передача числовых BLOB — на 45,45%. Оба кэша содержат по 6 144 строки. Физическая разница составляет 4 096 байт, одну страницу SQLite. При независимом порядке отзывов число промахов 39→13 на 288 событиях, выигрыш по попаданиям +9,03 п.п. [5,21; 13,19]. При направленном отзыве высокоранговых наблюдений 241→106, +46,88 п.п. [40,97; 53,13]. Обе группы используют одни и те же вопросы, различаются события.

При K=8 получено 56 дополнительных попаданий, +9,72 п.п. [6,60; 13,02]. Самый жёсткий случай — восемь направленных отзывов. При K=8 оба метода во всех 96 вопросах потребовали резерв. При K=64 новый кэш самостоятельно ответил в 26 из 96 вопросов, обычный — в 0. Из запрошенных восьми физически независимых записей полные восемь были доступны в 94 вопросах.

Для основного K=64 на 192 измеряемых нагрузках медиана времени запроса 9,025→7,175 мкс; p95 2 902,94→2 501,40 мкс. Для независимых отзывов медианы 5,60→5,50 мкс, p95 615,91→11,05. Для направленных — 828,58→12,63 мкс и p95 3 226,89→3 099,46. Смешение двух режимов (кэш и резерв) делает медиану чувствительной к доле попаданий около 50%. Сами попадания и сумма переоценок лучше переносятся между машинами. Зафиксированы 13 824 отдельных прогретых измерения на 16 статьях. Все 3 456 строгих сравнений результатов с независимым исчерпывающим ответом согласованы, включая отсутствие ответа. Обе системы с резервом возвращают одинаковый конечный результат.

Время записи 64 кандидатов на вопрос из двух уже построенных физических порядков составило 19 мс и 13 мс на 96 вопросов. Подготовка полного множества Pareto и двумерной структуры из исходного ранжирования в родительском исследовании заняла 3,16 с плюс 0,67 с на запись временной таблицы Pareto и 6,60 с чтения исходного порядка. Этот эксперимент использовал предварительно вычисленную полную таблицу для наполнения. На этапе обслуживания она не требуется. Общий резервный индекс с оценками и границами занимает 3 751 936 байт.

## Воспроизведение

Выполнить `python cache_study.py`, `python analyze.py`, `python verify.py --private`. Основной результат — стоимость работы при изменениях допустимой доказательной базы. Это повторное использование одного корпуса и сконструированных сценариев; они не задают естественную частоту отзывов в работающих агентах. Проверки разнообразия других способов заполнения K строк ведутся отдельно.

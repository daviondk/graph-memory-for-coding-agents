# Когда стоит сохранять путь к ещё не прочитанному файлу

Сохранение явных путей из уже показанных результатов поиска расширило достижимость целей в памяти агента. В повторной панели при одинаковом бюджете в шесть адресов найдены два дополнительных файла будущего патча, по одному в двух разных задачах. В основной панели дополнительные адреса расширили полный пул, но число попаданий в первые шесть осталось прежним. Проверенное правило повышения приоритета пути, показанного несколькими типами источников, отдельной прибавки не дало.

## Данные и метод

После каждого строгого пустого поиска восстанавливалось доступное агенту состояние. В старой памяти находились Python-файлы с ранее видимыми фрагментами и иногда непосредственно проверенный адрес текущего поиска. В новую память записывались буквальные имена ещё не прочитанных файлов из выводов ls, find, rg/grep со списком путей, traceback и нескольких строго определённых текстовых форм. Отображённое имя из одноаргументного ls разрешалось относительно каталога этой команды. Из обычной директивы import путь не выводился. Имя, показанное инструментом, само по себе не гарантирует, что файл существует в целевой версии. Репозитории для прогнозирования не индексировались.

В 459 событиях из четырёх непересекающихся групп репозиториев сохранены все прежние кандидаты и до 64 ссылок на корень. Два основных набора содержат полные ранее запечатанные 267 и 73 события R13. В пяти репозиториях предыдущего опыта R14 взяты все 111 подходящих событий, включая 30 исходных событий grounded. Ещё восемь событий получены из 26 доступных историй двух дополнительных репозиториев elastic/curator и apiflask/apiflask. Исходы прежних серий были известны на уровне агрегатов. Новые прогнозы зафиксированы до загрузки поэлементной разметки. Для каждого события повторили восстановление дополнительной памяти после физического удаления всех последующих сообщений. Совпали все 459 состояний. [VibeMemBench](https://arxiv.org/abs/2609.23570)

Сравнивались прежний граф, простая давность, BM25, детерминированный случайный порядок, чередование прежних и новых путей, плоская смесь BM25 с давностью и рангом старого графа. Предложенное правило добавляло к смеси фиксированную надбавку за подтверждение пути двумя различными типами источника в разных событиях. Контроль с перестановкой сохранял число надбавок. Ранжирования общие для трёх заранее заданных лимитов чтения. Величины Hit@k — попадание хотя бы в один целевой путь. Недостижимая цель получает ноль. Все системы получали только наблюдённые ранее данные.

## Достижимость и ранжирование

В таблице «старый → новый» для покрытия означает наличие цели в полном пуле. Для Hit@1, Hit@3, Hit@6 и MRR сравнивается прежний граф с расширенной смесью, учитывающей типы источников.

| Панель и цель | N | Покрытие | Hit@1 | Hit@3 | Hit@6 | MRR |
|---|---:|---:|---:|---:|---:|---:|
| R13 основная, строгий PR | 191 | 137 → 139 | 91 → 86 | 126 → 123 | 134 → 134 | 0,565 → 0,554 |
| R13 повторная, строгий PR | 45 | 35 → 37 | 28 → 27 | 32 → 34 | 35 → 37 | 0,674 → 0,689 |
| R14 все события с известным строгим PR | 29 | 25 → 25 | 14 → 12 | 17 → 19 | 21 → 21 | 0,583 → 0,540 |
| R13 основная, следующее чтение | 176 | 114 → 124 | 60 → 59 | 92 → 93 | 110 → 112 | 0,450 → 0,453 |
| R13 повторная, следующее чтение | 58 | 32 → 34 | 22 → 20 | 29 → 28 | 31 → 33 | 0,450 → 0,435 |
| R14 все, следующее чтение | 88 | 60 → 65 | 27 → 25 | 44 → 44 | 50 → 52 | 0,421 → 0,418 |

**Основное сравнение при бюджете шесть.** На повторной панели строгих PR добавилось два попадания при нуле потерь, ΔHit@6 +4,44 п.п., парный 95% кластерный интервал по задачам от 0 до +11,32 п.п. Те же 37/45 получили обычная давность, BM25 и плоская смесь. На основной панели прежний и новый методы дали 134/191 при двух приобретённых и двух потерянных попаданиях, интервал разницы от −2,06 до +2,16 п.п. Здесь при бюджете один новый метод потерял пять попаданий. Эти выборки поддерживают ограниченный вывод о расширении меню при k=6 и не дают основания объявить победу над SOTA.

**Выделение эффекта записи.** После основного сравнения удалили новые адреса из уже зафиксированного порядка всех файлов, сохранив относительные позиции прежних. На повторной панели strict PR результат снизился с 37 до 35. Оба дополнительно найденных адреса появились в выводе команды поиска, перечислявшей имена файлов. В основной панели при том же удалении результат остался 134/191. Непосредственно добавленные адреса дали 3, 2 и 2 попадания в следующее чтение на трёх панелях при k=6, при фиксированном порядке прежних файлов цель ни разу не была вытеснена. Сравнение двух ранжировщиков целиком даёт и приобретения, и потери, поскольку их старые файлы могут иметь разный порядок. Проверка после раскрытия результатов отмечена в [описании диагностики](POSTHOC_RU.md).

**Материалы по R14.** В исходном эксперименте шесть предъявленных адресов могли покрыть 13 из 19 строгих PR. Полное множество ранее наблюдавшихся файлов покрывало 17/19. Четыре из шести недоступных для решателя целей уже были представлены в старой памяти, но не прошли шестиместный отбор. Остальные две цели отсутствовали и после записи новых адресов. На этих 19 событиях ни один добавленный путь не был целевым. При том же лимите альтернативный BM25 получил 16/19, исходный граф в режиме top-6 — 14/19, новая смесь — 14/19. Число 13/19 описывает прежнее специально сформированное меню, а 14/19 — иной способ выбора шести из старой памяти. Этот результат объясняет, почему расширение хранилища и правильный выбор шести кандидатов требуют раздельной оценки.

**Источник подтверждения.** Среди 3722 позиций новой памяти только 25 имели два типа подтверждения в разных событиях. Таких префиксов было 13 из 459. На всех четырёх панелях для всех трёх целей Hit@6 расширенной смеси совпал с вариантом без этой надбавки. На повторной strict PR-панели варианты дали 27/45 при k=1, 34/45 при k=3 и 37/45 при k=6. MRR у смеси без надбавки составил 0,692 против 0,689. Обычное появление краткого списка имён оказалось более распространённым и достаточным для двух конкретных выигрышей.

## Второй источник целей и стоимость

Для каждого срабатывания после фиксации прогнозов сопоставлено официальное поле patch набора SWE-rebench-V2 с соответствующим instance_id. Из заголовков diff извлечены существовавшие до исправления производственные Python-файлы. Таких целей было 455 на 459 событий. Эта метка доступна и для задач, у которых не подтверждено строгое совпадение родителя PR. В трёх ранее исследованных панелях наборы целей двух источников совпали у 120 из 122, 31 из 31 и 21 из 21 задач со строгим PR. По официальной цели Hit@6 старого графа и расширенной смеси составил 174 → 176 из 265, 57 → 60 из 73 и 76 → 77 из 109 соответственно. На восьми префиксах дополнительных репозиториев подходящих упоминаний не было, оба метода дали 7/8 по официальной цели и 4/6 по наблюдаемому чтению. Этот малый внешний срез проверил переносимость процедуры, но не позволил оценить эффект добавленного пути. [Официальный SWE-rebench-V2](https://huggingface.co/datasets/nebius/SWE-rebench-V2)

Непустая дополнительная память возникла в 110/267, 28/73 и 51/111 событий. Медианный объём сериализованного хранилища с источниками среди таких событий составил 3410, 3626 и 2069 байт. Медиана по всем событиям составила два байта для пустого JSON-объекта в каждой панели. Наиболее крупное состояние требовало 18 840 байт. Отдельно оплачивалось множество адресов, когда-либо показавших содержимое в текущем корне: медианы сериализованных размеров 128, 65 и 130 байт. Это байты логического состояния. Накладные расходы Python-объектов, пиковое потребление процесса и хранение исходных историй сюда не включены. В первой и повторной панели строгих PR среди верхних шести новая политика в среднем использовала соответственно 0,47 и 0,64 ранее не открытых адреса.

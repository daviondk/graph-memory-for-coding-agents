# Проверка и повторение

Распакованный комплект проверяется на стандартной библиотеке Python командой `python -B verify.py`. Нужны только файлы этой папки. Проверяются SHA256, 459 соответствий «префикс — прогноз — метка», все шкалы ранжирования по сохранённым числам, целевые пути, Hit@1/3/6, MRR и средние парные разности. Поле prefix_sha в `causal_receipts.json.gz` позволяет повторно сверить физически обрезанную историю при наличии исходного набора.

Для пересчёта с исходных публичных историй в соседних сериях рабочего каталога должны быть папки `graph_memory_round13/reformulation`, `graph_memory_round14/grounded` и `graph_memory_round12/negative_external`. Локальный источник историй расположен на диске D в `D:/CodexResearch/x20-official-vibe/VibeMemBench/benchmark/history/python`, контрольный каталог исходных объектов находится рядом в `memory-stage-fetch/source-manifest.json`. Идентификаторы, пути к историческим файлам, SHA256 и принадлежность к панелям сохранены в `rosters.json.gz`. Нужные версии предыдущих программ и входов указаны в `flow.json`. Фиксация предыдущих данных и одинаковые идентификаторы не превращают повторные панели в независимые новые датасеты. Исходные истории повторяют опубликованный набор. [VibeMemBench](https://huggingface.co/datasets/Tongyi-ConvAI/VibeMemBench)

1. Выполнить `python -B freeze.py` в копии каталога. Процесс использует стандартную библиотеку и предыдущий извлекатель R13. Он проверяет данные материалов, строит снимки по порядку действий и для каждого повторяет извлечение с отброшенным полным суффиксом. Прогнозы, доказательства совпадения и входы фиксируются в `forecast.lock.json`.
2. Запустить `python -B labels.py` в окружении с PyArrow. На диске доступно `D:/CodexResearch/x20-r8-swerank-runtime/venv/Scripts/python.exe` с PyArrow и NumPy. Официальный parquet хранится в `D:/CodexResearch/x20-round12-negative-objects/SWE-rebench-V2.parquet`, его SHA256 сохранён в `outcome.lock.json`. Эталонные патчи используются только оценщиком для чтения имён из заголовков, в архиве сохраняются пути и хеши. Следующее фактическое чтение для всех событий пересчитывается из следующих пяти вызовов. Исходные 267, 73 и 30 поведенческих меток R13/R14 совпали с новым пересчётом. [SWE-rebench-V2](https://huggingface.co/datasets/nebius/SWE-rebench-V2)
3. Последовательно выполнить `python -B score.py`, `python -B write_effect.py`, `python -B tables.py` и `python -B verify.py`. Статистическая неопределённость оценивается по 5000 перевыборкам целых задач отдельно внутри панели и внутри соответствующего исхода, PCG64 seed 301754, percentile 2,5–97,5. Одно событие может входить в разные исходы. Вложенные срезы grounded_original и grounded_other_tasks не следует суммировать с grounded_all.
4. Для выпуска новой локальной сборки после проверки запустить `python -B package.py`. Временные измерения в квитанциях и хеши, зависящие от них, могут различаться между сборками. Для проверки воспроизводимости содержательных результатов сравнить `forecasts.json.gz`, `outcomes.json.gz`, `results.json`, `paired.json` и `write_effect.json`.

У каждого пути в `frontier_inputs.json.gz` сохранены первая и последняя позиция, число зарегистрированных событий, исходный тип и строка первого наблюдения каждого поддерживающего типа, а также ID последнего вызова. Повторения одного типа в промежутке не сохраняют отдельную полную строку в состоянии. Их можно восстановить из исходной истории и зафиксированного кода. Все конкуренты получают одни и те же прежние фрагменты и одинаковый бюджет top-k. Денежные затраты на LLM в данном автономном опыте отсутствуют.

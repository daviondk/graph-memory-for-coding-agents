# Оценка окончательного патча в изолированном контуре

Фиксированные две задачи и исходные SHA заданы в ../cohort.json. Для каждого соответствующего штатного образа до оценок сверяем локальный image ID и RepoDigest с записью в когорте. Проводим новые калибровки — публичный эталонный патч и текстовый маркер, не меняющий программную логику. Обе проходят через неизменённый release run_eval.evaluate_seed и vendor/eval.py c настоящими тестами; для R15 предыдущие оценки других запусков не заимствуются. Оценочные входы, эталоны и тестовые патчи хранятся вне каталога решателя на D. Docker работает в отдельном оценочном контейнере без сети, ограничение 0,5 CPU, один работник. Автоматические решения не получают оценочных меток.

Два исхода на одну траекторию: штатно обнаруженная авторским run_eval сдача и детерминированная политика, сохраняющая её непустое содержимое, иначе использующая один фактически полученный финальный tracked diff после возврата агента. Содержимое эпизода доступно оценщику только после seal.json. Возвращаем те же байты, включая пробелы и переводы строк. Неудачное чтение финального состояния записываем по RC и stderr; отсутствующая рабочая копия не восстанавливается по траектории. Если при отсутствии штатной сдачи capture недоступен, показан операционный результат без дополнительно сохранённого патча и отдельно отмечена неизвестная правильность ненаблюдавшегося рабочего состояния. Для одинаковой задачи идентичные патчи сравниваем побайтно и вычисляем один общий результат. Первичная метрика — штатный resolved. Отдельно записываем выполнение FAIL_TO_PASS, утрату PASS_TO_PASS, сохранение работоспособного оценочного стенда, число и размер патчей, стоимость снимка. Пустой патч пропускается через официальный evaluate_seed как отдельный вход, проверка его пригодности и запуска тестов отражается дословно. Результаты двух пар описательны.

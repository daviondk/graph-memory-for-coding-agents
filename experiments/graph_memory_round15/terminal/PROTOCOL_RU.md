# Однократная запись рабочего состояния при завершении настоящего решателя

В R13 одна правильная правка flake8 осталась в рабочем дереве при пустой сдаче. R14 показала, что последний доступный ранее опрошенный снимок достаточен в этой малой выборке, однако состояние непосредственно перед удалением тогда не запрашивалось. Здесь проверка проводится на **двух других репозиториях**, на которых известен работающий исполнительный контур. Это целевой перенос между проектами для способа сохранения состояния. Эти репозитории использовались в более ранних исследованиях Vibe, выбирать задания как неизученные во всём проекте нельзя.

Зафиксированы swerebenchv2/brazilian-utils-brutils-python:125-9046eed и swerebenchv2/s-knibbs-dataclasses-jsonschema:64-dad240e, по одному запуску. Память в prompt выключена, чтобы эффект заключался только в сохранении уже сделанной работы. Решатель Qwen3.8-27B UD-Q4_K_M, температура 0,5, seed replicate 1, лимит 24 модельных вызова, свежий контейнер, штатный mini-swe-agent и run_instance. Задание видит только безопасные поля из original test data. При завершении агента сравниваем штатную сдачу с политикой «сохранить официальную непустую сдачу, иначе единожды получить git diff HEAD по tracked-путям». Запись выполняется после возврата управления от агента и до удаления контейнера. При отсутствии контейнера исход регистрируем как недоступное чтение. Никакого выбора промежуточного состояния и дополнительных подсказок. Ожидаемый выигрыш нулевой, если официальная сдача пуста и финальная правка также отсутствует либо некорректна.

Одинаковые патчи в пределах задачи по точным байтам допускают единственный вызов официального оценщика. Проверяем эталонную и пустую либо нейтральную калибровки, опираясь на сохранившийся авторский тестовый патч. Фиксируем число поданных патчей, корректность по F2P/P2P, интервалы и размер снимка, цену чтения, число вызовов модели, статус контейнера. Первичная оценка — парная доля resolved.

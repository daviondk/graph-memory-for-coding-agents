# Проверка R15/menu_action

Из распакованного каталога выполните `python -B package.py`. Инвентаризация проверяет каждый обычный файл верхнего уровня, сохранённые квитанции по 32 публичным PR и содержимое файлов в `blobs`. Временные `vendor_git` (загружаемые зеркала для определения родительских коммитов) и `__pycache__` исключены. Собственные исходные тексты прочитанных файлов остаются материалами их upstream-репозиториев. Для сверки результатов и счётчиков по сохранённым данным нужны стандартный Python и соседний R15/frontier. Команды следует выполнять в рабочей копии: пересчёт перезаписывает соответствующие выходные файлы.

```powershell
python -B score.py
python -B exposure.py
python -B package.py
```

`score.py` проверяет цепочку контроля SHA256, точные тела JSON-запросов и ответов, соответствие параметру инструмента, успешные открытия по обоим хешам, нативно подтверждённые отсутствия. Из `menus.json.gz`, `reads.json.gz` и `heldout.json.gz` он восстанавливает `outcomes_scored.json.gz`, парные векторы, знаменатели и точные двусторонние sign tests. Дополнительно вычисляет описательные интервалы парной бутстреп-перевыборки задач (10 000, seed 20261121), без поправки на связь задач внутри проекта. При отсутствии различающихся запросов интервал из наблюдаемых пар вырожден и не характеризует неизвестное воздействие типизации. `exposure.py` извлекает только предшествующие наблюдения по выбранным префиксам и сверяет их с зафиксированными меню.

## Полный прогон с исходных данных

Используйте самостоятельную рабочую копию с новой пустой папкой результатов. Скопируйте в неё `PROTOCOL_RU.md` и сценарии *.py. Рядом нужны R15/frontier и те же предыдущие исследовательские каталоги на D. Для самостоятельного пересчёта исходного ранжирования см. [R15/frontier](../frontier/REPRODUCE_RU.md). Путь к модели и конфигурация сервера задаются вне этих скриптов. Исходный нативный сервер использовал Qwen3.8-27B UD-Q4_K_M, идентификатор API qwen38-27b-ud-q4km, system_fingerprint `b12441-164ab018f`, сценарий обращается только к 127.0.0.1:18952. Выбор инструмента, json schema, seed, greedy, отсутствие thinking и бюджет записаны в каждый исходный JSON запроса. Детерминированность вывода между разными сборками сервера и аппаратными платформами не гарантируется.

1. `python -B menu.py prepare` требует pyarrow и датасет метаданных SWE-rebench-V2 на пути, заданном в сценарии. Считываются только repo, instance_id, base_commit. SHA256 замка исходных прогнозов `85b7c82f0b767333618cb2401529bc58a9fc7cc871d974b220c4ef6da86635bd` проверяется до отбора. Готовые назначения записаны в `assignment.json` со ссылками на меню, тексты запросов и логические пары. [Данные метаданных](https://huggingface.co/datasets/nebius/SWE-rebench-V2/tree/d7608f017a29ab256400ad4b73d5248d97204966)
2. `python -B menu.py run` запускается на локальном сервере. Сохраняются полный ответ, тело, usage, elapsed time и контрольная сумма. При повторном запуске в той же папке ранее сохранённые отдельные ответы переиспользуются. Для чистой репликации нужна пустая папка. `python -B menu_coverage.py` строит входную диагностику других k. `python -B exposure.py` строит описание затрат и доступных ранее непрочитанных путей.
3. `python -B open_reads.py` проверяет запечатанные действия. При наличии файлов использует локальные копии Git-объектов, затем неизменяемый публичный URL с точным SHA коммита. Время ожидания и конкретный источник байтов зависят от состояния Git-кеша и сети, содержимое сверяется по SHA. Фиксирует `read.lock.json`.
4. Только после шага 3 `python -B truth.py` проверяет настоящий merge SHA в публичном PR, первый родитель, время и diff без автоматического поиска переименований. Учитываются старые пути со статусами M, D, T с исключением тестовых, документационных и example-файлов, как в предыдущем протоколе R13. Поведенческие метки восстанавливаются из контрольных сумм оригинальных JSON-историй и пяти последующих инструментальных действий. Нужны публичный Git-доступ и официальный локальный снимок истории, который использует R13/reformulation. SHA256 использованных источников R13: `prefix.py` ab421423a6b24f1159b602eddd963fb7e3ceabf33d30d00e1db8f93addd455c1 и `pr_oracle.py` 57046a7a85e8441463063f9f7fb5b9f69fd6f2ab3300f4ee06cf16ccbb258920. Затем `python -B score.py`. [Исходные истории](https://huggingface.co/datasets/Tongyi-ConvAI/VibeMemBench/tree/11164976b4f920cdb0d0cd570ca572e49acea1e8)
5. Перед созданием собственного манифеста добавьте отчёт и инструкцию. `python -B package.py --write` подписывает только результаты этой новой сборки. В исходной поставке достаточно режима проверки. Зависимые от времени величины, идентификаторы HTTP-сессий и любые контрольные суммы, включающие эти журналы, при отдельном запуске будут отличаться.

Поштучная таблица результатов содержит идентификаторы задачи/события, руку, запрошенный и реально открытый путь, валидность, достижимость и попадание обоих исходов, затраты. JSON-значение null у метрики означает отсутствие применимой метки. Независимое размножение идентичных LLM-запросов не проводилось. `logical_calls.json` восстанавливает, какой нативный ответ обслужил каждую из трёх веток.

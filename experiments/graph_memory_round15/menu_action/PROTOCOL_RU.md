# Проверяем, изменит ли запись ещё не прочитанных путей инструментальное действие

Исследователям известны прежние результаты R13/R14 и размеры новых панелей, но индивидуальные эффекты R15/frontier ещё не использованы. Исходы нового R15/menu_action не читаются до фиксации всех выборов и физического открытия выбранных файлов. Три исходных ранжирования уже запечатаны. Первичный контраст — typed_union против flat_union, оба работают с теми же допустимыми найденными путями. Дополнительный — против view_graph на ранее адресованных файлах.

Все три политики предлагают шесть путей. В первичную выборку входят префиксы, у которых во всех трёх политиках есть шесть различных путей и хотя бы одно из множеств шести различается. Берём первый допустимый префикс на задачу и до 12 задач на панель по фиксированному хешу. Изучаем именно случаи, когда состав видимого меню может повлиять на следующее действие. Среди трёх методик ожидаются и побайтно совпадающие входы. Число таких пар и общий охват всей совокупности отмечаем. Неисполненный вариант с пустым/коротким меню не засчитываем как ошибку модели. Исходные панели из Vibe использовались прежде, внешняя добавлена при R15.

Один Qwen3.8-27B UD-Q4_K_M с greedy и одним seed выбирает ровно один read_file по условию задачи, области и литералу закончившегося пусто запроса. Предъявляем только пути, отсортированные одним и тем же независимым хешем, без позиций/признака ранжировщика и без выделения новых записей. Варианты отличаются только составом возможных действий. Точная копия полного JSON-входа может ссылаться на уже полученный ответ. Выполняем чтение каждого логически выбранного пути по действительному base commit. Вся память и цены её извлечения учтены в соседнем опыте. Число пунктов фиксировано, длины имён и фактические токены фиксируем отдельно.

Первичный исход — прочитан ли один из существующих production Python-файлов будущего PR при точном совпадении base с первым родителем merge. Дополнительные — доступность такого файла в меню, изменение решения внутри задачи, ближайший фактический просмотр, отказы инструмента, токены, выигрыши и потери. Для идентичных меню детерминированный решатель с идентичным полным запросом логически не может дать иной результат. Сводить абсолютные проценты этой выбранной панели с результатами сквозного SWE-бенчмарка нельзя. [Происхождение путей](../frontier/PROTOCOL_RU.md)

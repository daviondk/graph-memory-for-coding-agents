# Совместимость с независимыми метриками IssueLoc-Bench и SWE-Explore

До открытия индивидуальных внешних меток проверяем пересечение идентификаторов официальных релизов с ранее запечатанными прогнозами рабочей памяти. Используем все исторические события обеих панелей R13/reformulation и 30 задач R14/grounded. Один заранее фиксированный префикс на задачу — самый ранний подходящий. Для IssueLoc требуем точное совпадение идентификатора и базовой Git-ревизии при наличии у обоих источников. Для SWE-Explore отдельно учитывать условия версии и потенциальный общий источник траекторий. Эксперименту уже известны результаты прежних внутренних метрик. Физически отделяем перечень доступных ID и метаданных версий от этапа открытия внешнего gold. Идентификаторы, написание разделителей и регистр сравниваются с явными правилами без неясного fuzzy-matching.

Если пересечение непустое, первична оценка зафиксированного ранга файлов, когда целевой пакет поддерживает метрику уровня файла. Для межбенчмаркового сравнения важна доступность тех же самых данных: наша память начинает с префикса реальной работы, авторский explorer может обращаться к всему дереву с начала. Нельзя переносить результаты подсхемы на весь официальный рейтинг. При отсутствии совпадений выводим измеренное покрытие, изучаем структуру оригинального scorer и решаем вопрос о новом сопоставимом запуске. У SWE-Explore результаты по регионам и строкам требуют выдавать настоящие адресованные диапазоны и оплачивать единый лимит строк; фиктивные диапазоны во имя получения балла не назначаются.

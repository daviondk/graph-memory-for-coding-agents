# Дополнительный контроль на публичных исходах двух бенчмарков

Исходными 245 (точное число в coverage.json) задачами R13/R14 охватить стандартные внешние релизы не удалось. До открытия индивидуальных внешних исходов через идентификаторы проверена другая серия архивных наблюдений — все 199 задач R11/readback. Совпали 198 номеров репозитория и задачи с преобразованным SWE-bench Verified в IssueLoc и 179 идентификаторов с SWE-Explore. Отбор основан только на идентификаторах. Весь архив предшествует этому внешнему оцениванию. Возможная общность источника траекторий для SWE-Explore должна быть показана отдельно.

Сравниваем **какую часть уже наблюдавшихся результатов редактирующего инструмента сохранять для следующего обращения**. Берём префикс до третьего видимого чтения включительно, если их меньше — все, при полном отсутствии возвращаем пустую память. Каждой задаче один префикс вне зависимости от последующего успеха. Точные номера строк предписано брать только из ранее показанных строк. Три заранее зафиксированных считывателя на одном входе (1) последнее чтение первым, затем ранее показанные строки; (2) первый увиденный файл первым; (3) прежде всего повторно наблюдавшиеся файлы, затем те, что разделяют больше идентификаторов с прочими увиденными фрагментами, затем давность, стабильный порядок по пути. Четвёртый контроль — только число повторных чтений без графовых связей. Каждый возвращает до трёх различных путей и до 60 уникальных строк всего, ограничение действует и для одного файла. Показываем эффективное покрытие задач и одинаковые предсказания. При префиксе в три чтения множество доступных файлов не может зависеть от ранжирования. Имеет смысл оценивать top-1, порядок и отбор строк при заполнении квоты.

Первично на исходном IssueLoc — его нативный file Hit@1 и Hit@3 при корректном соответствии задач. Отдельно на SWE-Explore — качество выдачи реальных регионов при общем лимите строк согласно штатному коду. Никаких выданных извне правильных имён или непоказанных диапазонов. Оцениваем целиком заранее определённые сопоставленные множества с нулями для пустой памяти, отдельно условный эффект при непустом входе. Если в явном публичном манифесте нет commit SHA, показываем метрики как переоценку задач по точному идентификатору и происхождению. Для доступного строгого сравнения необходимо аудировать исходную версию. Это не замена прогону опубликованного explorer с самого начала задачи. Запрещаем использовать метки R11/R15, тексты будущих наблюдений, ground_truth или read_step_info цели при построении выдачи.

# Поиск завершённых прошлых исправлений в SWEContextBench

Результаты от 16 ноября 2026 года. Представлены аудит ранее зафиксированных выборов на Lite и самостоятельный CPU-эксперимент на 258 официальных задачах вне Lite. Прежняя библиотека Lite содержит 300 траекторий. В новой библиотеке 1 007 описаний реальных PR с человеческими патчами. Автоматический составитель карточек получает симптом и признаки правки из уже завершённой работы. Входных данных о порядке действий агента в полной библиотеке нет.

## Что показал эксперимент

| Набор | Разные задачи | Разные целевые PR | Есть метка более раннего исправления | Есть метка того же целевого PR |
|---|---:|---:|---:|---:|
| Lite | 99 | 87 | 17 | 27 |
| Остальные | 258 | 193 | 38 | 91 |
| Все | 357 | 277 | 55 | 118 |

Имеются 360 уникальных связей (задача, источник опыта). Из них 55 ведут к ранее принятому PR, 187 — к другому PR, принятому в момент отсечения или позже, и 118 — к тому же PR. У всех размеченных связей удалось вынести решение. Источник считается доступным только после слияния его PR и строго до открытия новой задачи. Время открытия — самое раннее из дат указанных авторами issues, открытия целевого PR и поля created_at релиза. Для Django использована дата открытия тикета Trac. У 279/300 PR из библиотеки Lite слияние датировано GHArchive, у остальных 21 — явно указанным на странице GitHub событием слияния. Время исходного запроса Lite получено для 57 задач из GHArchive, 36 из Django Trac и шести со страниц GitHub. Семь из семи полученных ответов прямого GitHub REST при отдельной выборочной проверке дат совпали до секунды. Для оставшихся девяти из шестнадцати исходно выбранных запросов REST вернул ограничение частоты. Эти результаты сохранены в rest_spotcheck.json.

У первоначального читателя Qwen на статическом выборе 75/99 по any и first, 73/99 по last. На момент исходного запроса 13 из 75 правильных источников уже были приняты, 62 ещё не были доступны. Если брать момент открытия текущего PR, соответствующие числа 23 и 52. При слиянии целевого PR — 25 и 49 плюс одна неизвестная дата цели. Смена определения времени на «достаточно открытия прошлого PR» даёт 18/99 задач с размеченным опытом, при таком определении 14/75 правильных выборов уже существовали как открытые PR. Диагноз относится к переносу законченного решения между реальными задачами. Официальный статический выбор допускает весь предоставленный набор историй.

Сравнение патчей 27 размеченных пар с общей идентичностью целевого и исходного PR нашло 13 полных совпадений при нормализации изменённых строк и 0 совпадений исходных байтов. Для 75 пар с разными PR — 0 совпадений изменения и 0 совпадений байтов. Среднее мультимножественное сходство Жаккара 0,802 и 0,009. В ключ строки входят путь и тип операции, пустые строки отброшены, внутренние пробелы нормализованы. Это отдельная послепредикционная проверка опубликованных патчей. Qwen при прежнем выборе получил подготовленные описания опыта.

## Предсказания на 258 задачах

| Вход в поиск | Hit@1 | Hit@5 | MRR | Hit@1 в том же репозитории без фильтра времени |
|---|---:|---:|---:|---:|
| BM25 по 256 словам issue | 25 | 35 | 0,113 | 141 |
| BM25 по 192 словам issue | 26 | 35 | 0,115 | 145 |
| BM25 по признакам патча | 26 | 38 | 0,116 | 111 |
| BM25 по карточке 192 + до 64 | 26 | 36 | 0,117 | 151 |
| Карточка с правкой другой задачи | 22 | 34 | 0,106 | 130 |
| Самый поздний из допущенных PR | 18 | 31 | 0,092 | 13 |
| Взвешенное слияние двух ранжирований | 28 | 38 | 0,121 | 153 |

Знаменатель каждой задачи во всех методах сохранён, недоступная метка даёт ноль. В основном сравнении прочитываются завершённые PR из того же репозитория. Из 258 задач из 39 репозиториев метка присутствует у 38, медиана общего допустимого пула 4. У контрольного метода чужое поле заменяется по детерминированной циклической перестановке с тем же числом слов. При единственном подходящем кандидате другого донора нет, поэтому поле пустое. Раздельное ранжирование использует 2/(12 + ранг симптома) + 1/(12 + ранг признаков правки). Частоты BM25 посчитаны заново в допустимом пуле. Для объединённой карточки по сравнению с 256 словами симптома улучшились две задачи, ухудшилась одна. Разница +0,39 п.п., 95% bootstrap по репозиториям от −0,94 до +1,97 п.п., двухсторонний точный парный p = 1. При сравнении с чужим полем четыре улучшения и ноль потерь, p = 0,125. С 192 словами без правки количество первых попаданий то же. Все сравнения, кроме одного первичного, разведочные. Парные p по индивидуальным задачам описательные, доверительные интервалы построены отдельным методом с учётом репозитория. Небольшое число различающихся пар ограничивает точность обоих методов.

Если метка доступна и кандидатов ≥5, карточка дала 21/31, 256 слов — 20/31, чужая правка — 17/31, раздельное ранжирование — 23/31. В режиме поиска по всем репозиториям с временным отсечением карточка дала 27/258 против 25/258, медиана пула 445,5. Без отсечения в своём репозитории — 151/258 против 141/258, 20 улучшений и 10 потерь, +3,88 п.п. (95% от −1,36 до +8,68, p = 0,099). Временной перенос показал слабый сигнал достоинства раздельных полей, доказательства повышения успешности решения задач пока нет.

Текст карточек до токенизации — 1 285 563 байт против 1 215 131 у описаний. Признаки правки содержали в среднем 22,17 слов. Однопроцессорная реализация на Python при прогретом кэше завершила запись и семь ранжирований в трёх режимах за 17,19 с суммарно, включая запись 1,58 с. Пересекающиеся вычисления базовых методов были переиспользованы. Время скачивания, проверки часов и последующего анализа сюда не входит. Для рассматриваемых ранжирований LLM и GPU не задействовались.

## Что именно воспроизводится

В распакованной папке выполнить `python verify_local.py`. Требуется Python 3.10+. Доступ к сети, к исходному parquet и к другим папкам для этой проверки не требуется. Проверяются SHA-256 протокола, кода и предсказаний, все 5 418 списков (258 × 3 режима × 7 методов), их состав относительно независимого календаря, каждая оценка и агрегаты, 357 исходных задач, выбранные 99 записей Lite и пары патчей. Происхождение таблиц и текстов записано в файлах ниже.

- PROTOCOL.md и CLOCK_ADDENDUM.md задают дизайн и добавление аудита до вскрытия новых результатов. blind_freeze.json фиксирует состояние кода и предсказаний до получения оценок. Это локальная фиксация без внешнего реестра.
- blind_ranks.jsonl.gz содержит каждый полный список, а per_question.csv — каждую оценку. results.json включает все три режима, чувствительность к first/last, страты, число конкурентов, попарные расхождения, интервалы и p. Порядок ссылок first/last берётся из официальной таблицы связей. run_cost.json — время и объёмы.
- source_times_lite.csv и query_times_lite.csv содержат независимые от ответов ключи источников, даты источника и даты цели, действительные номера PR, страницы и происхождение часов. Суффикс ID текущей задачи иногда соответствует issue и не всегда совпадает с номером её PR.
- lite_chronology.csv и lite_source_links.csv содержат результаты проверки всех прежних выборов, lite_patch_overlap.csv — пары патчей, multiset-метрики и SHA-256 исходных текстов. full_chronology.csv и history_times_full.csv дают наименьший набор для проверки возможности переноса во всём релизе.
- github_times.json, case_refs.json, issue_dates.json, html_clock_evidence.json — кэш календаря и идентификаторы Git blobs с provenance. Запрос к GitHub Events и критерии обработки HTML записаны в prepare.py, date_fallback.py, issue_dates.py.
- Воспроизведение с исходниками требует Python 3.10+, pyarrow и requests. Скопировать пакет в отдельную пустую рабочую папку, чтобы сохранить оригинальные SHA-256. Из папки выполнить последовательно `python rank.py`, `python score.py` с доступом к указанным в source.json версиям parquet и включёнными календарными JSON. Полный повтор получения веб-календаря дополнительно запускается через prepare.py. Официальные parquet скачиваются в TRANSFER_CACHE при отсутствии копии. По умолчанию он расположен в D:/CodexResearch/x20-swe-context/full-transfer. Если рядом существует локальная копия, её хеш необходимо сверить с source.json либо results.json для Relationship. Для воспроизведения первичной выгрузки исходных 99 ответов нужна предыдущая папка sota_round/swe_context с хешами из lite_chronology.json. В пакет включены спроецированные выборы по ID.
- При полном перезапуске время исполнения, timestamp и заголовок gzip меняются. Сравнивать содержимое расжатого списка, per_question.csv и численные метрики. Публичные страницы и их HTML могут изменяться после указанной даты, при офлайн-проверке используется замороженный календарь.
- Предыдущая оценка этих 258 описаний пользовалась библиотекой всего из 300 траекторий. Задачи отличны от Lite, но повторно использованы в этой семье тестов. Опубликованные тексты issues могли редактировать позже, строгая дата слияния не гарантирует доступность записанной траектории в ту же секунду, а отсутствие метки не означает отсутствие других полезных предшественников. Полученные числа описывают поиск опыта, связанного с задачей в официальной разметке. Для оценки решателя нужны исполняемые тесты и повторные прогоны.

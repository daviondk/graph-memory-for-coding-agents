# Write-time transfer of historical bug-fix evidence (16 November 2026)
This is a locked local research protocol. We knew the preceding Lite experiment and its 258-query diagnostic with only 300 historical traces. We have not opened the non-Lite question-to-experience links or computed retrieval performance with the enlarged library in this study. The same benchmark family is reused. The 258 query descriptions are disjoint from Lite but were previously ranked against the smaller pool. There is no untouched test claim.

Population: unique Full related IDs minus 99 Lite IDs, 258 intended. Corpus: all unique IDs in the official Experience parquet at the same pinned HF revision as Lite. Each stored experience represents an earlier known human PR fix; it is not an observed agent trajectory. No current patch, test patch, hint, URL or link label is an input. For each query the primary pool is restricted to the queried repository and historical PRs confirmed merged strictly before the start of the target. Use GitHub event times via ClickHouse, with an optional public GitHub API fallback for missing timestamps. The ordinary target cutoff is the minimum of recorded creation and known official PR opening. Also collect the current issue numbers from official Full cases, and take the earlier observed issue creation where it exists. The strict sensitivity excludes cases without validated opening time for every associated number. Exclude self. Source without a positive observed merge timestamp is never admitted. No whole repository checkout. All candidate-frequency statistics are calculated within the eligible pool, never learned from later fixes.

Primary comparison: BM25 on a single compact card (first 192 sanitized whitespace words of the historical issue + at most 64 selected code/path words from the prior patch) versus first 256 words of the historical issue. Equal maximum text budget. Preserve the order of file paths, hunk anchors, identifiers newly added and then removed, omitting duplicate words and blank lines. Ranking tokenizer splits snake/camel compound identifiers; remove literal GitHub references, full/marked hashes, explicit issue/ticket numbers and wrapper paths in query and source issue. BM25 k1=1.2, b=.75, positive IDF; stable lexicographic instance-ID ties. Query first 280 sanitized words. No model tuning. Primary endpoint exact Match@1 for all non-Lite questions under the availability rule (impossible cases score zero). Secondary Recall@5, MRR (full list), and paired wins/losses, p from exact two-sided McNemar as descriptive; uncertainty by 10,000 repo bootstrap, seed 16112026. Show coverage, date diagnostics, repo cluster count, nontrivial subset with >=5 admissible candidates and gold present, both when strict metadata available vs all. Report both full subject-and-time condition and cross-repo (time only), as well as optional release-pool diagnostic without time filter clearly labelled offline only. Same precomputed rules throughout.

Controls: 192-word issue only, historical edit field only, equal word-count placebo (a different eligible case chosen by deterministic digest order cyclic shift within the eligible pool, truncated/repeated to match each card's true number of added words; no donor where only one case), and recency-only. Include cost of write payload and lexical retrieval with all controls amortized, full per-question predictions/ranks before reading gold, signed lock over source & code, gold score joins only after blind lock. Compare the per-question matches for the primary pair under any link, first link and last link. For each source hash/commit retain receipts and implement replay. Conditional strata are evaluated separately and are not leaderboard metrics. Optional logs or historical issues may have been edited later; reconstructed input is the released issue text, not a verified historical snapshot. A pass at retrieval does not measure solved patches.

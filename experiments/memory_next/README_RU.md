# Эксперименты с памятью кодового агента

Это том с первичными результатами нового этапа. Отчёт в Word и PDF использует данные из этого архива. В Word вложена побайтовая копия ZIP. Имена целевых файлов — agent-memory-next-results.docx, agent-memory-next-results.pdf и agent-memory-next-records.zip.

## Проверка без сети или GPU

Распакуйте **весь архив** в пустой каталог. Нужны Python 3.11+ и NumPy. В этом каталоге выполните:

    python -B verify.py

Проверка сверяет точный список и SHA-256 каждого файла. Затем она самостоятельно восстанавливает исходы из замороженных списков, сопоставляет прогнозы и метки, проверяет доступность источников по времени, подсчитывает расходы, сверяет с контрольными суммами ответы оценщика и исходы отдельных ремонтных работ. Временные файлы экспериментов, журналы и исходные назначения имеют собственные более ранние контрольные суммы там, где они фиксировались. Общий манифест показывает целостность поставки; фиксация протокола в локальном журнале не является публичной регистрацией с независимой меткой времени.

Запуск отдельных автономных проверок также возможен через write_factor/verify.py, read_policy/verify.py, transfer/verify_local.py, verify_time_read.py, abstain/verify.py, continuation/verify.py, map_audit/verify.py и repair/grading/verify_archive.py. Подробности по 128 перестановкам — в write_factor/perm_robustness/README_RU.md. Полный ранг и попадание в top-k — разные величины. Условный счёт среди вопросов с доступной меткой всегда требует отдельного знаменателя. Ключи полей и единицы затрат определены в протоколах соответствующих каталогов.

Для воспроизведения прогонов с нуля понадобится прежний пакет **agent-memory-benchmark-records.zip** (SHA-256 af79fefa9323063315170907e13c770c30ef7d17fcbcc4a69d97745066ef6a38). Разместите новое содержимое в work/memory_next и распакуйте прежний пакет в соседний work/sota_round, чтобы каталог swe_context находился в work/sota_round/swe_context. В нём находятся первоначальные карточки, запросы, код ранжирования, таблицы связей и зафиксированные предыдущие результаты. Часть путей внешних кэшей в исполняемых файлах привязана к диску D. Если расположение другое, укажите путь через поддерживаемую переменную окружения или в новой рабочей копии. Замороженные файлы архива сохраняйте отдельно.

1. **Факторный опыт записи.** Инструкции по генерации полных рангов на CPU, весам Contriever, версиям и порядку запуска находятся в write_factor/README_RU.md. Для повторного подсчёта по сохранённым рангам достаточно автономной проверки.
2. **Правило показа деталей.** В read_policy/README_RU.md задан порядок policy.py и evaluate.py. Пара состояний конкретного вопроса взята из журналов прежнего исследования. Запуск LLM для самой политики не требуется.
3. **Расширенная библиотека.** Порядок получения оригинальных parquet, метаданных времени и ранжирования описан в transfer/PROTOCOL.md. Основная цепочка — prepare.py, rank.py, score.py. Для доступа к parquet используется pyarrow, клиент HTTP — requests. Версии официального релиза, SHA-256 и источники дат — в source.json и в файлах проверок отдельных стадий. Текущие ответы внешних API могут отличаться; для сверки исходных дат сохранены их проекции.
4. **Чтение по времени.** В time_read сначала выполняется predict.py, затем read.py и score.py. Для генерации новых ответов требуется тот же сервер локальной модели и формат чата; для проверки уже состоявшихся обращений достаточно архива. Восстановление словаря только по прошлым документам и фильтрация уже посчитанного статического гибридного ранга — разные условия. Сопоставление с опубликованным статическим REM остаётся в предыдущем томе.
5. **Исправление кода.** Настройки лимитов решателя и исходные изменения протокола лежат в repair/PROTOCOL.md и repair/AMENDMENT-before-solver.md. Для новых запусков нужны Docker, авторские образы по дайджестам, локальный сервер Qwen и исходные данные. Для полного воспроизведения тестов ориентируйтесь на repair/grading/README_RU.md, upstream_pin.json и image_manifest.json. В repair/runs сохранены сообщения инструментов, модельные ответы, команды, расходы и фактический патч. У завершений по лимиту есть отдельный статус.
6. **Передача состояния.** В continuation/PROTOCOL.md зафиксированы общий checkout, правила сериализации прошлого журнала, бюджеты продолжения и оценивание. Чтобы вновь выполнить вторые сессии, нужны Docker и тот же локальный решатель. Сверка назначений, моделей, журналов и официальных результатов доступна автономно.
7. **Историческая селективная выдача и внешний аудит.** В abstain сначала выполняется predict.py, затем score.py. В map_audit классификация источников предшествует присоединению опубликованных исходов. Их агрегаты можно перепроверить по копии данных авторов. Локальный Qwen не решал эти 380 эпизодов.

В repair/grading/official_execution.zip находятся оригинальные подкаталоги receipts и attempts. Для повторного запуска оценивания продолжений, использующего файловый путь к первичным квитанциям, распакуйте этот внутренний ZIP в repair/grading отдельной **рабочей копии**. Позднейшая автономная проверка всего поставляемого архива сравнивает точный состав и проводится в чистом каталоге.

## Повторная сборка отчёта

За неё отвечают report.py, _layout.py и функции report_section.py соответствующих частей. Установите python-docx. Задайте переменную окружения MEMORY_NEXT_OUTPUT с абсолютным путём к каталогу сборки на D и поместите туда под исходным именем ZIP этого тома. Выполните python -B report.py из корня распакованного архива. Для PDF используйте LibreOffice в безоконном режиме с аргументами --convert-to pdf --outdir и именем полученного документа или доступный рендерер документов. Встроенную побайтовую копию исходного ZIP можно извлечь непосредственно из DOCX по имени word/embeddings/research-records.zip. Временная метка пакета Word и конкретный набор шрифтов могут изменить байты экспортируемого PDF при одинаковом содержании.

Модельные вызовы выполнялись через локальный API к Qwen3.8-27B. Текстовые summaries прошлого могут содержать ошибочное толкование результата самим агентом. Успешность исправления определялась исполнением тестов на исходной версии репозитория и конкретном патче. Разработческие PR в расширенной библиотеке — исторические исправления людей. Они имеют другой формат и происхождение, чем журналы действий в 300 записях Lite.

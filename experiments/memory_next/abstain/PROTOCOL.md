# Selective delivery of tool-derived experience at issue opening

Exploratory secondary experiment designed after knowing overall historical coverage (38/258 outside Lite) and overall ranker aggregates. No per-case outcomes or labels will enter policy code. Freeze the run inputs and all decisions before scoring. Universe: all 258 original non-Lite query identities and the 1,007 historical PRs, same candidate pool and already-frozen compact card top-1 from transfer ('repo_time', 'card'). Selection never changes the recommended record: only deliver it or abstain. Targets retain issue input; no solution, test, link or target PR number used in scoring the evidence. Prior content is the masked earlier issue plus historical edit identifiers from the old writer. This tests whether a memory broker can skip weak matches. Ground truth is a link in the release, not ground truth for actual usefulness to the solver.

Prediction policies and baselines set before running:
1. Offer every available top record. For pools with >=1 item, use uniform thinning matched to the policy's delivery count as an analytical expectation, separately across repositories.
2. BM25 absolute score using the already-selected document; and near-tie confidence: difference between its score and the strongest alternative (0 if no alternative). Online IDF from same historical pool, default transfer BM25. No supervised calibration.
3. Identifiable implementation evidence: case-sensitive complete file/path basenames with extension, Python-style dotted member names, camel/Pascal identifiers and underscore identifiers appearing literally in query and example. Mask issue/PR numbers and URLs first. Deduplicate. For each overlapping string compute log((N+1)/(df+.5)), weight 2 for a term present in edited paths/identifiers (an explicit observed edit) and 1 if only in earlier issue. Count only the strongest three contributions to avoid long documents. Predetermined operational rule: at least one such exact token in the earlier edited field, or two different exact identifiers in the earlier issue text.
4. Compare against absolute BM25 and margin at 25%, 50%, 75% budgets over nonempty pools (ceil; deterministic ties by SHA256 of query ID). These are retrospective budget curves; selecting a global quantile uses future unlabeled scores, so only the fixed rule is an immediately executable online policy. Main descriptive endpoint: number of originally linked top-1 records retained versus fraction of inputs delivered. Report precision = linked/calls and recall of gold that the all-offer policy would have found; overall and per-repo counts, known historical links unreachable by any current top-1, conditional extras versus matched random. Select no winner from the three budgets. Source cards are proxy observations reconstructed from historic human changes; no new solver success implied. Save per-query blinded score/decision and all scoring scripts. No further tuning on this cohort.

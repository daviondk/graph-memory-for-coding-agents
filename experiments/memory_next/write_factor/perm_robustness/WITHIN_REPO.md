# Контроль смешения репозиториев

К моменту регистрации известны 64 глобальных контрольных перестановки и результаты исходного факторного опыта. В Lite оказалось 12 репозиториев, каждый содержит минимум три исторических записи. Регистрируем вторичную механизмную проверку до просмотра её новых списков и исходов. Причина — у имён файлов/символов есть свойство указывать на репозиторий, поэтому обмен полями между разными проектами может дать чрезмерно лёгкий контроль.

Использовать те же чистые три BM25-поля, веса, 300 записей и первые 99 вопросов Lite. При каждом из 64 назначений строго сохранять репозиторий донора и получателя. Внутри проекта ранжировать документы по числу слов в правках и ранее определённому хешу salt|key, попарно обменивать соседние; если число нечётное, последние три в отсортированном порядке проходят циклическую перестановку. Для сравнимости использовать те же соли 0..63. Регистрация включает поле GitHub repo из source_times_lite.csv и query_times_lite.csv без меток. Подтвердить, что все карты переместились и весь набор полей/бюджет в каждом из 12 проектов полностью сохранился. Описать фактическую долю разных уникальных назначений, диапазон разности длин внутри пар и возможность ограниченной изменчивости в малых репозиториях.

Основной диагностический исход — число первых совпадений с разрешённой меткой на этих же 99 вопросах. Вторичные Hit@5, MRR и доля top1 из верного репозитория. Пересчитать показатели в полном пуле и после ограничения уже посчитанного списка репозиторием вопроса, в каждом случае сопоставить исходную лексическую систему, удаление поля, 64 исходных глобальных и 64 новых внутрипроектных назначения. Полный порядок (включая ничьи и глобальную IDF) сохранён, режим ограничения использует известный репозиторий и сохраняет глобальные статистики. Все новые прогнозы зафиксировать до присоединения готовых эталонов. Эти сравнения изучают причины различий в статическом наборе. Разброс определяется правилами перестановки и не является доверительным интервалом по будущим задачам. Условный тест на публикационный приоритет не ставится.

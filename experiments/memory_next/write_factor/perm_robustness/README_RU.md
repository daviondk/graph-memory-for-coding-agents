# Насколько вывод зависит от того, кому передали чужую правку

После основного факторного опыта проведены две дополнительные зафиксированные проверки для лексического поиска BM25 с объединением рангов. Первая проверяет чувствительность к 64 назначениям полей 300 карточек в 357 заданиях. Вторая использует только доноров из репозитория исходной карточки и спрашивает, сколько раз поиск нашёл именно размеченную запись среди 99 задач Lite. В обоих случаях сохранён полный порядок документов на вопрос. Первая регистрация предшествовала просмотру первой серии, вторая сделана после получения первой серии и до расчёта второй. Соли заранее известны, отбор лучших назначений не проводился.

| Условие на Lite | Match@1, 300 кандидатов | Match@1 с заранее известным репозиторием | Hit@5, 300 кандидатов |
|---|---:|---:|---:|
| Настоящие сведения о правках | 64 | 65 | 84 |
| Без поля правок | 61 | 62 | 83 |
| 64 обмена с любым репозиторием, диапазон (медиана) | 53–61 (57) | 54–62 (58) | 78–85 (83) |
| 64 обмена строго внутри проекта, диапазон (медиана) | 51–60 (55) | 52–61 (56) | 78–84 (81) |

В исходном поиске правильный репозиторий первой записи встретился в 94 случаях с настоящими правками, в 94 без поля и в 94 при каждом из 64 внутрипроектных обменов. Среди первых пяти исходный уровень 84/99 достигнут 10 глобальными и 3 внутрипроектными перестановками. Успех первого выбора таким образом чувствительнее к правильной привязке правки. Если не хранить дополнительное поле вообще, потеря по первому выбору составляет 3/99, существенно меньше сопоставления с нарочно перепутанной памятью. По 13 вопросам с меткой в дополнительном статическом пуле результат со своими правками 11/13, у 29 из 64 глобальных перестановок он был не ниже. Перенос на новые проекты требует независимых данных.

Во второй серии во всех 12 группах оказалось не менее 3 доноров. Абсолютная разница длин полей внутри назначений в среднем 2,97 слова, максимум 58. В каждом репозитории сохранялся один и тот же полный набор текстов, включая длины и словарь. Все 64 вектора назначений разные. В режиме известного проекта использовались глобальные IDF и фильтрация полного порядка по метаданным проекта. Интервалы min–max описывают способы выбора доноров на той же выборке; они ничего не сообщают о разбросе при изменении выборки новых задач.

Рисунок permutation_scores.png для Word построен из within_per_seed.csv. Команда python plot.py с Matplotlib 3.10.7 восстанавливает распределение 128 заранее заданных назначений.

Для автономной сверки из этого каталога выполните следующие команды.

    python -B score.py --verify
    python -B within_export.py --verify

Для нового расчёта в отдельном дереве данных запускайте predict.py, score.py, within_predict.py, within_export.py. Нужны проекции прежнего опыта и исходный rank.py, как описано в README родительского раздела. Вызовы LLM и GPU отсутствовали. Файлы registration.json и within_registry.json фиксируют алгоритмы до предсказаний. Файлы blind_lock.json и within_lock.json закрепляют прогнозы до чтения меток. При первом экспорте NumPy вернул скаляр int64, который стандартная библиотека JSON не сериализует по умолчанию. within_export.py переводит такие скаляры в числа Python. Исходный алгоритм сравнения в within_score.py и оба предсказания сохранили первоначальные контрольные суммы.

# Что добавляют наблюдавшиеся правки при индексировании опыта

На этапе завершения прежней задачи память сохраняет симптом со слов пользователя, последнюю открытую заметку агента и отдельный ключ из путей и идентификаторов, встретившихся в попытках редактирования. Здесь измерен вклад **этого третьего ключа в ранжирование до подачи контекста решателю**. Выдача ограничена пятью историями. Решатель не вызывался.

Один фактор меняет поисковый механизм — лексический или гибридный с двумя фиксированными векторными представлениями. Второй меняет только поле правок. Контроль с перестановкой сохраняет число полей, совокупность слов и байтов, число ненулевых лексических признаков и веса. Пропуск поля экономит индексирование.

## Все 99 задач SWE-ContextBench Lite

| Метод | Match@1 | Hit@5 | MRR по 300 | Macro Recall@5 |
|---|---:|---:|---:|---:|
| Лексический, без правок | 61/99 | 83/99 | 0,7194 | 0,8232 |
| Лексический, перемещённые правки | 54/99 | 84/99 | 0,6753 | 0,8333 |
| Лексический, свои правки | 64/99 | 84/99 | 0,7454 | 0,8333 |
| Гибридный, без правок | 63/99 | 81/99 | 0,7257 | 0,8030 |
| Гибридный, перемещённые правки | 61/99 | 82/99 | 0,7150 | 0,8131 |
| Гибридный, свои правки | 65/99 | 85/99 | 0,7449 | 0,8434 |

Hit@5 означает наличие хотя бы одной официальной связи. Macro Recall@5 усредняет долю всех известных связей каждого вопроса; эти числа могут различаться при нескольких правомерных прошлых историях. В MRR для каждого вопроса берётся первая допустимая история.

## Заранее назначенные пары

- **Правильная привязка минус пропуск поля.** Для Hit@5 выиграно 4, проиграно 0; Δ 4,04 п. п., 95% ДИ [0,00; 8,33], точный двусторонний p = 0,1250, p Холма = 0,2500. Для первой позиции 3 выигрышей и 1 потерь; Δ 2,02 п. п., 95% ДИ [−3,23; 5,48].
- **Правильная привязка минус перестановка.** Для Hit@5 выиграно 3, проиграно 0; Δ 3,03 п. п., 95% ДИ [0,00; 5,36], точный двусторонний p = 0,2500, p Холма = 0,2500. Для первой позиции 5 выигрышей и 1 потерь; Δ 4,04 п. п., 95% ДИ [−3,12; 13,00].

Взаимодействие двух факторов по Hit@5 (эффект добавления правок в гибридном поиске минус эффект в лексическом) — Δ 3,03 п. п., 95% ДИ [0,00; 7,69]. Парный bootstrap выбирает целые репозитории с повторениями. В Lite их 12. Точный тест Мак-Немара трактует задачи как независимые единицы, поэтому межзадачная зависимость в пределах репозитория ограничивает вывод. Две основные проверки по Hit@5 скорректированы совместно. Остальные сравнения описательны.

## Затраты и происхождение данных

Поле правок заняло 197,376 байт UTF-8 из 819,196 байт трёх текстовых полей (24,1%). Его отдельный индекс BM25 содержит 27,933 пар документ–термин. Число пар описывает размер логического индекса; байтовый размер структур Python и сериализованного поискового сервиса другой. Общие неизменные векторы двух полей документов составляют 1,843,200 байт в FP32. Число GPU-вызовов и LLM-вызовов равно нулю.

Контроль переставил все 300 привязок, полный текст совпал у 0 пар источник–донор. Абсолютная разница длин внутри назначений составила в среднем 0,26 слова, максимум 2. Переставленная выдача вычисляется перестановкой исходных BM25-оценок с той же устойчивой сортировкой. Независимое повторное индексирование переставленных документов дало ту же матрицу до сортировки.

Исходные top-10 воспроизведены для всех 357 гибридных и 357 лексических запросов. Три CPU-потока, PyTorch 2.6.0+cu124, Transformers 4.46.3. Времена по каждому этапу и пиковая рабочая память в costs.json. Время CPU не оценивает задержку или стоимость последующего агента.

## Воспроизведение

Для повторной проверки сохранённых чисел выполните python verify.py в этом каталоге с NumPy. Для полного пересчёта нужен предыдущий набор артефактов SWE-ContextBench (SWE_CONTEXT_BASE), локальный facebook/contriever (CONTRIEVER_PATH), PyTorch, Transformers, NumPy и psutil. Задайте CUDA_VISIBLE_DEVICES=-1, OPENBLAS_NUM_THREADS=1, OMP_NUM_THREADS=3, MKL_NUM_THREADS=3, HF_HUB_OFFLINE=1 и PYTHONDONTWRITEBYTECODE=1. Запустите generate.py freeze, generate.py predict, score.py, verify.py, summarize.py. Изначальная заморозка и её время сохраняются в design-lock.json. Слепой полный список в rankings.npz зафиксирован в predictions-lock.json до открытия таблицы связей. Метка source key извлекается из keys.json по смещению. Таблица per_query.csv содержит все позиции и исходы, scoring-inputs.json — минимальную проекцию для независимой проверки.

Ранее агрегаты того же теста уже были известны. Новые условия были записаны до вычисления прогнозов. Строгая причинная интерпретация относится к перестановке или удалению поля в заданном алгоритме для этого корпуса. Пары документов ограничены по длине; одна фиксированная перестановка не даёт интервала по возможным назначениям. Слова, связанные с правкой, могут сохраняться в симптоме и итоговой заметке. Исследование не устанавливает успех исправления кода или удобство той же записи для другой модели.

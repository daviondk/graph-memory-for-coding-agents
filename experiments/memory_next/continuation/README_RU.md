# Передача действий следующему агенту

Четыре заранее фиксированные задачи из SWEContextBench Lite после состояния brief переданы в восемь независимых чистых сессий. Оба агента в паре видели исходный issue, одну и ту же реально полученную старую карточку и последние два фактических действия со статусом и сокращённым выводом. В одном условии был также добавлен механический журнал с перечнем явно просмотренных файлов, тестовых команд, наблюдавшихся ошибок, изменённых путей и повторных запросов. Каждый файл handoffs/<идентификатор>/manifest_only.txt содержит ровно добавленный текст.

Во всех новых сессиях использовался локальный Qwen3.8-27B Q4_K_M на одном сервере, на задачу и шаг зафиксирован общий seed. Лимит восемь вызовов, максимум 768 выходных токенов за вызов, T=0,5 и top_p=0,95. Сначала на чистое дерево исходного commit накладывался сохранённый патч предшественника с новыми файлами из git diff; двоичное совпадение проверено для каждой ветви. У всех четырёх предшественников лимит 24 вызова исчерпан, исходные патчи по нулю байт, три исторические карточки доступны и у Flask карточки нет. По фактически наблюдавшимся состояниям проверяется передача выполненной разведки, а работа над уже изменённым кодом остаётся отдельным экспериментом. Игнорируемые и временные файлы, процессы и окружение прежней оболочки не переносятся. Модель не имела доступа к тестам оценщика, заготовкам решений или статусам предыдущих испытаний. Отдельный процесс оценил замороженные патчи официальным harness. Все восемь финальных патчей имели 0 байт, оценщик вернул No patch до выполнения F2P/P2P. Результат 0/4 означает, что исправлений не предъявлено.

С журналом потрачено 139,078 входных и 2,968 выходных токенов, при передаче двух действий — 109,165 и 2,654. Средний добавленный размер 881 символов. Общие повторы прежних команд 1 и 1. Событие требует совпадения нормализованного текста команды, смысловые повторы и эквивалентные другие команды сюда не попадают. Повтор теста после правки может быть оправдан. Описываем только затраты продолжения, поскольку предыдущие состояния общие.

Статус внешней оболочки отделён от содержания stdout. Для 7 из 12 распознанных исходных тестовых вызовов stdout/stderr содержит явный маркер неудачи при shell exit 0. В манифесте есть 6 таких команд. Протокол не присваивал утверждения «тест прошёл» нулевому коду конвейера. Полное воспроизведение вывода доступно в предыдущих actions.jsonl. Этот признак относится к предшественнику. Он не используется официальным grader.

Одна модель и по одному общему seed на задачу при четырёх постановках не отделяют устойчивый эффект памяти от стохастики генерации. Две из трёх задач Requests относятся к одному историческому PR. Для каждого из двух условий предоставлен разный объём текста. Измеряется весь эффект добавления журнала. Отделить пользу формата от дозы текста позволил бы дополнительный контроль с тем же токенным бюджетом.

## Воспроизведение и файлы

Для автономной проверки достаточно Python 3.10+ и команды python verify.py. Данные в runs/<цель>/<условие> содержат каждый запрос к модели, полный JSON ответа, реальные shell-команды и выводы, снимки патча по шагам, входные/выходные токены и финальный candidate.patch. Строка на испытание есть в per_run.csv, парный анализ в results.json. История событий наблюдателя сохранена в queue.log. Замки design_lock.json, implementation_lock.json, end_lock.json фиксируют дизайн, код и пакет перед отправкой оценщику. Числа изучаются после end_lock и из независимых receipts в grading/.

Для новых модельных запусков требуются те же входные данные предыдущего пилота в соседнем repair, зафиксированные образы и локальный OpenAI-совместимый сервер в той же конфигурации. Запускать повтор в отдельной копии. continue_runs.py изолирует рабочее дерево и восстанавливает принятые ответы после инфраструктурной ошибки, а wait_and_run.py координирует использование одной видеокарты. В grader передаётся только замороженный кандидат. При потере процесса непредставленные игнорируемые файлы пропадут при восстановлении и этот факт следует записать.

Сравнение схем передачи в других стендах приведено в RELATED_RU.md. Папка ../handoff_debt содержит отдельный повторный анализ 6 120 авторских первых запусков и 320 отложенных повторов с официальным SWE-bench Verified. Их числа не объединяются с восемью локальными продолжениями.

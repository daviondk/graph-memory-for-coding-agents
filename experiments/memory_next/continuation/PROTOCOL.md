Цель — проверить, помогает ли следующему агенту компактная передача наблюдавшихся действий поверх минимального описания. Не отбираем задачи по тому, успел ли предшественник их решить.

## Дизайн

Четыре заранее фиксированных ID из прежнего эксперимента: pallets__flask-4039, psf__requests-2344, psf__requests-3359, psf__requests-3481. Для каждого дожидаемся фиксации обычной истории brief после максимум 24 вызовов. Новый агент в обеих ветвях получает идентичную офлайн-среду из того же образа и чистого снапшота commit, поверх которого накладывается сохранённый candidate.patch. После git apply точный git diff --binary HEAD обязан совпасть байт-в-байт с исходным снимком патча. Этот способ воспроизводит изменения отслеживаемого дерева и представленные в патче новые файлы. Исключены временные файлы, игнорируемые файлы, сервисы, состояния отдельных процессов и переменные оболочки. Эти ограничения одинаковы в обеих ветвях. У предшественника, завершившего задачу ранее, всё равно проверяем обе передачи; F2P и P2P только у официального оценщика.

Начало новой сессии: общие в точности системная инструкция, исходное сообщение issue + первоначальная временно допустимая память в том виде, в котором они находились в первом запросе brief, одинаковая явная формулировка о восьми оставшихся вызовах и последние два фактических вызова инструментов предшественника (имя, аргументы с лимитом 700 символов, наблюдаемый результат с лимитом 750 символов). В манипуляции manifest к тому же пользовательскому сообщению добавляется единственный блок. В last_two этот блок отсутствует. Никаких успешностей задач, скрытых тестов, финальных сигналов оценщика, целевых патчей или суждений исследователя. Дополнительный журнал строится автоматически только на основе реально выполненных действий, их ответов и сохранённого git diff предшественника. Никакого текста скрытого рассуждения или свободной LLM-сводки. Оба агента могут изучать собственный рабочий diff.

Журнал включает: до 12 уникальных имён файлов из явно выписанных команд просмотра, до 6 фактически вызванных тестовых команд и внешний код возврата их оболочки, до 4 последних команд с ненулевым внешним кодом, до 8 путей из git diff, до 4 точных повторов нормализованной команды. Результаты тестов в конвейере могут быть замаскированы статусом последней команды, не делаем вывода об успехе теста из статуса оболочки. Сжатие фиксированное детерминированное, не перебираем варианты после наблюдения результатов. Гипотеза: журнал может сократить повторение ранее выполненных действий и улучшить долю исправлений при фиксированной длительности продолжения; конкурирующий прогноз — добавочный текст якорит агента на бесплодных действиях.

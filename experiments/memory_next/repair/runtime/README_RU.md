# Происхождение модельных вызовов

Все новые обращения решателя, получателя и двух читателей ранжированных списков идут через один локальный llama.cpp, один GPU-слот, RTX 3090 и Qwen3.8-27B-UD-Q4_K_M. Хеш GGUF и версия llama.cpp сохранены в model_receipt.json и runtime_receipt.json. Для первых двух семейств включены shell-инструменты и температура 0,5; в тесте выбора кандидатов используется жадная генерация. Код seed_proxy.py фиксирует фактически переданные параметры и отключает режим thinking и кэширование промпта. Все входные параметры сохраняются до обращения. У читателя доступна реконструкция промпта из read.py, предыдущих замороженных queries/cards и списков кандидатов. Новые модельные вызовы выполнялись локально. Codex использовался для подготовки программ, поиска и проверки результатов.

requests.jsonl — квитанции с расходом токенов, хешами и идентификаторами каждого ответа. reconciled.json сверяет каждый ответ оригинального сеанса, его продолжения, читателя и короткой проверки записи результата pytest с квитанцией нативного сервера. Низкоуровневые журналы и выборки потребления ресурсов лежат вместе с настройками процесса. Для проверки запустить python verify.py из этой папки в распакованном архиве. Комбинирование двух читателей с идентичной подсказкой снижает фактически исполненную стоимость очереди. Для сравнения затрат самостоятельных методов учитываются и повторно использованные записи, в time_read/costs.json.

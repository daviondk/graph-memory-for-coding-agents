# Может ли агент точно записать исход теста

Даны 20 shell-действий из записанных траекторий. Qwen3.8-27B на локальной RTX 3090 должна записать единственный проверяемый факт о вызванных тестах. С оригинальной командой и видимым выводом агент правильно классифицировал 17/20 действий. При выдаче собственных кодов pytest из чистых повторов, включая явные нули, и признака вызова только для сбора — 20/20. Поправлены три воздержания на действиях с падением тестов. Ошибочных записей «все тесты прошли» не дал ни один режим. Детерминированное преобразование кодов дало те же 20/20.

| Писатель | Правильны | Определённые A–D | Правильных среди A–D | Ложные «прошли» | Macro recall* |
|---|---:|---:|---:|---:|---:|
| Исходные команда и вывод | 17/20 | 17/20 | 17/17 | 0 | 94,12% |
| Команда, вывод и телеметрия | 20/20 | 20/20 | 20/20 | 0 | 100% |
| Всегда «тесты упали» | 17/20 | 20/20 | 17/20 | 0 | 33,33% |
| Исходный строгий regex | 11/20 | 11/20 | 11/11 | 0 | 21,57% |
| Декодер кодов без LLM | 20/20 | 20/20 | 20/20 | 0 | 100% |

\* По присутствующим в выборке трём классам. Эталоны — 17 падений тестов, одна ошибка вызова и два полностью успешных запуска. Отдельного полностью collect-only действия и эталонного unknown в наборе нет. Один из 21 входящих вызовов был collect-only после падения теста в том же действии. Независимая проверка по первому PIPESTATUS и непосредственному коду процесса даёт одинаковые эталоны. Полные матрицы во всех пяти классах, включая invalid как допустимый исход формата, лежат в results.json. Невалидных ответов модель не дала.

Обе ветки получили одинаковые опубликованное объяснение кодов, текст команды, оригинальный уже сокращённый context_output и число вызовов внутри команды. В измеренной ветке известные поля bool и int занимали те же позиции, что unknown в контроле. Предпочтение при смешанном исходе задавалось до первых ответов. Исходные команды получены из отдельных запусков кодового решателя. Для этой задачи использованы температуры 0, один seed и одна локальная сборка модели, обращения без истории и без повторов. Все 40 уникальных response_id и их полные API usage — в model_calls.jsonl. Расход в каждой руке одинаковый, 13 742 входных и 40 выходных токенов за 20 обращений.

Разности по формулировкам составили +2 из 13, +1 из 6, 0 из 1. Попарно три улучшения, ноль ухудшений, семнадцать ничьих. Условный exact sign test по дискордантам дал p=0,25. Три формулировки относятся к двум PR одного репозитория, поэтому этот p нельзя трактовать как статистическое подтверждение переноса на новые репозитории. Выборка происходит из малого пилота со слабым качеством исправлений. Телеметрия прямо кодирует критерий этого измерения. Исследовательский вопрос на будущее — уменьшает ли точная запись повторные ошибочные решения агента на отложенных задачах.

Регистрация исходных файлов и порядка — design_lock.json, отметка фиксации ответов — calls_lock.json. Для автономной проверки выполните verify.py при наличии соседнего ../raw.zip. Для воспроизведения с локальным сервером и исходными журналами — prepare.py, collect.py, score.py. Общая цена обеих веток 27 484 входных и 80 выходных токенов.

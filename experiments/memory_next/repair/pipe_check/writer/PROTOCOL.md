# Запись результата теста в память агента

При регистрации известны предыдущие частоты на 20 командах из трёх формулировок Requests и двух уникальных целевых PR. Предыдущие наблюдения и повторный запуск показывают ошибки нативной интерпретации. Перспективное вмешательство для тех же фиксированных наблюдений сравнивает две записи одного и того же LLM-писателя. Нового тестового набора здесь нет. Цель — точность атомарной фактической записи об исходе pytest в чистом повторе. Перенос в будущую работу агента остаётся отдельной задачей.

В исходном порядке run.py берутся ровно все 20 пар. Обе руки получают побайтово одинаковые оригинальную команду и уже сокращённый в родительском интерфейсе context_output, без повторной нарезки, новый запрос без предыдущей истории, один общий system prompt с кодами, общей легендой классов и единым правилом. В слоте для каждого pytest в порядке выполнения обе ветки видят одинаковые ключи. В контроле значения native_rc и collect_only представлены строками unknown. Для вмешательства заполняются нативный код и логический флаг --collect-only из исходно допущенного CPU-повтора. 0 и false передаются явно, пропуск или null не заменяются нулём. Никакие выводы оценщика, заранее готовая категория или сведения об идентификаторе задачи не поступают в модель. Скрыты и коды фильтров grep, head, tail. Число C1/C2-вхождений одинаково для обеих веток.

Единица решения — все pytest в одной shell-команде. Символы A=есть завершение 1 (test failures), B=ошибка запуска/использования (есть код 2,3,4,5,6, нет A), C=все исполнявшие тесты случаи успешны (все коды 0, хотя бы одно исполнение), D=только успешный сбор тестов (все коды 0 и все collect_only), E=не удалось установить статус. Для полной телеметрии применяется порядок A, B, E при иных/неизвестных кодах, затем C/D. Для неполного наблюдения разрешена прямая диагностическая информация из stdout, допускается воздержание. Писатель возвращает ровно одну букву; неверный формат считается ошибкой и отдельно указывается. Из 20 заранее известных эталонов A=17, B=1, C=2, D=0, E=0. Числа известны исследователю и отсутствуют в prompt модели. Набор не балансируется.

Ровно по одному вызову на каждую из 40 пар команда × режим. Одна и та же локальная модель qwen38-27b-ud-q4km, температура 0, фиксированный seed, одинаковый лимит ответа 8 токенов и stop на новой строке после ответа без внедрения грамматики. Порядок команд по SHA-256. В 10 парах первой идет ветка hidden, в 10 первой идет measured, чередование по рангу фиксировано до первого запроса. Сначала зафиксировать оба prompt и schedule, дождаться заморозки восьми предыдущих продолжений; отдельный журнал model_calls.jsonl сохраняет response_id, исходный API usage, время, необработанный ответ и хеш prompt. Не перевызывать модель для неформатного ответа и не настраивать prompt после открытия результатов.

Сравнения — всегда A, строгая исходная regex на сохранённом stdout/stderr (A при сигнале, иначе E), независимый безмодельный декодер нативных кодов/режима. Декодер реализует публичную формализацию исхода и потому показывает достижимый уровень для такого узкого решения. Эталон проверяется отдельно по необработанным pipeline-sidecars, а не по ответу модели. Сохранить матрицу 5×5 (плюс invalid при необходимости), accuracy, долю осмысленных утверждений A–D (coverage), точность по ним, ложные C, описательное macro recall по встреченным классам, парные победы/проигрыши/ничьи. Рассчитать точный двусторонний binomial/sign по дискордантам как иллюстрацию при условии независимости команд; так как многие исходят из одного checkout и решения, выводы основаны на поштучных данных и разбивке по исходным группам. Отдельно считать токены и неформатные ответы. Улучшение не считается доказательством преимущества модели над декодером, улучшения будущих патчей или превосходства над SOTA.

# Проверка сигналов записи исхода тестов

До новых запусков известен результат первичного текстового аудита. Среди 312 наблюдаемых tool actions 20 shell-команд содержат pytest, и у 11 команд наружный Exit 0 сочетается с распознанным выражением об ошибке/сбое в первоначальном выводе. Все 20 включены без отбора по словам, случаю или исходу. Единица первичного анализа — исходная команда. Дополнительно отдельно учитывается каждое вхождение pytest, включая две команды pytest в одной исходной строке и режим collect-only. Нативные коды до новых запусков неизвестны.

На свежем независимом checkout того же образа, базового tree, идентификатора пользователя, с отключённой внешней сетью и лимитом 75 с повторяется оригинальная строка как есть. Во втором свежем checkout Bash-функция, оборачивающая только python -m pytest, вызывает исходный python с теми же argv, направляет его stdout и stderr в исходный pipeline и записывает нативный код в отдельный файл. Сразу после каждого полного pytest pipeline записываются его наружный код и все PIPESTATUS, с сохранением последнего кода команды. Для сегментов с `cd &&` проверяется успешность перехода и совпадение нативного rc с первым PIPESTATUS. Внешние команды и обе копии выходных байтов сохраняются. Поток фактического pipeline сохраняет свою фильтрацию. Для наблюдаемого сигнала записываются сырые байты доступного в этом pipeline stdout и stderr. Наблюдения прошлого состояния взяты из исходных журналов. Повторы начинаются на чистом снимке и могут отличаться от рабочих деревьев при исходном решении.

Основная доля — среди всех полностью инструментированных команд с наружным rc=0 какая доля имеет хотя бы один pytest rc≠0. Дополнительно публикуются все три знаменателя (команды, pipeline pytest, отдельные события служебного сбоя), условная доля обнаружения коротким regex исходного аудита и таблица наружного кода против нативного. Код 0 pytest с --collect-only учитывается как успешный сбор, отдельно от выполнения тестов. Отдельно указываются pytest 1,2,3,4,5, иные коды, grep 1 (нет совпадений), grep 2 (ошибка), rc=141 (SIGPIPE/совместимый статус). Код 1 самого pytest при наличии заранее остановленного фильтра не доказывает причину сбоя. Код 0 с несколькими tool actions не заменяет сохранённое поштучное состояние. Опубликованные подсчёты исходного regex сравниваются с тем же regex на видимом инструментированном выводе и с нативным кодом на чистом snapshot.

При timeout (124/137), отсутствии полного sidecar, расхождении числа вызовов Python или нативного значения с первым PIPESTATUS помечаем команду непроверенной и сохраняем все наблюдения. Не исключаем такие попытки из общего входного знаменателя. Равенство кодов наружного интерфейса проверяется с исходным рабочим журналом и отдельным неизменённым повтором. Если сигнал 141 относится к самому pytest, запускаем это же pytest argv напрямую в третьем свежем checkout с полным выводом, помечая это самостоятельной диагностикой. Время тестов, случайные идентификаторы и terminal colors в тексте могут отличаться между повторами. Здесь только команды уже конкретного агента на данных четырёх формулировок, возможны повторы и общие PR. Наблюдения характеризуют ошибки записи результатов в этом материале. Не обобщаем частоту на произвольные проекты и модели. Новые обращения к LLM — ноль.

# SWE-ContextBench Lite — controlled interactive repair pilot
Registered before reading repair outcomes or the four gold/test patches. The 99 task retrieval scores and aggregate labels from the earlier round are known. Four targets chosen by repository name only: all canonical psf/requests (3) and pallets/flask (1), lightweight Python codebases. No selection by retrieval hit, patch, difficulty, or results. Preserve non-executable targets and report genuine missing outcomes separately. Original snapshots/graders from SWE-ContextBench. Four distinct targets, one seed per target-arm (shared deterministic per-turn seed within target), not 12 independent tasks. This is not an end-to-end leaderboard replication.
All arms receive exactly the same top1 from the frozen previous full Qwen choice, original unmasked new issue, same solver (Qwen3.8-27B Q4_K_M RTX3090), shell, instructions, issue symptom and past public closure from the card (capped 175 and 90 words). The evidence is the up to 40 words of recorded paths/identifiers from real past edit attempts. Brief: highlight and detail access disabled; Eager: show the details at start; On-demand: show them only when the solver explicitly calls the read_details tool. Tool schema present in all arms; what is available is signalled to avoid hidden capabilities. On repeat calls return a pointer to first response. Bash outputs and model-generated transcript are observable; save all. The hypotheses are that reading on demand preserves solved tasks at reduced exposure and that eager availability may help/harm on some targets. Never infer successful fixes from a code snippet or retrieval.
Run ordering deterministic per task via SHA256('next-repair|'+iid+'|'+arm), mix targets by round of conditions. Per run max 24 model calls including requests for tools, <=768 output tokens per turn, temp 0.5, top p .95, one solver slot, fresh isolated offline container from exact source commit, source history unavailable. Accept final working tree diff at the cap (includes newly created files via git add -N). Shared command timeout 75 s and capped output 6000 UTF-8 characters for context; record stdout and statuses. Save all prompts, model responses and graded patches, all usage including interrupted calls, never retry a completed assignment or tune by its grade. An executable empty-patch and gold-patch check in each official target image calibrates grading. Full F2P+P2P from the pinned author harness is the primary outcome. Distinguish evaluator/infrastructure misses from solver errors. Log paired wins/losses, read counts, timing, test and token counts, case-level results; with n=4 descriptive only. Record exact differences in local configuration from REM (which uses a different 100-turn solver, pricing and task count). All disk on D.

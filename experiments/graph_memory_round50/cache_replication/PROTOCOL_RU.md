# Перенос зафиксированной модели на публичные входы Test500

До просмотра исходов кеша регистрируем все Test500-состояния, которые вошли в существующий список R39 (491 из 500). Принадлежность к выборке определяется непустой строкой старого файла рангов; сами ранги игнорируются. Открытые сертификаты в прошлом использовались только для Cal500. В этом опыте target — появление точного входа кодировщика в следующем доступном пакете, поэтому закрытые сертификаты Test500 не требуются. Не отправляем ничего организаторам.

Во всех 500 опубликованных здесь Test500 отсутствуют сырые trajectory_prefix, run_id и base_commit. Хронология будет суррогатной. До токенизации сверяем по прежней Cal-панели, как часто безметочный парсер клиенто-доступного state_id восстанавливает настоящий строгий переход между префиксами. Группируем состояния по repo, instance_id, архивной версии корпуса и идентичной части state_id до терминального -sNNN (разрешён технический суффикс --...). Для Cal используем base_commit, для Test — corpus_id. Внутри группы принимаются только разные однозначные номера, прошлые идут в возрастающем порядке. Группа с неподдержанным ID либо дублированием шагов не передаёт память; все её состояния остаются в основном знаменателе. Для развёртывания требуется минимум 50 предложенных рёбер на Cal и не менее 98% соответствия эталонному непосредственному предшественнику по точному полному префиксу. Покрытие и обратную полноту сообщаем отдельно. При невыполнении — только аудит совместимости. Дата и время отдельных чтений на Test500 не восстанавливаются.

Фиксируем полный исходный переносный графовый и локальный коэффициенты из R50/cache_prediction (SHA manifest bb2837a91140d9143a33ca6bea1cb767b0b7d292ab6778d3212635fd5d200237). Никакого обучения и подстройки. Используется тот же точный GGUF-токенизатор, 511 входных токенов + EOS, те же три поля запроса, сервис только на CPU. Дубликаты удаляются внутри пакета, чтение до записи, восстановление из собственных резидентов. Основной результат — разница избегаемых токенов относительно frequency×cost, граф-специфический контраст — относительно frozen local. Дополнительно cost, cost-hot-LRU, GDSF. Лимит 31, те же правила равенства и те же исходные признаки. Индикатор просмотра берётся только из целевого состояния на момент решения о записи. Знаменатель — весь исходный вход, включая cold-состояния. Групповой percentile bootstrap по репозиториям, seed 501271, 20 000 переотборов. Нужна положительная нижняя граница каждого соответствующего контраста; отрицательные результаты публикуются. Проверяем нулевое пересечение исходных экземпляров, репозиториев и state_id с 484 состояниями R50. Числа не являются официальной метрикой достаточности SERBench или физической задержкой.

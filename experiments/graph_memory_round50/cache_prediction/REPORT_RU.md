# Когда стоит сохранить эмбеддинг по истории соседних фрагментов файла

На 179 состояниях из 68 репозиториев графовая политика при вместимости 31 вектор сэкономила **31 085 дополнительных входных токенов** относительно «частота × стоимость» и **20 670** относительно той же модели без файлового контекста. Выигрыш в доле исходного входа — **0,513 [0,077; 0,950] п.п.** и **0,341 [0,097; 0,570] п.п.** соответственно. Оба заранее заданных критерия для этой панели выполнены. Проценты описывают объём повторного кодирования. [Первичный протокол](PROTOCOL_RU.md) · [Машинные результаты](results.json)

## Что сохраняет метод

После выдачи агенту известны текущий пул фрагментов и до 31 ранее оставленного вектора. С каждым точным ключом токенов хранится короткая запись о файле, диапазоне строк, давности и числе наблюдений за время резидентности. При записи алгоритм группирует фрагменты по файлу и отмечает, какие соседние диапазоны сохранились, появились или перестали встречаться в текущем пуле. По локальным признакам и этим связям логистическая регрессия оценивает вероятность повторного предъявления точного ключа в следующем запросе. Это маленький двудольный граф фрагментов и файлов, построенный только на посещённых источниках. Изменение пула может отражать поиск, а не правку файла. [Признаки и выбор](predict.py)

Пусть для фрагмента i стоимость кодирования равна cᵢ, а вероятность его следующего предъявления равна pᵢ. При одинаковой ёмкости каждого вектора ожидаемая сумма сэкономленных токенов для набора S равна ∑ᵢ∈S cᵢpᵢ по линейности ожидания. Отсюда оптимальный набор для одношаговой задачи при известных вероятностях — 31 наибольшее произведение. Зависимость между будущими предъявлениями этому выводу не мешает. В эксперименте вероятности оцениваются по наблюдениям; у формулы нет гарантии многошаговой оптимальности или оптимальности задержки GPU.

## Как исключена информация о будущем

Для разработки использованы 305 состояний из 103 репозиториев. Каждый разработческий прогноз получен моделью, обученной на других репозиториях по пяти фиксированным фолдам. Для внешнего по репозиториям переноса модель переобучалась один раз на 143 доступных обучающих переходах из 76 репозиториев, 13 168 бинарных примеров с учётом всех кандидатов записи. 68 репозиториев переноса полностью отделены от 103 разработческих. Во время обучения метка означает присутствие ключа в непосредственно следующем наблюдаемом пуле того же запуска. Во время оценки каждый алгоритм удерживает только собственных резидентов. Для cold-состояний экономия равна нулю; они входят в знаменатель. Обе части публичной SERBench Cal500 уже изучались в других сериях. ## Из какого признака возникает эффект

Первичная абляция вместе удаляла факт открытия файла и сведения о соседних фрагментах. После её измерения зарегистрировали отдельную проверку этих двух источников. На переносе полная модель против local + open даёт 0,408 [0,183; 0,620] п.п. Добавление соседей без индикатора открытия к local даёт 0,349 [0,126; 0,555] п.п. Вклад открытия поверх соседства -0,008 [-0,092; 0,064] п.п. На development разность полного метода к local + open 0,162 [-0,005; 0,334] п.п. Результат поддерживает интерпретацию через состав соседства, однако эта проверка выполнена на уже открытой панели. ## Затраты и ограничения

Сериализованы и восстановлены из байтов 968 состояний метаданных. Максимальный суммарный объём — 510 144 байта, включая 31 вектор float32 по 16 384 байта, 64 байта метаданных на узел и 256 байт заголовка с коэффициентами регрессии. После восстановления записи и модели решения совпали. На панели переноса медиана выбора после выдачи: граф 0.573 мс, local 0.240 мс, «частота × стоимость» 0.163 мс. Это клиентская работа CPU в памяти, без кодировщика и дисковой сериализации, по три замера в чередующемся порядке. Временные индексы текущего пакета освобождаются после обновления. [Память и время](resources.json)

Результат алгоритма характеризует отбор уже рассчитанных векторов на последовательности архивных состояний. Он не измеряет вероятность решения issue, качество свободного агентного поиска или сквозное время. Пулы кандидатов, формирование observed_by_state, небольшая глубина многих линий и повторное использование Cal500 ограничивают переносимость. Координаты и идентификатор наблюдённого пути читаются из текущей структурированной выдачи, весь репозиторий индексировать не требуется. Независимый скалярный верификатор воспроизвёл все 1 936 прогнозов. Для пограничных равных приоритетов записано вычислительное уточнение; после него первичные числовые эффекты сохранились.

# Предварительная проверка прогнозирования повторных чтений по истории файла

**Задача.** После выдачи запроса выбрать не более 31 эмбеддинга, которые можно перенести на следующую выдачу кодового агента. Узел наблюдения — точный digest токенов, ребро связывает его с файлом и диапазоном строк. Сохранённый узел несёт свой идентификатор файла и координаты. Через это ребро можно увидеть, что соседние фрагменты файла исчезли из текущего пула, появились впервые или поменяли координаты. Проверяем, предсказывают ли такие признаки повторную потребность в данном наблюдении лучше, чем его стоимость и частота. Появление и исчезновение в пуле не удостоверяют фактическую правку файла в Git.

**Фиксация.** Разработка — все 305 ранее изученных состояний из 103 репозиториев R48. Для внутренней проверки five-fold по SHA256(имя репозитория) modulo 5, никакой настройки. Перенос — все 179 состояний R49 из 68 других репозиториев, ранее использованных в анализах других методов. Сигналы следующего состояния допускаются только как бинарные метки обучающих переходов на обучающих репозиториях. Инференс получает только собственных прежних резидентов и объявленный текущий пакет. Пакет читается из прежнего кеша до изменения состава. Для каждой выборки lineage задаёт прежний подписанный контракт строгого префикса одного запуска. Аргументы команд, содержимое диффов и эталонные группы доказательств не используются. Для признака пути открытого файла читается только текущее открытое множество.

**Метод.** Детерминированная L2-логистическая регрессия (liblinear, C=1, sigmoid, стандартизация по обучающим данным, max_iter=500). Кандидаты при записи — объединение текущих ключей и прежних резидентов. Выбираем top-31 по p(наличие в следующем уникальном пакете) × длина токенного входа. Это оптимум ожидаемой сэкономленной суммы при одинаковых размерах векторов и аддитивной цене. Развязка по digest. Обучение на каждом доступном ребре от непосредственно предыдущего состояния к следующему. При сборе примеров прежние резиденты порождает замороженный R48 frequency×cost; при инференсе каждая модель сама управляет своим кешем. Все переходы имеют одинаковый совокупный вес, нормированный до среднего числа примеров, один бинарный пример на потенциального резидента. Контроль local получает стоимость, признак присутствия сейчас и ранее, число наблюдений в период резидентности, давность, тип пути «тест» и Python, координаты и длину интервала, видимость observed_by_state и глубину. Graph добавляет факт открытия файла и признаки опубликованных в текущем пакете и удерживаемых ранее соседей того же файла: размеры этих множеств, их совпадение (без самого узла), исчезновение/приход соседей, перекрытие интервала с другими прежними наблюдениями. Статистика ограничена текущим пакетом и своими резидентами. Имена файлов, репозитория и идентификаторы узлов не подаются как признаки. Отдельно публикуем результат local как абляцию вклада рёбер.

**Сопоставление.** Ранее замороженные frequency×cost, cost-hot-LRU, batch-GDSF, только стоимость; вместимость строго 31 вектор, одинаковые входы и ограничения. Первичная метрика — разница межзапросной экономии токенов к frequency×cost на исходном общем входе. Вторичные — разность к cost-hot-LRU и local, число попаданий, абсолютные новые токены, макросредняя по репозиториям. Заранее считаем убедительным перенос с положительной нижней границей основного интервала; отдельная такая же граница к local нужна для специфического утверждения о вкладе графа. Парный кластерный percentile-bootstrap 20 000 перевыборок по репозиториям, seed 501271. Также запишем цену CPU-выбора после выдачи и объём постоянных метаданных по явно описанной упаковке. Время CPU имеет описательный характер. Отрицательные исходы сохраняются. Новых обращений к GPU и физического тайминга кодировщика нет.

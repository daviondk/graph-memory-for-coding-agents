# Порог разности косинусов для выбора второго источника

Регистрируем процедуру до вычисления порога и построения новой панели. Для обучения используются только 640 уже оценённых вопросов semantic_address (manifest a2300298ea1c4b9fed742f9d69403b328c4cc93038fe97b32b5dbcb77c35382e). Адресатор, шаблон энкодера и метод обращения к каталогу остаются прежними. Если dense и linked_dense различаются, отрыв g равен косинусу лидера минус косинус лучшего явно упомянутого. При g ≤ t выбираем явно упомянутый, иначе dense. Если адреса равны, используется общий адрес.

Проверяем вариант never плюс все наблюдённые значения g среди расходящихся адресов на обучающих 640. Максимизируем среднюю парную прибавку официального Answer F1 к dense по всей обучающей панели. При разнице в среднем F1 в пределах 10⁻¹² выбираем меньшее число переключений, затем меньший порог; never побеждает все равные модели. Дополнительно до применения к новым вопросам фиксируем интерполированный 25-й процентиль строго положительных отрывов на старых расходящихся адресах. Это отдельный заранее заданный диагностический вариант даже при выборе never. Всегда переходить к упомянутому показываем как контроль. Пятиблочная проверка на старых вопросах: блок = целое SHA256 UTF-8 «r50-adaptive-fold|» + хеш первого документа modulo 5, выбрать собственный порог на четырёх блоках, оценить на пятом; ни один первый документ не пересекается. Результат пяти блоков не меняет итоговый выбор порога на всех 640. Записываем числовые пороги, все границы и прогнозы исторической проверки, подписываем их до выборки новых вопросов.

Новая панель — 640 вопросов официального 2WikiMultiHopQA train из того же публичного массива. Новый порядок SHA256(r50-adaptive-heldout-v1| + ID). Повторяем фильтры qa_replication для 2Wiki dev, HotpotQA validation и MuSiQue train/dev. Дополнительно полностью исключаем прежние 640 train ID, их нормализованные вопросы и все их каталожные абзацы как возможные первые документы. В новом наборе различны нормализованные вопросы и первые документы. Публикуем количество пропусков и пересечение по прочим абзацам. Новая панель строится без gold и исходов QA, модель могла видеть публичные примеры в предобучении.

На новых вопросах повторяем R32 BM25-первое чтение, 192 wordpiece E5, инструкцию и Qwen3-Embedding-8B Q4_K_M semantic_address для query+первого видимого префикса и голых заголовков. Ридер идентичен Qwen3-4B-Instruct-2507 Q4_K_M с пределом 96 токенов. На каждом вопросе выбираются только два потенциальных плотных адреса; доставленный предел второго одинаков для всех вариантов и равен минимуму соответствующих длин и исходного бюджета четырёх lexical/mention вариантов и пяти прежних placebo. Одинаковые полные последовательности токенов повторно не генерируем. Между старой и новой панелью допускается заимствовать ответ только при полном совпадении токенов, но новая генерация каждого уникального входа также допустима. До загрузки эталонов фиксируем ранги, выбор пороговых политик, токены и ответы; проверяем 32 точных повтора.

Первичный результат — средняя парная разность официального Answer F1 выбранного на обучающей панели порога минус dense на всех 640 новых вопросах. Отдельно даём нижний квартиль минус dense, always-linked минус dense, EM, полное покрытие опорных заголовков, частоту переключений и выигрыши/потери. Интервалы 95% — 10 000 парных перевыборок уникальных первых документов, NumPy seed 470091. При never первичный прогноз совпадает с dense по определению; результаты квартиля не заменяют первичный. Это отдельный проектный holdout train, не официальный leaderboard. Весь анализ сохраняется независимо от знака результата.

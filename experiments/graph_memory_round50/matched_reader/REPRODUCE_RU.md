# Воспроизведение

Для проверки комплект содержит числовую проекцию пула, оба нативных порядка, замороженные деревья, оригинальные float64-полезности, упорядоченные исторические пакеты, координатные атомы эталона, прогнозы и все замеры. На Windows x64 с Python и NumPy выполнить `python -B verify.py`. Эта команда проверяет SHA-256 всех файлов, заново вычисляет признаки и полезности, запускает пять нативных политик, считает покрытие по координатам и воспроизводит доверительные интервалы. Сборка поставляемой библиотеки использует `python -B compile.py` и GNU C++17. На Linux сборку выполнить в рабочей копии: файл с именем kernels.dll загрузится через ctypes как локальная нативная библиотека. Проверка SHA должна использовать неизменённый поставленный файл на Windows. Исходный исходящий порядок кандидатов и массивы node ID в этом пакете представлены целочисленными индексами подписанной карты.

Для новых замеров в рабочей копии запустить `python -B run_matched.py`, затем `python -B stats.py`. Повторы записывают собственные выходные файлы. Столбцы сырых времён в наносекундах идут по порядку «из готовых полезностей» и «из готового числового пула», в каждой ячейке три повтора. Индексы политик и seed перечислены в common.py. Время включает Python-вызов с одинаковым возвратом списка для всех политик. Код динамического программирования компилировался с `-O3 -ffp-contract=off`. При вычислении признаков BLAS работает в один поток. Путь через CPU использовался для всех методов.

Чтобы в исходном исследовательском окружении ещё раз извлечь данные и вызвать официальный оценщик, выполните `export.py`, `original.py`, `run_matched.py`, `grade.py`, `stats.py` в этом порядке. Для такого импорта нужны артефакты R19–R43, каталог числовой проекции R33, опубликованный ISETrace-код, его Python-зависимости и исходные обученные ранги. Материализованные ранги по dev Full Support по умолчанию находятся в x20-r34-dev-metric на диске с рабочим пространством; путь переопределяется переменной R50_CHECKPOINT_RANKS. Источник каждого checkpoint и контрольные суммы зафиксированы в input_sources.json, официальных меток и функции оценивания — в score_receipt.json. Первичные записи траекторий и пользовательские тексты в пакет не включены. [Оригинал](https://arxiv.org/abs/2609.25913)

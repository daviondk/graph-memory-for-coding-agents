# Перенос пакетного ансамбля на полную официальную разработческую выборку ISETrace

Все 580 официальных запросов разработки из 352 траекторий, один ансамбль пяти зафиксированных семян 13,17,29,37,41. Прогнозы должны использовать замороженные train-only HGB на 3894 train-вопросах и независимые dense-проекции пяти реально обученных экземпляров. Один общий HGB с пятью разными входами даёт пять числовых полезностей. Каждая индивидуальная выдача строится существующим DP при том же порядке и пороге. Сравниваются votes_dp, votes_greedy, hamming_dp с mean_dp/mean_greedy и для справки native RRF и medoid. 2048 по той же исходной единице стоимости, те же коды C и стабильные развязки. Основной контраст votes_dp против mean_dp по Full Support. Вторичные — покрытие символов, расход, согласие голосования и Hamming. Уровень анализа — один ансамбль, 10 000 парных перевыборок полных траекторий по ранее утверждённому алгоритму (seed 50084). Все 580 оцениваем однократно; не оптимизируем бюджет, порог, голоса, деревья или чекпойнт.

Два раздельных режима ранее выбранных no-adjacency R-GCN — исходный R22 по Recall@5 и R34 по Full Support. При отсутствии исходного порядка одного из режимов не заменяем его близкими по названию весами. Предпочтительно восстановить исходный R22 forward на CPU из фактически выбранных оригинальных весов, проверить архитектуру, hashes версий и сверить доступные уникальные результаты. У R34 берутся фактические готовые dev ranks выбранной эпохи. Канонический порядок фрагментов фиксируется по прежней геометрии dev580. До открытия интервальной разметки выпустить файл прогнозов с SHA.

Разработка ранее использовалась для выбора чекпойнтов и порога, так что цель — воспроизводимость эффекта за пределами предыдущих 2000 test-вопросов. Это не внешний нетронутый тест. Проверить отсутствие совпадающих вопросов/траекторий с train/test и отсутствие dev-меток в HGB.fit и в inference-признаках. Строже отделяем узловое сходство от исходной задачи: измеряем полноту и долю покрытых символов source spans.

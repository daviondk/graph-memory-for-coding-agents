# Когда можно пропустить вычисление полезности в графовом читателе

Стоимость фрагмента и нативный ранг известны до запуска 80 деревьев HGB. У обязательного префикса и слишком длинных элементов полезность не влияет на решение. Проверили, окупается ли пропуск таких вычислений у действующего точного ридера. Дополнительно скомпилировали те же пороги и веса деревьев в обычные условные выражения C++. В результате сравнивались четыре варианта одного читателя. [Протокол](PROTOCOL_RU.md) · [Скрипт специализации](specialize.py)

| Лес и план оценки | Среднее время от числового пула до выдачи, мкс | Исход |
|---|---:|---|
| Интерпретация деревьев для всех фрагментов | 160,14 | Все идентификаторы совпали |
| Интерпретация только для нерешённых фрагментов | 155,71 | Ускорение 1,028× [1,023; 1,034] |
| Скомпилированные деревья для всех фрагментов | 85,26 | Ускорение 1,878× [1,851; 1,907] к полной интерпретации |
| Скомпилированные деревья только для нерешённых | 88,13 | Отношение времени полного плана к ленивому 0,967 [0,963; 0,972] |

2 000 вопросов, 1 207 траекторий, пять инициализаций и два заранее выбранных правила выбора эпохи. Таблица относится к первому чекпойнту (83,07% Full Support). На втором соотношения повторились: 1,872× для компиляции и 0,968× для ленивого вычисления на скомпилированном лесе. Три перемешанных повтора после прогрева для каждого случая и поштучная проверка 20 000 различных сочетаний вопроса, семени и правила выбора эпохи. Для всех четырёх методов упорядоченные пакеты совпали с исходным архивом. У всех фактически учтённых строк побитно совпала полезность. Показатель качества унаследован от [независимой оценки пакетов источников](../matched_reader/REPORT_RU.md). Числа относятся к тёплому CPU-пути после расчёта ранга и графовых данных.

**Граница применимости.** Ленивый план устранил вычисление леса лишь для 39 856 из 1 245 445 строк (3,20%) в основном сравнении. Целиком пропустить построение признаков удалось в 30 случаях на 10 000. Этой доли оказалось мало для уже быстрого леса с учётом получения и использования индексов. На том же оборудовании специализация модели потребовала 2,45 с однократно; её стоимость отделена от обслуживания. Сама компиляция деревьев и раннее применение дешёвых предикатов — известные техники. Практический результат этой проверки — измерение эффекта на том же пакете, включая случай, в котором дополнительная оптимизация ухудшает результат. [Все интервалы, p50 и p95](results.json) · [Hellerstein и Stonebraker](https://sigmodrecord.org/1993/06/03/predicate-migration-optimizing-queries-with-expensive-predicates/)

## Воспроизведение

Для нового замера нужны Python с NumPy, C++17 и соседний подписанный каталог matched_reader. На Windows выполнить `python -B specialize.py`, `python -B benchmark.py`, `python -B analyze.py`. Пересборка DLL может изменить двоичный хеш; делать это следует в отдельной копии. Текущие три повтора для каждого плана, исходные веса и версии закреплены. Для проверки сохранённых измерений выполнить `python -B verify.py`.

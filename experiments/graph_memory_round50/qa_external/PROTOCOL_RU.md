# Перенос выбора второго документа на 2WikiMultiHopQA

До извлечения адресов, генерации и оценки фиксируем 960 минимальных SHA256 UTF-8 строки «r50-2wiki-panel-v1|» плюс оригинальный ID среди всех 12 576 dev-записей. Каждый ID имеет одинаковое правило включения независимо от ответа, темы, подсказки или типа. На dev R32 ранее оценивал retrieval; задача нового опыта — реальные ответы замороженного Qwen по процедуре R49. Ограничение в 960 удерживает цену повторных генераций и при разбросе парной разности F1 порядка 0,20 даёт номинальную стандартную ошибку около 0,65 п.п. до поправки на кластеризацию. Планируемая единица bootstrap — первый точный документ.

Доменные входы — официальный parquet автора (revision 612bc5039a457880d9e7d84c3b0a4cf154b70e4f) и авторский data_ids.zip с алиасами. Сначала работаем только с ID, вопросом, каталогом и предложениями. Первый абзац раскрываем по R32; в этом корпусе при равенствах используется прежнее упорядочение SHA256(ID|заголовок). Объединяем предложения абзаца одним пробелом, как ReadOne. Сверяем все адреса основных ветвей с ранее зафиксированными R32, без чтения оценок. Второе чтение следует либо расширенному лексическому порядку, либо первому реально упомянутому заголовку в этом порядке. Пять placebo по неизменённой функции R47 и тем же семенам сохраняют число и позиции рёбер, решение сменить лидера, учитывают расстояние по рангам и длине заголовка. Фиксируем долю невозможных переназначений. Ранжировщик не получает текст вторых абзацев.

Во всех семи ветвях один и тот же Qwen3-4B-Instruct-2507 Q4_K_M, шаблон R49, максимум 80 токенов вопроса, до 192 на документ, общий фактический предел второго — минимум по исходным четырём альтернативам R46 и всем пяти placebo. Предел генерации 96, temperature=0, top_k=1, seed 460001, один слот, остановка на первой новой строке. Совпадающие запросы объединяем после проверки полной последовательности токенов. Воспроизводим 32 входа по зафиксированному порядку R49. Вопросы/тексты из архива остаются данными. Перед чтением gold фиксируются адреса, все токены и все прогнозы — тремя отдельными квитанциями.

Основной контраст на всех 960 — Answer F1 true минус expanded lexical с официальной обработкой yes/no/noanswer и авторскими aliases+demonyms. Вторичный — true минус среднее пяти placebo с тем же фактическим размером входа. Независимо воспроизводим EM/F1 для каждой ветви, долю полностью найденных заголовков опор, среднюю долю покрытых опор и балансы выигрышей/потерь. Срезы по факту замены второго ID и размеченному типу вопроса описательные. Интервалы 95% по 10 000 парным bootstrap кластеров идентичного первого документа, для placebo дополнительно совместная перевыборка 5 семян. Отдельный ретроспективный аудит точных вопросов и документов против Qwen-панелей R46/49 MuSiQue. Возможное предобучение модели на данных не устанавливается. Если ответный компонент объективно недоступен, сохраняем retrieval на той же панели с точным обозначением границы.

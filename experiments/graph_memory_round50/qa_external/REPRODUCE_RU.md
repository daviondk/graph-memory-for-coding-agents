# Воспроизведение

`python -B verify.py` в распакованной поставке проверяет SHA файлов, состав каждого полного токенового запроса, соответствие всех семи ветвей настоящим и переназначенным рёбрам, официально эквивалентные EM/F1 и документное покрытие всех 6 720 логических ответов. Для этой команды нужны только файлы самого исследования и стандартный Python.

Авторская версия dev отобрана по SHA256 ID из 12 576 записей. Все вопросы и документы проверяются по двум независимым представлениям — parquet создателя корпуса и dev из исходного архива с Wikidata-идентификаторами. Заголовки при оценке представлены хешами. Публичные ответы, алиасы и демонимы, использованные официальным оценщиком, хранятся в `gold.json.gz`. Эталонная строка, evidence и supporting_facts отсутствуют в видимой проекции ранжировщика и генератора. [Авторский набор](https://huggingface.co/datasets/xanhho/2WikiMultihopQA/tree/612bc5039a457880d9e7d84c3b0a4cf154b70e4f) · [Авторский код и ссылка на архив](https://github.com/Alab-NII/2wikimultihop/tree/13800e5be57df1b4040b9b1588c6c811779e69e9)

Для полного повтора нужны ранее замороженные R32, R46–R49 и их исполняемые среды. Проверяем SHA модели, llama.cpp и авторского оценщика; исходники ридера, декодирования и препроцессинга переиспользованы из R49. В исходном рабочем пространстве `paths50.py` указывает локальные каталоги. Скачиваемый ZIP читается как данные. Из публичного исходника верифицированного оценщика исполняется его официальная процедура, процедуры из текстов корпуса не исполняются. Для запуска авторского оценщика в окружении без ujson одноимённый JSON-интерфейс предоставляет стандартный модуль Python. Код расчёта метрик сохранён без изменений. Документные опоры в работе оцениваются по названиям; sentence-level и evidence-triple компоненты полного официального leaderboard не служат метриками здесь. [Официальный оценщик v1.1](https://github.com/Alab-NII/2wikimultihop/blob/13800e5be57df1b4040b9b1588c6c811779e69e9/2wikimultihop_evaluate_v1.1.py)

В исходном прогоне старый клиент записал все ответы и повторы, затем завершился при составлении квитанции из-за пути к runtime.py. До чтения эталонов seal50.py независимо сверил порядок и все ответы с журналом и привязал его хеш и хеш журнала сервера к квитанции. Время 334,67 с измерено по отметкам первого назначения и последнего освобождения слота. При повторении в чистом каталоге файл runtime.py уже присутствует, квитанцию пишет обычный клиент.

Сервер вызывает `stages.py input`, затем `stages.py answer` и завершает свой процесс. Корпус, официальный скрипт, ответы сервера и временные материалы оценщика находятся в `D:/CodexResearch/x20-r50-qa-external`; при повторе выберите изолированный путь. `costs50.py` учитывает непрерывный запуск и сопоставляет каждый адрес запроса с его строкой времени; квитанция устройства снята во время инференса. `orders.json.gz`, `contexts.json.gz`, `prompts.json.gz`, `answers.json.gz` и `outcomes.json.gz` образуют последовательность от выбора документа к фактически выданному ответу и двум оценкам.

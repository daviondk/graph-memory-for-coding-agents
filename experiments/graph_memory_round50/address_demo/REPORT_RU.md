# Выбор второго адреса по видимому упоминанию

Локальная консоль показывает все 1 280 сохранённых эпизодов подтверждающей проверки 2WikiMultiHopQA. Посетитель видит вопрос, первый прочитанный фрагмент и девять оставшихся адресов, упорядоченных по косинусному сходству Qwen3-Embedding-8B. У каждого адреса показан признак упоминания заголовка в первом фрагменте. Отрыв равен разности косинусов свободного лидера и лучшего упомянутого кандидата. Когда отрыв не превышает порог, выбирается упомянутый кандидат. В отсутствие упомянутых адресов выбирается свободный лидер. [Исходный эксперимент](../gate_confirmation/REPORT_RU.md)

Запуск `python -B address_server.py --port 0` из этой папки печатает локальный URL. Порт 0 выбирает свободный номер, явный номер также поддерживается. Для запуска достаточно Python со стандартной библиотекой и трёх соседних файлов: `address_server.py`, `address.sqlite`, `index.html`. Сервер привязан к `127.0.0.1`, SQLite открывается только для чтения. [Сервер](address_server.py) · [Страница](index.html)

На странице есть точные настройки 0, зарегистрированный порог 0,04178261756896973 и безусловное предпочтение лучшего упомянутого заголовка. Можно задать промежуточный порог. В SQLite запрос выбирает ранг и видимую связь, затем второй документ и записанный ответ читателя Qwen3-4B-Instruct-2507. Подстановка ответа требует точного совпадения SHA-256 входной последовательности токенов и снимка формирования запросов. При сборке проверяется каждый токенный хеш исходных 1 580 промптов и принадлежность каждому из 3 840 назначений. Если пользователь API укажет чужой снимок или неподходящий ключ запроса, сохранённый ответ и его F1 отсутствуют для этого выбора. Эталонные варианты и опорные заголовки раскрываются отдельным действием. Показанные F1 — индивидуальные сохранённые результаты оценки по официальным правилам.

При зарегистрированном пороге изменились 55 адресов, вырос F1 у 21 вопроса, снизился у 4. Средний Answer F1 составляет 41,62% при нулевом пороге, 42,70% при зарегистрированном, 42,58% при обязательном предпочтении упоминания. Начальный фильтр показывает 55 смен адреса. Фильтры улучшений и ухудшений отбирают эпизоды по известному результату. Для просмотра всей панели выберите All episodes. Внутри фильтра порядок задаёт хеш идентификатора. Это демонстрация прежних измерений, интерпретация и доверительные интервалы приведены в первичном отчёте.

Команда `python -B verify_smoke.py` проверяет SQLite, HTTP, точные ограничения на показ ответов, 3 840 решений, число переключений и агрегированные F1. При наличии исследовательского архива `python -B verify_smoke.py --study ../gate_confirmation` дополнительно сравнивает каждый адрес, ключ, стоимость входа, текст ответа и F1 с первичными артефактами. Выполнены обе проверки. В Chromium проверены выбор и смена эпизода, все три режима порога, собственный порог, раскрытие эталона и ширины 390/1 040 px. Новых обращений к моделям не было.

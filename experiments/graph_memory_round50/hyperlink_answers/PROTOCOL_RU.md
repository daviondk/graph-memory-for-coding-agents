# Реальные адреса Википедии и ответы Qwen

Канонический бесцелевой пакет содержит handoff.json с SHA256 8983736ca23bbe18337053578f291b2cd5c687dc2d046db30125f98f1e01cc07 и пары handoff-train/dev. Для href он отбрасывает невидимые записи об якорях до проверки метаданных. Для union используется объединение этого видимого множества и открытых текстовых ссылок с прежним порядком.

На уже изученных панелях 2WikiMultiHopQA принимаем предсказания hyperlink_control, запечатанные до оценки ответов нового опыта. Первичная панель — зафиксированные 640 train, вторичная — прежние 960 dev. Публикуем обе независимо от направления эффекта. Исходы предыдущих текстовых методов на обеих панелях известны. Новые условия отвечают на вопрос, помогает ли Qwen реальный адрес аннотации Википедии сверх точного текстового упоминания названия.

Все три порядка для второго чтения ограничены одним ранее зафиксированным лексическим ранжированием каталожных заголовков. True — первый фактически упомянутый заголовок. Href — первый заголовок, в который ведёт допустимая исходящая аннотация внутри видимого префикса первого документа. Union — первый кандидат из объединения двух множеств. При пустом множестве выбирается лексический лидер. Порядки и случаи отказа следуют основной подписанной проекции hyperlink_control. Проверяем её против прежнего назначения true и пересчитываем все три ID из множеств и порядка. На все вопросы сохраняется один первый документ и две фактические выдачи.

Первичная разность — официальный Answer F1 union минус true на 640. Вторичные — href минус true и union минус href на этой панели, затем все три на 960. Все знаменатели включают fallback и совпавшие ID. Также EM, полный набор опорных заголовков, парное число выигрышей/потерь и число реально сменившихся документов. 95% интервалы, 10 000 парных перевыборок кластеров точного первого документа, вес вопроса одинаков, NumPy seed 470091. Кластеризация особенно существенна на dev, где в прежнем исследовании было 949 разных первых документов.

Фиксируем прежние шаблон, модель Qwen3-4B-Instruct-2507 Q4_K_M, greedy, 96 выходных токенов, правила усечения вопроса и документов. Длину второго фрагмента ограничиваем прежним общим бюджетом соответствующей панели и фактической длиной выбранных href и union. Все три ветви на каждом вопросе получают один и тот же токенизированный префикс и фактическую длину. Ответ можно заимствовать только по совпадающим полным массивам ID токенов из подписанных qa_replication и qa_external; декларация всего списка использования и новые прогнозы фиксируются до оценки условий. Все остальные запросы исполняются локально; для независимого контроля повторяем 32 ранее сгенерированных и, если доступны, 32 новых запроса по наименьшему SHA256 строки r50-href-repeat| плюс хеш входа в каждой страте. Измеряем отдельно уникальные входы, повторное использование по ветвям/панелям, новые вызовы, повторы и стоимость. Опора оценивается по названиям. Возможное попадание публичных примеров в предобучение, повторное использование панели и единичная модель ограничивают перенос.

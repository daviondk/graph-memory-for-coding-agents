# Семантический выбор заголовка при двух чтениях

Регистрация до вычисления новых эмбеддингов, рангов и ответов. Ранее изучены ответы текстовых методов на всех 640 вопросах qa_replication, поэтому это проверка нового адресатора на известной панели. Все 640 вопросов из 2WikiMultiHopQA train и их первые страницы зафиксированы прежним manifest 2432a6a038dc1e8987deaf82bd9a90f0b885a47fd55e40d6b38542958afe01c7. Отбора по размеру эффекта или наличию явной ссылки не будет.

Сравниваем четыре метода выбора второго источника при фиксированном первом. Lex — прежний expanded lexical; true — первый фактически упомянутый кандидат в этом порядке с откатом на lex. Dense — первый заголовок по косинусной близости. Linked_dense берёт первый действительно упомянутый заголовок по тому же плотному порядку, при отсутствии упоминаний возвращает dense. Сам первый источник исключается. Для равенств используются прежний порядок SHA256(qid|title) и затем исходная позиция. Открывается ровно одна и та же первая страница; адресатор получает вопрос, каталог заголовков и тот же видимый префикс её текста в 192 wordpiece токена E5, который наблюдал предыдущий алгоритм. До второго выбора остальные тексты недоступны.

Энкодер — официальный Qwen3-Embedding-8B Q4_K_M (пин R39), last-token pooling, 4096 координат, float32, L2. Для запроса фиксируем точный шаблон `Instruct: Given a question and a passage already read, retrieve the title of the next passage needed to answer the question.\nQuery: {question}\n{visible first snippet}`. Документ энкодера — голая строка заголовка. Используем токенизацию llama.cpp без специальных маркеров внутри пользовательских данных, первые 511 токенов и один EOS 151643. Векторы точных повторов кодируются один раз за прогон. Цену поиска измеряем отдельно: число логических и уникальных векторов, токены и длительность кодирования заголовков и запросов, вычисление близостей и выбор.

Все четыре ветви используют один Qwen3-4B-Instruct-2507 Q4_K_M, прежний greedy-параметр, шаблон и предел 96 выходных токенов. Фактическая длина второго фрагмента — минимум прежнего общего предела qa_replication и длин выбранных dense-адресов. Заголовки и тексты вторых документов раскрываются ридеру только после фиксации выбора; для приведения длины сохраняем прежний офлайн-расчёт по уже запечатанным кандидатам. Для равных адресов и токенов дедуплицируем запросы внутри запуска, все уникальные прогнозы получаем заново. Проверим неизменившиеся входы и ответы базовых ветвей относительно прошлой поставки и 32 повтора по неизменному правилу. Прогнозы фиксируются до открытия новых оценок.

Основной контраст — официальный Answer F1 linked_dense минус dense на всех 640. Вторичные — true минус dense, dense минус lex, linked_dense минус true и true минус lex на общих токенах. Также EM, полностью найденные gold-заголовки, доля покрытых опор и переключения. Интервалы 95% — 10 000 парных перевыборок 640 уникальных первых документов; RNG numpy seed 470091. Срез по изменению второго адреса между двумя dense-методами описательный. Для проверки сторонним скриптом сохраняем числа косинусов всех кандидатов, порядок при равенствах, наблюдаемые адреса упоминаний, точные токенизированные запросы, ответы и метки после фиксации прогнозов. Исходники из корпуса остаются данными. Знак эффекта заранее не предполагаем.

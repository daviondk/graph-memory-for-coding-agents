# Проверка по гиперссылкам исходной Википедии

Заморожены прежние две непересекающиеся по ID панели 2Wiki: 960 dev и 640 train, с теми же первыми чтениями и фиксированным лексическим порядком оставшихся заголовков. Контроль использует только подлинные записи mentions/ref_url авторского para_with_hyperlink.zip. Доступна информация о ссылках внутри реально открытого префикса первого абзаца (192 токена E5 по прежнему ReadOne). Весь остальной текст источника используется только для технической сверки версий. Посещение второго документа по исходящему адресу считается ровно одним дополнительным чтением.

До просмотра метрик фиксируем следующее. Находим исходный абзац по тому же заголовку (NFC и эквивалентные пробелы/подчёркивания). Сверяем весь доступный читателю буквенный и пунктуационный префикс, разрешая лишь расхождения в пробельных символах. Отдельно измеряем строгую буквальную идентичность префикса и полного текста, а также полную идентичность без пробелов. Неравные видимые последовательности, неоднозначное происхождение, невалидная разметка и недоступные исходники означают возврат к прежнему lexical. При нескольких согласующихся записях требуем одинаковое множество выбираемых кандидатов. Ссылка допустима, только если якорь непуст, имеет корректные смещения предложения и целиком видим. Сопоставляем целевой ref_url с уникальным заголовком; можно разрешить однозначный ref_ids в уникальный Wikipedia ID кандидата по той же авторской таблице. Конфликт или неоднозначность адреса оставляем без перехода. Правило выбора — первый допустимый адрес в прежнем лексическом порядке с прежним fallback. Контроли: исходное текстовое упоминание и простой lexical на тех же двух чтениях; дополнительно только прямой ref_url, строгий видимый префикс и объединение текстового упоминания с авторской ссылкой.

Две стадии разделены контрольной суммой прогнозов до открытия gold. Первично на всех 960 dev сравним полное покрытие размеченных заголовков у href и подлинного текстового упоминания. Отдельно та же разность на удержанных 640 train. Знаменатель сохраняет пропуски и лексические возвраты. Приведём доступность/согласие адресов, пересечение с текстовыми связями, расхождения выбранных ID, победы/потери, среднюю долю заголовков, парный 95% интервал 10 000 перевыборок по точному первому документу. Основные пропорции и разности сообщим вне зависимости от результата. Проверяется достижимость и выбор заголовков, дополнительная генерация ответа не входит. Источник — один архив авторов; фиксируем SHA-256, единственный проверенный ZIP member, CRC32, число считанных байтов и причину каждого отказа.

# Память о частично выполненном изменении в момент остановки агента

Отдельный перспективный опыт во время уже начатой серии R12 на двух обычных задачах VibeMemBench. После двух завершившихся эпизодов с пустой submission, **до просмотра диффов остальных контейнеров**, фиксируем политику наблюдения. Первые два завершённых эпизода исключены, причина и число будут показаны. Третий может войти в поток с задержкой. Наблюдатель ничего не передаёт решателю и не меняет файлы в контейнере. В момент очередного ответа модели и при появлении контейнера читаем текущий git diff HEAD по отслеживаемым файлам и индексированным добавлениям. Патч, уже знакомый по SHA-256, сохраняем один раз. Это внешняя исполняемая запись частичного результата. Неиндексированные новые файлы не участвуют. Проверяем последнюю доступную версию при остановке. Полная выгрузка исходов benchmark для работавшего агента недоступна.

Главное сравнение: официальный submitted patch и заранее выбранный последний наблюдаемый патч, прогнанные одним и тем же официальным оценщиком на исходной версии. Отдельно состояние рабочего дерева при последних переданных проверках, число известных версий, объём фактических дельт и потери нормального submit. Если был успешный submit, он имеет первенство в консервативном варианте fallback, и считаем, изменило ли что-либо аварийное повторное использование накопленного. Публикуем actual n, left-truncation, долю полученных окончаний, число изменившихся причин и отдельно статусы инфраструктуры. Нулевой/неполный патч остаётся в знаменателе. Последний опрошенный снимок может отличаться от реального последнего состояния при быстрой остановке контейнера. Никакое новое состояние не выбираем по скрытым тестам; последующая постпроверка представляет диагностическую shadow-оценку, счёт официальной R12 не меняется.

Ближайший сильный контроль — один последний полный снимок без графа. Наблюдение адресуется следующей работе и отделяет потерю прогресса из-за формата завершения от неспособности написать полезный код. Построение полноценной новой системы или утверждение о SOTA требует независимой серии с включённым с начала сохранением для всех рук и непосредственного сравнения с указанным контролем.

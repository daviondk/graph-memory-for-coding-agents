# Прогноз следующего файла после неуспешного поиска

До вычисления следующих чтений и PR-меток фиксируется выборка: все 625 публичных историй VibeMemBench из 17 научных и аналитических Python-репозиториев, сохранённых в предыдущей серии. Предыдущая работа изучала только результат повторного текстового поиска на двух снимках дерева. Новые исходы здесь — фактический первый успешный просмотр файла после поиска и принадлежность файла независимому историческому PR. Знакомство с относительной редкостью точного повтора и общими числами R12 уже состоялось. Это ретроспективный replay с проспективным порядком вычисления и отдельным запечатыванием выходов, не вмешательство в действия агента.

**Момент прогноза.** По всем исходным сообщениям идём слева направо. Используем строгие случаи настоящего grep с согласованным численным exit 1 в двух полях, пустым показанным и сырым выводом и однозначной областью по грамматике R12. Нулевой лимит количества совпадений исключаем. В момент наблюдения пишем вход для рейтинга и запираем данные по SHA. Формирование файла для предиктора не читает будущие сообщения текущего префикса; в том же архиве остаются последующие шаги, но они не попадают во вход. Самостоятельный процесс предиктора принимает только эти входы, без Git, без тестовых меток и без сообщения после промаха. Публикуем хеши всех прогнозов до извлечения исходов. Все подходящие моменты, включая повторные на одной задаче, входят в знаменатель.

**Кандидаты.** Только .py-файлы в том же распознанном корне репозитория. Файл может ранее присутствовать в успешном прямом чтении (cat, sed, head, tail, nl), в успешном grep с однозначным адресом или в фактически выданных строках положительного поиска, привязанных к имени .py-файла. Добавляем явно указанный .py-путь текущего неуспешного поиска. Для каждого документа сохраняем ограниченный объём видимого текста, идентификаторы исходного обращения, тип действия, давность и путь. Текст задачи, поисковый литерал и область доступны всем методам. Никакого обхода репозитория на входе. Каталоги, произвольные интерпретаторы, данные вне распознанного корня и неразрешимые адреса в качестве файлов не размечаются.

**Что сравниваем.** (1) Последний прямо прочитанный файл, затем остальные по давности. (2) Сначала текущий путь поиска, затем последний прочитанный. (3) BM25 по одинаковым документам плюс разбиение идентификаторов camelCase/snake_case, условия входа фиксированы. (4) Сильная смесь места промаха, давности и BM25. (5) Дополнительная связь между файлами через редкие именованные идентификаторы из прошлых наблюдаемых фрагментов. Посев исходит от текущей области/последнего чтения и лексически подходящих файлов. Вклад кандидата зависит от частоты символа и числа документов, где он проявился. Одна фиксированная смесь сравнивается с (4), без поиска параметров по итоговым меткам. Абляция переназначает содержательные рёбра другим файлам с детерминированной перестановкой. Список и порядок формул фиксируются в исходнике до извлечения исходов.

**Основной исход навигации.** Первый успешно прочитанный .py-файл с явным адресом в одном из следующих пяти вызовов инструментов; сюда включаются чтения текстового фрагмента по одному файлу, но не поиски по каталогу, печатающие списки совпадений. Успех требует статус 0 и непустое содержательное наблюдение. Путь и корень определены по входу инструмента, подтверждены ответом. Если подходящего события в окне нет — явно цензурируем этот исход. Успешные просмотры из другого репозитория/корня не превращают прежнее наблюдение в совпадение. Отдельно отмечаем, когда ближайший подходящий файл вообще отсутствовал в доступной памяти. При наличии цели оцениваются все события, включая недостижимые с нулём. Верхняя граница = покрытие цели кандидатами. Дополнительно отчёт о прямых чтениях cat/sed/... отдельно от grep по одному файлу, а также о первом поисковом промахе на задачу. Исследуем действия, не утверждаем, что следующий выбранный агентом файл был лучшим.

**Независимый исход локализации.** Для каждой задачи с пригодными Git-метаданными сравниваем прогноз с изменёнными ранее существовавшими производственными .py-файлами настоящего PR. Требуем соответствия base_commit SWE-rebench-V2 первому родителю merge и корректной хронологии. Отделяем тесты, docs и examples. Бинарный положительный исход — хотя бы одно попадание в множество открытых изменённых путей. Дополнительный анализ включает также тестовые и любые .py-файлы патча, поштучно указываем недостижимые случаи, в т.ч. PR только с новыми файлами. Получаем Git-метки только после печати и хеширования прогнозов. Из R12 берём только публичные идентификаторы и происхождение ревизий, алгоритм ранжирования к ним не обращается.

**Метрики и неопределённость.** Число задач и запросов, цензурирование, покрытие кандидатов, Hit@1, Hit@3 и MRR с учётом недостижимых целей, число парных выигрышей/проигрышей и процентный эффект относительно простого и сильного контролей. Указываем разброс парной разницы при bootstrap по задачам с фиксированным seed, повторные запросы одной задачи остаются в одном блоке. Наборы репозиториев для прозрачной проверки переносимости — первые шесть по SHA256 строки R13-dev-after-miss|repo (контрольная характеристика) и остальные одиннадцать (зафиксированная внешняя страта). Параметры остаются одинаковыми, ни одна страта не служит для подбора. Меры стоимости — размер и число записей памяти, wall-clock CPU ранжирования и число кандидатов. Сохраняем доступные наблюдения и поштучные ответы. Если граф проиграет простой эвристике или не превысит её, это результат эксперимента.

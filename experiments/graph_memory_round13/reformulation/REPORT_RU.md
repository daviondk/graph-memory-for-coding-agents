# Какой файл читать после пустого поиска

В двух непересекающихся по репозиториям панелях граф по уже просмотренным фрагментам чаще выдавал первым файл, который впоследствии изменили разработчики. На основной панели прибавка к смеси BM25, давности и области поиска составила 5 попаданий на 191 прогноз, на повторной — 2 на 45. Для предсказания фактического следующего чтения агентом стабильного преимущества перед простым последним адресом не обнаружено. Улучшение качества решения задач и превосходство над опубликованной системой памяти остаются открытыми вопросами.

## Устройство эксперимента

Использованы 625 опубликованных историй из 17 преимущественно научных Python-репозиториев и отдельная репликация на 245 историях из 11 библиотек и инструментов Python. Ко второй панели относятся, например, Click, Hypothesis, attrs и setuptools. Строгие признаки пустого поиска включают настоящий вызов grep-подобной программы, согласованный код возврата 1 в двух полях, пустые видимый и сырой выводы и однозначную область поиска. Обе панели включают все подходящие действия в зафиксированных историях. Порогов по успеху задачи или длине истории нет. Истории и начальные версии происходят из двух открытых наборов. [VibeMemBench, фиксированная версия](https://huggingface.co/datasets/Tongyi-ConvAI/VibeMemBench/tree/11164976b4f920cdb0d0cd570ca572e49acea1e8) · [SWE-rebench-V2, фиксированная версия](https://huggingface.co/datasets/nebius/SWE-rebench-V2/tree/d7608f017a29ab256400ad4b73d5248d97204966)

В момент промаха для каждого видимого ранее Python-файла сохранялись путь, положение чтения в истории, отрывки полученного текста и ссылки на вызовы инструментов, которыми эти отрывки были получены. Объём ограничен 64 файлами на корень и 3072 символами последнего текста на файл. Текущий явно указанный в запросе .py-путь тоже доступен всем методам, даже если его содержимое ещё неизвестно. Предиктор видит этот снимок, литерал, область поиска и исходное описание задачи. Ранжирования запечатывались до извлечения последующих чтений и списков изменённых файлов, отдельно для каждой панели. Репликацию зарегистрировали после основной оценки и повторили с теми же коэффициентами и побайтно идентичным правилом ранжирования. [Основной протокол](PROTOCOL_RU.md) · [Протокол репликации](replication/PROTOCOL_RU.md) · [Код ранжирования](rank.py)

**Следующее чтение** — первый распознанный успешный просмотр одного Python-файла в том же корне за следующие пять вызовов bash. Сюда входит успешный непустой grep по одному конкретному файлу. Результаты для явных просмотров без grep выделены отдельно. **Файл патча** — любой ранее существовавший производственный .py-файл, который влитый PR модифицирует, удаляет или меняет по типу. Принимаются только задачи, где base из SWE-rebench-V2 в точности совпал с первым родителем merge-коммита и предшествовал ему по времени или имел ту же временную метку. Для проверки чувствительности отдельно размечены все .py-пути в PR, включая тесты и новые файлы. Знаменатель каждой метрики включает случаи, когда в памяти отсутствуют все подходящие файлы.

В основной панели несовпадение Git base исключило 44 задачи (74 промаха). В двух других случаях при точном совпадении версии подходящего изменения производственного Python-файла в PR не было. Во внешней панели несовпадение base исключило 18 задач (28 промахов). Единственность наблюдаемого следующего чтения и множественность возможных полезных чтений ограничивают поведенческую оценку.

## С чем сравнивали

Простой контроль выдаёт текущий файловый адрес поиска, затем файлы по давности прямого просмотра. Лексический контроль использует BM25 по путям и фрагментам со словами задачи, литерала и области поиска, включая разбиение compound identifiers. Сильный контроль объединяет нормированный BM25 (0,35), обратную давность позиции в списке прочитанных файлов (0,35) и близость пути к области поиска (0,30). Все методы получают одинаковые кандидаты.

Граф строится по отрывкам, уже показанным агенту. Ребро между двумя файлами имеет вес IDF-взвешенного косинусного сходства множеств встречавшихся в них идентификаторов. В ребро попадают слова длиной от четырёх символов, встретившиеся хотя бы в двух документах и достаточно редкие внутри данного снимка. Три лучших файла сильного контроля передают массу соседним файлам пропорционально сходству. После нормировки этой добавке присвоен вес 0,22. Вариант с перемешиванием сохраняет наборы идентификаторов и детерминированно переставляет их между файлами. Дополнительная абляция заменяет три стартовых файла всеми файлами с равной исходной массой. ## Интерпретация эффекта

Для локализации патча на основной панели у графа относительно смеси 6 выигрышей, 1 проигрыш и 184 совпадения по Hit@1. Разница +2,62 п.п., 95%-й парный bootstrap-интервал по задачам [0,00; +5,58] п.п. По MRR разница +0,0114 с интервалом [−0,0032; +0,0286]. На внешней панели 2 выигрыша, 0 проигрышей и 43 совпадения, +4,44 п.п. [0,00; +10,72]. По MRR +0,0204 [−0,0040; +0,0521], а Hit@3 снизился на один случай. Двусторонняя точная перестановка знаков парных эффектов целых задач для Hit@1 даёт p=0,125 и p=0,50. Удержание только первого подходящего промаха каждой задачи сохраняет направление — 59 против 54 на 120 задачах и 19 против 17 на 31. Внутреннее деление первых 17 репозиториев по заранее заданному хешу также доступно в результатах. [Основные парные эффекты](paired_effects.json) · [Репликация](replication/paired_effects.json)

Абляция объясняет, что именно стоит проверять дальше. Равномерная центральность воспроизводит прибавку к попаданию в патч и даёт лучший MRR на обеих панелях. Для предполагаемого преимущества особых стартовых узлов свидетельств пока недостаточно. Например, в Click предыдущие чтения показывали идентификатор split_arg_string. Совпадения связали shell_completion.py с parser.py, присутствовавшим в патче. В тесте PennyLane те же правила привели от реализации к тестовому файлу через controlledphaseshift, что стоило попадания по первому адресу. Такие связи можно проверять непосредственно по сохранённым фрагментам и идентификаторам действий. **Цена.** Медиана числа доступных файлов — 4 и 2, максимум — 39 и 15. Медиана сериализованного состояния файлов — 4212 и 3281 байт. На одном потоке Python 3.14.4 медиана вычисления всех шести ранжирований из уже созданного снимка — 1,19 и 1,01 мс. При этом медиана фазы подготовки идентификаторов и вычисления фактического графового слагаемого — 0,104 и 0,081 мс. Оба замера исключают дисковое чтение, запись и формирование наблюдений. По оригиналам проверены 4089 сохранённых ссылок на наблюдения и 234 полученных следующих чтения. Для всех 153 строгих пар исходные пути независимо сверены через git diff-tree.

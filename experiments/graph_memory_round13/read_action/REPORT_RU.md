# Меняет ли графовая подсказка реальное чтение файла

Локальный Qwen3.8-27B сделал **54 вызова инструмента read_file**. Все вызовы имели валидный аргумент, все выбранные файлы были прочитаны по неизменяемому SHA исходной версии. На заданиях, где два ранжирования предложили разные первые файлы, замена подсказки изменила выбор модели в **9/13** случаях первой панели и **2/5** внешней. При сопоставлении с независимыми изменениями кода сильнейшим практическим контролем оказалось условие без подсказки. [Реальные выборы модели](model.jsonl) · [Квитанции чтения и SHA файлов](reads.gz) · [Метрики](results.json)

| Источник подсказки | Основная панель, прочитан существующий production-файл последующего PR | Новые репозитории, та же метрика | Основная / внешняя, выбрана сама подсказка |
|---|---:|---:|---:|
| Без подсказки | **7/8** | 2/3 | — |
| BM25, давность и область | 2/8 | 2/3 | 8/13 и 2/5 |
| Та же база и граф общих идентификаторов | 6/8 | **3/3** | 10/13 и 3/5 |

Граф против плоской подсказки дал пять парных выигрышей и одну потерю на основной панели, один выигрыш без потерь на внешней. Без подсказки модель самостоятельно прочитала файл будущего патча в семи из восьми основных задач. При одинаковом списке вариантов графовая подсказка потеряла одно это попадание. На трёх внешних задачах граф добавил одно попадание относительно самостоятельного выбора. В сумме получается по 9/11 с графом и без подсказки. Эта сумма описательна, важны малые раздельные знаменатели. При прогнозе ближайшего наблюдаемого естественного чтения результаты для «без подсказки / плоская / граф» равны 1/11, 0/11, 1/11 для первой панели и 1/4, 1/4, 2/4 для второй. Файл в реальном PR и выбор первоначального агента — различные исходы.

Для префикса фиксировались задача, корень поиска, литерал, прежние файлы, отрывки их наблюдений и давность действий. Между условиями менялась одна строка с необязательной рекомендацией. Модель вызывала ровно один инструмент при greedy-декодировании. Реализация доставляла выбранный исходный файл отдельным чтением в указанной Git-версии. Во всех 54 случаях использовался публичный источник содержимого по точному commit SHA. Входов и запросов в основной панели 13×3, во внешней 5×3. На точную исходную ревизию и существующий production-путь в PR пришлись лишь 8 и 3 задачи. Остальные вызовы сохранены и учитываются в метрике изменения действия. Длина подсказки и число токенов по условиям находятся в построчных записях. [Протокол до инференса](PROTOCOL_RU.md) · [Данные на момент выбора](cases.gz) · [Парные исходы](outcomes.gz)

**Граница эффекта от этой формы доставки.** В исходных 267 и 73 префиксах верхние пути двух ранжирований различались лишь в 14 и 5 случаях, то есть в 5,24% и 6,85%. При одинаковом интерфейсе, одинаковом контексте и детерминированном выборе разница, действующая только через замену одной рекомендованной строки, физически не может изменить выбор на остальных случаях. Для вмешательства использован первый такой случай на задачу. Агент выбирал из малого меню ранее адресованных файлов. Из результатов нельзя вывести долю исправленных задач, экономию времени при свободном использовании shell или пользу предвычисления полного графа. Случаи несогласия выбирались без индивидуальных исходов, но авторам уже были известны агрегаты ранжирования. [Запечатанные знаменатели и входы](assignment.json)

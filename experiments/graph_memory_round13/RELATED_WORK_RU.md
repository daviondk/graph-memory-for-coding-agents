# Какие сравнения нужны для рабочей графовой памяти

Здесь важно разделить три результата — видимость факта в контексте, изменение действия агента и прохождение тестов исправленной программы. Для каждого уровня есть опубликованный ориентир и свой корректный эксперимент.

| Вопрос | Что сделали авторы | Как это меняет нашу проверку |
|---|---|---|
| Помогает ли представление состояния рабочего каталога действующему решателю? | Wang и соавторы предлагают Ledger. Слой inform показывает компактное состояние, govern перед выполнением команды может вернуть сохранённый результат. На 500 SWE-bench Verified авторы сообщают Pass@1 56,2% → 64,2% с GPT-5 mini и 75,8% → 81,0% с MiniMax M2.5. | Это сильный кандидат для сравнения полного цикла. Наши исторические проценты локализации и две задачи Vibe не сопоставимы с этими Pass@1. Нужно зафиксировать один и тот же scaffold, model, лимиты, набор задач, стоимость обслуживания и проверку исходов. [Первичная работа](https://arxiv.org/abs/2608.00808) |
| Как проверить, использует ли агент конкретное знание? | Mohammadi и соавторы рассматривают доступность связанных фактов перед редактированием. Они экспериментально предоставляют либо убирают знание, в том числе знания об изменившихся именах API, и измеряют последствия по выполненной работе. | Нужна парная интервенция при тех же путях и свидетельствах. Поэтому у нас отдельно фиксируются сохранённый документ, реально открытый инструментом файл и решение задачи. Из попадания правильного пути в top-1 не следует, что агент его выберет. [Первичная работа](https://arxiv.org/abs/2608.16630) |
| Как интерпретировать промежуточную удачную правку или пустую сдачу? | Yang и соавторы проверяют промежуточные патчи скрытыми тестами на ≈6000 прогонах восьми открытых моделей. Правило остановки после двух подтверждений сэкономило у них 23% в зарегистрированной репликации. Не меньшую результативность в зарегистрированном тесте установить не удалось. | В нашем опыте заранее выбирается последний рабочий снимок. Сравниваются один и тот же эпизод и одни и те же тесты. При выборе новой подсказки, которая меняет действия агента, требуется его новый запуск. Поиск лучшего снимка после просмотра gold-тестов допускается только как верхняя граница отдельной диагностики. [Первичная работа](https://arxiv.org/abs/2611.22901) |
| Должен ли граф обязательно охватывать исходники до старта? | В LocAgent авторы подготовили граф сущностей и затем локализуют код через поиск и обход связей. В VibeMemBench единицей памяти служит опыт, накопленный между задачами. | Для нашего вопроса на первом месте стоимость получения свидетельств непосредственно в траектории. Также нужны контроль на давность, сильный лексический гибрид, простая центральность по тем же вершинам и, для готового продукта, сравнение с подходящим опубликованным индексом на его бенчмарке. [LocAgent, ACL](https://aclanthology.org/2025.acl-long.426/) · [VibeMemBench](https://arxiv.org/abs/2609.23570) |

Поиск по темам выполнен на английском по сочетаниям coding agent, execution state, memory, patch selection, intermediate patches, working set, graph localization и next file. Для фактических утверждений использованы первичные публикации. Это целевой поиск ближайших контролей для текущих экспериментов. Библиографическое первенство механизма ранжирования по ограниченному набору статей определить нельзя.

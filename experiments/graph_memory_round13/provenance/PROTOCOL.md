# Provenance of negative code searches before reuse

Can evidence visible before an agent's empty search predict that the target Git base already contains a match, at a lower cost than verifying every search? This is a pre-specified screening comparison on the 147 already labeled R12/negative_external query instances, not independently unseen data. No query outcome or per-case result is inspected to choose the rules. The input population includes unsupported/missing-target cases if present; publish their denominator. The primary label is definite positive vs definite negative on the earlier immutable Git base only. Report missing scopes separately and in a pessimistic sensitivity. Do not equate a mismatch with a particular cause or the identity of the observed working copy.

Use strictly earlier completed tool results and commands from each published trajectory plus the identity of the current empty query, its reported cwd/path and the pinned target base. Never execute historical shell commands. Prefix-only evidence is free apart from parsing logged bytes. Verification against a target tree/blob is an explicitly paid extra operation. Historical writes, local modifications, ignored/untracked files, different versions and tool differences can invalidate provenance despite real matching lines. The R12 matched-witness implementation remains immutable. Compare R12 last witness with new extraction over all prior eligible steps. Use the R12 parser and thresholds for directory or content support; strictly matched content means at least 3 different normalized lines of at least 32 characters in one tracked file. A recent witness occurred within the previous 5 completed tool calls. In-scope files must be exactly the named path or below the query path and satisfy all supported include-glob semantics (union of globs); for a scoped directory listing require the requested scope or a directory beneath it. A matching earlier pwd is an explicit successful standalone pwd or cd path && pwd naming the inferred root/directory. A cwd-only baseline instead trusts the default /testbed mapping. Also register root-path-exists at the archive as a separate paid structural baseline. 

Policies: trust all; always query git; trust only default cwd or observed pwd; trust any prior matched directory; trust any file with two matching long lines; R12 most-recent witness; trust fresh content; trust scope-matched content; trust fresh + scope-matched + strict (3×32); trust evidence from two distinct matching tracked files in scope; and trust only scoped strict evidence without a conflicting earlier substantive plain-file observation. Declare a weak conflict only for an eligible successful cat/head/tail/sed/nl on a tracked file (or missing tracked path), at least two substantive output lines, with zero exact matching normalized long lines in its archived counterpart. Separately test a narrow positive red flag: the literal already appears in an earlier substantive in-scope displayed file line, either from the prefix alone or corroborated on exactly the same target blob line. A negative outcome with no red flag may still be unsafe. Signed confidence rank, fixed before labels: first absence of a corroborated positive line, then absence of scoped conflict, then strongest scope- and time-sensitive matching evidence (fresh strict > scoped two lines > root two lines > directory > explicit pwd > no evidence), then fewer tool calls since best qualifying witness. Tie break by SHA-256 of observation ID.

Primary endpoint selective risk (fraction of unsafe target-base positives among reused empty answers) against coverage (fraction reused among evaluable targets); one paid direct target search for each abstention; report unsafe misses over all, unsafe caught, actual reruns, and risk when no reused row as undefined. Compare each nontrivial policy to exact-count random selection both globally and conditional on its reuse count per task. Compute expected errors and a fixed 4096-permutation within-task interval/one-sided p with issue as a blocking factor, 10,000 task cluster bootstrap for risk and risk differences (seed 13027). Do not treat salts or bootstrap draws as tasks. Report uncertainty and event counts in addition to the risk. Risk–coverage curve at 10/25/50/75/90/100% for ranking and deterministic hash baseline, fixing #reused before grading. Any repository split is descriptive and not used to select rules. Report msec and bytes for prefix parsing and tree/blob work, paid direct target searches, per-query vs warm task-sharing accounting, raw output bytes for verification calls, and disclose when baseline recorded counts alone do not cover computation. Seal features and decisions on disk before loading old-label oracle. Preserve source hashes and target snapshot IDs.

Supplementary controlled twins: generate benign text-only trees with identical prior directory names and identical earlier visible lines at the same path. Place a unique literal in a previously unseen sibling file in one member, leaving it absent in the other. Repeat with a completely unchanged *viewed* target file plus a newly added unviewed matching suffix in its counterpart. Confirm ground truth with a paid exact literal search. The witnesses are intentionally identical for these prefixes, giving an identifiability limit, not an estimate of real prevalences. Include a positive control where displayed lines themselves expose the literal. Keep this diagnostic separate from the 147 real searches. No network calls or generated exploit cases.

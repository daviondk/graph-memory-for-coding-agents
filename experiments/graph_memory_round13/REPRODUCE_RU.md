# Воспроизведение тринадцатой серии

Разделы используют разные единицы наблюдения. Для ретроспективного ранжирования это префикс исторической траектории, для вмешательства в выбор чтения — отдельное задание с тремя вариантами подсказки, для оценки контрольного снимка — один эпизод настоящего решателя.

1. Для ранжирования используется [полная инструкция](reformulation/REPRODUCE_RU.md). Команда `python reformulation/verify_archive.py` автономно сверяет прогнозы, метки и исходы в обеих панелях. Отдельный аудит устанавливает, что будущие сообщения можно физически убрать без изменения входа.
2. Для проверки происхождения отрицательного ответа выбрать ту же исходную панель и выполнить этапы фиксации прогнозов, открытия Git-исходов и сопоставления с честной политикой того же покрытия. Условия и цены изложены в [отчёте](provenance/REPORT_RU.md).
3. Для контролируемого выбора чтения использовать первичные входы из reformulation и официальный base из предыдущей серии. Генерация протокола запускается командой `python read_action/experiment.py prepare`, инференс через локальный Qwen3.8-27B UD-Q4_K_M на порту 18952 — `python read_action/experiment.py run`. Затем выполнить `python read_action/experiment.py read` для фактического обращения к старой версии и `python read_action/score.py` для сравнения с исходами. Для переоценки уже проведённого опыта достаточно сохранённых [выборов](read_action/model.jsonl), [фактически открытых файлов](read_action/reads.gz), их контрольных сумм и файлов меток. Новый эксперимент проводится в новом рабочем каталоге. Предсказуемость включения в git-патч является метрикой локализации.
4. Наблюдатель `checkpoints/observe.py` использовался **во время** реальных эпизодов предыдущей серии. Зафиксированная выборка, различные версии патчей и журнал позволяют независимо перепроверить выбор последнего снимка. Отдельный нативный [оценщик](checkpoints/grading/score.py) использует те же образы и тесты, что и [исходный эксперимент](../graph_memory_round12/vibe/grading/README_RU.md). Новая выборка после перезапуска решателя может дать другие снимки. [Протокол отбора](checkpoints/PROTOCOL_RU.md)
5. Полный локальный ZIP проверяется командой `python package_local.py <архив> --verify`. Внутри — манифест SHA-256. Веса, временные среды, Git-сервера и скрытые входы оценщика загружаются отдельно, при необходимости нового прогона. Команды с жёстко заданным корнем D требуют настройки пути на другой машине.

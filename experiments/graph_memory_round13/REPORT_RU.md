# Тринадцатая серия. От подсказки к реальному действию кодового агента

**Локальный Qwen действительно меняет следующее чтение под влиянием графовой памяти. Преимущество перед самостоятельным выбором пока не воспроизвелось в обеих панелях.** В отдельной задаче обнаружено, что решатель создал правильный патч и потерял его при сдаче. Эти эффекты различаются по механизму, поэтому у каждого свой контроль.

| Исследовательский вопрос | Эксперимент и результат |
|---|---|
| Можно ли локализовать следующий полезный файл по малому графу уже увиденных данных? | 870 исторических траекторий в двух непересекающихся по репозиториям панелях. На 191 и 45 префиксах с надёжной Git-меткой граф общих идентификаторов поставил будущий изменённый файл первым в 91 и 28 случаях. Гибрид BM25, давности и области поиска — в 86 и 26. При прогнозе первого наблюдаемого чтения устойчивого преимущества нет. На внешней панели при трёх подсказках граф дал 32 попадания, гибрид — 33. Равномерная центральность дала 90/191 и 29/45, что ставит под вопрос пользу специальных стартовых вершин. [Основной отчёт и абляции](reformulation/REPORT_RU.md) |
| Меняет ли улучшенная выдача выполненное действие? | Три условия на одной и той же задаче и меню, 54 вызова реального инструмента Qwen на 18 разных задачах. При замене лучшего файла плоского гибрида на лучший файл графа Qwen изменил действие в 11/18 пар. Для задач со строгой меткой Git получено 6/8 против 2/8 на основной панели и 3/3 против 2/3 на внешней. Самостоятельный выбор дал 7/8 и 2/3. Различие обоих ранжирований по самому первому файлу возникает лишь в 14/267 и 5/73 всех пригодных префиксов. [Протокол, физические чтения и парные итоги](read_action/REPORT_RU.md) |
| Какие ранее показанные данные помогают решить, доверять ли отрицательной записи из другой рабочей копии? | На 147 ключах из 96 задач исходный Git дал совпадение для 29 ранее пустых результатов. Если сам литерал уже виден в отрывке из подходящей области, проверка всего шести таких записей обнаружила пять расхождений. Ещё 24 она пропустила. При сохранении 110 ответов семантическое ранжирование оставило четыре ошибочных, простое правило по типу пути — семь. При уравнивании покрытия внутри задачи эффект неопределён, а полноценная сверка свидетельств с Git стоит дороже прямого поиска. Внешняя панель не содержала ошибок среди 28 сопоставимых случаев. [Сравнения риска, покрытия и стоимости](provenance/REPORT_RU.md) |
| Что теряется между рабочим деревом и итоговой сдачей? | Четыре эпизода на двух задачах VibeMemBench. Официальная сдача дала 0/4, проверка последнего снимка дала 1/4. В эпизоде flake8 с плоской текстовой памятью прошли 1/1 целевой и все 102 регрессионных теста. У mpmath графовая память также оставила ненулевой снимок, но он не прошёл целевой тест. Правило отбора снимков фиксировалось после двух пустых сдач, которые исключены. [Нативная проверка и границы вывода](checkpoints/REPORT_RU.md) |

**Для дальнейшей работы** приоритетны способы предъявления проверяемых связей. Трудность состоит в том, что модель прислушивается и к ошибочному совету. Нужны условия, различающиеся только содержанием свидетельства, сильный контроль без совета и нейронный ранжировщик на том же наборе файлов. Для хранения состояния перспективна отдельная инженерная метрика — сколько правильных решений доходит до оценщика при фиксированной траектории и цене записи. Достаточность единственного финального снимка должна быть проверена до усложнения памяти. На полном бенчмарке превосходство по числу решённых задач остаётся открытым.

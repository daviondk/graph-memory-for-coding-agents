# Общее правило и обработка отказов

До нового расчёта уточнили поведение текущей реализации. Если ни у одного окна не прогнозируется прироста, три варианта с оценкой новизны воздерживаются от чтения. Поэтому основной режим допускает **до одного** открытия. Чтобы проверить одинаковое число операций, для каждой из трёх стратегий отдельно рассчитываем контроль: при отказе открыть первое окно по глобальному BM25. Первичные сравнения используют авторский общий метод rank_novelty с отказом против bm25 и first_positive с отказом; вторичные сравнения выполняются при обязательном открытии. Сравниваем суммарные расходы, долю отказов и число действительно добавленных символов. Показатели только среди совершённых чтений не подменяют исходы на всех 661 вопросах.

Функция прогнозирует ширину по отношению числа символов к числу видимых WordPiece в выбранном окне, из бюджета 256 вычитается точная стоимость короткого заголовка. Длина исходного поля ограничивает правую границу. Доля новизны — оценочная доля диапазона за пределами объединения уже доставленных координат. Оптимизируем долю, делённую на лексический ранг начиная с единицы. Приоритет при равном балле — лексический ранг и порядок показа. Дешёвый контроль берёт первое лексически упорядоченное окно, где эта доля положительна. Код обоих корпусов общий. [Реализация](../marginal_open/novelty.py)

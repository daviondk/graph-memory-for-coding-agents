# Какой размер фрагмента памяти читать при ограниченном контексте

На независимом корпусе MultiDoc2Dial смешанное чтение восстановило полное обоснование реплики в **444 из 661 диалога (67,17%)**. Чтение только коротких фрагментов дало 403/661, только крупных — 435/661. Перенос с ISETrace подтверждает преимущество над первым контролем. Для сравнения с крупными фрагментами неопределённость включает нулевой эффект. Простая комбинация двух размеров без обученных весов отстала всего на два случая. [Все результаты](results.json)

### Источник и условия эксперимента

В MultiDoc2Dial участники формулировали реплики пользователя и консультанта с опорой на официальные документы четырёх доменов. Из каждого из 661 открытых validation-диалогов заранее заданный хеш выбирал один следующий ход консультанта. Для поиска доступны три предшествующие реплики и все 488 документов, включая документы из других доменов. Фонд содержит 2 075 фрагментов по 256 WordPiece и 7 578 вложенных по 64. Для каждого из 661 вопросов удалось сопоставить авторские аннотации с оригинальными символами без исключений. Аннотации одного ответа во всех случаях относятся к одному документу; всего таких документов 237. Этот корпус проверяет чтение документированной информации в ходе диалога. Его реплики созданы краудсорсингом, их нельзя интерпретировать как журналы автономного программирования. [Статья](https://aclanthology.org/2021.emnlp-main.498/) · [Формат исходных данных](https://doc2dial.github.io/multidoc2dial/data_readme.html)

Поиск одинаков для всех политик. BM25 и квантованный E5-small-v2 ранжируют крупные и короткие фрагменты по всему фонду. Объединяем ранги методом reciprocal rank fusion. Только содержимое отобранных интервалов и их проверяемые адреса попадают в контекст. Общая выдача в каждом случае повторно токенизирована с учётом адресов. Все 3 966 выдач уместились в 2 048 токенов. Хеши исходной разметки, весов и прогнозов позволяют повторить расчёт. Отдельный аудит воспроизвёл те же входы после удаления всех полей с разметкой и всех координат авторских доказательств. [Протокол](PROTOCOL_RU.md) · [Проверка изоляции](blind-audit.json) · [Прогнозы до оценки](forecast-seal.json)

При переносе модели из ISETrace заморожены коэффициенты логистической регрессии, обученной на исходных 3 894 задачах. Девять её входов имеют документные аналоги, включая ранг родителя, локальные лексические признаки, размер и положение блока. Для трёх признаков, связанных с событиями инструментов, подставлены средние из train, что обнуляет их вклад после стандартизации. Поиск по документам меняет распределение рангов. Приоритет короткого фрагмента равен оценке полезности, делённой на фактическую стоимость предъявления этого фрагмента с адресом. Это внешняя проверка переноса весов с оговорённым преобразованием признаков. [Веса и имена признаков](../../graph_memory_round20/fine_train/model.json)

### Результаты при 2 048 токенах

Full Support означает полное покрытие всех эталонных символов в правильном документе. Coverage — покрытая доля эталонных символов. Span Recall — доля целиком предъявленных аннотированных интервалов. В столбце «Документ» учитывается появление любого текста из правильного документа, в том числе при отсутствии самого обоснования.

|---|---:|---:|---:|---:|---:|
| Крупные по рангу, с пропуском неумещающихся | 435/661 · 65,81% | 66,77% | 66,26% | 80,03% | 2 043,9 |
| Только короткие по гибридному рангу | 403/661 · 60,97% | 67,13% | 62,99% | 90,47% | 2 045,5 |
| Два крупных + короткие по гибридному рангу | 442/661 · 66,87% | **70,63%** | 67,80% | 90,32% | 2 045,1 |
| Два крупных + короткие по рангам родителя и текста | 442/661 · 66,87% | 69,85% | 67,55% | 88,80% | 2 045,3 |
| Два крупных + перенесённая оценка на токен | **444/661 · 67,17%** | 68,75% | 67,90% | 85,02% | 2 045,3 |
| Перенесённая оценка на токен, без защиты двух крупных | 438/661 · 66,26% | 67,72% | 66,92% | 84,27% | 2 045,1 |

Полные документы ранжировали по лучшей позиции любого их крупного фрагмента среди всего фонда. Исходный поиск нашёл золотой документ первым в 44,63% случаев и в первых пяти в 77,46%. После упаковки короткие отрывки чаще других политик затрагивают правильный документ. Зачастую они оставляют часть нужного диапазона за границами выдачи. Для каждого вопроса доступны координаты, фактический расход, плотность и F1 по источникам. [Пообъектные прогнозы](predictions.json.gz) · [Пообъектные метрики](per-query-scores.json.gz)

Для заранее заданной семьи из двух проверок совместные 95%-е интервалы Бонферрони составили [−0,52; +3,25] и [+2,12; +10,28] п.п. При кластеризации по 237 эталонным документам значения Holm p равны 0,124 и 0,00110. Разность в двух случаях между смешанными политиками является описательной. На имеющихся данных отдельный вклад обученных весов относительно простого смешанного контроля остаётся открытым. Лучшую Coverage среди шести политик дал добор по гибридному рангу без обученных весов.

### Граница переноса

Эксперимент даёт независимый от ISETrace пример того, что успешный поиск документа и полное чтение его доказательств могут расходиться. В прежних локальных отчётах встречались прогоны SWE-Explore и HotpotQA. MultiDoc2Dial как испытание этих политик в истории проекта не обнаружен. Сопоставление с задачей SWE-Explore учитывает, что её строки кода выводятся из успешных траекторий, а MultiDoc2Dial даёт вручную адресованные доказательства конкретной реплики. В Agent Retrieval Bench базовый эталон относится к файлам. У SWE-QA основные опубликованные критерии измеряют качество сгенерированного ответа. [SWE-Explore](https://arxiv.org/abs/2606.07297) · [Agent Retrieval Bench](https://arxiv.org/abs/2607.24882) · [SWE-QA](https://aclanthology.org/2026.findings-acl.402/)

Для сравнения с результатами авторов MultiDoc2Dial потребовались бы их DPR, разбиение на пассажи, полный набор оцениваемых ходов и их метрика. В этой проверке измерялось качество предъявления фрагментов с фиксированным бюджетом. Один публичный validation split, один энкодер, схожие по тематике документы и отсутствие генерации ограничивают вывод о качестве конечного ответа.

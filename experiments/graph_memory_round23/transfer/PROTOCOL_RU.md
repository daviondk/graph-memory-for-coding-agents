# Перенос способа чтения на диалоги с несколькими документами

План фиксируется до создания прогнозов и вычисления результатов на MultiDoc2Dial. Вопрос исследования — улучшает ли сохранение двух самых высокоранжированных фрагментов с последующим добором мелких блоков по полезности на токен полноту исходного обоснования ответа при том же ограничении контекста.

Используем авторский JSON MultiDoc2Dial v1.0. Весь фонд из 488 документов четырёх доменов одинаков для всех вариантов. Берём validation. До чтения ссылок на доказательства выбираем один следующий ход агента после пользовательского сообщения на диалог с минимальным SHA256 от dialog_id и turn_id, включая утверждения и короткие продолжения. Пустые, неприводимые к исходным координатам или отсутствующие ссылки учитываем в журнале и исключаем из метрик качества с ненулевым знаменателем. Ранжировщик получает не более трёх предыдущих реплик в обратной хронологии, включая последнюю пользовательскую. Не получает домен, ответ, ссылки, идентификатор правильного документа или метки. Поиск по всем четырём доменам. Обучения, подбора параметров и генерации ответа здесь нет.

Токенизатор WordPiece intfloat/e5-small-v2, ревизия ffb93f3bd4047442299a41ebb6fa998a38507c52. Текст каждого документа делится по offset mapping без перекрытия на крупные интервалы по 256 и вложенные интервалы по 64 WordPiece, сохраняя исходные символьные координаты; последний блок допускает остаток. Поиск независимо ранжирует крупные и мелкие блоки по BM25 и косинусному сходству с E5-small-v2, с заголовком документа. Нормализованный mean pooling, официальная CPU INT8 ONNX-модель; одинаковые оценки доступны всем политикам. Комбинация методом reciprocal rank fusion с константой 60 и детерминированным разрешением равных результатов. Отдельный документный ранг — лучшая позиция любого его крупного блока.

При бюджете 2 048 токенов сравниваем крупные блоки по гибридному рангу с пропуском неумещающихся (whole), одни мелкие по гибридному рангу (fine), два защищённых крупных + мелкие по гибридному рангу (two_fine), два защищённых + RRF рангов родителя и блока как в контроле ISETrace (two_rrf), два защищённых + оценка по замороженным коэффициентам fine_train на токен (two_ratio), и тот же последний вариант без защиты (ratio). Для two_rrf берём гибридный ранг родителя и лексический ранг блока. Для замороженной логистики сохраняем оригинальные коэффициенты, средние и стандартные отклонения train ISETrace; переносим ранг родителя, ранг BM25 блока, относительный BM25, долю слов запроса, длину, три позиционных признака внутри документа. Ранг родителя приходит от гибридного поиска, состав слов и набор кандидатов меняются. Три неприменимых к текстам признака (tool-output, противоположная роль, расстояние до события) заменяются их средними на ISETrace, то есть имеют нулевой вклад после стандартизации. Знаменатель two_ratio и ratio — фактическая стоимость интервала с адресом, в признаке log_cost — число токенов его исходного текста. Получаем перенос параметров с явно заданным отображением домена и пропущенными признаками. Это отдельная проверка после смены представления, которая не воспроизводит нативный граф ISETrace. Корпус найден поиском по литературе до просмотра результатов; по доступным локальным отчётам и исходникам предыдущего такого прогона нет.

Все методы получают один кап и формат содержимого, оплачивая видимый текст с адресами; считаем точный токенизатор по всей выдаче, без добавления специальных токенов и общего промпта. Уникальные адреса исходного текста, без перекрытия. Фиксируем индивидуальные выбранные адреса, хеш и точную стоимость итогового текста; доказательства доступны оценщику только после SHA всех прогнозов.

Первичная метрика Full Support@2048 — доля вопросов, где предъявлены все символы объединения аннотированных источников в правильных документах. Две парные гипотезы two_ratio против whole и fine. Двусторонняя поправка Holm на эти два контраста, SE с кластеризацией по диалогу, поскольку отобран один вопрос на диалог. Дополнительно кластеризация по идентичным наборам эталонных документов для проверки чувствительности, учитывая общие документы. Доверительные интервалы 95% и консервативные совместные интервалы для двух проверок. Описательно — покрытие эталонных символов, density, F1, касание всех золотых документов, Recall по целиком покрытым аннотированным spans, расход, top-1/5 по исходным документам, дополнительные варианты. Публикация измеряет DPR и качество генерации в иных единицах; прямое сравнение с таблицей лидеров или с живым агентом требует соответствующего полного протокола.

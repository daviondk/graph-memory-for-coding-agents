# Сравнение с опубликованным VerbatimRAG ModernBERT v2

Проверено условное чтение истории ISETrace. Каждому методу доступны одни и те же 16 верхних исходных узлов Dense-FT, вопрос и лимит 2048 токенов E5. В выборке 192 различных траектории, по одному вопросу на каждую. Ревизия опубликованной модели — 6a967332, 150 млн параметров. Использованы авторский process, реальные строки и точные координаты. Fine обучен на ISETrace train. Первичный парный контраст fine минус Verbatim с общим ядром составил **14,58 п. п. (95% ДИ 8,33 … 20,83)** по полному покрытию. Fine выиграл 34 пар и проиграл 6, точное двустороннее p = 8,36e-06. Доверительные интервалы получены парным bootstrap по траекториям. При одинаковом горизонте потолок достижимого полного покрытия составляет 90,6%, если передать все доступные интервалы без ограничения длины. [Все метрики и интервалы](test-results.json) · [построчные результаты](test-outcomes.json.gz)

В дополнительной проверке каждому контролю выдан индивидуальный бюджет, равный фактической длине Verbatim с ядром. При этом fine достиг 64,6%, Verbatim 65,1%, целые узлы 64,1%. Разность fine минус Verbatim -0,52 п. п. (95% ДИ -5,73 … 4,69). Средние фактические затраты составили 962,9, 978,2 и 933,2 токенов соответственно. Точный предел расходов одинаков внутри каждой пары, её участники могут использовать разное число оставшихся токенов. [Протокол одинаковых индивидуальных лимитов](EQUAL_SPEND_RU.md) · [результаты](test-equal-spend-results.json)

Классификатор обработал 3072 пар «вопрос, узел» на двух потоках CPU. Наиболее длинная пара содержала 761 токенов ModernBERT при окне 8192. Понадобилось свыше одного окна для 0 пар. При пороге 0,2 хотя бы один фрагмент выделен в 776 узлах, при 0,1 — в 1018. Для исходного порога измеренное время всех вызовов process на вопрос составило 7,43 с по медиане и 12,42 с по p95. Это время CPU в условиях соседних работ и одновременной тренировки на GPU. [Подписанные прогнозы и версии библиотек](test-seal.json)

Оценки относятся к поиску точных символьных свидетельств при известных кандидатах. Порог, гранулярность фрагментов, защищённое ядро и степень заполнения доступного контекста влияют на покрытие. Здесь нет оценки действий решателя, распределение тестовых объектов отличается от выборки по всем вопросам, а fine имеет доменное обучение. Опубликованный Word-F1 отмечает частичное совпадение слов на другом корпусе. Эти условия определяют границы сравнения. [Статья](https://arxiv.org/abs/2605.21102) · [независимая проверка](verify.py)

При общем потолке fine расходует почти вдвое больше токенов, чем Verbatim с ядром. После выравнивания допустимых затрат на каждом вопросе оценка разности полного покрытия меняет знак, а доверительный интервал включает ноль. Такой результат указывает на вклад длины выдачи в исходное сравнение. Индивидуальный лимит задаёт сам экстрактор, поэтому это сравнение относится к распределению выбранных им длин. Для вывода об эквивалентности методов понадобилась бы отдельно заданная граница практически значимого различия.

## Измеренная стоимость на общей панели

На 24 одинаковых входах у трёх читателей проверены совпадения SHA текста с основными результатами. В 144 вызовах после прогрева медиана/p95 для целых узлов 36,88/54,65 мс, для fine 162,07/284,19 мс, для Verbatim с ядром 8924,49/14118,79 мс. На уровне запросов медианное отношение Verbatim/fine 58,25× (диапазон 35,83–115,60×). В интервал включены вычисления читателя и повторная токенизация выдачи.

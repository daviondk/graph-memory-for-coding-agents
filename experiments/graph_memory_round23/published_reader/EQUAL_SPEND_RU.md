# Чувствительность к фактической длине выдачи

Дополнительное сравнение фиксируется после четырёх dev-проверок и до открытия тестовых оценок. Для каждого запроса берётся число реально прочитанных токенов исходного Verbatim с общим ядром и порогом 0,2. Это доступная без эталонных интервалов величина. В тех же 16 узлах пересобираются два контроля — целые узлы по порядку Dense-FT и защищённое ядро с блоками по замороженному fine. Порядок, правило вычитания перекрытия, переводы строк и токенизация совпадают с основной оценкой. Для всех трёх максимальный бюджет теперь индивидуальный, равный длине опубликованного экстрактора. Пропуск неделимого фрагмента может оставить остаток бюджета у контролей, поэтому публикуется также разность фактических затрат. Контроли должны физически укладываться в каждый индивидуальный бюджет. Этот условный контраст измеряет выбор содержания при доступной экстрактору длине, его величина зависит от распределения собственных запросов и объёмов выделения. Сравнения вторичные, без выбора порога или стратификации по ответам.

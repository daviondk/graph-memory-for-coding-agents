# Как повторить

Веса находятся вне репозитория в D:/CodexResearch/x20-published-reader/model. Семь файлов фиксирует plan.json, SHA-256 model.safetensors — 3127f7ead12786b4ab740191105d8a8e0febe6f8109e479ea0c1e9238fd79398. Для новой машины файл fetch_model.py загружает именно указанную ревизию. Исходное дерево экспериментов включает R18, R19, R20 и R22 с официальным списком 580 dev и 2000 test. На машине с подготовленными проекциями достаточно следующего запуска.

```powershell
$python='D:/CodexResearch/x20-isetrace-e5-gpu/venv/Scripts/python.exe'
& $python -B fetch_model.py
pwsh -NoProfile -File ./run.ps1
& $python -B equal_spend.py test
& $python -B verify.py dev test
& $python -B report.py
```

Очередь использует CPU, один экземпляр защищён именованной блокировкой. Прогноз каждого вопроса записывается атомарно и проверяется перед продолжением после прерывания. На этапе dev первый запуск остановился при сортировке смеси list и tuple в объединении интервалов. Исправление до получения первого прогноза приводит пары координат к единому типу. Второй dev-запуск завершился на всей фиксированной выборке. При первой подготовке дополнительной проверки одинакового бюджета имя «score» совпало с импортом старого модуля. Проверка теперь загружает scorer по точному пути. Код и критерии обеих тестовых оценок зафиксированы до открытия тестовых оценок. [Фиксация основного анализа](analysis-lock.json) · [фиксация равных бюджетов](equal-spend-plan.json)

Портативная численная проверка использует исходный split и gold из дерева результатов, подписанные прогнозы и построчные оценки. Для повторной токенизации буквального исходного текста требуются открытые исходные данные ISETrace и подготовленные проекции на диске D. При перерасчёте в новом каталоге время CPU и сжатые файлы, содержащие времена, могут иметь другие контрольные суммы. [Исходные данные и протокол](https://arxiv.org/abs/2609.25913)

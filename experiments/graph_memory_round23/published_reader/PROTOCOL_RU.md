# Проверка опубликованного экстрактора на истории инструментов

Вопрос исследования — в какой степени замена правила чтения на опубликованный экстрактор меняет полноту покрытия адресуемых свидетельств при одинаковом доступе к истории и лимите контекста. Все методы получают вопрос и первые 16 узлов одного Dense-FT ранжировщика ISETrace, обученного с seed 13. Для первичного теста выбираются 192 различных траектории из официальных 1207. Сортировка траекторий по SHA-256 от «r23-verbatim-traj-v1|test|ID», затем внутри каждой выбирается один запрос по SHA-256 от «r23-verbatim-query-v1|test|ID». Единица оценки — траектория с одним равновероятным по хешу вопросом. Доля запросов среди всех 2000 имеет другой знаменатель. Для проверки реализации выбираются четыре траектории из первых 500 dev по той же схеме с меткой dev. До открытия эталонных интервалов фиксируются манифест модели, состав выборки, версии программ и прогнозы всех методов.

Первичный показатель — доля вопросов с полным покрытием эталонных интервалов при бюджете 2048 токенов E5. Вторичные показатели — покрытая доля эталонных символов, плотность свидетельств, их гармоническое среднее, фактическая длина, число пустых выдач, число прочитанных узлов и время извлечения на CPU. Парный интервал — процентильный bootstrap по 192 траекториям, 10 000 повторов, seed 13. Дополнительно показываются дискордантные пары и точный двусторонний McNemar для первичного сравнения. Единственный первичный контраст — fine минус Verbatim с общим защищённым ядром и порогом 0,2. Остальные — диагностические.

В конечный текст входят дословные отрезки исходных полей и переводы строк между ними. Текст полностью токенизируется после добавления каждого фрагмента. Если затраты превышают 2048, фрагмент пропускается. Все методы используют одинаковую функцию объединения уже показанных символов внутри одного адреса и одинаковую функцию подсчёта цены. Каждое новое предложение вычитает перекрывающиеся старые интервалы и добавляет остаток в исходном порядке. После выбора первых 16 все варианты видят одинаковые исходные подстроки без предварительного усечения.

1. Простое чтение выбирает целые исходные узлы в порядке Dense-FT. Блоковый контроль сохраняет первые два узла и дополняет их исходными блоками в порядке лучшего родителя.
2. Fine сохраняет те же два узла. Используются замороженные коэффициенты учившегося на 3894 train-вопросах R20 fine-reader. Фон BM25, геометрия, ранги родителей и множество блоков пересчитываются в общем пуле 16, блок должен целиком принадлежать хотя бы одному родителю. Затем применяются баллы вероятности, делённой на стоимость блока. Это перенос весов при суженном горизонте.
3. VerbatimRAG ModernBERT v2 получает вопрос и исходный текст каждого из тех же узлов. Используется опубликованный метод process с порогом 0,2, минимумом 30 символов, зазором 20, окном 8192, перекрытием 256. Основной сопоставимый вариант сохраняет первые два целых узла, затем располагает найденные интервалы по убыванию вероятности, рангу родителя и началу отрезка. Вариант без ядра показывает эффект самого экстрактора. Дополнительный вариант после ядра и выделенных интервалов тратит остаток бюджета на целые исходные узлы. Вторичная чувствительность использует опубликованную конфигурацию коротких ответов с порогом 0,1 и минимумом 10 символов.
4. Перед публикацией оценок проверяются координаты по точным подстрокам, число входных токенов и число скользящих окон. Верхняя граница покрытия по 16 узлам вычисляется после фиксации прогнозов.

Исследование измеряет перенос опубликованного модуля на фиксированное чтение памяти ISETrace. Оценка качества совершения действий и соответствие данным другой публикации требуют отдельных опытов. Срез повторно использует тест ранее исследованного семейства методов и служит проверкой нового сравнения.

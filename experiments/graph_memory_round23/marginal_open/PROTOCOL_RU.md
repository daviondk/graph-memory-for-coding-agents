# Следующее чтение с сохранением ранее полученного контекста

Ретроспективная проверка R23 показала, что выигрыш от выбора поля может сокращаться, если предыдущая память остаётся доступной. Фиксируем новую политику до вычисления её исходов. Используем все 2 000 вопросов ISETrace из 1 207 траекторий. Они уже использовались для формирования гипотезы. Одинаковый вход каждому методу — реально оплаченная объединённая выдача `ratio/merged` до 2 048 токенов основного R-GCN без content.next seed 13, текст запроса и метаданные длины полей в символах. Вторая операция имеет лимит до 256 токенов с включённым в него заголовком адреса. Для этой задачи единица «символ» — кодовая точка Python.

Разбиваем каждый видимый отрывок на последовательные окна по 128 WordPiece отдельно. Для окна i поля f с координатами [l,u), n WordPiece и ценой открывающего заголовка hᵢ оценка правой границы — rᵢ=min(Lf, l+floor(max(0,256−hᵢ)·(u−l)/n)). При n=0 используется один символ на токен. Заголовок `[field:start] ` токенизируется отдельно без специальных токенов. Видимая часть поля задаётся объединением уже предъявленных интервалов V_f. Оценка новизны — длина [l,rᵢ) вне V_f, делённая на rᵢ−l; пустой прогноз даёт ноль. При выборе неизвестный текст поля недоступен. Длины фиксируются один раз в каталоге; размер и цена его построения указываются. Фактическая длина и новизна проверяются после исполнения выбранного чтения.

Основная политика максимизирует оценку новизны, делённую на 1 плюс нулевой ранг BM25. Выше ставится меньший лексический ранг, затем меньший индекс видимого окна. Ненулевые рациональные величины сравниваются точно. BM25 по одним и тем же видимым окнам использует k₁=1,2, b=0,75, положительный IDF и детерминированное разрешение равенства в порядке предъявления. Четыре контроля — первое предъявленное окно, глобальный BM25, первое окно BM25 с положительной новизной и максимальная новизна с разрешением равенства по появлению. Для трёх методов с учётом новизны нулевая новизна всех кандидатов означает отказ от вызова. Первые два при наличии окна делают ровно один вызов. Все бюджеты и порядок разрешения равенств зафиксированы до открытия gold.

Первично сравниваем Full Support объединения первоначально предъявленных источников и одного результата чтения у основной политики против глобального BM25. Главный сильный контроль — первое BM25-окно с положительной новизной. Для обоих контрастов показываем парные выигрыши и потери, ДИ по 10 000 bootstrap исходных траекторий и совместный интервал для двух сравнений. Вторичные — Coverage объединения, Full Support внутри одного tool output, число действительно добавленных уникальных символов, добавленное покрытие эталона, число нулевых и пустых открытий, отказы и фактически прочитанные токены. Вычислительная цена выбора и хранение длин отчётны отдельно от token budget. Оценщик получает разметку после публикации хешей действий и реально открытых диапазонов. Дальнейшая внешняя проверка возможна с тем же переносимым чистым модулем.

# Контроль одинаковых фактических затрат

После основного анализа фиксируем дополнительную проверку для трёх пар: rank_novelty с bm25, rank_novelty с first_positive, first_positive с bm25. Ранее выбранные адреса и предыдущие 2 048 токенов сохраняются. Для каждого запроса два ответа получают меньший из двух фактических бюджетов открытий, включая заголовок. Если хотя бы один метод отказался, обе стороны пропускают вызов. Каждую сокращённую строку ретокенизируем. Если реальная цена различается, уменьшаем общий лимит до меньшего достигнутого и повторяем. Если заголовок перестал помещаться, обе стороны пропускают вызов. Проверяем строгое равенство по всем 2 000 вопросам и каждой паре. Измеряем Full Support объединения, парные выигрыши и потери, среднюю цену. Симметричный лимит использует уже известные длины двух ответов. Это ретроспективный тест чувствительности.

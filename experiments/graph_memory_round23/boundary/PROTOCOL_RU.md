# Проверка влияния границы исходной записи

В исследовании одного чтения поиск координаты внутри первого поля давал положительный эффект на ISETrace и отрицательную точечную оценку на MultiDoc2Dial. У BM25 отличалось и среднее число возвращённых токенов. Проверяем на уже известном ISETrace, изменится ли вывод, если разрешить дополнить короткий конец поля контекстом слева. Это разведочный анализ механизма, запланированный после внешнего переноса.

Фиксируем все 2 000 вопросов и прежний выбор двух адресов для объединённого смешанного представления. Отправленное сообщение, id поля, точка начала, выбранная читателем, и лимит открытия в 256 WordPiece с заголовком постоянны. Если чтение дошло до конца поля при расходе менее 256, рассматриваем точки начала среди 264 последних WordPiece исходной строки, а для короткой строки также нулевое смещение. В порядке возрастания позиции выбираем первую точку раньше выбранной, с которой весь суффикс до конца, включая фактический адрес, помещается в лимит. Если такой точки нет, оставляем прежний ответ. Изначально выбранный текст сохраняется целиком; дополнение ограничено тем же полем. Изменение начала отражается в адресе сообщения. Токенизация содержит реальные WordPiece и Unicode-символы. Исследуем один выбранный запрос к источнику, дополнительных решений агента не требуется.

Оцениваем полное покрытие за одно чтение и средние токены. До открытия эталонов фиксируем два парных сравнения: разность между BM25 внутри первого поля и первой координатой при дополнении дo границы; изменение этой разности относительно прежнего режима. Одновременный 95% ДИ кластеризуем по траектории. Дополнительно считаем реальные изменения адресов, а также число ранее коротких чтений, которые могли получить дополнительный текст. Общий лимит у читателей одинаков, длина отдельных полей может быть меньше лимита.

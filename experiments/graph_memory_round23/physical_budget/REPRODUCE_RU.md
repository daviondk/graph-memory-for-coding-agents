# Воспроизведение физического эксперимента

Публичная фикстура состоит из числовых оценок, координат, размеров и упорядоченного эталона при 2 048 токенах. Тексты запросов, произвольный текст действий агента и контрольные точки LLM для проверки оператора не требуются. Воспроизводимая единица — один вопрос на исходную траекторию. Хеши и первичные сырые записи находятся в MANIFEST_SHA256.json. Команды следует выполнять в каталоге исследования.

Быстрая независимая проверка требует Python 3.11+ и NumPy. Она строит базу в оперативной памяти, проверяет каждый из 4 608 изменённых выходов, восстанавливает курсорные счётчики и сверяет их с опубликованными тремя повторностями. Повторный расчёт доверительных интервалов выполняет analyze.py.

```powershell
python -B audit.py
python -B analyze.py
```

Для собственного измерения создайте копию каталога и новое значение PACK_BUDGET_HOME на нужном диске. Промежуточные БД с COMMIT оставляются для аудита. Размер всех частных файлов в исследовании — несколько сотен МиБ. Финальная контрольная сумма бинарной библиотеки C++ зависит от ОС и компилятора. В данном эксперименте использовались MinGW g++ 16.1 и sqlite3.dll версии 3.50.4 из среды Python 3.12. Параметры сборки зафиксированы в native-build.json.

```powershell
$env:PACK_BUDGET_HOME='D:/CodexResearch/physical-budget-new-trial'
python -B edge_cases.py
python -B bench.py build
python -B bench.py static
python -B bench.py dynamic
python -B bench.py durability
python -B first_access.py
python -B commit_pairs.py
python -B native.py
python -B analyze.py
python -B audit.py --write
python -B report.py
```

Подготовка фикстуры из неизменённых данных ISETrace, если имеются оригинальные рабочие кеши, выполняется отдельно командами `python -B prepare.py plan` и `python -B prepare.py build`. После этого план и состав SHA-выборки сверяются с опубликованными. Каждый физический сценарий стартует из общего исходного состояния. Основная серия откатывает тестовую мутацию вне измеренного интервала, а исследование долговременной записи измеряет настоящие COMMIT с синхронизацией.

Поля dynamic-rep — номер повтора, номер траектории, бюджет, тип правки, алгоритм, фактическая ветвь, число физически изменённых исходных строк, наносекунды правки, наносекунды обработки кеша, число строк из курсора, переданные байты тела, записанные байты тела, изменение кешированной структуры, изменение идентификаторов выдачи. Байты кеша относятся к пользовательскому BLOB и отличаются от физических страниц журнала. Поля нативного таймера и признаки страничного кеша перечислены в native-check.json. Хеши выходных последовательностей содержатся в outcome-hashes.json.gz.

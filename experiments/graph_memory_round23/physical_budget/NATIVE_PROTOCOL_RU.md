# Нативная проверка физического оператора

Добавлена после первичных Python-измерений. Проверяем, сохраняется ли выигрыш при чтении SQLite через C API и компактном бинарном представлении кеша. На тех же 192 разных траекториях и при том же бюджете 2 048 сравниваем четыре правила. Полная инвалидизация стримит покрывающий индекс и условно заменяет закешированный ответ одним SQL UPDATE. Размер тела ответа составляет 32 байта на выбранный блок. Простой контроль проверяет только остаток токенов перед изменёнными элементами и при сомнении пересобирает выдачу полностью. Второй контроль учитывает также перекрытие исходных интервалов и затем всё равно пересобирает ответ. Полный кандидат переиспользует достоверный префикс при неудаче проверки. Все используют один и тот же формат кеша и один B-tree.

Измеряем семь повторов в перемешанном порядке для одного случайного, одного ранее выбранного, восьми, 32 и всех изменённых баллов. Запись самих баллов, чтение/восстановление кеша и его условное обновление входят в нативный таймер. Начальное открытие соединения, откат фикстуры и переход через Python FFI измеряются отдельно или исключены. Каждая выдача и порядок блоков должны совпасть с независимым полным расчётом. Счётчики VM, попаданий/промахов SQLite и строк индексного курсора сохраняются. Для первичного сравнения повторяем тот же парный bootstrap по 192 траекториям с медианой повторов внутри вопроса. Простая проверка остатка и проверка перекрытий — дополнительные сравнения, мотивированные результатами первичного эксперимента.

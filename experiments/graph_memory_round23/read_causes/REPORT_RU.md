# Что теряется при чтении коротких фрагментов

На полном публичном test ISETrace (2 000 вопросов, 1 207 траекторий) сравнили две стратегии поверх одного замороженного ранжирования R-GCN. Первая добирает целые блоки до бюджета, вторая оставляет первые два целиком и добирает 64-токенные фрагменты по отношению предсказанной полезности к стоимости. Фиксируем списки, реально сериализуем выдачу каждой стратегии, сокращаем до лимита тем же токенизатором и смотрим, что получит читатель. Адрес включает номер поля в пределах истории и начальную позицию в символах. Каталог из 72 184 полей занимает 14 782 464 байта в SQLite. Каждый из четырёх тысяч исходов без адреса совпал с R22 по расходу, покрытию и Full Support.

**Два заранее заданных сравнения.** При коротких адресах выигрыш мелких фрагментов по полному покрытию составил 1,65 п.п., 112 парных выигрышей и 79 потерь. Одновременный 95% ДИ по двум сравнениям [0,11; 3,19] п.п. При том же мелкозернистом отборе объединение смежных диапазонов дало +15,10 п.п. по доле вопросов с целыми цитатами, одновременный 95% ДИ [13,30; 16,90], 302 выигрыша и 0 потерь. Из прибавки 302 лишь 17 составил чистый прирост вопросов с полным покрытием. Остальная разница в агрегированных показателях объясняется 285 вопросами, для которых раздельная выдача уже содержала все символы, разбросанные по отрывкам. Подробные попарные исходы позволяют отличить чистый прирост от числа переходов. Единица повторной выборки — траектория. **Чем объясняются прежние 114 выигрышей и 70 потерь.** В 71 из 114 выигрышных случаев стратегия целых блоков полностью пропустила хотя бы одно нужное поле, ещё в 38 поле было, но нужный интервал не пересекался с выдачей, в 5 цитата была частичной. Среди 70 проигрышей мелких блоков в 53 случаях часть цитаты отрезана, в 15 нужное поле показано в другом месте, в 2 поле полностью пропущено. Для классификации нескольких цитат брали худший исход. Это точная декомпозиция двух фиксированных выдач. [Матрица переходов](results.json)

**Когда эффект меняет знак.** При записи полного идентификатора события и JSON Pointer мелкие блоки проиграли целым по полному покрытию 155 вопросов. При усечении короткой адресной выдачи до 512 токенов мелкие фрагменты покрыли 969 вопросов против 1 004, а при 1 024 — 1 293 против 1 317. Эти два среза используют список, составленный под 2 048. Оптимальную политику для самостоятельного бюджета 512 или 1 024 предстоит проверить отдельно. Вариант, который разрешает пропустить до восьми пробельных символов между отрывками одного поля, дал те же числа полных попаданий на всех трёх бюджетах.

**Интерпретация.** Если два пересекающихся или смежных отрывка одного поля объединить, любой вложенный в их объединение непрерывный интервал можно скопировать из одной записи. Поэтому рост по целостности частично следует из определения метрики. Возможный содержательный выигрыш измеряет полное покрытие под реальным лимитом, а пригодность для последующих действий — отдельная [проверка однократного чтения](../address_open/REPORT_RU.md). Для полного бюджета объединение изменяет число оплачиваемых адресов, повторяющиеся символы и порядок отрывков до усечения. Этот опыт измеряет их совместное влияние. Индексы истории использованы как внешний каталог, цена его хранения указана выше. Текстовые префиксы — подсказки читателю, проверяемая машинная адресация использует структурированные координаты. Измерены одна конфигурация ранжирования и уже известная публичная выборка. Вывод об ответах LLM или превосходстве над опубликованными системами требует других сравнений.

# Воспроизведение двенадцатой серии

Исходные скрипты, заполненные журналы и результаты разделены по шести опытам. Для чтения результатов достаточно развернуть архив. Команда `python package_local.py --help` описывает независимую проверку ZIP и его внутреннего манифеста. Для новых запусков использовать отдельный рабочий каталог без старых файлов запуска и сначала скопировать исходники. Для нового получения наблюдений понадобятся указанные исходники, исторические версии библиотек и доступ к опубликованным данным. Некоторые скрипты используют пути рабочей станции на D. При переносе следует сначала настроить эти корни. Распаковка архива сама по себе не устанавливает внешние среды.

| Опыт | Ресурсы и порядок | Проверяемый результат |
|---|---|---|
| Запросы к исходникам | Правила выбора, исходные логи Vibe, SHA репозиториев и команды в [пошаговой инструкции](negative_external/REPRODUCE_RU.md). Запустить извлечение наблюдений, проверку деревьев и пакетные измерения. | [Две независимые проверки и манифест](negative_external/verification.json) |
| Точный критерий изменения пустого ответа | Git и Python. Запустить `python predicate/git_probe.py` с тем же корнем данных. | [Таблица конечного перебора и реальные Git-переходы](predicate/results.json) |
| Повторное использование в траектории | Python, публичные истории, результаты предыдущего извлечения. Скрипты `subsumption/replay.py` и `subsumption/replication/scope.py` имеют пофазные интерфейсы. Сначала зафиксировать прогнозы, затем читать следующие события и сопоставлять ответы. | [Первая панель](subsumption/REPORT_RU.md) · [Правило для второй панели](subsumption/replication/PROTOCOL_RU.md) |
| Обновляемый граф тестовых зависимостей | Воспроизвести нативные запуски NetworkX, собрать записи, затем сравнивать представления по одной и той же матрице запросов. | [Команды и версии](dynamic_graph/REPRODUCE_RU.md) · [Проверка](dynamic_graph/verification.json) |
| DreamBench-SWE и метаданные пакетов | Публичный пакет и условия описаны в [отчёте](dreambench/README_RU.md). Артефакты исходных дистрибутивов и wheel на PyPI проверяются по SHA. Запуски внешнего публичного кода отделены от нашей оценки по полям. | [Проверка публичного релиза](dreambench/release-verification.json) · [Индивидуальные прогнозы](dreambench/predictions.gz) |
| Два задания VibeMemBench с действующим решателем | Восстановить указанные в [протоколе](vibe/PROTOCOL_RU.md) ревизии, Qwen GGUF, Python-окружение mini-swe-agent, исходный JSON истории и два Docker-образа по digest. Сначала рассчитать память через `vibe/memory.py`, сверить assignment-lock. Запустить `vibe/start_server.ps1`, proxy из `vibe/seed_proxy.py` и `vibe/run.py` на свободных локальных портах. Пути для среды WSL и Docker берутся из run.py. После завершения применить официальный оценщик согласно [инструкции к grader](vibe/grading/README_RU.md) и выполнить `python vibe/summarize.py`. | [Записанные шесть условий](vibe/order.json) · [Нативная оценка и контрольные патчи](vibe/grading/REPORT_RU.md) · [Телеметрия](vibe/requests.jsonl) |

Служебные pid, номер порта и аппаратные интервалы измерения относятся к сохранённому прогону. Воспроизводимость вывода LLM на другом GPU или версии серверного ПО проверяется новым парным запуском. Для ревизий с одними и теми же ссылками на commit имеются отдельные SHA входных данных и результатов. В архивацию не входят веса, слои контейнеров и полный тестовый датасет.

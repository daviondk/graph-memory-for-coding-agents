# Двенадцатая серия. Когда агенту стоит использовать сохранённое наблюдение

Можно ли переносить ранее пустой поиск через изменение кода, стоит ли сохранять такой ответ в ожидании следующего запроса и в каком виде доставлять историю действующему решателю. Дополнительно измеряли цену обновления графа тестовых зависимостей и сравнивали перенос факта из истории с прямым чтением текущего источника.

## Публичный бенчмарк с действующим решателем

Два новых задания VibeMemBench прошли через одинаковый mini-swe-agent и локальный Qwen3.8-27B UD-Q4_K_M. Условия — чистый контекст, две исторические выдачи BM25 либо связи между наблюдениями из тех же выдач. Выборка составлена из двух небольших Python-проектов до чтения исходов. Для положительного и отрицательного контролей оценщика использованы рабочий эталонный патч и безвредное добавление маркера. [Дизайн до запусков](vibe/PROTOCOL_RU.md) · [Результаты по конкретным тестам](vibe/grading/REPORT_RU.md)

Все три условия дали 0/2 официально решённых задач. Из шести сдач пять были пустыми после лимита в 24 обращения. В единственном непустом патче не прошёл целевой тест flake8-comprehensions и перестал проходить один из 102 регрессионных тестов. Контрольные патчи дали ожидаемый результат в 4/4 случаях. Затраты составили 144 запроса модели. [Работа с памятью, полные затраты и исходы](vibe/REPORT_RU.md)

## Вывод для следующей серии

На естественных траекториях почти нет подтверждённого спроса на прежний пустой ответ в проверенной грамматике. Для следующего эксперимента важнее другое последствие этого же события — выбор файла или инструмента сразу после промаха. Его можно проверить на наблюдаемом следующем действии и отдельно на независимом результате Git. Для записи о состоянии по-прежнему открыта проблема идентификации рабочего дерева, особенно при незакоммиченных правках и нескольких сессиях. При сравнении скорости необходимо включать готовые возможности базы данных и Git, стоимость построения памяти, затраты на запись и промахи сильных плоских контролей.

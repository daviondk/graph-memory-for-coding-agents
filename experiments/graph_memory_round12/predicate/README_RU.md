# Критерий актуальности отрицательного текстового поиска

Память хранит подтверждённый факт: в известной версии дерева в фиксированной области не было ни одной строки с литералом q. Версии обозначим T₀, T₁. Для нового или перенесённого в область файла берём все его строки в T₁. Для файла, остающегося в области, берём новые стороны вставок и замен в полном построчном diff. Удаления из области дают пустой вклад. Объединение полученных строк обозначим A.

**Утверждение.** При прежнем пустом результате новый поиск положителен тогда и только тогда, когда какая-либо строка A содержит q. Если в дереве T₁ совпадение есть, оно либо попало в область вместе с файлом, либо возникло в изменившейся строке. Неизменённая строка файла, уже входившего в область, дала бы совпадение и в T₀, что противоречит исходному наблюдению. Обратно, каждая строка A действительно присутствует в выбранной области T₁. Наличие одинаковых строк в нескольких местах, а также конкретное допустимое выравнивание diff доказательство не меняют. При известном **непустом** исходном результате одно добавление, как и удаление одного из нескольких совпадений, в общем случае требует других правил.

Разбор опирается на обычные отслеживаемые файлы, совпадающие правила области и регистра, однострочный непустой буквальный ключ и точную версию. Генераторы, переменные окружения, файлы вне Git, исключения ripgrep, ошибки команды и условия, зависящие от соседних строк, требуют дополнительных оснований. При запросе к существованию файла и при запросе к его содержимому действуют разные семантики. Реализация рассматривает перенос как удаление и добавление, разбирает нуль-разделённые имена, читает настоящий postimage blob для добавленных путей и использует различие blob-объектов для изменённых. Привязка к снимку может принимать форму хеша дерева или эквивалентного идентификатора рабочей области с учётом локальных правок.

Из 64 переходов выбрано восемь типов, включая создание, удаление, перенос области, копию, изменения текста и режима. Истину установил git grep -F на обеих версиях; ещё один прямой подсчёт сделан по байтам нового дерева. Извлечение общих дельт для 64 переходов вызвало Git 104 раза и передало в Python 11 436 байт stdout. Сравнивать время пакетного прохода с 1 040 **отдельными** процессами grep как ускорение системы было бы некорректно. Реальное сравнение с пакетными командами выполнено отдельно на VibeMemBench. Скрипт конечного перебора и контролируемые примеры доказывают реализационную границу, их частоты не характеризуют работу человека или агента.

# При каких условиях можно точно обновить запись «поиск был пуст»

Фиксируем до измерения. Для известного отрицательного результата проверяем детерминированный алгоритм обновления по содержимому добавленных строк Git. Запрос означает существование буквальной последовательности байтов в пределах одной строки обычного файла внутри фиксированного пути. Метрика — корректность факта «существует совпадение», а также число пробуждённых запросов, лишних пробуждений и пропущенных изменений. Предположения: известны обе неизменяемые версии и полный список изменённых путей, тот же фильтр путей, та же семантика регистра, нет неизвестных файлов рабочего дерева. Некорректная команда, недоступный каталог и подтверждённое отсутствие — разные состояния.

Предусмотрены создание файла, удаление, копия, перенос в область или из неё, смена исполнимого бита, одинаковые строки, усечённые окончания, строки с плюсами и скобками, пробелы в пути. Первое испытание — конечное пространство всех пар маленьких файловых деревьев с заранее заданным алфавитом; сравнение с полным прямым вычислением. Второе — минимум 48 контролируемых переходов в настоящем Git-репозитории, разные предикаты и области, состояние измеряется независимым git grep -F. Сравниваем старый ответ навсегда, фильтр изменённых путей, наивное чтение только + строк при обнаружении rename (может пропустить перенос неизменившегося файла в новую область), политику с обработкой членства пути и полный новый поиск. Отдельно проверяем отказ для неподдерживаемых запросов. При серии запросов к одному переходу цена получения diff или новых blob должна начисляться хотя бы один раз; показываем как общую стоимость, так и фактически просмотренные байты и вызовы Git. Не утверждаем уменьшения времени на основании одних байтов.

Это формальная и контролируемая проверка корректности. Эмпирическую частоту полезных обновлений измеряют на независимых журналах реальных агентов. Сравнение с redo/Tup относится к известному принципу регистрации отсутствия, git pickaxe — публичный ближайший механизм. Сгенерированные состояния не заменяют проверку на публичных историях.

# Дополнительная оценка амортизации на реальных группах запросов

Зафиксирована после одиночной оценки качества и до замера пакетных методов. Группа — уникальная тройка (репозиторий, действительный первый родитель merge, merge SHA). В расчёт входят все исходно отобранные прямые хронологические пары, включая пары с нулём допущенных наблюдений. Правила допуска те же, что в основном анализе: предшествующий свидетель рабочего каталога, два согласованных exit=1, отсутствие старого совпадения в Git. Каждой группе передаём ровно столько запросов, сколько осталось по её собственным наблюдениям. Сравниваем одинаковый выход — новое бинарное состояние каждого ключа.

1. Прямые git grep объединяются по одинаковым области, флагам и include. Одиночный запрос использует -q, несколько запросов в одной области — множественные -e. Полные строки штатного grep раскрывают все сработавшие литералы, включая перекрывающиеся. Токенизация вывода, доставка в Python и поиск каждого ключа в выданных строках входят в полную стоимость.
2. Список изменённых файлов можно получить один раз на группу и перепроверить только совпадающие области с тем же пакетным grep.
3. Список обновлённых строк можно получить одним git diff -U0 по объединению областей. Добавленные строки связываем с реальным путём файла и проверяем ключи только этой области. Оцениваем непосредственный бинарный ответ и более осторожный вариант с повторной проверкой каждым сработавшим запросом через общий пакетный grep.
4. Стандартный git diff -G с кэшем уникальных запросов исполняется для каждого различающегося литерала/области с сохранением соответствия ключу. Его бинарный ответ и вариант с обязательным подтверждением истинных результатов сравниваются с (3) в том же режиме.

Считаем число групп 0, 1, 2 и более ключей, реально сэкономленные Git-вызовы, обработанные байты и wall-clock на группу/всю выборку. Для нулевой группы все методы немедленно возвращают пустой ответ. Случайный порядок условий фиксирован, три повтора, локальный прогретый файловый кэш и один процесс измерения. Никакого увеличения числа записей для замера экономии и искусственной нагрузки. Если подход даёт ускорение только на малом множестве, сообщаем результат этой группы и всей выборки. Происхождение временных колебаний и стоимость подготовки Git-репозитория указываются отдельно.

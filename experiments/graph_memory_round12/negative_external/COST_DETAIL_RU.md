До чтения замеров времени выделяем две группы без подбора порога. Если в имени переданной области есть обычное расширение файла и отсутствует фильтр имён, сравниваем запрос как ограниченный путём к файлу. Все остальные запросы образуют группу поиска по области. Как дополнительный descriptive контроль времени рассматриваем правило «ищи непосредственно в явном файле, иначе используй стандартный git diff -G + необходимый поиск», варианты уже запущены в одинаковом случайном порядке. Маршрутизация определяется только входным аргументом, не требует списка репозитория или новых результатов. Время такого правила складывается из экспериментально измеренных ветвей, это оценка, а не отдельный реальный запуск комбинированного диспетчера. Для закрытого бинарного вопроса отдельно сообщаем стоимость вычисления одного изменения; если нужны конкретные строки результата, требуется их новое чтение и используем основной результат. Для полноты проверяем, не объясняется ли разница данными отдельных репозиториев.

# Внешняя проверка устаревания пустых поисков по исходному коду

До извлечения поисковых исходов и чтения исправлений фиксируется одна серия. Берём всю опубликованную историю VibeMemBench по заранее выбранным научным и аналитическим Python-репозиториям, отсутствующим в R11. Репозитории — alteryx/woodwork, bashtage/arch, codezonediitj/pydatastructs, CS-SI/eodag, fatiando/harmonica, hdmf-dev/hdmf, mpmath/mpmath, NeurodataWithoutBorders/pynwb, pandas-dev/pandas, PennyLaneAI/pennylane, pybamm-team/PyBaMM, pyccel/pyccel, pyqtgraph/pyqtgraph, Qiskit/qiskit-terra, sdv-dev/RDT, stac-utils/pystac, xgcm/xgcm. Отбираются все доступные истории, явно посвящённые обычным задачам науки и инфраструктуры библиотек. При явных терминах, указывающих на уязвимость, описание задачи исключается до анализа действий. История используется как корпус действий, официальный score VibeMemBench за решение задач здесь не вычисляется.

**Наблюдение.** Только реальный вызов bash с одним однозначно сопоставленным tool_call_id. У grep, rg или git grep обе записи численного exit должны равняться 1 (структура extra и отображённый <returncode>), обе версии stdout должны быть пустыми, исключения нет. Команды с exit 0, 2 и выше, диагностикой, неявным stdin, условными обработчиками, составными конвейерами, неизвестными путями и сложными выражениями считаются отдельно. Область — рабочее дерево /testbed или явно объявленный каталог репозитория, относительные пути допустимы только при подтверждённом cwd. Поддерживаются простые пути, опции отображения, рекурсия, ignore-case, whole-word и простые include-фильтры. Основной слой — один безопасно интерпретируемый однострочный буквальный текст. Регулярные выражения с якорями, границами или метасимволами, многострочные шаблоны, gitignore, нетекстовые и генерируемые файлы указываются в ограничениях. Следующий/прошлый контекст при выводе не меняет бинарного ответа. Дедуплицируем одинаковую семантическую операцию в каждой задаче. При более чем 96 допустимых задачах берём первые 96 задач по кругу репозиториев, внутри каждого упорядочивая по SHA256 строк R12-explicit-absence|instance_id. В выбранных задачах берём все подходящие запросы. Доступные ключи и состав отбора фиксируются до оценки.

**Пара ревизий.** Для задачи устанавливаем оригинальный base_commit из публичного SWE-rebench-V2 и конечный SHA исторического merged PR. Главная панель требует соответствия исходной версии первому родителю merge и зафиксированного хронологического порядка; если base — иной предок, отдельно оценивается именно первый родитель→merge с подтверждением старого отсутствия, метки различаются. При неизвестной или непроверяемой связи исходы не подменяются. На старом и новом дереве проверяем наличие совпадения по всем обычным отслеживаемым текстовым файлам соответствующей области. Если на исходном дереве область не существует или находит значение, отмечаем несовпадение и исключаем из знаменателя основного сравнения. Для Git-совместимой семантики фиксируем режим игнорирования, бинарные файлы и сопоставление аргументов. Нет искусственных добавлений строк.

**Сравнение на тех же ключах.** Сохранить прошлое значение; всегда выполнить поиск; проверять область при изменении пути; сверять целевой литерал с добавленными строками изменившихся файлов области (переименование через delete/add); нативный контроль Git с поиском по изменениям, где сопоставим. При обращении к обеим версиям в качестве верхней границы — прямой независимый Git-поиск. Все политики получают одинаковые поиск, репозиторий и его версии. При учёте бесплатного внешнего change feed явно отделяем этот режим от режима, когда список изменений/дифф надо получить и его стоимость оплачивается. Сравниваем число перепроверок, пропущенные изменения, ложные срабатывания, сырые байты, размеры памяти, время с касанием локальных Git-объектов. Цвет, оформление, обучающие веса, Docker и inference исключены. Порядок измерений стоимости перемешиваем фиксированным seed, сообщаем число повторов и режим файлового кэша; измерение без сравнимых условий остаётся явно отдельным. Проверяем вклад стоимости получения diff на тот же запрос/задачу и сравниваем с прямым чтением. Статистическая единица — механизмы изменения и задачи/репозитории, а не каждая строка диффа.

**Проверки.** Отмечаем наличие повторных реальных обращений, несовпадение рабочей копии и коммита, Git-ренеймы, отдельные неподдержанные типы запросов. Не утверждаем достигнутое ускорение работ агента, если тестируется только валидность результата инструмента. Публикуем нулевые результаты, диапазон применимости и все знаменатели. Если обнаружено мало случаев, сохраняем исходную панель. Любые последующие расширения описываются явно отдельно до их исходов.

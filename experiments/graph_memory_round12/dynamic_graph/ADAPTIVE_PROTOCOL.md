# Old-only representation choice per refreshed test

Exploratory hypothesis formed after seeing that GCS loses primarily on one module at 64 bytes. Give each fixed test slot one paid byte for a layout discriminator. Compare four identically charged alternatives: forced Bloom, forced Golomb-coded filter, select lower predicted false-positive probability, and a write-sensitive choice. For Bloom use observed 1-bit fraction to the selected power k, for GCS use distinct codes divided by its paid hash domain. Calculations use the current row only. For the write-sensitive policy, if either candidate's old-only predicted false-positive probability is at most 1%, choose among all meeting that target by the smallest actual price of changing the previous slot into the proposed slot (secondary key risk, stable tie to Bloom). If neither meets target, choose minimum risk, with actual patch size as tiebreaker. This is an engineering threshold, not learned from queries. Always compare to both fixed alternatives at same cost, plus the frozen full-capacity untagged baselines. These adaptive rules are exploratory engineering decisions inspired by the prior test, not a fresh validation. Run both budgets, four salts and complete streams without historical replay (unconditional replace). Seal all states before scoring.

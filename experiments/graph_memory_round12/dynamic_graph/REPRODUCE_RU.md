# Как воспроизвести R12

В архиве находятся все первичные данные: результаты коллекции тестов, версии и содержимое наблюдавшихся трасс, потоки событий, прошедшие и исключённые идентификаторы, контрольные суммы, двоичные входные журналы, состояния по шагам и ответы на каждое имя. Коллекция NetworkX проводилась Python 3.11.15 / pytest 7.4.4, код сравнения — Python 3.12.13 / NumPy 2.5.5. Нужен CPU. Целевой каталог D:/CodexResearch/x20-bench-workspace/work/graph_memory_round12/dynamic_graph. Родственная папка graph_memory_round10/multiset содержит закреплённые неизменные реализации reader.py, structures.py и common.py. Из корневой папки R12 доступны относительные пути ко всем небольшим артефактам.

**Проверка готовых артефактов** — python verify12.py. Она использует сохранённые нативные трассы, сверяет исходные состояния и независимым подсчётом проверяет основные метрики обеих версий. Все файлы с их SHA-256 перечислены в MANIFEST_SHA256.json. Крупная папка vendor с распакованными колёсами восстановима из release_lock.json и wide/release.json. Каталоги __pycache__ исключаются. Код не производит Git-записей или внешних отправок.

Для полной пересборки используйте чистую копию с исходниками и протоколами R12 и указанной папкой R10. В уже закрытом каталоге построитель проверяет наличие квитанции состояния и останавливается, чтобы не перезаписать сохранённый выпуск. Команды коллекции используют интерпретатор с pytest. На Windows для воспроизводимости задайте переменную окружения PYTHONHASHSEED=0 заранее.

    python acquire.py
    python collect.py 3.4.2 list
    python collect.py 3.5 list
    python collect.py roster
    python collect.py 3.4.2 run
    python collect.py 3.5 run
    python collect.py 3.5 repeat

Стадии построения и чтения запускаются отдельно. Для пропуска повторной коллекции можно использовать три включённых файла trace/repeat, списки коллекции, roster.json, release_lock.json, а acquire.py по-прежнему необходим для вычисления изменённых AST из опубликованных исходников.

    python prepare.py
    python write.py
    python dictionary.py
    python read.py
    python grade12.py
    python gcs.py
    python patches.py
    python cpu.py
    python adaptive.py
    python adaptive_eval.py
    python accounting.py
    python wider_native.py
    python wider_replay.py
    python verify12.py

В wider_native.py переменная PY указывает на локальный интерпретатор коллекции pytest. На другой машине замените её эквивалентным интерпретатором либо позвольте скрипту выбрать его по переменной окружения, предварительно адаптировав локальную копию. Для проверки уже упакованного результата этот путь не используется. Первичный коэффициент записи вычисляет accounting.py по числу байт исходного текстового представления изменённых рёбер. Значение оценивается на всю фазу замен, а не как среднее частных с нулевыми знаменателями.

Каталог archive/ содержит 4-байтовую длину и последовательные JSON массивы строк UTF-8, по одному на запуск. states/, exact_states/, gcs_states/ и adaptive_states/ содержат байтовое представление в base64 для всех шагов. predictions/, gcs_reads.json.gz и adaptive_reads.json.gz содержат маски тестов. Для основного core они хранятся в порядке массива keys из соответствующего predictions-файла. Представление каждой строки states — номер шага, фаза, байты на тест, соль, включение проверки одинаковой строки, метод, байты состояния, изменённые участки, прочитанные старые записи и дополнительные счётчики. Архивы JSON с gzip используются для доставки, учёт вычисляется по байтам payload. В wide/ лежит отдельная репликация первой серии с 2.8.8. В ней сохранены результаты тех же детерминированных методов, четыре соли и оба варианта подавления повторной записи. Дополнительно оплаченные кодеки GCS и адаптивный выбор исследовались только на основной панели. Итоговые исследовательские документы не требуют подписок, API, GPU или весов модели.

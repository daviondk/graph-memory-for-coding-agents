# Supplementary membership and write-granularity controls

The simple per-test Bloom arm needs a strong published alternative for independent small set storage. After observing the primary comparison, freeze a second independent per-test index based on the sorted Golomb-coded membership set of BIP 158. Use the identical old-only row replacement, fixed slot size and same active/digest gate as column Bloom. At build time hash distinct observed keys, scale each first 32-bit project hash into a fixed interval of size N·2^p, sort the values, encode successive gaps using unary quotients with p-bit remainders, pay the header, and select the highest fitting p among 0–23. Store N and p. A single slot that fails even p=0 conservatively matches any symbol. This is a membership/data-layout adaptation of a known algorithm (different hash and parameter selection), not a new primitive. Evaluate unmodified probes and same code revisions. Compare FP by module, time including cold lookup, and paid row replacement costs. 

For every existing primary arm and this control, reconstruct an optional validated on-wire binary patch to transform the previous resident image into the next image. Choose the smaller of whole-image replacement and variable-length-coded offset/gap + length + replacement bytes for all changed runs; include the mode byte. Merge unchanged gaps up to a fixed two bytes, an old-vs-new only engineering policy. Growing/shrinking exact dictionary images carry the new length. Report mean and per-module patch sizes on replacement phase, archive replay separately, separately from 4KiB touched pages. Measure the 64-byte and 4KiB pages genuinely dirtied by byte-level patching. A deterministic no-change needs zero writes; same rule for all arms. These are logical transfer sizes and do not include filesystem metadata, fsync, granularity of external storage, interruption journals, endurance or actual WAL device writes.

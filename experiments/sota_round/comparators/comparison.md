# Independent benchmark evidence, 16 November 2026

## LongMemEval-S

Use the author's cleaned September 2025 S file, HF revision `98d7416c24c778c2fee6e6f3006e7a073259d48f`, file SHA-256 `d6f21ea9d60a0d56f34a05b609c79c88a451d2ae03597821ea3d5a9678c3a442`. This revision comprises 500 questions. The original evaluator excludes 30 abstentions from retrieval. Score all 500 on QA, and report abstention separately if desired. Strict all@5 gives a question one point when the prefix of length five contains every gold session. Any@5 gives one point for one or more gold sessions. Mean evidence fraction averages the proportion of each question's gold sessions retrieved. Three questions require six distinct sessions, capping strict all@5 at 467/470. The original public repository supplies an evaluator and BM25, Contriever, Stella and GTE baselines. Its README and directory tree do not identify an official V1 leaderboard with verified submissions. [Official dataset](https://huggingface.co/datasets/xiaowu0162/longmemeval-cleaned/tree/98d7416c24c778c2fee6e6f3006e7a073259d48f) · [Official benchmark and skip rule](https://github.com/xiaowu0162/LongMemEval/tree/9e0b455f4ef0e2ab8f2e582289761153549043fc) · [Official scoring code](https://github.com/xiaowu0162/LongMemEval/blob/9e0b455f4ef0e2ab8f2e582289761153549043fc/src/retrieval/eval_utils.py)

Our standard-library replay joins question IDs to ground truth from the pinned full S split, computes prefix membership after truncation, checks that returned session IDs belong to the corresponding haystack, and recounts the four released QA judge log files. Per-question observations and task breakdowns are retained. These measurements replay existing outputs. They required zero API calls. Upstream retrieval and grading incurred separate expenses.

**Reader-input audit.** The published Papr routine reads raw cleaned JSON and sends `json.dumps(ss)` in its default JSON mode. The upstream generator removes `has_answer` annotations before serializing. We counted 896 true and 10,064 false such annotations in the cleaned file. Consequently the published Papr code path exposes evidence annotations if run with its documented input/default format. Archived answers and grades alone cannot establish which fields a historical private call saw or its effect. Papr's released reranking digest instead constructs text from the date, turn contents and any optional fact cache available. The full provenance/coverage of those optional fact cache files is unavailable at the pin. Preserve this distinction when assessing an independent reranker that inherits frozen Papr rankings. ## Executable coding tasks and an official leaderboard

VibeMemBench contains 111 targets from 90 repositories and 3,634 historical trajectories, selected for demonstrated usefulness of a frozen prior under a reference solver. Four seeds per target produce 444 trials per arm. Published MemoryOS with GLM-5 yields 57.0% resolved versus 55.0% with memory off. Its paired improvement of 2.0 points has interval [−3.38, +7.43]. That is the only positive pairing out of twelve ordinary retrieval systems/solvers. DeepSeek-V4-Pro with SimpleMem yields 66.9% versus 67.1% memory-off. Kimi-K2.7-Code with SimpleMem yields 69.6% versus 69.8%. Existing matched controls and the frozen prior, identical tools and seed rosters, and the external executable `FAIL_TO_PASS` and `PASS_TO_PASS` tests should anchor a repair claim. Solver compute alone runs into roughly 1.5–2.5M input tokens per trial, excluding memory setup and sandbox cost. Extraction and retrieval proxies cannot establish this endpoint. [Paper, Tables 1–2](https://arxiv.org/abs/2609.23570) · [Official harness](https://github.com/AlibabaResearch/DAMO-ConvAI/tree/faf754671f5b850e1b4d1ff870db37a6a2480df6/VibeMemBench) · [Official dataset](https://huggingface.co/datasets/Tongyi-ConvAI/VibeMemBench/tree/11164976b4f920cdb0d0cd570ca572e49acea1e8)

MemDev-Bench contains 555 base issues and 4,869 earlier tasks. The main controlled test compares 133 improvement and 50 preservation cases under three history regimes. On 133 improvement tasks, Claude-Mem achieves 41.6/40.1/42.6% resolved for relevant/noisy/repository histories, against 35.3% for no memory. FullTraj gives 39.1/37.3/39.6%, often with fewer steps and substantially more input. In a separate 150-task relevant-history roster, causal-memory leads the 29-system single-run comparison at 52.67%, with 6.18M input tokens, 56.50k outputs and 186.35 steps/task. NoMem averages 47.78±1.54% over three runs, 5.92M inputs, 54.78k outputs and 176.93 steps. This is a suitable real comparator on its stated roster; the result does not establish a reliable separation of the closely grouped leading systems. [Authors' report, Tables 2, 9 and 10](https://arxiv.org/abs/2610.27524) · [causal-memory provider repository](https://github.com/JingxuanC/causal-memory/tree/b05d671fc45d1f73c99c36a58f05c0bdd673cb88)

LongMemEval-V2 supplies an actual official leaderboard submission path for a different benchmark. Its queries concern experiences in web and enterprise trajectories. Each submission combines full paired domain runs for one tier, with latency/accuracy relative to a fixed reference frontier (LAFS). The official baseline is AgentRunbook-C/R or a released RAG configuration; the shipped example uses a fixed Qwen3.5-9B reader, Qwen3-Embedding-8B, and default GPT-5.2 judge. An S-split score cannot be submitted as that metric. [Official implementation](https://github.com/xiaowu0162/LongMemEval-V2/tree/2cc8c540bdb87fe6761629b585e727e1c4704520) · [Submission requirements](https://github.com/xiaowu0162/LongMemEval-V2/blob/2cc8c540bdb87fe6761629b585e727e1c4704520/leaderboard/README.md)

## Novelty and cost

Score fusion, support diversity and choosing a budgeted set have substantial precedent. Reciprocal rank fusion combines ranked runs, and maximal marginal relevance balances relevance against redundancy. In personal agent memory, AgentMemRec explicitly formalizes selection as a request-dependent slate, uses candidate generation and learning to rank, and measures completeness of multi-session evidence. Its experiments compare several strong memorizers and rerankers. Chen and Cheng separately studied blind, pre-query retention on LongMemEval with learned multifactor utility and show that future-query input greatly changes retention. GreedyDual-Size already combines fetch cost, size and locality for cache decisions. A new policy needs an accurately scoped novelty claim and measured advantage against these families at equal budget. [RRF](https://doi.org/10.1145/1571941.1572114) · [MMR](https://www.cs.cmu.edu/afs/cs/Web/People/jgc/publication/MMR_DiversityBased_Reranking_SIGIR_1998.pdf) · [AgentMemRec](https://arxiv.org/abs/2610.34673) · [Blind retention](https://arxiv.org/abs/2606.12945) · [GreedyDual-Size](https://pages.cs.wisc.edu/~cao/papers/gd-size.html)

Rank improvements on public reused questions, in a frozen upstream top-20 and under dialogue-only session labels, cannot verify cross-task coding memory, QA, blind write/evict performance, or an official leaderboard placing. Accumulate reader input/output, ingestion requests, reranker queries, search latency and stored bytes separately. Additional filtering over frozen public ranks may cost zero new API calls but inherits all upstream inference. Run a label-sanitized matched reader and evaluator to measure QA, and pair executable agents with no-memory, raw history and published memory controls to measure repairs.

## Replay and provenance

Run `python rescore.py` in this directory using the retained inputs, or `python rescore.py --download` to refetch and hash the official dataset, rebuild scoring metadata and pull commit-pinned comparator inputs. The script writes `recount.json` and `recount_per_question.csv`. Development inspection covered primary repositories, author reports and the official datasets as of 16 November 2026. Search expressions included LongMemEval-S plus strict/all-evidence/recall_all@5, the evidence denominator and possible numerators, as well as retrieval/QA rankings and competing dataset names. These searches bound the comparison to identified artifacts and leave unreported or inaccessible systems outside the ranking.

We then executed the benchmark authors’ unmodified `evaluate_retrieval` with NumPy 1.26.4 and verified row-wise agreement for both retrieval indicators at every measured cutoff on all 5,170 method/question/cutoff combinations. We also executed the unmodified `print_qa_metrics.py` four times on the released judge logs. `official_verification.json` retains scorer SHA, version and printed QA metrics. Reproduce with `uv run --python 3.12 --with numpy==1.26.4 python -X utf8 verify_official.py` after the recount. This verifies scoring and artifact integrity; it does not repeat inference or judge calls.

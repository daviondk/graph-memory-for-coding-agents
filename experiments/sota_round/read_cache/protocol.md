# Strictly prequential caching of shell read results

Question: when an ongoing agent reissues the identical literal read command, how often can a memory of an earlier observation replace execution without replaying stale bytes? Falsification: our concrete-path invalidation earns no advantage over a fixed short lifetime or a global flush if correct reuse is lower at equal observed stale counts, or a higher stale risk is needed for gains. We report all policies, even if no cache can meet the strict safety target.

Corpus: the same 2,470 original histories and SHA-256 hashes at Tongyi-ConvAI/VibeMemBench 11164976b4f920cdb0d0cd570ca572e49acea1e8. Process one trajectory at a time and reset all caches at boundaries. Single CPU process, no model calls, no source command execution, no filesystem snapshot or repo index, no goals, outcomes, reasoning or gold patches. All policies watch the same issued actions and original subsequent trajectory. Candidate queries are conservatively parsed straightforward cat, numeric sed -n line/range p, head, tail, wc, grep and rg reads of exactly one explicit regular-file-looking path; limited literal read-only output filters permitted. Admit only absolute operands or relative operands after an explicit single absolute cd joined by &&. Exclude globs, script bodies, special files, redirections, relative or ambient cwd, executable transforms, and unclassifiable commands. Anchors are string paths; hardlinks, symlinks and external writers are unobservable. Full literal command text including flags and spelling is the key. Each assistant decision can submit multiple commands. Only a batch of entirely read-only operations may return or fill any cache; a mixed/opaque batch invalidates as appropriate before later decisions. No sharing of information within a batch.

All six bounded arms use the same allowlist, output admissibility, key, admitted observations, LRU size limit of 32 records and 262,144 bytes for command key, concrete path, UTF-8 result and return code; each retained result must fit 16,384 bytes. Policies are exact-LRU with no explicit invalidation, global flush on any possible write, TTL at 1, 3 and 10 assistant decisions from the actual fill, and selective path invalidation. Include an unbounded number-of-records/exact-string comparator with same 16 KiB per-output cap; report separately from equal-cap arms. Global flush discards on every possibly mutating command, independent of exit result. Selective tracks only the actual remembered path: discard it when a known target path equals, contains or is beneath a declared concrete write, removal or move; clear all for command substitution, a script, ambiguous destinations, standalone cd, or any unclassified mutation. Starting with a read-only cd prefix serves only as an explicit path resolution scope for that invocation. An exact repeat answers even an earlier nonzero observation if admitted.

Decide serve/miss before reading results. On hit never refresh cached stdout or fill age from the now-hidden original observation; on miss the historical observed response may fill. Other commands' original behavior is held fixed in this offline replay. Recency used for eviction is touched by hits. Correct reuse requires identical exit code and byte-for-byte UTF-8 recorded combined process output (extra.raw_output); fallback only to contents of an intact standard output wrapper, preserving whitespace exactly. On writes refuse truncated, ambiguous, oversized or otherwise unrecorded outputs. On scoring a known full raw result can witness a later truncation; missing/incomplete observations are explicitly unscorable. No UUID, time, progress-line, whitespace, ANSI or path normalization. Agent-visible head/tail truncation is logged; data cannot establish true device stdout beyond recorded combined text or unobserved process side effects.

Report all detected reads, eligible all-read batches/queries, repetition count, fill/miss/eviction reasons, correct, stale and unscorable hits, observed stale rate per hit, mean and peak bytes, and exact calls avoided per 1,000 eligible queries. Primary joint comparison versus global flush on paired shared decisions (correct and stale per 1,000); also contrast every bounded control and unbounded reference. Strict operational comparison among policies with zero observed stale and zero unscorable serves; show maximal correct reuse under this criterion, or state none. If counts differ, do not relabel a lower rate as equal safety. Quantify the nonzero error trade-off without choosing a post hoc threshold. Bootstrap complete repositories (all 90, 10,000 resamples, seed 20261116) for paired differences. Avoided invocations are a counterfactual count under fixed historical requests, not measured elapsed time, task success, GPU savings, or lower reader tokens. Archive all candidate decisions for all arms and branch ledgers for every batch, source hashes, exact code, protocol and lock before scoring.

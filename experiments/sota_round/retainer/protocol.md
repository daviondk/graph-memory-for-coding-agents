# Frozen MSR experiment

The target is the expected number of aligned 16 KiB backing reads per original range request for a cache of 512 4 KiB pages. Three secondary endpoints are page misses, the proportion of original ranges served entirely from cache, and the share requiring at most one backing read. Source addresses, request sizes and their order are observed. The 4/16 KiB geometry, cache sizes, and read-only projection are our overlay. They are not benchmark ground truth. Reads within each range are assumed to check current residency before filling only explicitly demanded missing pages. Reading a backing block counts once per original request. Cross-request prefetch of neighboring pages is disabled for everyone. No payload values, wall time, physical-device latency, agent decisions, or QA outcomes are inferred.

Select the first 32,768 genuine Read operations from volume 0 of every server in the cacheMon distribution of the original MSR Cambridge CSVs (all 13 servers). Ignore writes. Each trace has exactly 8,192 fit, 8,192 validation and 16,384 held-out consecutive reads. No reordering. For final fitting use the first half; evaluation uses only the later half. Treat servers, not individual requests, as comparison units and report all individual paired results, equal-server mean, paired 95% percentile bootstrap over 13 servers with seed 327816 and 10,000 draws. Convenience sampling from a single data center makes the interval descriptive. Sensitivities at 128 and 2,048 pages, with no success threshold. Report all frozen comparisons regardless of outcome.

At each capacity compare the joint exact empirical objective with static strongest-page frequency, whole aligned backing blocks by touched-request count, online LRU, and the authors' S3-FIFO default Python implementation (cacheMon, pinned). Static decisions use the historical half, dynamic methods warm up on every warmup request, continue through the test, and can admit and evict pages. All get identical trace and payload capacity; counters, ghost IDs, training/replaying and one-time pin writes cost extra. Record the number of unique backing blocks needed to prefill fixed pins as a conservative extra charge per run.

At the primary 512-page budget also allow a hybrid with fixed candidate pin fractions 0, 1/2 and 1. Pin sets use either joint or marginal fit; remaining pages use online S3-FIFO. Fit-only pin sets are evaluated on validation, with the dynamic part warmed by the fit stream. Choose the lowest grouped backing reads on validation, breaking ties in favor of fewer pins. Refit pins on the historical half and warm dynamic pages on that half. Compare the validation-selected joint hybrid to S3-FIFO and the identically selected marginal hybrid. Report the fixed 1/2 arms as ablations. A pure dynamic cache and a policy that fills all pages once are both permitted. Pin fraction fitting requires historical counters and dynamic replay; no test-time updating of pin sets. Primary mechanism contrast is joint static versus static marginal at 512. The selected hybrid versus S3-FIFO is the operational contrast.

Separate native anchor: use the complete cacheMon preprocessed msr_hm_0.oracleGeneral.zst trace, respecting released object order and equal-size cache format. Evaluate S3-FIFO and LRU from empty at 10% of distinct objects, reporting full-stream object miss ratio. Also compare frozen static 4-page-group joint versus marginal on the later half **only if original numeric locality is checkable**; otherwise keep this anchor strictly conventional. Seek to execute current S4-FIFO original implementation alongside reference baselines with released inference if technically possible. Record native trace record count, fixed object size if present and capacities. Never compare native numbers directly with range-protocol figures. Describe differences from the published authors' fleet-wide experiment. No parameter fitting to published numbers.

Unchanged external(s), raw-data locators and checksums, forecast-only selection, source-prefix metadata, reproducible code and page/group miss logs must be supplied. An implementation fix needed for reproducible verification must be recorded; never inspect test outcomes when selecting methods and budgets above.

# Совместная стоимость чтения на производственных обращениях MSR Cambridge

При сохранении 512 страниц на следующих 212 992 запросах 13 серверов совместное планирование потребовало **1,87185** чтения на запрос против **1,90166** при сохранении самых частых страниц. Средняя экономия составила **0,02981**, или **1,57%**, с парным 95% бутстреп-интервалом по серверам **0,00945–0,05568**. В десяти томах потребовалось меньше чтений, в двух столько же, в одном больше. Опубликованные адаптивные алгоритмы дали **1,86402** для S3-FIFO и **1,87123** для S4-FIFO с выпущенным авторами компактным предиктором. Преимущество совместного планирования перед ними не подтвердилось.

## Проверка на исходном эксперименте авторов

Мы собрали ревизию артефакта SOSP 2023 и запустили её программу cachesim на всех **3 993 316 обращениях** к 439 187 различным объектам из hm_0. Использовали тот же бюджет 43 918 объектов и обычную долю промахов с единичным размером объекта. На этом томе три значения воспроизвелись до опубликованного знака. Были записаны стандартный вывод программы и каждый промах в отложенной части. У статических правил первые 20% обращений служили историей построения. Доля промахов на всей трассе для них не определялась, поскольку её первые ответы использовались бы для выбора кэша. Во внутренней валидации на втором дециле варианты с 0, 21 959 и 43 918 закреплёнными местами дали соответственно 78 040, 78 792 и 89 040 промахов. Поэтому выбранный гибрид совпал с самостоятельной Python-реализацией авторов S3-FIFO. Версии S3-FIFO различаются реализацией и параметрами очередей. Результаты каждой сохранены отдельно. Стандартная задача охватывает исходную последовательность операций чтения и записи и сводит каждый запрос к одному идентификатору. Совместная выгода сохранения нескольких полей в этой метрике отсутствует по построению.

## Что изменено для проверки групповых чтений

Из каждого из 13 серверов взят том 0 и его первые 32 768 настоящих запросов Read. Никакие синтетические обращения в выборку не добавлялись. У каждого исходного запроса сохранялись порядок и реальный диапазон байтов. Данные собраны Microsoft в одном центре в феврале 2007 года. По четверти последовательности отведено на начальное обучение и валидацию. После выбора доли закрепления использовалась вся первая половина. Вторая половина, 16 384 запроса на том, была отложена для оценки. Записи исключены. Ни одно тестовое обращение не участвует в оптимизации статического содержимого. [Описание исходных томов и формата](https://github.com/cacheMon/cache_dataset/blob/1e53a27824a406b10948699d5eba4c40def90c11/README.md#msr-cambridge-traces) · [Работа поставщика трасс](https://www.usenix.org/legacy/event/fast08/tech/full_papers/narayanan/narayanan.pdf).

В нашем интерфейсе место в памяти занимает страница 4 КиБ. Один вызов хранилища получает выровненный блок 16 КиБ. Если запросу нужны несколько отсутствующих страниц одного блока, вызов требуется один раз. Между запросами разрешён приём только явно затребованных страниц, предвыборка выключена. Реальные операции устройства, время ожидания, стоимость обучения, метаданные очередей, байты запросов к языковой модели и качество текстовых ответов не измерялись. При сравнении учитывается одинаковая ёмкость для полезных данных и отдельно приводится цена начальной загрузки закреплённых страниц.

Для блока b подсчитывается число учебных запросов каждого из 15 непустых подмножеств его четырёх страниц. Доход от сохранённого подмножества S равен числу запросов, которым в b достаточно страниц S. По лучшим вариантам для 0–4 мест на блок точная динамическая программа делит общий бюджет между блоками. Частотный контроль оптимизирует число попаданий отдельных страниц, контроль целыми блоками закрепляет наиболее востребованные блоки целиком. Оба имеют тот же объём и ту же историю. Содержание фиксированных политик в тесте постоянно. LRU, S3 и S4 используют последующие запросы для обычной замены содержимого. Гибрид оставляет им незакреплённую часть. Статические метаданные и офлайн-время поиска не ограничены бюджетом полезных страниц.

Для разовой загрузки каждого исходного блока с закреплёнными страницами отнесён один дополнительный вызов, распределённый на 16 384 тестовых задания. Это консервативная верхняя оценка цены загрузки уже наблюдённых страниц. Если данные оставались доступны при построении, платить отдельно за них может не потребоваться. Динамические методы прогреваются на той же наблюдавшейся истории. Таблица не приписывает экономии времени CPU или денег, потому что формирование закреплений, переигрывание истории и хранение счётчиков также имеют цену.

При 128 страницах экономия совместного метода относительно статической частоты равна 0,00346 чтения на запрос, при 2 048 — 0,05166. В основном бюджете статический joint даёт на 0,00782 чтения больше S3-FIFO (интервал для S3 минус joint от −0,05493 до +0,03237). Для S4 минус joint разность −0,00062 (−0,05378…+0,04564). Гибрид с выбранной долей дал относительно S4 экономию 0,00266 (−0,03422…+0,03088). Минимальное среднее у заранее заданной половинной схемы в колонке без загрузки не доказывает, что заранее удастся выбрать этот вариант или что выигрыш окупит его создание. Интервалы построены по 13 серверам, по 10 000 парных повторных выборок. Они описывают разброс между этими томами одного центра.

## Вся исходная неделя hm_0

Независимый по горизонту тест использовал реальные длины из полного CSV. Из всех 3 993 316 операций в нём **1 417 748** чтений. Граница по количеству разделила поток на обучение и проверку по **708 874** чтения. При 512 страницах среднее число чтений блоков в тесте составило **1,07083** у совместного метода, **1,07394** у частотного, **1,06237** у S4, **1,05936** у S3 из современного симулятора и **1,07033** у LRU. Тест и набор из 13 префиксов используют один и тот же том hm_0, поэтому их нельзя считать независимыми экземплярами. Год сбора, домен хранения и заданный контракт чтения ограничивают перенос результата на память языковых агентов.

## Версии алгоритмов и проверка источников

Артефакт S4-FIFO содержит оригинальный симулятор и пять заголовков с деревьями LightGBM в отдельном подмодуле CacheLib. Обычный CLI симулятора регистрирует признаки, а отправка признаков в модель предусмотрена внешним интерфейсом. Наш адаптер передаёт полные 20-интервальные гистограммы и счётчики в выпущенную функцию lightGBMPredict. Один раз на границе обучения он применяет возвращённые пять параметров с сохранением текущих элементов. Двенадцать из 13 томов получили предсказанную конфигурацию. Для src1_0 функция оставила параметры по умолчанию, поскольку при сборе признаков было лишь одно попадание. Для полного объектного запуска модель выставила 5% малой очереди, объём призрачной очереди в три ёмкости кэша и порог продвижения 2. Интеграция двух выпущенных подмодулей и конкретный момент переключения описаны в native_protocol.md. В тренировочном перечне авторов указан hm_0, поэтому оценки относятся к известному предобученной модели домену. [Артефакт S4-FIFO](https://github.com/cacheMon/osdi26-s4-fifo/tree/000095fc3c96a95ff1b9a19d101fb1411c7f4d54) · [Список обучения](https://github.com/cacheMon/osdi26-s4-fifo/blob/000095fc3c96a95ff1b9a19d101fb1411c7f4d54/analysis/train_traces.txt).

В OSL-MR v6 авторы оценивают последовательное удержание диалогов LoCoMo и LongMemEval при ограничении токенов. В проверенных HTML и исходном архиве arXiv нет реализации и закэшированных пометок DeepSeek. Поисковые запросы к GitHub и содержимое архивов зарегистрированы в availability.json. В The Value of Memory v4 от 10 ноября сравнены уже 3 075 вопросов и два читателя. Единственная ссылка на репозиторий в проверенной статье ведёт к MemOps. Таким образом, здесь воспроизведена статья о кэшировании, а для названных работ о памяти агентов зафиксированы условия, препятствующие точному повтору чисел. Новизна общей идеи оптимизации совместных затрат этим опытом не установлена. [OSL-MR v6](https://arxiv.org/abs/2606.10616v6) · [The Value of Memory v4](https://arxiv.org/abs/2610.31303v4).

В рабочем процессе планирования использован навык experimental-design. Его описание опубликовано Тимоти Кассисом и соавторами в 2026 году. [Scientific Agent Skills](https://doi.org/10.48550/arXiv.2609.00065).

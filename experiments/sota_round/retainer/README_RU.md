# Воспроизведение исследования MSR Cambridge

RESULTS_RU.md содержит результаты. Рядом лежат три самостоятельных протокола и их локальные фиксации SHA-256. Первичные файлы Microsoft, исходные деревья внешних проектов, обученные модели и исполняемые файлы хранятся вне поставки. sources.json задаёт проверяемые URL, смещения записей ZIP, CRC, контрольные суммы распознанных префиксов каждого тома и оригинальный код Python S3-FIFO. s4_sources.json задаёт точные ревизии и хеши пяти частей выпущенной модели. Построчные записи решений не содержат содержимого секторов диска.

## Локальная проверка результатов

Для офлайн-проверки достаточно CPython 3.14 и NumPy (в исходном прогоне 2.4.4). Из этого каталога выполните

    python -B verify.py

Проверяются фиксации SHA-256, 18 сравнений точной динамической программы с полным перебором и каждое сохранённое решение. Формат записи в results/steps — три little-endian uint32 на исходный запрос в порядке «обращения к группам, пропуски страниц, затребовано страниц», с gzip поверх записей. Количество исходных серверных запросов в основном тесте 212 992. Выходы нескольких совпавших вариантов дедуплицированы по SHA-256 несжатых записей. Файлы native_*.bits.gz и historical_*.bits.gz хранят по одному биту промаха на будущий запрос; младший бит соответствует более раннему событию, число значащих битов задано в JSON. Содержимое результатов по серверам можно читать непосредственно в results/servers.json, общие оценки в results/summary.json, результаты текущего S4 в results/range_s4.json, контроль целой недели в results/whole_week.json, числа оригинальной статьи и CLI в results/historical.json.

## Повторный запуск

Запуск проводился в Windows с Python и изолированным Alpine Linux 3.22.8 x86-64 для компиляции C/C++ библиотек. Поставку можно воспроизвести в обычном Linux с Python 3.14, NumPy, cmake, gcc/g++, GNU make, pkg-config, GLib, zstd, заголовками разработки и сетевым доступом к arXiv, GitHub и S3. Следующий пример для glibc хранит файлы в явно выбранном каталоге. Для проверки архивных цифровых следов используйте чистую копию поставки.

    export MSR_CACHE_ROOT=/absolute/path/to/msr-cache
    export MSR_ADAPTER="$PWD"
    mkdir -p "$MSR_CACHE_ROOT"
    python -B fetch.py
    python -B study.py
    python -B s4_fetch.py
    sh build_s4.sh "$MSR_CACHE_ROOT" "$MSR_ADAPTER"
    python -B native.py range
    python -B native.py native
    python -B week.py

Для текущего и исторического CLI нужно указать нормализацию размера до одного объекта. Важно запускать исторический CLI из каталога данных и использовать оригинальное имя файла в следующем примере. Старый CLI выбирает фактическую директорию вывода из имени трассы. Наш обработчик читает его result/hm_native.zst.

    python -B historical.py download
    cmake -S "$MSR_CACHE_ROOT/paper2023/libCacheSim" -B "$MSR_CACHE_ROOT/build2023" -DCMAKE_BUILD_TYPE=Release -DENABLE_TESTS=OFF -DUSE_TCMALLOC=OFF
    cmake --build "$MSR_CACHE_ROOT/build2023" --target cachesim -j4
    sh build_historical.sh "$MSR_CACHE_ROOT/paper2023/libCacheSim" "$MSR_CACHE_ROOT/build2023" "$MSR_ADAPTER" "$MSR_CACHE_ROOT"
    cd "$MSR_CACHE_ROOT"
    "$MSR_CACHE_ROOT/build/bin/cachesim" hm_native.zst oracleGeneralBin s3fifo,lru 43918 --ignore-obj-size=true -o "$MSR_CACHE_ROOT/native_cli.txt"
    "$MSR_CACHE_ROOT/build2023/bin/cachesim" hm_native.zst oracleGeneralBin s3fifo,lru,arc 43918 --ignore-obj-size=true -o historical_cli.txt
    cd "$MSR_ADAPTER"
    python -B historical.py
    python -B verify.py

В использованном Alpine отсутствует execinfo.h, который обе ревизии симулятора включают только для печати аварийной трассировки. Изолированная сборка подставила пустые backtrace/backtrace_symbols_fd через заголовок в /usr/local/include и установила argp-standalone. Для старой ревизии линковщику передано -DCMAKE_CXX_STANDARD_LIBRARIES=-largp. Исходники стратегий очередей не менялись. Для системы glibc эти локальные настройки не требуются. Сценарии Python в Windows передают пути в Linux через wsl -d, имя среды задаёт MSR_WSL. В Linux те же сценарии запускают программы напрямую.

До оценки записана гипотеза и порядок деления истории. После первого запуска native.py обнаружено, что опубликованные размеры объектов и исходные размеры запросов могут различаться при одинаковых адресах. Стартовая проверка остановила исполнение до результатов. amendment.json фиксирует исправление этой проверки. На первых 1 024 строках совпали все смещения и 992 длины. Объектная метрика использует единичный размер для всех обращений. Тест групповых чтений использует реальные размеры из исходного CSV.

Ревизии SOSP 2023 и 2026 имеют разные значения на одной трассе. historical.py использует программу и артефакт результатов 2023 года. Тест S4 использует текущий симулятор из выпущенного авторами артефакта, а их отдельная Python-версия S3 служит базой в тестах гибридов. Полное совпадение исторической публикации проверяется только для соответствующей исторической ревизии. Статистические интервалы описывают вариацию между 13 томами одного центра. Запросы одного тома не считаются независимыми испытаниями.

# Pre-outcome audit of the declared issue-reference mask
The final before/after byte comparison changed four cards and four query strings (two in the official 99). Only the data-cleaning step changed; the rank functions and target pool are the registered ones.
At 20:17 MSK, before any Qwen retrieval call or outcome access, an input-only count found prose references such as “PR 1234” or “ticket 1234” in four of 357 query rows and two of 300 cards. The originally declared mask removed URLs, explicit #nnn, SWE instance IDs and full hashes but did not handle these written-out references. Added the bounded prose pattern, relative issue/pull URLs and short hashes with an explicit commit/revision marker to implement the planned mask. Kept the first blind run, its input data, code, and predictions in pre-redaction-blind.zip (SHA-256 90f298b98a300b48c34b366b9173409ff4f3fbf7ffa3ac7bb83409f2c82b8ec1). Rebuilt all candidate and internal-control rows from scratch before opening labels. The unchanged original author comparator uses its own public preprocessing. This targeted mask does not anonymize code names, file paths, project names naturally present in issue text, or every possible free-form alphanumeric reference. Gold-grading metadata is never passed to ranking. A traced successful Match@1 is defined on a source issue ID. The run records the number of distinct source IDs so aliases, if any, can be recognized.

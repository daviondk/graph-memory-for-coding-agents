# Память агентов. Официальные тесты и контрольные эксперименты

Для быстрой проверки целостности после распаковки выполните `python verify.py --manifest-only`. Команда `python verify.py` дополнительно сверяет индивидуальные исходы, токены, выдачу памяти внутри эпизода и строки журналов побайтного сравнения. Перезапуск оригинальных метрик LongMemEval через `comparators/verify_official.py` требует NumPy 1.26.4 и доступа к GitHub для сверки авторского кода с закреплённой ревизией. В архив включены исходники скорера и входные предсказания для всех трёх систем поиска. Проверка основного манифеста сети не требует.
Все числовые итоги в Word сопровождаются файлами по отдельным вопросам, задачам или запросам. В папках protocol / PROTOCOL хранятся локальные протоколы с контрольными суммами. Они фиксируют порядок работ в этом исследовании; это не внешняя регистрация. Модели и полные сторонние датасеты загружаются по зафиксированным источникам. Расходы на архивные прогоны поставщиков не известны.
- comparators — перепроверка открытых списков Papr и gbrain и готовых авторских оценок ответов. Варианты разметки и бюджет получения результата указаны в comparison.md. verify_official.py проверяет вывод официальным кодом.
- dretr — полный запуск BM25, Contriever, Stella и абляций на LongMemEval-S. Два разных определения эталонных сессий. см. README.md.
- boundary — слепое перераспределение пяти позиций с открытыми рангами Papr, включая нулевой результат и отдельный бюджетный эксперимент. Команды в README.md.
- action и action_text — две формы выдачи решений на одних и тех же 34 программных задачах с 196 сессиями. Локальные исходные ответы, задания, приговоры исполняемых проверок и отрицательные контроли сохранены. Запуск второй формы следует за диагностикой первой. Попытки не складывать в 68 независимых наблюдений.
- coding и coding_holdout — поиск участков кода в SWE-Explore в исходных снимках репозиториев. Подробности в примыкающих протоколах и README. Полные снимки и зависимости отдельно.
- retainer — оригинальный след обращений и реализации алгоритмов из публикаций, перенос на стоимость группового чтения. Файлы логов на уровне запросов сжаты. Описание в README_RU.md.
- MANIFEST.sha256 — контрольная сумма каждого файла, кроме самого манифеста. verify.py — пересчёт основных таблиц из сохранённых записей без сети. Для перезапуска моделей нужны их веса; те же фиксированные ответы можно оценивать офлайн.
Каждая таблица предназначена для указанной метрики и состава наблюдений. Документ, ZIP и материалы предшествующего этапа хранятся отдельно.

## Как воспроизвести испытания памяти кодового агента

- В `swe_context` протокол задаёт, какие три поля извлекаются из прежней работы агента. Сначала запустите `python fetch.py`, затем `python cards.py`, `python rank.py`, `python choose.py` и в конце `python score.py`. Для первого шага нужен requests, для подготовки входов и проверки — pyarrow. Ранжирование использует numpy, torch и transformers. Переменная SWE_CONTEXT_DATA указывает каталог сырых данных. CONTRIEVER_PATH и MINILM_PATH указывают локальные каталоги моделей facebook/contriever и cross-encoder/ms-marco-MiniLM-L-12-v2. Запросы к Qwen направляются на SWE_CONTEXT_ENDPOINT. При автономной проверке приложенных предсказаний повторная генерация не требуется. Тестовые метки открывает только score.py. Для архива версии данных сверяются по source.json.
- В `vibe_memory` лежат результаты официального этапа формирования памяти VibeMemBench для всех задач и использованные поисковые методы. В `prior_files` лежат альтернативная запись наблюдавшихся изменений, хеш слепых предсказаний и независимый подсчёт попаданий в файлы. Новый репозиторий при создании записи не индексируется.
- В `vibe` собраны протоколы, контрольные запуски авторского оценщика, реальные патчи, итоги тестов и журналы потребления токенов. Подкаталог `qwen38_27b` хранит второй эксперимент с другим решателем и бюджетом. Для перезапуска среды используйте REPRODUCE.md и зафиксированные в provenance.json версии. В `vibe_qwen38` лежат контрольные суммы весов, системных библиотек, параметры сервера и проверка вызовов инструментов. Веса загружаются отдельно.
- Перед модельным выбором в `swe_context` после rank.py запустите cross_encoder.py. Скрипт подтверждает 12 слоёв у предусмотренной протоколом MiniLM-L12. Исходный локальный каталог MINILM_PATH содержит шестислойные веса с устаревшим полем имени модели в config.json. Результаты этой дополнительной проверки сохранены отдельно. Точные параметры и быстрый способ пересчёта приведены в swe_context/README.md.
- В `within_task` лежит последовательное воспроизведение решений внутри одной задачи. История видит только предыдущие уже завершившиеся обращения. Архив ledgers.zip содержит назначения и исходы. В `read_cache` отдельно оценивается повторное использование текста наблюдения при изменениях состояния рабочей копии.
- Для повторного создания Word после пересчёта расположите каталоги архива в work/sota_round проектной папки и создайте соседний outputs в корне проекта. Запустите report/package.py, затем report/build.py с установленным python-docx. Word включает копию ZIP с исходными результатами. Отдельная научная карта и библиография относились к предыдущему этапу обзора.

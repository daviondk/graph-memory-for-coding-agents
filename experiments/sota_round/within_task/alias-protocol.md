# Scoring-only checkout sensitivity

The original frozen metric which accepts /testbed under-covered the heterogeneous historical environments. On 16 Nov 2026 after the primary replay, its path extractor recognized only 95 of 2,797 qualifying events. A deterministic simple random sample (seed 173; 32 pathless labels) showed literal shell checkout roots such as /pandas, /moto and /pyccel, including both cd and absolute file arguments. Some original paths represented a patch transport file. The primary metric and all decisions remain in the release.

Before measuring this alternative: accept the case-insensitive absolute first directory whose spelling equals the public repository basename for this history as a second checkout alias; rewrite just that directory to /testbed. Preserve the normalized path case downstream. Drop patch.txt as a first target since it denotes a generic patch transport. Keep the original first-command-line rule, suffix whitelist, exact matching of executable + first detected target, pathless misses, population, return-code rule, candidate prefix, all nine stored rankings, confidence calculation, and freeze. Do not add guessed aliases for renamed repositories or path roles inferred from the data. Repository identity is used only in the scoring layer to canonicalize paths, never in ranking. Do not rerank or add any predictions. Reconstruct the original score for every published slot before computing new metrics. Report the widened metric separately as an outcome-informed sensitivity, including all-repo paired bootstrap, top-3, matched candidate ceilings and path coverage. Preserve new source and frozen hash before scoring. Reduced accuracy or a null result will be retained.

# Within-trajectory tool memory, prospective replay

Population: all 2,470 distinct byte-verified VibeMemBench source histories actually fed to the released 111-target memory stage at HF Tongyi-ConvAI/VibeMemBench revision 11164976b4f920cdb0d0cd570ca572e49acea1e8. Read local source manifest and all locally present .traj.json that meet the existing 64,000,000-byte single-file limit. Verify file content and counts. No API/model calls, no shell actions from traces, no target solutions, outcomes, thoughts, goals, provider text, metadata search, or cross-trajectory state. This is a new observational label, not an official VibeMemBench metric.

Prediction time and unit. For each assistant command batch, join bash actions with tool responses by ID strictly between that assistant message and the next assistant message. Use integer extra.returncode and agent-visible <output> content (fall back to extra.raw_output); unmatched/invalid responses remain unknown. Choose its first observed nonzero action in declared command order as the failure, including routine search misses and any compound command. One prediction per such batch after observation. Ignore siblings for the query. A bare/pure submit command is never a recovery. Treat a single bash invocation as atomic; a 0 only concerns the shell status. State used for ranking must come from strictly earlier batches, including candidate successor observations. A failure-to-command pair is written only when the FIRST declared command of the IMMEDIATELY NEXT assistant decision has completed with code 0 and is not a submission. Do not skip unsuccessful/unknown/empty assistant decisions to obtain an easier label. The end of the trajectory censors the previous failure. Do not skip intervening failures or choose other successful commands in the same batch. Keep all branches in the decision ledger.

Within the primary recurrence cohort, a current nonzero action has an earlier completed failure/success pair with the same leading executable family and numeric return code; its following observed label must qualify. Family strips leading workspace-changing cd and environment assignments, treats python variants uniformly, and otherwise identifies a leading executable with an explicit small list of shell wrappers. This is broad recurrence, not proof the underlying problem is the same. Report all labelled failures, no-history failures, an additional exact-error-fingerprint recurrence cohort, qualified rates, and the proportion for which any historical successful command contains the gold operation. No tune/train partition since every heuristic is frozen without scores or downstream labels.

Primary arm: sparse ranker over bounded failure/next-success pairs. Each written pair stores family, status, first normalized diagnostic line (casefolding, strip ANSI, collapse integers, path/name words retained), truncated failed command (384 UTF-8 bytes), diagnostic (384), and returned command prefix (1,024); never index full past outputs here. Rank prior pairs lexicographically by equal nonempty normalized diagnostic with same family/status, same family/status, BM25 of compact key, then more recent success. Empty fingerprints do not match. BM25 uses lowercase alphanumeric/dotted/slash/path tokens, k1=1.2, b=0.75, positive Robertson IDF, unique query terms. Raw baseline A: BM25 over all prior zero-exit command+full visible output steps. Raw baseline B (primary comparator): BM25 over every eligible earlier pair's full failed command+full visible failure output, same candidate pool as compact. Compare also paired raw BM25 with the identical fingerprint and family preference to isolate compression vs ranking; recent successful command; recent eligible pair; exact fingerprint (family+status) then recent pair; and the current failed command as a zero-memory repeat control. All methods use the same UTF-8 output command cap 1,024 and return up to 3 distinct command prefixes. Ties use most recent source. Empty state abstains; the simple repeat control returns one. Records and source offsets sufficient to reconstruct every prediction. Control/recovery commands never run.

Primary label: first concrete file target of the next zero-exit command (case-sensitive normalized relative repo-like filename/path with recognized extension; ignore heredoc body, /tmp, /dev, /proc, absolute paths outside /testbed, globs and pure submission; executable family plus exact first target). Count success at one result only for equal nonempty gold and predicted family+first target. Pathless labels are misses in the main denominator. Separately report condition on target being extractable, exact command replay (equal stripped command after CRLF normalization; truncated predictions cannot match longer gold), weak family-only, and top 3. Quantify exact gold-command replayability in history and strict family+target replayability. Count conditional label coverage and all failure triggers (including unlabelled) to avoid implications of autonomous fault correction. No causal test of patch success or fewer failures.

Uncertainty: paired differences on the same decisions, event-weighted; resample whole repositories with replacement, 10,000 replicates, Python random seed 20261116, percentile 95% interval. Report direction and discordant counts at primary top 1 against paired raw BM25, same-priorities raw, exact fingerprint, and recency; include top 3 and stronger candidate controls. Show per-repo denominators. Descriptive whole archive plus sampling sensitivity across repositories, no independent-event standard errors or claims of broad superiority. Report cumulative serialized UTF-8 key/value bytes written (text payload only; count each stored row once including returned command prefix; IDs, model tokenizer, physical index and shared runtime excluded), delivered prefix bytes, candidate population, runtime and software. Preserve source hashes, per-event prediction pointers, covered/missing branch counts and frozen protocol+implementation digests before running.
Implementation clarification before scoring: include a ninth arm, raw_steps, which indexes all prior joined tools' complete visible command/output documents (both successful and failed), and returns the stored command. This tests full unfiltered logs directly alongside the successful-only and error-paired raw baselines. All arm keys ignore assistant thoughts and the PR description.

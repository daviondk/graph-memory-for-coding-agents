# Retrieving a command after a repeated shell failure

The full census used 2,470 unique histories (1,449,010,288 bytes) from 90 repositories already fed to the authors' public memory-stage pipeline. Each source is verified against its pinned Git blob or LFS SHA-256. Every historical command is inert data. The full replay took 41.1 seconds on one CPU worker; no LLM, GPUs, user secrets or external services were used. The upstream dataset lists Apache-2.0. Results are observational within-history next-command prediction, a new study-specific proxy; the official benchmark measures separately executed repository tests. [Pinned source release](https://huggingface.co/datasets/Tongyi-ConvAI/VibeMemBench/tree/11164976b4f920cdb0d0cd570ca572e49acea1e8)

Of 12,369 nonzero batches, 7,966 directly preceded a first command with observed code zero, 1,989 preceded another nonzero, 2,409 ended the trace, 3 preceded a submission and 2 had an unknown result. All are in the ledger. Of 3,349 recognizable recurrences, 2,797 had the required next outcome. Their 1,118 histories and 82 repositories supplied the primary comparison. Exact top-one command replay was 4/2,797 for compact and paired full BM25; executable alone matched 1,078 and 1,058, respectively. Repeatable exact command text from any previous zero-exit action was even available in only 78/2,797. Only 95 original primary labels had an executable and recognizable filepath; compact and matched raw BM25 scored one hit each (same event).

The original path matcher required the common /testbed checkout. Thirty-two deterministic random pathless cases showed frequent per-project checkout roots. A separate scoring protocol therefore accepts the exact repository basename and drops patch.txt. The alternative was frozen before rescoring; it uses the same saved rankings and verifies all 7,966 rows' original item-level metrics first. The path coverage became 1,095/2,797. At top one compact and paired full-log BM25 each scored 84/2,797; 8 gains, 8 losses, 95% repository bootstrap interval −0.28 to +0.27 percentage points. At top three compact scored 124 versus 204 for simply recalling the last three zero-exit actions (−2.86 pp, −4.24 to −1.61). The paired and all-zero-exit candidate pools could represent at most 152 and 570 of these next operations, respectively. Raw commands can contain multiple parts; return status does not establish semantic recovery. First-file matching does not establish operation identity (e.g. reversing a backup copy still receives credit). A truncated 1,024-byte command prefix is for ranking/scoring and is not suitable for automatic execution. No causal claim about repository test success or an agent's ability to recover follows.

Compact text payload writes total 4,201,735 bytes, the same candidate pairs with full error text use 44,165,144, all previous joined steps use 444,975,791, and a recency-only memory of returned command prefixes from zero exits uses 26,894,009. These count text keys plus returned values, excluding physical index/metadata, with no OS compression. At the primary decision points compact served 864,014 bytes for the first suggestion and 2,001,309 bytes for up to three (see summary.json for exact). Across the 2,797 primary decisions the average was 2.45 distinct compact suggestions at a three-item budget.

## Reproduce

Python 3.14.4, NumPy version in summary.json. Commands assume this directory as the working directory. In the distributed archive, unpack ledgers.zip here first. To rerun from a fresh disk cache, use python prepare.py --base D:/vibe-work-cache to fetch the exact 2,470 data files (approximately 1.45 GB). The included 111-row input roster supplies repository, language and target ID only. Use an existing copy of the same hydrated dataset and original audit roster instead to eliminate the download.

    python canary.py
    python replay.py --base D:/vibe-work-cache
    python summarize.py
    python score_alias.py --base D:/vibe-work-cache

The supplied freeze.json and alias_freeze.json are the preregistration receipts. The latter verifies SHA-256 of decompressed ledgers so a different gzip timestamp is harmless. Original freeze times and scores must be retained for independent reproduction. Decisions are indexed by unique source session ID and a zero-based (assistant decision, declared command slot). Choice pointers are four integers (source failure batch and slot, source response-command batch and slot); raw arm pointers use the same pair twice. The only current-turn suggestion is the explicit zero-memory repeat control. In the primary ledger individual hit flags are 1 for full-command equality, 2 for executable and target, 4 for executable only (sum when simultaneous). The checkout sensitivity records one binary executable/file hit per same previously chosen slot. histories.jsonl.gz lists source path, SHA-256, counts, and stored text bytes even for histories that never generated a prediction. repositories.csv records paired contributions including zero-event repositories.

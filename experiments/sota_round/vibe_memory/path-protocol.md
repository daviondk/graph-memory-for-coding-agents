# Exploratory exact-path diagnostic

Declared after the full add/search run and before contacting target repository blob endpoints. No test/patch labels will be opened. Compare all 333 original memory.txt texts with the same extractor, ignoring the official provenance header. In each item, take the first three distinct syntactically plausible file paths with an explicit extension from a fixed list covering common source/config/docs. Accept path tokens separated by punctuation, trim diff a/ or b/, ./, quotes and line suffixes. Allow paths rooted at /testbed or the target repository checkout name, skip other absolute and traversal paths. Ignore saved patch.txt, any .patch/.diff, caches, environment/site-packages, node_modules, and VCS directories. Treat common root filenames with extensions as candidates too. Deduplicate per item and effective repo/commit/path HTTP check. Query GET Range 0-0 via raw.githubusercontent.com at the target base_commit from public whitelisted metadata. Success is HTTP 200/206, absence 404/410. Other failures or unavailable commits remain unknown and are reported separately. Check base-commit availability via one redundant path-independent object endpoint when all proposed paths in a target report missing, and treat unverifiable references as unknown. Primary descriptive result is number of all 111 targets per method offering at least one confirmed existing path. Also report proportion among issues offering paths, path-level denominators and per-target rows. A confirmed path shows navigability only, not relevance, correctness or a passing repair. Recognizable formatting and file availability differ across methods. No endpoint tuning on this diagnostic.

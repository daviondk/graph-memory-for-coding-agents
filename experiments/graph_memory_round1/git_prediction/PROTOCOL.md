# G1. Online prediction of Python co-edits from a single revealed anchor

Frozen before processing event paths or evaluating any prediction. Prior inspection covered mirror names, HEADs, available first-parent lengths and shallow flags only. No parameter search is planned. This is a custom diagnostic. No LLM or full source initialization.

**Sample.** Include all 12 shallow mirrors in the previous round's validity/mirrors directory, at the 12 HEADs in pins.json. In each first-parent chain start the agent with no data at its oldest available snapshot. Never treat that snapshot as a change. Process parent → child changes in first-parent topological order including merge diffs against first parent. Disable rename detection. Paths ending in .py only, case-sensitive. New and modified files can be targets; deletions leave the active inventory. Other file contents, text including commit messages, issues and future trees are invisible. The active inventory consists solely of Python paths actually seen by the agent and not subsequently deleted.

**Task.** For every transaction touching 2–20 non-deleted Python paths, reveal ONE of these as an oracle anchor. Pick index int(SHA256(repo + ':' + chronological_index), 16) modulo number of touched paths in lexical order. All remaining touched paths are positives, including unseen/unreachable. All methods share the same candidate set, active inventory minus anchor. Delivery limit K=5; shorter lists permitted only for smaller inventories. Score even empty candidates. This measures recommendation conditional on an already identified changed file. Within-commit time ordering is unobserved. Gold is withheld during ranking. Observe outcome after prediction and update. Transactions outside the eligible size still update the inventory and global frequencies; pair edges update for size 2–20 only. Use the first floor(available_changes/2) changes as development/warm-up and last half as primary evaluation; dev data are used online in the same fashion; no tuning. Report stages, support, cold-start coverage, and per-repository results.

**Comparators.** Global recency, frequency, lexical anchor-path similarity, raw direct historical co-edit count, and classical smoothed direct graph (constant 4 units of prior mass). Local path prior is built from token Jaccard on basename plus directory-token Jaccard, strong production/test basename agreement and smoothed global frequency. No issue description is given. Edge ties resolve by lexical path-criterion then frequency then path name. Compare normalized graph mass that writes 1/(m−1) per co-target in commit of size m; normalized edge at each anchor allocates exactly one total observation per transaction. Smoothed graph has score equal to edge mass plus four times a normalized path prior (Dirichlet posterior mean ordering). Raw-count and normalized smoothed graphs are both strong matched controls.

**Candidate policy.** Online mixture of (i) independent path prior, (ii) normalized co-change graph + that prior, (iii) recency prior, normalized on common candidates. Initially uniform over experts. Predict with weighted arithmetic mixture. After each eligible transaction, update mixture weights by exponentiating each expert's mean log probability on reachable targets, then mix in 1/32 uniform share to allow drift. If no reachable target, do not update the weights. An equal-weight static mixture is an ablation. Secondary diagnostic single prior/graph vs averaged graph, and normalized vs raw edges. The hypothesis is that adapting how much to trust the graph improves macro repository Recall@5 over the fixed normalized smoothed graph. Rival: fixed prior or direct links suffice because co-edit patterns repeat.

**Metrics.** Primary mean Recall@5 per eligible event, equal weight for each repository with ≥1 test event. Report event-weighted and macro Hit@1/Recall@5 and reachable-target fraction. 20,000 paired bootstrap resamples of repository-level deltas with replacement, seed 20261118; sign counts, no inference that these convenience repositories represent all repositories. No stopping on performance, no hyperparameter sweep. Include top-5 lists, positives, anchor, date/parent/SHA, split, target/candidate sizes, raw query metrics, per-repo summaries, parameters, code/software/checksums. Statistics are descriptive for this one preliminary study.

# G1c. Does matching training weights to actual query exposure improve ranking?

This protocol was added after seeing G1/G1b and G1 reader outcomes. A third independent panel has not been fetched or examined with this policy. Preselected repositories: pypa/wheel, python-trio/trio, python-hyper/h11, jazzband/pip-tools, aio-libs/aiohttp, celery/kombu, mkdocs/mkdocs, redis/redis-py, scrapy/scrapy, pypa/cachecontrol. Freeze default HEAD from the same shallow depth-240 procedure as G1b; list fetch failures. Keep the candidate universe, oracle anchor sampling, bandwidth, all-positives Recall@5, half-history warmup and G1 reader-free prediction settings unchanged.

For each historical transaction S of size m in [2,20], assign directed edge a→y a weight 1/[m(m−1)] for each distinct a,y in S. A uniformly revealed anchor equals a with probability 1/m. Candidate y yields reward 1/(m−1) in Recall@K when a equals the revealed anchor and y is recommended. With fixed inventory and ranking rule per anchor, unregularized expected training Recall@K over uniform events maximizes exactly the sum of selected weights. Sorting weights is optimal on this empirical objective. This statement does not imply gains for a chronological distribution shift, program repair, or a nonuniform agent-selected anchor. Scaling by a positive factor per anchor leaves the unregularized optimum unchanged.

Primary comparator is G1's unit graph. Conserve G1's total accessible mass separately for every anchor in every query, i.e. scale new weights to local sum of G1 unit weights, then add identical 4*pi(path) prior. Only the relative importance of large historical transactions then differs. Primary outcome equal-weight repository Recall@5 difference exposure-matched minus G1 unit graph on all evaluation events, seed 20261118, 20,000 repository bootstrap replicates and sign counts. Unsmoothed training-objective identity is mathematics, not evidence that finite-sample regularized test ranks must improve. No fitted exponent, no sweep, no choice after seeing scores. All outcomes reported. The source-level scorer and clone list will be hashed before calculating outcome metrics.

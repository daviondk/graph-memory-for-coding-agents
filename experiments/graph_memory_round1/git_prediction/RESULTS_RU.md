# Граф совместных правок при холодном старте

**Что установили.** Если один изменённый Python-файл уже найден, проверка связей с предшествующими коммитами помогает выбрать другие затронутые файлы. На второй, заранее выбранной группе из 10 репозиториев простой граф по счётчикам поднял среднюю по репозиториям полноту первых пяти рекомендаций с 39,27% у сравнения путей до 53,50%. Пара простых методов объясняет почти весь наблюдаемый выигрыш. Сложение разных источников с автоматически подстраиваемыми весами не превзошло нормированный граф на первой основной проверке. Для объяснимой дробной записи воспроизвёлся небольшой выигрыш перед сырым счётчиком, который перестал быть убедительным при строгом контроле силы сглаживания.

## Постановка

С пустой памятью двигаемся по доступной главной линии Git. Граф создаётся только из путей, возвращённых уже прошедшими коммитами; полные деревья и код для ранжирования не индексировались. Первую половину переходов используем для накопления опыта, вторую — для оценки с последовательным обновлением после каждого предсказания. На коммитах с 2–20 затронутыми Python-файлами по заранее фиксированному хешу открываем один файл-якорь. В списке из пяти нужно найти как можно больше остальных файлов этого коммита. Результат для события — число найденных различных целей, делённое на их полное число, включая недостижимые по памяти цели. Удалённые пути выбывают из доступного множества. При повторном появлении того же имени исторические связи возвращаются. Происхождение файла после переименования специально не восстанавливалось.

Даты, тексты сообщений коммитов и содержимое следующего коммита не входят в расчёт признаков. Один SHA используется как идентификатор результата. Отбор якоря — оценочное раскрытие одной заведомо верной подсказки. Внутри коммита порядок фактического редактирования неизвестен. Разработчик может прийти к нужному файлу совсем по-другому. Метрика измеряет локализацию при данном якоре, а не умение решать задачу разработки.

## Модель и контроли

Пусть старый коммит содержит набор путей S размера m. Сырые рёбра получают по единице для каждой совместно наблюдавшейся пары. Гораздо больший коммит оставляет по каждому якорю m−1 единиц. В нормированной записи вес соседу равен 1/(m−1), поэтому на один якорь остаётся ровно одна единица. `pi(y|a)` — распределение до наблюдения связей для кандидата y при якоре a. Оно использует сходство токенов путей, соответствие производственного и тестового имени и сублинейное влияние частоты. Сглаженный вес — число наблюдений ребра плюс 4·pi. Эквивалентное ранжирование даёт среднее распределение условной мультиномиальной модели с псевдонаблюдениями Дирихле.

Нормировка инцидентных рёбер — известная проекция гиперграфа, а рекомендация следующих файлов по истории совместных изменений известна по ROSE. Поэтому сравнение проверяет, когда такие механизмы помогают в памяти агента. Отдельно проверена гипотеза, что автоматически меняющееся доверие к сходству имён, графу и недавности улучшит результат. Онлайн-смесь обновлялась по логарифмической вероятности уже открытых ответов и после каждого обновления возвращала 1/32 веса равномерной смеси экспертов. [Newman, нормировка совместного участия](https://pmc.ncbi.nlm.nih.gov/articles/PMC387296/) · [Zimmermann et al., ROSE](https://thomas-zimmermann.com/publications/files/zimmermann-icse-2004.pdf)

## Основные результаты G1 и G1b

Все значения ниже — проценты. Каждому репозиторию соответствует одинаковый вес. Метрика Hit@1 засчитывает любой нужный файл на первом месте.

| Глобальная частота | 46,01 | 31,12 | 33,04 | 20,94 |
| Сходство путей и частота | 58,14 | 47,40 | 39,27 | 33,70 |

| Сырой граф с той же суммой весов, что у нормированного | — | — | 54,49 | 47,87 |

**G1.** 12 ранее доступных shallow-зеркал, 1813 переходов, 259 обучающих и 299 отложенных запросов. Медиана доступных кандидатов в тесте 37. Потолок полноты по доступности путей 86,85% при усреднении по репозиториям и 91,82% по событиям. Первичный контраст адаптивной смеси с нормированным сглаженным графом −0,43 п.п. 95% парный бутстрэп по 12 репозиториям [−2,23; +1,15] п.п., выигрыши / ничьи / проигрыши 2/6/4. При равном весе событий цифры меняются: 68,10% против 67,93%. Это основание заранее фиксировать единицу усреднения. На этой группе впервые замечена разница нормированной и сырой записи.

**G1b.** Протокол независимой панели зафиксирован после наблюдения G1. Все десять заранее указанных внешних проектов загрузились; 2589 переходов, 482 обучающих и 450 отложенных запросов. Медиана кандидатов 51, потолок по репозиториям 90,62%, по событиям 88,15%. Переносимый вторичный контраст нормированной и сырой записи с тем же текстовым prior +1,27 п.п., 95% [ +0,05; +2,34 ], 8 выигрышей и 2 проигрыша. Более строгий первичный контроль приводит сырые рёбра для каждого якоря к той же доступной сумме весов, что и нормированные, прежде чем сложить с prior. Разница с ним +0,75 п.п., 95% [−0,24; +1,67], 7 выигрышей и 3 проигрыша. Рангу помогло в том числе уменьшение объёма доверия к графу. По этим данным нельзя уверенно приписать весь эффект собственно перевзвешиванию больших коммитов.

Панели удобства включают открытые Python-библиотеки и не являются случайной выборкой всех репозиториев. Единица репликации — репозиторий, число кластеров небольшое. Commit-level зависимость исключает интерпретацию размеров выборки 299 и 450 как количества независимых результатов о репозиториях. Межпроектное сравнение показывает также заметное изменение трудности и пользы имён файлов. Методы с внешним поиском, embeddings и реальный кодовый агент в ранжировании G1/G1b не участвовали.

На третьей панели G1c проверяется явно выведенный вес, который учитывает также вероятность раскрытия якоря. Формула, протокол и фактические результаты приведены в соседнем файле [EXPOSURE_RESULTS_RU.md](EXPOSURE_RESULTS_RU.md).

## Журнал и воспроизведение

В `PROTOCOL.md`, `TRANSFER_PROTOCOL.md` и JSON-файлах freeze зафиксированы дизайн, версии и хеши до оценивания. В `pins.json` и `transfer_pins.json` записаны адреса исходников, точные HEAD и длины историй. Из-за shallow-клонов воспроизводителю нужны также сохранённые границы начальной истории; они доступны в исходных локальных зеркалах, файлах shallow и как первый parent в списке переходов. Репозитории из разных этапов не пересекаются. `run/predictions.jsonl` и `transfer_run/predictions.jsonl` содержат полный прогноз каждой стратегии и исход каждого запроса, включая разминку. В двух `summary.json` есть таблицы по каждому репозиторию, а в `manifest.json` — инвентарь и хеши.

`python run.py --out REPLAY_DIRECTORY` воспроизводит первую панель в новой директории. `python verify.py` отдельно проверяет каждый переход через git diff родительского и дочернего SHA, восстанавливает инвентарь, якоря, полный список целей и ранжирование по недавности, проверяет доступность выданных путей и пересчитывает метрики отдельных прогнозов. В `verification.json` все 4402 перехода G1 + G1b независимо проверены. Вычисления выполнялись на CPU стандартной библиотекой Python 3.14.4 и Git 2.49.0.windows.1.

# G1b. Unseen repositories; mechanism test before cloning or reading their data

The initial 12 repository evaluation is known. Its preregistered online mixture did not beat normalized historical edges. Exploratorily, replacing raw with fractional edges improved macro Recall@5 by 1.41 pp on that panel. An important confound is that fractional edges also decrease the total pseudo-count and hence increase shrinkage toward path similarity. This second protocol is written before fetching any of the following data or seeing any predictions on them.

Fixed convenience transfer panel, ten GitHub repositories disjoint from G1: psf/requests, urllib3/urllib3, pypa/packaging, pypa/build, pytest-dev/pluggy, tox-dev/tox, sphinx-doc/sphinx, django/asgiref, encode/httpx, psf/black. Clone default branch with depth 240, no tags. Pin initial HEAD in transfer_pins.json. If a clone fails, retry once; failures stay explicitly listed. Use the identical writer, oracle anchor sampling, active pool, first-parent chronology, evaluation, and bootstrap as G1. No parameter changes, all old methods retained. Some of these popular projects may be familiar from unrelated previous benchmarks. We are evaluating this exact policy on new histories. Git dates are not used as a surrogate for ancestry.

Primary endpoint is macro repository Recall@5, fractional smoothed graph minus equal-total-mass scaled smoothed raw graph. For each anchor and currently accessible neighbor set let R=sum raw_count and U=sum fractional_count, over that same set. Score matched_raw(y)=raw(y)*U/R + 4*pi(y) when R>0, otherwise 4*pi(y). This keeps graph/prior mixture strength identical to the fractional graph, while leaving relative contributions of old co-targets in their raw proportions. If fractional weighting wins here, altered edge allocation—not just stronger smoothing—can explain the direction. Compare against raw_smoothed, path-only, and the original adaptive mixture as secondary outcomes. Implement and sign transfer code before running any predictions. Ten repo sampling clusters give a descriptive percentile interval and paired sign counts, not a claim about all software.

The mirror bootstrap file is chronological only on the default first-parent lineage and is not a standardized SWE leaderboard. No human acts as a solver and no real fixes are generated. Frequency matching can only identify what this particular intervention changes; any general claim requires additional tasks and external evaluation.

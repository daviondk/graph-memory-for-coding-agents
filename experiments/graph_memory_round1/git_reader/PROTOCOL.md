# G1 Reader. Does showing actual historical pair evidence change local LLM localization?

Frozen before any prediction scores, individual historical paths, or labels of the transfer panel were viewed. G1 aggregate outcomes on different repositories are known. Use the ten previously named G1b transfer repositories/pins and their standard evaluation halves. Actor sees one revealed Python anchor, the same 8 candidate paths and prior marginal commit counts in each of three independent fresh prompts. No issue text, code, commit messages or future commit membership enters these prompts. The target is to select exactly one additional co-edited path. The anchor is oracle-supplied; this is not an autonomous repair.

Candidate construction uses only the past, top four lexical-prior files and first four distinct remaining unit_smoothed candidates; allow up to five from each ranking as supplied by G1, then fill open slots from frequency ordering. Within-slate order is a hash of the repo/SHA and candidate path, shared by all arms. Restrict to inventories that support eight candidates and at least two distinct edge weights among them so the shuffle is informative. Select 24 commit events: choose ascending SHA256("reader:"+repo+sha) within repo, interleave one per repo per cycle in sorted repo order (rotate initial repo lexicographic pass by hash of repo name). Exclude any event with security/vulnerability/exploit/attack/bioweapon indicators in its commit subject or touched/visible paths, for benign functionality only. A brief screening of selected titles, without answers or scores, may remove additional non-benign cases before running. Selection never uses target inclusion in the eight or any correctness measure. Log ceiling afterwards.

A masks pair values, B shows true pair evidence, C permutes the same pairs as a deterministic cyclic shift over the slate; choose smallest nonzero shift producing a different visible vector, starting from a hashed offset. Present both total count of historical shared transactions and conserved (1/(m−1)) weight. Causal interpretation only within these prompts. A and B/C have the same schema, B vs C is the primary token-content control; log actual token counts. All arms held at temperature zero, seed 18112026, max 8 tokens, thinking disabled; local Qwen3.8-27B UD-Q4_K_M, RTX 3090. Order the three arm calls by a deterministic hash per task. No dedup of equal answers; new request each time, no histories. Output must be a single candidate letter A–H; other replies count as failures. Save every prompt, raw response, usage, latency, connection retries, version/model. No retries for an incorrect or malformed successful completion.

Primary difference in task hit@1 B−C over all selected 24 (exact two-sided sign/McNemar on discordants), B−A descriptive, compare with deterministic lexical prior and normalized graph within same eight. Report candidate ceiling, per-arm input usage, limits, selected IDs, and protocol/source checksums. This is an exploratory underpowered reader mechanism probe, with a richer/more informative-than-average slate by construction, not a SOTA benchmark.

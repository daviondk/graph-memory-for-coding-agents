# Если альтернативы уже встретились при чтении
> Чтобы убрать стоимость дополнительного поиска, мы проверили вариант, который сохраняет только пути из уже открытой при первом ответе части графа.
Отобрано 168 пар в семи проектах переносной группы C, по 24 пары из каждого проекта с подходящими вопросами. В восьмом их не нашлось. На старом снимке прямой поиск в ширину читал ровно те же 1 124 исходных объекта для всех вариантов. Метод с одним доказательством и варианты с дополнительными путями имели одинаковую стоимость получения источников; объём сохраняемой записи мог различаться. Дополнительные цепочки присутствовали в просмотренной окрестности у 51 пары.
@ 7.1 2.8 2.9 4
| Что делается после нового коммита | Чтения blob | Верно | Записано байт |
| Открыть заново без памяти | 1 064 | 168 / 168 | 0 |
| Вернуть старый ответ вслепую | 0 | 164 / 168 | 15 251 |
| Проверить один сохранённый путь | 163 | 168 / 168 | 70 092 |
| Три кратчайших из уже виденных | 163 | 168 / 168 | 78 760 |
| Выбрать из виденных три разных | 163 | 168 / 168 | 78 760 |
| Сохранить дополнительные рёбра | 163 | 168 / 168 | 78 438 |
При одинаковой подготовке сохранение одного проверяемого пути уменьшило число исходных чтений за первый и повторный запрос с 2 188 до 1 287, на 41,2%. Четыре положительных ответа успели устареть; слепое повторение их пропустило. Дополнительные пути и ограниченный кэш рёбер дали ровно столько же чтений в каждом из 168 случаев, сколько и одно свидетельство.
При независимой проверке трёх групп воспроизвели 6 582 запроса, включая 87 утраченных зависимостей. На них и на 80 специально построенных контрольных примерах расхождений не обнаружено.
Выигрыш относится к повторной проверке ограниченной статической зависимости с известными концами. Он повторился в режимах, где были измерены реальные обращения к Git. Снизить количество чтений за счёт сложного графового выбора сверх одного пути на этих запросах не удалось.

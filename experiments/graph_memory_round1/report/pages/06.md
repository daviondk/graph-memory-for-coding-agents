# Инициализация по наблюдаемым правкам
> При первом знакомстве с репозиторием агент начинает с пустого списка файлов. Каждый увиденный коммит пополняет список и записывает, что менялось вместе.
Мы взяли 12 закреплённых Git-историй Python и двигались по первой родительской линии коммитов. Один уже известный изменённый файл сообщался поиску в качестве подсказки. Задача — порекомендовать другие файлы текущей правки. До выбора доступны только ранее встречавшиеся и ещё существующие пути. Текст задачи, содержимое файлов, будущий патч и порядок работы внутри коммита скрыты. Само наличие данной подсказки существенно упрощает локализацию.
События с 2–20 изменёнными файлами оценивались отдельно. Каждый метод получает пять мест и один набор кандидатов. Абсолютно новый файл мог попасть в эталон, даже когда его ещё нет в памяти. Первая половина истории каждого проекта служила прогревом, по второй набралось 299 оценённых событий. Сначала считаем долю верных файлов внутри события, затем усредняем по каждому проекту и даём проектам одинаковый вес.

**Изначальная гипотеза об адаптивной смеси не подтвердилась.** Разница по основному Recall@5 составила −0,43 п.п. При повторной выборке 12 репозиториев 95%-й интервал от −2,23 до +1,15 п.п. Дробная запись опередила обычную примерно на 1,41 п.п. Это наблюдение послужило основанием для отдельной проверки на других проектах.

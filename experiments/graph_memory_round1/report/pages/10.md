# Как проверить старую запись о зависимости
> Истинность факта «из модуля A можно дойти по импортам до B» подтверждает конкретная цепочка. Если подтверждение устарело, факт можно проверить повторно.
Сначала выбрали пары с цепочкой длиной 2–4 импорта. Через 12 коммитов проверили их снова. Эталон задаётся статическим синтаксисом Python и моделью разрешения локальных импортов, включая условные. Исполнение программ не измерялось.
Каждый вариант запоминает одну или до трёх цепочек. Для положительного ответа достаточно наличия всех вершин и прежнего содержимого файлов, которые поставляли рёбра одного из путей. Конечному модулю достаточно существовать. Если свидетельство не подтвердилось, читаем изменившиеся импорты и при необходимости повторяем точный поиск. Гарантия действует в пределах выбранной модели статического графа.

~ Модули A и C и описанные ими рёбра остаются прежними; конечный модуль D по-прежнему существует.
Каждый сценарий изменения — прошлый Git-коммит либо гипотетическое изменение одного промежуточного источника. Ценность набора путей равна взвешенной доле сценариев, в которых выживает хотя бы один. Добавление нового пути покрывает только ранее непокрытые сценарии. При неотрицательных фиксированных весах это монотонная субмодулярная функция покрытия. Для ограничения k равностоимостных путей жадный отбор имеет стандартную нижнюю границу 1−(1−1/k)ᵏ от оптимума на том же наборе сценариев и кандидатных путей. Реальное будущее в эти гарантии не входит.
В одном контроле сохраняли три кратчайших пути. В другом использовали жадное разнообразие, предполагая одиночное изменение без истории. Основной метод отдавал половину массы старым событиям Git и половину гипотезе одиночного изменения. Именно сравнение с чистым разнообразием показывает, добавила ли пользу история сверх наличия альтернатив. [Классический результат по покрытию](https://doi.org/10.1007/BF01588971)

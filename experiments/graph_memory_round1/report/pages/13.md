# Перенос проверки на новые зависимости
> Вывод про несколько свидетельств повторно проверили на восьми других Git-историях. Для этих проектов были известны результаты задачи совместных правок, измерения цепочек импортов ещё не проводились.
В группе C представлены asgiref, httpx, requests, build, packaging, pluggy, tox и urllib3. В одном проекте не нашлось подходящего вопроса. Для семи остальных набралось 2 023 вопроса, из которых 17 перестали быть истинными на новой версии. Глубина, правила отбора запросов и стратегия записи закреплялись до оценивания.
@ 11.1 5.7
| Что хранится | Быстрые подтверждения |
| Одна кратчайшая цепочка | 635 / 2 023 |
| Три кратчайших | 706 / 2 023 |
| Три по разнообразию источников | 722 / 2 023 |
| Три с учётом разнообразия и Git | 721 / 2 023 |
В первичном сравнении последней строки с тремя кратчайшими 16 случаев улучшились и один ухудшился. Макросредняя по проектам выросла на 0,56 п.п., 95%-й описательный интервал [+0,11; +1,19]. Картина для исторической информации сохранилась. У отобранных по разнообразию цепочек оказалось ещё одно быстрое подтверждение сверх исторического выбора.
## Можно ли читать только нужные источники
Во втором эксперименте хранились одни и те же три исторические цепочки. При постоянном порядке проверки понадобились 2 253 логических открытия файлов. Если в начале выбрать путь с меньшим числом уникальных изменившихся источников, достаточно 2 203 открытий. Возможность пересобирать цепочки из объединения прежних рёбер добавила варианты в 54 вопросах, но оставила те же 2 203 открытия. Отсутствие дополнительной экономии сохраняется на этом наборе; результат не обещает равенства на более глубоком графе.
Здесь считаются логические открытия при обработке каждого независимого вопроса. Полную цену в командах Git, байтах, времени и первичной подготовке показывает отдельный операционный аудит. Цель этой проверки — сравнить правила чтения при одинаковой записи и восстановить точный ответ по доступной версии.

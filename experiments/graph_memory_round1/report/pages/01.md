# Графовая память кодового агента
> Что сохранить при первом знакомстве с проектом, как найти прошлый опыт и когда после нового коммита ему ещё можно доверять.
Программисту полезно помнить, какие файлы менялись вместе, какой тест он уже запускал и где лежит реализация знакомого метода. Для агента такая память может быть графом. Узел обозначает файл, событие или утверждение. Ребро хранит конкретное наблюдение, например совместную правку или импорт. Эти две связи дают совсем разные основания прогнозировать следующее действие.
Мы проверили три операции на публичных историях программных проектов. При прогнозе следующего файла информация о совместных правках оказалась полезнее одной близости имён. Для поиска прошлой задачи связи между одноимёнными символами не улучшили сильную систему. Для повторной проверки существования зависимости несколько сохранённых цепочек иногда позволяют подтвердить старый ответ без чтения кода.
@ 3.5 7 6.3
| Операция | Что получает агент | Измеряемый результат |
| Записать изменение | Один уже известный файл и предшествующая история Git | Доля остальных изменённых файлов в первых пяти |
| Найти опыт | Описание новой задачи и карточки прежних сессий | Нужная сессия на первом месте |
| Проверить запись | Старые цепочки импортов и новая версия проекта | Ответ, подтверждённый без чтения содержимого файлов |
**Наиболее содержательная линия для статьи — стоимость проверяемой памяти.** Сохранённое свидетельство должно либо позволить принять правильный ответ, либо явно потребовать пересчёта. Для этого направления есть математическая модель и проверка на изменениях реального кода. Ускорение всего агента и превосходство над опубликованными системами по числу исправленных задач остаются открытыми вопросами.

# Поиск нужной прошлой сессии
> На SWE-ContextBench Lite дано описание новой задачи. Нужно поставить на первое место одну из 300 историй работы, которую авторы связали с этой задачей.
Мы построили двудольный граф из 300 сессий и 4 579 имён. Его 6 730 связей показывают, что в операции записи встречался путь либо технический идентификатор. Ранжирование начиналось с десяти кандидатов. Первый дополнительный признак учитывал редкие имена, буквально встретившиеся в текущем запросе. Второй измерял сходство с другими сессиями в первой пятёрке. Ту же процедуру применяли поверх готового гибридного поиска проекта и воспроизведённой авторской реализации Recall. Новых обращений к языковой модели не потребовалось.
@ 5.8 2.5 2.6 2.6 3.3
| Первая ступень | Было | Только имя | Имя и соседи | Попадания в топ‑5 до / после |
| BM25 + Contriever, 99 задач | 65 | 64 | 64 | 85 / 87 |
| Recall, те же 99 задач | 58 | 60 | 59 | 79 / 81 |
| BM25 по доступным на дату сессиям, 99 | 11 | 11 | 11 | 16 / 16 |
Для гибридного поиска смесь дала ноль выигрышей и один проигрыш на первом месте. Для Recall — два выигрыша и один проигрыш. Один точный технический идентификатор MediaOrderConflictWarning помог узнать нужную задачу Django. Близкие задачи SymPy содержали общий latex.py; при добавлении графа обе поисковые системы предпочли соседнюю неверную историю. У всех 99 запросов нашлось какое-либо сходство между историческими сессиями. Само его наличие оказалось слабым критерием доверия.
При отборе только предшествовавших завершённых PR официальный эталон был доступен в 17 из 99 случаев. На 258 дополнительных запросах при той же библиотеке из 300 сессий эталон нашёлся только для 13, на первом месте результаты были равны (11). Все 357 запросов уже использовались в прошлых сериях. Сохранены все предсказания, а повтор в другой версии Python совпал побайтно.

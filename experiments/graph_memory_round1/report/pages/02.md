# Как устроена графовая память
> Один инцидент может оставить несколько следов. Факт изменения файла, его предполагаемая причина и результат выполненного теста имеют разную доказательную силу.
## Запись и чтение на примере
Пусть вчера агент менял парсер и исправил тест формата даты. Эпизод содержит команду, версию кода, путь и наблюдавшийся результат. Связь «изменились вместе» позволяет предложить файл теста при новой правке. Связь «в этом запуске тест прочитал файл» позволяет проверить применимость прошлой диагностики. Запись «парсер исправен» сама по себе не содержит условий, при которых это утверждение получилось.

| Структурная | Файл, символ, импорт, вызов на снимке | Найти реализацию или зависимость |
| Эпизодическая | Сессия, команда, ответ инструмента, патч | Восстановить ход прошлой работы |
| Временная | Факт, версия, момент появления свидетельства | Отделить доступное раньше от узнанного позже |
| Процедурная | Условие задачи, способ действия, проверка результата | Повторить полезное действие при сходных условиях |
## Что происходит после нового коммита
Запись обновляется разными способами. У события сохраняется прежняя версия. Для производного факта можно отмечать интервал применимости и указывать, чем он подтверждён. Читателю доступны краткая запись и ссылка на исходный фрагмент. Если фрагмент изменился, пригодность проверяется заново. Для Git с ветвлением требуется проверить достижимость исходной версии от текущей базы. Одна дата коммита описывает порядок лишь приближённо.
Графовые связи можно хранить в SQLite или обычных списках смежности. Чтобы установить эффект способа записи, сравнивают методы на одном потоке наблюдений с одинаковым бюджетом чтения. Измерение задержки конкретного движка составляет другой эксперимент. [Артефакт IMCA](https://github.com/nicl-nno/IMCA) · [Zep](https://arxiv.org/abs/2501.13956)

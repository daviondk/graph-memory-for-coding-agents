# Перенос механизма и проверка альтернативного алгоритма чтения

18 ноября 2026. Предварительно известны все итоги G3 на A/B, итоги G1 на других задачах. Вопросы об импортах для следующих восьми проектов и их результаты ещё не рассчитывались. Выбор — все из десяти дополнительных зеркал G1b кроме двух совпадающих с G3 B (black, sphinx). Без отбора по интересности: asgiref, httpx, requests, build, packaging, pluggy, tox, urllib3. Закрепить SHA. Применить неизменённый протокол выборки, модели истории, глубины, число цепочек и подсчёт ошибок G3. Первичная репликация: исторический выбор трёх цепочек против трёх кратчайших по быстрым положительным ответам. Единица сравнения — репозиторий; интервал описательный. Проекты с нулём подходящих вопросов остаются в перечне и не имеют определённой оценочной доли.

Вторая проверяемая идея касается чтения уже сохранённых фактов. На всех вопросах храним те же максимум три цепочки, которые выбрало историческое правило G3. Перед проверкой доступна принадлежность файла данной версии и hash его содержимого. Если провайдер не изменился и целевой модуль по-прежнему существует, старое ребро известно. Если изменился, чтение его исходника проверяет сразу все исходящие рёбра. В сравниваемых вариантах объём памяти, имена, метаданные, цена открытия файла и поиск после исчерпания свидетельств одинаковы.

Сравнить (1) прежний фиксированный порядок, (2) сильный простой контроль: один раз отсортировать допустимые цепочки по числу различных файлов, требующих открытия, затем по длине и лексически, (3) пересчитывать самую дешёвую исходную цепочку после каждого чтения, (4) делать то же и разрешить составлять цепочки заново из объединения тех же сохранённых рёбер. Ограничение 4 перехода и простые пути. Среди требуемых файлов берём первый в выбранной цепочке; исключить априори удалённые узлы. Для всех методов начать новый полный поиск в ширину, когда все сохранённые доказательства опровергнуты, и использовать уже прочитанные файлы. Основной новый контраст (4) против (2) — среднее число открытий содержимого файлов на вопрос, одинаковый вес каждого репозитория. Дополнительно доля верных ответов, число изменений ответа, превосходство относительно (1), цена записи и число запросов, для которых рекомбинация вообще даёт ещё одну цепочку. Противоречие эталону требует аудита и протоколирования. Ожидание: преимущество перед (1) вероятнее, чем перед (2); на коротких путях пространство для улучшения может быть близко к нулю. Восьми групп недостаточно для точного популяционного интервала. Новизну в литературе и эффект на правки кода эта проверка не оценивает.

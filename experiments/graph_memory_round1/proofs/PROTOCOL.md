# Протокол G3. Сколько свидетельств о зависимости стоит запомнить

Дата фиксации — 18.11.2026 до построения графов и расчёта метрик. Исследовательская гипотеза. Предыдущие опыты проверяли поддержание полного множества результатов лексического поиска, включая на тех же 12 репозиториях. Итоги для импортов и разных путей до цели не изучались.

Набор A — все 12 локальных снимков Git из memory_session6/validity/mirrors. Набор B — четыре внешних открытых проекта psf/black, pallets/flask, pallets/werkzeug, sphinx-doc/sphinx, HEAD в момент первого скачивания. Имена выбраны за наличие пакетной структуры Python до открытия результатов. Оба набора имеют фиксируемые SHA. В каждом берём до шести непересекающихся переходов по 12 коммитов first-parent, отсчитывая назад от закреплённой вершины. До 24 более старых одиночных переходов доступны для оценки риска изменений. Неиспользуемые частичные окна и технические потери публикуются.

Задача агента — сохранить ранее подтверждённое положительное утверждение «из локального модуля s есть цепочка импортов до t не длиннее четырёх переходов» и ответить после новой версии. Это статический граф синтаксиса Python. Он включает импорты внутри условий и функций. Это не утверждение об исполнении рантайма. При наличии импорта from проверяем существующие модули по основному имени и имени импортируемого элемента. Запросы задаются исключительно по начальному снимку. Из наблюдённых начальных цепочек берём до 64 пар на переход без прямого импорта (кратчайший путь 2–4) равномерно фиксированным хешем, без отбора по факту последующего изменения. Максимум 24 старых исходных модулей с исходящим импортом по фиксированному хешу; до 16 путей на пару, простых, обход в ширину, лексическое разрешение ничьих, до 10000 путей на источник для подготовки. Факт наличия импорта и выбор начальных вопросов моделью не измеряются. Полная постройка начального индекса служит генерации примеров и эталону. При рабочем запросе модель метода нуждается в перечне локальных модулей и окрестности вопроса. Стоимость добывания начальных цепочек выделяется отдельно.

Память для одного ответа содержит до трёх прежних цепочек и четырёх рёбер в каждой. После обновления быстрый режим удостоверяет существование всех вершин и совпадение Git blob всех исходных файлов пути (содержимое конечной вершины не требуется). При неопределённости запускается точная перепроверка реестра импортов до глубины 4. Для контроля с повторным чтением проверяем лишь изменившиеся списки импортов на сохранённых путях и выполняем поиск, если ни один не подтвердился. Отдельно оцениваем правила: самый короткий путь, три кратчайших, жадный выбор по устойчивости к единичному изменению, жадный выбор с учётом прошлых Git-изменений. Функция выигрыша — вероятность наличия хотя бы одного неизменившегося пути. Половина массы распределения назначается прежним Git-изменениям, половина равномерно гипотетическому изменению одного исходного модуля-кандидата. При отсутствии истории используется только вторая часть. При равенстве сохраняется более короткий путь и затем лексически первый. Заполняем слоты и при нулевом приросте. Распределение — допущение модели потерь, проверяем полезность на фактическом будущем.

Первичный контраст — историческое покрытие минус три кратчайших по доле положительных ответов, которые можно вернуть без чтения содержимого файлов после обновления. Вторичные — доля повторно прочитанных файлов при проверке точных рёбер, прежние ложные ответы при слепом использовании памяти, фактический размер записи, число случаев с альтернативами. Для G3 положительный ответ после fallback проверяется против независимого полного обхода нового снимка; обнаруженное расхождение ведёт к исправлению реализации с явной записью. Единица неопределённости — репозиторий, до шести окон и повторяющиеся запросы зависимы; показываем разности с усреднением по репозиториям и исходные числа. Анализ источников расхождений разведочный. Статистика A и B выводится отдельно. Один локальный Git workspace на этом диске; открытые проекты, никакие команды из исходников не выполняются. Нет LLM, платных вызовов или метрики починки кода.

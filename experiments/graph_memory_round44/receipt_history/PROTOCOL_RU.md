# Запись прежних подтверждённых квитанций редактора в память

После положительного результата хранения нескольких наблюдений проверяем независимый фактор источника в той же панели. До оценки новой политики фиксируем основной контраст «LRU по просмотрам и прежним квитанциям» минус «LRU по просмотрам» при одинаковом глобальном писателе 8 192 байта и читателе 2 048 байт. Основной исход — безопасная востребованность сверх собственной квитанции текущей правки, средняя по 37 задачам. Оцениваем парный 95%-й интервал с перевыборкой целых задач, 10 000 повторов. Вторично рассматриваем вложенные ранее отложенные 1 071, основные 676, открытые и прослеженные до конца окна, число востребованных строк, байтов и полностью покрытых просмотров. Сохраняем возможность отрицательного результата из-за вытеснения более полезных чтений.

Три политики с LRU — только просмотры, только прежние успешные квитанции, оба источника. Четыре заранее заданные ёмкости записи на все пути одновременно — 2, 8, 32 КиБ и отсутствие ограничения. Используем реальное двоичное представление и проверку целых событий R44. Исходники разных наблюдений с одинаковыми координатами и содержимым получают одинаковый приоритет. При начале старой попытки записи весь соответствующий путь отзывается. При его ответе на успешную подтверждённую замену прежняя версия пути также очищается. Только затем соответствующие авторизованные писатели получают строки показанной этой операцией квитанции. Явный вход для парсера — содержимое квитанции и привязка к успешному действию, уже согласованная по номеру, пути и двум идентификаторам. Принимаем ровно один ожидаемый заголовок выдачи, единую непрерывную последовательность нумерованных строк, отсутствие маркеров отсечения и совпадение с проекцией информативных строк R37. Если условие нарушено, пропускаем весь квитанционный фрагмент. Исторический снимок до или после старой операции не передаётся писателю. Целевые нативные версии открывает отдельный оценщик после замораживания каждого прогноза. Дополнительно оцениваем точность всех подготовленных квитанционных строк по фактической версии непосредственно после их создания.

Внутри незавершённой операции не восстанавливаем старые состояния. У каждой целевой операции глобальная память фиксируется до появления её пути и координат во входе механизма вытеснения. Квитанция самой рассматриваемой операции используется только для вычитания уже выданных строк при выдаче и заведомо не может быть старым источником. Разрывы и непрозрачные действия очищают состояние во всех трёх режимах. Одинаковые readback, mapping, бюджеты, критерий пригодности, строй и метки спроса у всех писателей. На уровне каждого случая фиксируем точное равенство строк контрольного писателя уже подписанным результатам R44. Отдельно считаем парные результаты без лимита читателя.

Повторное использование публичной панели и ранее известный контроль позволяют изучать источник улучшения, а для оценки переноса потребуется независимая среда. Дату в название работы не включаем.

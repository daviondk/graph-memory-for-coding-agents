# Повторение

Для независимой проверки подписанного результата нужны Python со стандартной библиотекой и место для кратковременных SQLite-файлов. Команды выполняются из каталога исследования.

```powershell
python -B verify.py
python -B verify_states.py
Get-FileHash -Algorithm SHA256 -LiteralPath manifest.json
```

`normalized.json.gz` — JSON-массив из 1 207 траекторий. Индекс массива задаёт анонимный номер траектории. Каждая траектория — список закрытых групп. Группа содержит [[дельты], [эталонные флаги]]. Запись дельты состоит из номера локального источника, номера локальной цели и знака (+1/−1). Запись ненулевых флагов состоит из номера вершины и числа от 1 до 3. Бит 1 означает исходящее свидетельство, бит 2 — входящее. `verify.py` также строит канонический digest по мультимножествам операций внутри каждой границы, SHA256 `320c90bab604866d23bf84db32e6eff0c857ca1adb7d5d7f077446325ef5326a`. Он остаётся сопоставимым, если повторное извлечение из архива поменяет порядок обхода множества одновременно наблюдаемых значений.

Для нового хронометража используйте сборку SQLite с виртуальной таблицей dbstat и Python с NumPy для расчёта интервалов. В исходном окружении обе зависимости доступны в указанном интерпретаторе. Каталог результатов должен быть новым. Код проверяет хеш входной проекции до открытия баз и точное равенство каждого словаря вне таймера.

```powershell
$runner='D:/CodexResearch/x20-isetrace-e5-gpu/venv/Scripts/python.exe'
$out=Join-Path $env:TEMP ('sql-flow-'+[guid]::NewGuid())
& $runner -B replay.py --out $out
& $runner -B analyze.py --out $out
```

`run-REP-READS.json.gz` содержит значения в наносекундах для каждой траектории и плана в порядке записи, выдачи, проверки, первого обхода конечных состояний после переоткрытия и второго обхода. Внутри каждого файла имеются EXPLAIN QUERY PLAN, размеры объектов dbstat, число свободных страниц, стоимость schema/open и checkpoint. `results.json` включает отношения сумм с интервалами. `pair.sqlite`, `ends.sqlite` и `co.sqlite` — финальные снимки первой реплики с одним чтением, доступны в режиме только чтения.

Для повторного извлечения из публичных архивов нужны входные файлы и зависимости исходного R44/flow_view и R41/prefix_native. В новом рабочем каталоге той же структуры запустите `$runner -B fixture.py` до запуска SQL. Ровно одна стадия читает историю как данные. Она проверяет исходный шард и совпадение дельт с прежним инкрементальным индексом. Независимый повтор SQLite и обе проверки выше работают на компактной переносимой проекции.

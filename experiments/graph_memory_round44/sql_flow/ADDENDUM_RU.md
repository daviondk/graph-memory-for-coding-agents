До запуска SQLite добавляем ещё один заранее определённый план чтения для той же индексированной таблицы пар. За одно чтение он проходит по видимым взвешенным парам один раз, объединяя биты в словаре приложения. Это проверит зависимость результата от реализации запроса. Основное сравнение двух индексных DISTINCT с таблицей счётчиков сохраняется. На пустой схеме SQLite показал, что константа в списке SELECT DISTINCT приводит к временной сортировке. Для основного плана выносим константу направления за подзапрос DISTINCT и проверяем отсутствие временного B-дерева в EXPLAIN QUERY PLAN.

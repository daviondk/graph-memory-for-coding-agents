# R44. Физическое представление двух признаков FEEDS в SQLite

До измерения фиксируем все 1 207 траекторий и 31 279 закрытых групп из подписанного R44/flow_view. Извлекатель преобразует наблюдавшиеся события в единичные добавления и отзывы свидетельств между локальными номерами вызовов. Программа независимо сверит дельты, активные веса и флаги с прежним парным индексом R21/R44. В открытой постановочной проекции оставляем обезличенный номер траектории, порядок групп, локальные номера двух концов, знак и эталонные ненулевые флаги. Названия, аргументы, текст, идентификаторы сессий и вопросы в проекцию не включаем. Проекцию фиксируем хешем до измерения SQLite.

Вход API записи — полная группа подписанных единичных дельт одной траектории. Выход чтения — отображение всех активных локальных вершин этой траектории в два бита; отсутствующие ключи имеют значение 0. Проверяем точное совпадение полного отображения после каждой группы, включая пустые и обнуляющие, во всех планах. Один план хранит взвешенные пары с ключом (траектория,источник,цель) и обратным покрывающим индексом. Для чтения он использует два индексных DISTINCT без соединения и сортировки. Основная альтернатива хранит только вершины со счётчиками исходящих и входящих свидетельств и в транзакции пакетно применяет суммы по вершинам. Группировка знаковых весов выполняется в приложении у обоих основных планов. Дополнительные варианты материализуют те же счётчики с группировкой SQL GROUP BY из временной таблицы дельт либо обновляют в одной транзакции индексированные пары вместе со счётчиками. В варианте совместной записи приложению доступны идентичности пар. Одинокие счётчики отвечают только на запрос признаков.

Основной показатель — отношение суммарного времени «индексированные пары / счётчики» при одной выдаче всех флагов после каждой транзакции. Вторичные — четыре реальные последовательные выдачи, отдельно запись и чтение для обеих нагрузок, общий объём файлов и по объектам dbstat. Сравнение синхронного SQLite на одном хосте и фиксированном корпусе исследовательское. Используем независимые базы планов и нагрузок, одинаковую страницу 4 KiB, WAL, synchronous=NORMAL, фиксированный размер кеша, без параллельной записи, в одном процессе CPU. Транзакция на каждую группу, включая пустые. Время записи охватывает подготовку обновлений, BEGIN, SQL, COMMIT. Чтение включает материализацию всего словаря. Проверку результата выносим из таймера. Стоимость одноразовых open/schema, выделения событий/дельт, очистки WAL и проверки показываем отдельно от обслуживания. Внутри каждой реплики порядок планов чередуем детерминированно по траекториям. Две независимые реплики с новым файлом на план/нагрузку и обратным порядком; общие 10 000 парных bootstrap-перевыборок целых траекторий. Отдельно снимем первый полный обход после закрытия и нового подключения и повторный с прогретым соединением на конечных состояниях всех траекторий. Файловый кеш ОС принудительно не очищается. Проверим план индексного доступа EXPLAIN QUERY PLAN, физические страницы после checkpoint(TRUNCATE), freelist и размер WAL до checkpoint. Сохраним поштучные времена, проверяющий код, регистрацию и манифест. Дельты и эталоны будут доступны для независимого повтора без исходных историй или модели. Сопоставимость прежних признаков и качества ранжирования следует из R44/flow_view и R43/relation_budget; новая оценка ранжирования не проводится.

# Когда кодовому агенту стоит перечитывать прошлый эпизод

На всех 99 задачах SWE-ContextBench Lite выборочное чтение карточек прошлых сессий дало **73 верных выбора при 31 обращении к Qwen 27B**. Если читать карточки для каждой задачи, получаем 75 верных выборов при 99 обращениях. Если во всех случаях брать первую выдачу поиска, получаем 65. При том же числе обращений, распределённых случайно внутри тех же репозиториев, ожидаемый результат — 68,69. Эксперимент оценивает выбор релевантного эпизода по официальным связям между задачами. Патчи и долю решённых задач здесь не оценивали. [Исходный бенчмарк](https://arxiv.org/html/2602.08316v3) · [Протокол](PROTOCOL.md) · [Результаты](results.json)

## Правило и цена чтения

В памяти 300 исторических сессий. Для нового запроса сравниваются первые места трёх уже посчитанных выдач — BM25 по результату и правкам, поиск по трём лексическим полям и объединённый лексико-семантический поиск. При совпадении трёх ID агент может принять результат поиска. При расхождении 27B выбирает среди тех же пяти карточек, что и в контроле. Первая пятёрка содержит связанную сессию в 85 из 99 задач. Новое правило расчётно воспроизведено по зафиксированным выдачам и реально сгенерированным ранее ответам. Все модели, порядок вариантов и индивидуальные расходы контролей сохранены. Новых обращений к модели этот эксперимент не потребовал. [Входные ID и ранги](inputs.json.gz) · [Решения до оценивания](decision-seal.json)

Экономия входных токенов 27B составила 68,95%, выходных — со 198 до 62. Эти числа учитывают обращения к модели-переранжировщику. Сбор карточек и поиск по полям требуются в обеих ветвях. Дополнительное сравнение ID дёшево, но для работы третьего сигнала нужно иметь выдачу BM25 по результату. Полное время и денежную стоимость всей системы из этих показателей не выводим. Recall получил полные тексты историй и исходное описание запроса по правилам авторской реализации. Наш поиск использовал карточки и запросы с замаскированными явными ссылками на задачи. ## Где помогает вызов модели

На 31 случае расхождения выдач первая позиция поиска верна в 11 случаях, выбор 27B — в 19. Это восемь выигрышей без потерь. На оставшихся 68 случаях поиск верен в 54, постоянное чтение — в 56. Для главного сравнения с постоянным чтением изменились девять ID, наблюдались один выигрыш и три потери по Match@1. Разность −2,02 п.п., двухсторонний точный McNemar p=0,625. При повторной выборке 12 репозиториев 95%-й интервал для разности по задачам [−12,90; +1,18] п.п. При равном весе репозиториев разность составила −15,05 п.п. Два небольших проекта, Flask с одной задачей и Sphinx с двумя, особенно влияют на эту оценку. Сохранение качества требует независимой проверки с заранее выбранным допустимым снижением. [Парные решения по задачам](per_item.json.gz)

При случайном выборе ровно того же числа задач в каждом проекте 31 обращение дали бы в среднем 68,69 верного ответа и 103 342 входных токена. Точная вероятность получить как минимум наблюдаемые 73 — 0,00785 при этой случайной схеме. Распределение рассчитано перебором чисел выигрышей и потерь по каждому репозиторию и воспроизведено независимой динамической программой. Эта вероятностная оценка характеризует распределение фиксированного числа обращений на этих 99 задачах. [Оценивание](grade.py) · [Независимая проверка](verify.py)

Дополнительно проверены две стратегии оценки уверенности при тех же 31 обращении и том же бюджете каждого проекта. Обращение при малом пересечении трёх первых пятёрок дало в среднем 67,09 ответа (66–68 при всех разрешениях ничьих). Обращение при сильном понижении исходного лидера отдельным переранжировщиком MiniLM-L12 дало 70,08 (69–71). Средние входные расходы — 102 387 и 106 540 токенов 27B соответственно. Таким образом, на этой выборке варианты разрешения ничьих у обоих контролей дали меньше 73. У второго контроля есть дополнительная стоимость MiniLM. Эти сравнения зафиксированы после основного результата и требуют внешнего подтверждения. [Дополнительный протокол](CONTROL_PROTOCOL.md) · [Полные распределения](control-results.json)

## Сравнение с публикациями

Chen et al. сообщают 66/99 для REM с ручной схемой и 68/99 для автоматически выбранной схемы. Обе версии дают модели пять кандидатов. Из-за ошибок при извлечении документов авторы получили 267 из 300 карточек во втором варианте. Поиск REM использует Titan, другое представление эпизода и иной переранжировщик. В проверенной статье, приложениях и на страницах бенчмарка индивидуальных ответов REM не найдено. При одной и той же паре маргинальных сумм 73 и 68 возможный двухсторонний точный McNemar лежит от 0,0625 до 0,597. Это пределы математически допустимых попарных исходов при гипотетически одинаковой метке. Внутри нашей системы сравнение с постоянным чтением, а также с воспроизведённым Recall, действительно парное. [REM, таблица 1, приложения D и E](https://arxiv.org/html/2610.27377v1) · [Данные бенчмарка](https://huggingface.co/datasets/jiayuanz3/SWEContextBench)

Закреплённая таблица официальных связей содержит три задачи с двумя допустимыми источниками. Если засчитывать только одну связь на задачу, наш результат лежит между 71 и 73 из 99 при любом таком выборе. В двух задачах scikit-learn есть и доступная сессия, и отсутствующий в архиве второй источник, который REM считает целевым. Это объясняет, как наш показатель доступности «есть хотя бы один источник» может дать 99/99, когда REM сообщает две задачи без доступного oracle. Состояние базы материалов, правила разрешения нескольких связей и отсутствие ответов конкурента ограничивают сравнение с опубликованным максимумом. Для доли задач с применимым исправлением REM приводит отдельные измерения. [Официальные связи и проекция](label-source.json) · [Таблица 4 REM](https://arxiv.org/html/2610.27377v1#A3.T4)

## Перенос и роль графа

На 57 задачах прошлого опыта у 4B было 44 совпадения с настоящим графом переходов, 44 с одними вершинами и 45 с переставленными связями. Выборочное чтение дало **45/57 в каждой из трёх ветвей**. Число обращений каждой ветви сократилось с 57 до 14, входные токены — с 80 371 до 18 978. Правило распределяет чтения. Измеримого вклада топологии в таком сравнении не видно. Эти 57 задач входят в 99, ещё 33 непересекающиеся задачи участвовали в R59 при исследовании кандидатов. В сумме R59 уже охватывал 90 из 99. Архивные 27B-прогоны существовали для всех 99 до разработки нового правила. [Эксперимент с графом](../../graph_memory_round59/agent_benchmark/REPORT_RU.md)

Как второй переранжировщик использован MiniLM-L12. На Lite постоянное чтение дало 40/99, выборочное — 65/99, первую позицию без чтения правильно выбрали также в 65 случаях. На 258 других уникальных задачах полной опубликованной выборки, при сохранении старого пула из 300 сессий, постоянное чтение дало 9/258, выборочное 12/258, исходная выдача 11/258. Только для 13 из 258 задач в пуле вообще есть положительная сессия. Среди этих 13 результаты равны 9, 12 и 11. BM25 по результату и правкам также даёт 12/13. Здесь представлены всего два проекта, поэтому эти данные слабо характеризуют перенос метода. Критерий наличия положительной сессии применён после фиксации решений. ## Как повторить

Из этой папки выполните `python -B verify.py`. Нужна только стандартная библиотека Python. Проверяется SHA каждого входа и кода, 357 решений, расходы модели и точное распределение случайного контроля. Пересчёт с включёнными данными выполняют `python -B decide.py` и затем `python -B grade.py`. Для извлечения компактного входа из закреплённых таблиц и существующего локального архива нужны PyArrow и пути из `export_ids.py`. Выполните последовательно `python -B export_ids.py`, `python -B decide.py`, `python -B export_ids.py --labels`, `python -B grade.py`. Протокол и правило зафиксированы до подсчёта новых результатов. Исходный результат 27B на этом наборе был известен. [Контрольные суммы источников](source.json) · [Методика планирования, Kassis et al.](https://arxiv.org/abs/2609.00065)

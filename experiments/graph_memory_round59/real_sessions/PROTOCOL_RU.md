# Перенос равенств строк через перезапуск на записанных действиях SWE-agent

Вход — уже проанализированные в R57/R58 108 обезличенных траекторий двух исполнителей на 54 одних и тех же задачах. У нас есть адреса фактически показанных строк, размеры и порядковые идентификаторы равенства текста. Новая гипотеза: вместо сохранения текста можно сохранить компактные классы равных строк по разным наблюдавшимся адресам. При первом реальном запросе к классу исходная строка всё равно читается из рабочего дерева, после чего её результат обслуживает остальные адреса класса до следующего барьера. Никакого идентификатора будущего содержимого или ответа с диска для выбора сохраняемых классов. Никаких новых запросов к моделям.

**Рестарт и точность.** Политика получает префикс, окончившийся сразу после floor(W/2) показов редактора; при нуле показов граница находится до первого события. Расписание рестарта задаёт наблюдатель, политику не информируют о числе оставшихся окон. Включаются все сессии. И перед, и после рестарта каждый консервативный барьер R57 полностью очищает кэш и все связи. Для всех альтернатив свободен одинаковый растущий вплоть до барьера оперативный кэш строк, заполненных уже после рестарта. При запросе адреса план чтения определяется до наблюдения ответа. Для отложенного класса инициируется только чтение первого запрошенного представителя; две строки из одного класса внутри единственного показа могут разделить ответ. В независимой проверке сравниваем выданный идентификатор с наблюдаемым для каждой строки. При любом несовпадении сообщаем ошибку; метрику для метода с ошибкой нельзя трактовать как точное обслуживание.

**Основная сравниваемая пара.** При 1 КиБ лимита селективная отложенная таблица эквивалентности против пустого переноса с обычным чтением по требованию. Таблица содержит только классы как минимум двух виденных адресов. Для класса размера k со строкой длины L оптимистическая польза равна (k−1)L байт, если будут запрошены все адреса. Обходим классы по убыванию этой величины, при равенстве по более недавнему показу, затем по лексикографическому списку адресов. Принимаем класс целиком, если новый блок укладывается в 1 КиБ, а прирост двусторонней платы за метаданные строго меньше оптимистической пользы. Заголовки полной таблицы оплачиваются один раз. Это эвристика отбора из прошлого, вероятность будущих запросов не оценивается. Потенциально неподходящее для частной программы предположение стационарного файла проверяем на корпусе через полное совпадение выдачи и сообщаем ограничение.

**Контроли.** (1) Чтение по требованию с пустым переносом. (2) Совпадающий набор классов с предоплаченным текстом каждого класса, на естественном размере, который может превышать 1 КиБ; отдельно показываем максимальный размер. (3) Обычный недавний кэш, упорядоченный по файлу и строке с компактным хранением равного текста R58, при 1 КиБ. (4) Тот же компактный снимок всех видимых к барьеру строк без потолка. (5) Таблица всех дубликатов в том же порядке при том же потолке, исключив проверку окупаемости. Для всех режимов списки файлов, их UTF‑8 имена, varint адресов, словари и полезные байты включены. Ничего не записываем для пустой таблицы; естественную длину оплачиваем за запись и загрузку. Равенства на стороне получателя возникают только после фактической передачи текста или чтения представителя. Полные оригинальные байты отсутствуют, поэтому восстанавливаем длину определённого сериализуемого формата из метаданных. Оригинальную скорость I/O не измеряем.

**Исходы.** Первичный исход — двусторонняя плата за снимок плюс байты результата свежих чтений. В каждом окне сервер может заменить равные результаты ссылкой на предыдущую строку того же ответа, если это короче литерала (кодировка `uleb(2L)+body` или `uleb(2*backdistance−1)`, клиент знает запрошенные адреса по порядку). По всем политикам вторично считаем сырой объём исходного чтения, число строк и длительность логической жизни связей. Отдельная чувствительность — такое же общее транспортное сжатие между окнами; в этом режиме словарь связывает только фактически переданные по каналу строки, состояние словаря изначально пусто. Размер запросов/сетевых заголовков в первичном сценарии не оплачивается; дополнительно считаем для каждой непустой дозагрузки размер отправки адресов как полный путь и varint номеров строк в порядке возрастания с дельтами. Для одинаковых путей в одном показе оплачивается одно имя. Заранее фиксируем срезы 1, 4 и все доступные пострестартовые показы. Если показов меньше выбранного горизонта, берём все имеющиеся. Семейство с горизонтом редко встречающегося класса дополнительно не отбираем.

Публикуем парные итоги по всем сессиям, по проекту и отдельно среди сессий с непустой таблицей; условный срез диагностический. 95% эмпирический парный бутстрэп разности байтов между первичной парой на одном issue, 20 000 выборок с возвращением, seed 59021 и блок из обоих исполнителей; сообщаем выигрыши, ничьи, потери. Обязательно показать цену сброса на ближайшем барьере, число источников фактического эффекта, а также нулевые/отрицательные исходы. Проверка ранга, качества патча и реального обслуживания диска сюда не входит.

# Проверка согласования множеств и стоимость вычислений

Фиксация до замера времени. Результаты по числу байтов R59/reconcile уже известны. Цель репликации — личная цена точного восстановления XOR из кешированных событий сравнительно с сильным полным списком (лучший из абсолютных varint, разностей и bitmap). Первичная нагрузка — все 12 внешних плотных историй R58, 1 024 байта дополнительного кеша сверх общего write-warmed B8. Вторично 4 096 байт на тех же запросах. Исторический источник, физическая схема SQLite, tie-break и формат берём без изменений. Время и вычислительную нагрузку ещё не смотрели.

Пять полных блоков. Каждый блок проходит все 12 проектов в заранее воспроизводимом случайном порядке (seed 59371). После физического повторного открытия в половине принятых событий загружаем актуальные таблицы из SQLite для прогрева кэша страниц, в отдельном и одинаковом режиме для обеих политик. Исходные записи после границы выполняются одним реальным писателем; читатели получают событие только после успешного commit. При каждом запросе и изменении порядок четырёх сочетаний (ёмкость, метод) случайный. Сверяем точные пары ID/балл с полной историей, полученные BLOB, их размеры, вызовы SQLite и события восстановления по исходному покадровому журналу. Публикуем медиану пяти сумм по всем проектам, отдельные блочные значения, время чтения с SQL и обработкой сканирования, время обновления каждой схемы после успешно принятой общей записи, отдельно общий B8 и сам писатель. Метрика времени — perf_counter, основной endpoint чтения + поддержание кеша; общие source writes показаны, но исключены из парного endpoint. На Windows дополнительно измеряем процессорные циклы текущего потока через QueryThreadCycleTime при наличии; на других ОС — thread_time_ns с указанием единицы. Одинаковая инструментальная цена контрольной оболочки, без коррекции результатов путём её вычитания. Не делаем вывода о холодном диске, параллелизме и времени решения LLM-задачи.

Независимые тесты включают все подмножества малых корректных множеств, заданные ручные случаи в окрестности varint-границ и больших чисел, отрицательный пример нарушения условия «известное множество является подмножеством истинного» и отдельно работу на SQLite при откате, повторной доставке уже подтверждённого ID, конфликте и нескольких новых записях после перезапуска. Проверяем реальное сжатие полного списка, однозначность восстановления при достаточном числе моментов и переход на полный список при неполноте. Оптимизации стоимости сканирования не входят в заранее заявленный результат.

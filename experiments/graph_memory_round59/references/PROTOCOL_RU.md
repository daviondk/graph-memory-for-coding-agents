# Восстанавливать память агента по ссылкам на неизменяемые события

Снимок R58 заново записывал состав события, которое уже находится в обязательном долговременном журнале. Проверим при одних и тех же выбранных событиях гипотезу, что достаточно сохранить их адреса и при первом обращении к участвующему файлу загрузить подходящие тела. Если зарядить всю границу SQLite, экономия может частично объясняться более компактной кодировкой; время и число SQL могут измениться в противоположную сторону. Архив хранит бинарный SHA, упорядоченные составы и инвертированный список номеров изменений по пути.

**До сбора новых исходов.** Основной выбор — ровно те события, которые раньше помещались в 1 КиБ копируемого снимка при выборе по прошлой активности за 128 событий. Отдельно проверяем полный набор живых событий R58. Для каждого выбора сравниваем естественную копию тел, ту же копию с выбором более короткого из raw/zlib level 1, компактные ссылки с немедленной загрузкой и те же ссылки с загрузкой при первом обращении; холодный старт служит общим контролем. Кодек адресов выбирает самое короткое из абсолютных ID, разностей ID, разностей пропущенных ID и битовой карты, с тем же дополнительным вариантом zlib. Режим можно указать в четырёхбайтовом magic без дополнительной оплаты; все модели имеют одинаковые размер 40-байтового заголовка с CRC и проверку 20-байтовой ревизии. При прочих равных сортируем по стабильному ID кодека. Распакованные выбранные события остаются в RAM до конца сессии. Неизменяемость исходников, известная общая нумерация и общедоступность исходного SQLite — условия метода.

**Первичная метрика.** Сумма фактически переданных BLOB: сохранение + восстановление + проверка ревизии + чтение указателей и тел до конца следующей сессии. Первичный контраст — ленивые ссылки против сжатой копии при фиксированном отборе 1 КиБ на трёх исходных длинных историях. Покажем представления до и после сжатия, SQL-вызовы, ранние горизонты 0/1/4/16 и конец, память и ограничения. Слой совпадений и горячая запись новых событий одинаковы. Независимая проверка по 12 другим проектам — в плотном и редком расписании, без изменения правил после первичного сравнения. Во всех запросах точные восемь ID и баллы. По возможности проведём физические проверки SQLite при неверном/устаревшем снимке и проверим алгебраическое равенство стоимостей по трассе. Материалы по разделению ключей и значений и инкрементальным снимкам ограничивают утверждение о новизне общей идеи.

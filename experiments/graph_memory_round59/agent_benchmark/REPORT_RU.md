# Помогают ли связи между прошлыми чтениями и изменениями найти нужный опыт

На **57 задачах SWE-ContextBench Lite** прежние связи между чтением и последующим редактированием дали правильную историческую траекторию на первом месте в **44 случаях**. С теми же адресами без связей получено **44/57**, при перестановке концов рёбер — **45/57**. Даже когда вход с настоящей и переставленной структурой различался (53/57), выбранная траектория изменилась лишь на одной задаче. Цена вопроса и начальный выбор пяти кандидатов были одинаковы во всех трёх ветвях. [Протокол](PROTOCOL_RU.md) · [Метрики](results.json)

## Постановка и контроль

SWE-ContextBench проверяет перенос прежнего опыта в новую задачу программирования. Для отдельной задачи поиска авторы оценивают попадание первой исторической сессии в множество связанных задач, размеченных через GitHub issues и PR. На диске доступны 300 выпущенных исторических сессий Lite и авторская таблица связей. Для текущего анализа до выдачи и проверки ответов выбраны 57 из 99 новых задач, относящихся к восьми библиотекам математики, визуализации, массивов, документации и тестирования. Среди 58 задач этих репозиториев одна не прошла текстовый фильтр из протокола. У каждой из 57 есть релевантная сессия в полной библиотеке. Прошлые эксперименты уже публиковали результаты по общему Lite, поэтому этот опыт нельзя назвать независимой репликацией на новом датасете. Новые параметры зафиксированы до оценки и не обучались на релевантности. [Авторы, таблица 5](https://arxiv.org/html/2602.08316v3#S3.T5) · [Закреплённый датасет](https://huggingface.co/datasets/jiayuanz3/SWEContextBench/tree/12c65bd15e2559bc808065565e941ee7bbbd008f)

Из 170 исторических трасс подходящих проектов извлечено 416 различных рёбер, сохранённых после ограничения до шести на одну сессию. Ребро задаёт чтение одного файла в пределах восьми инструментальных действий до изменения другого либо того же файла. Оно указывает на последовательность вызовов, а не доказывает причинную связь. Остальные признаки — наблюдаемые адреса и короткие идентификаторы прежних правок. Для каждого нового вопроса использована прежняя пятёрка гибридного поиска по полной библиотеке, затем одна и та же локальная Qwen3-4B-Instruct-2507 Q4_K_M независимо выбрала один из пяти номеров в трёх условиях. Из 285 предъявлений карточек 275 имели разрешённый текст, 252 — хотя бы одно ребро. Десять карточек вне тематического фильтра были одинаково обезличены во всех трёх условиях. При перестановке сохранялись входящие и исходящие степени, словарь адресов, число связей и порядок карточек. В 4/57 вопросах перестановка сохранила полный вход. Основная пара «настоящие связи против перестановки» дала 0 улучшений, 1 потерю и 56 совпавших исходов. Разница −1,75 п.п., кластерный 95%-й бутстрэп по восьми проектам [−6,45; 0,00] п.п., точный двусторонний McNemar p=1. Против тех же вершин без рёбер изменились три выбранных ID, авторская оценка сохранилась во всех трёх случаях. Против Recall hybrid результат выше на 4 задачи (8 улучшений, 4 потери, интервал [−2,00; +20,00] п.п.). При сравнении с сильнейшим доступным прежним читателем 27B на той же пятёрке получено 0 улучшений и 3 потери. Эти два последних сравнения меняют несколько элементов системы. Добавочный эффект конкретного графа измеряет основная пара. [Решения и метки по каждой задаче](scored.json.gz) · [Журнал исходных ответов](responses.jsonl)

Всего получено 167 новых ответов на RTX 3090 из 171 назначения. Байт-в-байт одинаковые токенные входы использовали одну детерминированную генерацию. На одну ветвь пришлось ровно 80 371 входных и 114 выходных токенов на все 57 задач. Фактически сервер обработал 236 590 входных и 334 выходных токена, все ответы содержали допустимый номер. Прежний полнотекстовый Qwen 27B использовал 198 433 входных токена на тех же задачах. Новый прогон использует исходные выборы Recall из закреплённой версии опубликованного кода. Табличные числа публикаций с другими знаменателями не используются для парных сравнений. В частности, REM сообщает 68/99 на всём Lite, индивидуальные решения в проверенном публичном материале отсутствуют. Текущая работа измеряет выбор сессии по авторской связи, не запуская решение GitHub-задачи. Ни изменение процента прошедших тестов, ни победа над REM из этих результатов не следуют. ## Повтор

Команда `python -B verify.py` проверяет идентичность токенных бюджетов, переадресацию рёбер, хеши входов, ответов и итоговые счётчики в сохранённой копии. Для повторного запуска понадобятся закреплённые библиотеки и исходные ранги [предыдущего опыта](../../sota_round/swe_context/README.md), `pyarrow` для считывания оригинальной таблицы, локальные llama-server и GGUF из [R52](../../graph_memory_round52/reranker/common.py). В чистой копии каталога с исходниками последовательность команд — `python -B roster.py`, `python -B graph.py`, `python -B run.py`, `python -B grade.py`, `python -B verify.py`. Каждый новый ответ записывается сразу; возобновление использует только совпавшие модель, программу и целиком запечатанный набор входов.

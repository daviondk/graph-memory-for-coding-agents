# От выбора прошлой траектории к проверяемой роли связей между действиями

SWE-ContextBench Lite определяет для каждой новой задачи допустимые прошлые эпизоды через опубликованные отношения между задачами. Первичная метрика — Match@1 по официальному множеству идентификаторов. Вся Lite содержит 99 новых задач и 300 исходных сессий. До извлечения новых связей и сравнения с метками зафиксировано 57 задач из восьми библиотек (математика, графики, массивы, документация и инструменты тестирования), по заранее заданному списку проектов и текстовому фильтру. Получился поднабор официального Lite. Известны прежние агрегаты по полным 99, те же задачи могли участвовать в прошлых рейтингах. Новый метод не обучается и не настраивается по этой выборке. Проверяется получение исторического контекста, без исполнения патчей. [Исходная публикация и таблица 5](https://arxiv.org/html/2602.08316v3#S3.T5)

**Механизм.** В прошлой траектории явное чтение файла связывается с последующим редактированием или созданием файла, если они разделены максимум восемью действиями инструментов. Для каждой пары учитываем частоту и последнее такое событие. На траекторию без доступа к текущему вопросу сохраняются до шести частых различных направленных пар с предпочтением более позднего наблюдения при равенстве. Для редактируемого пути разрешены до четырёх собственных идентификаторов из уже наблюдённых изменений. Полное содержимое команд, патчей, инструментальных ответов и внутренних рассуждений не передаётся. Слова и сопоставление имён извлекаются только у пригодных исторических эпизодов. Остальные кандидаты могут быть возвращены базовой выдачей как анонимный ID с закрытым текстом, чтобы не изменить список и покрытие.

**Основная пара.** В пяти заранее упорядоченных кандидатах из прежней hybrid fusion каждый получает одно и то же короткое описание прежней задачи и результата, одни и те же имена прочитанных и изменённых путей и идентификаторы. В первой ветви показываем реальные связи между номерами путей, во второй циклически сдвигаем последовательность целевых номеров внутри каждой карточки, сохраняя длину и степени обеих сторон. Такой контроль проверяет добавочную ценность самих связей среди уже сохранённых источников и приёмников. Повторные номера могут сделать перестановку неразличимой. Третья ветвь скрывает таблицу связей, оставляя те же вершины. Первая и третья образуют вторичное сравнение. Никакие другие признаки карточек по условию не меняются.

Фиксируем slate как исходную пятёрку fusion, порядок предъявления как SHA от номера задачи и ID кандидата. Модель Qwen3-4B-Instruct-2507 Q4_K_M, GPU RTX 3090, greedy, один вызов и один номер из пяти, максимум восемь сгенерированных токенов. Общая квота в каждом вопросе по всем ветвям, выравнивание пробельными токенами в секции связей. Недопустимый ответ заменяем исходной первой позицией fusion, объявляем число замен. Полностью одинаковые входные токены означают одну новую генерацию. Сначала фиксируем токены и хеши входов, затем ответы, затем обращаемся к авторской таблице связей.

**Сопоставления.** На тех же 57 ID пересчитываем Recall keyword и hybrid по опубликованной реализации (ранее атомарно сохранённые результаты конкретной версии), прежние BM25, MiniLM, fusion и прежние Qwen 27B со всеми доступными выборами. Указываем структуру shortlist, исходную библиотеку и разные расходы моделей, включая совпадение серьёзного контроля Qwen 27B по той же пятёрке. Опубликованная REM сообщает 68/99 по всему Lite, индивидуальный вывод в ранее проверенном релизе не обнаружен. При любом результате этот агрегат не будет использован как парный контроль другого знаменателя. Для основной пары показываем разные top-1, улучшения и потери, случаи без смены исхода, разницу долей, bootstrap по проектам, табличные итоги по всем проектам и верхнюю границу по покрытию пятёрки. Перенос на другой решатель и качество исправления не проверяются.

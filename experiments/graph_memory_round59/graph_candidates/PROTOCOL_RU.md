# Меняет ли граф поиска состав пяти предложенных траекторий

В этом опыте граф применяется на этапе формирования списка, до выбора одного ответа. Источник — закреплённые 300 прежних траекторий и 99 задач официального SWE-ContextBench Lite. Перенос касается других задач и целиком других репозиториев по отношению к опыту соседнего каталога. Сначала проверены только названия и тематические ограничения. Независимая целевая подвыборка задаётся номерами 2–7, 9–24, 28, 32–37, 52, 54, 55, 58 из официального порядка. Темы включают ORM, схемы данных, формы, отображение параметров, настройки Pylint и обработку текста. Номера и проектные множества не пересекаются с первыми 57. Формирование выборки предшествует просмотру её старых меток или ответов. Прежняя публикация уже сообщала другие результаты по полному Lite из 99 задач, поэтому это удержание по проектам для предложенного метода, с известным общим корпусом.

**Предсказание.** Сохраняем первые четыре идентификатора прежней fusion. Простая схема оставляет исходный пятый. Три конкурирующие схемы могут использовать весь библиотечный каталог для замены пятого места. По каждому разрешённому историческому случаю извлекаем до шести пар «прочтённый путь → позднее изменённый путь» с тем же кодом, который использовался на первых проектах. Позиции с исключённым историческим текстом не имеют поисковых признаков, но могут занимать место в штатном fusion. Отбор разрешённых сессий основан на исторических описаниях, без текущих ответов.

Разбиваем публичный запрос и адреса на идентификаторы, сегменты имён и пути. Оставляем совпадающие токены длиной от трёх, встречающиеся максимум в одной пятой разрешённых документов, с минимумом двух доступных документов для верхнего порога. Вес токена — 1+log((N+1)/(df+1)). Веса оцениваем только по прошлому каталогу. Документу нужны хотя бы два различных лексических совпадения для замены пятой позиции, иначе оставляем исходный список. В плоском варианте глобально ранжируем по сумме весов разных совпавших токенов в прочитанных и изменённых путях и идентификаторах изменений. Графовый вариант добавляет максимальный вес подтверждённой пары различных токенов, один в источнике ребра, другой в его конце. Вес пары — меньший из двух весов. При перестановке используем тот же код и фиксированный циклический сдвиг концов рёбер внутри каждой карточки. При равенстве максимального счёта предпочитаем исходное пятое место, далее лексикографический ID. Ищем среди всех подходящих документов вне первой четвёрки, источники не фильтруются по репозиторию текущего вопроса. Первая пара для интерпретации — настоящий граф против плоского глобального поиска по тем же вершинам. Вторые сравнения — перестановка и исходный fusion.

В каждой ветви предъявляем ровно пять различных кандидатов одному локальному Qwen3-4B-Instruct-2507. На этой стадии предъявляем для всех ветвей только одинаково усечённые историю задачи и результат, 150 токенов на карточку с нейтральным заполнением, без таблицы связей. Порядок пять кандидатов определяется SHA задачи и исторического ID; входная длина и выходной лимит совпадают по ветвям. Различные упорядоченные списки требуют новой генерации; тождественные токенные входы объединяются внутри нового опыта. Ни один старый ответ 27B не переносится на новую пятёрку. Исторический 27B учитывается отдельно лишь со своей первоначальной пятёркой. Один greedy-вызов, до восьми токенов, при некорректном формате берётся первый исходный ID (одинаковая первая позиция всех ветвей).

**Оценка.** Фиксируем все выборы до подключения авторских связей. Первичный исход — доля задач с хотя бы одним правильным историческим ID среди ровно пяти (Hit@5, также coverage@5), вторичный — официальный Match@1 после выбора читателем. Когда размечено несколько релевантных ID, отдельно считаем долю всех релевантных ID, вошедших в пять (Recall@5). Указываем добавленные и потерянные правильные записи, изменившиеся пятые позиции, изменения выбора решателя и исходов по каждой задаче/проекту, парную неопределённость, пересечение с настоящей пятёркой прошлых вариантов и сильнейшие доступные исходные контроли. Результат зависит от четырёх проектов и состава доступных прошлых источников. Табличный REM на 99 задачах описывает иной знаменатель.

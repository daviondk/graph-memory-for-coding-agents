# Исполняемый пилот ClassEval: приносит ли пользу код, который вызывает скрытый метод?

На 61 методе из 32 классов Qwen3-4B-Instruct-2507 прошёл все целевые тесты в **41/61** случае с фрагментом реального вызывающего метода, **42/61** с фрагментом, выбранным BM25, и **41/61** без тела соседнего метода. Первичная разность графового и текстового вариантов равна **−1,64 п.п.**, 95% кластерный интервал **[−5,36; 0,00]**. Был один парный проигрыш, 60 совпадений, точный двусторонний sign-flip по классам дал p=1. Базовый поиск уже учитывал идентификаторы в теле исходного кода и нашёл тот же адрес в 50 из 61 случаев. Наблюдений с реально изменившимся контекстом — одиннадцать в семи классах.

При разрешении до **768 выходных токенов** все три метода дали **43/61**. Графовый и текстовый варианты совпали по полному прохождению на каждом из 61 заданий. Вариант без тела прошёл столько же, хотя состав успешно выполненных методов отличается.

| Память перед генерацией | Прошли все тесты метода | Средняя по методам доля пройденных тестов | Пройдено из 308 тестов |
|---|---:|---:|---:|
| Лучший по BM25 среди реальных вызывающих методов | 41/61 (67,21%) | 77,16% | 237 |
| Лучший по BM25 среди всех соседних методов | 42/61 (68,85%) | 79,45% | 244 |

У графового и текстового плеча одинаковая длина наблюдения в каждом вопросе, в среднем 73,89 нативного токена, максимум 192. Сравнение c вариантом без тела изменяет также длину запроса. Парные разности по полному прохождению: граф против варианта без тела 0,00 п.п. [−9,23; +9,53], BM25 против варианта без тела +1,64 [−7,94; +11,86]. Первичные условия — greedy, RTX 3090, Q4_K_M, максимум 384 выходных токена. Всего 183 назначения и 133 уникальные реальные генерации, 21 626 выданных токенов.

**Что проверялось.** В авторском Python-классе скрыли один метод, сохранив его опубликованный контракт и остальные реализации. В уже доступных соседних методах нашли статические вызовы self.target, cls.target или ClassName.target. В обоих вариантах использовали один и тот же BM25 по коду и документации. Обнаруженная связь в первом варианте ограничивает множество допустимых соседей. Читатель видел класс, поля, контракты, сигнатуры и не более одного фрагмента кода. Целевой код и тесты в запросе отсутствовали. Все адреса и нативные входы зафиксированы до генерации, все ответы — до оценивания. Первичный исход проверяет исходным unittest-классом каждую реализацию после подстановки её тела в неизменённый класс.

**Отбор.** Исходный файл содержит 100 авторских классов. Фиксированный список прикладных и алгоритмических классов исключил 35, ограничение стандартной библиотеки и разрешённых операций ещё 5. Структурным критериям соответствовали 64 метода. Для каждого запустили исходную реализацию и намеренно пустое тело. Одна задача не прошла критерий чувствительности пустого варианта, ещё две были исключены зарегистрированным пределом по четыре метода на класс. Для оставшихся 61 все оригинальные реализации прошли свои тесты, все пустые реализации провалили хотя бы один. На метод пришлось 2–6 тестов. Тестами и подсчётом займался отдельный процесс в Docker, Python 3.12.16, без сетевого доступа и монтирования хостовых файлов. Для всех 126 разобранных уникальных ответов в новых контейнерах повторно получены те же результаты, включая тайм-ауты. Второй аудит восстановил адреса поиска из программ с уже удалённой целевой реализацией.

**Разбор первичного результата.** В EightPuzzle.move граф предъявил метод solve, текстовый поиск — get_possible_moves. В первом случае генерация закончилась на лимите, синтаксически незавершённое тело не прошло ни одного из пяти тестов. Во втором прошли все пять. В NumberWordFormatter.trans_three граф выбрал format_string и также получил незавершённую программу. BM25 выбрал trans_two и прошёл два из пяти тестов. Оба варианта не прошли метод целиком. Только эти две задачи различались по доле пройденных тестов. В остальных условиях и задачах происходили и иные ошибки, их статусы опубликованы в results.json. При таких числах нельзя заключить, что информация о месте вызова в целом ухудшает разработку.

Это адаптация публичного ClassEval к одношаговому заполнению фиксированного метода с существующими соседями, а не весь класс или исправление реального issue. Публичные классы могли встречаться модели в предобучении. В выборке представлены безопасно исполняемые задачи с наблюдаемым статическим вызывающим методом. Данные не устанавливают преимущество графовой политики по прохождению тестов или результат на лидерборде ClassEval. ## Контроль лимита вывода

Семь из 133 исходных ответов остановились из-за ограничения длины. После наблюдения первичного эффекта зарегистрировали дополнительный опыт: все три варианта получают до 768 токенов при тех же входе, весах и greedy-декодере. Для каждого из семи ограниченных ответов повторно получили 384 токена и сверили их с первоначальным текстом; первые 384 нативных token ID и байтовый префикс расширенной генерации совпали во всех семи случаях. Остальные 126 ответов остановились по EOS раньше первоначального лимита, три заранее выбранных таких ответа воспроизведены при большем лимите. Одна из семи расширенных генераций снова достигла ограничения.

На 768 токенах итоговая доля полностью прошедших методов составила 70,49% у каждого варианта. На EightPuzzle.move графовый ответ теперь успешно выполняет все 5/5 тестов. Суммарно прошли 248/308 тестов с графом, 250/308 с BM25 и 248/308 без тела соседа. Единственная различившаяся по доле тестов задача между графом и BM25 — NumberWordFormatter.trans_three (0/5 против 2/5). Ни в одном из 61 случаев граф и BM25 не разошлись по полному прохождению; как и положено для такого набора наблюдений, парный эмпирический bootstrap вернул [0; 0]. Это отражает отсутствие изменившихся бинарных исходов в данной выборке и не даёт универсального интервала эквивалентности методов. Для BM25 и варианта без тела всего по два полных выигрыша в каждую сторону. Дополнительный результат обусловлен случаем остановки на лимите и остаётся чувствительностью к бюджету генерации.

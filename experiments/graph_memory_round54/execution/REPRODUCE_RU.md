# Воспроизведение пилота ClassEval

Из этой папки последовательно выполнить четыре команды. Повторение измерений записывает новые артефакты здесь; для сохранения исходных результатов используйте копию репозитория.

~~~text
python -B study.py
python -B generate.py
python -B grade.py
python -B audit.py
~~~

study.py получает только зафиксированный ClassEval_data.json авторов, если локальная копия отсутствует, и проверяет SHA256. Рабочие файлы находятся на D:/CodexResearch/x20-r54-execution. Для автономного запуска положите исходный JSON в эту папку заранее. Использованы Python 3 с requests и numpy, исполняемый llama-server, Qwen3-4B-Instruct-2507 Q4_K_M и зафиксированный локальный образ python:3.12-slim с ID из study.py. Сборка llama.cpp и веса проверяются по SHA256 из R52. Файлы из R52 используются только для запуска локального сервера и проверки его идентичности. Для исполнения нужен доступный Docker Engine с этим образом. Внешний сетевой запрос не требуется при наличии данных, образа и модели.

**Источник и граница сравнения.** ClassEval — опубликованный набор классов на Python со спецификациями и собственными тестами. Эксперимент повторно использует его исходные методы и назначенные им тестовые классы в постановке «один скрытый метод при фиксированных соседях». Это условная оценка восстановления метода у единственного декодирования. Оригинальный benchmark также оценивает генерацию целого класса и другие стратегии; сравнение с официальным рейтингом потребовало бы повторения условий. [Работа ClassEval](https://arxiv.org/abs/2308.01861), [Закреплённая версия авторских данных](https://github.com/FudanSELab/ClassEval/blob/eaeac44d0d5dcd8a95feec50726d66fedc73a98f/data/ClassEval_data.json), [Официальные режимы генерации](https://github.com/FudanSELab/ClassEval/blob/eaeac44d0d5dcd8a95feec50726d66fedc73a98f/generation/README.md).

**Пакет доказательств.** Исходная версия и правила отбора в PROTOCOL_RU.md. В observations.json.gz для каждой задачи лежат видимый контракт, порядок BM25, извлечённые связи, адреса и тела выбранных соседей. В calibration.json.gz сохранены проверки авторского и пустого варианта. В prompts.json.gz и contexts.json.gz находятся нативные токены и связывание их с задачами. В answers.json.gz — полные фактические выводы LLM. После фиксации answer-seal.json запускается отдельный код оценивания. unittest.json.gz содержит исходы авторских тестов, records.json.gz — парные наблюдения, results.json — метрики и интервалы. Повторный запуск в новых контейнерах сравнивается с первоначальным в audit.json и repeat-tests.json.gz. Идентификаторы Docker и нативных весов, параметры greedy и устройство доступны в selection.json и input-seal.json. Промежуточный построчный журнал генерации остаётся в рабочей папке D.

**Изоляция.** Каждое решение исполняется в независимом процессе Python с isolated mode. Группы процессов размещены в контейнерах с файловой системой только для чтения, без подключения томов хоста, сети и хостовых переменных. Непривилегированный UID/GID и ограничения ресурсов действуют на всех трёх вариантах, включая контрольные реализации. Отдельный тайм-аут на тестируемый метод — 4 секунды. Проверяется только назначенный целевому методу тестовый класс, а не весь проект. Докстринг с опубликованными примерами — часть разрешённого контракта. Реализация целевого метода и размеченные тесты не входят в агентный запрос. Метаданные о базовых тестах доступны оценщику.

Для дополнительного контроля лимита после основной серии запустить `python -B cap.py` и `python -B verify_cap.py`. Оригинальные 133 ответа и результаты 384 токенов сохраняются отдельно. Контрольные суммы, новые ответы, исходные и продолженные token ID, тесты и итоговые сравнения имеют префикс cap-.

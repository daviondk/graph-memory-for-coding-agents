# ClassEval: выбор исходного фрагмента перед восстановлением метода

Первичный исход — доля скрытых методов, для которых предложенная реализация прошла все назначенные авторами ClassEval модульные тесты этого метода. Сравниваем выбор одной соседней функции с учётом статического вызова и сильный лексический BM25. Набор FudanSELab/ClassEval, ревизия eaeac44d0d5dcd8a95feec50726d66fedc73a98f, SHA256 оригинального JSON 50a1ac0e4d0c238573c10c0ab11feae00b14a80ae9e4c9cc28148707ecf0b6a2. Для воспроизведения оставляем исходные ID класса, метода и тестового класса. Оригинальный benchmark оценивает, в частности, целые классы. Здесь закрывается одна реализация, остальные методы заданы, поэтому эксперимент оценивает выбор памяти при завершении метода. Это отдельная постановка, без сопоставления с классным pass@k лидерборда.

**Выборка.** Только заранее перечисленные доброкачественные алгоритмические и прикладные классы в study.py. Предварительная проверка статически исключает доступ к сети, файловой системе, операционной системе, процессам, произвольной динамической загрузке и eval/exec внутри пользовательской задачи. Допускаются библиотеки из фиксированного списка стандартной библиотеки Python. Выбираем именованные методы авторского каталога кроме магических, с двумя или более доступными соседями и хотя бы одним настоящим вызовом из другого метода того же класса; распознаются только непосредственные вызовы self.target, cls.target, ClassName.target. Используем строго все пригодные задачи в порядке SHA256, до 80, до четырёх на один класс. Отсутствие/ошибка теста в исходной авторской реализации исключает задачу до генерации. Для включения также требуется, чтобы тот же тестовый класс обнаруживал замену тела исключением NotImplementedError. Публикуем поток отбора и причины исключений. Набор ограничен средами, где эта конкретная связь наблюдаема, возможна прежняя встречаемость публичных задач в предобучении.

**Три чтения.** Текстовое ранжирование Okapi BM25 (k1=1.2, b=.75) использует слова исходного контракта, идентификатор метода и контекст класса. Кандидат включает имя, тело, документированный контракт и идентификаторы. Слова выделяются из snake_case и CamelCase с дополнительными термами полных идентификаторов. Ничьи детерминированы по имени. Графовый вариант использует то же ранжирование среди реально вызывающих скрытый метод соседей. При подаче показываем реально существующий исходный фрагмент метода-соседа с сигнатурой и телом; докстринг соседа удаляем. Фрагмент обоих вариантов обрезается до минимальной из длин и 192 нативных токенов, включая имя. Фрагменты и точная длина фиксируются до генераций. Совпадающие входные токены используют один ответ. Третье вторичное плечо показывает только общий контракт, поля и каталог сигнатур без тела соседа, поэтому его физический запрос короче. Перемешанные иные подходы не добавляем.

Генератор Qwen3-4B-Instruct-2507 Q4_K_M, локальный llama.cpp, greedy, один слот, seed 540271, не более 384 токенов ответа. Просим вывести полное определение целевого метода; заменяем только тело, сохраняя оригинальные сигнатуру и декораторы. Код, который нельзя разобрать как единственное определение целевого метода, или запрещённые операции дают непройденную задачу. Эталонные тела, тесты и прогноз успеха недоступны ранжировщикам/генератору. Все входы и выходы фиксируем до оценивания сгенерированного кода. Исполнение идёт в дочерних процессах изолированного Docker-контейнера python:3.12-slim с read-only FS, без сети, bind mount, оболочки и хостовых переменных. У каждой проверки ограничено время.

**Оценка.** Одно парное наблюдение на целевой метод. Первичное сравнение граф минус BM25 по доле полностью прошедших методов, процентные пункты. Кластерный парный bootstrap по классам, 10 000 выборок с seed 540272, двухсторонняя смена знаков суммарных внутриклассовых разностей. Вторичные результаты: два контраста с одним и тем же общим контекстом без соседней реализации, средняя доля пройденных тестов, числа ошибок парсинга, семантических ошибок и истечений времени. Небольшую выборку интерпретируем как исполняемый пилот; положительный или отрицательный результат сохраняем одинаково.

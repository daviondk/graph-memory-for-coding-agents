# Независимый аудит

До оценки результатов генерации решено повторить все исполняемые комбинации «метод × уникальный ответ» в новых контейнерах в обратном порядке. Сравниваем число запущенных, проваленных и ошибочных тестов и итог полного прохождения по каждому прогнозу, сохраняем расхождения при их наличии. Это диагностирует зависимость от начального состояния процесса, порядка или внутренней случайности тестов. Первичный результат остаётся первым запуском. Проверяем также допустимость исходных рёбер путём повторного разбора класса уже после подстановки пустого тела вместо целевого метода, целостность контрольных сумм, соответствие тестов оригинальному классу ClassEval и каждый выровненный вход. Для извлечения метода принимается единственное AST-определение нужного имени, в том числе при единственной внешней ограде Markdown; заменяется только тело, включая возможный докстринг.

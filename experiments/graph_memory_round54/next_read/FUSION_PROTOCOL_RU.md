# Дополнительный опыт. Как взвешивать предложения агента

Условие целесообразности чтения — независимое подтверждение пути. Дополнительный тест фиксируется после нулевого результата с raw_final_files и до оценки явного списка suggested_unread_files. В выбранных трёх статических top-20 имеется одна запись пути на модель, в памяти агента — упорядоченные указатели. Проверяем два способа объединить четыре голоса при одинаковом списке уже открытого контекста и одном новом чтении.

Основной дополнительный контраст — reciprocal rank fusion (`k=60`) трёх прежних списков и явного списка агента против fusion трёх прежних списков и четвёртого статического Qwen3-Embedding-8B. Также сообщаем сравнение с исходными тремя, с семью статическими моделями авторов и с памятью поверх всех семи. Внутренние контроли с тем же числом измерений: (1) одному и тому же множеству допустимых предложений дать одинаковый вес первого места, (2) использовать локальный список агента в обратном порядке. Пустые и недоступные предложения веса не дают. Записи в статических списках получают 1/(60+исходная позиция), у пути из явного списка — дополнительное слагаемое того же вида. При равенстве лексикографический порядок пути. Основная мера — Hit@1 нового адреса среди официальных необходимых файлов, парные ДИ по репозиториям и общий file recall. Фиксированные коэффициенты, обучение отсутствует. Панель повторно используемая, новые ответы LLM не генерируются. Результаты по каждому вопросу и лучшим из доступных адресов сохраняются.

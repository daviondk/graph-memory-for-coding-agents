# Протокол. Какое следующее чтение стоит выполнить по завершении поиска файлов

**Вопрос.** Может ли запись «агент предложил этот путь, но ещё не открыл его» дать полезный дополнительный документ? В архиве Agent Retrieval Bench есть реальные траектории GPT-5.4-mini. Перед выдачей официальная строгая процедура убирает непрочитанные предложения. Проверяем использование такого предложения как указателя для одного следующего обращения к источнику. Точность ответов LLM и успех исправления этим опытом не измеряются.

**Материал.** Положительные типы задач в пересечении основного релиза и публичных strict-context траекторий в ревизии Hugging Face `5901e1ee3aff048290db72edf9c63bc498b79ea3`. Требуется совпадение ID, репозитория и базового коммита у всех методов. Из основной оценки заранее исключены просмотренный для понимания схемы `01323034afde8983e978b8d2` и напечатанные в статье `f39b3eb29d5ba2f6c18b0555`, `35154a761b37d4f5767d1cfa`, `0f88458fc1fe4acce078ce3f`, `8b6ab1ba0883ff8104d28524`. При наличии других типов приводим их количество отдельно. Заранее были доступны заголовки и опубликованные агрегированные результаты работы авторов. Графа обращений и результаты публикуются в виде хешированных адресов. Из архива нет необходимости исполнять код репозиториев. [Данные](https://huggingface.co/datasets/eyuansu71/agent_retrieval_bench/tree/5901e1ee3aff048290db72edf9c63bc498b79ea3/releases) · [Первоисточник](https://arxiv.org/html/2607.24882v1)

**Политики.** Во всех условиях сохранить исходные фактически открытые файлы финального ответа. На последнем шаге разрешён один новый источник. Кандидат должен существовать в корпусе данной версии. Уже прочитанные пути и явно выданные начальные пути из полей запроса исключить. Контроль — reciprocal rank fusion первых 20 файлов трёх авторских моделей: lexical_all_files, RepoMap и Qwen3-Embedding-4B. Балл — сумма 1/(60+ранг), ранги от 1, при равенстве лексикографический порядок пути. Основная экспериментальная политика — первый в исходном порядке финального предложения агента новый допустимый путь. Если подходящего пути нет, использовать тот же контроль. Сильные дополнительные сравнения — каждый компонент, Qwen3-Embedding-8B и более осторожное правило «принимать предложение, только если присутствует в top-20 хотя бы одного компонента». Для каждого выбора открыть и записать контрольную сумму первого доступного фрагмента из зафиксированного корпуса. Поиск артефакта офлайн и проверка наличия адреса не моделируют реальную задержку чтения с диска.

**Показатели.** Основной — средняя по задачам разность попадания дополнительного адреса в официальный список необходимых файлов (Hit@1 дополнительного чтения), политика предложения минус fusion. Вторичные — изменение среднего file recall объединения с исходным строгим ответом, полное покрытие, наличие хотя бы одного верного файла и доля изменившихся решений. При полном исходном покрытии следующий новый адрес не может добавить эталонный файл, вопрос остаётся в знаменателе. Дополнительно раскрыть исходы для задач с предложенным адресом, без него и по типам, количество недоступных адресов. Отдельно сравнить каждую исходную модель с одинаковой политикой добавления подтверждённого предложения.

**Анализ.** Сначала сохранить прогнозы и их SHA-256, затем открыть gold_files исключительно в функции оценки. Парные 95% percentile bootstrap по репозиториям, 10 000 выборок с seed 54021, с повторным расчётом средних по задачам. Описательные срезы без выбора порога по качеству. Каждый вопрос соответствует одной архивной траектории одного решателя. Сравнение с опубликованными ранжированиями внутри одного продолжения траектории является модифицированной постановкой, официальная таблица методов измеряет поиск с нуля.

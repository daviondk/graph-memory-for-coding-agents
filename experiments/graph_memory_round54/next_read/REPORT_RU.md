# Отчёт. Стоит ли вернуться к файлу, который агент предложил, но ещё не открыл

Из 287 опубликованных строгих траекторий GPT-5.4-mini в Agent Retrieval Bench взяли 283 задачи из 25 репозиториев. Четыре задачи исключены до оценивания как просмотренные примеры. После завершения исходной траектории сохраняется её итоговый набор прочитанных файлов. Каждой политике разрешено ещё одно чтение ранее не открытого файла. Выбранный адрес проверяется в снимке базового коммита, а содержимое первого фрагмента подтверждается SHA-256. В этих данных **выбор первой допустимой рекомендации агента нашёл новый нужный файл в 20/283 случаях**. Слияние трёх опубликованных ранжирований нашло его в 16/283, а один опубликованный Qwen3-Embedding-4B — в 26/283. Общего преимущества при равной цене чтения не установлено. [Работа авторов](https://arxiv.org/html/2607.24882v1) · [Численные результаты](explicit-results.json)

## Что именно удалось извлечь из памяти

Два поля в логе решают разные задачи. В raw_final_files записано то, что агент пытался включить в итоговый контекст. В первом варианте именно это поле использовалось как источник для следующего чтения. После исключения уже открытых и начальных файлов только у трёх задач осталась подходящая рекомендация. Изменился один выбор, количество попаданий совпало. В архиве отдельно хранятся запланированные чтения, suggested_unread_files. Уточнение поля зарегистрировано после анализа первого результата. Для 278/283 задач оно совпало с массивом, возвращённым действием агента. В остальных пяти архивный список содержал также пути из исходного финального ответа. Первоначальный нулевой результат, исправленные прогнозы и оба протокола сохранены. [Первичный протокол](PROTOCOL_RU.md) · [Первый вариант](results.json) · [Дополнение](ADDENDUM_RU.md) · [Запечатанные решения](explicit-seal.json)

Всего в явных рекомендациях было 773 новых указания после удаления повторов внутри вопроса и исключения прочитанных и выданных путей. Из них 26 отсутствовали в корпусе соответствующего снимка. Девять раз недоступным был самый первый путь. Первый существующий путь удалось открыть у 274/283 задач, в остальных действовала та же резервная схема, что у контроля. Достаточный новый файл присутствовал хотя бы среди предложений в 48 задачах, но первым допустимым он оказался только в 20. Число 48 — ретроспективная оценка достижимости при известной разметке.

Первый выбор агента и слияние списков дали разные адреса у 225 задач. В 15 случаях только агент указал нужный файл, в 11 — только слияние списков. Разность по попаданию нового чтения составила **+1,41 п.п. [−2,06; 3,80]**, а по среднему итоговому Recall — **+1,01 [−1,75; 2,95]**. Для Qwen3-Embedding-4B разность агента по попаданию была −2,12 [−11,34; 3,53]. Все интервалы — парный bootstrap 10 000 раз по репозиториям. Успех дополнительного чтения зависит от характера задачи: на comment2context получено 5 против 9 попаданий, на trace2code — 7 против 1, на code2test — 8 против 6. Эти срезы описательные. ## Равное число ранжирований

В дополнительном опыте сравнили два способа получить четвёртый сигнал. К одним и тем же трём исходным спискам добавили либо ранги рекомендаций агента, либо статический список Qwen3-Embedding-8B. Веса были фиксированы до градации явных рекомендаций. Первый вариант дал 7,07%, второй — 6,71% попаданий, **+0,35 п.п. [−2,93; 3,18]**, 9 выигрышей и 8 потерь. Разность полного среднего Recall составила +1,00 [−1,16; 2,98]. После добавления рекомендаций ко всем семи статическим моделям число попаданий снизилось с 24 до 21 (1 выигрыш и 4 потери). При фиксированном множестве трёх статических моделей одинаковый вес всех рекомендаций и вес по рангу поменяли шесть решений, но по попаданию дали одинаковый результат на каждом вопросе. [Протокол](FUSION_PROTOCOL_RU.md) · [Ранги кандидатов](fusion-inputs.json.gz) · [Метрики и интервалы](fusion-results.json)

Это воспроизведение выбора адреса в архивированном состоянии агента. Публичные исходные списки и прошлые траектории получены авторами бенчмарка. Мы заново выполнили проверку адресов, чтение фрагментов и парную оценку. Время построения опубликованных индексов, реакция GPT на добавленный фрагмент и доля решённых задач в эксперимент не входили. Фильтрация по точному наличию пути требует индекса имён файлов или обращения к конкретному снимку. Публикуются хешированные адреса и результаты каждого выбора. Для ограниченного набора публичных проектов интерфейс также сохраняет названия файлов, достаточные для интерактивной проверки.

## Воспроизведение

Python 3.14 с поддержкой Zstandard и NumPy. Исходные архивы можно указать через `--cache D:/путь`. Скрипт сверяет оба SHA-256 с опубликованными квитанциями для закреплённой ревизии. Все команды запускаются из данного каталога.

~~~text
python -B decide.py
python -B grade.py
python -B suggestions.py decide
python -B fusion.py freeze
python -B suggestions.py grade
python -B fusion.py grade
~~~

Для проверки сохранённых материалов без сети и полного корпуса достаточно `python -B grade.py --verify`, `python -B suggestions.py verify` и `python -B fusion.py verify`. Последняя команда заново принимает решения для всех 283 вопросов по архивным рангам. [Сводка серии](../REPORT_RU.md) · [Демонстрация чтения](../trace_demo/)

# Поиск затронутого файла через наблюдаемый символ и область его видимости

Официальный edit2ripple из Agent Retrieval Bench содержит 58 задач, 10 репозиториев, кандидаты — файлы базового коммита. Известны опубликованные общие результаты и пример из приложения статьи. До измерений фиксируем исключение этой показанной задачи 8b6ab1ba0883ff8104d28524. Из входов, видимых до ответа, разрешены только repo, id, base_commit, anchor_file, anchor_diff, intent, корпус до изменения и готовые списки top_files опубликованных BM25/RepoMap/lexical. Поля gold, metrics, gold_ranks и промежуточная авторская оценка закрыты до фиксации наших адресов. Для работы с обычными задачами разработки применяем прежний тематический фильтр R27 к видимым intent + пути + секции изменённых строк diff. Публикуются число исключённых и все знаменатели. Эталонные пути никогда не участвуют в отборе задач. Родственный стандарт RepoBench уже многократно измерялся в проекте, здесь независимый корпус и другое назначение действий.

**Гипотеза.** Изменение наблюдаемого участка кода создаёт потенциально два вида спроса: на внешнее объявление упомянутого символа либо на внешний файл, использующий объявление отредактированного участка. Наименования символов допускают одноимённые совпадения. Граница модуля или явно записанный импорт могут сделать сигнал специфичнее. Используем точные полные лексемы с регистром из изменённых строк и самый узкий перекрытый объявленный символ из авторского снимка, а также названия новых объявлений из видимого diff. Слова из пути другого файла, полные строки patch, вызовы внешних программ и код исправления не используются для построения наших структурных связей. Якорь исключается из всех возвращаемых списков. Источник официальных BM25 и RepoMap — доступный авторский список top-20 на той же задаче, без золотого ранга. Сопоставление с оригинальными метриками отдельно различает отсев/удаление anchor.

**Сильный текстовый контроль.** Для каждого файла считаем направленные совпадения имён: внешнее объявление совпадает с упоминанием на изменённых строках либо в тексте внешнего файла есть имя изменённого локального объявления. Вес имени — логарифмический обратный частотный вес по файлам данного snapshot. Суммы строятся по различным именам отдельно по направлениям и складываются. Все корпусные файлы участвуют в политике; адрес anchor пропускается, отрицательные кандидаты сохраняются. При совпадении числовых показателей используем одинаковый порядок исходного BM25, затем RepoMap, затем путь.

**Связность.** На базе тех же совпадений усиливаем только связи, совместимые с областью имени. Для явной зависимости проверяем присутствие адресующего импорта в видимом тексте исходного файла. Для Go и Java допускается одна реальная декларация пакета, для Rust — общий модуль по каталогу с учётом пути или явно записанный mod/use, для Python и TypeScript — разрешаемое указание import/from, require и namespace. Полные правила и их ограничения остаются видимы в коде, в отчёте отмечаем, что это консервативная статическая аппроксимация. Обратное совпадение усиливается лишь при связи от кандидата к якорю, прямое — от якоря к кандидату. Источник — фактический базовый anchor и соответствующие файлы из официальных chunks. Доступ к дереву и общей таблице уже предоставлен benchmark; из этого опыта не выводим экономию первоначальной индексации в живом проекте.

**Решение и контроль.** Первичное сравнение двух ранжирований. Общая основа — RRF с константой 20 из официальных BM25 и RepoMap плюс ранг текстового контроля. Последний голос — либо второй голос того же текста, либо ранг по сумме text + подтверждённой части text. Ни один дополнительный потраченный голос не добавляется при отсутствии совпадений. Заранее сохраняем BM25, RepoMap и lexical в отдельности, два голоса BM25 + RepoMap без наших сигналов, чистое ранжирование по именам и метод с проверкой области. В контроле происхождения совпадений направление импорта меняем на противоположное при одинаковой процедуре объединения; симметричные внутрипакетные связи при этом сохраняются. Обучения и выбора коэффициентов на задачах нет.

**Метрики.** Официальная единица — множество затронутых файлов; Recall@5 (доля эталонных файлов в пяти предложениях), парная разность graph против удвоенного сильного текстового голоса при равном бюджете — первичный показатель. Для всех методов также измеряем MRR@20, Recall@1/10/20, наличие хотя бы одного попадания, долю полного покрытия при k=5 и число изменившихся top-5. Интервал разности — парный кластерный bootstrap по репозиториям с сохранением веса задач, 10 000 перевыборок, seed 540131. Дополнительно результаты по репозиториям и точность после исключения *из оценки*, по окончании заморозки, вопросов, где полный золотой путь буквально виден в intent/anchor_diff. Широкий интервал и выигрыш на одном репозитории будут интерпретированы соответственно. Проверяются независимая идентичность снимка, отсутствие anchor в выдаче, пригодность адресов и воспроизведение авторских top_files до применения наших ограничений. Метаполя и ответ для закрытого теста отделены в процедуре чтения.

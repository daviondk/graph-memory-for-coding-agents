# Перенос на код. Какие файлы ещё потребуются после наблюдаемой правки

Проверили, помогает ли память о связи между изменённым символом и его внешними потребителями выбрать следующий файл. В **54 реальных PR из 10 репозиториев** дополнительная проверка импорта или области видимости дала **Recall@5 33,49%** против **33,02%** у того же метода с совпадением имён. Сильный опубликованный лексический поиск с удалением уже прочитанного файла дал **48,92%**, RepoMap — **44,60%**. Преимущество графового правила над этими контролями отсутствует.

## Данные и гипотеза

Qin и Xie выпустили Agent Retrieval Bench для оценки поиска файлов, необходимых кодовому агенту. В задаче edit2ripple даны описание намерения и изменение одного файла. Нужно вернуть другие файлы, на которые распространяется изменение. В авторском наборе 58 задач. До прогнозов исключены три вопроса по тематике их видимых входов и один разобранный авторами в статье пример. Остались 54 случая на 42 зафиксированных базовых коммитах. В каждом полном каталоге после исключения уже данного файла было от 103 до 11 138 адресов. Рассматривались Go, Rust, Python, TypeScript и Java. [Статья и постановка](https://arxiv.org/html/2607.24882v1) · [Авторский релиз](https://huggingface.co/datasets/eyuansu71/agent_retrieval_bench/tree/5901e1ee3aff048290db72edf9c63bc498b79ea3/releases/v2_edit2ripple)

В отличие от ранних опытов проекта на RepoBench, здесь прогнозируется множество следующих файлов в реальном изменении репозитория. В R52 кодовый опыт предсказывал следующий наблюдаемый путь внутри траектории агента после редактирования. Здесь нет непрерывной модели-решателя. Проверяем отдельное решение о том, какой дополнительный файл дать после первого наблюдения. Из результата не следует изменение успешности выполнения задач.

- **Доступ до прогноза.** Разрешены изменения только известного якорного файла, описание задачи, файлы и объявления из базового коммита, опубликованные списки top-20 трёх поисковых систем. Из раздела изменения берутся имена и позиции, а не полный патч PR. Данные фиксации, списки будущих файлов, gold ranks и ref-variants не используются. До открытия gold заморожены 486 списков (9 политик × 54 вопроса). После оценки проверено, что полный эталонный путь буквально не был дан ни в одном видимом вопросе; проверка не исключает естественных подсказок по именам.
- **Что запоминаем.** Выделяются различные идентификаторы на изменённых строках, новые объявления и наиболее узкое существующее объявление, накрывающее позицию правки в базовом файле. Сохраняются тип связи, её направление и причина совместимости области. Обрабатываются две ситуации: якорю нужно чужое объявление, либо другой файл использует изменяемое объявление якоря. На 40 из 54 вопросов найдено имя изменённого объявления, на 33 есть хотя бы одна поддержанная областью связь. Слова в самих путях не превращаются в собственные свидетельства.
- **Сильный сопоставленный контроль.** Точные совпадения имён по направлениям получают вес 1+log((N+1)/(df+1)), где df — число файлов снимка с таким именем. В основном варианте повторный вес получает совпадение с совместимым импортом/пакетом именно в нужном направлении. Прямые и относительные импорты разрешаются простыми правилами для пяти языков. Объявленный пакет используется для Go и Java, общий каталог Rust обозначается отдельно как приближение. Это статические признаки. Алиасы импорта, переэкспорт, диспетчеризация методов, макросы и реальное исполнение файлов охвачены частично. Начальную стоимость обхода репозитория здесь не измеряем.
- **Сравнение.** Общая основа — RRF опубликованных BM25 и RepoMap и ранг имени. Четвёртый голос поступает либо тому же лексическому сигналу, либо сигналу с проверкой области. Порядок равных оценок одинаков. При нулевом совпадении нет дополнительного голоса. Обратный контроль меняет направления проверки. Формула и веса зафиксированы без обучения на этом наборе.

## Результаты

Recall@k здесь — средняя по задачам доля всех её эталонных файлов, оказавшихся в k первых адресах. MRR@20 учитывает место первого попадания и даёт ноль при отсутствии попадания на доступной глубине.

| Опубликованный BM25 | 7,72% | 27,93% | 32,41% | 51,70% | 0,236 |
| Опубликованный RepoMap | 16,67% | 44,60% | 53,86% | 63,73% | 0,350 |

| Только имена | 8,95% | 23,46% | 27,93% | 42,90% | 0,221 |
| Только имена с проверкой области | 11,11% | 24,54% | 28,55% | 44,44% | 0,275 |
| Общая основа + равный дополнительный голос имён | 17,59% | 33,02% | 47,69% | 60,19% | 0,335 |

Изменилось шесть пятёрок файлов, а метрика сдвинулась один раз. Девять из десяти проектов не дали ни одного изменения первичной метрики. При к=10 и 20 у графового варианта оказалась меньшая полнота. Относительно опубликованного Lexical разность составила **−15,43 п. п.** [−22,46; −5,86], семь выигрышей и 19 потерь. Относительно RepoMap — −11,11 п. п. [−21,43; +2,92], относительно BM25 — +5,56 п. п. [−1,85; +15,63]. Использованы 10 тыс. парных перевыборок целых репозиториев с сохранением вопросных весов. Малое число репозиториев и сильная концентрация изменений ограничивают перенос.

**Конкретное попадание.** Для задачи etcd a8e245be8d5dfb1782bf8c18 граф поднял server/etcdserver/v3_server.go на четвёртое место, заменив один неэталонный путь в пятёрке текстового контроля. Это один из четырёх эталонных файлов. Прибавка ровно 1/4 в одной задаче объясняет весь эффект +0,46 п. п. по 54 вопросам. Приписывать её устойчивой способности учесть графовую зависимость оснований нет.

## Сверка с авторским протоколом

Подготовленный сравниваемый режим пропускает уже данный anchor у **всех** политик. Авторский top-5 содержит этот известный файл у BM25 в 46/54 вопросах, у RepoMap и Lexical в 54/54. При сохранении исходного списка авторов на тех же вопросах имеем BM25 22,22%, RepoMap 37,19%, Lexical 43,36% по Recall@5. Точное воспроизведение каждого опубликованного Recall@5/10/20 проверено для всех 162 ранжирований. На глубине 20 при удалении якоря мы возвращаем последний резервный адрес, если опубликованный top-20 не даёт двадцати новых путей. В этой выборке это не сдвинуло Recall@20 авторских вариантов. Публикация отдельно сообщает Recall@20 = 71,12% у Qwen3-Embedding-4B на исходных 58 вопросах. Разные знаменатели и обработка anchor не позволяют представлять это число как парное сравнение с нашей системой. ## Воспроизведение и ограничения

Запуск на CPU использует Python 3.14 (потоковое чтение zstd), NumPy и архив 128 720 663 байт. Архив хранится на D; полная распаковка снимков не требуется. Повторный прогноз читает только официальные corpus chunks, разрешённые поля вопроса и подготовленные исходные top-20. Проверка отдельно подтвердила доступность всех выданных путей и 486 парных метрик из эталонных множеств. Выборка по десяти проектам, оценка только 54 из 58 задач. Полный лексический контроль оказался сильнее как метода области, так и его текстовой абляции. Эта серия не подтверждает перенос выигрыша графового чтения из Wikipedia на поиск затронутого кода.

# Критерий обращения к индексу для top-k при знаковых изменениях

Из первого опыта серии известны времена пяти физических планов и преимущество упакованного снимка при k≤8. Здесь таблица истории неизменна. Гипотеза касается числа чтений текущего индексного top-8 во время записи. Каждая транзакция включает рождения источников с начальной оценкой 0 и знаковое изменение оценок существующих источников, порядок задаётся парой (оценка по убыванию, ID по возрастанию). Для источников, изменённых вне верхней восьмёрки, новую оценку возвращает тот же UPDATE; все дополнительные расходы учитываются.

**Проверяемое утверждение.** Пусть B — предыдущие лучшие восемь пар. Добавить/обновить в B всех кандидатов с изменившейся оценкой и новые источники, отсортировать, взять первые восемь. Если до операции источников меньше восьми либо новый восьмой ключ не хуже прежнего, ни один неизменившийся внешний кандидат не может попасть в новый top-8. В обратном случае запросить точный top-8 в общем индексе. Кроме того, когда оценки действующих победителей не менялись, новые кандидаты уступают последнему, а восьмёрка полна, можно вернуть прежнее состояние без сортировки. Пустые и повторно применённые события соблюдают семантику хранения предыдущего опыта.

**Сравнения.** 1. Исходный актуальный SELECT сортированного индекса после каждой транзакции. 2. Пропуск только при доказанно прежнем списке, при любом возможном изменении выполняется SELECT. 3. Критерий границы с локальным пересчётом, включая обновления, которые меняют ответ. У всех одна схема SQLite, единая атомарность, snapshot-on-change, один общий полный ответ для k=2,4,8. Оценки изменившихся старых кандидатов в двух новых вариантах извлекаются UPDATE RETURNING. Исходный план использует обычный UPDATE. Память между транзакциями в каждой сессии ограничена предыдущей восьмёркой на запрос и номером ревизии, включает проверку после записи другим клиентом.

**Конечные точки.** Первичный исход — число запросов полного текущего top-8 в обслуживании 1 072 транзакций. Подготовительные обращения при холодном состоянии считать отдельно. Вторичны число записанных версий и время записи и смешанной нагрузки (восемь чтений на коммит, тот же график чтения, что у пяти схем). Семь чередуемых блоков на диске D, случайный порядок внутри блока с seed 540421; bootstrap отношений средних по парным блокам 10 000 раз. Указывать цену процессорной работы при экономии чтений индекса. Сравнить все исторические пары на всех 1 112 состояниях и трёх k. Проверить конкурентную смену ревизии, rollback, ничьи и полное малое пространство знаковых изменений. Предыдущие исходы по времени известны; этот дополнительный опыт регистрируется до расчёта критерия на потоке.

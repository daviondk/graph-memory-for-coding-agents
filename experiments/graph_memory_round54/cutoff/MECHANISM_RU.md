# Почему сохранённая граница иногда сильнее текущего восьмого ключа

Условие для изменения решения можно объяснить на семействе детерминированных событий. Оно отделяет два конкретных проверенных алгоритма и не утверждает приоритет хранения границ в исследованиях баз данных.

Пусть k=L=8. Семь старших кандидатов имеют фиксированные оценки от 20 до 26. У восьмого изначально 6, у единственного внешнего кандидата — 1. После загрузки восьми строк из индекса допустимой верхней оценкой любого неизвестного кандидата служит 6. Только оценка восьмого меняется по циклу 9, 7, 9, 7, … . Каждое изменение — реальное знаковое обновление одной связи в запущенной SQLite, оцениваемая пара ID/балл меняется каждый раз.

**Переменный точный префикс.** После роста до 9 последний элемент точного префикса имеет оценку 9. Когда она понижается до 7, правило сравнения с текущим последним ключом не может гарантировать, что изменённый кандидат всё ещё восьмой. Префикс содержит семь гарантированных строк, поэтому наша реализация алгоритма Yi и соавт. запрашивает из индекса одну строку при каждом снижении. После возврата этой строки состояние снова удовлетворяет тем же условиям. Таким образом, T циклов вызывают T дополнительных запросов. [Первичная работа, раздел 3](https://cse.hkust.edu.hk/~yike/topk/icde03.pdf)

**Сохранённая граница неизвестных.** У любого источника вне кэша оценка уже была ограничена шестью. События затрагивают только известного восьмого, поэтому этот верхний предел остаётся действительным. Оба его новых значения выше шести. По индукции ни один из 2T шагов не требует обращения к индексу; сохраняются те же восемь строк и один ключ границы. При общей холодной загрузке прочитано по восемь строк. После T=1,4,32 циклов измерены соответственно 1,4,32 дополнительных обращения у точного префикса и 0,0,0 у варианта с границей. Завершающее снижение до нуля потребовало запроса у обоих методов и привело к смене восьмого ID.

Пример заранее сконструирован для иллюстрации. Он показывает возможность расхождения алгоритмов, но не частоту таких колебаний на реальных графах. Результаты реальных потоков приведены отдельно, включая совпадение с опубликованным подходом при достаточном резерве. Близкая идея ограничений, позволяющих не запрашивать источник до нарушения области допустимости, также встречается в распределённом мониторинге top-k при другой постановке. [Babcock & Olston, SIGMOD](https://infolab.usc.edu/csci599/Fall2003/Data%20Streams/Distributed%20Top-k%20Monitoring.pdf)

# Когда обновлённый top-k можно восстановить без обращения к индексу

На 40 траекториях ISETrace система после каждой ревизии поддерживает восьмёрку доступных источников с наибольшей суммой весов действующих свидетельств. Старые связи могут ослабевать или отзываться. При одинаковом балле приоритет получает меньший ID. Зная прежнюю восьмёрку и новые оценки затронутых источников, удалось обслужить **494 изменения результата локально**, ещё 539 ревизий сохранили прежний список. Полный SELECT top-8 после обновления потребовался **39 раз из 1 072**. Во всех 1 112 состояниях и для каждого k=2,4,8 упорядоченные пары ID и оценки совпали с независимым пересчётом. [Протокол](PROTOCOL_RU.md) · [Проверки и количества](correctness.json)

## Условие корректности

Для источника i ввести ключ (score, −i), больший ключ лучше. Пусть b — последний ключ прежней полной восьмёрки. Для каждого источника вне восьмёрки, которого не коснулось обновление, ключ был и остался меньше b. Содержимое прежнего top-k объединяется с новыми значениями **всех** затронутых кандидатов и всеми рождениями. Если восьмой ключ этого объединения не меньше b, все восемь гарантированно лучше любого неизвестного кандидата. Если источников прежде было меньше восьми, прежний список уже содержал весь старый набор. Иначе при снижении новой границы приходится обратиться к текущему индексу. В частности, по последнему случаю критерий консервативен: высокий внешний кандидат возможен, но его фактическое наличие неизвестно из сохранённой восьмёрки.

Критерий работает при атомарной группе известных изменений и стабильном правиле ничьей. Для индекса с меняющимися весами модели или неизвестными правками гарантия требует расширить перечень затронутых источников. При обнаружении другой записавшей сессии номер версии не совпадёт, и старый top-k загружается заново. Идея хранения запаса ранжированных строк для уменьшения числа обращений к базовому индексу имеет прямых предшественников в области материализованных представлений. [Yi et al., ICDE](https://cse.hkust.edu.hk/~yike/topk/icde03.pdf) · [Наше дополнительное сравнение с запасом кандидатов](../reserve/)

## Физические результаты

| Обслуживание текущего top-8 | Запросов top-8 после изменения | Дополнительные холодные запросы | Записано версий | Только запись, мс | Запись с восемью чтениями на ревизию, мс |
|---|---:|---:|---:|---:|---:|
| Всегда читать SQL-индекс | 1 072 | 40 | 533 | 84,34 | 165,11 |
| Проверять сохранение старого результата | 533 | 40 | 533 | 84,66 | 166,92 |
| Обновлять из затронутых источников при достаточной границе | **39** | 40 | 533 | **78,06** | 167,09 |

Число запросов текущего top-8 уменьшилось на **96,36%** относительно обязательного SELECT и на **92,68%** относительно пропуска только неизменившихся результатов. В обеих схемах продолжают выполняться проверка квитанции и версии, запись рёбер и обновления индекса. Затронутые значения вне кэша получены через UPDATE RETURNING. Сокращение запросов top-k не эквивалентно такому же сокращению всех обращений к SQLite.

Без пользовательских чтений отношение полных времён составило **1,08 [1,02; 1,13]**. При восьми чтениях — **0,99 [0,94; 1,03]**; устойчивого выигрыша времени в этом режиме нет. Семь перемешанных парных блоков на одной машине, среднее времени всего потока включая инициализацию и checkpoint. Результат важен прежде всего для числа обращений к источнику рангов. [Все замеры](timings.json.gz) · [Интервалы](results.json)

Выполнен независимый расчёт по всем состояниям потока и перебор 85 683 сочетаний перехода и k для четырёх источников с рождениями, ничьими и снижением оценок. Проверены транзакционный откат, повтор сообщения, конфликт записей и передача состояния между двумя пишущими соединениями. Все три плана записали идентичную последовательность 533 пакетов. `python -B run.py --verify` повторяет этот аудит и расчёт интервалов. `python -B run.py` заново измеряет нагрузку. При переносе передать временную папку параметром `--scratch`. В каталоге [diagnostics](diagnostics/) оставлены первые замеры и код до исправления проверки сериализации списка k в JSON; основная таблица получена повторным полным прогоном.

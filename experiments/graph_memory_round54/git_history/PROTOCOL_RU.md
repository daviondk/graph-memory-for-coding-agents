# Перенос поддержки точного top-8 на граф импортов Git

До чтения исходников или результатов фиксируем шесть доступных локальных зеркал на D: pallets/click, urllib3/urllib3, tox-dev/tox, psf/requests, pypa/packaging, pytest-dev/pluggy. Ровно 120 последовательных снимков (HEAD и 119 первых родителей) в хронологическом порядке на проект. Локальные зеркала attrs и jinja дают только 52 и 53 первых родителя включая HEAD, соответственно; они не входят. Выбор по наличию истории и знакомым Python-проектам. SHA всех снимков и хеши плана фиксируются до расчёта графов.

**Единица наблюдения.** Один переход между коммитами, включая пустые для графа. Python-файлы всех отслеживаемых обычных файлов (включая тесты и документацию), классифицируются по пути. Версия 1 является отдельной загрузкой полного начального снимка. Синтаксические ошибки AST дают пустой список исходящих импортов; учитываем их количество. Собственный цикл не учитываем. Имена модулей получаем из имени .py, сняв начальный src/ и конечный __init__, только для компонент-идентификаторов. При коллизии приоритет src/, затем лексикографический путь. Абсолютный import берёт полное локально разрешённое имя. В from-импорте сначала ищем подмодуль каждого имени, затем точное имя базового модуля. Relative from разрешаем от пакета importer's path. Это статический граф файлов, без исполнения, dynamic imports, анализа sys.path или транзитивных зависимостей.

**Значимость источника.** Число разных файлов-импортёров на текущем снимке. Ребро от импортируемого файла к импортёру имеет вес 1. ID создаётся при первом наблюдении пути, для одновременных рождений сортировка по пути. Ранжирование по убыванию веса, затем возрастанию ID. Исчезнувшие пути теряют входящие и исходящие связи, остаются кандидатами нулевого веса. Переименование эквивалентно исчезновению старого пути и появлению нового. Количество подтверждённых Git переименований по -M50% учитываем отдельно. При нулевой ничьей ответ может содержать исторический путь, это определение ранжируемой совокупности. Не считаем это оценкой качества чтения кода агентом.

**Политики.** Прежние cutoff-8, eager-12 и lazy-12 без изменений, k=8. При готовности реализованного отдельно Yi-style top-12 добавляем как заранее объявленный сильный контроль. Прежние признаки и веса не подбираем. Сравнение парное по тем же объектам, их рождениям, пакетным +/-1 и полной истории. Для каждой версии сравнить текущие баллы и top-8 SQLite с независимым полным пересчётом по файлам Git. Проверить исторические k=2,4,8 на всех коммитах.

**Запуск.** Начальную загрузку из пустой БД измерить отдельно с рождением всех файлов и добавлением всех активных связей. После загрузки закрыть соединение и уничтожить кеш, перед первым рабочим коммитом каждая политика запрашивает непустой индекс предыдущего снимка. Основной режим далее непрерывен; чувствительность: перезапуск перед переходами 26, 51, 76 и 101, т.е. через каждые 25 рабочих переходов. Регистрируем отдельные cold/warm ordered SELECT и фактическое число строк, чтения и записи SQL по callback, RETURNING score, состояние кеша, размер итоговой БД после checkpoint, число записанных пакетов. Эти счётчики относятся к транзакции поддержки индекса; проверочные запросы исключены. Стоимость построения AST и базового графа общая и измеряется отдельно по файлам, байтам и рёбрам. Первичное сравнение lazy-12 с лучшими фиксированными контролями по total ordered rows (warm+cold). Параллельно сообщаем статистику лишь по изменившим граф коммитам и общее число транзакций. При шести целенаправленно подобранных репозиториях вывод описательный; декомпозиция по каждому репозиторию. Результаты допускают равенство и ухудшение. Все числовые приращения, идентификаторы и SHA публикуются.

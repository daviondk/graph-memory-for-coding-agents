# Какие опубликованные методы позволяют оценить перенос на кодовые задачи

Этот целевой обзор разбирает ближайшие сравнения для экспериментов серии. Отбирались первичные статьи с опубликованным протоколом и по возможности исходные данные или код авторов. Вопросы поиска — repository agent memory, executable evaluation, code context retrieval, graph-guided code localization, materialized top-k views. Проверены arXiv, ACL Anthology, материалы авторов и связанные выпуски кода и датасетов. Это тематическая подборка. Подсчёт полноты всей исследовательской литературы не проводился.

| Публикация | Что оценивают авторы | Как это влияет на наш эксперимент |
|---|---|---|
| Qin и Xie, *Agent Retrieval Bench* | На фиксированной версии репозитория оценивается, какие файлы нужны для следующего шага работы. Публичные артефакты включают исходные ранжирования и историю фактически открытых файлов. Лидеры различаются по метрике и типу задачи. | Наше прямое сравнение по тем же задачам пересчитывает опубликованные выдачи под ограничением «ранее не открытый файл». Указываются и исходные авторские метрики на совпадающих ID. [Статья](https://arxiv.org/html/2607.24882v1) · [Релиз](https://huggingface.co/datasets/eyuansu71/agent_retrieval_bench) |
| Sepidband et al., *How Should Agents See Code?* | При фиксированном агенте сравниваются AST, граф вызовов, зависимости модулей и другие представления. Выигрыш от локализации и снижение расхода токенов могут сопровождаться близкими результатами по исполняемым исправлениям. | В этой серии отдельно проверяются Recall файлов, успех по тестам, выходной лимит решателя и стоимость обслуживания БД. [Статья](https://arxiv.org/html/2611.07286v1) |
| Chen et al., *LocAgent*, ACL | Поиск по графу репозитория в ответ на issue связывает файлы, классы и функции. Источник оценивает локализацию и пользу контекста для решения задачи. | Наш узкий переход от известного файла в edit2ripple работает с иной наблюдаемой информацией. Он сравним с опубликованными ранжированиями Agent Retrieval Bench после выравнивания бюджета. Заявление о превосходстве над LocAgent потребовало бы прогона всего агента в общей постановке. [Статья](https://aclanthology.org/2025.acl-long.426/) |
| Du et al., *ClassEval* | Авторы предоставили задачи генерации целых классов и unit-тесты поведения. | Для изоляции одного чтения мы скрываем один метод и показываем один соседний. Целевая величина — прохождение тестов этого метода. Итоги нельзя переносить на официальный показатель генерации класса целиком. [Статья](https://arxiv.org/abs/2308.01861) · [Репозиторий](https://github.com/FudanSELab/ClassEval) |
| Fan et al., *VibeMemBench*; Chen et al., *MemDev-Bench* | Первая работа предварительно отбирает задачи, в которых инъекция конкретного прошлого опыта помогла референсному исполнителю, и проверяет перенос на другие решатели. Вторая конструирует истории разной релевантности и оценивает исполнимые решения, включая случаи ухудшения при наличии памяти. | Выбор полезного файла, применение знания внутри модели и готовое исправление — разные единицы оценки. В текущей серии контроль с исходным контрактом класса показал, что допустимый вызывающий метод далеко не всегда добавляет необходимую информацию. [VibeMemBench](https://arxiv.org/html/2609.23570v1) · [MemDev-Bench](https://arxiv.org/html/2610.27524v1) |
| Yi et al., *Efficient Maintenance of Materialized Top-k Views*, ICDE | Материализация дополнительных лидирующих строк позволяет реже пополнять представление при изменениях и удалениях. Авторы рассматривают переменный размер резерва и стоимость пополнения. | Проверяем вариант для знаковых свидетельств в ходе работы агента. Измеряем точные исторические ответы, реальные SQL-обращения, строки и время отдельно. Для оценки новизны важно учесть прямого предшественника стратегии с запасом кандидатов. [Статья авторов](https://cse.hkust.edu.hk/~yike/topk/icde03.pdf) |

**Вывод для подачи.** Демотрек просит обосновать систему, взаимодействие посетителя с ней, техническую новизну и значимость. Основной тезис этой серии — на каждой доступной ревизии можно проверить, откуда получен адрес чтения, при каких изменениях разрешено восстановить точную выдачу локально и какая часть этого выигрыша сохраняется на реальном коде. Для утверждения о росте успешности полноценного кодового агента имеющихся результатов недостаточно. [Официальный CFP ICDE](https://icde2027.github.io/cf-demonstrations.html)

При организации поиска и парных сравнений использованы процедуры Literature Review и Experimental Design из библиотеки K-Dense. [Kassis, Agarwal, He, Patel и Brueckner, *Scientific Agent Skills*](https://arxiv.org/abs/2609.00065)

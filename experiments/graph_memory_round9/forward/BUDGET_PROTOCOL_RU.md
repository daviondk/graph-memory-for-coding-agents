# Поисковая абляция размера наблюдаемого окружения

После основного прогона и внешнего переноса на новых проектах проверяем физическую цену более широкой локальной памяти. Фиксируем 1, 2, 4, 8 первых изменённых путей на каждый старый запрос согласно уже установленному порядку. Предсказания и модель адресации те же. Каждая политика действительно разбирает только выбранные файлы и видит прошлую и текущую версии этих файлов. Считаем исходные байты виртуального холодного чтения (сумма размеров двух версий), число опознанных старых адресов и правильных пар «роль+адрес». Основной для абляции контраст: один против восьми файлов по последней метрике для L на всех исходных запросах, где при восьми файлах существовал однозначный старый адрес. Если тот же запрос нельзя инициализировать на меньшем фронтире, это промах, а не исключение. Дополнительно считаем тип и адрес для E и для строгого согласия. Запросы/пороги уже исследованы, поэтому проверка диагностическая. Для бюджета 8 результаты по каждому примеру должны совпасть с изначальными. Строгое равенство read bytes проверяем независимым суммированием размеров. Git-метаданные, стоимость парсинга и кеширование межзапросных файлов в весах стоимости отсутствуют.

# Как разделить ограниченную память между результатами тестов

Каждый выполненный тест связан как с собственным кодом, так и с множеством определений, использованных при общей инициализации Python. Если записывать отдельный фильтр Блума для каждого наблюдения, он многократно кодирует одинаковые зависимости. Проверили, помогает ли выделить общие связи один раз **при том же общем числе байтов**.

Пусть Aᵢ — прошлые зависимости теста i, C — их пересечение по всем тестам. Тогда Aᵢ = C ∪ (Aᵢ ∖ C) в точности. При запросе об изменившемся символе сначала можно проверить один общий фильтр для C и отдельный фильтр остатка. В этой схеме лишнее совпадение ведёт к дополнительному тесту. Истинные совпадения точного графа сохраняются по построению. Это свойство кодирования. Оно не исправляет отсутствующие в исходном графе зависимости.

На этапе записи алгоритм перебирает распределения байтов между общей частью и остатками. Для фильтра с m битами, n элементами и k хешами использует приближение вероятности ложного совпадения (1 − (1 − 1/m)^(kn))^k. Для общего и частного фильтров оценивает объединение двух вероятностей. Числа будущих изменений, нужные символы и новые исходы тестов в выборе параметров не участвуют. Длины массивов и числа хешей оплачиваются из тех же байтов. Тесты и порядок их идентификаторов известны обеим сторонам. У всех вариантов сохранённый буфер реально сериализуется и декодируется. Сравниваем с плоским фильтром, у которого также адаптивно выбирается число хешей. [Протокол и первичная конечная точка](PROTOCOL.md) · [Реализация](sketch.py)

На первичной панели обе стороны вместе допускают бюджет 256 × число тестов задачи. Всего точный граф выбрал 122 из 206 повторных проверок. На основной соли плоская память потребовала 146, вынесение общей части — 123. Парная разница −11,17 п. п. по всем решениям, 95% интервал по восьми задачам [−23,56; −0,48]. Соли проверяют чувствительность реализации и не добавляют независимых задач. При 64 байтах интервал для той же разницы пересёк ноль. На обеих панелях все положительные пересечения точного графа воспроизвелись. Зафиксированная адаптивная политика здесь дала те же решения, что и выбор общей таблицы. [10 задач](testmemory_compat/results.json) · [8 задач](testmemory_holdout/results.json) · [Чувствительность к среде 3.14](testmemory/results.json)

Число повторных проверок — решение реального графа зависимостей в режиме воспроизведения, алгоритм не запускал pytest заново по каждой соли. Исходы проверены отдельно на обеих версиях. На внешней восьмёрке штатный pytest-testmon выбрал 94 запуска суммарно в двух направлениях и обнаружил все 16 смен исхода. Сам pytest-testmon хранит другую базу и не ограничен нашим бюджетом. Следовательно, выигрыш относится к цене сжатия графа, а не к общему превосходству над регрессионным тестированием. Измерено компактное финальное состояние. Построитель видел полные множества прошлых наблюдений при консолидации, а общий фильтр требует известной группы тестов. Это отдельные затраты для онлайн-агента. Представление нескольких множеств фильтрами имеет самостоятельную литературу. Для позиции статьи нужен сильный индекс, учитывающий принадлежность одного ключа нескольким тестам, и замер реальной цены сериализации плюс чтения. Размер фильтра и стоимость действий агента — отдельные метрики.

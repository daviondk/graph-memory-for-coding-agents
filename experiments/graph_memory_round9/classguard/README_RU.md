# Каким путём была создана зависимость тестового наблюдения

В SymPy тест проверяет, что готовый объект Basic не имеет __dict__. Введение __slots__ в родительский класс Printable меняет поведение объекта. При откате штатный pytest-testmon 2.3.1 в этой конфигурации сохранил прежний зелёный ответ. Ошибка воспроизвелась при изолированном запуске и независимо от порядка тестов и времени изменения файла. Ранее в проекте pytest-testmon уже описывались особенности привязки зависимости к переменным класса, есть предложение регистрировать импорты. [Проверка R9](../testmemory_compat/README_RU.md) · [Сообщение проекта](https://github.com/tarpas/pytest-testmon/issues/191) · [Предложение об импортах](https://github.com/tarpas/pytest-testmon/pull/256)

Проверили узкое дополнение. При сборе теста сохраняем типы упомянутых в нём глобальных объектов и их классы в порядке разрешения методов (MRO). После правки смотрим, затронута ли форма класса: базы, декораторы или присваивания на уровне класса. У прямого подхода обнаружилась ошибка идентичности: SymPy выставляет Printable.__module__ публичному модулю printing/defaults.py, хотя определение находится в core/_print_helpers.py. Зависимость, записанная по публичному имени, указывает в другой файл. Такую причину удалось увидеть по поштучному журналу без интерпретации модельных ответов.

| Политика при откате | 10 исходных задач, повторные проверки из 106 | Пропущено новых падений | 8 других задач, проверки / пропуски из 103 |
|---|---:|---:|---:|
| Штатный pytest-testmon | 48 | 1 | 47 / 0 |
| Публичный путь типа + MRO | 48 | 1 | 47 / 0 |
| Физический путь при создании класса + MRO | 59 | 0 | 47 / 0 |
| Та же физическая память, записи циклически переставлены между тестами | 59 | 0 | 47 / 0 |
| Запускать все тесты при любом изменении формы класса | 60 | 0 | 47 / 0 |

В прямом направлении штатный инструмент выполнил 49 тестов, учёт физического MRO — 59, перепроверка всех — 60. Пропусков не было. Запись при создании класса действительно восстанавливает физический источник, но на наборе много однотипных объектов. Перестановка связей не меняет агрегат, индивидуальная привязка даёт экономию всего в одну проверку относительно общего пересчёта. Во внешней восьмёрке форма классов в проверяемых патчах ни разу не менялась. Данных, чтобы выбрать этот механизм как общий модуль памяти, недостаточно. Сохраняются наблюдения объектов в каждой из двух версий, список зависимостей каждого теста, исходы, журналы и состояние окружения. Для воспроизведения из этой папки и затем папки origin запустить `python collect_types.py`, `python score.py`. Предсказание использует только классы, уже доступные при обнаружении теста в старой версии, и текущую производственную дельту.

# Зависимость старого тестового наблюдения от формы класса

Гипотеза возникла после наблюдения одного ложного зелёного исхода на откате SymPy. Если тест использует заранее созданный объект, старый результат может зависеть от Python-класса, ни одна строка которого не исполняется во время самого теста. При первоначальном discovery pytest у функции теста доступны co_names и словарь globals. Сохраняем типы глобальных значений, к которым скомпилированное тело теста прямо обращается, и классы по их цепочке MRO. Учитываем только определения внутри исходного проекта. Когда Git меняет базы класса, декораторы или присвоения в теле класса (включая __slots__), повторяем тест, чья старая запись содержит этот класс. Такой сигнал дополняет готовый pytest-testmon 2.3.1. Он не требует трассировать каждый вызов. Возможны лишние связи для неисполненных ветвей теста. Не все косвенные типы тест использует в виде глобальных имён.

Фиксируем сравнения: исходные решения pytest-testmon; повторная проверка всех тестов при любом изменении схемы класса; привязка только к непосредственному типу; привязка к типу и родителям по MRO. Для диагностического контроля — тот же MRO при циклической перестановке наборов типов между отсортированными тестами одной задачи, включая пустые наборы. Ключ формы класса вычисляется статически из собственных присваиваний, базовых типов, ключевых аргументов классу и декораторов. Новое имя класса или удаление также учитываются. Встроенные данные от будущих версий не входят в запись на старом снимке. Диагностируем отдельно исчезновение отдельных атрибутов, случаи без изменений схемы и случаи с измеренными результатами.

Основной открытый пример sympy-20590 — место разработки гипотезы. Все десять задач из совместимого прогона R8 рассматриваем как одну изученную панель, восемь непересекающихся задач R7 — как внешнюю для механизма панель. Заранее известны состав панелей и результаты предварительного R8 сравнения. До открытия исходов новых методов фиксируем правило и $0 внешних API. Два направления одного изменения зависимы. Считаем сколько действительных результатов изменилась, сколько добавочных проверок потребовало каждое правило и сколько старых результатов оно ошибочно разрешило использовать. Для вызвавшего гипотезу случая отдельно указываем число затронутых тестов. Возможный ноль новых релевантных изменений на второй панели считаем отрицательным результатом по информативности.

# Физический адрес, при котором создаётся класс

Это дополнительная абляция после просмотра ошибки первоначального определения через __module__. В sympy-20590 класс Printable определён в core/_print_helpers.py, но код библиотеки явно меняет его __module__ на sympy.printing.defaults для публичного интерфейса. Память, использующая только публичное имя, указывает на другой файл.

Новая политика записывает местоположение определения при создании объекта класса. Во время обычного обнаружения тестов перехватываем __build_class__ без изменения возвращаемого значения; регистрируем путь и квалифицированное имя для классов, созданных из исходников SymPy. При чтении записи возникает тот же вопрос об имевшихся при тестировании прямых типах и MRO. При отсутствии записи используем прежний путь по __module__. Порогов и последующего подбора нет, всё остальное соответствует протоколу classguard. Входы обеих когорт те же. Эта гипотеза возникла из конкретного примера, случай служит функциональной проверкой механизма. У внешней восьмёрки заранее известен ноль изменений формы класса, она измеряет ложные срабатывания в этих условиях.

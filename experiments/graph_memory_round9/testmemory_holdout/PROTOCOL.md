# Можно ли повторно использовать результат теста после правки кода

Единица блока — одна из восьми математических задач SymPy, зафиксированных в graph_memory_round7/reader и roster.json. Все задачи и ранее выбранные целевые и контрольные тесты берём до просмотра трасс исполнения. Предыдущие результаты показывают известные переходы fail→pass и стабильные pass→pass. Используем их только для формирования одинакового набора тестов в обеих версиях и последующей независимой сверки. Предиктор получает имена тестов без групп FAIL_TO_PASS и PASS_TO_PASS. Две ветви: реальное применение эталонного изменения и контролируемый откат того же изменения. Обе стороны содержат одинаковые тесты. Повторяем оба состояния с инструментированием в новых рабочих копиях D. Это парный повторный анализ одной панели, а не шестнадцать независимых задач.

Память теста содержит предыдущий двоичный результат и множество ранее исполненных сущностей. Между запусками доступны изменения исходников. Политики (1) перечитать всё, (2) переиспользовать всё, (3) перепроверять только прежде упавшие тесты, (4) пересечение на уровне файлов, (5) пересечение на уровне функций или модульного контекста, (6) то же пересечение через фиксированный битовый фильтр Блума 2048 бит, четыре хеша. У решения нет сведений об исходе новой версии. Фиксированное дополнительное сравнение: фильтр 512 бит, и варианты, где любой прежний провал принудительно перепроверяется. Гипотеза — более точный граф тест→определение сокращает проверки по сравнению с файлами при сохранении риска пропустить изменившийся результат. Двоичные результаты pass/fail; setup/collection ошибки, расхождения с историческим контролем и исчезнувшие тесты маркируем явно, не заменяем задачи.

Собираем покрытие на уровне строк для исходных файлов sympy, отдельно по тестам и при импорте/сборке. Файл в момент формирования памяти может быть прочитан полностью для установления квалифицированных имён через AST. Сведения не зависят от будущего diff. Выполненные строки тела принадлежат наиболее вложенному определению, строки объявления, декораторов, значений по умолчанию — внешнему контексту. Уровень MODULE включает код классов вне методов. Общий контекст импорта учитывается для каждой записи, с возможностью хранить один общий фильтр на пакет тестов. Изменившееся пространство имён и несовпадающие имена выражаются обоими идентификаторами, обработка неразбираемого файла консервативная. Время самого построения и запуска тестов и числа записей измеряются отдельно. Время сохранённых запусков оцениваем суммой длительностей тестов в новой версии без фиксированной инициализации pytest; это модель затрат, не замер ускорения CI.

Основные исходы — число пересчитанных записей и ошибочно переиспользованных результатов по каждой ветви, отдельно пропущенные новые падения. Считаем парные изменения с bootstrap по задачам, обе стороны задачи не выдаём за независимые. Контроли проверяют технически важную альтернативу, что достаточно всегда перепроверять ранее упавший тест. Для Блума проверяем условие: все перечитывания точного графа входят в множество перечитываний фильтра (ложноположительные чтения допустимы). Все связи, наблюдаемые исходы, контексты и результаты по тестам сохраняются. Гарантия фильтра касается только закодированного множества. Динамическое покрытие на одном входе и неизменный снимок внешней среды не гарантируют неизменность теста после правки.

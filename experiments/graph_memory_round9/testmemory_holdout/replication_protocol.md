# Проспективный перенос testmemory на другую панель SymPy

До запуска зафиксированы все восемь ранее выбранных R7/reader задач в roster.json. Пересечение с десятью задачами R8/agent равно нулю. Состав тестов берётся дословно из ранее сохранённого control.json; метки по будущей версии открывает score после записи SHA-256 прогнозов. Способы определения зависимостей, размер фильтров, область анализа, сопоставление тестов, направление изменения, бюджет и трактовка расхождений не подбираются заново. Исходные правила приведены в PROTOCOL.md и TESTMON.md; source/adaptation-хеши фиксируются до запуска.

Среда рассчитана на исторические проекты: CPython 3.11.15, pytest 7.4.4, coverage 7.13.5, pytest-testmon 2.3.1, mpmath 1.2.1. В первом сборе R9 на десяти задачах R8 использовались Python 3.14.4 и pytest 9.0.3. Для количественного сопоставления между наборами предпочтителен отдельный совместимый прогон из testmemory_compat, если он идентичен этой среде. Панель проверяет перенос на другие задачи того же репозитория; обе стороны одной задачи зависимы. Все изменения происходят во временных копиях на D в отдельном корне, кеши и базу testmon между направлениями не переносят. Откат — контролируемое обращение того же изменения, не независимый реально произошедший Git-коммит.

Сохраняются все отчёты pytest, графы и решения, фактические выборки плагина, число стабильных/изменённых исходов, пропуски и расхождения по тестам. Для статуса сравниваем с историческими контролями и плагином. Несовпадения подвергаются аудиту и явно исходят из основного анализа согласно прежнему правилу, без замены задач.

# Память о выполненных тестах после изменения кода. Проверка на восьми других задачах SymPy

**Результат.** После изменения исходников точный граф «тест → исполненные функции» выбрал 61 повторный запуск из 103 в каждом направлении, файловая политика — все 103, штатный pytest-testmon — 47. Все три политики обнаружили все восемь изменений результата в каждом направлении. Сохранение общего контекста импорта один раз на набор тестов позволило приблизить компактный фильтр к точному графу: 62 повторных запуска против 96 у обычного фильтра такого же локального размера. Плата за точно сохранённый общий контекст учитывается отдельно.

## Выборка и воспроизводимость

Оценены восемь математических задач из зафиксированного списка R7/reader: sympy__sympy-18698, 19040, 19637, 20801, 21596, 22914, 23534, 24539. Идентификаторы задач не совпадают с десятью задачами R8/agent, используемыми в исходной панели testmemory. Проект и способ отбора тестов общие. Входы, алгоритмы и критерии исключения закреплены до подготовки этих графов. Скрипты ранжирования и оценки перенесены побайтно; изменены путь к данным, фиксированный список, размещение временных копий и путь к штатному плагину. Исходные checkout R7 используются только для чтения. [Состав выборки и хеши](roster.json) · [Протокол переноса](replication_protocol.md) · [Базовый протокол](PROTOCOL.md) · [Контроль pytest-testmon](TESTMON.md)

Единица измерения — пара «задача, pytest nodeid». На задачу приходится 13 тестов, кроме 23534 с 12. Для 103 таких пар исполнялись базовая версия и версия после реального эталонного изменения, с одинаковым test patch. Затем тестировали два направления: переход base→gold и обратный gold→base. Получилось 206 решений. В базовых снимках 95 тестов прошли и 8 упали; после исправления все 103 прошли. Откат создаёт контролируемые новые падения тех же восьми тестов. Направления одной задачи зависимы. Отобранный набор включает заранее известные тесты FAIL_TO_PASS и PASS_TO_PASS; частоту переходов в обычном CI по этим цифрам оценивать нельзя.

Для данных финального прогона использовалась одна фиксированная среда CPython 3.11.15, pytest 7.4.4, coverage 7.13.5, pytest-testmon 2.3.1, mpmath 1.2.1 и py 1.11.0. Версии всех дистрибутивов проверены до и после. Первая историческая панель R9/testmemory на задачах R8 использовала CPython 3.14.4 и pytest 9.0.3. Соседняя серия testmemory_compat переносит прежние задачи в сопоставимую среду. Политики оцениваются внутри одной панели и по одним и тем же исходам. ## Результаты

Числа — количество реально выбранных повторных проверок среди 103 пар для каждого направления. Для testmon выбор восстановлен по pytest-отчётам самого плагина. Прочие политики оценены по графам от реальных прошлых запусков и фактически исполненным полным тестам обеих версий.

| Политика повторной проверки | Исправление, запусков / устаревших ответов | Откат, запусков / устаревших ответов |
|---|---:|---:|
| Все тесты | 103 / 0 | 103 / 0 |
| Никакие тесты | 0 / 8 | 0 / 8 |
| Только прежние неудачи | 8 / 0 | 0 / 8 |
| Пересечение изменённых и исполненных файлов | 103 / 0 | 103 / 0 |
| Пересечение на уровне функций и модульного контекста | 61 / 0 | 61 / 0 |
| Пересечение на уровне строк | 38 / 0 | 50 / 0 |
| Bloom, 512 бит на тест | 103 / 0 | 103 / 0 |
| Bloom, 2048 бит на тест | 96 / 0 | 96 / 0 |
| Общие точные ключи + Bloom, 512 бит на тест | 69 / 0 | 69 / 0 |
| Общие точные ключи + Bloom, 2048 бит на тест | 62 / 0 | 62 / 0 |
| pytest-testmon 2.3.1 | 47 / 0 | 47 / 0 |

В исправлениях, где достаточно повторить прежние упавшие тесты, эта простая политика выполнила меньше всего проверок среди вариантов с нулём устаревших ответов. При откате она пропустила все восемь новых падений. Построчная политика выполнила на 9 тестов меньше плагина при исправлении и на 3 больше при откате. Парные разности доли перезапуска равны −8,74 п. п. [−19,23; −0,96] и +2,91 п. п. [−8,91; +17,31] соответственно. Интервалы — 10 000 bootstrap-выборок целых задач. В панели лишь восемь блоков. Наблюдавшееся отсутствие пропусков не даёт гарантии для других изменений, тестовых входов и окружений.

Объединение общих ключей с 2048-битным фильтром дало на одну проверку больше точного графа при обоих направлениях. Обычный 2048-битный фильтр, дублирующий общие ключи в каждом тесте, потребовал на 34 проверки больше варианта с общей частью (33,01 п. п., 95% ДИ от 7,84 до 61,54). Для каждой пары тест–изменение проверено свойство Блума: все срабатывания точного графа входят в решения компактного фильтра.

| Накопленная память | Медиана на задачу и направление |
|---|---:|
| Исполненные символы общего контекста | 646,5 |
| Общие ключи в JSON + gzip | 4 367,5 байта |
| Точный граф с однократно записанной общей частью, JSON + gzip | 10 616,5 байта |
| Файлы базы pytest-testmon после построения | 118 784 байта |

Это размеры разных представлений. Плагин реализует собственные функции хранения, его база и gzip-описание графа реализуют разные форматы. Размер локального 2048-битного фильтра равен 256 байтам на тест; точные общие ключи занимают дополнительные байты. Результаты rerun являются количеством решений, а время тестовых фаз и работы плагина сохранено в детализации отдельно. Эксперимент проходил параллельно на CPU; прямое ускорение CI не измерялось. ## Целостность и повторный запуск

Итоговый цикл выполнил 16 запусков полных тестов с coverage и 32 вызова pytest-testmon: для каждого из восьми issue отдельное построение базы и селекция в обоих направлениях. Ошибок сбора — 0, ошибок запуска плагина — 0. Каждый исход полного теста сверялся с историческим control.json (прошлая и текущая версия) и, для выполненных тестов, с результатом плагина. Все 206 запланированных решений допущены к анализу. Выполнение исторического падающего теста — предусмотренный исход задачи. Идентификаторы, исходы и пересечение с точными ключами дополнительно восстановлены независимым скриптом из 16 графов и per-test логов. [Независимый аудит](audit.json) · [Исходы всех решений](outcomes.json) · [Проверка допуска каждого теста](verification.json)

Во время первоначального технического прогона общее окружение было дополнено пакетом py==1.11.0 для совместимости со старыми SymPy. Все 137 файлов первого запуска и их SHA сохранены в initial_attempt. После закрепления окружения полностью повторили все стадии. В исходном запуске также были допущены 206/206 решений. Между запусками совпали все прошлые и текущие статусы тестов и все решения о повторной проверке. Состав частного графа исполнения различался в 26 тестовых контекстах, у 24 из них поменялось число достигнутых символов. Все общие контексты и пересечения с изменёнными ключами совпали. По этому наблюдению нельзя приписать различие самому пакету py отдельно от вариативности повторного исполнения. Для анализа памяти фиксированной ёмкости нужно использовать корневые файлы финального прогона. Для воспроизведения требуется R7/reader/tasks с base, grading.json и grades_v2/control.json, соседний R8/agent/assign.json для сверки выборки, Git для применения зафиксированного патча в изолированных копиях и указанная среда. В отдельной рабочей копии R9/testmemory_holdout запускаются `run_holdout.ps1` (collect, predict, testmon_pair, score), затем `python -B audit_holdout.py`. Скрипт freeze_runtime.py с аргументом before или after проверяет точную venv. Скрипт compare_attempts.py сопоставляет результаты с сохранённой первой попыткой. Для чтения уже собранного графа и итоговых исходов достаточно Python с gzip и json. Эксперимент не требует GPU или обращения к LLM.

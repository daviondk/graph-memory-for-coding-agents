# Selective memory reads on held-out Loc-Bench V1

The experiment tests whether a second observation pointing to a remembered function justifies reading that function. Small-compute full-repository function retrieval on a released split. Training, thresholds and ranker weights are frozen. This is an issue-localization simulation, with no patch or generative agent. 

## Population and sampling

Use the original Salesforce SweRank archive, AND the 560 instance IDs from the pinned test parquet of czlll/Loc-Bench_V1 (c44cf3b74e07ca642cec841b471a9939907c12a7); project instance_id only. Remove all six Loc-prefixed archive cases used in round 8. Use SHA256('R9-witness-v1|'+instance_id) order within each of three archive-size strata: up to and including 20,000 compressed bytes, (20,000, 50,000], (50,000, 80,000]. Sample up to six cases per stratum, at most one case from each repository. Restrict to document counts 11–450. Safe-domain screening by issue/repository excludes security, weapons and biomedical topics (script regex; document every exclusion). Sample without conditioning on source topology, named functions, model ranking or judgments. Publish number remaining for each screen; this is a small-compute stratified test, not representative of large repositories. One vote per issue; report bands separately. No labels in prediction. Timing and SHA manifests precede first access to selected qrels.

## Fixed task and read model

The initial retriever is the unmodified published 137M Salesforce/SweRankEmbed-Small. Rank the complete original function corpus for each issue by raw CLS dot product, query prefix and 1024-token limit matching the authors' GitHub scorer (CPU FP32 instead of BF16). The issue itself and the list of addressable function names are observable. The simulated tool reads bodies of the first six dense functions once and retains each observed call as (caller official ID, called basename, target official ID), restricted to globally unambiguous basename matches. Parse Python AST, skipping nested definitions, decorators, default expressions and docstrings. Each distinct caller provides at most one witness to any target. No gold, diffs, hindsight or title edits used to read memories. Seed functions remain in place in every policy.

Test budget for suggestions is at most two fresh functions beyond dense top-10. For n>10, place one selected function at rank 10 or two at ranks 9 and 10, preserving the initial order of all other functions. No reordering of the initial top eight is permitted. MRR@10 can have a ceiling here; the primary endpoint is official-style all-target Acc@10. Secondary endpoints are macro Recall@10, Hit@10, MRR@10, nDCG@10 and Acc@5/15, plus extra function reads per issue, saved provenance edges, triggers, source tokens/bytes, overlap of suggestions and positive qrels. Count the six source reads separately from the 0–2 suggested next reads. Dense and query-only policies require no source reads; comparisons against them must expose that difference.

## Frozen policies

- Dense raw dot only, plus an independent BM25 reference for calibration.
- Query identifiers: at most two dense outsiders whose exact basename was explicitly called, quoted or code-shaped in the issue; highest original dense rank first. Budget equal to graph suggestions, no source reads.
- One witness: nominate every outside target reached from a seed. Rank by number of distinct source functions + one for exact issue identifier, then original dense rank.
- Corroborated (primary treatment): same sorting and nominations as one-witness, but require two independent provenance sources, defined as distinct source functions or one source function and an exact explicit issue mention. These are independent addresses/evidence channels, not statistically independent observations. Do not fill unused slots. 
- Two-callers-only ablation omits the query as a witness. 
- Matched null: for every actual corroborated proposal choose a replacement outside the initial top-10 and outside the actual proposals. Match its original dense rank band (11–20, 21–40, 41–80, 81+) and log2-binned globally unique-caller indegree (floor(log2(degree+1))); choose the nearest degree bin within rank band, then nearest rank band, then rank gap if no exact stratum. Resolve residual ties with hash of issue, original target and null candidate ID. Count exact pairs, fallbacks and shortfalls. Full AST pass for degree matching is evaluation-only and is charged separately. Null scores preserve actual trigger decisions when matches exist.

Primary contrast: corroborated minus dense on strict all-target Acc@10. Key mechanism contrast: corroborated versus one-witness; compare reads as well as accuracy. Secondary contrasts include query-only, matched null and two-callers-only. Paired 10,000 stratified bootstrap replicates (seed 91108) resample whole issues within size bands, two-sided exact sign/McNemar test for the primary binary paired contrast. Report individual winning and losing issues, number of labels per task and ceiling effects. Operational all-target denominator includes every positive function qrel; also audit authors' ID normalization, official Acc@10 implementation truncates ideal list at max_k=15 and any impact is explicitly reported. No claim about the full leaderboard from this subset.

# Повторная проверка выбора тестов после изменения кода

В десяти исторических задачах SymPy полностью восстановлены исходы **106 из 106** выбранных тестов для исходного и исправленного кода. Каждый переход рассмотрен в обе стороны, получено 212 решений о повторном запуске без исключений. Точный граф зависимостей выбирал 61 тест на направление и обнаружил все 11 смен исхода. Штатный pytest-testmon 2.3.1 запускал меньше тестов, но в одном случае при откате оставил устаревшее положительное заключение.

У 45 тестов в каждом направлении изменившийся файл присутствовал в общей истории, но изменённая функция или область модуля не совпадала с зависимостями теста. Во всех 45 случаях фактический исход сохранился. Для различия в доле запусков точного графа и testmon интервал кластерного бутстрэпа по задачам включает ноль в обоих направлениях (от −1,9 до +33,8 п.п. для исправления и до +36,9 п.п. для отката). При таком объёме вывод об общем превосходстве ненадёжен. Два направления зеркально используют одинаковые десять изменений. ## Изменение структуры класса

В задаче `sympy__sympy-20590` исправление добавляет `__slots__ = ()` в класс `Printable`. Это влияет на наличие `__dict__` у наследующих объектов. При откате `test_immutable` меняется с прошедшего на упавший. В сохранённой SQLite-базе этого прошедшего теста отсутствует связь с `sympy/core/_print_helpers.py`. В одиночном прогоне зависимостями теста оказались четыре других файла. В списке со всеми 13 тестами в обратном порядке плагин зафиксировал этот модуль для другой записи, но связь с данным тестом так и не появилась. В точном графе область модуля видна через **общую инициализацию**; локальный список покрытых функций самого теста этой связи также не содержит.

Проверено пять отдельных исполнений с новой базой, выключенной записью pyc и двумя разными фиксированными mtime с интервалом 200 секунд. В обоих сценариях отката тест остался невыбранным, отдельный обычный pytest подтвердил падение. В противоположном направлении плагин повторил ранее падавший тест и тот прошёл. Изменение непосредственно тела теста привело к его выбору и ожидаемому падению. При одном только изменении mtime содержимое осталось прежним, плагин пропустил тест, отдельный pytest прошёл. Эти измерения связывают пропуск с отсутствием ребра в наблюдавшихся зависимостях. Пропуск воспроизводился при разном порядке тестов и явно различающихся метках времени. [Сценарии и независимые исходы](immutable_audit_final/results.json), [состав записи после успешного одиночного теста](immutable_audit_final/single_revert/details.json), [описание зависимостей testmon](https://www.testmon.org/blog/determining-affected-tests/).

## Граница применимости графа

В отдельном синтетическом примере функция пытается загрузить необязательный модуль арифметических правил и при его отсутствии использует запасное правило. Создание файла изменяет ответ и вызывает падение ранее зелёного теста. Ни точный граф положительных зависимостей, ни testmon не выбрали тест. При зеркальном удалении файла оба метода выбрали тест, и он снова прошёл. Этот пример не входит в 106 наблюдений. Он показывает потребность в отдельной записи **наблюдавшегося отсутствия** потенциальной зависимости. [Исходники и сценарий](absence_probe.py), [фактические решения и трассы](absence_audit/results.json).

## Как воспроизвести

Отдельная venv на D использует Python 3.11.15, pytest 7.4.4, coverage 7.13.5, pytest-testmon 2.3.1, mpmath 1.2.1 и py 1.11.0. Хеши исходников реализации testmon совпадают с первым запуском. Базовое историческое окружение исходников не менялось. В первой попытке без пакета py три старые версии SymPy не смогли импортировать `py.test`. Логи находятся в `before_legacy_py`; после установки исторической зависимости все десять задач были прогнаны целиком. [Состав зависимостей](runtime-freeze.txt), [контрольные версии и хеши](compatibility-verification.json).

В исходном прогоне Python 3.14 допускал 102 из 106 сопоставимых тестов. Четыре расхождения относятся к тестам парсера задачи `sympy__sympy-24661`. На историческом окружении восстановлены три стабильно проходящих теста и одно реальное исправление, поэтому число смен выросло с 10 до 11. Результаты двух сред сохранены раздельно. [Сравнение сред для каждого исключённого теста](compatibility-verification.json), [итоги первой среды](../testmemory/results.json).

Из текущей папки последовательно выполнить `collect.py`, `predict.py`, `testmon_pair.py`, `score.py`, `audit_immutable.py`, `absence_probe.py` и `verify_compat.py` интерпретатором `D:/CodexResearch/x20-round9-test311-runtime/venv/Scripts/python.exe -B`. Сбор и временные копии расположены на D. Списки тестов и хеши исходных задач совпадают с исходным протоколом.

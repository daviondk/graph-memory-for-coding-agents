# Воспроизведение экспериментов R9 и проверка архива

Девятая серия хранится на диске D в `D:/CodexResearch/x20-bench-workspace/work/graph_memory_round9`. Восемь каталогов ниже содержат разные исследования, их исходные протоколы, результаты по задачам и технические квитанции. Время измерений и исходные ответы сохраняются в том виде, в котором их записал стенд.

## Проверка, упаковка и экспорт

Упаковщик работает со стандартной библиотекой Python 3.11 или новее. Эти команды запускаются из каталога R9. Две первые операции только читают источники. Полный список путей можно сохранить отдельно при необходимости.

```powershell
python package_local.py --audit
python package_local.py --list
python package_local.py --output D:/CodexResearch/x20-bench-workspace/outputs/graph-memory-round9-records.zip
python package_local.py --verify D:/CodexResearch/x20-bench-workspace/outputs/graph-memory-round9-records.zip
python package_local.py --verify D:/CodexResearch/x20-bench-workspace/outputs/graph-memory-round9-records.zip --export D:/CodexResearch/x20-bench-workspace/exports/round9-records
```

Для экспорта в имеющуюся локальную копию Git укажите **новый дочерний каталог** внутри неё. Экспорт проверяет хеши, создаёт только это дерево файлов и не обращается к Git. Состояние индекса и коммиты управляются отдельно. По умолчанию упаковщик отказывается перезаписывать существующий zip. Явный параметр `--replace` нужен только для его замены.

В `MANIFEST.sha256` перечислен каждый обычный файл архива с относительным путём и SHA-256. Сам манифест исключён из собственного перечня. Перед публикацией архива упаковщик перечитывает исходники, проверяет инвентарь и побайтовое содержимое ZIP. Если во время этого кто-то записал новые результаты, сборка прерывается и её можно повторить. Экспорт сверяет SHA-256 каждой выгруженной записи. Для единообразия между машинами архив использует постоянные метки атрибутов, времени и порядка. Запись SHA-256 всего ZIP в выводе позволяет отдельно проверить передачу файла.

## Что включается

| Каталог | Результаты в архиве | Что понадобится для повторения расчёта |
|---|---|---|
| `testmemory` | Записи базового и изменённого прогона pytest, узлы тестов, графы, прогнозы выбора тестов, стоимость состояния и журналы pytest-testmon | Базовые снимки задач из R8 и исходный интерпретатор эксперимента. Пути и контрольные суммы в collection-inputs и testmon-input. |
| `testmemory_compat` | Повтор в совместимом окружении, состояния до обновления зависимостей, проверки неизменности, снимки баз SQLite, тесты отсутствующих записей | Окружение из runtime-freeze, изолированные копии репозитория и исходники R8. Название immutable_audit_final отличает итоговую проверку от более ранней попытки. |
| `testmemory_holdout` | Независимый набор задач, фиксированные версии пакетов, первоначальная попытка и повтор, изменения состояния и логи | Базы задач из R7 reader и окружение совместимого pytest. Точки входа указаны в replication_protocol и run_holdout.ps1. |
| `budget` | Входные графы по ссылкам на соседние панели, фактически сериализованные состояния, выделение байтов, прогнозы, строки результатов | Данные завершённых панелей testmemory и стандартная библиотека. Параметр evaluate.py — имя панели для пересчёта. |
| `classguard` | Протокол, наблюдения типов при сборе тестов и оценка фильтра инвалидирования | Изолированные базовые деревья из R8 agent и R7 reader, тестовое окружение и рабочий каталог classguard. |
| `forward` | Протоколы основного и отложенного Java-наборов, отбор случаев, ссылки и хеши исходников, предсказания до разметки, бюджетная абляция и результаты | Исходные Java-блобы RefactoringMiner из sources.json.gz, кэш и Python с tree-sitter и tree-sitter-java. |
| `retrieval` | Официальные ID и решение об отборе, исходные dense/BM25-баллы всех функций, полные ранги, запросы к памяти, разметка, контроль глубины, CSV и стоимость чтения | Точная версия SweRank, корпус Loc-Bench и файлы реализации R8. Запуск сверки исходного энкодера требует весов и CPU-окружения. |
| `agentvalue` | Зафиксированные сообщения, ответы решателя, распределение и исходы тестов, логи pytest и JUnit XML, вспомогательные проверки и тесты устойчивости | QuixBugs, предыдущие среды/стенды, исходные задания, локальные веса Qwen и llama.cpp для новой генерации. |

Упаковщик включает файлы научных журналов (.log), тексты и скрипты, разметку и табличные результаты, сериализованные записи .gz, а также малые фиксированные .sqlite для аудита. В retrieval/dense текущий формат баллов — JSON с исходными значениями для каждой функции. Поддерживаются также небольшие числовые массивы с расширениями .npy/.npz и фиксированные бинарные состояния в предусмотренных каталогах. Если появляется неизвестный формат, инвентаризация сообщает его путь для проверки. Диагностические попытки, включая retrieval/format_smoke и testmemory_holdout/initial_attempt, сохраняются с оригинальными именами.

Для проверки целостности готового снимка достаточно архива и упаковщика. При новой генерации или сборе трасс используйте отдельное рабочее дерево, так как скрипты опытов записывают результаты рядом со своими входами. Исходные большие файлы продолжают храниться на D.

# Локальное изменение видимого ребра у обученного ридера

Проверяется дополнительный сценарий: пользователь помечает одно ребро как недоступное для ранжирования при том же фактически прочитанном тексте. Первичное требование — совпадение выбранного заголовка и правила разрешения равенства с полным пересчётом SQL для каждого фактического ребра всех трёх панелей. Дополнительно перебираем включение каждого отсутствующего ребра на тех же кандидатах. Все данные для такого вмешательства наблюдаемы, само вмешательство имитируется. Метрики качества трёх исходных панелей уже известны. Не подбираем веса или бенчмарки по исходу вмешательства.

После одноразового ранжирования одной группы достаточно знать лидера и кандидата на втором месте. Если уменьшается балл одного кандидата с положительным весом ребра, результат меняется только при вмешательстве в лидера. Пониженный балл сравнивается со вторым по полному стабильному ключу. При увеличении балла может выиграть только прежний лидер либо изменившийся кандидат. Пересчитываем балл изменённой записи из исходных признаков в той же арифметике, что и полный SQL. Если кандидат единственный, выбор всегда прежний. Это частный случай поддержки top-1 при обновлении одного кортежа, а не новая общая теория инкрементного поиска.

Регистрируем полные знаменатели по удалению и вставке, число смен, число смен без известного на том же входе модельного ответа и долю таких случаев. Неизвестным ответам не приписываем оценку. Скорость обработки оператором этим перебором не измеряем. Удаление признака связи при неизменном тексте и реальная редакция содержимого источника — разные вмешательства.

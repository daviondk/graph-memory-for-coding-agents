# Стоимость следующего чтения в SQLite

Добавлено после проверки эквивалентности SQL для всех 2 560 вопросов. Измеряем только стоимость получения второго адреса из уже вычисленных признаков одной SQLite-базы. Обучение, первый документ, эмбеддинги, создание лексических рангов и генерация лежат до/после измеряемой операции. Отдельно оцениваем однократное построение индекса для замороженных коэффициентов.

Фиксируем три запроса с тем же входом qid и выходом candidate. DENSE возвращает первый адрес по индексу (qid, dense_rank), GRAPH сортирует до девяти строк по линейному выражению, INDEXED_GRAPH находит того же победителя в выраженном индексе с замороженными коэффициентами. Индекс SQLite требует, чтобы выражения совпадали и параметры модели в его определении были литералами. Индекс рассчитан на повторные чтения тех же каталогов с неизменными весами; новый или изменённый каталог создаёт цену записи, а перенос на новые пары «вопрос–первая страница» требует посчитать их признаки. Для изменения весов нужен другой индекс. Сравнение INDEXED_GRAPH против DENSE включает преимущества покрывающего индекса с возвращаемым candidate; делаем и DENSE covering. Порядок при равенстве — исходный номер dense.

Сохраняем на диске новую БД временного опыта, данные 2 560 панельных вопросов и девяти или меньшего числа доступных заголовков. Измеряем размер файла после закрепления транзакций и до/после выраженного индекса, размер самих индексов по dbstat если доступно, время сборки на трёх копиях базы. Время полного синхронного CREATE INDEX + COMMIT (recreate on pristine copy). Не включаем время копирования. Шесть сбалансированных раундов с разным случайным порядком вопросов и чередованием шести перестановок трёх запросов по каждому вопросу. Первый разогрев вне измерения. У каждого режима одинаковые qid и количество вызовов. Сохраняем отдельные wall-clock наносекунды запросов execute + fetchone() при горячей базе и кэше sqlite statement. Агрегаты median и mean, парная разность и 95% интервал по средним на вопрос. Интервал отражает вариативность наблюдённых вопросов на одной машине. Операционная точка безубыточности условная: однократная средняя цена CREATE INDEX / средняя экономия одного чтения при горячей базе. Издержки поддержания индекса при новых записях здесь не измеряются.

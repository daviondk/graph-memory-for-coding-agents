# Дополнение после ретроспективной оценки доступных ответов

Завершаем недостающие наблюдения двух полных ранжирований, без переобучения. По каждому вопросу берём общий лимит L = min(старый L, длина новой страницы graph, длина новой страницы hybrid) в токенах исходного решателя. При сокращении L реконструируем исходные варианты с теми же заголовками, обрезаем только второй фрагмент, запускаем каждый новый массив токенов. Проверяем, что реконструкция каждой архивной страницы даёт точное побайтовое совпадение токенов при прежнем L. Сокращённые вопросы обозначаем отдельно. Хэши префикса и суффикса и размер проверяются по всем сравниваемым вариантам. У всех правил в этой проверке одинаковый контекстный бюджет в каждом конкретном вопросе.

Генерируем на одном GPU и тех же версиях llama.cpp и Qwen3-4B-Instruct-2507 Q4_K_M, что в R50. Кэш используем только по SHA256 точного массива токенов, с проверкой запроса и прошлой конфигурации. Проверяем воспроизводимость на независимой детерминированной контрольной выборке по 12 архивным промптам каждой панели, выбранным хешем идентификатора без доступа к ответу. При любом расхождении останавливаем объединение, указываем расхождение, продолжаем с повторным расчётом несогласующихся сравнений либо с предыдущими границами. Качество ответов считается отдельно на всех 640 и всех 1 280 без объединения. Дополнительные прямые контрасты graph против hybrid, dense, linked и gate по F1, EM и полному покрытию с указанием количества замен и парных 95% интервалов. Начальный основной критерий не меняется.

# Как проверить результаты

Из каталога baseline на диске D используется Python из D:/CodexResearch/x20-isetrace-e5-gpu/venv/Scripts/python.exe. CPU-проверки используют Python, NumPy, SciPy и стандартный sqlite3; повтор генераций также использует requests, исходные GGUF-веса и идентичную сборку llama.cpp. Проверки предполагают соседние неизменённые каталоги R50, R51 transfer и R51 routing. Команды PowerShell для числовой проверки

```powershell
$runner='D:/CodexResearch/x20-isetrace-e5-gpu/venv/Scripts/python.exe'
$env:OPENBLAS_NUM_THREADS='1'
& $runner -B verify_all.py
# Или отдельно по этапам
& $runner -B verify.py
& $runner -B verify_complete.py
& $runner -B confirm/verify.py
```

Первая проверка независимо восстанавливает градиенты на обучающих парах, исходные веса, 15 360 полученных в ретроспективных панелях решений, совпадения хэшей промптов, ранее частично наблюдаемый F1 и интервалы. Вторая сравнивает результаты SQL с решениями Python, восстанавливает каждую длину и общий префикс и суффикс во всех трёх панелях, сверяет новые ответы, учитывает только действительно сгенерированные токены и пересчитывает парные интервалы и измеренные стоимости. Внешний архив с полным корпусом и GPU для этих проверок не нужны. Последняя команда относится к отдельной последующей подтверждающей панели.

Последовательность для пересборки в копии каталога: `study.py register`, `study.py fit`, `study.py select`, `study.py grade`, `hotpot_select.py`, `complete_answers.py`, `grade_complete.py --official`, `sql_check.py`, `sql_timing.py`. До шага генерации требуются исходные архивы видимых документов на диске D по путям из complete_answers.py и два исходных оценщика. GPU-скрипт открывает временный loopback-порт 18896, проверяет версии модели и сервера, строит одинаково длинные входы, перепроверяет старые генерации и останавливает собственный процесс после завершения. Для проверки только текстовых оценок без офлайн-копий авторских скриптов достаточно `verify_complete.py`. Экспериментальный исход при каждом повторе сверяется по полям ответов отдельно от системных измерений времени. Поштучные значения времени при новом запуске будут зависеть от нагрузки и файловой системы.

На первом запуске переноса HotpotQA обнаружились девять коротких каталогов, поэтому оригинальная проверка числа кандидатов прекращала вычисление до первого прогноза. Первоначальный вариант проверяется по hotpot_select_v1.py и hotpot-plan-original.json. Окончательный запуск воспроизводится командой `hotpot_select.py`, проверяет hotpot-plan-transfer.json и охватывает все 640. [Описание совместимости](hotpot_cardinality_note.md)

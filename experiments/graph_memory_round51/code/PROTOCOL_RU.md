# Регистрация эксперимента по обновлению памяти кодирующего агента

Изучаем переходы между наблюдаемыми состояниями одной задачи SERBench. Ранг предыдущего состояния может сохранить полезный сигнал либо помешать новой информационной потребности. Одновременно проверяем, можно ли при почти том же порядке переиспользовать уже переданный фрагмент кода. Два заранее заданных опыта измеряют разные величины.

**Панели и наблюдения.** Берём 101 состояние R47 facet_confirmation для выбора одного коэффициента и 204 состояния outside R47 facet_reader для окончательной оценки. Репозитории панелей не пересекаются. Это повторное использование открытой Cal500; архивные результаты текущего ранжирования известны. Метрики новых вариантов до регистрации не вычислялись. Для каждого состояния используем последний доступный строгий префикс R50 и одну собственную предыдущую выдачу соответствующего варианта. Нельзя переносить информацию из другого запуска или более позднего шага. При отсутствии предыдущего состояния все методы выдают начальный пакет. Для перехода подходит только точное совпадение типа, исходного пути, координат, хеша содержимого и опубликованного текста фрагмента в том же репозитории и коммите. Идентификатор текущего кандидата восстанавливаем из локального пула. Для идентичных записей выбираем лучший предшествующий ранг. Учитываем уникальные идентичности при передаче.

**Опыт с прошлым рангом.** База — архивная модель Qwen3-Embedding-8B плюс обученный одноместный предиктор полезности и отсрочка просмотренного. Для обеих панелей берём целиком зафиксированную выдачу. Для совпавшего фрагмента усредняем логарифм текущего одномерного ранга и логарифм предыдущего базового ранга, вес прежнего ранга λ. Для отсутствующего предшественника используем текущий ранг. Итоговый порядок сохраняет разбиение по признаку «уже просмотрено» и на равенстве предпочитает текущий порядок. Коэффициент выбирается на 101 состоянии из {0, +1/4, −1/4, +1/2, −1/2, +1, −1} по Complete-MSS@8, при равенстве берётся первый по этому списку. Положительное значение поощряет устойчивость, отрицательное — рост оценки. Референс — текущий порядок при λ=0. Фиксированные ±1/2 публикуем для диагностики, независимо от выбора. Для отрицательного контроля циклически перемешиваем доступные значения прежнего ранга внутри групп «просмотрено × восьмёрка текущих рангов»; порядок перестановки задаётся SHA256 от state и ID. Контроль видит те же доступные записи. Первичный показатель — парная разность Complete-MSS@8 на всех 204 состояниях. Точность на состояниях с предшественником, GroupRecall@8, число обменов и разрезы по репозиториям вторичны.

**Опыт с передачей изменённого пакета.** Кэш клиента содержит только целый пакет последнего доступного состояния соответствующей политики. Возвращаем K=min(8,N) элементов. Потеря ранга пакета — сумма выбранных однобазных рангов минус 1+…+K. Допускаем максимум 4, число уже просмотренных в наборе фиксируем на уровне базы. Этот контракт даёт конечный алгоритм: элемент на позиции далее K+4 не может находиться в допустимом пакете. Среди всех допустимых пакетов минимизируем суммарную длину новых для кэша уникальных фрагментов по ранее измеренной сериализации Qwen. На равенстве предпочитаем меньшую потерю ранга, затем лексикографически меньший список рангов. Холодный старт у всех тривиален. Порядок внутри пакета соответствует замороженной базе. Сравниваем с тремя вариантами: неизменный лучший top-8 с тем же точным кэшем, минимизация общей длины пакета с игнорированием кэша при планировании, минимизация числа промахов без учёта размера. Реально переданные токены у всех считаются по собственным точным ключам. Первичный показатель на панели 204 — взвешенная по состояниям средняя разность числа переданных токенов за состояние к неизменному top-8. Для решения о пригодности требуем положительную нижнюю границу экономии и нижнюю границу двустороннего 95% ДИ разницы Complete-MSS@8 выше −2 п.п. Это исследовательский инженерный допуск. Пара с планом «более короткие фрагменты» оценивает добавку от исторических связей. Жадная локальная эвристика при необходимости в отдельной работе.

**Процедура и неопределённость.** Сохраняем все зашифрованные в смысле хеширования ключи, видимые порядки, выходы вариантов и хеши до вычисления окончательных метрик. Оценивание по публичным минимальным достаточным наборам и обязательным группам; перекрёстная проверка с реализацией авторов. Интервалы индивидуальные (20 000 парных перевыборок целых репозиториев, seed 510311, одна и та же матрица по вариантам); число выигрышей, проигрышей, запросов и репозиториев публикуем. Профилируем число реально выданных токенов полезной нагрузки при локальном точном кэше, без служебного протокола, полных токенов инференса и GPU-времени. Исполнение сценария Python на CPU с сохранёнными оценками Qwen. Протокол не измеряет конечное решение issue и официальный закрытый test. Источник задачи и оценщика — [SERBench](https://github.com/LordTARN1SHED/SERBench).

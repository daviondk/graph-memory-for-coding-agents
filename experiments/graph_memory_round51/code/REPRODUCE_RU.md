# Воспроизведение

Числовые архивы содержат результаты согласованного контроля R47, причинно доступных префиксов R50, метки Cal500 и размеры физического кадра каждого варианта. Сырые фрагменты берутся из публичного дистрибутива [SERBench](https://github.com/LordTARN1SHED/SERBench). Внешней отправки предсказаний не требуется. Зависимости для всех опытов — Python 3.14 с модулем compression.zstd, NumPy и файлы SERBench. Для одного пересчёта ранжирования годится более ранний Python с NumPy. В измерении формата использованы Python 3.14.4, NumPy 2.4.4 и libzstd 1.5.7. Исходное оценивание отбора выполнялось NumPy версии, записанной в [results.json](results.json).

Из каталога code выполнить:

```powershell
python -B -X utf8 verify.py
```

Эта проверка не требует исходного текста корпуса. Она восстанавливает 2 440 оценок из архивных порядков и публичных ординальных сертификатов. Альтернативный перебор множеств обменов проверяет оптимум всех трёх методов, ограниченных потерей ранга. Затем проверяются парные интервалы, суммы байтов, времена и внешние агрегаты. Для реального воспроизведения сжатых байтов указать путь к исходному SERBench, содержащий data/cal500, data/test500 и src/serbench. Затем выполнить:

```powershell
$env:SERBENCH_ROOT = 'D:/CodexResearch/x20-bench-workspace/work/memory_session5/serbench/upstream'
python -B -X utf8 verify.py --source
```

В этом режиме получатель начинает каждую цепочку с пустой памяти и использует только ранее восстановленный пакет. Все 7 320 кадров Cal500 базовых 24 режимов, 816 дополнительных фиксированных проверок и 1 964 кадра четырёх режимов Test500 кодируются, сверяются по хешу и декодируются без рассогласований. Отдельный стенд измерения задержки выполнил семь повторов плюс прогрев для каждого из четырёх вариантов каждого из 204 состояний. Точное совпадение байтов компрессора предполагает указанную версию libzstd. При другой версии идентичное восстановление может сохранить содержимое при различающемся потоке.

Для пересоздания прогнозов и результатов порядок команд следующий. Тайминги зависят от нагрузки. Для повторного замера, который должен сосуществовать с архивным, работать в копии структуры каталогов.

```powershell
python -B -X utf8 prepare.py
python -B -X utf8 predict.py
python -B -X utf8 evaluate.py
python -B -X utf8 wire.py
python -B -X utf8 columns.py
python -B -X utf8 external.py
```

Команды используют относительные пути к R34, R39, R47 и R50 в том же репозитории. Состав источников и их SHA256 зафиксирован в [input-seal.json](input-seal.json). [forecast-seal.json](forecast-seal.json) фиксирует прогнозы перед оценкой, [external-results.json](external-results.json) дополнительно фиксирует официальный файл Test500 и ранее выпущенные предсказания R39. Для [первого протокола](PROTOCOL_RU.md), [побайтовой передачи](WIRE_PROTOCOL_RU.md), [проверки функциональной зависимости](COLUMNS_PROTOCOL_RU.md) и [внешнего переноса](TEST500_PROTOCOL_RU.md) сохранены разные предварительные планы. Тексты фрагментов в релизе не дублируются.

# Проверка функциональной зависимости поля digest и цены одиночного кодировщика

Завершён первичный побайтовый опыт: ссылки дают только 0,299% на общей панели по сравнению с уже сильным словарным кодированием. До проверки содержимого hash-поля задаём одну дополнительную гипотезу. У неизменяемого фрагмента метаданные могут включать SHA256 от опубликованного content_excerpt. Если это так, независимый получатель может восстановить это поле; терять записи с усечённым или нормализованным текстом нельзя. Проверяем единственное условие, content_sha256 == SHA256(content_excerpt.encode("utf8")). Без нормализации строк/пробелов и без перебора эвристик. Несовпавший digest всегда передаётся буквально.

Основная пара использует форматы строк со ссылками, выбранный ранее уровень Zstd 19 и словарь предыдущего пакета. Сильный контроль кодирует поля компактно: evidence_id, имеющий канонический префикс и 24 строчные hex-цифры, передаётся как 12 байт, digest из 64 строчных hex — как 32 байта; неприменимые по форме значения передаются полностью. Прочие значения, включая None и UTF-8, имеют типизированные длины; это позволяет проверить эффект восстановления digest отдельно от устранения текстового hex. Представления обеих сторон идентичны, кроме локального выбора между литералом и специальным обозначением вычислимого SHA. Ранее использованная гипотеза «скопировать прошлую строку или прошлое тело» применяется одинаково. Физический словарь в обеих сторонах — одинаковый прошлый полный компактно сериализованный пакет, чтобы не смешивать эффект преобразования текущего сообщения и прошлого словаря. Общая byte-разность, 95% ДИ с 20 000 перевыборками репозиториев (seed 510313), для всех 204 и для 99 тёплых состояний. Также показываем долю выводимых хешей в выдаваемых строках и прямое сравнение с ранее оценёнными лучшими фиксированными JSON-форматами. До измерения неизвестно, хеш чего именно представлен полем. Отрицательный результат оставляем в журнале.

Отдельно измерим время одиночных форматов «JSON-строки» и «JSON-строки со ссылками» из завершённой dev-селекции, а также пары фиксированных бинарных кодировщиков этого протокола. Для каждого из 204 состояний семь чередующихся измерений, порядок четырёх режимов задаётся устойчивым хешем идентификатора и номера повтора. Предварительный прогрев каждого режима отдельно. Кодирование и декодирование измеряются раздельно, подготовка словаря из доступной прошлой капсулы входит в каждое измерение, чтение с диска исключено. Публикуем медианы запусков для каждого запроса, отношение сумм и 95% ДИ по репозиториям. Измеряем в одном локальном процессе, выводы о сетевой/полной задержке требуют работы на приложении.

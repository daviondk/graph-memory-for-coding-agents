# Дополнительная зарегистрированная проверка побайтовой передачи

Отбор по минимуму переданных токенов в основном опыте потерял два полных набора и не достиг порога не меньшего качества. Проверяем другую интервенцию после фиксации этого результата. Выбирается ровно исходный текущий top-8 для каждого состояния. Меняется исключительно представление на канале между хранилищем и клиентом. Гипотеза — разделение локальных идентификаторов текущего состояния и неизменяемых тел позволяет повторно использовать тела из прежнего пакета, поверх стандартного словарного сжатия, сохраняя весь контекст. Никакие значения размеров провода до этого протокола не подсчитывались.

**Контракт.** Капсула — полная упорядоченная восьмёрка исходных (evidence_id, source_type, source_path, line_start, line_end, content_sha256, content_excerpt). Отличия версии снабжают ребро при подготовке входов, допустимые переходы подтверждены внутри одного базового коммита и запуска. При декодировании известны только код алгоритма и предыдущая уже восстановленная капсула той же цепи. Для холодного начала словарь пуст. Капсула сериализована детерминированным UTF-8 JSON. Номера позиций прошлого пакета заданы вместо передачи неизменившегося тела. Сохраняем текущие evidence_id отдельно, включая случай, когда он изменился у того же тела. При совпадении всего ряда допускаем короткую ссылку на ряд. Все идентификаторы режимов и служебные символы входят в измерение. Доставка/подтверждение предыдущего пакета, TCP/TLS, хеш транспортной защиты и пересогласование после потери здесь вне измерения.

**Сильные контроли.** Прямой JSON по строкам и JSON с двумя столбцами (ID и тела отдельно); каждый со Zstandard 3, 9, 19 без словаря и с предыдущей капсулой того же представления в качестве raw dictionary. Чтение соло проверяет каждый кадр. Экономичный протокол добавляет последовательность, где одиночный номер копирует целую старую строку, пара (ID,номер) — старое тело, самостоятельный массив — новую строку; отдельно вариант со столбцом ссылок на тела и непрерывным массивом ID. Каждый вариант кодируется с теми же уровнями и с/без предыдущего логического полного пакета в словаре, чтобы новые куски тоже могли повторно использовать код. Все режимы используют однобайтовое самодостаточное обозначение семейства, уровня и словаря, включая холодные состояния. Время кодирования дополнительное — две альтернативные политики выполняют 12 либо 24 кодирования на вопрос, что должно быть явно отражено при интерпретации; измерим одним процессом прогретую парную задержку обеих политик отдельно.

**Заранее заданные сравнения.** Для каждого пакета эталон сильного общего компрессора пробует все 12 комбинаций без явных ссылок, выбирая самый короткий кадр. Исследуемое правило пробует тот же набор и ещё 12 вариантов с передачей локальной ссылки. Равенство отдаём раннему базовому варианту. Побайтная экономия монотонна по построению; научная величина — частота реального выбора и размер выигрыша, а также время. Отдельно сравниваем две фиксированные единственные конфигурации (каждая лучшая на dev в своей группе) на 204 состояниях. Это предотвращает интерпретацию полного перебора как бесплатного улучшения. Основное сравнение — процент дополнительных сэкономленных байтов от сильного эталона на 204 и 95% ДИ по парной перевыборке 69 целых репозиториев, 20 000 повторов, seed 510312. Вторично — те же числа на 99 переходах, число строго улучшенных пакетов, средние байты и время. Проверка каждого декодированного ряда/идентификатора на исходной выборке обязательна. Точность Complete-MSS@8 поэтому тождественна текущему порядку по конструкции. Обе панели уже использовались для других экспериментов. Официальное описание формата Zstandard — [RFC 8878](https://www.rfc-editor.org/rfc/rfc8878).

# Интерактивное обслуживание потока наблюдений

В рабочий пакет Demonstrations добавлены две SQLite-консоли. В **Streaming packets** можно проследить за растущей историей инструментов. Посетитель выбирает один из трёх журналов, частоту сохранения состояния таблицы и момент следующего чтения. Каждая сессия начинает с пустой памяти, приобретает новые наблюдения и учитывает пересмотр числа исходящих связей. В интерфейсе видны выбранные ID, цена пакета в токенах и число строк, вычисленных после изменения источников. Кнопка проверки независимо строит оптимальный контекст по текущим наблюдениям.

На средней траектории при чтении каждой группы в девятой группе обновление возвращает алгоритм к строке 48. Обработана 31 из 79 строк полной таблицы. Если пропустить несколько промежуточных чтений, к той же группе потребуется другое число строк. В обоих случаях можно проверить полный порядок выдачи. Все три примера выбраны по хешу и интервалу длины без доступа к эталонным ответам. Их 78 групп проверены независимо при четырёх вариантах хранения промежуточных строк.

В **Learned evidence packets** посетитель меняет точку чтения и сравнивает допустимые нижние границы. Для последней точки длинной истории 2 фрагмента обязательны, 107 можно исключить, ещё 61 требует оптимизации. Точная проверка сравнивает 22 812 вычислений остаточной DP со 189 290 у полного плана. Проверены две политики на четырёх точках трёх историй (24 сценария). Новая консоль демонстрирует целочисленную модель Q32. В отдельной проверке сохранена арифметика float64 первоначального читателя. В распакованном архиве команда `python -B demo.py` запускает все шесть локальных консолей, `python -B verify_candidate.py` выполняет проверки SQLite и HTTP. Совокупный аудит проверяет 312 состояний новой консоли, 24 сценария отбора обученным читателем, остальные четыре приложения, контрольные суммы и согласованность исходников с содержимым архива. Для воспроизведения самой записи экрана требуется Windows с английским синтезом речи, Chrome или Edge, Playwright, Pillow и FFmpeg. Рабочий черновик оставляет авторам заполнение авторского блока и научную вычитку.

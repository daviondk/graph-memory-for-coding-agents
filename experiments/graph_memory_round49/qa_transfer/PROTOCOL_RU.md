# Перенос зафиксированной Qwen-политики на весь MuSiQue-Ans dev

Берём все 2 417 записей официального answerable dev v1.0 по исходному ID, без отбора тем, наличия упоминания или успешности placebo, без исключения общих документов. Ранее R32 использовал эти вопросы для retrieval, R33 полностью оценил ответы экстрактивного DistilBERT. Замороженные R46/R47 с Qwen оценивались на 1 024 вопросах официального train. Этот опыт переносит связку ридера, правила и двух контролей на другой split; данная выборка известна проекту. Учебный корпус самой Qwen публично ретроспективно не инвентаризируется.

Главный контраст — средний официальный MuSiQue Answer F1 по всем вопросам для выбора второго документа по подлинному упоминанию его заголовка в первом прочитанном абзаце против того же лексического ранга с расширением по первому фрагменту. Вторичный — F1 подлинных переходов против среднего пяти placebo по R47 (те же seed 47011, 47023, 47039, 47051, 47063). Все семена присутствуют в каждом вопросе. Используем прежние неизменённые R31/R32 choose/Evidence и R47 place. Позиции, число связей и решение переключиться с лексического лидера сохраняются; при невозможности подмены работает прежнее правило. Сначала запираем ID и порядки, затем собираем фактические токены. Проверяем официальную версию файла, отдельно перекрытие нормализованных вопросов, ID и абзацев (SHA256 заголовка и текста) с R46 панелью и полным train. Все документы одного примера являются исходным фиксированным каталогом.

Формирование контекста повторяет R46/R47. Вопрос ограничен 80 токенами GGUF, каждый из двух документов 192. Внутри одного вопроса длина второго фрагмента — минимум среди четырёх исходных ветвей R46 и пяти placebo R47 (true и lex входят в исходные четыре). Фактический размер каждого из семи полных запросов обязан совпасть. Шаблон, порядок документов, Qwen3-4B-Instruct-2507 Q4_K_M, хеш llama.cpp, один слот, temperature=0, top_k=1, seed 460001, предел 96 выходных токенов и останов на переводе строки — по R47. Все разные последовательности этого split генерируем заново. Для совпадающего входа проверяем точное равенство токенов и переиспользуем ответ внутри опыта. Воспроизводим 32 разных входа, выбранных по SHA256 с солью r49-repeat; расхождения публикуем. Никакие действия или инструкции из документов не исполняются. Генератор читает только токены после запирания. Грейдер получает доступ к ответам, алиасам и поддерживающим абзацам после фиксации всего набора прогнозов.

Для EM и F1 проверяем балл каждого вызова независимым нормализатором и проверяем среднее официальным AnswerMetric. Сохраняем per-question ответы и назначенные вторые документы по каждой ветви. По полным знаменателям публикуем средние, парные разности, положительные/отрицательные/нулевые изменения; интервалы 95% по 10 000 повторным выборкам кластеров точного первого документа. Второй интервал placebo повторно выбирает также общие пять семян (R47). Покажем срез ID-переключений (true против lex), неизменённых входов, числа опор, фактической подмены, перекрытия первых документов с R46; это описательные срезы. Полнота поддержки и наличие ответа в доставленном тексте вторичны. Различаем долю изменённых адресов среди всех, покрытие по факту и качество ответа. Предел ресурсов не меняет панель после начала генерации. Все 2 417 запланированы. Время и число уникальных запусков будут измерены.

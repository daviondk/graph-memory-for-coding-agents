# Отбор задач до оценки

Используем все 111 целевых строк из закреплённой версии VibeMemBench. В локальном Docker имеются ранее использованные Click-1915 и Traitlets-670. В публичном файле это единственные строки этих двух репозиториев. Поэтому для переноса берём другую пару задач одного проекта. Ограничиваем скрининг тремя Python-библиотеками для табличных данных или тестирования с двумя строками: alteryx/woodwork, HypothesisWorks/hypothesis, sdv-dev/RDT. Они входят в заранее определённый набор реализуемых областей. Выбор условен относительно этого домена и не является случайной выборкой из всех 111.

Для каждого из шести контейнеров запрашиваем только публичный манифест Docker Hub Linux amd64. Пригодный репозиторий должен давать две новые задачи с публичными постановками, выполнимыми правками существующих Python-исходников и независимым официальным оценщиком. Исключаем задачи по разработке/воспроизведению уязвимостей, инструкции, зависящие от внешних сервисов, и отсутствие описания требуемого поведения. Допускаем одну пригодную задачу, если ни одна пара не проходит. Выбираем сначала пару, затем минимальные суммарные сжатые байты уникальных слоёв образов в паре. При равном размере используется алфавит имени репозитория. Максимум 900 МБ на пару и не менее 2,75 ГБ свободного места на D: после консервативной четырёхкратной оценки размера загрузки. Проверяем фактическое свободное место перед каждым образом; без удаления исследовательских артефактов.

До фиксации задач смотрим только instance_id, repo, image_name, base_commit, problem_statement, created_at и язык. PR описания, patch, test_patch и названия тестов не открываем. Каноническая оценка будет запущена после блокировки всех патчей. Проверка произвольной сложности задач и замена из-за результатов решателей запрещены. Образ проверяется до передачи снимка и хранится локально.

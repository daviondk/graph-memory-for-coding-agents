# Слепой опыт на задаче Woodwork

После скрининга без тестов и исправлений ни одна полная пара не удовлетворила зарезервированному месту на D:. В резервной одноцелевой ветви выбран наименьший подходящий индивидуальный образ из шести. Это alteryx__woodwork-640, 619 196 672 сжатых байта, коммит 7bde24e9c9b5c5a0e228b4c62c094fced9901c3b. Публичная постановка требует удаления столбцов с переносом типизации. Снимок и результаты одинаковы для всех трёх условий. Единица вывода — одна целиком взятая задача. Условия — графовая память, плоская лексическая память, пустая память. По одному независимому исполнителю одной конфигурации на условие, без наследования переписки, с перемешиванием адресов случайным генератором ОС.

До встречи с решателями одна подготовительная сессия выполняет обычные действия публичного API на маленькой синтетической таблице. Стандартный профилировщик Python записывает фактически выполненные вложенные вызовы собственных функций Woodwork. Для каждого наблюдённого узла записывается ограниченный фрагмент около определения с координатами. Обе политики выбирают из одних и тех же наблюдений. Сильный лексический порядок использует BM25 на терминах из полной постановки, удваивает токены пути и имени функции, расщепляет CamelCase и подчёркивания. Порядок графа — равновесное распределение персонализированного PageRank; начальные веса пропорциональны положительному BM25 с добавлением 0,01, коэффициент перехода 0,6, на каждом узле нормализация фактически наблюдённых связей по весу log(1+число вызовов). Для короткого контекста возвращаем по 4 разные выполненные функции фиксированными блоками до 400 байт. Если текст короче, следующий узел дополняет до одинаковой длины самого короткого из двух представлений; заголовки и границы включены в байты. Печатаются только подлинные фрагменты исходного коммита. Отсутствие различий между пакетами будет зафиксировано.

Используются вызовы init, выбор по имени и набору имён, просмотр schema, копия DataFrame и чтение logical_types. Нет вызова требуемой новой операции и просмотра эталона. Ошибка отдельного калибровочного действия логируется. Граф показывает динамический стек вложенных вызовов; статические совпадения имён и каузальное следование, не подтверждённое вызовом, не добавляются. Пересчитываем ранги на фактически полученных узлах без выбора по интересности результата.

Общий лимит доставленных исходных наблюдений — 16 000 байт на исполнителя, включая память, поиск, чтения и список путей. Пустая память оставляет весь лимит интерактивному чтению. Ввод публичной задачи, метаданные бюджета и JSON-обёртки считаем отдельно. До 18 чтений, 12 поисков, 8 изменений, 2 листингов и 3 изменённых файлов. Все работы ограничены фактическими Python-файлами производственного пакета, полный checkout, тесты, сторонние команды, сеть и внешний контекст исполнителю запрещены. По окончании все три запечатанных патча фиксируются в общем обезличенном lock; только после этого читаются официальные тесты и авторский патч. Соответствие условиям раскрывается после фиксации оценок.

Первичный исход — точное сравнение множества прошедших тестов нативным оценщиком VibeMemBench. Вторичные — количество F2P/P2P, потреблённые байты с учётом пакета, уникальные пути, операции. Перед интерпретацией контрольные база и авторский патч обязаны дать соответственно отрицательный и положительный результат. При технической ошибке не подменяем задачу и сохраняем причину. Одного наблюдения на условие недостаточно для проверки статистической значимости или переноса на популяцию задач.

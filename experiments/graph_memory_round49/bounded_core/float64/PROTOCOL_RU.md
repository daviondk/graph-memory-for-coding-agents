# Проверка исходной численной семантики обученного читателя

После обнаружения трёх расхождений Q32 с исходными float64-пакетами фиксируем новый физический план. При предварительном сокращении задачи используем целые интервальные границы; оптимизируем оставшиеся элементы в **исходной арифметике BINARY64 и порядке рангов**. Чтобы не изменять порядок сложения обязательных к включению положительных элементов хвоста, этот вариант только удаляет доказуемо недопустимые переменные; все остальные элементы проходят стандартный float64 DP. Строго лишние варианты должны иметь разрыв, превышающий консервативный запас по округлению. Сравнение — полный оптимизированный float64 DP с тем же порядком, допускающий мгновенную выдачу целиком помещающегося хвоста. Базовая нижняя граница — максимум двух допустимых решённых жадно пакетов (по плотности и по текущему рангу). Параметры не настраиваются по выходам.

Основной показатель — полное совпадение исходных упорядоченных архивных выдач на всех 40 000 состояниях (2 000 вопросов × 4 состояния × 5 инициализаций), парное время на seed13, затем среднее по пяти с двусторонними интервалами. Проверки на малых входах и однократный прогрев, пять рандомизированных повторов. Сохраняем исходные float64 двоичными массивами и публикуем расчёт защитного запаса. Метод защищает именно бюджетный выбор при данных моделях и контрактах входа, оценка скорости не включает пересчёт графовых логитов.

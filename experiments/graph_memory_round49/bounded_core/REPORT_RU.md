# Точная сборка контекста обученного графового читателя после обновления весов

На четырёх последовательных срезах 2 000 историй вопросов ISETrace и пяти инициализациях модели удалось воспроизвести **все 40 000 исходных упорядоченных пакетов float64**. Выбор контекста занял в среднем **131,11 мс против 278,75 мс** на 8 000 состояний одной инициализации. Ускорение **2,13× [2,08; 2,18]**. Другие условия, включая ранги модели, полезности, стоимости кандидатов, защищённый префикс и бюджет 2 048 токенов, одинаковы. Это измерение CPU-оператора после расчёта оценок графовой модели. Оно относится к основному читателю R41 с ранее измеренным финальным Full Support 82,60%, а не к иному варианту на графе без рёбер смежности, давшему 83,07%. Глобальный рекорд по качеству или времени этой проверкой не устанавливается. [Срезы и проверка порядка](../learned_stream/REPORT_RU.md) · [Все замеры float64](float64/results.json)

## Какие решения можно исключить

Пусть uᵢ и cᵢ — текущие целочисленные полезность и цена необязательного фрагмента, B — доступный остаток бюджета. Допустимый пакет даёт нижнюю границу L. Для любого неотрицательного λ дробная релаксация допускает верхнюю границу U = λB + Σ max(0,uᵢ−λcᵢ). Берём отношение полезности к цене первого элемента, не помещающегося при непрерывном заполнении в порядке плотности. При положительной приведённой стоимости rᵢ = uᵢ−λcᵢ отказ от этого элемента уменьшает верхнюю границу на rᵢ. При отрицательной — включение уменьшает её на |rᵢ|. Если |rᵢ| > U−L, ни одно оптимальное решение не может выбрать худший из двух исходов. Строгость сравнения сохраняет все оптимальные наборы при ничьей. Остаток решается исходной динамической программой в порядке рангов. Границы сравниваются после домножения на знаменатель λ в целой арифметике; для всех входов проверена вместимость 64-битного типа. При cᵢ=0 случай обрабатывается отдельно. Выделение ядра задачи о рюкзаке — известный метод. Исследуемый вклад — его применение к изменяющимся бюджетным представлениям исполнения, проверка сохранения полного порядка и прямой эксперимент с предыдущим пакетом как источником нижней границы. [Pisinger, Operations Research](https://doi.org/10.1287/opre.45.5.758)

## Целочисленное сокращение и роль прошлой выдачи

Средняя стоимость относится ко всем четырём срезам на 2 000 вопросах в одной инициализации. Для каждого вопроса берётся медиана пяти чередующихся измерений. Доверительные интервалы получены 6 000 перевыборками целых траекторий и инициализаций. Публикуются и результаты заранее выбранного seed 13.

| Точный план Q32 | Seed 13, мс | Среднее по пяти, мс | Обновления ячеек на пяти инициализациях |
|---|---:|---:|---:|
| Полная DP | 263,07 | 273,49 | 2 770 260 163 |
| Граница из допустимого пакета по плотности | 62,08 | 63,18 | 368 510 459 |
| Та же граница плюс ранее выбранное свидетельство | 61,99 | 62,74 | 344 718 200 |
| Та же граница плюс жадное чтение текущего ранга | 58,23 | 59,05 | 311 228 721 |

По сравнению с полной DP вариант с прошлым контекстом получил 4,24× [4,14; 4,35] на основной инициализации и 4,36× [4,24; 4,48] на пяти. Но относительно исходной границы только по плотности отношение составило **1,007× [0,998; 1,016]**. Уточнение по рангу текущего снимка оказалось быстрее предыдущего пакета. Исторический вариант действительно усилил нижнюю границу на 2 702/40 000 снимках, текущий ранг — на 8 375. По этим данным преимущество обеспечивает безопасное исключение кандидатов, преимущество от хранения прежнего решения в этой задаче не подтверждено. ## Зачем понадобился второй вариант

Ускоренный алгоритм Q32 полностью совпал с полным Q32-решателем в 40 000/40 000 состояниях. В трёх из них целочисленный контракт и опубликованная float64-реализация выбрали разные ID. Решения были почти неразличимы по полезности, однако смена даже одного ID нарушает требование к контексту агента. Во втором плане сохраняются исходные двоичные числа, порядок рассмотрения кандидатов и порядок сложения. Приведённая стоимость в Q32 применяется только для **исключения** кандидата из задачи, с запасом на округление. Каждый оставшийся кандидат проходит ту же float64-DP, что и у полного решателя. Это также сохраняет порядок накопления суммы при равенстве.

При n положительных полезностях округление каждого значения до ближайшей единицы Q32 даёт ошибку суммы не более n/2. Для обычного последовательного сложения в binary64 при nε < 0,01 ошибка не превосходит nε/(1−nε) от суммы положительных слагаемых. В коде целочисленный запас на обе сравниваемые суммы берётся как n+4+ceil(4nε(Σuᵢ+n)). Лишь когда возможность включить элемент проигрывает нижней границе сильнее этого запаса, удаляем его. Проверены исходные положительные конечные значения, верхняя граница nε и соответствие каждого сохранённого Q32 значения исходному float64. Число исключённых позиций на всей панели — **2 289 134 из 3 123 868** хвостовых кандидатов с учётом повторения по четырём срезам и пяти инициализациям. На seed 13 время сократилось с 268,75 до 127,41 мс, **2,11× [2,06; 2,16]**. Подтверждены все 40 000 исходных пакетов и 420 пограничных синтетических входов. [Численная спецификация](float64/PROTOCOL_RU.md) · [Исходный бенчмарк](https://arxiv.org/abs/2609.25913)

Воспроизведение из общей серии — `python -B verify.py` с NumPy и g++ с поддержкой C++17. Проверяются предсказания всех четырёх целых планов, два вещественных плана, арифметические расхождения, полные числовые интервалы и SHA исходных весов. `PACKET_BUILD_DIR` задаёт существующий каталог для временных библиотек. `bench_core.py` и `float64/run.py` повторяют каждый свой временной эксперимент в отдельной копии. Внутри `float64/weights-*.f64.gz` лежат little-endian числа binary64 в порядке хешей вопросов и срезов. Для сборки из оригинального графового прогноза служит `float64/extract.py`; опубликованных чисел достаточно для независимого запуска.

## Независимый решатель

На отдельной заранее хешированной панели из 128 вопросов (512 состояний) два опубликованных решателя Google OR-Tools 9.15, динамическая программа и метод ветвей и границ, подтвердили целевую сумму Q32 во всех 512/512 случаях. Из 512 оптимумов 498 превысили предел знакового int32. По ID совпали 512/512 у внешней DP и 490/512 у ветвей и границ. Это объясняет, почему для воспроизводимой памяти имеет значение также правило разрешения ничьих. Измерения через разные Python-интерфейсы пригодны для описания этих запусков; они не устанавливают превосходства по скорости нативных решателей. [Панель и исходы](classic/REPORT_RU.md)

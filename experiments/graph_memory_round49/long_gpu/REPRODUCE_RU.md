# Воспроизведение физических измерений

Для автономной проверки нужны Python и NumPy. Выполните `python -B verify.py`. Проверяются все 96 полных рангов, корректность источника каждого повторно использованного вектора, фактические токены, сдвиг итогового качества, порядок условий, 21 парный кластерный интервал и положительный аппаратный счётчик для каждого запроса. В каталоге содержатся только идентификаторы, числовые прогнозы, ординальные сертификаты, хеши и показатели стоимости.

Полный повтор требует Windows с WDDM, RTX 3090, точной сборки llama.cpp, зафиксированного Q4_K_M, локальной Cal500 и файлов из [R48/embedding_reuse](../../graph_memory_round48/embedding_reuse/REPRODUCE_RU.md) и [R48/cache_admission](../../graph_memory_round48/cache_admission/REPRODUCE_RU.md). Сборочный путь `work/graph_memory_round39/author_baseline` заполняется из [опубликованного Qwen-комплекта R39](../../graph_memory_round39/qwen_reference/QWEN_REPRODUCE_RU.md). Для сервера требуется requests. Исходные проекты не исполняются. Доступ к сети не требуется.

```powershell
$env:OPENBLAS_NUM_THREADS='1'
$env:OMP_NUM_THREADS='1'
python -B panel.py
python -B pdh.py
./gpu.ps1
if ($LASTEXITCODE -ne 0) { python -B finalize_receipts.py }
python -B transfer.py
python -B split_audit.py
python -B score.py
python -B stages.py
python -B verify_transfer.py
python -B heap_audit.py
python -B report.py
python -B verify.py
```

Gpu.ps1 берёт общий именованный mutex. По умолчанию контрольные точки уровня целой репозиторной цепочки лежат в `D:/CodexResearch/x20-r39-embedding-runtime/r49-real-vector-cache`; новый замер делайте с самостоятельным пустым каталогом квитанций в отдельной копии проекта. Процесс верифицирует условия по полной подписи перед использованием прежних квитанций. Оригинальный манифест сохраните отдельно. До начала отсчёта каждого запроса числовые векторы соответствующего метода присутствуют только для допущенных кешем ключей. Оригинальные строки находятся в общей памяти стенда для одинаковой подачи всем четырём вариантам.

Служба PDH читает `GPU Engine(*)/Running Time` и выбирает записи того PID, который запустил стенд. Поля device_engines дают приращения каждого движка в секундах. Основная аппаратная величина compute_engine_s включает только CUDA/Compute/3D; copy engines сохранены отдельно. Этот счётчик не равен исключительно времени запуска отдельных CUDA-ядер. Лог времени RPC включает и клиентскую обработку ответа, и передачу через 127.0.0.1. [Контракт эксперимента](PROTOCOL_RU.md)


Стенд с тихим логированием уровня 3 завершил все восемь цепочек, затем не нашёл в логе текстовый баннер выгрузки на GPU. Для упаковки использован независимый этап finalize_receipts.py. Он проверяет подписи всех восьми исходных квитанций, имя модели в серверном логе и положительный счётчик WDDM CUDA для всех 96 запросов. Скрипт завершается ошибкой при неполных квитанциях. При нескольких логах укажите ему нужный файл через --log. Численные значения времени и прогнозы взяты из исходных квитанций. Структура run-seal.json сохраняет происхождение итогов.

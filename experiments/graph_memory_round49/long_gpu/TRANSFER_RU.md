# Дополнительная проверка расхода токенов на полном наборе других репозиториев

До первого подсчёта токенных исходов на этой группе и до анализа физического сравнения фиксируем числовой replay всех 179 train-состояний R34. До начала R49 ни одно из них не входило в 305 состояний R48. Политики полностью заморожены в предыдущей серии. На входе те же native Qwen token IDs и namespace; разрешены только строгие предшественники в одной траектории, задаче, репозитории и коммите. Каждый запрос сначала использует текущее содержимое кеша, а внутрипакетные дубли устраняет отдельно; затем меняет долгосрочное состояние. Размер 524 288 байт, до 31 вектора.

Публикуем входные токены без кеша, внутрипакетную и дополнительную межсостояниевую экономию отдельно. Для 179 основная величина переноса — разница долей сэкономленных токенов «частота × стоимость» против пакетного hot-LRU со стоимостным разрешением равенств, дополнительная — против пакетного GDSF. Общий знаменатель — токены исходного запроса и всех предоставленных документов до дедупликации. 20 000 целых репозиторных перевыборок с seed 490731. Вторично повторяем на состояниях вне 24 физически проверяемых и на строгих стадиях с 0/1/2+ предшественниками. Для измеренных 24 сравниваем числовой replay с реальным индивидуальным счётчиком для каждого режима. Если допустимая история полного набора у конкретного состояния шире истории измеренного запроса, пересчитываем аппаратную пару в её собственном порядке и объясняем разницу. Временные оценки из replay не выводятся. Этот анализ не изменяет первичную физическую проверку 8 цепочек.

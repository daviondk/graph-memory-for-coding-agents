# Воспроизведение

Запустите `python -B verify.py` в распакованном исследовании. Требуется стандартная библиотека Python 3.10+ и g++ с C++17 в PATH. Временная библиотека собирается на месте. Проверяются 40 000 оптимальных выборок Q32, три несовпадения с исходной float64-реализацией, полные списки ID, цены, 30 000 переходов и числители со знаменателями в пяти сводках. Для каждого случая расхождения автономно повторяется последовательный float64 DP. Манифест фиксирует все числовые входы, результаты и программы.

`python -B analysis.py 13 17 29 37 41` повторяет все диагностические расчёты, сохраняя отдельный ledger и summary для каждого seed. Для bootstrap нужен NumPy. Во входных input-*.json.gz на каждый вопрос имеются хешированный ключ и траектория, список ID в настоящем хронологическом порядке, стоимости, а в каждом состоянии — процент, номер события, список ID в ранговом порядке, массив Q32-полезностей и архивная выдача обученного читателя.

Для полной реконструкции числовых входов используйте `python -B extract.py 13 17 29 37 41` в исходном дереве исследований с R20/R21, R33, R35, R39, R41 и проекцией соседнего stream_packet из R49. Нужны сохранявшиеся признаки x20-r33-budget-loss, стек научного Python и исходный float64 kernel R39. Ключи соответствуют именно позиции неизменного кандидата опубликованной панели. Те же идентификаторы связаны с фактическим порядком появления полей в R49. Программа независимо проверяет происхождение признаков, цены всех кандидатов и подписанные данные и прогнозы R41. Копии исходных трасс и эталонные ответы в архиве для проведения эксперимента не требуются.

# На скольких строках сохраняется состояние опубликованного обученного читателя

Отбираем все 2 000 вопросов, четыре заранее опубликованные доли завершённых групп (25, 50, 75, 100%) на одной основной инициализации Dense-FT 13. Каждая пара соседних состояний, включая совпавшие срезы по исходному событию, входит в знаменатель. До анализа фиксируем источники: R41/causal_budget/state и предсказания того же seed, R33 признаки и цены, R35 модель порядка и R39/global_packet HGB. Это идентичные представления и параметры исходной политики на четырёх этапах. При наличии ресурсов повторяем на остальных четырёх seed отдельно. Эталонные ответы, качество и границы отбора не оптимизируются.

Заново вычисляем ранги, обязательный префикс 1024 и целочисленную нормализованную полезность Q32 на каждом срезе. Проверяем упорядоченный результат точной динамической программы с устойчивым приоритетом более раннего ранга при равенстве по всем подписанным спискам R41. Величина бюджета 2048. Публикуем любое отличие при переходе на Q32. Ускорение вычислений не предполагается.

Первичная диагностика в дополнение к известной итоговой точности R41 — сколько обновлений DP можно гарантированно не выполнять, если предыдущие таблицы были записаны до нужной вместимости. Сильный полный контроль пропускает целиком помещающийся хвост, удаляет отдельные элементы тяжелее текущей остаточной ёмкости, выполняет только допустимые по цене переходы по столбцам. Регистрируем начальные одинаковые строки (ID, стоимость, полезность) хвоста в оригинальном порядке и длину подтверждённого префикса. Базовые планы повторного чтения: только последняя сохранённая строка с фактической вместимостью; блок каждые 16 строк при достаточной прежней вместимости; оптимистический потолок хранения каждой строки с запасом до полного бюджета. Печатаем агрегат по вопросам, максимум, медиану, долю нулевых, условный анализ по действительно изменившимся составам и парный кластерный bootstrap по траектории. Затраты измеряем в пропущенных обновлениях ячеек; этих величин недостаточно для вывода о времени, памяти или полном ускорении.

Дополнительная граница для хронологического обхода по реальному первому появлению: сравниваем первые совпадающие эффективные строки среди обработанных кандидатов после маркировки обязательных и непомещающихся элементов. Для физического воспроизведения оригинального решения требуется прежнее ранговое правило при ничьей. Дополнительная оценка при снятом требовании к рангу — только оптимистическая числовая граница; отдельно рассматриваем необходимость сохранения рангового приоритета. Не используем будущее при вычислении весов/рангов. После результатов выберем только форму отображения, параметры здесь фиксированы.

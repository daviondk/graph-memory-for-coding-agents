# Точное обслуживание контекста по мере поступления фрагментов и пересмотра связей

В R48 сопоставлялись разные поправки к весам на одном видимом пуле. Здесь проверяем обслуживание всей последовательности снимков, начиная с пустой памяти. В один момент приходят новые фрагменты, меняется состав обязательного префикса и обновляются исходящие подтверждения FEEDS для старых результатов. Сравниваем точный полный пересчёт и сохранение промежуточных строк динамической программы между чтениями. Основная гипотеза — на одно чтение после каждой реальной группы инструментов промежуточная строка каждые 16 старых фрагментов уменьшает полное время обновления и получения того же упорядоченного пакета относительно оптимизированного полного C++-пересчёта. Учитываются запись, восстановления и чтение ID. Публикуем и сравнение с более сильным простым планом, который сохраняет только последнюю строку между пополнениями и при изменении ранее обработанного элемента начинает вычисление с нуля.

**Рабочая нагрузка.** Все 2 000 официальных тестовых вопросов ISETrace по 1 207 траекториям, зафиксированные публичные кандидаты и стоимость, закрытая группа инструментальных вызовов задаёт один момент. Каждая комбинация вопроса и траектории — отдельный запуск из пустого состояния. Пользовательский вопрос в действительности сгенерирован по полной траектории, мы моделируем его доступность на каждом шаге. Выполнение инструментов не воспроизводится. История читается только как данные. Эталонные диапазоны и совпадение с исходными задачами открываются после фиксации всех выбираемых пакетов. Вычисление эмбеддингов и добыча исходных связей ранее выполнены и не входят во время ни у одного плана.

**Семантика.** Фрагмент запоминается при доступности всех его полей. Элементы упорядочены по времени появления, внутри группы — по SHA256 ID. Память резервирует новейший непрерывный префикс стоимостью до 1 024 токенов, окончательный предел 2 048. Полезность старого элемента складывается из положительной, не зависящей от прочих кандидатов оценки и добавки за фактическую текущую поддержку источника. Семантическая основа — исходная покандидатная E5 косинусная оценка данного вопроса из подписанного списка; до Q32 берём exp(12·(s−0,7)). Прибавляем min(count,4)/16 для каждого различного поля результата кандидата; count — число исходящих подтверждений производителя после группы. Добавка служит фиксированной политикой. Для сравнения качества служат версии с нулевой прибавкой и first-fit по E5, сверяются на одинаковых пулах и бюджетах. На равной целевой функции предпочитаем отсутствие самого позднего различающегося элемента хвоста; в контекст выдаём ID от новых к старым. Это другой читатель, чем в R48. Отдельно показываем его качество; преимущества выбора всех релевантных свидетельств не предполагаются.

**Почему возможно переиспользование.** После пополнения в старой части потока могут только добавиться элементы, переставшие быть обязательными: сдвиг границы монотонен при неотрицательных ценах и фиксированном пороге. Для этого необязательного хронологического префикса храним оптимальные значения по вместимостям и биты выбора. Если изменена полезность ранее включённого элемента, восстанавливаем последнюю строку до самого раннего затронутого и пересчитываем последующие. Ёмкость хвоста при смене обязательной части может как расти, так и падать, поэтому сохранённая строка покрывает все вместимости до 2 048. Полный конкурент каждый раз обрабатывает только фактическую остаточную ёмкость. После каждой операции независимо сравниваются **все ID в заданном порядке**. Это частное применение динамического программирования и его промежуточных состояний к графовой памяти. [Динамическое обслуживание DP](https://drops.dagstuhl.de/entities/document/10.4230/LIPIcs.STACS.2023.36) · [Исходный ISETrace](https://arxiv.org/abs/2609.25913)

**План анализа.** Первичный результат — отношение среднего времени полного и сохраняющего каждую 16-ю строку планов при одном чтении на границу. Измерительные единицы — полные траектории вопроса; в пределах каждого вопроса одинаковые входы, один процесс, один CPU-поток C++ на план, один прогрев, 5 чередующихся повторов. Для времени до построения последнего пакета включаем подготовку собственного внутреннего состояния и запись всех прочитанных ID. Показываем объём пикового алгоритмического состояния, обработанные DP-строки, строки восстановления, ближние контроли: только конечная строка, другая плотность записей (4, 64), выборка чтений только в конце/каждую четвёртую группу (простое отложенное применение всех обновлений). Оценки вторичные. Для полного множества запросов качество — Full Support и покрытие на финальном шаге и при заранее заданной восьмой группе (для журналов короче восьми — недоступно, знаменатель показывается). Интервалы 95% по 10 000 парным перевыборкам целых траекторий; отчёт не объединяет качество и скорость в одну меру. При обилии траекторий проверки на синтетических малых пулах с ничьими/нулевыми ценами требуют независимого перебора.

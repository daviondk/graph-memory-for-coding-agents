# Контроль опубликованными политиками вытеснения

Фиксируем обе законченные панели целиком: 305 состояний разработки из 103 репозиториев R48 и 179 состояний переноса из 68 других репозиториев R49. Результаты прежних политик известны. Для SIEVE и S3-FIFO показатели на этих панелях ещё не вычислялись. Гипотеза — учёт стоимости повторного кодирования способен сохранить больше входных токенов, даже когда классические политики чаще попадают в кеш по числу документов.

Вместимость 31 вектор по 16 384 байта, начало каждой проверяемой линии — пустой кеш. Предшественники определены строгим вложением наблюдённых событий того же запуска. Сравниваем отдельно два интерфейса. **Поток**: по одному уникальному фрагменту пакета в исходном порядке списка кандидатов, hit и обновление немедленно. Методы — SIEVE, S3-FIFO, LRU и фиксированная частота × цена, применённая к одному входу за раз. **Пакет (основной)**: до любой записи читаем все уникальные фрагменты из исходных резидентов. SIEVE и S3-FIFO обновляются в исходном порядке; дополнительная адаптация для каждой — сначала исходные промахи, затем хиты, внутри каждой части от дешёвых к дорогим, стабильная развязка по убыванию digest. Для усиления сравнения включаем прежний усиленный LRU с тем же порядком, оригинальный batch-GDSF, изолированную стоимость и фиксированную частоту × стоимость. У классических политик допуск на шаге записи определяется их текущим состоянием. У пакетного интерфейса выдача уже завершена до этой симуляции. Внутрипакетная дедупликация одинакова для всех. Во вторичном потоковом контроле также развернём исходный порядок уникальных объектов внутри каждого запроса в обратную сторону.

Основная метрика — разница межзапросной экономии токенов на общем исходном входе (в потоке: экономия по последовательным попаданиям внутри представления уникальных ключей); отдельно число попаданий, макросредняя по репозиториям, чистые токены. Знаменатель включает запрос и входы с дублями. Парный процентильный bootstrap по целым репозиториям, 20 000 перевыборок, seed 491902, 95%. Ключевые четыре контраста — пакетная политика R48 против каждой из двух опубликованных политик в двух предопределённых вариантах записи, отдельно по двум панелям. Доверительные интервалы отдельных контрастов. Результат относительно наиболее сильного стоимостного контроля также обязателен. Без выбора лучшего варианта после измерения. Новых физических замеров, времени GPU или нового поиска в этом опыте нет.

S3-FIFO: фиксируем C-реализацию libCacheSim ревизии 5fa68ef6902350aa9734398862bec7912d59f5e3 с её параметрами 10%/90%, порог двух попаданий; в дискретных слотах small target 3, main target 28, до 27 ghost-ключей при единичном размере объекта (floor .9*31). SIEVE: FIFO-порядок, один бит посещения, hand указывает следующую жертву, просмотр от старых объектов к новым и циклический возврат. Для каждого алгоритма зарезервировано по 64 байта на каждую резидентную запись и 256 байт заголовка; 27 ghost-ключей с индексом по 40 байт там, где они требуются. Реконструкция будет сверена с оригинальным кодом/псевдокодом на миниатюрных потоках до обработки бенчмарка.
